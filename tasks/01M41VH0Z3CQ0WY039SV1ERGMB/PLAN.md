   приложения, не отдельным файлом `tests/` ветки (основание —

один шаг.

## Влияние на систему
Меняется только текст правил аналитика — после мержа приложения новые
SPEC перестают заказывать повторы долгоживущих тестов и отдельные сторожа
в `tests/` для правок приложением. Гейты, guard, лимиты, тесты и
инварианты не затрагиваются; существующие пункты скила не меняются и не
удаляются (дифф без строк «-»). Сторож свойства этой правки — сама
планка задачи (`acceptance_tests/test_spec_authoring_appendix.py`
проверяет скил по копии с наложенным приложением), отдельного файла в
`tests/` ветки нет — ровно по вводимому правилу. Откат — revert
merge-коммита задачи (приложение накладывается коммитом мержа).

## Предложения системе
- `orchestrator/plank_run.py:140` передаёт pytest АБСОЛЮТНЫЙ путь
  (`str(tests_dir / selected)`), а сторож роли `conftest.py:55-68`
  (`_is_targeted_path`) признаёт только пути, начинающиеся с `tests/`
  или `tasks/…/acceptance_tests`: в шаге роли (`ARTEL_ROLE` задан)
  `plank-run` отказывает всегда — с файлом и без, «полный прогон
  запрещён», код 2. Единственный штатный способ прогона планки в шаге
  нерабочий; починка — путь относительно `code_dir` в `plank_run.py`
  либо признание абсолютного пути под `tasks/<id>/acceptance_tests/`
  в `conftest.py`.

# SPEC: Правила аналитика — тест по свойству, сторож и замер для правки приложением

## Контекст
Пересчёт 03.10.2026 по 27 задачам после 29.09: 19 полных повторов
долгоживущих тестов в `tests/`, 8 из них заказаны самим SPEC (задача
01M3Y753QNG6TS5C7MTJS1MEV6, требование 10; разовый тест AC-6 задачи
01M3YQB4KMADY0BET5N8279N6B). Отдельно: CI ветки идёт без приложений PLAN,
а гейт мержа ждёт зелёный CI ветки до их наложения
(`orchestrator/fsm_merge_gate.py`) — сторож в отдельном файле `tests/`
ветки для свойства, которое доставляет приложение, красен на ветке
(ликвидация 01M41JYGHTP8ZVXVPEF8K8W381), а замер «после» по CI ветки для
такой правки невозможен (замечание ревью 01M41M6KGWA9PJ6G1KPDC6XY70).
Правила аналитика (`skills/spec-authoring.md`) сейчас этого не говорят;
`doc-commit` правку правил ролей не принимает, поэтому — задачей.

## Требования
1. В `skills/spec-authoring.md`, раздел «## Границы» (перед
   «## Запрещено»), добавляется пункт по смыслу: тест в `tests/`
   заказывается по свойству, а не по месту — свойство, которое уже
   держит долгоживущий приёмочный тест автора тестов (ADR-0020), SPEC
   повторно в `tests/` не требует. Основание-прецедент — пересчёт
   03.10.2026 (19 повторов, 8 заказаны SPEC).
2. В том же разделе добавляется пункт по смыслу: для правки, которая
   едет приложением к защищённому пути, сторож свойства требуется
   внутри того же приложения, не отдельным файлом `tests/` ветки
   (основание — 01M41JYGHTP8ZVXVPEF8K8W381); замер «после» по CI ветки
   для такой правки не заказывается — «до» берётся по CI `main`,
   «после» даёт первый CI `main` после мержа (основание — замечание
   ревью 01M41M6KGWA9PJ6G1KPDC6XY70).
3. Формулировка пунктов — на усмотрение роли, по-русски, с названными
   основаниями-прецедентами.
4. Правка `skills/spec-authoring.md` — unified-дифф приложением к PLAN,
   проверенный `git apply --check` на чистом дереве; других изменений
   (в коде, тестах, прочих правилах) задача не вносит.

## Критерии приёмки
Содержимое `skills/spec-authoring.md` проверяется по копии дерева с
наложенным приложением PLAN (сам файл защищён и в ветке не меняется).

AC-1. В `skills/spec-authoring.md` с наложенным приложением раздел
«## Границы» (до «## Запрещено») содержит пункт о том, что тест в
`tests/` заказывается по свойству, а не по месту: свойство, которое
держит долгоживущий приёмочный тест автора тестов, SPEC повторно в
`tests/` не требует; пункт ссылается на ADR-0020 и на пересчёт
03.10.2026 как основание.

AC-2. В том же разделе есть пункт о правке приложением к защищённому
пути: сторож свойства требуется внутри того же приложения, а не
отдельным файлом `tests/` ветки; пункт называет основание
01M41JYGHTP8ZVXVPEF8K8W381.

AC-3. В том же пункте или рядом сказано, что замер «после» по CI ветки
для правки приложением не заказывается: «до» — по CI `main`, «после» —
первый CI `main` после мержа.

AC-4. Приложение PLAN к `skills/spec-authoring.md` применяется к
чистому дереву ветки (`git apply --check` без ошибок), и PLAN
подтверждает эту проверку.

AC-5. Дифф приложения затрагивает только `skills/spec-authoring.md` и
только добавляет строки в раздел «## Границы»: прочие разделы файла не
меняются, существующие строки не удаляются. Кодовая ветка задачи не
меняет ничего, кроме `docs/codebase-map.md` (если её регенерация
потребуется).

## Не входит
- Правка других правил ролей (прочих файлов `skills/`) — граница ТЗ.
- Механическая проверка повторов тестов (в guard, гейтах или скриптах).
- Изменение гейтов.
- Правка `orchestrator/`, `tests/`, `scripts/`, `docs/adr/`,
  `docs/backlog.md`, `templates/`, `CLAUDE.md` — только чтение по ТЗ.
- Зелёный полный `tests/`, зелёный CI ветки, неизменность защищённых
  путей в кодовой ветке и непревышение бюджета — их держит пульт.

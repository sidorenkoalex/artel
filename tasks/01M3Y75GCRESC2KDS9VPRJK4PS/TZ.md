# ТЗ: pin-update называет живые циклы auto, запущенные на старом коде

Источник: строка копилки 02.10 (П2) «Живой цикл auto после pin-update продолжает работать на старом коде»; решение Оператора 02.10.

Факты (origin/main 28b09389; номера строк аналитик сверяет):
- `orchestrator/pin.py::cmd_pin_update` (около строк 50–76): fetch, сверка канарейки (ADR-0013), `git merge --ff-only`, запись журнала «pin обновлён». О живых циклах `auto` и одиночных `run` ничего не сообщает.
- Отвязанный цикл — отдельный процесс Python, загрузивший модули пульта при старте; после сдвига пина он продолжает исполнять прежний код до своего завершения (ожидание зоны может длиться до `config.ZONE_WAIT_MAX_SEC` = 6 ч).
- 02.10: задача 01M3XTF5506GF43HD51ECE230T эскалировала в 10:06Z из процесса pid 2063 (старт 08:27Z, до мержа исправления 01M3XTF1CEBXT4J7P0EKG5J342 и пина 393172e4) без признака эскалации разработчика — после ответа и approve цикл повторил эскалацию, понадобился второй ответ. Цикл 01M3SF7DPF… ждал зону с 07:4xZ на старом коде; Оператор перезапускал оба вручную (`stop` + `auto`).
- Живые циклы видны по lease (`store.all_leases`: task_id, pid, hostname, heartbeat_ts) и журналу «auto старт».

Требуется:
1. `pin-update` после успешного сдвига печатает и пишет в журнал (запись «pin обновлён» или отдельная рядом) перечень живых на этой машине циклов `auto`/`run`, чей процесс стартовал раньше сдвига: id задачи, pid, время старта, состояние задачи — и готовые команды перезапуска (`stop <id>`, затем `auto <id>` с аргументами наблюдения `--client`/`--chat`, если цикл был под наблюдением).
2. Сам `pin-update` циклы не останавливает и не перезапускает (решение — за Оператором).
3. `doctor` получает проверку «циклы на коде старше пина»: предупреждение с тем же перечнем, пока такие процессы живы.
4. Время старта процесса — из надёжного источника (журнал «auto старт»/«run» задачи с pid либо системные сведения о процессе), выбор обосновать в SPEC; ошибка определения — запись «не удалось определить», не молчание и не отказ `pin-update`.
5. Тесты в новом файле `tests/test_pin_update_stale_cycles.py`, каждый с «Ловит мутацию: …»: живой цикл, стартовавший до сдвига, назван с командами; цикл, стартовавший после, не назван; мёртвый lease не назван; `doctor` предупреждает; `pin-update` не шлёт сигналов процессам.

Зоны: orchestrator/pin.py, orchestrator/doctor/, tests/test_pin_update_stale_cycles.py, docs/codebase-map.md.

Только чтение (не менять): orchestrator/auto.py, orchestrator/lease.py, orchestrator/store.py, orchestrator/canary.py, остальные файлы tests/, skills/, docs/adr/, docs/invariants.md, tests/test_invariants.py, tasks/.

Не входит: автоматическая проверка пина внутри цикла `auto` на границе шагов; перезапуск циклов пультом.

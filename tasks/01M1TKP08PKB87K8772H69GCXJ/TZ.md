# ТЗ: R3 — `fsm.py`: подтяжка в модуль `pull.py` с явными исходами, approve как таблица переходов

Источник: роадмап §3, фаза R, пункт R3. Замер 06.09 (после мержа
«причины конфликта подтяжки» 01M1REVMB5): `_pull_main_or_escalate` —
218 строк (свежесть против origin, merge, авторазрешение карты,
детализация конфликта, WIP-чекпоинт не-картовых правок из «карты и
подтяжки» 01M1RA0R9A, откат/сохранение слияния, эскалация),
`_cmd_approve` — 125 строк цепочки `if state == ...`.

Правила фазы R: поведение не меняется; тексты журнала и эскалаций
байт-в-байт (на них опираются планки 01M1NBWP «свежесть ветки»,
01M1RA0R9A «карта и подтяжка», 01M1REVMB5 «причина конфликта»,
tests/test_branch_freshness_gate.py, tests/test_fsm_map_conflict_
autoresolve.py, tests/test_fsm_merge_conflict_note.py); тесты без правки
утверждений; подмены `mock.patch.object(fsm, "...")` в существующих
тестах продолжают работать (реэкспорт имён из `fsm.py`).

Требуется:
1. Новый модуль `orchestrator/pull.py`: подтяжка main в ветку задачи
   возвращает явный исход — перечисление/датакласс вида `Fresh`,
   `Pulled(sha)`, `Conflict(files, note)`, `Refused(reason)`; каждая ветка
   сегодняшней функции — отдельная короткая функция (свежесть, merge,
   авторазрешение карты, детализация конфликта, чекпоинт, финализация).
2. `fsm._pull_main_or_escalate` остаётся точкой входа с прежней
   сигнатурой и прежним контрактом возврата для вызывающих (переходы
   in_dev/acceptance/merge_gate), внутри — вызов `pull.py` и перевод
   исхода в прежние записи журнала/эскалации.
3. `_cmd_approve`: таблица «состояние → обработчик» (словарь) вместо
   цепочки условий; обработчики — существующие функции переходов, тексты
   отказов («в состоянии X нечего подтверждать» и др.) прежние.
4. Юнит-тесты на `pull.py` по исходам (лёгкая песочница с поддельным
   git, как в tests/test_fsm_map_conflict_autoresolve.py) и на таблицу
   approve (каждое состояние ведёт к ожидаемому обработчику).
5. Смоук: три записанных сценария подтяжки (свежая ветка, конфликт
   только по карте, конфликт по двум файлам) — журнал и stdout
   байт-в-байт как до правки; фикстуру снять до правки кода.

Зоны: orchestrator/fsm.py, orchestrator/pull.py (новый), tests/.
Свободны. Не входит: `fsm_advance.py` (R2), `fsm_merge_gate.py` (R7
смержен), изменение правил подтяжки по существу.

Рамка: $35.

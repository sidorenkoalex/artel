# PLAN: объявленный стек пульта, часть 1 — манифест, инвариант «только стандартная библиотека», проверка doctor

## Подход

Один новый модуль `orchestrator/stack.py` — единственный источник
значений манифеста (версия Python, минимальные версии `git`/`gh`/
`claude` со способом проверки, пустой список допустимых исключений
правила «сторонних пакетов нет») и функция `check_stack()`, которая
сравнивает факт с манифестом без сети. Три места подключают этот
модуль, не копируя его логику: `docs/stack.md` (человекочитаемое
описание, ссылка на модуль как источник), `tests/test_invariants.py`
(новый класс — `ast`-скан `orchestrator/`/`scripts/`/`tests/` на
сторонние импорты, сверка со `sys.stdlib_module_names` и списком
исключений манифеста), `orchestrator/doctor.py::all_checks` (одна
строка `checks.extend(stack.check_stack())`). `orchestrator/version.py`
дописывает вывод `cmd_version()` двумя новыми блоками (версия Python
исполнителя, результат `check_stack()`), не трогая три существующие
строки. `tests/test_stack.py` — постоянная регрессия манифеста и трёх
сценариев `check_stack()` (ok/warn/fail), переживающая закрытие
приёмочной планки задачи.

Ключевое решение: `check_stack()` возвращает свои собственные
`StackCheck`-неймтаплы (`name status detail`), а не переиспользует
`doctor.Check` — так `orchestrator/stack.py` не импортирует
`orchestrator/doctor.py` (у doctor и так много зависимостей; обратный
импорт создал бы цикл, так как `doctor.py` импортирует `stack`).
Совместимость обеспечивается одинаковой формой полей (name/status/
detail) и одинаковыми значениями `status` («ok»/«warn»/«fail»),
которые уже понимает `doctor.LABELS`.

Минимальные версии `git`/`gh`/`claude` не зафиксированы SPEC численно
(AC-2/AC-3 проверяют структуру и факт вызова `--version`, не число) —
выбраны заведомо ниже версий, реально установленных в среде роли и CI
(`git` 2.30.0, `gh` 2.0.0, `claude` 1.0.0), чтобы `doctor`/`version` не
кричали WARN на здоровой машине без причины.

## Шаги

1. `orchestrator/stack.py`: `REQUIRED_PYTHON = (3, 11)`, манифест
   инструментов (`git`/`gh`/`claude` — минимальная версия + argv
   `--version`), `THIRD_PARTY_EXCEPTIONS = ()` (список пар
   модуль/причина), `check_stack()` (4 проверки: python + 3
   инструмента, WARN при заниженной версии, FAIL при отсутствии
   инструмента, без сети).
2. `docs/stack.md`: что входит в стек, почему только стандартная
   библиотека, как проверить (`artel.py version`, `artel.py doctor`),
   явная ссылка на `orchestrator/stack.py` как на единственный источник
   значений — без дублирования чисел версий.
3. `tests/test_invariants.py`: новый класс — независимый (от кода
   задачи) `ast`-скан `orchestrator/`/`scripts/`/`tests/`, сверка со
   `sys.stdlib_module_names`/пакетами репозитория/
   `stack.THIRD_PARTY_EXCEPTIONS`; тест на чистом текущем дереве и на
   синтетическом дереве с подсаженным сторонним импортом.
4. `orchestrator/doctor.py`: импорт `stack`, одна строка
   `checks.extend(stack.check_stack())` в `all_checks` — без
   собственной логики сравнения версий.
5. `orchestrator/version.py`: `cmd_version()` — добавить строку с
   версией Python исполнителя и строки с результатом
   `stack.check_stack()`, вызванным как `stack.check_stack()` (атрибут
   модуля, не `from`-импорт) — существующие три строки вывода не
   трогать.
6. `tests/test_stack.py`: постоянная регрессия — константы манифеста
   (`REQUIRED_PYTHON`, каждый из `git`/`gh`/`claude`), три сценария
   `check_stack()` (ok/warn/fail) с подменёнными `subprocess.run`/
   `sys.version_info`, отсутствие сетевых вызовов.

Один шаг = один MR (монолит, см. SPEC «Оценка объёма и деление» —
манифест и оба потребителя неразделимы содержательно).

## Влияние на систему

- `orchestrator/doctor.py::all_checks` получает 4 новые проверки
  (python/git/gh/claude) в общий список — не блокирующие (`preflight_checks`
  их не подключает, только `all_checks`/`cmd_doctor`), поэтому старт шага
  агента (`runner.cmd_run`) не затрагивается; на здоровой машине с
  установленными git/gh/claude выше выбранных минимумов все 4 — `ok`,
  `cmd_doctor` не меняет код возврата.
- `tests/test_doctor.py` уже мокает `subprocess.run` через
  `claude_only_run`/`claude_only_popen` (не-`claude`-вызовы уходят в
  РЕАЛЬНЫЙ `subprocess.run`) — новые вызовы `git --version`/
  `gh --version` внутри `check_stack()` в существующих тестах doctor
  пойдут в реальные бинарники машины (они есть и на роли, и в CI-раннере
  ubuntu-latest), получат заведомо высокие версии — `ok`, не меняют
  проверяемые тестами имена чеков (`token`/`cli-version`/
  `orphans-dirs`) и не поднимают новый `fail` там, где его не было.
- `tests/test_version.py` мокает `doctor.subprocess.run` (тот же
  объект модуля `subprocess`, что видит и `stack.py`) одним и тем же
  ответом на любой argv — `git`/`gh` внутри `check_stack()` получат тот
  же текст, что и `claude` (например, значение `config.CLI_VERSION_PIN`
  как "версия"), что может дать WARN по `git` при заниженном относительно
  выбранного минимума значении фикстуры — не задевает assertions
  существующих тестов (они проверяют только `РАСХОЖДЕНИЕ`/пин/схему,
  не отсутствие WARN по стеку); новый текст WARN не содержит слова
  «РАСХОЖДЕНИЕ» — не пересекается с `assertNotIn` веткой.
- Инвариант «только стандартная библиотека» — новый неослабляемый тест
  в `tests/test_invariants.py`; ничего в системе не ослабляет, только
  добавляет защиту. Не добавляю строку в `docs/invariants.md` (реестр
  инвариантов) — файл не входит в зоны этой задачи
  (`orchestrator/stack.py, docs/stack.md, tests/test_invariants.py,
  tests/test_stack.py, orchestrator/doctor.py, orchestrator/version.py`)
  и не входит в `config.COMMON_ZONES`; правка вне зон — отдельная тема
  для Оператора при желании завести номерной инвариант.
- Откат: `git revert` коммита — новый модуль и подключения атомарны,
  ничего не удаляет и не меняет в существующих файлах кроме двух
  дополнительных строк в `all_checks`/`cmd_version`.

## Риски

- Реальная версия `git`/`gh`/`claude` на конкретной машине роли/CI ниже
  выбранного минимума — тогда `doctor`/`version` начнут показывать WARN
  по этому инструменту. Не авария (WARN, не FAIL, не блокирует), но
  видимый шум. Оператор может поднять минимум обратно вниз правкой
  `orchestrator/stack.py`, если это будет мешать.
- `docs/stack.md` не проверяется автоматически на отсутствие
  продублированных чисел версий (сама SPEC явно оставляет эту грань
  ревью Оператора/PLAN, не механической проверке, AC-4).

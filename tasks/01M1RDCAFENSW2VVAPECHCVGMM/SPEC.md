# SPEC: объявленный стек пульта, часть 1 — манифест, инвариант «только стандартная библиотека», проверка doctor

## Контекст
У пульта нет объявленного стека: код, скрипты и тесты не импортируют
сторонние библиотеки де-факто, но это правило нигде не зафиксировано
и не проверяется — как и минимальная версия Python и версии внешних
инструментов (`git`, `gh`, `claude`). Интерпретатор разный в каждом
месте (локально pyenv 3.13, системный 3.9, в CI — системный Python
раннера, у роли — первый `python3` из PATH Оператора), роли подхватывают
из окружения машины инструменты, которых у проекта нет (пример:
pytest в 217 логах шагов). Решение Оператора (разбор 05.09, копилка
роадмапа §4 п.8): стек объявляется в репозитории и проверяется кодом,
а не удерживается запретами. Эта задача — часть 1 из трёх: манифест,
инвариант «только стандартная библиотека» и проверка `doctor`.
Закрепление версии Python в CI и окружение роли — отдельные задачи
(части 2 и 3).

## Требования

1. Модуль `orchestrator/stack.py` объявляет манифест стека: минимальная
   версия Python константой `REQUIRED_PYTHON = (3, 11)`; внешние
   инструменты `git`, `gh`, `claude` — с минимальной версией каждого и
   способом проверки версии; правило «сторонних пакетов нет» —
   явным списком допустимых исключений с обязательной причиной на
   каждое (список сейчас пуст).
2. `docs/stack.md` человекочитаемо описывает тот же стек (что входит,
   почему только стандартная библиотека, как проверить) и ссылается на
   `orchestrator/stack.py` как на единственный источник значений — не
   дублирует числа отдельно от модуля.
3. `tests/test_invariants.py` содержит тест, который разбирает
   `orchestrator/`, `scripts/`, `tests/` через `ast` и падает, если в
   исходниках встречается импорт модуля, который одновременно не входит
   в `sys.stdlib_module_names` и не является пакетом репозитория
   (`orchestrator`, `scripts`, `tests`). Модули из списка исключений
   манифеста (требование 1) в падение не засчитываются.
4. `orchestrator/stack.py` содержит функцию `check_stack()`,
   сравнивающую фактические версии (`sys.version_info`, `git --version`,
   `gh --version`, `claude --version`) с манифестом:
   - расхождение версии инструмента с минимально требуемой — статус
     WARN, текст в одну строку с именем инструмента, фактической и
     требуемой версией;
   - отсутствие инструмента в PATH/системе — статус FAIL;
   - проверка не обращается к сети (инвариант 35, `docs/invariants.md`).
5. `orchestrator/doctor.py` подключает `check_stack()` к списку проверок
   (`all_checks`) одной строкой, без переноса логики сравнения версий
   в сам `doctor.py`.
6. Команда `artel.py version` (реализация — `orchestrator/version.py`,
   `cmd_version`) дополняется строкой с версией Python и строкой(-ами)
   с результатом `check_stack()`, не изменяя существующие строки
   вывода — существующие тесты `version` остаются зелёными без правок.

## Критерии приёмки

AC-1. `orchestrator/stack.py` существует и определяет константу
`REQUIRED_PYTHON = (3, 11)`.

AC-2. `orchestrator/stack.py` определяет для каждого из инструментов
`git`, `gh`, `claude` минимальную версию и способ проверки её версии
(команда и разбор вывода).

AC-3. `orchestrator/stack.py` определяет список допустимых исключений
из правила «сторонних пакетов нет»; список пуст на момент этой задачи;
структура требует причину на каждую будущую запись списка.

AC-4. `docs/stack.md` описывает состав стека (что входит, почему только
стандартная библиотека, как проверить) и явно ссылается на
`orchestrator/stack.py` как на единственный источник значений — числа
версий в `docs/stack.md` не продублированы отдельно от модуля.

AC-5. В `tests/test_invariants.py` есть тест, который через `ast`
разбирает файлы `orchestrator/`, `scripts/`, `tests/` и падает при
обнаружении импорта модуля, отсутствующего в `sys.stdlib_module_names`,
не являющегося пакетом репозитория (`orchestrator`, `scripts`, `tests`)
и отсутствующего в списке исключений манифеста.

AC-6. Тот же тест не падает на текущем состоянии дерева `orchestrator/`,
`scripts/`, `tests/` (сторонних импортов там нет).

AC-7. `orchestrator/stack.py` содержит функцию `check_stack()`,
возвращающую по одной проверке на каждый инструмент манифеста
(Python, `git`, `gh`, `claude`).

AC-8. При расхождении фактической версии инструмента с минимально
требуемой `check_stack()` даёт статус WARN с текстом, содержащим имя
инструмента, фактическую версию и требуемую версию в одной строке.

AC-9. При отсутствии инструмента `check_stack()` даёт статус FAIL для
этого инструмента.

AC-10. `check_stack()` не выполняет сетевых обращений (инвариант 35).

AC-11. `orchestrator/doctor.py::all_checks` подключает результат
`check_stack()` одной строкой; логика сравнения версий не дублируется
в `doctor.py`.

AC-12. Вывод команды `artel.py version` дополнен строкой с версией
Python, фактически запущенной у исполнителя.

AC-13. Вывод команды `artel.py version` дополнен строкой(-ами) с
результатом `check_stack()`.

AC-14. Все строки вывода `artel.py version`, существовавшие до этой
задачи, остаются без изменений — существующие тесты `tests/test_version.py`
проходят без правок.

AC-15. Есть тест, читающий манифест `orchestrator/stack.py` и
проверяющий наличие описанных в требовании 1 констант (версия Python,
запись на каждый из `git`/`gh`/`claude`, список исключений).

AC-16. Есть тест инварианта из AC-5/AC-6, который на временном дереве с
подсаженным сторонним импортом (модуль вне `sys.stdlib_module_names` и
вне пакетов репозитория) фиксирует падение, а на чистом временном
дереве — не фиксирует.

AC-17. Есть тест `check_stack()` с подменёнными `subprocess.run` и
`sys.version_info`, покрывающий три сценария: версия соответствует
манифесту (ok), версия ниже требуемой (WARN), инструмент отсутствует
(FAIL).

AC-18. Полный существующий набор `tests/` проходит зелёным после
внесённых изменений (регрессий нет).

## Оценка объёма и деление
Сработавшие сигналы: число файлов зоны — 6 (`orchestrator/stack.py`,
`docs/stack.md`, `tests/test_invariants.py`, `tests/test_stack.py`,
`orchestrator/doctor.py`, `orchestrator/version.py`) ≥ 5
(`SPLIT_SIGNAL_ZONE_FILES`); число критериев приёмки — 18 ≥ 10
(`SPLIT_SIGNAL_AC_COUNT`).

**Обоснование монолита.** Задача уже является результатом деления
Оператором более крупной инициативы «объявленный стек пульта» на три
независимые части (часть 1 — эта задача; часть 2 — закрепление версии
Python в CI; часть 3 — окружение роли), см. «Не входит». Внутри самой
части 1 манифест (`orchestrator/stack.py`) и оба его потребителя
(инвариант в `tests/test_invariants.py`, проверка в `doctor.py` через
`check_stack()`) — не самостоятельные приращения, а одна атомарная
смена механики: манифест без потребителей — мёртвая структура данных,
которую нечем проверить содержательно (AC-15 читает те же константы,
которые AC-5/AC-9 обязаны использовать как источник истины); потребитель
без манифеста не существует по определению требования. Промежуточное
состояние «манифест смержен, инвариант или doctor-проверка — нет»
оставляет ровно ту проблему, ради которой заведена задача (незамеченный
дрейф стека), нерешённой, то есть неработоспособно. Разбиение на 2–3
подзадачи добавило бы 2–3 полных цикла SPEC/PLAN/REVIEW ради набора
изменений, каждое из которых — несколько констант, один `ast`-проход,
одна строка подключения и два `print` — без снижения реального риска,
так как весь риск сосредоточен в одном и том же объекте (манифест),
потребляемом одинаково всеми частями. Заметный список файлов зоны (6)
— следствие того, что манифест по своей природе имеет двух потребителей
и человекочитаемую копию (`docs/stack.md`), а не следствие широты
задачи по существу.

## Не входит

- Закрепление версии Python в CI (часть 2).
- Окружение роли (часть 3).
- Установка отсутствующих инструментов.
- Менеджер зависимостей.
- Перенос логики сравнения версий в `doctor.py` — там только точка
  подключения (требование 5).
- Правка существующих строк вывода `artel.py version` (требование 6,
  AC-14).

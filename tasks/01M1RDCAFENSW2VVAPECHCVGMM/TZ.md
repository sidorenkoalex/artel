# ТЗ: объявленный стек пульта, часть 1 — манифест, инвариант «только стандартная библиотека», проверка doctor

Источник: разбор 05.09 (копилка роадмапа §4 п.8). У пульта нет
объявленного стека: код, скрипты и тесты не импортируют ни одной
сторонней библиотеки, но ни это правило, ни версия Python, ни внешние
инструменты (git, gh, CLI claude) нигде не зафиксированы. Интерпретатор
разный в каждом месте: локально pyenv 3.13, системный 3.9, в CI —
системный Python раннера, у роли — первый `python3` из PATH Оператора.
Роли подхватывают из окружения машины инструменты, которых у проекта
нет (pytest в 217 логах шагов). Решение Оператора: стек объявляется в
репозитории и проверяется кодом, а не удерживается запретами.

Требуется:
1. Манифест стека — модуль `orchestrator/stack.py` с константами:
   минимальная версия Python (`REQUIRED_PYTHON = (3, 11)` — ниже
   синтаксис `X | None` в аннотациях кода пульта не работает без
   `__future__`), внешние инструменты с минимальными версиями и
   способом проверки (`git`, `gh`, `claude`), правило «сторонних
   пакетов нет». Человекочитаемое описание того же — `docs/stack.md`
   (что входит, почему только стандартная библиотека, как проверить).
   Единственный источник значений — модуль; документ ссылается на него.
2. Инвариант «только стандартная библиотека»: тест в
   `tests/test_invariants.py` разбирает `orchestrator/`, `scripts/`,
   `tests/` через `ast` и падает на импорте модуля вне
   `sys.stdlib_module_names` и вне пакетов репозитория. Исключения —
   только явным списком в манифесте с причиной (сейчас пустой).
3. Проверка `doctor`: `check_stack()` сравнивает фактические версии
   `sys.version_info`, `git --version`, `gh --version`, `claude --version`
   с манифестом; расхождение — WARN с именем инструмента, факт и
   требование в одну строку; отсутствие инструмента — FAIL. Проверка
   без сети (инвариант 35). Реализация в `orchestrator/stack.py`,
   в `doctor.py` — одна строка подключения в список проверок.
4. Команда пульта печатает стек: `artel.py version` дополняется строкой
   с версией Python и результатом `check_stack` (без изменения
   существующих строк вывода — тесты `version` зелёные).
5. Тесты: манифест читается; инвариант ловит подсаженный сторонний
   импорт во временном дереве и пропускает чистое; `check_stack` с
   подменёнными `subprocess.run`/`sys.version_info` даёт ok/WARN/FAIL
   по трём сценариям; существующий набор `tests/` зелёный.

Зоны: orchestrator/stack.py (новый), docs/stack.md (новый),
tests/test_invariants.py, tests/test_stack.py, orchestrator/doctor.py
(одна строка), orchestrator/version.py или место реализации `version`.
Порядок: `doctor.py` сейчас правит задача «группа процессов»
(01M1PNBSHR…, на ревью) — код этой задачи стартует после её мержа либо
подтягивается; вставка одной строки конфликта не даёт.
Не входит: закрепление Python в CI (часть 2), окружение роли (часть 3),
установка инструментов, менеджер зависимостей.

# PLAN: Команда `knowledge` для роли — карточки по месту, журнал обращений, подсказка в миссии (К-4б)

## Подход
Вся новая логика — в `orchestrator/knowledge_cards.py` поверх чтения
(`read_cards`/`_read_main`), проверки формы и сверки места (`match`,
`_query_error`) из К-4а; остальные модули зоны получают точечные правки.
Тяжёлые модули (`runner`, `store`, `brief`, `workspace`, `suite_lock`,
`watch`, `roles`) импортируются внутри функций: `knowledge_cards` уже
импортирует `notes` на верхнем уровне, и цикл
`notes → knowledge_cards → … → notes` не должен появиться.

- Команда `cmd_knowledge(rest)`: проверка окружения роли
  (`runner.in_role_environment`; роль без `ARTEL_TASK` — отказ при любом
  `<id>`), строка задачи — соединением `sqlite3` `mode=ro` (приём
  `preflight._open_db_readonly`), сверка `<id>` с `ARTEL_TASK` по полному
  id, затем форма запроса (`_query_error` К-4а) — отвергнутый запрос
  отказывает до чтения и записи журнала.
- Вывод: системные карточки и их пометки — без обёртки; проектные карточки,
  подробность отказа проектного вида, пометки проектных карточек и строка
  «ещё N…» (если в ней есть проектные ключи) — одним блоком
  `brief.wrap_boundary(brief.new_run_id(), …)` с
  `brief.BOUNDARY_INSTRUCTION` перед ним. Строка отказа вида — «карточки
  <вид> не прочитаны: <код>» (код из `REFUSAL_CODES`), у системного вида —
  с подробностью `refusal_text`, усечённой до 200 символов; у проектного —
  только код вне границы, подробность внутри. «не заведён»/«нет поля» —
  строкой, код возврата 0; отказ любого вида — код 1 после выдачи.
- Свежесть `p::s`: кэш разбора на вызов (ключ — источник и путь, один
  `ast.parse` на файл). Рабочая копия: `resolve()` пути против
  `resolve()` корня + `os.lstat`/`O_NOFOLLOW|O_NONBLOCK`/`fstat`, только
  обычный файл не больше `KNOWLEDGE_CARD_STALE_FILE_MAX_BYTES`. Голова
  `main` пульта (системные карточки задач внешних проектов): `ls-tree`
  (нет файла / режим `120000` / не блоб), `git cat-file -s` до чтения,
  затем `gitcmd.show`. `.py` — `ast.parse` под
  `warnings.catch_warnings()` (символы верхнего уровня, тела
  верхнеуровневых `if`/`try`, вложенно — тела классов); прочие файлы —
  последний сегмент символа отдельным словом.
- Журнал: `ACCESS_ACTION = "knowledge: обращение роли"`,
  `HINT_REFUSAL_ACTION = "knowledge: темы подсказки не прочитаны"`, автор
  `JOURNAL_ACTOR = "knowledge-cards"`. `detail` — префикс «обращение к
  карточкам:», роль (перечень `roles.load()`, иначе «роль не определена»;
  вне окружения роли — «оператор»), запрос
  `json.dumps(watch.safe_text(q), ensure_ascii=False)`, числа по видам,
  число помеченных «возможно устарела», коды отказов, `sha256` файлов.
  Предел: записи `ACCESS_ACTION` без префикса «предел журнала обращений
  исчерпан» считаются по журналу (соединение `mode=ro`); у предела —
  одна запись «предел исчерпан» на задачу. Запись — коротким
  `store.db()`; `(sqlite3.Error, OSError)` — `suite_lock.defer_journal`;
  сбой очереди — одна строка stderr.
- `suite_lock`: `deferrable` принимает `ACCESS_ACTION`; `_deliver` ставит
  ему автора `JOURNAL_ACTOR` и держит предел по задаче (счётчик на задачу
  за один досыл, запись «предел исчерпан» не считается и пишется не
  больше одной); лишние файлы убираются. Правило досыла
  (переименование) не меняется.
- Гейт `tests_writing`: из сравнения исключается пара «`JOURNAL_ACTOR` +
  (`ACCESS_ACTION` | `HINT_REFUSAL_ACTION`)», как уже исключён `lease`.
- Подсказка миссии: `knowledge_cards.hint_line(task_id, project)` — одна
  строка (полный путь к `artel.py` пульта, id, «только чтение», ключи до
  `KNOWLEDGE_CARD_HINT_MAX_KEYS` и «и ещё N», «тем нет», коды отказа
  без цитат). `role_prompt.mission_brief_package` дописывает её в общий
  хвост перед абзацем рабочего каталога; при отказе вида и `conn` —
  `budget.journal_warning_once(…, key=None)`; сбой БД записи шаг не
  останавливает.
- `artel.py`: строка в справке, `knowledge` в `_ROLE_ALLOWED_COMMANDS`,
  комментарий над списком по требованию 12, запись диспетчера.

## Шаги
1. `knowledge_cards.py`: константы журнала, проект задачи по строке,
   свежесть, команда `cmd_knowledge`, `hint_line`; правка докстринга модуля.
2. `artel.py`: справка, белый список, комментарий, диспетчер.
3. `suite_lock.py`: `deferrable`, автор и предел досыла.
4. `advance_gates/tests_writing.py`: исключение пары автор+действие.
5. `role_prompt.py`: строка-подсказка и запись отказа в журнал.

   подсказки); прогон долгоживущих файлов, планки, тестов затронутых
   модулей; регенерация `docs/codebase-map.md`.

## Влияние на систему
- Белый список роли расширяется одной командой; закрытость по умолчанию
  не меняется. Команда пишет одну запись журнала с автором, которому не
  доверяет ни один читатель: действия не совпадают ни с одним `*_ACTION`
  пакета (проверяет долгоживущий тест AC-8), `spec_audit`/`brief`/`review`
  их не читают.
- Гейт `tests_writing` становится строже, не слабее: поздняя запись
  обращения или отказа подсказки больше не может заслонить маркер
  отброшенных файлов; запись этого автора с любым другим действием не
  исключается.
- Очередь отложенного журнала принимает одно новое действие со своим
  автором и пределом; прежнее действие досылается как раньше
  (`DEFERRED_ACTOR`).
- Миссия каждой роли растёт на одну строку; сборка миссии делает один-два
  дополнительных `git ls-tree`/`show` на чтение системного вида. Ожидания
  существующих тестов миссий не меняются — проверяю прогоном их файлов.
- Откат — revert merge-коммита задачи: схема БД, состояния FSM и файлы
  карточек не меняются.

## Риски
- Существующие тесты, считающие вызовы git/записи журнала при сборке
  миссии, могут увидеть лишний `git ls-tree`; прогоняю файлы миссий и
  брифов до сдачи, расхождение — эскалация, не правка ожиданий.

# Эпики, шаг Э4: проекция доски наружу — board, report из модели, внешние ссылки задач и эпиков

## Факты

ADR-0028 (принят 25.10.2026), п. 12–16; шаг Э4 после Э1 (01M5TBBDFS6DWQY6MS263T1KPY — модель `orchestrator/board.py`).

1. `report` — статическая HTML-доска (`orchestrator/report.py`, колонки `STATE_ORDER` `:46`, `_board_html` `:598`, группировка по проекту `:767`), строится не из модели `board.py`.
2. Внешних ссылок задач (ключ задачи во внешнем трекере) в БД нет.

## Требуется

1. **Вывод модели.** `artel.py board --project <имя> [--json | --md | --html]` печатает модель `board.py`: `--json` — словарь с `schema_version` (контракт для будущего интерфейса доски), `--md` — таблица, `--html` — страница. Без сети и без записи в БД.
2. **report из модели.** `report` строится из модели `board.py`; вид и содержимое HTML-доски для проекта без эпиков не меняются (сверка с текущим выводом на фикстуре), с эпиками — добавляется группировка по эпикам.
3. **Внешние ссылки.** Таблица `external_refs`: вид (`task` | `epic`), идентификатор, система (свободная строка из записи проекта или списка, например `kaiten`, `gitlab-issue`), ключ, URL (необязательно), кто и когда записал. Запись: `new … --ref <система>:<ключ>` (до создания ветки задачи) и `artel.py link <task|epic> <id> <система> <ключ> [--url …]`; `link --remove`. Ссылки — в модели доски (`cards[].refs`, `epics[].refs`). Пульт трекер не вызывает и не читает.
4. **Поле записи проекта `policy.ref_required`** (по умолчанию нет): если задано — `new` без `--ref` этой системы отказывает с причиной. (Имя ветки по ключу — отдельная задача поставки через MR, ADR-0029; здесь только хранение ключа.)

Критерии приёмки:
- `board --json` песочного проекта с эпиком: `schema_version`, `columns`, `epics`, `cards` с `waiting_on` и `refs`; два вызова без изменений БД — одинаковы (кроме `generated_at`); число изменений соединения БД — 0;
- `board --md` и `--html` строятся из той же модели (подмена модели меняет оба);
- `report` проекта без эпиков — вывод прежний; с эпиком — группировка;
- `new --ref kaiten:123` — ссылка записана и видна в модели; `link` добавляет и `--remove` снимает; `ref_required` без `--ref` — отказ `new`.

## Зоны
- **Отклонение 1 (существенное).** Требование 3 и AC-14 заставляют читать
  журнал для `waiting_on` пакетно. Решение `waiting_on` = `dependency`
  принимает `zone_lock.queue_wait` (`orchestrator/zone_lock.py:850`). Он
  читает `steps` по каждой задаче и по задачам очереди на десятке
  внутренних функций (`_waiting` `:476`, `_occupies` `:388`,
  `_stay_since_id` `:370`, `_occupier` `:487`, `_waiting_dependency`
  `:537`, `queue_order`, `_holds_queue`). Файла `orchestrator/zone_lock.py`
  в зонах SPEC нет. В пределах зон остаются два пути:
  - **(а)** переписать решение очереди зон в `board.py` поверх заранее
    прочитанного журнала. Получится копия логики `claim`, которая может
    разойтись с самим `claim`, — ровно то, от чего `queue_wait` и сделан
    общим (его docstring, `zone_lock.py:851-853`);
  - **(б)** не считать `waiting_on` для `report` вовсе: плитка
    (`report.py:565-593`) его не показывает. Но требование 3 прямо
    требует пакетного чтения «для `waiting_on`».

  Нужно решение Оператора: добавить `orchestrator/zone_lock.py` в зоны;
  разрешить модели для `report` строиться без `waiting_on`/с `None`; или
  принять дубль логики в `board.py`.
- Остальные требования в зонах укладываются:
  - `external_refs` — `schema.py` и `store.py`;
  - `--ref`, `ref_required`, `ref_systems`, наследование — `catalog.py`
    (`spawn_subtask` там же, `fsm.py` не нужен);
  - поля `policy` — `targets.py` (`LOCAL_FIELDS`). Плоская запись артели
    (`targets.py:579` `check`) неизвестные поля не отвергает, так что
    `ref_required` у артели правки `targets.yaml` пульта не требует.
    `targets.yaml` защищён (`config.PROTECTED_PATHS`, `config.py:784`) —
    SPEC его не трогает;
  - команды — `artel.py`.
- Песочница ролей: `_ROLE_ALLOWED_COMMANDS` (`orchestrator/artel.py:2233`)
  закрыт по умолчанию. Новые `board` и `link` под ролью откажут, и это
  верно для `link` (пишет БД). SPEC о белом списке молчит. Добавить туда
  `board` молча — значит расширить песочницу. Без решения Оператора не
  добавлять. Не отклонение, а примечание исполнителю.
- Защищённые пути SPEC не меняет. Обход команд `tests/test_invariants.py`
  оставлен операторским коммиту («Не входит»).

## Пути обхода гейтов
- **AC-3 через своё соединение.** Команда `board` берёт `store.db()`
  (новое соединение) и что-то пишет. Тест, замеряющий `total_changes`
  своего «уже открытого» соединения, увидит 0, и критерий ТЗ «число
  изменений соединения БД — 0» формально выполнен. Закрыть можно, если
  AC-3 потребует подмену `store.db()` на измеряемое соединение или замер
  `PRAGMA data_version`/содержимого файла БД.
- **Требование 3 флагом модели.** `build_model(conn, project,
  waiting=False)` для `report` даёт AC-14 при нуле запросов на
  `waiting_on`, и AC-7 тоже проходит. По букве требования 3 («журнал для
  `waiting_on` читается пакетно») это обход, по смыслу — разумное
  упрощение (плитка `waiting_on` не показывает). Оператору стоит выбрать
  явно (см. «Зоны», отклонение 1).
- **AC-5 до внесения эталона.** Пока эталона нет, байтовое равенство
  держит только проверка формы. Порядок внесения эталона задан решением
  Оператора (гейт №1, п. 5), отклонением не поднимается.

## Вердикт
concerns. Отклонения:
1. **Зоны: требование 3 / AC-14 без `orchestrator/zone_lock.py`.** Пакетное
   чтение журнала для `waiting_on` требует правки `zone_lock.py`
   (`queue_wait` `:850`, `_waiting` `:476`, `_occupies` `:388`) или копии
   логики очереди зон в `board.py`. Плитка `report.py:565-593`
   `waiting_on` не показывает. Нужно решение Оператора: расширить зоны,
   разрешить модель для report без `waiting_on`, или принять копию логики.
2. **Матрица: нет строки по E1-тестам `waiting_on`.**
   `tests/test_01m5tbbdfs6dwqy6ms263t1kpy_board_model.py:222` (ac23) и
   `:202` (ac22) подменяют `zone_lock.queue_wait` с сигнатурой
   `(conn, task_id, t=None)`. Пакетный путь мимо `queue_wait` для
   `board`/`status` их красит, а мандата на этот файл нет.
3. **AC-3 не ловит запись через собственное соединение команды.**
   `store.db()` открывает новое соединение (`orchestrator/store.py:403`).
   Нужна подмена `store.db()` на измеряемое соединение или замер по
   файлу БД.
4. **Матрица: покрытие по `tests/test_report.py:1018` завышено.** Тест не
   строит доску (`:1025-1031`). Свойство «запросы к steps не растут» для
   доски покрывает только AC-14.
5. **Малые пробелы в AC.**
   - «без сети» (ТЗ п. 1, требование 1) не проверяется ни одним AC;
   - порядок «ссылка до ветки» (ТЗ п. 3, требование 7) не проверяется
     AC-9 (`catalog.py:694` `_ensure_task_worktree`);
   - отказ на пустую систему (требование 6) не проверяется AC-12;
   - AC-5 не требует чередования id карточек двух проектов;
   - AC-14 не фиксирует одно множество проектов в обоих наборах (один
     запрос `last_step_times` на проект, `board.py:130`).

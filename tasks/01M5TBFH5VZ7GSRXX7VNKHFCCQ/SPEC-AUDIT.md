## ТЗ и SPEC
Требования 1–6 SPEC повторяют пункты «Требуется» 1–4 ТЗ, AC-1…AC-9 повторяют
критерии ТЗ. «Не входит» и зоны совпадают с ТЗ. Файлов ANSWER-n нет, решений
гейта SPEC в брифе нет. Расхождения:

1. **ТЗ «Существующие тесты» потеряно наполовину.** ТЗ требует, чтобы правка
   тестов `report` шла «без ослабления, с матрицей и независимой проверкой»
   и касалась «около 12 файлов» (так же в ADR-0028, таблица шагов, строка Э4).
   SPEC (`SPEC.md:71`) называет только `tests/test_report.py:246,:255,:261` и
   `tests/test_01m4mqagrwmwr0gfdm9086p3td_spec_audit_units.py:357`. Ни матрицы
   неослабления, ни перечня затрагиваемых тестов, ни готовой строки мандата
   для ANSWER в SPEC нет. Матрица ниже (раздел «Матрица неослабления») может её
   заменить, но только если Оператор примет её на гейте.
2. **Система ссылки.** В ТЗ (п. 3) система — «свободная строка из записи
   проекта или списка». В SPEC (`SPEC.md:31`) осталась только «свободная
   строка», а оговорка «из записи проекта или списка» пропала. Как понимать
   её в ТЗ, неясно: есть ли перечень допустимых систем в записи проекта или
   его нет. Выбор аналитика нигде не обоснован — решать Оператору.
3. Требований сверх ТЗ в SPEC нет.

## Пути обхода гейтов
1. **report без модели.** Требование 2 выполнено буквально по AC-5/AC-6:
   старая `_board_html` на строках `all_tasks` плюс группировка по
   `epic_id` из тех же строк. Расхождение двух видов доски, ради которого
   задача существует (ADR-0028 п. 12: «расхождение видов исключено
   устройством»), остаётся. Нет критерия-подмены для `report`.
2. **Модель «как бы».** Отчёт зовёт `build_model`, но плитку дорисовывает
   полями из строк БД (`review_iters`, `escalated_from`, `target`), потому
   что в карточке их нет. Формально отчёт «из модели», по сути — из двух
   источников. SPEC не говорит, расширяется ли карточка этими полями.
3. **Обход `ref_required` делением.** Части деления заводятся через
   `catalog.spawn_subtask` (`catalog.py:786`, вызов `fsm.py:1070`) мимо
   `cmd_new`. В проекте с `ref_required` они появляются без ссылки и без
   отказа. ТЗ называет только `new`. Нужно решение Оператора: требование
   распространяется на части (ссылку наследовать от родителя или отказывать)
   или нет.
4. **Слабая фикстура AC-5.** Фикстура с одним проектом и одним состоянием
   делает AC-5 «вид не изменился» тривиальным (см. таблицу проверяемости).

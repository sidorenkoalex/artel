## Пути обхода гейтов
1. **Пустой ключ проходит `ref_required`.** Req 6 (SPEC.md:39) требует непустую систему, AC-12 (SPEC.md:73) проверяет только пустую систему. Про ключ не сказано ничего, поэтому `new --ref kaiten:` (система `kaiten`, ключ `""`) буквально удовлетворяет req 9 (SPEC.md:46): ссылка «этой системы» есть, но ключа нет. Смысл `ref_required` — по ADR-0028 п.13 будущее имя ветки строится из ключа — обходится.
2. **`link --remove` снимает обязательную ссылку.** Req 7 (SPEC.md:40-44) разрешает снять любую ссылку. После `new --ref kaiten:1` команда `link --remove task <id> kaiten 1` оставляет задачу проекта с `ref_required` без ссылки этой системы. ТЗ этот случай не оговаривает, поэтому это вопрос Оператору: отказывать в снятии последней ссылки требуемой системы или считать снятие осознанным действием Оператора.
3. Иных путей не найдено. Флаг `canary` из CLI недоступен. Отказ `new` до `_new_task_row` закреплён AC-11/AC-12. Запрет `waiting_on` для report закреплён AC-14 (`queue_wait` не вызывается). Запись через своё соединение `board` ловит AC-3.

## Вердикт
**concerns** — SPEC можно вести дальше. Отклонения решает Оператор на гейте:

1. Пустой ключ ссылки не запрещён и проходит `ref_required` (SPEC.md:39, :46, :73). Предложение: req 6 — «система и ключ — непустые строки»; AC-12 — `new --ref kaiten:` и `link task <id> kaiten ''` отказывают, ссылка не записывается.
2. `link --remove` позволяет после `new` снять обязательную по `ref_required` ссылку (SPEC.md:40-46). Нужно решение Оператора: отказ на снятие последней ссылки требуемой системы или явная строка «снятие не ограничено» в «Не входит».
3. Порядок карточек внутри группы эпика не задан (SPEC.md:35, AC-6 SPEC.md:61): «прежним порядком» сказано только про карточки без эпика. Мутацию «карточки эпика в группе в обратном порядке» AC-6 не ловит. Предложение: «внутри группы — по возрастанию id задачи (как прежде)».
4. Источник поля «кто записал» не определён (SPEC.md:38, :45): кто это для `new --ref`, `link` и копии при делении (req 11, SPEC.md:48) — Оператор/сессия, пульт или переносится от родителя. AC-9 проверяет только непустоту, AC-13 — только систему и ключ. Это не блокирует, но в модели (контракт будущего интерфейса) значение будет произвольным.
5. Формат `--ref <система>:<ключ>` не уточнён для ключа с `:` (например, URL или `group/proj#1`) и для значения без `:` (SPEC.md:41). Предложение: делить по первому `:`, значение без `:` — отказ с причиной.
6. В матрице нет строки о свойстве «report не меняет БД и не зовёт git» (`tests/test_01m4rzayh3swjw4wfbw4qw15fp_command_report.py:417`), хотя report теперь идёт через `build_model`. Свойство остаётся покрытым тем же тестом без правки (см. раздел «Матрица неослабления»). Это замечание к полноте матрицы.

Расхождений между решениями Оператора на гейте SPEC №1–№3 и ANSWER-1 нет: более поздние решения уточняют ранние (пакетное чтение заменено флагом без `waiting_on`), и SPEC идёт за последними.

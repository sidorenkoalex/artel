# SPEC: B1a — изоляция обвязки целевого: MCP-вектор и флаги CLI

## Контекст
Роадмап §3, фаза B: «B1a — изоляция обвязки целевого, флаги CLI ($25)».
Норматив — ADR-0003 п.14 («Агентская обвязка целевого не наследуется»,
принцип: окружение роли определяет только пульт) и строка аудита v5:
«отдельный HOME/CONFIG_DIR, --setting-sources, --strict-mcp-config, пин
CLI + смоук-тест обоих векторов». Часть механики уже в строю (отдельный
HOME/CLAUDE_CONFIG_DIR ролей, `--setting-sources user`, пин CLI,
isolation-smoke user-/project-слоя и project-/local-хуков, live-smoke) —
живой остаток B1a: MCP-вектор конфиг-инъекции не закрыт. `claude`
подхватывает `.mcp.json` репозитория, в котором запущен, — право
коммита в целевой проект означает возможность подключить произвольный
MCP-сервер (исполнение кода) в шаг роли с её токенами. Для догфуда риск
теоретический, для внешнего GitHub-target (B1b, sled) — прямой. Флага
строгого MCP-режима в команде запуска роли нет; смоук-теста MCP-вектора
в doctor нет.

## Требования
1. Запуск шага роли (`orchestrator/runner.py`, `run_agent_once`,
   команда, передаваемая в `spawn_agent`) жёстко ограничивает MCP-конфиг
   стороной пульта: используется только явно переданная конфигурация
   MCP, `.mcp.json` рабочего каталога и прочие ambient-источники
   игнорируются. Курируемого списка MCP-серверов у пульта сейчас нет —
   целевое состояние: ноль MCP-серверов в шаге роли. Точную комбинацию
   флагов сверить с `claude --help` установленного пина CLI
   (`config.CLI_VERSION_PIN`); если фактическое поведение флага
   отличается от ожидаемого — фактура фиксируется в артефакте задачи,
   критерии приёмки под неё не подгоняются.
2. `doctor.isolation_smoke` расширяется маркером MCP-вектора, по
   аналогии с уже реализованными в этой же функции маркерами
   user-/project-слоя и project-/local-хуков: подложный `.mcp.json` в
   рабочем каталоге роли не должен быть достижим шагом. Уровень
   проверки — офлайн-сборка cmd/env шага, без реального запуска
   `claude` (тот же приём, что уже применён к `--setting-sources`);
   живой прогон на каждый `doctor` не бесплатен.
3. `doctor` при осмотре target'а (ADR-0003 п.14) фиксирует наличие
   `.claude/`, `.mcp.json`, `CLAUDE.md`/`AGENTS.md` в целевом репо —
   информационно (`warn`, если обвязка обнаружена, `ok` — если нет),
   ничего не блокирует. Результат — основа для будущей подсветки
   изменений этих путей в MR (сама подсветка — A7, вне объёма).

## Критерии приёмки
AC-1. Команда запуска шага роли содержит строгий MCP-режим; в шаге роли
недоступен ни один MCP-сервер из `.mcp.json` рабочего каталога.

AC-2. `isolation-smoke` красный при утечке MCP-вектора и зелёный на
текущей конфигурации; существующие проверки смоука не ослаблены.

AC-3. `doctor` осмотр target'а сообщает об обнаруженной агентской
обвязке целевого репо.

AC-4. Полный тестовый набор зелёный.

## Не входит
- Песочница (контейнер) — вне объёма: это B3, другая линия защиты.
- GitHub-адаптер, Draft-MR, verifying — вне объёма (B1b).
- Подсветка защищённых путей в MR по результатам инвентаризации
  target'а — вне объёма (A7).
- Ослабление существующей изоляции (`--setting-sources`, `ROLE_HOME`
  и прочее) — принцип целостности (ADR-0002); изменения этой задачи
  только аддитивные.

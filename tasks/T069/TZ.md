# ТЗ: B1a: изоляция обвязки целевого — MCP-вектор

# ТЗ: B1a — изоляция обвязки целевого: MCP-вектор и флаги CLI

## Контекст

Роадмап §3, фаза B: «B1a — изоляция обвязки целевого, флаги CLI ($25)».
Норматив — ADR-0003 п.14 («Агентская обвязка целевого не наследуется»,
принцип: окружение роли определяет только пульт) и строка аудита v5:
«отдельный HOME/CONFIG_DIR, --setting-sources, --strict-mcp-config,
пин CLI + смоук-тест обоих векторов».

Большая часть механики уже в строю и НЕ входит в объём этой задачи:

- отдельный HOME/CLAUDE_CONFIG_DIR ролей (`config.ROLE_HOME`,
  `config.ROLE_CONFIG_DIR`) — user-слой изолирован;
- `--setting-sources user` в запуске шага роли
  (`orchestrator/runner.py`, `config.AGENT_SETTING_SOURCES`) —
  project-/local-слой настроек (включая хуки) исключён (SPEC T058);
- пин версии CLI (`config.CLI_VERSION_PIN`) + проверка `cli-version`
  в doctor; `isolation-smoke` (маркеры user- и project-слоя,
  resolve-сурсы) и `live-smoke` — работают.

## Проблема (живой остаток B1a)

MCP-вектор конфиг-инъекции не закрыт: `claude` подхватывает
`.mcp.json` репозитория, в котором запущен, — право коммита в целевой
проект означает возможность подключить произвольный MCP-сервер
(исполнение кода) в шаг нашей роли с нашими токенами. Для догфуда
риск теоретический, для внешнего GitHub-target (B1b, sled) — прямой.
Флага `--strict-mcp-config` в команде запуска роли нет; смоук-теста
MCP-вектора в doctor нет.

## Что нужно

1. Запуск шага роли (`runner`) должен жёстко ограничивать MCP-конфиг
   стороной пульта: `--strict-mcp-config` (использовать только явно
   переданную конфигурацию MCP, игнорируя `.mcp.json` репозитория и
   прочие ambient-источники). Курируемого списка MCP-серверов у пульта
   сейчас нет — целевое состояние: ноль MCP-серверов в шаге роли.
   Точную комбинацию флагов сверить с `claude --help` установленного
   пина CLI; если поведение флага отличается от ожидаемого —
   зафиксировать фактуру в артефакте, не подгонять критерии.
2. `doctor` isolation-smoke расширить маркером MCP-вектора: подложный
   `.mcp.json` в рабочем каталоге роли не должен достигать шага
   (по аналогии с существующими маркерами user-/project-слоя; уровень
   проверки — офлайн-сборка cmd/env, как сделано для setting-sources:
   живой прогон на каждый doctor не бесплатен).
3. Инвентаризация обвязки целевого при подключении (ADR-0003 п.14):
   doctor при осмотре target фиксирует наличие `.claude/`, `.mcp.json`,
   `CLAUDE.md`/`AGENTS.md` в целевом репо — информационно (warn/ok),
   как основа для подсветки изменений этих путей в MR (сама подсветка —
   A7, вне объёма).

## Границы

- Песочница (контейнер) — вне объёма: это B3, другая линия защиты.
- GitHub-адаптер, Draft-MR, verifying — вне объёма (B1b).
- Подсветка защищённых путей в MR — вне объёма (A7).
- Ослаблять существующую изоляцию (setting-sources, ROLE_HOME) нельзя —
  принцип целостности; изменения только аддитивные.

## Критерии приёмки (ориентир для SPEC)

- Команда запуска шага роли содержит строгий MCP-режим; в шаге роли
  недоступен ни один MCP-сервер из `.mcp.json` рабочего каталога.
- isolation-smoke красный при утечке MCP-вектора и зелёный на текущей
  конфигурации; существующие проверки смоука не ослаблены.
- doctor осмотр target'а сообщает об обнаруженной агентской обвязке
  целевого репо.
- Полный тестовый набор зелёный.

# ТЗ: регрессия №14 — приёмка гоняет планку на коде кодовой ветки, а не на коде пульта

Источник: два инцидента 05.09 сразу после мержа регрессии №12
(01M1R9YEK08XEQWBFX0929WFVJ, «приёмка и мерж читают артефакты из
артефактной ветки»). `acceptance.materialize_from_branch` кладёт планку
из артефактной ветки во временный каталог (`tempfile.mkdtemp`), а
`acceptance.run` запускает `python3 -m unittest discover -s <planка>` с
`cwd=config.ROOT`. Планки задач вычисляют корень репозитория от
`__file__` (`Path(__file__).resolve().parents[3]`) и вставляют его в
`sys.path`: во временном каталоге там нет `orchestrator/`, импорт
проваливается на `cwd` — корень пульта, то есть код MAIN (пина), а не код
кодовой ветки задачи. Итог: планка проверяет не тот код. Стек ч.3
(01M1RDCEF0…, AC-4 белый список окружения) и критерий сироты
(01M1REVP9W…, AC-6 отказ без origin) покраснели на подтяжке main при
зелёной планке в worktree; любая задача с планкой на новое поведение
теперь не проходит приёмку и подтяжку.

Требуется:
1. Планка из артефактной ветки материализуется в worktree задачи по
   штатному пути `tasks/<id>/acceptance_tests/` (поверх устаревшей
   копии кодовой ветки, если она есть), а не во временный каталог;
   источник истины остаётся артефактная ветка (№12 не откатывается).
2. `acceptance.run` запускает прогон с `cwd` = worktree задачи (код
   кодовой ветки); для внешних target — workspace target. Импорт
   `orchestrator` из планки резолвится в код ветки и через `__file__`, и
   через `cwd`.
3. То же для прогона после подтяжки main (`fsm._pull_main_or_escalate`)
   и для автогейта acceptance (`fsm_advance`): один вход
   материализации и один вход прогона, без дублей.
4. Отказ приёмки называет, из какого каталога и с каким `cwd` шла
   планка (одна строка в detail), чтобы такой класс дефекта был виден
   сразу.
5. Тесты: планка, импортирующая `orchestrator` относительно `__file__`,
   при расхождении кода ветки и main видит код ветки (фикстура: ветка с
   изменённой функцией, планка на новое поведение — зелёная; на main —
   красная); материализация поверх устаревшей копии заменяет её; прогон
   после подтяжки использует тот же путь; существующие тесты №12
   (`tests/test_artifact_materialization.py`, `test_fsm_autogate.py`)
   зелёные без ослабления.

Зоны: orchestrator/acceptance.py, orchestrator/fsm.py
(_pull_main_or_escalate), orchestrator/fsm_advance.py (acceptance),
tests/. Приоритет: критичный — блокирует приёмку всех живых задач;
порядок с регрессией №13 (fsm.py, fsm_advance.py — её developer уже в
работе): №13 первой, эта сразу за ней. До мержа — протокол Оператора:
планку гонять руками в worktree и проводить приёмку мостом с записью в
журнал.

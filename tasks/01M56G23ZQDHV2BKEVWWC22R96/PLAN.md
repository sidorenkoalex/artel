# PLAN: команда проверки артефакта для роли и миссии ролей внешнего проекта по профилю

## Подход

Три независимые правки в зонах SPEC, без новых модулей.

1. `orchestrator/artel.py` — команда `guard <id> [<файл>]` (`_cmd_guard`).
   Правило не копируется: команда собирает argv эталона — абсолютные пути
   файлов каталога документов (`artifact_branch.docs_dir(<id>, <target>)`)
   — и зовёт `scripts.guard.main()` в том же процессе с подменённым на
   время вызова `sys.argv`. Тем самым режим по файлам (`check` +
   `spec_path_errors` + `plan_appendix_errors`, пропуск записок и
   паспорта) и путь-метка — буквально эталонные. Без `<файл>` — все
   `*.md` первого уровня каталога, одним вызовом; `<файл>` — имя или
   `tasks/<id>/<файл>`. Код выхода — код `guard.main()`. Только чтение:
   БД читается `store.get_task`/`task_target`, lease и журнал не
   трогаются. `guard` добавлена в `_ROLE_ALLOWED_COMMANDS`.
2. `orchestrator/plank_run.py` — `[файл]` дополнительно принимает путь
   долгоживущего файла своей задачи: путь (без `::узла`) проходит
   `Profile.is_long_lived(<id>, путь)` профиля проекта задачи
   (`project_profile.decide(target).profile`; нет профиля — прежнее
   поведение). Для такого пути пропускаются только отказ «планки нет» и
   поиск в планке; файла нет в рабочей копии кода — именованный отказ
   «файла нет в рабочей копии кода». Дальше — те же отказы до выкладки
   (документы в `tasks/<id>/`, ссылка не прочитана, расхождение планки) —
   тем же кодом, затем прогон `acceptance.run_plank` тем же раннером
   (профиль `pytest-own` или раннер пульта) БЕЗ выкладки планки:
   долгоживущий файл лежит в рабочей копии сам, выкладка не нужна и
   ничего не стирает. Цель для `pytest-own` — абсолютный путь (с узлом):
   `acceptance._own_target` абсолютный путь не переводит, а
   относительный с `::узлом` перевёл бы неверно (`acceptance.py` вне зон);
   для раннера пульта — путь от корня рабочей копии (сторож
   `conftest._is_targeted_path` абсолютный путь не признаёт).
3. `orchestrator/role_prompt.py` — развилка по уже вычисленному признаку
   `artel` (`brief.is_artel_task`): у задачи артели строки миссий не
   меняются байт в байт; у внешнего проекта analyst/developer/spec_auditor
   называют `python3 <config.ROOT>/orchestrator/artel.py guard <id> …`,
   пункт 5 test_author — `plank-run <id>` и `plank-run <id>
   <long_lived_prefix(id)><имя>.py` без `python3 -m pytest`, ревьювер —
   перечень `guard`/`plank-run`/`suite-run` командами пульта вместо
   «Права не сужены».

## Шаги

1. Команда `guard` в `artel.py` + белый список роли.
2. Приём пути долгоживущего файла в `plank_run.py`.
3. Миссии внешнего проекта в `role_prompt.py`.
4. Прогон долгоживущих тестов задачи и тестов затронутых модулей
   (`test_plank_run*`, `test_role_prompt*`, тесты белого списка), планки
   (`plank-run`), регенерация `docs/codebase-map.md`.

## Влияние на систему

- Белый список роли (`_ROLE_ALLOWED_COMMANDS`) расширен одной только
  читающей командой `guard`; прочие формы и отказы роли не меняются.
- `plank-run`: для всех прежних вызовов путь выбора цели и все отказы
  прежние — новая ветка включается, только когда `[файл]` проходит
  `Profile.is_long_lived` задачи; отказы до выкладки (`plank_run.py`
  документы/ссылка/расхождение) общие для обеих веток — одним кодом, не
  копией. Отказ «планки нет» сужен ровно на эту ветку (матрица SPEC).
- Миссии артели не меняются байт в байт (AC-9, разовая планка).
- Откат — revert коммита задачи.

## Риски

- `guard.main()` печатает в stdout и читает `sys.argv`: подмена argv
  возвращается в `finally`.
- `spec_path_errors` разрешает пути от текущего каталога процесса — тот
  же, что у эталона `python3 scripts/guard.py` из рабочего каталога роли.

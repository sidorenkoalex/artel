# Команда проверки артефакта для роли и миссии ролей внешнего проекта по профилю

## Факты

Строки бэклога 18.10 «Команды проверки для роли внешнего проекта и тексты миссий по профилю» и 17.10 «Команда прогона долгоживущих файлов в задании test_author — по профилю проекта»; разбор «что прибито под артель». Миссии велят ролям прогнать `scripts/guard.py` на своих артефактах (`orchestrator/role_prompt.py:59` analyst, `:117` developer, `:217` spec_auditor). У роли внешнего проекта список разрешённых инструментов сужен до `Bash(python3 <корень пульта>/orchestrator/artel.py:*)` (`orchestrator/providers/claude.py:114-122`), а в рабочем каталоге проекта `scripts/guard.py` нет — логи шагов sled 01M55SKHZ293CCAK0N7T4H7ZMR: «guard требует подтверждения», роль сдаёт формат вслепую. Белый список команд пульта для роли (`orchestrator/artel.py:1877-1880`, `_ROLE_ALLOWED_COMMANDS`) команды проверки артефакта не содержит. Пункт 5 миссии test_author (`role_prompt.py:89-95`) называет прогон долгоживущих файлов командой `python3 -m pytest … -p timeout` из рабочего каталога — у sled (`runner: pytest-own`, `workdir: backend`, `command: [uv, run, --frozen, pytest, …]`) это неверная команда. Миссия ревьювера (`role_prompt.py:139-142`) говорит «права не сужены: тесты, guard … запускай» — у внешнего проекта неверно.

## Требуется

1. Команда пульта для роли — проверка артефакта задачи тем же правилом, что `scripts/guard.py` у артели (`artel.py guard <id> [<файл>]` или иное имя — аналитик обосновывает), только читающая; добавляется в `_ROLE_ALLOWED_COMMANDS`. Доступна ролям артели и внешнего проекта.
2. Миссии ролей внешнего проекта (analyst, developer, spec_auditor) называют эту команду пульта вместо `scripts/guard.py`; у артели текст миссий не меняется ни на байт (или аналитик обосновывает замену и у артели — без смены смысла).
3. Пункт 5 миссии test_author у внешнего проекта: прогон долгоживущих файлов — командой пульта, исполняющей профиль (`plank-run`/`suite-run` по путям, если они это умеют; иначе — назвать в SPEC); не `python3 -m pytest` пульта.
4. Миссия ревьювера у внешнего проекта говорит, какие проверки доступны (команды пульта из белого списка), а не «права не сужены».
5. У артели белый список, миссии и поведение команд не меняются, кроме добавленной команды; зафиксировать тестами до правки.
6. Тесты детерминированы, без сети: роль (окружение роли) вызывает новую команду на своём артефакте — проверка проходит/отказывает с тем же текстом, что `scripts/guard.py`; миссии учебного внешнего проекта не содержат `scripts/guard.py` и `python3 -m pytest`, у артели — прежние.

Критерии приёмки:
- роль внешнего проекта проверяет свой артефакт командой пульта;
- миссии ролей внешнего проекта называют доступные им команды и команду прогона по профилю;
- у артели миссии прежние.

Зоны: `orchestrator/artel.py`, `orchestrator/role_prompt.py`, `tests/`.

Только чтение: `scripts/guard.py`, `orchestrator/providers/claude.py`, `orchestrator/plank_run.py`, `orchestrator/suite_run.py`, `orchestrator/project_profile.py`, `skills/`, `docs/backlog.md`. Правка вне зон — эскалация до SPEC.

Не входит: правка текстов скилов (`skills/coding-standards.md`, `skills/test-authoring.md`, `skills/spec-audit.md` — `python3 -m pytest tests/`, `config.PROTECTED_PATHS` вместо `no_paths`, регенерация карты) — отдельной задачей приложением к PLAN; окружение шага роли (PATH, uv, логи suite-run); Codex на внешних проектах.

Рамка: $30. Набор моделей — по умолчанию.

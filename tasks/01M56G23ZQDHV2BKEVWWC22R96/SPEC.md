# SPEC: Команда проверки артефакта для роли и миссии ролей внешнего проекта по профилю

## Контекст
Миссии analyst, developer и spec_auditor велят прогнать `scripts/guard.py`
на своём артефакте (`orchestrator/role_prompt.py:64`, `:120`, `:272`). У роли
внешнего проекта разрешён только `Bash(python3 <корень пульта>/orchestrator/artel.py:*)`
(`orchestrator/providers/claude.py:114-122`), а `scripts/guard.py` в рабочем
каталоге проекта нет: в шагах sled 01M55SKHZ293CCAK0N7T4H7ZMR «guard требует
подтверждения», и роль сдаёт формат вслепую. В белом списке команд роли
(`orchestrator/artel.py:1907-1910`, `_ROLE_ALLOWED_COMMANDS`) команды
проверки артефакта нет. Пункт 5 миссии test_author (`role_prompt.py:88-95`)
велит прогонять долгоживущие файлы командой `python3 -m pytest … -p timeout`
из рабочего каталога. У sled (`runner: pytest-own`, `workdir: backend`,
`command: [uv, run, --frozen, pytest, …]`) эта команда неверна, а
`plank-run` по путям долгоживущих файлов не умеет: `[файл]` принимается
только из планки (`orchestrator/plank_run.py:58-69`, отказ `:151-155`).
Миссия ревьювера (`role_prompt.py:141-145`) пишет «Права не сужены»; у
внешнего проекта это неверно.

Решение Оператора по батчу (ANSWER-1, 18.10.2026): вариант A, зона
расширена на `orchestrator/plank_run.py` — только приём и прогон путей
долгоживущих файлов задачи.

Имя новой команды — `guard`: она исполняет то же правило, что
`scripts/guard.py`, и одно имя у скрипта артели и у команды пульта не
оставляет роли двух названий одной проверки.

## Требования

1. В `orchestrator/artel.py` появляется команда `guard <id> [<файл>]`.
   Она проверяет артефакт задачи `<id>` из каталога документов задачи
   тем же правилом, что `scripts/guard.py` (функции модуля
   `scripts/guard.py`, без своей копии правил). `<файл>` — имя артефакта
   в каталоге документов (`SPEC.md`) или путь `tasks/<id>/<файл>`. Без
   `<файл>` проверяются все `*.md` артефакты каталога документов, которые
   проверил бы `scripts/guard.py`; записки шагов и паспорт задачи
   пропускаются так же, как в `scripts/guard.py --all`. Строки нарушений и
   код выхода — те же, что у `python3 scripts/guard.py` на том же
   содержимом: 0, когда нарушений нет, и ненулевой код, когда они есть.
2. Команда `guard` только читает: строка задачи, журнал, ссылки, ветка
   задачи и файлы каталога документов не меняются, lease не берётся.
   Команда внесена в `_ROLE_ALLOWED_COMMANDS` и в окружении роли не
   отказывается ни для задачи артели, ни для задачи внешнего проекта.
3. Миссии analyst, developer и spec_auditor задачи внешнего проекта
   называют команду пульта `python3 <корень пульта>/orchestrator/artel.py
   guard <id> <файл>` вместо `scripts/guard.py`; строки `scripts/guard.py`
   в них нет.
4. `plank-run <id> [<файл>]` в аргументе `[<файл>]` дополнительно принимает
   путь долгоживущего файла своей задачи: путь от корня рабочей копии
   кода, для которого `Profile.is_long_lived(<id>, путь)` профиля проекта
   задачи истинно, а файл есть в рабочей копии кода. Такой путь
   прогоняется тем же раннером профиля, что планка (`acceptance.run_plank`
   с профилем `pytest-own` проекта, иначе раннер пульта).
5. Путь, который не входит ни в планку, ни в шаблон долгоживущего файла
   своей задачи (долгоживущий файл другой задачи, путь вне каталога
   `long_lived_dir`, имя вне шаблона), `plank-run` отклоняет прежним
   отказом «файла … нет в планке», pytest при этом не запускается. Вызов
   без аргумента и вызов с файлом планки дают прежний исход: прежний
   набор целей прогона, прежние отказы, прежний код выхода.
6. Пункт 5 миссии test_author задачи внешнего проекта велит прогонять
   долгоживущие файлы задачи командой пульта `plank-run <id> <путь
   долгоживущего файла>`. Строки `python3 -m pytest` в миссии нет.
7. Миссия ревьювера задачи внешнего проекта перечисляет доступные роли
   проверки: команды пульта из белого списка ролей, не меньше `guard`,
   `plank-run` и `suite-run`. Строки «Права не сужены» в ней нет.
8. У задачи артели тексты миссий analyst, developer, spec_auditor,
   test_author и reviewer совпадают с текстами до правки байт в байт, а
   `_ROLE_ALLOWED_COMMANDS` отличается от прежнего ровно одной командой
   `guard`. Тесты, фиксирующие это, написаны и зелёные на коде до правки
   (ТЗ, требование 5).
9. Тесты детерминированы и не ходят в сеть.

## Критерии приёмки

AC-1. Команда `artel.py guard <id> SPEC.md`, вызванная в окружении роли
(`runner.role_env`) для задачи внешнего проекта и для задачи артели, на
артефакте без нарушений завершается кодом 0. На артефакте с нарушением она
завершается ненулевым кодом и выводит те же строки нарушений, что
`python3 scripts/guard.py` на файле того же содержимого.

AC-2. Без аргумента `<файл>` команда `guard <id>` проверяет все артефакты
`*.md` каталога документов задачи, кроме записок шагов и паспорта. Если
нарушение есть хотя бы в одном артефакте, код выхода ненулевой, и это
нарушение есть в выводе.

AC-3. После `guard <id>` (с файлом и без) строка задачи и её журнал в БД,
ссылка документов `refs/artifacts/<id>`, ветка задачи и содержимое каталога
документов не меняются, lease задачи не взят. `guard` входит в
`_ROLE_ALLOWED_COMMANDS`.

AC-4. Миссии analyst, developer и spec_auditor задачи учебного внешнего
проекта не содержат строки `scripts/guard.py` и содержат `artel.py guard`.

AC-5. Для задачи внешнего проекта с профилем `pytest-own` вызов `plank-run
<id> <путь долгоживущего файла этой задачи>` прогоняет этот файл командой
профиля (`command` профиля, `workdir` профиля). Код выхода `plank-run` —
код выхода этого прогона.

AC-6. Вызов `plank-run <id> <путь>` с долгоживущим файлом другой задачи или
с путём вне шаблона долгоживущего файла (другой каталог, имя вне шаблона)
отклоняется отказом «файла … нет в планке», и прогона нет. Вызов `plank-run
<id>` без аргумента и с файлом планки даёт прежний исход: тот же набор целей
прогона и тот же код выхода, что до правки.

AC-7. Пункт 5 миссии test_author задачи учебного внешнего проекта с профилем
называет `plank-run` для долгоживущих файлов и не содержит строки
`python3 -m pytest`.

AC-8. Миссия ревьювера задачи учебного внешнего проекта не содержит строки
«Права не сужены» и называет команды пульта `guard`, `plank-run` и
`suite-run`.

AC-9. Для задачи артели (`conn=None` и задача проекта артели в БД) тексты
миссий analyst, developer, spec_auditor, test_author и reviewer совпадают
байт в байт с эталонами, снятыми с кода до правки. Множество
`_ROLE_ALLOWED_COMMANDS` равно прежнему множеству с добавленной командой
`guard`.

## Оценка объёма и деление
Сработавший сигнал: `budget_usd` ≥ $30. Это рамка ТЗ Оператора: $30, та же
ставка, что в батче QUESTIONS. Других сигналов нет: зон 4, критериев 9.

Материал для решения Оператора — монолит. Нарезка по зонам дала бы
«команда `guard` + миссии guard/ревьювера» (`artel.py`, `role_prompt.py`) и
«`plank-run` по путям + пункт 5 test_author» (`plank_run.py`,
`role_prompt.py`). Но обе части правят `role_prompt.py`, то есть одну зону с
одним эталоном неизменности миссий артели (AC-9). Кроме того, части малы:
каждая меньше порога одной итерации ревью, и на два прохода конвейера
ушло бы больше рамки. Каждая часть по отдельности мержима, так что
промежуточное состояние работоспособно, а значит неразрезаемости
механики нет. Довод за монолит — цена и общая зона `role_prompt.py`.

# QUESTIONS: Команда проверки артефакта для роли и миссии ролей внешнего проекта по профилю

## Вопросы

Контекст для вопроса 1. Требование 3 ТЗ: прогон долгоживущих файлов в
пункте 5 миссии test_author внешнего проекта — «командой пульта,
исполняющей профиль (`plank-run`/`suite-run` по путям, если они это
умеют; иначе — назвать в SPEC)». Сверка по коду:

- `plank-run <id> [файл]` по путям долгоживущих файлов НЕ умеет: аргумент
  `[файл]` принимается только внутри планки `acceptance_tests/`
  (`orchestrator/plank_run.py:58-69`), иначе отказ «файла … нет в
  планке» (`plank_run.py:151-155`); прогон — одним целевым путём каталога
  планки (`plank_run.py:185-192`). Сам раннер профиля умеет несколько
  путей (`orchestrator/acceptance.py:1096` `run_plank(targets, cwd,
  profile)`), и гейт выхода из `tests_writing` гонит долгоживущие файлы
  вместе с планкой (`orchestrator/advance_gates/acceptance.py:405`,
  `extra=long_lived`).
- `suite-run <id>` по путям тоже не умеет: это полный набор проекта по
  профилю, фоном (`orchestrator/suite_run.py:1-33`); аргументы — только
  `--wait`/`--failed`.
- ТЗ относит `orchestrator/plank_run.py` и `orchestrator/suite_run.py` к
  «только чтение» и велит «правка вне зон — эскалация до SPEC». Зоны ТЗ:
  `orchestrator/artel.py`, `orchestrator/role_prompt.py`, `tests/`.

Значит, «команды, которая уже умеет», нет, а выбор того, что назвать в
SPEC, упирается в границу зон — это решение Оператора, не аналитика.
Остальная часть ТЗ (команда `guard`, миссии analyst/developer/
spec_auditor/reviewer, неизменность у артели) достаточна для SPEC;
ответ нужен только по пункту 5 test_author.

1. **Какой командой пульта миссия test_author внешнего проекта велит прогонять долгоживущие файлы задачи (пункт 5, требование 3 ТЗ)?**
   - A) Расширить зону задачи на `orchestrator/plank_run.py`: `plank-run <id> [файл]` дополнительно принимает пути долгоживущих файлов задачи (каталог `long_lived_dir` профиля, префикс задачи `long_lived_prefix(<id>)`) из рабочей копии кода и гонит их тем же профилем (`acceptance.run_plank`), без аргумента — планку вместе с долгоживущими файлами, как гейт выхода из `tests_writing`; миссия называет `plank-run`.
     - ломается: ничего у артели — новые формы аргумента, прежние вызовы `plank-run` дают прежний результат; у внешнего проекта `plank-run` без аргумента начинает гнать и долгоживущие файлы задачи.
     - ослабляется: ничего; отказ на чужой путь (`plank_run.py:151-155`) остаётся для путей вне планки и вне префикса задачи.
     - цена: +1 файл зоны (4 файла, 1 из них read-only по ТЗ снимается), ~+$5 к рамке ($30 укладывается).
     - чьё решение: Оператор (смена зон ТЗ).
   - B) Остаться в зонах ТЗ: новая логика целиком в `orchestrator/artel.py` — отдельная читающая команда (например `long-lived-run <id> [файл]`) в `_ROLE_ALLOWED_COMMANDS`, вызывающая `acceptance.run_plank` с профилем задачи по путям долгоживущих файлов; миссия называет её.
     - ломается: ничего у артели; в белом списке ролей две новые команды вместо одной.
     - ослабляется: ничего; но логика прогона дублирует выбор профиля и рабочей копии из `plank_run.py:123-192` в диспетчере CLI — второе место, которое придётся держать в согласии.
     - цена: в рамке $30; долг — дубликат узла выкладки/выбора профиля.
     - чьё решение: Оператор (вторая новая команда сверх ТЗ «добавляется команда проверки»).
   - C) Без новой команды прогона: миссия test_author внешнего проекта называет `suite-run <id>` (полный набор проекта по профилю, фоном, отчёт `--wait`) как способ прогнать свои долгоживущие файлы, а `plank-run` — для планки; SPEC фиксирует, что прогона по путям у роли нет.
     - ломается: ничего в коде; test_author тратит полный прогон набора проекта ради своих файлов (минуты, замок полных прогонов машины общий с гейтами — `suite_run.py:21-23`).
     - ослабляется: адресность проверки — отчёт `suite-run` даёт все падения набора, свои файлы роль ищет в нём сама.
     - цена: минимальная по коду (только `role_prompt.py`); дороже по времени шага test_author.
     - чьё решение: Оператор.
   - дефолт: A — единственный вариант, где миссия называет одну команду, исполняющую профиль по путям, без дубля логики; при молчании Оператора зона задачи расширяется на `orchestrator/plank_run.py` только для этого пункта.

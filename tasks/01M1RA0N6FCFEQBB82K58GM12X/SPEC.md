# SPEC: Гейт ёмкости diff не считает артефакты задачи в кодовой ветке

## Контекст

Гейт ёмкости на переходе `in_dev -> review` (`fsm_advance._capacity_gate_refuses`)
меряет `git diff main...HEAD` целиком, включая копию `tasks/<id>/` (SPEC,
PLAN, залоченную планку acceptance_tests/), которая материализуется в
кодовой ветке. У канарейки ч.1 планка дала 175 КБ при коде 101–114 КБ:
суммарный diff 276–289 КБ при потолке 262 144 байт, переход дважды
проводился мостом Оператора. Планка не предмет ревью-диффа: ревьювер
получает артефакты отдельными компонентами пакета из артефактной ветки
(`review.review_package`), поэтому их присутствие в diff-мере — не
сигнал, а шум, раздувающий и гейт ёмкости, и инкрементальный дифф
ревью-пакета (регрессия №10).

## Требования

1. Мера гейта ёмкости (`fsm_advance._capacity_gate_refuses`) исключает
   `tasks/<id>/` (артефакты и `acceptance_tests/`) из diff: `git diff
   main...HEAD -- . ':!tasks/'` либо эквивалент через существующий
   `review.git_diff_part`; порог `REVIEW_SNAPSHOT_DIFF_MAX_BYTES` не
   меняется.
2. Инкрементальный и полный diff ревью-пакета (`review.git_diff_part`,
   вызовы из `review.review_package`, регрессия №10) тем же правилом не
   несёт `tasks/<id>/` — ни в `--stat`, ни в самом diff: артефакты уже
   идут в пакет своими компонентами, дубль в diff только раздувает
   контекст.
3. Отказ гейта называет две цифры: размер diff кода (без `tasks/<id>/`)
   и размер исключённых артефактов (diff внутри `tasks/<id>/`), чтобы
   Оператор видел, что именно превысило потолок.

## Критерии приёмки

AC-1. Мера гейта ёмкости на переходе `in_dev -> review` считает размер
diff БЕЗ `tasks/<id>/` (артефакты и `acceptance_tests/`); порог
`REVIEW_SNAPSHOT_DIFF_MAX_BYTES` остаётся прежним.

AC-2. Диф ревью-пакета (`review.git_diff_part`/`review.review_package`,
и полный, и инкрементальный) тем же правилом не несёт содержимого
`tasks/<id>/` — ни в `--stat`, ни в самом diff.

AC-3. Отказ гейта ёмкости (журнал и печать) называет две цифры: размер
diff кода (без `tasks/<id>/`) и размер diff, приходящегося на
`tasks/<id>/` (исключённые артефакты).

AC-4. Тест: ветка, где diff кода ниже потолка, а diff артефактов
(планка/SPEC/PLAN в `tasks/<id>/`) достаточно велик, чтобы суммарный
(неисключённый) diff превысил потолок, — переход `in_dev -> review`
гейт ёмкости не отклоняет.

AC-5. Тест: ветка, где diff кода сам по себе выше потолка, — переход
отклонён (поведение не изменилось относительно текущего).

AC-6. Тест: diff ревью-пакета (`review.review_package`/
`review.git_diff_part`) не содержит строк из `tasks/<task_id>/` ни в
стат-списке, ни в самом diff.

AC-7. Существующие тесты гейта ёмкости и ревью-пакета
(01M1GCN1FPSC1A6WK9WD1Q1V8X, T029, регрессия №10) остаются зелёными без
ослабления.

## Не входит

- Смена потолка `REVIEW_SNAPSHOT_DIFF_MAX_BYTES`.
- Исключение из diff-меры путей, кроме `tasks/<id>/`.

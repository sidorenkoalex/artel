# ТЗ: CR-2 ревизии №23 — тихая финализация соединения БД из чужого потока

Источник: docs/audits/code-revision-2026-09-02.md, находка CR-2
(наследник мотивации CR-3 прошлой ревизии: «шум хоронит настоящие
предупреждения»). Деструктор автозакрывающегося соединения
(orchestrator/store.py, класс _AutoClosingConnection, наследие T090)
бросает sqlite3.ProgrammingError, когда сборщик мусора добивает
объект из другого потока: 28 строк «Exception ignored …
SQLite objects created in a thread…» за прогон полного набора.
Оператор уже потратил внимание на такую строку в логе A7 (03.09).

Требуется:
1. Финализация соединения не поднимает исключений: закрытие в
   деструкторе обёрнуто узким перехватом sqlite3.ProgrammingError
   (чужой поток) — закрытие из чужого потока невозможно по
   ограничению sqlite3 и штатно остаётся сборщику мусора; остальные
   исключения не глушатся.
2. Поведение T090 сохранено: закрытие из СВОЕГО потока работает как
   сейчас (ResourceWarning не возвращаются — их ловит существующий
   тест).
3. Тест: прогон, воспроизводящий финализацию из чужого потока
   (создать соединение в одном потоке, отпустить ссылки и добить gc
   в другом), не печатает «Exception ignored» в stderr; существующие
   тесты зелёные.

Зоны: orchestrator/store.py (одна функция), tests/.
ЗАПУСКАТЬ СТРОГО ПОСЛЕ мержа A7 (01M1H224X5…) — store.py в её зоне.

Не входит: ревизия потоковой модели соединений; изменение механики
автозакрытия T090.

Рамка: $10.

# SPEC: Гейт зон признаёт долгоживущие файлы задачи внешнего проекта по профилю

## Контекст
Гейт зон (`orchestrator/advance_gates/zones.py::_zones_gate`, строки
274-276) добавляет к заявленным зонам задачи `config.COMMON_ZONES` только
у артели (`repo_context.is_artel`); у артели туда входит `tests/`, и
долгоживущий файл задачи `tests/test_<id>_<имя>.py` всегда в зоне. У
внешнего проекта общих зон нет: долгоживущий файл задачи в
`long_lived_dir` профиля (у sled — `backend/tests/test_<id>_<имя>.py`)
отказывается как «вне заявленных zones», если каталог не вписан в зоны
задачи. Обход сегодня — вписывать `long_lived_dir` в зоны целиком
(ТЗ задачи sled 01M55SKHZ293CCAK0N7T4H7ZMR вписывает `backend/tests/`),
что даёт разработчику зону на все тесты проекта. Чекпоинт test_author
после 01M551W0TFCT2XRQ71XFXJDKB9 уже признаёт свои долгоживущие файлы
по каталогу и шаблону профиля (`project_profile.Profile.is_long_lived`).

## Требования

1. Гейт зон у задачи внешнего проекта считает зоной собственные
   долгоживущие файлы задачи — пути, для которых
   `Profile.is_long_lived(task_id, path)` истинно (каталог `long_lived_dir`
   и шаблон `long_lived_name` с id задачи). Профиль берётся тем же
   источником, что у гейта выхода из `tests_writing`
   (`project_profile.decide` по проекту задачи). Прочие пути
   `long_lived_dir` (без id этой задачи в имени по шаблону) в зону не
   входят и отказываются как прежде. Признание — по полному совпадению
   с шаблоном имени файла (`is_long_lived`), не по префиксу пути
   (`long_lived_prefix`): путь, начинающийся с префикса своего файла, но
   не совпадающий с шаблоном (например
   `backend/tests/test_<id>_x/conftest.py`, `backend/tests/test_<id>_x.json`),
   в зону не входит. `config.COMMON_ZONES` не меняется.
   Решение Оператора 18.10 (паритет с артелью): зоной признаётся и НОВЫЙ
   файл по шаблону своей задачи в `long_lived_dir`, добавленный ролью
   developer (не только файлы перечня долгоживущих файлов test_author), —
   так же, как у артели такой файл в `tests/` в зоне через
   `config.COMMON_ZONES`.
2. У задачи внешнего проекта: отказ определения профиля
   (`Decision.refusal`) — гейт зон не расширяет зону (сегодняшнее
   поведение); если дифф несёт пути вне зон, текст отказа гейта зон
   называет причину отказа профиля. У внешнего проекта без
   `test_profile` (`Decision.skip`) расширения нет — поведение
   сегодняшнее (в том числе нет фолбэка на каталог и шаблон по
   умолчанию). Требование 2 к артели не относится.
3. У артели поведение гейта зон и тексты его отказов (действие, detail,
   hint) не меняются — в том числе когда `test_profile` артели не
   прочитан (определение профиля отказывает). Это фиксируется тестами
   до правки кода.
4. Сверка других мест, где зоны задачи сверяются с диффом (требование 4
   ТЗ), — результат ниже; правка вне зон задачи не требуется:
   - чекпоинт (`orchestrator/checkpoint.py::_zone_paths`/
     `_stray_staged_paths`, строки 1564-1603; `_commit_worktree_change`,
     1770-1773): свои долгоживущие файлы test_author по профилю уже
     передаются фильтру как `own_zones` (`_test_author_checkpoint`,
     строки 448-454), их удаление test_author не откатывается по профилю
     (`_role_may_delete`, строка 528) — та же правка не нужна;
   - гейт мержа (`orchestrator/fsm_merge_gate.py`): зоны задачи с диффом
     не сверяет (общий с гейтом зон только текст отказа защищённого пути,
     строка 71) — правка не нужна;
   - ревью-пакет (`orchestrator/review.py`): зоны задачи с диффом не
     сверяет — правка не нужна.
5. Тесты детерминированы и без сети: учебный внешний проект с
   `long_lived_dir: backend/tests`, задача с зонами `backend/src/`.

## Критерии приёмки

AC-1. У артели гейт зон прежний: для задачи артели с одинаковым диффом
действие, detail и hint отказа гейта зон (и отсутствие отказа) до и после
правки совпадают — в том числе для пути под `config.COMMON_ZONES` вне
заявленных зон (отказа нет) и для пути вне заявленных зон и
`COMMON_ZONES` (прежний отказ «переход отклонён: гейт зон» с прежним
текстом).

AC-2. Учебный внешний проект с профилем `long_lived_dir: backend/tests`,
задача с зонами `backend/src/` (без `backend/tests/`): дифф из файла
`backend/src/…` и своего долгоживущего файла задачи
`backend/tests/test_<id>_x.py` (имя по шаблону профиля с id задачи)
проходит гейт зон — отказа «переход отклонён: гейт зон» нет.

AC-3. Тот же учебный внешний проект и те же зоны: дифф с файлом
`backend/tests/test_other.py` (без id задачи) — отказ «переход отклонён:
гейт зон», detail называет `backend/tests/test_other.py`.

AC-4. Тот же учебный внешний проект и те же зоны: долгоживущий файл с id
ДРУГОЙ задачи (`backend/tests/test_<чужой id>_x.py`) — отказ «переход
отклонён: гейт зон», detail называет этот файл.

AC-5. Внешний проект, у которого определение профиля отказывает
(`test_profile` не прочитан): дифф со своим долгоживущим файлом задачи в
каталоге вне зон — отказ гейта зон (зона не расширена), и текст отказа
содержит причину отказа профиля.

AC-6. Внешний проект без `test_profile`, задача с зонами `backend/src/`:
дифф с файлом `tests/test_<id>_x.py` (каталог и шаблон по умолчанию, id
этой задачи) — отказ «переход отклонён: гейт зон», detail называет
`tests/test_<id>_x.py` (расширения нет, фолбэка на профиль по умолчанию
нет).

AC-7. Учебный внешний проект из AC-2 и те же зоны: дифф с путём
`backend/tests/test_<id>_x/conftest.py` (и отдельно — с
`backend/tests/test_<id>_x.json`), где `<id>` — id этой задачи, — отказ
«переход отклонён: гейт зон», detail называет этот путь (сверка по
шаблону имени файла, не по префиксу).

AC-8. Задача артели, у которой определение профиля отказывает
(`test_profile` артели не прочитан): для одинакового диффа действие,
detail и hint отказа гейта зон (и отсутствие отказа) совпадают с
поведением до правки — причина отказа профиля в текст гейта зон не
добавляется.

## Оценка объёма и деление

Сработавшие сигналы (по guard): число затрагиваемых модулей/файлов и
отсутствие прогноза диффа. Число модулей набирают пути, названные в тексте
только для чтения (требование 4, «Не входит», «Материалы»); правятся лишь
`orchestrator/advance_gates/zones.py` и новые/дополненные файлы `tests/`.

Прогноз диффа: 12 КиБ.

Обоснование монолита: правка — одно условие в одной функции
(`_zones_gate`) плюс её тесты; резать нечего — тесты фиксации поведения
артели (требование 3) и проверки внешнего проекта бьют в ту же функцию, а
часть «код без тестов» или «тесты без кода» по отдельности не дают
проверяемого результата. Решение утверждает Оператор на гейте SPEC.

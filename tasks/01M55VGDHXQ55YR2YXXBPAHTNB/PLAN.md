# PLAN: Гейт зон признаёт долгоживущие файлы задачи внешнего проекта по профилю

## Подход
Одна правка в `orchestrator/advance_gates/zones.py::_zones_gate`, сразу
после вычисления `out_of_zone` (строки 274-276): у задачи НЕ артели
(`not repo_context.is_artel(ctx)`) и при непустом `out_of_zone` гейт берёт
`project_profile.decide(target)` — тот же источник, что у гейта выхода из
`tests_writing`, — и:
- `Decision.profile` — из `out_of_zone` убираются пути, для которых
  `profile.is_long_lived(task_id, path)` истинно (полное совпадение с
  шаблоном имени, не префикс `long_lived_prefix`); перечень test_author не
  читается — новый файл по шаблону своей задачи, добавленный developer,
  тоже в зоне (решение Оператора 18.10);
- `Decision.refusal` — зона не расширяется, причина отказа профиля
  дописывается к detail отказа гейта зон (`… — профиль тестов не
  определён, свои долгоживущие файлы зоной не признаны: <причина>`);
- `Decision.skip` — ничего (сегодняшнее поведение, без фолбэка на
  каталог/шаблон по умолчанию).
У артели ветка не выполняется вовсе: `decide` не зовётся, тексты и исходы
байт-в-байт прежние (требования 3, AC-1, AC-8). `config.COMMON_ZONES` не
меняется. Профиль запрашивается только если есть пути вне зон — у
прошедшего дифф гейт не трогает `targets.yaml` лишний раз.

## Влияние на систему
Гейт зон у внешнего проекта становится мягче ровно на пути
`long_lived_dir/<шаблон с id задачи>` — то же, что у артели даёт
`COMMON_ZONES` (`tests/`), и уже признаётся чекпоинтом test_author. Чужие
файлы каталога, файлы чужих задач и файлы не по шаблону отказываются как
прежде. Защищённые пути проверяются раньше и не затронуты. При отказе
профиля поведение fail-closed (зона не расширяется) + причина в тексте.
Откат — revert одного коммита.

## Риски
- `decide` читает `targets.yaml`; исключение там уже обработано внутри
  `repo_context.profile_of` (исход PROFILE_UNREAD), гейт его не ловит
  отдельно.

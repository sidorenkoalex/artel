## Пути обхода гейтов

- **Номер `#1`.** Два теста `x` в одном файле дают `…::x` и `…::x#2` —
  находка есть. Одиночный тест с именем `x#2` теперь получает `…::x#2#1` и
  находкой не считается: это ровно цель требования 4, не обход. Тест с
  именем, оканчивающимся на `#1`, повтором не притворится — номер берётся с
  конца идентификатора, а `test_id` всегда дописывает свой суффикс. Обхода не
  нашёл.
- **Класс ошибки по `constructor`.** Тест вправе объявить свой
  `class AssertionError extends Error {}` и бросить его: по правилу г) это
  засчитается провалом проверки без настоящего `expect`. Класс не новый:
  сейчас то же даёт `err.name = "AssertionError"`, а `--expect.requireAssertions`
  остаётся. Правило г) поверхность подделки не расширяет по существу, это не
  отклонение. Отмечаю для ревью тестов sled: распознавать подделку по имени
  класса пульт не может.
- **Правила б)/в) переводят тест в `fail`/`ERROR`.** Записать зелёным то, что
  упало, через них нельзя: оба правила дают только `ERROR`, а явный
  `skip`/`todo` остаётся пропуском. Обхода гейтов неослабления нет.
- **Буквальное исполнение без сужения зон** (п. 1): по SPEC разработчик может
  законно трогать любые функции шести файлов. Это путь обойти смысл
  ограничений ТЗ, а не гейт.
- **AC-15 на пути приёмки** (п. 7): буквально исполненный критерий оставляет
  сбор `repeats` в `tests_writing.py` непроверенным.

1. Потеряно «Ограничение зон по смыслу» ТЗ (SPEC.md:7, SPEC.md:348-380) —
   вернуть перечень мест на файл зоны.
2. Таблица ожидаемых записей подана как наблюдённая (SPEC.md:102); три
   выведенные строки ТЗ не помечены.
3. Сигнал деления «`budget_usd` ≥ порога» не назван (SPEC.md:324-327;
   `scripts/guard.py:5450-5452`).
4. ADR-0026 уже поправлен (e503fe10) — пункт «Не входит» устарел
   (SPEC.md:356), сама граница верна.
5. Обоснование «других правок не нужно» (SPEC.md:319-321) опирается на
   прототип без правок гейтов; вывод верен по
   `tests/test_01m5aqh8m2dkbv30nby86j34a7_fail_to_pass.py:92,1061`.
6. Правило г) для записи хука и записи уровня файла (SPEC.md:76) не держит ни
   один AC (AC-6, AC-10 — классы с одинаковыми полями).
7. AC-15 (SPEC.md:300-302) не называет гейт; сбор `repeats`
   (`orchestrator/advance_gates/tests_writing.py:1185-1188`) может остаться
   без проверки.
8. Порядок `beforeEach` → `afterEach` (SPEC.md:58) не держит AC-5; приоритет
   правил б)/д) (SPEC.md:62, SPEC.md:79) не задан.
9. `node` — неявная зависимость полного набора вне `stack.DECLARED_TOOLS`
   (`orchestrator/runner.py:1103`, `:942-955`); тест падает, а не
   пропускается (SPEC.md:166-171).
10. Мандат: не назван маркер «Ослабление тестов разрешено:», а матрица,
    которую `answer` потребует (`orchestrator/advance_gates/mandate.py:664-666`),
    в SPEC отсутствует (SPEC.md:305); строки матрицы и строка мандата — в
    разделе «Матрица неослабления» выше.

Фактических ошибок о коде нет; без ответа Оператора вердикт выносится, поэтому
эскалации нет.

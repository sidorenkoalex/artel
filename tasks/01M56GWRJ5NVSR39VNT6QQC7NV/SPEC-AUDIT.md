## Пути обхода гейтов
1. **Переименование чужого долгоживущего файла в своё имя.** `_stray_staged_paths` читает `git diff --cached --name-only` (`checkpoint.py:1595`) без `--no-renames`: при умолчании git `diff.renames=true` переименование `backend/tests/test_other.py → backend/tests/test_<id>_x.py` даёт одну строку — имя назначения. Сегодня у внешнего проекта назначение постороннее → снимается со стейджа и `restore_out_of_bounds_deletions` (вызов только при `stray`, `checkpoint.py:233-234, 897-898`) восстанавливает `test_other.py`. После правки назначение — «своя зона», `stray` пуст, восстановление не вызывается, и удаление чужого `test_other.py` уходит в коммит пульта. Это нарушает тр.4 («прочие пути `long_lived_dir` в зону не входят — во всех местах») буквально выполненным SPEC; AC-2/AC-5 проверяют только раздельные добавление и удаление. (Механизм name-only — дефект и для переименований из-вне в заявленные зоны сегодня, но этой задачей он впервые открывается для каталога тестов внешнего проекта; удаление чужого теста дальше ловит гейт неослабления, однако тр.4 говорит о чекпоинте.) `pult_commit_failed_paths` (`:1698`) тоже берёт только назначение `-> `.
2. **Тесты только на `commit_success_checkpoint` для чужого файла.** AC-2 и AC-6 проверяют один путь; реализация, расширяющая зону по каталогу только в `_wip_checkpoint` (или игнорирующая отказ профиля только там), пройдёт все AC. Тр.4 и тр.6 требуют «во всех местах»; риск снижен, если расширение сделано в общем `_commit_worktree_change`, но SPEC этого не требует.

  гейт зон» и «прочие пути `long_lived_dir` не входят». Условное «и чекпоинт

  ТЗ п.3 → тр.5, AC-5 (зелёные и до правки, и после). ТЗ п.4 → тр.6, AC-1/AC-2.

## Матрица неослабления
Задача расширяет набор путей, которые фильтр коммита пульта считает зоной.
Это сужение проверки «посторонний путь» для одного класса путей, и его прямо
требует ТЗ (паритет с гейтом зон). Ожидания существующих тестов не меняются,
поэтому раздел «Меняемое поведение» в SPEC справедливо отсутствует. Тестов,
которые сегодня утверждали бы снятие со стейджа `long_lived_dir`-файла внешнего
проекта, нет: grep `backend/tests|long_lived_dir` по
`tests/test_checkpoint_zone_filter.py`, `tests/test_role_commit_by_pult.py`,
`tests/test_timeout_checkpoint.py` пуст.

| Что меняется | Какое свойство сейчас держит (тест, гейт, лимит, проверка — файл:строка) | Остаётся ли свойство после изменения | Чем покрыто после (тест файл:строка) или «не покрыто» | Решение |
|---|---|---|---|---|
| Фильтр посторонних путей WIP-чекпоинта developer (`checkpoint.py:1770-1785`) | путь вне зон снимается со стейджа и журналится — `tests/test_checkpoint_zone_filter.py` | да, кроме своих `is_long_lived`-файлов внешнего проекта (сознательное расширение по ТЗ) | AC-2 (чужой файл каталога), AC-5 (артель) | принять |
| Отказ подтяжки на постороннем (`refuse_on_stray`, `checkpoint.py:1782-1784`; `pull.py:523-531`) | `tests/test_timeout_checkpoint.py::CommitPullCheckpointTest` | да | AC-3 (с `test_other.py` — отказ целиком), AC-5 | принять |
| Отказ профиля — без расширения | новое свойство | — | AC-4 (частично, О-4) | принять |
| `pult_commit_failed_paths` (`checkpoint.py:1694-1707`) — что считается результатом шага после отказа git | считает по `_zone_paths` без профиля | меняется неявно: свой файл при отказе git останется «посторонним» и не назовётся | не покрыто (О-2) | вопрос Оператору |

## Пути обхода гейтов
- **П-1 (О-1).** SPEC можно выполнить буквально, правкой только ветки
  `_wip_checkpoint:230-238` и `commit_pull_checkpoint`: все AC проходят тестами
  через `commit_timeout_checkpoint`, а штатный успешный шаг
  (`commit_success_checkpoint:895`) по-прежнему не коммитит свой файл.
- **П-2 (мелкое, класс существовал и раньше).** Фильтр читает
  `git diff --cached --name-only` (`checkpoint.py:1595`). При обнаружении
  переименований (по умолчанию в git) переименование
  `backend/tests/test_other.py` → `backend/tests/test_<id>_x.py` показывается
  одним путём назначения, и тот теперь в зоне. Чужой тест каталога уйдёт из
  дерева коммитом пульта, хотя тр.2 говорит, что чужие пути `long_lived_dir`
  в зону не входят. Тот же класс уже есть для переименования из-вне-зон в
  зону, а удаление теста ловит гейт неослабления тестов (по
  `weakening_scope` профиля). AC-2 переименование не покрывает. Отмечаю для
  Оператора, отклонением SPEC не считаю.

## Вердикт
**concerns.** SPEC верно переносит ТЗ, факты о коде подтверждены, зоны
достаточны. Решить на гейте:

1. **О-1 (существенное):** `commit_success_checkpoint`
   (`orchestrator/checkpoint.py:828-911`, вызов `:895-896`; вызывается из
   `orchestrator/runner.py:1931`) — основной путь коммита пультом за
   developer — в SPEC не назван (SPEC «Требования» п.1, «Материалы» «~:229»).
   AC-1 не требует проверки этим путём. Предлагаю дописать в тр.1/AC-1:
   «включая чекпоинт штатного завершения шага (`commit_success_checkpoint`)»,
   либо явно вынести его в «Не входит», если Оператор так решит.
2. **О-2 (мелкое):** `pult_commit_failed_paths`
   (`orchestrator/checkpoint.py:1694-1707`) считает по `_zone_paths` без
   профиля. Если git откажет коммиту своего долгоживущего файла внешнего
   проекта, файл не будет назван незакоммиченным результатом шага.
   Расширять ли туда — решение Оператора (ТЗ не требует).
3. **О-3 (мелкое):** удаление developer своего долгоживущего файла внешнего
   проекта будет восстановлено `restore_out_of_bounds_deletions`
   (`checkpoint.py:525-526`, зоны без профиля), хотя добавление того же файла
   теперь коммитится. SPEC сознательно оставил это вне задачи («Не входит»),
   асимметрию фиксирую.
4. **О-4 (мелкое):** тр.4/AC-4 не различают исходы `decide` — `refusal`
   (`project_profile.py:143-152`) и `skip` (`:158-159`). AC-4 стоит уточнить:
   какой исход проверяется (лучше оба).
5. **П-2 (наблюдение):** переименование чужого теста каталога в своё имя
   проходит фильтр (`checkpoint.py:1595`, `--name-only` с обнаружением
   переименований). Это класс, существовавший и раньше, его закрывает гейт
   неослабления тестов.

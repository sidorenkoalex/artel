# PLAN: G3б-1 — заменяемые тесты в SPEC, сверка на гейте планки, запреты планки и amend-tests для файлов с меткой

## Подход

Одна задача — монолит, как в SPEC (граница — решение Оператора 21.10).
Новое поведение включается только непустым разделом «## Заменяемые тесты»
и правилом планки не по умолчанию; у артели и `test_profile` без раздела
все пути прежние побайтно (AC-20).

- **guard (`scripts/guard.py`).** Раздел — по образцу «Меняемое
  поведение»: `REPLACED_TESTS_SECTION`, `ReplacedTest` (поле `line` —
  разобранная строка пункта, она же деталь журнала),
  `parse_replaced_test_line` (форма одной строки), `replaced_test_items`
  (весь раздел: пустые строки пропускаются, заглушка `<…>` — пустой
  раздел, номер критерия сверяется с «Критерии приёмки», повтор),
  `replaced_tests_errors` в `_content_errors` — одна функция на CLI и
  `spec_writing -> spec_gate`. Форма идентификатора — `is_test_id_form`,
  тот же разбор `partition`, что `project_profile.parse_test_id` (guard не
  импортирует профиль: обратный импорт — цикл). Запреты: `_BAN_TABLE` +
  `_table_arguments` (цепочка `….each` и шаблонный литерал, аргументы —
  первая пара скобок после литерала), `suite` с меткой — тем же условием,
  что `describe`; `_test_calls` читает имя после `.each\`…\``. Общий
  предикат файла с меткой первого уровня — `is_labelled_plank_test`, его
  зовут `acceptance_test_files` и `amend.py`.
- **spec_audit.signals** — сигнал сразу после «Меняемое поведение» по
  `section_body(...).strip()`.
- **mandate.py** — `REPLACED_TESTS_ACTION`, `approved_replacements` (последняя
  запись, деталь разбирается `guard.parse_replaced_test_line`; отзыв —
  пустая деталь).
- **fsm.py** — `_replaced_tests_declaration` рядом с
  `_behavior_change_declaration`; в `_approve_spec_gate` вызов сразу после
  сверки «Меняемое поведение» тем же текстом SPEC; записи DECLARED и
  REPLACED пишутся только после обеих сверок. Порядок проверок —
  требование 2 (форма → отказ решения профиля → граница/`skip` → компонент →
  маски `tests` → голова `main` и файл → `matrix_refusals(..., test_ids=…)`).
  Канарейка — ни сверки, ни записи; раздела нет при прежней записи — отзыв.
- **refusal_classes / tests_writing** — `REPLACEMENT_REFUSAL_ACTION`
  («чинит роль»); сверка в `_tests_writing_fail_to_pass_gate` сразу после
  `_spec_anchor_check` по `_criterion_numbers(covered)`, деталь — строка на
  нарушение. Импорты — внутри функции (зона ограничена функцией).
- **amend.py** — `LABELLED_REFUSAL` и `_refuse_labelled` сняты. При правиле
  не по умолчанию: группа 2 — `_rule_plank_errors` (состав
  `tests_writing.py:373–389`, файлы `acceptance_test_files(tdir, rule)` /
  `_snapshot_plank_files` для `--from-branch`), без условия
  `plank_has_group_lines`; группа 3 — `_labelled_long_lived_errors` (состав
  `tests_writing.py:500–512` + сверка удаления по `plank_test_names`) при
  `long_lived_rule` не `None`, иначе прежний `_long_lived_errors`. В
  `--from-branch` статика долгоживущих файлов с меткой — при каждом вызове с
  непустым перечнем, сбор и прогон — только при расхождении
  (`_check_code_head_long_lived(..., static=False)`). Трассируемость — по
  правилу: долгоживущие файлы передаются парами (путь, текст) при правиле не
  по умолчанию (`_trace_sources`), как на выходе из `tests_writing`
  (`fsm.py:656`), иначе текстами, как прежде. Маркер красноты упавшего
  долгоживущего файла — с `rule` (у правила по умолчанию меток нет, разбор
  прежний).
- **Тесты.** Долгоживущие файлы задачи (`tests/test_01m5gxzk2wtz89axq7qy2rjd9r_*.py`)
  покрывают AC-1..AC-14, 16..20, 23..25 и не правились. Три метода
  мандата ANSWER-1 переписаны на проход (AC-21) в пределах условий 1–5.

Оценка бюджета SPEC не пересматривается.

## Влияние на систему

- Гейты не ослабляются: новое — дополнительные отказы (approve, выход из
  `tests_writing`, amend-tests). Единственное снятое — временный отказ
  `LABELLED_REFUSAL`; вместо него `amend-tests` исполняет над файлами с
  меткой те же проверки, что выход из `tests_writing` (AC-16..AC-19, AC-23).
  Три теста, закреплявшие отказ, переписаны по мандату ANSWER-1 (условия
  1–5): прочие методы, `LabelledSandbox`, `CarryOverSandbox`,
  `FailToPassSandbox` и значения констант `AMEND_REFUSAL` не тронуты,
  константы читаются только в `assertNotIn`.
- Правило по умолчанию (артель, `test_profile`): в `amend.py` ветвление
  `_by_rule(rule)` оставляет прежние вызовы; маркер красноты с `rule` по
  умолчанию даёт тот же разбор (меток нет). `_approve_spec_gate` без раздела
  не печатает и не пишет ничего нового (AC-20).
- Прежние находки запретов и разбор файлов без метки не меняются: текст
  находки `describe` прежний, `_BAN_CALL` не тронут, шаблонная таблица —
  отдельный проход (AC-15).
- Откат — revert merge-коммита; схема БД не меняется (новое действие
  журнала — строка в `steps`).
- merge_after не меняется.

## Предложения системе

- Сценарий роли в Bash не может писать временный файл вне рабочего каталога
  (`/tmp` — подтверждение) и не принимает heredoc: диф приложения пришлось
  набирать руками и проверять `git apply --check` со stdin. Не хватает
  команды пульта «собери диф приложения по правке файла» (класс: обход
  вместо команды пульта).

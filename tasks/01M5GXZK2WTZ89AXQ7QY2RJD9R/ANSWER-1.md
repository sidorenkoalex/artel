# ANSWER-1: ответ Оператора

## Ответы

Мандат Оператора на гейте SPEC задачи 01M5GXZK2WTZ89AXQ7QY2RJD9R (G3б-1), требование 8 SPEC. Требование 6 снимает временный отказ `LABELLED_REFUSAL` (`orchestrator/amend.py:239`); три метода ниже закрепляют этот отказ и по требованию переписываются на новое ожидание. Методы не удаляются: каждый прежний случай остаётся и проверяет проход через проверки требования 6. Свойство «файлы с меткой не обходят проверки через amend-tests» после правки держат новые тесты критериев AC-16–AC-19 (условия — в матрице ниже).

Ослабление тестов разрешено: tests/test_01m5aa5ts90rdj2afxb882wtpd_labelled_gates.py::Ac11AmendLabelledRefusalTest::test_ac11_worktree_mode_refuses_labelled_files, tests/test_01m5aa5ts90rdj2afxb882wtpd_labelled_gates.py::Ac11AmendLabelledRefusalTest::test_ac11_from_branch_mode_refuses_labelled_files, tests/test_01m5aqh8m2dkbv30nby86j34a7_fail_to_pass.py::Ac25AmendAndTemplateTest::test_ac25_amend_md_only_plank_labelled_long_lived_refused

Константы `AMEND_REFUSAL` (`tests/test_01m5aa5ts90rdj2afxb882wtpd_labelled_gates.py:1371`, `tests/test_01m5aqh8m2dkbv30nby86j34a7_fail_to_pass.py:2362`) элементами мандата не названы сознательно. Гейт неослабления сравнивает только тестовые методы (`scripts/guard.py:1115`, `qualified_test_methods`; находки — `orchestrator/advance_gates/test_integrity.py:442–509`), а голое имя модульной константы в утверждении остаётся в нормальной форме именем, без значения (`scripts/guard.py:1609–1621`, `_AssertionNormalizer`). Значит, правку присваивания на уровне модуля гейт не видит вовсе, а элемент «путь файла» покрыл бы любую находку обоих файлов целиком и расширил бы мандат далеко за три метода. Смена утверждений, которые употребляют константу, — находка метода, и её покрывают три элемента выше. Поэтому для констант действует условие из матрицы: значение не меняется; константа либо удаляется вместе с последним употреблением, либо остаётся побайтно прежней и употребляется только в `assertNotIn`.

Обязательные условия мандата (сверяются с SPEC круга 2 поштучно):
1. Номера критериев AC-16–AC-21 SPEC сохраняются; новые критерии получают номера с AC-23.
2. AC-17 в обоих путях (рабочая копия и `--from-branch`) несёт, кроме пяти нынешних случаев, ещё два: «изменён только `.md` планки, неизменённый файл планки с меткой несёт запрет — отказ» и «удалён единственный файл планки с меткой, покрывавший критерий, — отказ трассируемости». Среди случаев долгоживущего файла есть планка только из `.md`.
3. Тесты AC-17 и AC-18 при отказе сверяют все четыре величины: голову ветки документов, голову кодовой ветки, `tests_locked_sha` и число записей «правка планки» (как `state_of`, `tests/test_01m5aa5ts90rdj2afxb882wtpd_labelled_gates.py:1406–1412`), а также префикс текста отказа по решению А3.
4. Переписанные методы сохраняют все прежние случаи (четыре, два и один) и проверяют в каждом новое ожидание AC-21 круга 2: вывод без `AMEND_REFUSAL` и без «amend-tests: отказ», `tests_locked_sha` сдвинут на голову ветки документов, записей «правка планки» стало на одну больше; для правки долгоживущего файла — голова кодовой ветки сдвинута и перечень нового лока несёт сумму правленого файла; для удаления `.test.jsx` — деталь записи несёт «удалены:» с его путём.
5. Правка допустима только в трёх методах и в помощниках класса `Ac11AmendLabelledRefusalTest`. Общие помощники `LabelledSandbox`, `CarryOverSandbox`, `FailToPassSandbox` и прочие методы обоих файлов не правятся.

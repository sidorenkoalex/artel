# ТЗ: Команда doc-commit: документы и конфигурация Оператора коммитятся от origin/main механикой note

Источник: решение Оператора 19.09 («если изменение — команда, если
команды нет — её нужно сделать»). Парная задача — «Защита main главной
копии git-хуками»: после её мержа ручной коммит документов в main
невозможен, а команда есть только для трёх разделов docs/backlog.md.

Факты:
- `note` (`orchestrator/notes.py`) умеет ровно одно: строку в раздел
  «Копилка»/«Бэклог»/«Очередь Оператора» файла docs/backlog.md. Механика
  переносима: отдельный рабочий репозиторий `.artel/notes-work`
  (`_ensure_work_repo`), `fetch origin/main` и пересборка правки от
  актуального содержимого (`_fetch_and_build`), коммит и push с
  повторами при non-fast-forward (`_commit_and_push`,
  `MAX_PUSH_ATTEMPTS`), удержание в `.artel/notes-pending/` при сетевом
  отказе и в окне тишины (`_hold_pending`, `_silence_window_reason`),
  отправка `--flush`.
- Документы, которые Оператор и ассистентская сессия правят руками вне
  задач: docs/operator-session.md (контракт сессии, уроки), docs/roadmap.md,
  docs/research/*, docs/audits/*, docs/reference/*; конфигурация
  Оператора: roles.yaml, gates.yaml, targets.yaml (защищённые пути,
  `config.PROTECTED_PATHS` — правит только Оператор). Сегодня все они
  коммитятся прямым `git commit` в главной копии, что после защиты main
  станет невозможно, а до неё ломает пин HEAD.
- Главная копия должна оставаться чистой: гейты фиксации пишут
  «sha зафиксирован … чисто=True» по рабочему дереву `config.ROOT`;
  изменённый файл в рабочем дереве — грязь.

Требуется:
1. Команда `artel.py doc-commit <путь-в-репозитории> --from <файл>
   [--message "<текст>"]`: берёт содержимое `<файл>` (любой путь на
   диске, например из каталога сессии) и коммитит его как новое
   содержимое `<путь-в-репозитории>` от `origin/main` в рабочем
   репозитории `note`, затем пушит — тем же механизмом, что `note`:
   повторы при non-fast-forward, удержание при сетевом отказе и в окне
   тишины, отправка `note --flush`/`doc-commit --flush`. Главная копия
   `config.ROOT` не трогается ни при одном исходе.
2. Допустимые пути: `docs/**` (кроме docs/backlog.md — для него `note`)
   и файлы конфигурации Оператора `roles.yaml`, `gates.yaml`,
   `targets.yaml`. Любой другой путь (код, тесты, скилы, шаблоны,
   `tasks/`) — именованный отказ «код и артефакты меняются задачами, не
   doc-commit». Вызов из окружения роли (`runner.in_role_environment`)
   — отказ, как у `answer`/`zones-extend`.
3. Сверка базы: если содержимое `<путь>` в `origin/main` отличается от
   содержимого того же пути в HEAD главной копии (пин), команда
   отказывает «файл изменился в origin после пина — сначала
   pin-update», чтобы правка, сделанная поверх устаревшей версии, не
   затёрла чужую. Новый файл (нет ни в origin, ни в HEAD) допустим.
4. Сообщение коммита: `docs: <путь> — <message>` (для конфигурации —
   `config: <путь> — <message>`); без `--message` — отказ: основание
   правки обязательно. Журнал пульта не пишется (как у `note`), вывод
   команды называет sha коммита в origin.
5. `note --flush` и `doc-commit --flush` отправляют удержанные записи
   обоих видов из одного каталога `.artel/notes-pending/` (общий формат
   JSON с полем `kind`).
6. Тесты (tests/): успешный doc-commit нового содержимого docs-файла
   (в тестовом origin появляется коммит, главная копия не изменена);
   отказ по недопустимому пути; отказ при расхождении origin/main и
   HEAD по файлу; удержание в окне тишины и отправка `--flush`;
   конфигурационный путь с префиксом `config:`; отказ из окружения роли.
   Существующие `tests/test_notes.py` остаются зелёными.

Зоны: orchestrator/notes.py, orchestrator/artel.py, tests/.

Только чтение (не менять): orchestrator/runner.py
(`in_role_environment` — переиспользовать), orchestrator/config.py
(`PROTECTED_PATHS`, `NOTE_SILENCE_WINDOW_STATES`), orchestrator/gitcmd.py,
orchestrator/pin.py, docs/operator-session.md (описание команды —
самим `doc-commit` после мержа, не в ветке задачи).

Не входит: правка кода, тестов, скилов и шаблонов вне задач; применение
приложений PLAN к защищённым путям (отдельное ТЗ после мержа задачи про
мьютекс мержа); перенос `note` на новый интерфейс (совместимость
сохраняется).

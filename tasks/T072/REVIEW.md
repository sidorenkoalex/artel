## Замечания

Нет открытых blocker/major. Оба замечания итерации 2 проверены
исполнением и подтверждённо закрыты:

1. (было blocker) `scripts/guard.py --all` на HEAD ветки (`dfb597c`) —
   `GUARD: ок (241 файлов)`, 0 нарушений (было 63). Проверил также, что
   миграция не задела ничего лишнего: из 65 файлов `tasks/T*/REVIEW.md`
   ни один approved-файл не остался без секции (скрипт-проверка, см.
   «Проверено исполнением»), и среди файлов, тронутых коммитом `2b03dff`,
   нет ни одного не-`approved` (единственный не-`approved` файл в общем
   diff ветки — `tasks/T072/REVIEW.md` сам, предсуществующий артефакт
   иерархии ревью этой же задачи, не продукт миграции).
2. (было blocker) `git diff main...HEAD -- templates/ skills/` — пусто.
   `git branch --contains bc72aac -a` показывает, что коммит остаётся в
   истории только этой ветки (не в `main`) — это ожидаемо: шаг 8 отменяет
   диф содержимого через `git checkout main -- ...`, а не переписывает
   историю, и этого достаточно, чтобы после мержа `main` не получил
   изменений защищённых путей. Проверил и практическую сторону: CI-джоб
   `protected-paths` (`.github/workflows/ci.yml:47`) сравнивает
   `git diff --name-only BASE...HEAD` (содержимое дерева, не список
   коммитов-участников) — при нулевом net-diff файл в списке изменённых
   не появится, предупреждение не сработает.

Дополнительно проверил потенциальный источник шума, не нашёл дефекта:
`docs/codebase-map.md` на HEAD хранит `built_at_sha: bc72aac...`, хотя
HEAD — уже `dfb597c` (на два коммита впереди). Не блокер: ни `2b03dff`,
ни `dfb597c` не трогают `.py`-файлы, регенерация картой не требовалась
конвенцией; убедился прогоном `python3 scripts/codebase_map.py`, что
единственная строка diff — сам `built_at_sha` (содержимое карты
идентично), а CI-джоб `codebase-map` (`ci.yml:75-77`) сверяет карту,
явно игнорируя строку `built_at_sha` — свежесть по существу не нарушена
(рабочую копию после проверки вернул в исходное состояние командой
`git checkout -- docs/codebase-map.md`, `git status --short` — чисто).

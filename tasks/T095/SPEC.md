# SPEC: Метрика «трение» — доля непродуктивных токенов шага

## Контекст
Роадмап P3 требует к go/no-go метрику «трение»: детерминированную (без
LLM) оценку доли токенов/событий шага, ушедших не на предмет задачи —
повторные чтения одного файла, ошибки инструментов и ретраи вызовов,
перечитывания больших кусков. Парсер логов шага уже частично существует
(`orchestrator/agent_log.py`), учёт стоимости/токенов из событий потока —
прецедент T040/T082. Отображать метрику нужно в `artel report` (T092),
который остаётся read-only и самодостаточным.

## Требования

1. Детерминированная (без LLM) функция вычисляет метрику «трение» по
   логу шага (`--output-format stream-json`, файлы
   `.artel/logs/<id>-<role>-N.log`) — долю токенов/событий шага, ушедших
   на сигналы непродуктивности; ТЗ называет как минимум: повторные
   чтения одного и того же файла, ошибки инструментов и ретраи вызовов,
   перечитывания больших кусков. Точный состав сигналов и пороги — по
   фактическому формату живых логов, решение разработчика в PLAN.
2. Есть агрегация метрики: на задачу (по её шагам) и на корпус (по всем
   задачам).
3. `artel report` содержит блок с метрикой трения: значения по
   последним задачам и тренд. Блок не меняет read-only и
   самодостаточный характер команды `report` (никаких новых внешних
   сервисов, сети или демонов; данные — только из того, что уже доступно
   локально).
4. Способ получения данных для блока — один из двух, выбор и
   обоснование (с учётом retention логов: лог шага может быть уже
   вычищен `prune`) делает разработчик в PLAN:
   а) ленивый расчёт при генерации report — по файлам логов, доступным
      на машине в момент генерации; лог, недоступный на момент расчёта
      (вычищен `prune` или отсутствует), — честный пропуск метрики по
      этому шагу, не ошибка и не падение `report`;
   б) запись метрики в журнал по завершении шага.
5. Изменения ограничены зонами: `orchestrator/agent_log.py` (расширение
   парсера), `orchestrator/report.py`; при выборе варианта 4(б) —
   дополнительно точка завершения шага. Не меняются: catalog/store-ядро,
   fsm-фиксации, ветко-чтения, guard, coldstart, canary (зона
   параллельной задачи T094). Конфликт зон с T094 по ходу реализации —
   эскалация, не выход за границу.

## Критерии приёмки

AC-1. Существует детерминированная (без LLM) функция, вычисляющая долю
непродуктивных токенов/событий шага по логу шага
(`--output-format stream-json`), учитывающая как минимум сигналы,
названные в ТЗ: повторные чтения одного файла, ошибки инструментов и
ретраи вызовов, перечитывания больших кусков.

AC-2. Метрика агрегируется на уровень задачи (по шагам этой задачи) и
на уровень корпуса (по всем задачам).

AC-3. `artel report` показывает блок с метрикой трения: значения по
последним задачам и тренд.

AC-4. Блок метрики трения не превращает `report` в команду, зависящую
от сети, внешних сервисов или демона: данные берутся только из уже
доступных локально источников (файлы логов и/или `state.db`).

AC-5. Если способ получения данных — ленивый расчёт при генерации
report (вариант 4а SPEC): лог шага, недоступный на момент расчёта
(вычищен `prune` или отсутствует), пропускается по этому шагу честно —
без ошибки и без падения генерации `report`.

AC-6. Если способ получения данных — запись в журнал по завершении
шага (вариант 4б SPEC): изменения не затрагивают catalog/store-ядро,
fsm-фиксации, ветко-чтения, guard, coldstart, canary.

AC-7. PLAN задачи фиксирует, какой из двух способов (4а или 4б)
выбран, и обоснование выбора с учётом retention логов (лог шага может
быть уже вычищен `prune`).

AC-8. Изменения задачи не выходят за зоны `orchestrator/agent_log.py`,
`orchestrator/report.py` и (только при варианте 4б) точки завершения
шага; catalog/store-ядро, fsm-фиксации, ветко-чтения, guard, coldstart,
canary не затронуты.

AC-9. Задача не добавляет пороги и алерты по метрике трения.

AC-10. Задача не добавляет регресс-флаги.

AC-11. Формат логов stream-json (что и как пишет CLI агента) не
меняется — расширяется только разбор существующего формата.

AC-12. Существующий набор тестов (`tests/`) остаётся зелёным после
изменений.

## Не входит

- Пороги и алерты по метрике трения — сначала накопить фактуру.
- Регресс-флаги (отдельная строка B-вставки роадмапа).
- Правки формата логов stream-json.
- Изменения catalog/store-ядра, fsm-фиксаций, ветко-чтений, guard,
  coldstart, canary (зона параллельной задачи T094).

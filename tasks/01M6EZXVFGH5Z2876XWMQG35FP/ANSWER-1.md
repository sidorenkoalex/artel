# ANSWER-1: ответ Оператора

## Ответы

Уточнения сессии при Операторе (права волны G) к SPEC части 3 Б2.3 по аудиту на гейте, 03.11.2026.

1. Подмодуль по ssh-адресу на том же хосте — `warn` «подмодуль <путь>: ssh-адрес, токеном слота не проверяется»; https — проба с токеном, как в SPEC.
2. Разборщик `.gitlab-ci.yml`: прочие ключи заданий и верхнего уровня (`stage`, `image`, `rules`, `artifacts`, `needs`, `inherit` и др.), если синтаксис разобран, пропускаются как неважные; «не разобран» — только при нарушении синтаксиса подмножества. `retry` формой отображения (`retry: {max: N}`) при N > 0 — находка перезапуска.
3. `http_status` заполняется при любом сбое чтения заданий конвейера, независимо от итога (`red` не скрывает 403 на заданиях); треб. 5: задания токену недоступны — `fail` (права) / `skip` (временный), даже при красном конвейере; AC на 403 заданий при `failed` конвейере.
4. Пробелы критериев закрываются тестами задачи: `$CI_PIPELINE_SOURCE`/`$CI_DEFAULT_BRANCH` в `if`; `include:` — `warn` «не разобран: include»; неподдержанный `if` и `changes`/`exists` — `warn` (правило может сработать); нет файла CI — `warn`; запись `target-human` без компонента `ci`/`both` — строк треб. 8/9 нет; относительный адрес подмодуля — разрешается от адреса записи; подмодуль чужого хоста — `warn`.

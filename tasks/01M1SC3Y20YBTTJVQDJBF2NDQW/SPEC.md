# SPEC: идемпотентность `workspace.ensure` не зависит от символических ссылок в пути

## Контекст

Первый боевой прогон канарейки v2 05.09 (`canary --k 2`, прогон
20260905T175403Z) убил обе задачи набора как «не сошлась» после трёх
холостых проходов, ни один шаг роли не стартовал, расход $0.
Воспроизведение Оператором в эфемерном клоне: `agent run SKIPPED —
рабочий каталог роли не создан: … fatal: '<клон>/.artel/worktrees/<id>'
already exists`.

Канарейка заводит worktree явно (`workspace.ensure`), затем первый шаг
роли (`runner.role_cwd`) зовёт `ensure` повторно. Идемпотентность
`ensure` определяется регистрацией пути в `git worktree list`, но
сравнение путей идёт без нормализации: эфемерный клон лежит в
`tempfile.mkdtemp()` под `/var/folders/...`, а git отдаёт
зарегистрированный путь как `/private/var/folders/...` (символическая
ссылка macOS) — строковое сравнение не находит совпадения, и `ensure`
зовёт `git worktree add` на каталог, который уже существует, что
падает.

Из-за этого же дефекта канарейка не распознаёт причину провала: вместо
немедленной остановки задачи набора с диагностикой она крутит холостые
проходы до стоп-крана (`CANARY_MAX_STALL_ITERS`), и настоящая причина
(`agent run SKIPPED`, рабочий каталог роли не создан) видна только
внутри уже уничтоженного эфемерного клона — в итоговом отчёте прогона
её нет.

## Требования

1. `workspace.ensure` и все внутренние сравнения пути worktree
   задачи с содержимым `git worktree list` (`workspace._registered`,
   используемая `ensure`/`on_task_branch`/`remove`) сравнивают пути
   после `Path.resolve()` с обеих сторон — как путь, который сравнивают,
   так и каждый путь из вывода `git worktree list --porcelain`.
2. Повторный вызов `workspace.ensure` для worktree, уже
   зарегистрированного под путём, отличающимся от переданного только
   символической ссылкой в одном из компонентов (тот же случай, что
   `/var/folders/...` vs `/private/var/folders/...` на macOS),
   возвращает тот же путь и `None` вместо ошибки — не зовёт `git
   worktree add` повторно.
3. `canary._drive_task`, обнаружив в журнале шага задачи запись `agent
   run SKIPPED` с причиной «рабочий каталог роли не создан» или
   «каталог окружения роли не создан», не продолжает считать холостые
   проходы до `CANARY_MAX_STALL_ITERS` — завершает ведение ЭТОЙ задачи
   набора немедленно как «не сошлась» (`_kill_inconclusive` или
   равноценный путь), используя текст причины из записи журнала, а не
   общую формулировку «проходов подряд без прогресса».
4. `cmd_canary`/`_run_one_task` печатают в отчёте прогона для каждой
   задачи с исходом `killed` причину исхода: «штатно» — если убита на
   `merge_gate`/`verifying` (эти пути и раньше не были ошибкой
   конвейера), иначе — «не сошлась: <причина>» с текстом причины
   (из требования 3 выше, где применимо).

## Критерии приёмки

AC-1. `workspace.ensure`, вызванный дважды подряд для одной задачи,
когда её worktree зарегистрирован в `git worktree list` под путём,
отличающимся от переданного `path(task_id)` только заменой одного
сегмента на символическую ссылку (фикстура с `os.symlink`), оба раза
возвращает `(path(task_id), None)` — второй вызов не запускает `git
worktree add`.

AC-2. `workspace.ensure`/`on_task_branch`/`remove` сравнивают пути
после `Path.resolve()` с обеих сторон (переданный путь и каждая запись
`git worktree list --porcelain`), а не сырыми строками.

AC-3. `canary._drive_task`, когда очередной проход `auto.cmd_auto` не
меняет состояние и последняя запись журнала шага — `agent run SKIPPED`
с причиной «рабочий каталог роли не создан» или «каталог окружения
роли не создан», завершает ведение задачи как «не сошлась» на ЭТОМ же
проходе (не ждёт `CANARY_MAX_STALL_ITERS` холостых проходов), и в
журнал/алерт уходит причина из записи `agent run SKIPPED`, а не общая
формулировка про проходы без прогресса.

AC-4. Отчёт прогона `cmd_canary` (`_run_one_task`) для задачи с итоговым
состоянием `killed` печатает причину исхода: «штатно» — при
`merge_gate`/`verifying`, «не сошлась: <причина>» — в остальных
случаях, где причина известна из журнала (в том числе случай AC-3).

AC-5. Тест: `workspace.ensure` вызван дважды для задачи, чей worktree
зарегистрирован под путём через `os.symlink`-фикстуру, отличающимся
от `path(task_id)` только заменой сегмента на символическую ссылку —
второй вызов не падает и не создаёт лишнего worktree.

AC-6. Тест: `canary._drive_task` в песочнице, где журналируется `agent
run SKIPPED` с причиной «рабочий каталог роли не создан» (или
«каталог окружения роли не создан») и состояние между проходами не
меняется, завершает задачу как «не сошлась» немедленно (не после
`CANARY_MAX_STALL_ITERS` проходов), с текстом причины из журнала в
детали убийства.

AC-7. Существующие тесты `tests/test_workspace.py` и `tests/test_canary.py`
(включая `DriveTaskStallCapTest`, который не журналирует `agent run
SKIPPED` и обязан по-прежнему упираться в стоп-кран
`CANARY_MAX_STALL_ITERS`) остаются зелёными.

## Не входит

- Изменение сравнений путей worktree вне `orchestrator/workspace.py`
  (например, `doctor._orphan_worktrees`/`doctor.check_orphans`) — вне
  зоны этой задачи и вне описанного в ТЗ дефекта.
- Устранение других причин `agent run SKIPPED` (промпт не записан/не
  прочитан, `claude CLI не найден`) из общего механизма холостых
  проходов канарейки — требование 3/AC-3 сужено ТЗ ровно до причин
  «рабочий каталог роли не создан» и «каталог окружения роли не
  создан».
- Изменение потолков `CANARY_MAX_STALL_ITERS`/`CANARY_MAX_ESCALATION_CYCLES`
  и поведения канарейки для генуинного «нет прогресса» без записи
  `agent run SKIPPED` в журнале — этот путь (`DriveTaskStallCapTest`)
  не меняется.
- Устранение самой символической ссылки macOS в `tempfile.mkdtemp()`
  (`/var/folders` vs `/private/var/folders`) — задача нормализует
  сравнение путей, не окружение ОС.
- Изменение формата/состава пула канарейки, маркеров эскалации,
  бейзлайна и прочей механики v2, не упомянутой в требованиях выше.

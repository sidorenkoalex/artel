# SPEC: Полный прогон tests/ пульта на дереве «ветка плюс приложения PLAN»

## Контекст
Код задачи может краснеть без приложений PLAN к защищённым путям
(прецедент 05.10, 01M45FJVGQT1K0P8HDEXZX6HS7: профиль в `targets.yaml`,
песочница `tests/test_invariants.py`). Сегодня приложения накладывают
только CI ветки (`scripts/plan_appendix_ci.py`) и гейт мержа
(`orchestrator/fsm_merge_gate.py::_apply_plan_appendices`). Автогейт
приёмки (`orchestrator/fsm_autogate.py`, вызов `acceptance.full_suite` ~297)
и approve в `acceptance` (`orchestrator/fsm.py::_acceptance_full_suite_ok`
~1067-1124) гоняют полный набор в рабочей копии задачи без приложений: 05.10
14 инвариантов красны по построению, приёмка прошла только через
`approve --accept-red`, а роль тратила шаги на «починку» тех же падений.
Задача переводит три полных прогона ветки — автогейт приёмки, approve в
`acceptance` и `suite-run` (команда задачи 01M462QACEH29RPRD2RZHGHQFM,
мержится раньше этой) — на временное дерево с наложенными приложениями тем
же узлом, что на гейте мержа.

## Требования

1. Автогейт приёмки, approve в `acceptance` и прогон ветки `suite-run`
   гоняют полный набор `tests/` на временном дереве: состояние рабочей
   копии задачи (для `suite-run` — с незакоммиченными правками; для
   автогейта и approve — голова ветки задачи) плюс приложения PLAN
   задачи, наложенные тем же разбором (`scripts/guard.py::plan_appendices`)
   и тем же `git apply` (`orchestrator/advance_gates/plan_appendix.py::
   git_apply`), что на гейте мержа, в том же порядке. Источник PLAN — тот
   же, что у гейта мержа (ссылка документов задачи).
2. Рабочая копия задачи, её индекс, ветка и ссылки после прогона по
   требованию 1 не изменены; временное дерево убирается на любом исходе
   (зелёный, красный, отказ наложения, сбой git, исключение).
3. PLAN без приложений или задача не артели (`repo_context.is_artel` —
   ложь) — прогон идёт как сегодня, в рабочей копии задачи, без
   временного дерева.
4. Неприменимое приложение — прогон не идёт; отказ называет номер
   приложения и его пути: автогейт — «не пройден» с этой причиной,
   approve — отказ, `suite-run` — отказ. Сбой git при подготовке дерева
   или наложении — тоже отказ без прогона, а не прогон без приложений
   (fail-closed).
5. Итог прогона с приложениями (запись журнала, detail, отчёт
   `suite-run`) называет, что прогон шёл с приложениями PLAN, и пути
   наложенных приложений.
6. Прогон базы `suite-run` (дерево базы задачи) приложения задачи не
   накладывает — база сравнения остаётся деревом main.
7. Гейт мержа и новые места используют один общий узел наложения
   приложений; порядок и условия наложения на гейте мержа (в том числе
   условие полного прогона `_FULL_SUITE_APPENDIX_PREFIXES`) не меняются.

## Критерии приёмки

AC-1. Автогейт приёмки задачи артели, у которой тест `tests/` красен на
голове ветки и зелёный с наложенным приложением PLAN, даёт зелёный прогон
полного набора (автогейт по полному набору пройден).

AC-2. approve в `acceptance` той же задачи (тест красен без приложения,
зелёный с ним) проходит без `--accept-red`.

AC-3. `suite-run` той же задачи даёт отчёт без этого теста среди упавших;
незакоммиченная правка рабочего дерева задачи прогону видна (тест,
ставший красным только незакоммиченной правкой, отчёт называет упавшим и
при наложенных приложениях).

AC-4. Приложения накладываются в порядке их следования в PLAN тем же
`git apply`, что на гейте мержа: два приложения, второе из которых
применимо только поверх первого, дают зелёный прогон на автогейте,
approve и `suite-run`.

AC-5. После прогона по AC-1..AC-3 у рабочей копии задачи не изменены
`git status --porcelain`, индекс, голова ветки и ссылки (`refs/`), в
том числе незакоммиченные правки `suite-run` на месте; временного дерева
прогона на диске нет.

AC-6. Неприменимое приложение: автогейт — не пройден, approve — отказ,
`suite-run` — отказ; в каждом случае причина называет номер приложения и
его пути, а полный набор не запускается.

AC-7. Сбой git при подготовке временного дерева или наложении (например,
ненулевой код `git worktree add`/`git apply`) — отказ на автогейте,
approve и `suite-run` без прогона; прогона в рабочей копии без
приложений не происходит.

AC-8. Временное дерево отсутствует на диске после прогона на каждом
исходе: зелёный, красный, отказ наложения, сбой git, исключение в ходе
прогона.

AC-9. Задача с PLAN без приложений и задача не артели — полный набор на
автогейте, approve и `suite-run` идёт с `cwd`, равным рабочей копии
задачи (`workspace.path`), как до задачи.

AC-10. Запись журнала автогейта и approve и отчёт `suite-run` при
прогоне с приложениями содержат признак «с приложениями PLAN» и пути
наложенных приложений.

AC-11. Прогон базы `suite-run` идёт на дереве базы задачи без приложений
задачи: тест, зелёный на базе только при наложенном приложении, в итоге
базы красен.

AC-12. Гейт мержа после выноса узла накладывает приложения в прежнем
порядке и при прежних условиях: задача с применимыми приложениями мержится
как до задачи, неприменимое приложение даёт прежний отказ гейта мержа.

## Оценка объёма и деление

Сработавшие сигналы: файлов зоны ≥ 5 (`orchestrator/acceptance.py`,
`orchestrator/fsm_autogate.py`, `orchestrator/fsm.py`, модуль команды
`suite-run`, `orchestrator/fsm_merge_gate.py`, новые файлы `tests/`,
`docs/codebase-map.md`); критериев приёмки ≥ 10 (12); `budget_usd` ≥ $30.

Материал для решения Оператора — обоснование монолита: все три места
(автогейт, approve, `suite-run`) переходят на один общий узел «временное
дерево + наложение приложений», вынесенный из гейта мержа; узел и его
отказы (требования 2, 4, 5) одни и те же для всех мест, и приёмка одного
места без другого оставила бы автогейт и approve на разных деревьях при
той же планке (01M45FJVGQ прошла бы автогейт и не прошла approve). Узел
без хотя бы одного потребителя — мёртвый код. Возможный разрез, если
Оператор предпочтёт деление: часть 1 — общий узел, гейт мержа, автогейт и
approve (не зависит от `suite-run`); часть 2 — `suite-run` (после части 1
и после 01M462QACEH29RPRD2RZHGHQFM). Цена деления — ещё один цикл
analyst/test_author (~$8) при едином наборе критериев.

## Не входит

- Изменение порядка и условий наложения приложений на гейте мержа (вне
  выноса общего узла, требование 7).
- Прогоны роли напрямую pytest (вне `suite-run`).
- Замок одного полного прогона на машину (отдельная строка копилки).
- Внешние проекты (не артель) — для них поведение прежнее (требование 3).
- Правка `scripts/plan_appendix_ci.py`, `scripts/guard.py`, `conftest.py`,
  `tests/test_invariants.py`, `docs/invariants.md`, `docs/adr/`,
  `docs/roadmap.md`, `docs/backlog.md`, `docs/operator-session.md`,
  `templates/`, `skills/`, `CLAUDE.md`, `models.yaml`, `roles.yaml`,
  `targets.yaml`, `.github/workflows/ci.yml` — только чтение по ТЗ.
- Отдельные тесты `tests/` сверх приёмочных: пункт 6 ТЗ (тесты с заявками
  «Ловит мутацию» на свойства AC-1..AC-12) держат долгоживущие приёмочные
  тесты автора тестов (ADR-0020), повторно в `tests/` не заказываются.
- Неослабление существующих тестов и зелёный полный набор `tests/` — их
  держит пульт.

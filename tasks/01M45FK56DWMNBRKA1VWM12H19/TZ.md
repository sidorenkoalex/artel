Требуется:
1. Защищённые пути проекта — одна функция «перечень защищённых путей
   проекта»: для внешнего проекта — `no_paths` его записи; для артели
   — источник выбирает SPEC (`config.PROTECTED_PATHS`, ADR-0021 п.8,
   либо `no_paths` её записи) с обоснованием. Все места сверки из
   «Фактов» берут перечень проекта задачи (формула
   `config.is_protected_path` с явным перечнем). Расхождение двух
   перечней артели запрещено: поле `no_paths` записи `artel` приводится
   приложением к действующему перечню (18 записей), комментарий записи
   о «декларации» приводится к действительности, тест-сторож сверяет
   совпадение двух перечней и называет расхождение. Если выбор
   источника требует менять формулировку документа инвариантов (он
   называет единым источником `config.PROTECTED_PATHS`) — эскалация с
   вопросом Оператору.
2. Проверки пункта 8 этой части — гейт зон, замер объёма диффа,
   защищённые пути (в диффе на гейте мержа и в местах сверки из
   «Фактов»), приложения к PLAN, карта кодовой базы — исполняются для
   любого проекта с разрешённым контекстом, в клоне и рабочей копии
   задачи из `repo_context`; развилки этих проверок из «Фактов»
   удаляются. SPEC таблицей перечисляет каждую из этих проверок:
   источник репозитория, что берётся из профиля (части 1) или записи
   проекта, поведение при неразрешённом контексте и без профиля.
   Поведение для артели не ослабляется ни в одном месте. Отдельно SPEC
   решает: общие зоны вне конфликта для внешнего проекта; классы
   приложений, требующие полного прогона; карта кодовой базы у проекта
   без генератора.
3. Тесты в `tests/` с заявками «Ловит мутацию» на пп.1–2 этой части;
   существующие тесты не ослабляются. Смену ожиданий существующих
   тестов (тесты из «Фактов», закрепляющие пропуск проверок для внешнего
   проекта, и любые другие, найденные при работе) роль выносит
   эскалацией с точным списком — файл, тест, прежнее и новое ожидание —
   и проводит по мандату Оператора разделом SPEC «Меняемое поведение»
   механикой задачи «Смена поведения в существующих тестах», с перечнем
   в PLAN. Дополнение записей `targets.yaml` в фикстурах — не смена
   ожидания и перечисляется в PLAN отдельно.

# ТЗ: note: окно тишины — удержание строк во время живых циклов

Источник: копилка docs/backlog.md, строка П2 от 12.09 «Нет команды note
--hold» (коммит 26e7518a) и строка П1 от 11.09 «Документные коммиты note
сбивают цикл мержа». Решение Оператора 12.09: во время живых циклов
строки копилки удерживать, отправлять пачкой на границе волны; правило
должно исполняться пультом, не памятью сессии.

Факты:
- `note` (orchestrator/notes.py, `_attempt` ~272–305) на каждую строку
  делает fetch/правку/commit/push в main отдельным коммитом. Удержание
  (`_hold_pending`, ~88; каталог `.artel/notes-pending/*.json`,
  формат `{"kind": "insert"|"append"|"drop"|"set-state"|"set-priority",
  ...}`) срабатывает только при отказе сети/push; `_flush_pending` (~311)
  допушивает удержанные в начале КАЖДОГО `cmd_note` и по `note --flush`.
- Сдвиг origin/main во время живого цикла задачи ведёт к подтяжке на
  трёх точках сверки свежести (in_dev -> review, acceptance -> merge_gate,
  merge_gate -> done): 11.09 три записи копилки сбили цикл мержа
  01M283NC; 12.09 push мержа части 2 отклонён из-за записи копилки;
  12.09 документные сдвиги main дали ложные отказы гейта зон (строка П1
  12.09). Задача 01M2ARQMTY (смержена 12.09) снимает подтяжку по
  чисто документным коммитам, не пересекающимся с диффом ветки, но не
  снимает гонку push самого мержа с push заметки.
- 12.09 сессия Оператора удерживала строки вручную сценарием, пишущим
  JSON того же формата в `.artel/notes-pending/` (обход без команды
  пульта), и отправляла `note --flush` после закрытия волны.
- Живой держатель окна мержа — таблица `merge_locks`
  (`store.merge_lock`/`release_merge_lock`, orchestrator/store.py:666–691).
  Состояния задач — `store.all_tasks(conn)`.

Требуется:
1. `note` сам удерживает запись вместо push, когда открыто «окно
   тишины»: есть живой держатель `merge_locks` ЛИБО хоть одна задача в
   состоянии из набора `in_dev`, `verifying`, `review`, `acceptance`,
   `merge_gate` (константа в config.py с именем и комментарием). Запись
   валидируется как обычно (отказы валидации — до удержания, как сегодня
   до push), затем кладётся в `.artel/notes-pending/` и команда печатает
   «заметка удержана: <причина окна тишины>; отправка — note --flush
   либо автоматически следующим note вне окна».
2. `note --flush` отправляет удержанное независимо от окна тишины
   (явное решение Оператора); `note --now <раздел> --text …` — записать и
   отправить немедленно в обход окна (тот же явный обход). Автоматический
   допуш в начале `cmd_note` (`_flush_pending`) уважает окно: вне окна —
   допушивает, в окне — нет.
3. Формат JSON удержанной записи и каталог не меняются (совместимость с
   уже лежащими файлами); порядок отправки — по имени файла (время).
4. Тесты в tests/test_notes.py по образцу существующих (стенд с bare
   origin): (а) при задаче в `merge_gate` `note копилка --text …` не
   пушит, файл в notes-pending есть, origin не изменился (мутация «окно
   не проверяется» — красный); (б) без таких задач — прежний немедленный
   push; (в) `--flush` в окне пушит; (г) `--now` в окне пушит; (д) живой
   `merge_locks` без задач в состояниях набора — удержание; (е)
   существующие тесты notes — без ослабления.

Зоны: orchestrator/notes.py, orchestrator/config.py, tests/.

Приложением: orchestrator/store.py (`merge_lock`, `all_tasks`),
docs/backlog.md (строки П2 12.09 и П1 11.09), docs/operator-session.md
(правило записи аномалий «сразу» — исполняется удержанием, не push).

Не входит: правка store.py, pull.py, fsm_merge_gate.py; изменение
классификации документных путей; авто-flush из цикла мержа.

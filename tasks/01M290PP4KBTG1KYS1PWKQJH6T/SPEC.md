# SPEC: дозор watch — классы stops/ci, identity сессии не через ppid, отказ пустой --mine, выход по событию --exit-on

## Контекст

Копилка 11.09 (три строки П1) зафиксировала три слепых пятна `watch`:
остановки цикла `auto` на красном CI (01M283NC…, 01M283NJ…) дозор не
печатает — классы событий (`transitions/refusals/gates/steps/budget/
alerts`) их не покрывают, находка была сделана только чтением лога
`auto` вручную; `watch --mine` пуст для отвязанного цикла — identity
сессии резолвится через `ppid`, а lease отвязанного `auto` берётся как
`ppid-1`, и пустая выборка молча завершается кодом 0; фоновый `watch`
не завершается никогда, а клиент сессии отдаёт вывод фоновой команды
только по её завершении — событие лежит в файле дозора десятки минут
незамеченным. Отдельная строка П2 копилки отмечает шум: отказы
предварительного advance класса «роль ещё не закончила» попадают в
класс `refusals` как обычные отказы и прячут настоящие события.
Контракт `docs/operator-session.md`, шаг 4, требует, чтобы эскалация и
ожидание Оператора отражались в чате сами — без этих правок дозор не
соответствует контракту.

## Требования

1. Новые классы событий `watch`: `stops` (любая запись остановки цикла
   `auto` — «auto остановлен: …», любая причина, любой `actor`) и `ci`
   (вердикт CI ветки не зелёный — записи «статус CI ветки …»). Оба
   входят в набор по умолчанию (`_DEFAULT_EVENTS`); `--events`
   принимает их по имени; справка/ошибка команды по неизвестному
   классу перечисляет их в списке доступных.
2. `session.resolve_session_id` без явного аргумента и без
   `ARTEL_SESSION_ID` читает идентификатор из файла сессии в `.artel/`
   — файл создаётся при первом обращении; отвязанный цикл `auto`
   наследует его через окружение дочернего процесса, так что lease
   отвязанного цикла и `watch --mine` той же сессии видят один и тот
   же identity. Формат `ppid-<n>` остаётся fallback'ом только когда нет
   ни переменной, ни файла. Существующие записи `ppid-1` в журнале не
   мигрируются.
3. Пустая выборка `--mine` — именованный отказ на stderr «watch
   --mine: у сессии <id> нет живых задач (lease взят другой identity:
   <список>)» с ненулевым кодом возврата, не тихий выход с кодом 0;
   `--tasks` с неизвестным id — отказ того же класса (именованное
   сообщение на stderr, ненулевой код), не бесконечный пустой цикл и не
   молчаливое завершение.
4. Режим завершения по событию: `watch --exit-on <класс>[,<класс>...]`
   завершает процесс кодом 0 сразу после первой напечатанной строки
   любого из перечисленных классов; `--once` — синоним `--exit-on` с
   классами по умолчанию. Без флага — поведение прежнее (бесконечный
   поток до `--until`/истощения выборки).
5. Отказы предварительного advance класса «роль ещё не закончила»
   (тексты, производимые `auto._pre_advance_step` — например «переход
   отклонён: замечания ревью не отработаны» и «переход отклонён:
   дерево не на ветке задачи») в класс `refusals` дозора не попадают;
   фильтр — по существующим текстам этих отказов, вынесенный в одну
   именованную константу (до появления отдельной пометки класса в
   самом журнале — задача другой роли, вне этой зоны).
6. Приложением к PLAN.md для Оператора (защищённый путь, применяет сам
   Оператор) — unified-диф правки `docs/operator-session.md`, шаг 4
   «Возобновление сессии»: способ постановки дозора под клиент (`watch
   --mine --exit-on gates,stops,ci` фоновым процессом с перезапуском по
   завершении), не голый бесконечный процесс.

## Критерии приёмки

AC-1. Классы `stops` и `ci` присутствуют в наборе допустимых классов
`watch` и в наборе по умолчанию; `--events stops` и `--events ci`
принимаются без отказа; неизвестное имя класса в `--events`
по-прежнему даёт именованный отказ, и его текст перечисляет доступные
классы, включая `stops`/`ci`.

AC-2. Запись журнала «auto остановлен: …» (любая причина, любой
`actor`) печатается дозором, когда в наборе событий класс `stops`, и не
печатается, когда `stops` явно исключён из `--events`.

AC-3. Запись журнала «статус CI ветки …», чей текст называет вердикт не
зелёным, печатается дозором, когда в наборе событий класс `ci`; та же
запись с зелёным вердиктом классом `ci` не печатается.

AC-4. Без явного аргумента и без `ARTEL_SESSION_ID`
`session.resolve_session_id` читает идентификатор из файла сессии в
`.artel/`, создавая файл при первом обращении, если его ещё нет; при
отсутствии и переменной, и файла — прежний fallback `ppid-<pid
родителя>`; явный аргумент и `ARTEL_SESSION_ID` по-прежнему сильнее
файла (порядок приоритета не меняется, меняется только последний
fallback).

AC-5. Lease, взятый отвязанным циклом `auto` (identity из файла
сессии, унаследованного через окружение дочернего процесса), и
`session_id`, который резолвит `watch --mine`, вызванный из той же
сессии, совпадают — задача, заведённая отвязанным циклом, видна в
`watch --mine` без явного `--tasks`.

AC-6. Пустая выборка `--mine` завершает `watch` ненулевым кодом
возврата и печатает на stderr текст «watch --mine: у сессии <id> нет
живых задач (lease взят другой identity: <список>)»; `--tasks` с id,
которого нет среди задач в БД, завершает `watch` отказом того же
класса (именованное сообщение на stderr, ненулевой код), не тихим
завершением и не бесконечным циклом без единой строки.

AC-7. `watch --exit-on <класс>[,<класс>...]` завершает процесс кодом 0
сразу после первой напечатанной строки любого из перечисленных
классов, не дожидаясь следующего опроса `--interval`; `--once`
завершает процесс кодом 0 после первой строки любого класса из набора
по умолчанию (`_DEFAULT_EVENTS`, включая `stops`/`ci`); без
`--exit-on`/`--once` `watch` не завершается по факту печати строки —
поведение как до этой задачи.

AC-8. Отказ предварительного advance класса «роль ещё не закончила»
(воспроизведённый тем же текстом, что производит
`auto._pre_advance_step` — «переход отклонён: замечания ревью не
отработаны» либо «переход отклонён: дерево не на ветке задачи») не
печатается классом `refusals` дозора; отказ другого класса (не из
`_pre_advance_step`) классом `refusals` по-прежнему печатается.

AC-9. `tests/test_watch.py` и `tests/test_session.py` остаются зелёными
без ослабления существующих проверок (ни одна не удалена, ни одна не
смягчена).

# ТЗ: дозор watch: классы stops и ci, identity сессии не через ppid, именованный отказ пустой --mine, выход по событию --exit-on

Источник: копилка 11.09, три строки П1 о дозоре `watch` (слеп к остановкам
цикла; фоновым процессом не доносит события до чата; `--mine` не видит
отвязанные циклы и выходит молча) и строка П2 «ожидаемые отказы
предварительного advance попадают в бриф и в дозор». Контракт
docs/operator-session.md, шаг 4 «Возобновление сессии»: эскалация и
ожидание Оператора отражаются в чате сами, а не по запросу статуса.

Факты 11.09:
- 01M283NC… (16:18Z) и 01M283NJ… (16:55Z) остановились на красном CI
  («auto остановлен: CI ветки красный — решение Оператора», actor=operator;
  «статус CI ветки (verifying): … не зелёный»). Классы событий `watch`
  (`_EVENT_CLASSES`: transitions/refusals/gates/steps/budget/alerts) эти
  записи не покрывают — дозор `--tasks` промолчал оба раза, остановки
  найдены чтением лога `auto` по слову Оператора «статус».
- `watch --mine` пуст: владелец задачи — `session_id` последней записи
  «lease взят» (`watch._owner_session_id`), отвязанный `auto` (с мержа
  01M1TNMBY8) берёт lease как `ppid-1`, а identity сессии —
  `ppid-<pid оболочки>` (`session.resolve_session_id`), у ассистентской
  сессии новый на каждую команду. `_should_stop` на пустой выборке даёт
  True — выход с кодом 0 без единой строки. Воспроизведено: created
  ppid-55379, lease ppid-1, watch ppid-86404.
- Клиент сессии отдаёт вывод фоновой команды только по её завершении, а
  `watch` не завершается никогда: красный CI и остановка цикла лежали в
  файле дозора более 20 минут.
- Отказы предварительного advance класса «роль ещё не закончила» («нет
  шага developer после возврата», «PLAN.md ветки не прочитан») попадают в
  класс `refusals` дозора как обычные отказы — шум, который прячет
  настоящие события.

Требуется:
1. Новые классы событий `watch`: `stops` — любая запись остановки цикла `auto` («auto остановлен: …», любая причина, любой actor) и `ci` — вердикт CI ветки не зелёный (записи «статус CI ветки …»). Оба входят в набор по умолчанию (`_DEFAULT_EVENTS`); `--events` с их именами принимается; справка команды перечисляет их.
2. Identity сессии не через ppid: `session.resolve_session_id` берёт идентификатор из переменной окружения `ARTEL_SESSION_ID`, а при её отсутствии — из файла сессии в `.artel/` (создаётся при первом вызове, наследуется отвязанным циклом `auto` через окружение дочернего процесса), так что lease отвязанного цикла и `watch --mine` той же сессии совпадают; формат `ppid-<n>` остаётся только как совместимый fallback, если ни переменной, ни файла нет. Существующие записи `ppid-1` в журнале не мигрируются.
3. Пустая выборка `--mine` — именованный отказ на stderr «watch --mine: у сессии <id> нет живых задач (lease взят другой identity: <список>)» с ненулевым кодом, не тихий выход с кодом 0; `--tasks` с неизвестным id — тот же класс отказа.
4. Режим завершения по событию: `watch --exit-on <классы>` завершает процесс после первой напечатанной строки любого из перечисленных классов (код 0), чтобы завершение фонового процесса само будило сессию; `--once` — синоним `--exit-on` с классами по умолчанию. Без флага поведение прежнее (бесконечный поток).
5. Фильтр шума: отказы предварительного advance класса «роль ещё не закончила» (тексты из `auto._pre_advance_step`, отдельная задача помечает их в журнале префиксом класса) в класс `refusals` не попадают; до появления пометки — фильтр по существующим текстам этих отказов, вынесенный в одну константу.
6. Тесты: класс `stops`/`ci` печатает остановку по красному CI (мутация «класс не в наборе по умолчанию» — красный); `--mine` при lease `ppid-1` и identity из файла сессии видит задачу; пустая `--mine` — ненулевой код и текст отказа; `--exit-on gates` завершает процесс после первой строки «ЖДЁТ ОПЕРАТОРА»; отказ pre-advance не печатается в `refusals`; существующие тесты `watch` и `session` — без ослабления.

Зоны: orchestrator/watch.py, orchestrator/session.py, tests/.
Приложением к PLAN (защищённый/занятый путь, применяет Оператор):
docs/operator-session.md — шаг 4 «Возобновление сессии»: способ
постановки дозора под клиент (`watch --mine --exit-on gates,stops,ci`
фоновым процессом с перезапуском по завершении), не голый бесконечный
процесс.

Не входит: пометка класса отказа в журнале (`auto.py`, `brief.py` —
отдельная задача о зацикливании предварительного advance);
`orchestrator/lease.py`; `orchestrator/store.py`; гарнитурный монитор
клиента; миграция старых записей журнала.

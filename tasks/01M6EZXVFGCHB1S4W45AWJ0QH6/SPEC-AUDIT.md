## Пути обхода гейтов
- **О-1 (бит исполнения).** Роль из оболочки делает `chmod -x
  <config.ROOT>/scripts/git-hooks/target-human/pre-push`. Содержимое не
  меняется, сумма равна эталону, `clone-push-hook` — `ok`. При этом git
  хук не вызывает, и отправка роли в `base` из оболочки проходит. Так же
  действует коммит в `HEAD` пульта с режимом `100644`. SPEC буквально
  выполнен, второй рубеж выключен (Д-1).
- **О-2 (токен на чужой хост).** `HOSTING_CREDENTIAL_HELPER`
  (`orchestrator/gitcmd.py:45-47`) отвечает на `get` для любого хоста.
  Подмодуль проекта с адресом на другом хостинге получит в клоне
  подмодуля (требование 10) токен проекта в Basic-авторизации. Достаточно
  подмодуля в `.gitmodules` репозитория проекта, а `.gitmodules` правят
  люди проекта или роль в ветке задачи (Д-2).
- **О-3 (AC-15 вхолостую).** Если выбрать `--recurse-submodules`, проверка
  «вызова клона подмодуля» сводится к проверке единственного вызова
  `git clone` (Д-3).
- Подмена файла политики ролью (`base=` другой, шаблон шире) хуком не
  держится. Её ловит строка `doctor` (AC-12) — как и `core.hooksPath` по
  модели угроз ТЗ. Отправки пульта держит `gitcmd`. Не отклонение.

## Вердикт
`concerns`. SPEC вести дальше можно; четыре отклонения Оператор решает на
гейте — дополнить SPEC или принять.

- **Д-1 (бит исполнения хука, О-1).** SPEC, требование 8, AC-11;
  `orchestrator/doctor/git_hooks.py:52-53`, `:70-75`. Строка
  `clone-push-hook` должна сверять не только сумму, но и бит исполнения
  `pre-push` (и `pre-commit`) каталога `target-human`. `--fix` должен его
  ставить, как `_fix_git_hooks` для главной копии. Нужен AC: хук без бита
  исполнения даёт `fail`, после `--fix` — `ok`. Иначе строка `doctor`
  показывает `ok` при выключенном хуке.
- **Д-2 (охват токена в клоне подмодулей, О-2).** SPEC, требование 10;
  `orchestrator/gitcmd.py:45-47`, `:149-165`. ТЗ п. 3 требует слот проекта
  и для подмодулей, но не говорит, кому отдавать токен. Вопрос Оператору:
  ограничить помощник хостом адреса записи (`credential.<url>.helper` или
  сверка `host` в помощнике) и отказывать или не давать токен подмодулю на
  чужом хосте — или принять утечку как есть. Если ограничивать — нужен AC:
  подмодуль на другом хосте токен не получает.
- **Д-3 (AC-15 зависит от формы).** SPEC, требование 10 («форму выбирает
  разработчик»), AC-15. Либо форма фиксируется в SPEC, либо AC-15 говорит,
  что проверять при каждой форме. Например: подменённый git видит токен в
  вызове `git clone … --recurse-submodules` или в отдельном вызове
  `submodule update`, а подмодуль после подготовки извлечён в клоне.
- **Д-4 (неполное покрытие требований 3–4).** SPEC, AC-2, AC-4, AC-5. Не
  проверены:
  - отказ ссылке вне `refs/heads/*`, `refs/tags/*` и `artifacts_prefix`
    (например `refs/notes/x`);
  - пропуск удаления `refs/artifacts/<id>`;
  - отказ при ключе с пустым значением.

  Мутации «хук отказывает только тегам», «хук отказывает любому удалению»
  и «хук проверяет только наличие ключа» проходят все AC.

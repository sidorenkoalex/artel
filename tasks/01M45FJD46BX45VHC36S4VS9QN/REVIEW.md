## Замечания

- **major — SPEC.md задачи, раздел «Меняемое поведение», строка `…::test_mandate_marks_only_covered_findings`; код `scripts/guard.py` (`parse_behavior_change_line`, `_content_errors`).**
  - Суть. Строка `` `self.assertIsNone(...)` для всех трёх случаев → `отказ (не None) для ANSWER-1 и ANSWER-3, None для ANSWER-2` `` несёт текст вне обратных кавычек. Новый guard отклоняет её: `python3 scripts/guard.py <SPEC.md>` возвращает код 1, «текст … вне пар».
  - Сценарий поломки. После мержа пульт кладёт снимок артефактной ветки в `tasks/<id>/` на main (так сделано в коммите f30d7b22 для предыдущей задачи). На пуше в main CI-джоб `guard` выполняет `python3 scripts/guard.py --all` (`.github/workflows/ci.yml:44`) уже с новым кодом и краснеет на SPEC этой задачи. Сегодня `guard --all` на ветке зелёный («ок (1450 файлов)») только потому, что SPEC задачи ещё не в дереве. Есть и второй путь: если pin пульта обновится до мержа этой задачи, полная проверка guard на гейте мержа откажет её собственным документам.
  - Решение. Код здесь прав, неверна строка SPEC. Нужна правка строки Оператором до мержа, см. «Эскалация». Ослаблять проверку формы ради этой строки нельзя.
- **minor — `scripts/guard.py` (`_LiteralMasker`, `_expectation_pairs`, `_constant_roles.single`).**
  - Суть. Отрицательное число в исходнике — `UnaryOp(USub, Constant)`, а маскируется только `Constant`. Проверено прогоном:
    - `assertEqual(x, -2)` → `-3` даёт фактическую пару `(2, 3)`, объявленная честная пара `` `-2` → `-3` `` не совпадает, отказ «не совпала»;
    - `1` → `-1` даёт «иная смена формы», то есть ослабление;
    - `assertGreater(x, -5)` → `-3` даёт «правило не умеет оценить строгость».
  - Сценарий. Каждая объявленная смена с отрицательным числом попадает в эскалацию. Хуже того, отказ подсказывает «фактически `2` → `3`», и объявление такой ложной пары пройдёт сверку. Отказ fail-closed, пропуска ослабления нет, поэтому это minor.
  - Решение. Маскировать `UnaryOp(USub/UAdd, Constant)` как один литерал со значением `-c`, тем же приёмом, что `equality()` уже разворачивает унарный знак. Делать это в этой задаче либо отдельной задачей — на выбор Оператора (вопрос 2).

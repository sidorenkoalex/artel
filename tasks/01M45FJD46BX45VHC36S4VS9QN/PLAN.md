# PLAN: Смена поведения в существующих тестах без эскалации; ослабление — по-прежнему мандатом

## Подход

Изменённые утверждения метода, сохранившего имя, переходят из наблюдения
в узел отказа гейта неослабления, кроме смены ожидания, объявленной в
разделе SPEC «Меняемое поведение» и доказанной двусторонним прогоном.

- **Правило — в `scripts/guard.py`** (требования 1-2, 5, 9). Разбор раздела
  (`behavior_change_items`/`parse_behavior_change_line`) подключён в
  `_content_errors` для `type: spec` — значит, работает и в CLI, и на
  `spec_writing -> spec_gate` (`fsm.guard_refuses` зовёт `check_content`).
  Различение — публичная `assertion_changes` рядом с
  `changed_test_assertions`, на тех же нормальных формах
  (`_own_assertions` теперь отдаёт и узел нормальной формы, а
  `test_assertions` строится из общего `_assertion_records` — ответ прежний
  байт-в-байт). R/A — мультимножества; утверждения R сопоставляются
  свободным утверждениям A с равной маскированной формой (константы → одна
  метка) по порядку появления. Строгость — по роли позиции константы в
  нормальной форме (`_constant_roles`: равенство, допуск, регулярное
  выражение, вхождение, порядок; отрицание `assertFalse`/`not`, сторона
  константы в сравнении порядка); константа без роли — признак «правило не
  умеет оценить строгость». Сверка пар по типу и значению —
  `literal_pair_keys`/`value_pair_keys`.
  Отступление в пользу здравого смысла: сравниваемые значения
  `assert[Not]AlmostEqual` и первый аргумент `pytest.approx` отнесены к
  «равенству» (смена значения строгость не меняет), допуск оценивается
  отдельно; элементы литералов-контейнеров (`[1, 2]`) у равенства — тоже
  равенство.
- **approve гейта SPEC** (`fsm._behavior_change_declaration`, требование
  3): только артель и не канарейка; голова `origin/main` клона задачи (как
  у `gitcmd.diff_base`), иначе локальный `main`; нет файла/метода/ответа
  git — мягкий отказ «approve отклонён» тем же каналом, что сверка путей.
  Успех — запись «объявлена смена поведения тестов», строки раздела как
  есть (по одной на метод, через `\n`), чтобы узел разбирал их тем же
  `parse_behavior_change_line` (требование 4: объявленное — из ПОСЛЕДНЕЙ
  такой записи, не из текущего SPEC).
- **Узел `advance_gates/test_integrity.py`** (требования 6-8, 11-12): один
  проход `_compare` (теперь `Comparison`) собирает и изменения по методам,
  и тексты файлов для храповика; `_evaluate` без журнала даёт находки,
  исходы по методам и перечень исхода 7а — его зовут оба рубежа и
  ревью-пакет. Находка об утверждениях — `Finding(путь, Класс::метод,
  "Класс::метод: <причина>", alias)`, то есть мандат покрывает её тем же
  `Finding.mandate_elements`. Храповик — только при пустом остатке; на
  гейте мержа метод 7а без записи «двусторонний прогон пройден» для
  текущей головы — находка. Публичная `ratchet_finding(base, head,
  mandate)` — контракт ANSWER-1 (AC-26 на уровне функции).
- **Двусторонний прогон — новый модуль `advance_gates/two_sided.py`**
  (требование 10): два `git worktree add --detach` в клоне задачи во
  временном каталоге, по одному прогону pytest на сторону по узлам всех
  методов 7а, команда и окружение — `acceptance._pytest_command`/
  `_pytest_env`, таймаут — `config.TWO_SIDED_PYTEST_TIMEOUT_SEC`. Класс и
  фазу исхода пишет крошечный плагин pytest, выкладываемый во временный
  каталог под уникальным именем (корень пульта в `PYTHONPATH` заслонил бы
  пакет `orchestrator` проверяемого дерева). `setUp` unittest исполняется у
  pytest в фазе call, поэтому плагин отмечает кадр `setUp` в трассе.
  Уборка — `finally`; любой сбой — отказ (fail-closed).
- **Ревью-пакет** (требование 13): `review._changed_assertions_part` берёт
  `test_integrity.review_lines` — прежняя строка наблюдения + исход рубежа
  + «было → стало (требование N)» + итог двустороннего прогона для текущей
  головы; текст «переход и мерж от них не зависят» заменён текстом
  требования 13.
- **Существующие тесты** (требование 16): правка ровно методов раздела
  «Меняемое поведение» SPEC и фикстуры `EarlyReturnFindingTest`. Смена
  утверждений восьми методов раздела покрыта мандатом Оператора
  `tasks/01M45FJD46BX45VHC36S4VS9QN/ANSWER-2.md` (вариант (а), строка
  «Ослабление тестов разрешено: …» по каждому из восьми методов); методы
  не удалены и не переименованы. Фикстура раннего return правит в голове
  модуль (`EXTRA = 1`), а не утверждение — мандат ей не нужен.

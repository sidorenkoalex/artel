# SPEC: Отбор циклов на старом коде не зависит от погрешности времени процесса в ОС

## Контекст
CI main красный с 085b3ab1: долгоживущий тест
`tests/test_01m3y75gcresc2kds9vprjk4ps_stale_cycles.py::PinUpdateSelectionTest::test_ac3_cycle_started_after_shift_is_not_named`
падает на Linux-раннере (прогоны 37029861705, 37030340144, 37030343176).
`orchestrator/doctor/stale_cycles.py::stale_cycles` (строки 69–92)
оставляет цикл в перечне при `process_start_time(pid) < pin_moment`, а
`process_start_time` (строки 29–52) читает `ps -o lstart=`. Это время
округлено вниз до секунды. На Linux к нему добавляется вторая потеря
(`btime` из `/proc/stat` в целых секундах), и в сумме старт выходит раньше
настоящего почти на 2 с. Поэтому цикл, запущенный через `GAP_SEC = 1.5` с
после сдвига пина, называется работающим на старом коде. Тот же дефект
есть в боевой работе пульта на Linux. На macOS `lstart` только округлён
вниз до секунды. Пока тест красный, `pin-update` и гейты мержа видят
красный CI main.

Решение по способу (ТЗ, п.1 — выбор за аналитиком):

- **Вариант (а) отклонён.** Метки самого пульта для момента старта цикла
  сейчас нет. В `leases` есть только `heartbeat_ts`, а он обновляется по
  ходу работы и момента старта не хранит. Чтобы такая метка появилась,
  нужна новая колонка или запись в `orchestrator/store.py` и
  `orchestrator/lease.py`. Схема БД по ТЗ «не входит», оба модуля — только
  для чтения.
- **Выбран вариант (б) с точным источником на Linux.** Время старта
  берётся с известной погрешностью источника, то есть как интервал
  возможного настоящего старта. Цикл, у которого этот интервал накрывает
  момент сдвига, называется с пометкой «время старта не различимо от
  сдвига». Если брать на Linux только допуск ~2 с к `ps`, поздний цикл
  долгоживущего теста AC-3 (старт через 1,5 с после сдвига) попал бы в
  пограничные и был бы назван, а утверждение AC-3 — «не назван». Поэтому
  на Linux основным источником служит таблица процессов с субсекундной
  точностью (`/proc`), а `ps -o lstart=` остаётся запасным источником с
  допуском 2 с.
- **Цена решения.** (1) Для Linux появляется отдельный путь чтения
  времени старта. (2) Пока источник — `ps` (на macOS всегда), цикл,
  стартовавший в пределах ~2 с до или после сдвига, называется с
  пометкой, а не однозначно. (3) Перечень может получить строки нового
  вида, с пометкой. Решение о перезапуске остаётся за Оператором, как и
  сейчас.

## Требования
1. Время старта процесса цикла определяется вместе с погрешностью
   источника, то есть интервалом возможного настоящего старта:
   - на Linux, когда таблица процессов `/proc` доступна, — с погрешностью
     не больше 0,1 с в обе стороны;
   - иначе по `ps -o lstart=` (на любой ОС): настоящий старт не раньше
     ответа `ps` и меньше чем на 2 с позже него;
   - ни один источник не дал ответа — время неопределимо, как сейчас.
2. Отбор `stale_cycles` раскладывает живой цикл этой машины в один из
   четырёх классов. Решение одно для обоих потребителей: `pin.cmd_pin_update`
   и проверки `doctor` `check_stale_cycles`.
   - весь интервал старта раньше момента сдвига пина — «старый»: в
     перечне, как сейчас;
   - весь интервал не раньше момента сдвига — «новый»: в перечень не
     входит;
   - интервал накрывает момент сдвига — «пограничный»: в перечне с
     пометкой «время старта не различимо от сдвига»;
   - время неопределимо — в перечне с пометкой «не удалось определить»,
     как сейчас.
3. Строка пограничного цикла несёт те же поля, что строка старого: id
   задачи, pid, время старта процесса, состояние задачи и команды
   `stop <id>` и `auto <id>`, у наблюдаемого цикла — с `--client`/`--chat`.
4. Огрубление времени старта, будь то двойная потеря секунды `lstart` на
   Linux или округление вниз на macOS, не включает молча в перечень цикл,
   стартовавший после сдвига: такой цикл либо не назван, либо назван с
   пометкой из требования 2.
5. Долгоживущий тест AC-3 задачи 01M3Y75GCR детерминированно зелёный на
   Linux-раннере CI. `GAP_SEC` в нём не увеличивается, его утверждения не
   ослабляются.
6. Регрессионный тест лежит в новом файле
   `tests/test_stale_cycles_start_precision.py`, его докстринг содержит
   «Ловит мутацию: …». Сценарий теста: время старта по `ps -o lstart=`
   огрублено так, как его отдаёт Linux, то есть на 2 с раньше настоящего,
   а цикл стартовал после сдвига. Тест проверяет, что этот цикл не входит
   в перечень молча.

## Критерии приёмки
AC-1. На Linux с доступной `/proc` живой цикл этой машины, чей процесс
стартовал больше чем на 0,1 с позже момента сдвига пина, не назван ни в
выводе и журнале `pin-update`, ни в предупреждении `doctor` «циклы на
коде старше пина».

AC-2. Время старта цикла берётся из `ps -o lstart=` (точного источника
нет). Если ответ `ps` раньше момента сдвига, а ответ плюс 2 с не раньше
его, цикл назван в перечне `pin-update` и `doctor` с пометкой «время
старта не различимо от сдвига». Строка такого цикла содержит id задачи,
pid, время старта, состояние задачи и команды `stop <id>` и `auto <id>`.

AC-3. Время старта по `ps -o lstart=` отдано на 2 с раньше настоящего, а
цикл стартовал после сдвига пина. Такой цикл не назван в перечне без
пометки «время старта не различимо от сдвига»: он либо не назван, либо
назван с этой пометкой.

AC-4. Цикл, весь интервал старта которого раньше момента сдвига, назван в
перечне, как до задачи, без пометки «время старта не различимо от
сдвига». Цикл с неопределимым временем старта назван с пометкой «не
удалось определить», и `pin-update` при этом завершается успешно.

AC-5. Тест
`tests/test_01m3y75gcresc2kds9vprjk4ps_stale_cycles.py::PinUpdateSelectionTest::test_ac3_cycle_started_after_shift_is_not_named`
зелёный на Linux-раннере CI ветки задачи. `GAP_SEC` в файле равен 1.5, а
утверждения теста те же, что в main 5e8d6bc7.

AC-6. Файл `tests/test_stale_cycles_start_precision.py` существует, его
тест разыгрывает сценарий AC-3 (огрубление `lstart` на 2 с раньше
настоящего, цикл после сдвига), а докстринг теста содержит «Ловит
мутацию: …».

## Не входит
- Изменение порядка шагов `pin-update`: сверка CI до сдвига, отчёт о
  циклах после.
- Изменение схемы БД, в том числе метка момента старта цикла в `leases`
  (по этой причине отклонён вариант (а)).
- Отправка сигналов циклам. `pin-update` и `doctor` по-прежнему только
  называют циклы.
- Правка `orchestrator/store.py`, `orchestrator/lease.py`,
  `orchestrator/liveness.py`, `orchestrator/doctor/__init__.py`,
  `tests/test_invariants.py`, прочих файлов `tests/` вне зон, `skills/`,
  `docs/adr/`, `docs/invariants.md`, `tasks/` (по ТЗ — только чтение).
  Долгоживущий файл задачи 01M3Y75GCR правится только через
  `amend-tests` Оператора с точным списком и только если без этого не
  обойтись. Выбранный способ рассчитан на то, чтобы обойтись.
- Увеличение `GAP_SEC` как способ починки.
- Полный зелёный набор `tests/` и зелёный CI ветки: их держит пульт.

# ТЗ: Отбор циклов на старом коде не зависит от погрешности времени процесса в ОС

Источник: строки копилки 02.10 «Нестабильный тест планки 01M3Y75GCR AC-3» (П2) и «Предсказанный риск сбылся» (П1); решение Оператора 02.10. Задача чинит красный main.

Факты (origin/main 5e8d6bc7; номера строк аналитик сверяет):
- CI main красный с 085b3ab1: тест `tests/test_01m3y75gcresc2kds9vprjk4ps_stale_cycles.py::PinUpdateSelectionTest::test_ac3_cycle_started_after_shift_is_not_named` упал на трёх коммитах подряд (прогоны 37029861705, 37030340144, 37030343176; остальные 3862 теста зелёные). Раньше на ветке 01M3Y75GCR — один провал из трёх прогонов (37019693646). Локально на macOS зелёный стабильно.
- Механизм: `orchestrator/doctor/stale_cycles.py::stale_cycles` (около строки 69) оставляет цикл в перечне, если `process_start_time(pid) < pin_moment`. `process_start_time` (около строки 29) читает `ps -o lstart=` — время с точностью до секунды, отброшенной вниз. На Linux `lstart` считается как время загрузки (`btime` из `/proc/stat`, тоже целые секунды вниз) плюс тики старта процесса; две потери до секунды каждая дают старт раньше настоящего почти на 2 с. Тест запускает «поздний» цикл через `GAP_SEC = 1.5` с после сдвига пина — на Linux его старт по `ps` оказывается раньше `pin_moment`, и цикл называется как работающий на старом коде. Пример (37029861705): ранний цикл 15:52:11Z, поздний 15:52:14Z — назван.
- Тот же дефект и в работе пульта на Linux-машине: цикл, запущенный в первые ~2 с после сдвига пина, будет назван ложно. На macOS `lstart` точен (боевая машина Оператора).
- `pin-update` и гейты мержа сверяют цвет CI main — пока тест красный, пин не сдвигается, а каждый мерж оставляет main красным.

Требуется:
1. Отбор «цикл стартовал до сдвига пина» не даёт ложного включения цикла, стартовавшего после сдвига, из-за огрубления времени старта процесса в ОС — на Linux и на macOS. Способ выбирает аналитик; варианты для оценки: (а) сравнение не времени ОС с часами, а меток самого пульта (момент взятия lease/запуска цикла, записанный пультом, против записи журнала «pin обновлён»), с `ps` только как запасной источник; (б) сравнение с явным допуском на огрубление `lstart`, где пограничный цикл (в пределах допуска) называется отдельной пометкой «время старта не различимо от сдвига», а не молча включается или исключается. Решение и его цена — в SPEC.
2. Поведение для явно старых циклов (стартовавших заведомо до сдвига) и для цикла с неопределимым временем старта не меняется: они в перечне, как сейчас.
3. Долгоживущий тест AC-3 задачи 01M3Y75GCR зелёный на Linux-раннере CI детерминированно (не за счёт увеличения паузы: увеличение `GAP_SEC` — не решение). Если без правки этого долгоживущего файла не обойтись — правка через `amend-tests` Оператора с точным списком; утверждения AC-3 не ослабляются.
4. Регрессионный тест в новом файле с «Ловит мутацию: …»: время старта процесса, огрублённое так, как его отдаёт Linux (`lstart` на 2 с раньше настоящего), для цикла, стартовавшего после сдвига, не включает его в перечень молча.

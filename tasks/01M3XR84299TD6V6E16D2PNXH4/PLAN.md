# PLAN: Правило о тестовых методах в tests/ и счёт его срабатываний

## Подход
- Правило — новый пункт раздела «## Тесты» `skills/coding-standards.md`
  сразу после пункта о долгоживущих файлах задачи. Путь защищённый —
  правка идёт «Приложением» ниже; в кодовой ветке скил не меняется.
- `scripts/test_rule_stats.py` — черновик Оператора из ТЗ, приведённый к
  скилу и идиоме `scripts/`:
  - путь БД — `config.DB` (тот же `.artel/state.db`), соединение URI
    `file:…?mode=ro` через `sqlite3.connect` — запись отказывается на
    уровне SQLite (AC-9); `store.db()` не используется: он мигрирует схему;
  - строка отказа гейта — импорт `TEST_INTEGRITY_REFUSAL_ACTION` из
    `orchestrator/advance_gates/test_integrity.py`, а не копия строки:
    переименование действия не обнулит счёт молча;
  - окно: журнал — `ts >= 'YYYY-MM-DD'` (ts в UTC, формат `store.now`);
    мержи — время коммиттера `%ct` против полуночи UTC дня `--since`, а
    не `git log --since` (разбор даты без времени зависит от пояса и
    текущего времени суток машины) (AC-3);
  - мержи — `git log origin/main --merges --first-parent`, id задачи — из
    темы мержа пульта `<id>: …` по регулярке; мерж без id в теме в счёт не
    идёт (черновик брал «всё до двоеточия» и давал мусорный id); статус
    `M` в `git diff --name-status <sha>^1 <sha> -- tests/` (AC-5);
  - группы 1/3 — по первой эскалации разработчика с перечнем
    `tests/\S+\.py::\w+::\w+` и первому отказу гейта; эскалация после
    отказа — группа 3 (AC-4, AC-6); группа 4 — по действию записи
    (AC-7); строка «Порог триггера №31 достигнут» — только при непустой
    группе 3 (AC-8);
  - fail-closed: нет БД / сбой SQLite / сбой git — код 2 и причина в
    stderr, без сводки (нулевая сводка читалась бы как «правило работает»);
    неверная `--since` — ошибка argparse.
  - Вывод: «N. <группа>: <число>» и id задач строками с отступом —
    формат, который читает долгоживущий файл задачи.
- Тесты: долгоживущий `tests/test_01m3xr84299td6v6e16d2pnxh4_rule_stats.py`
  (не правится) покрывает AC-3…AC-9; свой `tests/test_test_rule_stats.py`
  — только непокрытое: fail-closed на отсутствующей БД, отказ на неверной
  дате, мерж без id в теме не в фоне. Песочница переиспользуется импортом
  `RuleStatsSandbox` из долгоживущего файла.

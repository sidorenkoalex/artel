# PLAN: занятость зоны — только по старту developer (регрессия 01M1REVJ8AJ)

## Подход
`zone_lock._occupies` (orchestrator/zone_lock.py:187-196) считает
занятостью запись `"agent run started"` ЛЮБОГО актора — регрессия
01M1REVJ8AJ. Фикс точечный: `_visit_has_action` получает необязательный
параметр `actor` — при передаче сверяет `row["actor"]` с ним, при
отсутствии (по умолчанию `None`) ведёт себя как раньше. `_occupies`
зовёт его с `actor="developer"` для `_AGENT_STARTED_ACTION` и БЕЗ
фильтра для `RELEASE_ACTION` (требование 1: фильтр роли применяется
только к первой записи). Никакой отдельной новой функции не заводится —
`_visit_has_action` уже параметризована по действию, актор — тот же
класс параметра.

Архитектурно не значимо, ADR не требуется — сужение одного условия
внутри уже существующей функции.

## Шаги

1. `orchestrator/zone_lock.py`: параметр `actor` в `_visit_has_action`,
   вызов из `_occupies` с фильтром `developer` для `agent run started` и
   без фильтра для `RELEASE_ACTION`; правка докстрингов модуля/функции,
   упоминающих старое поведение («агент какой угодно роли»), под новое.
2. `tests/test_zone_lock.py`: новый тест-класс, буквально
   воспроизводящий регрессию (AC-7) — граница пребывания пройдена, в
   том же пребывании старт актором `test_author`, старта `developer`
   нет вовсе, сосед с пересекающейся зоной не блокируется. Существующие
   тесты не трогаю (AC-6, они уже журналируют `"developer"` явно).

## Влияние на систему

Правка сужает ОДИН булев признак внутри `_occupies` — не трогает
`_stay_since_id` (границу пребывания), `RELEASE_ACTION`, очередь
(`queue_order`/`queue_position`/`cmd_zone_reorder`) и внешние target'ы
— всё это явно «Не входит» SPEC. `blocking_conflict`/`refusal`
переиспользуют `_occupies` без изменений сигнатуры — вызывающий код
(`catalog.py`, `doctor.py`, `runner.py`/`auto.py`) не меняется.

Существующие тесты `tests/test_zone_lock.py` (в т.ч.
`_mark_already_started`, журналирующий актора `"developer"` явно) и
`tests/test_zones_gate.py` не затронуты правкой сигнатуры вызовов —
проверено прогоном (см. ниже), AC-6 закрыт без правки их ассертов.

Откат — тривиален: убрать параметр `actor`/фильтр, вернуть старый вызов
`_visit_has_action(conn, task_id, since_id, _AGENT_STARTED_ACTION)`.

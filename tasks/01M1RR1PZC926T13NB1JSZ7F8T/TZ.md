# ТЗ: занятость зоны — только по старту developer (регрессия задачи 01M1REVJ8AJ)

Источник: диагностика 05.09 при проверке возможности запуска задачи
01M1RFVWV6WWTXRC5F40K61632. После мержа 01M1REVJ8AJDKAMK5VTKES5J6D
(коммит d617c148, в пине с 10:57Z) `zone_lock._occupies` считает
задачу занимающей зоны, если после границы пребывания (`state ->
tests_writing`) есть любая запись `"agent run started"` — без сверки
роли. Прогон test_author идёт сразу после входа в `tests_writing`, то
есть КАЖДАЯ задача с планкой «занимает» зоны ещё до первого шага
developer, а занимающая задача по `blocking_conflict` никогда не
блокируется. Итог: механика зон выключена для всех задач с планкой.
Факт по журналу 05.09: у 01M1RFVWV6 и 01M1R5B33C (общие зоны
`orchestrator/doctor.py`, `orchestrator/fsm_postmerge.py`) developer не
стартовал ни у одной, `_occupies` — True у обеих, `blocking_conflict` —
None у обеих; в 10:41Z (старый пин) та же пара давала честный отказ
«зона doctor.py занята». SPEC 01M1REVJ8AJ, требование 1 и AC-1/AC-2,
говорят буквально «`agent run started` РОЛИ developer»; планка задачи
пропустила дефект, потому что её песочница журналировала старт без
прецедента test_author в том же пребывании.

Требуется:
1. `zone_lock._occupies` (через `_visit_has_action` либо отдельной
   проверкой) считает признак занятости только по записям `"agent run
   started"` с `actor == "developer"` после границы пребывания;
   `RELEASE_ACTION` — как сейчас. Записи analyst/test_author/reviewer
   признаком не являются.
2. Семантика SPEC 01M1REVJ8AJ (ждущая задача зон не держит, владелец
   остаётся владельцем до `done`/`killed`, возврат из ревью не
   перепроверяет) не меняется — меняется только фильтр роли.
3. Тесты: задача с прогоном test_author после `tests_writing` и без
   старта developer НЕ занимает зоны и НЕ блокирует соседа с
   пересечением; задача со стартом developer занимает; задача со
   `RELEASE_ACTION` занимает; `refusal` называет владельца по
   обновлённому фильтру; планка 01M1REVJ8AJ и `tests/test_zone_lock.py`,
   `tests/test_zones_gate.py` зелёные без правки ассертов. Песочница
   тестов журналирует старт test_author в том же пребывании — иначе
   тест не отличим от планки, пропустившей дефект (принцип «тест
   обязан ловить заявленную мутацию»).
4. Копилка/скил (приложением к PLAN, защищённый путь не трогать):
   класс дефекта «маркер журнала без сверки роли» — в
   `skills/test-authoring.md` строкой про фикстуры журнала с чужими
   ролями в том же пребывании, если разработчик сочтёт нужным.

Зоны: orchestrator/zone_lock.py, tests/. Порядок: срочно, до запуска
developer у задач с пересекающимися зонами (сейчас — 01M1RFVWV6 и
01M1R5B33C); класс — частичная поломка запущенной версии (ADR-0013 п.2:
hotfix конвейером, не аварийный режим).

Не входит: очередь ожидания и её порядок; зоны внешних target; изменение
границы пребывания (`state -> tests_writing`).

Рамка: $15.

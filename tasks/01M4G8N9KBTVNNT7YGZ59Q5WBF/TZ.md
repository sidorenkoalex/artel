# ТЗ: Гейт неослабления тестов видит утверждения в унаследованных помощниках и в tests/sandbox.py

Источник: строка бэклога «Гейт неослабления видит утверждения в
помощниках» (приоритет 1), находка TR-22 ревизии тестов 05.10
(`docs/audits/tests-revision-2026-10-05.md` ~286–298); решение Оператора
09.10.2026 — заводить параллельно с 01M4FYTB8QWJNHYCP35K8QC4E3.

Факты (main af5e1111, сверка 09.10):
- Утверждения тестового метода собирает `_assertion_records`
  (`scripts/guard.py` ~927, по TR-22): помощники ищутся только среди
  методов того же класса (`class_methods[owner]`) и функций модуля.
  Помощник, унаследованный от базового класса (песочницы того же файла
  или `tests/sandbox.py`), не учитывается: 525 вызовов таких помощников с
  утверждениями в 56 файлах; 9 методов выглядят для гейта как методы без
  утверждений (например
  `tests/test_01m41ab597b330p2rcxcmvrzpe_docs_ref_refixation.py:441`, вся
  проверка — в `check_advance_incident` класса `DocsRefSandbox`).
  Утверждения помощников `tests/sandbox.py` (например
  `assert_acceptance_run_called`) не видны тоже.
- Следствия: ослабление утверждения внутри такого помощника гейт не
  ловит; вынос проверок из метода в унаследованный помощник или в
  `tests/sandbox.py` гейт считает убылью утверждений.
- Гейт — `orchestrator/advance_gates/test_integrity.py` (сравнение базы и
  головы, наблюдение изменённых утверждений, храповик `_counts`/
  `_ratchet_decline`, мандат ANSWER). Правила находок — `docs/operator-gates.md`,
  «Гейт merge», п.4: перенос утверждения в помощника, которого метод
  зовёт напрямую, и обратно — не находка.

Требуется:
1. Сбор утверждений метода учитывает помощники, найденные по наследованию
   классов внутри `tests/` (в том числе базовые классы из
   `tests/sandbox.py` и других модулей `tests/`) и функции `tests/sandbox.py`,
   вызванные методом напрямую — на той же глубине, что сегодня для
   помощников своего класса.
2. Ослабление утверждения внутри такого помощника (удаление, смена вида,
   смена аргумента — по правилам п.4 «Гейта merge») — находка у каждого
   метода, который его вызывает; текст находки называет помощника и его
   файл.
3. Перенос утверждения из метода в унаследованный помощник или в
   `tests/sandbox.py` и обратно — не находка и не убыль храповика.
4. Мандат ANSWER на путь помощника (`tests/sandbox.py` или файл базового
   класса) снимает находки в его помощниках; формат мандата не меняется.
5. Методы, у которых утверждения есть только в унаследованных
   помощниках, перестают считаться методами без утверждений; итоговое
   число таких методов на main — в PLAN (до и после).
6. `docs/operator-gates.md`, п.4 «Гейта merge»: что гейт теперь видит в
   помощниках, одним абзацем.

Критерии приёмки (направление; планку пишет test_author):
- Удаление `assert…` в помощнике базового класса из другого модуля
  `tests/` даёт находку у вызывающего метода с именем помощника.
- Удаление утверждения в функции `tests/sandbox.py` даёт находку у
  вызывающих методов; мандат на `tests/sandbox.py` её снимает.
- Перенос утверждения из метода в унаследованный помощник — без
  находки и без убыли храповика.
- Метод, проверяющий только через унаследованный помощник, не
  числится методом без утверждений.
- Существующие находки и наблюдения гейта на прежних сценариях не
  меняются (долгоживущие тесты гейта зелёные без правки утверждений).

Зоны: orchestrator/advance_gates/test_integrity.py, scripts/guard.py,
docs/operator-gates.md, docs/codebase-map.md, tests/.

Только чтение (не менять): tests/sandbox.py (помощники песочницы не
переписываются ради гейта), tests/test_invariants.py,
orchestrator/runner.py, orchestrator/auto.py, orchestrator/fsm.py,
orchestrator/acceptance.py, docs/adr/, docs/invariants.md, AGENTS.md,

Не входит: глубина вызовов помощников больше одного уровня; утверждения
в помощниках вне `tests/`; сетевые адреса в тестах (отдельная строка
бэклога, тоже в `scripts/guard.py` — пойдёт после этой задачи).

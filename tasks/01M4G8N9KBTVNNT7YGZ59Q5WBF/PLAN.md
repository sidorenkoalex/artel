# PLAN: Гейт неослабления тестов видит утверждения в унаследованных помощниках и в tests/sandbox.py

## Подход
Свойство меняется в одном месте — в сборе утверждений `scripts/guard.py`
(`_assertion_records`), а три потребителя гейта (наблюдение изменённых
утверждений, храповик `_counts`, мандат) получают его через общий проход
`_compare` в `orchestrator/advance_gates/test_integrity.py`.

- **Сбор (guard).** Новый `guard.TestModules(load)` — модули `tests/`
  одной стороны сравнения с кэшем разбора. `_HelperScope` разрешает имена
  по импорту `tests.<…>` (`from tests.x import B as C`, `from tests import
  sandbox`, `import tests.x as y`, относительный импорт от пакета файла) и
  обходит базовые классы в глубину слева направо с памятью пройденных
  (цикл не роняет). `self.<имя>(…)` ищется сначала в своём классе (прежняя
  форма), затем по базовым классам (тот же файл, другой модуль `tests/`,
  `tests/sandbox.py`); голое имя — функция своего модуля, иначе функция
  `tests/sandbox.py` (голым именем или `sandbox.<fn>`). Глубина — один
  уровень вызова, как прежде. Запись утверждения несёт происхождение:
  `None` у прежних видов, (`Класс.метод`/`fn`, путь файла) у новых;
  `AssertionChange.origins` — происхождение каждого изменённого
  утверждения base. `test_assertions`/`assertion_changes` получили
  необязательные `path`/`modules`; без них поведение прежнее, кроме
  базовых классов своего файла (требование 1 их включает).
- **Гейт (test_integrity).** `_compare` сначала читает весь дифф `tests/`,
  затем строит модули сторон (`_side_modules`: файл диффа — текст своей
  стороны, файл вне диффа — одно чтение из головы, он одинаков по обе
  стороны) и сравнивает с ними. Вызывающие вне диффа: `guard.
  weakened_helpers` называет функции/методы файлов диффа, потерявшие
  утверждение; `git grep -l -w -F` по этим именам в `tests/` головы даёт
  кандидатов, каждый кандидат сравнивается сам с собой при модулях base и
  head. Сбой `git grep` (код не 0/1) и чтения кандидата — тот же «git не
  ответил», что у остальных чтений узла (fail-closed на переходе,
  fail-open на мерже). Поиск вызывающих идёт только при ослабленном
  помощнике — обычный дифф лишних вызовов git не получает.
- **Текст находки** (требование 2): хвост «(помощник Base.check из
  tests/x.py)» у находки и у строки наблюдения, только если изменены
  утверждения помощников новых видов — прежние строки (AC-5) байт в байт.
- **Мандат** (требование 4): `Finding.helpers` — путь файла помощника,
  если ВСЕ изменённые утверждения метода из помощников одного этого файла;
  элемент мандата с этим путём покрывает находку, наблюдение, исход 7а и
  убыль храповика (`_decline_source(…, helpers)`). Смешанная находка
  (своё утверждение рядом с утверждением помощника либо помощники двух
  файлов) путём помощника не снимается — fail-closed. Формат строки
  мандата не менялся.
- **Храповик** (требование 3): `_counts` считает с модулями стороны, по
  тем же файлам диффа, что и прежде; вызывающие вне диффа в счёт не
  входят (SPEC: «число утверждений диффа `tests/`»), их ослабление и так
  называет находка.

## Риски
- Поиск вызывающих по слову-имени помощника: частое имя (`setUp`, `run`)
  даёт много кандидатов — больше чтений git, но не ложных находок
  (каждый кандидат разбирается точно).
- Модуль-пакет `tests/<x>/__init__.py` и `import tests.x` с вызовом
  `tests.x.fn` разрешаются по общему правилу; цепочки длиннее
  `<модуль>.<имя>` (`tests.x.Class.method` как функция) не разрешаются —
  они вне требований.
- Метод, который в двух местах цепочки классов находит одноимённый
  помощник, берёт первый в обходе глубину-слева-направо — для ромбовидного
  наследования это может отличаться от MRO Python; в `tests/` таких
  иерархий не найдено.

  функции верхнего уровня в одном модуле (`scripts/`, `orchestrator/`).

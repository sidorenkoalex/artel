## Подход
`skills/` — защищённый путь, поэтому правка едет только приложением к PLAN
(`skills/conventions-core.md`, раздел «Git»). Кодовая ветка задачи остаётся
пустой относительно main. Приложение — один хунк `@@ -112,18 +112,21 @@`. Он
заменяет абзац `skills/test-authoring.md:114-126` текстом «Стало» из SPEC
01M551W0TFCT2XRQ71XFXJDKB9 («Материалы», «Готовый текст правки
`skills/test-authoring.md`»), который дословно приведён в SPEC этой задачи.
Диф собран машинно (`git diff --no-index` исходного файла и копии с
заменённым абзацем), а не руками, чтобы хедер хунка совпал с реальным
диапазоном. Строки 93-112 (правила статической проверки долгоживущего
файла) попадают в диф только как контекст и не меняются.

## Влияние на систему
Меняется только текст скила роли test_author, и только после того, как
Оператор применит приложение отдельным MR. Код, тесты, гейты и guard не
меняются: кодовая ветка относительно main пуста, `docs/codebase-map.md` не
регенерируется, потому что `*.py` не правились. Текст скила приводится в
соответствие с уже смерженным поведением пульта (каталог и шаблон
долгоживущих тестов из профиля проекта, 01M551W0TFCT2XRQ71XFXJDKB9). Ни
одно правило при этом не ослабляется: запреты на правку, переименование и
удаление файлов и на файл без префикса сохранены, меняется только адрес
каталога. Откат — revert MR Оператора с применённым приложением.

**Проверка применимости:** `git apply --check -v <диф приложения>` на чистом
дереве рабочей копии задачи, HEAD = main = 6fbeaa8de4918b479b4b66182e73303ee1c47382
(`git status --short` пуст). Результат: «Checking patch
skills/test-authoring.md...», код выхода 0, патч применяется.

## Риски

  не наложиться. Тогда понадобится пересборка дифа, текст «Стало» от этого
  не меняется.

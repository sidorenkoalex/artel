# PLAN: Уборка оборванной канарейки и отвязанный запуск

## Подход

Клон, origin-заглушка и временная копия базы получают маркер владельца с pid. Общие функции проверки маркера используются канарейкой и `doctor`. При выходе из клона канарейка читает `run.json` его `suite-run`, снимает группы указанных живых процессов и затем удаляет каталоги. Обработчик SIGTERM/SIGHUP прерывает ожидание ведения исключением; обычный путь `finally` выполняет уборку, а внешний путь записывает красную строку с именем сигнала. `--detach` запускает тот же CLI в новой сессии и передаёт ему путь результата.

Ревью R1-F1 закрыто привязкой живого `suite-run` к конкретной базе: современная копия несёт собственный маркер, а для копии без него `doctor` сверяет cwd pid из `run.json` с её путём. R1-F2 закрыто проверкой маркера origin до появления remote-связи; после связи владельцем origin считается связанный клон. При исправлении origin удаляется раньше связанного клона, сохраняя возможность повторной проверки.

## Риски

PID может быть переиспользован ОС; критерий SPEC основан на живости pid маркера, поэтому это остаточный риск до отдельного решения о более сильной идентичности процесса. Временный каталог может быть повреждён: удаление и снятие процессов не должны затрагивать группу самого `doctor`.

# ТЗ: Учёт стоимости шага при таймауте и обрыве потока

Учёт стоимости при таймауте/обрыве потока (строка беклога P3; прецеденты T022, T023, T037).

Проблема: стоимость шага снимается с финального события потока CLI (orchestrator/spend.py). Таймаут шага (T022: 30 минут = $0.00; T037 26.08: 30 минут developer = $0.00) или обрыв stdout-пайпа (T023: весь цикл из 6 агентных шагов = $0.00) теряют стоимость молча: события «agent cost UNKNOWN» в журнале есть, алерта нет, spent_usd занижен — бюджеты задач и стоп-лосс программы считают не всё.

Что сделать (вариант из беклога, выбрать в PLAN с обоснованием): при отсутствии финального события потока — (а) суммировать промежуточные события usage из stream-json лога шага, если они есть, и записать сумму как стоимость шага с пометкой «частичная»; и/или (б) при невозможности восстановить стоимость — событие журнала «стоимость шага неизвестна» + алерт alerts kind=incident (source вида spend.unknown_cost), чтобы недоучёт был виден, а не молчал. Минимум — (б); (а) — если промежуточные события реально несут usage (проверить по логам T037-developer-1.log).

Границы: механика бюджетов (enforce_budget, потолки, пороги программы) не меняется — меняется только полнота учёта; задним числом старые шаги не пересчитываются.

Критерии приёмки (ориентир): (1) шаг, завершившийся таймаутом, не записывается со стоимостью $0.00 молча: либо частичная сумма из промежуточных событий, либо событие «стоимость неизвестна» + открытый алерт kind=incident; (2) обрыв пайпа — так же; (3) нормальный шаг с финальным событием учитывается как раньше, алертов не заводит; (4) существующие тесты зелёные (правки — по правилам песочницы T037).

## Замечания

- minor — `orchestrator/runner.py:478` — `cause = "таймаут шага" if timed_out else "обрыв stdout-пайпа"` жёстко приписывает ветке `pump.error is not None` единственную причину «обрыв stdout-пайпа», хотя `pump.error` — сигнал куда шире: он же взводится при сбое ОТКРЫТИЯ файла лога (`agent_log.py: stream_to_log`, `except OSError: tee_lines(...); raise` → `OutputPump.run` ловит как `self.error`), а не только при реальном обрыве самого stdout-пайпа. Существующий код `close_pump` для того же `pump.error` пишет нейтральное «лог не записан: {pump.error}» (`orchestrator/runner.py:530`), не называя причину. Сценарий поломки: диск полон / нет прав на каталог логов во время шага → `pump.error` = `OSError` от `open()`, шаг успешно завершается (rc=0, `pump.cost` не пришёл по не связанной причине) — событие и алерт `spend.unknown_cost` получат текст «обрыв stdout-пайпа», хотя пайп был цел, а сломался лог. Для целей SPEC (деньги не теряются молча) это не критично — запись и алерт всё равно появятся, — но неточная причина в тексте инцидента может увести расследование не в ту сторону. Предложение: либо взять текст причины из `close_pump`/generic «сбой перекачки потока» вместо специфичного «обрыв stdout-пайпа», либо явно сузить условие до случаев, когда `pump.error` — действительно ошибка чтения пайпа (например, различать по типу/источнику исключения).
- minor — `alerts.raise_alert` дедупит по точному совпадению `message`, а `message` в `charge_missing_result` содержит `numbered` («попытка N/M»). Для таймаута это не страшно (таймаут не ретраится — `numbered` в рамках задачи неизменен между запусками `run`, тест `test_repeated_identical_failure_does_not_duplicate_the_alert` это подтверждает). Но для обрыва stdout-пайпа с ретраями (`попытка 1/3`, `попытка 2/3`, ...) каждая попытка даёт свой текст → свой алерт, дедуп не сработает между попытками одного и того же шага. Не противоречит SPEC (алерт заводится «если восстановить нельзя», без ограничения на количество) и не блокер, но стоит иметь в виду при разборе будущих серий алертов — на один многоразовый обрыв пайпа может прийтись N алертов вместо одного.

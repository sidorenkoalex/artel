# SPEC: Merge-последовательность merge_gate через gitcmd.git

## Контекст
`orchestrator/fsm.py:440-449` — единственная git-последовательность
системы, идущая мимо эталонной обёртки `gitcmd.git`: четыре голых
`subprocess.run(["git", ...])` (checkout main, pull --ff-only, merge
--no-ff, push) в самом опасном месте — мерже задачи в main. Это мимо
единого шва тестируемости и обработки отказов, который для git-вызовов
уже существует (`gitcmd.git`, ADR/CR-2026-08-26-4). Задача класса
«рефакторинг» (правила T015): поведение не меняется, меняется только
механизм вызова git.

## Требования

1. Четыре вызова `subprocess.run(["git", ...])` в `merge_gate`-ветке
   `orchestrator/fsm.py` (checkout main, pull --ff-only, merge --no-ff,
   push) переводятся на `gitcmd.git`.
2. Поведение не меняется: тот же порядок команд, те же аргументы команд
   (в т.ч. текст сообщения мержа `f"{task_id}: merge {branch}"`), тот
   же рабочий каталог (`config.ROOT`), та же обработка результата
   (проверка `returncode`).
3. Текст записи журнала «merge FAILED» с хвостом `stderr` до 500
   символов не меняется.
4. Текст отказа `sys.exit` при провале команды и текст успешного
   перехода задачи в `done` не меняются.
5. Правки тестов допустимы только в путях патчей (мокать `gitcmd.git`
   вместо `fsm.subprocess.run`); сценарии и ассерты существующих
   тестов не меняются.
6. Никаких попутных изменений: соседние ветки `cmd_approve` (например,
   проверка `ci.branch_status`), тексты сообщений вне merge-
   последовательности, ретраи — вне зоны задачи.

## Критерии приёмки

AC-1. В fsm.py не остаётся прямых `subprocess.run(["git", ...])`.

AC-2. Отказ любой из четырёх команд по-прежнему пишет «merge FAILED» в
журнал и завершает CLI с тем же текстом.

AC-3. Успешный путь по-прежнему переводит задачу в `done` с той же
записью журнала.

AC-4. Все существующие тесты зелёные, правки в тестах — только пути
патчей.

## Не входит

- Изменение сигнатуры или поведения `gitcmd.git` самой по себе.
- Изменение соседних веток `cmd_approve` (проверка CI, переходы
  состояний вне merge-последовательности).
- Изменение текстов сообщений, добавление ретраев или иной новой
  логики обработки отказов.
- Правки за пределами `orchestrator/fsm.py` и путей патчей в тестах.

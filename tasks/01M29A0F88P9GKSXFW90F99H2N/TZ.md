# ТЗ: гейт заявки мутации: новые и изменённые тесты в tests/ без «Ловит мутацию» отклоняются на выходе in_dev, а не кругом ревью

Источник: копилка docs/backlog.md, строка П2 от 11.09 «Три задачи подряд
теряют круг ревью на одном и том же замечании» и её дополнения: шесть
задач за 11.09 (01M28NWK5X, 01M28NX43E, 01M28NX0M2, 01M290PP4K,
01M291EJMA, 01M29284PT) получили от ревьювера major «новый тест в
tests/ без заявки “Ловит мутацию: …” в докстринге». Цена круга на
задачу — ревьювер $1.3–3.7, шаг разработчика $1.1–1.9, ожидание CI
ветки около 8 минут; код при этом не менялся. Решение Оператора 11.09:
класс не закрывается напоминанием, нужна проверка кодом.

Факты:
- Правило сформулировано для test_author (skills/test-authoring.md,
  строки 47–63): в докстринге каждого тестового метода строка «Ловит
  мутацию: <что сломали — и тест покраснеет>». Ревьювер сверяет по
  review-checklist фаза B п.3 («каждый новый или изменённый тест»).
  Разработчик получает скилы conventions-core, escalation-rules,
  coding-standards (roles.yaml) — правила о заявке в них нет;
  skills/coding-standards.md — защищённый путь, правка Оператора.
- Канал обратной связи уже есть: отказ advance записывается в журнал
  (`fsm_advance._run_gates` → `store.journal(... refusal.action,
  refusal.detail)`), а следующий запуск роли получает его в промпте
  блоком «--- ОТКАЗ ADVANCE (история) ---» (`runner.py` строки
  370–379, `brief.advance_refusal_history`). Отказ гейта на
  `in_dev -> verifying` стоит один шаг разработчика (~$1) без ревьювера
  и без CI ветки.
- Сканер докстрингов по AST уже есть в scripts/guard.py:
  `module_docstring` (ast.parse, строки 340–354), `has_redness_marker`
  и `REDNESS_MARKER` (маркер «Красен до реализации:», строки 224–229,
  357–378) — тот же приём для докстрингов функций.
- Гейт зон в `fsm_advance._zones_gate` (строки 728–750) уже берёт базу
  сравнения `gitcmd.diff_base(t["branch"])` и список файлов
  `gitcmd.diff_names(base, branch)`; порядок гейтов на выходе `in_dev`
  — `in_dev()` (строка 1242): … `_zones_gate_refuses` →
  `_review_rework_gate_refuses` → `_origin_push_gate` →
  `_acceptance_run_refuses`.
- В `tests/` 131 файл, заявку несут 79: проверка всего каталога сделала
  бы CI красным; проверять можно только то, что задача добавила или
  изменила.

Требуется:
1. В scripts/guard.py — функция `test_functions_without_mutation_claim(base_source: str | None, head_source: str | None) -> list[str]`: по AST HEAD-версии файла собирает все функции и методы с именем `test_*` (на уровне модуля и внутри классов), берёт из них новые (имени нет в base_source или base_source is None — файл добавлен) и изменённые (текст сегмента функции в HEAD отличается от base), и возвращает имена тех, чей докстринг не содержит строки, начинающейся с «Ловит мутацию:» с непустым текстом после двоеточия; регулярное выражение — константа `MUTATION_CLAIM` по образцу `REDNESS_MARKER`. Файл HEAD не парсится (SyntaxError) — возвращается один элемент «<не парсится: текст ошибки>», не исключение.
2. В orchestrator/fsm_advance.py — гейт `_mutation_claim_gate(conn, task_id, t, branch) -> GateRefusal | None` на выходе `in_dev` сразу после `_zones_gate_refuses` и до `_review_rework_gate_refuses`: база `gitcmd.diff_base(branch)`, список файлов `gitcmd.diff_names`, отбираются только пути `tests/test_*.py`; содержимое base- и HEAD-версий читается из git (`git show <sha>:<path>`, удалённый в HEAD файл пропускается), для каждого зовётся функция из требования 1. Есть хотя бы одно имя — `GateRefusal` с action «переход отклонён: гейт заявки мутации», detail — перечисление «<файл>: <функция>, <функция>; …» и текст правила («каждый новый или изменённый тест в tests/ несёт в докстринге строку “Ловит мутацию: <что сломали — и тест покраснеет>”, skills/test-authoring.md»), hint — «допиши заявку и повтори artel.py advance <id>». Ошибки git (база или дифф не определились) — отказ с именованной причиной по образцу гейта зон, не пропуск.
3. Гейт не зовётся для канареечных задач (`t["is_canary"]`) и для задач с внешним target (`t["target"] != config.DEFAULT_TARGET`) — тем же условием, что и `_origin_push_gate`.
4. Отказ этого гейта доходит до следующего шага разработчика штатным блоком «ОТКАЗ ADVANCE (история)» без правки runner.py и brief.py; в ТЗ фиксируется как проверяемое свойство: после отказа `brief.advance_refusal_history(conn, task_id, "developer", "in_dev")` содержит перечисление файлов и функций из detail.
5. Тесты в tests/: функция guard — новая функция без заявки (красный), новая с заявкой (пусто), изменённая без заявки (красный), неизменённая без заявки (пусто — старые тесты не трогаем), метод класса без заявки (красный), заявка с пустым текстом после двоеточия (красный), непарсящийся HEAD (один элемент с текстом ошибки); гейт — отказ на ветке с новым тестом без заявки и проход с заявкой (репозиторий-стенд по образцу тестов гейта зон), отказ не зовётся для канарейки, отказ не зовётся при `t["target"]` вне DEFAULT_TARGET, файлы вне `tests/test_*.py` не проверяются; существующие тесты `fsm_advance.in_dev`, гейта зон и guard — без ослабления.

Зоны: scripts/guard.py, orchestrator/fsm_advance.py, tests/.

Приложением: skills/test-authoring.md (формулировка заявки), skills/review-checklist.md (фаза B п.3), docs/backlog.md (строка П2 от 11.09).

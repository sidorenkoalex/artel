# SPEC: гейты зон и ёмкости сравнивают ветку с точкой расхождения от origin/main, а не с локальным main целиком

## Контекст

Гейт зон (`orchestrator/fsm_advance.py::_zones_gate_refuses`) берёт
двухточечный `git diff --name-only main <ветка>`
(`gitcmd.diff_names(config.MAIN_BRANCH, t["branch"])`): любой коммит
`main`, ещё не влитый в ветку задачи, выглядит правкой самой задачи и
ложно отказывает переход как «вне зон» (стек ч.1 05.09: чужие
`docs/roadmap.md`, `docs/triggers.md`). Гейт ёмкости
(`_capacity_gate_refuses`) и полный diff ревью-пакета
(`review.git_diff_part` при `iteration == 1`) уже трёхточечные
(`base...branch`), но базой служит ЛОКАЛЬНЫЙ `config.MAIN_BRANCH` —
пин запущенной версии, который по построению отстаёт от `origin/main`,
тогда как ветка задачи подтягивает именно `origin/main`: точка
расхождения с локальным main старее, дифф включает чужие коммиты (05.09
гейт ёмкости — 303 КБ при устаревшем пине против 35 КБ после
pin-update). Три ложных отказа за день (бэклог 05.09, приоритет 1)
требуют одной точки правды для базы сравнения.

## Требования

1. Одна точка правды для базы сравнения — функция в
   `orchestrator/gitcmd.py` (например `diff_base(branch) -> str | None`):
   merge-base ветки задачи с `refs/remotes/origin/<MAIN_BRANCH>`, если
   такой ref есть в репозитории; если ref отсутствует (репозиторий без
   remote, песочница тестов) — merge-base с локальным
   `config.MAIN_BRANCH`. Функция не делает сетевых обращений (инвариант
   «тесты не выходят в сеть», 01M1QHQ277…): ref `origin/main` уже
   обновляется механикой подтяжки и входа в `verifying`. Git не ответил
   — `None`.
2. Гейт зон сравнивает ветку с этой базой трёхточечно (список файлов от
   merge-base до головы ветки); гейт ёмкости и полный diff ревью-пакета
   подставляют ту же базу вместо `config.MAIN_BRANCH`. Инкрементальный
   diff ревью (база — sha предыдущего вердикта) не меняется.
3. Потребитель, у которого `diff_base` вернула `None`, отказывает
   fail-closed тем же способом (журнал + печать причины), что сейчас при
   `None` от `diff_names`/`git_diff_part`.
4. В журнальных записях отказов гейта зон и гейта ёмкости называется
   база сравнения: sha merge-base и откуда он взят (`origin/main` или
   локальный `main`), чтобы Оператор видел, с чем сравнивали.
5. Внешний (не self) target функцией и её потребителями не покрывается
   этой задачей — ветка сравнивается с его main той же функцией только
   если она уже параметризована репозиторием; иначе — прежнее поведение
   (только self, оба гейта и так пропускают внешний target).

## Критерии приёмки

AC-1. `orchestrator/gitcmd.py` несёт функцию `diff_base(branch) ->
str | None`: при наличии `refs/remotes/origin/<MAIN_BRANCH>` в
репозитории возвращает merge-base ветки `branch` с этим ref; иначе —
merge-base ветки `branch` с локальным `config.MAIN_BRANCH`. Функция не
вызывает `fetch`/`ls-remote` или любую другую сетевую git-команду. Git
не ответил на проверку существования ref или на саму команду
merge-base — функция возвращает `None`.

AC-2. Гейт зон (`_zones_gate_refuses`) сравнивает ветку задачи с базой
из AC-1 трёхточечно (список файлов от merge-base до головы ветки)
вместо текущего двухточечного `gitcmd.diff_names(config.MAIN_BRANCH,
t["branch"])`.

AC-3. Гейт ёмкости (`_capacity_gate_refuses`) и полный diff
ревью-пакета (`review.review_package` при `iteration == 1`) используют
базу из AC-1 вместо `config.MAIN_BRANCH` как первый аргумент своего
`git diff`/`git_diff_part`.

AC-4. Инкрементальный diff ревью-пакета (база — sha предыдущего
вердикта, `iteration > 1` с непустым `prev_sha`) этой задачей не
меняется.

AC-5. `diff_base` вернула `None` — гейт зон и гейт ёмкости отказывают
переход fail-closed (журнал + печать причины), тем же способом, что
сейчас при `None` от `diff_names`/`git_diff_part`.

AC-6. Журнальная запись отказа гейта зон и журнальная запись отказа
гейта ёмкости называют базу сравнения: sha merge-base и источник
(`origin/main` или локальный `main`).

AC-7. В песочнице тестов с локальным `origin/main`, ушедшим вперёд
локального `main` на файл вне зон, и веткой задачи, влившей
`origin/main`: гейт зон не отказывает по этому файлу; гейт ёмкости не
учитывает его байты в diff снимка; полный diff ревью-пакета не содержит
этот файл.

AC-8. В той же песочнице, но без ref `origin/main` (репозиторий без
remote) — поведение всех трёх потребителей (гейт зон, гейт ёмкости,
полный diff ревью-пакета) прежнее: сравнение с локальным
`config.MAIN_BRANCH`.

AC-9. `tests/test_zones_gate.py`, существующие тесты гейта ёмкости и
существующие тесты ревью-пакета остаются зелёными без ослабления
ассертов.

## Не входит

- Сама подтяжка `main`/`origin/main` в ветку задачи (механика pull не
  меняется).
- Обновление пина запущенной версии.
- Поведение внешних (не self) target: ветка сравнивается с их main той
  же функцией, если она уже параметризована репозиторием; иначе — для
  внешних target остаётся только self (требование 5).

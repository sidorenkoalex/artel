# ТЗ: гейты зон и ёмкости сравнивают ветку с точкой расхождения от origin/main, а не с локальным main целиком

Источник: бэклог 05.09 (docs/backlog.md, приоритет 1), фактура трёх
ложных отказов за день.

Сегодня:
1. Гейт зон (`orchestrator/fsm_advance.py`, `_zones_gate_refuses`, строка
   с `gitcmd.diff_names(config.MAIN_BRANCH, t["branch"])`) берёт
   ДВУХТОЧЕЧНЫЙ `git diff --name-only main <ветка>`: любой коммит main,
   ещё не влитый в ветку, выглядит правкой задачи. Стек ч.1 05.09: чужие
   `docs/roadmap.md`, `docs/triggers.md` — «вне зон».
2. Гейт ёмкости (`_capacity_gate_refuses`) и полный дифф ревью
   (`review.git_diff_part`) уже трёхточечные (`base...branch`), но база —
   ЛОКАЛЬНЫЙ `config.MAIN_BRANCH` главной копии, то есть пин запущенной
   версии, который по построению отстаёт от `origin/main`; ветка задачи
   при этом подтягивает `origin/main` (регрессия №5). Точка расхождения
   с локальным main старее, чем с origin/main, и дифф включает чужие
   коммиты: 05.09 гейт ёмкости — 303 КБ при устаревшем пине против 35 КБ
   после pin-update; часть 2 наблюдателя карты (01M1RGQV4D…) — после мержа
   hotfix зон в origin/main дифф «показал» zone_lock.py, docs/retro/…,
   tasks/01M1RR1PZC….

Требуется:
1. Одна точка правды для базы сравнения — функция в `orchestrator/gitcmd.py`
   (например `diff_base(branch) -> str | None`): merge-base ветки задачи с
   `refs/remotes/origin/<MAIN_BRANCH>`, если такой ref есть в репозитории;
   если ref отсутствует (репозиторий без remote, песочница тестов) — merge-base
   с локальным `config.MAIN_BRANCH`. Сетевых обращений функция не делает
   (инвариант «тесты не выходят в сеть», 01M1QHQ277…): ref origin/main уже
   обновляется механикой подтяжки и входа в verifying. git не ответил —
   `None`, потребители отказывают fail-closed, как сейчас при `None` от
   `diff_names`.
2. Гейт зон сравнивает ветку с этой базой трёхточечно (список файлов от
   merge-base до головы ветки), гейт ёмкости и полный дифф ревью-пакета
   подставляют ту же базу вместо `config.MAIN_BRANCH`. Инкрементальный дифф
   ревью (база — sha предыдущего вердикта) не меняется.
3. В журнальных записях отказов гейтов называется база (sha merge-base и
   откуда он взят: origin/main или локальный main), чтобы Оператор видел,
   с чем сравнивали.
4. Тесты (`tests/`): в песочнице с локальным `origin/main`, ушедшим вперёд
   локального main на файл вне зон, и веткой задачи, влившей origin/main:
   гейт зон не отказывает; гейт ёмкости считает только байты задачи;
   ревью-пакет не содержит чужого файла. Без ref origin/main — прежнее
   поведение относительно локального main. git не ответил — отказ
   fail-closed. Существующие `tests/test_zones_gate.py`, тесты гейта ёмкости
   и ревью-пакета зелёные без ослабления ассертов.

Зоны: orchestrator/fsm_advance.py, orchestrator/gitcmd.py,
orchestrator/review.py, tests/.

Не входит: сама подтяжка main в ветку, обновление пина, поведение
внешних target (ветка сравнивается с их main той же функцией, если она
уже параметризована репозиторием; иначе — только self).

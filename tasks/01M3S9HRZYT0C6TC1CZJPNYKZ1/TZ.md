# ТЗ: Критерий приёмки не дублирует проверки, которые держит сам пульт

Источник: решение Оператора 30.09.2026; строка копилки 30.09 (П2)
«Автогейт приёмки отказывает по skip-критерию, который дублирует его же
собственную проверку»; отчёт `docs/research/2026-09-30-canary-models-stage3.md`
(дефект 3).

Факты (пин 34b298c7):
- Аналитик (и на Opus 5.5, и на codex) пишет в SPEC критерий вида
  «Полный существующий набор `tests/` на ветке задачи зелёный». Этот набор
  и так прогоняют пульт и CI: автогейт приёмки
  (`orchestrator/fsm_autogate.py`, условие полного `tests/` в worktree)
  и `approve` на приёмке.
- test_author не может проверить такой критерий тестом планки (запуск
  всего набора из теста рекурсивен и не укладывается в предел прогона
  планки) и метит его `skip` или `manual` с причиной «проверяется CI».
  Любая такая пометка выключает автогейт приёмки всей задачи
  (`skills/test-authoring.md`, раздел о manual/skip) — задача уходит
  Оператору на ручную приёмку без причины.
- Канарейка 30.09: так отказал автогейт в прогонах на шаблоне
  `canary-usage-invariant` — у опоры (skip) и у двух наборов codex
  (manual).
- `skills/spec-authoring.md` и `skills/test-authoring.md` такой случай не
  называют.

Требуется:
1. `skills/spec-authoring.md`: в SPEC не пишется критерий приёмки,
   который проверяет сам пульт при любой задаче: полный набор `tests/`
   зелёный, CI ветки зелёный, неизменность защищённых путей, бюджет не
   превышен. Если такое требование есть в ТЗ, аналитик не превращает
   его в AC, а упоминает в разделе «Не входит» одной строкой «держит
   пульт». Перечень проверок пульта — по ADR-0007 (условия автогейта) и
   существующему тексту скилов, не шире.
2. `skills/test-authoring.md`: если в SPEC всё же есть такой критерий,
   test_author не метит его `skip`/`manual`, а эскалирует пометкой
   `escalate` с вопросом «критерий держит пульт — убрать из SPEC?», как
   прочие неисполнимые формулировки.
3. Обе правки — приложением PLAN (защищённый путь): разработчик кладёт
   готовый текст правки в приложение, пульт применяет его на мерже.
4. Тесты в `tests/`: проверка текста скилов — оба скила содержат правило
   (по устойчивым ключевым фразам, которые выбирает SPEC), и оно
   называет полный `tests/` и CI ветки. «Ловит мутацию: правило удалено
   из скила».

Зоны: tests/.
Приложением: skills/spec-authoring.md, skills/test-authoring.md (защищённый путь, применяет пульт на мерже).

Только чтение (не менять): orchestrator/fsm_autogate.py,
orchestrator/advance_gates/, orchestrator/config.py, scripts/guard.py,
templates/, docs/adr/, docs/invariants.md, tests/test_invariants.py,
docs/backlog.md, docs/research/, tasks/, остальные файлы skills/.

Не входит: изменение автогейта приёмки (он по-прежнему отказывает на
любом skip/manual); проверка текста SPEC программой (guard); критерий `ci`
в канарейке.

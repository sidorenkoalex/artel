# PLAN: Критерий приёмки не дублирует проверки пульта

## Подход

Добавить в скил аналитика запрет превращать четыре общие проверки пульта в критерии SPEC и правило для строки «Не входит», если проверка пришла из ТЗ. В скил test_author добавить точный исход `escalate` для оставшегося критерия. Оба защищённых файла меняет пульт при мерже по единому приложению ниже; в кодовой ветке они остаются без правок.

Ответ Оператора в `ANSWER-1.md` уточнил AC-4: разовый тест в `tasks/01M3S9HRZYT0C6TC1CZJPNYKZ1/acceptance_tests/test_skill_appendices.py` проверяет добавленные строки приложения. Долгоживущий тест в `tests/` не создаётся: до мержа он читал бы старые версии скилов и краснел. Залоченную планку не меняю.

## Влияние на систему

Меняются только инструкции двух ролей после применения приложения при мерже. Правило не ослабляет гейты, бюджет, ограничения защищённых путей или существующие тесты: перечисленные проверки остаются у пульта. Разовый тест уже зафиксирован и проверяет содержимое приложения до мержа. Откат — revert коммита мержа с приложением.

## Риски

До мержа файлы `skills/*.md` в кодовой ветке содержат прежний текст. Проверка должна читать добавленные строки PLAN из артефактной ветки, как делает зафиксированный разовый тест; чтение рабочих файлов скилов до мержа дало бы ложную красноту. ## Предложения системе

- Корневой `conftest.py` отвергает запуск конкретного файла через программный `pytest.main([...])` как полный набор, потому что внешняя команда — `python3 -`. Для локальной проверки приложения до автокоммита PLAN нужен штатный способ подать черновик артефакта разовой планке; сейчас приходится подменять чтение PLAN тестовым плагином.
- Задача с одними защищёнными путями не даёт разработчику файлов для кодового коммита, хотя `coding-standards` требует закончить ход таким коммитом; нужен явный маршрут для PLAN-only задач без пустого коммита.
- `git commit --allow-empty` для маркировки хода отказал: общий `.git/worktrees/<id>/index.lock` вне разрешённой области записи роли (`Operation not permitted`). PLAN остаётся артефактом автокоммита оркестратора; кодовых файлов для коммита нет.
- Повторный возврат из `verifying` требует ручной подтяжки `main`, но область записи роли не включает общую `.git/worktrees/<id>/`: `git merge --ff-only origin/main` отказал на `ORIG_HEAD.lock`. Нужен штатный маршрут подтяжки ветки задачи через пульт или доступ роли к Git-метаданным её worktree.

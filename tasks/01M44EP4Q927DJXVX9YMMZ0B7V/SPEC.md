# SPEC: Помощник планки от пульта

## Контекст
Планка приёмки выкладывается в рабочую копию кода пультом
(`orchestrator/acceptance.py::materialize_from_branch`, `::materialize_files`,
общий узел `::_write_plank`, уборка `::drop_from_code_copy`/
`::plank_in_code_copy`), но кладёт только файлы ссылки документов или
черновика. Чтение артефактов задачи, дифф задачи от базы и проверку
приложений PLAN роли пишут сами в каждой задаче заново (модуль `_plank.py`
планок 01M443HPZBMJGCHVGV4JQN88RS и 01M443HV9SJYVYQTHJSQ87QV68) — через
пакет `orchestrator` рабочей копии, код которой и есть предмет задачи, и через
`artifact_branch.show`/`ls_tree`, которые из планки не находят клон
(`config.ROOT` планки — корень рабочей копии без `.artel/`). Прецеденты:
12.09 AC-8 01M2B6K3EM (PLAN.md читался с диска), 13.09 AC-4 01M2CN465W
(merge-base с локальной main, равной пину). Задача — пункт (1) строки
бэклога (помощник пульта) и пункт (3) (строка скила); пункт (2) сделан
наполовину задачей 01M2XJKKPH.

Решения, которые ТЗ отдало SPEC:
- исходный текст помощника — модуль `orchestrator/plank_helper.py`; имя
  файла выкладки в каталоге планки — `_pult.py` (подходит под `_<имя>.py`
  `scripts/guard.py::ACCEPTANCE_TESTS_ALLOWED_TOP_LEVEL`, без слова
  «artel», не совпадает с `_plank.py` исторических планок);
- `artifact_text(name)` при отсутствии файла в ссылке возвращает `None`;
  сбой git — именованное исключение `ArtifactReadError` помощника;
- `changed_paths()` считает список тем же правилом, что гейт зон
  (`orchestrator/advance_gates/zones.py::_zones_gate`): пути
  закоммиченного диффа `база...HEAD` плюс неотслеживаемые файлы рабочей
  копии, кроме собственного каталога задачи `tasks/<id>/`; изменённые, но
  не закоммиченные отслеживаемые файлы гейт зон не включает — не включает
  и помощник. `branch_diff()` — закоммиченный дифф `база...HEAD`.

## Требования
1. Модуль `orchestrator/plank_helper.py` — исходный текст помощника
   планки. Помощник импортирует только стандартную библиотеку Python и не
   импортирует ничего из пакета `orchestrator` (ни рабочей копии, ни
   пульта).
   Открытый набор помощника:
   - константы `TASK_ID`, `CODE_ROOT` (корень рабочей копии кода, в
     которую выложена планка), база диффа и её источник
     (`origin/<main>` или локальная основная ветка) — константами;
   - `artifact_text(name)` — текст `tasks/<id>/<name>` из ссылки документов
     задачи ровно той ревизии, с которой выложена планка; файла нет —
     `None`; сбой git — исключение `ArtifactReadError`, отличимое от
     «файла нет»;
   - `branch_diff()` — закоммиченный дифф задачи от базы выкладки до HEAD
     рабочей копии;
   - `changed_paths()` — список путей задачи по правилу гейта зон (раздел
     «Контекст»); правило — включает неотслеживаемые файлы, исключает
     `tasks/<id>/`, не включает незакоммиченные правки отслеживаемых
     файлов — записано в докстринге помощника;
   - `apply_check(diff, reverse=False)` — применимость unified-диффа к
     дереву HEAD рабочей копии без изменения рабочей копии и индекса:
     пустая строка — git согласился, иначе ответ git; `reverse=True` —
     обратное наложение («правка уже в дереве»); дифф подаётся git тем же
     способом, что в `orchestrator/advance_gates/plan_appendix.py::git_apply`.
2. База диффа и её источник вычисляются пультом при выкладке теми же
   `gitcmd.diff_base`/`gitcmd.diff_base_source`, что у гейта зон, и
   подставляются в помощник; помощник базу сам не вычисляет.
3. Выкладка: `acceptance.materialize_from_branch` и
   `acceptance.materialize_files` кладут `_pult.py` в каталог планки
   (`tasks/<id>/acceptance_tests/` рабочей копии) с подставленными
   значениями: id задачи, путь репозитория ссылки документов, ревизия
   выкладки, база диффа и её источник. `_write_plank` не удаляет
   `_pult.py` как лишний файл; `drop_from_code_copy` убирает его вместе с
   планкой. Все потребители выкладки (`orchestrator/pull.py`,
   `orchestrator/advance_gates/tests_writing.py`,
   `orchestrator/advance_gates/acceptance.py`, `orchestrator/fsm_advance.py`,
   `orchestrator/amend.py`, `orchestrator/plank_run.py`) получают помощник
   без правки каждого из них.
4. Помощник не попадает ни в ссылку документов задачи (лок
   `tests_locked_sha`, автокоммит `orchestrator/checkpoint.py`), ни в
   кодовую ветку, ни в каталог документов задачи.
5. Имя `_pult.py` зарезервировано: файл с этим именем на первом уровне
   планки в ссылке документов или в черновике `tests_writing` отклоняет
   выход из `tests_writing` именованным действием с подсказкой «имя занято
   помощником пульта». При выкладке файл пульта имеет приоритет над
   файлом планки с тем же именем.
6. Отказ гейта «планка читает артефакты с диска» — рецепт
   `scripts/guard.py::ARTIFACT_DISK_READ_RECIPE_TMPL` и подсказка
   `orchestrator/advance_gates/tests_writing.py::_tests_writing_artifact_source_gate`
   — называют `artifact_text(name)` помощника вместо `gitcmd.show(...)`.
   Правило проверки (что именно отказывается) не меняется.
7. Приложение к PLAN — правка `skills/test-authoring.md`: раздел о
   помощнике пульта (имя файла `_pult.py`, четыре функции, константы) как
   единственном рекомендуемом способе читать артефакты, считать дифф
   задачи и проверять приложения; разделы «Источник артефактов задачи —
   только артефактная ветка» и «База диффа задачи — точка расхождения с
   `origin`» ссылаются на него.
8. `docs/codebase-map.md` несёт строку о модуле-помощнике и о его
   выкладке.
9. Свойства требований 1–6 закреплены тестами в `tests/` с заявками
   «Ловит мутацию» (долгоживущие приёмочные тесты `tests/test_<id>_*.py`
   test_author этим требованием засчитываются, отдельного повтора не
   нужно).

## Критерии приёмки
AC-1. `orchestrator/plank_helper.py` существует; его импорты — только
модули стандартной библиотеки, ни одного импорта `orchestrator` в любой
форме. Выложенный `_pult.py` даёт константы `TASK_ID`, `CODE_ROOT`
(корень рабочей копии, куда выложена планка), базу диффа и источник базы,
а также функции `artifact_text`, `branch_diff`, `changed_paths`,
`apply_check`; докстринг выложенного помощника называет правило
`changed_paths()` (неотслеживаемые включены, `tasks/<id>/` исключён,
незакоммиченные правки отслеживаемых файлов не включены).

AC-2. Выкладка из ссылки документов (`materialize_from_branch`) и из
черновика (`materialize_files`) кладёт `_pult.py` в
`tasks/<id>/acceptance_tests/` рабочей копии с подставленными id задачи,
путём репозитория ссылки, ревизией выкладки, базой диффа и источником
базы; повторная выкладка (`_write_plank`) его не удаляет;
`drop_from_code_copy` убирает его вместе с планкой.

AC-3. `artifact_text(name)` возвращает текст `tasks/<id>/<name>` ревизии
ссылки документов, с которой выложена планка: после нового коммита в
ссылку с другим содержимым файла помощник по-прежнему возвращает текст
ревизии выкладки. Файла в этой ревизии нет — `None`. Сбой git (например,
недоступный репозиторий ссылки) — исключение `ArtifactReadError`, не
`None`.

AC-4. Помощник работает, когда планка исполняется в рабочей копии, в
корне которой нет `.artel/` (нет `state.db` и клона по `config.PROJECTS`),
и когда пакет `orchestrator` рабочей копии сломан (например, не импортируется):
`artifact_text`, `branch_diff`, `changed_paths`, `apply_check` отвечают
штатно.

AC-5. База диффа в помощнике равна значению `gitcmd.diff_base`, источник
— значению `gitcmd.diff_base_source` для той же ветки в момент выкладки.
На ветке, где `refs/remotes/origin/<main>` ушла вперёд локальной основной
ветки (сценарий 13.09), `changed_paths()` совпадает со списком файлов
гейта зон (`_zones_gate`: закоммиченный дифф от базы плюс
неотслеживаемые файлы вне `tasks/<id>/`) для той же ветки, а
`branch_diff()` — закоммиченный дифф от той же базы до HEAD.

AC-6. `apply_check(diff)` возвращает пустую строку для диффа, который
применим к дереву HEAD, и непустой ответ git — для неприменимого;
`apply_check(diff, reverse=True)` возвращает пустую строку для диффа,
уже наложенного в HEAD. Ни прямой, ни обратный вызов не меняют файлы
рабочей копии и индекс (статус рабочей копии и индекс до и после вызова
совпадают).

AC-7. После шага с выложенной планкой `_pult.py` нет ни в коммите
ссылки документов (автокоммит `orchestrator/checkpoint.py`, лок
`tests_locked_sha`), ни в кодовой ветке задачи, ни в каталоге документов
задачи.

AC-8. Файл `_pult.py` на первом уровне планки в ссылке документов либо в
черновике `tests_writing` отклоняет выход из `tests_writing` именованным
действием, подсказка которого содержит «имя занято помощником пульта».
При выкладке планки, несущей свой `_pult.py`, на диске оказывается файл
пульта.

AC-9. Отказ гейта «планка читает артефакты с диска» — текст
`ARTIFACT_DISK_READ_RECIPE_TMPL` и подсказка
`_tests_writing_artifact_source_gate` — называет `artifact_text(`, а не
`gitcmd.show(`; планка, которую гейт отказывал до задачи, отказывается и
после неё.

AC-10. PLAN.md несёт приложение к `skills/test-authoring.md`: раздел о
помощнике пульта называет имя файла `_pult.py`, четыре функции и
константы и объявляет помощник единственным рекомендуемым способом
читать артефакты, считать дифф задачи и проверять приложения; разделы
«Источник артефактов задачи — только артефактная ветка» и «База диффа
задачи — точка расхождения с `origin`» ссылаются на помощник; приложение
проходит `git apply --check` на чистом дереве.

AC-11. `docs/codebase-map.md` содержит строку о модуле
`orchestrator/plank_helper.py` и о выкладке помощника рядом с планкой.

## Оценка объёма и деление
Сработавший сигнал: число критериев приёмки ≥ 10 (11). Файлов зоны вне
общих зон — 4 (`orchestrator/plank_helper.py`, `orchestrator/acceptance.py`,
`orchestrator/advance_gates/tests_writing.py`, `scripts/guard.py`).
`budget_usd` 45 — уровень таблицы «до 15 критериев и до 7 файлов зоны»;
он выше рамки ТЗ ($30) — расхождение оставлено на решение Оператора на
гейте SPEC.

Материал для решения «монолит»: помощник (требование 1), его выкладка
(3–4) и резервирование имени (5) — одна смена механики: выкладка без
резервирования молча перетирает файл планки с тем же именем, а
резервирование без выкладки отказывает имени, которого пульт не кладёт.
Рецепт отказа (6) и приложение скила (7) без помощника в main указывают
ролям на несуществующую функцию — промежуточное состояние вводит ролей в
заблуждение. Возможная нарезка, если Оператор её предпочтёт: часть 1 —
требования 1–5, 8, 9 (зоны `orchestrator/plank_helper.py`,
`orchestrator/acceptance.py`, `orchestrator/advance_gates/tests_writing.py`,
`tests/`, `docs/codebase-map.md`); часть 2 после неё — требования 6–7
(зона `scripts/guard.py`, `orchestrator/advance_gates/tests_writing.py`
пересекается с частью 1 — подсказка гейта источника артефактов живёт в
том же файле, поэтому граница зон при нарезке не чистая).

# PLAN: G2б-2 — честный FAIL_TO_PASS на выходе из tests_writing, тесты критериев на ветке, запреты в тексте планки

## Подход
Ядро — один разбор записей отчёта по правилу планки, общий для выхода из
`tests_writing` и приёмки ветки; он живёт в
`orchestrator/advance_gates/acceptance.py` (модуль гейтов приёмки уже
импортируется модулем `tests_writing`, обратного импорта нет — цикла не
будет): файлы задачи (тестовые файлы планки компонента + свои
долгоживущие файлы) с компонентом-владельцем, путём записи в отчёте
(`<plank_layout с id>/<имя>` либо путь долгоживущего файла), видом метки и
маркером «Зелёный с рождения:»; номер критерия записи — по последнему
сегменту полного имени (« > » у `pult-vitest`, «::» у JUnit).

- `acceptance.run` (требование 1): необязательные `records` и
  `continue_on_collection_errors`. У профиля с отчётом в `records` ложится
  сам `ReportRun` (поля `refusal`/`timed_out`/`state`) и его записи
  `CaseResult`; на ранних выходах (отказ плана планки, отказ выкладки,
  отказ `workdir`) — `ReportRun(refusal=…)`. Ключ
  `--continue-on-collection-errors` добавляет `_report_argv` только при
  команде pytest и только по флагу гейта. Без новых аргументов поведение
  и argv прежние.
- Гейт `_tests_writing_fail_to_pass_gate(conn, task_id, acc_tdir, run_cwd,
  covered, profiles, *, long_lived_paths=None)` в
  `orchestrator/advance_gates/tests_writing.py` — подпись из ANSWER-1;
  `long_lived_paths` — необязательный ключевой параметр: переход передаёт
  уже прочитанные пути долгоживущих файлов (у задачи без кодовой ветки —
  пусто), прямой вызов без него читает дифф кодовой ветки сам. Порядок:
  граница (`reported` и `from_components`, иначе `None`) → опора SPEC и
  «SPEC изменён после одобрения» → правило планки не построено → «критериев
  с тестом нет» (запись журнала, `None`) → пустой `failure_errors`
  компонентов файлов → прогон по компоненту (`acceptance.run` с `records`
  и ключом pytest) → отказ подготовки → находки (таймаут → повторы `#n` →
  по критериям и маркеру → ошибки уровня файла) одним отказом.
- Опора SPEC: последняя запись «state -> tests_writing» с деталью константы
  модуля `SPEC_GATE_PASSED_DETAIL`; первая после неё «sha зафиксирован»
  раньше первой «agent run started» и без записи «… без паспорта и
  фиксации» между; `артефакты=` — sha; SPEC.md читается
  `artifact_branch.show` в опоре и на голове ссылки документов.
- Ветка (требование 6): в `_acceptance_run_body` у профиля в границе прогон
  зовётся с `records`; после зелёного исхода и до `_seed_repeats_escalate`
  — сверка записей по критериям, покрытым планкой и долгоживущими файлами
  перечня; отказ — `BRANCH_CRITERION_REFUSAL_ACTION`.
- Запреты (требование 7): `guard.plank_ban_errors(files, rule)` — маска
  комментариев и строк одним проходом (позиции сохраняются), токены
  `.fails/.skipIf/.runIf/.only`, `vi.setConfig`, аргументы первого уровня
  вызовов `it/test/describe/suite` с цепочками (у `.each` — вторая пара
  скобок), литерал имени с двумя метками, литерал `describe` с меткой.
  Зовётся в гейте групп, гейте долгоживущих и в `preflight._groups`/
  `_long_lived` (сторож равенства множеств).
- Переносы: `_closing_paren` пропускает `//` и `/* */`; чекпоинт пишет
  запись умолчания правила один раз на визит `tests_writing` и только в нём;
  гейт посторонних пропускает записи `PLANK_RULE_DEFAULT_ACTION`; текст
  `_plank_rule_refusal` для правила не по умолчанию — G3б.
- Шесть действий — литералами в `REFUSAL_CLASSES`, константы гейтов
  импортируют их оттуда.

Рамка поднята Оператором до $95 (ANSWER-1, п. 2); переоценка `budget_usd`
полем PLAN не нужна.

## Влияние на систему
- Новый гейт строже прежнего выхода из `tests_writing` только у компонента
  записи `components:` с `report`; у артели, `test_profile` (в том числе
  `pytest-own` с `report`) и компонентов без `report` гейт не создаётся —
  прежние гейты, их порядок, тексты и уборка в `finally` не меняются.
- Проверка ветки — дополнительное условие после зелёного прогона, прежний
  отказ красного прогона и его деталь не меняются; вне границы не
  исполняется.
- Запреты — новая проверка гейтов групп/долгоживущих только у файлов с
  меткой `AC-<n>: `; файлы pytest не затронуты.
- `_closing_paren` теперь пропускает комментарии — разбор стал терпимее
  к апострофам, распознаёт не меньше тестов, чем прежде.
- Чекпоинт пишет запись умолчания реже (раз на визит) — гейт посторонних
  дополнительно пропускает её при поиске последней записи визита.
- Существующий метод G2б-1 (шаг 8) вёл задачу `pult-vitest` из
  `tests_writing` в `in_dev` без перехода гейта SPEC и с отчётом, где нет
  ни одного теста критерия, — новый гейт по AC-30 обязан отклонить такой
  выход («опора SPEC не найдена»). Сценарий метода приведён к механике
  (опора и провал проверки на базе), утверждения не менялись: метод
  по-прежнему требует `in_dev`, перечень, отказ сверки перечня и гейта
  зон. Ревьюверу — сверить, что правка только подготовки.
- Ничего не ослабляется: ни один существующий тест, гейт или лимит не
  снят. Откат — revert merge-коммита задачи.

## Пути обхода гейтов
- Е1 (новое). Подмена опоры «Зелёного с рождения» при неотвеченном git на переходе.
  - Как: ссылка документов не прочитана в момент `approve` → переход в
    `tests_writing` идёт без фиксации (`orchestrator/store.py:822-830`). На старте шага
    сверка не пропустит роль, пока git молчит. Когда git ответил, голова равна
    `fixed_sha`, и шаг test_author запускается.
  - test_author дописывает в SPEC.md раздел «## Зелёный с рождения». Чекпоинт шага
    фиксирует голову (`orchestrator/checkpoint.py:1368`/`:1412`).
  - По букве треб. 5 эта фиксация — «первая "sha зафиксирован" после перехода», то есть
    опора. Отказ «SPEC изменён» не срабатывает, и тест базы под маркером принимается —
    ровно тот сценарий, который AC-28 запрещает.
  - Условие узкое (сбой git в момент перехода), но гейт открывается молча.
  - Варианты закрытия (выбор за Оператором):
    - опорой считать фиксацию, стоящую сразу за переходом, без записей шага между ними;
    - запись «голова не прочитана» с текстом «переход в tests_writing…» между переходом
      и фиксацией считать случаем «опора не найдена» (AC-30);
    - либо принять риск.
- Прочие пути, рассмотренные и закрытые SPEC:
  - правка перечня test_author'ом — AC-28;
  - возврат из эскалации — фильтр по детали;
  - отказы «чинит Оператор» не уходят в цикл роли — AC-29;
  - запреты через комментарии и строки — AC-17;
  - доступ по строке (`it['only']`) — принятое ограничение, решение №1 п. 9.

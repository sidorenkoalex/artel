# SPEC: Автогейт acceptance по политике gates.yaml (ADR-0007)

## Контекст

ADR-0007 вводит политику гейтов в `gates.yaml`: за 65 прохождений
ручных гейтов — 0 reject, на acceptance ни одной находки Оператора
сверх пойманного тестами; при N=5 подтверждение зелёного стало главным
потребителем внимания Оператора. Решение — сделать acceptance первым
автоматизируемым гейтом: при выполнении всех условий оркестратор сам
проводит переход, без ожидания `approve`. Дефолт всех гейтов остаётся
manual (fail-closed); kill-switch — правка `gates.yaml`.

## Требования

1. `gates.yaml` получает секцию политики гейтов вида
   `gates: {spec_gate: manual, acceptance: auto, merge_gate: manual}`
   (конкретный формат — решение разработчика в PLAN, консистентный
   с текущим содержимым файла). Неизвестное значение политики гейта
   или отсутствие секции трактуется как `manual` (fail-closed).
2. На переходе `review -> acceptance`, если политика гейта acceptance
   = `auto`, оркестратор сам проверяет условия автопрохода — ВСЕ
   обязательны:
   а) каталог приёмочных тестов задачи существует и непуст, среди
      разметки критериев 0 `manual` и 0 `skip`;
   б) прогон приёмочных тестов задачи в worktree ветки — зелёный;
   в) полный набор `tests/` в worktree ветки — зелёный;
   г) бюджет задачи не превышен; программные пороги (A1) не пробиты;
   д) вердикт REVIEW текущей итерации — `approved` (фиксируется
      явной проверкой, хотя переход и так её требует).
3. Если все условия п.2 выполнены — гейт acceptance проходится
   автоматически: переход `acceptance -> merge_gate` тем же
   действием; журнал несёт `actor=autogate` с перечнем выполненных
   условий; вывод команды явно сообщает «acceptance пройден
   автогейтом (политика gates.yaml)».
4. Если хотя бы одно условие п.2 не выполнено (manual/skip-критерий,
   красный тест, превышен бюджет, пробит порог A1, политика manual,
   `gates.yaml` не читается) — поведение прежнее: задача
   останавливается в `acceptance` и ждёт Оператора; причина «почему
   не автогейт» — одной строкой в выводе и в журнале.
5. Инвариант 7 в `docs/invariants.md` переформулируется по ADR-0007
   (текст готовит разработчик в PLAN, вносит Оператор при мерже).
   Тест `ManualGatesNeedTheOperatorTest` при политике manual (дефолт
   песочниц) сохраняет прежнее поведение байт-в-байт, без ослабления
   существующих сценариев; новый сценарий автогейта покрывается
   отдельным тестом.
6. Инвариант 18 не меняется: автогейт — исполнение объявленной
   политики в точке перехода, не действие `auto`-цикла; `auto`
   по-прежнему не вызывает `approve`/`reject`. `merge_gate` и
   `spec_gate` не получают автопути от этой задачи.
7. Дефолт политики во всех гейтах в свежесозданных песочницах и
   инсталляциях — manual; политика `acceptance: auto` включается
   значением непосредственно в `gates.yaml` реального пульта
   (коммитится в этой же задаче).

## Критерии приёмки

AC-1. При политике `gates.yaml` acceptance=`auto` и выполнении всех
условий — каталог приёмочных тестов задачи существует и непуст с
0 `manual` и 0 `skip` критериев; прогон приёмочных тестов задачи в
worktree ветки зелёный; полный набор `tests/` в worktree ветки
зелёный; бюджет задачи не превышен и пороги A1 не пробиты; вердикт
REVIEW текущей итерации `approved` — переход `review -> acceptance ->
merge_gate` происходит одним действием без операторского `approve`.

AC-2. При автопроходе по AC-1 запись в журнале несёт `actor=autogate`
и перечень выполненных условий.

AC-3. При автопроходе по AC-1 вывод команды явно сообщает: «acceptance
пройден автогейтом (политика gates.yaml)».

AC-4. При наличии хотя бы одного из: manual-критерий, skip-критерий,
красный тест приёмочных или красный тест полного набора, превышенный
бюджет задачи, пробитый порог A1 — задача останавливается в состоянии
`acceptance` и ждёт Оператора; причина «почему не автогейт»
присутствует в выводе команды и в журнале одной строкой.

AC-5. При политике гейта acceptance=`manual`, либо отсутствии секции
политики в `gates.yaml`, либо нечитаемом `gates.yaml` — поведение
перехода `review -> acceptance` байт-в-байт совпадает с сегодняшним:
задача останавливается в `acceptance` и ждёт Оператора, без автогейта.

AC-6. Гейты `merge_gate` и `spec_gate` не получают автоматического
пути ни при какой политике, введённой этой задачей.

AC-7. `test_invariants.ManualGatesNeedTheOperatorTest` зелёный, его
сценарии при политике manual не изменились; добавлен и зелёный
отдельный тест сценария автогейта; полный набор `tests/` зелёный.

## Не входит

- Автогейт `merge_gate` (ждёт детекторов деградации, ADR-0007 п.4).
- Автогейт `spec_gate` (без горизонта автоматизации, ADR-0007 п.5).
- Изменение механики reject/эскалаций.
- UI/status-доработки сверх отличимой строки журнала.

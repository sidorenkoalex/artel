## Пути обхода гейтов
1. **Условный `pytestmark` на файле базы.** Буквальное прочтение AC-5 (первая половина только про `pytest.mark.skip`) допускает реализацию, где `pytestmark = pytest.mark.skipif(True, reason="временно")` в существующем файле послабляется для всех методов: условие есть, причина-константа есть. Треб. 4 (SPEC.md:57-58) говорит «только тестовым методам, которых нет в базе», но ни один AC это не проверяет (SPEC.md:75).
2. **Модульный вызов внутри `if`.** `if True: pytest.skip("x", allow_module_level=True)` на уровне модуля по правилу «вызов в теле» (`_skip_calls`, `test_integrity.py:316-337`) условен. AC-6/AC-7 (SPEC.md:76-77) проверяют только вызов вне `if`, поэтому реализация с послаблением условного модульного вызова и для методов базы проходит планку.
3. **У артели — метка из модуля `tests/`, отличного от `tests/sandbox.py`.** Треб. 1 (SPEC.md:38-40) ограничивает артель `tests/sandbox.py`. `tests/marks.py: requires_pg = pytest.mark.skip` + `from tests.marks import requires_pg` + `@requires_pg` на методе базы — находки нет. Пробел следует из ТЗ (правило помощника части 1), но в «Не входит» он не назван как известный (SPEC.md:98-108). Решать Оператору: заявить пробел или расширить правило для меток.
4. **Безусловная метка с причиной на новом методе** (`requires_pg = pytest.mark.skip(reason="…")`). По треб. 2 это находка, но AC-3 отрицательного случая не содержит. Это ослабление нового теста, базу оно не трогает, поэтому риск ниже.
5. **Смена значения метки на классе / смена значения существующего `pytestmark`.** Треб. 3 говорит только о методах базы с меткой (SPEC.md:48-52). Неясно, даёт ли находку смена `requires_pg` на классе базы и смена уже существующего `pytestmark = pytest.mark.skipif(cond, reason=…)` на `pytest.mark.skipif(True, reason=…)`. Для прямых декораторов смена аргументов не видна и сейчас — это прежний пробел, но для `pytestmark` SPEC выбор не фиксирует.

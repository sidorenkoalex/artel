Расхождения и неполнота:
- **Т-1.** Перечень хостинговых git-операций в требовании 1 (fetch, push,
  `refs/artifacts/*`, мерж) неполон. В коде есть ещё обращения к `origin`:
  - `ls-remote`: `gitcmd.py:524` (`remote_branch_sha`), `gitcmd.py:538`
    (`remote_ref_state`), `doctor/artifact_branches.py:22`,
    `artifact_cleanup.py:30`;
  - `push --delete`: `artifact_cleanup.py:99`.
  Механизм «по `-C`» накрыл бы их сам, если подставлять помощник любой
  git-команде в клоне. Но SPEC позволяет и подстановку только для
  перечисленных подкоманд: тогда `ls-remote` приватного внешнего
  репозитория идёт без токена.
- **Т-5.** SPEC не говорит, как `ci.gh` узнаёт проект. Единственный
  признак в коде — `repo=` (ci.py:57). Часть вызовов `gh`, которые
  доходят до задач внешнего проекта, `repo` не передаёт:
  - `_commit_workflow_runs` — ci.py:369, из `verifying_status`;
  - `find_run_id` — ci.py:1148;
  - `check_run_workflow_run` — ci.py:1207;
  - `trigger_rerun` — ci.py:1240-1253.
  При определении проекта по `repo=` эти вызовы для внешнего проекта
  останутся без `GH_TOKEN` проекта. Требование 1 («вызовы `gh`») этого не
  допускает, а AC-2 такую поломку не ловит.
- **Т-4.** По требованию 14 push `_push_closing_sha` должен идти «тем же
  механизмом, что и требование 1». Механизм требования 1 определён как
  «проект по пути `-C` внутри `.artel/projects/<проект>/`». При
  `source` = главная копия (artifact_branches.py:137, :174) путь `-C`
  вне `.artel/projects/`, и этот механизм проект не определит. SPEC
  требует результата, которого описанный механизм дать не может; второго
  признака (например, URL аргумента push, равный `url` записи) SPEC не
  называет. AC-13 поведение закрепляет, но способ остаётся догадкой
  исполнителя.
- **Т-3.** `workspace.py:111`: `in_repo(clone.parent, "clone", …)` даёт
  `-C .artel/projects/<имя>` — сам каталог проекта. Будет ли он «внутри
  `.artel/projects/<проект>/`» для механизма требования 1, SPEC не
  говорит. Если будет, `git clone` при `target-init` получит токен слота
  и сброс помощников. Это противоречит формулировке «Не входит» («без
  токена слота… с его авторизацией») — `workspace.py` при этом не
  меняется.

## Пути обхода гейтов
- Т-5: исполнитель передаёт токен только по `repo=` и выполняет AC-2 на
  пути `ensure_draft_mr` (github_adapter.py:168). Проверки CI и rerun
  внешней задачи (ci.py:369, :1148, :1207, :1240) идут без токена проекта
  — и к тому же по `{owner}/{repo}` из cwd пульта, то есть по
  репозиторию артели. Критерии буквально выполнены.
- Т-1: подстановка помощника только для `push` и `fetch` проходит AC-3 и
  AC-13, а `ls-remote` и `push --delete` остаются на авторизации
  Оператора.
- Т-2: проверка одного `ARTEL_ROLE` проходит AC-12.
- Правило `Bash(python3 <корень>/orchestrator/artel.py:*)` открывает роли
  все команды пульта, а не только три названные (knowledge, suite-run,
  plank-run). ТЗ п.4 такую форму разрешает, ADR-0023 п.8 (ANSWER-1 п.3) —
  принятый риск. Не отклонение, отмечаю для полноты.

## Вердикт
concerns — SPEC можно вести дальше, отклонения решаемы Оператором на
гейте:

1. **Т-5** (ci.py:57, :369, :1148, :1207, :1240-1253;
   github_adapter.py:111). Не задан признак проекта для `ci.gh`, вызовы
   без `repo=` останутся без токена проекта, AC-2 их не ловит.
   Предложение: требование «каждый вызов `gh` по задаче внешнего проекта»
   и AC на `verifying_status`/`trigger_rerun` внешней задачи. Или явно
   вынести эти вызовы в «Не входит» (вместе с D0).
2. **Т-4** (artifact_branches.py:137, :174; требование 1 против
   требования 14). «Тот же механизм» по `-C` не узнаёт проект при
   источнике — главной копии. Предложение: назвать второй признак —
   URL аргумента push, совпадающий с `url` записи.
3. **Т-1** (gitcmd.py:524, :538; artifact_cleanup.py:30, :99;
   doctor/artifact_branches.py:22). Перечень хостинговых операций
   неполон. Предложение: «любая git-команда с `-C` в клоне или worktree
   проекта» либо явно добавить `ls-remote` и `push --delete`.
4. **Т-2** (runner.py:1067-1068; AC-12). Критерий не покрывает
   распознавание роли по `HOME`. Предложение: второй случай AC-12 —
   `HOME` = дом роли без `ARTEL_ROLE`.
5. **Т-3** (workspace.py:111). Не определено, попадает ли
   `-C .artel/projects/<имя>` (сам каталог проекта) под механизм
   требования 1. От этого зависит, верна ли формулировка «Не входит»
   про `target-init`.

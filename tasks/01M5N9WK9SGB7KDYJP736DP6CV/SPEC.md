# SPEC: ADR-0027, часть А2 — guard прослеживает фикстуры pytest и отказывает скрытым пропускам, скрытым вариантам и смешению стилей в файлах планки

## Контекст
ADR-0027 «Новые тесты артели в стиле pytest» (`docs/adr/0027-pytest-style-tests.md`, пп. 3–5) принят Оператором 23.10.2026. Исполнение разделено: А1 — общие фикстуры `tests/fixtures.py` (задача 01M5N9V4S984GRRXSMBK5JX7V1, идёт параллельно, зоны не пересекаются), А2 (эта задача) — правила guard, Б — приложения к скилам и инвариант. Сейчас guard видит помощника теста только по вызову (`_HelperScope`, `scripts/guard.py:1828`; `test_assertions`, :1949; `_assertion_records`, :1968): фикстура, подставляемая по имени параметра, не прослеживается, а `weakened_helpers` (:1999) ищет потерю утверждений, которых у фикстуры по правилу ADR-0027 нет. Пропуски `pytest.xfail(...)`/`pytest.importorskip(...)` в теле теста и `pytest.skip(...)` внутри фикстуры (`SKIP_CALL_NAMES`, :1089; `test_skip_markers`, :1155; `resolved_skip_markers`, :1312) и варианты `@pytest.fixture(params=…)`, `indirect=`, `pytest_generate_tests` (`_is_parametrize`, :1395; `parametrize_variants`, :1492) guard не видит. В докстринге `scripts/guard.py:865` стоит устаревшая фраза «unittest на гейте».

## Требования

1. Фикстура — объявление `@pytest.fixture` (с вызовом или без) в том же файле или в `tests/fixtures.py`. Для теста-функции и тестового метода фикстурами считаются: параметры с именем фикстуры, имена из `@pytest.mark.usefixtures(...)` и фикстуры `autouse=True` своего файла. Фикстура, запрошенная другой фикстурой, прослеживается на один уровень (как помощник).
2. Прослеживание данных фикстур: тест, запрашивающий фикстуру, получает в разборе утверждений (`_assertion_records`) запись о данных фикстуры — возвращаемые (`return`/`yield`) и присваиваемые литералы — с указанием происхождения (имя фикстуры, файл), так что наблюдение гейта неослабления различает сторону базы и сторону головы, в том числе у вызывающих вне диффа.
3. Ослабление фикстуры: `weakened_helpers` возвращает имя фикстуры, если изменилось её тело (сравнение синтаксических деревьев `ast.dump`); вызывающие находятся прежним `_helper_callers` (`orchestrator/advance_gates/test_integrity.py:788`). `orchestrator/advance_gates/test_integrity.py` не меняется.
4. Отказ guard в файлах планки и в долгоживущих файлах — в `long_lived_errors_from_files` (`scripts/guard.py:3982`), рядом с `lint_errors_from_files`, до фильтра по группе, только при `network_addresses`; вызывающие (`tests_writing`, `preflight`, `amend`, `fsm_advance`) не меняются. Строка отказа — «<файл>::<функция>: строка N: <нарушение>». Формы нарушения:
   - (а) утверждение (`assert`, `pytest.raises`, `pytest.warns`, `self.assert*`, `self.fail`) внутри фикстуры;
   - (б) `pytest.xfail(` и `pytest.importorskip(` в теле теста;
   - (в) `pytest.skip(` внутри фикстуры;
   - (г) `@pytest.fixture(params=…)`;
   - (д) аргумент `indirect=` у `parametrize`;
   - (е) функция `pytest_generate_tests`;
   - (ж) `request.getfixturevalue(`;
   - (з) `@pytest.fixture(name=…)`.
   Для `amend-tests` с `lint_base` нарушение метода (или фикстуры) не считается, если у метода (или фикстуры) с тем же именем в базе одинаковый `ast.dump` — как у линта детерминизма.
5. Смешение стилей — отказ в тех же местах и при том же признаке `network_addresses`: файл, в котором есть и тест-функция модуля, и класс с тестовыми методами. Для `amend-tests` с `lint_base` — отказ только если залоченный текст стили не смешивал.
6. Двусторонний прогон и счёт тестов не меняются (ошибка фикстуры уже даёт фазу setup; одна функция — один тест).
7. Устаревшая фраза «unittest на гейте» в `scripts/guard.py:865` исправляется на «pytest на гейте».
8. Тесты задачи — новые файлы в `tests/`, сами в стиле pytest (функции и `parametrize`), без общих фикстур А1 (их может ещё не быть в main), у каждой функции в докстринге «Ловит мутацию: …». Покрывают формы (а)–(е) критериев приёмки ниже; мутации, которые они обязаны ловить: фикстура не прослеживается; `pytest.xfail` пропущен; `fixture(params=)` пропущен; проверка без признака артели.
9. Существующие тесты не правятся и остаются зелёными.

## Критерии приёмки

AC-1. Правка ожидаемого литерала в фикстуре залоченного теста: `weakened_helpers(base, head)` возвращает имя этой фикстуры, а запись данных фикстуры в `_assertion_records` (с именем фикстуры и файлом происхождения) различается на стороне базы и на стороне головы.

AC-2. Тест получает запись данных фикстуры (литералы `return`/`yield` и присваиваемые литералы), запрошенной каждым из способов: параметром с именем фикстуры, через `@pytest.mark.usefixtures(...)`, через `autouse=True` фикстуру своего файла, и фикстурой, запрошенной другой фикстурой (один уровень вложенности); фикстура может быть объявлена в том же файле или в `tests/fixtures.py`, с вызовом `@pytest.fixture(...)` или без.

AC-3. При `network_addresses=True` `long_lived_errors_from_files` отказывает файлу планки на каждой форме требования 4 (а)–(з) строкой вида «<файл>::<функция>: строка N: <нарушение>» с адресом нарушения.

AC-4. Чистые формы — `@pytest.mark.skipif` с причиной, `parametrize` литералами, фикстура без утверждений — отказа `long_lived_errors_from_files` не дают.

AC-5. Файл планки, содержащий и тест-функцию модуля, и класс с тестовыми методами, получает отказ смешения стилей при `network_addresses=True`; при `amend-tests` с `lint_base`, где залоченный текст этого файла уже смешивал стили, отказа смешения нет.

AC-6. При `network_addresses=False` (чужой проект) ни одна форма требования 4 (а)–(з) и смешение стилей отказа не дают.

AC-7. `amend-tests` с `lint_base`: залоченный метод (или фикстура) с формой требования 4, чей `ast.dump` совпадает с базой под тем же именем, отказа не даёт; тот же нарушающий метод, добавленный правкой (в базе его нет или его `ast.dump` иной), получает отказ.

AC-8. Докстринг `scripts/guard.py` в месте прежней строки 865 говорит «pytest на гейте»; фразы «unittest на гейте» в `scripts/guard.py` нет.

AC-9. Ветка не меняет `orchestrator/advance_gates/test_integrity.py` и `orchestrator/advance_gates/two_sided.py`; счёт тестов guard (`count_test_methods`) для тест-функции, запрашивающей фикстуру с `params=` или параметризованной `parametrize`, остаётся «одна функция — один тест».

## Оценка объёма и деление

Сработавший сигнал: зона задевает механизм, на который опирается запись в `docs/invariants.md` — `scripts/guard.py` и `tests/` названы в инварианте 38 (гейт неослабления тестов: `weakened_helpers`/`_assertion_records` — его узел наблюдения).

Обоснование монолита (материал для решения Оператора): Оператор уже разрезал исполнение ADR-0027 по зонам на А1 (`tests/fixtures.py`), А2 (`scripts/guard.py`) и Б (скилы, инвариант). Внутри А2 кодовая зона — один файл `scripts/guard.py`; дальнейшая нарезка (прослеживание фикстур, требования 1–3, отдельно от отказов, требования 4–5) резала бы этот файл поперёк. Кроме того, признак ослабления фикстуры по изменению тела (требование 3) опирается на правило «фикстура без утверждений» (требование 4 (а)): часть с прослеживанием без отказа пропускала бы утверждения в фикстурах, которые `weakened_helpers` больше не сравнивает по утверждениям, — промежуточное состояние ослабляло бы наблюдение гейта неослабления.

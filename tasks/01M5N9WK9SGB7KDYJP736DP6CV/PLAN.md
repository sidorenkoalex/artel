# PLAN: ADR-0027, часть А2 — guard прослеживает фикстуры pytest и отказывает скрытым пропускам, вариантам и смешению стилей

## Подход
Вся правка — в `scripts/guard.py` (плюс регенерация `docs/codebase-map.md`).

1. **Имена pytest через псевдонимы** (треб. 2): `_pytest_aliases(tree)` собирает
   имена, связанные с модулем `pytest` (`import pytest`, `import pytest as pt`) и
   имена из `from pytest import …`; `_pytest_name(node, aliases)` даёт каноническое
   `pytest.<…>` для цепочки Name/Attribute (вызов разворачивается). Им пользуются
   все новые правила.
2. **Фикстуры и их разрешение** (треб. 1): фикстура — функция с декоратором
   `pytest.fixture` (с вызовом или без), имя регистрации — `name=` либо имя
   функции. Пространство имён теста: фикстуры своего класса → своего модуля →
   `tests/fixtures.py` (через `TestModules.module`, только правило артели, у
   внешнего проекта не грузится). Запрошенные имена: параметры (кроме
   `self`/`cls` и имён аргументов `parametrize`, не помеченных `indirect`),
   `usefixtures` на тесте, классе, в `pytestmark` класса и модуля, `autouse`
   своего файла. Фикстура, запрошенная фикстурой, — один уровень.
3. **Запись данных фикстуры** (треб. 3, 8): собственный вид записи — узел
   `_FixtureDatum(value=<литерал>)` (подкласс `ast.AST`): все литералы тела
   фикстуры кроме докстринга (знак над числом — часть литерала, как `_literal`),
   затем литералы помощников первого уровня, которых фикстура зовёт (функции
   своего модуля, методы своего класса и функции любого модуля `tests/` по
   импорту — `_fixture_helper_calls`, ревью R1-F1; происхождение записи
   помощника чужого файла — `("фикстура <имя> → <помощник>", путь помощника)`,
   мандат на файл помощника покрывает находку). Ключ —
   `(файл фикстуры, имя фикстуры, порядковый номер, ast.dump литерала)`, текст —
   «данные фикстуры <имя> [→ помощник <h>] (<файл>): <литерал>», происхождение —
   `None` у фикстуры своего файла, иначе `("фикстура <имя>", путь)` (как у
   помощника чужого модуля: мандат на `tests/fixtures.py` покрывает находку).
4. **Потребители** (треб. 4): `_assertion_kind` даёт записи фикстуры свой вид
   «данные фикстуры» (без обращения к `func`), `_constant_roles` — пустые роли,
   поэтому пара получает «правило не умеет оценить строгость» и объявление в
   «Меняемое поведение» находку не снимает (AC-10); `method_literal_keys`,
   храповик, `assertion_changes` работают без изменений через
   `_literal_positions`.
5. **`weakened_helpers`** (треб. 5): к прежнему правилу добавлены фикстуры с
   изменённым телом (`ast.dump` узла) или исчезнувшие, помощники фикстур с
   изменённым телом и фикстуры своего файла, которые вызывают такого помощника
   или запрашивают изменённую фикстуру. Сверх того — функции модуля (не тесты,
   не фикстуры) с иной последовательностью литералов или исчезнувшие
   (R1-F1): помощник фикстуры чужого файла виден записи только литералами,
   и по его имени поиск вызывающих находит файл фикстуры. Сравниваются именно
   литералы, а не всё тело, чтобы правка `tests/sandbox.py` без смены данных
   не расширяла поиск вызывающих.
6. **Отказы стиля pytest** (треб. 6, 7): `pytest_style_errors_from_files` —
   формы (а)–(з) и смешение стилей, строка «<файл>::<функция>: строка N:
   <нарушение>», модульная форма — «<файл>::<модуль>: …». Исключение
   `lint_base`: нарушение функции не считается, если все функции, на которых оно
   стоит (фикстура и помощник у формы (а)), в базе совпадают по `ast.dump`;
   модульное — если в базе есть оператор верхнего уровня с тем же `ast.dump`;
   смешение — если залоченный текст стили смешивал. Вызов — в
   `long_lived_errors_from_files` рядом с `lint_errors_from_files`, до фильтра
   группы, только при `network_addresses`.
7. Докстринг: «unittest на гейте» → «pytest на гейте» (треб. 9).

Расхождения с оценкой SPEC нет, `budget_usd` не меняется.

## Шаги
1. Псевдонимы pytest, разрешение фикстур, запись данных фикстуры в
   `_assertion_records`, вид записи у потребителей, `weakened_helpers`.
2. `pytest_style_errors_from_files` и подключение в `long_lived_errors_from_files`;
   докстринг; карта кода.
3. Свои тесты `tests/test_guard_pytest_fixtures.py` (pytest-стиль) на свойства
   сверх долгоживущих файлов: `indirect=` оставляет имя фикстурой, фикстура
   тела класса, своя фикстура, переопределяющая одноимённую общую, `indirect=`
   в `pytestmark` (адрес «<модуль>»), `weakened_helpers` по фикстуре,
   запросившей изменённую.
4. Прогон долгоживущих файлов задачи, планки (`plank-run`) и тестов затронутых
   модулей guard / test_integrity; мутационная проверка заявок.

## Влияние на систему
- Гейт неослабления (инвариант 38) становится строже: записи данных фикстур
  входят в сравнение, храповик и поиск вызывающих вне диффа. Прежние записи
  утверждений и их ключи не меняются — существующие тесты unittest-стиля фикстур
  не имеют, их наблюдение прежнее.
- Новые отказы `long_lived_errors_from_files` касаются только артели
  (`network_addresses`) и залоченных текстов не задевают (`lint_base`).
- `orchestrator/advance_gates/test_integrity.py` и `two_sided.py` не меняются.
- Откат — revert коммита задачи.

## Риски
- Запись фикстуры с нескалярным литералом (строка, байты) — ключ по `ast.dump`, роль
  пустая; любая правка — находка, это ожидаемо (ADR-0027 п. 3).
- Большие фикстуры дают много записей — только в тестах нового стиля.
- Поиск вызывающих вне диффа — один шаг по имени (`test_integrity.py` не
  меняется): помощник из модуля `X`, импортированный фикстурой
  `tests/fixtures.py`, которая сама вне диффа, находит `tests/fixtures.py`, но
  не тест в третьем файле, запросивший эту фикстуру. Если в диффе меняется сама
  фикстура или её файл, тест находится (требование 5). Цепочка «помощник → общая
  фикстура → тест» требует второго шага поиска в `test_integrity.py` — вне зоны.
- Функция модуля `tests/` с иными литералами теперь расширяет поиск вызывающих
  (больше файлов сравнивается); находок без смены записей это не даёт.

## Предложения системе
- Мутационная проверка сторожа в шаге разработчика требует `sys.argv` под
  сторож `conftest.py` и подмены модуля в памяти — штатной команды «прогони
  файл tests/ с временной мутацией» у пульта нет; так же неудобно и test_author
  (записка: временный плагин-стаб).

# ADR-0027, часть А2: guard прослеживает фикстуры pytest и отказывает скрытым пропускам, скрытым вариантам и смешению стилей в файлах планки

## Факты

ADR-0027 «Новые тесты артели в стиле pytest» принят Оператором 23.10.2026 (`docs/adr/0027-pytest-style-tests.md`, пп. 3–5). Исполнение: А1 — общие фикстуры `tests/fixtures.py` и их подключение (задача 01M5N9V4S984GRRXSMBK5JX7V1, идёт параллельно; зоны не пересекаются); А2 (эта) — правила guard; Б — приложения к скилам и инвариант. Сверено с пином 8cff887c; независимая проверка черновика 24.10.

- guard (`scripts/guard.py`): тестом считаются и функции модуля, и методы (`_collect_qualified_test_functions`, :1040). Пропуски: `SKIP_DECORATOR_NAMES` (:1082), `SKIP_CALL_NAMES = ("skipTest", "pytest.skip")` (:1089), `test_skip_markers` (:1155), `resolved_skip_markers` (:1312) — `pytest.xfail(...)` и `pytest.importorskip(...)` в теле теста и `pytest.skip(...)` внутри фикстуры не видны. Параметризация: `_is_parametrize` (:1395), `parametrize_variants` (:1492) — `@pytest.fixture(params=…)`, `indirect=`, `pytest_generate_tests` не видны.
- Помощники прослеживаются только по вызову: `_HelperScope` (:1828), `test_assertions` (:1949), `_assertion_records` (тот же разбор); фикстура, подставляемая по имени параметра, не видна. `weakened_helpers` (:1999) находит помощника, потерявшего утверждения, — фикстура по правилу ADR-0027 утверждений не несёт, поэтому этим признаком её ослабление не найти. `_helper_callers` (`orchestrator/advance_gates/test_integrity.py:788`) ищет вызывающих поиском слова (`git grep -w`) по `tests/` — имя параметра-фикстуры находит без правки.
- Правила файлов планки и долгоживущих файлов исполняет `long_lived_errors_from_files` (:3982), там же — линт детерминизма (`lint_errors_from_files`) до фильтра по группе при `network_addresses`; признак проекта артели передают вызывающие (`tests_writing`, `preflight`, `amend`, `fsm_advance`) параметром `network_addresses=repo_context.is_artel(target)`. Для `amend-tests` есть `lint_base` (текст залоченного состояния).
- Устаревшая фраза «unittest на гейте» — `scripts/guard.py:865`.

## Требования

1. Фикстура — объявление `@pytest.fixture` (с вызовом или без) в том же файле или в `tests/fixtures.py`. Для теста-функции и метода фикстурами считаются: параметры с именем фикстуры, имена из `@pytest.mark.usefixtures(...)` и фикстуры `autouse=True` своего файла. Фикстура, запрошенная другой фикстурой, прослеживается на один уровень (как помощник).
2. Прослеживание данных фикстур: тест, запрашивающий фикстуру, получает в разборе утверждений (`_assertion_records`) запись о данных фикстуры — возвращаемые (`return`/`yield`) и присваиваемые литералы — с указанием происхождения (имя фикстуры, файл), так что наблюдение гейта неослабления различает сторону базы и сторону головы и у вызывающих вне диффа.
3. Ослабление фикстуры: `weakened_helpers` возвращает имя фикстуры, если изменилось её тело (сравнение синтаксических деревьев `ast.dump`), — вызывающие находятся прежним `_helper_callers`. `orchestrator/advance_gates/test_integrity.py` не меняется.
4. Отказ guard в файлах планки и в долгоживущих файлах — в `long_lived_errors_from_files`, рядом с `lint_errors_from_files`, до фильтра по группе, только при `network_addresses`; вызывающие не меняются. Строка отказа — «<файл>::<функция>: строка N: <нарушение>». Формы: (а) утверждение (`assert`, `pytest.raises`, `pytest.warns`, `self.assert*`, `self.fail`) внутри фикстуры; (б) `pytest.xfail(` и `pytest.importorskip(` в теле теста; (в) `pytest.skip(` внутри фикстуры; (г) `@pytest.fixture(params=…)`; (д) аргумент `indirect=` у `parametrize`; (е) функция `pytest_generate_tests`; (ж) `request.getfixturevalue(`; (з) `@pytest.fixture(name=…)`. Для `amend-tests` с `lint_base` нарушение метода не считается, если у метода (или фикстуры) с тем же именем в базе одинаковый `ast.dump` — как у линта детерминизма.
5. Смешение стилей — отказ в тех же местах и при том же признаке: файл, в котором есть и тест-функция модуля, и класс с тестовыми методами. Для `amend-tests` с `lint_base` — только если залоченный текст стили не смешивал.
6. Двусторонний прогон и счёт тестов не меняются (ошибка фикстуры уже даёт фазу setup; одна функция — один тест).
7. Устаревшая фраза `scripts/guard.py:865` исправляется на «pytest на гейте».
8. Тесты (новые файлы в `tests/`, сами в стиле pytest — функции и `parametrize`; общие фикстуры А1 не используются — их может ещё не быть в main; у каждой функции — «Ловит мутацию:»): (а) правка ожидаемого литерала в фикстуре залоченного теста — `weakened_helpers` называет фикстуру, запись данных фикстуры различает базу и голову; (б) прослеживание по параметру, по `usefixtures`, по `autouse` и на один уровень вложенности (`parametrize` по формам); (в) каждая форма требования 4 — отказ с адресом; чистые формы (`@pytest.mark.skipif` с причиной, `parametrize` литералами, фикстура без утверждений) — без отказа; (г) смешение стилей — отказ; `amend-tests` по залоченному смешанному файлу — без отказа; (д) чужой проект — без отказа по всем формам; (е) `amend-tests`: залоченный метод с формой (б) не меняется правкой — без отказа, добавленный правкой — отказ. Мутации: фикстура не прослеживается; `pytest.xfail` пропущен; `fixture(params=)` пропущен; проверка без признака артели.
9. Существующие тесты не правятся и остаются зелёными.

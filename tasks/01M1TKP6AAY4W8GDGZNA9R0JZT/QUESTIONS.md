# QUESTIONS: P1a — раннер pytest в пульте: acceptance, dry_run, amend и их тесты

## Вопросы

1. **Требование 1 ТЗ.md называет `orchestrator/dry_run.py` в списке
   «мест, где пульт сам запускает тесты и читает итог» и требует, чтобы
   разбор итога там перешёл со строки unittest «Ran N … OK» на сводку
   pytest («N passed», «failed», «error»); зона задачи тоже включает
   этот файл. По факту `dry_run.py` (прочитан целиком) НЕ запускает
   тесты и НЕ парсит итог прогона вообще: докстринг модуля прямо
   говорит «не запускает unittest» (dry_run.py:5), команда только читает
   `SPEC.md`/`acceptance_tests/` с ветки через git и печатает статичный
   разбор AC-маркеров (`guard.scan_ac_content`) — ни `subprocess`, ни
   регулярки вида `_RUN_SUMMARY` (та живёт только в `amend.py:47-48`) в
   файле нет. Это расходится с буквальным текстом ТЗ, и без ответа
   непонятно, какое именно требование к `dry_run.py` писать в SPEC —
   варианты:
   A) `dry_run.py` попал в список по ошибке (перепутан с `amend.py`,
      единственным реальным местом с разбором «Ran N … OK» вне
      `acceptance.py`) — исключить файл и из требования 1, и из зон
      задачи;
   B) У `dry_run.py` есть скрытое ожидание — какое именно (например,
      сухой прогон должен начать реально запускать pytest, а не только
      статически парсить AC-маркеры) — уточнить формулировкой в TZ.md;
   — дефолт: A (файл исключается из требования 1 и из зон задачи; SPEC
   зон будет: `orchestrator/acceptance.py`, `orchestrator/amend.py`,
   `orchestrator/stack.py`, `orchestrator/doctor.py`, `pyproject.toml`,
   `tests/`) — расхождение с явным поведением кода перевешивает
   буквальное упоминание файла в ТЗ, а безопасный дефолт при
   молчании — не расширять зону задачи требованием, не выводимым из
   действующего кода.

# ТЗ: Штатная команда правки зафиксированной планки приёмки

Источник: ADR-0012 (принят 02.09.2026) — учреждает механизм и прямо
поручает завести эту задачу. Фактура: три случая за 02.09, каждый
потребовал ручной цепочки «правка → обновление tests_locked_sha
прямой записью в БД → запись в журнал руками» с войной правок в
первом случае.

Суть: одна операторская команда исполняет правку планки целиком —
атомарно, журналируемо, с машинно-проверяемым основанием, — заменяя
ручную цепочку и ссылки на ADR в коммитах.

Требуется:
1. Операторская команда (имя — решение исполнителя, например
   `amend-tests <id> --reason "<основание>"`): фиксирует уже
   внесённые Оператором в worktree задачи изменения каталога
   `tasks/<id>/acceptance_tests/` коммитом в ветку задачи,
   обновляет `tests_locked_sha` на новый коммит и пишет журнальное
   событие (actor=operator) с прежним и новым sha и основанием.
2. Команда отказывает именованно, если: изменений в каталоге нет;
   изменения выходят за пределы `acceptance_tests/`; задача не
   проходила фиксацию лока (lock ещё не ставился); основание
   (--reason) пустое.
3. Журнальное событие команды — признаваемое ревьювером основание
   правки планки (skills/review-checklist.md уже обновлён ADR-0012);
   ссылка на ADR в сообщении коммита после появления команды не
   требуется — коммит формирует сама команда со стандартным
   сообщением, включающим основание.
4. Ограничители ADR-0012 — в поведении команды: событие журнала
   помечено как «правка планки»; счётчик таких событий доступен
   отчётности; превышение порога (больше одной правки на пять
   задач, скользяще) поднимает алерт «планка девальвируется»
   существующим механизмом alerts.
5. Команда не оценивает существо правки (неослабление проверяет
   ревьювер по чек-листу) и не запускает агентов.
6. Тесты: успешная правка (коммит, лок, журнал, стандартное
   сообщение); каждый именованный отказ из п.2; счётчик и алерт
   порога; существующие тесты (включая LockTest инварианта 27)
   зелёные без ослабления.

Зоны: orchestrator/artel.py (регистрация), новый модуль
orchestrator/amend.py (или размещение по выбору исполнителя),
orchestrator/store.py — только точечное обновление tests_locked_sha
и журнал существующим API, orchestrator/alerts.py (порог), tests/.
ЗАПУСКАТЬ ПОСЛЕ мержа A7 (01M1H224X5…): его ориентировочные зоны
включают store.py/catalog.py/fsm_merge_gate.py. Конфликт зон —
эскалация.

Не входит: изменение механики лока (инвариант 27 не трогается —
команда легальный вход в него, не ослабление); автоматическая
генерация правок; правка других артефактов задачи.

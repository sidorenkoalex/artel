# ANSWER-1: ответ Оператора

## Ответы

Вопрос 1 — вариант B.

Окно порога «планка девальвируется» (ADR-0012 п.3, ТЗ п.4) —
последние 5 задач пульта, ДОШЕДШИХ до фиксации лока (вышедших из
`tests_writing`), по порядку заведения, по всем target (как пороги
программы, инвариант 23); задач меньше 5 — берётся всё, что есть.
Правки считаются по числу журнальных событий «правка планки» с
task_id из этих 5 задач (повторная правка той же задачи — вторая
единица). Проверка — сразу после записи нового события правки.

Обоснование: население «любые 5 последних заведённых» (вариант A)
разбавляется всплесками заведения — 03.09 заведено шесть задач,
три ещё не прошли лок; при A порог, только что превышенный вчетверо,
не сработал бы. Кумулятивное отношение (вариант C) не стареет —
сегодняшний всплеск размазался бы навсегда. Считать по тем, у кого
планка вообще существует, — единственно осмысленный знаменатель.

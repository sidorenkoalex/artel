# ANSWER-3: ответ Оператора

## Ответы

Решение Оператора 03.09: задача написана до A7, модель планки в ней
устарела; объём пересматривается этим ответом (пересмотр SPEC по
машинно-видимому каналу, ADR-0012).

Вопрос 1 (фикстура `AmendSandbox`) — вариант (б): переписать
`AmendSandbox` по образцу `tests/test_acceptance_tests_flow.py::LockTest`:
SPEC.md/PLAN.md/acceptance_tests пишутся прямо в артефактную ветку
задачи (через `artifact_branch.commit_files` либо приём `LockTest`),
worktree кодовой ветки (`workspace.ensure`) используется только там,
где им реально оперирует команда. Лок снят Оператором на файл
`tasks/01M1HNNHDMP2C1AJTH5QF1BTN2/acceptance_tests/_sandbox.py`
целиком под это переписывание; ограничители ADR-0012: содержание и
утверждения AC-1..AC-13 в тестовых файлах не меняются и не
ослабляются, другие файлы `acceptance_tests/` не трогать, кроме
минимальных правок вызовов фикстуры, если её интерфейс изменился
(перечислить в PLAN); отдельный коммит с ссылкой на этот ANSWER-3.

Вопрос 2 (`orchestrator/amend.py`) — дефект признаётся, правка в
объёме этой задачи. Требование 1 SPEC читать так: после A7 планка
задачи живёт в артефактной ветке пульта (`artifact/<id>`), и «коммит
в ветку задачи» означает коммит в АРТЕФАКТНУЮ ветку. Команда
`amend-tests`:
- берёт правку Оператора из `tasks/<id>/acceptance_tests/` рабочего
  каталога задачи (worktree; если каталога нет — материализует его из
  артефактной ветки перед правкой, отдельной подкомандой либо
  указанием в подсказке команды — выбор разработчика, зафиксировать
  в PLAN);
- коммитит новое содержимое `acceptance_tests/` в артефактную ветку
  без чекаута (`artifact_branch.commit_files`, тем же приёмом, что
  `checkpoint._commit_external_step_artifacts`), с основанием в
  сообщении коммита;
- переводит `tests_locked_sha` на голову артефактной ветки после
  этого коммита — ту же, с которой гейт `in_dev -> review` сверяет
  лок;
- игнорируемые `.gitignore` файлы (`__pycache__`, `*.pyc`) в коммит
  не попадают;
- юнит-тест «amend-tests -> сразу advance в review проходит гейт
  лока» в `tests/test_amend.py`.

Обязательный прогон до итоговой строки: планка задачи и полный
`tests/`; обе строки «Ran N … OK» — в PLAN, «Влияние на систему».
Бюджет задачи поднят до 50.

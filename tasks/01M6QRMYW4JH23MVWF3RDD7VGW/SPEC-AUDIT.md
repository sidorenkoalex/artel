- `realpath(<t>/r.git#main)` → `<t>/r.git#main` (внутри дерева) —

- `<t>/sub/../../t2` → `<p>/t2`; ссылка `t/link` → `<p>/t2`; `t/inner` →

`h/r.git#main` доходит до проверки как `<каталог compose>/h/r.git#main`,
то есть именно случай решения №2.2; на корректность SPEC это не влияет:
оба вида отвергаются.

## Пути обхода гейтов
- Распознавание адреса git только по `.git#`: проходит AC-3, но
  `https://…`/`git@…` всё равно отвергаются «закрыто по умолчанию» (не
  абсолютны) — смысл не обходится.
- Проверка привилегий только у сервиса тестов (`profile.compose_service`)
  при всех случаях AC-6 на нём: стенд с привилегированным сервисом БД
  прошёл бы. Функция профиль не получает (`:1077`), и требование 2 говорит
  «у сервиса» — мутация маловероятна; см. отклонение 3.
- Именованный том короткой строкой, ставший отказом, не обходит гейт, а
  ломает законные стенды — см. отклонение 1.

## Вердикт
`concerns` — SPEC вести дальше можно, отклонения решаются на гейте:

1. Требование 5 (`SPEC.md`, «Требования» п. 5: «короткая строка без `/`,
   `.` и `~` в начале по-прежнему читается как именованный том») не
   закреплено критерием: AC-7 подаёт именованный том только длинной формой
   `type: volume`. Мутация «каждый источник короткой строки проверяется как
   путь» (правка `_bind_sources` `orchestrator/acceptance.py:1070-1073`)
   отвергнет `name:/data` как неабсолютный — тест зелёный. Аналогично нет
   положительного случая короткой строки bind внутри дерева. Вывод
   `config --format json` даёт длинную форму, так что вред практический мал;
   решение — добавить в AC-7 случаи `"<имя тома>:/data"` и
   `"<дерево>/<подкаталог>:/y"` или принять как есть.
2. Требование 3 («`up` и `run` после отказа не зовутся»; текст называет
   поле и значение) явно закреплено только в AC-1 и AC-2; AC-3, AC-5, AC-6
   требуют лишь «отказ запуска» (AC-6 — имя сервиса и поля, без значения).
   Мутация «отказ по привилегии формируется без значения поля» не поймана.
   Минорно: возврат один (`:1289-1290`).
3. AC-6 не требует случая привилегии на сервисе, отличном от сервиса
   тестов; мутация «проверяется только `compose_service`» прошла бы
   (минорно, см. «Пути обхода гейтов»).
4. Незаданные краевые случаи (не отклонение, к сведению): `file: null` у
   секрета — «секрет без `file`» или «`null` — отказ»; `build` словарём без
   ключа `context`. compose-go таких значений не выдаёт; разработчик выберет
   сам, тесты их не касаются.

Факты SPEC и решений Оператора о коде и `realpath` подтверждены (раздел
«Факты против кода»); тесты ядра не краснеют.

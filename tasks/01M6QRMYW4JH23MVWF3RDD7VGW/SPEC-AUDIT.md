## Пути обхода гейтов
- Требование 4 «для того же объекта»: у сервиса два bind — первый вне
  дерева, второй сокет; реализация «по источнику» даст текст «вне дерева».
  AC-9 с одним bind этого не различает; запуск отказан в любом случае —
  безопасность не страдает, замечание без отклонения.
- `build` словарём без `context`: не сказано, отказ это (как `null`) или
  пропуск. Вывод `config` контекст всегда заполняет — обхода нет,
  замечание без отклонения.
- Перечень привилегий требования 2 закрытый (например `security_opt`
  `seccomp=<файл>` читает файл машины клиентом docker) — вне ТЗ, не
  отклонение.

## Вердикт
concerns — два малых отклонения, решаемых Оператором на гейте:
1. SPEC.md:57 — «элемент раздела `secrets`/`configs` не словарь — отказ»
   без случая в AC-5 (SPEC.md:124-130; решение 6 перечислило только три
   случая). Сейчас orchestrator/acceptance.py:1114 на строковом элементе
   падает `AttributeError`; мутация «элемент не словарь — исключение или
   пропуск» тестами не ловится. Варианты: добавить случай
   `secrets: {n: "x"}` в AC-5 (дефолт) либо принять требование без теста.
2. SPEC.md:50, AC-3 SPEC.md:104-106 — три git-значения `https://h/r.git`,
   `git@h:r.git`, `h/r.git#main` неабсолютны и отказываются уже правилом
   «закрыто по умолчанию»; мутация «нет проверки адреса git» не ловится.
   Отличил бы её только абсолютный путь в дереве вида `<tree>/r.git#main`
   (`realpath` оставляет его в дереве — опыт выше); воспринимает ли такой
   контекст сборщик как адрес git — опытом не проверено (docker нет).
   Варианты: добавить случай `<tree>/r.git#main` — отказ; либо принять
   git-пункт как избыточный к «закрыто по умолчанию».

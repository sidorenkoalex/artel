# ТЗ: Гейт свежести: документные коммиты main без подтяжки

Источник: копилка docs/backlog.md, строка П1 от 11.09 «Документные
коммиты `note` сбивают цикл мержа». Решение Оператора 12.09: волна 3.

Факты:
- Гейт свежести (`fsm._pull_main_or_escalate` -> `pull.evaluate`,
  orchestrator/pull.py:~314–345) считает ветку несвежей при ЛЮБОМ
  количестве коммитов `origin/<main>`, которых нет в ветке
  (`gitcmd.commits_behind(branch, base=origin_sha)` > 0), и делает
  подтяжку (merge main в ветку) с последующим WIP-чекпоинтом,
  материализацией и прогоном планки; на merge_gate -> done после
  подтяжки ещё и ждёт зелёный CI на новом sha. Три точки сверки:
  in_dev -> review, acceptance -> merge_gate, merge_gate -> done.
- `note` (orchestrator/notes.py:~272–305) пушит в main КАЖДУЮ строку
  копилки/бэклога отдельным коммитом (`docs/backlog.md`); операторские
  документные коммиты (роадмап, ADR, копилка) — тоже по одному.
- 11.09 шестую подтяжку цикла approve у 01M283NC… (adcb5617), после
  которой истёк потолок 3600 с без единого мержа, вызвали три записи
  копилки той же сессии в 18:30–18:34Z; 12.09 push мержа части 2
  (01M291EPQ2) отклонён из-за записи копилки посреди цикла — approve
  перезапускался. Сессия сама сбивает свой мерж; правило «не писать
  копилку во время цикла мержа» противоречит правилу «аномалия
  фиксируется сразу».
- Класс пуша ADR-0016 (scripts/ci_push_class.py, `_DOC_PATTERN =
  r"^(docs/|tasks/|[^/]+\.md$)"`, `_is_doc_path`, `classify`) уже
  признаёт: документный пуш в main при зелёном родителе тестов не
  требует. Один источник истины классификации — этот модуль
  (orchestrator уже импортирует `scripts.guard`, `scripts.codebase_map`
  тем же приёмом `from scripts import …`).
- Плотницкий merge на merge_gate -> done (`fsm_merge_gate`) идёт в
  scratch-worktree на sha origin/main и вливает ветку задачи — итоговое
  дерево main содержит и документные коммиты, и дифф ветки независимо
  от того, подтянута ли ветка.

Требуется:
1. `pull.evaluate`: ветка признаётся свежей (`Fresh`) не только при
   `behind == 0`, но и когда ВСЕ файлы, изменённые в main с точки
   расхождения (`git diff --name-only <merge-base(branch, base)>
   <base>`), (а) документные по классификации `scripts.ci_push_class`
   (`_is_doc_path` — сделать публичной `is_doc_path`, без изменения
   регулярного выражения) и (б) не пересекаются с файлами диффа самой
   ветки (`git diff --name-only <merge-base> <branch>`). Оба условия
   обязательны; любой недокументный либо пересекающийся файл —
   прежнее поведение (подтяжка) байт-в-байт.
2. Пропуск подтяжки журналируется записью «свежесть: N документных
   коммитов main без подтяжки» с перечнем путей (первые 10) в
   `detail`, чтобы в `log` было видно, почему подтяжки не было.
3. Правило действует одинаково на всех трёх точках сверки; на
   merge_gate -> done сверка зелёного CI по-прежнему идёт по sha головы
   ветки — новых требований к CI нет (ADR-0016 уже принимает
   «документные изменения тестов не требуют»).
4. `scripts/ci_push_class.py`: публичное имя `is_doc_path` (старое
   `_is_doc_path` остаётся псевдонимом либо переименовывается вместе с
   его тестами в tests/test_ci_push_class.py без ослабления).
5. Тесты в tests/test_pull.py (стенд с bare origin по образцу
   существующих): (а) main ушёл вперёд только на коммит
   `docs/backlog.md` — `Fresh`, merge-коммита в ветке нет, запись
   журнала есть (мутация «подтяжка всё равно делается» — красный);
   (б) main ушёл на коммит `docs/x.md` + `orchestrator/a.py` — прежняя
   подтяжка (`Pulled`); (в) main изменил документный файл, который
   ветка тоже правит (например docs/backlog.md в обеих) — подтяжка;
   (г) корневой `README.md` — документный, `skills/x.md` — нет
   (классификация ci_push_class). Существующие тесты pull и merge_gate
   — без ослабления.

Зоны: orchestrator/pull.py, scripts/ci_push_class.py, tests/.

Приложением: orchestrator/fsm.py (`_pull_main_or_escalate`, вызов
`pull.evaluate`), orchestrator/fsm_merge_gate.py (окно мержа, порядок
«свежесть -> зелёный CI -> плотницкий merge»), orchestrator/notes.py
(`_attempt`, механика удержания `.artel/notes-pending/`),
docs/adr/0016-*.md (класс пуша), docs/backlog.md (строка П1 от 11.09
«Документные коммиты `note` сбивают цикл мержа»).

Не входит: удержание `note` на время живого мержа (кандидат (б) —
отдельное решение); правка notes.py, fsm.py, fsm_merge_gate.py; правило
operator-session (кандидат (в) — правка Оператора); изменение самого
регулярного выражения класса документного пути.

# PLAN: Бриф роли внешнего проекта: конвенции и карта проекта, а не пульта

## Подход
Одна развилка `brief.is_artel_task(conn, task_id)` —
`repo_context.is_artel(store.task_target(conn, task_id))`, тот же признак
проекта, что у остальных потребителей (требование 1). На ветке артели код
четырёх сборщиков брифа не меняется ни порядком вызовов, ни текстом
(AC-1 сравнивает побайтно); на ветке внешнего проекта:

- карта пульта (`_fresh_map_text_and_note`/`fresh_map_text`, проекция,
  `MAP_PROJECTION_NOTE`, `_handle_map_size_alert`) не вызывается вовсе —
  нет ни сверки свежести, ни регенерации, ни алертов карты (требования 2-3);
- `CLAUDE.md` пульта (`_main_branch_text`) не читается; вместо него —
  `_project_conventions_parts`: `CLAUDE.md` и `AGENTS.md` корня
  `refs/heads/<base>` клона проекта. База и клон — `repo_context.resolve`,
  коммит базы — `reference_cache.branch_commit` (без `fetch`), состав корня —
  `git ls-tree <sha>`, текст — `git show <sha>:<файл>` байтами (не
  `gitcmd.show`, чей `None` одинаков для «файла нет» и сбоя git): так «файла
  нет в ls-tree» (пометка «файла нет») отличается от «файл есть, чтение не
  удалось» (пометка «конвенции проекта не прочитаны: <причина>») —
  требования 4, 7, 9;
- сбой чтения базы (контекст не разрешён, клона нет, ветки нет, git не
  ответил, ls-tree не удался) — одна пометка «конвенции проекта не
  прочитаны: <причина>» и запись журнала `бриф: конвенции проекта не
  прочитаны` с той же причиной, без `sys.exit` (требование 8); чтение
  SPEC.md (`_developer_spec_text`) идёт раньше и по-прежнему отказывает;
- оформление — `render` соседей роли: `_manifest_component` у developer и
  spec_auditor, `_journal_component` у analyst и test_author (требование 5);
  у test_author добавка внешнего проекта не `None` всегда (требование 6).

Миссии (`role_prompt.py`): у задачи внешнего проекта developer —
«SPEC задачи, конвенции проекта (CLAUDE.md и AGENTS.md базовой ветки
проекта) и шаблон … — в БРИФЕ РОЛИ; правила работы роли — в скилах
пульта»; analyst и spec_auditor — без карты кодовой базы. Тексты артели —
прежние строки как есть (требование 10-11).

## Влияние на систему
Задеты только сборка брифа и миссии ролей задач внешних проектов. Ветка
артели исполняет прежний код в прежнем порядке — бриф, опись, журнал
компонентов и миссии те же (AC-1 эталоном с базы ветки). Гейты, guard,
лимиты не трогаются; отказ на нечитаемом SPEC.md сохранён. Новое для
внешнего проекта: чтение git в его клоне (`ls-tree`/`show` локального
коммита базы, таймаут `CORE_REFERENCE_GIT_TIMEOUT_SEC`), без записи и без
сети. Карта пульта больше не регенерируется сборкой брифа внешней задачи —
её свежесть для задач артели обеспечивается прежним путём. Откат — revert
merge-коммита задачи.

## Предложения системе
- `gitcmd.show` возвращает `None` и для «файла нет», и для сбоя git
  (`orchestrator/gitcmd.py:623-650`) — читателям, которым нужно различие,
  приходится обходить его своим `ls-tree`; стоит дать `show` третий исход.

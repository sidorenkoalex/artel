## Пути обхода гейтов
- **Г1 (concerns).** Требование 4 говорит «корень базовой ветки проекта», но не уточняет ref (локальная `refs/heads/<base>` клона, как `reference_cache.branch_commit`, `orchestrator/reference_cache.py:293-309`, или `origin/<base>`) и не задаёт исход при сбое чтения: нет клона, нет ветки, git не ответил, `repo_context.resolve` вернул `None`. Требование 6 описывает только отсутствие файла. Буквальное исполнение допускает два плохих варианта. (а) Любой сбой git сводится к пометке «файла нет»: шаг идёт без конвенций проекта, и это не видно — смысл требования 4 обойдён молча. (б) Сбой даёт `sys.exit`, как `_main_branch_text`: тогда существующие тесты шагов внешнего проекта на лёгком git (`tests/test_multitarget_invariants.py:375-397`, `tests/test_01m545eb0a9f191wtdspch36ga_project_role_step.py:199-224`) могут перестать запускать шаг, и разработчик начнёт подгонять тесты в `tests/` без требования-замены. Нужно решение: сбой чтения — отказ шага с именованной причиной или отдельная пометка, отличимая от «файла нет».
- **Г2 (minor).** Признак «внешний проект» можно взять из `foreign` (`_artifact_source_branch`, `brief.py:614`), а не из проекта задачи. Требование 1 это запрещает, а AC-1 ловит, только если фикстура артели несёт задачу с чужой артефактной веткой. Ошибку ловит AC-1 с фикстурой задачи артели в штатной форме; отдельного отклонения не поднимаю.

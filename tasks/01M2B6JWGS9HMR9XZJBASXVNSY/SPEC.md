# SPEC: lease: живой держатель своей сессии не переписывается

## Контекст

`lease.acquire` (orchestrator/lease.py:95–167), ветка «своя сессия»
(`row["session_id"] == session_id`, строки 115–117) сегодня переписывает
pid/hostname/heartbeat lease pid'ом ТЕКУЩЕГО процесса без проверки, жив
ли прежний держатель. 12.09 13:00:56Z команда `budget 01M2ARQD7C` той же
сессии, что и работающий `auto` (pid 21120, агент developer pgid 35482),
перезаписала lease своим pid (35909) и тут же завершилась: `status`
показал «[lease: ppid-15998 мёртв]» у живого цикла (`catalog.
_lease_holder_suffix` проверяет только pid держателя, не pgid агента), а
команда ДРУГОЙ сессии того же host перехватила бы такой lease немедленно
как «мёртвый» (проверка живости на своём host не ждёт протухания
heartbeat) и запустила бы вторую роль поверх работающей. Тот же путь
открыт для любой мутирующей команды своей сессии под `run_locked`
(`run`, `auto`, `answer`, `amend-tests`, `zones-extend`, `budget`);
сегодня двойной запуск такого рода (инцидент T043, 27.08) закрыт только
хуком клиента `.claude/hooks/guard-artel-bg.py`, привязанным к
конкретной LLM, а не пультом.

## Требования

1. `lease.acquire`, ветка «своя сессия» (`row["session_id"] ==
   session_id`): если pid прежнего держателя (`row["pid"]`) жив
   (`liveness._pid_alive`) и НЕ равен pid текущего процесса — строка
   lease НЕ переписывается (pid/hostname/heartbeat остаются прежними
   держателя).
   - Вызов с `same_host_ok=True` (сегодня единственный такой вызыватель
     — `budget`): возврат «не отказ, не взято с нуля» (`(None, False)`)
     без мутации строки — потолок задачи по-прежнему меняется под живым
     шагом (SPEC 01M1VBEDGM).
   - Остальные вызыватели (`same_host_ok=False`): именованный отказ
     `"[<task_id>] задачу прямо сейчас ведёт процесс <pid> этой же
     сессии (<действие держателя, если известно>) — дождись завершения
     шага либо artel.py stop <id>"` — тот же класс отказа, что уже
     существует для чужой сессии («задачу ведёт сессия …»).
   - `force=True` (сегодня единственный такой вызыватель — `kill`)
     перешагивает этот отказ так же, как уже перешагивает существующий
     отказ по чужой сессии: строка lease перезаписывается.
   - Продление тем же процессом (`row["pid"] == os.getpid()`) —
     поведение не меняется.
2. Отказ по требованию 1 останавливает повторный запуск `run`/`auto`
   той же сессии поверх уже работающего цикла на уровне пульта: второй
   `auto`/`run` той же сессии при живом первом (другой pid, та же
   сессия) отказывает ДО запуска роли агента.
3. `catalog._lease_holder_suffix`: статус «жив»/«мёртв» определяется по
   pid держателя И по pgid агента (`liveness._group_member_count`
   применительно к `row["pgid"]`) — если pid держателя мёртв, а группа
   pgid агента непуста, суффикс показывает «жив (агент pgid N)», а не
   «мёртв».
4. Разработчик отмечает в PLAN.md (секция «Предложения системе»), что
   после требований 1–2 хук клиента `.claude/hooks/guard-artel-bg.py`
   становится избыточным для закрытия двойного запуска — решение о его
   снятии принимает Оператор отдельно (файл вне зон этой задачи,
   править его в этой задаче не нужно).

## Критерии приёмки

AC-1. `lease.acquire`: своя сессия, pid прежнего держателя жив, НЕ равен
pid текущего процесса, `same_host_ok=False` — возвращается именованный
отказ, содержащий `task_id`, pid держателя и слова «этой же сессии»;
строка lease в БД (session_id/pid/hostname/heartbeat) остаётся прежней.

AC-2. То же условие (своя сессия, pid держателя жив, не равен
текущему), но `same_host_ok=True` — `acquire` возвращает `(None,
False)` без отказа; строка lease в БД остаётся прежней.

AC-3. Своя сессия, pid прежнего держателя мёртв (`liveness._pid_alive`
→ `False`) — строка lease перезаписывается pid/hostname/heartbeat
текущего процесса, как и до этой задачи.

AC-4. Своя сессия, pid прежнего держателя равен pid текущего процесса
— строка lease продлевается (heartbeat обновляется), как и до этой
задачи.

AC-5. Своя сессия, pid прежнего держателя жив и не равен текущему,
`force=True` — строка lease перезаписывается (отказ по AC-1
перешагивается), как перешагивается существующий отказ по чужой сессии.

AC-6. Второй вызов `run`/`auto` той же сессии, пока lease первого жив
(другой pid, та же сессия, `same_host_ok=False`) — получает отказ по
AC-1 до запуска роли агента.

AC-7. `catalog._lease_holder_suffix`: pid держателя мёртв, но
`liveness._group_member_count(row["pgid"]) > 0` — суффикс строки
`status` показывает «жив (агент pgid N)» вместо «мёртв».

AC-8. `catalog._lease_holder_suffix`: pid держателя жив — суффикс
«жив», как и до этой задачи; pid держателя мёртв и группа pgid пуста
(pgid отсутствует либо `_group_member_count` вернул 0) — суффикс
«мёртв», как и до этой задачи.

AC-9. Существующие тесты `tests/test_lease*.py`, `tests/test_budget*.py`
и `tests/test_catalog*.py` проходят без ослабления (ни одна существующая
проверка не удалена и не смягчена).

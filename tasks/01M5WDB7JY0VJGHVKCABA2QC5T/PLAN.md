# PLAN: GitLab Б1.2 — автор, соавтор и трейлер пульта, сжатие и перебазирование на входе в verifying, перезапись своей ветки

## Подход
Одно правило подписи коммита пульта — в `orchestrator/gitcmd.py` (там же,
где единая точка отправки части 1), все места коммитов пульта зовут его:

- `gitcmd.commit_author(project)` / `pult_identity(_args)` — автор и
  коммиттер `machine.commit_author`, иначе прежний автор места;
  `pult_message` — строка `policy.co_author` и трейлер
  `Artel-Actor: orchestrator` последним абзацем при любой записи;
  `journal_pult_commit` — запись «коммит пульта: <sha> (<вид>)» с `actor`
  `orchestrator` только при `commit_author` (журнал прочих проектов байт
  в байт прежний).
- Сверка автора — в `_push_plan` (единая точка отправки): для отправки
  ветки живой задачи проекта с `commit_author`, пока у задачи нет записи
  «ветка отправлена», зовётся `forge.token_user`; совпадение — отправка,
  именованный отказ реестра «token_user: не реализовано для <хостинг>» при
  том, что у реализации хостинга проекта в `forge.IMPLEMENTATIONS` функции
  `token_user` нет (сейчас — только github), — запись «сверка автора —
  после адаптера» и отправка (`gitcmd._token_user_unimplemented`; значение
  `forge` записи с литералами хостинга не сравнивается — сторож А0
  `test_ac9_no_support_literals_outside_targets`), любой иной исход, в том
  числе «не реализовано» от хостинга, у которого функция есть, — именованный отказ
  «отправка отказана … сверка автора …» с обоими значениями или причиной.
  Так сверку проходят все пути: переход, `amend-tests`, `pull-main`,
  адаптер.
- Запись «ветка отправлена» теперь читается как «ветка отправлена: <sha>»
  (действие `PUSH_SENT_ACTION = "ветка отправлена:"`, `detail` — по-прежнему
  `<sha> <ветка>`); записи прежнего вида `_last_sent_sha` тоже читает.
- Переход `in_dev -> verifying` (`fsm_advance.in_dev`): поля доставки
  читаются из записи проекта самим обработчиком; при `freshness: rebase`
  узел подтяжки зовётся с `merge_main=False` — чекпоинт WIP и отказ
  «посторонние файлы» на прежнем месте, без `git merge` и планки. После
  ВСЕХ рубежей (последний — сетевые адреса) при `squash_before_mr: true`
  `pull.prepare_branch`: отказ при любой незакоммиченной правке, сжатие
  `reset --soft <точка ответвления от головы main на origin>` + коммит
  пульта по `commit_template`, при `rebase` и кодовом отставании —
  `git rebase` на голову main; конфликт карты — регенерация
  `scripts/codebase_map.py`, аддитивных документов — прежнее union-слияние
  (стадии индекса при перебазировании обращены — порядок «main, затем
  ветка задачи» сохранён), прочий — `rebase --abort`, возврат ветки,
  эскалация с `PULL_CONFLICT_ROLE_STEP_MARKER`.
- Рубеж отправки (`_origin_push_gate`) для проекта со сжатием —
  `_rewrite_push_gate`: голова сервера через `remote_ref_state` (сбой —
  отказ «сеть»); записи нет и ветки нет — обычная отправка; записи нет,
  ветка есть — эскалация «ветка на сервере без записи отправки»; голова
  сервера ≠ sha записи — эскалация «чужой коммит»; иначе
  `--force-with-lease=refs/heads/<ветка>:<sha записи>`; отказ сервера —
  эскалация «перезапись отвергнута сервером» с текстом, без повтора;
  прочий сбой — «сеть». Отказ сверки автора на переходе — эскалация (и
  для проектов без сжатия). После любого отказа/эскалации отправки
  `pull.restore_branch` возвращает ветку к голове до сжатия.
- Приёмка остаётся после отправки (`_acceptance_run_refuses`) — гонится на
  итоговой голове.
- Пакет ревью: sha прошлого вердикта существует, но не предок головы —
  полный дифф от `gitcmd.diff_base` с пометкой «ветка перезаписана — дифф
  полный».
- Окружение роли (`runner.role_env`): `commit_author` записи проекта
  перекрывает `GIT_AUTHOR_*`/`GIT_COMMITTER_*` после `setdefault`.

## Шаги
1. `gitcmd.py`: подпись коммита пульта, запись «коммит пульта», сверка

   чекпоинты), `artifact_branch._write` (документы, паспорт, закрытие),
   `snapshot._history_commit`, `amend._commit_long_lived`,
   `pull._run_merge`/`_auto_resolve_conflict`; `runner.role_env`.
3. `pull.py`: `merge_main=False`, `prepare_branch`, `restore_branch`,
   разрешение конфликтов перебазирования; `fsm._pull_main_or_escalate` —
   проброс флага (только когда он не по умолчанию).
4. `fsm_advance.in_dev` и `advance_gates/tests_writing._origin_push_gate`
   — порядок «рубежи → сжатие → отправка → приёмка», перезапись и исходы.
5. `review.py` — полный дифф после перезаписи.
6. Свой тест `tests/test_pult_commit_signature.py` (чтение записи прежнего
   вида, трейлер без `commit_author`, соавтор и запись журнала);
   регенерация карты.

## Влияние на систему
- Без новых полей переход прежний: обработчик не сжимает, рубеж отправки
  идёт прежним `ensure_head_in_origin`, узел подтяжки зовётся прежним
  вызовом (флаг `merge_main` не передаётся); единственное изменение
  коммитов пульта для таких проектов — трейлер `Artel-Actor: orchestrator`
  последним абзацем (тема коммита прежняя — тесты, сверяющие темы
  `%s`, не задеты). Журнал задач без `commit_author` байт в байт прежний.
- Действие записи «ветка отправлена» получило двоеточие; читатель
  (`_last_sent_sha`) читает оба вида — sha аренды белого списка части 1
  сверяется так же.
- Гейты не ослабляются: рубежи видят коммиты роли (сжатие после них),
  незакоммиченная правка после рубежей не коммитится (отказ), чужая голова
  на сервере не затирается (lease с sha журнала, эскалации), сверка
  автора закрыта по умолчанию.
- Откат — revert одного merge-коммита задачи; данных и схемы БД задача не
  меняет.

## Риски
- Классификация «сеть» / «отказ сервера» по stderr `git push`
  (`[rejected]`, `[remote rejected]`, `stale info`, `hook declined`):
  неизвестный текст отказа считается «сетью» — переход отклоняется без
  эскалации, ветка возвращается; повтор `advance` безопасен.
- `github_adapter._ensure_draft_mr_after_publish` (приватная функция
  адаптера) зовётся из `_rewrite_push_gate` после первой отправки, чтобы
  черновик MR заводился так же, как у прежнего пути.

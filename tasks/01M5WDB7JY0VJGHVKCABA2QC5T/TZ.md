Требуется:
1. Автор, соавтор и трейлер: для записи с `commit_author` окружение роли и коммиты пульта в ветке задачи и в `refs/artifacts/<id>` (чекпоинт, фиксация, документы, коммит `amend-tests`, коммит закрытия, сжатый коммит, merge-коммит подтяжки, коммит авторазрешения конфликта подтяжки `pull.py:462-463`) получают этого автора и коммиттера. `co_author` дописывается строкой в сообщение каждого такого коммита — не настройкой, которую может сменить роль; коммиты роли без сжатия не переписываются. Каждый коммит пульта несёт трейлер `Artel-Actor: orchestrator`, запись журнала о нём — `actor` `orchestrator`. Трейлер — только сведение: решения гейтов на трейлер без журнала не опираются; кода различения коммитов пульта и роли по автору в пульте нет (`checkpoint.py:962-966` — докстринг), часть его не заводит. До первой отправки — сверка `commit_author` с владельцем токена через адаптер (`forge.token_user`, А1); пока адаптера нет — шаг пропускается с записью журнала «сверка автора — после адаптера».
2. Подготовка ветки на входе в `verifying` (каждый переход `in_dev → verifying`, ADR-0015 п. 2): сжатие и перебазирование выполняются ПОСЛЕ всех рубежей перехода (`fsm_advance.py:776-821`, в том числе `_review_rework_gate` `:816`), непосредственно перед отправкой (`_origin_push_gate`, `:831`) и переходом; рубежи видят ветку, не переписанную этим переходом, — коммиты роли. При `squash_before_mr: true` коммиты задачи от точки ответвления от `origin/<base>` сжимаются в один с сообщением по `commit_template` (`{text}` — название задачи). Подтяжка методом `freshness`: `merge` — как сейчас, на `fsm_advance.py:771`; `rebase` — перебазирование ветки задачи на `origin/<base>` в месте после рубежей (после сжатия), только в рабочей копии задачи, `base` не меняется; подтяжки `merge` на `:771` при `rebase` нет. Конфликт перебазирования — прежний путь конфликта подтяжки: `escalated` с меткой `PULL_CONFLICT_ROLE_STEP_MARKER` (`pull.py:575,589`), перебазирование прервано. `freshness` действует только на этом переходе; все прочие вызовы узла подтяжки (перед шагом разработчика, `pull-main`, `approve` приёмки `fsm.py:1577`, гейт мержа `fsm_merge_gate.py:727`, приёмка канарейки `canary.py:1384`) — прежний `merge` при любом `freshness`. Рубежи перехода при сжатии/перебазировании видят ветку до перезаписи; итоговую голову проверяют приёмка (`_acceptance_run_refuses`, `fsm_advance.py:833`, после отправки), CI отправленной головы и гейт неослабления по исходам на гейте мержа. Без новых полей поведение перехода не меняется.
3. Перезапись своей ветки (после сжатия/перебазирования) — только `push --force-with-lease=refs/heads/<ветка>:<sha>`, где `<sha>` — из последней записи журнала задачи «ветка отправлена: <sha>» (её пишет единая точка отправки части 1 после успешной отправки); записи нет — первая отправка, без перезаписи. Голова на сервере не совпала с этим sha — чужой коммит: эскалация задачи в `_origin_push_gate` (`advance_gates/tests_writing.py`), без перезаписи. На гейте мержа (`fsm_merge_gate.py:701`) поведение без изменений — перезаписи там нет. В `github_adapter.py` меняется только место отправки ветки; поведение черновика MR не меняется.
4. Пакет ревью (`review.py`): если ветка задачи перезаписана после прошлого ревью (sha прошлого вердикта не предок головы), пакет несёт полный дифф задачи с явной пометкой «ветка перезаписана — дифф полный», а не «инкрементальный» дифф от sha прошлого вердикта; без перезаписи пакет прежний.

Критерии приёмки:
- перезапись: `--force-with-lease` несёт sha последней записи «ветка отправлена»; без записи — отправка без перезаписи; голова сервера другая — на переходе `in_dev → verifying` задача в `escalated`, отправки нет;
- `squash_before_mr: true` и `freshness: rebase` на фикстурном репозитории: после перехода в `verifying` в ветке один коммит с сообщением по шаблону, автором и коммиттером `commit_author`, строкой `Co-authored-by` и трейлером `Artel-Actor: orchestrator`, ветка поверх `origin/<base>`, `base` не изменён;
- `freshness: merge`, `origin/<base>` впереди: без сжатия merge-коммит подтяжки и коммит авторазрешения конфликта (`pull.py:462-463`) — с `commit_author`, строкой `Co-authored-by` и трейлером; с `squash_before_mr: true` — после перехода один коммит поверх `origin/<base>` с `commit_author` и строкой `Co-authored-by`;
- конфликт перебазирования — `escalated` и метка `PULL_CONFLICT_ROLE_STEP_MARKER`, как у конфликта `merge`; незавершённого перебазирования нет;
- после `changes_requested` без коммита developer (`squash_before_mr: true`, `freshness: rebase`, `origin/<base>` впереди) `advance` из `in_dev` отказан рубежом переделки ревью, задача в `in_dev`, голова ветки не изменилась;
- запись с `commit_author`: окружение роли и коммиты пульта — чекпоинт, документ в `refs/artifacts/<id>`, коммит `amend-tests` (`amend.py:799`), коммит закрытия (`snapshot.py:272`) — несут этого автора, строку `Co-authored-by` и трейлер `Artel-Actor: orchestrator`; без адаптера — запись журнала «сверка автора — после адаптера»;
- ветка перезаписана сжатием/перебазированием после прошлого ревью — пакет ревью следующей итерации несёт полный дифф задачи и пометку «ветка перезаписана — дифф полный»; без перезаписи — прежний инкрементальный;
- `freshness: rebase`: подтяжка перед шагом разработчика, `pull-main`, `approve` приёмки, гейт мержа и приёмка канарейки (`canary.py:1384`) — прежний `merge`;
- артель и проект с полями по умолчанию: существующие тесты подтяжки, отправок, `cleanup` и пакета ревью зелёные без правки. Если правка существующего теста всё же понадобится — только разделом «Меняемое поведение» и матрицей неослабления SPEC этой части (мандат Оператора 26.10), иначе эскалация.

Матрица неослабления части: сжатие и перебазирование против рубежа переделки ревью (`advance_gates/review.py:110-129`, `fsm_advance.py:816`) — свойство остаётся (место после рубежей), покрыто критерием про `changes_requested`; рубежи `fsm_advance.py:776-821` при `rebase`/сжатии смотрят ветку до перезаписи — ок при условии: итоговую голову проверяют приёмка (`fsm_advance.py:833`) на итоговой голове, CI отправленной головы и гейт по исходам на мерже; инкрементальный дифф ревью (`review.py:245`, `:864-866`) после перезаписи — заменой на полный дифф с пометкой, покрыто критерием про пакет ревью; различение коммитов пульта и роли по автору — потребителя нет (`checkpoint.py:962-966` — докстринг), трейлер `Artel-Actor: orchestrator` только сведение, решения гейтов на него без журнала не опираются.

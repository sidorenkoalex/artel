# SPEC: Канарейка v2 (часть 2): привязка пина к зелёной канарейке, триггер doctor, откат пина

## Контекст

Обновление пина запущенной версии (`orchestrator/pin.py::cmd_pin_update`)
сейчас делает `git fetch` + `git merge --ff-only` без какой-либо
проверки зелёного прогона канарейки — ADR-0013 требует, чтобы
обновление пина допускалось ТОЛЬКО после зелёного прогона канарейки
v2, и чтобы у откатa пина была штатная команда. Часть 1 задачи
(01M1NEEWH5K1XPFRDGRMPYSBXJ, родитель) строит саму механику прогона
канарейки и журнал её прогонов; эта задача (часть 2) привязывает к
этому журналу `pin-update`, `doctor` и вводит откат пина `pin --to`.
Старт разработки — после мержа части 1 в main (нужен её журнал
прогонов); до мержа этот SPEC остаётся единственным готовым
артефактом задачи.

## Требования

1. Команда `pin-update` отказывает выполнять обновление пина, если на
   целевом sha main артели нет зелёного прогона канарейки (по журналу
   прогонов части 1) не старше N мержей main, где N — именованная
   константа в `orchestrator/config.py`; отказ именован и приводит
   команду запуска канарейки.
2. `doctor` поднимает алерт `kind=trigger`, когда число мержей main,
   прошедших с последнего зелёного прогона канарейки, достигает той
   же константы N.
3. Команда `pin --to <sha>` возвращает запущенную версию (пин) на
   указанный `<sha>`; без аргумента `<sha>` — на sha предыдущего
   зелёного прогона канарейки по журналу; main при этом не изменяется
   (ADR-0013 ч.3).
4. Каждый откат пина (`pin --to`, явным sha и по умолчанию)
   журналируется отдельной записью с прежним sha, новым sha и
   причиной отката.

## Критерии приёмки

AC-1. При отсутствии на целевом sha зелёного прогона канарейки не
старше N мержей main `pin-update` отказывает: пин не обновляется,
сообщение отказа именовано (отличимо от прочих отказов `pin-update`)
и содержит команду запуска канарейки.

AC-2. При наличии на целевом sha зелёного прогона канарейки не старше
N мержей main `pin-update` выполняет обновление пина как прежде (без
регресса существующего поведения).

AC-3. `doctor` поднимает алерт `kind=trigger`, когда число мержей
main, прошедших с последнего зелёного прогона канарейки, достигает
значения именованной константы N из `orchestrator/config.py` (той же
константы, что в AC-1).

AC-4. `doctor` не поднимает такой алерт `kind=trigger`, если число
мержей main с последнего зелёного прогона канарейки меньше N.

AC-5. `pin --to <sha>` откатывает пин запущенной версии на указанный
`<sha>`, не изменяя main.

AC-6. `pin --to` без аргумента `<sha>` откатывает пин на sha
предыдущего зелёного прогона канарейки по журналу прогонов, не
изменяя main.

AC-7. Каждый вызов `pin --to` (с явным `<sha>` и без него) добавляет
в журнал отдельную запись с прежним sha, новым sha и причиной отката.

AC-8. Существующий набор тестов (`tests/`) остаётся зелёным после
изменений.

## Не входит

- Механика прогона канарейки и пул шаблонов (часть 1,
  01M1NEEWH5K1XPFRDGRMPYSBXJ) — эта задача только читает её журнал
  прогонов.
- Автоматическое обновление пина (по зелёному прогону или иначе) —
  `pin-update` остаётся операторской командой.

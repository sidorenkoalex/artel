# PLAN: Команда models показывает фактическую модель роли

## Подход
`orchestrator/models.py::cmd_models` перестаёт строить столбец ролей по
`tiers:` (`_roles_by_tier` + `tier_of_model`). Вместо этого один проход по
ролям-агентам карты исполнителей зовёт `resolve_role(role, catalog, local)`
на уже прочитанных слоях — единственный источник правила (требование 1).
Результат каждой роли кладётся:
- в столбец «роли» у модели `resolved.model` с источником
  `role_models: <роль>` (роль есть в `local.role_models`) либо
  `<ярус>: <роль>` — роль, переведённая записью, у модели яруса не
  появляется сама собой, потому что ярус больше не читается в обход
  разрешения (требования 2–4);
- в итоговую строку под таблицей `роль → модель → провайдер (источник)`,
  источник — `ярус <ярус>` или `role_models` (требование 5).

`ResolutionError` (и любой `ModelsError`) одной роли перехватывается на
уровне роли: итоговая строка `роль → не разрешено: <текст отказа>`, прочие
роли и таблица печатаются (требование 6). Над таблицей при этом остаётся
строка «роли показаны не полностью: …» — прочерк в столбце не должен
читаться как «ролей нет» (прежний R1-F5). Нечитаемая карта исполнителей —
прежняя строка «карта исполнителей не прочитана: …» над таблицей;
нечитаемый локальный слой — прежняя строка «локальный слой не прочитан: …»,
столбец ролей и итоговые строки не строятся (как раньше столбец).
Команда по-прежнему ничего не пишет: `resolve_role`/`load_local` — чистые
чтения (требование 7).

Помощник `_roles_by_tier` заменяется `_role_resolutions(catalog, local)` —
тот же перехват нечитаемой карты, но результатом — список
`(роль, Resolution | текст отказа)`.

## Шаги
1. `orchestrator/models.py`: `_role_resolutions` вместо `_roles_by_tier`,
   столбец «роли» по разрешению с источником, итоговые строки под
   таблицей, перехват отказа по роли; заголовок «роли».
2. `docs/stack.md`, пункт «посмотреть, что где действует»: столбец ролей с
   источником (ярус или `role_models`) и итоговые строки «роль → модель →
   провайдер (источник)».
3. `tests/test_models.py`: ожидаемый заголовок «роли по ярусам» → «роли»
   (разрешено SPEC, «Не входит»); свой тест на отказ разрешения с
   пометкой «не полностью» над таблицей. Регенерация карты
   `python3 scripts/codebase_map.py`.

## Влияние на систему
Меняется только вывод команды чтения `models`; `resolve_role` не
трогается, `doctor`, `runner`, `roles.py` не меняются. Гейты, лимиты,
инварианты не затронуты. Единственная правка прежнего теста — ожидаемое
имя столбца (`tests/test_models.py`, явно допущено SPEC); ассерты о
строках-причинах и «только чтении» сохраняются. Откат — revert одного
merge-коммита.

## Риски
- Источник подписи (`role in local.role_models`) читается отдельно от
  `resolve_role` — это подпись, не правило выбора модели: модель и
  провайдер берутся только из `Resolution`.

## Пути обхода гейтов

- **Г1. Шаг до коммита закрытия.** SPEC.md:77–89 (буквально по ТЗ) ставит
  шаг между `_finalize_done_state` и `cleanup._commit_closing`
  (fsm_merge_gate.py:1331–1332). Требование «не оставляют задачу в
  `merge_gate`» выполнено, но остановка процесса (SIGTERM/Ctrl-C) или
  зависание вне 60-секундного срока git К-3а (запись кэша, разбор) в шаге
  оставляют задачу `done` без коммита закрытия с RETRO, без уборки
  worktree/ветки (:1334) и без ожидания CI main (:1335). Восстановления нет:
  doctor досылает только уже существующий closing sha
  (orchestrator/doctor/artifact_branches.py:81–86). Перенос шага после
  `_commit_closing` (или после `_cleanup_merged_task` — объекты коммита
  остаются в клоне) снял бы риск без потери смысла. Решение — Оператору
  (позиция задана ТЗ).
- **Г2. Отсутствие приложения.** Ни один гейт не замечает пустого «##
  Приложения» (признано ТЗ); AC-13 держит только ревью. Принято ТЗ,
  компенсируется проверкой Оператора после `pin-update` (SPEC.md:101–106).
- **Г3.** В3 выше: шаг без собственного `try/except` проходит AC-12, пока
  К-3а глотает исключения; первая регрессия К-3а сорвёт закрытие
  (`done` уже выставлен, но `_commit_closing`/уборка не выполнятся).
- **Г4 (наблюдение).** Алерты предела и предупреждения — по проекту, а
  размер считается от головы ветки конкретной задачи (`sha=None`, SPEC
  К-3а, требование 6): бриф задачи А со справочником в пределе снимает
  алерт `brief.core_reference_oversized`, поднятый брифом задачи Б того же
  проекта. Сигнал может мигать/пропадать при параллельных задачах. Тот же
  приём, что у карты, но карта одна на пульт. Решение — Оператору.

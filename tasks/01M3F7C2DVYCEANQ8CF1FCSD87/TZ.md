# ТЗ: Команда пульта ci-rerun: повтор упавшего CI ветки на verifying

Источник: строка бэклога П2 от 26.09 «Команда пульта ci-rerun <id>: повтор
CI ветки на verifying» (docs/backlog.md; решение Оператора 26.09 после
двух перезапусков руками). Задача вне линии провайдеров.

Факты (main f89bab7c):
- В состоянии verifying цикл auto читает статус CI головы ветки
  (orchestrator/ci.py::verifying_status, branch_status) и при красном
  останавливается: config.AUTO_STOP_VERIFYING_RED «CI ветки красный —
  решение Оператора» (orchestrator/auto.py). Команды, которая исполняет
  это решение, нет: штатные выходы — reject в in_dev (лишний шаг
  разработчика, ~$2–5) либо перезапуск руками через gh run rerun.
- На гейте мержа повтор нестабильного теста уже есть:
  orchestrator/fsm_merge_gate.py::_ci_confirm_red_or_flake зовёт
  orchestrator/ci.py::trigger_rerun(branch) — тот находит id упавшего
  прогона головного sha (ci.find_run_id: среди завершённых прогонов
  берётся с не-зелёным заключением; один sha несёт прогоны push и
  pull_request), запускает gh run rerun <id> --failed и ждёт gh run watch
  до config.CI_RERUN_WAIT_SEC; исход пишется в журнал записью flake-rate.
  На verifying этот узел не вызывается.
- 26.09 два перезапуска руками для 01M3EKCZ: оба раза упал один
  нестабильный тест tests/test_models.py::test_command_writes_nothing
  (прогон push красный при зелёном pull_request того же sha); отдельно
  22–26.09 main был красен по тесту каталога — тогда перезапуск был бы
  маскировкой дефекта main (строка копилки 26.09 о красном main; урок
  12.09 в копилке: перезапуск CI замаскировал реальный дефект).
- Журнал задачи ведёт store.journal(conn, task_id, actor, action, detail);
  команды пульта регистрируются в orchestrator/artel.py (таблица команд и
  текст usage).

Требуется:
1. Команда `ci-rerun <id> --reason "<основание>"`: только для задачи в
   verifying с красным CI головы ветки (иначе именованный отказ с текущим
   состоянием и статусом CI); `--reason` обязателен — основание Оператора
   попадает в журнал.
2. Сверка перед запуском: голова ветки не менялась с момента статуса
   (sha, по которому цикл остановился, совпадает с текущим head_sha
   ветки); упавшие проверки красны НЕ на вершине main — если то же
   задание CI красно и на последнем прогоне main, команда отказывает
   «дефект main, не флейк» с именем задания и sha main, ничего не
   перезапуская. Способ сверки (по именам упавших заданий из check-runs
   ветки и main) — обосновать в SPEC.
3. Повтор — существующим узлом orchestrator/ci.py::trigger_rerun (тот же
   поиск прогона по sha с предпочтением упавшего, gh run rerun --failed,
   ожидание gh run watch); дублирующего кода не заводить. Итог — запись
   журнала задачи: основание Оператора, id прогона, исход ожидания
   (зелёный / снова красный / gh не ответил); best-effort — сбой gh не
   исключение, а именованный отказ.
4. После зелёного повтора цикл auto в verifying читает новый статус и
   идёт дальше штатно — команда сама состояние не меняет и роль не
   запускает; если после повтора снова красный — задача остаётся в
   verifying, запись журнала называет это, повторный ci-rerun допустим
   только с новым --reason.
5. Документация: docs/operator-session.md (раздел «Правки main только
   командами» либо «Запуски и рабочие копии») — строка о команде и о
   правиле «красно и на main — не перезапускать»; текст usage в artel.py.
6. Тесты (tests/): отказ вне verifying и при зелёном CI; отказ при
   несовпадении головы; отказ «дефект main» при том же красном задании на
   main; штатный путь — вызов trigger_rerun с подменённым gh и запись
   журнала с основанием и id; повторный красный — запись и состояние
   без изменений; auto после зелёного повтора продолжает (подменённый
   статус CI). gh в тестах подменяется, сети нет.

Зоны: orchestrator/ci.py, orchestrator/artel.py, orchestrator/fsm.py,
docs/operator-session.md, tests/.

Только чтение (не менять): orchestrator/fsm_merge_gate.py (узел повтора
на гейте мержа не меняется — переиспользуется trigger_rerun из ci.py),
orchestrator/auto.py, orchestrator/config.py (CI_RERUN_WAIT_SEC
действующий), orchestrator/store.py, .github/workflows/ci.yml,
docs/backlog.md, tests/test_invariants.py (защищённый путь).

Не входит: починка самих нестабильных тестов (отдельная задача 26.09);
автоматический повтор без Оператора на verifying (решение остаётся за
Оператором — это его команда); повтор CI main; правка гейта мержа.

Рамка: $30.

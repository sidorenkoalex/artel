# ТЗ: Гейт неослабления тестов: условный пропуск в новом тесте — с названной причиной

Источник: строка бэклога 27.09 «Гейт неослабления тестов не отличает
новый тест с условным пропуском от ослабления»; решение Оператора 27.09
(вариант «пропуск в новом тесте — только с названной причиной, которую
проверяет ревьювер»). Задача вне линии провайдеров.

Факты (origin/main b21f01e6):
- `orchestrator/advance_gates/test_integrity.py::_file_findings`
  сравнивает маркеры пропуска по имени тестового метода между базой и
  веткой; для НОВОГО файла база пуста (`base_source = None`), и любой
  `self.skipTest`, `skip`, `skipIf`, `skipUnless` в новом методе даёт
  находку, требующую мандата Оператора «Ослабление тестов разрешено:».
- Прецедент 27.09, задача 01M3H3K73XBMJMD0EPXZX6HYY9: новый тест оболочки
  входа честно неприменим на машине без `/bin/zsh`; разработчик написал
  ранний `return` вместо пропуска — рубеж обойдён формулировкой, а тест
  на такой машине зелёный, ничего не проверив.
- Гейт стоит на переходах `in_dev -> verifying` и на гейте мержа
  (инвариант 38, задача 01M3FQ2V77QNK95Z599DM124QN).

Требуется:
1. Условный пропуск в НОВОМ тестовом методе (метода нет в базе
   сравнения) не считается ослаблением, если у пропуска названа причина
   непустой строкой в самом вызове (`self.skipTest("<причина>")`,
   `@skipUnless(<условие>, "<причина>")` и подобные). Пропуск без
   причины, с пустой причиной либо безусловный (`@skip`, `skipTest` первым
   действием метода без условия) остаётся находкой.
2. Пропуск, появившийся в СУЩЕСТВУЮЩЕМ методе, остаётся ослаблением и
   требует мандата — поведение прежнее.
3. Ранний `return` первым действием тестового метода под условием —
   находка того же класса, что пропуск без причины: тест, который молча
   ничего не проверяет. Способ распознавания (разбор синтаксического
   дерева) и границы (что считается «под условием окружения») — в SPEC;
   ложные срабатывания на существующем наборе `tests/` перечисляются в
   PLAN, существующие тесты под находку не подгоняются.
4. Находки по новым пропускам с причиной не теряются: гейт пишет в
   журнал задачи запись обычного уровня «новый тест с условным
   пропуском: <файл::метод> — <причина>», чтобы ревьювер и Оператор
   видели их в одном месте.
5. Тесты (tests/): новый метод с пропуском и причиной — не находка, запись
   журнала есть; без причины — находка; существующий метод с новым
   пропуском — находка; ранний `return` под условием — находка;
   существующие tests/test_test_integrity_gate.py и остальной набор
   зелёные, ни один не ослаблен.
6. Документация: docs/operator-gates.md — правило о пропуске в новом
   тесте.

Зоны: orchestrator/advance_gates/test_integrity.py,
docs/operator-gates.md, tests/.

Только чтение (не менять): orchestrator/fsm_advance.py,

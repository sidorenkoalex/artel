   У такого эпика ссылки не будет вовсе, пока Оператор не выполнит над ним
   какую-нибудь команду `epic …`, а `epic restore` ответит «ссылки нет».

   прочтение SPEC законно, но резервная копия, ради которой задача заведена

   Оператору.
2. **ADR-0028 п. 6 не учтён (к сведению).** По ADR-0028:40 «эпик готов к

   закроет эпик, в котором они висят. Нужно решение Оператора: в Э3 или
   отдельно.

## Пути обхода гейтов
- **Рамка как подсказка, не потолок Оператора.** По AC-2 promote может
  записать `budget_usd` без `budget_source=operator`. Тогда первый же SPEC
  аналитика с `budget_usd` поднимет потолок выше рамки Оператора
  (`apply_spec_budget`), и AC-2 при этом зелёный. Обходится смысл рамки как
  решения Оператора (п. 6).
- **Перечни без проверки при `add`/`edit`.** Если не проверять элементы
  `--start-after`/`--after` (SPEC.md:21-22), черновик с опечаткой примется,
  и отказ всплывёт только на `promote`. Ни один AC этого не поймает (п. 5).
- **Слабые данные в тесте restore.** AC-12 без заданных «трудных» данных
  проходит с разбором Markdown, который потеряет `## `-секции ТЗ черновика
  или пробелы решения. Восстановление, ради которого существует копия,
  тогда молча расходится с исходником (п. 9).
- **Пункт `docs --fetch-all`.** Чтобы пройти буквальное «ведут себя как
  без ссылки эпика» (AC-11), исполнитель может отфильтровать `epic-` из
  `fetch_all_from_origin`. Тогда ссылка эпика не будет приноситься, и
  требование 14 сломается. Нужна ясность про итоговую строку (п. 8).

# Эпики, шаг Э3: черновики и решения эпика, копия эпика в refs/artifacts/epic-<id>

## Факты

ADR-0028 (принят 25.10.2026), уровень 3, п. 11; решение Оператора 25.10.2026 — копия эпика в ссылке `refs/artifacts/epic-<id>` репозитория его проекта. Шаг Э3 после Э1 (01M5TBBDFS6DWQY6MS263T1KPY — таблица `epics`, команды `epic …`).

1. Документы задачи живут в ссылке `refs/artifacts/<id задачи>` репозитория проекта: плотницкая запись и отправка в `origin` (`orchestrator/artifact_branch.py`, область `deferred_sends`, отправка один раз на команду), забор по шаблону `refs/artifacts/*` (`artifact_branch.py:712-720`), retention их не удаляет (`docs/retention.md`).
2. Черновики ТЗ будущих задач и решения Оператора по линии сейчас живут вне пульта (память ассистентской сессии).

## Требуется

1. **Черновики.** Таблица `epic_drafts`: эпик, порядковый номер, название, текст ТЗ, рамка, `start_after` (задачи или черновики), `merge_after`, состояние (`draft` | `promoted` | `dropped`), задача-результат. Команды `epic draft add <id> --tz <файл> [--start-after …] [--after …] [--budget N]`, `epic draft edit <черновик> …`, `epic draft drop <черновик>`, `epic draft promote <черновик>` — заводит задачу тем же путём, что `new` (проверка ТЗ, зоны, «Порядок:»), с `epic_id`, `start_after`, `merge_after` и рамкой; ссылки на черновики разрешаются в id заведённых задач, ссылка на ещё не заведённый черновик — отказ promote с перечнем. Перевод — только командой Оператора.
2. **Решения.** Таблица `epic_decisions`: эпик, время, дословный текст, к чему относится (черновик, задача, конверт). Команда `epic decision <id> "<дословно>" [--for <черновик|задача|envelope>]`. Решения гейтов задач остаются в ANSWER задач.
3. **Копия эпика.** Ссылка `refs/artifacts/epic-<id>` в репозитории проекта эпика, тем же механизмом, что документы задач (плотницкая запись, отправка в `origin` проекта в области `deferred_sends`, отказ отправки — журнал и повтор): каталог `epics/<id>/` — `EPIC.md` (цель, конверт, состав задач с состоянием и `closed_as`), `drafts/<n>.md` (черновик с рамкой, `start_after`, `merge_after`, состоянием), `DECISIONS.md` (решения дословно). Ссылку обновляет каждая команда `epic …`, меняющая эпик, его черновики или решения. `epic export <id>` печатает тот же Markdown. Забор при подключении и сверке — существующим шаблоном `refs/artifacts/*` (проверить, что префикс `epic-` не путается с id задач в местах разбора ссылок документов задач).
4. **Восстановление.** `epic restore <проект> <id>` (или шаг подключения проекта) воссоздаёт строки `epics`, `epic_drafts`, `epic_decisions` из ссылки, если их нет в БД; при расхождении с БД — отказ с перечнем.

Критерии приёмки:
- `epic draft add` → `promote`: задача заведена с эпиком, рамкой и зависимостями; promote черновика, зависящего от незаведённого черновика, — отказ;
- `epic decision` пишет дословный текст;
- после каждой команды, меняющей эпик, ссылка `refs/artifacts/epic-<id>` в `origin` песочного проекта несёт актуальные `EPIC.md`, `drafts/`, `DECISIONS.md`; отправка одна на команду;
- места, перебирающие ссылки документов задач (уборка, сверка, `doctor`), не принимают `epic-<id>` за задачу (тест на песочнице с обеими ссылками);
- `epic restore` на чистой БД воссоздаёт эпик из ссылки; повторный — без изменений; расхождение — отказ.

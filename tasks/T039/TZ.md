# ТЗ: cmd_new коммитит ТЗ сам и требует дерево на main

cmd_new --tz коммитит ТЗ сам; отказ при дереве не на main (строка беклога P3, инцидент T035 26.08).

Проблема: new создаёт tasks/<id>/TZ.md и tasks/<id>/SPEC.md (шаблон) untracked, а гейт чистоты _dirty_refuses требует, чтобы каталог артефактов был чист. Коммит «Tnnn: ТЗ Оператора» — устоявшийся ручной шаг с T027, который забывается; 26.08 забытый коммит обернулся буксующим циклом auto на ~$9. Ослаблять гейт чистоты нельзя: ТЗ — версионируемый вход (ответ Оператора на батч вопросов = правка TZ.md), без него approve-по-sha не описывает каталог задачи.

Что сделать: (1) cmd_new (orchestrator/catalog.py) после создания файлов коммитит tasks/<id>/ сообщением «<id>: ТЗ Оператора (<название>)» — и с флагом --tz, и без него (шаблонный SPEC.md коммитится в обоих случаях, как в ручном прецеденте T027–T037); (2) перед созданием задачи cmd_new проверяет, что рабочее дерево стоит на config.MAIN_BRANCH и чисто в части будущего каталога — иначе именованный отказ БЕЗ создания задачи и без расхода номера счётчика (тот же принцип, что существующий отказ при нечитаемом файле ТЗ: сначала все проверки, потом побочные эффекты).

Границы: git-вызовы — через обёртку gitcmd.git (образец T036); никаких изменений в _dirty_refuses и фиксации; поведение advance/approve не меняется.

Критерии приёмки (ориентир): (1) new "<название>" --tz <файл> оставляет tasks/<id>/ чистым: TZ.md и SPEC.md закоммичены одним коммитом с сообщением «<id>: ТЗ Оператора (<название>)»; (2) new без --tz так же коммитит шаблонный SPEC.md; (3) при дереве не на MAIN_BRANCH — отказ с названной веткой, задача не создана, номер счётчика не израсходован; (4) при провале самого коммита (git не ответил) — внятная ошибка, задача не остаётся в полусозданном состоянии без следа в журнале; (5) существующие тесты зелёные, правки тестов — только пути патчей/песочница.

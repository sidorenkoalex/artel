# ТЗ: Набор задачи: new --set, модель и стоимость с учётом задачи, set-models

Родительская задача: 01M3Y9YCKBFRJ8T9HSD40Z3AQN — Набор моделей отдельной задачи: new --set с допуском по ADR-0019 п.5
Зоны: orchestrator/catalog.py, orchestrator/store.py, orchestrator/schema.py, orchestrator/models.py, orchestrator/runner.py, orchestrator/spend.py, orchestrator/stack.py, orchestrator/artel.py, orchestrator/fsm.py, orchestrator/fsm_autogate.py, orchestrator/config.py, docs/stack.md, docs/operator-session.md, tests/
Порядок: после части 1
Рамка: $50

Часть 2 из 3 деления задачи «Набор моделей отдельной задачи — new --set с
допуском по ADR-0019 п.5». Опирается на часть 1: файл `model_sets.yaml`
(наборы, пары, классы шаблонов) и проверку допуска набора.

Только чтение (не менять): orchestrator/canary.py,
orchestrator/canary_drive.py, orchestrator/pin.py, models.yaml,
orchestrator/fsm_merge_gate.py, orchestrator/providers/, scripts/guard.py,
skills/, templates/, docs/adr/, docs/invariants.md,
tests/test_invariants.py, docs/backlog.md, tasks/, .artel/, .codex/.

Факты: модель роли разрешается `orchestrator/models.py::resolve_role(role,
catalog, local)` без контекста задачи; вызовы без задачи — `runner.py:425`,
`runner.py:1035` (запуск шага), `spend.py:442` (стоимость по тарифу),
`stack.py:194`, `stack.py:532` (окружение и `doctor`).

Требуется:
1. `new <title> <тз> --set <набор>` заводит задачу с набором из
   `model_sets.yaml`; роль без записи в наборе идёт на боевой модели. В
   строку задачи в БД пишется имя набора и его состав на момент `new`
   (миграция схемы — тем же приёмом, что прежние миграции `store.py`);
   набор действует до закрытия задачи; правка файла модели задачи в
   работе молча не меняет. Недопущенный набор по проверке части 1
   (недопущенная или приостановленная пара либо нет зелёного прогона
   трудного класса набором целиком) — отказ `new` до заведения задачи
   (нет строки в БД и ветки) с именем пары или набора и причиной.
2. Шаг роли задачи с набором идёт на модели набора; провайдер, CLI, вход
   и тариф — от модели набора тем же порядком fail-closed, что у
   `role_models:` (каталог, `experimental`). Стоимость шага (`spend.py`)
   — по тарифу модели, на которой шаг фактически шёл. Задачи без набора
   ведутся ровно как сейчас; поведение боевого набора не меняется.
3. Если на старте шага пара роли из записанного состава набора больше не
   допущена в `model_sets.yaml` (допуск снят командой допуска или пара
   приостановлена Оператором), шаг этой роли идёт на боевой модели этой
   роли с записью в журнал; молчаливого продолжения на снятой паре нет.
4. Видимость: `status` показывает набор задачи рядом с бюджетом; запись
   журнала старта шага называет роль, модель и источник (набор задачи,
   `role_models:` или ярус); подсказки `approve` на гейтах SPEC, приёмки
   и мержа задачи с набором называют набор.
5. Смена набора у задачи в работе — только командой Оператора (например
   `set-models <id> <набор>|--default`) с записью в журнал; разрешена
   только в `spec_gate`, `acceptance`, `merge_gate`, `escalated` и у
   приостановленной командой `pause` задачи; в остальных состояниях —
   отказ с перечнем допустимых. Новый набор проходит ту же проверку
   допуска, что и `new --set`.
6. Пока не смержена часть 3 (пробный период), задача с набором не
   проходит приёмку автогейтом: приёмка любой задачи с набором — ручной
   гейт Оператора, причина называет набор (решение ANSWER-1 п.3 родителя:
   ни одна задача с набором не идёт без ручной приёмки).
7. Документация: в `docs/stack.md` — набор задачи и разрешение модели
   с учётом задачи; в `docs/operator-session.md` — пункт о запуске задачи
   на наборе.
8. Тесты в `tests/`: задача с набором — шаг роли из набора на модели
   набора, роль без записи — на боевой, соседняя задача без набора — на
   боевой («Ловит мутацию: разрешение модели без учёта задачи»);
   стоимость шага задачи с набором — по тарифу модели набора; `new --set`
   с недопущенной и с приостановленной парой — отказ без заведения задачи
   (нет строки в БД и ветки); правка состава набора в файле после `new`
   не меняет модель задачи в работе; снятый допуск — шаг на боевой модели
   с записью в журнал; `set-models` вне допустимых состояний — отказ с
   перечнем; задача с набором не проходит приёмку автогейтом.
   Существующие тесты разрешения моделей, канарейки и автогейта не
   удаляются и не ослабляются.

Не входит: счётчик пробных задач и автоматическая приостановка (часть 3);
команда допуска (часть 1); автоматический выбор набора без команды
Оператора; возврат связки `role_models:`; наборы канарейки.

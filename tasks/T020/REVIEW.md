## Замечания

- minor — `tasks/T020/PLAN.md` («Риски», п.1), `docs/invariants.md` (вторая
  таблица, строка про `tasks.id`) — требование 3 SPEC в тексте приводит
  пример «T001 у artel и T001 у второго target сосуществуют», а
  реализация тестирует числовую независимость на ОТЛИЧИМЫХ id
  (`SLED-T001`), буквальная коллизия строки остаётся непроверяемой и
  открыто названа риском. Формально это не расходится с критерием
  приёмки 4 SPEC («задачи с одинаковым **номером**»), и решение
  задокументировано трижды (PLAN «Подход», PLAN «Риски», вторая таблица
  invariants.md) с честной причиной — ровно по образцу, который сама
  SPEC разрешает («инварианты, которые тестом не выражаются — в таблицу
  некодируемых с честной причиной»). Не блокер. Оставляю видимым для
  Оператора: при появлении команды `new` для второго target формат id
  придётся выбрать до того, как первая же задача с номером 1 столкнётся
  с существующей `T001` пульта.

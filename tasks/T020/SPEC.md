# SPEC: A2 — инварианты мультитаргета и изоляции workspace (тестовый слой)

## Контекст

Третья задача фазы A (roadmap §2 A2). A1 (T019) заложила
мультитаргетный фундамент: targets.yaml, структура
`.artel/projects/<target>/`, колонка target, счётчик per-target,
отдельный HOME ролей. Фундамент работает, но его свойства держатся
на реализации, а не на инвариантах: ни одно из них не закодировано
неослабляемым тестом (реестр docs/invariants.md), и регресс любого
свойства сейчас обнаружился бы чужим сбоем, а не красным тестом.
A2 — чисто тестовый слой: кодирование инвариантов мультитаргета
до того, как на них обопрутся A2b (git-первичка) и фаза B (внешние
target). Продакшен-код меняется только там, где тест вскрыл дефект
фундамента, — такое изменение оформляется отдельным пунктом PLAN
с обоснованием.

## Требования

Закодировать тестами и внести в реестр (docs/invariants.md,
секция кодируемых, с парными тестами) следующие инварианты:

1. **Изоляция артефактов пульта** (ADR-0003 3д): `.artel/`
   игнорируется git пульта целиком; артефакты и логи внешнего
   target не появляются в рабочем дереве репо ни на одном
   переходе FSM.
2. **Изоляция workspace** (ADR-0003 п.4): для внешнего target
   рабочий каталог роли — только `.artel/projects/<target>/workspace/`;
   окружение процесса роли не содержит путей и конфигов пульта
   сверх явно переданного (HOME/CLAUDE_CONFIG_DIR из `.artel/` —
   T019; негативный тест: подложный маркер в HOME Оператора
   и в конфигах пульта роли недоступен).
3. **Кросс-таргет изоляция БД** (ADR-0003 3ж): задачи разных
   target не пересекаются — нумерация независима per-target
   (T001 у artel и T001 у второго target сосуществуют), команды
   жизненного цикла (advance, approve, kill, status с фильтром)
   одного target не читают и не меняют строки другого.
4. **Экономика сквозная, учёт раздельный** (ADR-0003 3ж, roadmap
   §5): spent_usd копится per-task независимо от target; пороги
   программы 70%/90% считаются суммой по всем target (тест с двумя
   target, расход раскидан).
5. **Счётчик не переиспользует номера и при disconnect-архивации**
   (ADR-0003 3ж): архивация строк target (без DELETE) не приводит
   к коллизии номеров при reconnect.

Инварианты, которые тестом оркестратора не выражаются (если такие
вскроются в ходе работы), — в таблицу некодируемых invariants.md
с честной причиной, по образцу существующих строк.

## Критерии приёмки

1. Каждый инвариант 1–5 имеет строку в docs/invariants.md
   со ссылкой на тест(ы) и источник (якорь ADR-0003).
2. Мутационная проверка реестра: для каждого нового инварианта
   в PLAN/REVIEW зафиксирован способ сломать (какую строку кода
   снять/изменить) и подтверждение, что тест краснеет.
3. Тест изоляции workspace включает негативный сценарий: маркер
   в HOME Оператора и маркер в конфиге пульта не достигают
   окружения роли внешнего target.
4. Тест кросс-таргет: две задачи с одинаковым номером в разных
   target живут независимо; операции с фильтром target не трогают
   чужие строки.
5. Все существующие тесты и guard --all зелёные; продакшен-код
   не изменён, либо каждое изменение названо в PLAN отдельным
   пунктом с вскрывшим его тестом.

## Не входит

- Git-первичка projects/<target> и approve-по-sha (A2b).
- doctor, смоук-тест изоляции CLI-флагов, пин версии (A3).
- Флаги --setting-sources/--strict-mcp-config (B1a), песочница (B3).
- Реальный второй target в targets.yaml (тесты используют
  временный/фиктивный target).
- Новые механизмы — задача тестового слоя, не фич.

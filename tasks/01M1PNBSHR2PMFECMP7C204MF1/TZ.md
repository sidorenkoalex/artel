# ТЗ: Роль в своей группе процессов: таймаут, kill, pause --now бьют дерево; сторож зависших прогонов

# ТЗ: роль запускается в своей группе процессов; таймаут, kill, pause --now и обрыв бьют всё дерево; сторож зависших прогонов

Источник: инцидент 04.09. После таймаутов шагов (30 мин), обрыва
сессии Оператора и `pause --now` в системе остались шесть прогонов
тестов возрастом 5–6 часов (`pytest`/`unittest` из оболочек ролей в
worktree канарейки ч.1 и регрессии №9): пульт убивает только процесс
роли (`claude -p`), дочерние оболочки с командами роли переходят под
launchd (родитель 1) и живут дальше. Зависшие прогоны держали load
average 10–12 весь день: полный набор не укладывался в две минуты,
клиент уводил команды ролей в фон, роли завершали шаг без результата
(восемь пустых шагов, ~$15 учтённых и >100 млн токенов неучтённых).
Тот же класс: `pause --now` (T074) прерывает процесс `auto`, а процесс
роли остаётся сиротой (копилка роадмапа 04.09, п.6).

Требуется:
1. Запуск агентного шага роли — в новой группе процессов (сессии):
   `subprocess.Popen(..., start_new_session=True)` либо эквивалент;
   pid группы пишется в lease/журнал шага рядом с pid роли.
2. Все пути принудительного завершения шага бьют группу целиком, не
   один pid: таймаут шага (`runner`), `kill`, `pause --now`,
   `release` мёртвого lease и уборка после обрыва (`doctor`): сначала
   SIGTERM группе, через короткий грейс — SIGKILL; факт добивания
   потомков — в журнал шага (число снятых процессов).
3. Сторож: `doctor` находит процессы прогонов тестов
   (`python -m unittest`/`pytest`) с cwd внутри `.artel/worktrees/` и
   возрастом старше именованной константы (по умолчанию 10 минут) без
   живого lease их задачи и поднимает алерт `kind=warning` с pid,
   возрастом и worktree; авто-ack при исчезновении. `doctor --fix`
   снимает их (группой) с записью перечня в журнал алертов; без `--fix`
   — только отчёт.
4. Тесты: роль стартует в новой группе (pgid != pgid пульта);
   таймаут/kill/pause --now снимают запущенного ролью потомка (стаб —
   `sleep` в дочерней оболочке), потомок не переживает завершение
   шага; сторож находит старый прогон без lease и не трогает прогон с
   живым lease; существующие тесты (T041/T074/T044/T062) зелёные без
   ослабления.

Зоны: orchestrator/runner.py (запуск и таймаут), orchestrator/
pause.py, orchestrator/lease.py (pgid), orchestrator/doctor.py
(сторож), orchestrator/artel.py (kill/release), tests/. Не входит:
изменение таймаута шага и ретраев; поведение клиента CLI в режиме
`-p` (фоновые команды — его сторона); отвязка циклов от процесса
сессии (01M1NWCHVT…, отдельная задача — пересекается по runner.py:
стартовать после её мержа либо согласовать зоны при заведении).

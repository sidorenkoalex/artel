# SPEC: Роль в своей группе процессов: таймаут, kill, pause --now бьют дерево; сторож зависших прогонов

## Контекст

Инцидент 04.09: пульт запускает CLI-процесс роли обычным
`subprocess.Popen` — без своей группы процессов, поэтому таймаут шага
и `pause --now` убивают только сам процесс `claude -p`
(`orchestrator/runner.py`, `orchestrator/pause.py::_terminate_pid`), а
дочерние оболочки с командами роли (`pytest`/`unittest` и т.п.)
переходят под launchd (родитель 1) и живут дальше. Команда `kill`
(`orchestrator/cleanup.py::cmd_kill`) сегодня вообще не трогает OS-
процесс — только переводит состояние задачи, снимает lease и убирает
worktree/ветку. После таймаутов шагов, обрыва сессии Оператора и
`pause --now` в системе остались шесть прогонов тестов возрастом
5–6 часов, державшие load average 10–12 весь день, что срывало
последующие прогоны (клиент уводил команды ролей в фон, роли
завершали шаг без результата — восемь пустых шагов, ~$15 учтённых и
>100 млн токенов неучтённых). Нужно: (1) запускать шаг роли в своей
группе процессов и (2) сделать так, чтобы каждый путь принудительного
завершения шага снимал всю группу, а не один pid; плюс (3) сторож в
`doctor`, который находит уже зависшие прогоны тестов без живого
lease их задачи и умеет их снимать под `--fix`.

## Требования

1. Агентный шаг роли запускается в новой группе процессов (сессии).
2. Все пути принудительного завершения шага бьют группу целиком, не
   один pid: таймаут шага (`runner`), `kill`, `pause --now`, `release`
   мёртвого lease и `doctor --fix` — сначала SIGTERM группе, через
   короткий грейс — SIGKILL; факт добивания потомков — в журнал шага.
3. `doctor` — сторож зависших прогонов тестов (`python -m unittest`/
   `pytest`, cwd внутри `.artel/worktrees/`, старше именованной
   константы по умолчанию 10 минут, без живого lease их задачи):
   алерт `kind=incident` с pid/возрастом/worktree, авто-ack при
   исчезновении; `doctor --fix` снимает их группой с записью перечня
   в журнал алертов, обычный прогон — только отчёт.
4. Покрывающие тесты, существующие тесты (T041/T074/T044/T062)
   остаются зелёными без ослабления.

## Критерии приёмки

AC-1. Агентный шаг роли (`orchestrator/runner.py`) запускается в
новой группе процессов (сессии) — так что pgid дочернего процесса
отличается от pgid пульта.

AC-2. pid группы (pgid) агентного шага пишется рядом с существующим
pid — в lease и/или журнал шага — так, чтобы каждый из путей
требования 2 мог его прочитать.

AC-3. Таймаут шага (`orchestrator/runner.py`, истечение
`AGENT_TIMEOUT_SEC`) при срабатывании шлёт SIGTERM всей группе
процессов агентного шага, а не только его непосредственному pid;
после короткого грейса не завершившимся членам группы — SIGKILL.

AC-4. Команда `kill` (`orchestrator/cleanup.py::cmd_kill`) при живом
процессе лизы шлёт SIGTERM всей его группе процессов, после грейса —
SIGKILL, до снятия lease и уборки worktree/ветки задачи.

AC-5. `pause --now` (`orchestrator/pause.py::cmd_pause_now`) при
прерывании шлёт SIGTERM/SIGKILL всей группе процессов лизы, а не
только pid, который сегодня получает `_terminate_pid`.

AC-6. Снятие мёртвого lease (`release` мёртвого lease требования 2 —
путь `doctor.check_leases`/`orchestrator/release.py::cmd_release` для
уже неживого держателя) добивает остаточную группу процессов, если
она ещё жива, в рамках снятия lease.

AC-7. Каждый из путей AC-3–AC-6 записывает в журнал шага факт
добивания потомков — число снятых процессов группы.

AC-8. `doctor` находит процессы прогонов тестов (`python -m
unittest`/`pytest`) с cwd внутри `.artel/worktrees/` и возрастом
старше именованной константы (по умолчанию 10 минут).

AC-9. Из найденных требованием AC-8 сторож рассматривает только те,
для чьей задачи нет живого lease; на процесс с живым lease его задачи
сторож не поднимает алерт и не претендует его снять.

AC-10. Найденный сторожем (AC-8, AC-9) процесс поднимает алерт
`kind=incident` с pid, возрастом и путём worktree в сообщении;
открытый алерт авто-ack’ается, когда процесс исчезает (тем же
приёмом, что `_auto_ack_gone` для `check_leases`).

AC-11. `doctor --fix` снимает процессы, найденные сторожем (AC-8,
AC-9), группой — SIGTERM, грейс, SIGKILL — с записью перечня снятых
процессов в журнал алертов.

AC-12. Обычный прогон `doctor` (без `--fix`) сторожа зависших
прогонов процессы не трогает — только отчёт/алерт (AC-10).

AC-13. Тест подтверждает: агентный шаг роли стартует в новой группе
процессов — pgid дочернего процесса не равен pgid пульта.

AC-14. Тест подтверждает: таймаут шага, `kill` и `pause --now` каждый
снимает запущенного ролью потомка (тестовый стаб — команда `sleep` в
дочерней оболочке, по образцу `spawn_sleep_process` из
`tests/test_pause_now.py`), и этот потомок не переживает завершение
шага.

AC-15. Тест подтверждает: сторож находит старый тестовый прогон без
lease его задачи и не трогает (не алертит, не снимает) прогон с живым
lease.

AC-16. Существующие тесты T041 (`tests/test_timeout_checkpoint.py`),
T074 (`tests/test_pause_now.py`), T044 (`tests/test_lease.py`), T062
(`tests/test_release.py`) остаются зелёными без ослабления.

## Оценка объёма и деление

Сработавшие сигналы: число затрагиваемых модулей зоны — 5
(`orchestrator/runner.py`, `orchestrator/pause.py`,
`orchestrator/lease.py`, `orchestrator/doctor.py`,
`orchestrator/artel.py`/`cleanup.py`) при пороге
`SPLIT_SIGNAL_ZONE_FILES = 5`; число критериев приёмки — 16 при
пороге `SPLIT_SIGNAL_AC_COUNT = 10`.

Обоснование монолита: требование 1 (новая группа процессов + запись
pgid, AC-1–AC-2) само по себе не наблюдаемо и не тестируемо отдельно
от требования 2 — pgid, который никто не читает и не использует для
kill, не меняет поведение системы и не покрывается содержательным
тестом (тест на «pgid записан, но ничем не используется» не ловит
регрессию инцидента). Требование 2 (AC-3–AC-7), в свою очередь,
бессмысленно без требования 1 — группу нечем убивать, пока она не
заведена. Требование 3 (сторож, AC-8–AC-12) переиспользует тот же
приём group-kill (SIGTERM → грейс → SIGKILL), что и требование 2, и
адресует тот же инцидент 04.09 (зависшие прогоны без владельца) —
самостоятельный мерж сторожа без механики group-kill оставил бы его
либо без действующего `--fix`, либо с дублирующей реализацией того же
примитива. Промежуточное состояние после любой попытки разреза (часть
с записанным, но не используемым pgid; часть, убивающая группу без
самой группы; сторож без общего с остальным SPEC приёма) не работает
и не закрывает инцидент — только сумма всех трёх требований даёт
проверяемое поведение. Оператор — на гейте SPEC.

## Не входит

- Изменение таймаута шага и ретраев (`AGENT_TIMEOUT_SEC`, backoff) —
  сама величина не меняется, меняется что именно снимается по
  истечении.
- Поведение клиента CLI в режиме `-p` (уводит команды ролей в фон при
  превышении двух минут) — сторона клиента, не пульта.
- Отвязка циклов `run`/`auto` от процесса сессии (задача
  01M1NWCHVTYQ0M8PCJ1YJ2N78P, ветка
  `task/01m1nwchvtyq0m8pcj1yj2n78p-tsikly-run-auto-otvyazany-ot-p`, на
  момент SPEC ещё не смержена в main) — пересекается по
  `orchestrator/runner.py`; согласование очерёдности/зон между двумя
  задачами — вне мандата этого SPEC.

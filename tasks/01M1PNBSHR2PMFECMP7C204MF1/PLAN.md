# PLAN: Роль в своей группе процессов: таймаут, kill, pause --now бьют дерево; сторож зависших прогонов

## Подход

Три требования SPEC реализованы одним монолитным MR (обоснование
монолита уже зафиксировано в SPEC «Оценка объёма и деление» — pgid,
которым никто не пользуется, не тестируется отдельно от group-kill, а
group-kill нечем бить, пока группа не заведена).

1. **Новая сессия шага (AC-1/AC-13).** `runner.spawn_agent` ставит
   `kwargs.setdefault("start_new_session", True)` — единственная точка
   спавна агента, дальше по стеку менять нечего: pgid спавненного
   процесса равен его собственному pid по построению POSIX (`setsid`),
   поэтому `os.getpgid` для его вычисления не нужен нигде в проекте.

2. **Хранилище pgid (AC-2).** Новая колонка `leases.pgid` (не пере-
   используем существующий `leases.pid` — это pid ДЕРЖАТЕЛЯ lease,
   т.е. процесса пульта/сессии CLI, ведущего шаг, а не спавненного
   агентного процесса; они разные процессы уже сегодня, см. докстринг
   `orchestrator/lease.py`). `store.update_lease_pgid(conn, task_id,
   pgid)` пишет её сразу после успешного спавна в `run_agent_once`, не
   трогая остальные поля строки. Лизы может не быть вовсе (шаг
   запущен в обход `lease.acquire`, юнит-тесты) — `UPDATE ... WHERE
   task_id=?` тогда тихо не меняет ни одной строки.

   Тестовые дубли агентного процесса (`FakeProc`/`FakeAgentProc`/
   `mock.Mock()`, десяток существующих файлов `tests/test_*.py`) не
   несут `pid` реального OS-процесса — `pid` либо отсутствует, либо
   сам `Mock`. Запись pgid и последующий group-kill (см. ниже)
   защищены явной проверкой `isinstance(agent_pid, int)`: реальный
   `subprocess.Popen` продакшена такой всегда, тестовый дубль — почти
   никогда, и тогда группа просто не пишется/не бьётся (деградация до
   прежнего поведения `proc.kill()` на таймауте — единственное место,
   где старое поведение было наблюдаемо существующим тестом
   `tests/test_agent_log.py::CmdRunLoggingTest::
   test_timeout_kills_process_and_journals`, которая иначе перестала
   бы проходить не из-за дефекта, а из-за смены типа тестового дубля).

3. **Group-kill, общий примитив (AC-3..AC-7).** `liveness.
   terminate_process_group(pgid)` — SIGTERM всей группе (`os.killpg`),
   опрос числа живых членов группы через `ps -o pid= -g <pgid>`
   (переносимо между BSD/macOS и Linux `ps`, в отличие от `/proc`),
   эскалация до SIGKILL после грейса; возвращает число процессов
   группы НА МОМЕНТ сигнала — для журнала (AC-7). Функция — лист графа
   импортов (только stdlib), как и весь остальной `liveness.py`, и
   защищена от удара по собственной группе вызывающего (`pgid ==
   os.getpgid(0)` — no-op). `liveness.group_kill_detail(pgid, count)`
   — общая формулировка журнальной строки для всех путей ниже (единый
   текст, который ловит регекс приёмочного теста AC-7: корень «групп»
   рядом с цифрой).

   Четыре точки вызова:
   - `runner.run_agent_once`, таймаут: вместо `proc.kill()` —
     `liveness.terminate_process_group(agent_pid)`; count — в детали
     журнальной записи `agent run TIMEOUT`.
   - `cleanup._group_kill_lease_step` (новая функция), вызывается из
     `_cmd_kill` ДО `lease.release_any` (AC-4: «до снятия lease и
     уборки worktree/ветки») — только если `row['pid']` (держатель
     lease) жив и на этом host (не задевать чужой host случайным
     совпадением номеров).
   - `pause.cmd_pause_now`, СРАЗУ ПОСЛЕ существующего
     `_terminate_pid(row['pid'])` (SPEC AC-5: «не только pid, который
     сегодня получает `_terminate_pid`» — оставляем прежнее поведение
     и добавляем group-kill записанного pgid).
   - `release.cmd_release`, для МЁРТВОГО lease — БЕЗ флага, немедленно
     (ANSWER-1, вопрос 2, вариант B): только если host совпадает.

4. **Сторож зависших прогонов (AC-8..AC-12/AC-15), `orchestrator/
   doctor.py`.** Новая именованная константа `config.
   HUNG_TEST_RUN_AGE_SEC = 600`. Поиск (`_find_hung_test_runs`) —
   `ps -axww -o pid=,etime=,command=` по всей машине, фильтр по
   командной строке (`-m unittest`/`pytest`), возрасту (парсинг
   `etime`) и cwd через `lsof -a -p <pid> -d cwd -Fn`
   (`.resolve()` с обеих сторон снимает разницу симлинков ОС,
   например `/var` -> `/private/var` на macOS); задача по первому
   сегменту пути относительно `config.WORKTREES`. Фильтр по lease
   (AC-9) — та же логика «мёртв», что уже применяет кандидатам
   `check_leases` (свой host и pid не адресуем — иначе лиза
   консервативно считается живой).

   `check_hung_test_runs` (в `all_checks`, безусловно) — только
   поиск + алерт `kind=incident` (ANSWER-1, вопрос 1: не `warning`,
   которого нет в `alerts.KINDS`) + авто-ack тем же приёмом, что
   `_auto_ack_gone` уже применяет к `check_leases` (AC-10). `_fix_
   hung_test_runs` (только в ветке `if fix:` `cmd_doctor`, до
   `all_checks`, по образцу `sweep_orphan_artifact_branches`/`_fix_
   ignored_artifact_files`) — снимает найденных кандидатов ГРУППОЙ
   (`os.getpgid(pid)` вычисляется здесь явно — в отличие от AC-1/AC-2,
   этот pgid не заведён нашим кодом, дискаверится по чужому,
   стороннему процессу) и пишет перечень снятых в НОВЫЙ алерт (AC-11:
   «в журнал алертов», не только в журнал задачи).

   Тот же водораздел «наблюдение/действие» для AC-6: `_fix_dead_
   lease_groups` (тоже только в `if fix:`) снимает остаточную группу
   МЁРТВОГО lease у кандидатов `check_leases` — `check_leases` сама
   как naблюдательная проверка не меняется (ANSWER-1, вопрос 2,
   вариант B).

## Шаги

1. `config.py` — `HUNG_TEST_RUN_AGE_SEC`; `store.py` — колонка
   `leases.pgid` (SCHEMA + `add_column` для существующих БД),
   `update_lease_pgid`; `liveness.py` — `terminate_process_group`,
   `group_kill_detail`, приватные хелперы подсчёта членов группы.
2. `runner.py` — `spawn_agent` (новая сессия), запись pgid и
   group-kill на таймауте (с деградацией для тестовых дублей без

3. `cleanup.py`/`pause.py`/`release.py` — три немедленных пути
   group-kill (AC-4/AC-5/AC-6-немедленный).
4. `doctor.py` — сторож зависших прогонов (поиск/алерт/авто-ack,
   AC-8..AC-10/AC-12/AC-15) и обе `--fix`-гейтованные уборки
   (зависшие прогоны AC-11, остаточная группа мёртвого lease
   AC-6-doctor); регенерация `docs/codebase-map.md`.
5. Юнит-тесты нового кода (store/liveness) — покрывают то, что не

## Влияние на систему

- Новая колонка `leases.pgid` — аддитивная миграция (`add_column`,
  тот же приём, что и у всех прежних колонок `tasks`/`leases`); старые
  строки получают `NULL`, все читатели (`cleanup`/`pause`/`release`/
  `doctor`) явно проверяют `row['pgid']` перед использованием — не
  ломает ни один существующий путь без записанного pgid.
- `liveness.py` остаётся листом графа импортов (только stdlib,
  добавлен `subprocess`) — не тянет `config`/`store` и не создаёт
  новых циклов; `pause.py`/`release.py` уже импортировали `liveness`
  до этой задачи, `cleanup.py`/`runner.py` — новый импорт, оба
  направления ациклические (проверено прогоном полного набора тестов).
- `doctor.check_hung_test_runs` сканирует ВСЕ процессы машины
  (`ps -axww`) на каждом прогоне `doctor`/`preflight` — новый
  постоянный расход по сравнению с прежним поведением; порог возраста
  (10 мин по умолчанию) и фильтр по командной строке/cwd защищают от
  ложных срабатываний на процессах вне worktree'ов пульта. Полный
  прогон `tests/` (1473 теста) — без регрессии по времени,
  content-fail count 0.
- Group-kill никогда не бьёт группу самого вызывающего процесса
  (`pgid == os.getpgid(0)` — no-op в `terminate_process_group`) и
  никогда не адресует чужой host (явная проверка `hostname` перед
  каждым вызовом в `cleanup`/`release`; `pause.cmd_pause_now` уже
  проверяет host раньше, до всей ветки прерывания) — числовое
  совпадение pgid/pid с ЛОКАЛЬНЫМ процессом на другой машине не может
  превратиться в непреднамеренный SIGKILL.
- Ни один существующий тест/гейт/лимит не ослаблен: AC-16
  (T041/T074/T044/T062, 73/73) и полный набор `tests/` (1473/1473)
  зелёные после правки; единственная точечная адаптация — тестовый
  дубль без реального pid деградирует group-kill до старого
  `proc.kill()` (см. «Подход», п.2) вместо падения на
  `TypeError`/`sqlite3.ProgrammingError` при попытке передать `Mock`
  как integer bind-параметр или как pid `os.killpg`.
- Откат: git revert коммита(ов) этой задачи; колонка `leases.pgid`
  остаётся в схеме БД (аддитивная, безвредна для кода, который её не
  читает).

## Риски

- Формат `ps -o etime=` — `[[дни-]часы:]минуты:секунды`; разрешение в
  целую секунду (BSD/macOS `ps` не несёт Linux-only `etimes`) —
  учтено приёмочными тестами (только целые секунды в порогах/выдержке,
  см. докстринги `test_ac8`/`test_ac9`/`test_ac10`/`test_ac15`).
- `_find_hung_test_runs` — лучшее усилие: `ps`/`lsof` не ответили —
  тихая деградация (пустой список), сторож не отчитывается о находке,
  но и не падает; тот же класс деградации, что и у остальных
  OS-примитивов пульта (git, `os.kill(pid, 0)`).

## Предложения системе

- Класс «тестовый дубль без реального `pid`/OS-процесса ломается
  новым кодом, ожидающим реальный `int`» — coding-standards не
  называет этот класс явно; стоит явно предупреждать будущих
  разработчиков, что любой код, трогающий `subprocess.Popen`-подобные
  объекты через `os.kill`/`os.killpg`/бинды в SQL, обязан
  подстраховаться `isinstance(..., int)`, а не полагаться на то, что
  атрибут вообще есть.

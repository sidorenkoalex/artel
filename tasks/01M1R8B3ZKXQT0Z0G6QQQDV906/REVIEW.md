## Замечания

- major — `orchestrator/auto.py:267-388` (в частности строки 272 `if steps >= config.AUTO_MAX_STEPS`, 279 `steps += 1`, 299-309 ветка перехода) — новый порядок «advance, потом run» тратит ОТДЕЛЬНУЮ единицу лимита `AUTO_MAX_STEPS` на переход, который раньше был «бесплатным» довеском к шагу роли, написавшему артефакт. Раньше (`run`, затем немедленный `advance` по СВЕЖЕМУ результату того же шага) один реальный агентный вызов = один потраченный «шаг». Теперь артефакт пишется на одной итерации (1 шаг, `advance` отказывает «не готов»), а переход по нему случается только на СЛЕДУЮЩЕЙ итерации (ещё 1 шаг, без единого вызова агента) — то есть на каждый реальный вызов агента лимит расходует ~2 единицы вместо 1. Проверено трассировкой существующего (не ослабленного) теста `tests/test_auto_cycle.py::AutoStopsWhereTheOperatorIsNeededTest::test_review_iterations_are_passed_without_the_operator`: 4 вызова агента (`len(self.agent.calls)==4`) обходятся ЦИКЛУ в 8 итераций/шагов (у меня в трассировке — iteration1 run, iteration2 переход, iteration3 run, iteration4 переход, iteration5 переход (план всё ещё `ready`, developer снова пропущен), iteration6 run, iteration7 run, iteration8 переход) — то есть счёт `steps` идёт вдвое быстрее счёта реальной агентной работы. Сценарий поломки: при боевом `AUTO_MAX_STEPS=30` (`orchestrator/config.py:197`) полный проход `developer → review → verifying` за несколько итераций ревью, который раньше укладывался в один вызов `auto`, теперь регулярно упирается в «лимит 30 шагов исчерпан» на середине работы — Оператору придётся звать `artel.py auto <id>` вдвое чаще, чем до этой задачи, хотя ни SPEC (требование 7: «пороги… не меняются»), ни PLAN («Влияние на систему») этот эффект не called и не тестируют. Предложение: не гейтить `AUTO_MAX_STEPS` итерациями, где предварительный `advance` сам выполнил переход без вызова `runner.cmd_run` (например, считать «шаг» только там, где либо был реальный вызов роли, либо `advance` вернул журналируемый отказ/guard) — либо, как раньше, пробовать advance ПОВТОРНО сразу после `run` в границах ТОЙ ЖЕ итерации (в дополнение к предварительному, но не в замену), чтобы переход по свежему артефакту не откладывался на отдельный шаг.

- minor — `orchestrator/auto.py:1-3` (докстринг модуля) → `docs/codebase-map.md:148` — новый докстринг переносит строку посреди предложения («...затем — если роль ещё\nне закончила — run...»), а `scripts/codebase_map.py:62` берёт в «Назначение» только ПЕРВУЮ строку докстринга (`docstring.strip().splitlines()[0]`). В результате сгенерированная карта содержит оборванное предложение: «Цикл `auto`: advance (по готовым артефактам), затем — если роль ещё» — без сказуемого, что хуже старого («Цикл `auto`: run+advance, пока в шаге работает агент.» — законченное предложение в одну строку). Проверено: `grep -n "^## orchestrator/auto.py" -A5 docs/codebase-map.md` показывает именно этот обрыв на закоммиченной карте. Предложение: переписать первую строку докстринга как самостоятельное законченное предложение (по образцу остальных модулей), перенос — только со второй строки.

- minor — `orchestrator/fsm_advance.py:668-670` и `:767-768` — введённая для ветки `escalate` строка `plan_text = (tdir / "PLAN.md").read_text(encoding="utf-8")` в `else`-branch (не-foreign) читает PLAN.md отдельно от `artifacts.frontmatter(tdir / "PLAN.md")`, которая внутри читает тот же файл ещё раз (`orchestrator/artifacts.py:16-20`) — двойное чтение там, где `foreign`-ветка выше уже показывает более простой путь (`plan_meta = yamlmini.frontmatter(plan_text) or {}`, без повторного чтения диска). Тем же следствием строка 767-768 (`full_plan_text = (plan_text if plan_text is not None else (tdir / "PLAN.md").read_text(...))`) стала мёртвым кодом: `plan_text` после этой правки гарантированно не `None` в обеих ветках к моменту достижения строки 767 (при `foreign` ранний `return False` на строке 666 отсекает случай `None`) — `else`-часть выражения недостижима. Предложение: в `else`-ветке тоже использовать `yamlmini.frontmatter(plan_text) or {}` (как в `foreign`-ветке) вместо повторного чтения через `artifacts.frontmatter`, и убрать ставший мёртвым тернарник на строке 767-768, оставив просто `full_plan_text = plan_text`.

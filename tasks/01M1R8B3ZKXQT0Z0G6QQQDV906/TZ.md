# ТЗ: auto: переход по готовым артефактам до запуска роли; PLAN status escalate уводит в escalated (регрессия №11)

# ТЗ: auto сначала пробует переход по готовым артефактам, потом запускает роль; PLAN со status escalate уводит задачу в escalated (регрессия №11)

Источник: наблюдения 05.09. (1) Цикл `auto` в любом состоянии сначала
запускает агентный шаг роли и только затем пробует переход `advance`.
Если артефакты уже готовы (PLAN `status: ready` после возврата из
эскалации по бюджету, планка уже сдана, ревью уже вынесено), роль
тратит шаг ($1–6) на подтверждение очевидного: сегодня так потеряны
шаги у зон части 3, тестов без сети, стоимости по видам, канарейки.
(2) PLAN со `status: escalate` в артефактной ветке не переводит задачу
из in_dev в escalated: `auto` перезапускает developer, пока не
сработает детекция буксования (5 шагов, канарейка ч.1 — четыре холостых
шага дважды за день, ~$15). Реестр регрессий нового контура, №11.

Требуется:
1. `auto` перед каждым агентным шагом вызывает `advance` (идемпотентный,
   по зафиксированному состоянию): если переход возможен — выполняет его
   и продолжает цикл без запуска роли; шаг роли запускается только когда
   переход отклонён по причине «артефакт роли не готов» (PLAN draft,
   планка не сдана, вердикта нет). Отказы других классов (лок планки,
   свежесть, гейт ёмкости, guard) — как сейчас: стоп-кран/эскалация,
   роль не запускается.
2. Артефакт роли со `status: escalate` (PLAN developer, REVIEW
   reviewer, QUESTIONS/SPEC analyst — по правилам guard «эскалация
   только статусом») на `advance` переводит задачу в `escalated` с
   текстом раздела «Эскалация» в журнале — независимо от того, лежит
   артефакт в рабочем каталоге или только в артефактной ветке
   (материализация по 01M1NKTF173WV5CPDZ1C3WW69K). Возврат Оператором
   — как для любой эскалации (ANSWER-n + approve).
3. Журнал: каждый пропуск шага роли по причине «переход уже возможен»
   пишется одной строкой («шаг <роль> не нужен: переход выполнен по
   готовым артефактам»), чтобы экономия была видна в отчёте.
4. Тесты: готовый PLAN после возврата из эскалации → `auto` не
   запускает developer и переходит в review; PLAN `status: escalate` в
   артефактной ветке → escalated без запуска роли; отказ лока планки →
   роль не запускается, стоп как сейчас; существующие тесты `auto`
   (T014, T038, детекция буксования) зелёные без ослабления.

Зоны: orchestrator/auto.py, orchestrator/fsm_advance.py (чтение
статуса escalate из источника артефактов), tests/. Пересечение с
зонами частью 2 (auto.py, fsm_advance.py) — старт кода после её мержа
(идёт 05.09); до мержа — SPEC и планка.

Не входит: изменение лимитов auto (число шагов, детекция буксования);
смена состояний FSM.

Рамка: $25.

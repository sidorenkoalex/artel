## Пути обхода гейтов
1. Буквальное выполнение AC-1 без детерминированной проверки: исполнитель
   меняет `task_id`, но никакой тест не закрепляет «нет цифр после префикса
   ни при каком зерне». Позднее откат фикстуры проходит гейт зелёным
   (флейк вернётся с вероятностью ~1% на прогон). SPEC.md:63-66.
2. Буквальное выполнение AC-2 без проверки обоих порядков: часы, сдвигаемые
   один раз (исходная гонка), на обычном прогоне почти всегда дают тот же
   исход. AC-2 формулирует свойство, но не способ его наблюдать, и ревью с
   планкой могут принять реализацию с гонкой. SPEC.md:68-73.
3. Подмена `Popen.wait` целиком в копии (обёртка, которая сама бросает
   `TimeoutExpired` при пределе N) формально оставляет «`proc.wait(timeout=…)`
   в `_run_full_suite_to_log` исполняется», но обрыв делает уже фикстура, а
   не настоящий `Popen._wait`. AC-4 такую подмену не отличит: обе мутации
   всё равно краснят по тексту отчёта. SPEC требование 2 запрещает её
   («`proc.wait` исполняется настоящим»), но ни один AC этого не
   проверяет. SPEC.md:39-48 против :68-73.
4. AC-3 / требование 3 на пути мутации: если реализация не отпускает пробник
   при пределе ≠ N, мутация «config вместо профиля» краснит тест только по
   истечении потолка `--wait 1` (60 с реального времени). Исход тогда
   определяет страховочный потолок — против SPEC.md:49-51. Распространяется
   ли требование 3 на прогон под мутацией, SPEC не говорит.

## Вердикт
concerns. SPEC верно передаёт ТЗ, факты о коде подтверждены, зоны
достаточны. Ниже — отклонения, решаемые Оператором на гейте:

1. SPEC.md:63-66 (AC-1) — «при любом зерне» без детерминированной проверки;
   откат фикстуры ловится только вероятностно (~1% зёрен). Предложение:
   AC-1 требует проверки генератора id фикстуры по фиксированному набору
   зёрен (или структурно: после префикса нет цифр).
2. SPEC.md:31 против SPEC.md:39-48 — «исходная точка» (диф ТЗ) подменяет
   `subprocess.Popen.wait` копии обёрткой `_sandbox_wait`, которая ещё и
   пишет файл-стоп пробника. Требование 2 запрещает подменять что-либо,
   кроме источника времени/таймаута, и требует настоящего `proc.wait`.
   Оператору решить: допустима ли обёртка, вызывающая настоящий
   `Popen.wait` (тогда SPEC стоит сказать это явно), или подмена — только
   `subprocess._time`, а пробник отпускается иначе.
3. SPEC.md:68-73 (AC-2) — независимость от порядка «старт пробника / первое
   чтение часов» не наблюдается ни одним названным тестом; исходная гонка
   07.10 прошла бы гейт. Предложение: AC-2 требует детерминированно
   прогнать оба порядка (пробник стартовал до первого чтения часов и после).
4. SPEC.md:39-48 — подмена держится на закрытых деталях CPython
   (`subprocess._time`, опрос часов в `Popen._wait`, проверено для 3.13 —
   `orchestrator/stack.py:68`). Смена `_wait` в будущей версии Python
   молча вернёт тест на реальные часы или сломает обрыв. Пометка Оператору;
   при желании — требование проверить, что подмена срабатывает (иначе
   красный, не зелёный по реальному времени).
5. SPEC.md:49-51, :75-76 (требование 3 / AC-3) — не сказано, чем измеряется
   «не длиннее 5 с» и относится ли это к прогону под мутациями AC-4 (без
   отпускания пробника мутация краснеет только по потолку `--wait 1`,
   60 с).

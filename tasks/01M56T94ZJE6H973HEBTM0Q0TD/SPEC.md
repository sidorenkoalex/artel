# SPEC: Неустойчивый тест предела полного прогона — две найденные причины, детерминированно

## Контекст
Тест `tests/test_01m48wre8bhfdy011q0hqgq91b_full_suite_limit_runs.py::SuiteRunProfileLimitTest::test_ac5_suite_run_cuts_at_profile_limit_and_reports_it`
пять раз краснел на CI при зелёном коде (07.10, 11.10, 13.10, 17.10, 18.10),
и каждый раз CI повторяли вручную. Задача 01M55VG9Q5A5341ZED8NRJKVTC нашла две
причины и ликвидирована решением Оператора 18.10: её критерий «50 прогонов
под нагрузкой» оказался слишком тяжёл для шага роли. Причины:
1. Строка отчёта «не уложился» начинается со случайного id задачи фикстуры
   (`orchestrator/suite_run.py:439`, `render`). Утверждение «нет отдельно
   стоящего значения config» (тест `:621-622`, `COPY_LIMIT = 60`,
   `standalone` — `:119-120`) ложно срабатывает, когда в id между буквами
   оказывается «60»: `standalone` не считает букву границей. Это причина
   падения 17.10.
2. Гонка часов в подмене времени. Пробник ветки стартовал раньше первого
   чтения часов в `Popen._wait`, предел вычислялся от более раннего момента,
   и обрыв не наступал (сигнатура 07.10 «пробник не стартовал до обрыва»).

Сегодня тест держит исход на реальных часах: обрыв через N = 11–13 с,
пробник на 100 с, `--wait 1` с таймаутом вызова 100 с (`:606-614`).
Исходная точка правки — диф задачи 01M55VG9Q5 из раздела «Материалы» ТЗ.

Решения Оператора по аудиту SPEC 18.10 (возврат со spec_gate) вошли в
требования 1–3 и критерии AC-1, AC-2, AC-3, AC-5:
(1) AC-1 проверяется детерминированно на генераторе id фикстуры;
(2) обёртка над `Popen.wait`, которая вызывает настоящий `Popen.wait` и
отпускает пробник файлом-стопом, допустима;
(3) AC-2 детерминированно прогоняет оба порядка «старт пробника / первое
чтение часов»;
(4) тест проверяет, что подмена часов сработала;
(5) «не длиннее 5 с» измеряется `time.monotonic` в тесте, а для прогона под
мутациями AC-4 допустим страховочный потолок `--wait`.

## Требования

1. Данные фикстуры (id задачи, имя проекта, номер прогона), попадающие в
   строку отчёта «не уложился», ни при каком зерне не дают в ней отдельно
   стоящее значение config (`COPY_LIMIT`). Это достигается правкой
   фикстуры, а не правкой утверждения. Свойство держит детерминированная
   проверка генератора id фикстуры (решение Оператора 18.10, п.1). Подходит
   любая из двух форм:
   - структурная: после префикса в id нет цифр;
   - перебор фиксированного набора зёрен.
2. Свойство теста — фоновый `suite-run` обрывает прогон по пределу профиля N
   и называет в отчёте N, а не значение config — доказывается без
   зависимости от реального времени:
   - Подменяется только источник времени или таймаута.
   - Обрыв выполняет настоящий код копии пульта: `_run_full_suite_to_log`
     (`orchestrator/acceptance.py:1598`, `proc.wait(timeout=limit[0])`) на
     пути `suite_run.py:579-581` → `acceptance.py:1538-1540`. Эта функция
     исполняется настоящей.
   - Допустима обёртка над `subprocess.Popen.wait` копии, которая вызывает
     настоящий `Popen.wait` и отпускает пробник файлом-стопом. Обрыв по
     пределу при этом выполняет настоящий `Popen.wait` копии пульта.
     Обёртка не может сама бросать `TimeoutExpired` или иначе решать
     исход вместо настоящего `Popen.wait` (решение Оператора 18.10, п.2).
   - Гонка часов закрыта: исход один и тот же, когда пробник стартовал до
     первого чтения часов в `Popen.wait` и когда после. Оба порядка
     прогоняются детерминированно (решение Оператора 18.10, п.3).
   - Тест проверяет, что подмена часов сработала. Если она не сработала,
     тест красен, а не зелёный по реальному времени (решение Оператора
     18.10, п.4).
3. Ни одно ожидание по реальным часам, от которого зависит исход теста, не
   длиннее 5 с. Время подменённых часов не считается. Реальное ожидание
   измеряется в тесте через `time.monotonic`. Пределы `cli(timeout=…)` и
   `--wait` остаются только страховочными потолками: на незамутированном
   коде исход не определяется их срабатыванием. На прогоне под мутациями
   из требования 4 исход может определить страховочный потолок `--wait`
   (решение Оператора 18.10, п.5).
4. Утверждения метода не удаляются и не ослабляются. Тест по-прежнему ловит
   мутации из докстринга метода (`:601-604`):
   - фоновый прогон берёт `config.FULL_SUITE_TIMEOUT_SEC` вместо подполя
     профиля;
   - отчёт о таймауте печатает значение config, а не N.

   Правка смерженного долгоживущего файла идёт по общим правилам `tests/`
   и гейта неослабления.
5. В шаге роли нет нагрузочных серий. Устойчивость доказывается
   детерминированно: подменой часов, замороженным пробником, фиксированным
   зерном по нескольким значениям.

## Критерии приёмки

AC-1. Строка отчёта «не уложился» ни при каком зерне фикстуры не содержит
отдельно стоящего (в смысле `standalone` теста) значения config
`COPY_LIMIT`. Утверждение `assertFalse(any(standalone(self.COPY_LIMIT, line) …))`
при этом не изменено. Свойство держит детерминированная проверка генератора
id фикстуры: структурно (после префикса нет цифр) или по фиксированному
набору зёрен. Откат генератора id к алфавиту с цифрами эта проверка
краснит при любом зерне прогона.

AC-2. Исход теста не зависит от реального времени и нагрузки. Проверка
детерминированная, а не серия прогонов: подменённый источник времени или
таймаута, замороженный пробник, фиксированные зёрна по нескольким
значениям. Обрыв выполняет настоящий `Popen.wait`, вызванный из
`proc.wait(timeout=…)` в `_run_full_suite_to_log` копии пульта. Обёртка,
которая вызывает настоящий `Popen.wait` и отпускает пробник файлом-стопом,
допустима. Оба порядка детерминированно прогоняются и дают один исход:
пробник стартовал до первого чтения часов в `Popen.wait` и пробник
стартовал после. Подмена, переводящая часы однократно при старте пробника
(исходная гонка 07.10), в одном из двух порядков краснит тест.

AC-3. Ни одно реальное ожидание, от которого зависит исход теста на
незамутированном коде, не длиннее 5 с. Тест измеряет это ожидание через
`time.monotonic`, время подменённых часов не считается. Возврат обрыва к
реальному отсчёту предела N (11–13 с) краснит тест. На прогоне под
мутациями AC-4 исход может определить страховочный потолок `--wait`.

AC-4. Мутации из докстринга тест по-прежнему ловит. Тест красен, если
фоновый `suite-run` берёт `config.FULL_SUITE_TIMEOUT_SEC` вместо подполя
профиля. Тест красен, если отчёт о таймауте печатает значение config, а не
N.

AC-5. Тест проверяет, что подмена часов в копии пульта сработала. Если
подмена не действует (например, `Popen.wait` не опрашивает подменённый
источник времени), тест красен с текстом провала об этом и не зеленеет по
реальному времени.

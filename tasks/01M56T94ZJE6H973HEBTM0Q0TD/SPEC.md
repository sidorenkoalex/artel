# SPEC: Неустойчивый тест предела полного прогона — две найденные причины, детерминированно

## Контекст
Тест `tests/test_01m48wre8bhfdy011q0hqgq91b_full_suite_limit_runs.py::SuiteRunProfileLimitTest::test_ac5_suite_run_cuts_at_profile_limit_and_reports_it`
краснел на CI пять раз при зелёном коде (07.10, 11.10, 13.10, 17.10, 18.10),
каждый раз — ручной повтор CI. Задача 01M55VG9Q5A5341ZED8NRJKVTC нашла две
причины и ликвидирована решением Оператора 18.10 (её критерий «50 прогонов
под нагрузкой» был слишком тяжёл для шага роли):
1. строка отчёта «не уложился» начинается со случайного id задачи фикстуры
   (`orchestrator/suite_run.py:439`, `render`), и утверждение «нет отдельно
   стоящего значения config» (тест `:621-622`, `COPY_LIMIT = 60`,
   `standalone` — `:119-120`) ложно срабатывает, когда в id между буквами
   оказывается «60» (`standalone` не считает буквы границей) — причина
   падения 17.10;
2. гонка часов в подмене времени: пробник ветки стартовал раньше первого
   чтения часов в `Popen._wait`, предел вычислялся от более раннего момента,
   обрыв не наступал (сигнатура 07.10 «пробник не стартовал до обрыва»).

Сегодня тест держит исход на реальных часах: обрыв через N = 11–13 с,
пробник на 100 с, `--wait 1` с таймаутом вызова 100 с (`:606-614`).
Исходная точка правки — диф задачи 01M55VG9Q5 из раздела «Материалы» ТЗ.

## Требования

1. Данные фикстуры (id задачи, имя проекта, номер прогона), попадающие в
   строку отчёта «не уложился», не могут дать в ней отдельно стоящее
   значение config (`COPY_LIMIT`) ни при каком зерне. Достигается правкой
   фикстуры, не правкой утверждения.
2. Свойство теста — фоновый `suite-run` обрывает прогон по пределу профиля N
   и называет в отчёте N, а не значение config — доказывается без
   зависимости от реального времени: подменяется только источник времени
   или таймаута; обрыв выполняет настоящий код копии пульта
   (`orchestrator/acceptance.py:1598`, `proc.wait(timeout=limit[0])` в
   `_run_full_suite_to_log`; путь `suite_run.py:579-581` →
   `acceptance.py:1538-1540`), и эта функция, и `proc.wait` исполняются
   настоящими. Гонка часов (пробник стартовал раньше первого чтения часов
   в `Popen._wait`) закрыта: исход не зависит от того, что случилось
   раньше — старт пробника или первое чтение часов.
3. Ни одно ожидание по реальным часам, от которого зависит исход теста, не
   длиннее 5 с; пределы `cli(timeout=…)` и `--wait` остаются только
   страховочными потолками (исход не определяется их срабатыванием).
4. Утверждения метода не удаляются и не ослабляются; мутации из докстринга
   метода (`:601-604`: фоновый прогон берёт `config.FULL_SUITE_TIMEOUT_SEC`
   вместо подполя профиля; отчёт о таймауте печатает значение config, а не
   N) тест по-прежнему ловит. Правка смерженного долгоживущего файла идёт
   по общим правилам `tests/` и гейта неослабления.
5. Нагрузочных серий в шаге роли нет: устойчивость доказывается
   детерминированно — подменой часов, замороженным пробником,
   фиксированным зерном по нескольким значениям.

## Критерии приёмки

AC-1. При любом зерне фикстуры строка отчёта «не уложился» не содержит
отдельно стоящего (в смысле `standalone` теста) значения config
`COPY_LIMIT`; утверждение `assertFalse(any(standalone(self.COPY_LIMIT, line) …))`
при этом не изменено.

AC-2. Исход теста не зависит от реального времени и нагрузки: проверка
детерминированная (подмена источника времени или таймаута, замороженный
пробник, фиксированные зёрна по нескольким значениям), не серия прогонов;
обрыв выполняет настоящий `proc.wait(timeout=…)` в
`_run_full_suite_to_log` копии пульта, и исход один и тот же независимо от
того, стартовал пробник до или после первого чтения часов в `Popen.wait`.

AC-3. Ни одно ожидание по реальным часам, от которого зависит исход теста,
не длиннее 5 с.

AC-4. Мутации из докстринга тест по-прежнему ловит: фоновый `suite-run`
берёт `config.FULL_SUITE_TIMEOUT_SEC` вместо подполя профиля — тест красен;
отчёт о таймауте печатает значение config, а не N — тест красен.

# ТЗ: Канарейка v2: пул вне корня, эфемерный клон, условие обновления пина и откат пина

# ТЗ: Канарейка v2 (пул вне корня, эфемерный клон) + условие обновления пина и откат пина

Источник: ADR-0013 (03.09), роадмап §3 К3 и строка P3 «Канарейка v2:
пул шаблонов + per-task бейзлайны», решение брейншторма 29.08
(память: клон + GUID + пул вне ROOT), решение Оператора 01.09
(V7-4: бейзлайн К3 — первым прогоном пула v2, живые задачи
несравнимы). Триггер К3 «первое обновление пина CLI» сработал 03.09
без прогона — первый прогон v2 является немедленным долгом.

Суть: механика прогона типовых задач полным циклом в эфемерном
клоне пульта, без следов в main, — и привязка её к пину: запущенная
версия не обновляется без зелёной канарейки; откат пина — одной
командой.

Требуется:
1. Пул шаблонов ТЗ вне корня пульта (`~/.artel-canary`, свой
   приватный git-remote для сохранности); 10–15 шаблонов с
   параметризацией от сида (имена/поверхность меняются, семантика и
   сложность — нет); машиночитаемый маркер «ожидается эскалация» в
   ТЗ-подвохах — честность ролей сверяется кодом. Шаблоны пишут
   Оператор и ассистент руками, вне конвейера (иначе утечка в
   контекст ролей до первого прогона); задача конвейера — только
   механика чтения пула и прогона.
2. Прогон — только в эфемерном клоне пульта (свой каталог, своя БД,
   свой origin-заглушка): ноль следов в main пульта — ни RETRO, ни
   копилки, ни веток, ни снапшотов (дыра v1: RETRO killed-канареек
   тёк в main). Клон удаляется после прогона; метрики — в БД пульта
   отдельной таблицей/пометкой, не в журнал живых задач.
3. Canary-GUID в каждом шаблоне + CI-проверка утечки GUID в
   skills/, templates/, docs/ пульта (контаминация через поверхности
   контекста ролей).
4. Случайная выборка k из N шаблонов на прогон; бейзлайн per-task
   (не суммой) по набору метрик К3 роадмапа §3 (шаги ролей,
   итерации ревью, эскалации, стоимость, вердикты гейтов); первый
   прогон = бейзлайн К3 (решение 01.09). Обход verifying (CI чужого
   remote в клоне не нужен) — как решено V7-4.
5. Обязательное покрытие пулом путей, не покрытых планкой A7
   (инцидент 03.09): маршрут analyst у задачи нового флоу; эскалация
   с QUESTIONS → ANSWER Оператора (заглушкой) → возврат; удаление
   артефакта ролью и его исчезновение из артефактной ветки.
6. Привязка к пину (ADR-0013 ч.1): команда обновления пина
   (stage1 A7) отказывает, если нет зелёного прогона канарейки на
   целевом sha main не старше N мержей (константа); отказ именованный,
   с командой запуска канарейки. Доктор-триггер «N мержей с последнего
   canary» — алерт kind=trigger (роадмап).
7. Откат пина (ADR-0013 ч.3): `pin --to <sha>` (по умолчанию —
   предыдущий зелёный по журналу канарейки) возвращает запущенную
   версию; журналируется с прежним/новым sha и причиной; main не
   трогается.
8. Реакция на красное отклонение канарейки — за Оператором: алерт,
   не авторешение (роадмап).
9. Тесты: прогон в клоне не оставляет следов в пульте (проверка
   веток/RETRO/копилки до и после); утечка GUID ловится CI; отказ
   обновления пина без канарейки; откат пина журналируется;
   существующие тесты зелёные.

Зоны: orchestrator/canary.py (переработка v1), orchestrator/pin.py
(привязка и откат), orchestrator/doctor.py (триггер), .github/
workflows/ci.yml (проверка GUID — мандат этим ТЗ), tests/. Конфликт
зон с активными задачами — эскалация. Старт — после мержа hotfix A7
(01M1KT0792125J9ZNJNZJ86E9Q): прогон канарейки на сломанном новом
флоу бессмыслен.

Не входит: шифрование пула (решение 29.08 — не до B3); авторешения
по красной канарейке; шаблоны пула как часть задачи (руками вне
git).

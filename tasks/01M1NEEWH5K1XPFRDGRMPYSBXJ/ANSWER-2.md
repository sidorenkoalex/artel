# ANSWER-2: планка канарейки виснет — причина безрезультатных шагов developer

## Наблюдение Оператора 04.09
Девять шагов developer подряд завершились без готового PLAN. Причина
не в коде задачи, а в прогоне планки: в системе найдены и сняты три
прогона `pytest tasks/01M1NEEWH5K1XPFRDGRMPYSBXJ/acceptance_tests/`
возрастом 5–6 часов, стартовавшие из шагов developer этой задачи.
Планка не завершается: в ней есть тесты с реальными подпроцессами,
которые ждут ввода или события, которого не будет. Developer ждал
итог, клиент уводил команду в фон, шаг заканчивался пустым.

## Указание
1. Прогонять планку ТОЛЬКО в переднем плане с явным таймаутом команды
   (до 10 минут) и по одному файлу: `python3 -m unittest
   tasks.<id>.acceptance_tests.test_acN_…`; фоновых прогонов не
   ждать (скил coding-standards, «Тесты»).
2. Найти тест(ы), которые не завершаются: для каждого подпроцесса в
   планке — `timeout=` и закрытый stdin (`stdin=subprocess.DEVNULL`),
   без интерактивного ожидания. Если зависание в самой планке
   (тест ждёт того, чего реализация по SPEC не даёт), — это спор с
   тестом: эскалация статусом `escalate` с именем теста и причиной,
   не правка планки и не бесконечное ожидание.
3. PLAN довести до `status: ready` с итоговыми строками прогонов по
   файлам.

# ТЗ: Проверка формата идентификатора — до фиксации приёмочных тестов

Источник: инцидент 02.09.2026 (задача «Наблюдаемость сессий»).
Приёмочный тест зашил формат идентификатора задачи («T и три цифры»)
в проверку вывода `status`. CI-проверка формата (T094, job
id-format-greplint) поймала это только на пулл-реквесте — когда
каталог `acceptance_tests/` уже был зафиксирован локом (инвариант 27)
и роль законно не могла его править. Развязка потребовала
операторского вмешательства, отката правки конвейером и лишних
кругов ревью. Дефект планки приёмки надо ловить ДО того, как планка
становится неприкасаемой.

Требуется:
1. Проверка новых строк на образцы формата идентификатора задачи
   (тот же набор образцов, что в CI-job id-format-greplint,
   .github/workflows/ci.yml) выполняется на переходе
   `tests_writing → in_dev` для содержимого `tasks/<id>/
   acceptance_tests/` — до записи фиксации лока. Найденный образец —
   отказ перехода с именем файла, строкой и подсказкой «формат
   идентификатора знает только генератор; строй проверку от
   фактического идентификатора».
2. Набор образцов — единый источник для CI и перехода (вынести в
   разделяемое место — способ выбирает разработчик: файл с образцами,
   читаемый обоими, либо скрипт, вызываемый обоими), чтобы CI и
   переход не могли разойтись.
3. Отказ не эскалирует задачу: test_author чинит тесты тем же шагом,
   что и прочие отказы выхода из `tests_writing` (маркеры красноты,
   трассируемость).
4. Тесты: образец в тесте — отказ с именем файла/строки; чистые
   тесты — переход как раньше; общий источник образцов используется
   переходом (изменение образца меняет поведение без правки кода
   перехода); существующие тесты зелёные.

Зоны: orchestrator/fsm.py или fsm_advance.py (выход из
tests_writing), .github/workflows/ci.yml (вынос образцов в общий
источник; job остаётся, меняется только источник образцов),
scripts/ при необходимости, tests/. Конфликт зон с активными
задачами — эскалация.

Не входит: изменение набора образцов (какие форматы ловим — как в
T094); штатная команда операторской правки залоченной планки с
обновлением лока — смежный пробел той же истории, отдельная задача
по отдельному решению Оператора; распространение проверки на другие
артефакты.

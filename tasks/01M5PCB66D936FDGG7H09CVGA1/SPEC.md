## Контекст

23.10.2026). ADR-0027 п. 8 и ADR-0020 п. 8: старые тесты переводятся и
удаляются волнами консолидации. Доказательство — множество убиваемых
мутаций, мандат Оператора по путям и независимая проверка мутаций. Мандат
Оператора 23.10.2026: «Волна сведения тестов по note; после бери все

работы тот же, что у 1а: решения её гейта SPEC (круги 1–3) ТЗ перенесло в

сразу и называет держателя. Параллельно свои прогоны мутаций ведёт
волна 1а.

## Требования

1. Мутации. Для каждой строки «Ловит мутацию» шести файлов волны готовится
   патч к коду `orchestrator/` в файле `tasks/<id>/mutation-<nnn>.diff`.
   Патчи лежат первым уровнем каталога документов, номера идут подряд.
   Строки, одинаковые по смыслу, — одна мутация со списком тестов.
2. Таблица «до» — команда
   `mutation-run <id> --ref base --tests <шесть файлов>`. Набор можно делить
   на части `--patches` под предел шага. Вывод каждой части переносится в
   PLAN, раздел «Мутации до», дословно и с шапкой — до старта следующей
   части.
3. Доказательством не считается мутация, которую «убили» только ошибка
   сбора, ошибка импорта, ошибка setup или только падение подготовки
   песочницы (`setUp`). Такой патч переписывается так, чтобы падало
   утверждение теста. Узлы, где падает подготовка, роль отмечает в PLAN.
4. Мутация, которую не убил ни один тест, — находка в PLAN. Если замок
   занят прогоном другой задачи, прогон повторяется позже, без эскалации.
5. Свод. Тесты шести файлов переносятся в новый
   `tests/test_doc_commit_module.py` в стиле pytest: функции, `assert`,
   `parametrize`, фикстуры `tests/fixtures.py` и собственные фикстуры файла.
   Помощники с утверждениями — функции модуля.
6. Утверждения и проверяемые свойства при своде не меняются, ожидания
   переносятся дословно.
   - `pytest.raises(..., match=re.escape(<текст>))` — только там, где
     исходник проверял текст исключения. Голый `assertRaises(E)` →
     `pytest.raises(E)` без `match`.
   - Перебор по константам кода — `parametrize` по самой константе или
     цикл в теле функции, не литералы.
   - Итерации с общим состоянием и случайный выбор остаются прежним
     циклом.
7. Дубль удаляется только при двух условиях:
   - (а) каждую его мутацию по таблице «до» убивает и другой сохраняемый
     тест;
   - (б) каждый литерал и вид каждого утверждения удаляемого теста есть в
     утверждениях сохраняемого теста, убивающего те же мутации.

   Удалённые дубли перечисляются в PLAN вместе с мутациями. Тест, чью
   мутацию не убил никто, не удаляется: его строка «Ловит мутацию»
   переписывается на мутацию, которую он убивает (со своим патчем), либо
   тест становится находкой в PLAN.
8. У каждой функции нового файла есть строка «Ловит мутацию:».
9. Таблица «после» — команда
   `mutation-run <id> --ref worktree --tests tests/test_doc_commit_module.py`,
   вывод переносится в PLAN, раздел «Мутации после».
   - Каждая мутация, убитая «до», убита и «после».
   - Дерево `orchestrator/` у ревизий обеих шапок совпадает:
     `git diff --quiet <sha до> <sha после> -- orchestrator/`.
   - sha256 каждого патча в обеих шапках совпадает.
   - Если между прогонами в ветку подтянут main, прогон «до» повторяется.
10. Число тестов, число строк и время адресного прогона до и после свода
    записываются в PLAN.
11. Шесть исходных файлов удаляются по мандату `answer` на гейте SPEC. Не
    разрешены: удаление утверждения без переноса, ослабление сравнения,
    `skip`/`xfail`, подъём пределов.
12. Ограничение зон по смыслу. В `tests/` меняются только две вещи:
    удаляются шесть файлов волны и появляется новый
    `tests/test_doc_commit_module.py`. Не меняются `tests/fixtures.py`,
    `tests/sandbox.py`, файлы волны 1а (`tests/test_notes.py`,
    `tests/test_notes_apply.py`, `tests/test_notes_row_format.py`,
    `tests/test_01m563947r26nzw2tjekm36qrd_note_window_project.py`,
    `tests/test_notes_module.py`) и код `orchestrator/`. Мутации живут
    только во временной копии `mutation-run`.
13. Независимая проверка — повтор `mutation-run` сессией при Операторе на
    зафиксированном наборе патчей — проходит до approve на merge_gate.

## Критерии приёмки

AC-1. В каталоге документов задачи первым уровнем лежат патчи
`mutation-<nnn>.diff`, номера идут подряд без пропусков. Каждый патч меняет
только файлы под `orchestrator/`. В PLAN каждая строка «Ловит мутацию»
шести исходных файлов сопоставлена мутации. Строки, одинаковые по смыслу,
сопоставлены одной мутации со списком тестов.

AC-2. В PLAN есть раздел «Мутации до» с выводом `mutation-run` (`--ref base`,
тесты — шесть исходных файлов). Вывод перенесён дословно, с шапкой
(источник патчей, sha ревизии, sha256 патчей). Если набор делился
`--patches`, перенесён вывод каждой части. В таблице есть каждая мутация
набора.

AC-3. Ни одна мутация не засчитана доказательством, если её убили только
ошибка сбора, ошибка импорта, ошибка setup или только падение подготовки
песочницы (`setUp`). Узлы, убитые падением подготовки, отмечены в PLAN у
каждой мутации. У каждой мутации доказательства хотя бы один убивший узел
«до» в эту отметку не входит.

AC-4. Мутации, которые «до» не убил никто, перечислены в PLAN находками и в
доказательство не входят.

AC-5. Файл `tests/test_doc_commit_module.py` есть на ветке. Тесты в нём —
функции модуля в стиле pytest: нет классов-наследников `unittest.TestCase`,
нет `subTest`. Помощники с утверждениями — функции модуля, а не фикстуры.

AC-6. Каждый `pytest.raises` с `match` несёт `re.escape(...)` и стоит только
там, где исходный тест проверял текст исключения. На месте голого
`assertRaises(E)` стоит `pytest.raises(E)` без `match`. Перебор по константе
кода задан `parametrize` по самой константе либо циклом в теле функции, а не
списком литералов. Итерации с общим состоянием и случайный выбор остались
циклом.

AC-7. Ожидаемые значения перенесённых тестов совпадают с исходными
дословно. Ни одно сравнение не ослаблено.

AC-8. У каждой тестовой функции `tests/test_doc_commit_module.py` есть строка
«Ловит мутацию:».

AC-9. Каждый тест исходных файлов, не перенесённый в новый файл, перечислен
в PLAN удалённым дублем вместе со своими мутациями. Для каждого такого теста
выполнены два условия: (а) каждую его мутацию по таблице «до» убивает и
другой сохраняемый тест; (б) каждый литерал и вид каждого утверждения
удалённого теста есть в утверждениях сохраняемого теста, убивающего те же
мутации. Тест, чью мутацию не убил никто, не удалён.

AC-10. В PLAN есть раздел «Мутации после» с выводом `mutation-run`
(`--ref worktree`, тесты — `tests/test_doc_commit_module.py`), перенесённым
дословно, с шапкой. Каждая мутация есть в обеих таблицах. Каждая мутация,
убитая «до», в таблице «после» убита, и убивший узел назван.

AC-11. Шапки таблиц «до» и «после» согласованы:
- дерево `orchestrator/` у ревизий из обеих шапок совпадает —
  `git diff --quiet <sha до> <sha после> -- orchestrator/` завершается с
  кодом 0;
- sha256 каждого патча в обеих шапках совпадает.

AC-12. В PLAN названы число тестов, число строк и время адресного прогона
до и после свода.

AC-13. Шести исходных файлов на ветке нет: `tests/test_doc_commit.py`,
`tests/test_doc_commit_suite_gate.py`,
`tests/test_01m3y75x6k2zmd85971tcwv41e_held_base.py`,
`tests/test_doc_commit_held_base.py`,
`tests/test_01m4s0jvb85w9ty1esgnbh97fp_doc_commit.py`,
`tests/test_notes_batch_flush_edges.py`.

AC-14. В `tests/test_doc_commit_module.py` нет `skip`/`xfail`. Пределы
тестов (таймауты, допуски, пороги) не выше, чем в исходных файлах.

AC-15. Diff ветки против её базы в `tests/` — только удаление шести файлов
из AC-13 и новый `tests/test_doc_commit_module.py`. Не изменены
`tests/fixtures.py`, `tests/sandbox.py`, файлы волны 1а (требование 12) и
всё под `orchestrator/`.

## Оценка объёма и деление

Сработавшие сигналы:
- `budget_usd` ≥ $30 — ставка $70 из ТЗ;
- число критериев приёмки ≥ 10 — их 15.

Обоснование монолита (материал для решения Оператора на гейте SPEC).
Оператор уже разделил волну 1 по `notes` в ТЗ: 1а — копилка, бэклог и окно
тишины; 1б — `doc-commit` и сверка по базе (эта задача). Внутри 1б свод и
удаление неделимы:
- удаление исходных файлов без нового файла теряет покрытие;
- новый файл без удаления оставляет полные дубли;
- доказательство сравнивает убийства «до» на шести исходных файлах с
  убийствами «после» на одном сводном файле.

Файлы волны связаны импортами: suite_gate → test_doc_commit,
batch_flush_edges → suite_gate. Свод по частям потребовал бы промежуточных
импортов из удалённых файлов, а на каждую часть — свой мандат, свой набор
мутаций и свою независимую проверку. Зона — один новый файл и шесть
удалений в `tests/` плюс регенерация карты; резать её по смыслу нечего.

## Пути обхода гейтов
1. **«После» убито подготовкой.** AC-3 исключает «убийство» только
   падением подготовки лишь для таблицы «до»; AC-10 для «после» требует
   «убита, и убивший узел назван». В сводном файле подготовка песочницы,
   вынесенная в тело функции или в помощник-функцию модуля (ADR-0027 п. 3
   прямо толкает помощники с утверждениями в функции), падает как `failed`
   и засчитывается «убита» (`orchestrator/mutation_run.py:387-390`). Тест,
   убивавший мутацию утверждением «до», может «после» убивать её только
   сломанной подготовкой — доказательство формально сходится, а
   утверждение, может быть, не перенесено.
2. **Грубый патч.** AC-1 требует сопоставления строки «Ловит мутацию»
   мутации, но не требует, чтобы патч реализовал именно описанную строкой
   мутацию. Патч вида «`sys.exit` в начале `cmd_doc_commit`» убивает почти
   всё «до» и «после»: условие (а) удаления дубля (AC-9) выполняется для
   любого теста, а сравнение «до/после» перестаёт что-либо различать.
   Сдерживает (б) AC-9 и независимая проверка, но планка этого не видит.
3. **Части «после».** Если «после» не уложится в 900 с одного прогона, а
   SPEC не разрешает части, исполнитель либо сдаёт таблицу со строками
   «не прогнана (предел)» (AC-10 не выполним), либо делит по своему чтению
   — тогда «шапки обеих таблиц» AC-11 сверяются неоднозначно (какие шапки
   с какими при нескольких частях).
4. Мандат на путь заглушает гейт неослабления по шести файлам целиком
   (матрица, строка «Гейт неослабления»): единственный механический рубеж
   «ожидания дословно» — планка test_author по AC-7. Это принятая схема
   волны 1а, не отклонение; отмечено, чтобы гейт SPEC видел, что AC-7
   обязан проверяться планкой, а не доверием.

## Вердикт
concerns. SPEC переносит ТЗ без потерь, факты о коде подтверждены; вести
дальше можно, отклонения решаемы Оператором на гейте SPEC:

1. **Части «после» не предусмотрены** — SPEC.md треб. 9, AC-10, AC-11

   `mutation-run` — 900 с (`orchestrator/config.py:223`,
   `orchestrator/mutation_run.py:512`, `:531`), набор ~70 патчей «после»
   в него не войдёт. Нужно разрешить `--patches` для «после» с переносом
   каждой части и уточнить AC-11: шапки сверяются попарно по частям
   (дерево `orchestrator/` всех ревизий совпадает, sha256 каждого патча —
   в шапке «до» и «после» его части). Образец — SPEC волны 1а, треб. 7.
2. **«Убийство» подготовкой «после» не исключено** — SPEC.md треб. 3,
   AC-3 (только «до»), AC-10; `orchestrator/mutation_run.py:387-390`.
   Предложение: отметка узлов, убитых только подготовкой, и правило «хотя
   бы один убивший узел вне отметки» — и для «после».
3. **Патч не обязан реализовать мутацию своей строки** — SPEC.md треб. 1,
   AC-1. Предложение: в PLAN у каждой мутации — строка «Ловит мутацию» и
   патч, реализующий именно её; проверка — ревью и независимая проверка.
4. **Устаревшие ссылки в докстрингах** на удаляемый

   `tests/test_models.py:815`; SPEC треб. 12 / AC-15 их правку запрещают.
   Мелкое: принять как есть либо разрешить правку
   `tests/test_models.py:815`.
5. **Литеральные наборы `subTest`** (`tests/test_01m4s0jvb85w9ty1esgnbh97fp_doc_commit.py:223-271`,
   `tests/test_notes_batch_flush_edges.py:53-55`): AC-5 запрещает

# SPEC: Команда version

## Контекст
У `artel.py` нет способа быстро увидеть три версии, от которых зависит
согласованность прогона: на какую версию CLI закреплён пульт, какая
версия CLI фактически установлена, и какую версию схемы артефактов
понимает текущий `guard.py`. Расхождение пина CLI с фактической версией
сейчас видно только через `doctor` (предупреждением в общем наборе
проверок) — нужна отдельная лёгкая read-only команда, которая просто
печатает эти три версии.

## Требования
1. В `artel.py` появляется команда `version`.
2. Команда печатает: версию пина CLI из конфига, фактическую версию
   установленного `claude`, версию схемы артефактов.
3. Если пин CLI расходится с фактической установленной версией, вывод
   содержит явную пометку об этом расхождении.
4. Команда только печатает — не меняет конфиг, БД, git ни при каких
   условиях.
5. Место команды в общей справке `artel.py` — на усмотрение разработчика,
   при условии что Оператор сможет её найти.

## Критерии приёмки

AC-1. `artel.py version` — валидная команда CLI (не падает как
неизвестная подкоманда).

AC-2. Вывод `artel.py version` включает версию пина CLI из конфига.

AC-3. Вывод `artel.py version` включает фактическую версию
установленного `claude` (определяется тем же способом, что и в
`doctor.cli_version()`).

AC-4. Вывод `artel.py version` включает версию схемы артефактов
(`guard.SUPPORTED_SCHEMA_VERSION`).

AC-5. Если версия пина CLI не совпадает с фактически установленной
версией `claude`, вывод содержит явную текстовую пометку о расхождении;
при совпадении такой пометки нет.

AC-6. Выполнение `artel.py version` не изменяет ни один файл конфига,
ни БД (`.artel/state.db`), ни состояние git (ни в одном из состояний
из AC-5 — совпадение или расхождение пина).

AC-7. Команда `version` видна в общей справке `artel.py` (`--help`/`-h`)
— конкретное расположение в тексте справки выбирает разработчик.

## Не входит

- Автоматическое обновление пина CLI (`config.CLI_VERSION_PIN`) —
  остаётся ручным шагом Оператора.
- Любое изменение поведения `doctor` или его существующих проверок.
- Проверка версии CLI на каждом шаге агента (per-step preflight) —
  сознательно не входит в объём `doctor` (см. `orchestrator/doctor.py`,
  раздел докстринга про версию CLI) и не входит в объём этой задачи.

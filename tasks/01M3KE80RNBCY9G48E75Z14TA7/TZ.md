# ТЗ: Ретроспектива в снимке артефактов — верный исход и счётчики приёмочных тестов

Источник: две строки копилки 27.09 (разбор читателей каталога `tasks/`),
ADR-0018 «Следствия» — первое условие уборки каталога `tasks/` из `main`.

Факты (origin/main d345c66e, проверено на задаче
01M3HP7WAXKFK3GYZ3T6HX08M0, смерженной 27.09 18:25Z):
- Снимок `refs/artifacts/01M3HP7WAXKFK3GYZ3T6HX08M0` несёт
  `tasks/<id>/RETRO.md` со строками «Итог: killed — причина: причина не
  найдена в журнале» и «Адрес артефактов: артефакты не сохранены (ветка
  удалена при kill)», хотя задача смержена; `docs/retro/<id>.md` в `main`
  для той же задачи — «Итог: done, sha …».
- Причина: `orchestrator/cleanup.py` (функция публикации снимка при
  закрытии, строка 414 на b21f01e6) вызывает
  `snapshot.publish_and_cleanup(conn, task_id, target, "killed")` с
  исходом `"killed"` всегда, в том числе на пути закрытия смерженной
  задачи.
- `docs/retro/<id>.md` последних задач несёт «Приёмочные тесты: 0
  тест(ов), 0 manual, 0 skip» при непустом каталоге приёмочных тестов
  (01M3HP7W — 10 тестов, 01M3HJQV2QV9BXNXSH3F8STAYH — 36). Причина:
  `orchestrator/retro.py` (строки 253 и 439 на b21f01e6) читает
  `config.TASKS / <id>` главной копии, где каталога закрываемой задачи в
  момент записи нет.

Требуется:
1. Исход, передаваемый в публикацию снимка, соответствует состоянию
   задачи: `done` для смерженной, `killed` для ликвидированной.
   Ретроспектива в снимке смерженной задачи несёт «Итог: done», sha
   мержа и причину только для `killed`.
2. Строка «Адрес артефактов» в ретроспективе снимка смерженной задачи
   называет `refs/artifacts/<id>` (ADR-0005, пункт 4; ADR-0018, пункт 1),
   не «артефакты не сохранены».
3. Счётчики приёмочных тестов (число тестов, manual, skip) в обеих
   ретроспективах (`docs/retro/<id>.md` и снимок) считаются по каталогу
   приёмочных тестов из артефактной ветки задачи либо из её снимка, а не
   из главной копии. Источник чтения обосновать в SPEC: на момент записи
   ретроспективы артефактная ветка может быть уже удалена.
4. Порядок вызовов при закрытии не меняется: снимок публикуется строго
   до удаления кодовой и артефактной веток (ADR-0005, пункт 4).
5. Ретроспективы уже закрытых задач не переписываются (история);
   исправление снимков прошлых задач — не в рамке, отдельное решение
   Оператора.
6. Тесты (`tests/`): смерженная задача — в снимке «Итог: done» и адрес
   по ссылке; ликвидированная — «Итог: killed» с причиной, как сейчас;
   счётчики равны числу тестов каталога приёмочных тестов при
   отсутствии каталога задачи в главной копии; канареечный прогон
   снимка по-прежнему не публикует. Корень и пути подменяются через
   общие помощники `tests/sandbox.py`.
7. Документация: `docs/stack.md` — в разделе о закрытии задачи одно
   предложение об исходе в ретроспективе снимка.

Зоны: orchestrator/cleanup.py, orchestrator/snapshot.py, orchestrator/retro.py, docs/stack.md, tests/.

Только чтение (не менять): orchestrator/fsm_merge_gate.py,
orchestrator/fsm_postmerge.py, orchestrator/artifact_branch.py,
scripts/guard.py, docs/adr/, docs/backlog.md, tests/test_invariants.py.

Не входит: отмена наложения снимка на `main`; уборка каталога `tasks/`;
вторые копии для каталогов без снимка; правка формата `docs/retro/`.

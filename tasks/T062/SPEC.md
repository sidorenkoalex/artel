# SPEC: Команда release: операторское снятие lease + ревизия порога

## Контекст

Строка P3 роадмапа «Lease: ручной release Оператора + пересмотр порога».
Прецеденты T046, T051, T060: застрявший lease (например, от убитого
`auto`) блокирует мутирующие команды на весь `LEASE_STALE_AFTER_SEC`
(7200с), а снятие требовало прямой записи в БД руками. С включением
лимитера параллельных задач (T060, инвариант 32) застрявший чужой lease
занимает слот лимитера и мешает не только своей задаче, но и чужой —
до первого перехвата. Нужна явная операторская команда снятия lease
вместо прямых записей в БД, и по факту (не вслепую) пересмотренный
порог протухания.

## Требования

1. Новая команда CLI `artel.py release <task_id>` — операторское снятие
   lease задачи: удаляет строку `leases` этой задачи и пишет запись
   в журнал задачи (`actor=operator`) с данными бывшего держателя —
   `session_id`, `pid`, `hostname`, возраст heartbeat на момент снятия.
2. `release` снимает lease независимо от его свежести: и живой (heartbeat
   моложе `LEASE_STALE_AFTER_SEC`), и протухший — решение о снятии живого
   замка на совести Оператора, команда не проверяет свежесть перед
   снятием.
3. Отсутствие lease у задачи — не ошибка: `release` печатает дружелюбное
   сообщение о том, что снимать нечего, и завершается кодом возврата 0.
4. `release` не берёт lease задачи сама (только снимает существующий) и
   не проходит проверку лимитера `MAX_PARALLEL_TASKS` — тот же класс
   не-агентных команд, что `kill`/`status`/`approve`/`reject`/`budget`/
   `log`/`doctor` (инвариант 32, docs/invariants.md).
5. Developer в PLAN исследует по факту (не вслепую), продлевается ли
   heartbeat lease задачи в течение долгого агентного шага (шаг живёт
   до таймаута `AGENT_TIMEOUT_SEC`), и фиксирует вывод в PLAN.md с
   конкретной фактурой (файлы/строки/наблюдения, на которых вывод
   основан).
6. Если по итогам исследования (требование 5) heartbeat статичен на
   протяжении шага — `LEASE_STALE_AFTER_SEC` в `orchestrator/config.py`
   не понижается, остаётся 7200; строка роадмапа P3 сворачивается с этим
   обоснованием в PLAN.
7. Если по итогам исследования (требование 5) heartbeat продлевается по
   ходу шага — `LEASE_STALE_AFTER_SEC` снижается до 900 с сохранением
   существующей семантики протухания (замок протух, когда возраст
   heartbeat превышает порог).

## Критерии приёмки

AC-1. `release <id>` для задачи с существующим lease удаляет строку этой
задачи из `leases` и добавляет в журнал задачи запись с данными бывшего
держателя (`session_id`, `pid`, `hostname`, возраст heartbeat).

AC-2. `release <id>` снимает как свежий (heartbeat моложе
`LEASE_STALE_AFTER_SEC`), так и протухший lease — без разбора свежести.

AC-3. `release <id>` для задачи без lease завершается кодом возврата 0 и
печатает дружелюбное сообщение о том, что снимать нечего; ведение
журнала в этом случае (без записи или с явной записью «нечего снимать»)
— решение разработчика, задокументированное в PLAN.

AC-4. После `release` чужой задачи, державшей слот лимитера
`MAX_PARALLEL_TASKS`, запуск (`run`/`auto`) своей задачи, которая до
этого отказывала по инварианту 32 из-за занятых слотов, проходит.

AC-5. `release` не берёт lease задачи сама и не проходит проверку
лимитера `MAX_PARALLEL_TASKS` — вызывается без входа через
`lease.run_locked`/`parallel_limit`.

AC-6. PLAN.md несёт зафиксированный вывод исследования — продлевается ли
heartbeat lease в течение долгого агентного шага, — с фактурой
(конкретные файлы/строки/наблюдения).

AC-7. Значение `LEASE_STALE_AFTER_SEC` в `orchestrator/config.py`
соответствует выводу PLAN.md (требование 5): 7200 при статичном
heartbeat в течение шага, 900 при продлевающемся — без изменения
существующей семантики протухания.

AC-8. Все существующие тесты проходят зелёными.

## Не входит

- Автоматическое снятие протухших lease без явной команды `release`
  (перехват протухшего lease при `acquire` уже существует — T044, не
  меняется).
- Изменение механики продления heartbeat самой по себе: если требование
  5 покажет, что heartbeat нужно продлевать в течение шага, — это
  отдельная строка роадмапа P3 с фактурой из PLAN этой задачи, не код
  этой задачи.
- relock `acceptance_tests/` — соседняя строка роадмапа P3, отдельно.

# ТЗ: Команда release: операторское снятие lease + ревизия порога

## Контекст

Строка P3 роадмапа «Lease: ручной release Оператора + пересмотр
порога». Прецеденты: T046 (27.08) — lease убитого auto блокировал
мутирующие команды на LEASE_STALE_AFTER_SEC=7200с (2 часа), снятие
потребовало прямой записи в БД руками с ручной журнальной записью;
повторы прямых записей — T051, T060 (перелок — соседний класс). С
включением N=2 (T060) застрявший lease мешает не одной сессии, а
обеим: чужая задача с мёртвым lease занимает слот лимитера до
перехвата.

## Решение (Оператор 28.08)

1. Новая команда CLI `artel.py release <task_id>` — операторское
   снятие lease задачи: удаляет строку leases с записью в журнал
   (actor=operator, кто держал: session_id/pid/hostname, возраст
   heartbeat). Работает и для живого, и для протухшего lease —
   команда операторская, решение о снятии живого замка на совести
   Оператора (это и есть force-override, сознательно отложенный
   в T044 — теперь в явной команде с журнальным следом, а не в
   прямой записи в БД).
2. Отсутствие lease у задачи — не ошибка: сообщение «lease нет,
   снимать нечего», код возврата 0.
3. Пересмотр порога LEASE_STALE_AFTER_SEC — по факту, не вслепую:
   developer в PLAN исследует, продлевается ли heartbeat lease
   В ТЕЧЕНИЕ долгого агентного шага (шаг живёт до 30 мин таймаута).
   Если heartbeat статичен на протяжении шага — порог НЕ снижать
   (снижение до ~600с заставило бы чужую сессию «перехватывать»
   живой рабочий шаг), зафиксировать вывод в PLAN, порог остаётся
   7200; строка P3 сворачивается с этим обоснованием. Если heartbeat
   продлевается по ходу шага — снизить до 900с (15 мин) с сохранением
   существующей семантики протухания.
4. `release` не проходит через лимитер и не берёт lease сам (он
   его снимает) — тот же класс, что kill/status (инвариант 32,
   не-агентные команды).

## Границы

- orchestrator/ (artel.py, lease.py, при надобности store), тесты,
  карта. Механика acquire/протухания не меняется сверх п.3.
- Не ослаблять существующее (ADR-0002): release не обходит лимитер
  «в обратную сторону» — он не запускает шаги, только снимает замок.

## Не входит

- Автоматическое снятие протухших lease без команды (перехват при
  acquire уже существует — T044).
- Изменение механики heartbeat (если п.3 покажет, что его нужно
  продлевать в течение шага — это ОТДЕЛЬНАЯ строка P3 с фактурой
  из PLAN, не эта задача).
- relock acceptance_tests (соседняя строка P3 — отдельно).

## Приёмка (минимум)

- `release <id>` снимает существующий lease: строки нет, журнал несёт
  запись с данными бывшего держателя.
- `release <id>` без lease — дружелюбное сообщение, код 0, журнал
  без мусорной записи (или с явной записью «нечего снимать» — выбор
  developer, задокументировать).
- После release чужой задачи слот лимитера освобождается: запуск
  своей задачи проходит (связка с инвариантом 32).
- Вывод по порогу зафиксирован в PLAN с фактурой (как продлевается
  heartbeat); значение LEASE_STALE_AFTER_SEC соответствует выводу.
- Все существующие тесты зелёные.

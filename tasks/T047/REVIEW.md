## Предложения системе

- Класс «диф для Оператора в PLAN.md как код-блок» (прецедент T046,
  повтор в T047 итерация 1) не проверяется автоматически на
  applicability — доверие остаётся на глазомере автора. T047 итерация 2
  подтверждает, что лечится он именно проверкой `git apply --check` на
  этапе подготовки: после того как разработчик сам прогнал эту команду
  и приложил результат, дефект хедера исчез. Стоит закрепить этот шаг
  как часть шага «полный прогон» в PLAN (или явным пунктом в скиле
  conventions-core для защищённых путей) для всех задач, готовящих
  такой диф, иначе класс дефекта («хедер хунка не совпадает с реальным
  диапазоном») продолжит повторяться при каждой подготовке диффа для
  Оператора.

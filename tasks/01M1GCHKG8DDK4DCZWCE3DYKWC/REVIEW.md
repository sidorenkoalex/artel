## Замечания

- **blocker** — `tasks/01M1GCHKG8DDK4DCZWCE3DYKWC/acceptance_tests/
  test_ac11_status_shows_holder.py:38-42` (коммит `19a4031`, автор —
  человек, не автокоммит оркестратора, `2026-09-02 14:09`) — суть:
  залоченный приёмочный тест этой задачи отредактирован
  (`EXISTING_COLUMNS_RE`: якорь id `^T\d{3}` ослаблен до `^\S+`) с
  комментарием «правка Оператора 02.09, линт T094», но ни в одном
  артефакте задачи (SPEC.md, PLAN.md, REVIEW.md любой итерации) и ни в
  одном ADR (`docs/adr/0001..0010` — просмотрены все, ни один не
  описывает это решение) нет ни строки об этом решении. По
  conventions-core «Артефакт = единственный канал передачи между
  ролями. Всё, что не в артефакте, — не существует» и по ADR-0002,
  пункт 2, дословно: «Ослабление любых защит (тест, гейт, лимит, guard,
  инвариант) — только Оператором через ADR; для ролей это blocker в
  ревью» — правки, ослабляющей ассерцию залоченного теста, без ссылки
  на ADR, само правило требует заворачивать безусловно, независимо от
  того, кто автор коммита и звучит ли обоснование в сообщении коммита
  правдоподобно.
  Обоснование в комментарии («id задачи — непрозрачная строка», отсылка
  к переходу на ULID, SPEC T094) при проверке по существу не
  подтверждается для ЭТОГО теста: `setUp` заводит фикстурные задачи
  буквальными литералами `"T001"`/`"T002"`/`"T003"` через прямой
  `store.insert_task(...)` (строки 53-58), а не через `cmd_new`/
  `idgen` — реальный генератор ULID здесь вообще не участвует, и
  `_lines()` (строка 74-75) отдельно фильтрует строки вывода по
  `ln.startswith("T0")` до применения `EXISTING_COLUMNS_RE`. То есть
  для данного конкретного теста утверждение «формат id теперь ULID,
  строгий якорь `T\d{3}` больше не подходит» не соответствует
  фактической механике теста — фикстурные id всегда буквально
  `T00N` независимо от того, что генерирует `idgen.py` в проде.
  Ослабление конкретно этой ассерции ничем не мотивировано по существу,
  а формальная авторизация (ADR/артефакт задачи) отсутствует.
  Последствие: `approved` в таком состоянии закрепляет прецедент правки
  залоченных приёмочных тестов задачи вне артефактного канала и без
  ADR — ровно то, что ADR-0002 явно называет blocker'ом.
  Предложение: одно из двух — (а) разработчик/Оператор добавляет
  артефактную ссылку на решение (ADR в `docs/adr/` либо запись в
  PLAN.md «Итерация N», по образцу уже принятого в этой же задаче
  разбора R1-F1, документирующая, ПОЧЕМУ якорь ослаблен и почему это не
  снижает ловлю мутаций теста); либо (б) коммит `19a4031` отменяется —
  по разобранной выше механике теста ослабление не требуется, строгий
  якорь `T\d{3}` корректно матчит фикстурные id этого теста независимо
  от изменений формата id в проде.

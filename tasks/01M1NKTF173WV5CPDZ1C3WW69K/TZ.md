# ТЗ: артефакты роли — из артефактной ветки на старте шага (регрессия нового флоу A7 №9)

Источник: инцидент 04.09, пять задач волны (01M1KS8K…, 01M1KVG3…,
01M1NBWPKN…, 01M1NBWRTA…, 01M1NEEWH5…). Правки Оператора в SPEC на
гейте (редактура — законный ход, docs/operator-gates.md) записаны в
артефактную ветку; следующая роль читала SPEC не из брифа, а с диска
своего рабочего каталога: после автокоммита каталог `tasks/<id>/`
стирается, но копия лежит в КОДОВОЙ ветке (роль коммитит её сама по
скилу), роль видит «файл удалён», восстанавливает его `git checkout`
из кодовой ветки — старую версию — и её автокоммит записывает старый
SPEC обратно в артефактную ветку. Правка Оператора стирается молча;
у канарейки v2 планка написана под отменённый монолитный SPEC.

Требуется:
1. На старте каждого агентного шага задачи с артефактной веткой
   каталог `tasks/<id>/` рабочего каталога роли материализуется из
   ГОЛОВЫ артефактной ветки (тем же приёмом, что `acceptance.
   materialize_from_branch`), поверх любого содержимого на диске.
2. Бриф роли несёт актуальный текст SPEC (и PLAN/REVIEW по роли) из
   артефактной ветки с fingerprint в журнале — роль не обязана читать
   его с диска; инструкция «прочитай tasks/<id>/SPEC.md» в
   role_prompt/скилах заменяется на «SPEC — в брифе; на диске — та же
   версия».
3. Роли не коммитят `tasks/<id>/` в кодовую ветку: скилы
   (conventions-core, spec-authoring, test-authoring, review-checklist)
   и role_prompt перестают требовать `git add/commit` артефактов;
   единственный путь артефактов в git — автокоммит оркестратора в
   артефактную ветку. Существующие копии `tasks/<id>/` в кодовых ветках
   живых задач не трогаются (уйдут с мержем; в main их нет).
4. Сторож: если после шага содержимое `tasks/<id>/` на диске отличается
   от головы артефактной ветки в файлах, которые роль НЕ меняла в этом
   шаге (по журналу изменений/размеру), но которые изменились в ветке
   после старта шага — автокоммит не перезаписывает их, а пишет алерт
   kind=incident «конфликт артефактов: правка в ветке новее рабочего
   каталога».
5. Тесты: правка SPEC в артефактной ветке между шагами доходит до
   следующей роли (бриф и диск); автокоммит не откатывает правку;
   роль без коммита в кодовую ветку проходит шаг штатно; существующие
   тесты зелёные без ослабления.

Зоны: orchestrator/runner.py (старт шага), orchestrator/brief.py,
orchestrator/role_prompt.py, orchestrator/checkpoint.py (сторож),
skills/*.md, tests/. Конфликт зон с задачами `.gitignore`
(01M1KVG3…), WIP-чекпоинт (01M1NBWTSX…), ANSWER в брифе ревьювера
(01M1NBWRTA…): старт in_dev после их мержа; до мержа — только SPEC.

Не входит: изменение механики артефактной ветки и снапшотов (A7);
миграция старых задач.

# ТЗ: наблюдатель роста карты, часть 2 — блок report и оценка в деньгах

Родительская задача: 01M1RFVWV6WWTXRC5F40K61632 («Наблюдатель роста
карты кодовой базы»), SPEC которой на гейте 05.09 сужен до части 1
(статистика `map_stats`, запись «карта: размер» на мерже,
`doctor.check_map_growth`). Эта часть — требования 4–5 и критерии
AC-16..AC-19 исходного SPEC родителя, дословно; источник ТЗ —
`tz-map-growth-watch.md`. Без части 1 в журнале нет записей «карта:
размер», и блок отчёта был бы вечно пуст, поэтому старт — после мержа
части 1.

Требуется:
1. Оценка «стоимость карты за шаг developer» (`orchestrator/report.py`):
   `tokens` = `bytes_projection` последней записи ряда «карта: размер»
   target, если поле есть, иначе `bytes_total`, делённое на 3 (без
   токенизатора); `calls` — медиана числа вызовов инструментов агента
   `developer` по логам его шагов за последние 10 задач глобально по
   всем target (курс роли один на все target, `config.TOKEN_RATES`);
   при нехватке данных — константа-ориентир из `config` с пометкой
   «оценка»; `cost_usd` = `tokens × calls × cache_read_usd_per_token`
   + `tokens × cache_creation_usd_per_token` роли `developer`.
2. Оценка не заводит алертов и не влияет ни на один переход или гейт:
   только число-ориентир для решения Оператора при `ack` алерта
   `map.growth`.
3. Блок в `artel report` по каждому target: таблица последних 12
   записей «карта: размер» (дата, `bytes_total`, `bytes_projection`
   при наличии, `sections_total`, `bytes_by_dir`), медиана окна
   калибровки, если уже посчитана, список открытых алертов
   `map.growth` этого target, оценка из п.1.
4. Target без единой записи «карта: размер» — строка «измерений нет:
   карта ни разу не регенерировалась после мержа этой версией» вместо
   таблицы, без ошибки.
5. Тесты: блок на фикстурном ряде записей (константы `MAP_*` и
   ориентир вызовов — из `config`, не литералами); «измерений нет» на
   пустом ряде; оценка при наличии и отсутствии `bytes_projection`;
   независимость рядов двух target (инвариант 22); существующие
   `tests/test_report.py` зелёные без правки существующих ассертов.

Зоны: orchestrator/report.py, orchestrator/config.py (константа-
ориентир числа вызовов developer), tests/. Порядок: после мержа части 1
(родитель 01M1RFVWV6WWTXRC5F40K61632).

Не входит: всё из части 1 (статистика, запись на мерже, проверка
doctor, пороги роста); автоматические действия по алерту; абсолютные
пороги; изменение потолков `CONTEXT_*`.

Рамка: $15.

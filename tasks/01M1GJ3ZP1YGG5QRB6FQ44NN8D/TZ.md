# ТЗ: Сухой прогон приёмки — предпросмотр без исполнения

Источник: протокол ручных гейтов (docs/operator-gates.md, гейт
приёмки): Оператор до approve обязан свериться с приёмочными тестами
— число тестов против AC, каждая пометка manual/skip прочитана.
Сегодня для этого нет отдельной команды: либо смотреть файлы руками
(ветко-зависимо, легко ошибиться чекаутом), либо ждать реального
прогона на переходе гейта. Нужен дешёвый read-only предпросмотр,
который по построению не может быть принят за прохождение приёмки.

Требуется:
1. Операторская read-only команда сухого прогона приёмки по id
   задачи (имя и место регистрации — решение исполнителя;
   регистрация в orchestrator/artel.py): показывает обнаруженные
   тестовые файлы и методы, все AC-маркеры (manual/skip/escalate
   с причинами) и сводку трассируемости — какой AC покрыт каким
   тестом либо пометкой, какие не покрыты.
2. Разбор — тем же кодом, что уже держит трассируемость и сводку
   (scripts/guard.py::scan_acceptance_tests), без дублирования
   логики: расхождение источников должно быть невозможно
   по построению.
3. Команда ничего не исполняет и не мутирует: unittest не
   запускается, БД и журнал не пишутся, состояние задачи не
   меняется, lease не берётся (тот же класс, что status/log).
4. Вывод явно помечен: «сухой прогон — не является прохождением
   приёмки»; никакой результат команды не записывается и не может
   быть предъявлен как пройденная приёмка (эквивалент passed: null).
5. Чтение acceptance_tests — ветко-корректное (инвариант 28:
   источник истины — ветка задачи, чужой чекаут не подменяет);
   ветки/каталога нет — честный именованный отказ, не пустая сводка.
6. Тесты: сводка совпадает с фактическим содержимым ветки; пометки
   с причинами показаны; непокрытый AC назван; отсутствие записи
   в журнал/БД; ветко-корректность (чужой чекаут); отказ на
   отсутствующем каталоге; существующие тесты зелёные.

Зоны: orchestrator/artel.py (регистрация команды),
orchestrator/acceptance.py (реализация), tests/. Не трогать:
scripts/guard.py (переиспользуется как есть), catalog.py (зона
задачи «Наблюдаемость сессий», пока не смержена), fsm_advance.py
(зона задачи «Лимиты пакетов», пока не смержена). Конфликт зон —
эскалация, не выход за границу.

Не входит: запуск тестов в каком-либо режиме (в том числе
«безопасном»); изменение механики перехода acceptance и автогейта;
изменение формата AC-маркеров.

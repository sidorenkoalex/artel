# SPEC: Допуск набора сверяет роли вне набора с боевыми моделями

## Контекст
`orchestrator/models.py::set_admitted` (строки 1239–1274 на пине
a6904801) засчитывает набору зелёный прогон канарейки на шаблоне класса
`трудный`, если сводка моделей прогона (`summary_models`, строка 1080)
совпадает с набором только по ролям набора (строка 1270); модели
остальных ролей не сверяются. Так набор `codex-dev` (`developer:
gpt-6-sol`) признаётся допущенным по прогону 20260930T120255Z набора
канарейки `c-codex-mix`, где на Codex шли все четыре роли, — хотя
ADR-0019 п.5 требует зелёного прогона набором целиком, с проверкой пары
и в соседстве. Прогон с правильным соседством (роли вне набора — на
боевой модели) есть: 20261002T201326Z. Боевая модель роли —
`models._combat_model(role)` (строка 1230).

## Требования
1. Зелёный прогон на шаблоне класса `трудный` засчитывается набору,
   только если (а) сводка прогона совпадает с набором по ролям набора И
   (б) каждая роль сводки, которой нет в наборе, шла на боевой модели
   этой роли (`_combat_model`). Роль набора, отсутствующая в сводке
   прогона, — прогон не засчитывается.
2. Пояснение `set_admitted` при допуске называет засчитанный прогон; при
   отказе по этому условию — причину «нет зелёного прогона набором
   целиком на шаблоне класса «трудный» (роли вне набора — на боевых
   моделях)».
3. Прочие условия допуска (допуск пар в `pairs:`, приостановка пары,
   класс шаблона, вердикт `green`) не меняются.
4. Тесты в `tests/` закрывают новое условие (критерии AC-1, AC-2);
   существующие тесты допуска набора, `new --set` и `set-models` не
   удаляются и не ослабляются.
5. `docs/stack.md`, раздел «Допуск набора» (строки 842–848): уточнение,
   что роли сводки прогона вне набора должны идти на боевых моделях.

## Критерии приёмки
AC-1. Зелёный прогон на шаблоне класса `трудный`, сводка которого
совпадает с набором по ролям набора, но хотя бы одна роль сводки вне
набора шла на модели, отличной от её боевой модели (`_combat_model`), —
не засчитывается: при отсутствии другого подходящего прогона
`set_admitted` возвращает «не допущен» с причиной «нет зелёного прогона
набором целиком на шаблоне класса «трудный» (роли вне набора — на боевых
моделях)». Тест несёт пометку «Ловит мутацию: прогон с другими моделями у
ролей вне набора засчитан».

AC-2. Зелёный прогон на шаблоне класса `трудный`, сводка которого
совпадает с набором по ролям набора, а каждая роль сводки вне набора шла
на своей боевой модели, — засчитывается: `set_admitted` возвращает
«допущен», и пояснение называет `run_stamp` этого прогона.

AC-3. Когда в `canary_runs` есть оба прогона — с не-боевыми моделями у
ролей вне набора и с боевыми (порядок строк любой), `set_admitted`
допускает набор, и пояснение называет именно прогон с боевыми моделями у
ролей вне набора.

AC-4. Зелёный прогон на шаблоне класса `трудный`, в сводке которого нет
роли набора, не засчитывается: при отсутствии другого подходящего
прогона `set_admitted` возвращает «не допущен» с причиной из AC-1.

AC-5. Прочие условия допуска не меняются: при прогоне, удовлетворяющем
AC-2, набор с недопущенной или приостановленной пульт парой не допущен с
прежней причиной о паре; прогон не на шаблоне класса `трудный` либо с
вердиктом не `green` не засчитывается.

AC-6. `docs/stack.md`, абзац «**Допуск набора**», сообщает, что роли
сводки прогона, не входящие в набор, должны идти на боевых моделях.

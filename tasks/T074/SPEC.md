# SPEC: pause --now — жёсткая приостановка + чекпоинт аварийного шага

## Контекст
T070 дала грейсфул-паузу: пометка в БД, бегущий шаг дорабатывает,
следующий не начинается. Жёсткий вариант — прерывание бегущего шага —
сознательно вынесен из T070 в отдельную задачу (SPEC T070, «Не входит»)
как свёртка с P3-строкой «чекпоинт при rc-обрыве». Фактура необходимости:
29–30.08 остановка живых циклов делалась убийством процессов руками —
два инцидента целостности «грязная копия артефактов» на рестарте (T070,
T072), WIP спасался ручными чекпоинт-коммитами Оператора. Механика
чекпоинта уже есть: T041 (WIP-чекпоинт на таймауте шага) + T059
(worktree-осведомлённость, `add` только путей задачи) — но включается
она сегодня ТОЛЬКО на таймауте.

## Требования

1. `pause --now <id>` ставит обычную пометку паузы задачи (как `pause`,
   T070) и, если сейчас бежит агентный шаг задачи, прерывает его:
   процесс агента корректно завершается, незакоммиченный WIP worktree
   задачи чекпоинтится служебным коммитом с пометкой причины «pause
   --now» (механика T041/T059: актёр orchestrator, `add` только путей
   worktree задачи), lease держателя освобождается, журнал несёт полную
   последовательность действий.
2. Бегущий шаг может исполняться в другом процессе той же машины
   (параллельная CLI-сессия, фоновый `auto`) — адресация выполняется
   через данные lease задачи (pid, host). Lease нет или его процесс уже
   мёртв — честное сообщение и деградация до обычного `pause`, не
   ошибка. Прерывание процесса на другом host — вне объёма, честный
   отказ с текстом.
3. Правило чекпоинта WIP (T041) расширяется: чекпоинт выполняется не
   только при таймауте шага, но и при аварийном завершении шага (rc !=
   0, обрыв потока), если дерево worktree грязное; пометка причины
   стоит и в коммите, и в журнале. Диагностическая ценность сохраняется
   в самом чекпоинт-коммите.
4. Стоимость прерванного шага учитывается по существующей механике T040
   (частичные суммы промежуточных usage-событий; отсутствие данных —
   алерт `spend.unknown_cost`). Шаг, прерванный `pause --now`, не
   считается провалом роли — счётчики отказов/итераций не
   инкрементятся.
5. После `resume <id>` команды `auto <id>`/`run <id>` перезапускают шаг
   заново, стартуя от чекпоинта в worktree — как после таймаута T041.
   Инцидент целостности «грязная копия» после `pause --now` возникать
   не должен: чекпоинт закрывает дерево до выхода команды.
6. `pause --now <id>` задачи без бегущего агентного шага деградирует до
   обычного `pause` с сообщением об этом.

## Критерии приёмки

AC-1. `pause --now <id>` на задаче с бегущим агентным шагом в другом
процессе той же машины (параллельная CLI-сессия или фоновый `auto`)
корректно завершает процесс агента.

AC-2. `pause --now <id>` при этом ставит обычную пометку паузы задачи —
той же семантики, что и `pause` (T070).

AC-3. Незакоммиченный WIP worktree задачи на момент прерывания
зачекпоинчен служебным коммитом с пометкой причины «pause --now» —
механика T041/T059 (актёр orchestrator, `git add` только путей worktree
задачи).

AC-4. Lease держателя прерванного шага освобождается.

AC-5. Журнал задачи содержит полную последовательность действий `pause
--now`: обнаружение бегущего шага, прерывание процесса, чекпоинт,
снятие lease, пометка паузы.

AC-6. Адресация бегущего шага в другом процессе выполняется через
данные lease задачи (pid, host).

AC-7. Lease задачи не найден или его процесс уже мёртв — `pause --now`
не завершается ошибкой: печатает честное сообщение и деградирует до
обычного `pause`.

AC-8. Lease задачи указывает на процесс другого host — прерывание не
выполняется: честный отказ с сообщением о том, что прерывание процессов
на другом host вне объёма.

AC-9. Аварийное завершение агентного шага (rc != 0 или обрыв потока
агента) с грязным деревом worktree порождает WIP-чекпоинт с пометкой
причины — расширение правила T041 не только на таймаут; пометка стоит
и в коммите, и в журнале.

AC-10. Стоимость шага, прерванного `pause --now`, учитывается по
механике T040 (частичные суммы промежуточных usage-событий из stream-
json лога шага); при отсутствии данных открывается алерт
`spend.unknown_cost`.

AC-11. Шаг, прерванный `pause --now`, не считается провалом роли:
счётчики отказов/итераций роли не инкрементятся.

AC-12. После `pause --now` бегущего шага последующий `auto`/`run`
честно стоит на паузе (не начинает следующий агентный шаг) — по той же
механике, что и обычная пауза (T070), — пока не выполнен `resume`.

AC-13. После `resume <id>` команда `auto <id>` (или `run <id>`)
перезапускает шаг заново, стартуя от зачекпоинченного состояния
worktree — как после таймаута T041.

AC-14. Сверка целостности (`fixation.check_integrity`) на рестарте
после `pause --now` не порождает инцидент «грязная копия артефактов»:
чекпоинт закрывает дерево до выхода команды `pause --now`.

AC-15. `pause --now <id>` на задаче без бегущего агентного шага
деградирует до обычного `pause` и печатает сообщение об этой
деградации.

AC-16. Полный тестовый набор зелёный; новые тесты `pause --now` и
расширенного чекпоинта аварийного шага — в общей песочнице
(tests/sandbox.py).

## Не входит

- Панельная кнопка `pause --now` — вне объёма (этап 2 панели).
- Прерывание процессов агента на другом host — вне объёма, только
  честный отказ (AC-8).
- Ослабление таймаут-механики T041, существующих лимитов и
  инвариантов — запрещено (принцип целостности); все изменения этой
  задачи — аддитивные.
- Изменение наблюдаемого поведения обычных `pause`/`resume` (T070) —
  вне объёма: их сценарии остаются как в SPEC T070.
- Изменения FSM-состояний, гейтов и инвариантов автомата.

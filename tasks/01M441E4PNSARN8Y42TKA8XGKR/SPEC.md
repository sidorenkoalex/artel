# SPEC: canary-status-sort

## Контекст
Оператор хочет сразу видеть самые дорогие задачи в выводе `artel.py
status`. При этом скрипты сводки Оператора читают вывод `status`
построчно и сверяют строки по их номеру, поэтому порядок строк вывода
переставлять нельзя ни при каком флаге (ТЗ, п.3). Сейчас `cmd_status`
(`orchestrator/catalog.py:825`) печатает по одной строке на задачу в
порядке `store.all_tasks`, затем секцию «Триггеры…»
(`orchestrator/catalog.py:860`); флагов у команды нет, диспетчер —
`orchestrator/artel.py:1533`.

Допущение (ANSWER-1: Оператор поручил выбрать наименее рискованное
прочтение противоречия п.1 и п.3 ТЗ, батч QUESTIONS.md вопросы 1–3):
- `--sort cost` не переставляет и не меняет ни одной строки, которую
  `status` печатает без флага. Порядок по расходу выводится отдельным
  блоком, дописанным ПОСЛЕ всего прежнего вывода (после строк задач и
  после секции триггеров), так что номера всех прежних строк
  сохраняются. Это единственное прочтение, при котором выполняются
  и п.1, и п.3; риск — блок окажется не тем видом, которого ждал
  Оператор, но ни один скрипт сводки от него не сломается.
- «Израсходованное» — поле задачи `spent_usd`, то же число, что
  печатается в строке задачи как `$X/…`, без оценки незавершённого
  шага.

## Требования
1. `artel.py status --sort cost` печатает весь вывод, который `status`
   печатает без флага, байт в байт и в том же порядке строк, а после
   него — блок, открывающийся строкой `По расходу:`, в котором каждая
   задача из списка `status` встречается ровно одной строкой,
   начинающейся (после ведущих пробелов) с её id и содержащей её
   израсходованное `$<spent_usd>` с двумя знаками после точки.
2. Строки задач в блоке упорядочены по убыванию `spent_usd`; при равном
   `spent_usd` — по id задачи по возрастанию.
3. Вывод `artel.py status` без флага не меняется — ни строки, ни их
   порядок.
4. Неизвестное значение `--sort` (любое, кроме `cost`) — отказ с кодом
   выхода 2 и сообщением, называющим переданное значение и допустимое
   значение `cost`; вывод задач при этом не печатается.

## Критерии приёмки
AC-1. На наборе задач с разным `spent_usd` блок после строки
`По расходу:` в выводе `status --sort cost` перечисляет id задач по
убыванию `spent_usd`.

AC-2. На наборе задач, у части которых `spent_usd` равен, задачи с
равным расходом идут в блоке по id по возрастанию.

AC-3. Вывод `status` без флага на том же наборе задач совпадает с
выводом до изменения (строки и их порядок); вывод `status --sort cost`
до строки `По расходу:` совпадает с выводом `status` без флага строка в
строку, включая секцию триггеров при открытом триггере.

AC-4. `status --sort <неизвестное значение>` завершается с кодом выхода
2, сообщение называет переданное значение и допустимое `cost`.

## Не входит
- Сортировка по другим полям.
- Вывод в JSON.
- Перестановка строк основного вывода `status` при любом флаге (ТЗ,
  п.3).
- Учёт оценки расхода незавершённого шага (`budget.spent_with_estimate`)
  в сортировке.
- Зелёный полный набор `tests/`, зелёный CI ветки, неизменность
  защищённых путей и непревышение рамки $25 — их держит пульт.

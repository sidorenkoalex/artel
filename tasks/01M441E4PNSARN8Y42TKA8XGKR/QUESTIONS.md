# QUESTIONS: canary-status-sort

## Вопросы

1. **П.1 и п.3 ТЗ противоречат друг другу: как совместить сортировку по
   расходу с запретом переставлять строки `status`?** П.1 требует, чтобы
   `artel.py status --sort cost` печатал задачи по убыванию
   израсходованного (то есть переставлял строки задач). П.3 запрещает
   менять порядок строк вывода `status` «ни при каком флаге», потому что
   скрипты сводки сверяют строки по номеру. Сейчас `cmd_status`
   (`orchestrator/catalog.py:825`) печатает одну строку на задачу в
   порядке `store.all_tasks`, так что любая сортировка по расходу
   переставит строки. Обоим пунктам буквально удовлетворить нельзя.
   Варианты:
   A) п.3 относится только к выводу БЕЗ флага (тогда он повторяет п.2):
      `--sort cost` переставляет строки задач, а скрипты сводки флаг не
      передают;
   B) `--sort cost` не трогает строки задач, а печатает после них
      отдельный блок (например, «По расходу:») с теми же задачами по
      убыванию расхода. Номера строк основного блока сохраняются;
   C) сортировка выносится из `status` в отдельную команду или вывод
      (например, `status-cost`), а `status` остаётся как есть;
   D) п.1 снимается, задача закрывается.
   — дефолт: **нет**. Здесь выбирается, что именно строить, и любой
   выбор без Оператора — интерпретация «на свой вкус» (escalation-rules).
   Пока ответа нет, задача стоит.

2. **Какая строка остаётся неизменной при флаге: только строки задач или
   весь вывод `status`, включая секцию триггеров и алертов после
   задач?** От этого зависит, куда можно поместить новый блок в
   варианте 1B. Сейчас после строк задач `cmd_status` печатает секцию
   «Триггеры…» (`orchestrator/catalog.py:860` и далее), и её строки
   скрипты тоже могут сверять по номеру. Варианты:
   A) неизменны только строки задач, а блок сортировки идёт после всего
      вывода;
   B) неизменен весь вывод, а сортированный блок печатается последним,
      после всех существующих секций (номера прежних строк не
      сдвигаются).
   — дефолт: B. Этот вариант сохраняет номера всех строк, которые сейчас
   печатает `status`, и он строже. Вопрос имеет смысл только при ответе
   1B.

3. **Что считать «израсходованным» для сортировки?** Строка `status`
   показывает `spent_usd` (`$X/Y`), а в пульте есть ещё оценка расхода
   незавершённого шага (`budget.spent_with_estimate`). Варианты:
   A) поле `spent_usd` задачи, то же, что печатается в `$X/…`;
   B) `spent_usd` плюс оценка незавершённого шага.
   — дефолт: A. Это число Оператор видит в той же строке, и п.1 ТЗ
   говорит именно об «израсходованном».

# PLAN: Уборка по седьмой ревизии: карта кодовой базы с подпакетами, рудимент NoteError, пин версии CLI

## Подход

Три независимые правки одним MR (монолит утверждён на гейте SPEC), из них
неразрезаемы только требования 1–5 — генератор и собранная им карта.

**Генератор (`scripts/codebase_map.py`).** Четыре точечные правки, ни одна
не трогает формат вывода:

1. `discover_module_paths` — `dir_path.glob("*.py")` -> `rglob("*.py")` с
   отсечением служебных каталогов (`__pycache__` и скрытые `.…`) и
   сортировкой по кортежу сегментов относительного пути
   (`p.relative_to(root).parts`), а не по `p.name`. Сортировка по
   сегментам — то, что даёт AC-4 «непрерывный блок»: `misc_checks.py`
   подпакета не встаёт по алфавиту между модулями верхнего уровня, а
   каталог сортируется как один сегмент. Для сегодняшних модулей
   верхнего уровня порядок не меняется (общий префикс + `name` ==
   последний сегмент), поэтому уже существующие секции карты остаются на
   своих местах, а новые вклиниваются блоками.
2. `module_dotted_name` — имя строится по пути целиком:
   `".".join(parts[:-1] + (stem,))`, а для `__init__.py` — по одному
   каталогу (`".".join(parts[:-1])`). Для путей верхнего уровня результат
   прежний, поэтому юниты `ModuleDottedNameTest` не правятся.
3. Новая `module_package_name(rel_path)` — dotted-имя ПАКЕТА, внутри
   которого лежит модуль (`orchestrator/doctor/preflight.py` ->
   `orchestrator.doctor`). `parse_module` передаёт её в
   `extract_imported_dotted_names` вместо `rel_path.parts[0]`.
4. `extract_imported_dotted_names` — сигнатура `(tree, package)`
   сохраняется дословно (AC-11 запрещает править ожидания
   `tests/test_codebase_map.py`, которые зовут её с `"orchestrator"`),
   меняется только разбор уровня: вместо «уровень 1 — можно, глубже —
   `continue`» уровень N отсекает N-1 хвостовых сегментов `package`
   (`from .. import y` внутри `orchestrator.doctor` -> `orchestrator.y`),
   а уровень глубже корня пакета по-прежнему пропускается. При
   `package == "orchestrator"` поведение побайтно прежнее: уровень 1 даёт
   `orchestrator.x`, уровень 2 отбрасывается.

Правила проекции (`_section_kind`/`_KEPT_FIELDS_BY_KIND`) и `map_stats`
не правятся вовсе: оба разбирают путь заголовка по ПЕРВОМУ сегменту
(`rel.split("/", 1)[0]`, `header.split("/")[0]`), то есть секция
`orchestrator/doctor/preflight.py` уже сегодня опознаётся как
`orchestrator` — требование 2 (одноуровневый заголовок с префиксом
пакета) именно поэтому и выбрано SPEC. AC-5 и AC-6 закрываются
отсутствием правки, а не правкой.

**Карта (`docs/codebase-map.md`)** пересобирается тем же генератором тем
же коммитом (требование 5): иначе CI-джоб свежести красен в обе стороны.

**Рудимент и пин** — механически: `class NoteError` с докстрингом уходит
из `orchestrator/notes.py` целиком (ссылок в дереве нет — проверено
`git grep`), `CLI_VERSION_PIN` поднимается до `"2.1.267"` с пометкой
решения в той же строке (AC-9 читает именно строку присваивания).

Расхождения с оценкой SPEC по числу файлов и шагов нет — `budget_usd` в
frontmatter не поднимается.

## Влияние на систему

- **Потребители карты.** Формат `## <относительный путь>` — структурный
  контракт: по нему ходят `codebase_map.map_stats` (суммирование байт по
  первому сегменту пути), `codebase_map._section_kind` (выбор правила
  проекции), `orchestrator/brief.py` (встраивает проекцию в бриф),
  `orchestrator/advance_gates/capacity.py` и
  `orchestrator/review.py` (исключают файл карты из меры diff по имени
  файла, не по содержимому). Формат не меняется ни на байт — меняется
  только состав секций, поэтому ни один разбор не переписывается.
- **Порог переполнения проекции.** `config.CONTEXT_FILE_MAX_BYTES` и
  условие алерта в `brief._handle_map_size_alert` не трогаются
  (SPEC «Не входит»); вместо этого новый юнит меряет проекцию реальной
  карты против порога и покраснеет, если запас исчерпается, — это
  усиление, а не ослабление.
- **Алерт роста карты.** `doctor` map-growth на мерже ожидаемо поднимет
  алерт (+34 секции разом); пороги `MAP_GROWTH_RATIO` и
  `MAP_GROWTH_CALIBRATION_MERGES` не трогаются, ack — действие Оператора
  (SPEC, требование 5).
- **Гейт ёмкости и ревью-пакет.** `docs/codebase-map.md` исключён из меры
  обоих (01M31DRD81), поэтому +50 КиБ карты их не задевает; проверяется
  зелёностью `tests/test_capacity_gate_map.py` и
  `tests/test_review_package_map.py`.
- **`orchestrator/doctor/`, `orchestrator/advance_gates/`,
  `orchestrator/providers/`, `orchestrator/brief.py`,
  `.github/workflows/ci.yml`** — только чтение, ни одной правки; AC-10
  сверяет это дифом ветки.
- **Пин версии.** Единственный потребитель сравнения —
  `doctor.check_cli_version` (warn, не блок) и `orchestrator/version.py`
  (печать). Подъём пина снимает warn; тесты, читающие константу, держат
  её через `config.CLI_VERSION_PIN`, а `tests/test_stack.py` — литералами
  фикстур, которых подъём не касается (проверено прогоном).
- **`NoteError`.** Ни одной ссылки во всём дереве (`git grep` вне
  `tasks/` и `docs/audits/` — пусто); поведение команды `note` не
  зависит от объявления, валидация отказывает через `sys.exit`.
- **Откат** — revert одного merge-коммита: генератор, карта, пин и
  рудимент едут вместе, промежуточных состояний нет.

## Риски

- **Порядок секций.** Смена ключа сортировки с `p.name` на кортеж
  сегментов пути теоретически могла бы переставить существующие секции;
  для модулей одного каталога ключи изоморфны, но проверяется это не
  рассуждением, а дифом перегенерированной карты: в нём обязаны быть
  только добавления секций подпакетов и дополнения перечней
  «Импортирует»/«Импортируется», без перестановок.
- **Запас порога проекции.** +34 секции подпакетов съедают часть запаса
  (63 958 из 131 072 байт до правки). Замер после перегенерации —
  в юните AC-6-класса; если бы запас кончился, уточнять пришлось бы
  правило проекции, а не порог (SPEC «Не входит»).
- **Рекурсия по служебным каталогам.** `rglob` без фильтра подобрал бы
  `__pycache__`; фильтр отсекает служебные сегменты пути, а не только
  имя каталога верхнего уровня, — иначе мусор из вложенного
  `__pycache__` подпакета попал бы в перечень.

## Предложения системе

- `tests/test_invariants.py:1905-1913` (`StdlibOnlyImportsInvariantTest`)
  сканирует только `glob("*.py")` каталогов с докстрингом «у
  orchestrator/scripts/tests сегодня нет вложенных пакетов (тот же
  приём, что `codebase_map.discover_module_paths`)» — после этой задачи
  утверждение неверно, и инвариант «только стандартная библиотека» не
  видит 34 модуля подпакетов. Правка вне требований этой задачи
  (SPEC не называет её) — отдельная задача на тот же класс «проверка
  дерева, написанная под плоскую структуру».
- `brief.MAP_WATCH_GLOBS` (и те же три glob'а в
  `.github/workflows/ci.yml`) сторожат свежесть карты по
  `orchestrator/*.py`/`scripts/*.py`/`tests/*.py` — правка файла
  подпакета карту не «стухнет» для сторожа, хотя теперь меняет её.
  SPEC вынес это в «Не входит» как вопрос расширения зон к Оператору;
  фиксирую, чтобы вопрос не потерялся вместе с контекстом задачи.

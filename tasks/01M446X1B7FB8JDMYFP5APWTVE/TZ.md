# ТЗ: дозор показывает ход шага роли

Источник: бэклог — строка «Дозор показывает ход шага роли» (приоритет 2,
$25; предложение Оператора 04.10.2026). Решение Оператора 04.10 «заводи
волну один».

Факты (пин 0a87c8b0, сверка кода 04.10):
- `orchestrator/watch.py::cmd_watch` (~281, цикл ~320-364): heartbeat
  наблюдения, выборка новых записей журнала `steps` по задачам набора
  (`_emit_steps` ~202, `store.task_steps_since`), фильтр классов
  (`_matches_class` ~170; класс `steps` — действия, начинающиеся с
  «agent run»), алерты; период — `config.OBSERVATION_HEARTBEAT_PERIOD`
  = 30 с; формат строки — `_print_line` ~190
  («<ts>  <id>  <actor>  <action>  | <detail>»).
- Между записями «agent run started» и «finished/TIMEOUT» шаг идёт до
  `config.AGENT_TIMEOUT_SEC` = 2700 с (45 мин); в журнале в это время
  ничего не появляется. Начало шага — `ts` записи «agent run started»
  (`orchestrator/runner.py` ~1387), путь лога шага — в её detail
  («лог: <path>»).
- Лог шага пишет `orchestrator/agent_log.py` (`OutputPump` ~353-382,
  `tee_lines` ~154): строки вызовов инструментов «· <Tool> <аргумент>» и
  текст ассистента. Результаты инструментов (`tool_result`) в лог не
  пишутся: `ClaudeProvider._user_event`
  (`orchestrator/providers/claude.py` ~381-400) отдаёт их в
  `event.tool_results` с пустым `log_text`; у Codex аналог —
  `orchestrator/providers/codex.py` ~714. Сырой stream-json не
  сохраняется. Итоговая строка pytest («N failed, M passed …») доступна
  только в живом потоке, в `tool_results`.
- Прецедент 04.10: этап 2 ADR-0021 — пять шагов developer по 45 мин, ход
  виден Оператору только по ручным запросам «статус» и чтению лога;
  число падений тестов Оператор измерял сам отдельными прогонами по 22 мин.

Требуется:
1. Пульт сохраняет в журнал задачи итоговую строку каждого прогона pytest
   внутри шага роли (строка вида «N failed, M passed …» или «N passed …»
   из результата инструмента) отдельным действием журнала, не шире одной
   строки на прогон; для Claude и Codex одинаково. Прочие результаты
   инструментов в журнал и лог не попадают.
2. `watch --observation` показывает эти записи по умолчанию (новый класс
   событий или включение в существующий — решение SPEC).
3. Во время живого шага роли `watch` раз в `N` минут (константа
   `config`, SPEC предлагает значение 5–10) печатает одну строку сводки
   по задаче: прошло M из 45 мин, последние 2–3 вызова инструментов из
   лога шага (сжато), число изменённых файлов рабочей копии задачи.
   Без живого шага сводки нет.
4. Ранние предупреждения одной строкой: прошло 35 из 45 мин, а новых
   коммитов ветки с начала шага нет; стоимость шага — если она доступна
   в живом потоке — перешла порог (константа `config`). Каждое
   предупреждение — один раз за шаг.
5. Объём вывода ограничен: строки дозора приходят сессии Оператора
   уведомлениями, поэтому сводки редкие и короткие; SPEC фиксирует
   верхнюю границу строк в час на задачу.
6. Тесты в `tests/` с заявками «Ловит мутацию» на пп. 1–5 (запись строки
   pytest из потока Claude и Codex; сводка печатается по таймеру и не
   печатается без живого шага; предупреждение 35/45 — один раз).
   Существующие тесты `tests/test_watch.py`, `tests/test_agent_log.py` не
   ослабляются.

Зоны: orchestrator/, tests/, docs/codebase-map.md, docs/operator-session.md.

Только чтение (не менять): docs/adr/, docs/roadmap.md, docs/backlog.md,
templates/, skills/, CLAUDE.md, models.yaml, roles.yaml, scripts/guard.py,
.github/workflows/ci.yml, conftest.py, tests/test_invariants.py,
docs/invariants.md.

Не входит: сохранение сырого stream-json; сообщение о задаче без живого
цикла; изменение формата существующих строк `watch`.

Рамка: $25.

# SPEC: Перефиксация не узаконивает сдвиг ссылки документов мимо пульта

## Контекст
Роль может из своего шага сдвинуть `refs/artifacts/<id>` мимо пульта
(`git commit-tree` + `git update-ref`): ссылка живёт в общем git-хранилище,
рабочая копия кода задачи — его worktree. Задача 01M409YKM3QE5KVRGV0G94F5ZC
закрыла это только для автокоммита и чекпоинтов шага
(`orchestrator/checkpoint.py::_docs_ref_moved_past_pult`,
`_record_step_fixation`). Остальные записи пульта перефиксируют безусловно:
`orchestrator/store.py::set_state` на любом переходе FSM коммитит паспорт
поверх текущей головы (`_append_passport_line`) и записывает её в
`tasks.fixed_sha` (`record_fixation`); так же — `answer.py` (два места),
`amend.py`, `snapshot.py`, `doctor/ignored_artifacts.py`,
`checkpoint._commit_step_artifacts_to_branch`,
`checkpoint.commit_pull_checkpoint`. Сверка `fixation.check_integrity`
стоит только на старте шага (`orchestrator/runner.py`), поэтому цепочка
«роль сдвигает ссылку → шаг кончается → `advance` → `set_state`
перефиксирует подменённую голову → сверка на старте следующего шага
расхождения не видит» узаконивает подмену. Сверка кода на пине d1279b85
(`store.set_state` → `_append_passport_line` → `record_fixation` без
сравнения головы с `fixed_sha`) дыру подтверждает; воспроизведение —
красный тест AC-1.

## Требования
1. Любая запись пульта, которая перефиксирует состояние документов задачи
   — переход FSM через `store.set_state`, команды Оператора `answer`,
   `zones-extend`, `amend-tests`, снимок/закрытие задачи
   (`snapshot.py`), `doctor` (`doctor/ignored_artifacts.py`), чекпоинты
   шага (`_commit_step_artifacts_to_branch`, `commit_pull_checkpoint`) —
   до записи сверяет голову ссылки `refs/artifacts/<id>` с
   `tasks.fixed_sha`.
2. При расхождении — инцидент целостности: эскалация задачи с именованной
   причиной и записью журнала; ни перефиксации (`tasks.fixed_sha` не
   меняется), ни коммита (паспорта, автокоммита, ответа, правки планки,
   закрытия) поверх подменённой головы. Сам переход в эскалацию по
   инциденту тоже не перефиксирует подменённую голову и не коммитит
   поверх неё. Задача, уже стоящая в эскалации, получает именованный
   отказ команды без смены состояния.
3. Сверка — один узел, который зовут все места требования 1; копии
   сравнения «голова ссылки против `fixed_sha`» по местам вызова нет.
4. Законные сдвиги ссылки самим пультом (коммит паспорта, автокоммит,
   `answer`, `amend-tests`, коммит закрытия) не дают ложного инцидента:
   каждый такой коммит перефиксирует сам, как сейчас.
5. Деградация «git не ответил» — как у `fixation.check_integrity` сейчас:
   фиксации нет — сверять не с чем (поведение не меняется); фиксация есть,
   а голова ссылки не прочитана — без нового тихого пропуска: подменённая
   голова не перефиксируется, и сверка на старте следующего шага остаётся
   fail-closed.
6. Выход Оператора из инцидента сохраняется как сейчас: `approve <id>
   <sha>` с явным sha, совпадающим с живой головой, — решение Оператора,
   узаконивающее голову; `approve` без sha при расхождении отказывает
   именованным отказом с обоими sha (инвариант 25).
7. Для внешнего target сверка читает репозиторий, где живёт ссылка задачи
   (репозиторий проекта, ADR-0021 часть (б2); узел чтения
   `artifact_branch`), для задачи артели — git главной копии пульта.
8. Инвариант 25 `docs/invariants.md` — при необходимости уточнение
   «перефиксация не узаконивает сдвиг мимо пульта» приложением к PLAN.md;
   то же для `tests/test_invariants.py`, если его правка нужна.
9. Тесты — постоянные сторожа в `tests/` с заявками «Ловит мутацию».

## Критерии приёмки

AC-1. В `tests/` есть тест сценария «роль сдвигает ссылку
`refs/artifacts/<id>` мимо пульта, затем `advance`», который на коде пина
d1279b85 красный (подменённая голова оказывается в `tasks.fixed_sha`), а
на коде задачи зелёный.

AC-2. Роль сдвинула ссылку мимо пульта, затем `advance`: задача уходит в
эскалацию с именованной причиной (инцидент целостности, сдвиг ссылки
документов мимо пульта) и записью журнала; `tasks.fixed_sha` не изменён;
голова ссылки осталась подменённой головой — коммита паспорта поверх неё
нет; старт следующего шага агент не запускает.

AC-3. Тот же сдвиг, затем `answer` (и, отдельным сценарием,
`zones-extend`): ответ/правка зон в ссылку не коммитятся, `tasks.fixed_sha`
не изменён, задача остаётся/уходит в эскалацию с именованной причиной
инцидента и записью журнала.

AC-4. Тот же сдвиг, затем `amend-tests`: правка планки в ссылку не
коммитится, `tasks.fixed_sha` не изменён, инцидент с именованной причиной
и записью журнала.

AC-5. Тот же сдвиг перед коммитом закрытия (`snapshot.py`), `doctor`
(`doctor/ignored_artifacts.py`), `commit_pull_checkpoint` и
`_commit_step_artifacts_to_branch`: ни одно из этих мест не коммитит поверх
подменённой головы и не перефиксирует её; исход — инцидент с именованной
причиной и записью журнала.

AC-6. Сравнение головы ссылки с `tasks.fixed_sha` перед перефиксирующей
записью реализовано одним узлом: все места требования 1 (включая прежние
места `_docs_ref_moved_past_pult` в `checkpoint.py`) зовут его, отдельной
копии сравнения в местах вызова нет.

AC-7. Цепочка законных записей пульта без вмешательства роли — переход
FSM с коммитом паспорта, автокоммит конца шага, `answer`, `amend-tests`,
коммит закрытия, в любом порядке подряд — инцидента не даёт; после каждой
записи `tasks.fixed_sha` равен голове ссылки.

AC-8. Фиксация есть, а голова ссылки не прочитана (git не ответил):
перефиксирующая запись не записывает в `tasks.fixed_sha` непроверенную
голову, и `fixation.check_integrity` на старте следующего шага отказывает
так же, как сейчас; фиксации нет — поведение записей пульта не меняется.

AC-9. После инцидента AC-2 `tasks.fixed_sha` по-прежнему прежний;
`approve <id>` без sha отказывает именованным отказом с обоими sha;
`approve <id> <sha>` с явным sha живой головы проходит и фиксирует эту
голову.

AC-10. Сценарии AC-2 и AC-7 проходят и для задачи артели (ссылка в git
главной копии), и для задачи внешнего target (ссылка в репозитории
проекта, прочитанная узлом `artifact_branch`); для внешнего target сверка
не читает git главной копии.

AC-11. Каждый новый тест задачи в `tests/` несёт заявку «Ловит мутацию».

AC-12. Если PLAN.md меняет инвариант 25 `docs/invariants.md` или
`tests/test_invariants.py`, правка дана приложением к PLAN.md, и PLAN.md
подтверждает, что приложение проходит `git apply --check` на чистом
дереве.

## Оценка объёма и деление
Сработавшие сигналы: число критериев приёмки 12 (≥ 10); зона задевает
механизм, на который опирается запись реестра `docs/invariants.md`
(инвариант 25, хэш-фиксация документов задачи); зона `orchestrator/` —
каталог, затронуто ≥ 5 модулей (`store.py`, `answer.py`, `amend.py`,
`snapshot.py`, `checkpoint.py`, `doctor/ignored_artifacts.py`,
`fixation.py`/`artifact_branch.py`).

Материал для решения Оператора — обоснование монолита: ТЗ требует сверку
одним узлом (требование 3), и смысл задачи — закрыть ВСЕ пути
узаконивания. Нарезка «узел + `set_state`» / «команды Оператора» /
«снимок, `doctor`, чекпоинты» оставляет после первой части ту же дыру
через `answer`/`amend-tests`/закрытие (инвариант 25 формально остаётся
нарушенным), а части 2–3 без узла первой части мержить нечего — каждая
состояла бы из одной-двух строк вызова и тестов. Альтернатива для
Оператора — нарезка на две: (1) узел + `set_state` + выход через
`approve <sha>` + сторожа AC-1/AC-2/AC-7..AC-10; (2) остальные места
(AC-3..AC-6). Обе части не режут зону поперёк (`orchestrator/`, `tests/`).

Бюджет: калибровка по классу (12 критериев) даёт ~$45; `budget_usd`
выставлен по рамке ТЗ ($35). Задача точечная по механике (один узел и
его вызовы), но в зоне 7+ модулей — риск подъёма потолка при второй
итерации ревью; решение — за Оператором на гейте SPEC.

## Не входит
- Изоляция файловой системы ролей — запрет записи в git-хранилище пульта
  на уровне прав (отдельная строка бэклога).
- ADR-0021 часть (в) и этапы 2–4.
- Переименование гейта неослабления тестов (строка бэклога 03.10).
- Правка путей только для чтения: `docs/adr/`, `docs/roadmap.md`,
  `docs/backlog.md`, `docs/operator-session.md`, `templates/`,
  `targets.yaml`, `models.yaml`, `roles.yaml`, `CLAUDE.md`,
  `.github/workflows/ci.yml`, `scripts/guard.py`, `skills/`;
  `docs/invariants.md` и `tests/test_invariants.py` — только приложением к
  PLAN.md.
- Неослабление существующих тестов, зелёный полный набор `tests/` и CI
  ветки — её держит пульт.

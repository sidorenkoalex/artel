# ТЗ: Перефиксация не узаконивает сдвиг ссылки документов мимо пульта

Источник: строка бэклога П1 от 03.10.2026 «Сверка фиксации пропускает
подмену ссылки документов ролью» (находка автора тестов задачи
01M409YKM3QE5KVRGV0G94F5ZC); ADR-0021 п.3 и п.7; инвариант 25
`docs/invariants.md`; решение Оператора 03.10.2026 «готовь ТЗ».

Факты (пин d1279b85 — после мержа ADR-0021, этап 1 (б1) и (б2); сверка кода 03.10):
- Роль может из своего шага сдвинуть `refs/artifacts/<id>` мимо пульта
  (`git commit-tree` + `git update-ref`): ссылка живёт в общем
  git-хранилище главной копии, рабочая копия кода задачи — его worktree.
- Задача 01M409YKM3QE5KVRGV0G94F5ZC (ADR-0021, этап 1 (б1)) закрыла это
  для автокоммита и чекпоинтов шага: `checkpoint._docs_ref_moved_past_pult`
  сверяет голову ссылки с `tasks.fixed_sha`, `_record_step_fixation` при
  расхождении фиксацию не обновляет, автокоммит конца шага и перенос
  документов из рабочей копии на старте шага не выполняются (журнал
  «ссылка документов сдвинута мимо пульта»). Тот же узел уже стоит на
  чекпоинте test_author (`_test_author_checkpoint`, вызов
  `_record_step_fixation`). Приёмочный тест AC-10 той задачи проверяет
  сценарий «шаг роли — сразу следующий шаг».
- Перефиксация вне этого узла безусловна: `store.set_state` на ЛЮБОМ
  переходе FSM сначала коммитит строку паспорта в ссылку
  (`_append_passport_line` поверх текущей головы), затем
  `record_fixation` записывает в `fixed_sha` текущую голову. Так же
  безусловно перефиксируют `answer.py` (два места), `amend.py`,
  `snapshot.py`, `doctor/ignored_artifacts.py`,
  `checkpoint._commit_step_artifacts_to_branch` (после коммита),
  `checkpoint.commit_pull_checkpoint`.
- Сверка `fixation.check_integrity` стоит только на старте шага
  (`runner.py`). В штатном цикле между шагами роли всегда есть переход
  (`advance` после шага). Предполагаемая дыра: роль сдвигает ссылку →
  шаг кончается (фиксация не обновлена) → `advance` → `set_state`
  перефиксирует подменённую голову (с паспортом поверх) → сверка на
  старте следующего шага расхождения не видит. Та же дыра — через любую
  команду Оператора из перечня выше, выполненную после такого шага.
- Если сверка по коду неверна и дыры нет — SPEC это показывает
  воспроизведением, и задача сводится к сторожам.

Требуется:
1. Любая запись пульта, которая перефиксирует состояние документов
   задачи (переход FSM через `set_state`, команды Оператора `answer`,
   `zones-extend`, `amend-tests`, снимок/закрытие, `doctor`, чекпоинты
   шага), до записи сверяет голову ссылки с `tasks.fixed_sha`. При
   расхождении — инцидент целостности (эскалация задачи с именованной
   причиной и записью журнала), а не перефиксация и не коммит поверх
   подменённой головы. Сверка — одним узлом, не копией в каждом месте.
2. Законные сдвиги ссылки самим пультом (коммит паспорта, автокоммит,
   answer, amend, коммит закрытия) не дают ложного инцидента: каждый
   такой коммит перефиксирует сам, как сейчас.
3. Деградация «git не ответил» — как у `fixation.check_integrity`
   сейчас (fail-closed на старте шага), без нового тихого пропуска.
4. Для внешнего target сверка читает репозиторий, где живёт ссылка
   задачи (с части (б2) ADR-0021 — репозиторий проекта; узел чтения
   `artifact_branch`).
5. Инвариант 25 — при необходимости уточнение «перефиксация не
   узаконивает сдвиг мимо пульта» приложением к PLAN, проверенное
   `git apply --check`.
6. Тесты (`tests/`, постоянные сторожа с заявками «Ловит мутацию»):
   сдвиг ссылки ролью, затем переход FSM (`advance`) — инцидент, не
   перефиксация; то же через `answer` и `amend-tests`; законные коммиты
   пульта (паспорт, автокоммит, answer) инцидента не дают; задача
   артели и внешний target. Сначала — красный тест, воспроизводящий
   дыру на текущем коде. Существующие тесты не ослабляются.

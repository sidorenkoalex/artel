# ANSWER-1: ответ Оператора

## Ответы

Ответ на эскалацию test_author (AC-1, AC-3, AC-12) — уточнения SPEC,
обязательные для планки и реализации.

AC-1 — имена констант порогов в orchestrator/config.py:
SPLIT_SIGNAL_ZONE_FILES = 5 (число модулей/файлов зон),
SPLIT_SIGNAL_AC_COUNT = 10 (число критериев приёмки),
SPLIT_SIGNAL_BUDGET_USD = 30 (рамка бюджета),
SPLIT_SIGNAL_DIFF_FORECAST_RATIO = 0.5 (доля от
REVIEW_SNAPSHOT_DIFF_MAX_BYTES, с которой прогноз диффа считается
сигналом). Прогноз диффа — поле frontmatter SPEC `diff_forecast_kib`
(целое, КиБ); отсутствие поля при любом другом сработавшем сигнале —
само по себе сигнал «прогноз не дан».

AC-3 — правило вычисления сигнала «затронут инвариантный механизм»:
сигнал срабатывает, если хотя бы одна строка пути вида
`orchestrator/<имя>.py` или `scripts/<имя>.py`, встречающаяся в
разделе «Зоны» SPEC (либо во frontmatter-поле зон, если оно есть),
встречается как подстрока в тексте docs/invariants.md. Сравнение
буквальное, без разбора смысла; инварианты, в тексте которых путей
нет, в сигнале не участвуют.

AC-12 — размер диффа для отчёта: новая колонка `diff_bytes` в таблице
`tasks` (схема store.py), заполняется при входе задачи на merge_gate
значением размера диффа, которое уже считается для гейта ёмкости
ревью-пакета; `artel report` читает колонку без вызова git (контракт
T092 сохраняется); для задач, закрытых до появления колонки, отчёт
показывает прочерк.

Остальные критерии без изменений.

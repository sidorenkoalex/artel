# SPEC: Ревью-пакет задачи внешнего проекта: конвенции проекта, без карты пульта

## Контекст
Задача 01M5634E094QF7JX8HD3KSG4KN (смержена 18.10) положила в брифы ролей
задачи внешнего проекта конвенции проекта (`CLAUDE.md`, `AGENTS.md` корня
базовой ветки клона) вместо карты пульта, но ревьювер остался вне её зон:
пакет ревьювера собирает `orchestrator/review.py::review_package`
(`review.py:721`, сборка частей `:870-1002`). Сегодня в пакете ревьювера
задачи внешнего проекта конвенций проекта нет, а абзац об исключениях из
diff (`review.py:965-975`) кроме исключения `tasks/<id>/` называет
`docs/codebase-map.md` пульта, джоб CI «Карта кодовой базы генерируется и
свежа» и команду `python3 scripts/codebase_map.py` — у внешнего проекта
(sled) их нет.

## Требования
1. Ревью-пакет задачи внешнего проекта несёт конвенции проекта (`CLAUDE.md`,
   `AGENTS.md` корня базовой ветки клона проекта) тем же источником, что брифы
   ролей после 01M5634E094QF7JX8HD3KSG4KN, — функцией
   `orchestrator/brief.py` (`_project_conventions_parts` /
   `_read_project_conventions`), без дублирования чтения в `review.py`; с теми
   же пометками: «файла нет» (`brief.PROJECT_CONVENTIONS_ABSENT_MARK`) на
   месте отсутствующего файла и «конвенции проекта не прочитаны: <причина>»
   (`brief.PROJECT_CONVENTIONS_UNREAD_MARK`) на месте нечитаемого файла или
   вместо всех, если не прочитана базовая ветка.
2. Компонент конвенций проекта в пакете оформлен как остальные компоненты
   пакета (`review.artifact_part`, `review.py:170-202`): заголовок с путём
   файла, размером в байтах и sha256 текста; тело — внутри пары граничных
   маркеров `brief.wrap_boundary` с общим `run_id` этого пакета.
3. Место компонентов конвенций в порядке частей пакета SPEC не задаёт:
   разработчик называет его в PLAN.
4. У задачи внешнего проекта из абзаца пакета об исключениях из diff
   (`review.py:965-975`) убирается только часть о карте пульта: джоб CI
   «Карта кодовой базы генерируется и свежа» и команда регенерации
   `python3 scripts/codebase_map.py`. Фраза об исключении артефактов
   `tasks/<id>/` из стат-списка и diff сохраняется. Остаётся короткое
   упоминание, что `docs/codebase-map.md` исключён из diff (исключение
   действует для любого проекта — `snapshot_exclude`, `review.py:298`), без
   команды и джоба пульта. Признак проекта — тот же, что у брифа
   (`repo_context.is_artel` / `brief.is_artel_task`).
5. У задачи артели пакет ревьювера не меняется ни на байт. Это фиксируется
   тестом до правки: эталон пакета артели — литерал в тесте (не результат
   вызова `review_package` в том же прогоне); коммит, вносящий этот тест, в
   истории ветки задачи стоит отдельно и раньше первого коммита, меняющего
   `orchestrator/review.py`. Ревьювер сверяет этот порядок по истории ветки.
6. Тесты детерминированы и без сети: учебный внешний проект — песочничный
   git-клон с базовой веткой.

## Критерии приёмки
AC-1. Пакет ревьювера задачи учебного внешнего проекта, в базовой ветке клона
которого есть `CLAUDE.md` и `AGENTS.md`, содержит текст обоих файлов.

AC-2. В пакете ревьювера задачи учебного внешнего проекта текст `CLAUDE.md`
стоит между парой граничных маркеров `brief.wrap_boundary` с `run_id` этого
пакета, а заголовок компонента снаружи маркеров несёт путь `CLAUDE.md`, его
размер в байтах и sha256 его текста.

AC-3. Пакет ревьювера задачи учебного внешнего проекта, в базовой ветке клона
которого нет `CLAUDE.md`, содержит пометку `файла нет` для `CLAUDE.md`
(текст пометки — `brief.PROJECT_CONVENTIONS_ABSENT_MARK`, как в брифе роли).

AC-4. Пакет ревьювера задачи учебного внешнего проекта, базовую ветку которого
прочитать нельзя, содержит пометку `конвенции проекта не прочитаны` с
причиной (текст — `brief.PROJECT_CONVENTIONS_UNREAD_MARK`), и сборка пакета
при этом не падает.

AC-5. Пакет ревьювера задачи учебного внешнего проекта, `CLAUDE.md` базовой
ветки которого не читается как UTF-8, содержит пометку `конвенции проекта не
прочитаны` с причиной, называющей `CLAUDE.md`, и сборка пакета при этом не
падает.

AC-6. Пакет ревьювера задачи учебного внешнего проекта называет исключение
артефактов `tasks/<id>/` этой задачи из стат-списка и diff и исключение
`docs/codebase-map.md` из diff и не содержит строк `scripts/codebase_map.py`
и `Карта кодовой базы генерируется и свежа`.

AC-7. Пакет ревьювера задачи артели на фиксированном входе (одинаковые
SPEC/PLAN/форма вердикта/ветка/diff и тот же идентификатор запуска) побайтно
совпадает с эталоном — литералом в тесте, снятым с кода до правки: в нём
по-прежнему есть абзац об исключении `docs/codebase-map.md` с джобом CI и
командой `python3 scripts/codebase_map.py` и нет компонентов конвенций
проекта.

AC-8. Тесты AC-1–AC-7 не обращаются к сети: учебный внешний проект — локальный
git-репозиторий песочницы.

## Оценка объёма и деление
Сработавший сигнал — «число затрагиваемых модулей/файлов»: guard считает все
упомянутые в тексте `orchestrator/*.py`/`scripts/*.py`, а большинство из них
здесь — пути только для чтения из ТЗ (`brief.py`, `repo_context.py`,
`role_prompt.py`, `codebase_map.py`). Правится один модуль —
`orchestrator/review.py` (развилка артель/внешний проект в `review_package`) —
плюс тесты в `tests/`.

Прогноз диффа: 14 КиБ

Обоснование монолита: правка — одна развилка в одной функции и её тесты;
требование 5 («у артели пакет не меняется») и требования 1-4 проверяются на
одном и том же месте сборки пакета, резать нечего — часть без развилки не
даёт наблюдаемого изменения, часть без тестов не мержима по ТЗ (требование
5 требует фиксацию тестом до правки).

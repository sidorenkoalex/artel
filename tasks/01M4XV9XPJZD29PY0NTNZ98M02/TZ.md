# Lease: идентичность хоста при совпадении сессии и PID

## Факты
Копилка13.10 отметила ветку acquire своейsession_id с same_host_ok, которая не сверяет hostname; чужаяsession ветка сверяет. При уточнении14.10 найден существующий явный тест OwnSessionLiveHolderTest::test_holder_on_different_host_with_same_host_ok_returns_none_false_without_mutation в tests/test_lease.py:285: он намеренно допускает (None,False) без изменения строки для той же сессии на другом host при same_host_ok (budget). Поэтому считать этот конкретный исход новым непокрытым багом нельзя без сверки прежнего решения.
Отдельная ветка row.session_id==session_id и row.pid==os.getpid() вызывает update_lease без сверкиhostname: PID локален хосту, совпадение номера на другом хосте не доказывает тот же процесс и может переписать чужую строку. Докстринг и разрешение same_host_ok требуют инвентаризации реальных контрактов, а не общего утверждения «все чужие хосты всегда отказываются».

Требуется:
1. Воспроизвести недопустимое продление/захват lease при одинаковых session_id и PID, но разных hostname, в отдельной БД без настоящих процессов на втором хосте. Строка другого хоста не переписывается по совпадению локального номераPID. Обычный вызов безforce не разрешает запись только на основании session_id.
2. Аналитик сверяет все ветки acquire и вызыватели same_host_ok/force с прежними SPEC/ANSWER/тестами; фиксирует точную границу операционных разрешений. Отдельно разобрать уже проверяемый same_host_ok другойhost безмутации. При конфликте требования с зафиксированным поведением вынести вопрос доSPEC; не менять такой тест/мандат молча.
3. Сохранить продление своего реального процесса на том жеhostname, same_host_ok для разрешённых сценариев своегохоста безмутации, перехват реально мёртвого local PID, TTL и force для штатного kill. Не определять живость remote PID локальным os.kill. Не вводить обход блокировки, не ослаблять ограничения или forceвсем вызовам.
4. Сохранить атомарность BEGIN IMMEDIATE, событияжурнала, commit/rollback, устойчивость гонки захвата. Тесты проверяют отсутствие изменения всейстроки remotelease, коллизииsame/differentPID, same/differentSession, флагиsame_host_ok/force по согласованным контрактам; действующие тесты всех иныхветок продолжают держать их свойства.
5. SPEC содержит полную пятиколоночную матрицу неослабления и точные ожидаемые исходы/изменяемое поведение. Исправление ловит регрессию remotehostname и не ломает бюджетный или killмаршрут. Любая смена вида/удаление/смягчение старого assertion без отдельного мандата запрещена.

Зоны: orchestrator/lease.py, tests/test_lease.py и относящиеся новые tests/. Иныевызыватели только чтение, если нужнаяправка выходитза этизоны — эскалацияпередSPEC. Не входит: распределённый coordinatorlease, новыхосты/инфраструктура, изменение бюджетнойполитики, прочие строки копилки.

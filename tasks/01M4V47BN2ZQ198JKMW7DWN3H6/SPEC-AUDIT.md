# SPEC-AUDIT: Чужие записки не выкладываются проверяющим ролям

## ТЗ и SPEC
ANSWER-n.md у задачи нет: в ссылке `refs/artifacts/01M4V47BN2ZQ198JKMW7DWN3H6` лежат
только TZ.md, SPEC.md, PASSPORT.md и записка аналитика (`git ls-tree`).
Решений Оператора на гейте SPEC в брифе тоже нет.

- Требования 1–4 ТЗ (TZ.md:22-25) переходят в требования 1–4 SPEC
  (SPEC.md:24-38) почти дословно. Лишних требований в SPEC нет.
- **Потеряно (A1).** ТЗ поручает аналитику «точное соответствие имён записок
  ролям по действующему коду» (TZ.md:22). SPEC сказал только «все чужие
  `NOTE-*.md`» (SPEC.md:24-27, 42-48) и не назвал источник. В коде записка
  определяется точным перечнем имён, а не маской:
  `guard.STEP_NOTE_ROLES`/`STEP_NOTE_NAMES`/`is_step_note` (scripts/guard.py:1907-1924),
  комментарий «не маска `NOTE-.*`» (scripts/guard.py:2025-2027). В итоге
  неясны два места. Первое: фильтр работает по перечню или по маске. Второе:
  считать ли запиской `NOTE-*.md` в подкаталоге (например `acceptance_tests/`)
  — по `is_step_note` это не записка.
- **Потеряно (A2).** Из абзаца ТЗ «Меняемое поведение» (TZ.md:31) в SPEC не
  перешло условие: «если реализация требует изменения … существующих
  залоченных тестов — эскалация с матрицей неослабления». Это важно, потому
  что сигнатура `runner.role_cwd(conn, task_id, target)` (runner.py:1089)
  закреплена существующими тестами: позиционный вызов с тремя аргументами в
  tests/test_docs_dir_layout.py:71,95,121,141,167,204,226,247,
  tests/test_step_autocommit.py:200, tests/test_multitarget.py:459 и
  других, `mock.patch.object(artifact_branch, "materialize_task_dir")` в
  tests/test_docs_dir_layout.py:119. Кроме того, doctor вызывает
  `role_cwd(None, None, target)` (orchestrator/doctor/isolation.py:102).
  SPEC не требует обратно-совместимой передачи роли (необязательный параметр).
- **Расхождение рамки (A3).** В ТЗ «Рамка: $15» (TZ.md:14), в SPEC
  `budget_usd: 25` (SPEC.md:9). Ответа Оператора, поднимающего рамку, нет.
  Значение соответствует калибровке скила spec-authoring («до 5 критериев и
  до 3 файлов зоны — ~25»), так что это решение для Оператора, а не ошибка.

## Факты против кода
SPEC почти не делает утверждений о коде: нет имён функций и мест.
Подразумеваемые факты сверены с рабочим каталогом.

- «Общая материализация каталога» есть: `artifact_branch.materialize_task_dir`
  (orchestrator/artifact_branch.py:604-654) делает диск зеркалом головы ссылки,
  без учёта роли. Вызывает её только `runner.role_cwd`
  (orchestrator/runner.py:1156-1157). Подтверждено.
- «Запасной путь после сбоя чтения ссылки» есть: `materialized_sha == ""`, тогда
  `_place_harvested_docs` (runner.py:1160-1161, 1165-1173). При сбое
  материализации диск каталога документов не трогается вовсе
  (artifact_branch.py:614-615, 628-634). Значит, остатки прошлого шага там
  остаются. Сам набор `harvested` записок не несёт: на старте шага
  `_filter_step_notes` с `role=None` отбрасывает любую
  (checkpoint.py:146-147, 1234-1237; тест
  tests/test_01m4rzbpg6exm74mtbptegw2d4_note_autocommit.py:456-484).
  Подтверждено.
- Роль шага в момент выкладки известна вызывающему: `cwd = role_cwd(...)`
  стоит в функции, где `role` уже в области видимости (runner.py:1466). Самому
  `role_cwd` роль не передаётся (runner.py:1089). Подтверждено, что требуется
  передача роли.
- «Не превращается при автокоммите в удаление»: в действующем коде отсутствие
  записки на диске уже не даёт удаления. Кандидат на удаление должен нести
  frontmatter `type` из `_DELETABLE_ARTIFACT_TYPES = {"questions"}`
  (checkpoint.py:184, 1135-1143), а у записок frontmatter нет. Требование 3
  SPEC защищает существующее свойство от регрессии. Подтверждено.
- Бриф чужих записок проверяющим уже не даёт:
  `STEP_NOTE_FOREIGN_AUTHORS["spec_auditor"] == ()` и `["reviewer"] == ()`
  (orchestrator/brief.py:119-125). То, что «Не входит» не меняет брифы, с
  кодом согласовано.
- Проблема наблюдается вживую: в каталоге документов этого шага аудитора
  лежит `NOTE-analyst.md` (проверено `test -f`, файл не читался).

## Проверяемость критериев

| Критерий | Проверяем | Ловимая мутация |
|---|---|---|
| AC-1 | да, с оговоркой (В1) | фильтр не применяется для `spec_auditor` (выкладка — полное зеркало) → `NOTE-analyst.md` на диске; фильтр снимает все записки, включая свою → нет `NOTE-spec_auditor.md` |
| AC-2 | да, с оговоркой (В1) | то же для `reviewer`: `NOTE-developer.md` выложен; своя `NOTE-reviewer.md` удалена |
| AC-3 | частично (В2) | очистка остатков только в `materialize_task_dir`, а ветка `materialized_sha == ""` (runner.py:1160) остатки не трогает → предзасеянная `NOTE-analyst.md` переживает сбой выкладки. Ветка «подтвердить нельзя» не определена — тест на неё не построить однозначно |
| AC-4 | да | фильтр удаляет записку через `commit_files(remove=…)` либо расширяет `_step_artifact_deletion_candidates` → записки нет в ссылке после автокоммита шага `reviewer`; фильтр задевает `SPEC.md`/`TZ.md`/`ANSWER-n.md`/`SPEC-AUDIT.md` → их нет на диске; фильтр включён для всех ролей → у `developer` нет `NOTE-analyst.md` |
| AC-5 | да (мета-критерий, сводит AC-1…AC-4) | возврат `materialize_task_dir` к полному зеркалу; удаление записки из источника |

- **В1.** AC-1/AC-2 говорят «при подготовке документов», но не привязаны к
  реальному пути шага. Тест может проверить отдельный помощник фильтра
  (или `materialize_task_dir(..., role=...)`) и пройти, хотя вызов на
  runner.py:1466 роль не передаёт. Тогда в настоящем шаге фильтр не
  включится. Нужна привязка: проверка через `runner.role_cwd` с ролью,
  переданной тем путём, которым её передаёт запуск шага
  (`run_agent_once`/`_spawn_and_wait`), либо явная мутация «запуск шага не
  передаёт роль».
- **В2.** «Если безопасную выкладку подтвердить нельзя, не запускать
  проверяющую роль с чужими записками» (SPEC.md:29-31, 52-53) не
  конкретизировано. Не сказано, что такое «нельзя подтвердить» (сбой
  `unlink`? каталог не читается? сбой чтения ссылки при остатках?) и чем
  кончается шаг. Готовый механизм для этого есть — `OSError` из `role_cwd`
  ведёт к «agent run SKIPPED / рабочий каталог роли не подготовлен»
  (runner.py:1465-1473), — но SPEC его не называет. Тестировщик и
  разработчик могут выбрать разные исходы.

## Пути обхода гейтов
- **О1. Ссылка документов читается мимо выкладки.** `refs/artifacts/<id>`
  живёт в том же репозитории, что и рабочая копия роли. Проверено:
  `git -C <worktree> ls-tree --name-only refs/artifacts/01M4V47BN2ZQ198JKMW7DWN3H6`
  выдаёт `NOTE-analyst.md`. Значит, `git show refs/artifacts/<id>:tasks/<id>/NOTE-analyst.md`
  из рабочего каталога и команда пульта `artel.py docs <id> NOTE-analyst.md`
  (orchestrator/docs_fetch.py) отдают чужую записку проверяющему. ТЗ
  требует, чтобы независимость держалась «составом доступной выкладки, а не
  только инструкцией» (TZ.md:19). Буквально выполненный SPEC убирает файл с
  диска, но канал git остаётся, и держит его снова только инструкция.
  «Не входит» в ТЗ исключает «полную изоляцию от всех журналов и
  черновиков», но про ссылку документов SPEC молчит. Оператору нужно решить:
  либо явно вписать этот канал в «Не входит» как принятый остаточный риск,
  либо расширить объём.
- **О2. Фильтр без проводки роли** (см. В1): фильтр реализован и
  протестирован как функция, а запуск шага роль не передаёт — AC-1/AC-2
  формально зелёные, поведение шага прежнее.
- **О3. Фильтр по маске против перечня** (см. A1). Если фильтр сделать по
  перечню `STEP_NOTE_NAMES`, а тест проверять маской (или наоборот), то
  записка с непредусмотренным именем либо проходит, либо ложно краснит.
  Практический риск мал: guard и автокоммит не пускают `NOTE-<не роль>.md`
  в ссылку (scripts/guard.py:2025-2032).

## Вердикт
**concerns.** SPEC в целом соответствует ТЗ и проверяем. Отклонения не
мешают вести задачу, но требуют решения Оператора на гейте:

1. A1 — соответствие имён записок ролям не задано по коду, хотя ТЗ это
   поручало (SPEC.md:24-27 против TZ.md:22; код — scripts/guard.py:1907-1924,
   2025-2027).
2. A2 — потеряно условие эскалации при правке залоченных тестов (TZ.md:31).
   Не требуется обратная совместимость сигнатуры `runner.role_cwd`
   (runner.py:1089; tests/test_docs_dir_layout.py:71-247,
   tests/test_step_autocommit.py:200, orchestrator/doctor/isolation.py:102).
3. A3 — `budget_usd: 25` (SPEC.md:9) выше «Рамка: $15» (TZ.md:14) без ANSWER.
4. В1/О2 — AC-1/AC-2 (SPEC.md:42-48) не привязаны к реальному пути запуска
   шага (runner.py:1466), поэтому возможен зелёный тест при непроведённой
   роли.
5. В2 — исход «безопасную выкладку подтвердить нельзя» (SPEC.md:29-31,
   52-53) не конкретизирован. Готовый механизм отказа — runner.py:1465-1473.
6. О1 — ссылка документов читается из рабочей копии роли через git и
   `artel.py docs`, мимо выкладки. Без явной записи в «Не входит»
   (SPEC.md:65-70) независимость держится той же инструкцией, от которой ТЗ
   уходит (TZ.md:19).

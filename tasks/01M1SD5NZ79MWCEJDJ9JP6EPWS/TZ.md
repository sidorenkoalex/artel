# ТЗ: R6 — `store.py`: схема и миграции отдельно, запросы по областям

Источник: роадмап §3, фаза R, пункт R6. `orchestrator/store.py` — 1019
строк, 55 функций: создание схемы и `migrate` (130 строк) вместе с
запросами по задачам, журналу, lease, алертам, канарейке, зонам; каждая
новая колонка правит один и тот же файл, конфликты подтяжки в нём —
регулярные.

Правила фазы R: поведение не меняется; смоук байт-в-байт; тесты без
правки утверждений; защиты и инварианты не трогаются.

Требуется:
1. Схема и миграции — в новом модуле `orchestrator/schema.py`: `SCHEMA`
   (DDL), `migrate(conn)` и вспомогательные `add_column`/проверки
   версии; `store.py` импортирует их, публичные имена `store.create_schema`,
   `store.migrate` сохраняются как реэкспорт (обратная совместимость
   вызовов и тестов).
2. Запросы `store.py` сгруппированы по областям внутри файла с
   заголовками-разделителями (задачи и переходы; журнал `steps`; lease;
   алерты; канарейка; зоны и очередь) — без смены сигнатур; функции,
   используемые только одним модулем-потребителем (проверить grep по
   `orchestrator/`), переезжают к потребителю только если их ≤ 3 и это не
   ломает тестовые подмены `mock.patch.object(store, ...)`.
3. Смоук байт-в-байт: `python3 orchestrator/artel.py status` и
   `artel report` на копии живой БД пульта в песочнице дают тот же
   вывод до и после; `sqlite3 .schema` новой пустой БД идентична прежней
   (тест сравнивает DDL).
4. Существующие тесты `tests/test_store*.py`, миграций и все тесты,
   подменяющие `store.*`, зелёные без правки утверждений.

Зоны: orchestrator/store.py, orchestrator/schema.py (новый), tests/.
Свободны. Не входит: новые колонки, смена формата журнала, изменение
миграций по существу.

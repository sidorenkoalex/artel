# SPEC: Долгоживущие тесты внешнего проекта: правило импортов по профилю

## Контекст
Правило импортов долгоживущих файлов (`scripts/guard.py:2604-2614`:
`_allowed_import_tops` = стандартная библиотека + `orchestrator`, `scripts`,
`tests` + `stack.THIRD_PARTY_EXCEPTIONS`; применение `:2709-2730`) — правило
артели, но действует и у внешнего проекта. У sled (`workdir: backend`, код в
`backend/src`) импорт `from src…`, `fastapi`, `httpx`, `sqlalchemy`,
`pydantic` в долгоживущем файле — «импорт вне перечня»: отказ на выходе из
`tests_writing` (`orchestrator/advance_gates/tests_writing.py:351, 470`), в
`preflight` (`orchestrator/preflight.py:186, 203`), в `amend-tests`
(`orchestrator/amend.py:512`). Долгоживущий тест внешнего проекта,
импортирующий код проекта, завести нельзя. Текст отказа (`guard.py:2597-2598`)
говорит про «помощники из tests/sandbox.py» — то есть про артель.

Источник перечня (решение Оператора, ANSWER-1, вопрос 1, вариант A): новое
необязательное подполе профиля `test_profile.long_lived_imports` — список
верхних имён импорта. Обоснование: имена дистрибутивов зависимостей часто не
совпадают с именами импорта (`pyjwt` → `jwt`, `python-dotenv` → `dotenv`), а
вывод перечня из `pyproject.toml`/lock-файла прибивает правило к менеджеру
пакетов и делает исход рубежа зависимым от файла ветки задачи; явный перечень
в декларации пульта таких расхождений не имеет. Зоны расширены Оператором на
`orchestrator/targets.py` и `orchestrator/project_profile.py` (ANSWER-1).

Применимость остальных признаков статического разбора к внешнему проекту
(ТЗ, п.2), сверено по `scripts/guard.py:2581-2589, 2691-2806`:
- «tasks/», «номер задачи», «git-вызов», «sys.path», «patch закрытого»,
  «закрытый атрибут» — от пакетов артели не зависят, у внешнего проекта
  применимы как есть, правок не требуют;
- «git-модуль» (`_GIT_MODULES` — `orchestrator.gitcmd`,
  `orchestrator.artifact_branch`) — про модули пульта, у внешнего проекта
  срабатывает только на импорт этих модулей пульта; правок не требует;
- «закрытое имя» (`_CODE_PACKAGES = ("orchestrator", "scripts")`) — у внешнего
  проекта на пакеты кода проекта не действует; по решению Оператора (ANSWER-1,
  вопрос 3, вариант B) в этой задаче не меняется.

## Требования

1. Профиль тестов проекта (`test_profile` записи `targets.yaml`) принимает
   новое необязательное подполе `long_lived_imports` — список верхних имён
   импорта (строки). Проверка записи проекта отказывает подполю неверного вида
   (не список, или элемент списка не строка-имя); запись без подполя проходит
   проверку с прежним исходом. Разобранный профиль (`project_profile.Profile`)
   несёт значение подполя; без подполя значение пусто.
2. У задачи внешнего проекта, в профиле которого задано `long_lived_imports`,
   проверка импортов долгоживущих файлов разрешает верхние имена этого
   перечня сверх прежнего разрешённого набора. Импорт, верхнее имя которого
   не входит ни в прежний набор, ни в перечень проекта, — по-прежнему признак
   «импорт вне перечня»; текст отказа называет перечень проекта (подполе
   `long_lived_imports` и его значение).
3. Требование 2 действует одинаково на всех трёх рубежах: выход из
   `tests_writing` (оба места, `tests_writing.py:351, 470`), `preflight`
   (`preflight.py:186, 203`), `amend-tests` (`amend.py:512`).
4. У внешнего проекта, в профиле которого подполя `long_lived_imports` нет,
   набор разрешённых имён прежний (ANSWER-1, вопрос 2, вариант A); текст
   отказа «импорт вне перечня» у такого проекта дополнительно называет
   подполе `test_profile.long_lived_imports`, которое надо заполнить.
5. У артели правило импортов долгоживущих файлов и тексты отказов не
   меняются; это фиксируется тестами до правки.
6. Тесты детерминированы, без сети, на учебном внешнем проекте.

## Критерии приёмки

AC-1. У артели долгоживущий файл с импортом вне прежнего перечня (например,
`import fastapi`) получает на выходе из `tests_writing`, в `preflight` и в
`amend-tests` отказ «импорт вне перечня» с тем же текстом, что до правки; файл
с импортами только из стандартной библиотеки, `orchestrator`, `scripts`,
`tests` проходит все три рубежа, как до правки.

AC-2. У учебного внешнего проекта с `test_profile.long_lived_imports`,
содержащим `src` и имя зависимости проекта, долгоживущий файл с
`from src.app import x` и импортом этой зависимости не получает признака
«импорт вне перечня» на выходе из `tests_writing`.

AC-3. Тот же файл, что в AC-2, не получает признака «импорт вне перечня» в
`preflight`.

AC-4. Тот же файл, что в AC-2, не получает признака «импорт вне перечня» в
`amend-tests`.

AC-5. У того же учебного внешнего проекта долгоживущий файл с импортом,
верхнее имя которого не входит ни в прежний разрешённый набор, ни в
`long_lived_imports`, получает отказ «импорт вне перечня» на всех трёх
рубежах; текст отказа называет подполе `long_lived_imports` и его значение.

AC-6. У учебного внешнего проекта без подполя `long_lived_imports` импорт
`from src.app import x` в долгоживущем файле получает отказ «импорт вне
перечня» (прежний набор разрешённых имён); текст отказа называет подполе
`test_profile.long_lived_imports`, которое надо заполнить.

AC-7. Проверка записи проекта отказывает записи, у которой
`test_profile.long_lived_imports` неверного вида (не список; элемент списка не
строка); запись без подполя проходит проверку с прежним исходом.

AC-8. Профиль, разобранный из записи с `long_lived_imports`, несёт значение
подполя; профиль из записи без подполя несёт пустое значение, остальные поля
профиля — прежние.

## Оценка объёма и деление

Сработавшие сигналы: число файлов зоны ≥ 5 (шесть файлов + `tests/`);
`budget_usd` ≥ $30.

Материал для решения о монолите: подполе профиля (требование 1,
`targets.py`/`project_profile.py`) и его потребитель — правило импортов на
трёх рубежах (требования 2–4, `guard.py`, `tests_writing.py`,
`preflight.py`, `amend.py`) — одна механика. Часть «только подполе» объявляла
бы поле профиля, которое пульт не читает (запись с ним проходит проверку, но
поведение рубежей не меняется — декларация без действия); часть «только
рубежи» без поля не имеет источника перечня. Деление по рубежам режет одно
правило поперёк: рубежи разошлись бы в исходе на один и тот же файл. Объём
правки малый (новое подполе с проверкой вида, параметр перечня в
`long_lived_sign_hits`/`long_lived_errors_from_files`, передача профиля в трёх
местах вызова, текст пояснения признака), рамка Оператора — $30. Решение
«монолит» или нарезку утверждает Оператор на гейте SPEC.

## Не входит

- Признак «закрытое имя» у внешнего проекта (пакеты кода проекта) — не
  меняется (ANSWER-1, вопрос 3, вариант B).
- Правки остальных признаков статического разбора (см. «Контекст») — по
  сверке правок не требуют.
- Внесение значения `long_lived_imports` в запись sled в `targets.yaml` —
  защищённый путь, делает Оператор отдельно.
- Вывод перечня из `pyproject.toml`/lock-файла проекта и отключение правила
  у внешнего проекта — не выбраны (ANSWER-1, вопрос 1).
- Изъятие `orchestrator`/`scripts` из разрешённого набора у внешнего проекта
  — ТЗ требует расширить разрешённое, не сузить.
- Гейты по тестам на чужом стеке (помощники, параметризация, async) —
  отдельная строка бэклога.
- Выкладка планки внутрь `workdir` — отдельная строка бэклога.
- Каталог `tasks/` и признак «tasks/» — не меняются (упомянуты только как
  применимый признак и адрес документов задачи).
- Полный зелёный набор `tests/`, зелёный CI ветки, неизменность защищённых
  путей, непревышение бюджета — их держит пульт.

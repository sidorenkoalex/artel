## Контекст
Правило импортов долгоживущих файлов (`scripts/guard.py:2604-2614`:
`_allowed_import_tops` = стандартная библиотека + `orchestrator`, `scripts`,
`tests` + `stack.THIRD_PARTY_EXCEPTIONS`; применение — `_import_signs`
`:2709-2730`) — правило артели, но действует и у внешнего проекта. У sled
(`workdir: backend`, код в `backend/src`) импорт `from src…`, `fastapi`,
`httpx`, `sqlalchemy`, `pydantic` в долгоживущем файле — «импорт вне
перечня»: отказ на выходе из `tests_writing` (гейт планки
`orchestrator/advance_gates/tests_writing.py:351`, гейт кодовой ветки `:470`),
в `preflight` (`_groups` `orchestrator/preflight.py:186`, `_long_lived` `:203`),
в `amend-tests` (`orchestrator/amend.py:512`). Долгоживущий тест внешнего
проекта, импортирующий код проекта, завести нельзя. Пояснение признака
(`guard.py:2597-2598`) говорит про «помощники из tests/sandbox.py» — то есть
про артель.

Источник перечня (решение Оператора, ANSWER-1, вопрос 1, вариант A): новое
необязательное подполе профиля `test_profile.long_lived_imports` — список
верхних имён импорта. Обоснование: имена дистрибутивов зависимостей часто не
совпадают с именами импорта (`pyjwt` → `jwt`, `python-dotenv` → `dotenv`), а
вывод перечня из `pyproject.toml`/lock-файла прибивает правило к менеджеру
пакетов и делает исход рубежа зависимым от файла ветки задачи; явный перечень
в декларации пульта таких расхождений не имеет. Перечень проекта разрешается
сверх прежнего набора (стандартная библиотека, `orchestrator`, `scripts`,
`tests`, `stack.THIRD_PARTY_EXCEPTIONS`) — чтение подтверждено Оператором при
возврате с гейта SPEC 18.10, п.1. Зоны расширены Оператором на
`orchestrator/targets.py` и `orchestrator/project_profile.py` (ANSWER-1).

Признак «артель/внешний проект» на рубежах берётся внутри зон через
`repo_context.is_artel` по проекту задачи — так, как это уже делает
`amend.py:513-515` (`repo_context.is_artel(workspace.task_target(task_id))`);
`orchestrator/fsm_advance.py` (там на выходе из `tests_writing` флаг
вычисляется в `:587` и доходит до гейтов только как `network_addresses`,
`:588-593`) не правится (решение Оператора, возврат 18.10, п.5).

Применимость остальных признаков статического разбора к внешнему проекту
(ТЗ, п.2), сверено по `scripts/guard.py:2581-2589, 2691-2806`:
- «tasks/», «номер задачи», «git-вызов», «sys.path», «patch закрытого» — от
  пакетов артели не зависят, у внешнего проекта применимы как есть, правок не
  требуют;
- «закрытый атрибут» — освобождение корня цепочки идёт по стандартной
  библиотеке и пакету `tests` (`guard.py:2692-2706`, `top == "tests"`); у sled
  каталог тестов — `backend/tests` при `workdir: backend`, то есть тот же
  пакет `tests`; имена из кода проекта и зависимостей не освобождены — так же,
  как имена `orchestrator` у артели. Применим как есть, правок не требует;
- «git-модуль» (`_GIT_MODULES` — `orchestrator.gitcmd`,

- «закрытое имя» (`_CODE_PACKAGES = ("orchestrator", "scripts")`) — у внешнего

  вопрос 3, вариант B) в этой задаче не меняется.

## Требования

1. Профиль тестов проекта (`test_profile` записи `targets.yaml`) принимает
   новое необязательное подполе `long_lived_imports` — список верхних имён
   импорта. Элемент списка — непустая строка, являющаяся идентификатором
   Python (имя модуля верхнего уровня, без точек и шаблонов). Пустой список
   допустим и равнозначен отсутствию подполя. Проверка записи проекта
   отказывает подполю неверного вида: не список; элемент — не строка, пустая
   строка или строка, не являющаяся идентификатором Python (например,
   `"src.app"`, `"*"`). Запись без подполя проходит проверку с прежним
   исходом. Разобранный профиль (`project_profile.Profile`) несёт значение
   подполя; без подполя или с пустым списком значение пусто.
2. У артели подполе `long_lived_imports` не действует: проверка записи артели
   (`config.DEFAULT_TARGET`), несущей это подполе, — отказ; правило импортов
   долгоживущих файлов и тексты отказов у артели не меняются, это
   фиксируется тестами до правки.
3. У задачи внешнего проекта, в профиле которого `long_lived_imports` не пуст,
   проверка импортов долгоживущих файлов разрешает верхние имена этого перечня
   сверх прежнего разрешённого набора; верхнее имя импорта сравнивается с
   элементом перечня на точное совпадение. Импорт, верхнее имя которого не
   входит ни в прежний набор, ни в перечень проекта, — по-прежнему признак
   «импорт вне перечня»; текст отказа называет перечень проекта (подполе
   `long_lived_imports` и его значение).
4. У внешнего проекта, в профиле которого `long_lived_imports` нет или он
   пуст, набор разрешённых имён прежний (ANSWER-1, вопрос 2, вариант A);
   текст отказа «импорт вне перечня» у такого проекта дополнительно называет
   подполе `test_profile.long_lived_imports`, которое надо заполнить.
5. Требования 3 и 4 действуют одинаково на всех трёх рубежах и в обоих местах
   каждого рубежа, где они есть: выход из `tests_writing` — гейт планки
   (`tests_writing.py:351`) и гейт кодовой ветки (`tests_writing.py:470`);
   `preflight` — проверка групп планки (`preflight.py:186`) и проверка
   долгоживущих файлов кодовой ветки (`preflight.py:203`); `amend-tests`
   (`amend.py:512`).
6. Признак «артель/внешний проект» на рубежах определяется внутри зон
   задачи через `repo_context` по проекту задачи; `orchestrator/fsm_advance.py`
   не правится. Если требование без правки `fsm_advance.py` не исполнимо —
   эскалация, не правка вне зон.
7. Тесты детерминированы, без сети, на учебном внешнем проекте.

## Критерии приёмки

AC-1. У артели долгоживущий файл с импортом вне прежнего перечня (например,
`import fastapi`) получает отказ «импорт вне перечня» с тем же текстом, что
до правки: текст отказа содержит литерал «только стандартная библиотека,
orchestrator, scripts, tests — помощники из tests/sandbox.py» (ожидание в
тесте — этот литерал, не значение, вычисленное из кода пульта) и не содержит
`long_lived_imports`, — в каждом из пяти мест:
`tests_writing.py:351`, `tests_writing.py:470`, `preflight.py:186`,
`preflight.py:203`, `amend.py:512`; файл с импортами только из стандартной
библиотеки, `orchestrator`, `scripts`, `tests` проходит эти места, как до
правки. Проверка записи артели, несущей `test_profile.long_lived_imports`, —
отказ.

AC-2. У учебного внешнего проекта с `test_profile.long_lived_imports`,
содержащим `src` и имя зависимости проекта, долгоживущий файл с
`from src.app import x` и импортом этой зависимости не получает признака
«импорт вне перечня» на выходе из `tests_writing` — ни в гейте планки
(`tests_writing.py:351`), ни в гейте кодовой ветки (`tests_writing.py:470`).

AC-3. Тот же файл, что в AC-2, не получает признака «импорт вне перечня» в
`preflight` — ни в проверке групп планки (`preflight.py:186`), ни в проверке
долгоживущих файлов кодовой ветки (`preflight.py:203`).

AC-4. Тот же файл, что в AC-2, не получает признака «импорт вне перечня» в
`amend-tests` (`amend.py:512`).

AC-5. У того же учебного внешнего проекта долгоживущий файл с импортом,
верхнее имя которого не входит ни в прежний разрешённый набор, ни в
`long_lived_imports`, получает отказ «импорт вне перечня» в каждом из пяти
мест AC-1; текст отказа называет подполе `long_lived_imports` и его значение.
Элемент перечня, являющийся началом верхнего имени, импорта не разрешает
(перечень `["s"]` не разрешает `import sqlalchemy`).

AC-6. У учебного внешнего проекта без подполя `long_lived_imports` и у
учебного внешнего проекта с пустым `long_lived_imports` импорт
`from src.app import x` в долгоживущем файле получает отказ «импорт вне
перечня» (прежний набор разрешённых имён) в каждом из пяти мест AC-1; текст
отказа называет подполе `test_profile.long_lived_imports`, которое надо
заполнить.

AC-7. Проверка записи внешнего проекта отказывает записи, у которой
`test_profile.long_lived_imports` — не список, или содержит элемент — не
строку, пустую строку, строку `"src.app"` или `"*"`; запись с
`long_lived_imports: [src, fastapi]` и запись с пустым списком проходят
проверку; запись без подполя проходит проверку с прежним исходом.

AC-8. Профиль, разобранный из записи с непустым `long_lived_imports`, несёт
значение подполя; профиль из записи без подполя и из записи с пустым списком
несёт пустое значение; остальные поля профиля — прежние.

## Оценка объёма и деление

Сработавшие сигналы: число файлов зоны ≥ 5 (шесть файлов + `tests/`);
`budget_usd` ≥ $30.

Материал для решения о монолите: подполе профиля (требование 1,
`targets.py`/`project_profile.py`) и его потребитель — правило импортов на
трёх рубежах (требования 3–5, `guard.py`, `tests_writing.py`,

правило поперёк: рубежи разошлись бы в исходе на один и тот же файл. Объём
правки малый (новое подполе с проверкой вида, перечень и признак проекта в

«монолит» или нарезку утверждает Оператор на гейте SPEC.

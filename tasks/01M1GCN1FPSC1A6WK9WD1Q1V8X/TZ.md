# ТЗ: Лимиты пакетов контекста и гейт ёмкости диффа ревью

Источник: docs/research/2026-09-01-evidence-gates-proposals.md, п.3
(ядро ревизии; очередь Оператора 01.09, роадмап §4 п.2г).

Суть: сборка контекста в единый документ уже есть — ревью-пакет
вместо свободного чтения (T011), бриф разработчика (T028),
инкрементальный дифф поздних итераций (T029). Не хватает дисциплины
размера и доказательства полноты: (а) роль перечитывает уже
включённое (метрика трения T095 измеряет, но не предотвращает);
(б) опаснее — инструмент чтения молча усекает длинный файл или дифф,
и роль (особенно ревьювер) выносит вердикт по неполному материалу;
(в) неограниченный дифф уходит ревьюверу молча — вердикт по объёму,
не помещающемуся в один контекст, ненадёжен по построению.

Требуется:
1. Машинная опись пакета (бриф разработчика и ревью-пакет): для
   каждого включённого файла — путь, размер, sha256; для не влезшего
   — ссылка с причиной пропуска (превышен лимит файла/пакета).
   Опись — часть самого пакета, роль видит, что включено целиком,
   а что читать адресно.
2. Потолки размера: на один включённый файл и на пакет целиком —
   именованные константы config.py (стартовые значения — порядка
   24 КиБ и 64 КиБ, точные — решение исполнителя в SPEC по фактике
   существующих пакетов; повышение лимитов после мержа — класс
   «лимит» ADR-0002, только Оператор).
3. Пакет крупнее порога одного чтения делится на нумерованные части
   фиксированного размера; опись несёт размеры и sha256 частей,
   промпт роли требует прочитать все части по порядку. Деление —
   по границам строк, конкатенация частей байт-в-байт равна полному
   пакету.
4. Дифф в ревью-пакете подчиняется той же дисциплине: до порога —
   целиком, крупнее — частями со sha256; молча усечённый дифф
   исключается конструкцией.
5. Гейт ёмкости: переход in_dev → review отказывает, если полный
   дифф снимка превышает верхний предел (именованная константа,
   порядка 256 КиБ — уточнить по фактике в SPEC), с явной причиной
   «снимок не помещается в один контекст ревью — разделить задачу»
   и именем задачи. Отказ журналируется; путь дальше — решение
   Оператора (разделение задачи либо повышение лимита), гейт сам
   ничего не эскалирует автоматически.
6. Инкрементальный дифф поздних итераций (T029) сохраняет текущее
   поведение и получает ту же опись/лимиты; лимит ёмкости меряется
   по полному диффу снимка, не по инкременту.
7. Промпты/скилы затронутых ролей дополняются протоколом описи
   (читать части по порядку, включённое не перечитывать, пропущенное
   читать адресно); мандат на правку skills под это ТЗ предоставлен.
8. Тесты: опись соответствует фактическому содержимому (sha256);
   файл больше лимита — пропущен со ссылкой и причиной; пакет
   делится и конкатенация частей равна целому; гейт ёмкости
   отказывает на диффе больше предела и пропускает на меньшем;
   отказ журналируется; T011/T028/T029-поведение не регрессирует;
   существующие тесты зелёные.

Зоны: orchestrator/brief.py, orchestrator/review.py,
orchestrator/fsm_advance.py (переход in_dev → review),
orchestrator/config.py (константы лимитов), orchestrator/role_prompt.py
(протокол чтения), skills/ (по мандату), tests/. НЕ трогать зоны
параллельной задачи «Наблюдаемость сессий» (01M1GCHKG8DDK4DCZWCE3DYKWC):
orchestrator/lease.py, liveness.py, store.py сверх существующего API,
runner.py, doctor.py, catalog.py, cleanup.py, release.py, pause.py.
Конфликт зон по ходу реализации — эскалация, не выход за границу.

Не входит: границы недоверенных данных в брифах (п.6 документа —
отдельная задача ПОСЛЕ мержа этой: та же зона сборки пакетов);
изменение состава включаемого в брифы (что включать — как сейчас,
меняется только дисциплина размера и опись); ретроспективная правка
старых пакетов; автоматическое разделение задач.

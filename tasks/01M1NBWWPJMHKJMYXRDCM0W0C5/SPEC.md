# SPEC: Автогейт приёмки читает планку через источник артефактов

## Контекст
Автогейт приёмки (ADR-0007, `orchestrator/fsm_autogate.py::_autogate_conditions`)
проверяет каталог `tasks/<id>/acceptance_tests/` на диске рабочей копии.
После переноса артефактов задачи в артефактную ветку (A7) этот каталог
на диске рабочей копии пуст после автокоммита шага, и автогейт всегда
отвечает «каталог приёмочных тестов пуст или отсутствует» — каждая
задача падает на ручной гейт приёмки, хотя сама приёмка
(`acceptance.run`) прогоняется штатно. Наблюдение подтверждено на всех
мержах 03–04.09 (роадмап, реестр регрессий нового флоу A7, №6).

## Требования
1. Условия автогейта, которые сейчас читают `acceptance_tests/*.py` и
   AC-пометки (manual/skip/escalate) с диска рабочей копии
   (`_autogate_conditions`), переведены на чтение через источник
   артефактов задачи (`artifact_source.resolve` +
   `gitcmd.ls_tree_files`/`gitcmd.show`) — тем же приёмом, что
   `fsm_advance.tests_writing`/`fsm._tests_writing_ac_state` и разбор
   `guard.scan_ac_content` по ветке. Диск рабочей копии для этого
   чтения не используется.
2. Остальные условия автогейта acceptance из ADR-0007 п.3 (б — полный
   прогон приёмочных тестов задачи зелёный; в — полный набор tests/
   зелёный; г — бюджет задачи не превышен; д — вердикт ревью approved
   текущей итерации) поведение не меняют — меняется только источник
   чтения планки и её AC-пометок (условие «а»). Журнал автогейта, в
   записях, где решение зависит от чтения планки/пометок (пройден по
   условию «а», отказ по пустому/отсутствующему каталогу, отказ по
   manual- или skip-критериям), называет источник чтения — ветку и sha,
   с которых прочитана планка.
3. Задача нового флоу (планка `acceptance_tests/` без manual/skip-
   критериев существует только в артефактной ветке, не на диске
   рабочей копии) проходит автогейт acceptance так же, как раньше
   проходила бы задача с планкой на диске. Задача с хотя бы одним
   manual-критерием в планке (прочитанной из артефактной ветки) не
   проходит автогейт и остаётся на ручном гейте приёмки с прежней
   причиной («автогейт: критерии manual — AC-...»); аналогично для
   skip-критериев («автогейт: критерии skip — ...»). Существующий набор
   тестов остаётся зелёным.

## Критерии приёмки
AC-1. `_autogate_conditions` определяет наличие `acceptance_tests/*.py`
и разбирает AC-пометки (manual/skip/escalate) через источник
артефактов задачи (`artifact_source.resolve` + `gitcmd.ls_tree_files`/
`gitcmd.show`), не через путь на диске рабочей копии (`acc_tdir`).

AC-2. Задача, у которой планка (`acceptance_tests/` без manual/skip-
критериев) закоммичена только в артефактную ветку и отсутствует на
диске рабочей копии в момент входа в `acceptance`, проходит автогейт
(переход `acceptance -> merge_gate`, `actor=autogate`) при выполнении
остальных условий ADR-0007 п.3 (б–д) — без ручного вмешательства
Оператора.

AC-3. Та же задача, но с хотя бы одним manual-критерием в планке
(прочитанной из артефактной ветки), не проходит автогейт: состояние
остаётся `acceptance`, причина в журнале и выводе — «автогейт: критерии
manual — AC-<номера>» (та же формулировка, что до этой правки).

AC-4. Та же задача с хотя бы одним skip-критерием — не проходит
автогейт, причина — «автогейт: критерии skip — AC-<номера>».

AC-5. Задача, у которой каталог `acceptance_tests/` в источнике
артефактов пуст или отсутствует, не проходит автогейт с причиной
«автогейт: каталог приёмочных тестов пуст или отсутствует» (то же
поведение, что и раньше, при пустом/отсутствующем каталоге — теперь
проверяется по ветке, а не по диску).

AC-6. Записи журнала автогейта, где решение зависит от чтения планки
или её AC-пометок (AC-2..AC-5 выше), называют источник чтения — ветку
и sha артефактной ветки, с которых планка прочитана.

AC-7. Условия ADR-0007 п.3 б) полный прогон приёмочных тестов задачи
зелёный, в) полный набор `tests/` зелёный, г) бюджет задачи не
превышен, д) вердикт ревью approved текущей итерации — не изменены
этой правкой: поведение автогейта по этим условиям (порядок проверки,
причины отказа, короткое замыкание на первом невыполненном условии)
остаётся прежним.

AC-8. Существующий набор тестов (`tests/`), включая тесты
`orchestrator/fsm_autogate.py`, остаётся зелёным после правки.

## Не входит
- Изменение политики ADR-0007 (состав условий автогейта acceptance,
  их порядок, дефолт `manual`, механизм `gates.yaml`).
- Изменение ручного гейта приёмки (путь, которым Оператор approve/
  reject проходит `acceptance` вручную, когда автогейт не сработал или
  политика не `auto`).
- Изменение прогона самой приёмки (`acceptance.run`/`run_full_suite`)
  и материализации `acc_tdir` для этого прогона в вызывающем коде
  (`fsm_advance.verifying`/`review`) — правка касается только условий
  автогейта в `_autogate_conditions`.

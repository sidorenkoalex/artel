# SPEC: Паритет окружения шага Codex: интерпретатор и PATH как у шага Claude

## Контекст

В шаге Codex команда оболочки сейчас использует системный Python, хотя
`role_env` ставит интерпретатор пульта первым в PATH. Причина установлена
проверкой на пульте 27.09: команды Codex исполняются через `/bin/zsh -lc`,
а `/etc/zprofile` вызывает `path_helper`, который ставит системные каталоги
в начало PATH. Это нарушает паритет с шагом Claude и заставляет роль искать
иной интерпретатор вручную.

## Требования

1. Устранить изменение PATH оболочкой входа, сохранив изоляцию шага Codex.
   Конкретный способ выбирается и обосновывается на этапе PLAN по проверке;
   он не задан заранее данным SPEC.
2. Команды оболочки шага Codex должны получать PATH, собранный `role_env`:
   `python3`, `pytest`, `git` и `gh` резолвятся в те же пути, что в шаге
   Claude.
3. Белый список окружения и защита от секретов чужих провайдеров остаются
   без ослабления.
4. Запись журнала окружения шага должна однозначно указывать, описывает ли
   она окружение пульта, либо должна содержать PATH роли; существующие
   читатели записи сохраняют работу.
5. Документация курируемого дома Codex описывает интерпретатор и PATH,
   видимые из шага. Если решение использует файл дома роли, этот файл
   включается в `docs/reference/role-home/codex/` и в сверку дома роли.

## Критерии приёмки

AC-1. Офлайн-тест с окружением шага Codex и его домом роли запускает
`/bin/zsh -lc 'command -v python3'` и получает путь к интерпретатору
пульта; Codex CLI в тесте не запускается.

AC-2. Офлайн-проверка собирает окружения и команды шагов Codex и Claude и
подтверждает, что после исполнения оболочки входа `python3`, `pytest`,
`git` и `gh` резолвятся в одинаковые пути, а PATH шага Codex соответствует
PATH, собранному `role_env`.

AC-3. Если выбранное решение задаётся ключом окружения оболочки, этот ключ
присутствует и в конфигурации курируемого дома, и в параметрах команды
шага Codex; если решение использует файл дома роли, файл присутствует в
референсе `docs/reference/role-home/codex/` и проверяется сверкой дома роли.

AC-4. Офлайн-смок `codex-isolation-smoke` и проверка
`foreign-provider-secrets` остаются зелёными без изменения их ожиданий;
в окружение команд шага не добавляются переменные вне белого списка
манифеста или секреты чужих провайдеров.

AC-5. Запись журнала окружения либо явно помечена как описание окружения
пульта, либо содержит PATH роли; существующие читатели записи не ломаются.

AC-6. `docs/reference/role-home/codex/AGENTS.md` документирует
интерпретатор и PATH, которые видит шаг Codex; при изменении
`config.toml` это же отражено в нём.

AC-7. `tests/test_providers_codex.py`, `tests/test_providers.py` и
`tests/test_provider_scoped_step_env.py` остаются зелёными без ослабления
существующих проверок.

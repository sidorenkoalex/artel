# SPEC: Паритет окружения шага Codex: интерпретатор и PATH как у шага Claude

## Контекст

`runner.role_env` формирует для процесса роли белый список переменных и
PATH, в котором первым стоит `bin/` venv пульта. Однако команды оболочки
в живом шаге Codex увидели системный `python3` 3.9 вместо этого окружения.
Справка Codex CLI 0.155.1 указывает настройку
`shell_environment_policy.inherit`; её значение `all` позволяет оболочке
агента получить окружение уже запущенного процесса роли. Поэтому причиной
расхождения является политика наследования окружения оболочки Codex по
умолчанию, а не построение PATH в `role_env`.

## Требования

1. Для шага Codex задать `shell_environment_policy.inherit = "all"` и
   продублировать это значение в курируемом `config.toml` и в
   `CONFIG_OVERRIDES` команды шага. Выбор обоснован тем, что CLI наследует
   уже ограниченное `runner.role_env`, а не окружение Оператора.
2. Сохранить изоляцию окружения шага и действующие проверки отсутствия
   чужих секретов.
3. Добавить офлайн-проверку равенства PATH и путей разрешения `python3`,
   `pytest`, `git` и `gh` для шагов Codex и Claude.
4. Устранить вводящую в заблуждение запись fingerprint окружения шага без
   нарушения существующих читателей журнального поля.
5. Описать в курируемом доме Codex интерпретатор и PATH, которые видят
   команды шага.

## Критерии приёмки

AC-1. Для команды оболочки шага Codex действует
`shell_environment_policy.inherit = "all"`; ключ и значение присутствуют
как в `docs/reference/role-home/codex/config.toml`, так и среди
`CONFIG_OVERRIDES` argv шага. Обоснование в коде или документации
фиксирует, что настройка наследует уже ограниченное `runner.role_env`.

AC-2. Офлайн-тест, не запуская Codex CLI, строит окружение и команду
шага для ролей на Codex и Claude и подтверждает одинаковый PATH, а также
одинаковые пути, которыми в нём разрешаются `python3`, `pytest`, `git` и
`gh`.

AC-3. Белый список переменных шага сохраняется: в окружение команды Codex
не попадают переменные вне белого списка манифеста и секреты чужих
провайдеров; `codex-isolation-smoke` и `foreign-provider-secrets` остаются
зелёными без изменения их ожиданий.

AC-4. Журнальная запись об окружении однозначно сообщает, что она описывает
окружение пульта, либо содержит PATH роли; существующие читатели поля
`detail` продолжают работать.

AC-5. `docs/reference/role-home/codex/AGENTS.md` описывает интерпретатор
и PATH, которые видят команды шага Codex; при изменении конфигурации это
же отражено в `config.toml` референса.

AC-6. Тесты покрывают паритет PATH двух провайдеров и, при выбранном ключе
политики оболочки, его наличие в конфигурации и argv; существующие
`tests/test_providers_codex.py`, `tests/test_providers.py` и
`tests/test_provider_scoped_step_env.py` проходят без ослабления.

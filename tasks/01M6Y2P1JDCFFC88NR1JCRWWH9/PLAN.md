# PLAN: Правила guard для общего состояния: фикстуры уровня модуля только через shared_readonly, build — помощник гейта неослабления (ADR-0032, этап 5, часть б)

## Подход
Одно распознание общей фикстуры в `scripts/guard.py` —
`_shared_readonly_calls(tree)`: `<имя> = shared_readonly(<класс>, <функция>)`
позиционными аргументами оператором уровня модуля, где `shared_readonly`
назван любой формой импорта из `tests.sandbox` (`_imported_names`); все
прочие вызовы `shared_readonly` — отдельным списком. Этим распознанием
пользуются три потребителя:

- `_fixture_table` кладёт общую фикстуру как `_Fixture(…, shared=True)` с
  узлом `build`; `_FixtureScope.records` прослеживает `build` и его
  помощников первого уровня, но не его параметры (`sb` — песочница);
  `_changed_fixture_names` называет имя общей фикстуры при смене `build`,
  его помощника или самого присваивания.
- `_style_violations` проверяет `build` как тело фикстуры (утверждения,
  скрытый пропуск, помощник первого уровня) и вызывает новые правила
  `_shared_state_violations`: `scope=` шире функции (любой вызов
  `pytest.fixture` — декоратор и присваивание), иной вызов
  `shared_readonly`, вторая общая фикстура, `build` не функция файла, и в
  модуле с общей фикстурой — тесты, берущие фикстуры песочниц
  `tests/fixtures.py` прямо или через фикстуры файла (транзитивно, разбор
  `_FixtureScope.requested`/`resolve`), вызовы-создания и наследники классов
  песочниц (`_SandboxRefs`: имена импорта, атрибуты модулей `tests.*`,
  локальные цепочки), вызовы `tests.fixtures._sandbox`.
- Перечень классов песочниц — `_sandbox_class_names(sources)` по
  исходникам модулей песочниц (наследники `TmpDirTest`/`TmpRootTest`,
  определённых там же, в том числе между модулями). Источник — новый
  параметр `sandbox_sources` у `pytest_style_errors_from_files` (`None` —
  `config.ROOT`, читается лениво и только для файла с общей фикстурой);
  `long_lived_errors_from_files` пробрасывает свой `sandbox_sources`, так что
  `preflight`, выход из `tests_writing` и `amend-tests` (уже передающие его)
  проверяют по дереву своей ветки без правок вызывающих.

Освобождение `lint_base`: у `_StyleViolation` новое поле `statements` —
операторы, которые сверх прежнего условия обязаны быть в базе; у правил
общего состояния это присваивание общей фикстуры, поэтому присваивание,
добавленное в залоченный файл, освобождения не даёт.

Требование 4 — `sb = None` до `try`, создание песочницы внутри `try`,
уборка только при `sb is not None` (`tests/sandbox.py`,
`_SharedModuleState.construct`). Требование 5 — `_size_rules_apply`
отдаёт `False` для метки `^(tasks/[^/]+/)?acceptance_tests/`.

## Шаги
1. `tests/sandbox.py`: конструктор песочницы внутри `try` (требование 4).
2. `scripts/guard.py`: распознание общей фикстуры, таблица фикстур и
   `_changed_fixture_names` (требование 2, гейт неослабления).
3. `scripts/guard.py`: правила стиля общего состояния, `sandbox_sources`,
   освобождение `lint_base` с присваиванием (требования 1–3, 6).
4. `scripts/guard.py`: правила размера не на файлах планки (требование 5).
5. Тесты: долгоживущие файлы задачи (109 тестов) зелёные; свой
   `tests/test_guard_shared_readonly_rules.py` — свойства сверх них
   (`weakened_helpers` по общей фикстуре, освобождение неизменённого
   залоченного файла, параметр `build` не фикстура), каждая заявка
   мутации проверена временной мутацией (все три теста краснели).
   Карта регенерирована.

## Влияние на систему
Ослаблений нет: прежние отказы стиля и записи гейта неослабления не
меняются, добавляются новые. Таблица фикстур только растёт (общие
фикстуры), `_changed_fixture_names` называет больше имён — поиск
вызывающих вне диффа шире, не уже. Условие освобождения `lint_base`
прежних нарушений не меняется (`statements` у них пуст). Правила размера
сняты только с меток файлов планки — им отказ даёт
`long_lived_plank_errors` (не меняется); долгоживущие файлы с сегментом
`acceptance_tests` в середине пути правил не теряют. Прогнаны тесты
затронутых модулей: долгоживущие файлы задачи (109), guard-фикстуры,
assertion_changes, fixture_records/gate, plank_forms, size_rules/size_gate_paths,
shared_readonly части а, size_marks_sources, helper_scope(_modes),
test_ast, test_groups, test_integrity_helper_heirs, declared_change,
long_lived_template_shape, test_lint, preflight, tests_writing
test_groups, network_address(-gate), amend_network_scope — все зелёные.
Откат — revert коммита задачи.

## Риски
- Правило «других песочниц нет» опирается на статический разбор имён:
  `cls = RealGitSandbox; cls()`, `getattr` и динамический импорт не
  ловятся — принятый пробел (SPEC «Не входит»).
- Имя класса песочницы при `from tests.<любой модуль> import <Имя>`
  сверяется по имени из перечня модулей песочниц — строже, чем «только
  из модуля песочниц».

## Предложения системе
- Слепая зона правил общего состояния (SPEC требование 6): файлы `tests/`,
  которые меняет разработчик в `in_dev`, и планка в `amend-tests` (там
  только линт детерминизма, `orchestrator/amend.py`) правилами
  `scope=`/`shared_readonly`/«других песочниц нет» не проверяются.
- `orchestrator/test_lint.heavy_sandbox_names` и
  `guard._sandbox_class_names` — один обход наследования с разными корнями;
  при правке `test_lint` стоит обобщить корни параметром.

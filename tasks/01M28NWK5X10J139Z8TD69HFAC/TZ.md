# ТЗ: класс пуша ADR-0016 не маскирует красный main — документный пуш наследует итог тестов родителя

# ТЗ: класс пуша (ADR-0016) не маскирует красный main — документный пуш наследует итог тестов родителя

Источник: копилка 11.09 («Main красный, а CI main зелёный»). Операторский
коммит cb122d21 (диффы защищённых путей) уронил один тест, прогон CI
этого коммита красный, но два следующих документных коммита (роадмап,
копилка) получили «success»: задание `changes` (.github/workflows/ci.yml,
«Класс пуша — менялся ли код») для пуша в main, где все файлы под
`docs/`, `tasks/` или `*.md` в корне, выставляет `code=false`, задание
`python` пропускается, а пропущенное задание не портит итог workflow.
Краснота main всплыла только на подтяжке main в ветку задачи
(01M1THKWFX, мерж отклонён), между тем пин (`pin-update`) и гейт свежести
канарейки читают именно итог прогона main.

Требуется:
1. Классификатор пуша выносится из bash внутри YAML в
   `scripts/ci_push_class.py` (stdlib, без сторонних пакетов): вход —
   имя события, ref, `before`, HEAD и список изменённых файлов (либо
   вызов `git diff --name-only`), выход — `code=true|false` и строка
   причины на stdout. Логика ADR-0016 сохраняется дословно (fail-closed:
   любое сомнение — `true`; `artifact/**` — `false`; `task/**` и PR —
   `true`).
2. Новое правило для документного пуша в main: `code=false` только если
   последний завершённый прогон workflow `ci` для родительского коммита
   (`before`) на ветке main завершился `success` И его задание `python`
   не было пропущено ИЛИ само наследовало зелёный итог по цепочке.
   Практически: скрипт спрашивает GitHub API (`gh api
   repos/{owner}/{repo}/actions/runs?head_sha=<before>&branch=main`)
   — при `conclusion != success`, при отсутствии прогона, при любой
   ошибке запроса — `code=true` (тесты идут). Так документный коммит
   поверх красного main даёт красный прогон, а не зелёную плашку.
3. Классификатор печатает в лог задания причину решения одной строкой
   («документный пуш, родитель <sha> зелёный — тесты пропущены» /
   «родитель <sha> красный — тесты идут» / «нет данных о родителе —
   тесты идут»).
4. Правка `.github/workflows/ci.yml` (защищённый путь) — unified-дифф
   приложением к PLAN.md, проверенный `git apply --check`: задание
   `changes` вызывает `python3 scripts/ci_push_class.py` и передаёт
   `GITHUB_TOKEN` в окружение; ADR-0016 (`docs/adr/`, защищённый путь)
   — абзац «наследование итога родителя» тем же приложением.
5. Тесты `tests/test_ci_push_class.py`: (а) все ветки классификации
   ADR-0016 на подставных входах — те же ответы, что давал bash;
   (б) документный пуш при красном родителе → `code=true`; при
   зелёном → `false`; при ошибке API → `true`; (в) причина в stdout
   называет sha родителя; (г) существующие тесты зелёные.

Зоны: scripts/ci_push_class.py, tests/.
Приложениями к PLAN (защищённые пути): .github/workflows/ci.yml,
docs/adr/0016-ci-jobs-by-push-class.md.
Порядок: без зависимостей.

Не входит: изменение набора заданий CI, двойной прогон push+pull_request
на один sha (отдельная строка копилки), пропуск тестов для веток задач.

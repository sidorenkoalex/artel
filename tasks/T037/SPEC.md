# SPEC: Общая тестовая песочница и ревизия мокинга subprocess

## Контекст

Класс `TmpRootTest` скопирован в 9 тестовых файлов, хелпер `capture` —
в 17 файлах (24 определения), `fake_git` — в 8 файлах (14 определений).
Каждая копия патчит своё подмножество путей `config`: непропатченный
путь в очередной копии — тихая утечка теста на реальное дерево пульта.
Отдельно, тесты 8+ модулей мокают `runner.subprocess.Popen` с точными
счётчиками вместо мокинга функции-обёртки (по образцу `gitcmd.git` /
`keychain.token`) — любой новый системный вызов в пути шага ломает
десятки чужих тестов; прецеденты — keychain-hotfix, git-идентичность,
76 тестов при сверке пина CLI, стабы pre-flight. Из-за последнего
прецедента сверка пина CLI (tasks/T022, требование 5) сейчас выполняется
только в `doctor`, не в pre-flight каждого шага — решение Оператора
25.08 по эскалации T022 сузило требование именно из-за конфликта
с мокингом Popen. Задача — CR-2026-08-26-3 + строка беклога P3
(«Ревизия мокинга subprocess в тестах»).

Задача класса «рефакторинг» (правила tasks/T015): поведение системы
не меняется, зелёность существующих тестов и неизменность их сценариев
и ассертов — определение неизменности. Правки в тестовых файлах
допустимы только по импортам и путям патчей.

## Требования

1. Вынести песочницу в общий модуль `tests/sandbox.py`: класс
   `TmpRootTest` с параметризуемым, по умолчанию полным набором
   патчируемых путей `config`, общие хелперы `capture` и `fake_git`.
   Существующие тестовые файлы переходят на импорт из `tests/sandbox.py`
   вместо собственных копий.
2. Завести обёртку cli-вызова агента (модуль `runner.py`, вызов
   `subprocess.Popen` на пути запуска шага) по образцу `gitcmd.git`
   и `keychain.token`. Перевести тесты, которые сегодня мокают
   `runner.subprocess.Popen`, на мокинг этой обёртки.
3. Вернуть сверку пина CLI (`config.CLI_VERSION_PIN` против
   `claude --version`) в pre-flight (`orchestrator/doctor.py`,
   `preflight_checks`) — после перевода тестов на мокинг обёртки
   вызова агента конфликт с мокингом `Popen`, из-за которого сверку
   сузили при T022, снят.
4. Правки тестовых файлов в рамках задачи ограничены импортами
   и путями патчей: существующие сценарии и ассерты тестов не меняются.
5. До и после рефакторинга — полный прогон `python3 -m unittest
   discover -s tests` зелёный, число тестов не уменьшилось.

## Критерии приёмки

AC-1. `TmpRootTest`, `capture` и `fake_git` определены в одном модуле
`tests/sandbox.py`; в тестовых файлах, которые ими пользуются, остаются
только импорт и наследование/вызов — не собственные копии классов
и функций.

AC-2. Набор патчей по умолчанию в `tests/sandbox.py` покрывает все пути
`config`, используемые песочницами сегодня: `DB`, `TASKS`, `LOGS`,
`ROOT`, `PROJECTS`, `TARGETS`, `ROLE_HOME`, `ROLE_CONFIG_DIR`,
`BACKUP_MARKER`.

AC-3. Прямого мокинга `runner.subprocess.Popen` в тестах не остаётся —
тесты, ранее мокавшие `Popen` на пути вызова агента, мокают заведённую
обёртку cli-вызова.

AC-4. Сверка пина CLI (`config.CLI_VERSION_PIN`) выполняется в
`preflight_checks` (`orchestrator/doctor.py`), а не только в `doctor`.

AC-5. Полный прогон `python3 -m unittest discover -s tests` зелёный;
число тестов не меньше числа тестов до начала задачи.

AC-6. В диффе тестовых файлов нет изменённых ассертов и сценариев —
только изменения импортов и путей патчей (правило проверяет ревьювер
по диффу).

## Не входит

- Любые изменения поведения продукта или тестовых сценариев/ассертов —
  задача класса «рефакторинг», поведение не меняется.
- Дедупликация кода, не относящегося к песочнице (`TmpRootTest`,
  `capture`, `fake_git`) — только идентичные/почти идентичные куски
  этих трёх сущностей.
- Обёртки для системных вызовов вне cli-вызова агента (`gitcmd.git`
  и `keychain.token` уже существуют и не меняются в этой задаче).
- Попутные улучшения вне описанного объёма.

Требуется:

1. **Запись.** Снять отказ «исполняется после G2б». Порядок проверок компонента: форма шаблона → «шаблон или пара» → наличие. Форма (только у вида `path_template`, у `plank_layout` правила прежние), отказ с текстом: `<id>` и `<name>` — ровно по одному разу и только в последнем сегменте; `<dir>` — не больше одного раза и только целым сегментом; часть пути до первого заполнителя (корень) непуста; у компонента, чьё правило планки — метка `AC-<n>: `, последний сегмент шаблона обязан подходить под его маски `tests` (решение Оператора 19.10, п. 4); признак «правило — метка» в `targets.py` — `tests` непуст и команда не pytest, тем же правилом, что `is_pytest_command`, но без импорта `acceptance` (цикл импорта); при сверке с маской заполнители заменяются образцами (`<id>` — образец идентификатора задачи, `<name>` — «a»). Шаблон вместе с парой — прежний отказ; у единственного компонента ни шаблона, ни пары — новый текст «нет ни шаблона long_lived, ни пары long_lived_dir/long_lived_name» вместо «нет поля 'long_lived_dir' — обязательно у единственного компонента записи». Форма проверяется у компонента любой записи, включая запись из нескольких компонентов; тест G1а на поле сверить и привести к новому правилу.
2. **Пара при чтении записи.** После проверки формы `targets.py` дополняет поля компонента парой: `long_lived_dir` — корень шаблона, `long_lived_name` — остаток (может начинаться с `<dir>/`): `frontend/src/<dir>/<name>.<id>.test.jsx` → `frontend/src` и `<dir>/<name>.<id>.test.jsx`; `backend/tests/test_<id>_<name>.py` → та же пара, что у sled сегодня. `repo_context.profile_of`, `Profile.from_values`, `_with_component_fields`, `component_profiles` получают пару без правки; все места, читающие `long_lived_dir` как корень для git и диска (включая цель полного набора и выкладку `pytest-own`), работают без правки.
3. **Правило имени.** `is_long_lived_test_path` понимает `<dir>`: ноль или больше сегментов, каждый — `[A-Za-z0-9_-][A-Za-z0-9_.-]*` (сегмент с точки, в том числе каталог выкладки `.artel-plank`, не подходит); `<id>` — идентификатор задачи в нижнем регистре, `<name>` — прежнее `[a-z0-9_]+`. Одна функция `guard` строит пример пути для подсказок: `<id>` — идентификатор в нижнем регистре, `<name>` — переданная подстановка (`<имя>` либо `*`), `<dir>` → `<каталог>`; `Profile.long_lived_example` зовёт её. Паритет при `<dir>` принят: долгоживущие файлы по шаблону с `<dir>` — в любом подкаталоге; сверка сумм ловит правку и удаление, добавление тестов не ослабляет (решение Оператора 19.10).
4. **Подсказки.** Каждый текст, называющий путь долгоживущего файла как префикс плюс «<имя>.py» или «*.py» (`long_lived_plank_errors`, подсказка `runner.py`, пункты 2а и 5 задания test_author, фраза задания developer — с подстановкой `*`), берёт пример пути из п. 3; где в тексте есть `<имя>`, рядом — пояснение и для `<каталог>` (каталог модуля). У шаблона без `<dir>`, оканчивающегося на `<name>.py` (артель, sled), тексты побайтно прежние.
5. **Строка группы у файла с меткой `AC-<n>: `.** У файла, который правило планки проекта признаёт файлом с меткой (по имени файла), строка группы читается из первого комментария (`guard.first_comment`), значения, правила и тексты отказов — прежние, место в тексте — «в первом комментарии файла» вместо «в докстринге модуля»; в блоке `/* … */` перед «Группа:» допускается ведущая « * ». Применяется: к тестовым файлам планки по правилу (гейт групп выхода из `tests_writing`, `preflight`), к долгоживущим файлам (гейт долгоживущих, `preflight`). Файлы Python — прежний разбор. Долгоживущий файл не с расширением `.py`, не признанный файлом с меткой, — отказ гейта долгоживущих «<файл>: не файл с меткой AC-<n>: и не Python — группа и статика не проверяемы» (решение Оператора 19.10, п. 4); файл `.py` — прежний разбор (синтаксически битый `.py` у артели и sled — прежний исход, отказ даёт сухой сбор).
6. **Статика долгоживущего файла с меткой.** Признаки — по тексту: любое вхождение литерала «имя каталога tasks с косой чертой после него» (как у Python-файлов) и идентификатора задачи без учёта регистра, включая комментарии (тексты признаков прежние, строка — номер строки файла); у каждого вызова теста, который распознаёт `plank_test_names` (за головой «(» или «.each(»), в комментарии непосредственно над вызовом — строка «Ловит мутацию: <непустой текст>», иначе отказ «<файл>:<строка>: тест «<имя>» долгоживущего файла без «Ловит мутацию: …» в комментарии над вызовом». Файл планки с меткой и строкой «Группа: долгоживущий» — прежний отказ `long_lived_plank_errors` с примером пути из п. 3 и та же статика (как у Python в `_tests_writing_test_groups_gate`).
7. **Трассируемость долгоживущих по правилу.** Долгоживущие источники передаются парами (путь, текст) с правилом планки проекта: `fsm._tests_writing_ac_state` (оба пути), `fsm_advance.tests_writing`, `guard.acceptance_traceability_errors` (правило — и для `extra_sources`), `preflight` (`_traceability`). `it('AC-<n>: …')` долгоживущего файла с меткой покрывает AC-n; файл Python — прежний разбор.
8. **`amend-tests` для файлов с меткой — отказ до G3б** (решение Оператора 19.10, вынос 3): если в правке или на голове ветки есть файл планки или долгоживущий файл с меткой `AC-<n>: `, команда отказывает «amend-tests для файлов планки с меткой AC-<n>: — до G3б не исполняется; правка планки — reject на гейте» до любых записей; файлы Python — прежний путь.
9. **Гейт зон и сверка сумм** — через `Profile.is_long_lived` без правки их модулей: файл developer `frontend/src/<каталог>/<имя>.<id>.test.jsx` признаётся своим долгоживущим, перечень `long_lived.sha256.txt` пишется на выходе из `tests_writing` и сверяется на переходах и гейте мержа. Новая функция `guard`, вызванная в телах перехода, вызывается и в `orchestrator/preflight.py`; сторож предпроверки не правится.
10. **У артели, записей `test_profile` и компонентов с парой полей пути, тексты и исходы — прежние.** Аналитик перечисляет в SPEC тексты, закрепляемые тестами до правки: отказы `_check_component_rules` о паре полей (кроме заменяемого текста п. 1), `LONG_LIVED_ACTION` с подсказкой `_long_lived_refusal`, отказы `_diff_entry_error`, «нет строки «Группа: долгоживущий» — в … кодовой ветки только долгоживущие файлы», отказ `long_lived_plank_errors`, отказы `plank_file_group`, подсказку `runner.py` об обязательном артефакте test_author, пункты 2а и 5 задания test_author и фразу задания developer.
11. Тесты детерминированы, без сети и без Node: учебный проект с двумя компонентами (`junit-xml` на pytest с шаблоном `backend/tests/test_<id>_<name>.py` и `pult-vitest` с шаблоном `frontend/src/<dir>/<name>.<id>.test.jsx`) — форма записи, разбор шаблона, принадлежность путей, подсказки; места через `decide` (чекпоинт test_author, гейт долгоживущих, перечень и его сверка, гейт зон, трассируемость, `preflight`, отказ `amend-tests` п. 8, `plank-run` долгоживущего файла) — на записи `components:` из одного компонента каждого вида.

Критерии приёмки:
- запись с единственным компонентом и `long_lived: frontend/src/<dir>/<name>.<id>.test.jsx` читается; шаблон с `<name>` вне последнего сегмента, с `<dir>` внутри сегмента или с пустым корнем — отказ с текстом;
- у `pult-vitest` файл `frontend/src/components/button.<id>.test.jsx` test_author коммитится чекпоинтом, покрывает `it('AC-1: …')` критерий AC-1, попадает в перечень сумм и признаётся гейтом зон; `frontend/src/.artel-plank/<id>/button.<id>.test.jsx` и файл другой задачи — не свои;
- долгоживущий `.jsx` без «// Группа: долгоживущий» в первом комментарии, с литералом литерала «имя каталога tasks с косой чертой после него» (как у Python-файлов) или без «Ловит мутацию:» над тестом — отказ выхода из `tests_writing` и `preflight` с именем файла и строкой;
- тестовый файл планки `.test.jsx` без строки группы в первом комментарии — отказ гейта групп; долгоживущий `.ts` при метке только для `*.test.jsx` — отказ; шаблон `long_lived` с последним сегментом вне масок `tests` — отказ записи;
- `amend-tests` с файлом `.test.jsx` — отказ с текстом п. 8;
- у артели перечисленные в SPEC тексты и исходы прежние; сторож предпроверки зелёный без правки.

Решения по умолчанию (аналитику не спрашивать): `<dir>` допускает ноль сегментов (модуль в корне шаблона); у файла с меткой признаки импорта, закрытых имён и git не проверяются — разбор синтаксиса JS вне ADR-0026 («Не входит»); правило импортов `long_lived_imports` — только Python; «комментарий над вызовом» — подряд идущие строки `//` либо один блок `/* … */`, кончающийся на строке прямо над головой вызова, пустая строка его обрывает; признак «файл с меткой» у долгоживущего файла — по имени файла правилом планки проекта, файл `.py` — по правилам Python, иное расширение без метки — отказ п. 5; отказ построения правила планки (компонент `pult-vitest` без `tests`) — прежние исходы G2а-1; автогейт и сводка приёмки читают долгоживущие файлы как сегодня (автогейт для правила не по умолчанию закрыт, см. «Не входит»).

## Пути обхода гейтов
1. **Сторож предпроверки не видит помощников.** `transition_guard_calls` (tests/test_01m4p4zp…:235-247) собирает обращения к guard только в трёх телах. Если новую функцию guard (статику или группу файла с меткой) позвать из помощника `tests_writing.py` или из `fsm_advance.tests_writing`, а не из самого тела, предпроверку можно не дописывать — AC-14 останется зелёным. AC-6–AC-9 требуют исхода preflight на своих случаях, а отказ AC-10 — нет. Связано с отклонением 3.
2. **`amend-tests --from-branch`.** Требование 8 и AC-11 буквально выполнимы отказом только в `_cmd_amend_tests` (amend.py:645). Тогда `_cmd_amend_tests_from_branch` (amend.py:988) сдвигает `tests_locked_sha` на планку `.test.jsx`, которую `_test_files` (amend.py:167, :1079) не читает: без группы, статики и трассируемости. Это отклонение 4.
3. **Вызовы теста вне `TEST_CALL_HEAD`.** `it.skip(`, `it.only(`, `test.todo(` и `it.each` с шаблонной строкой не распознаются (guard.py:220-221, :295-301). Для них нет ни требования «Ловит мутацию», ни трассируемости. Запреты в тексте планки ТЗ относит к G2б-2 — здесь отклонением не считаю, отмечаю для G2б-2.
4. **`plank_layout` без каталога с точки под корнем `long_lived`.** Вид `layout` (targets.py:493-510) такой каталог допускает, а правило имени отсекает только сегменты с точки (SPEC.md:33). Выложенная копия планки с именем по шаблону признавалась бы своим долгоживущим файлом чекпоинтом (checkpoint.py:397) и предпроверкой (preflight.py:147-149). Пример ADR-0026 использует `.artel-plank`; риск низкий, на гейте стоит решить, нужна ли проверка записи.
5. Импорты JS у файла с меткой не проверяются — решение Оператора по умолчанию (ТЗ), не отклонение.

## Вердикт
**concerns** — SPEC ведома дальше, ни одно отклонение не требует возврата аналитику. Но часть пунктов меняет исход для записей вне заявленной границы или оставляет поведение без критерия; решить их может Оператор на гейте.

1. **Граница против отказа требования 5** (SPEC.md:18 против :35). Отказ «не файл с меткой AC-<n>: и не Python» задевает пары и записи `test_profile` с не-Python `long_lived_name`. Сегодня такой файл проходит молча (guard.py:3357-3360, tests_writing.py:474, guard.py:3679). В tests/ такие пары есть: tests/test_01m590gjaf0edv4nbc4c99mfvh_report_outcome.py:571, tests/test_01m59z0fw1699sjq2fa5y76cz3_component_plank_layout.py:262, tests/test_01m59kmpg2zmk10v556vzvqd65_plank_rule.py:178 (`<id>_<name>.test.js`). Для пары с правилом-меткой и тем же именем меняется ещё и разбор группы и статики. Требование 2 сводит шаблон к той же паре, поэтому `Profile` не отличает шаблон от пары, и «пара — прежние исходы побайтно» неисполнимо вместе с требованием 5. AC-13 ограничен файлами Python и расхождения не поймает. Нужно решение: либо граница читается как «прежние исходы для Python-файлов» и отказ распространяется на всех, либо отказ ограничивается компонентами с `long_lived` (тогда профилю нужен признак происхождения).
2. **Сверка последнего сегмента с масками не определена** (SPEC.md:27, AC-1 :55, AC-3 :59). Не сказано, с чем сверять: с полной маской или с её последним сегментом, как это делает правило планки (guard.py:2600-2606; project_profile.py:458). Не задан и регистр образца `<id>`. `targets.py` не может импортировать ни guard, ни project_profile, поэтому сверка пишется заново и может разойтись с `PlankRule.is_labelled`. Тогда запись пропускает шаблон, чьи файлы потом не признаются «файлами с меткой». Либо, при сверке полной маской, отклоняет любую реальную запись с масками `frontend/**/*.test.jsx`. Стоит дописать «по последнему сегменту маски, тем же правилом, что `PlankComponent.is_test`, `<id>` — в нижнем регистре» и зафиксировать в AC-1 маски с каталогом.
3. **AC-10 недостижим в заявленной форме и не требует preflight** (SPEC.md:73, :35, :49). Пример «`.ts` при метке только для `*.test.jsx`» отклоняется уже записью: требование 1 и AC-3 (:59). А требование 11 ведёт места через `decide`. Достижимые случаи — компонент с правилом по умолчанию и не-Python шаблоном или маска уже образца `a`. Кроме того, ни требование 5, ни AC-10 не требуют этого отказа в `preflight` (preflight.py:199-214). Предпроверка разойдётся с переходом вопреки своему контракту (preflight.py:9-13), и сторож этого не поймает (путь обхода 1).
4. **`amend-tests --from-branch` не назван** (SPEC.md:38, AC-11 :75). У команды два режима: amend.py:645 и :988. Критерий надо распространить на оба, иначе отказ в одном режиме проходит AC-11, а второй сдвигает лок на непроверенную планку `.test.jsx`.
5. **Требование 4 для шаблона с `<dir>` без критерия** (SPEC.md:34). Новые тексты runner.py:1338, role_prompt.py:205, :250, :284 и пояснение `<каталог>` ни одним AC не закреплены. Мутация «role_prompt оставил `{prefix}<имя>.py`» (test_author получит `frontend/src/<dir>/<имя>.py`) не краснит ни один тест.
6. **AC-8 уже требования 6** (SPEC.md:36 против :69). Нет вызовов `.each(`, «Ловит мутацию» в блоке `/* … */` и «tasks/» в комментарии. Мутации «заявка проверяется только у `it(`/`test(`» и «распознаётся только `//`» проходят.

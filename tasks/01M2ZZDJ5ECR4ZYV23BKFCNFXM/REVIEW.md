## Замечания

- **major — orchestrator/review.py:322-323 (перечень), :369-370
  (pathspec)** — `git log --name-only` с включённым по умолчанию
  определением переименований отдаёт ТОЛЬКО новое имя файла, поэтому
  прежний путь в pathspec инкремента не попадает. Сценарий поломки
  (воспроизведён на настоящем git 2.50.1: база вердикта, один
  собственный коммит ветки, в нём `orchestrator/alpha.py` →
  `orchestrator/beta.py` + правка одной строки и удаление
  `tests/test_gone.py`):

  ```
  own_commit_paths -> ['orchestrator/beta.py', 'tests/test_gone.py']
  инкрементальный --stat:  orchestrator/beta.py | 41 +++++++++++++++
                           tests/test_gone.py   | 10 ----------
  полный --stat от базы:   orchestrator/{alpha.py => beta.py} |  1 +
                           tests/test_gone.py                 | 10 ---
  ```

  То есть ревьювер видит `beta.py` как 41 строку нового файла и НЕ видит
  ни одной строки о том, что `alpha.py` перестал существовать. Простое
  удаление (`tests/test_gone.py`) доезжает корректно — класс ровно один:
  пре-образ переименования. Цена конкретна: переименование модуля или
  тестового файла в итерации доработки прячет от ревьювера удаление
  старого файла, а `skills/review-checklist.md` обязывает его сверять
  именно «дифф tests/ — удалённые ассерты». Инкремент при этом не пуст,
  поэтому откат требования 7 не срабатывает и дефект молчит.

  Предложение: добавить `--no-renames` в аргументы `git log`
  (`review.py:322-323`) — тогда git перечисляет оба пути пары, а
  определение переименования на стороне `git diff` (pathspec несёт обе
  стороны) отрабатывает как обычно. Проверено тем же прогоном:
  `own_commit_paths -> ['orchestrator/alpha.py', 'orchestrator/beta.py',
  'tests/test_gone.py']`, и инкрементальный `--stat` становится
  байт-в-байт равен полному. Плюс тест в `OwnCommitPathsTest`
  (настоящий git уже поднят фикстурой): собственный коммит
  переименовывает файл — в перечне оба пути.

- **minor — orchestrator/review.py:95** — строка отсутствия для трёх
  артефактов задачи по-прежнему говорит «в дереве — файл не найден»,
  хотя проверялся каталог `tasks/<id>/` рабочего каталога шага. Успешный
  откат источник называет (`STEP_WORKDIR_NOTE`), неуспешный — нет.
  Сценарий: ревьювер видит «(не показан: в ветке — …; в дереве — файл не
  найден)» для SPEC.md, читает это как «в главной копии пульта нет»,
  идёт искать файл туда — ровно тот ручной обход, который требование 1
  и снимает. AC-3 просит обе причины фактическими. Предложение: передать
  ярлык диска тем же keyword-параметром, что и `disk_note` («в рабочем
  каталоге шага — файл не найден» / «в дереве — …» для формы вердикта).

- **minor — orchestrator/review.py:726-728 (и комментарий :676-677)** —
  `package_note` печатает для того же PLAN.md две строки подряд:
  «артефакты задачи: рабочий каталог шага — PLAN.md» и «не из ветки, а
  из рабочего дерева: tasks/<id>/PLAN.md». Вторая называет источником
  рабочее дерево пульта, которым он больше не является. Сценарий:
  Оператор разбирает странный вердикт по `log <id>`, по второй строке
  идёт за версией PLAN.md в главную копию пульта, там файла нет (с 11.09
  их там не бывает) — и не восстанавливает, какой текст видел ревьювер.
  Предложение: либо переименовать ключ/формулировку под фактический
  источник, либо не печатать `from_worktree` для трёх артефактов задачи
  — их источник уже несёт поле `artifact_source`.

## Предложения системе

- Ревью-пакет собирается кодом ДО мержа правки самого сборщика, поэтому
  ревьювер задачи «почини сборщик пакета» получает пакет со старым
  дефектом. Здесь это безобидно (артефакты дочитываются с диска), но
  класс — «задача чинит механику собственного шага» — стоит называть в
  брифе явной строкой «пакет собран версией из main», чтобы ревьювер не
  тратил итерацию на диагностику уже известного.
- `skills/review-checklist.md` велит сверять «дифф tests/ — удалённые
  ассерты», но инкрементальный diff по построению может не показать
  удалённый файл целиком (R1-F1 — частный случай). Правило проверки и
  механика инкремента живут в разных местах и расходятся молча.

# ТЗ: Ревью-пакет: артефакты из артефактной ветки и инкрементальный diff по якорю вердикта

Источник: строки копилки П1 20.09 «Ревью-пакет не несёт SPEC.md и
PLAN.md» и П2 20.09 «Инкрементальный diff ревью-пакета на итерации 2
пуст»; предложения системе ревьюверов 01M2ZNTHSN (обе итерации) и
01M2ZNJX2N. Внеплановая задача перед задачей 2 плана провайдеров
(docs/research/providers-codex-plan.md): гейт плана держится на
инициативе ревьювера, а не на пакете.

Факты:
- Сборщик пакета `orchestrator/review.py::review_package` читает
  `tasks/<id>/SPEC.md`, `PLAN.md`, `REVIEW.md` функцией
  `artifact_text(branch, rel)`: сначала `git show <кодовая ветка
  task/…>:<rel>`, затем `config.ROOT / rel`. С 11.09 артефакты живут
  в артефактной ветке `artifact/<id>` (автокоммит оркестратора) и в
  рабочем каталоге шага `.artel/worktrees/<id>/tasks/<id>/`, а не в
  кодовой ветке и не в главной копии. Итог: в промпте ревьювера у всех
  25 задач с 01M2B6JN… (≈11.09) по 01M2ZNTHSN обе секции — «(не показан:
  в ветке — path does not exist; в дереве — файл не найден)». Последние
  полные пакеты — T080–T084. Ревьюверы дочитывают файлы с диска сами.
- Бриф developer те же артефакты уже берёт правильно:
  `orchestrator/brief.py::_branch_or_disk_text(task_id, branch, rel,
  foreign)` с веткой из `orchestrator/artifact_source.py::resolve(conn,
  task_id)` (артефактная ветка задачи и признак «дерево на чужой
  ветке»). ANSWER-n.md пакет уже читает этим резолвером
  (`_answer_rels`), SPEC/PLAN/REVIEW — нет.
- База инкрементального diff (итерация > 1):
  `review.previous_verdict_sha` берёт поле `код=` ПРЕДПОСЛЕДНЕЙ записи
  «sha зафиксирован» журнала, исходя из того, что между двумя входами
  в `review` ровно два перехода. Сегодня записей больше: фиксация
  пишется на каждом переходе (`in_dev -> verifying -> review`), на
  каждом автокоммите артефактов и на чекпоинте. Журнал 01M2ZNTHSN:
  вердикт итерации 1 вынесен на коде 550c53cc (запись при «state ->
  in_dev | замечания ревью, итерация 1»), а предпоследняя запись перед
  входом в review итерации 2 — код 23ca007b, HEAD ветки после
  автокоммита подтяжки main. Пакет: «строк diff 0, diff
  инкрементальный, итерация 2» у обеих задач 20.09 при пяти правленых
  файлах. Алерт `alerts.raise_diff_not_collected_alert` не срабатывает:
  diff собран, просто пуст. Класс ловили в T082 и T087, ревьювер лечит
  руками по sha из своего REVIEW итерации 1.
- Между вердиктом и входом в review итерации 2 в ветку попадают и
  коммиты подтяжки main (merge); честный инкремент — правки
  разработчика за итерацию, не изменения main.
- Вызов сборщика: `orchestrator/role_prompt.py` (prev_sha —
  `previous_verdict_sha`, ветка — `t["branch"]`, кодовая). Тесты:
  `tests/test_review_package.py` (классы ReviewPackageTest,
  IncrementalReviewPackageTest, PreviousVerdictShaTest и другие).

Требуется:
1. Артефакты в пакете: SPEC.md, PLAN.md, REVIEW.md читаются из
   артефактной ветки задачи через `artifact_source.resolve`, тем же
   приёмом, что `brief._branch_or_disk_text` (ветка → рабочий каталог
   шага; кодовая ветка и главная копия — не источники). Файла нет ни
   там, ни там — прежняя именованная строка «(не показан: …)» с
   фактическими источниками. Шаблон `templates/REVIEW.md` читается как
   сегодня. Заголовок части пакета называет источник (артефактная
   ветка или рабочий каталог), как `WORKTREE_NOTE` сегодня.
2. База инкрементального diff: sha кодовой ветки, на котором вынесен
   предыдущий вердикт, — запись «sha зафиксирован», сопровождающая
   переход «state -> in_dev» с detail «замечания ревью, итерация N-1»
   (либо иной однозначный якорь журнала на момент вердикта — выбор
   аналитика, обосновать в SPEC). Не «предпоследняя запись».
   Журнал старой задачи без такого якоря — прежняя деградация на
   полный diff с именованной причиной.
3. Содержимое инкремента: diff несёт правки разработчика за итерацию и
   не несёт изменений main, пришедших коммитами подтяжки (например,
   diff по коммитам ветки без merge-коммитов с момента базы, либо
   исключение путей, изменённых только подтяжкой — способ выбирает
   аналитик, фиксирует тестом). Заметка под diff'ом называет базу и
   HEAD, как сегодня.
4. Пустой инкремент при непустых правках: если инкрементальный diff
   пуст, а полный diff кодовой ветки от базы вердикта до HEAD (без
   `tasks/`) не пуст — пакет откатывается на полный diff с именованной
   причиной в заметке и журнале («инкрементальный diff пуст при
   непустых правках — показан полный»), и заводится тот же алерт, что
   для «diff не собран» (или отдельный `kind=warning` того же
   источника — на усмотрение аналитика). Инкремент пуст и правок нет —
   штатно, без алерта, заметка говорит об этом прямо.
5. Журнал «ревью-пакет собран» (`package_note`) дополняется источником
   артефактов (артефактная ветка / рабочий каталог / не найден) и базой
   инкремента (sha) — чтобы дефект такого класса был виден по журналу,
   а не по промпту.
6. Тесты (tests/): SPEC/PLAN/REVIEW берутся из артефактной ветки, а не
   из кодовой (тест с двумя ветками, где файлы есть только в
   артефактной); откат на рабочий каталог шага; база инкремента
   выбирается по якорю вердикта при лишних записях фиксации
   (подтяжка, автокоммит, чекпоинт) между итерациями; инкремент без
   изменений main; пустой инкремент при непустых правках даёт полный
   diff и алерт; пустой инкремент без правок — без алерта; журнал
   несёт источник и базу. Существующие `tests/test_review_package.py`,
   `tests/test_review_freshness.py`, `tests/test_fsm_review_rework_sha_gate.py`
   остаются зелёными (ожидания, привязанные к «предпоследней записи»,
   обновляются с перечнем в PLAN).

# ТЗ: критерий сироты для `doctor --fix` и предпросмотр кандидатов

Источник: бэклог 04–05.09 (`docs/backlog.md`). Уборка сирот `doctor
--fix` считает сиротой любую локальную ветку `artifact/<id>` без строки
в локальной `state.db`. База — локальный кэш: холодный старт задачи в
полёте не сеет (T049, требование 11), на чужой копии с
материализованными ветками команда снесёт локальные копии живых задач
(origin не трогается, ветки восстановимы). На пульте ждут уборки около
1900 сиротских веток, и её нельзя запускать без доработки.

Требуется:
1. Критерий сироты: ветка `artifact/<id>` — сирота, если id нет в
   `state.db` И ветки нет на origin (одна сверка `git ls-remote --heads
   origin 'artifact/*'` на весь прогон, не по ветке). Ветка, которая
   есть на origin, сиротой не считается, даже если БД её не знает.
2. Предпросмотр: `doctor` без `--fix` печатает кандидатов на удаление
   (число и первые N имён, N — константа `config`), с пометкой «удалит
   `doctor --fix`»; `doctor --fix` печатает тот же список перед
   удалением и число удалённых после.
3. Без сети (origin недоступен, `ls-remote` не ответил) уборка не
   выполняется: FAIL с именованной причиной, ни одна ветка не удаляется
   (принцип целостности); предпросмотр в этом случае печатает
   «критерий не вычислим без origin».
4. Тесты: ветка без БД и без origin — кандидат; ветка без БД, но с
   origin — не кандидат; `ls-remote` вызывается один раз; отказ без сети
   ничего не удаляет; предпросмотр без `--fix` ничего не удаляет; сеть в
   тестах запрещена (инвариант 35) — origin в тестах локальный
   репозиторий-фикстура; существующие тесты `doctor` зелёные.

Зоны: orchestrator/doctor.py (уборка сирот), orchestrator/config.py
(константа), tests/. Порядок: код после мержа стека ч.1 (одна строка в
doctor.py) и пула канарейки (doctor --restore); SPEC и планка — сразу.
Не входит: уборка кодовых веток `task/*`, снапшотов `refs/artifacts`,
изменение критерия для внешних target'ов.

Рамка: $10.

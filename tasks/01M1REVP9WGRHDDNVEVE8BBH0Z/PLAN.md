# PLAN: критерий сироты для `doctor --fix` и предпросмотр кандидатов

## Подход

Критерий сироты артефактной ветки (`orchestrator/doctor.py::
_orphan_artifact_branches`) сегодня сравнивает локальные ветки `artifact/
<id>` только со `state.db`. Требование 1 добавляет вторую сверку — с
origin — и требование 3 обязывает ровно ОДИН запрос `git ls-remote
--heads origin 'artifact/*'` на весь прогон уборки (AC-3), независимо от
того, печатает ли команда только предпросмотр (`doctor`) или ещё и
удаляет (`doctor --fix`).

Ключевое решение: разнести вычисление списка кандидатов и его
использование.

1. Новая функция `doctor._remote_artifact_branch_names() -> set[str] |
   None` — единственное место, вызывающее `gitcmd.git("ls-remote",
   "--heads", "origin", "artifact/*")`. `None` — origin не ответил
   (ненулевой код возврата или git не ответил вовсе); иначе — множество
   имён веток `artifact/<id>`, разобранных из `refs/heads/<имя>` вывода.

2. `_orphan_artifact_branches(conn, remote=<sentinel>)` — сигнатура
   расширена необязательным параметром `remote` (предвычисленное
   множество веток origin). Без явного аргумента (как сегодня зовут
   локальные тесты `doctor._orphan_artifact_branches(conn)`) функция сама
   вызывает `_remote_artifact_branch_names()` — обратная совместимость
   для прямых юнит-тестов и для контракта акцептанс-тестов (`_sandbox.py`).
   `None` у `remote` (origin недоступен) — вся функция возвращает `None`
   (fail-closed, требование 6), не пустой список: пустой список сегодня
   уже означает легитимный «сирот нет», спутать эти два случая означало
   бы удалить произвольную локальную ветку, посчитав origin пустым.
   Иначе — прежняя логика (регистронезависимая сверка с БД) плюс фильтр
   «не среди веток origin».

3. `sweep_orphan_artifact_branches(conn, orphans=<sentinel>)` —
   аналогично получает необязательный `orphans` (уже вычисленный список
   кандидатов). Без аргумента вызывает `_orphan_artifact_branches(conn)`
   сама (обратная совместимость с прямыми вызовами в существующих
   юнит-тестах). `orphans is None` — уборка НЕ выполняется вовсе:
   `git branch -D` не зовётся ни разу, incident не заводится, возврат —
   `None` (требование 5/AC-6). Остальная логика (удаление, разбор
   удалось/не удалось, один incident-алерт) не меняется.

4. `cmd_doctor` вызывает `_orphan_artifact_branches(conn)` РОВНО ОДИН РАЗ
   за весь прогон (что в режиме предпросмотра, что под `--fix`) и
   передаёт получившийся список явно в `sweep_orphan_artifact_branches`,
   когда `fix=True` — так второй вызов не делает повторного запроса
   origin (AC-3).
   - `orphans is None` (origin недоступен): в режиме без `--fix`
     печатается «критерий не вычислим без origin» (требование 6/AC-7); в
     режиме `--fix` — вместо предпросмотра/уборки добавляется `Check`
     со статусом `fail` и именованной причиной («origin недоступен») в
     общий список проверок doctor — это переиспользует существующий
     механизм печати `[FAIL]`/подсчёта провалов/`sys.exit(1)`, не
     заводит отдельный несогласованный путь выхода (требование 5/AC-6).
   - `orphans` — список (возможно пустой): новая общая функция
     `_print_orphan_branch_candidates(orphans)` печатает число кандидатов
     и первые `config.DOCTOR_ORPHAN_PREVIEW_LIMIT` имён с пометкой про
     `doctor --fix` (требования 3/4) — используется и в режиме
     предпросмотра, и в `--fix` (там — до вызова `sweep_orphan_artifact_
     branches`, требование 4/AC-5).
   - После удаления (`--fix`) добавлено число фактически удалённых
     веток в печатаемую строку (было только перечисление имён) — нужно,
     чтобы предпросмотр «до» и факт «после» были различимы в выводе
     (AC-5).

5. Новая именованная константа `config.DOCTOR_ORPHAN_PREVIEW_LIMIT`
   (требование 3/4) — число `N` из SPEC. Значение 20 — тот же порядок,
   что уже используют соседние «превью-N» константы пульта
   (`CI_RUN_LIST_LIMIT`).

6. Уборка ИГНОРИРУЕМЫХ ФАЙЛОВ/мёртвых lease-групп/зависших тестов
   (`_fix_ignored_artifact_files`, `_fix_dead_lease_groups`,
   `_fix_hung_test_runs`) НЕ блокируется недоступностью origin — SPEC
   «Требование 5» адресует именно уборку веток-сирот («ни одна ветка не
   удаляется»), это отдельные, не связанные с origin механики
   `doctor --fix`; они продолжают выполняться как раньше.

7. Один существующий юнит-тест (`tests/test_doctor.py::
   OrphanArtifactBranchSweepTest::
   test_cmd_doctor_fix_sweeps_once_and_lists_output`) не задаёт
   работоспособный git/origin (мокает только `sweep_orphan_artifact_
   branches` целиком) — до этой задачи это было безопасно, потому что
   критерий сироты origin вообще не спрашивал. Теперь предпросмотр
   `cmd_doctor` перед вызовом (замоканного) `sweep_orphan_artifact_
   branches` делает РЕАЛЬНЫЙ запрос `_orphan_artifact_branches`, который
   в этой песочнице (временный каталог без `git init`) обречён получить
   отказ git и вернуть `None` — тест сломался бы не из-за дефекта кода, а
   потому что раньше не нуждался в рабочем origin. Правка (в зоне
   `tests/` этой задачи) — добавить туда мок `doctor.
   _remote_artifact_branch_names` (возвращает пустое множество), не
   меняя ни одной проверки/ассерта теста: он по-прежнему проверяет то же
   самое (`sweep` вызван один раз, имя ветки в выводе), только не
   утверждает больше молчаливо, что origin недостижим не важно.

## Влияние на систему

- Сигнатуры `_orphan_artifact_branches`/`sweep_orphan_artifact_branches`
  расширены необязательными параметрами с сентинел-дефолтом — вызовы без
  аргумента (существующие юнит-тесты, `_sandbox.py` приёмочных тестов)
  ведут себя как раньше (сами вычисляют то, что нужно). Обратная
  совместимость сохранена буквально, не просто «по духу».
- Возврат `sweep_orphan_artifact_branches`/`_orphan_artifact_branches`
  расширен: `None` — новое законное значение (было — только `list[str]`).
  Единственный внешний вызывающий код за пределами этой задачи —
  `cmd_doctor` (правится этим же PLAN) и юнит-тесты (`tests/test_doctor.
  py`, где прямые вызовы уже проверяют `list[str]`, не `None`, — эти
  сценарии origin недоступным не делают, `None` там не возникает).
- Единственная правка существующего (не залоченного) теста —
  `test_cmd_doctor_fix_sweeps_once_and_lists_output` (см. «Подход» п.7):
  не ослабляет и не удаляет ни одной проверки, только даёт тесту
  работоспособный ответ origin, который до этой задачи не был нужен ни
  одному его ассерту. Остальной набор `tests/test_doctor.py` (в т.ч.
  соседние тесты того же класса, использующие `fake_git`/`gitcmd.git`
  с фиксированным успехом на любую команду) видит от таких моков «на
  origin веток artifact/* нет» естественно, без правки (AC-8, докстринг
  приёмочного `test_ac8_existing_tests_stay_green.py`).
- Уборка игнорируемых файлов/мёртвых lease-групп/зависших тестов внутри
  `doctor --fix` не завязана на доступность origin — принцип
  целостности не запрещает им продолжать работать: они не про сирот
  веток, и SPEC «Не входит»/«Требования» не просит их тоже блокировать.
- Откат: правка локальна `orchestrator/doctor.py`/`config.py`/
  `tests/test_doctor.py`, старое поведение (без сверки с origin)
  восстанавливается удалением параметра `remote`/`_remote_artifact_
  branch_names` и возвратом прежнего тела двух функций — никакой
  миграции схемы БД или данных нет.

## Риски

- Прогон полного `tests/` (не только `test_doctor.py`) в шаге не делается
  (конвенция: полный набор гоняет CI на пуш ветки) — точечно прогнан
  только `tests/test_doctor.py` и модули, которые могли бы неявно
  задеть `doctor.py`/`config.py` (`tests/test_invariants.py`,
  `tests/test_coldstart.py`).
- `config.DOCTOR_ORPHAN_PREVIEW_LIMIT = 20` — значение по аналогии с
  соседними лимитами, не из явного указания SPEC (SPEC оставляет число
  на усмотрение реализации, требуя только именованную константу) — крутилка
  Оператора при необходимости.

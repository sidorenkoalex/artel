# SPEC: критерий сироты для `doctor --fix` и предпросмотр кандидатов

## Контекст

Уборка сирот `doctor --fix` (`orchestrator/doctor.py::sweep_orphan_artifact_
branches`, `_orphan_artifact_branches`) сейчас считает сиротой любую
локальную ветку `artifact/<id>`, для которой нет строки в локальной
`state.db`. База для этого сравнения — только локальный кэш: холодный
старт задачи в полёте не сеет его (T049, требование 11), а на чужой
копии с материализованными ветками команда снесёт локальные копии живых
задач (origin не трогается, ветки восстановимы). На пульте накопилось
около 1900 сиротских веток, и запускать уборку в текущем виде нельзя.

Источник: бэклог 04–05.09 (`docs/backlog.md`).

Порядок работ: код меняется после мержа стека части 1 (одна строка в
`doctor.py`) и пула канарейки (`doctor --restore`); SPEC и планка
(тесты) пишутся сразу, независимо от этого порядка.

## Требования

1. Ветка `artifact/<id>` считается сиротой, только если ОБА условия
   верны: id отсутствует в `state.db` И ветки нет на origin. Проверка
   присутствия на origin — одна сверка `git ls-remote --heads origin
   'artifact/*'` на весь прогон уборки (не отдельный запрос на каждую
   ветку-кандидата).
2. Ветка, которая есть на origin, сиротой не считается, даже если БД её
   не знает.
3. `doctor` без `--fix` печатает предпросмотр кандидатов на удаление:
   число кандидатов и первые N имён (N — именованная константа в
   `orchestrator/config.py`), с пометкой, что их удалит `doctor --fix`.
   Без `--fix` ни одна ветка не удаляется.
4. `doctor --fix` печатает тот же список кандидатов (число и первые N
   имён с той же пометкой) перед удалением, затем — число фактически
   удалённых веток после попытки удаления.
5. Если origin недоступен (`git ls-remote --heads origin 'artifact/*'`
   не ответил или вернул ошибку), уборка (`doctor --fix`) не
   выполняется вообще: FAIL с именованной причиной недоступности, ни
   одна ветка не удаляется (принцип целостности).
6. В том же случае недоступности origin предпросмотр (`doctor` без
   `--fix`) вместо списка кандидатов печатает «критерий не вычислим без
   origin».

## Критерии приёмки

AC-1. Ветка `artifact/<id>` без строки в `state.db` и отсутствующая на
origin — кандидат на удаление (сирота).

AC-2. Ветка `artifact/<id>` без строки в `state.db`, но присутствующая
на origin, — НЕ кандидат на удаление.

AC-3. За один прогон уборки (`doctor --fix`, включая предпросмотр в
`doctor` без `--fix`) выполняется ровно один запрос `git ls-remote
--heads origin 'artifact/*'`, не по одному на каждую ветку-кандидата.

AC-4. `doctor` без `--fix` печатает число кандидатов на удаление и
первые N их имён (N — именованная константа `orchestrator/config.py`) с
пометкой, что их удалит `doctor --fix`; ни одна ветка при этом не
удаляется.

AC-5. `doctor --fix` печатает тот же список кандидатов (число и первые
N имён с той же пометкой) до удаления и число фактически удалённых
веток после.

AC-6. Если `git ls-remote --heads origin 'artifact/*'` не отвечает или
возвращает ошибку, `doctor --fix` не удаляет ни одной ветки и
сообщает FAIL с именованной причиной («origin недоступен» или
аналогичной, отличимой от прочих FAIL).

AC-7. В том же случае недоступности origin `doctor` без `--fix`
печатает «критерий не вычислим без origin» вместо списка кандидатов.

AC-8. Существующие тесты `orchestrator/doctor.py` (включая прежние
сценарии сирот-веток без сверки с origin) остаются зелёными после
изменения критерия.

## Не входит

- Уборка кодовых веток `task/*`.
- Уборка снапшотов `refs/artifacts`.
- Изменение критерия сироты для внешних target'ов (критерий и уборка —
  только для пульта, `origin` артели).

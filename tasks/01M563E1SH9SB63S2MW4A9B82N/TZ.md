# Одно наблюдение на задачи разных проектов; проект задачи в status

## Факты

Строка бэклога 18.10 «Несколько проектов: одно наблюдение, проект в status и report», разбор «что прибито под артель». Наблюдение привязано к одному проекту: `observe add` отказывает задаче другого проекта (`orchestrator/artel.py:1150-1160`, `_validated_observation_tasks`: «задача … принадлежит другому проекту»); 17.10 для задачи sled пришлось заводить второе наблюдение и второй `watch`. Фильтр дозора (`orchestrator/watch.py:299`) пропускает алерты только по id задач или по проекту наблюдения — алерты уровня пульта (стоп-кран волны, `alerts.py:238`; лишняя рабочая копия, `doctor/orphans.py:185`) заводятся на проект артели и наблюдению sled не видны. `status` и `report` не показывают проект задачи (`orchestrator/catalog.py:974-982`, `orchestrator/report.py:544`) — задачи артели и sled в выводе не различить.

## Требуется

1. Наблюдение принимает задачи любых проектов: `observe register|add` не отказывает задаче другого проекта; поле проекта наблюдения (`store.observation`) аналитик либо сохраняет как проект по умолчанию, либо обосновывает в SPEC иное. Задача несуществующая — прежний отказ.
2. Дозор (`watch --observation`) показывает события всех задач наблюдения и алерты проектов этих задач, а также алерты уровня пульта (проект артели) — без потери сегодняшних событий у наблюдения одного проекта.
3. `status` показывает проект задачи (короткой меткой, например `[sled]`, для задач не артели; у артели строка не меняется — либо аналитик обосновывает новую колонку для всех); `report` — проект на плитке задачи.
4. Команды, требующие членства задачи в наблюдении (`run`, `auto --observation`), принимают задачу внешнего проекта в наблюдении, заведённом на артель, и наоборот.
5. У наблюдения одного проекта поведение `observe`/`watch` не меняется; зафиксировать тестами до правки.
6. Тесты детерминированы, без сети: наблюдение с задачей артели и задачей внешнего проекта — `observe add` принимает обе; `watch` выдаёт события обеих и алерт пульта; `status` показывает метку проекта внешней задачи.

Критерии приёмки:
- одно наблюдение ведёт задачи артели и внешнего проекта одним `watch`;
- `status` и `report` различают проект задачи;
- у наблюдения одного проекта — прежнее поведение.

Зоны: `orchestrator/artel.py`, `orchestrator/watch.py`, `orchestrator/catalog.py`, `orchestrator/report.py`, `tests/`.

Только чтение: `orchestrator/store.py`, `orchestrator/alerts.py`, `orchestrator/doctor/`, `docs/backlog.md`. Правка вне зон (в том числе схемы БД) — эскалация до SPEC.

Не входит: окно тишины и мьютекс мержа по проекту (отдельные задачи); уборка задачи внешнего проекта после kill.

Рамка: $30. Набор моделей — по умолчанию.

# ТЗ: B1b: GitHub-адаптер, Draft-MR и состояние verifying

# ТЗ: B1b — GitHub-адаптер, Draft-MR-флоу, состояние verifying

Источник: роадмап §3 «Фаза B», строка B1b; критический путь §4 п.3.

Построить внешний GitHub-контур конвейера поверх изоляции обвязки
целевого из B1a (T069):

1. GitHub-адаптер целевого (семейство `forge: github` из targets.yaml)
   для операций конвейера: ветка задачи, Draft-MR, чтение статусов
   CI (check-runs), merge. Первый прогон — на самой артели (догфуд,
   ADR-0003 3д).
2. Draft-MR-флоу: MR заводится черновиком при старте разработки,
   переводится в готовый на merge_gate.
3. Новое состояние FSM `verifying` — ожидание CI между ревью
   и merge_gate. Первый обитатель — ожидание завершения проверок CI.
4. В объём ВКЛЮЧИТЬ строку P3 «CI-события GitHub теряются»
   (фактура 26.08, T040): в `verifying` различать «проверок нет
   вообще» (пуш не породил check-runs; ждать с потолком и внятной
   подсказкой; `gh run list` по ветке — второй источник против
   check-runs коммита) и «проверки идут». Ветку не «будить» пустыми
   коммитами — это ломает approve-по-sha.
5. Учесть остаток T052 (возврат из merge_gate): связка возврата
   с verifying/await-ci.

Границы: песочница (B3), креды в контейнере — вне объёма (B-спайк).
Пути no_paths целевого не трогать. Оценка рамки: $25+15 (роадмап).

# SPEC: Единая тестовая песочница: FakeProc, claude-only моки, TmpRootTest

## Контекст

Ревизия 28.08 (находка CR-2026-08-28-2, ★5, самая дорогая находка
очереди, docs/audits/code-revision-2026-08-28.md) фиксирует второе
поколение копипасты тестовых обвязок мимо общей песочницы T037
(`tests/sandbox.py`): класс `FakeProc` продублирован по тестовым
файлам вместо импорта, claude-only side_effect (фейк только для
запуска `claude`, настоящий git — и для `run`, и для `Popen`) собран
заново в нескольких местах вместо общего хелпера, а часть файлов,
появившихся после T037, патчит своё подмножество путей `config`
вручную вместо наследования `sandbox.TmpRootTest` — непропатченный
путь означает тихую утечку теста на реальное дерево пульта
(тот же класс проблемы уже стоил CR-2026-08-26-3). Задача доносит
песочницу T037 до этих файлов и хелперов.

## Требования

1. В `tests/sandbox.py` появляется единый класс `FakeProc` с текущим
   контрактом (`__init__(self, lines, returncode)`; `stdout` — поток
   заготовленных строк; `wait(timeout=None)` возвращает `returncode`).
   Все локальные определения `class FakeProc` в `tests/*.py` (кроме
   `tasks/*/acceptance_tests` — см. «Не входит») заменяются на импорт
   из `tests.sandbox`.
2. В `tests/sandbox.py` появляется единая пара claude-only хелперов
   side_effect — один для `subprocess.run`, один для `subprocess.Popen`
   / `runner.spawn_agent`: фейк отвечает только на вызов `claude`,
   всё остальное (включая git-вызовы того же общего модуля
   `subprocess`) уходит в настоящий вызов. Локальные копии в
   `tests/test_git_fixation.py` (2 инлайн-closure) и
   `tests/test_doctor.py` (`claude_only_run`, `claude_only_popen`)
   заменяются на импорт.
3. Файлы `tests/test_brief.py`, `tests/test_fsm_map_regen.py`,
   `tests/test_fsm_retro.py`, `tests/test_fsm_branch_correct_status_reads.py`,
   `tests/test_gitcmd_branch_reads.py`, `tests/test_retro.py`
   переходят на наследование `sandbox.TmpRootTest` с полным набором
   подменяемых путей `config` (`sandbox.ALL_CONFIG_ATTRS`) — точечный
   `mock.patch.object(config, attr, value)` по своему подмножеству
   путей в них не остаётся.
4. Локальные хелперы `fake_git*` в `tests/test_fsm_retro.py`,
   `tests/test_fsm_map_regen.py` и `tests/test_brief.py` заменяются на
   `sandbox.fake_git`; там, где сценарию нужно поведение, которого
   `sandbox.fake_git` не покрывает (например, имитация упавшей
   git-команды), используется общий параметризуемый фейк в
   `tests/sandbox.py`, а не новая локальная копия.
5. Поведение тестов не меняется: сценарии и ассерты — как были;
   допустимые изменения — импорты, базовый класс песочницы и пути
   патчей. Ревьюер сверяет это по диффу.
6. Дедупликация — только идентичных или заведомо эквивалентных кусков;
   попутные улучшения и расширения объёма задачи не допускаются.
7. Изменения — только в `tests/` (включая `tests/sandbox.py`);
   `orchestrator/` и `scripts/` не трогаются. Карта кодовой базы не
   регенерируется (задача не касается модулей, которые она описывает).
8. PLAN.md несёт таблицу переносов по файлам (файл → что переносится →
   куда); откат в проде — revert одного merge-коммита задачи.
9. До начала переноса фиксируется фактическое число тестов полного
   прогона `unittest` в текущем main (ориентир ТЗ — 820, но после T060
   в main могло измениться); после переноса число тестов идентично
   зафиксированному, весь прогон зелёный.

## Критерии приёмки

AC-1. `class FakeProc` определён один раз — в `tests/sandbox.py`; grep
по `tests/*.py` (вне `tasks/`) не находит других определений.

AC-2. claude-only side_effect существует единственной парой хелперов
в `tests/sandbox.py` (для `run` и для `Popen`); локальные копии в
`tests/*.py` удалены.

AC-3. Шесть перечисленных в требовании 3 файлов наследуются от
`sandbox.TmpRootTest` (либо используют его полный набор путей);
ручного частичного патчинга `config` в них нет.

AC-4. Полный прогон `unittest`: число тестов идентично зафиксированному
до начала переноса, все тесты зелёные, ассерты не менялись (сверка по
диффу).

## Не входит

- Правка `orchestrator/` и `scripts/`.
- Правка приёмочных тестов прошлых задач (`tasks/*/acceptance_tests`)
  — их клоны хелперов остаются как есть (залоченные каталоги).
- Изменение семантики какого-либо теста.
- Любые попутные улучшения тестового кода за пределами переноса на
  общую песочницу (новые проверки, рефакторинг несвязанной логики,
  расширение покрытия).

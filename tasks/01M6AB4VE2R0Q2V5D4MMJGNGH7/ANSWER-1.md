# ANSWER-1: ответ Оператора

## Ответы

Уточнения сессии при Операторе (права волны G) к SPEC Б2.2 по второму аудиту, 01.11.2026. SPEC не меняется; это толкование требований для автора тестов и разработчика.

Правка константы `HINT` (подсказка «(шаг Б2.2)» в тексте отказа `awaiting_human`) — по мандату Оператора 26.10 на тесты, которые меняет ADR-0029; без ослабления: проверки файла остаются, меняется только ожидаемый текст подсказки.

Ослабление тестов разрешено: tests/test_01m5xz9z68v75vxf5z66c708t4_awaiting_commands.py

1. **Б-3.** «MR не найден» — ответ хостинга 404 на `GET` MR (`forge.MergeRequest.reason` с кодом 404); прочие отказы `forge` — итог «неизвестно». В таблице итогов «MR не найден» и «MR переведён на другую ветку» — первыми, «неизвестно» — после них.
2. **Б-2.** sha закрытия по (б) — самый поздний коммит `origin/<base>` после точки ответвления, чей `git patch-id --stable` совпадает с patch-id последнего коммита задачи; не найден однозначно — признак (б) не засчитывается.
3. **Е-1.** Признак (а) засчитывается только при статусе MR «влит»; при открытом MR (а) не применяется, `--confirm` по (а) отказывает.
4. **В-1.** AC-3: добавить сценарий «точка ответвления записана, затем base ушёл вперёд через вливание этой правки» — используется записанная точка, а не пересчёт `merge-base`.
5. **Б-4.** Цикл `auto <id>` в `awaiting_human` не живёт (как сейчас). Опрос по `policy.mr_sync_interval_min` — только в надзоре эпика (`auto --epic`); вне эпика — только ручной `mr-sync`.
6. **Б-5/Е-2.** «Принятая голова» записывается в `fsm._approve_escalated` только когда эскалация вызвана инцидентом «чужой коммит» (по записи журнала этой эскалации); иная эскалация голову не принимает — отрицательный AC.
7. **Б-1.** Сверка ссылки документов на `--confirm` — тот же узел, что путь `done` (`fsm_merge_gate.py:1512`); текст отказа без подсказки `approve`: «ссылка документов не сверена с origin: <причина>; повтори mr-sync <id> --confirm после docs --fetch-all».
8. **В-2.** На `--confirm` локальная ветка задачи убирается вместе с рабочей копией, как на пути `done`; ветка на сервере и MR не трогаются.

Ответ на эскалацию автора тестов (AC-17): см. п. 5 — опрос `mr-sync` по `policy.mr_sync_interval_min` исполняет только надзор эпика (`auto --epic`); AC-17 проверяется на надзоре эпика с подменёнными часами и шпионом `mr-sync`, цикл `auto <id>` в `awaiting_human` не заводится.

Независимая проверка: аудит SPEC 01M6AB4VE2R0Q2V5D4MMJGNGH7 (замечание А-1) — меняется только ожидаемый текст подсказки отказа в `awaiting_human`; число тестов и проверок файла прежнее, проверка отказа остаётся.

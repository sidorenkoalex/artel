# SPEC: Сессия при Операторе в чате Codex: запуск и дозор задач штатными командами

## Контекст

Пульт уже принимает `codex` как клиента отсоединённых `run` и `auto`, но
инструкция сессии при Операторе описывает только Claude Code и запрещает
ведение задач из Codex. Из-за этого в Codex отсутствует штатный непрерывный
дозор: события эскалации и отказы переходов не доходят в чат, пока Оператор
не спросит статус. Нужен проверяемый порядок ведения задач из Codex без
изменения состояния задач механизмом уведомления.

## Требования

1. Штатный порядок «зарегистрировать наблюдение → поставить наблюдателя →
   проверить свежесть → запустить `auto`/`run` → остановить» доступен из
   чата Codex с `--client codex --chat "$CODEX_THREAD_ID"`. Подсказки
   `cycle_hint` и тексты отказов `run`, `auto` и `observe` для Codex называют
   `$CODEX_THREAD_ID`, а для Claude Code — `$CLAUDE_CODE_SESSION_ID`.
2. Для Codex выбран синхронный штатный Stop-хук: он запускает и держит
   канонический `watch --observation <ID>` для наблюдения данного чата, так
   что heartbeat наблюдения остаётся свежим между ходами сессии. При новом
   событии из этого наблюдения хук возвращает штатное продолжение хода Codex;
   способ подтверждается живой проверкой в Codex 0.157. Фоновый пользовательский
   `~/.codex/hooks/project-monitor` не является частью решения.
3. В репозитории есть образец настроек рабочего места Оператора для Codex и
   штатная команда пульта для установки, проверки и снятия механизма доставки.
   Установка выдаёт необходимое доверие хуку, повторный вызов не меняет
   конфигурацию, снятие восстанавливает исходный файл, а чужие пользовательские
   хуки не изменяются. Ни хук, ни доставка не меняют состояние задач, БД,
   гейты и не запускают задачи.
4. Механизм доставки выдаёт продолжение хода только для события задачи из
   набора наблюдения текущего чата и проекта. Для другого чата, вне каталога
   проекта, в окружении роли (`runner.in_role_environment`) и после остановки
   наблюдения он ничего не выдаёт.
5. Локальный PreToolUse-хук `guard-artel-bg`, требующий отсутствующее в Codex
   поле `run_in_background`, снимается штатной командой `hook-migrate`.
   Выбран вариант снятия, а не совместимая замена: `hook-migrate` уже адресно
   распознаёт этот хук и сохраняет остальные подключения, тогда как его
   ограничение относится к протоколу Claude Code и мешает штатному запуску
   из Codex.
6. `doctor` сообщает готовность рабочего места Codex: механизм доставки
   установлен и доверен, а мешающий хук отсутствует. Эта проверка действует
   только когда сессия Оператора заявлена для Codex активным наблюдением с
   `client=codex` либо явным флагом.
7. `docs/operator-session.md` заменяет запрет на сессии при Операторе в
   Codex и описывает порядок фоновых запусков и таблицу отказов для обоих
   клиентов. `docs/stack.md` описывает клиента сессии Оператора.

## Критерии приёмки

AC-1. Для `--client codex` подсказки и отказы называют
`$CODEX_THREAD_ID`; для `--client claude` они называют
`$CLAUDE_CODE_SESSION_ID`.

AC-2. После регистрации наблюдения Codex штатный Stop-хук поддерживает
свежесть его связи во время ведения задач и при новом событии задачи из
набора этого наблюдения выдаёт штатное продолжение хода Codex.

AC-3. Команда установки доставки помещает образец в заданный каталог
настроек Codex и выдаёт ему доверие; повторная установка не меняет файл,
снятие восстанавливает исходный файл, а чужие пользовательские хуки остаются
без изменений.

AC-4. Доставка не выдаёт продолжение для другого чата, вне каталога проекта,
в окружении роли (`runner.in_role_environment`) или после остановки
наблюдения; при этом она не меняет состояния задач, БД, гейты и не запускает
задачи.

AC-5. `hook-migrate` снимает адресный PreToolUse-хук `guard-artel-bg`, не
затрагивая соседние подключения, и после снятия штатный запуск из Codex не
блокируется требованием `run_in_background`.

AC-6. При заявленной сессии Codex `doctor` сообщает, установлена ли и доверена
ли доставка и отсутствует ли мешающий хук; при незаявленной сессии Codex эта
проверка не срабатывает.

AC-7. В `docs/operator-session.md` дан единый порядок фоновых запусков и
таблица отказов для Codex и Claude Code, а в `docs/stack.md` описан клиент
сессии Оператора.

AC-8. В живом чате Codex с версией 0.157 зарегистрировано наблюдение на
задачу, запущен `auto`, и при эскалации либо гейте событие появляется в чате
без запроса Оператора о статусе. Проверку выполняет Оператор или сессия при
нём до approve приёмки.

## Оценка объёма и деление

Сработали сигналы: зон задачи не менее пяти и `budget_usd` не ниже $30.

**Обоснование монолита.** Порядок запуска, постоянный heartbeat, доставка
события Stop-хуком, безопасное снятие конфликтующего хука, условная проверка
`doctor` и инструкция — одна атомарная гарантия управляемой сессии Codex.
Промежуточный мерж любой отдельной части либо направляет Оператора в
неработающий порядок (без установленной и доверенной доставки), либо скрывает
неготовое рабочее место, либо оставляет блокирующий PreToolUse-хук. Отдельно
изменённые документы также не могут честно объявить Codex равноправным
клиентом до готовности механизма доставки и дозора.

## Не входит

- Роли конвейера на моделях Codex, включая `model_sets.yaml` и ошибку доступа
  `suite-run` у роли на Codex.
- Отключение Claude Code как клиента.
- Канарейка.
- Полный набор `tests/`, зелёный CI ветки, неизменность защищённых путей и
  соблюдение бюджета: эти проверки держит пульт.

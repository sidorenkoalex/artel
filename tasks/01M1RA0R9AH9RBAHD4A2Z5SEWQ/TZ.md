# ТЗ: перегенерированная карта после шага роли не ломает подтяжку main

Источник: наблюдение 05.09 (копилка роадмапа §4 п.8б). Роли
перегенерируют `docs/codebase-map.md` в worktree по правилу «после
правки *.py» и часто оставляют её незакоммиченной (карту коммитит
пульт на мерже). На следующем переходе подтяжка main
(`fsm._pull_main_or_escalate`) получает от git «Your local changes to
the following files would be overwritten by merge» и уводит задачу в
escalated как «конфликт подтяжки» — так дважды за день (зоны часть 3,
плавающий тест) готовые к приёмке задачи ушли в эскалацию, а помощник
Оператора вернул их в разработку.

Требуется:
1. Перед подтяжкой main пульт приводит worktree в чистое состояние по
   правилу: незакоммиченная `docs/codebase-map.md` отбрасывается
   (`git checkout -- docs/codebase-map.md`, карту всё равно
   перегенерирует и закоммитит мерж), прочие незакоммиченные правки —
   WIP-чекпоинт по мандату роли (механика 01M1NBWTSX…), не отказ.
2. Отказ подтяжки «local changes would be overwritten» после этого
   невозможен; если всё же случился — журнал называет файлы и это
   инцидент (`kind=incident`), не «конфликт подтяжки».
3. Тесты: worktree с изменённой картой подтягивается без эскалации;
   worktree с изменённым кодом роли получает WIP-чекпоинт и
   подтягивается; настоящий конфликт содержимого по-прежнему
   эскалируется как сейчас; существующие тесты подтяжки (T067, №5)
   зелёные без ослабления.

Зоны: orchestrator/fsm.py (`_pull_main_or_escalate`), orchestrator/
checkpoint.py (переиспользование WIP-чекпоинта), tests/. Пересечение
с B2 ТЗ-1 по fsm.py — код этой задачи короткий, идёт первым.
Не входит: правило регенерации карты в скилах ролей.

Рамка: $10.

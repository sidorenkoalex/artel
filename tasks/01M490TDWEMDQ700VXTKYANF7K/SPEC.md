# SPEC: guard --all принимает паспорт задачи артели без frontmatter

## Контекст
С мержа части 3 этапа 3 ADR-0021 (01M484RNV3QBDY3B0M16J916ZP) паспорт
задачи `tasks/<id>/PASSPORT.md` ведётся и у задач артели, а снимок
артефактной ветки ложится на main. Паспорт пишет пульт: заголовок
«# Паспорт живой задачи» и строки «<время> <состояние> actor=<кто>»,
frontmatter у него нет. `scripts/guard.py --all` (`main`, ~3764) пропускает
паспорт через белый список первого уровня `TASK_ROOT_ALLOWED_MD` (~1674), но
затем отдаёт его в проверку артефакта и отказывает «нет frontmatter» (~3657).
Гейт мержа зовёт `guard --all` по дереву мержа
(`orchestrator/fsm_merge_gate.py::_guard_all_violations`), поэтому мерж любой
задачи артели сейчас отказывает (06.10, задача 01M48FRD9RJDBBVT2SN0FY5G2A).
Правка guard в ветке задачи действует уже на её собственном мерже.

## Требования
1. `scripts/guard.py --all` не проверяет frontmatter и обязательные разделы у
   файла `tasks/<id>/PASSPORT.md` первого уровня каталога задачи: паспорт —
   не артефакт роли. Прочие проверки не ослабляются: посторонний `.md`
   первого уровня — по-прежнему отказ «посторонний файл в каталоге задачи»;
   `PASSPORT.md` в любом другом месте (`acceptance_tests/`, вложенный
   каталог первого уровня) — по-прежнему посторонний с прежней причиной;
   артефакты рядом с паспортом проверяются как раньше.
2. Проверка одиночного файла `scripts/guard.py tasks/<id>/PASSPORT.md` (без
   `--all`) ведёт себя так же, как `--all`: без ложного отказа. Решение SPEC
   (ТЗ оставило выбор): пропуск с пометкой — guard завершается кодом 0 и
   печатает строку `<путь>: паспорт задачи, не артефакт роли — пропущен`.
   Паспортом считается файл с именем `PASSPORT.md`, чей каталог лежит
   непосредственно в каталоге `tasks` (первый уровень каталога задачи);
   файл `PASSPORT.md` в любом другом месте проверяется как прежде.
3. Тесты в `tests/` с заявками «Ловит мутацию» закрепляют требования 1–2:
   дерево `tasks/` с паспортом без frontmatter и корректными артефактами —
   `guard --all` код 0; тот же паспорт под другим именем первого уровня —
   отказ «посторонний файл»; `SPEC.md` без frontmatter рядом с паспортом —
   по-прежнему отказ «нет frontmatter». Требование закрывают долгоживущие
   приёмочные тесты задачи в `tests/` (ADR-0020) по критериям ниже;
   повторять те же свойства отдельным тестом в `tests/` не нужно.

## Критерии приёмки

AC-1. Дерево `tasks/` с каталогом живой задачи (нет `docs/retro/<id>.md`),
в котором лежат корректный по guard артефакт (например `SPEC.md`) и
`PASSPORT.md` без frontmatter (заголовок «# Паспорт живой задачи» и строки
вида «<время> <состояние> actor=<кто>»): `scripts/guard.py --all`,
запущенный из корня этого дерева, завершается кодом 0, и в выводе нет
нарушения по `PASSPORT.md`.

AC-2. То же дерево, но содержимое паспорта лежит под другим именем `.md`
первого уровня каталога задачи (например `JOURNAL.md`), не входящим в белый
список: `guard --all` завершается кодом 1, в выводе — строка
`<путь>: посторонний файл в каталоге задачи` для этого файла.

AC-3. Дерево AC-1, в котором `SPEC.md` рядом с паспортом лишён frontmatter:
`guard --all` завершается кодом 1, в выводе — нарушение «нет frontmatter»
для `SPEC.md`; нарушения по `PASSPORT.md` в выводе нет.

AC-4. Файл `PASSPORT.md` без frontmatter в `tasks/<id>/acceptance_tests/`
живой задачи: `guard --all` завершается кодом 1, в выводе — строка
`<путь>: посторонний файл в каталоге планки` для этого файла.

AC-5. Файл `PASSPORT.md` без frontmatter во вложенном каталоге первого уровня
(например `tasks/<id>/wip/PASSPORT.md`): `guard --all` завершается кодом 1,
в выводе — строка `<путь>: посторонний файл в каталоге задачи` для этого
файла.

AC-6. `scripts/guard.py tasks/<id>/PASSPORT.md` (одиночный файл, без
`--all`) на паспорте без frontmatter завершается кодом 0, и в выводе есть
строка `tasks/<id>/PASSPORT.md: паспорт задачи, не артефакт роли — пропущен`;
отказа «нет frontmatter» нет.

AC-7. `scripts/guard.py tasks/<id>/acceptance_tests/PASSPORT.md` (одиночный
файл не первого уровня каталога задачи, без frontmatter) завершается кодом 1
с нарушением «нет frontmatter» — как до правки.

## Оценка объёма и деление
Прогноз диффа: 8 КиБ

Сработавший сигнал: зона `scripts/guard.py` задевает механизм, на который
опирается запись `docs/invariants.md` (guard структуры артефактов). Прочие
сигналы молчат: одна кодовая зона, 7 критериев, `budget_usd` 25.

Обоснование монолита: правка — одно узкое исключение в обходе guard
(паспорт первого уровня не идёт в проверку артефакта) и тот же признак в
режиме одиночного файла. Если её разрезать, часть без исключения в `--all`
оставляет мерж любой задачи артели заблокированным, а исключение без
тестов-сторожей не закрывает требование 3 ТЗ. Делить нечего.

## Не входит

- Формат паспорта и его запись пультом (`orchestrator/artifact_branch.py`).
- Правка задач 01M48FRD9RJDBBVT2SN0FY5G2A и 01M48WR0HKZW8KJCBWDZTFC4ZY: их
  мерж Оператор повторит после мержа этой задачи.
- Правка `orchestrator/fsm_merge_gate.py`, `tasks/`, `conftest.py`,
  `tests/test_invariants.py`, `docs/invariants.md`, `docs/adr/`,
  `templates/`, `skills/` и прочих путей «только чтение» ТЗ.
- Неослабление существующих тестов — его держит пульт (гейт неослабления
  тестов), отдельного критерия нет.

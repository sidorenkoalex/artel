## Проверяемость критериев

| Критерий | Проверяем | Ловимая мутация |
|---|---|---|
| AC-1 | да | фикстура отдаёт подкласс/не тот класс (например, `tmp_root` → `InitializedTmpRootTest`) или экземпляр без `setUp()` |
| AC-2 | да | `tmp_dir` не исполняет уборку — каталог остаётся после завершения |
| AC-3 | да | уборка не исполняется/исполняется не полностью — `config.<attr>` остаётся подменённым, корень не удалён |
| AC-4 | да | сбор ошибок уборки и `RuntimeError` убраны; первое упавшее действие обрывает остальные; сообщение без класса/`repr` |
| AC-5 | да | при падении `setUp()` уборка не исполняется; исходное исключение подменено (`RuntimeError` уборки вместо него); ошибки уборки не добавлены заметкой |
| AC-6 | да | `import tests.sandbox` на уровне модуля `tests/fixtures.py` (меняет `TWO_SIDED_OBSERVATION` с `True` на `False`, `config.ROLES`, `shutil.which`) |
| AC-7 | да | фикстура не объявлена `@pytest.fixture` / переименована / модуль не грузится как плагин при флагах гейта |
| AC-8 | да, слабо | экземпляр без `setUp()` (AttributeError на `self.root`/`self.TASK`) — то же ловит AC-1; значение результата критерий не фиксирует |
| AC-9 | да | файл тестов в виде `unittest.TestCase`; функция без «Ловит мутацию:»; правка `tests/sandbox.py` или существующих файлов `tests/` |

Отклонение C-1: требование 2 задаёт обратный порядок вызова действий уборки
(SPEC, «Требования», п.2), но ни один AC его не проверяет. Мутация «действия
вызываются в порядке регистрации» проходит AC-2…AC-5: у сегодняшних классов
патчи стоят на разных атрибутах и конечное состояние `config` совпадает, а
при двух патчах одного атрибута (например, `use_role_map` поверх уже
подменённого атрибута) прямой порядок оставит промежуточное значение.
Варианты: дополнить AC-4 проверкой порядка (два действия, добавленные
тестом через `addCleanup`, пишут в список; ожидается обратный порядок) или
принять как есть.

Замечание без отклонения: AC-8 не фиксирует ожидаемый результат (например,
`git("rev-parse", "--abbrev-ref", "HEAD")` → `main\n`, `state()` → начальное
состояние задачи); отдельной мутации, которую поймал бы только AC-8, не
нахожу — его роль покрывают AC-1 и AC-3.

## Пути обхода гейтов
- AC-7 буквально: «временный проект с `conftest.py`… фикстура из
  `tests.fixtures` видна». Исполнитель мог бы положить во временный проект
  собственный модуль-заглушку `tests/fixtures.py` — проверка видимости тогда
  ничего не говорит о настоящем модуле. Формулировка «фикстура из
  `tests.fixtures`» читается как настоящий модуль артели (через `sys.path`/
  `PYTHONPATH` на корень рабочей копии); ревью стоит сверить. Отдельным
  отклонением не поднимаю: SPEC называет модуль однозначно.
- Требование 2 «обратный порядок» — без AC (C-1 выше): реализация в прямом
  порядке пройдёт планку.
- Иных путей не нашёл: AC-1 (`type is`) закрывает подмену класса,
  AC-4/AC-5 — тихий успех уборки, AC-6 — импорт на уровне модуля, AC-9 —
  правку существующих тестов.

# ТЗ: ADR-0014, часть 2 — однократная переоценка бюджета на PLAN

Деление по решению Оператора 06.09 (гейт SPEC родителя, часть 2).
Нормативные тексты — ADR-0014 п.3 и SPEC родителя
(`artifact/01m1shdcw7fgjptmd0fsfwgz5s`,
`tasks/01M1SHDCW7FGJPTMD0FSFWGZ5S/SPEC.md`): требование 6,
PLAN-половина 7–8, часть 10 (скил разработчика); критерии AC-6..AC-9,
AC-11 (второе предложение), AC-12, AC-14 (PLAN-сценарии), AC-15 (диф
скила разработчика). Опирается на часть 1 (`ROLE_BUDGET_CAP`, общая
guard-проверка потолка ролей для SPEC и PLAN, поле `budget_usd` в
`templates/PLAN.md`). Старт — после мержа части 1.

Кратко:
1. `fsm_advance.in_dev`: при ПЕРВОЙ сдаче PLAN (`status: ready`,
   `review_iters == 0`, переоценки ещё не было) `budget_usd` из PLAN
   применяется один раз и только вверх, не выше `ROLE_BUDGET_CAP`,
   `budget_source = plan`, журнальная запись (старый, новый потолок,
   источник). PLAN без поля потолок не меняет; значение ниже текущего —
   не применяется с записью «не применён: ниже потолка»; после возврата
   из ревью или приёмки повторная сдача потолок не трогает; потолок
   `budget_source = operator` не перебивается. Значение выше потолка
   ролей — отказ guard из части 1, нового кода не заводится.
2. `docs/invariants.md`, инвариант 10 — PLAN-часть формулировки;
   `tests/test_invariants.py`: PLAN выше `ROLE_BUDGET_CAP` не поднимает;
   переоценка не более одного раза и не после возврата; потолок
   Оператора PLAN не перебивается.
3. Приложением к PLAN: диф скила разработчика (правило однократной
   переоценки: по числу файлов и шагов, только при расхождении с
   оценкой SPEC, обоснование в «Подходе»).
4. Тесты: PLAN $90 при потолке $45 на первой сдаче — потолок $90
   (`plan`); повторная сдача с $100 после возврата — без изменений; PLAN
   $30 при $45 — не применён; потолок Оператора $60 не перебивается.

Зоны: orchestrator/fsm_advance.py, docs/invariants.md, tests/.
Порядок: после части 1.
Не входит: всё из части 1; авто-подъём при исчерпании; стоп-лосс.

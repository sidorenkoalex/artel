# ТЗ: auto — единые правила «отказ, который чинит роль → повтор шага роли»; run продвигает состояние

Источник: бэклог — строка «auto: единые правила «отказ → повтор роли» и
run с advance» (приоритет 1, $35); прецеденты 04.10.2026 (задача
01M443HPZBMJGCHVGV4JQN88RS: отказ гейта заявки мутации остановил `auto`,
Оператор вручную делал `run`, `advance`, `auto`; этап 2 ADR-0021: пять
шагов developer через `run` и ручные `advance`). Решение Оператора 04.10
«заводи волну один».

Факты (пин 0a87c8b0, сверка кода 04.10):
- Решение «повторить роль или остановиться» после отказа перехода —
  `orchestrator/auto.py::_pre_advance_step` (~820-970). Роль
  перезапускается только на отказах из двух перечней:
  `ROLE_NOT_FINISHED_REFUSAL_ACTIONS` (~294: «замечания ревью не
  отработаны», «дерево не на ветке задачи») и
  `_IN_DEV_ROLE_FIXABLE_REFUSAL_ACTIONS` (~319: «мандат есть, раздел PLAN
  не оформлен», «приложение PLAN неприменимо»). Любой другой отказ в
  `in_dev` — `other_class_refusal` (~937): первый раз `Refused` без шага
  роли, второй такой же — остановка «почини причину и повтори
  artel.py advance» (~941).
- Отказ guard'а артефакта (`fsm.cmd_advance` вернул истину, ~838) —
  немедленная остановка в любом состоянии.
- Гейт заявки мутации — `orchestrator/advance_gates/review.py::
  _mutation_claim_gate` (~180-273): один текст действия «переход отклонён:
  гейт заявки мутации» и для отсутствия заявки (чинит роль), и для сбоя
  git (~207, ~215, ~257 — не чинит роль).
- `run` (`orchestrator/runner.py` ~1699) печатает «дальше: artel.py
  advance <id>» и состояние не двигает; флага продвижения нет
  (`orchestrator/artel.py` ~796, `_cmd_run_or_detach`).
- Ограничители уже есть: `config.AUTO_MAX_STEPS` = 30,
  `config.AUTO_STALL_STEPS_LIMIT` = 5,
  `_role_step_between_repeated_refusals` (~794: роль получает одну
  попытку на отказ, который она чинит).

Требуется:
1. Отказы переходов делятся на два класса явно, одним перечнем рядом с
   гейтами: «чинит роль» (недостаток артефакта или кода текущей роли) и
   «чинит Оператор» (решение, мандат, бюджет, сбой окружения, git,
   push). SPEC перечисляет каждый существующий отказ `in_dev`, `review`,
   `tests_writing`, `spec_writing` и его класс.
2. На отказ класса «чинит роль» `auto` запускает шаг текущей роли, текст
   отказа (действие и подробность журнала) попадает в бриф этого шага;
   повтор того же отказа после шага роли — остановка (как сейчас у
   `_role_step_between_repeated_refusals`). На отказ класса «чинит
   Оператор» — остановка с именем причины.
3. Один текст действия гейта не смешивает классы: у гейта заявки
   мутации отсутствие заявки и сбой git дают разные действия журнала
   (или иной различимый признак), первый — «чинит роль», второй —
   «чинит Оператор». SPEC проверяет остальные гейты на то же смешение.
4. Отказ guard'а артефакта текущей роли (дефект формата её артефакта) —
   класс «чинит роль»: один повтор шага с текстом отказа в брифе, затем
   остановка.
5. `run <id>` после успешного шага роли (rc=0) один раз выполняет
   `advance`, если задача в агентском состоянии; исход `advance`
   печатается. Отказ перехода здесь не запускает новый шаг (это дело
   `auto`). SPEC решает, нужен ли флаг отключения.
6. Существующие ограничители (`AUTO_MAX_STEPS`, `AUTO_STALL_STEPS_LIMIT`,
   две эскалации подряд по конфликту подтяжки) сохраняются.
7. Тесты в `tests/` с заявками «Ловит мутацию» на пп. 1–5, в том числе:
   отказ гейта заявки мутации из-за отсутствия заявки — шаг developer с
   текстом отказа в брифе; сбой git того же гейта — остановка; отказ
   класса «чинит Оператор» — остановка без шага роли; `run` после шага
   двигает состояние. Существующие тесты не ослабляются.

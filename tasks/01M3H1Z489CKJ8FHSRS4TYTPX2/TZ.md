# ТЗ: Предварительные зоны и предупреждение о пересечении для подзадач деления

Источник: строка бэклога 27.09 «Предварительные зоны для подзадач
деления» (docs/backlog.md), из «Предложений системе» PLAN задачи
01M3GKJ84XM5QPC6TK5EE307Q9. Пробная задача: SPEC этой задачи пишет роль
analyst на провайдере Codex (решение Оператора 27.09, план провайдеров
раздел 7.1); разработка, тесты и ревью — как обычно.

Факты (origin/main a6da0abe):
- `cmd_new` (orchestrator/catalog.py::cmd_new) после общего скелета
  `_new_task_row` пишет зоны строки «Зоны:» ТЗ в колонку `tasks.zones`
  как предварительные (`_record_preliminary_zones`, запись журнала
  `PRELIMINARY_ZONES_ACTION`) и печатает предупреждение о пересечении зон
  с задачами в полёте (`_warn_zone_overlap`, фильтр по target).
- `spawn_subtask` (orchestrator/catalog.py::spawn_subtask) заводит
  подзадачу деления тем же скелетом `_new_task_row`, но ни
  `_record_preliminary_zones`, ни `_warn_zone_overlap` не вызывает: ТЗ
  подзадачи (`tz_body` — подраздел секции «## Деление» родителя с полями
  «Зоны:», «Порядок:», «Рамка:») кладётся в TZ.md как текст. Колонка
  `zones` подзадачи пуста до approve на её гейте SPEC, и прогноз очереди
  зон (`new`, `status`, orchestrator/zone_lock.py) подзадач не видит —
  а подзадачи одного деления и есть волна с пересекающимися зонами.
- Вызывает `spawn_subtask` только `orchestrator/fsm.py::_approve_spec_gate`
  при заведении деления (не публичный CLI-путь).
- Разбор строки «Зоны:» — `_tz_zone_items` (один разбор с `_tz_path_check`,
  склейка разорванного переносом пути `_TZ_WRAPPED_PATH_BREAK`).

Требуется:
1. `spawn_subtask` после `_new_task_row` записывает предварительные зоны
   подзадачи из строки «Зоны:» её `tz_body` тем же `_record_preliminary_zones`,
   что и `cmd_new` (одна реализация, без копии разбора); пустая или
   отсутствующая строка «Зоны:» колонку не трогает (как у `cmd_new`).
   Строка «Родительская задача: …», добавляемая первой в TZ.md, разбору
   зон не мешает.
2. Предупреждение о пересечении зон для подзадачи: тем же
   `_warn_zone_overlap`, с target подзадачи; пересечение с родителем и с
   подзадачами того же деления, заведёнными раньше в этом же вызове,
   печатается и пишется в журнал подзадачи как у `cmd_new`. Отказом не
   становится (деление сознательно кладёт зоны рядом).
3. Порядок вызовов в SPEC: зоны записываются до предупреждения (иначе
   вторая подзадача не увидит первую); обосновать, где в
   `spawn_subtask` встают оба вызова относительно `update_task(parent_task_id)`.
4. Документация: docs/stack.md — в разделе о заведении задач и прогнозе
   очереди зон одно предложение о подзадачах деления.
5. Тесты (tests/): подзадача с «Зоны:» получает `tasks.zones` и запись
   журнала предварительных зон; подзадача без «Зоны:» — колонка NULL;
   две подзадачи одного деления с общим путём — у второй предупреждение
   с id первой; существующие tests/test_catalog_spawn_subtask.py,
   tests/test_catalog_zone_overlap.py, tests/test_zone_lock_forecast.py
   зелёные, ни один не ослаблен.

Зоны: orchestrator/catalog.py, docs/stack.md, tests/.

Только чтение (не менять): orchestrator/fsm.py (вызов `spawn_subtask`
не меняется), orchestrator/zone_lock.py, orchestrator/store.py,
scripts/guard.py, docs/backlog.md, tests/test_invariants.py.

Не входит: изменение формата секции «## Деление»; строгий режим
(отказ) при пересечении; правка `cmd_new`.

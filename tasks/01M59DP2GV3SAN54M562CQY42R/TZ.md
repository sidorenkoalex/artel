# Метрика «круги до кода»: аудиты SPEC, возвраты и эскалации на задачу — в report и оповещение по порогу

## Факты

Разбор ночи 18–19.10.2026: у задач волны G было 3–4 круга аудита SPEC и 1–2 эскалации с вопросами на задачу (G1а 01M58FNWBV25FF26E7AZ9Q9912, G1а-2 01M58PG72PG64GS790XM2EWS61, G1б 01M590GJAF0EDV4NBC4C99MFVH). Это было видно только утром по разбору журнала; ни `report`, ни оповещения этого не показывают.

- Журнал шагов — таблица `steps` (`store.journal`, `orchestrator/store.py:1136`; роль шага — столбец `actor`). События: `state -> spec_audit` (вход в аудит SPEC), `аудит SPEC: возврат аналитику по fail` (возврат аудита), `state -> spec_writing` пишется в трёх случаях — с detail «аудит SPEC: вердикт fail…» (возврат аудита), с detail, начинающимся «возврат из spec_gate:» (возврат с гейта SPEC командой `reject`), с detail «эскалация разрешена, продолжаем» (снятие эскалации); `state -> escalated`; стоимость шага — detail события `agent cost KNOWN`, разбор — `spend.known_cost_pairs` (используется в `report.py:397`). Итерации ревью — столбец `tasks.review_iters`.
- `store.set_state` (`store.py:930`) при каждом переходе закрывает оповещения внимания (`close_attention_alerts`) — оповещение внимания для «один раз на задачу» не годится.
- Окно отчёта — `report.OPERATOR_WINDOW_DAYS` (`report.py:59`). Тесты `report`: `tests/test_report.py`, `tests/test_report_project_label.py`, `tests/test_01m57pmbhwk5egq8hpa5tqx72h_report.py`, `tests/test_01m4rzayh3swjw4wfbw4qw15fp_command_report.py`.
- `report`: `orchestrator/report.py` — шаги всех задач `_all_steps` (`:147`), блоки метрик `_metrics_html` (`:797`), разбивка по проекту `_split_metrics_html` (`:778`), команда `cmd_report` (`:1346`).
- Оповещения — `orchestrator/alerts.py`: `raise_alert` (`:93`), `raise_attention_alert` (`:116`); цикл `auto` уже поднимает оповещение внимания (`orchestrator/auto.py:577`).

Требуется:

1. Подсчёт по задаче (новый модуль `orchestrator/rounds.py`, общий для `report` и оповещения): аудиты SPEC (число `state -> spec_audit`); возвраты аудита (`аудит SPEC: возврат аналитику по fail`); возвраты с гейта SPEC (`state -> spec_writing` с detail, начинающимся «возврат из spec_gate:»; снятие эскалации не считается); эскалации (`state -> escalated`); итерации ревью (`tasks.review_iters`); расход «до планки» — сумма `agent cost KNOWN` шагов с `actor` analyst и spec_auditor (разбор — `spend.known_cost_pairs`, нового разбора не писать) и расход всего.
2. `report`: новый блок «Круги до кода» — таблица по задачам, созданным за `OPERATOR_WINDOW_DAYS` (по `created_at` задачи): задача, проект, аудиты SPEC, возвраты, эскалации, итерации ревью, расход до планки / всего; строки, где аудитов SPEC ≥ 3 или эскалаций ≥ 2, выделены. Медиана и среднее по столбцам — строкой итога. При задачах больше одного проекта — по проекту, как остальные блоки.
3. Оповещение: цикл `auto` после каждого перехода задачи сверяет подсчёт с порогом — аудитов SPEC ≥ 3 или эскалаций ≥ 2 — и поднимает `alerts.raise_alert(conn, <проект>, "warning", "rounds", …)` (не оповещение внимания: его закрывает переход) с текстом «задача <id>: N аудитов SPEC, M эскалаций до кода — ТЗ недоопределено?». Один раз на задачу: признак — запись `steps` с действием «круги до кода: оповещение»; при её наличии повтор не поднимается. Пороги — константы `orchestrator/config.py`. Задачи, которые ведут вручную (`advance`/`approve` без `auto`), оповещения не получают — их видит блок `report`.
4. Прежние блоки `report`, прежние оповещения и тексты — без изменений; утверждения перечисленных тестов `report` не меняются; если новый блок меняет порядок или число секций, проверяемых этими тестами, — эскалация. Зафиксировать тестами до правки.
5. Тесты детерминированы: учебная база с журналом задачи (аудиты, возвраты, эскалации) — подсчёт, блок отчёта, оповещение один раз.

Критерии приёмки:
- подсчёт по учебному журналу даёт ожидаемые числа по каждому столбцу, в том числе возврат с гейта SPEC отличён от возврата аудита;
- блок «Круги до кода» есть в `report` и выделяет строки по порогу; строка итога — медиана и среднее;
- третий вход в аудит SPEC (или вторая эскалация) поднимает одно оповещение `rounds`; четвёртый — нового не поднимает, в том числе после закрытия оповещений внимания переходом;
- прежние блоки `report` и прежние оповещения — без изменений.

Решения по умолчанию: окно — `OPERATOR_WINDOW_DAYS` по `created_at`; пороги 3 и 2; «расход до планки» — шаги ролей analyst и spec_auditor (не граница `tests_writing`).

Зоны: orchestrator/report.py, orchestrator/auto.py, orchestrator/rounds.py, docs/codebase-map.md, tests/

Только чтение: `orchestrator/store.py`, `orchestrator/alerts.py`, `orchestrator/spend.py`, `orchestrator/fsm.py`, `orchestrator/fsm_advance.py`, `docs/backlog.md`. Правка вне зон — эскалация до SPEC.

Не входит: оповещение при ручном ведении (`fsm.cmd_approve`/`cmd_advance`); аудит ТЗ и консультация роли (поправка ADR-0022); правило эскалации аналитика; изменения конвейера.

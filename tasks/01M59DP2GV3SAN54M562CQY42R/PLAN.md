# PLAN: Метрика «круги до кода»: аудиты SPEC, возвраты и эскалации на задачу — в report и оповещение по порогу

## Подход
Один подсчёт — `orchestrator/rounds.py`: чистая функция `count(steps,
review_iters)` над уже прочитанными строками журнала задачи (отчёт отдаёт
ей свой срез `_all_steps` — ни одного нового запроса к `steps`, одно
`store.db()` за прогон, риск из SPEC «Материалы») и `task_rounds(conn,
task_id)` для `auto` (журнал задачи через `store.task_steps` — сырого SQL
вне store.py нет). Стоимость — `spend.known_cost_breakdown(detail)[0]`,
нового разбора нет. Порог — `rounds.over_threshold(r)` поверх констант
`config.ROUNDS_ALERT_SPEC_AUDITS = 3` и `config.ROUNDS_ALERT_ESCALATIONS =
2`; ими пользуются и выделение строки отчёта, и оповещение.

Отчёт: новая секция `<section class="panel"><h2>Круги до кода</h2>` —
последней, после «Рост карты кодовой базы»: прежние секции и их порядок не
трогаются (требование 9; блок «Разведка ролей» в тестах режется по
следующему `<section`, порядок прежних секций тот же). Таблица на проект
(h3 с именем проекта — только при задачах больше одного проекта, как
`_metrics_html`), строки задач окна `OPERATOR_WINDOW_DAYS` по
`created_at` (`_in_window`), выделение — класс `rounds-hot` у `<tr>`,
последняя строка таблицы — итог «медиана / среднее» (`statistics.median`
— обычная медиана) по каждому числу, составные столбцы — «X / Y».

`auto`: `_rounds_check(conn, task_id)` после каждого перечитывания
состояния в цикле `_cmd_auto` (после предварительного advance, шага роли,
опроса verifying) и перед каждым выходом из `_cmd_auto` (остановки внутри
шагов, финальная остановка на `escalated`). Однократность — запись журнала
«круги до кода: оповещение»: при её наличии ничего не делается; иначе
`alerts.raise_alert(conn, <проект задачи>, "warning", "rounds", текст)` и
та же запись. Оповещение внимания не используется.

## Шаги
1. `orchestrator/config.py` — константы порогов; `orchestrator/rounds.py` —
   подсчёт, порог, текст оповещения, однократный подъём.
2. `orchestrator/report.py` — блок «Круги до кода».
3. `orchestrator/auto.py` — сверка порога в цикле.
4. Юнит-тесты `tests/test_rounds.py` (свойства вне долгоживущего файла:
   медиана/среднее чистой функцией, `None` разбора стоимости, однократность
   `raise_once` напрямую), карта `scripts/codebase_map.py`.

## Влияние на систему
- `report`: добавлена одна секция в конец `<main>`; прежние секции,
  тексты и порядок прежние; запросов к `steps` не прибавляется (подсчёт по
  уже выбранному журналу), `store.db()` — один раз.
- `auto`: добавлена только сверка порога; условия цикла, остановки, тексты
  `auto_stop` и оповещение внимания не меняются. Ошибка внутри сверки не
  ловится молча — это обычный код пульта, как прочие шаги цикла.
- Гейты, FSM, лимиты не затрагиваются. Откат — revert merge-коммита.

## Риски
- Эскалации считаются по всем `state -> escalated` задачи, включая
  эскалации после кода (как в SPEC/ТЗ) — текст «до кода» может быть
  неточен для поздних эскалаций; оповещение однократно, шум ограничен.

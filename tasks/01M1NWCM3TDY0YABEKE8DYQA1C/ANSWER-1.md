# ANSWER-1: ответ Оператора

## Ответы

Вопрос 1 — вариант B с отдельной колонкой: верхняя оценка при
неизвестном курсе пишется в новую колонку `tasks.spent_estimate_usd`
(накопительно, с записью в журнал «верхняя оценка стоимости шага»),
`spent_usd` остаётся точной суммой плюс частичные суммы по курсу
(требование 1). Бюджетный гейт (`enforce_budget`/`budget_block`)
сравнивает с потолком сумму `spent_usd + spent_estimate_usd`; RETRO и
`artel report` показывают оценку отдельной строкой, не смешивая с
точной. Пересчёт истории не входит.

Вопрос 2 — вариант A: тариф — таблица по идентификатору роли из
roles.yaml (цена входного и выходного токена, дата калибровки) в
orchestrator/config.py; roles.yaml не правится. Переход тарифа на
модель — отдельная задача после появления поля модели у роли (бэклог
04.09).

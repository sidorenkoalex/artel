# PLAN: Исследование — watchdog живости конвейера

## Подход
Задача исследовательская (SPEC: `skip_tests` — прозаический документ,
код не пишется). Один шаг = один MR, размер — сам документ-предложение.

Метод: карта → дыры → кандидаты → рекомендация, строго по требованиям
SPEC. Карта строится чтением кода/спек прямо по ссылкам из SPEC
«Материалы» (без домыслов о том, что «наверное» реализовано — проверено
grep'ом там, где сомнительно, например реестр №12 — не реализован
нигде в коде, только запись в реестре отказов v5).

Постоянный носитель предложения (требование 6 SPEC) —
`docs/research/2026-08-31-t084-watchdog-liveness.md`: новая директория
`docs/research/` по аналогии с `docs/audits/` (жанр другой — это не
аудит роадмапа, а прицельное исследование конкретной строки беклога),
файл датирован и содержит явную ссылку на T084 в первой строке.
Отдельно — вычёркивание строки P3 «Исследование: watchdog живости
конвейера» в `docs/roadmap.md` тем же приёмом, что и прошлые закрытые
строки беклога (`~~...~~ — закрыта T084 (31.08)` + сводка), со ссылкой
на новый документ. Оба файла — вне protected-paths.

Никакого кода механизма watchdog (heartbeat/возраст состояния в
doctor/scheduled watchdog) не пишется — только документ и правка
роадмапа (AC-5).

## Влияние на систему
Правки — новый файл `docs/research/` (новая директория, не protected
path) и одна строка `docs/roadmap.md` (не protected path, обычная
практика закрытия строк беклога прошлыми задачами — T035, T041, T044
и др. делали то же самое). Код `orchestrator/*.py`/`scripts/*.py`/
`tests/*.py` не трогается — карта кодовой базы (`docs/codebase-map.md`)
регенерации не требует. Тесты, гейты, лимиты, инварианты — не
затрагиваются: задача не меняет поведение системы, только фиксирует
анализ. Откат — `git revert` двух файлов.

## Риски
- Карта может устареть быстрее, чем документ прочитают (система живая,
  P3 в активной разработке) — смягчено явными ссылками файл:строка,
  которые легко перепроверить, вместо пересказа своими словами.
- Оценка кандидатов — субъективна по стоимости/риску; явно помечена как
  рекомендация, не решение (Оператор решает последующий запуск).

# ТЗ: note --drop, --set-state, --set-priority: снятие и правка строк копилки/бэклога тем же циклом fetch/правка/push

Источник: копилка 11.09 П2 «нет команды пульта для снятия и правки
строк копилки/бэклога». Правила docs/backlog.md (шапка): закрытые
пункты не хранятся, заведённое через `cmd_new` снимается через один
цикл сверки; правило «обход вместо команды пульта — не молча»
(CLAUDE.md, решение Оператора 06.09).

Факт 11.09: `note` умеет только вставку строки (`--text` в раздел) и
дописывание в колонку состояния (`--append <ключ> --text`), а сверка
«закрыто/заведено — снять» делается прямым коммитом. Две сессии сняли
пересекающиеся наборы строк П1 независимо (7651f67f в origin и
40970b97 в главной копии); push главной копии отклонён (origin ушёл на
29 коммитов, в копии лежал непушенный 0fc0638e), остаток применён
обходом — worktree поверх origin/main, коммит d464852e. Механика
`notes._attempt` (fetch → правка от актуального содержимого → commit →
push с повтором non-fast-forward) для снятия и замены не используется.

Требуется:
1. `note --drop <ключ>`: снимает ровно одну строку любой из трёх таблиц, найденную по подстроке ключа тем же поиском, что `--append` (`_iter_matching_rows`: ноль или больше одной — именованный отказ, файл не изменён); сообщение коммита «оператор: <раздел> — снята: <первые 80 символов наблюдения>»; тот же цикл fetch/правка/push с повторами и удержанием при отказе сети (`_hold_pending`, `--flush`).
2. `note --set-state <ключ> --text "<новое состояние>"`: заменяет колонку состояния целиком (в отличие от `--append`, который дописывает); тот же поиск, тот же цикл, сообщение коммита «оператор: <раздел> — состояние: …».
3. `note --set-priority <ключ> --text <1..4>`: меняет колонку «П» строки; отказ на значение вне 1..4.
4. Удержанные операции всех видов (`insert`, `append`, `drop`, `set-state`, `set-priority`) сериализуются в `.artel/notes-pending` одним форматом и допушиваются `--flush` в порядке создания; `doctor` (проверка pending-notes) считает их все.
5. Тесты: `--drop` снимает одну строку и не трогает соседние (мутация «удалена строка по индексу без проверки ключа» — красный); `--drop` при двух совпадениях — отказ без изменений; `--set-state` заменяет, `--append` дописывает; `--set-priority 5` — отказ; удержание `drop` при отказе push и допуш `--flush`; существующие тесты notes — без ослабления.

Зоны: orchestrator/notes.py, tests/.

Не входит: изменение структуры docs/backlog.md; редактирование
роадмапа; `orchestrator/doctor/` (проверка pending-notes читает
`notes.pending_notes()` — новые виды видны без правки doctor).

# SPEC: note --drop, --set-state, --set-priority — снятие и правка строк копилки/бэклога тем же циклом fetch/правка/push

## Контекст
`note` сейчас умеет только вставку строки (`--text` в раздел) и
дописывание в колонку состояния (`--append <ключ> --text`); снятие
строки и правка приоритета/состояния делаются прямым коммитом в обход
`notes._attempt` (цикл fetch → правка от актуального содержимого →
commit → push с повтором non-fast-forward и удержанием при отказе
сети). 11.09 это привело к тому, что две сессии независимо сняли
пересекающиеся строки П1 (7651f67f в origin и 40970b97 в главной
копии), push главной копии отклонён, остаток применён обходом через
отдельный worktree (d464852e) — правило «обход вместо команды пульта —
не молча» (CLAUDE.md, решение Оператора 06.09) нарушено самой
механикой. Нужны команды `note`, использующие тот же цикл fetch/
правка/push, что и существующие `insert`/`append`.

## Требования

1. `note --drop <ключ>` снимает ровно одну строку любой из трёх таблиц
   `docs/backlog.md`, найденную по подстроке ключа тем же поиском, что
   уже использует `--append` (`_iter_matching_rows`): ноль совпадений
   или больше одного — именованный отказ, файл не изменён. Сообщение
   коммита: «оператор: <раздел> — снята: <первые 80 символов
   наблюдения>». Используется тот же цикл fetch/правка/push с
   повторами non-fast-forward и удержанием при отказе сети
   (`_hold_pending`, допуш `--flush`), что несёт `notes._attempt` для
   остальных видов.
2. `note --set-state <ключ> --text "<новое состояние>"` заменяет
   колонку состояния найденной строки целиком — в отличие от
   `--append`, который дописывает к текущему значению колонки. Поиск
   строки — тот же, что у `--append`/`--drop`. Сообщение коммита:
   «оператор: <раздел> — состояние: …». Тот же цикл fetch/правка/push
   с повторами и удержанием.
3. `note --set-priority <ключ> --text <1..4>` меняет колонку «П»
   найденной строки. Значение вне диапазона 1..4 — отказ, файл не
   изменён.
4. Удержанные операции всех видов (`insert`, `append`, `drop`,
   `set-state`, `set-priority`) сериализуются в `.artel/notes-pending`
   одним общим форматом и допушиваются `--flush` в порядке создания.
   `doctor` (проверка pending-notes) считает их все — читает через
   `notes.pending_notes()`, без отдельной правки doctor.
5. Тестовый слой покрывает: изоляцию `--drop` (снимает ровно одну
   строку, соседние строки не тронуты — регресс на мутацию «удаление
   по индексу без проверки ключа»); отказ `--drop` при двух
   совпадениях без изменения файла; раздельное поведение `--set-state`
   (замена колонки) и `--append` (дописывание); отказ
   `--set-priority 5`; удержание `drop` при отказе push и успешный
   допуш через `--flush`; существующие тесты `notes` — без ослабления.

## Критерии приёмки

AC-1. `note --drop <ключ>` снимает ровно одну строку из таблицы любого
из трёх разделов, найденную тем же поиском по подстроке ключа, что
`--append` (`_iter_matching_rows`), и не меняет остальные строки файла.

AC-2. `--drop` при отсутствии совпадений или более чем одном
совпадении отказывает именованным сообщением; `docs/backlog.md` не
изменён.

AC-3. Коммит `--drop` несёт сообщение вида «оператор: <раздел> —
снята: <первые 80 символов наблюдения>».

AC-4. `--drop` использует тот же цикл fetch/правка/push с повторами
non-fast-forward и удержанием заметки при отказе сети (`_hold_pending`),
что и остальные виды `note`; удержанная операция `drop` успешно
допушивается `--flush`.

AC-5. `note --set-state <ключ> --text "<новое состояние>"` заменяет
колонку состояния найденной строки целиком (не дописывает); `--append`
для той же колонки по-прежнему дописывает.

AC-6. Коммит `--set-state` несёт сообщение вида «оператор: <раздел> —
состояние: …».

AC-7. `note --set-priority <ключ> --text <1..4>` заменяет колонку «П»
найденной строки; значение вне диапазона 1..4 отказывает без изменения
файла.

AC-8. Удержанные операции всех пяти видов (`insert`, `append`, `drop`,
`set-state`, `set-priority`) сериализуются в `.artel/notes-pending`
одним общим форматом и допушиваются `--flush` в порядке создания;
`doctor` считает их все через `notes.pending_notes()` без правки
doctor.

AC-9. Существующие тесты `notes` проходят без ослабления — ни один
существующий тест не удалён и не смягчён.

## Пути обхода гейтов
- **П-1 (через фикстуру).** Самый дешёвый способ вернуть зелень
  существующим тестам внешних проектов (М-1) — убрать `token_slot` из
  `_PROJECT_TARGET_ENTRY` (`tests/sandbox.py:1061`): по треб. 2/AC-16
  запись без слота идёт «с прежней авторизацией», утверждения тестов не
  трогаются, гейт неослабления правку фикстуры-строки не видит. Итог —
  ни один старый сценарий внешнего проекта не проходит через новый
  механизм. SPEC не запрещает и не предписывает.
- **П-2 (через исключение `config.ROOT`).** SPEC.md:55-57 и AC-1
  (SPEC.md:131-133) исключают из подстановки «пути под `config.ROOT`».
  `config.PROJECTS = ROOT / ".artel" / "projects"`
  (`orchestrator/config.py:50`) — клоны и рабочие копии всех внешних
  проектов лежат под `config.ROOT`. Буквальное исполнение выключает
  механизм треб. 1 целиком; а исключение «главной копии» по пути
  противоречит треб. 8 / AC-11 / AC-13 (источник `config.ROOT`, URL
  проекта — токен нужен). Смысл, видимо, «сам `config.ROOT` и рабочие
  копии артели вне `config.PROJECTS`, и только для признака по пути», но
  в SPEC это не сказано — порядок признаков (путь vs URL) не задан.
- **П-3 (AC-15).** AC-15 выполним вакуумным тестом, утверждающим
  `GH_TOKEN` на пустом множестве вызовов (Ф-1).
- **П-4 (5.3).** Подстрочный поиск `pull_request` удовлетворит AC-8 и
  на `pull_request_target`/комментарии — warn «verifying будет ждать до
  потолка» не появится там, где триггера нет. Низкая значимость.

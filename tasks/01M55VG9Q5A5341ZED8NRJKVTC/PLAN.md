# PLAN: Неустойчивый тест предела полного прогона: детерминированное доказательство

## Подход
Правится только фикстура долгоживущего файла
`tests/test_01m48wre8bhfdy011q0hqgq91b_full_suite_limit_runs.py`; утверждения
метода `SuiteRunProfileLimitTest::test_ac5_…` и помощник `standalone` не
тронуты. Код пульта рабочего дерева не меняется.

1. **Часы `proc.wait` в копии пульта (требование 1).** В CPython 3.13
   `Popen.wait(timeout)` считает срок по `subprocess._time`
   (`endtime = _time() + timeout`, `_remaining_time`). Константа `COPY_CLOCK`
   дописывается в `orchestrator/config.py` копии пульта из
   `SuiteRunLimitSandbox.add_project_task(limit)` (config импортирует весь
   пакет копии, т.е. и фоновый процесс `suite-run`). Она:
   - подменяет `subprocess._time` часами, которые вне вызова отдают
     настоящее время, а в вызове `Popen.wait` прогона pytest стоят на моменте
     входа и, как только пробник группы процессов прогона (`pgid == proc.pid`,
     в запись пробника добавлено поле `pgid`) записал «start», показывают
     ровно на N (предел профиля) больше;
   - оборачивает `Popen.wait` только ради выбора режима часов на время
     вызова (thread-local): дальше вызывается настоящий `Popen.wait` с тем же
     переданным пределом. Обрыв (`TimeoutExpired`) бросает он сам на строке
     `proc.wait(timeout=limit[0])` (`orchestrator/acceptance.py:1598`);
     `run_full_suite`, `_run_full_suite_now`, `_run_full_suite_to_log`
     исполняются настоящими (AC-3);
   - предел, отличный от N (config, N ± k, N/2 …), часы не переводят и
     отпускают пробник stop-файлом: прогон кончается сам, строки «не уложился»
     в отчёте нет, утверждение `:619` краснеет (AC-6, N-чувствительность).
   - Прогон базы (второй `proc.wait`, без пробника) часы не обрывают: события
     «start» его группы нет, прогон кончается сам.
   Исход больше не зависит от того, сколько реального времени пробник ждал
   процессора: часы переходят по событию пробника, а не по сроку (AC-1, AC-2).
2. **id фикстуры без цифр (требование 3).** `SuiteRunLimitSandbox.task_id`
   переопределён: `"01M"` + 23 буквы `ALPHABET` без цифр (`ID_LETTERS`).
   Строка «не уложился» состоит из id, «№1», N, имени проекта (`"p"` + буквы
   `LETTERS`) — отдельно стоящего 60 в ней не бывает ни при каком зерне (AC-5).
   Общий `ProbeSandbox.task_id` (тесты гейта мержа) не меняется.

Оценка бюджета SPEC не меняется.

## Влияние на систему
- Меняется только фикстура долгоживущего файла; утверждения всех методов
  файла и `standalone` не тронуты — гейт неослабления ослабления не увидит.
  Поле `pgid` в записи пробника — добавочное, тесты гейта мержа его не
  читают.
- Подмена часов живёт только в `config.py` копии пульта в песочнице
  (`self.root/orchestrator`), процесс самого теста и `orchestrator/`
  рабочего дерева её не видят.
- Откат — revert коммита задачи.

## Риски
- `COPY_CLOCK` опирается на деталь CPython: `Popen.wait` считает срок по
  `subprocess._time`. Если будущая версия Python перестанет читать
  `_time`, часы не сработают и обрыв вернётся к реальным N секундам: тест
  станет медленнее, AC-1 (планка) покраснеет, но ложного зелёного не будет.
- Обёртка распознаёт прогон pytest по элементу `"pytest"` в argv
  (`[python, -m, pytest, …]` профиля фикстуры).

## Предложения системе
- `suite-run --wait` отдаёт код 1 и на «не зелёный отчёт», и на «процесс
  пропал», и на «ожидание истекло» (`orchestrator/suite_run.py:721-739`):
  по копилке 07.10 нельзя было восстановить исход — различимые коды выхода
  упростили бы разбор неустойчивых тестов.

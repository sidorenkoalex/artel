## Требования

1. `amend-tests` после успешной фиксации правки планки в ссылку
   документов убирает из рабочей копии кода задачи каталог `tasks/<id>/`,
   материализованный этой командой; прочие пути рабочей копии не
   трогаются. На отказе команды каталог `tasks/<id>/` в рабочей копии не
   трогается — правка Оператора остаётся на диске.
2. Заведение рабочего каталога роли не падает на занятой ссылке
   отслеживания. Способ: fetch базы ветки при заведении рабочего каталога
   идёт БЕЗ обновления ссылок отслеживания `refs/remotes/origin/*`
   (только в приватную ссылку, как сейчас), так что блокировка
   `refs/remotes/origin/<MAIN_BRANCH>` чужим процессом ему не мешает.
   Ветка задачи по-прежнему заводится от головы `origin/<MAIN_BRANCH>`,
   полученной этим fetch. Прочие отказы fetch (remote недоступен, ветки
   нет и т. п.) — прежний именованный отказ «база ветки недоступна: fetch
   origin не удался: <причина>» без отката на локальную `MAIN_BRANCH`.
3. `artel.py observe add <obs> …` и `artel.py observe remove <obs> …` с
   лишними позиционными аргументами (не флагами и не значениями флагов),
   например `--tasks A B`, отказывают ненулевым кодом возврата с
   именованной причиной, называющей лишний аргумент и подсказывающей
   форму «номера задач через запятую» (`--tasks A,B`), и не выполняют
   даже частичного действия: список задач наблюдения не меняется.
4. `python3 scripts/guard.py <путь>/SPEC.md` (вызов по одному файлу SPEC)
   выдаёт ту же находку о неклассифицированных путях, что `approve` на
   `spec_gate`, — через тот же узел `guard.spec_unclassified_paths` и тот
   же текст `guard.unclassified_paths_refusal`; находка — нарушение, guard
   завершается ненулевым кодом. `approve` на `spec_gate` сохраняет свою
   проверку без изменений.
5. Каждый из пунктов 1–4 покрыт тестом в `tests/` с заявкой «Ловит
   мутацию»; долгоживущие приёмочные тесты этой задачи в `tests/`
   засчитываются, дублировать их отдельными тестами не нужно.

## Критерии приёмки

AC-1. `amend-tests` с реальной правкой планки, успешно зафиксированной в
ссылку документов, завершается с каталогом `tasks/<id>/` отсутствующим в
рабочей копии кода задачи; прочие отслеживаемые и неотслеживаемые файлы
рабочей копии вне `tasks/<id>/` не изменены.

AC-2. `amend-tests`, завершившийся отказом (например, правка за пределами
`acceptance_tests/`), оставляет каталог `tasks/<id>/` в рабочей копии кода
с правкой Оператора побайтно как был.

AC-3. Заведение рабочего каталога роли для задачи без ветки при занятой
ссылке отслеживания (существует файл блокировки
`refs/remotes/origin/<MAIN_BRANCH>.lock` в репозитории пульта) завершается
без отказа, и ветка задачи стоит на голове `<MAIN_BRANCH>` удалённого
репозитория.

AC-4. Fetch базы ветки при заведении рабочего каталога роли не меняет
`refs/remotes/origin/<MAIN_BRANCH>`: при голове origin, ушедшей вперёд,
ссылка отслеживания после заведения указывает на прежний коммит.

AC-5. Заведение рабочего каталога роли при недоступном remote (иной отказ
fetch) возвращает именованный отказ, начинающийся с «база ветки
недоступна: fetch origin не удался», и ветку задачи не заводит.

AC-6. `artel.py observe add <obs> --tasks A B` завершается ненулевым кодом,
текст отказа называет лишний аргумент `B` и подсказывает перечисление
номеров через запятую; список задач наблюдения `<obs>` после вызова тот же,
что до него (задача `A` не добавлена).

AC-7. `artel.py observe remove <obs> --tasks A B` (A и B — задачи
наблюдения) завершается ненулевым кодом с той же именованной причиной;
список задач наблюдения не изменён (задача `A` не убрана).

AC-8. `python3 scripts/guard.py <путь>/SPEC.md` на SPEC с путём
существующего файла репозитория в проверяемом разделе, не покрытым
`zones:` и разделами-декларациями, завершается ненулевым кодом и печатает
текст `guard.unclassified_paths_refusal` для этого пути — тот же, что
отказ `approve` на `spec_gate` для того же SPEC.

AC-9. `python3 scripts/guard.py <путь>/SPEC.md` на SPEC, все пути которого
классифицированы, не даёт находки о неклассифицированных путях;
`approve` на `spec_gate` по SPEC с неклассифицированным путём
по-прежнему отказывает.

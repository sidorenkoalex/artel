## Пути обхода гейтов
1. **Код 0 при незапущенном шаблоне.** SPEC.md:179-180 и AC-11
   (SPEC.md:291-292): «0, только если все дочерние завершились с кодом 0».
   Шаблон, чей дочерний не запустился (SPEC.md:173-175), дочернего не имеет.
   Буквальное исполнение вернёт 0 при красной строке «процесс задачи не
   запущен». Отвязанный запуск запишет `status: complete`
   (`artel.py:1582-1600`), сессия Оператора увидит успех. То же и в ТЗ п. 6.
2. **Дубль строки шаблона после SIGKILL.** SPEC.md:150-154 требует красную
   строку SIGKILL безусловно, SPEC.md:166-172 — строку только при отсутствии
   строки шаблона. Дочерний, успевший записать «оборвана сигналом» и
   застрявший в уборке клона до SIGKILL, по букве получит вторую красную
   строку. Файл результата понесёт две строки одного шаблона, счёт задач
   прогона разойдётся с `tasks` записи. Чего SPEC хочет, по тексту не решить.
3. **Причина красной строки родителя.** «С причиной …» в AC-11/AC-13
   (SPEC.md:288-291, 300-301) при «исход `_DRIVE_FAILED_OUTCOME`» допускает
   два прочтения. В `_report_drive_failure` поле исхода в строке одно
   (`canary.py:2754`), причина — только в печати (2759-2760). Требование 5 это
   уточняет («строка вывода родителя», SPEC.md:153), требование 6 — нет.
   Автор тестов, ищущий причину в поле строки, навяжет коду иную форму строки
   (класс `тест-навязывает-устройство`).
4. **AC-17 без режима** — см. «Проверяемость»: перенос 1 для параллельной
   ветки можно не выполнить, и критерий останется зелёным.

## Вердикт
concerns — SPEC вести можно; каждое отклонение решается уточнением Оператора
на гейте без возврата аналитику. Отклонения:

1. SPEC.md:179-180, SPEC.md:291-292 (AC-11) — код выхода родителя не учитывает
   шаблоны, чьи дочерние не запустились (SPEC.md:173-175): возможен код 0 при
   красной строке. Нужно «0 — только если запущены и завершились с кодом 0
   все дочерние, иначе ненулевой». Унаследовано из ТЗ п. 6.
2. SPEC.md:150-154 против SPEC.md:166-172 — красная строка SIGKILL безусловна,
   строка «без строки прогона» условна. Возможен дубль строки шаблона в
   `canary_runs` и в файле результата. Нужно назвать: строка SIGKILL — только
   при отсутствии строки шаблона, или всегда.
3. SPEC.md:166-171, AC-11 SPEC.md:288-291 — не названо, где живёт причина
   красной строки за дочернего без строки прогона: в выводе родителя (как в
   `_report_drive_failure`, `orchestrator/canary.py:2754-2760`) или в поле
   строки.
4. AC-17 (SPEC.md:319-321) не требует параллельного режима. В
   последовательном режиме свойство уже держит main
   (`orchestrator/canary.py:3288-3291`), поэтому для новой ветки критерий
   мутаций не ловит. Требование 7 (SPEC.md:196-197) называет оба режима.
5. AC-12 (SPEC.md:294-297) потерял проверку ТЗ п. 9 «таблица canary_baseline
   после прогона с сигналом родителю совпадает с прежней».
6. Нет критериев для ветвей SPEC.md:148-149 (выход не по сигналу + сигнал во
   время остановки → 128 + n) и SPEC.md:75-76 (исключение при ожидании
   дочернего: судьба его шаблона и строки не определена).
7. Наблюдения, не требующие решения: AC-5 не ловит удаление новой проверки
   попарной различности (тест идёт через `orchestrator/canary.py:417-419`, как
   велит ТЗ; при случайной выборке имена различны по построению, 378-392).
   Литерал AC-1 «снятый до правок» ревью сверит по `git`. Состояние AC-16
   строится файлами реестра (`orchestrator/canary.py:3162`).

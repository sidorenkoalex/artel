# SPEC-AUDIT: Мерж не ждёт CI main под замком: цвет main сверяет следующий мерж, идущий CI main он дожидается (ADR-0031, этап 2)

## ТЗ и SPEC
- Требования ТЗ 1–5 перенесены в SPEC «Требования» 1–5 без потерь и без
  добавок. Критерии ТЗ (6 сценариев и мутации) — SPEC AC-1…AC-7, уточнены
  (вызов `main_line_status` один раз, `main` в `origin` не сдвинут). ANSWER-n
  нет, решений Оператора на гейте SPEC нет.
- Зона тестов сужена с «`tests/` (долгоживущие файлы задачи)» ТЗ до
  `tests/test_01m6trm2ekzjv2fxp6c5yne9fc_*.py`. Это то же самое по смыслу.
- `budget_usd: 40` не выше рамки ТЗ $45.
- ТЗ требует эскалации, если краснеет тест, закрепляющий ожидание после
  мержа. SPEC («Не входит», последний пункт) утверждает, что сверил это по
  main, и называет только `tests/test_main_ci_line.py` и
  `tests/test_01m4s24ebvb72b8wyj3jy96y0e_merge_reference.py`. Такие тесты
  есть, и они краснеют (раздел «Матрица неослабления», О-1).

## Факты против кода
Подтвердилось:
- `MAIN_CI_WAIT_LIMIT_SEC = 18 * 60` — `orchestrator/fsm_merge_gate.py:56`.
- `MAIN_CI_AFTER_MERGE_ACTION` — `:63`.
- `_refuse_if_main_red` — `:607-650`, вызов `:1547`. Идущий и неизвестный
  CI проходят с записью журнала (`:639-642`).
- `--fixes-main` — `:632-638`: у SPEC номера строк верные, у ТЗ (`:631-637`)
  сдвинуты на одну.
- `_await_main_ci` — `:653-692`, вызов `:1570`; `send_pending()` — `:665`.
- Пауза `config.VERIFYING_POLL_INTERVAL_SEC` — `:687`, `config.py:361`.
- Heartbeat — `merge_lock.touch_heartbeat`, `:672`.
- Проверка «только артель» — `repo_context.is_artel`, `:624`, `:666`.
- Замок держится весь внешний цикл approve: `merge_lock.acquire` до
  `while`, `release` в `finally` (`:2017-2047`). Ожидание в
  `_refuse_if_main_red` действительно идёт под замком.
- ADR-0031 п. 6 и строка этапа 2 — `docs/adr/0031-test-runs-strategy.md:34,41`.

Не подтвердилось:
- SPEC («Не входит», «Сверено по main») утверждает, что текст исхода
  «неизвестно» (треб. 1) сохраняет подстроку «не дождался», которую ждёт
  `tests/test_main_ci_line.py:324,327`. Слово «неизвестно» этой подстроки
  не содержит. Тест останется зелёным, только если текст исхода
  «неизвестно» по-прежнему содержит «не дождался», а треб. 1 этого не
  требует (О-3).
- Утверждение SPEC, что существующие тесты не краснеют, ложно. См. О-1:
  проверено опытом.

## Проверяемость критериев

| Критерий | Проверяем | Ловимая мутация |
|---|---|---|
| AC-1 | да | ожидание после мержа оставлено: `main_line_status` вызван больше одного раза или вызвана пауза; запись не называет «идёт — цвет сверит следующий мерж»; замок не снят |
| AC-2 | да | идущий CI — проход без опроса (нет второго вызова и паузы, нет записей начала и исхода с sha) |
| AC-3 | да | идущий CI — проход: мерж выполняется поверх красного, задача уходит из `merge_gate` |
| AC-4 | да, при подставных часах | по исчерпании предела — проход вместо отказа (`main` сдвинут); предел не ограничен (зависание ловит подставная пауза) |
| AC-5 | да | `--fixes-main` всё равно ждёт (пауза вызвана) |
| AC-6 | частично | неизвестный исход ждёт или отказывает; не ловит «сбой `gh` посреди ожидания — ждать до предела»: AC-6 задаёт сбой только на первом чтении (О-4) |
| AC-7 | да | обе мутации ловят AC-1 и AC-2/AC-3 |

Красная фаза. Тесты запускаются до кода, и код `main`, ожидающий после
мержа, тогда исполняется под тестами AC-1/AC-2/AC-4. Цикл
`_await_main_ci` меряет предел по `time.monotonic()`
(`fsm_merge_gate.py:682`). Безопасная форма ТЗ и SPEC («`time.sleep` —
подмена») не требует подставных часов. Если тест AC-1 подменит паузу
`Mock`-ом, а `main_line_status` будет вечно отвечать «идёт», красная
фаза уйдёт в горячий цикл на 18 настоящих минут, а при застывшем
`monotonic` — навсегда. Образец безопасной формы уже есть:
`tests/test_01m3sf7dpfgez7vyeggxgtx49e_main_ci.py:201-211,231-234`
(`monotonic`/`time` от подставного счётчика, пауза двигает часы и падает
за пределом). Критерии такую форму не задают (О-2).

## Зоны
Зоны покрывают требования: вся правка в `orchestrator/fsm_merge_gate.py`,
карта генерацией, новый файл тестов задачи. Защищённых путей нет. Модули
«только чтение» правки не требуют: `ci.MAIN_RUNNING`, `merge_lock`,
`config.VERIFYING_POLL_INTERVAL_SEC` уже есть. Если Оператор разрешит
правку тестов О-1, зону нужно расширить на
`tests/test_01m3sf7dpfgez7vyeggxgtx49e_main_ci.py`.

## Пути обхода гейтов
- **О-5. Подгонка текста под старые тесты.** `:776` ищет запись и строку
  вывода с «зелён» и «main» (`main_records`, `:770-774`). `:831` ищет
  «не дождал» и 15–20 минут подставных часов. Тогда тесты проходят без
  правки, хотя проверяют уже не ожидание после мержа:
  - ожидание следующим мержем печатает исход «CI main <старая голова> зелёный»;
  - отказ по пределу или запись исхода содержит «не дождался».

  Гейт неослабления тестов этого не видит: файл тестов не тронут. SPEC
  этот путь не закрывает и тесты не называет.
- По `--fixes-main` (треб. 4) и по проходу на неизвестном (треб. 2) новых
  путей нет — это обходы, задуманные ТЗ.

## Вердикт
concerns. Все отклонения Оператор может снять на гейте SPEC, ни одно не
мешает вести SPEC дальше. Без решения по О-1 разработчик неизбежно
эскалирует посреди `in_dev`: это прямо предписывает ТЗ.

- **О-1.** Два существующих теста закрепляют ожидание после мержа и
  краснеют при буквальном исполнении треб. 1:
  - `tests/test_01m3sf7dpfgez7vyeggxgtx49e_main_ci.py:776`
    `MergeWaitsForMainCiTest::test_ac4_green_after_running_is_reported_green`;
  - `:831` `MergeWaitsForMainCiTest::test_ac4_unfinished_ci_is_reported_after_15_to_20_minutes`.

  SPEC («Не входит», «Сверено по main») их не называет: в нём нет ни
  мандата, ни раздела «Меняемое поведение», ни расширения зоны.
  Рекомендация Оператору — одно из двух:
  - решением на гейте SPEC дать мандат на замену этих двух тестов и
    расширить зону на этот файл, затем вернуть SPEC аналитику, чтобы тот
    объявил замену;
  - принять плановую эскалацию в `in_dev`.
- **О-2.** Безопасная форма тестов (SPEC «Не входит», п. 1; ТЗ
  «Безопасность тестов») не требует подставных `time.monotonic`/`time.time`,
  связанных с паузой, и отказа подставной паузы за пределом. Красная фаза
  AC-1/AC-2/AC-4 исполняет цикл `fsm_merge_gate.py:668-688`, где предел
  мерится по `monotonic`. С паузой-`Mock` и вечным «идёт» это горячий цикл
  на 18 минут или зависание. Образец формы —
  `tests/test_01m3sf7dpfgez7vyeggxgtx49e_main_ci.py:201-211,231-234`.
- **О-3.** Утверждение SPEC («Не входит»), что текст «неизвестно»
  сохраняет подстроку «не дождался», не следует из треб. 1. Тест
  `tests/test_main_ci_line.py:324,327` зелёный, только если текст исхода
  «неизвестно» содержит «не дождался». Это условие стоит записать в треб. 1.
- **О-4.** Треб. 2 и AC-6 не задают исход сбоя `gh` посреди ожидания: CI
  был «идёт», затем `gh` не ответил. Мутация «ждать до предела и отказать»
  тестами не ловится.
- **О-5.** Подгонка текста под старые тесты `:776`/`:831` (раздел «Пути
  обхода гейтов») — следствие О-1, закрывается тем же решением.

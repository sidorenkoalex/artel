# ТЗ: ADR-0021, этап 2 — клон и рабочие копии задач в области проекта; главная копия пульта перестаёт меняться

Источник: ADR-0021 (принят 29.09.2026), пункты 1, 2, 6, 7, 10, 12, 13
(«этап 2»); решения Оператора 29.09 (п. 6 и 10 раздела решений);
этап 1 исполнен 03-04.10 (части (а), (б1), (б2), перефиксация, (в1),
(в2)). Решение Оператора 04.10.2026 «готовь ТЗ этапа 2».

Факты (пин 9afc1792, сверка кода 04.10):
- Рабочие копии задач артели — `config.WORKTREES` = `.artel/worktrees/<id>`
  (`orchestrator/workspace.py:21-23`), заводятся `git worktree add` в git
  главной копии `config.ROOT` (`workspace.py:49-80`); ветка `task/*` —
  тоже в git главной копии. На диске 244 каталога, из них в
  `git worktree list` главной копии — 2 задачи (остальные — сироты).
- Внешний проект: один общий `.artel/projects/<имя>/workspace` на все
  задачи (`orchestrator/runner.py:337-339, 1033-1041`,
  `orchestrator/plank_run.py:32`, `orchestrator/checkpoint.py:1091, 1258`).
  Для артели такой клон уже есть (`.artel/projects/artel/workspace`,
  `core.hooksPath=scripts/git-hooks`); каталогов `repo/` и `worktrees/`
  нет.
- `orchestrator/repo_context.py:39-48`: для артели
  `path=config.ROOT, remote="origin"`, поля записи `artel` в
  `targets.yaml` не читаются; для внешнего — `projects/<имя>/workspace`.
- Ссылки документов артели `refs/artifacts/<id>` пишутся в git главной
  копии (`orchestrator/artifact_branch.py:69-103`, `update-ref` на
  ~315, ~493): там 238 ссылок.
- Мерж задачи артели: временная рабочая копия `worktree add --detach` в
  git главной копии (`orchestrator/fsm_merge_gate.py:158-176`), push
  ветки и `main` — через git главной копии (~641, ~995); удаление веток
  — `orchestrator/cleanup.py:101, 125, 147`.
- Шаги мержа, включаемые сравнением пути с главной копией
  (`ctx.path == config.ROOT` и подобные): `fsm_merge_gate.py` ~87
  (защищённые пути в диффе), ~121 (сохранность тестов в диффе), ~483
  (`guard --all`), ~515 и ~558 (цвет CI `main`), ~877 (приложения PLAN),
  ~946 (карта кодовой базы и RETRO); `repo_context.py:56, 64`,
  `artifact_branch.py:95, 101`; сравнение каталогов с главной копией —
  `checkpoint.py:~1095`, `plank_run.py:~93`, `acceptance.py:~404`. Если
  путь артели станет клоном, эти шаги молча отключатся.
- `orchestrator/gitcmd.py:32-43`: `gitcmd.git` исполняется с
  `cwd=config.ROOT`; вызовов вне `gitcmd` — 50 в 25 модулях.
  Упоминаний `config.ROOT` — 190 в 57 модулях `orchestrator/` и
  каталога сценариев пульта.
- Хуки защиты `main`: `orchestrator/doctor/git_hooks.py` проверяет и
  ставит `core.hooksPath scripts/git-hooks` только в главной копии.
- `note`/`doc-commit` коммитят и пушат через отдельный git
  `.artel/notes-work` (`orchestrator/notes.py:227-228, 633-643, 1060,
  1101`), базу берут из HEAD главной копии (`notes.py:287, 778, 885,
  887`). `canary pool-seal` пишет файлы прямо в рабочее дерево главной
  копии (`orchestrator/pool_seal.py:71-76`).
- Канарейка (этап 0 исполнен): клон пульта во временном каталоге
  (`orchestrator/canary.py:~1086, ~1173`), атрибуты `config` клона
  перенаправлены (`canary.py:~457`); области `projects/artel` внутри
  временного каталога нет — для артели корнем служит сам клон.
- Инварианты 20 и 21 (`docs/invariants.md:50-51`) говорят о внешнем
  проекте; их держат `tests/test_multitarget_invariants.py`
  (`PultArtifactIsolationTest`, `ExternalWorkspaceIsolationTest`).

Требуется:
1. Область проекта для любого проекта, включая артель:
   `.artel/projects/<имя>/repo` — клон репозитория проекта;
   `.artel/projects/<имя>/worktrees/<id>/` — отдельная рабочая копия
   ветки кода каждой задачи; общий `workspace/` внешнего проекта
   заменяется ими. Клон заводится и обновляется пультом
   (`init`/`doctor --fix` либо при первом `new` — способ в SPEC).
2. Все git-операции задачи — ветка `task/*`, рабочая копия, подтяжка
   `main`, автокоммиты, ссылка документов `refs/artifacts/<id>`, push,
   временная рабочая копия мержа, push `main`, уборка веток и рабочих
   копий — идут в клоне проекта. Главная копия пульта в ходе задачи не
   меняется: ни веток, ни коммитов, ни ссылок, ни рабочих копий в её
   git (ADR-0021 п.1). Её git меняют только `pin-update`/`pin --to` и
   ремонт самого пульта (`doctor` хуков главной копии).
3. Шаги мержа и проверки, которые сегодня включаются сравнением пути с
   `config.ROOT` (перечень в «Фактах»), включаются по признаку проекта
   (артель / внешний), а не по пути, и для артели продолжают работать на
   клоне — ни один не отключается молча. SPEC перечисляет каждое такое
   место и его замену. Полное снятие развилок `DEFAULT_TARGET` — этап 3,
   не здесь.
4. `gitcmd.git` без явного репозитория перестаёт быть способом работать
   с проектом: вызовы, относящиеся к задаче, получают репозиторий
   проекта явно; оставшиеся вызовы по главной копии перечислены в SPEC
   с причиной.
5. Команды Оператора, пишущие в `main` артели (`note`, `doc-commit`,
   `canary pool-seal`), коммитят и пушат через клон артели в её области
   (п.6 ADR-0021) и не меняют рабочее дерево и git главной копии; база
   для сверки удержанных записей — `origin/main` клона, не HEAD главной
   копии. Отдельный `.artel/notes-work` упраздняется, если клон его
   заменяет (решение — в SPEC).
6. Хуки защиты `main` в клоне проекта артели берутся из пина (путь к
   `scripts/git-hooks` главной копии), а не из проверяемого кода клона;
   `doctor` проверяет хуки и в главной копии, и в клоне.
7. Канарейка строит в своём временном каталоге область `projects/artel`
   (клон и рабочие копии) так же, как боевой пульт, и исполняет код
   проверяемого коммита (ADR-0021 п.10).
8. Переход: исторические ссылки `refs/artifacts/*` (238 в главной копии)
   доступны чтению после этапа (через клон/`origin`; `docs`,
   `retro_corpus`, `show` работают); старые каталоги `.artel/worktrees/`
   пультом больше не создаются — их уборка не входит. Живых задач на
   момент мержа нет (ADR-0021 п.13).
9. Инварианты — приложением к PLAN, проверенным `git apply --check`:
   20 и 21 распространяются на любой проект, включая артель (таблица
   п.12 ADR-0021); новый инвариант «git главной копии пульта не меняется
   в ходе задачи» с проверкой в `tests/test_invariants.py` (тем же
   приложением): сквозной прогон FSM задачи артели в песочнице оставляет
   ветки, ссылки и рабочие копии главной копии неизменными.
   Изменения `tests/test_multitarget_invariants.py` — в объёме ADR-0021,
   с перечнем в PLAN.
10. Тесты в `tests/` с заявками «Ловит мутацию» на пп.1–7 (сторож
    свойства, которое доставляет приложение к защищённому пути, — в том
    же приложении). Существующие тесты не ослабляются; меняются только в
    объёме, прямо требуемом ADR-0021, — с перечнем в PLAN.

Зоны: orchestrator/, scripts/git-hooks/, tests/, docs/codebase-map.md.

Приложением: docs/invariants.md, tests/test_invariants.py, targets.yaml.

Только чтение (не менять): docs/adr/, docs/roadmap.md, docs/backlog.md,
docs/operator-session.md, templates/, skills/, CLAUDE.md, models.yaml,
roles.yaml, scripts/guard.py, .github/workflows/ci.yml, conftest.py.

Не входит: этап 3 (перевод проверок п.8 ADR-0021 на `repo_context`,
снятие развилок `DEFAULT_TARGET`, профиль тестов проекта); этап 4
(отмена наложения снимка и уборка `tasks/` из `main`); уборка старых
каталогов `.artel/worktrees/` и веток `task/*` в `origin`; разделение
журналов и базы по проектам (триггер №29).

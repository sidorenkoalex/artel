## Пути обхода гейтов
- Е1. «Первый шаг роли» не определён записью журнала (требования 4, 10: «в журнале ещё не было ни одного шага роли»). В журнале единственный маркер старта агента — «agent run started» (`orchestrator/runner.py:1608`; так же читают `zone_lock.py:225`, `models.py:1593`); отказы же паузы и стоп-крана пишутся актором роли (`runner.py:344`, `:360`), так будет и отказ конверта/`start_after`. Буквальная реализация «есть запись актором роли» делает первый отказ «шагом» — второй `run`/`auto` проходит и конверт, и `start_after`. Нужна строка в SPEC: шаг роли = запись «agent run started» любой роли, и AC на повторный отказ.
- Е2. Цикл через `merge_after` ловится только в одну сторону: требование 9 проверяет запись `start_after`; запись `merge_after` после `start_after` (`new --after` Э1, SPEC-поле на гейте, PLAN, ANSWER) идёт через `merge_after.check` с графом только `merge_after` (`merge_after.py:173`). Порядок записи обходит запрет цикла — задачи стоят взаимно навсегда (A ждёт B на запуске, B ждёт A на мерже). ТЗ «цикл, в том числе через `merge_after`» требует проверки взаимной, SPEC — только одной стороны.
- Е3. `epic envelope` разрешает любое число, разборное `cli_number` (`spend.py:22-29` принимает `0` и отрицательные): `epic envelope E 0` или `-5` — либо «без конверта» (если хранение как у `budget_usd`, где ≤ 0 — нет потолка, `budget.py:263-267`), либо вечное исчерпание. ТЗ «задаёт или поднимает» — SPEC не говорит, можно ли понизить конверт и что значит 0/отрицательное; понижение до 0 отключило бы проверку в обход смысла конверта.
- Е4. `epic start-after` на задачу, у которой шаг роли уже был, по требованию 10 ничего не держит (проверяется только первый шаг) — запись принимается молча. ТЗ это допускает буквально; SPEC не требует ни отказа, ни предупреждения. Не блок, кандидат решения на гейте.

## Пути обхода гейтов
- Проверка в `_refuse_before_start` закрывает `run`, `auto <id>` и
  повторный запуск (AC-10, AC-11): иного пути к `run_agent_once`, кроме
  `_cmd_run`, в коде нет.
- «Первый шаг» по записи «agent run started» любой роли (требование 6):
  задача, у которой агент стартовал и сразу упал, уже «начата» и дальше
  идёт при исчерпанном конверте — это буква решения №1 п. 1, не обход.
- Части деления начатой задачи эпика — новые задачи без «agent run
  started», их первый шаг при исчерпанном конверте отказан; соответствует
  ADR-0028 п. 8 (`:51`) буквально. Не отклонение.
- `epic envelope` с понижением ниже потраченного + подъём заново сбросят
  счёт алерта 80 % (требование 5) — лишний алерт, не обход отказа.
- Путей обойти отказ конверта или `start_after` буквальным исполнением
  SPEC не нашёл.

## Вердикт
`concerns` — блокирующих отклонений нет, решения гейта №1–№3 внесены
полностью; остаются две мелочи на решение Оператора:

1. Требование 10 (SPEC, раздел «Требования», п. 10) упоминает «алертов
   80/100 %», а алерта 100 % нет ни в ТЗ, ни в ADR-0028
   (`docs/adr/0028-epics-and-board-projection.md:51`), ни в требованиях
   5, 7 SPEC. Рекомендация: читать как «без алерта 80 % и без отказа
   100 %»; алерт 100 % не вводить.
2. Требование 4 / AC-7 / AC-27: «событие начисления» для `watch` не
   привязано к действиям журнала; реализация на одном `agent cost KNOWN`
   (`spend.py:557`) пропустит пересечение порога на `agent cost PARTIAL`
   / `ESTIMATED` (`spend.py:824`, `:834`). Рекомендация: события
   начисления — `KNOWN`, `PARTIAL`, `ESTIMATED`; тест — хотя бы одно не
   `KNOWN` событие.

Наблюдение для ревью (не отклонение): тексты причины/подсказки
требования 18 — в `auto.py`, не константами `config.py` как
`AUTO_STOP_PAUSE`/`AUTO_STOP_WAVE_BREAKER` (`config.py:935`, `:979`),
потому что `config.py` по ТЗ только для чтения.

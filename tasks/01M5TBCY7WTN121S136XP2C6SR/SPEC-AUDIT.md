## Пути обхода гейтов
- **Части деления как «новые» задачи.** Э1 даёт частям наследование эпика
  (`docs/adr/0028-epics-and-board-projection.md:104`), `spawn_subtask`
  (`catalog.py:735`) заводит новые строки без «agent run started». По
  треб. 6 части начатой и поделённой на гейте SPEC задачи — «не
  начатые»: при исчерпанном конверте они стоят, хотя ТЗ говорит «Начатые
  задачи доходят под своими потолками». Обратное толкование (части
  наследуют «начатость») дало бы обход конверта делением. SPEC молчит —
  отклонение 4 (вопрос Оператору на гейте).
- **`watch` без источника «до».** Треб. 4 требует пересечения порога, но
  `budget.epic_spent` даёт только текущее значение, а `watch` сейчас не
  считает денег вовсе (`watch.py:458`, `:492` — только строки журнала и
  алерты). Буквальное исполнение толкает либо к второй формуле «потрачено
  до события» из сумм в detail журнала (дефект по треб. 1), либо к
  упрощению «строка при первом событии ≥ порога», которое AC-7 не отличит
  — отклонение 2.
- Обход проверки запуска через `run`/`auto`/канарейку: все идут через
  `runner.cmd_run` → `_cmd_run` → `_run_developer_step` →
  `_refuse_before_start` (`runner.py:163`, `:257`, `:286`); AC-10 закрывает
  «отказ считается первым шагом». Иных путей старта агента нет.
- Гонка двух задач эпика у границы конверта (обе прошли проверку до
  начисления) — допускается смыслом ТЗ («начатые доходят»), не отклонение.

## Вердикт
**concerns.** Все 16 решений Оператора на гейте SPEC (№1 — 9, №2 — 7)
внесены; факты о коде пульта подтверждены. Отклонения — на решение
Оператора на гейте:

1. **Код Э1 не сверен** — `epics.py`, `board.py`, `new --epic`, `new
   --after` в main отсутствуют (`git grep` пуст; ADR-0028 `:33`, `:104`);
   треб. 9, 11, 14, 19 и AC-14, AC-19 (канал `new --after`), AC-24, AC-25
   опираются на интерфейсы Э1. SPEC это признаёт (SPEC «Материалы»);
   `merge_after: 01M5TBBDFS6DWQY6MS263T1KPY` в frontmatter держит порядок
   мержа, но не сверку. Оператору: принять как есть или требовать сверки
   после мержа Э1.
2. **`watch` — пересечение порога не определено и не проверено** (SPEC
   треб. 4, AC-7): не названо, откуда `watch` берёт «потрачено до события»
   без второй формулы (`watch.py:458`, `:492` денег не считают); AC-7 не
   ловит мутацию «строка при любом событии ≥ порога, раз за сессию»
   (нет AC с сессией, начатой уже выше порога).
3. **Нет AC на «только первый шаг» для `start_after`** (SPEC треб. 15):
   мутация «проверять `start_after` на каждом шаге» проходит все AC;
   аналог AC-12 для `start_after` отсутствует.
4. **Части поделённой начатой задачи** (SPEC треб. 6, 8;
   `fsm.py:974-981`, `catalog.py:735`; ADR-0028 `:104`): не сказано,
   считаются ли части задачи, у родителя которой шаг роли был, «начатыми»
   для конверта — оба толкования расходятся с ТЗ («начатые доходят» либо
   обход конверта делением).
5. **«Алерт 100 %» в треб. 10** — не определён ни ТЗ, ни треб. 5, ни
   решением №1 (4); формулировка допускает лишний механизм. Правка слова
   на гейте.

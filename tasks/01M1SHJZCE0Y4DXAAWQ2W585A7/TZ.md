# ТЗ: штатный канал заведения подзадач деления — пульт заводит их из SPEC при approve, не роль

Источник: копилка 05.09 (docs/backlog.md, приоритет 2), третий за неделю
случай класса «скил отстаёт от механики». Скил `skills/spec-authoring.md`
(раздел «Нарезка на 2–4 подзадачи») велит аналитику «заведи подзадачи
командой `cmd_new`», а инвариант «пульт только из главной копии» (T056)
запрещает команды пульта из worktree роли; analyst задачи наблюдателя
карты (SPEC 01M1RFVWV6…) честно отказался и оставил заведение
Оператору. Решение Оператора 05.09: у роли появляется штатный канал
заявки на подзадачу через артефакт, заводит пульт.

Требуется:
1. Формат заявки в SPEC: раздел `## Деление` с подразделами по одной
   подзадаче — название (строка), ТЗ подзадачи (текст, который станет
   `TZ.md`), зоны, рамка, порядок (зависимость от предыдущей части);
   формат проверяется `scripts/guard.py` (обязательные поля, 2–4
   подзадачи, зоны не режут зону родителя поперёк — хотя бы проверка,
   что каждая зона подзадачи входит в зоны родителя или в общие зоны).
2. При `approve` на `spec_gate` SPEC с разделом «Деление» пульт заводит
   подзадачи через ту же механику, что `cmd_new` (`catalog.cmd_new` или
   её внутреннюю функцию): название, `TZ.md` из текста заявки с
   первой строкой «Родительская задача: <id> — <название>», зоны и
   рамка — в текст ТЗ (аналитик подзадачи оформит SPEC как обычно).
   Родительская задача при этом переходит в состояние, которое сегодня
   получает поделённая задача (по механике 01M1KS8K9R…: если такого
   состояния нет — `killed` с записью «поделена на …» в журнале и
   перечнем id подзадач; уточнить по коду и назвать в SPEC).
3. Идентификаторы подзадач печатаются Оператору и пишутся в журнал
   родителя; повторный approve не заводит дубли (идемпотентность по
   записи журнала «поделена на …»).
4. Приложением к PLAN (защищённые пути): `skills/spec-authoring.md` —
   вместо «заведи подзадачи командой cmd_new» описание раздела
   «Деление»; `docs/operator-gates.md`, гейт SPEC, п.6 — Оператор видит
   заявку на деление в SPEC и утверждает её approve.
5. Тесты: SPEC с корректным разделом «Деление» — approve заводит N
   подзадач с TZ.md и ссылкой на родителя, журнал родителя содержит их
   id; повторный approve дублей не заводит; неполная заявка — отказ
   guard с названием поля; зона подзадачи вне зон родителя — отказ
   guard. Существующие тесты `cmd_new` и гейта SPEC зелёные без
   ослабления.

Зоны: orchestrator/catalog.py, orchestrator/fsm.py, scripts/guard.py,
templates/SPEC.md, tests/.

Не входит: механика родительства в БД (связка остаётся текстом, как
сегодня); автоматический порядок запуска подзадач; деление на этапе
PLAN.

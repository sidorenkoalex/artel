# SPEC: Единый коммит результата роли через пульт для всех провайдеров

## Контекст
Задача сужена решением Оператора 02.10 при возврате с гейта SPEC: с 02.10
все роли конвейера постоянно работают на `claude-opus-5-5`, Codex в
рабочих задачах не используется. Канарейка 20261002T092509Z (developer на
`gpt-6-sol`) прошла без эскалаций. Поэтому в задаче остаются только
дефекты, которые от провайдера не зависят.

Первый дефект — контракт. Миссия developer (`orchestrator/role_prompt.py`,
пункт 4: «закоммить код в ветку») и скил `coding-standards.md` («ход
разработчика заканчивается коммитом кода», коммит пультом — «дефект шага»)
требуют коммита от роли. При этом пульт штатно коммитит оставленный в
worktree код существующим механизмом `checkpoint.py`
(`commit_success_checkpoint`, SPEC 01M283NC4JJXK7QS68Y9ET8TBK). Роль,
которая не может или не стала коммитить, считает это своим дефектом и
эскалирует (01M3SX69E8P64D77J1XTHMHE40, 01M3V4ZPB6HFDJ36MTDAQG5VNT).

Второй дефект — диагностика. Сбой git внутри
`checkpoint._commit_worktree_change` (`add`/`reset`/`commit`) возвращает
«не закоммичено» без записи в журнал. Следующий `advance` объясняет
грязную копию текстом «роль обязана коммитить артефакты»
(`fsm._dirty_refuses`), а не настоящей причиной. С записью
`TEST_AUTHOR_NOT_COMMITTED_ACTION` у test_author то же самое: текста
ошибки git в ней нет.

## Требования
1. Контракт роли. Миссии ролей, которые собирает `orchestrator/role_prompt.py`,
   не требуют от роли выполнять `git add`/`git commit` для кода. Миссия
   developer прямо сообщает: код, оставленный в worktree незакоммиченным,
   по итогам шага коммитит пульт существующим механизмом `checkpoint.py`.
   Роль может оставить код незакоммиченным.
2. Успешный штатный коммит пульта — норма, а не дефект роли. Исход шага
   остаётся «ok», алерт не заводится, запись провала или отказа шага в
   журнал не пишется. Если журнал получает запись об этом коммите, она не
   квалифицирует его как дефект или нарушение роли.
3. Реальная ошибка коммита пульта не проходит молча. Это ненулевой код
   возврата git на операции коммита пульта (`add`, `reset`, `commit`),
   кроме случая «нечего коммитить». В этом случае:
   - журнал получает запись с именем операции git и текстом ошибки git;
   - изменения остаются в worktree, не откатываются и не теряются;
   - задача не переходит из текущего состояния;
   - текст отказа `advance` по грязной копии (`fsm._dirty_refuses`)
     называет незакоммиченный результат шага и не утверждает, что
     коммитить обязана роль.
4. test_author. Если git отказывает при коммите собственных долгоживущих
   файлов задачи, срабатывает требование 3. Запись
   `TEST_AUTHOR_NOT_COMMITTED_ACTION` несёт имя операции git и текст его
   ошибки, а файлы остаются в worktree. Мандат test_author не расширяется.
5. Содержательная эскалация роли сохраняется. PLAN со `status: escalate`
   уводит задачу в `escalated` при `advance`, даже когда пульт успешно
   закоммитил код этого шага. Автоматически эскалация не снимается.
6. Документация. `docs/stack.md` описывает правило: штатный коммит кода
   результата шага делает пульт существующим механизмом `checkpoint.py`,
   роль коммитить не обязана. `docs/operator-session.md` описывает, что
   Оператор видит в журнале при отказе git на коммите пульта и как это
   разобрать.
7. Приложение для Оператора к PLAN.md (защищённые пути роль не правит).
   Это unified-диф к `skills/coding-standards.md` и
   `skills/conventions-core.md`:
   - в `coding-standards.md` (раздел «Завершение хода») он убирает
     требование заканчивать ход коммитом кода и квалификацию коммита
     пультом как дефекта шага;
   - в `conventions-core.md` он правит строки о том, что роль коммитит
     код, и о регенерации карты «тем же коммитом».

   Диф проверен `git apply --check`. `templates/` правок не требуют: ни один
   шаблон не требует от роли коммита кода.

## Критерии приёмки
AC-1. Текст миссии developer, который собирает `role_prompt.mission_brief_package`, не содержит требования закоммитить код и сообщает, что незакоммиченный код worktree по итогам шага коммитит пульт. Ни одна из миссий analyst/test_author/developer/reviewer не требует от роли выполнить `git add` или `git commit`.

AC-2. Успешный штатный коммит пульта не заводит алерт и не пишет в журнал запись провала или отказа шага. Если журнал несёт запись об этом коммите, в ней нет слов «дефект» и «нарушение».

AC-3. Отказ git пульта. Операция коммита пульта (`add`, `reset` или `commit`) возвращает ненулевой код, и это не случай «нечего коммитить». Тогда:
- журнал несёт запись с именем этой операции git и текстом ошибки git;
- изменения остаются в worktree незакоммиченными и не откаченными;
- последующий `advance` не переводит задачу из текущего состояния;
- текст отказа `advance` по грязной копии (`fsm._dirty_refuses`) называет незакоммиченный результат шага и не утверждает, что коммитить обязана роль.

AC-4. test_author. В `tests_writing` git отказывает при коммите собственного файла задачи `tests/test_<префикс задачи>_<имя>.py`. Тогда запись `TEST_AUTHOR_NOT_COMMITTED_ACTION` содержит имя операции git и текст его ошибки, а файл остаётся в worktree.

AC-5. Содержательная эскалация. Шаг developer оставил PLAN.md `status: escalate` и незакоммиченный код, и пульт успешно закоммитил код. Тогда `advance` переводит задачу в `escalated`.

AC-6. `docs/stack.md` содержит правило: штатный коммит кода результата шага делает пульт, роль коммитить не обязана. `docs/operator-session.md` содержит описание записи журнала при отказе git на коммите пульта и порядок разбора.

AC-7. PLAN.md несёт приложение-диф к `skills/coding-standards.md` и `skills/conventions-core.md`. Оно убирает требование, чтобы роль заканчивала ход коммитом кода, и квалификацию коммита пультом как дефекта шага. Диф применяется `git apply --check` на чистом дереве ветки.

## Оценка объёма и деление
Сработавшие сигналы:
- в зоне 6 путей (порог 5);
- зона `orchestrator/checkpoint.py` задевает механизм фиксации SHA и
  WIP-чекпоинтов, на который опираются записи `docs/invariants.md`.

Решение — обоснование монолита (утверждает Оператор на гейте SPEC):
- Код меняется в одной обвязке: журналирование отказа git в
  `checkpoint._commit_worktree_change` и в записи test_author, плюс текст
  отказа `fsm._dirty_refuses`. Механика коммита не меняется. Остальные
  пути зоны — текст миссии (`role_prompt.py`), два документа и один
  тестовый файл.
- Если делить, получится плохое промежуточное состояние. Часть «только
  контракт» снимает с роли требование коммита, а отказ git пульта
  остаётся молчаливым, и `advance` по-прежнему отправляет роль коммитить.
  Часть «только диагностика» оставляет миссию, которая называет штатный
  коммит пульта дефектом роли.
- Объём уже сужен Оператором 02.10. Деление удвоило бы постоянную часть
  цены (analyst, test_author и ревью на каждую часть) при рамке $20.
- Бюджет. Калибровочный класс — «до 10 критериев и до 4 файлов» либо
  «до 15 критериев и до 7 файлов» (~$40–45). `budget_usd: 20` — рамка
  Оператора из решения 02.10. Это ниже калибровочной планки $25, и гейт
  SPEC покажет строку «рамка ниже калибровки». Если две итерации ревью
  упрутся в потолок, поднять его может Оператор командой `budget`.

- Снятие содержательных эскалаций роли (PLAN/REVIEW `status: escalate`,
  `QUESTIONS.md`, пометки `AC-n: escalate`).
- Второй механизм коммита рядом с `checkpoint.py`. Аварийный автокоммит
  (01M283NC4JJXK7QS68Y9ET8TBK) и зонный фильтр
  (01M290PVYG2VJK6442H5BAX9MA) переиспользуются как есть.
- Регрессии по провайдерам (Codex с недоступным git index, Claude) и
  ручной живой прогон канарейки с developer на Codex. Решение Оператора
  02.10: Codex в рабочих задачах не используется.
- Сохраняются без изменения поведения, отдельные критерии не нужны
  (решение Оператора 02.10):
  - внешний target: workspace не коммитится, ADR-0003 §4;
  - песочница и права ролей, в том числе мандат test_author и отсутствие
    права коммитить код у analyst и reviewer;
  - зонные проверки, защита main, лок приёмочных и долгоживущих тестов;
  - разделение кодовой и артефактной веток, lease, аварийные
    WIP-чекпоинты и фиксация SHA;
  - текущее поведение коммита пульта: момент коммита до «agent run
    finished», отбор посторонних файлов (`STRAY_WORKTREE_FILES_ACTION`),
    отсутствие пустого или дублирующего коммита при повторе, частичные
    коммиты роли.
- Мандат Оператора «Расширение зон разрешено» из `ANSWER-n.md` в зонах
  коммита пульта (`advance_gates/zones.py`, `advance_gates/mandate.py`).
  Его нет в перечне «Оставить» решения 02.10, и его пути не входят в зоны.
- `orchestrator/runner.py`, `orchestrator/brief.py` и несуществующий
  `orchestrator/agent_prompt.py` из зон ТЗ. Миссии собирает
  `role_prompt.py`. Решение 02.10: `runner.py` не трогать, если правка его
  не требует.
- Правка существующих файлов `tests/`. Новые тесты — только в
  `tests/test_role_commit_by_pult.py` (решение 02.10).
- Прямая правка `skills/` и `templates/`. Только приложение к PLAN.md для
  Оператора (требование 7).
- Полный зелёный набор `tests/`, зелёный CI ветки, неизменность
  защищённых путей и непревышение бюджета — их держит пульт.

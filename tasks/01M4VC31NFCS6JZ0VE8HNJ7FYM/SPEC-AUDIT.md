**Т-1 (пробел AC-1…AC-3).** Все фикстуры журнала в критериях состоят только
из переходов (`created`, затем записи `state -> …`). Между ними нет ни одной
записи другого действия (SPEC.md:98-117). В реальном журнале клона между
`state -> spec_audit` и `state -> escalated` стоят записи шага роли:
«agent run …» пишет `cmd_run` (докстринг canary.py:1840-1846), есть и записи
аудита SPEC.

Мутацию «роль по непосредственно предыдущей записи; если это не переход, то
`spec_writing`» проходят все три критерия:
- в AC-1 первую эскалацию предваряет `created`, мутация даёт `analyst`;
- вторую эскалацию предваряет `state -> spec_audit`, мутация даёт
  `spec_auditor`.

В живой канарейке та же мутация запишет ловушку как `analyst,analyst`, и
прогон останется не чистым — цель ТЗ не достигнута. Закрыть пробел можно
требованием, чтобы фикстура AC-1 (или AC-2) несла записи прочих действий
между `state -> X` и `state -> escalated`, как в настоящем журнале клона.

## Пути обхода гейтов
- **П-1 (Т-1).** Разработчик определяет источник по непосредственно
  предыдущей записи журнала. AC-1…AC-3 зелёные, приёмка пройдена. В живой
  канарейке эскалация аудитора записывается как `analyst`, ловушка остаётся
  не чистой — в обход смысла требования 1.
- **П-2 (Т-2).** Чтобы не уронить tests/test_model_sets.py:97-112,
  разработчик добавляет в `canary_row` ключ `escalation_roles` со значением
  по умолчанию. Если значение будет не `None`, а, например, `''`, все
  проверки этого файла молча уйдут с ветки старого правила на новую, и
  проверка «старые строки — по числу» в нём исчезнет. Гейт неослабления
  смену помощника может и не поймать: ожидания утверждений остаются
  прежними.
- Иных путей не нашёл. Перечень вычисляет пульт, клон подделать его не
  может: вычисление идёт из `steps`, которые клон и так отдаёт пульту.

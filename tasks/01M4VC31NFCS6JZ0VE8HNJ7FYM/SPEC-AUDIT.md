## Пути обхода гейтов
- П-1 (О-1): разработчик реализует AC-3 буквально (`_previous_state_name`
  → `None` → неизвестная роль), фикстуры AC-1/AC-4 строит с записью
  `state -> spec_writing` — все критерии зелёные, приёмка пройдена, а в
  живой канарейке каждая эскалация аналитика при первом визите
  `spec_writing` становится неизвестной ролью: ловушки остаются не
  чистыми, цель ТЗ не достигнута, и обнаружится это только на следующем
  прогоне `admit`.
- П-2 (О-4): допустимый перечень ролей возвращает «чистый» раньше
  проверки отказа автогейта — приёмка не поймает, прогон с отказом по вине
  роли засчитается чистым в допуск ADR-0019 п.5.
- П-3 (О-3): поле перечня добавлено в `_DRIVE_METRIC_FIELDS` — прогон
  канарейки кодом коммита до этой задачи (клон без нового поля) пишется
  красным «результат без полей»; либо обратное — поле не обязательно, и
  его потеря молча переводит строку в «без данных о ролях» (старое
  правило, строже — не ослабление, но ловушка снова не чистая).

## Вердикт
**fail** — SPEC в таком виде ведёт к реализации, которая проходит приёмку
и не достигает цели ТЗ.

Отклонения:
- **О-1 (блокирующее).** AC-3 (SPEC.md:80-83) и треб. 1 (SPEC.md:38-39)
  определяют «состояние-источник не установлено» как «нет предшествующего
  перехода в журнале». Первый визит `spec_writing` в журнал переходом не
  пишется (`orchestrator/catalog.py:667`, `:670`; `orchestrator/auto.py:400`),
  поэтому эскалация аналитика в прогоне-ловушке станет неизвестной ролью.
  SPEC должен явно задать: нет предшествующей записи `state -> X` →
  состояние-источник — начальное состояние задачи `spec_writing`
  (analyst), и AC-1/AC-4 должны требовать журнал без
  `state -> spec_writing` перед первой эскалацией (как в реальном клоне);
  «неизвестная» — только для источника вне сопоставления ролей.
- **О-2.** AC-5 (SPEC.md:91-102) «называет неизвестную роль» — литерал
  неизвестной роли в перечне и в причине не зафиксирован, проверить это
  тест может, только навязав имя (риск `тест-навязывает-устройство`).
  Нужен литерал в SPEC.
- **О-3.** SPEC не называет, где вычисляется перечень (код клона —
  `canary_drive.py:71-78` — или пульт по `steps` результата), и как
  ведёт себя приём результата без нового поля
  (`orchestrator/canary.py:291-295`, `:2333`).
- **О-4.** Нет критерия, что строка с данными о ролях при допустимом
  перечне остаётся не чистой при отказе автогейта по вине роли / итерациях
  ревью / не green (`orchestrator/models.py:1140-1143`, `:1152-1154`);
  требование 5 приёмкой не закреплено.

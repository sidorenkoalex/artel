## Пути обхода гейтов

- Е-7 (повтор ссылки на часть, низкая значимость; SPEC.md:94-97). Отказ за повтор требование 5 называет только для элемента-id («по правилам `merge_after.check` по задаче»). Повтор номера части («после части 1, части 1») не запрещает ни одно требование, и буквальное исполнение может записать в `merge_after` части «X, X». ТЗ требует, чтобы каждая запись проходила `merge_after.check`, а повтор — одно из правил этого `check` (`orchestrator/merge_after.py:167-168`). Исправить можно одной строкой («повтор элемента, в том числе номера части») или принять: на гейте SPEC части повтор вылезет отказом формы в SPEC части.
- Е-8 (порядок проверок, к сведению). Преемник (требование 4) определён только для ациклического графа частей: при цикле среди частей может не оказаться кандидата «от которого не зависит ни одна часть». Требование 5 строит виртуальный граф с поправкой на преемника, поэтому цикл между самими частями нужно проверять до расчёта преемника. Иначе реализация падает (`max` пустого множества) вместо отказа. Такой сбой ловит AC-6, так что это не отклонение.
- Е-3 (сторож, к сведению; SPEC признаёт в «Не входит»). Сторож ловит только литерал-контейнер. Составные выражения его обходят, их ловит только ревью.
- Е-6 (форма рамки, к сведению). Строгое «$N» откажет на привычной записи «Рамка: $30. Набор моделей — по умолчанию.»: `cli_number("30. Набор…")` даёт `None`. Это строгость по ТЗ, а не обход. Ошибка guard называет часть.
- Других обходов смысла гейтов буквальным исполнением SPEC не найдено. Рамку выше cap и ≤ 0 отсекают guard и approve. Цикл и мёртвую зависимость отсекает виртуальный граф с поправкой на преемника. Записи до отказа запрещает требование 6, и проверяет это AC-10.

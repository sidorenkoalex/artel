# SPEC: Наборы моделей: файл model_sets.yaml и команда допуска пары

## Контекст
Часть 1 из 3 деления задачи 01M3Y9YCKBFRJ8T9HSD40Z3AQN («Набор моделей
отдельной задачи — new --set с допуском по ADR-0019 п.5», решение
Оператора 02.10.2026). ADR-0019 п.5 требует, чтобы допуск пары «роль —
модель» и набора выдавался решением Оператора, записанным в репозитории,
по числам прогонов канарейки. Сейчас такого носителя нет: наборы
канарейки (`canary_sets:`) живут в локальном слое вне git, а
`models.yaml` защищён и решений о допуске не несёт. Эта часть заводит
отслеживаемый файл решений `model_sets.yaml`, проверку допуска набора
(вход части 2) и команду Оператора выдачи/снятия допуска пары с проверкой
чисел ADR-0019 п.5 по таблице `canary_runs`.

## Требования

1. **Файл `model_sets.yaml`.** Новый отслеживаемый git файл в корне
   репозитория пульта (не раздел `canary_sets:` локального слоя и не
   `models.yaml`). Формат — YAML в подмножестве, которое читает
   `orchestrator/yamlmini.py` (вложенные отображения), три раздела верхнего
   уровня:
   - `sets:` — именованные наборы задач: `<имя набора>:` -> `<роль>: <id
     модели каталога>` для части ролей;
   - `pairs:` — допущенные пары: `<роль>:` -> `<id модели каталога>:` ->
     поля `date` (дата решения), `basis` (основание: ссылки на прогоны
     канарейки или документ замера), `state` (`допущена` /
     `приостановлена` — выставляет команда допуска);
   - `canary_templates:` — `<имя шаблона, как в поле title строки
     canary_runs>: <класс>`, класс — `быстрый` / `средний` / `трудный`;
     заполняет Оператор.
   Счётчик пробных задач в файле не хранится. Файл несёт только решения
   Оператора: пульт коммитит его только командой допуска (требование 3).
   В репозиторий файл кладётся с тремя разделами без записей.
2. **Защита и правка файла.** `model_sets.yaml` входит в
   `config.PROTECTED_PATHS` (роли его не правят) и в
   `notes.DOC_COMMIT_CONFIG_PATHS` (Оператор правит его `doc-commit`).
3. **Команда допуска пары** `admit <роль> <модель> --basis <текст>` и
   снятие `admit --revoke <роль> <модель> --basis <текст>`.
   - Выдача печатает сводку прогонов канарейки этой пары из
     `canary_runs` (прогон пары — строка, в сводке `models_summary`
     которой роль идёт этой моделью) против чисел ADR-0019 п.5: не меньше
     трёх чистых прогонов (требование 5) не меньше чем на двух разных
     шаблонах, из них хотя бы один на шаблоне класса `средний` по разделу
     `canary_templates:`; для роли `analyst` — дополнительно хотя бы один
     прогон пары с правильным исходом неясности ТЗ: заданный
     `expected_escalation`, `actual_escalation = 1`,
     `marker_mismatch = 0`.
   - Сводка прямо пишет «повторы developer: нет данных» — условие «без
     повтора developer» не проверяется.
   - Шаблон без записи класса не засчитывается в «средний» и называется
     в перечне недостающего.
   - Недобор хотя бы по одному числу — отказ (ненулевой код выхода) с
     перечнем недостающего; `model_sets.yaml` не меняется. Флага,
     выдающего допуск вопреки недобору, нет.
   - Достаточно — пара записывается в `pairs:` с `state: допущена`,
     датой и основанием из `--basis`.
   - `--revoke` записывает паре `state: приостановлена` (дата и
     основание обновляются).
   - Запись в `model_sets.yaml` — изолированным коммитом тем же
     механизмом, что `doc-commit` (окно тишины, удержание).
4. **Проверка допуска набора** — одна функция (ею пользуется часть 2):
   набор из `sets:` допущен, если (а) каждая его пара «роль — модель»,
   отличная от боевой (модель, которую роль получает разрешением моделей
   пульта без набора), записана в `pairs:` с `state: допущена`, И (б) в
   `canary_runs` есть строка с `verdict = green`, сводка «роль -> модель»
   которой совпадает с составом набора по всем его ролям, на шаблоне
   класса `трудный` по разделу `canary_templates:`. Шаблон без записи
   класса трудным не считается.
5. **Чистый прогон** — строка `canary_runs` с `verdict = green`,
   `review_iterations = 0`, без эскалаций кроме ожидаемой
   (`escalations = 0` либо заданный `expected_escalation`,
   `actual_escalation = 1`, `marker_mismatch = 0`) и с
   `autogate_refusal` пустым или отнесённым к пульту/пулу по правилу
   вины (требование 6).
6. **Правило вины отказа автогейта** — одна функция (ею пользуется и
   часть 3), классифицирующая `autogate_refusal` в один из трёх исходов:
   - «роль» — причина: критерии `manual`/`skip` в планке (test_author),
     красный полный набор `tests/` или непройденный критерий `ci`
     (developer);
   - «пульт/пул» — причина: ошибка источника планки или пустой каталог
     приёмочных тестов, незаведённый worktree, таймаут прогона или
     отсутствие `tests/` в worktree, исчерпанный бюджет, отказ попытки
     роли, классифицированный `orchestrator/failure_classification.py`;
   - «не установлена» — причина вне обоих перечней; прогон с ней не
     чистый.
7. **Документация.** Раздел в `docs/stack.md`: файл `model_sets.yaml`
   (разделы и их смысл), допуск пары и набора, команда `admit`.
8. **Тесты** в `tests/` на поведение требований 3–6 (см. критерии
   приёмки). Существующие тесты разрешения моделей, канарейки и
   автогейта не удаляются и не ослабляются.

## Критерии приёмки

AC-1. В корне репозитория есть отслеживаемый git файл `model_sets.yaml`
с разделами `sets:`, `pairs:`, `canary_templates:`; он читается
`orchestrator/yamlmini.py` без ошибок; в нём нет поля счётчика пробных
задач.

AC-2. `model_sets.yaml` входит в `config.PROTECTED_PATHS`
(`config.is_protected_path("model_sets.yaml")` истинно) и в
`notes.DOC_COMMIT_CONFIG_PATHS`.

AC-3. `admit <роль> <модель> --basis <текст>` при недоборе прогонов
(меньше трёх чистых, либо меньше двух шаблонов, либо ни одного чистого
на шаблоне класса `средний`) завершается отказом с перечнем
недостающего, а содержимое `model_sets.yaml` и HEAD репозитория не
меняются.

AC-4. Прогон пары на шаблоне без записи в `canary_templates:` не
засчитывается в «средний»; имя этого шаблона названо в перечне
недостающего отказа `admit`.

AC-5. `admit analyst <модель> --basis <текст>` при трёх чистых прогонах
на двух шаблонах с одним средним, но без прогона с заданным
`expected_escalation`, `actual_escalation = 1`, `marker_mismatch = 0`, —
отказ с перечнем, где назван недостающий прогон с неясностью ТЗ; файл не
меняется.

AC-6. Сводка, которую печатает `admit`, содержит строку «повторы
developer: нет данных».

AC-7. `admit <роль> <модель> --basis <текст>` при достаточных прогонах
записывает в `pairs:` пару с `state: допущена`, датой и основанием и
создаёт изолированный коммит, затрагивающий только `model_sets.yaml`,
механизмом `doc-commit`.

AC-8. `admit --revoke <роль> <модель> --basis <текст>` записывает паре
`state: приостановлена` изолированным коммитом, затрагивающим только
`model_sets.yaml`.

AC-9. Прогон с `verdict = green`, `review_iterations = 0`,
`escalations = 0` и `autogate_refusal`, отнесённым правилом вины к
пульту/пулу (например, исчерпанный бюджет), признаётся чистым.

AC-10. Прогон с теми же полями, но с `autogate_refusal`, отнесённым к
роли (например, красный полный набор `tests/`), чистым не признаётся;
прогон с причиной вне обоих перечней получает исход «не установлена» и
чистым не признаётся.

AC-11. Прогон с `review_iterations > 0` или с эскалацией, не являющейся
ожидаемой (`escalations > 0` без заданного `expected_escalation` с
`actual_escalation = 1`, `marker_mismatch = 0`), чистым не признаётся.

AC-12. Функция проверки допуска набора возвращает «не допущен» для
набора, все не-боевые пары которого записаны с `state: допущена`, но в
`canary_runs` нет зелёного прогона набором целиком на шаблоне класса
`трудный`; та же функция возвращает «не допущен», если такой прогон есть
только на шаблоне без записи класса.

AC-13. Функция проверки допуска набора возвращает «допущен», если каждая
не-боевая пара набора записана с `state: допущена` и есть зелёный
прогон, сводка моделей которого совпадает с составом набора по его
ролям, на шаблоне класса `трудный`; и «не допущен», если хотя бы одна
не-боевая пара отсутствует в `pairs:` или записана с
`state: приостановлена`.

AC-14. В `docs/stack.md` есть раздел о файле `model_sets.yaml`, допуске
пары и набора и команде `admit`.

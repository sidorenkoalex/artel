# ТЗ: Наборы моделей: файл model_sets.yaml и команда допуска пары

Родительская задача: 01M3Y9YCKBFRJ8T9HSD40Z3AQN — Набор моделей отдельной задачи: new --set с допуском по ADR-0019 п.5
Зоны: model_sets.yaml, orchestrator/models.py, orchestrator/notes.py, orchestrator/artel.py, orchestrator/config.py, docs/stack.md, tests/
Порядок: первая, без зависимостей
Рамка: $40

Часть 1 из 3 деления задачи «Набор моделей отдельной задачи — new --set с
допуском по ADR-0019 п.5» (решение Оператора 02.10.2026, ANSWER-1 этой
задачи). Условия допуска — строго по ADR-0019 п.5.

Только чтение (не менять): orchestrator/failure_classification.py,
orchestrator/fsm_autogate.py, orchestrator/canary.py,
orchestrator/canary_drive.py, orchestrator/pin.py, models.yaml,
orchestrator/fsm_merge_gate.py, orchestrator/providers/, scripts/guard.py,
skills/, templates/, docs/adr/, docs/invariants.md,
tests/test_invariants.py, docs/backlog.md, tasks/, .artel/, .codex/.

Требуется:
1. Новый отслеживаемый git файл `model_sets.yaml` в корне (не
   `canary_sets:` локального слоя и не защищённый `models.yaml`); формат
   выбирает SPEC. Файл несёт ТОЛЬКО решения Оператора, пульт его сам не
   коммитит вне команды допуска:
   - именованные наборы задач: набор — отображение «роль -> модель
     каталога» для части ролей;
   - допущенные пары «роль — модель каталога»: роль, модель, дата,
     основание (ссылки на прогоны канарейки или документ замера),
     состояние, выставленное командой допуска (`допущена` /
     `приостановлена`);
   - раздел шаблонов канарейки: имя шаблона (как его пишет поле `title`
     строки `canary_runs`) -> класс `быстрый` / `средний` / `трудный`;
     заполняет Оператор.
   Счётчик пробных задач в файле НЕ хранится (он считается из БД частью 3).
   Файл добавляется в `config.PROTECTED_PATHS` (роли его не правят) и в
   `notes.DOC_COMMIT_CONFIG_PATHS` (Оператор правит его `doc-commit` и
   командой допуска).
2. Проверка допуска набора (одна функция, ею пользуется часть 2): набор
   допущен, если допущена каждая его пара, отличная от боевой, И в
   `canary_runs` есть зелёный прогон канарейки этим набором целиком
   (сводка «роль -> модель» прогона совпадает с составом набора по его
   ролям) на шаблоне трудного класса по разделу шаблонов. Шаблон без
   записи класса трудным не считается.
3. Команда Оператора выдачи и снятия допуска пары (имя выбирает SPEC,
   например `admit <роль> <модель> --basis <текст>` и `admit --revoke`).
   Команда печатает сводку прогонов канарейки этой пары из `canary_runs`
   против чисел ADR-0019 п.5: не меньше трёх чистых прогонов не меньше
   чем на двух шаблонах, из них хотя бы один среднего класса; для
   analyst — ещё прогон на шаблоне с неясностью ТЗ с правильным исходом.
   Недобор — отказ с перечнем недостающего; выдать допуск вопреки
   недобору нельзя. Запись в `model_sets.yaml` — изолированным коммитом
   тем же механизмом, что `doc-commit` (окно тишины, удержание).
   - Шаблон без записи класса не засчитывается в «средний» и называется
     в перечне недостающего.
   - «Неясность ТЗ с правильным исходом» для analyst — строка прогона с
     заданным `expected_escalation`, `actual_escalation = 1`,
     `marker_mismatch = 0`.
   - Чистый прогон — `verdict = green`, `review_iterations = 0`, без
     эскалаций, кроме ожидаемой (`escalations = 0` либо
     `expected_escalation` задан, `actual_escalation = 1`,
     `marker_mismatch = 0`), `autogate_refusal` пуст или отнесён к
     пульту/пулу по правилу вины (п.4). Условие «без повтора developer»
     не проверяется: таблица повторов не хранит, `orchestrator/canary.py`
     не трогать; сводка команды прямо пишет «повторы developer: нет
     данных».
4. Правило вины отказа автогейта (одно на эту часть и часть 3): отказ
   относится к роли, если его причина — критерии `manual`/`skip` в
   планке (test_author), красный полный набор `tests/` или непройденный
   критерий `ci` (developer); к пульту/пулу — ошибка источника планки или
   пустой каталог приёмочных тестов, незаведённый worktree, таймаут
   прогона или отсутствие `tests/` в worktree, исчерпанный бюджет, отказ
   попытки роли, классифицированный `orchestrator/failure_classification.py`.
   Причина вне обоих перечней — «не установлена»: прогон с ней не чистый
   (ADR-0019 п.5: отказ по дефекту пульта не портит прогон, «если
   причина установлена»).
5. Документация: раздел в `docs/stack.md` — файл наборов, допуск пары и
   набора, команда допуска.
6. Тесты в `tests/`: команда допуска при недоборе прогонов — отказ с
   перечнем, файл не меняется; шаблон без класса не засчитан в
   «средний» и назван в перечне; analyst без прогона с правильной
   эскалацией — отказ; прогон с отказом автогейта по вине пульта —
   чистый, по вине роли или с неустановленной причиной — нет; набор с
   допущенными парами без зелёного прогона трудного класса набором
   целиком — не допущен. Существующие тесты разрешения моделей,
   канарейки и автогейта не удаляются и не ослабляются.

Не входит: `new --set`, разрешение модели с учётом задачи, пробный период,
приостановка (части 2–3); выдача допуска конкретным парам (решение
Оператора после мержа); изменение чисел допуска ADR-0019; возврат связки
`role_models:`; наборы канарейки и её вердикты; колонка повторов developer
в `canary_runs`.

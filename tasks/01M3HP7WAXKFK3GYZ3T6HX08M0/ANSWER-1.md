# ANSWER-1: ответы Оператора на вопросы аналитика

1. **Способ учёта повторов — вариант A, подавление без счёта.** Журнал
   остаётся только дописываемым, `orchestrator/store.py` не правится и в
   зоны не входит. Требование 1 в SPEC: повтор не журналируется
   отдельной записью в пределах одного пребывания задачи в состоянии;
   каждое срабатывание по-прежнему печатается в stdout. Слово
   «считаются» из ТЗ снимается.

   Уточнение к ключу подавления. Для `pre-flight WARNING` и «бюджет из
   SPEC не применён» ключ — текст предупреждения: другой текст (другая
   версия CLI, другая причина) — новая запись. Для «бюджет:
   предупреждение» текст несёт текущие суммы и меняется на каждом шаге,
   поэтому ключ — не текст, а порог, который пересечён: одна запись на
   пересечение порога в пределах пребывания в состоянии; запись о
   ИСЧЕРПАНИИ бюджета и эскалация по бюджету подавлению не подлежат.

2. **Общий узел — вариант A:** внутри файлов заявленных зон, размещение
   выбирает разработчик в PLAN. Новый модуль не заводится.

3. **`budget_usd` — вариант B, $40.** Рамка $25 в ТЗ занижена против
   калибровки; действует уровень калибровочной таблицы.

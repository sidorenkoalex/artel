Источник: ADR-0021 (принят 29.09.2026), пункты 8, 9, 12, 13 («этап 3:
проверки из пункта 8 переводятся на `repo_context`, развилки

другом (часть 1 — профиль тестов и проверки тестов, часть 2 — защищённые

тестах». Мандаты на смену ожиданий существующих тестов Оператор выдаёт по
эскалации роли, а не заранее.

Требуется:
1. Профиль тестов проекта в записи `targets.yaml` (ADR-0021 п.9):
   команда запуска тестов, каталог и шаблон имени долгоживущих тестов,
   область гейта неослабления и заявки мутации, формат отчёта (JUnit
   XML), установка зависимостей. Имя и форму поля задаёт SPEC; поле
   необязательно (запись без него — проект без профиля), разбор и
   проверка — `orchestrator/targets.py` с названием поля в причине
   отказа. Запись артели получает профиль, равный её нынешнему
   поведению (pytest, `tests/test_<id>_<имя>.py`), — приложением.
   Профиль доступен проверкам через `repo_context` (поле контекста либо
   функция рядом, решает SPEC). Зашитые в код значения из «Фактов»
   (команда pytest, область неослабления, область заявки мутации,
   префикс долгоживущего файла) проверки берут из профиля проекта.
2. Проект без профиля работает только с разовыми тестами (ADR-0021
   п.9): проверки, зависящие от языка (неослабление, заявка мутации,
   долгоживущие файлы, строки группы, перечень сумм, раздел изменённых
   утверждений пакета ревью), у него не включаются — с записью в журнал
   задачи, какие проверки не выполняются и почему; молча не
   отключается ничего. Для артели отсутствие или неразборчивость
   профиля — отказ перехода (fail-closed, ADR-0002), а не отключение
   гейтов целостности тестов самого пульта.
3. Проверки тестов пункта 8 — неослабление тестов (переход, раздел
   изменённых утверждений пакета ревью, шаг гейта мержа), «Ловит
   мутацию», долгоживущие файлы, строки группы (в том числе в
   `amend-tests`) и перечень сумм (автогейт приёмки, выход из
   `tests_writing`, прогон приёмки, лок планки на мерже) — исполняются
   для любого проекта с разрешённым контекстом, в клоне и рабочей копии
   задачи из `repo_context`; все развилки этих проверок из «Фактов»
   удаляются, жёсткий аргумент `on_task_branch` на
   `orchestrator/advance_gates/tests_writing.py:383` — тоже. SPEC
   таблицей перечисляет каждую из этих проверок: источник репозитория,
   что берётся из профиля, поведение при неразрешённом контексте и без
   профиля. Поведение для артели не ослабляется ни в одном месте.
4. Прогон планки и долгоживущих тестов — одна ветка логики для любого
   проекта: рабочая копия задачи в области проекта, заведённая и
   выписанная на ветку задачи; прогон в главной копии пульта
   (`orchestrator/advance_gates/tests_writing.py:199`,
   `orchestrator/advance_gates/acceptance.py:248`) исключён; нет рабочей
   копии — отказ перехода с причиной, как сегодня у внешнего проекта.
   Команда прогона берётся из профиля.
5. Тесты в `tests/` с заявками «Ловит мутацию» на пп.1–4 этой части;
   существующие тесты не ослабляются. Смену ожиданий существующих
   тестов (тесты из «Фактов», закрепляющие пропуск проверок для внешнего
   проекта, и любые другие, найденные при работе) роль выносит
   эскалацией с точным списком — файл, тест, прежнее и новое ожидание —
   и проводит по мандату Оператора разделом SPEC «Меняемое поведение»
   механикой задачи «Смена поведения в существующих тестах», с перечнем
   в PLAN. Дополнение записей `targets.yaml` в фикстурах профилем
   артели — не смена ожидания и перечисляется в PLAN отдельно.

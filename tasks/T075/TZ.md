# ТЗ: ANSWER-артефакт: канал ответа Оператора на эскалацию

# ТЗ: ANSWER-артефакт — штатный канал ответа Оператора на эскалацию

## Контекст

Роадмап, P3-строка «ANSWER-артефакт» — предусловие C2 (аудит 27.08:
профиль эскалаций системных задач неприемлем для внешнего target).
Сегодня канала ответа нет. Фактура 29.08 (T073): ответ Оператора,
записанный в журнал БД, роль не видит — бриф журнал не включает;
analyst после approve эскалации перезапустился от того же ТЗ
и переэскалировал тот же вопрос ($0.66 холостых). Рабочий обход —
дописка ответа в TZ.md ветки коммитом Оператора — работает, но
неструктурен: ответ размывает исходное ТЗ, нумерации и связи
с QUESTIONS нет, для эскалаций из in_dev (не про SPEC) канала
нет вовсе. Заявленный ролью дефолт «если Оператор промолчит»
неисполним: роль не наблюдает «молчание».

## Что нужно

1. Носитель ответа: файл `tasks/<id>/ANSWER-n.md` в ветке задачи
   (n — порядковый номер, парный эскалации/QUESTIONS), по шаблону
   из `templates/` (frontmatter, валидация guard). Содержимое —
   ответы Оператора по пунктам вопросов.
2. CLI-команда для Оператора (например `answer <id> <файл-с-текстом>`
   или ввод текстом): создаёт ANSWER-n.md в worktree задачи, коммитит
   в её ветку авторством Оператора, журналирует — Оператор не лазит
   в worktree руками. Точную форму выбрать в SPEC/PLAN.
3. FSM: возврат из эскалации класса «вопрос роли» (эскалация
   с QUESTIONS.md или полем question) требует наличия нового
   ANSWER-n — approve без него отказывает с внятным текстом.
   Эскалации других классов (инцидент целостности, конфликт подтяжки,
   лимиты) ответа не требуют — как сейчас. Адресация возврата
   (роадмап): вопрос о реализации → in_dev, вопрос о SPEC →
   spec_writing (analyst инкорпорирует ответ, повторный гейт).
4. Видимость: бриф роли при следующем запуске включает ANSWER-n
   (при наличии — и связку QUESTIONS→ANSWER), чтобы ответ
   гарантированно достиг роли. Это ядро задачи — канал обязан
   доходить до адресата, а не только существовать.
5. Пересмотр залоченных тестов по итогам ответа — только через
   Оператора (существующее право, задача его не меняет).

## Границы

- Панель/UI — вне объёма.
- Автоответы/дефолты без Оператора — вне объёма и запрещены
  (класс «решение Оператора», ADR-0002).
- Изменение механики самих эскалаций (когда они возникают) —
  вне объёма; меняется только возврат и доставка ответа.

## Критерии приёмки (ориентир для SPEC)

- Эскалация с вопросом → команда ответа создаёт ANSWER-n.md в ветке
  с журналом; approve возвращает задачу по адресации; следующий
  запуск роли получает ответ в брифе (проверяемо по собранному
  промпту/брифу) и не переэскалирует тот же вопрос.
- approve эскалации-вопроса без ANSWER — внятный отказ.
- Эскалации без вопроса (инцидент) возвращаются как сейчас,
  ANSWER не требуют.
- Шаблон ANSWER в templates/ (дифф для Оператора, если путь
  защищён), guard валидирует структуру.
- Полный тестовый набор зелёный.

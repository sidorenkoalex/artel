# SPEC: Команда docs, подсказка show и уборка веток artifact/**

## Контекст
Вторая часть деления задачи 01M41VCKTEB1SRTD2VW4X2Y6HM (ADR-0021, этап 1,
часть (в)). Документы задачи живут в `refs/artifacts/<id>` репозитория её
проекта, но читатели вне конвейера (`show <id>` —
`orchestrator/catalog.py::cmd_show` → `_artifact_frontmatter`;
`orchestrator/retro_corpus.py`) видят только локальные ссылки, а команды,
подтягивающей ссылку из `origin`, нет: на второй машине или после чистого
клона документы закрытых задач недоступны. Кроме того, в `origin` артели
остались 229 веток `artifact/**`, в главной копии — 5 локальных
`artifact/*`; для их уборки нужна команда с предпросмотром и сверкой.
Источник — ADR-0021 пп. 3, 13 (этап 1); решение Оператора 02.10.2026 о
локальных ветках `artifact/*`; SPEC родителя, требования 1–5, 9, 11.

## Требования

1. **Команда `artel.py docs <id> [файл]`.** Команда подтягивает
   `refs/artifacts/<id>` из `origin` репозитория задачи узлом
   `orchestrator/artifact_branch.py`. Репозиторий — артели или внешнего
   проекта, по target задачи. С аргументом файла печатает
   `tasks/<id>/<файл>` из подтянутой головы, без аргумента — перечень
   файлов документов задачи.
   - Исторические снимки (ссылки закрытых задач, созданные до части (а))
     читаются так же.
   - Ссылки нет ни в `origin`, ни локально — именованный отказ (называет
     задачу и причину) с ненулевым кодом возврата.
   - Локальная ссылка с коммитами, которых нет в `origin`, не
     перезаписывается; вывод называет расхождение с `origin`.
2. **`artel.py docs --fetch-all`.** Подтягивает все `refs/artifacts/*` из
   `origin` одним вызовом git на репозиторий (артель и каждый внешний
   проект с клоном). Печатает число принесённых ссылок (их не было
   локально) и число обновлённых. Правило «не перезаписывать локальные
   коммиты» из требования 1 действует и здесь.
3. **Процессу роли команды недоступны.** `docs` и
   `artifact-branches-cleanup` не входят в
   `orchestrator/artel.py::_ROLE_ALLOWED_COMMANDS`; процесс роли получает
   отказ диспетчера. Причины (из ТЗ): команды ходят в сеть и переписывают
   локальные ссылки, в том числе ссылку живой задачи с зафиксированным
   коммитом; документы своей задачи роли материализует пульт.
4. **`show <id>` без локальной ссылки.** Если локальной
   `refs/artifacts/<id>` нет, `show` называет команду `docs <id>`.
5. **`retro_corpus` не меняет поведения**: работает только с локальными
   `refs/artifacts/*`, без сети. Его модульный докстринг и секция
   `orchestrator/retro_corpus.py` в `docs/codebase-map.md` называют
   `docs --fetch-all` как способ наполнить корпус. Карта берёт первую
   строку докстринга (`scripts/codebase_map.py`), карта регенерируется
   запуском генератора.
6. **Команда `artel.py artifact-branches-cleanup [--execute]`.**
   - Без флага — предпросмотр: перечисляет ветки `artifact/**` в `origin`
     артели и локальные ветки `artifact/*` главной копии, ничего не
     удаляет.
   - С `--execute` сначала сверяет, что у каждой задачи из перечня (id из
     имени ветки) есть `refs/artifacts/<id>` в `origin`; при нехватке
     называет такие задачи и не удаляет ничего — ни в `origin`, ни
     локально.
   - Сверка прошла — удаляет ветки и в `origin`, и в главной копии.
   - Исполняет уборку Оператор после мержа, канарейки и `pin-update`, не
     эта задача.
7. **Постоянные тесты в `tests/`** с заявкой «Ловит мутацию:» в
   докстринге покрывают девять сценариев (требование 11 SPEC родителя):
   - `docs` подтягивает версию `origin`, которая новее локальной;
   - `docs` без локальной ссылки;
   - `--fetch-all` приносит ссылку, которой нет локально;
   - чтение исторического снимка;
   - `docs` для внешнего проекта читает его `origin`;
   - `show` без локальной ссылки называет `docs`;
   - предпросмотр уборки ничего не удаляет;
   - уборка отказывает при задаче без ссылки в `origin`;
   - уборка удаляет ветки `origin` и локальные.

## Критерии приёмки

AC-1. Пусть `origin` задачи несёт голову `refs/artifacts/<id>` новее
локальной, и в этой голове файл `tasks/<id>/<файл>` изменён. Тогда
`artel.py docs <id> <файл>` печатает содержимое файла из головы `origin`,
а локальная ссылка после команды равна голове `origin`.

AC-2. Пусть локальной `refs/artifacts/<id>` нет, а в `origin` она есть.
Тогда `artel.py docs <id> <файл>` печатает файл из головы `origin`, и
локальная ссылка после команды существует и равна ей.

AC-3. `artel.py docs <id>` без аргумента файла печатает перечень файлов
документов задачи в подтянутой голове ссылки и не печатает содержимое
файлов.

AC-4. Исторический снимок — ссылка закрытой задачи, созданная до части
(а): один коммит без родителя с деревом `tasks/<id>/`. `artel.py docs
<id> <файл>` читает из него файл так же, как из ссылки живой задачи.

AC-5. Для задачи внешнего проекта `artel.py docs <id> <файл>` подтягивает
ссылку из `origin` репозитория этого проекта, а не из `origin` артели, и
печатает файл из неё.

AC-6. Если `refs/artifacts/<id>` нет ни в `origin`, ни локально,
`artel.py docs <id>` завершается ненулевым кодом и печатает именованный
отказ, который называет задачу и отсутствие ссылки. Пустого вывода с
кодом 0 нет.

AC-7. Пусть локальная `refs/artifacts/<id>` несёт коммит, которого нет в
`origin`. Тогда ни `artel.py docs <id>`, ни `artel.py docs --fetch-all`
её не перезаписывают: после команды она указывает на прежний коммит, и
вывод называет расхождение с `origin`.

AC-8. `artel.py docs --fetch-all` приносит из `origin` ссылку
`refs/artifacts/<id>`, которой не было локально, и печатает число
принесённых и число обновлённых ссылок. Для каждого репозитория
выполняется ровно один вызов `git fetch`.

AC-9. Процесс роли получает отказ диспетчера `orchestrator/artel.py` на
`docs <id>`, `docs --fetch-all` и `artifact-branches-cleanup` (с флагом и
без). `_ROLE_ALLOWED_COMMANDS` не содержит ни `docs`, ни
`artifact-branches-cleanup`.

AC-10. `artel.py show <id>` для задачи без локальной
`refs/artifacts/<id>` печатает подсказку, которая называет команду
`docs <id>`.

AC-11. Модульный докстринг `orchestrator/retro_corpus.py` и его секция в
`docs/codebase-map.md` называют `docs --fetch-all`. `retro_corpus`
по-прежнему читает только локальные `refs/artifacts/*`, без сетевых
вызовов git.

AC-12. `artel.py artifact-branches-cleanup` без флага перечисляет ветки
`artifact/**` в `origin` артели и локальные ветки `artifact/*` главной
копии и не удаляет ни одной ветки: множества веток в `origin` и локально
до и после команды совпадают.

AC-13. `artel.py artifact-branches-cleanup --execute` при задаче из
перечня, у которой нет `refs/artifacts/<id>` в `origin`, завершается
отказом, который называет такие задачи, и не удаляет ни одной ветки ни в
`origin`, ни локально.

AC-14. `artel.py artifact-branches-cleanup --execute` при ссылках
`refs/artifacts/<id>` в `origin` у всех задач перечня удаляет все ветки
`artifact/**` в `origin` и все локальные ветки `artifact/*` главной
копии. Ссылки `refs/artifacts/*` при этом не трогаются.

AC-15. Каждый из девяти сценариев требования 7 закрыт постоянным тестом
в `tests/`, в докстринге которого есть строка «Ловит мутацию:».

Соответствие нумерации SPEC родителя (ТЗ: «AC-1…AC-11, AC-16…AC-19 SPEC
родителя»): AC-1…AC-11 здесь = AC-1…AC-11 родителя; AC-12…AC-15 здесь =
AC-16…AC-19 родителя.

## Оценка объёма и деление

Сработавший сигнал: 15 критериев приёмки (порог `SPLIT_SIGNAL_AC_COUNT` =
10). Остальные сигналы не срабатывают: зона кода — один каталог
`orchestrator/` (плюс общие зоны `tests/`, `docs/codebase-map.md`),
`budget_usd` 40 ниже `SPLIT_SIGNAL_BUDGET_USD` = 60.

Материал для решения Оператора — **обоснование монолита**:
- задача уже сама является второй частью деления родителя
  01M41VCKTEB1SRTD2VW4X2Y6HM, утверждённого на гейте SPEC; её состав и
  рамка $40 заданы заявкой деления;
- обе механики (команда `docs` с подсказкой `show` и команда уборки)
  регистрируются в одном диспетчере `orchestrator/artel.py` и в одном
  перечне `_ROLE_ALLOWED_COMMANDS` (AC-9 покрывает обе команды разом), а
  сверка уборки («есть `refs/artifacts/<id>` в `origin`») опирается на
  тот же узел `artifact_branch`, что и подтягивание `docs`; дальнейшая
  нарезка режет зону `orchestrator/artel.py` поперёк;
- обе части без зависимостей в конвейере: деление не снимает риска, а
  добавляет шаг аналитика на каждую подзадачу при рамке $40.

## Не входит

- Исполнение уборки веток `artifact/**` — действие Оператора после мержа,
  канарейки и `pin-update`; задача поставляет только команду.
- Сеть в `retro_corpus`: он остаётся локальным, меняется только
  докстринг.
- Ссылки на документы по номеру коммита в `status` и описании MR.
- Этапы 2–4 ADR-0021.
- Задача о перефиксации 01M41AB597B330P2RCXCMVRZPE.
- Правка `scripts/codebase_map.py` — генератор карты только запускается
  для регенерации `docs/codebase-map.md`.
- Первая часть деления родителя: отмена CI на `artifact/**`, режим
  `scripts/guard.py --artifact-branch`, класс `artifact/` в
  `scripts/ci_push_class.py`, инвариант 36.
- Зелёный полный набор `tests/`, зелёный CI ветки, неизменность
  защищённых путей, непревышение бюджета — их держит пульт.

# ТЗ: Канарейка: повтор developer на красной планке (вариант а)

Источник: копилка docs/backlog.md, строка П1 от 12.09 «Канарейка на новом
пине 27ddceb3 красная по новой причине: цикл канарейки не умеет шаг
„красная планка -> повторный developer“» (коммит 85ca2927). Решение
Оператора 12.09: вариант (а) — повтор developer только в цикле канарейки,
поведение `auto` не меняется.

Факты:
- Прогон 20260912T113132Z (шаблон canary-usage-invariant, задача
  01M2AP66XR, $6.85): гейт SPEC ведёт в tests_writing (правка
  01M2A22CG2 работает), test_author написал планку ($4.07), developer
  сдал шаг ($1.54), на выходе in_dev планка красная по делу — мутация
  «убрать команду workspace из usage-блока» не красит новый тест
  разработчика (AssertionError 0 == 0).
- Отказ выхода in_dev по красной планке журналируется
  `fsm_advance._acceptance_run_refuses` (orchestrator/fsm_advance.py:
  ~1297–1305) записью `action` = «переход отклонён: приёмочные тесты»,
  `detail` = «acceptance_tests красные:\n<хвост>\nокружение: …», и печатью
  «дальше: почини код (не тест) и повтори artel.py advance <id>».
- `auto` на два подряд одинаковых отказа в in_dev останавливается
  стоп-краном T038 (orchestrator/auto.py: ~760–766, `Stop` с подсказкой
  «почини причину и повтори artel.py advance <id>»; журнальная запись
  `auto_stop` — «auto остановлен»). Шаг роли при этом не запускается:
  отказ трактуется как «причина вне зоны агента».
- В реальном конвейере на этом месте Оператор возвращает разработчика
  командой `run <id>`: `runner._cmd_run` (orchestrator/runner.py:
  ~374–379) вкладывает в бриф блок «--- ОТКАЗ ADVANCE (история) ---» с
  текстом последнего отказа — developer видит, какой тест красный.
- Цикл канарейки `canary._drive_task` (orchestrator/canary.py:773–849)
  после `auto.cmd_auto` лишь сверяет подпись (состояние, потраченное)
  между проходами: при остановленном `auto` подпись не меняется, три
  прохода подряд (`config.CANARY_MAX_STALL_ITERS = 3`) — `_kill_inconclusive`
  «3 проходов подряд без прогресса в состоянии in_dev — задача не
  сходится». В прогоне 12.09 — восемь отказов за 6 секунд и kill.
- Итог: зелёный прогон канарейки возможен только если канареечная задача
  сходится с первого раза; `pin.cmd_pin_update` требует зелёный прогон
  не старше `CANARY_MAX_MERGES_SINCE_GREEN = 10` мержей — гейт сдвига
  пина заблокирован механикой самой канарейки.
- Потолки цикла канарейки живут в orchestrator/config.py рядом:
  `CANARY_MAX_ESCALATION_CYCLES = 3` (строка ~310),
  `CANARY_MAX_STALL_ITERS = 3` (~319).

Требуется:
1. Новая константа `config.CANARY_MAX_DEV_RETRIES = 2` (с докстрингом-
   комментарием по образцу соседних потолков канарейки): сколько раз
   цикл канарейки повторно запускает developer на красной планке в
   одном визите состояния in_dev.
2. `canary._drive_task`: после `auto.cmd_auto`, если задача осталась в
   `in_dev` и последняя запись журнала отказа перехода — «переход
   отклонён: приёмочные тесты» (либо `auto` остановлен стоп-краном с
   этим же текстом причины), цикл делает то, что делает Оператор:
   вызывает `runner.cmd_run(task_id)` (developer получает бриф с блоком
   «ОТКАЗ ADVANCE (история)») и продолжает цикл очередным
   `auto.cmd_auto`. Счётчик повторов — на визит состояния in_dev;
   превышение `CANARY_MAX_DEV_RETRIES` — `_kill_inconclusive` с текстом
   «canary: <N> повторов developer на красной планке — задача не
   сходится». Повтор developer считается прогрессом: `stall_streak`
   сбрасывается, потраченное растёт.
3. Отказы другого класса на выходе in_dev («планка не найдена в
   источнике», зоны, гейт заявки мутации, лок планки) повтором
   developer НЕ лечатся — прежнее поведение (стагнация до
   `CANARY_MAX_STALL_ITERS`) сохраняется байт-в-байт.
4. В отчёт прогона канарейки (строка задачи «шагов=… исход=…»)
   добавляется «повторов developer=<n>», чтобы факт повтора был виден в
   отчёте, а не только в steps.txt.
5. Тесты в tests/test_canary.py по образцу существующих тестов цикла:
   (а) стенд, где первый `auto.cmd_auto` оставляет задачу в in_dev с
   журнальной записью «переход отклонён: приёмочные тесты», — цикл
   вызывает `runner.cmd_run` ровно один раз и продолжает (мутация
   «повтор не вызывается» — красный); (б) `CANARY_MAX_DEV_RETRIES` + 1
   отказов подряд — `_kill_inconclusive` с названным текстом, `run` не
   вызывается сверх потолка; (в) отказ другого класса в in_dev —
   `runner.cmd_run` не вызывается, прежний kill по стагнации; (г) отчёт
   несёт «повторов developer=…». Существующие тесты канарейки — без
   ослабления.

Зоны: orchestrator/canary.py, orchestrator/config.py, tests/.

Приложением: orchestrator/auto.py (стоп-кран T038, `Stop`, `auto_stop`),
orchestrator/runner.py (`cmd_run`, блок «ОТКАЗ ADVANCE (история)»),
orchestrator/fsm_advance.py (`_acceptance_run_refuses`),
.artel/canary/20260912T113132Z/ (журнал красного прогона),
docs/backlog.md (строка П1 от 12.09, коммит 85ca2927).

Не входит: изменение поведения `auto` для обычных задач (вариант (б)
копилки — отдельное решение Оператора через ADR); правка auto.py,
runner.py, fsm_advance.py, pin.py; изменение
`CANARY_MAX_STALL_ITERS` и `CANARY_MAX_MERGES_SINCE_GREEN`; сдвиг пина.

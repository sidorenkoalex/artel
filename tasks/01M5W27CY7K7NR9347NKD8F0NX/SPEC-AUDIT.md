## Пути обхода гейтов
1. **Проверка `new` в CLI-обёртке** (отклонение 1). Требование 3 называет `catalog.cmd_new`, но AC-2 проверяет только CLI `new --target`. Проверка в `new_cli_target` проходит AC-2, а `epic draft promote` её обходит. Ревью поймает это по тексту требования, тест — нет.
2. **Дубль списка через помощника** (отклонение 2). Новое `_gate_of(t) != "operator"` в runner/fsm, по образцу `cleanup._forge_of`, сторож по имени поля не увидит. Сторож по литералу увидит, но заодно сработает на пяти сравнениях актора, которые SPEC не перечисляет.
3. Для сведения, не отклонение (ТЗ эти команды не перечисляет): `advance` (`fsm_advance.in_dev` → `github_adapter.ensure_head_in_origin`), `pull-main`, `ci-rerun` проверку не получают. Новой задачи такого проекта до них не дойдёт: `run`/`approve` откажут раньше. Задача, уже бывшая в полёте до смены записи, дойдёт — так было и в прошлом аудите, гейт решил принять перечень ТЗ.

Отклонения:
1. AC-2 (SPEC, «Критерии приёмки», AC-2) проверяет только CLI `new --target`. Проверка, поставленная в `catalog.new_cli_target` (catalog.py:491), а не в `catalog.cmd_new` (catalog.py:678), как требует требование 3, проходит критерий, и `epic draft promote` (epics.py:796) заводит задачу неподдержанного проекта. Предложение: в AC-2 добавить вызов `catalog.cmd_new(target=…)` напрямую, без CLI, с тем же итогом.
2. AC-9 и «Исключения сторожа AC-9» не определяют, как сторож отличает «сравнение поля `forge`/`merge_gate`» от прочих сравнений. Литерал `"operator"` сравнивается с актором журнала в пяти местах (brief.py:1069, brief.py:1354, report.py:371, auto.py:1214, advance_gates/review.py:414), а SPEC упоминает только `store.journal(…)`. Сравнение через помощника (`cleanup.py:304`, `_forge_of(...) == "github"`) имени поля не содержит. Сторож по имени поля пропустит новый дубль через помощника; сторож по литералу без перечня мест актора упадёт на существующем коде. Предложение: закрепить в AC-9 сторож по литералам `"github"`/`"gitlab"`/`"target-human"` в сравнениях и по `"operator"` в сравнениях, кроме сравнений `actor`, с поимённым перечнем исключений.

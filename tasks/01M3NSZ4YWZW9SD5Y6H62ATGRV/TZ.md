# ТЗ: amend-tests для долгоживущих файлов в tests/ и исключение их из диффа ревью (ADR-0020, задача 3)

# ТЗ: Долгоживущие приёмочные тесты — amend-tests для файлов в tests/, исключение их из диффа ревью и меры гейта ёмкости, docs/stack.md

Источник: ADR-0020 (решение Оператора 28.09.2026), пункты 3 и 6;
ADR-0012 (правка зафиксированных приёмочных тестов Оператором) — третья
из трёх задач внедрения. Зависит от задачи 2 «Долгоживущие приёмочные
тесты — test_author добавляет файлы в tests/ ветки задачи, пульт
фиксирует их перечнем контрольных сумм» (перечень, префикс имени,
сверка сумм): заводится после её мержа. Ревью схемы 28.09, пункты 8 и 11.

Факты (origin/main 183b8c6b, после мержа задач 01M3N0BWYQ9KHVN41Z4G72706R, 01M3N3Z1ZHTGMSQZ4SNRYNJ2SJ, 01M3NMHHAMTFN2BNKBN209E15M):
- `orchestrator/amend.py`: команда `amend-tests` в двух режимах — правка
  из worktree задачи (`_cmd_amend_tests`, изменённые пути читает
  `_worktree_changed_paths`) и расхождение ветки документов с локом
  (`_cmd_amend_tests_from_branch`, флаг `--from-branch`). Коммитит только
  в ветку документов и сдвигает `tasks.tests_locked_sha`; перед этим
  проверяет трассируемость и строку красноты, прогоняет приёмочные тесты
  (`acceptance.run`). Счётчик ADR-0012, пункт 3: окно `WINDOW_SIZE = 5`
  задач, порог `WINDOW_THRESHOLD = 1`, алерт «планка девальвируется».
- После задачи 2 долгоживущие файлы задачи лежат в `tests/` кодовой
  ветки, их суммы — в перечне в ветке документов под локом; сверка сумм
  стоит на переходах и на гейте мержа. Штатного способа поправить такой
  файл после лока нет.
- `orchestrator/review.py::snapshot_exclude` — один исключающий pathspec
  на двух читателей: дифф пакета ревью (`_shown_diff`, полный и
  инкрементальный) и мера гейта ёмкости
  (`orchestrator/advance_gates/capacity.py`, потолок
  `config.REVIEW_SNAPSHOT_DIFF_MAX_BYTES`). Сейчас исключает
  `tasks/<id>/` и `docs/codebase-map.md`; `tasks/<id>/` ревьювер получает
  отдельными компонентами пакета. Имена с `*`, `[`, `:` пакет защищает
  магией `:(literal)`, глобов в исключениях нет.
- Долгоживущие файлы задачи попадают в дифф ревью и в меру гейта
  ёмкости: ревьювер видит их как код разработчика, гейт ёмкости может
  отказать там, где раньше проходил.
- `docs/stack.md` о судьбе приёмочных тестов после мержа не говорит
  (разделы «Зоны и подтяжка main», «Закрытие задачи: снимок артефактов»).

Требуется:
1. `amend-tests` из worktree принимает правку долгоживущих файлов своей
   задачи (пути перечня): до записи применяет к ним проверки задач 1 и 2
   (строка группы, статические признаки, «Ловит мутацию», сухой сбор,
   трассируемость) и прогон приёмочных тестов вместе с долгоживущими;
   затем коммитит правку в кодовую ветку задачи, пересчитывает перечень
   в ветке документов и сдвигает `tests_locked_sha`. Отказ любой
   проверки — обе ветки не меняются.
2. Порядок записи: сначала кодовая ветка, затем перечень. Сбой между
   двумя записями не оставляет задачу в состоянии, из которого нет
   штатного выхода: следующая сверка сумм отказывает честно, а повторный
   вызов `amend-tests` (режим `--from-branch` либо иной, выбирает SPEC)
   пересчитывает перечень по уже закоммиченным файлам после тех же
   проверок. SPEC называет этот путь и доказывает его тестом.
3. Счётчик ADR-0012 общий: один вызов `amend-tests` — одно событие
   журнала, сколько бы веток он ни затронул; окно и порог не меняются.
4. Правка ограничена путями перечня и каталогом приёмочных тестов.
   Добавление нового долгоживущего файла и удаление файла из перечня
   через `amend-tests` — SPEC решает в границах ADR-0012 (основание —
   механический конфликт или дефект формы); удаление, ослабляющее
   проверку, без такого основания — отказ.
5. Долгоживущие файлы задачи исключаются из диффа пакета ревью (полного
   и инкрементального) и из меры гейта ёмкости одним узлом
   `snapshot_exclude`; способ вывести пути (по префиксу задачи или из
   перечня) выбирает SPEC без глобов, ломающих защиту `:(literal)`.
   Ревьювер получает эти файлы отдельным компонентом пакета, как
   приёмочные тесты, — чтобы проверить границу групп.
6. `docs/stack.md`: абзац о судьбе приёмочных тестов — две группы и
   где каждая живёт; перечень сумм и сверка на переходах и мерже;
   правка только `amend-tests`; после мержа долгоживущие — обычная
   часть `tests/`, разовые — в архиве `refs/artifacts/<id>`; замена
   чужого долгоживущего теста — через приёмочные тесты новой задачи
   (ADR-0020, пункт 8).
7. Тесты (`tests/`, песочница `tests/sandbox.py`): правка долгоживущего
   файла через `amend-tests` — коммит в кодовую ветку, новый перечень,
   сдвинутый лок, следующая сверка сумм зелёная; правка, нарушающая
   проверки задачи 1, — отказ, обе ветки прежние (заявка мутации
   «проверка перед записью снята»); сбой после записи в кодовую ветку —
   повторный вызов восстанавливает согласие перечня; одно событие
   счётчика на вызов; долгоживущий файл отсутствует в диффе пакета
   ревью и в мере гейта ёмкости, но присутствует компонентом пакета;
   пакет задачи без долгоживущих файлов — прежний байт в байт. Полный
   набор `tests/` зелёный; ни один существующий тест и гейт не
   ослаблен.

Зоны: orchestrator/amend.py, orchestrator/review.py, docs/stack.md, tests/.

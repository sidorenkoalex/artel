Не названо в SPEC или неточно:
1. **У GitHub нет `project_info`/`token_expiry`.** В «Контексте»
   (SPEC.md:10-14) сказано: «в них есть `forge.project_info`,
   `forge.token_expiry`…». Однако `_GitHub` реализует только
   `pipeline_status` (forge.py:115-120). Для github эти функции отдают
   `reason` «не реализовано для github» (forge.py:197-199). Есть и второе
   обстоятельство. Тесты `doctor` для GitHub зовут
   `check_base_branch("sled", entry)` с проектом `sled`, которого нет в
   `targets.yaml` (tests/test_doctor.py:633-637, :673-703), а `forge.*`
   читает запись по имени через `targets.target` (forge.py:172-175). Если
   выбирать реализацию по `forge.*(name)` или `forge.hosting(name)`,
   тесты `test_matching_base_branch_is_ok`/`test_diverging_base_branch_is_warn`
   получат `skip` «запись проекта sled не прочитана» вместо `ok`/`warn`.
   Без литерала остаётся одна дорога: выбор по переданному `entry` —
   `forge.IMPLEMENTATIONS.get(entry.get("forge"))` с проверкой наличия
   функции. Другой вариант — разбор текста причины «не реализовано». SPEC
   этого не говорит. Ловушка проявится только на полном прогоне.
   Строки срока токена это касается так же. Чтобы отличить «у github
   строки нет» от «ошибка запроса — `skip`», нужно то же различение
   «реализации нет» и «запрос не удался».
2. **Причина `skip` в `test_non_github_forge_is_skipped`** (SPEC.md:167,
   :185-188): «адаптер отказывает по адресу `file://` раньше токена».
   Фактически адаптер `url` записи теста не читает. `sled` не объявлен,
   поэтому `forge._hosting` отказывает раньше:
   «запись проекта sled не прочитана» (forge.py:172-175). Итог тот же —
   `skip`, транспорт не вызван. Эту формулировку задал п. 4 решения гейта,
   поэтому как отклонение она не поднимается. Это примечание для Оператора.

## Пути обхода гейтов
1. **Литерал за именем.** Разработчик пишет в `misc_checks.py`
   `GITLAB = "gitlab"`, а в `check_base_branch` —
   `if entry.get("forge") == GITLAB:`. AC-6 ищет только строковую константу
   в теле двух функций (SPEC.md:141-145) и этого не увидит. Сторож А0
   исключает `check_base_branch` (tests/test_01m5w27cy7k7nr9347nkd8f0nx_unsupported_project.py:418)
   и считает литералом только `ast.Constant`, а не имя (там же, :445-450).
   Так требование «сравнение уходит» (SPEC.md:39-40) выполнено буквально, но
   по смыслу нарушено. Второй вариант того же: модульный помощник
   `def _lab(value): return value == "gitlab"`. Сторож не узнаёт `value` как
   поле (`field_like`, :425-442), а AC-6 помощника не разбирает. Закрыть
   можно расширением AC-6: в этих функциях нет `ast.Compare`, где операнд —
   значение `forge` записи или `forge.hosting(...)`, а в модуле нет
   строковых констант `"github"`/`"gitlab"`.

`test_non_github_forge_is_skipped` (SPEC.md:167) на деле — необъявленный
`sled` (forge.py:172-175), а не адрес `file://`. Итог `skip` верен.

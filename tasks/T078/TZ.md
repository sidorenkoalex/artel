# ТЗ: отказ advance доносится до следующего запуска роли

## Контекст

Роадмап, P3-строка «Отказ advance не доносится до следующего запуска
роли». Фактура T069 (29.08): после «переход отклонён: трассируемость
AC» повторный запуск test_author не получил причину отказа в промпт —
прогон шёл вслепую по исходному брифу, роль перечитала свои файлы
и заключила «всё сделано, менять нечего» ($1.23 холостых). Стык
со строкой «стоп-кран: потолок топтания» (T038 ловит повторные
ОТКАЗЫ advance, но роль между ними не узнаёт, что чинить).

## Что нужно

Бриф роли, запускаемой в состоянии, из которого предыдущий advance
был отклонён guard'ом/условием перехода, включает последние
журнальные записи «переход отклонён» этой задачи ПО ЭТОМУ состоянию
(текст причины целиком — адреса файлов и требований, как их печатает
guard), с явной рамкой «предыдущая попытка сдать шаг отклонена
вот почему — почини это». Записей может быть несколько (N последних
по состоянию, разумный потолок — чтобы бриф не разбухал).

Отказы других состояний и чужих задач в бриф не попадают. Если
отказов не было — бриф не меняется вовсе (ноль регрессии для
чистого пути).

## Границы

- Механика самих отказов advance и guard — вне объёма (тексты
  сообщений — соседняя задача ревизии guard).
- ANSWER-механика (T075) — вне объёма и не дублируется: ANSWER —
  канал Оператора при эскалации, здесь — доставка машинного отказа
  guard той же роли без участия Оператора.
- Стоп-кран T038 не ослабляется.

## Критерии приёмки (ориентир для SPEC)

- Сценарий T069: после отклонённого advance следующий запуск роли
  того же состояния несёт в брифе причину отказа (проверяемо по
  собранному промпту шага).
- Запуск без предыстории отказов — бриф без нового блока.
- Отказы иного состояния/задачи в бриф не просачиваются.
- Полный тестовый набор зелёный.

## Замечания

- **major** — `orchestrator/advance_gates/outcome_integrity.py` (`_judge_ci`,
  строки «Неразобранный ключ головы идентификатора не имеет: тест базы под
  ним «исчез» по сравнению…» и `head, _unresolved = _ci_cases(...)`) —
  ANSWER-1 п.1 (D2), обязательное толкование Оператора: «Запись отчёта
  головы сопоставляется с тестом базы по ключу отчёта `<classname>::<name>`
  той же записи базы; модуль не найден в дереве головы — находка BROKEN, не
  GONE». Код выбрасывает неразобранные ключи головы (`_unresolved`), и тест
  базы уходит в `compare` как GONE. Проверено исполнением (сценарий
  `test_ac8_module_missing_in_head_tree_is_not_a_match`: голова удаляет файл
  тестов, отчёт головы несёт те же ключи `success`) — гейт пишет
  `merge отклонён: гейт неослабления по исходам` со строками
  «исчез: <id> — база: passed; ветка: нет записи» для всех трёх тестов, а не
  «сломан правкой: …» и не `BROKEN_REFUSAL_ACTION`. Последствие: вид
  находки и действие отказа расходятся с решением Оператора (и с тем, как
  находка снимается мандатом как BROKEN — п.8 SPEC/ANSWER-3 родителя);
  долгоживущий тест расхождение не ловит, т.к. вид не утверждает.
  Предложение: строить карту «ключ отчёта базы → id базы»; запись головы,
  ключ которой совпал с ключом зелёной записи базы, а модуль не найден в
  дереве головы (в `_unresolved` головы), давать находкой BROKEN по id базы
  (не GONE); добавить в `tests/` (не повторяя долгоживущий файл) тест,
  утверждающий вид BROKEN для этого случая с заявкой «Ловит мутацию:
  неразобранный ключ головы отброшен — находка «исчез» вместо «сломан
  правкой»».
- **minor** — `tests/test_report_outcome_module.py::test_forge_report_key_without_separator_and_record_shape`
  — части «статус вне перечня → UNKNOWN» и «два ключа → UNKNOWN» повторяют
  свойства, уже держимые долгоживущим файлом задачи (AC-8, AC-12;
  ADR-0020 п.4). Новое здесь — только ключ без `::` и форма записи; можно
  оставить, но лишнее дублирование. Не блокирует.
- **minor** — `outcome_integrity.py::_judge_ci` — блок мандатов/отказа/записи
  прохода (`_answer_mandates` … `GateRefusal(...)`) почти дословно копирует
  хвост `_judge`; вынос общего хвоста в помощник упростил бы сопровождение.
  Вкус.

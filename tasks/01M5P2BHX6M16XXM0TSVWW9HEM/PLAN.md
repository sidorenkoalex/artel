# PLAN: mutation-run — строки таблицы исходов в отчёте `--wait`

## Подход
Один помощник `_print_table(task_id, run_no)` в `orchestrator/mutation_run.py`:
читает основную таблицу `_table_path(task_id, run_no)` прогона из
`mutation-run.json` и печатает её содержимое дословно (байты файла,
декодированные utf-8, без правки строк) с предшествующей строкой-разделителем
`--- таблица <путь> ---`. `_wait` зовёт его в каждой ветке отчёта, до текста
отчёта:
- есть `mutation-result.json` этого прогона (закончен, отказ, исключение,
  обрыв пределом, повторный `--wait`) — таблица, затем прежняя сводка
  `report`; файла таблицы нет (отказ до шапки) — ничего не печатается;
- фоновый процесс умер без отчёта — таблица (если файл есть), затем прежний
  текст «прогон №<n> оборван …»;
- время ожидания вышло — таблица на момент вызова, затем прежний текст
  «прогон №<n> ещё идёт»; файла нет — строка «таблица ещё не начата».
Формат таблицы, набор исходов, фоновый процесс, каталог документов и ссылка
`refs/artifacts/<id>` не меняются. Оценка SPEC ($25) совпадает с объёмом.

## Влияние на систему
Меняется только вывод команды `mutation-run --wait`: добавлены строки
таблицы перед прежними текстами; прежние тексты и коды выхода те же. Гейты
таблицу не читают (докстринг модуля). Существующие тесты
`tests/test_01m5npkpwfewtymbywvr797am6_mutation_run.py` проверяют наличие
текстов, не их единственность — прогоняются в шаге. Откат — revert коммита.

## Риски
Чтение таблицы в момент дозаписи фоновым процессом может захватить
недописанную последнюю строку — строка пишется одним `write` в режиме `a`,
окно мало; AC-3 сверяет со срезом файла на момент вызова.

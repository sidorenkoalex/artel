# SPEC: mutation-run — таблица исходов видна роли: строки таблицы в отчёте `--wait`

## Контекст
Таблица «мутация → исход» команды `mutation-run` пишется только в
хозяйство `suite-run` — `.artel/logs/suite-run/<id>/`
(`orchestrator/mutation_run.py:122-123`, `_table_path`). Этот каталог
открыт только шагу роли на Codex; роли на Claude (developer по умолчанию)
он закрыт. Отчёт `--wait` печатает только сводку по исходам
(`orchestrator/mutation_run.py:691-696`, `_wait`), поэтому роль не может
приложить таблицу к PLAN и набирала бы её руками.

Решение Оператора (ANSWER-1, 24.10.2026): копия таблицы в каталоге
документов задачи из задачи снята целиком (требование 1 ТЗ отменено —
она красит существующий
`IsolationTest.test_ac6_copy_removed_and_repositories_untouched` и
ненадёжна при автокоммите шага). Роль получает таблицу из вывода команды:
отчёт `--wait` печатает дословно содержимое основной таблицы, роль
переносит этот текст в PLAN. Подлинность таблицы держит независимая
проверка (повтор прогона сессией), не роль.

## Требования

1. Отчёт `--wait` по законченному прогону `mutation-run` — и повторный
   вызов `--wait` после окончания прогона — печатает, кроме сводки,
   дословно содержимое основной таблицы прогона
   `<id>-mutation-run-<n>.mutations.tsv`: шапку (строки `#` — источник
   патчей, ревизия прогона с её sha, sha256 каждого патча), строку колонок
   и все строки исходов (номер, исход, узлы). Строки таблицы в выводе
   побайтно равны строкам файла; вывод может дополнительно нести строку-
   разделитель.
2. Отчёт `--wait` по прогону, который ещё идёт (время ожидания вышло до
   конца прогона), печатает строки таблицы, записанные к этому моменту, и
   пометку «прогон идёт» прежним текстом «прогон №<n> ещё идёт»
   (`orchestrator/mutation_run.py:706`); новых литералов пометки не
   вводится. Если файла таблицы этого прогона ещё нет — печатается прежний
   отчёт «прогон №<n> ещё идёт» и строка «таблица ещё не начата».
3. Отчёт `--wait` по прогону, оборванному пределом, печатает строки
   таблицы до обрыва — в том числе строку патча с исходом «оборвана по
   пределу» — и строки исхода «не прогнана (предел)» для оставшихся
   патчей.
4. Если шапка таблицы уже записана, отчёт `--wait` по прогону,
   кончившемуся отказом пульта или исключением пульта посреди прогона,
   тоже печатает шапку и все записанные к этому моменту строки таблицы —
   дословно, как в требовании 1.
5. Если шапка таблицы уже записана, отчёт `--wait` об исходе «фоновый
   процесс умер без отчёта» (прежний текст «прогон №<n> оборван —
   фонового процесса … больше нет, отчёта он не оставил»,
   `orchestrator/mutation_run.py:697-702`) тоже печатает шапку и все
   записанные к этому моменту строки таблицы — дословно, как в
   требовании 1.
6. Каталог документов задачи и ссылка `refs/artifacts/<id>` командой
   по-прежнему не меняются (докстринг модуля
   `orchestrator/mutation_run.py:26-27` остаётся верным).
7. Поведение закрепляют тесты в новом файле `tests/` в стиле pytest; у
   каждой тестовой функции — пояснение «Ловит мутацию:». Существующие
   файлы `tests/` не правятся.

## Критерии приёмки

AC-1. Отчёт `--wait` по законченному прогону печатает все строки
основной таблицы прогона (строки `#` шапки, строку колонок
`номер\tисход\tузлы` и все строки исходов), и каждая из них побайтно
равна соответствующей строке файла `<id>-mutation-run-<n>.mutations.tsv`
(кроме строки-разделителя вывода, которой в файле нет); сводка прогона
(поле `report` файла `mutation-result.json` этого прогона) при этом
по-прежнему есть в выводе.

AC-2. Повторный вызов `--wait` после окончания прогона печатает те же
строки таблицы, что и в AC-1.

AC-3. Отчёт `--wait` по прогону, который ещё идёт, печатает строки
таблицы, записанные к этому моменту (побайтно равные строкам файла на
момент вызова), и строку «прогон №<n> ещё идёт» с номером этого прогона;
если файла таблицы этого прогона ещё нет — печатает строку «прогон №<n>
ещё идёт» и строку «таблица ещё не начата».

AC-4. Отчёт `--wait` по прогону, оборванному пределом (сценарий с
подменой исхода прогона патча на обрыв по пределу), печатает строки
таблицы до обрыва, строку патча с исходом «оборвана по пределу» и строки
с исходом «не прогнана (предел)» для патчей, не прогнанных из-за
предела, — каждая побайтно равна строке файла таблицы.

AC-5. Отчёт `--wait` по прогону, кончившемуся отказом пульта посреди
цикла патчей после записи хотя бы одной строки исхода (сценарий: сброс
временной копии к основе после второго патча оставляет копию нечистой —
сбой воспроизводится публичным путём, обёрткой git, оставляющей
посторонний файл после очистки копии), печатает шапку таблицы и все
строки исходов, записанные в файл к моменту отказа (в этом сценарии —
строки первого и второго патчей), — каждая побайтно равна строке файла
таблицы; сводка отказа (поле `report`) по-прежнему есть в выводе.

AC-6. Отчёт `--wait` по прогону, оборванному исключением пульта посреди
цикла патчей (сценарий: подмена прогона второго патча, бросающая
исключение, после записи строки первого патча), печатает шапку таблицы и
строку исхода первого патча — каждая побайтно равна строке файла
таблицы; сводка исключения (поле `report`, «прогон оборван исключением
пульта …») по-прежнему есть в выводе.

AC-7. Отчёт `--wait` об исходе «фоновый процесс умер без отчёта» по
прогону, у которого таблица уже начата (шапка записана), печатает строку
«прогон №<n> оборван — фонового процесса … больше нет, отчёта он не
оставил» и шапку с записанными строками таблицы, побайтно равные строкам
файла.

AC-8. После прогона `mutation-run` с выводом `--wait` каталог документов
задачи на диске побайтно тот же, что до прогона (в нём не появилось ни
одного файла, в том числе `mutation-run-<n>.tsv`), и ссылка
`refs/artifacts/<id>` не сдвинулась.

AC-9. Тесты AC-1–AC-8 лежат в новом файле `tests/` в стиле pytest, и у
каждой тестовой функции этого файла есть пояснение «Ловит мутацию:».

  (требование 3 ТЗ).
- Изменение основной таблицы `<id>-mutation-run-<n>.mutations.tsv`, её
  формата и набора исходов.
- Коммит чего-либо в `refs/artifacts/<id>` самой командой.
- Доступ роли к `.artel/logs/`.
- Печать таблицы в отчёте об отказе, случившемся до записи шапки
  таблицы (таблицы ещё нет).
- Правка существующих файлов `tests/`: в `tests/` — только новые файлы.
- Зелёный полный набор `tests/` (требование 5 ТЗ, «остаются
  зелёными») — отдельным критерием приёмки не оформляется: его держит

  действует.

# SPEC: mutation-run — таблица исходов видна роли: копия в каталоге документов задачи и строки таблицы в отчёте `--wait`

## Контекст
Таблица «мутация → исход» команды `mutation-run` пишется только в
хозяйство `suite-run` — `.artel/logs/suite-run/<id>/`
(`orchestrator/mutation_run.py:122-123`, `_table_path`;
`orchestrator/suite_lock.py:40-44`). Этот каталог открыт только шагу роли
на Codex; роли на Claude (developer по умолчанию) открыт лишь каталог
документов задачи (`orchestrator/providers/claude.py:194`, `--add-dir`).
Отчёт `--wait` печатает только сводку по исходам
(`orchestrator/mutation_run.py:691-696`, `_wait`). В итоге роль не может
приложить таблицу к PLAN и набирала бы её руками. Задача делает таблицу
видимой роли: копия в каталоге документов задачи и строки таблицы в
отчёте `--wait`. Факты сверены Оператором с origin/main 4e1c8a18.

## Требования

1. После прогона `mutation-run` — в том числе оборванного по пределу —
   команда кладёт копию таблицы исходов в каталог документов задачи на
   диске (`artifact_branch.docs_dir(id, target)`) файлом первого уровня
   `mutation-run-<n>.tsv`, где `<n>` — номер прогона; ведущей точки в
   имени нет.
2. Строки копии пишутся по мере прогона, как в основной таблице (строка —
   сразу после каждой мутации); оборванный по пределу прогон оставляет в
   копии строки, записанные до обрыва.
3. Каталога документов задачи на диске нет — копия не пишется, отчёт
   прогона говорит об этом, прогон при этом не падает.
4. Ссылка `refs/artifacts/<id>` командой не меняется: копию переносит в
   git автокоммит шага роли, как прочие документы задачи.
5. Отчёт `--wait` (и повторный вызов `--wait` после окончания прогона)
   печатает, кроме сводки по исходам, шапку таблицы, все её строки
   (номер, исход, узлы) и путь копии.
6. `scripts/guard.py` не меняется: имя `mutation-run-<n>.tsv` уже не
   считается посторонним файлом `tasks/<id>/`
   (`scripts/guard.py:3470`, `is_extraneous_task_root_file`).
7. Поведение закрепляют тесты в новом файле `tests/` в стиле pytest; у
   каждой тестовой функции — пояснение «Ловит мутацию:». Существующие
   файлы `tests/` не правятся.

## Критерии приёмки

AC-1. После завершённого прогона `mutation-run` в каталоге документов
задачи есть файл первого уровня `mutation-run-<n>.tsv` (`<n>` — номер
прогона), побайтно равный основной таблице прогона
`<id>-mutation-run-<n>.mutations.tsv`.

AC-2. Прогон, оборванный по пределу, оставляет в каталоге документов
задачи копию `mutation-run-<n>.tsv`, которая содержит строки таблицы,
записанные до обрыва.

AC-3. Если каталога документов задачи на диске нет, копия не пишется,
отчёт прогона сообщает, что копия не записана из-за отсутствия каталога,
и прогон завершается без падения.

AC-4. Отчёт `--wait` по завершённому прогону (и повторный вызов `--wait`
после окончания) печатает, кроме сводки, шапку таблицы, все её строки
(номер, исход, узлы) и путь копии.

AC-5. `guard.is_extraneous_task_root_file("mutation-run-3.tsv")` ложно —
копия таблицы не посторонний файл `tasks/<id>/`.

AC-6. Тесты AC-1–AC-5 лежат в новом файле `tests/` в стиле pytest, и у
каждой тестовой функции этого файла есть пояснение «Ловит мутацию:».

## Оценка объёма и деление

Сработавшие сигналы (по guard): «число затрагиваемых модулей/файлов»,
«затронут инвариантный механизм», «прогноз диффа не дан». Первые два
порождены упоминаниями путей в тексте SPEC, а не зоной правки: guard
считает все пути `orchestrator/*.py`/`scripts/*.py` текста, и пять из
шести названных — перечень «Только чтение» из ТЗ
(`scripts/guard.py` — тот путь, что совпал с `docs/invariants.md`;
он по требованию 6 не меняется). Меняемый модуль — один:
`orchestrator/mutation_run.py`, плюс новый файл в `tests/` и
регенерация `docs/codebase-map.md`.

Прогноз диффа: 15 КиБ (порог сигнала — 128 КиБ).

Обоснование монолита: правка — одна точка записи таблицы и один отчёт
`--wait` в одном модуле; копия (требования 1–4) и печать строк в отчёте
(требование 5) по отдельности осмысленны, но каждая часть вместе с тестом
— несколько КиБ, и деление удвоило бы число шагов (аналитик, аудит,
ревью) без выигрыша в мержимости. Решение о монолите — за Оператором на
гейте SPEC.

# ТЗ: команда `reference <проект>` и порог справочника ядра — настройка проекта

Источник: строка бэклога «Команда сборки справочника ядра по требованию»
(13.10) с дополнением — решение Оператора 13.10.2026 (порог `min_uses`
настройкой проекта; рамка $20). Повод: справочник ядра артели на
722a8028 — 30 386 байт при пределе 32 768 и пороге предупреждения 90%;
за сутки вырос с 26,7 КБ; собрать и измерить его сегодня можно только
обходом (`scripts/core_reference.py` в stdout, без кэша).

Факты (origin/main 722a8028):
- Справочник собирают только два места: бриф developer/test_author
  (`brief.py` ~765, `reference_cache.get_reference(conn, task_id,
  reason="brief")`) и последний шаг мержа
  (`fsm_merge_gate._rebuild_core_reference`, `reason="merge"`). Команды
  пульта нет.
- `reference_cache.get_reference(conn, task_id, *, reason, sha=None)`
  (~94) берёт проект из строки задачи; без `sha` — голова ветки задачи в
  клоне (`_branch_head`, ~240). Кэш —
  `<область проектов>/<проект>/knowledge/derived/core-reference.md`
  (`CACHE_REL`, ~37); запись в журнал «справочник ядра: построен»
  (`BUILT_ACTION`) с sha, байтами, записями, длительностью и поводом.
- Порог использования — константа `config.CORE_REFERENCE_MIN_USES = 3`
  (`config.py` ~983); `reference_cache` передаёт её генератору в
  `_build` (~151) и в сверке кэша `_read_cache` (~217). Порог — поле
  шапки справочника `CORE_REFERENCE_MIN_USES`, которое сверяет
  `reference_sha` (`scripts/core_reference.py`: `setting_fields` ~161
  берёт поля настройки по явному списку, `reference_sha` ~202), поэтому
  смена порога делает старый кэш негодным; лишний ключ `min_uses` в
  настройке в шапке не задваивается — генератор править не нужно.
- Источник алерта выбирает `ALERT_SOURCES.get(reason, …)` в
  `reference_cache`; повода, отличного от `brief`/`merge`, там нет —
  неизвестный повод упадёт на источник `brief.core_reference`.
- `store.journal(conn, task_id, …, *, target=None)` (`store.py` ~1136):
  `task_id=None` допустим (колонка `steps.task_id` пустая разрешена, так
  пишет `notes.py`), но без явного `target=` запись уходит на
  `config.DEFAULT_TARGET`.
- Белый список команд роли `_ROLE_ALLOWED_COMMANDS` (`artel.py` ~1857)
  закрытый: новая команда под ролью отказывает без правок.
- Настройка проекта — поле `core_reference` записи `targets.yaml`;
  проверка — `targets._check_reference` (~166), допустимые подполя —
  `REFERENCE_FIELDS = ("modules", "constants_module", "constants")`
  (~67); неизвестное подполе — `TargetsError`.
- Предел и предупреждение — в брифе: `config.CORE_REFERENCE_MAX_BYTES =
  32_768` (~992), алерт `warning` при размере > 90% предела и `incident`
  при размере > предела (`brief.py` ~774-790, источники
  `brief.core_reference_near_limit` / `brief.core_reference_oversized`).
- `projects.cmd_target_init` (~40) после каталогов заводит клон
  (`workspace.ensure_clone`, ~63) и печатает его путь.
- Замер 13.10 на 722a8028 (`scripts/core_reference.py` по дереву) для
  настройки artel: порог 3 → 30 386 байт, 4 → 26 432, 5 → 21 290,
  8 → 16 949.

Требуется:
1. Необязательное подполе `min_uses` в `core_reference` записи
   `targets.yaml`: целое число от 1 до 1000. `_check_reference`
   принимает его и отказывает `TargetsError` с именем проекта, поля и
   подполя на любое иное значение (не целое, булево, меньше 1, больше
   1000; булево `true`/`false` — не целое). Нет подполя — действует
   `config.CORE_REFERENCE_MIN_USES`.
2. `reference_cache` передаёт генератору порог из настройки проекта
   (или умолчание) и в сборке (`_build`), и в сверке кэша
   (`_read_cache`): кэш, собранный с другим порогом, не годен и
   пересобирается. Неверное подполе — тот же исход, что сегодня у
   неверной настройки: справочник проекта отсутствует (`absent`) с
   алертом, без падения брифа и шага мержа.
3. Общий вход без задачи в `reference_cache`:
   `get_reference_for_target(conn, target, *, reason, sha)` (имя — на
   усмотрение SPEC, форма — эта). `get_reference(conn, task_id, …)`
   сводится к нему (проект — из строки задачи, sha по умолчанию — голова
   ветки задачи, как сейчас); `brief.py` и `fsm_merge_gate.py` не
   меняются, их поведение и алерты прежние. Повод `reference`: вход не
   поднимает и не снимает НИ ОДНОГО алерта (ни `brief.core_reference`,
   ни других) — недостатки сборки, сбои и незаписанный кэш только
   возвращаются в результате и пишутся в журнал.
4. Команда `reference <проект> [--sha <sha>]`, только главная копия.
   `reference` НЕ вносится в `_ROLE_ALLOWED_COMMANDS`: из окружения роли
   команда отказывает, как прочие команды Оператора.
   - порядок проверок: имя проекта сверяется через `targets.target()`
     до любых действий (неизвестное — именованный отказ с перечнем
     проектов; сломанная запись `targets.yaml`, в том числе неверный
     `min_uses`, — отказ `TargetsError` с ненулевым кодом выхода, без
     состояния `absent`); затем клон; затем sha;
   - без `--sha` — коммит ссылки `refs/heads/<base>` клона проекта
     (`<base>` — поле записи; `refs/heads/<base>^{commit}`, без
     `fetch`); клона нет — именованный отказ с подсказкой `target-init`;
     ссылки нет — именованный отказ; `--sha` — только полный sha из 40
     шестнадцатеричных знаков (форма `SHA_FORM`), иное — отказ;
   - собирает справочник через вход требования 3 (без второй реализации
     сборки, без обхода пределов и сроков `config.CORE_REFERENCE_*`),
     записывает кэш;
   - печатает: состояние (`off` / `fresh` / `cached` / `absent` с
     причиной), sha, размер в байтах, предел `CORE_REFERENCE_MAX_BYTES`,
     долю в процентах, порог использования и его источник (настройка
     проекта или умолчание), и строку-вывод по тем же формулам, что бриф
     (`brief.py` ~781-783): «больше предела — в бриф не попадёт» при
     `size > limit`; «больше 90% предела — бриф поднимет
     предупреждение» при `size*10 > limit*9` (строго больше); иначе «в
     пределе» (ровно 90% — «в пределе»);
   - запись журнала о сборке (как `BUILT_ACTION`, повод `reference`)
     пишется с `task_id=None` и явным `target=<проект>`;
   - код выхода: 0 — справочник собран или взят из кэша (в том числе
     больше предела — это сообщение, не ошибка команды) и при `off`; не 0
     — `absent`, неизвестный проект, нет клона, неверный `--sha`.
5. `target-init <имя>` после успешного клона вызывает ту же сборку для
   проекта с полем `core_reference` и печатает ту же сводку; сбой сборки
   не отменяет `target-init` (каталоги и клон остаются), а печатается
   именованной причиной; БД пульта не заведена — строка «справочник
   ядра: журнал недоступен — сначала init», без падения. Проект без поля
   — строка «справочник ядра: выключен (нет поля core_reference)».
6. Справка пульта: строка команды `reference` в общем перечне и текст
   справки (с формой `--sha`); `docs/codebase-map.md` обновляется в той
   же задаче.
7. Тесты в `tests/` с заявками «Ловит мутацию»: повод `reference`
   поднял алерт (в том числе через источник `brief.core_reference`);
   запись журнала команды ушла на `DEFAULT_TARGET` (проверять на
   проекте, отличном от artel); `get_reference` по задаче перестал
   давать прежний результат (бриф и мерж); граница 90%: ровно 90% —
   «в пределе»; `reference` выполнилась из окружения роли; порог из настройки не
   передан генератору (взят из `config`); порог не участвует в сверке
   кэша (кэш с другим порогом засчитан годным); неверное `min_uses`
   (0, 1001, `true`, строка) принято; `reference` на неизвестном
   проекте создал каталоги/кэш или вызвал git; `reference` без клона не
   отказал; сводка не называет состояние «больше предела» при размере
   больше `CORE_REFERENCE_MAX_BYTES` (тест подменяет предел, а не строит
   справочник на 32 КБ); `reference` поднял или снял алерт брифа;
   `target-init` упал или удалил клон при сбое сборки. Песочницы —
   временный `targets.yaml` и синтетический клон; настоящий
   `targets.yaml` не меняется.

Матрица неослабления: предел `CORE_REFERENCE_MAX_BYTES`, порог
предупреждения 90%, алерты брифа и шага мержа, сроки и пределы чтения
коммита не меняются; умолчание порога — прежняя константа, поведение
проектов без подполя не меняется; новая команда только читает клон и
пишет тот же кэш, что бриф.

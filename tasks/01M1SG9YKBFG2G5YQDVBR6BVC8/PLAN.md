# PLAN: автопамять CLI отключена у ролей курируемого слоя

## Подход
Добавить ключ `"autoMemoryEnabled": false` в референсный
`docs/reference/role-home/claude/settings.json` (единственная правка
конфигурации, требуемая AC-1) и покрыть его юнит-тестом в `tests/`
(AC-2). Раскатка изменённого файла в фактический
`.artel/home/.claude/settings.json` — операторское действие после
мержа (см. «Не входит» SPEC), в зону задачи не входит и здесь не
делается. Существующая функция `orchestrator.doctor.
check_role_home_reference`/`_role_home_diff` уже сравнивает
`settings.json` побайтово между референсом и деплоем — код этой
функции не трогаем (AC-3), она продолжит покрывать новый ключ
автоматически, т.к. сравнение идёт по всему файлу, а не по
конкретным ключам.

## Шаги

1. Добавить `"autoMemoryEnabled": false` в
   `docs/reference/role-home/claude/settings.json` внутрь корневого
   объекта, рядом с `permissions`.
2. Добавить в `tests/test_doctor.py` тестовый метод, который читает
   `docs/reference/role-home/claude/settings.json` и проверяет, что
   `autoMemoryEnabled` присутствует и равен булеву `false` — по
   соседству с существующими тестами `check_role_home_reference` в
   том же файле (согласованность со стилем соседних тестов).

## Покрытие требований

| Требование | Шаг |
|---|---|
| 1 (ключ autoMemoryEnabled: false в референсе) | 1 |
| 2 (тест в tests/, проверяющий ключ) | 2 |
| 3 (check_role_home_reference не ослаблена) | не требует правки кода — функция не изменяется этой задачей |

## Влияние на систему
Правка ограничена одним JSON-файлом референса (добавление ключа, без
удаления существующих) и одним новым тестовым методом в `tests/`.
`orchestrator/doctor.py::check_role_home_reference`/`_role_home_diff`
не редактируются — сравнение деплоя и референса по-прежнему идёт по
полному содержимому `settings.json`, включая новый ключ, так что
любое расхождение (например, деплой без ключа после раскатки) будет
и дальше замечено WARN'ом. Само добавление ключа в JSON не может
сломать существующий парсинг: `permissions.deny` не меняется. Откат —
удалить добавленную строку из референса и тестовый метод. Раскатка
в фактический `.artel/home/.claude/settings.json` — вне зоны, делает
Оператор после мержа (см. «Не входит» SPEC); до раскатки поведение
самого CLI не меняется, меняется только референс и его тест.
Существующие файлы `.artel/home/.claude/projects/*/memory/` этой
задачей не создаются, не читаются и не удаляются (AC-4, manual).

## Риски
Файл `.artel/home/.claude/settings.json` вне git (`.artel/` в
`.gitignore`) — раскатка ключа в фактический деплой не автоматизирована
этой задачей и требует отдельного операторского шага после мержа,
иначе автопамять физически продолжит работать до раскатки. Это прямо
названо в разделе «Не входит» SPEC, поэтому не является дефектом
плана — фиксирую здесь как риск для видимости.

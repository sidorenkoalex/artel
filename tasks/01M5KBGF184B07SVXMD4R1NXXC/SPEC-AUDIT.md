## Проверяемость критериев

| Критерий | Проверяем | Ловимая мутация |
|---|---|---|
| AC-1 | да | вторая запись не пишется; пишется до прежней; actor `autogate` вместо `fsm`; вид перепутан («машина занята» на таймауте); подсказка без id; вторая строка вывода печатается до первой или не печатается; прежняя деталь подменена текстом класса; переход в `merge_gate` на отказе |
| AC-2 | да | классификатор знает только таймаут; вид «машина занята» не различён; то же, что AC-1, для второй ветки |
| AC-3 | да | классификатор по `autogate_refusal_blame == BLAME_PULT` (ловят `_db_in_tree_note`, `FULL_SUITE_NO_TESTS_NOTE`, бюджет); по «прогон не начат» без «машина занята» (ловит `_db_in_tree_note`); по исходу `FULL_SUITE_NOT_STARTED` (ловит `UNKNOWN_PREFIX`); вторая строка на любом отказе |
| AC-4 | да | в `suspend_on_autogate_refusal` передан текст подсказки вместо причины; вызов дважды или пропущен в ветке окружения; правка правила вины |
| AC-5 | да | вторая запись под прежним именем действия «автогейт acceptance не пройден» — `_acceptance_from_steps` вернул бы деталь класса |
| AC-6 | да | литерал начала таймаута разошёлся с производителем; префикс не снимается (случай «без префикса»/«с префиксом»); суффикс `[без приложений PLAN: …]` ломает классификацию (сравнение целиком вместо начала) |

Непокрытые мутации:
- **Р-1.** Замена проверки начала (`startswith`) на вхождение (`in`) в
  `autogate_refusal_class` не ловится: ни AC-3, ни AC-6 не несут
  отрицательного случая, где текст окружения стоит не в начале причины.
  Реальный производитель такой причины есть:
  `orchestrator/acceptance.py:3508-3512` — отказ «checks_local компонента
  задачи не определены: …», за которым через `\n` идёт `run.detail`, в том
  числе `"прогон не начат: машина занята прогоном …"`; после схлопывания
  пробелов (треб. 1) текст окружения окажется внутри строки, и мутация
  отнесла бы отказ конфигурации к «окружению». Решение — отрицательный
  случай в AC-6 (или AC-3) с текстом окружения не в начале.
- **Р-2.** Схлопывание пробельных символов (SPEC треб. 1) не проверяется ни
  одним AC: все причины AC-1/2/6 начинаются без пробелов и переводов строк
  до конца распознаваемого начала, мутация «без схлопывания» выживает.
  Реального производителя, которому схлопывание нужно, в коде нет — риск
  низкий; это недоопределённость, а не дыра гейта.

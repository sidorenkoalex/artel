# SPEC: Шаблон сообщения коммитов пульта в ветке задачи без сжатия: policy.commit_message_template

## Контекст
Коммиты пульта в кодовой ветке задачи (чекпоинты тестов и кода
`orchestrator/checkpoint.py` около `:925-934`, аварийный чекпоинт около
`:776`, подтяжка `base` и прочие коммиты ветки `orchestrator/pull.py:473`,
`:556`, коммиты `amend-tests` `orchestrator/amend.py:806`) пишутся
служебным текстом с префиксом `<id задачи пульта>: `; подпись добавляет
`gitcmd.pult_message` (`orchestrator/gitcmd.py:585-593`). Шаблон с ключом
трекера есть только у сжатого коммита — `policy.commit_template`
(`orchestrator/targets.py:418-419`, исполнитель `pull.commit_title`,
`orchestrator/pull.py:926-940`), и только при `policy.squash_before_mr:
true`. Соглашения проектов на хостинге часто требуют сообщение
`<ключ задачи трекера>: <текст>` для каждого коммита ветки; без сжатия
коммиты пульта этому не следуют. Задача вводит отдельный шаблон первой
строки сообщения коммитов пульта в кодовой ветке задачи.

## Требования

1. Новое необязательное поле `policy.commit_message_template` локального
   слоя записи проекта: непустая строка, подстановки в которой — только из
   `{id}`, `{ref}`, `{title}`, `{text}`; `{ref}` допустим только при
   заданном `policy.ref_required`. Любое иное значение (пустая строка, не
   строка, подстановка вне перечня, `{ref}` без `ref_required`) — отказ
   загрузки записи, текст которого называет поле полным именем
   `policy.commit_message_template` в форме отказов `_check_delivery`
   (`поле 'policy.commit_message_template' — …`,
   `orchestrator/targets.py:667-669`), а не отказ «неизвестное поле»
   (`orchestrator/targets.py:539-541`, `orchestrator/projects.py:781-783`).
   Умолчание (поле
   отсутствует) — `{id}: {text}`, то есть прежнее сообщение побайтно.
2. Подстановки шаблона:
   - `{id}` — id задачи;
   - `{ref}` — ключ ссылки задачи в системе `policy.ref_required` (тем же
     правилом выбора ссылки, что `pull.commit_title`);
   - `{title}` — название задачи; пустое название — id задачи;
   - `{text}` — прежний служебный текст коммита без префикса `<id>: `.

   Подстановка однократная: каждая подстановка шаблона раскрывается один
   раз, а литералы вида `{…}`, пришедшие в подставленных значениях — в
   названии задачи или в служебном тексте (например в причине
   `amend-tests`, которую текст коммита `orchestrator/amend.py:1106` несёт
   целиком), — остаются в первой строке как есть и повторно не
   раскрываются, при любом порядке подстановок в шаблоне (решения
   Оператора на гейте SPEC: возврат 06.11, 3; возврат 07.11, 1).
3. Шаблон применяется к первой строке сообщения каждого коммита пульта в
   кодовой ветке задачи: чекпоинты `orchestrator/checkpoint.py` (тестов и
   кода около `:925-934`, после таймаута `:369`, аварийный `:776`,
   `pause --now` `:821`, перед подтяжкой `:1572`), коммит авторазрешения
   конфликта подтяжки `orchestrator/pull.py:473`, merge-коммит подтяжки
   `base` `orchestrator/pull.py:556`, коммит правки долгоживущих тестов
   `amend-tests` `orchestrator/amend.py:806`. Подпись, которую
   добавляет `gitcmd.pult_message` (соавтор, служебная строка), не
   меняется. Коммиты артефактной ветки `refs/artifacts/*` и сжатый коммит
   по `policy.commit_template` не меняются при любом значении поля.
4. Шаблон содержит `{ref}`, а ссылки системы `ref_required` у задачи нет —
   коммит делается с сообщением по умолчанию (`{id}: {text}`), в журнал
   задачи пишется запись с действием `шаблон сообщения не применён` и
   причиной `нет ссылки системы <значение ref_required>`; шаг не
   останавливается.
5. Поле записывается командой
   `target-set <проект> policy.commit_message_template <значение>`.

## Критерии приёмки

AC-1. Given вымышленная запись проекта с `policy.ref_required: tracker`,
`policy.commit_message_template: "{ref}: {title}"` и задача со ссылкой
`tracker:ABC-12`, When пульт коммитит чекпоинт тестов (за роль
test_author) и чекпоинт кода (за роль developer) в кодовой ветке задачи,
Then первая строка сообщения каждого из двух коммитов —
`ABC-12: <название задачи>`, а подпись (строка соавтора и служебная
строка) совпадает с подписью того же коммита без поля.

AC-2. Given та же запись и задача, но шаблон `"{ref}: {text}"`, When пульт
коммитит чекпоинт тестов, Then первая строка сообщения —
`ABC-12: долгоживущие тесты закоммичены пультом за роль test_author — шаг
завершён` (служебный текст без префикса `<id>: `); и Given шаблон
`"{ref}: {title}"` и название задачи, содержащее литералы `{ref}` и
`{text}`, When тот же коммит, Then первая строка — `ABC-12: ` и название
задачи как есть, литералы в нём не раскрыты.

AC-3. Given запись без поля `commit_message_template`, When пульт коммитит
чекпоинты тестов и кода, Then сообщения коммитов побайтно совпадают с
прежними; и при любом допустимом значении поля коммиты артефактной ветки
`refs/artifacts/<id>` и сжатый коммит по `policy.commit_template` —
прежние побайтно.

AC-4. Given запись с `policy.commit_message_template`, равным `"{foo}: x"`,
пустой строке или шаблону с `{ref}` без `policy.ref_required`, When
загрузка записи проекта, Then отказ, текст которого содержит полное имя
поля `policy.commit_message_template` в форме отказа `_check_delivery`
(`поле 'policy.commit_message_template' — …`) и не является отказом
«неизвестное поле»; позитивный контроль в том же критерии — та же запись
с годным шаблоном (`"{id}: {title}"`; `"{ref}: {text}"` при
`policy.ref_required`) загружается без отказа.

AC-5. Given запись с `policy.ref_required: tracker` и шаблоном,
содержащим `{ref}`, и задача без ссылки системы `tracker`, When пульт
коммитит чекпоинт в кодовой ветке задачи, Then коммит сделан с сообщением
по умолчанию (`<id>: <служебный текст>`), в журнале задачи есть запись с
действием `шаблон сообщения не применён` и причиной
`нет ссылки системы tracker` (тест сверяет и действие, и причину), шаг не
остановлен.

AC-6. Given вымышленный локальный слой во временной песочнице, When
`target-set <проект> policy.commit_message_template "{ref}: {title}"`,
Then поле записано в запись проекта, а недопустимое значение (например
`"{foo}"`) отклонено без записи файла, отказом с полным именем поля
`policy.commit_message_template` в форме отказа `_check_delivery`, не
отказом «неизвестное поле»; годный шаблон той же записи после записи
загружается без отказа (позитивный контроль).

AC-7. Given вымышленная запись с `policy.ref_required: tracker`,
`policy.commit_message_template: "{ref}: {text}"`, задача со ссылкой
`tracker:ABC-12` и голый origin во временной песочнице, When пульт делает
merge-коммит подтяжки `base` в кодовую ветку задачи
(`orchestrator/pull.py:556`) и коммит правки долгоживущих тестов
`amend-tests` (`orchestrator/amend.py:806`), Then первая строка сообщения
каждого из двух коммитов — `ABC-12: ` и служебный текст этого коммита без
префикса `<id>: `, подпись прежняя; мутация «шаблон применяется только в
чекпоинте разработчика» делает этот критерий красным. И Given та же
запись и причина `amend-tests`, содержащая литерал `{title}`, When коммит
правки долгоживущих тестов `amend-tests`, Then первая строка его сообщения
несёт литерал `{title}` буквально (не раскрыт названием задачи);
мутация «цепочка последовательных замен `{id}`, `{ref}`, `{text}`,
`{title}`» делает этот критерий красным.

## Оценка объёма и деление

Сработавший сигнал: число затрагиваемых модулей/файлов зоны (четыре
модуля `orchestrator/` плюс общие зоны `tests/`, `docs/codebase-map.md`).
Критериев — 7, `budget_usd` — 35 (ниже порога сигнала).

Прогноз диффа: 40 КиБ (код — поле и проверка в `targets.py`, одна функция
сборки первой строки и её вызов в восьми местах коммитов; основной
объём — долгоживущие тесты), ниже половины потолка гейта ёмкости
(`REVIEW_SNAPSHOT_DIFF_MAX_BYTES` = 256 КиБ).

Обоснование монолита (решение — за Оператором на гейте SPEC): поле
`policy.commit_message_template` в `targets.py` и его применение в
`checkpoint.py`/`pull.py`/`amend.py` — одна смена механики. Часть «только
поле» оставляет принимаемую загрузкой и `target-set` настройку, которая
ничего не делает, — проект с ней получит прежние сообщения при видимо
заданном шаблоне; часть «только применение» без поля не наблюдаема и не
проверяема ни одним критерием. Нарезка по местам коммитов дала бы
состояние, где одни коммиты ветки задачи следуют шаблону, а другие нет, —
ровно то нарушение соглашения проекта, которое задача устраняет.
Объём при этом мал (прогноз выше), деление не экономит ни шагов, ни
бюджета.

## Не входит

- Сообщения коммитов артефактной ветки `refs/artifacts/*`.
- Служебная строка подписи `pult_message` (отдельная задача
  `policy.commit_trailer`).
- Сжатый коммит и поле `policy.commit_template` — без изменений.
- Переписывание уже сделанных коммитов.
- Правка настоящего локального слоя `.artel/targets.yaml` в тестах и при
  разработке: тесты — только на вымышленных проектах и репозиториях во
  временной песочнице (`tests.sandbox`), без сети.
- Правка `orchestrator/gitcmd.py`, `orchestrator/artifact_branch.py`,
  `orchestrator/snapshot.py`, `orchestrator/store.py`,
  `orchestrator/projects.py`, `tests/sandbox.py` — только чтение (ТЗ).
  `target-set` берёт перечень полей из `targets.LOCAL_FIELDS`
  (`orchestrator/projects.py:780`), поэтому требование 5 выполнимо в
  зоне `orchestrator/targets.py`.
- «Существующие тесты — зелёные без правки»: полный зелёный набор
  `tests/` держит пульт; покраснение существующего теста — эскалация с
  именем теста, без его правки (ТЗ).

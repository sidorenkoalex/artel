## Пути обхода гейтов
- Опознание подтяжки по теме, собранной шаблоном **на момент рубежа**:
  если между подтяжкой и переходом из `in_dev` у задачи меняется значение
  `{ref}` (команда `link --remove` снимает первую из двух ссылок системы
  `ref_required` — `catalog.py:752-763` запрещает снять только последнюю;
  `commit_title`-правило берёт первую строку `external_refs`), тема прежней
  подтяжки уже не совпадёт с пересобранной и подтяжка засчитается шагом
  developer: при `code_ts > review_ts` рубеж выходит `review.py:371-372`
  раньше журнальной проверки `:373-375`. Решение №4.5 принимает риск только
  для смены `commit_message_template` командой `target-set`; смену ссылки
  командой `link` оно не называет. Класс тот же (действие Оператора), вред
  тот же.
- Шаблон без `{text}` (например `"{ref}: {title}"`): тема подтяжки
  совпадает с темой чекпоинта кода — отсеиваются оба; рубеж тогда опирается
  на журнальный признак шага developer (`review.py:373-375`) — fail-closed,
  не обход (наблюдение аналитика в «Материалах»; не отклонение).
- Иных путей буквального исполнения в обход смысла рубежа или проверки
  поля не найдено: подстановка однократная закреплена AC-2/AC-7, ветка
  подтяжки — `base` записи (AC-8), деградация — к прежнему префиксу.

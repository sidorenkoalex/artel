## Проверяемость критериев

| Критерий | Проверяем | Ловимая мутация |
|---|---|---|
| AC-1 | да | шаблон не читается в `commit_success_checkpoint` (первая строка `<id>: …`); `{title}` подставляет id или служебный текст; шаблон переносится внутрь `pult_message` и меняет подпись (сравнение подписи с коммитом без поля) |
| AC-2 | да | `{text}` подставляется с префиксом `<id>: ` или названием задачи (как в `commit_title`) |
| AC-3 | да | умолчание не `{id}: {text}` (лишний пробел/двоеточие); шаблон применён к `artifact_branch` (:371) или к сжатому коммиту (`pull.py:1107`) |
| AC-4 | частично | проверка подстановок/`{ref}` без `ref_required` снята — ловит, только если поле уже известно загрузчику; до кода тест зелёный (см. отклонение 2) |
| AC-5 | частично | при отсутствии ссылки — пустой `{ref}` в сообщении или остановка шага ловится; отсутствие записи журнала — ловится лишь при заданной форме записи (см. отклонение 3) |
| AC-6 | да | поле не внесено в `LOCAL_FIELDS["policy"]` (позитивная часть); недопустимое значение записывается (отказ без `merge_local`) |

Красная фаза (тесты до кода): все критерии исполнимы на вымышленном проекте
и временных git-репозиториях `tests.sandbox` (так же, как существующие
`tests/test_01m3vfyp4rxby0bg8d3a0b18hd_pult_commit.py`,
`tests/test_timeout_checkpoint.py`); хуков, pager, fsmonitor, порождения
процессов и меняющих команд против настоящего репозитория критерии не
требуют. AC-1, AC-2, AC-5, позитивная часть AC-6 — красные до кода (поле
отклоняется загрузчиком как неизвестное). AC-3 — зелёный до кода по замыслу
(страж неизменности). AC-4 и отказная часть AC-6 — зелёные до кода по
чужой причине:
- `targets._check_local_sections` уже отклоняет неизвестное поле
  `'commit_message_template'` текстом, называющим поле
  (`orchestrator/targets.py:539-541`);
- `target-set` уже отклоняет поле вне `LOCAL_FIELDS` без записи файла
  (`orchestrator/projects.py:781-783`).

Отклонения:
1. **Места требования 3 вне критериев.** AC-1…AC-3, AC-5 проверяют только
   `commit_success_checkpoint` (чекпоинты тестов/кода). Ни один критерий не
   проверяет подтяжку (`pull.py:473`, `pull.py:556`), `amend-tests`
   (`amend.py:806`), аварийный (`checkpoint.py:776`), таймаут (`:369`),
   `pause --now` (`:821`), перед подтяжкой (`:1572`). Мутация «шаблон
   применён только в `commit_success_checkpoint`» (`checkpoint.py:925-934`)
   проходит все AC, оставляя ровно то состояние, которое «Оценка объёма»
   SPEC называет нарушением соглашения проекта. ТЗ тоже ограничилось
   чекпоинтами тестов/кода — решение за Оператором: добавить критерий на
   merge-коммит подтяжки и коммит `amend-tests` (или на общий помощник
   `_commit_worktree_change` + оба места `pull.py` + `amend.py`), либо
   принять покрытие только ревью.
2. **AC-4 не отличает новую проверку от отказа «неизвестное поле».** Тест
   AC-4 в нынешней форме зелёный до кода (targets.py:539-541) — отказ
   называет поле `commit_message_template` и без реализации. Нужна
   оговорка: отказ — не «неизвестное поле» (или в том же тесте допустимый
   шаблон `{ref}: {title}` при `ref_required` загружается). То же для
   отказной части AC-6 (projects.py:781-783).
3. **AC-5: форма записи журнала не задана.** «Запись с причиной» без
   действия/текста: тест либо навяжет устройство (имя действия), либо
   проверит «появилась какая-то запись» — тогда ловится и посторонняя
   запись (например `journal_pult_commit`, gitcmd.py, у проекта с
   `commit_author`). Предлагаю задать наблюдаемое: запись называет поле
   `commit_message_template` и систему `ref_required`.
4. (незначительное) Порядок/однократность подстановки не задан: значения
   `{title}` (название задачи) и `{text}` (в `amend` — `reason` Оператора,
   amend.py:1106) могут содержать литерал `{id}`/`{ref}`/`{text}`;
   цепочка `str.replace` как в `commit_title` (pull.py:938-939) подставит
   его повторно. Ни один AC этого не проверяет; решение — оговорка
   «подстановка однократная, значения не перечитываются» или принять как
   есть.

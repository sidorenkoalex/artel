# SPEC: Деление переписывает merge_after зависящих задач

## Контекст
Родительская задача: 01M4JASKTKX6XYG5P2SACJYJH7 (порядок старта в очереди
зоны). Деление задачи на гейте SPEC (approve на `spec_gate` с секцией
«## Деление», `orchestrator/fsm.py::_spawn_division_subtasks`, ~819)
переводит родителя в `killed`, но `merge_after` задач, зависящих от
родителя, по-прежнему указывает на него. Поэтому
`orchestrator/merge_after.py::check` (~126) и `merge_gate_refuses` (~387)
отказывают зависящей задаче «зависимость убита». Так случилось 05.10:
01M45FJD46 поделили на подзадачи. Сейчас снять или заменить такую
зависимость можно только вручную, ответом Оператора.

## Требования
1. Когда задачу делят на гейте SPEC (approve на `spec_gate` с секцией
   «## Деление»), `merge_after` каждой задачи, зависящей от родителя
   (родитель есть в её `merge_after`), переписывается: элемент-родитель
   заменяется последней подзадачей деления, прочие элементы остаются.
2. Запись идёт через `orchestrator/merge_after.py::rewrite` (~286).
   В журнал зависящей задачи пишется запись «было → стало».
3. Ожидание существующих тестов `tests/` меняется только через раздел
   SPEC «Меняемое поведение» (инвариант 38). Код main проверен:
   требования 1–2 не меняют ожидание ни одного существующего метода.
   Действующие тесты деления (`tests/test_catalog_spawn_subtask.py`,
   `tests/test_division_parent_cleanup.py`) не заводят задач, зависящих
   от родителя. Поэтому раздела «Меняемое поведение» в этом SPEC нет.

## Критерии приёмки
AC-1. Задачу P делят на гейте SPEC на подзадачи S1…Sn. Задача D имеет
`merge_after`, где P стоит в паре с другой задачей X. После деления
`merge_after` D совпадает с прежним, только элемент P заменён на Sn
(последняя подзадача деления). X остаётся. Если от P зависят две
задачи, переписываются обе.

AC-2. Каждое такое деление добавляет в журнал зависящей задачи D запись
`merge_after` «было → стало». В ней названо прежнее значение (с P) и
новое (с Sn).

AC-3. После деления P approve на `merge_gate` задачи D не отказывает
«зависимость мержа убита» из-за P: в журнале D нет записи
`approve отклонён: зависимость мержа убита` по P.

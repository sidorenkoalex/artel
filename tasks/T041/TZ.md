# ТЗ: Протокол рестарта после таймаута шага: WIP-чекпоинт оркестратора

Протокол рестарта после таймаута шага (строка беклога P3; прецеденты T022 и T037 26.08).

Проблема: связка «таймаут посреди работы агента × сверка целостности при старте следующего шага» — гарантированный инцидент, решаемый только руками: оборванный шаг оставляет незакоммиченный WIP в рабочем дереве, сверка целостности (fixation.check_integrity, «грязная копия артефактов») честно уводит задачу в escalated, и Оператор коммитит WIP чекпоинтом вручную (T022; повторено 26.08 на T037: чекпоинт «WIP-чекпоинт Оператора после таймаута шага developer»).

Что сделать: при таймауте агентного шага (orchestrator/runner.py, ветка обработки истёкшего AGENT_TIMEOUT_SEC) оркестратор САМ коммитит рабочее дерево ветки задачи чекпоинтом с сообщением вида «<id>: WIP-чекпоинт после таймаута шага <role>» и записью в журнал (actor orchestrator, action с пометкой таймаута). Рестарт шага стартует от этого чекпоинта штатно, без эскалации по грязной копии — эскалация по таймауту как таковая (нужен ли Оператор для решения о продолжении) остаётся как есть.

Границы: чекпоинт коммитится только в ветку задачи и только при таймауте (не при обычном провале rc!=0 — там дерево должно оставаться как есть для диагностики); сверка целостности не ослабляется — она просто перестаёт встречать незакоммиченное состояние после таймаута; git — через обёртки gitcmd.

Критерии приёмки (ориентир): (1) таймаут шага с незакоммиченными правками в дереве → в ветке задачи появляется коммит-чекпоинт с именем роли и записью журнала; (2) последующий run/advance не эскалирует по «грязной копии» из-за хвостов оборванного шага; (3) провал шага по коду возврата (не таймаут) чекпоинт НЕ коммитит — прежнее поведение; (4) таймаут при чистом дереве (агент ничего не успел) чекпоинт не создаёт пустым коммитом; (5) существующие тесты зелёные (правки — по правилам песочницы T037).

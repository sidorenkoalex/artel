# SPEC: Протокол рестарта после таймаута шага: WIP-чекпоинт оркестратора

## Контекст
Таймаут агентного шага (`orchestrator/runner.py`, ветка обработки истёкшего
`AGENT_TIMEOUT_SEC`) обрывает шаг посреди работы агента и оставляет
незакоммиченный WIP в рабочем дереве ветки задачи. Сверка целостности при
старте следующего шага (`fixation.check_integrity`) честно встречает
«грязную копию артефактов» и уводит задачу в `escalated` — рестарт после
таймаута решается только руками Оператора: он коммитит WIP чекпоинтом
вручную (прецедент T022; повторено 26.08 на T037, чекпоинт «WIP-чекпоинт
Оператора после таймаута шага developer»). Задача — сделать этот шаг
автоматическим действием оркестратора.

## Требования
1. При таймауте агентного шага (ветка обработки истёкшего
   `AGENT_TIMEOUT_SEC` в `orchestrator/runner.py`) оркестратор сам
   коммитит рабочее дерево ветки задачи чекпоинтом — без участия
   Оператора.
2. Сообщение коммита-чекпоинта имеет вид
   «`<id>: WIP-чекпоинт после таймаута шага <role>`».
3. Факт чекпоинта отражается записью в журнале задачи: actor
   `orchestrator`, action с пометкой таймаута.
4. Чекпоинт коммитится только в ветку задачи и только при таймауте шага.
   При провале шага по коду возврата (rc != 0, не таймаут) чекпоинт не
   коммитится — рабочее дерево остаётся как есть, для диагностики
   (прежнее поведение не меняется).
5. Сверка целостности (`fixation.check_integrity`) не ослабляется и не
   меняется в своей логике — после чекпоинта она просто не встречает
   незакоммиченное состояние, оставшееся от оборванного шага.
6. Эскалация по самому таймауту (решение о том, нужен ли Оператор для
   продолжения) остаётся как есть — не меняется этой задачей.
7. Все git-операции чекпоинта выполняются через обёртки `gitcmd`, не
   через прямой вызов `subprocess`/`git` в обход модуля.

## Критерии приёмки
AC-1. Таймаут шага с незакоммиченными правками в рабочем дереве ветки
задачи → в ветке задачи появляется коммит-чекпоинт с сообщением вида
«`<id>: WIP-чекпоинт после таймаута шага <role>`» и соответствующая
запись в журнале задачи (actor `orchestrator`, action с пометкой
таймаута).

AC-2. После таймаута с чекпоинтом по AC-1 последующий `run`/`advance`
не эскалирует задачу по «грязной копии» артефактов из-за хвостов
оборванного шага.

AC-3. Провал шага по коду возврата (rc != 0, не таймаут) чекпоинт не
коммитит — рабочее дерево ветки задачи остаётся незакоммиченным, как до
этой задачи.

AC-4. Таймаут при чистом рабочем дереве (агент ничего не успел
изменить/закоммитить) не создаёт пустой коммит-чекпоинт.

AC-5. Существующий набор тестов остаётся зелёным.

## Не входит
- Изменение поведения при провале шага по коду возврата (rc != 0) —
  дерево в этом случае по-прежнему не коммитится оркестратором.
- Изменение логики эскалации по самому факту таймаута (нужен ли
  Оператор для решения о продолжении шага) — остаётся как есть.
- Ослабление, отключение или изменение проверок
  `fixation.check_integrity` — сверка целостности не трогается.
- Коммит чекпоинта куда-либо, кроме ветки задачи (например, в `main`
  или в артефактный репозиторий target'а отдельно от ветки задачи).

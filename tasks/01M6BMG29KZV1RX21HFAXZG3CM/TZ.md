# ТЗ: GitLab: гейт неослабления по исходам для full_suite ci — на verifying по отчёту CI отправленной головы

# GitLab: гейт неослабления по исходам для компонента `full_suite: ci` — на `verifying` по отчёту CI отправленной головы, а не локальным прогоном на `in_dev`

## Факты

ADR-0029 п. 9; ADR-0026 п. 6; решение Оператора 30.10 (уточнение ADR-0029: «гейт исходов на `in_dev` для `ci` пока локальный» — временно, до этой задачи). Влиты: В1.1 (источник полного набора), В1.2 (гейт по исходам из отчётов CI на гейте мержа), Б1.2 (сжатие и перебазирование перед отправкой). Аналитик сверяет строки по коду после мержа В1.2.

1. Переход `in_dev → verifying` — `fsm_advance.in_dev` (`orchestrator/fsm_advance.py:759`): рубежи по порядку, гейт по исходам `_outcome_integrity_gate_refuses` (`:843`) стоит ДО сжатия ветки (`:855`) и отправки на `origin` (`_origin_push_gate`, `:868`). В этой точке головы на сервере нет, отчёта CI по ней нет — для компонента `ci` гейт гоняет полный набор локально (две выписки).
2. Ожидание CI — `fsm_advance.verifying` (`:441`): зелёный CI головы → `review`; иначе ждёт до `config.VERIFYING_CEILING_SEC`, затем эскалация.
3. Гейт по исходам из отчётов CI на гейте мержа — `outcome_integrity.merge_gate_escalates` (`orchestrator/advance_gates/outcome_integrity.py:1153`) после В1.2: отчёт головы (конвейер ровно sha), отчёт базы (конвейер точки ответвления или коммита с тем же деревом), сравнение `compare`.
4. Для проекта, у которого полный набор требует служб (база, очередь, хранилище), локальный полный прогон на машине пульта недоступен или долог; полный набор в CI идёт минуты.

## Требуется

1. **Компонент `full_suite: ci`**: гейт по исходам на `in_dev` не гоняет полный набор локально; переход `in_dev → verifying` идёт без него (прочие рубежи и их порядок прежние).
2. **Гейт по исходам на `verifying`**: после зелёного CI головы и до перехода в `review` — сравнение исходов из отчёта задания `ci_job` конвейера ровно отправленного sha с отчётом базы тем же ядром, что на гейте мержа (В1.2: правило поиска отчёта базы, перевод идентификаторов, «неизвестно» не зелёный). Голова — sha, отправленный на входе в `verifying` (после сжатия и перебазирования), а не локальный коммит роли.
   - Находка без мандата — возврат в `in_dev` с находками в журнале тем же текстом и записью, что отказ гейта на `in_dev` сейчас (разработчик получает те же сведения); счётчик возвратов — общий с прежним гейтом.
   - Отчёт головы ещё не готов, отчёта нет или он не разобран — ожидание в `verifying` с именованной причиной (не зелёный, не пропуск); по потолку `VERIFYING_CEILING_SEC` — эскалация с этой причиной.
   - Нет отчёта базы ни у точки ответвления, ни у коммита того же дерева — эскалация «нет отчёта базы», не пропуск.
   - Мандат Оператора на исход (ADR-0026) читается с ветки-источника `tasks/<id>/` тем же путём, что сейчас.
3. **`both`**: локальная часть гейта — на `in_dev` без изменений; часть по отчётам CI — на `verifying` по п. 2; переход в `review` — только при обеих.
4. **Гейт мержа** (`merge_gate_escalates`) — без изменений: повторная сверка на подтверждённой голове остаётся.
5. **Компонент `local`** (по умолчанию) и артель — порядок рубежей, записи журнала и существующие тесты прежние.
6. Уточнение ADR-0029 от 30.10 «гейт исходов на `in_dev` для `ci` пока локальный» снимается: строка в «Решения Оператора» — doc-commit Оператора после мержа (не в зонах задачи).

Критерии приёмки (подменённый `forge`, песочницы — вымышленные проекты):
- `ci`: на `in_dev` шпион прогона не видит полного набора; задача уходит в `verifying`, ветка отправлена;
- `ci`, CI головы зелёный, отчёт головы и базы без расхождений → `review`, запись журнала с конвейером головы, конвейером базы и числом тестов;
- `ci`, тест зелёный в отчёте базы и красный или пропавший в отчёте головы, без мандата → `in_dev`, находки в журнале тем же текстом, что у отказа на `in_dev`; с мандатом на этот тест → `review`;
- `ci`, отчёт головы `None` / задание `running` → задача в `verifying` с причиной; по истечении подменённого потолка — `escalated` с той же причиной;
- `ci`, нет отчёта базы ни у точки ответвления, ни у коммита того же дерева → `escalated` «нет отчёта базы»;
- голова для гейта — отправленный sha после сжатия (шпион чтения отчёта видит sha сжатого коммита, а не коммита роли);
- `both`: локальный отказ — на `in_dev` как сейчас; отказ по отчётам — на `verifying`; `review` только при обоих зелёных;
- задание `ci_job` перезапущено между чтением годности и чтением отчёта (номер задания до и после различается) → сбой подготовки «перезапущено во время чтения», не сравнение — и на `verifying`, и на гейте мержа (решение D3 В1.2; код `outcome_integrity.py` ~`:1062` уже это делает, теста нет — находка проверяющего приёмки В1.2);
- `local` и артель: существующие тесты гейта по исходам, переходов `in_dev`/`verifying` и журнала зелёные без правки.

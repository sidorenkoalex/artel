# ТЗ: циклы run/auto отвязаны от процесса сессии Оператора (второй заход)

Источник: задача 01M1NWCHVTYQ0M8PCJ1YJ2N78P (закрыта Оператором 06.09
по решению «завести заново»): её планка была написана до механик,
смерженных позже (переход по готовым артефактам до запуска роли,
лимит буксования цикла, гейт ёмкости диффа, PATH роли из манифеста
стека), и структурно с ними конфликтует; две ручные правки планки
вскрывали следующий разрыв. Код задачи готов и сохранён.

Готовые материалы (ветки главной копии пульта, читать через `git show`
/ `git diff`, в worktree роли их нет):
- `keep/01m1nwchvt-code` — кодовая ветка закрытой задачи: реализация
  отвязки циклов (developer, 8 шагов), дифф к main ~650 строк в
  `orchestrator/` и `tests/` (`git diff main...keep/01m1nwchvt-code --
  orchestrator tests`). Переиспользовать, не переписывать; расхождения
  с main после подтяжки — разрешать в пользу main.
- `keep/01m1nwchvt-artifacts` — артефакты закрытой задачи: SPEC.md
  (требования и критерии), PLAN.md с разделом «Риски» (разбор трёх
  структурных конфликтов старой планки с новой механикой — обязателен к
  прочтению test_author'ом, чтобы не повторить их).

Требуется:
1. Аналитик: SPEC по SPEC закрытой задачи (`keep/01m1nwchvt-artifacts`,
   `tasks/01M1NWCHVTYQ0M8PCJ1YJ2N78P/SPEC.md`) с теми же требованиями и
   критериями (детач `run`/`auto`, `--attach` передний план, журнал
   stdio, lease/heartbeat у цикла, `stop`, `kill` цикла, doctor три
   состояния, запись причины при обрыве); правки — только там, где
   механика main ушла вперёд (назвать явно). Зоны — по факту диффа
   `keep/01m1nwchvt-code`.
2. Test_author: планка под СЕГОДНЯШНЮЮ механику. Песочница не должна
   зависеть от порядка PATH процесса (PATH роли собирается из каталогов
   инструментов манифеста; подставной `claude` — через подстановку всех
   инструментов манифеста в один каталог либо через мок точки запуска
   агента, как в `tests/sandbox.py`), от `/bin` в PATH роли (абсолютные
   пути в скриптах-заглушках), от отсутствия кодовой ветки у задачи в
   in_dev (гейт ёмкости диффа сверяет `main...<ветка>` до запуска роли),
   от заглушки ревьювера со статусом `draft` (лимит буксования
   `AUTO_STALL_STEPS_LIMIT` гоняет её пять кругов). Сценарии,
   измеряющие время, — с запасом относительно бэкоффов и стоп-кранов
   цикла, а не впритык. Каждый сценарий — с явным обоснованием, какую
   мутацию ловит.
3. Разработчик: перенести реализацию с `keep/01m1nwchvt-code` (cherry-pick
   или ручной перенос диффа) на свежую ветку от main, довести до зелёной
   планки; правку `tests/test_git_fixation.py::enter_in_dev` (ветка
   задачи и REVIEW-заглушка) переносить только если планка её требует.

Зоны: orchestrator/auto.py, orchestrator/runner.py, orchestrator/lease.py,
orchestrator/liveness.py, orchestrator/doctor.py, orchestrator/catalog.py,
orchestrator/artel.py, tests/ (уточнить по диффу keep-ветки на этапе SPEC).

Не входит: изменение механик, с которыми конфликтовала старая планка
(лимит буксования, гейт ёмкости, PATH роли) — они правятся своими
задачами; ручные правки планки Оператором.

Рамка: $30 (по калибровке ADR-0014: >10 AC, но код готов).

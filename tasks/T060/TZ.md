# ТЗ: Лимитер параллельных задач: MAX_PARALLEL_TASKS=2

## Контекст

Очередь Оператора п.2б роадмапа, решение 28.08: лимитер параллельных
задач — он же формальное ВКЛЮЧЕНИЕ N=2. Контур параллельности собран
(lease T044, worktree T045, CAS T050, сверка свежести T051, возврат
T052, merge queue T053, изоляция хуков T058, автокоммит T059), но
формального N в системе нет — неявная бесконечность, сдерживаемая
дисциплиной. Лимит нужен как код (принцип «оркестратор не думает»):
темп расхода = f(N) при стоп-лоссе $2000; ручные гейты упираются в
пропускную способность Оператора; runaway-выводок auto уже случался.

## Решение (Оператор 28.08)

1. Константа `config.MAX_PARALLEL_TASKS = 2`.
2. Команды, запускающие агентный шаг (`run`, `auto`), перед стартом
   шага считают число ДРУГИХ задач, находящихся в работе прямо сейчас:
   задачи с живым lease чужой сессии и живым pid (механика
   `store.all_leases` + `liveness._pid_alive` / `_age_seconds`,
   протухшие и мёртвые не в счёт). Своя задача в счёт не входит.
3. Счёт ≥ MAX_PARALLEL_TASKS → именованный отказ с перечнем: id задач,
   session_id держателей, значение потолка — шаг не стартует, журнал
   получает запись об отказе. Никакого ожидания в цикле.
4. Лимит — защита класса «лимит» (ADR-0002): поднять значение может
   только Оператор правкой config (как бюджетные потолки); кодируется
   неослабляемым тестом в test_invariants.py (запуск шага при
   достигнутом потолке отказывает; отказ не обходится ни advance, ни
   повторным вызовом).
5. Не-агентные команды (status, log, doctor, approve, reject, kill,
   budget, new) лимитер НЕ трогает: kill обязан срабатывать всегда
   (инвариант 14), гейты и наблюдение не должны зависеть от занятости
   конвейера.
6. Текст строки для docs/invariants.md готовится в PLAN (по образцу
   T058), вносит Оператор при мерже.

## Границы

- orchestrator/ (runner/auto/config и смежные), тесты, карта.
- Не ослаблять существующее (ADR-0002); lease-механика не меняется —
  лимитер только ЧИТАЕТ leases.

## Не входит

- Изменение lease (порог, release-команда — отдельная строка P3).
- Очередь ожидания/автозапуск при освобождении слота.
- Per-target потолки (один глобальный на пульт).
- Фактическая правка docs/ — текст в PLAN, вносит Оператор.

## Приёмка (минимум)

- Две задачи держат живые lease чужих сессий → `run`/`auto` третьей
  отказывает с перечнем держателей и значением потолка; запись в
  журнале.
- Одна занятая (или lease протух/pid мёртв) → запуск второй проходит.
- Собственный lease задачи не считается против неё самой (повторный
  run своей задачи не блокируется её же lease).
- kill/status/approve/reject работают при достигнутом потолке.
- Неослабляемый тест инварианта зелёный; все существующие тесты
  зелёные.

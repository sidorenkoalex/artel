# SPEC: Предел полного прогона tests/ — поле профиля тестов проекта

## Контекст
Канарейка 20261006T122912Z на 73ce3329: полный прогон `tests/` автогейта
превысил `config.FULL_SUITE_TIMEOUT_SEC = 900`; под параллельной нагрузкой
прогон долгоживущих файлов идёт в 4–5 раз дольше. Поднять предел штатно
Оператор не может: константа живёт в коде (`orchestrator/config.py:195`),
`doc-commit` принимает только `docs/**` и конфиги, push кода в main
останавливает pre-push. Задача выносит предел в профиль тестов проекта
(`targets.yaml`, поле `test_profile`), который Оператор правит штатно
командой `doc-commit targets.yaml`; без нового поля всё работает как
сегодня.

## Требования
1. Профиль тестов проекта (`test_profile` записи `targets.yaml`) принимает
   необязательное подполе `full_suite_timeout_sec` — целое число секунд,
   больше нуля.
2. Неверное значение `full_suite_timeout_sec` (не целое — строка, дробное,
   логическое; либо целое ≤ 0) — отказ разбора профиля тем же путём, что
   другие ошибки профиля (`targets.TargetsError` из проверки записи;
   `repo_context.profile_of` → «не прочитан»); причина называет подполе
   `test_profile.full_suite_timeout_sec`.
3. Действующий предел полного прогона `tests/` проекта задачи —
   `full_suite_timeout_sec` профиля этого проекта, если подполе задано;
   иначе `config.FULL_SUITE_TIMEOUT_SEC` (900). Значение константы
   читается в момент прогона (тесты её подменяют).
4. Действующий предел требования 3 применяется ко всем полным прогонам
   `tests/` пульта: автогейт приёмки, `approve` в `acceptance`, гейт мержа
   (`merge_gate`, прогон после приложений) и команда `suite-run`.
5. Тексты исхода «прогон не уложился в предел» (запись журнала, `detail`
   отказа, вывод команды, отчёт `suite-run`, строка ожидания замка о
   пределе прогона) называют действующий предел в секундах и его источник:
   «профиль тестов проекта <имя проекта>» либо «config». Существующие
   начала текстов сохраняются («прогон полного набора tests/ превысил …»,
   «прогон не уложился в <N> с …»): источник дописывается к ним, а не
   заменяет их.
6. `doctor` показывает строку о пределе полного прогона по каждому
   проекту `targets.yaml`: имя проекта, действующий предел в секундах и
   источник («профиль тестов проекта <имя>» либо «config»). Решение
   «где показывать» по пункту 3 ТЗ — `doctor`, не `status`: предел —
   свойство проекта, а не задачи.
7. Тесты в `tests/` к требованиям 1–6 несут заявки «Ловит мутацию».
   Существующие тесты не ослабляются; `FULL_SUITE_LOCK_WAIT_SEC` не
   меняется.
8. PLAN задачи содержит готовую строку для Оператора на после мержа:
   команду `doc-commit targets.yaml`, вносящую `full_suite_timeout_sec:
   1500` в профиль артели (само внесение — вне задачи).

## Критерии приёмки
AC-1. Профиль тестов проекта с подполем `full_suite_timeout_sec: <N>`
(целое > 0) разбирается без ошибки, а запись `targets.yaml` с таким
профилем проходит проверку записи (`targets.load`).

AC-2. Подполе `full_suite_timeout_sec` со значением 0, отрицательным
целым, строкой (`"1500"` в кавычках) или дробным числом — отказ разбора
профиля (`targets.TargetsError`), причина называет
`test_profile.full_suite_timeout_sec`; гейт пульта, читающий профиль этого
проекта, отказывает тем же путём, что при любой другой ошибке профиля.

AC-3. Полный прогон `tests/` на гейте пульта для проекта, в профиле
которого задано `full_suite_timeout_sec: <N>`, обрывается по пределу `N`
секунд, а не по `config.FULL_SUITE_TIMEOUT_SEC` (проверяется при `N`,
отличном от значения константы).

AC-4. Полный прогон `tests/` на гейте пульта для проекта, в профиле
которого подполя `full_suite_timeout_sec` нет, обрывается по пределу
`config.FULL_SUITE_TIMEOUT_SEC` (значение, подменённое тестом, читается в
момент прогона).

AC-5. Команда `suite-run` для задачи проекта с `full_suite_timeout_sec:
<N>` в профиле обрывает прогон по пределу `N` секунд, и её отчёт о
таймауте называет `N`.

AC-6. Текст исхода таймаута полного прогона на гейте (автогейт или
`approve` в `acceptance`, гейт мержа) называет действующий предел в
секундах и источник: «профиль тестов проекта <имя>» при заданном подполе,
«config» — без него.

AC-7. Начала существующих текстов таймаута сохранены: исход прогона
по-прежнему начинается с «прогон полного набора tests/ превысил <N>с», а
отказ гейта мержа содержит «прогон не уложился в <N> с», где `<N>` —
действующий предел.

AC-8. `doctor` выводит по каждому проекту `targets.yaml` строку с именем
проекта, действующим пределом полного прогона в секундах и источником:
«профиль тестов проекта <имя>» для проекта с подполем, «config» — для
проекта без подполя или без профиля.

всех местах полного прогона; часть, принимающая подполе в профиле без
применения на всех гейтах, оставила бы Оператору поле, которое на гейте

мержа такой части было бы небезопасно. Правка в каждом модуле — несколько
строк (чтение предела вместо константы и дописанный источник в текст);
строка `doctor` отделима, но её отдельная задача стоила бы дороже самой
строки. Решение — за Оператором на гейте SPEC.

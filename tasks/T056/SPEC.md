# SPEC: Инвариант: пульт исполняется только из главной копии

## Контекст

28.08 дважды за день (T052, T055) Оператор запускал
`python3 orchestrator/artel.py approve/auto` с cwd внутри
`.artel/worktrees/<id>`: исполнялась копия кода из worktree,
`config.ROOT` резолвился в worktree, и код на ходу создавал там
паразитную пустую `.artel/state.db`. Повезло, что команды падали («no
such table: leases») — тихий вариант исполнился бы мимо настоящего
пульта (журнал, счётчики, задачи). Worktree-норма T045 объявила
main-копию территорией оркестратора, но держится только дисциплиной;
инцидент доказал, что без guard'а она не держит. Нужен инвариант,
который останавливает запуск `artel.py` из worktree до того, как код
коснётся БД.

Зона изменений — только `orchestrator/` (`artel.py` и, при
необходимости, `config`/`gitcmd`), тесты и карта кодовой базы.
`docs/invariants.md` в этой задаче не редактируется: текст строки
готовит разработчик в PLAN, вносит его Оператор при мерже.

## Требования

1. `artel.py` на входе — до любого обращения к БД и до диспетчеризации
   команд — проверяет, что `config.ROOT` является главной копией
   репозитория, а не git-worktree.
2. Признак worktree: `ROOT/.git` — файл-ссылка вида `gitdir: ...`, а не
   каталог. Этого признака достаточно. Дополнительный (дешёвый)
   признак — путь `ROOT` содержит `.artel/worktrees/` — по усмотрению
   разработчика как ранний быстрый отказ.
3. Обнаружен worktree → именованный отказ до создания каких-либо
   файлов, каталогов или БД. Сообщение называет фактический `ROOT` и
   путь главной копии (читается из содержимого файла `ROOT/.git`:
   `gitdir: <main>/.git/worktrees/<id>`), с подсказкой перезапустить
   из главной копии. Никакая паразитная `.artel/` не создаётся.
4. Проверка и отказ распространяются на ВСЕ команды CLI, включая
   читающие (не только мутирующие) — читающая команда над паразитной
   пустой БД тоже возвращает ложный результат.
5. Тестовые песочницы (временные каталоги без файла-ссылки `.git`) под
   проверку не подпадают — для них поведение не меняется.
6. Запуск из главной копии — поведение байт-в-байт прежнее.
7. Инвариант закреплён неослабляемым тестом в `test_invariants.py`:
   вызов CLI с `ROOT`, указывающим на git-worktree, приводит к отказу,
   `.artel/` и БД в этом ROOT не создаются.

## Критерии приёмки

AC-1. Запуск любой команды CLI с `config.ROOT` внутри git-worktree
завершается именованным отказом, называющим фактический `ROOT` и путь
главной копии, с подсказкой перезапустить оттуда; каталог `.artel/` в
worktree не появляется, БД не создаётся.

AC-2. Запуск любой команды CLI из главной копии — поведение идентично
прежнему, байт-в-байт.

AC-3. Неослабляемый тест инварианта в `test_invariants.py` зелёный; все
существующие тесты зелёные, включая тесты, использующие временные
песочницы (не git-worktree) — их проверка не задевает.

## Не входит

- Авто-редирект исполнения на главную копию: исполнять код ветки над
  боевой БД запрещено — Оператор явно отверг самонаведение, только
  отказ.
- Запрет молчаливого создания БД в `store.db()` — обобщение класса
  проблемы вынесено отдельной строкой (P3), не эта задача.
- Обёртки/alias в PATH, клиентские хуки.
- Изменение worktree-механики T045: `workspace.ensure` и работа ролей
  внутри worktree не меняются — роли не запускают `artel.py`.
- Правка `docs/invariants.md`: строку готовит разработчик в PLAN,
  вносит Оператор при мерже.

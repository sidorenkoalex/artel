# ТЗ: Инвариант: пульт исполняется только из главной копии

## Контекст

Инцидент 28.08, повторившийся дважды за день (T052, T055): Оператор
запускал `python3 orchestrator/artel.py approve/auto` с cwd внутри
`.artel/worktrees/<id>` — исполнялась копия кода из worktree,
`config.ROOT` (Path(__file__)...) резолвился в worktree, и код на ходу
создавал там паразитную пустую `.artel/state.db`. Повезло, что команды
падали («no such table: leases»); тихий вариант — команда, которой
хватает пустой БД, исполнилась бы в паразитном мире мимо настоящего
пульта (журнал, счётчики, задачи). Worktree-норма T045 объявила
main-копию территорией оркестратора, но держится только дисциплиной —
инцидент доказал, что дисциплина без guard'а не держит. При N=2 класс
станет только вероятнее (вторая сессия запустит пульт из чужого
worktree).

## Решение (принято Оператором 28.08)

Новый инвариант (следующий номер в docs/invariants.md):
**«Мутирующая команда пульта исполняется только из главной копии над
её БД»**. Детект worktree — реализация, не суть инварианта.

1. `artel.py` на входе (до любого касания БД и до диспетчеризации
   команд) проверяет, что `config.ROOT` — главная копия, а не
   git-worktree. Железный признак worktree: `ROOT/.git` — файл-ссылка
   `gitdir: ...`, а не каталог; дополнительный (дешёвый) признак —
   путь ROOT содержит `.artel/worktrees/`. Достаточно первого;
   второй — по усмотрению developer как ранний быстрый отказ.
2. Обнаружен worktree → именованный отказ ДО создания каких-либо
   файлов/каталогов/БД: сообщение называет фактический ROOT и путь
   главной копии (он читается из файла `.git`: `gitdir:
   <main>/.git/worktrees/<id>`) с подсказкой «перезапусти из главной
   копии». Никакая паразитная `.artel/` не создаётся.
3. Отказ распространяется на ВСЕ команды CLI, не только мутирующие:
   читающая команда над паразитной пустой БД лжёт (пустой status —
   тоже вред). Формулировка инварианта — про мутирующие (ядро
   гарантии), реализация — тотальная, это строже и проще.
4. Инвариант кодируется неослабляемым тестом (test_invariants:
   вызов CLI с ROOT-worktree → отказ, БД не создана) и строкой в
   docs/invariants.md (правку invariants.md вносит Оператор при
   мерже — роль готовит текст строки в PLAN).
5. Песочницы тестов не задеваются: их временные каталоги — не
   git-worktree (нет файла `.git` со ссылкой), проверка для них
   прозрачна.

## Границы

- Только orchestrator/ (artel.py и, при надобности, config/gitcmd),
  тесты, карта. docs/invariants.md — текст строки готовится в PLAN,
  вносит Оператор.
- Не ослаблять существующие тесты/гейты/инварианты (ADR-0002).

## Не входит

- Авто-редирект на главную копию (исполнять код ветки над боевой БД
  запрещено — отвергнуто Оператором явно; отказ, не самонаведение).
- Запрет молчаливого создания БД в store.db() (обобщение класса —
  отдельная строка P3, не эта задача).
- Обёртки/alias в PATH, клиентские хуки.
- Изменение самой worktree-механики T045 (workspace.ensure и роли
  в worktree работают как работали — роли НЕ запускают artel.py).

## Приёмка (минимум)

- Запуск любой команды CLI с ROOT внутри git-worktree → именованный
  отказ с путём главной копии; `.artel/` в worktree не появляется,
  БД не создаётся.
- Запуск из главной копии — поведение байт-в-байт прежнее.
- Неослабляемый тест инварианта зелёный; все существующие тесты
  зелёные (песочницы не задеты).

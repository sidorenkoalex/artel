# ТЗ: Канарейка сохраняет причину отказа автогейта приёмки

# ТЗ: Канарейка сохраняет причину отказа автогейта приёмки и отмечает прогон с приёмкой вручную

Источник: решение Оператора 30.09.2026; строки копилки 29.09 (П2, «вердикт
канарейки green скрывает отказ автогейта приёмки») и 30.09 (сценарий
сессии ассистента, снимающий причину отказа из базы клона — обход);
отчёт `docs/research/2026-09-29-canary-models-stage2.md`; подготовка
решения о допуске моделей по ADR-0019 п.5.

Факты (пин 34b298c7):
- Учебную задачу ведёт процесс клона (`orchestrator/canary_drive.py`,
  `_drive_task` в `orchestrator/canary.py`). Когда автогейт приёмки
  отказывает, `orchestrator/fsm_autogate.py` пишет в журнал клона запись
  «автогейт acceptance не пройден» с причиной, задача остаётся в
  `acceptance`, и канарейка проводит её дальше помощником
  `_pass_acceptance_gate` («эквивалент operator approve»).
- Причина отказа не доходит до Оператора: выдержка журнала
  (`_journal_excerpt_lines`) берёт только переходы состояний, «переход
  отклонён» и «auto остановлен»; строка итога и `canary_runs` её не
  несут; диагностика (`_needs_diagnostics`) сохраняется только при
  нештатном исходе или расхождении маркера; клон после прогона удаляется.
  Шаги журнала клона при этом уже приходят в процесс пульта в
  JSON-результате (`steps`).
- Итог: прогон, где приёмку провела канарейка, и прогон, где автогейт
  прошёл сам, в строке итога и в `canary_runs` неразличимы (оба
  `green`). В этапе 2 замера моделей 29–30.09 так было в 10 прогонах из
  18; причины пришлось снимать сценарием из базы клона во время прогона.
  Автогейт может не пройти и мгновенно, до прогона полного `tests/`
  (прогон 20260930T054358Z), — такую причину сценарий не поймал.

Требуется:
1. Причина в итоге прогона. Если в журнале учебной задачи есть запись
   «автогейт acceptance не пройден», строка итога задачи в сводке прогона
   называет её причину (текст `detail` записи, схлопнутый в одну строку и
   ограниченный по длине — предел выбирает SPEC). Если задача прошла
   `acceptance` без записи автогейта (политика гейта не `auto`, автогейт
   не запускался), строка итога говорит это прямо. Выдержка журнала
   прогона включает запись отказа автогейта.
2. Запись прогона. `canary_runs` получает сведения о приёмке: как
   пройдена (`autogate` — автогейт сам; `manual` — провела канарейка
   помощником; пусто — задача до `acceptance` не дошла) и причина отказа
   автогейта. Схема — через существующую миграцию `add_column` в
   `orchestrator/store.py`, прежние строки таблицы читаются.
3. Диагностика. При отказе автогейта приёмки диагностика прогона
   сохраняется (`_save_diagnostics`) и при штатном исходе; строка
   «диагностика: …» печатается, как сейчас.
4. Вердикт не меняется. Прогон с приёмкой, проведённой канарейкой,
   остаётся `green`, если по прежним правилам он `green`; вход гейта
   сдвига пина (`store.green_canary_runs`, `orchestrator/pin.py`) не
   меняется. Отметка «приёмка вручную» — отдельное поле (требование 2) и
   пометка в строке итога («приёмка вручную: <причина>»), по которой
   прогон не засчитывается в допуск моделей. Сам допуск — не в этой
   задаче.
5. Совместимость. Проверяемый коммит, чей процесс клона возвращает
   прежний JSON-результат, обрабатывается как сейчас: сведения о приёмке
   строятся из `steps` результата процессом пульта. Если для этого
   понадобится новое поле результата — прежний результат без него не
   ведёт к красному прогону.
6. Тесты в `tests/`: отказ автогейта в журнале → причина в строке итога,
   в `canary_runs` (`manual` + причина), диагностика сохранена, вердикт
   `green` («Ловит мутацию: отказ автогейта не попадает в итог»);
   автогейт прошёл сам → `autogate`, причины нет, диагностики нет при
   штатном исходе; задача не дошла до `acceptance` → поле пусто; прежняя
   строка `canary_runs` без новых колонок читается; `green_canary_runs`
   возвращает прогон с приёмкой вручную так же, как до задачи.
   Существующие тесты канарейки не удаляются и не ослабляются.

Зоны: orchestrator/canary.py, orchestrator/canary_drive.py, orchestrator/store.py, tests/.

orchestrator/pin.py, orchestrator/auto.py, orchestrator/fsm.py,

orchestrator/runner.py, orchestrator/models.py, orchestrator/config.py,

# PLAN: Канарейка сохраняет причину отказа автогейта приёмки

## Подход

Внешний процесс пульта разбирает переходы и отказ автогейта из `steps` прежнего JSON результата. Причину сворачивает в одну строку и обрезает до 500 символов для сводки; исходные шаги остаются в диагностике. Ленивая схема `canary_runs` получает два nullable столбца и мигрирует прежние строки. Сохранение диагностики при отказе отделяется от формулы вердикта, чтобы ручная приёмка оставалась зелёной на прежних условиях.

## Шаги

1. Дополнить `orchestrator/canary.py`: извлечение сведений о приёмке из шагов, выдержку журнала, строку итога и сохранение диагностики при отказе.
2. Дополнить `orchestrator/store.py`: столбцы и запись способа приёмки и причины с совместимостью прежних строк и вызовов.

## Влияние на систему

Меняются только вывод канарейки, её диагностика и два nullable столбца собственной таблицы. `canary_runs.verdict`, `green_canary_runs`, сравнение с бейзлайном и гейты пина сохраняют прежнюю формулу. Старые строки читаются после идемпотентного `add_column`; старый JSON не требует новых полей. Откат кода — revert коммита; добавленные столбцы остаются безвредными для старого кода.

## Риски

Записи журнала могут быть длинными и появляться далеко от конца выдержки; тест проверит предел причины и сохранение отказа при обрезке выдержки.

# ТЗ: Гейт неослабления на чужом стеке: пропуск через метку, помощники, параметризация, async

# Гейт неослабления на чужом стеке: пропуск через метку, помощники, параметризация, async

## Факты

Строки бэклога 18.10 «Гейты по тестам на чужом стеке» (П2) и копилки 17.10 «Гейт неослабления не видит пропуск через переменную-метку»; разбор «что прибито под артель».
- Пропуск через переменную-метку: `guard.SKIP_DECORATOR_NAMES` (`scripts/guard.py:649-650`) опознаёт декоратор по последнему сегменту имени (`skip`, `skipIf`, `skipUnless`, `expectedFailure`, `skipif`, `xfail`); `requires_pg = pytest.mark.skipif(...)` и `@requires_pg` — не пропуск: ни находки, ни записи об условном пропуске (так прошла задача sled 01M55SKHZ293CCAK0N7T4H7ZMR — мандат был в ТЗ, но гейт его даже не спросил). Модульный `pytest.skip(..., allow_module_level=True)`, `pytestmark = …skip…` и `pytest.importorskip` на уровне модуля не ловятся (`guard.py:656-697` смотрит тела функций).
- Помощники: поиск вызывающих ослабленного помощника — только в `tests/` (`orchestrator/advance_gates/test_integrity.py:631-650`), перевод имени модуля `tests.x` → `tests/x.py` (`guard.py:1013-1019`), прослеживание — только `tests/sandbox.py` (`guard.py:1087`); помощники sled (`backend/tests/rbac_support.py` и т. п.) гейту невидимы.
- Параметризация: двусторонний прогон ищет точный id узла, у параметризованного теста отчёт — `::test_x[...]` (`orchestrator/advance_gates/two_sided.py:175-187`) → «узел не найден»; у sled параметризация в 61 файле. Изменения аргументов `@pytest.mark.parametrize` не видят неослабление, храповик и заявка мутации (`guard.py:1765-1768`: сегмент источника без декораторов; `:790-799`).
- `async def test_` не считается тестовым методом (`guard.py:178`, `TEST_METHOD`; 18 файлов sled).

## Требуется

1. Пропуск через имя, связанное в модуле с `pytest.mark.skipif/skip/xfail` или `unittest.skip*` (в том числе импортированное из модуля тестов проекта), и модульные пропуски (`pytestmark`, `pytest.skip(allow_module_level=True)`, `importorskip` уровня модуля) опознаются гейтом неослабления как пропуск — тем же классом находки и тем же послаблением для условного пропуска с причиной, что прямой декоратор. Для артели — то же (усиление существующего свойства).
2. Поиск вызывающих и прослеживание помощников — по области ослабления профиля проекта задачи (`weakening_scope`), с переводом имени модуля в путь от корня проекта с учётом `workdir`; у артели — как сейчас.
3. Двусторонний прогон находит параметризованный тест по базовому id (все его варианты), вердикт по совокупности вариантов; изменения аргументов `parametrize` у метода, сохранившего имя, — наблюдаемое изменение тем же каналом, что изменённые утверждения (журнал, ревью-пакет).
4. `async def test_…` считается тестовым методом во всех местах разбора (`TEST_METHOD`, `qualified_test_methods` и т. п.).
5. Аналитик сверяет, какие из пп.1–4 требуют правок вне зон, и разбивает на подзадачи при сигнале деления; у артели все прежние исходы, кроме пп.1, 4 (усиление), фиксируются тестами до правки.
6. Тесты детерминированы, без сети, на учебном проекте с `workdir: backend` и `weakening_scope: [backend/tests/**/*.py]`.

Критерии приёмки:
- `@requires_pg`-подобный пропуск и модульные пропуски — находка гейта неослабления (или условное послабление с журналом);
- ослабление через помощник внешнего проекта — находка;
- параметризованный тест — вердикт двустороннего прогона, не «узел не найден»;
- `async def test_` учитывается.

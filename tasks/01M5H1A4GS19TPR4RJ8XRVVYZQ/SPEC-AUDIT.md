## Пути обхода гейтов
1. **Диспетчер-помощник.** Буквальное прочтение треб. 2 («общий код
   подслучая — во вспомогательный метод») позволяет вынести весь
   `if/elif` по меткам в помощник и звать его из каждого нового метода:
   гейт по старому имени промолчит, AC-7 пройдёт. Это не ослабление, но
   и не «по одному подслучаю на метод» статически: каждый метод
   формально несёт утверждения всех ветвей. Пусть Оператор решит, разрешено
   ли это (вердикт, п. 1).
2. **Второй уровень.** Если общий код подслучая вместе с вызовами
   `refusal`/`no_gate_refusal`/`assert_prepare`/`assert_depth`/`check_home`
   (это помощники с утверждениями: `outcome_gate.py:864-883`, :1134;
   `spec_audit_flow.py:692-702`; `pytest_own_places.py:431-444`) уйдёт в
   новый помощник, их утверждения окажутся на втором уровне и пропадут из
   `guard.test_assertions` по обе стороны нового кода. Треб. 2 это
   запрещает («утверждения… во вспомогательном методе первого уровня»), но
   AC-7 как «⊆ объединения» поймает это только при честной сверке по
   старой стороне; на эту ловушку стоит указать явно.
3. **Переупорядочение `PLACES`.** Треб. 3 велит сортировать по метке, но
   не запрещает отсортировать сам литерал `PLACES` (:62). Тогда тихо
   сдвинутся `FULL_PLACES`/`TWO_SIDED` (:66-67), и `test_ac4`/`test_ac5`
   начнут проверять не те места, а AC-6 этого не поймает (`PLACES` не
   импортируется другими файлами). Сортировать надо копию в доле, не
   константу.
4. **K = числу элементов.** «Фиксированное число долей» при K, равном
   текущей длине перечня, даёт по одному элементу на долю; новый элемент
   попадёт в долю 0 вместе с прежним. Формально AC-3 выполнен, но это
   дорожка к пункту 2 матрицы (перекрёстная проверка `homes`).

   гейта → эскалация. Посылка ТЗ «находок гейта не даёт» для них неверна.
   Варианты решения: (а) разрешить в SPEC диспетчер-помощник, чтобы

   «Ловит мутацию» (:510-513); AC-2/AC-7/AC-8 этого не ловят. Нужно
   либо требование «в доле `test_ac3_*` не меньше двух прогонов», либо

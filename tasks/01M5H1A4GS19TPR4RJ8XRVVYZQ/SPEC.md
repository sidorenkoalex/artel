## Требования

1. **Разбиение циклов подслучаев.** В каждом разбиваемом методе (перечень —
   «Контекст») цикл подслучаев заменяется отдельными методами (или
   параметризованными подклассами unittest) — по одному подслучаю (или
   одному месту/признаку) на метод.
2. **Перенос дословно.** Тела, утверждения, зёрна, тексты подслучаев и строки
   «Ловит мутацию» переносятся дословно; общий код подслучая — во
   вспомогательный метод класса, имя которого не начинается с `test`.
   Исходное имя метода сохраняется за первым подслучаем или первой долей,
   остальные получают новые имена. Утверждения остаются в самом тестовом
   методе или во вспомогательном методе, который тест вызывает напрямую
   (первый уровень). Вспомогательные методы добавляются в тестовые классы, не
   в классы подготовки (`OutcomeGateSandbox` и т. п.). Каждый новый метод
   несёт докстринг с «Сценарий» и «Ловит мутацию:» своего подслучая; для
   долей — исходный текст целиком.
3. **Перечни, построенные во время выполнения** (`places` у
   `PultUnchangedTest`, `PLACES` у `pytest_own_places`, категории
   путей-признаков из `config` у `test_ac9`), делятся на фиксированное число
   долей `перечень[i::K]` по детерминированному порядку (сортировка по метке);
   перемешивание — внутри доли. Перечень остаётся единственным источником:
   разбиение не заменяет его вписанной копией, и новый элемент перечня
   по-прежнему попадает под проверку без правки теста. Сценарием в PLAN:
   объединение долей равно полному перечню, доли не пересекаются.
4. **Время.** Самый длинный тест каждого из четырёх файлов при отдельном
   прогоне файла — не более 10 с; замеры «до» и «после» — в одном PLAN на
   одной машине.
5. **Вспомогательный метод `tests_dir`** переименовывается (имя не
   начинается с `test`) во всех местах вызова; число тестов набора
   уменьшается ровно на число классов, где он собирался.
6. **Неизменное.** Классы подготовки `OutcomeGateSandbox` и все прочие имена
   (классы, функции, константы), которые импортируют другие файлы `tests/`
   (`tests/test_01m5ddtvzea40zb9bheh4ydee7_merge_outcome_gate.py` импортирует
   из файла outcome_gate `ENTRY_HEAD`, `PLAN_READY`, `PLANK_PY`, `SEP`,
   `OutcomeGateSandbox`, `flow`, `js_source`, `py_source`, `py_tests`,
   `spec_text`, `ulid`), не меняются — ни имена, ни поведение, ни значения;
   `tests/sandbox.py`, `conftest.py`, `pyproject.toml` не меняются.
7. **Доказательство неослабления в PLAN.md:**
   - таблица «старый тест → новые тесты» для каждого разбитого метода;
   - сверка деревьев функцией `guard.test_assertions` по обеим сторонам,
     мультимножествами: утверждения старого метода ⊆ объединение
     утверждений его новых методов;
   - мутации из строк «Ловит мутацию» разбиваемых тестов — по одной на
     разбиваемый метод: каждая применяется к коду пульта в worktree задачи;
     до правки красный хотя бы один старый тест, после правки краснеет новый
     метод того же подслучая; в конце `git status --porcelain orchestrator/`
     пуст; итог — в таблице;
   - число тестов до и после с пересчётом (минус `tests_dir`, плюс методы
     разбиения);
   - время самого длинного теста каждого файла до и после (`--durations`).
8. Новых тестов в `tests/` сверх получившихся разбиением задача не добавляет.

## Критерии приёмки

AC-1. Ни один разбиваемый метод из перечня «Контекст» не содержит цикла подслучаев: каждый подслучай (место, признак) проверяется отдельным тестовым методом или параметризованным подклассом unittest, для перечней из требования 3 — отдельной долей; исходное имя каждого разбиваемого метода существует и несёт первый подслучай или первую долю.

AC-2. Тела, утверждения, зёрна, тексты подслучаев и строки «Ловит мутацию» перенесены дословно; общий код подслучая вынесен во вспомогательный метод тестового класса (не класса подготовки), имя которого не начинается с `test`; утверждения стоят в тестовом методе или во вспомогательном методе первого уровня; каждый новый метод несёт докстринг с «Сценарий» и «Ловит мутацию:» своего подслучая (для долей — исходный текст целиком).

AC-3. Перечни `places`, `PLACES` и категории путей-признаков из `config` делятся на фиксированное число долей `перечень[i::K]` после сортировки по метке, перемешивание — внутри доли; вписанной копии перечня в тесте нет, и элемент, добавленный в исходный перечень, попадает в одну из долей без правки теста; PLAN.md несёт сценарий, показывающий, что объединение долей равно полному перечню и доли не пересекаются.

AC-4. При отдельном прогоне каждого из четырёх файлов зоны самый длинный тест длится не более 10 с; PLAN.md несёт замеры `--durations` «до» и «после» по каждому файлу, снятые на одной машине.

AC-6. `OutcomeGateSandbox` и имена, импортируемые из файлов зоны другими файлами `tests/` (перечень — требование 6), не изменились ни именем, ни поведением, ни значением; `tests/sandbox.py`, `conftest.py`, `pyproject.toml` и файлы `tests/` вне зоны не изменены.

AC-7. PLAN.md несёт таблицу «старый тест → новые тесты» для каждого разбитого метода и сверку `guard.test_assertions` по обеим сторонам мультимножествами, показывающую: утверждения каждого старого метода ⊆ объединение утверждений его новых методов.

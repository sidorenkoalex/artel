## Требуется

1. **Разбиение циклов подслучаев.** В названных методах цикл подслучаев заменяется отдельными методами (или параметризованными подклассами unittest) — по одному подслучаю (или одному месту/признаку) на метод. Тела, утверждения, зёрна, тексты подслучаев и строки «Ловит мутацию» переносятся дословно; общий код подслучая — во вспомогательный метод класса, имя которого не начинается с `test`. Исходное имя метода сохраняется за первым подслучаем или первой долей, остальные получают новые имена. Утверждения остаются в самом тестовом методе или во вспомогательном методе, который тест вызывает напрямую (первый уровень). Вспомогательные методы добавляются в тестовые классы, не в классы подготовки (OutcomeGateSandbox и т. п.). Перечни, построенные во время выполнения (places, PLACES, категории из config), делятся на фиксированное число долей перечень[i::K] по детерминированному порядку (сортировка по метке); перемешивание — внутри доли; сценарием в PLAN: объединение долей равно полному перечню, доли не пересекаются. Каждый новый метод несёт докстринг с «Сценарий» и «Ловит мутацию:» своего подслучая; для долей — исходный текст целиком. Перечень подслучаев, который тест строит во время выполнения (категории путей-признаков из `config` у `test_ac9`, перечень `places` у `PultUnchangedTest`, `PLACES` у мест `pytest_own_places`), остаётся единственным источником: разбиение не заменяет его вписанной копией, и новый элемент перечня по-прежнему попадает под проверку без правки теста. Самый длинный тест каждого файла при отдельном прогоне файла — не более 10 с; замеры «до» и «после» в одном PLAN на одной машине. (Без нагрузки все тесты четырёх файлов уже короче 30 с: PultUnchangedTest 26,1 с, SignalDepthTest::test_ac9 24,5 с, pytest_own_places ac6 24,5 с, ac3 19,3 с, outcome_gate Ac7 19,3/18,9 с, Ac4 14,4/12,9 с.)
2. **Вспомогательный метод `tests_dir`.** Переименовывается (имя не начинается с `test`) во всех местах вызова; число тестов набора уменьшается ровно на число классов, где он собирался.
3. **Классы подготовки** `OutcomeGateSandbox` и все прочие имена (классы, функции, константы), которые импортируют другие файлы `tests/` (перечни — в «Факты»), не меняются (ни имена, ни поведение, ни значения); `tests/sandbox.py`, `conftest.py`, `pyproject.toml` не меняются.
4. **Доказательство неослабления** в PLAN.md:
   - таблица «старый тест → новые тесты» для каждого разбитого метода;
   - сверка деревьев функцией guard.test_assertions по обеим сторонам, мультимножествами: старый метод ⊆ объединение по его новым методам;
   - мутации из строк «Ловит мутацию» разбиваемых тестов — по одной на разбиваемый метод: каждая применяется к коду пульта в worktree задачи — до правки красный хотя бы один старый тест, после правки краснеет новый метод того же подслучая; в конце `git status --porcelain orchestrator/` пуст; итог в таблице;
   - число тестов до и после с пересчётом (минус `tests_dir`, плюс методы разбиения);
   - время самого длинного теста каждого файла до и после (`--durations`).
5. Новые тесты задачи не нужны сверх тех, что получаются разбиением; приёмочные критерии SPEC — свойства из п. 1–4, проверяемые сценарием и прогоном.

Мандат на ослабление при заведении не выдаётся: разбиение с сохранением исходных имён находок гейта неослабления не даёт; находка гейта — эскалация с её текстом. (Мандат Оператора 21.10 на правку файлов остаётся в силе для четырёх файлов.)

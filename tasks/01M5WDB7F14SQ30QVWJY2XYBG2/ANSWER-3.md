# ANSWER-3: ответ Оператора

## Ответы

Решение сессии при Операторе (права волны G) по замечанию ревью R3-F1 (итерация 3), 26.10.2026.

**R3-F1 в этой задаче не исправляется — перенесено в шаг Б2; ревьювер ставит ему статус `accepted` со ссылкой на это решение.**

Основание: аргументы вызова `git` формирует только код пульта, роли их не задают. Псевдоним в самой команде, у которого назначение отправки спрятано в теле значения (`-c alias.p=push <клон> main`, `!`-форма с `git -C <клон> push`, `--config-env` с таким значением), — это класс «произвольная команда внутри значения». Перебором форм в `gitcmd` его не закрыть. Закрывается он в Б2 по-другому: в конфигурацию клона внешнего проекта постоянно прописывается `core.hooksPath` на каталог хуков пульта, а хук `pre-push` проверяет те же правила при любой отправке из этого клона, как бы её ни запустили. `doctor` сверяет контрольную сумму хука. До Б2 проектов с `merge_gate: target-human` нет (отказ А0), поэтому риск не живой.

Разработчику: больше ничего не менять. Достаточно отметить R3-F1 в PLAN.md как перенесённое в Б2.

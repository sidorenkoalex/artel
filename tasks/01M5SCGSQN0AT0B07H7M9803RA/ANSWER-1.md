## Решения гейта SPEC (аудит concerns, без возврата аналитику)

1. AC-12 («сведение, теряющее поле, — отказ сверки») проверяется без подмены внутренних функций: на записи со значением, которое `yamlmini` после записи читает иначе (тип или вид значения меняется при чтении), `targets-migrate` отказывает до записи файла с именем поля. Имена внутренних функций сведения тест не навязывает.
2. Правило кавычек уточняется: кавычки ставятся только у скаляров; элемент потокового списка пишется как есть; значение, которое `yamlmini` записать не может (например, с обоими видами кавычек), — отказ `targets-migrate` с именем поля до записи файла.
3. `policy.sandbox`: в записи sled пина поля нет — сравнение «поле в поле» на записи sled идёт без него; перенос `policy.sandbox` на верхний уровень без изменения значения проверяется отдельным сценарием на синтетической записи.
4. Требование 9: сумма локального слоя сверяется и в ветке, где `git status` после шага не ответил (`_main_copy_status()` вернул `None`) — расхождение суммы попадает в предупреждение и тогда.
5. Свойства требования 15 ТЗ переносятся поштучно в AC-1…AC-15 SPEC — форма принимается.
6. Потолок задачи — $60 (поднят командой `budget` при заведении).
7. В локальном слое допустим только корневой ключ `targets:`; иной корневой ключ — отказ чтения с его именем. Значение с `<cache>` не может выходить за каталог кэша: путь после подстановки, содержащий `..` вне `.artel/projects/<имя>/cache`, — отказ с именем поля.

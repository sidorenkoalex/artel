# ТЗ: вынос повторяющейся подготовки тестов в tests/sandbox.py (ревизия тестов 05.10, TR-23, TR-24, TR-25)

TR-3, TR-23, TR-24, TR-25, план п. 4); строка бэклога «Вынос

Факты (пин 73ce3329, сверка ревизии 05.10):
- `setUpClass`/`setUpModule` не используются: вся подготовка заново на
  каждый метод. Основания: `TmpRootTest` (`tests/sandbox.py` ~1302) —
  ~1 522 метода, `RealGitSandbox` — ~691.
- Замер ревизии (среднее из 20, нагрузка 7–10): `git init` заглушки клона в
  `TmpRootTest.setUp` — 34 мс; init + 2 × config + add + commit в
  `RealGitSandbox.setUp` — 119 мс; репозиторий + bare-origin + push — 195
  мс; копия готового репозитория `shutil.copytree` — 14 мс. Оценка
  выигрыша — ≈ 100 с работы процессов, ≈ 25 с по стене при `-n 4`.
- TR-23: запись артели с профилем тестов в `targets.yaml` песочниц
  переписывается дословными копиями в десятках файлов. TR-24: заведение
  bare-origin написано заново в 31 файле. Помощник `add_synced_origin`
  (`tests/sandbox.py` ~1682) уже есть; голый origin заводится `git init
  --bare` без `-b` — 06.10 это дало красный CI (в CI ветка по умолчанию
  `master`, строка копилки 06.10).

Требуется:
1. Шаблон репозитория (TR-25, TR-3): однокоммитный репозиторий
   `RealGitSandbox` и заглушка клона `TmpRootTest` заготавливаются один раз
   на процесс вне каталогов тестов и копируются в `setUp`; каждый тест
   получает собственную копию, путь к шаблону наружу не отдаётся. Общее
   состояние между тестами (`setUpClass` с записью) не вводится.
2. Голый origin песочницы (`add_synced_origin` и новый общий помощник
   TR-24) заводится с HEAD на `config.MAIN_BRANCH` независимо от
   `init.defaultBranch` машины; тесты песочницы проходят с
   `GIT_CONFIG_NOSYSTEM=1`.
3. Построитель записи `targets.yaml` песочницы (TR-23) и общий помощник
   bare-origin (TR-24) в `tests/sandbox.py`; файлы, переписывающие их
   дословно, переходят на помощники. Долгоживущие файлы задач
   (`tests/test_01m*_*.py`) не трогаются — их правит только Оператор
   (`amend-tests`); перечень таких файлов-кандидатов — в PLAN строками для
   Оператора.
4. Замер в PLAN: полный набор `tests/` до и после (`-n 4` и `-n 8`), время
   `setUp` основных оснований.
5. Утверждения тестов не меняются и не переносятся в помощники; помощник
   подготовки не содержит `assert*`. Если вынос требует перенести
   утверждение — эскалация с точным списком.
6. Тест в `tests/` с заявкой «Ловит мутацию»: две копии шаблона в двух
   тестах независимы (запись в одну не видна в другой); голый origin
   песочницы смотрит на `config.MAIN_BRANCH` при `GIT_CONFIG_NOSYSTEM=1`.
   Существующие тесты не ослабляются.

# SPEC: Карточки знаний — формат, хранение, проверка формы, doc-commit (К-4а)

## Контекст
Решение Оператора 12.10.2026: план обогащения ролей знаниями, задача 4,
часть А. Знание, которого нет в коде (правило, причина, чем гейт его ловит,
инциденты), хранится карточками: системные — `knowledge/system.yaml`
репозитория пульта (защищённый путь), проектные — файл из нового поля
`knowledge` записи проекта в `targets.yaml`. Эта часть вводит формат,
проверку формы и пределы, чтение двух видов, чистую сверку места и путь
наполнения через `doc-commit` Оператора. Новый код не вызывается ни одной
командой роли, гейтом или брифом — поведение шагов не меняется; команда
`knowledge`, журнал обращений и подсказка в миссии — часть Б (К-4б).
Сегодня похожего механизма нет: каталог `.artel/projects/<проект>/knowledge/`
заводит `target-init` (`config.PROJECT_DIRS`), читателей у него нет; поле
`project_skills` `targets.yaml` проверяется `targets.check`, но кодом не
читается. Опора: ADR-0003 пп. 3а, 3е, 3з, 14;
`docs/research/2026-09-22-chatgpt-agent-integration.md`, «Итог обсуждения
(27.09.2026)», §§ 2–4.

## Требования

1. **Модуль и форма карточки.** Новый модуль `orchestrator/knowledge_cards.py`
   разбирает файл карточек `yamlmini.mapping` и проверяет его форму.
   Верхний уровень — ровно один ключ `cards`; его значение — отображение
   «ключ карточки → карточка». Пустой раздел `cards:` — ноль карточек, не
   отказ. Ключ карточки (её тема) — форма `[a-z0-9][a-z0-9-]{0,47}`. Поля
   карточки:
   - `where` — обязательный непустой список строк; элемент — маска пути в
     форме `project_profile.mask_matches` (`*` — внутри сегмента, `**` —
     любое число сегментов) либо `<путь>::<символ>` (путь без `*`, символ —
     имена через точку, каждое `[A-Za-z_][A-Za-z0-9_]*`);
   - `rule`, `why` — обязательные строки, непустые после `strip()`;
   - `check` (чем гейт это ловит; пусто — «гейтом не ловится»), `example` —
     необязательные строки;
   - `incidents` — необязательный список строк.
   Docstring модуля несёт образец формы (каркас для Оператора) с пометкой:
   идентификаторы инцидентов — только с буквой (число в потоковом списке
   читается числом, а кавычки в нём не разбираются).
2. **Отказы формы.** Отказ называет файл, ключ, поле и (где есть) номер
   строки. Отказ даёт каждый из случаев: файл не разобран `yamlmini`; нет
   раздела `cards` или его значение не отображение (в том числе строка
   `'{}'` от `cards: {}`); значение карточки не отображение (`a: 5`,
   `a: ~`); ключ не по форме; неизвестное поле; нет `where`/`rule`/`why`;
   `rule` или `why` пусты; значение не строка — число или логическое
   значение в любом текстовом поле и в любом элементе списка (`rule: true`,
   `where: [22]`, число в `incidents`); `where` не список (`where: x.py`);
   `where` — пустой список; элемент `where` пуст, абсолютный, с `..`, с
   ведущими точкой и косой чертой (префикс `./<путь>`), с `*` в пути формы
   `путь::символ`, символ не по форме; двойная кавычка внутри значения.
   «Ведущие точка и косая черта» ТЗ — именно префикс `./<путь>`: ведущая точка
   без косой черты (`.github/workflows/*.yml`) — допустимая маска, ведущую
   косую черту закрывает «абсолютный».
   Пустое значение необязательного поля (`check:` или `example:` без
   значения, которое `yamlmini` отдаёт как `None`, и `""`) — пусто, не
   отказ: у `check` это «гейтом не ловится» (ТЗ). `incidents:` без значения
   — как отсутствие поля; `incidents`, не являющийся списком, — отказ (форма
   ТЗ «список строк»). Пустое значение `rule:`/`why:` — «пусты», отказ.
3. **Неизвестный раздел и повторы.** Любой ключ верхнего уровня, кроме
   `cards`, и повтор строки `cards:` — отказ «неизвестный раздел» (код
   причины «поле не по форме», подробность «неизвестный раздел», см.
   требование 7). Повтор
   ключа карточки и повтор поля внутри карточки — отказ «повтор»; повторы
   ищутся построчным проходом по тексту (так как `yamlmini` молча оставляет
   последнее значение): проход начинается после строки `cards:`, пропускает
   пустые строки и строки-комментарии, считает ключом карточки строку с
   отступом ровно 2, полем — ровно 4. Ключ строки прохода — текст до первого
   `:` с обрезкой пробелов по краям (так его отдаёт `yamlmini`): строки
   `  a :` и `  a:` — один ключ `a`, их пара — повтор (так же `    rule :` и
   `    rule:` у поля). Строка прохода (не пустая, не
   комментарий) с отступом, отличным от 0, 2 и 4 (в том числе 3 или 5,
   которые `yamlmini` принимает), — отказ «поле не по форме» с подробностью
   «отступ» и номером строки: иначе повтор на таком отступе проход не
   видит и `yamlmini` его молча затирает — ровно то, от чего ТЗ вводит
   проход. Отступ 0 после `cards:` — ключ верхнего уровня, отказ
   «неизвестный раздел».
4. **Пределы.** Суммарная длина текстовых полей карточки (`rule`, `why`,
   `check`, `example`, элементы `incidents`) — не больше
   `config.KNOWLEDGE_CARD_MAX_CHARS`; карточек в файле — не больше
   `config.KNOWLEDGE_CARD_MAX_PER_FILE`. Значения читаются из `config`, не
   литералами модуля. Превышение — отказ формы с ключом и фактической
   величиной.
5. **Константы `config`.** Одним блоком с комментарием, что это лимиты
   класса ADR-0002 (меняет Оператор): `KNOWLEDGE_CARD_MAX_CHARS = 1200`,
   `KNOWLEDGE_CARD_MAX_PER_FILE = 80`, `KNOWLEDGE_CARD_QUERY_MAX_CHARS = 200`,
   `KNOWLEDGE_CARD_SYSTEM_REL = "knowledge/system.yaml"`, и константы для
   части Б: `KNOWLEDGE_CARD_OUTPUT_MAX = 12`,
   `KNOWLEDGE_CARD_HINT_MAX_KEYS = 40`,
   `KNOWLEDGE_CARD_JOURNAL_MAX_PER_TASK = 200`,
   `KNOWLEDGE_CARD_STALE_FILE_MAX_BYTES = 2 МиБ` (2 * 1024 * 1024).
6. **Поле `knowledge` в `targets.yaml`.** Новое необязательное поле записи
   проекта. `targets.check` отказывает полю, если оно: не строка; путь с
   `..`, с ведущими точкой и косой чертой (префикс `./<путь>`, как в требовании
   2), с `//` или обратной косой чертой, без суффикса `.yaml`; путь с
   ведущей косой чертой исключён точными формами ниже. У проекта `config.DEFAULT_TARGET` поле —
   ровно `knowledge/<имя>.yaml` (один уровень), кроме
   `knowledge/system.yaml`; у любого другого проекта — ровно
   `.artel/projects/<имя этого проекта>/knowledge/<имя>.yaml` (один
   уровень: не `derived/`, не каталог другого проекта, не клон `repo/`,
   не `knowledge/` пульта). Поле читается кодом: проектные карточки берутся
   из названного им файла. Нет поля — проектных карточек нет.
7. **Два вида и выдача.** Системные карточки — файл
   `config.KNOWLEDGE_CARD_SYSTEM_REL`, выдаются задачам всех проектов;
   проектные — файл поля `knowledge` проекта задачи, выдаются только
   задачам этого проекта. Функция модуля отдаёт карточки проекта задачи по
   виду вместе с `sha256` прочитанного текста каждого файла
   (`brief.component_hash`; `brief` импортируется внутри функции, не на
   верхнем уровне модуля — иначе цикл импорта `notes → knowledge_cards →
   brief → store → models → notes`). Результат чтения вида — одно из трёх:
   карточки, «не заведён», отказ; отказ несёт код причины из
   фиксированного перечня модуля («git не ответил», «файл не прочитан»,
   «файл не разобран», «ключ не по форме», «поле не по форме», «повтор»,
   «предел размера», «предел числа карточек») и подробность отдельным
   полем. Перечень восьми кодов закрыт; отказы формы требований 1–4
   распределяются по нему так: `yamlmini` не разобрал файл — «файл не
   разобран»; ключ карточки не по форме — «ключ не по форме»; повтор ключа
   карточки или поля — «повтор»; превышения требования 4 — «предел
   размера» и «предел числа карточек»; все прочие отказы формы (нет раздела
   `cards` или он не отображение, неизвестный раздел, значение карточки не
   отображение, неизвестное поле, нет или пусто обязательное поле, значение
   не строка, `where`/`incidents` не список, пустой `where`, элемент
   `where` не по форме, двойная кавычка, отступ) — «поле не по форме», с
   подробностью, называющей случай. Нет файла `targets.yaml` или он не разобран
   (`targets.TargetsError`) — проектных карточек нет, как при отсутствии
   поля, исключение наружу не выходит.
8. **Чтение файлов в `knowledge/` репозитория пульта** — с головы ветки
   `config.MAIN_BRANCH` главной копии (`config.ROOT`), не с диска. Это и
   системный файл, и проектный файл проекта `config.DEFAULT_TARGET`
   (поле `knowledge` вида `knowledge/<имя>.yaml`, например
   `knowledge/artel.yaml`). Сначала
   `gitcmd.in_repo(config.ROOT, "ls-tree", "--name-only",
   config.MAIN_BRANCH, "--", <путь>)`: код 0 и пустой вывод — «не заведён»
   (не отказ); ненулевой код или `None` — отказ «git не ответил»; только
   при непустом выводе файл читается `gitcmd.show`. Нет `.git` в
   `config.ROOT` ни каталогом, ни файлом — «не заведён», не отказ (в
   рабочей копии worktree `.git` — файл, и репозиторий там есть: такой
   корень читается через `ls-tree`, как главная копия). Репозиторий есть, ветки
   `config.MAIN_BRANCH` нет — отказ «git не ответил».
9. **Чтение файлов `.artel/projects/<имя>/knowledge/`** — с диска от
   `repo_context.projects_root()`; при `NO_AREA` (песочница с подменённым
   корнем) карточек нет — исход «не заведён», не отказ, — боевая область
   не читается. Нет файла — «не
   заведён». Ссылка, специальный файл, путь, вышедший по `resolve()` из
   каталога знаний проекта, нечитаемый файл или не UTF-8 — отказ чтения
   вида.
10. **Сверка места** — чистая функция модуля без чтения файлов: по запросу
    формы `<путь>`, `<путь>::<символ>` или `::<символ>` и набору карточек
    отдаёт совпавшие. Маска `where` подходит под путь запроса
    (`mask_matches`); элемент `p::s` подходит под запрос `<путь>`, если `p`
    равен пути; под `<путь>::<символ>` — если `p` равен пути и `s` равен
    символу запроса или его префиксу по точкам (`Class` подходит под
    `Class.method`); под `::<символ>` — по тому же правилу символа в любом
    файле. Порядок результата: системные, затем проектные, внутри вида — по
    ключу. Форма запроса проверяется: не длиннее
    `config.KNOWLEDGE_CARD_QUERY_MAX_CHARS`, без управляющих символов, путь
    относительный, без `..`, без ведущих точки и косой черты (префикс
    `./<путь>`, как в требовании 2; запрос `.github/…` по форме допустим), не
    более одного `::`; нарушение — отказ с текстом формы запроса.
11. **Защищённый путь.** В `config.PROTECTED_PATHS` добавляется запись
    `knowledge/` — в конец литерала кортежа (длина 18 → 19); первые 12
    записей и их порядок не меняются, ни одна прежняя запись не снимается
    и не переставляется. Запись стоит в самом литерале присваивания
    `PROTECTED_PATHS = (...)`, который разбирает джоб CI `protected-paths`
    (`scripts/ci_protected_paths.protected_paths_from_source`), а не
    добавляется отдельной операцией после него.
12. **`doc-commit` для карточек.** `doc-commit` принимает путь ровно
    `knowledge/<имя>.yaml` (один уровень, суффикс `.yaml`); путь не входит
    в `notes.DOC_COMMIT_CONFIG_PATHS` (гейт полного набора `tests/` не
    заводится); `_doc_commit_prefix` даёт ему префикс `knowledge`; форма
    проверяется кодом требований 1–4 до окна тишины и до удержания записи
    на любой ветке пути записи, в том числе при отказе `fetch`; отказ
    формы — без коммита и без удержанной записи, с кодом причины и
    подробностью. ТЗ называет местом проверки `_build_doc_commit`, но на
    ветке отказа `fetch` он не вызывается, а запись удерживается
    (`orchestrator/notes.py:1289–1291`, `:1304`); поэтому проверка формы
    стоит в общей точке `_doc_commit_request` (`notes.py` ~1494) до `_run`
    — её проходят обе точки входа записи, `cmd_doc_commit` и публичная
    `doc_commit_content` (`notes.py:1509`), и ни одна не проводит
    `knowledge/<имя>.yaml` без проверки формы. Новый файл в новом каталоге
    `knowledge/` коммитится (база «файла не было» допустима). Вызов из
    окружения роли отказывает, как прежде (`DOC_COMMIT_ROLE_REFUSAL`);
    прочие пути `doc-commit` ведут себя как прежде.
13. **Не вызывается шагами.** Ни одна команда роли, гейт или бриф новый
    код не вызывают; из модулей пакета оркестратора модуль

17. **Публичный интерфейс `orchestrator/knowledge_cards.py`** (решение
    Оператора на гейте SPEC 13.10.2026, аудит О-1) — через него пишутся
    тесты требований 1–10; внутреннее устройство сверх него — за
    разработчиком.
    - Константы вида: `SYSTEM = "system"`, `PROJECT = "project"`.
    - Константы кодов причины — строки перечня требования 7:
      `GIT_NO_ANSWER = "git не ответил"`, `FILE_UNREADABLE = "файл не
      прочитан"`, `FILE_UNPARSED = "файл не разобран"`, `KEY_FORM = "ключ
      не по форме"`, `FIELD_FORM = "поле не по форме"`, `DUPLICATE =
      "повтор"`, `SIZE_LIMIT = "предел размера"`, `COUNT_LIMIT = "предел
      числа карточек"`; `REFUSAL_CODES` — кортеж ровно этих восьми.
    - Константы исхода чтения вида: `CARDS = "cards"`, `NOT_SET_UP =
      "not_set_up"` («не заведён»), `REFUSED = "refused"`.
    - `SAMPLE: str` — текст образца формы; docstring модуля несёт его
      дословно (требование 1).
    - `Card` — неизменяемая запись (frozen dataclass) с полями `kind`
      (`SYSTEM`/`PROJECT`), `key: str`, `where: tuple[str, ...]`,
      `rule: str`, `why: str`, `check: str`, `example: str`,
      `incidents: tuple[str, ...]`; отсутствующее или пустое необязательное
      поле — `""` или `()`. Вид карточки для порядка сверки места несёт
      поле `kind`.
    - `Refusal` — неизменяемая запись отказа формы или чтения с полями
      `code: str` (из `REFUSAL_CODES`), `detail: str`, `file: str`,
      `key: str | None`, `field: str | None`, `line: int | None` (`None` —
      где у отказа нет ключа, поля или номера строки).
    - `KindRead` — неизменяемая запись исхода чтения вида с полями `kind`,
      `outcome` (`CARDS`/`NOT_SET_UP`/`REFUSED`), `cards: tuple[Card, ...]`
      (непусто только при `CARDS`; пустой раздел `cards:` — `CARDS` с `()`),
      `file: str | None` (путь файла вида; `None`, если файл не назван),
      `sha256: str | None` (`brief.component_hash` прочитанного текста при
      `CARDS`, иначе `None`), `refusal: Refusal | None` (только при
      `REFUSED`).
    - `check_text(text: str, file: str, kind: str) -> tuple[Card, ...] |
      Refusal` — проверка текста формы (требования 1–4), чистая, без чтения
      файлов; `file` идёт в отказ.
    - `read_cards(project: str) -> tuple[KindRead, KindRead]` — чтение
      карточек по имени проекта (запись `targets.yaml`, не id задачи):
      системный вид первым, проектный вторым (требования 6–9).
    - `match(query: str, cards: Iterable[Card]) -> tuple[Card, ...] |
      QueryRefusal` — сверка места (требование 10); `QueryRefusal` —
      неизменяемая запись с полем `detail: str`, называющим нарушенную форму
      запроса.

## Критерии приёмки

AC-1. Файл с образцом карточки из ТЗ (`merge-lock-order` с полями `where`,
`rule`, `why`, `check`, `example`, `incidents`) разбирается модулем
`orchestrator/knowledge_cards.py` без отказа; файл с пустым разделом
`cards:` даёт ноль карточек без отказа; ключ длиной 48 символов по форме
`[a-z0-9][a-z0-9-]{0,47}` принят, длиной 49 — отвергнут; образец
`SAMPLE` проходит `check_text` без отказа, docstring модуля содержит его
дословно и несёт пометку, что
идентификаторы инцидентов — только с буквой.

AC-2. Каждый случай требования 2 даёт отказ формы (`Refusal` требования
17), называющий файл, а ключ, поле и номер строки — где они есть (у
отказов уровня файла — неразобранный файл, нет `cards`, `cards: {}` —
ключа и поля нет): неразобранный файл; нет `cards`;
`cards: {}`; `a: 5`; `a: ~`; ключ не по форме; неизвестное поле; нет
`rule`; нет `where`; нет `why`; `rule: ""`; `rule:` без значения; `why` из
одних пробелов; `rule: true`; `where: x.py`; `where: []`; `where: [22]`;
`incidents: x` (не список); число в `incidents`; элемент `where` пустой,
абсолютный (`/a.py`), с `..`, с префиксом `./<путь>`; `*` в пути элемента
`путь::символ`; символ не по форме; двойная кавычка внутри значения. Код
причины каждого из этих отказов — по распределению требования 7
(неразобранный файл — «файл не разобран», ключ не по форме — «ключ не по
форме», прочие — «поле не по форме»). Без отказа принимаются: элемент
`where` с ведущей точкой без косой черты (`.github/workflows/*.yml`);
`check:` и `example:` без значения и `check: ""`; `incidents:` без
значения.

AC-3. Ключ верхнего уровня, отличный от `cards` (до и после раздела
`cards`), и повторная строка `cards:` дают отказ с кодом «поле не по
форме» и подробностью «неизвестный раздел»; повтор ключа карточки (отступ
2) и повтор поля (отступ 4) дают отказ с кодом «повтор», в том числе
при пробеле перед двоеточием в одной из строк (`  a :` и `  a:`,
`    rule :` и `    rule:`); файл с
карточками на отступе 3 и полями на отступе 5 (в том числе с повтором
ключа на этом отступе) — отказ с кодом «поле не по форме», подробностью
«отступ» и номером строки, а не молча принятый; пустая строка или
строка-комментарий (с любым отступом) между карточками и между полями
ложного повтора и отказа по отступу не дают.

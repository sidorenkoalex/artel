Образец файла карточек:

```yaml
cards:
  merge-lock-order:
    where: [orchestrator/merge_lock.py, orchestrator/fsm_merge_gate.py::merge_gate, orchestrator/advance_gates/*.py]
    rule: "Лок мержа берётся до чтения головы main: иначе гонка двух approve"
    why: инцидент двух одновременных мержей — второй перетёр первый
    check: "tests/test_invariants.py::MergeOnlyFromMergeGateTest"
    example: "with merge_lock.held(conn): head = gitcmd.rev_parse('origin/main')"
    incidents: [01M290PS4Z, T043]
```

Требуется:
1. Модуль `orchestrator/knowledge_cards.py`: разбор и проверка формы
   файла карточек. Ключ карточки — её тема, форма
   `[a-z0-9][a-z0-9-]{0,47}`. Поля: `where` — непустой список строк,
   элемент — маска пути (форма `mask_matches`) или `<путь>::<символ>`
   (путь без `*`, символ — имена через точку `[A-Za-z_][A-Za-z0-9_]*`);
   `rule`, `why` — обязательные непустые после `strip()` строки; `check`
   (чем гейт это ловит; пусто — «гейтом не ловится») и `example` —
   необязательные строки; `incidents` — необязательный список строк.
   Отказ с названием файла, ключа, поля и (где есть) номера строки:
   файл не разобран `yamlmini`; нет раздела `cards` или его значение не
   отображение (в том числе строка `{}`); значение карточки не
   отображение; ключ не по форме; неизвестное поле; нет `where`/`rule`/
   `why`; `rule` или `why` пусты; значение не строка (число или логическое
   значение в любом текстовом поле и в любом элементе списка — `rule:
   true` читается как логическое значение); `where` не список; элемент
   `where` пуст, абсолютный, с `..`, с ведущими точкой и косой чертой, с `*` в пути формы
   `путь::символ`, символ не по форме; двойная кавычка внутри значения;
   повтор ключа карточки или поля — повторы ищутся построчным проходом по
   тексту (ключ карточки — строка с отступом 2, поле — с отступом 4), так
   как `yamlmini` их молча затирает. Верхний уровень файла — один ключ `cards`; любой другой ключ
   верхнего уровня и повтор `cards:` — отказ «неизвестный раздел»
   (`yamlmini` их молча принимает или затирает). Построчный проход
   повторов начинается после строки `cards:`, пропускает пустые строки и
   строки-комментарии, считает ключом карточки строку с отступом ровно 2,
   полем — ровно 4. Пустой раздел `cards:` — ноль карточек, не отказ.
   Образец формы — в docstring модуля (он же каркас для Оператора), с
   пометкой: идентификаторы инцидентов — только с буквой (число в
   потоковом списке читается числом, а кавычки в нём не разбираются).
2. Пределы проверяются кодом, значения — константы `config`, не литералы
   модуля: суммарная длина текстовых полей карточки (`rule`, `why`,
   `check`, `example`, элементы `incidents`) не больше
   `config.KNOWLEDGE_CARD_MAX_CHARS` (предложение — 1200); карточек в файле
   не больше `config.KNOWLEDGE_CARD_MAX_PER_FILE` (предложение — 80).
   Превышение — отказ формы с ключом и фактической величиной.
3. Два вида карточек:
   - системные — файл `config.KNOWLEDGE_CARD_SYSTEM_REL` =
     `knowledge/system.yaml` репозитория пульта, выдаются задачам всех
     проектов;
   - проектные — файл, названный новым необязательным полем `knowledge`
     записи проекта в `targets.yaml`, выдаются только задачам этого
     проекта. `targets.check` проверяет поле: строка; путь от корня пульта
     без `..`, без ведущих точки и косой черты, без `//` и обратной косой черты, суффикс
     `.yaml`; у проекта `config.DEFAULT_TARGET` — ровно
     `knowledge/<имя>.yaml` (один уровень), кроме `knowledge/system.yaml`;
     у любого другого проекта — ровно
     `.artel/projects/<имя этого проекта>/knowledge/<имя>.yaml` (один
     уровень: не `derived/`, не каталог другого проекта, не клон
     `repo/` — репозиторий целевого недоверенный). Нет поля — проектных
     карточек нет.
   Функция модуля отдаёт карточки проекта задачи по виду, вместе с
   `sha256` прочитанного текста каждого файла (`brief.component_hash`) —
   для записи журнала части Б (ADR-0003 п. 3е: «по какой версии знал
   агент»).
4. Чтение. Файлы внутри `knowledge/` репозитория — с головы ветки `main`
   главной копии пульта. Отсутствие файла отличается от отказа git:
   сначала `gitcmd.in_repo(config.ROOT, "ls-tree", "--name-only",
   config.MAIN_BRANCH, "--", <путь>)` — код 0 и пустой вывод означают
   «файл карточек не заведён» (ноль карточек, НЕ отказ), ненулевой код
   или `None` — «git не ответил» (отказ чтения вида), и только при
   непустом выводе файл читается `gitcmd.show`. Если каталога
   `.git` в корне пульта `config.ROOT` нет (лёгкая песочница тестов — в
   боевом пульте он есть всегда), системных карточек нет: результат «файл
   карточек не заведён», не отказ (иначе `ls-tree` вернёт код 128 «не
   git-репозиторий», и каждый шаг тестов получит отказ чтения и запись
   журнала). Репозиторий есть, но ветки `config.MAIN_BRANCH` в нём нет —
   «git не ответил» (отказ чтения вида). Файла `targets.yaml` нет или он
   не разобран (`targets.TargetsError`) — проектных карточек нет, как при
   отсутствии поля `knowledge`: чтение карточек не падает, пульт обязан
   работать и при сломанном файле (так же `repo_context.resolve` не
   читает `targets.yaml` для артели). Файлы
   `.artel/projects/<имя>/knowledge/` — с диска от
   `repo_context.projects_root()` (в песочнице с подменённым корнем —
   `NO_AREA`, карточек нет, боевая область не читается): нет файла — «не
   заведён»; ссылка, специальный файл, путь, вышедший по `resolve()` из
   каталога знаний проекта, нечитаемый или не UTF-8 — отказ чтения вида.
   Результат чтения вида — одно из трёх: карточки, «не заведён», отказ
   (код причины из фиксированного перечня модуля: «git не ответил»,
   «файл не прочитан», «файл не разобран», «ключ не по форме», «поле не
   по форме», «повтор», «предел размера», «предел числа карточек» — и
   подробность отдельным полем).
5. Сверка места (чистая функция модуля, без чтения файлов): по запросу
   формы `<путь>`, `<путь>::<символ>` или `::<символ>` и набору карточек
   отдаёт совпавшие. Маска `where` подходит под путь запроса
   (`mask_matches`); элемент `p::s` подходит под запрос `<путь>`, если
   `p` равен пути; под `<путь>::<символ>` — если `p` равен пути и `s`
   равен символу запроса или его префиксу по точкам (`Class` подходит под
   `Class.method`); под `::<символ>` — по тому же правилу символа в любом
   файле. Порядок результата: системные, затем проектные, внутри вида —
   по ключу. Форма запроса проверяется: не длиннее
   `config.KNOWLEDGE_CARD_QUERY_MAX_CHARS` (предложение — 200), без
   управляющих символов, путь относительный, без `..`, без ведущих точки и косой черты,
   не более одного `::`; нарушение — отказ с текстом формы запроса.
6. Константы `config` для части Б заводятся здесь же, одним блоком с
   пределами этой части: `KNOWLEDGE_CARD_OUTPUT_MAX` (карточек в одном
   ответе, предложение — 12), `KNOWLEDGE_CARD_HINT_MAX_KEYS` (тем в
   подсказке, 40), `KNOWLEDGE_CARD_JOURNAL_MAX_PER_TASK` (записей журнала
   обращений на задачу, 200), `KNOWLEDGE_CARD_STALE_FILE_MAX_BYTES` (файл
   для проверки свежести, 2 МиБ). Блок — с комментарием, что это лимиты
   класса ADR-0002 (меняет Оператор).
7. В `config.PROTECTED_PATHS` добавляется запись `knowledge/` — в конец
   литерала кортежа; первые 12 записей и их порядок не меняются.
8. `doc-commit` принимает путь ровно `knowledge/<имя>.yaml` (один
   уровень, суффикс `.yaml`): путь НЕ входит в
   `notes.DOC_COMMIT_CONFIG_PATHS` (иначе `_config_path_request` заведёт

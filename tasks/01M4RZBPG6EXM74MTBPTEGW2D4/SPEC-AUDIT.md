## Пути обхода гейтов

- **П1 (через AC-7, см. В1).** Разработчик может прочитать «не
  отбрасывается … и тогда, когда голова ушла вперёд» (SPEC.md:252–256)
  как требование закоммитить версию с диска. Тогда он проведёт записки
  мимо `_apply_artifact_conflict_guard`
  (orchestrator/checkpoint.py:930–973), и стухшая выкладка затрёт правку
  Оператора в голове ссылки. Буква AC-7 выполнена, защитное свойство
  конфликт-гварда ослаблено, а в матрице такой строки нет. То же самое
  навязывает тест, который проверяет «в ссылке — версия с диска».
- **П2 (назван в ТЗ, не отклонение).** spec_auditor или reviewer читает
  чужие `NOTE-*.md` с диска каталога документов. Держит только AC-14;
  механическое закрытие вынесено в «Не входит» решением Оператора.
- **П3 (следует из ТЗ п. 8, не отклонение).** Analyst пишет в
  `NOTE-analyst.md` ожидаемое поведение сверх AC, и test_author эту
  записку получает. Держат только AC-13 и строка блока «при расхождении
  верны SPEC…».
- **П4 (ложная пометка, решение ТЗ п. 9).** Записку с CRLF требование 5
  хэширует по байтам, а бриф читает через `gitcmd.show` с нормализацией
  (orchestrator/gitcmd.py:44). Такая записка каждый раз помечается
  «изменена вне шага» с записью журнала.
- Других путей не нашёл:
  - запись «записка шага сохранена» пишет пульт, и только после коммита;
  - чужую записку отбрасывает автокоммит;
  - записка, попавшая в ссылку мимо автокоммита (без записи о сохранении
    или с другим sha256), в бриф не идёт (требования 8–9);
  - поддельный маркер не пройдёт: id запуска — `secrets.token_hex(16)`;
  - мандатов из `NOTE-*.md` никто не читает.

## Вердикт

**concerns.** SPEC отражает ТЗ и оба набора решений Оператора, факты о
коде подтвердились, зон хватает, защищённых путей нет. Остаются три
отклонения в формулировках. Оператор может снять их на гейте одной
строкой, возврат аналитику не нужен.

1. **В1 — AC-7 расходится с конфликт-гвардом**
   (SPEC.md:252–256; orchestrator/checkpoint.py:949–972, 1302–1304).
   - Сценарий второй фразы AC-7 («голова ушла вперёд правкой именно этой
     чужой записки»): по действующему коду неизменённая выкладка такой
     записки исключается из коммита конфликт-гвардом с алертом
     `incident`. Буквально она «отбрасывается», хоть и не как чужая.
   - Если сдвиг головы сделан мимо фиксации, весь автокоммит пропускается
     с записью журнала `_docs_ref_drift` — тогда «не даёт записи журнала»
     не выполнится вовсе.
   - Тест, написанный по букве AC, может потребовать версию с диска в
     ссылке, и это ослабит конфликт-гвард (П1).

   Предложение строкой решения: «AC-7: такая записка не отбрасывается
   как чужая — записи "чужая записка отброшена" нет; конфликт-гвард
   `_apply_artifact_conflict_guard` работает для неё как прежде (версия
   головы остаётся); в тесте голова сдвинута записью пульта с
   перефиксацией».
2. **В2 — проверка guard по одному файлу.** Освобождение по требованию 2
   (SPEC.md:40–45) задано только для `guard --all` и гейта мержа.
   Паспорт пропускается и в проверке одного файла
   (scripts/guard.py:4442–4444), а записка — нет: `scripts/guard.py
   tasks/<id>/NOTE-<роль>.md` ответит «нет frontmatter» (:4445). При этом
   миссия developer велит «прогони scripts/guard.py на своих
   артефактах» (orchestrator/role_prompt.py:109). Роль может потратить
   шаг на frontmatter для записки. Буквой ТЗ это не требуется (ТЗ п. 2
   называет два места), поэтому решать Оператору. Варианты:
   - (а) так и оставить;
   - (б) `is_step_note` пропускает записку и в проверке одного файла,
     как паспорт;
   - (в) абзац миссии о записке говорит «guard на записку не запускай».
3. **В3 — второй пункт AC-17 почти ничего не ловит** (SPEC.md:323–324).
   Поддельный маркер «с другим id» не содержит id этого запуска, поэтому
   «ровно дважды» выполнится при любой обёртке. Пункт ловит только
   записку без границы или с двойной обёрткой, а это уже ловит первый

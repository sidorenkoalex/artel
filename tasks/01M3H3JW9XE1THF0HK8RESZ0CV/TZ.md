# ТЗ: Один разбор строки зон с учётом переноса строки внутри пути

Источник: строка бэклога 27.09 «Корень разрыва путей ТЗ переносом»
(docs/backlog.md), из ревью задачи 01M3GKJ84XM5QPC6TK5EE307Q9
(замечание R2-F1 и «Предложения системе» PLAN и REVIEW). Задача вне
линии провайдеров.

Факты (origin/main a6da0abe):
- `scripts/guard.py::zone_items` разбирает строку зон («Зоны: …» ТЗ либо
  frontmatter `zones:` SPEC): делит по запятым, снимает завершающую
  точку, добавляет кандидаты `_path_mention_candidates` из той же
  строки. Переносы строк внутри пути не снимает: путь, разорванный
  вёрсткой ТЗ после `/`, `_` или `-`, даёт обрывок-каталог и теряет
  настоящий путь.
- `orchestrator/budget.py::count_zone_paths` считает пути той же строки
  своим разбором (деление по запятым, завершающая точка) — число зон
  для калибровки бюджета; разорванный путь считается по вёрстке.
- Задача 01M3GKJ8 починила только свой узел:
  `orchestrator/catalog.py::_tz_zone_items` снимает разрыв регулярным
  выражением `_TZ_WRAPPED_PATH_BREAK` (перенос после `/`, `_`, `-` с
  отступом следующей строки) ДО вызова `guard.zone_items`. Снимать все
  переносы нельзя — обоснование в комментарии над выражением
  (orchestrator/catalog.py:271–279). Сверка путей ТЗ
  (`catalog._tz_path_check`, orchestrator/catalog.py:188) и калибровка
  `new` (orchestrator/catalog.py:223) зовут `guard.zone_items` и
  `budget.count_zone_paths` без склейки.
- Прецедент: 2 из 4 ТЗ волны 27.09 несли перенос внутри перечня зон;
  три отказа гейта классификации путей 26.09 из-за разорванных путей
  чинились правкой ТЗ руками.

Требуется:
1. Склейка разорванного переносом пути — в самом разборе строки зон
   `scripts/guard.py::zone_items` (то же правило, что
   `_TZ_WRAPPED_PATH_BREAK`: перенос после `/`, `_`, `-` с отступом),
   чтобы каждый потребитель разбора получал её без собственной копии.
2. `orchestrator/budget.py::count_zone_paths` считает пути тем же
   разбором (через общую функцию либо ту же склейку), число зон для ТЗ с
   переносом внутри пути равно числу зон того же ТЗ без переноса.
   Кандидаты упоминаний путей в счёт не входят, если не входили до
   задачи — поведение на строках без переноса не меняется.
3. `orchestrator/catalog.py` этой задачей не правится: его
   предварительная склейка остаётся и на уже склеенной строке ничего не
   меняет; свойство проверяется тестом (повторная склейка не меняет
   результат).
4. Тесты (tests/): строка зон с переносом внутри пути даёт тот же набор
   элементов и то же число зон, что без переноса; перенос после слова
   прозы путь не склеивает и не теряет; строка без переносов — прежний
   результат; существующие tests/test_guard_zones.py,
   tests/test_guard_path_mentions.py, tests/test_catalog_tz_path_check.py,
   tests/test_catalog_zone_overlap.py, tests/test_spec_budget.py,
   tests/test_budget_calibration_table.py зелёные, ни один не ослаблен.

Зоны: scripts/guard.py, orchestrator/budget.py, tests/.

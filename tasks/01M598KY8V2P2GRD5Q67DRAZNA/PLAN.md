# PLAN: Механическая проверка ТЗ в `new`: вызывающие вне зон и ссылки `файл:строка`

## Подход
Новый модуль `orchestrator/tz_check.py` — чистая проверка содержания ТЗ по
дереву проекта; `catalog.cmd_new` зовёт её одной точкой после
`workspace.ensure_clone` и до `idgen.new_task_id` (требование 1), только при
ТЗ и `canary=False`; `spawn_subtask` её не зовёт вовсе.

- Дерево (требование 2): артель — `git -C config.ROOT rev-parse HEAD^{commit}`
  (корень обязан сам нести `.git`, иначе git поднялся бы в чужой
  репозиторий-предок); внешний проект — `origin/<base>` клона
  `workspace.repo(target)`, `<base>` из `repo_context.resolve`. `fetch` нет.
  Любой сбой git (`rev-parse`, `ls-tree`, `show`, `grep`) — `_TreeError` →
  одно предупреждение «дерево недоступно — проверка ТЗ не выполнена: <причина>».
  Дерево не открывается, если в ТЗ нет ни одного совпадения грамматики ссылки
  и ни одного `модуль.имя` в кавычках до первой метки (требование 2.4) —
  тогда `check` отдаёт `None` и вывод `new` прежний.
- Ссылки (требование 4): `REF_RE` — путь `[A-Za-z0-9_./-]`, последняя часть
  с расширением, `:N` или `:a-b`, левая граница — не середина пути (URL и
  `host/api:8080` не ссылки). Форма без каталога ищется по имени файла в
  `ls-tree`: 0 — не ссылка, 1 — полная ссылка, >1 — предупреждение
  «имя файла неоднозначно — не проверено». Длина — число `\n` содержимого
  `git show <sha>:<путь>` (байтами, файл любого вида); отказы собираются все
  разом. «Имя рядом» — первый `` `имя` ``/`` `модуль.имя` `` после конца
  ссылки и до начала следующей ссылки строки, пути (требование 4.4) пропускаются;
  окно `[a-3, b+3]`, сверка целым словом; файл с байтом NUL не сверяется.
- Вызывающие (требование 5): текст кандидатов — до первой строки
  `^(Зоны|Не входит|Только чтение[^:\n]*|Приложением):` (собирается в
  `catalog._TZ_CANDIDATE_BOUNDARY` из тех же `_TZ_ZONES_LABEL`/
  `_TZ_DECLARING_LABELS`); кандидаты — последние части `` `a.b` ``-имён (кроме
  путей) и определения по ссылкам `файл.py:N` (def/class на строке `N`,
  иначе объемлющее по отступу; диапазон — все начатые в `a..b` плюс объемлющее
  `a`; строка уровня модуля — ничего; пустая строка берёт отступ следующей
  непустой). Поиск — `git grep -n -w -F <имя> <sha> -- '*.py'`, затем фильтр:
  не `tests/`, вызов `имя(` или обращение `.имя`, не строка `def/class имя`.
  Покрытие — `guard._classified` (тот же, что у прежней сверки путей ТЗ:
  зоны с вложенностью, `config.COMMON_ZONES`, объявляющие разделы). Имя
  короче 4 знаков или из списка общих — пометка «общее имя — не проверено»
  без поиска, вне счёта M и вне `--strict-tz`.
- Вывод (требование 3): `проверка ТЗ: N отказов, M предупреждений, дерево
  <sha коммита>` и строки находок; без находок — ничего. Отказ (или
  предупреждение под `--strict-tz`) — `sys.exit` текстом находок до id, строки
  БД и ссылки документов. Иначе текст печатается и после `_new_task_row`
  пишется в журнал задачи действием `проверка ТЗ`.
- Флаг (требование 6): `artel._new_strict_tz_arg` снимает `--strict-tz` из
  любого места argv до `_parse_new_args` (её возврат `(title, tz_path)` не
  меняется); `cmd_new(strict_tz=True)` передаётся только при флаге —
  прежние сверки вызова `cmd_new` (`tests/test_task_model_set_units.py`)
  не задеты. `_NEW_USAGE` дополнен `[--strict-tz]`.

Бюджет SPEC ($45) не переоценивается: 3 файла кода + тесты, как и оценил SPEC.

## Влияние на систему
- Затронут только путь `new` с ТЗ для не-канарейки. Прежние проверки
  (пути/зоны, «Порядок:», «Проект:») стоят раньше и не менялись: их отказ
  печатается дословно, новая проверка до него не доходит (AC-12 закрепляет).
  ТЗ без ссылок и имён в кавычках дерево не открывает — вывод прежний.
- Гейты, лимиты, guard, инварианты не ослаблены; `scripts/guard.py` и
  `orchestrator/repo_context.py`/`workspace.py` только читаются
  (`guard._classified`, `guard._path_mention_candidates` — переиспользование
  прежнего правила классификации путей, без правки).
- Новый отказ `new` возможен только по ссылке на несуществующий файл или
  строку за концом файла; остальное — предупреждения, не останавливающие
  `new` без `--strict-tz`.
- Откат — revert коммита задачи: модуль новый, правки `catalog.py`/`artel.py`
  аддитивны (keyword `strict_tz` с дефолтом `False`).

## Риски
- Ссылки, записанные не от корня репозитория (`advance_gates/x.py:12` вместо
  `orchestrator/advance_gates/x.py:12`), дают отказ «файла нет» — замер
  01M590GJ… показал 4 таких на одно ТЗ. Это поведение SPEC (требование 4,
  путь от корня); Оператору придётся писать полный путь.
- Ссылка ТЗ на файл другого проекта (sled `ci.yml` в ТЗ артели) сверяется с
  деревом проекта задачи — ложное «имя рядом» или отказ.
- Поиск по слову: `X.PATH`-подобные обращения к атрибутам дают ложные
  вызывающие (допустимо по «Не входит» SPEC — предупреждение).

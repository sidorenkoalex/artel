## Пути обхода гейтов

- Требование 2.3 позволяет любой сбой свести к предупреждению «дерево
  недоступно». Широкий `except` вокруг всей проверки без `--strict-tz`
  превратит дефект проверки в молчаливый пропуск. Это ловят AC-1/AC-2:
  отказ обязателен там, где дерево заведомо доступно. Отдельного
  отклонения нет.
- Отклонение 1 ниже — путь в обратную сторону. Буквальное исполнение
  засыпает Оператора ложными предупреждениями, а под `--strict-tz`
  делает флаг непригодным. Смысл проверки обесценивается.

## Вердикт

concerns — отклонения ниже решаются уточнением Оператора на гейте, без
нового круга аналитика.

1. **Форма «имени в обратных кавычках» не отделена от имени файла.**
   Требование 5.1 SPEC (кандидаты «вида `модуль.функция` или
   `Класс.метод`») и требование 4.3 (имя рядом со ссылкой) не исключают
   имена файлов в кавычках: `` `targets.yaml` ``, `` `QUESTIONS.md` ``,
   `` `catalog.py` ``. По форме это `модуль.имя`.
   - Сценарий: в ТЗ до «Зоны:» стоит `` `targets.yaml` `` (обычная
     ситуация; в ТЗ этой задачи до «Зоны:» есть `` `QUESTIONS.md` ``).
     Кандидатом становится `yaml`: 4 знака, не из списка общих имён.
     `git grep` по «обращению `.yaml`» находит строковые литералы
     `"targets.yaml"` в модулях вне зон (например,
     `orchestrator/config.py:17-41`; вне `COMMON_ZONES` — `targets.py`,
     `roles.py`, `models.py`). Получается предупреждение «в зонах нет
     вызывающих `targets.yaml`», а под `--strict-tz` — отказ `new`.
     `` `QUESTIONS.md` `` даёт пометку «общее имя — не проверено» с
     именем `md`.
   - Вдобавок AC-12/требование 7 («без имён в обратных кавычках»)
     сохраняют прежний вывод только для ТЗ, где нет даже путей в
     кавычках, то есть почти ни для одного живого ТЗ.
   - Вопрос Оператору: исключить ли из кандидатов и из «имени рядом»
     содержимое кавычек с `/` или с последней частью — расширением
     файла (или именем, существующим в дереве как файл)?

2. **Кандидат по ссылке-диапазону и по строке вне функции не
   определён.** Требование 5.1 (и AC-6) говорит: «определение в этой
   строке или ближайшее объемлющее `def`/`class` выше строки ссылки».
   - Для `файл.py:a-b` не сказано, какая это строка: `a`, или все
     определения в диапазоне. В ТЗ этой задачи `catalog.py:174-196`
     охватывает два `def`.
   - Для строки на уровне модуля (константы
     `orchestrator/catalog.py:167-171`, на которые ссылается ТЗ) не
     сказано, что значит «объемлющее»: объемлющего определения нет, а
     ближайший `def` выше по тексту — чужая функция.
   - Без разбора синтаксиса (`Не входит`) «объемлющее» реализуется
     либо по отступу, либо как «ближайшее выше». Тест-автор и
     разработчик выберут по-разному, AC-6 этого не различает.
   - Вопрос Оператору: (а) диапазон — все `def`/`class` в `a..b` плюс
     объемлющее для `a`, или только строка `a`? (б) строка уровня
     модуля — кандидата нет, или ближайшее определение выше?

3. **«sha проверенного дерева» — коммит или объект дерева.**
   Требование 3 и AC-13 SPEC («40 шестнадцатеричных знаков», «sha
   именно проверенного дерева») допускают и `rev-parse origin/<base>`,
   и `origin/<base>^{tree}`. Приёмочный тест пишет независимая роль:
   выбор, отличный от выбора разработчика, даст красную планку на
   верной реализации. Дефолт, если Оператор промолчит: sha коммита
   (`origin/<base>` / `HEAD`).

4. **Грамматика ссылки `файл:строка` не задана** (требование 4).
   Не сказано, обязательно ли расширение, допускаются ли ссылки вне
   обратных кавычек, какие знаки входят в путь. Для формы без каталога
   ложное срабатывание гасит правило «имени в дереве нет — не ссылка».
   Для формы с каталогом — нет: текст вида `host/api:8080` или
   `origin/main:12` даёт **отказ** «файла нет в дереве».
   Вопрос Оператору: требовать ли у полной ссылки расширение файла
   (или известный файл без расширения), чтобы отказ не срабатывал на
   адреса и refspec?

# ТЗ: cmd_new отклоняет нераспознанные аргументы

Источник: два инцидента одной сессии 01.09.2026.

Суть: разбор аргументов `artel.py new` принимает первый позиционный
аргумент как название задачи и молча игнорирует всё нераспознанное.
Следствия, наблюдённые живьём: (а) `new --help` завёл мусорную задачу
T097 с названием «--help»; (б) путь к файлу ТЗ, переданный позиционно
вместо `--tz`, был молча проигнорирован — T098/T099 родились без
TZ.md и ушли под kill. Тихое проглатывание аргументов расходует
номера задач и создаёт мусор, который приходится убивать.

Требуется:
1. `new` с нераспознанным аргументом (лишний позиционный, неизвестный
   флаг) отказывает ДО расходования номера задачи и создания ветки,
   называя нераспознанное и показывая правильную форму вызова.
2. `new --help` / `new -h` (и вызов без аргументов) печатают форму
   вызова и завершаются без создания задачи.
3. Название, начинающееся с `-`, не принимается как название.
4. Существующие корректные формы (`new "Название"`,
   `new "Название" --tz <файл>`) работают без изменений.
5. Тесты: каждый случай отказа (лишний позиционный, неизвестный флаг,
   `--help`, без аргументов) — номер задачи не израсходован, ветка
   и каталог не созданы; корректные формы — регресс.

Зона: orchestrator/artel.py (разбор argv команды `new` — валидация
до вызова catalog.cmd_new), tests/. НЕ трогать: orchestrator/catalog.py
и остальные файлы зоны параллельной M1 (T094); при конфликте зон —
эскалация, не выход за границу.

Не входит: общий рефакторинг разбора argv остальных команд на
argparse; изменение семантики `--tz`.

Рамка: $10.

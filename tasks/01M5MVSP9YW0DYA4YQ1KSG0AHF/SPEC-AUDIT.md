## Пути обхода гейтов
1. **Помощники планки** `_*.py` и `markers.py` (guard.py:4124, 2721–2722).
   Оператор принял этот пробел (п. 4) — не отклонение.
2. **Ранний выход `_group_line_errors`** (amend.py:187–188, 193–194): функция
   возвращает `[]`, если у проекта нет профиля или лок планки не несёт строк
   группы. SPEC называет `_group_line_errors` местом подключения. Если
   разработчик вставит линт внутрь функции после раннего выхода, планка,
   залоченная до правила строк группы, пройдёт amend-tests без линта, и
   добавленный в неё метод с `time.sleep(1)` отказа не получит. AC-6 этого не
   поймает: в тестах будет свежая планка со строками групп. Пробел узкий
   (касается только старых задач), но вызов надёжнее ставить рядом с тремя
   вызовами (859, 957, 1207), а не внутри функции.
3. **Восстановление через `--from-branch` у задачи со старым нарушением.**
   Worktree-путь с долгоживущими файлами сначала коммитит правку в кодовую
   ветку. Если затем не удаётся коммит в ветку документов, он отправляет
   Оператора на `--from-branch` (amend.py:926–927, 1002–1005). По требованию 4
   worktree-путь гасит залоченный старый метод с нарушением. На `--from-branch`
   базы нет (решение Оператора п. 2), и тот же метод даёт отказ
   (amend.py:1228–1231, 1280). Задача, залоченная до этой правки с нарушением в
   долгоживущем файле (класс канарейки, `run_relative`), застревает: кодовая
   ветка уже несёт правку, лок не сдвинуть. Это не обход гейта, а тупик на
   пути восстановления — следствие решения п. 2, вынесенное к Оператору.

## Вердикт

   назвать в требовании 4 приведение меток к одной форме.
2. **`--from-branch` без базы (решение п. 2) — тупик восстановления.**
   Worktree-путь отправляет туда при сбое коммита в ветку документов

   долгоживущем файле, `--from-branch` отказывает за метод, который worktree-путь
   пропустил («Пути обхода», п. 3). Нужно подтверждение Оператора: либо принять
   следствие, либо базой на `--from-branch` для планки брать снимок на
   `tests_locked_sha` (он уже читается, amend.py:1151), а для долгоживущих —
   файлы, чьи суммы совпадают с перечнем лока.
3. **Случай `--from-branch` в AC-6 не называет файл.** Непонятно, планки или
   долгоживущий. Линт подключается в двух местах: amend.py:1207 (планка) и
   amend.py:1228–1231 → 1280 (долгоживущие, только при расхождении с перечнем).
   Тест на одно место оставляет второе без проверки. Предложение: в AC-6 два
   случая `--from-branch` — файл планки и долгоживущий файл.

   (amend.py:187–194) не задано — «Пути обхода», п. 2.

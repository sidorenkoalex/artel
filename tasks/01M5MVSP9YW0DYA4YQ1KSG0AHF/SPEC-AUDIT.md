## Пути обхода гейтов
1. Правило живых файлов ловит только пути от `__file__` и от имён,
   связанных с ним. Для планки есть корень, который правило не ловит:
   `_pult.CODE_ROOT` — корень рабочей копии (`orchestrator/plank_helper.py`,
   «константы `TASK_ID`, `CODE_ROOT`», `skills/test-authoring.md:150`).
   - Обход. `Path(_pult.CODE_ROOT) / "docs" / …` (а также `Path.cwd()` или
     `os.getcwd()`) читает тот же живой файл, и отказа нет.
   - Обратная сторона. У планки нет пути исключения, аналогичного
     `_EXCEPTIONS`: гейт перечень не читает (требование 4).
   - Последствие. Планку, предмет которой — сам живой файл (AC вида
     «docs/… называет …»), гейт отклонит, если она читает файл от
     `__file__`. Test_author перейдёт на `CODE_ROOT` — тот самый обход.
   - История. Проверены ссылки документов `refs/artifacts/*` (634 задачи,
     8440 файлов `acceptance_tests/**/test_*.py`) нынешним
     `DeterministicTestsLintTest.findings`. Находки есть в 39 задачах; из
     419 находок живых файлов 150 — пути `docs`. Среди 150 последних задач
     находки есть у двух. `01M4AXPY1PY4PS1YAFAMD47VBY`
     `test_operator_session.py::OperatorSessionTextTest::test_ac14_…`
     читает `Path(__file__).resolve().parents[3] / 'docs' / …` — законная
     проверка документа задачи. `01M4P9PHCTT7TXWF422E3Y9GXN`
     `test_ac4_ac5_liveness.py::_spawn_live_group` — цикл по часам.
   - ТЗ прямо распространяет правило на `acceptance_tests/`, поэтому это не
     ошибка SPEC, а последствие для решения Оператора.
2. Долгоживущий файл на пути рабочей копии `amend-tests` получает базой
   голову кодовой ветки до правки, как в `_code_head_long_lived`
   (`amend.py:933`, требование 4). Если голова уже разошлась с перечнем лока
   (коммит мимо пульта), нарушение в этом расхождении погасится. На
   `--from-branch` база — ревизия с суммой из перечня, и нарушение там не
   погасится. Риск низкий: CI-инвариант
   `test_tests_tree_has_no_wall_clock_waits_or_live_file_reads`
   (`tests/test_invariants.py:2420`) ловит такой метод в `tests/` всё равно.
   База пути рабочей копии задана ТЗ; пути расходятся только в этом
   случае.

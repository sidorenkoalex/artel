## Критерии приёмки

AC-1. `_commit_worktree_change` и все её вызыватели
(`commit_timeout_checkpoint`, `commit_abnormal_checkpoint`,
`commit_pause_now_checkpoint`, `commit_pull_checkpoint`) после `git add
-A` коммитят только пути, входящие в зоны задачи (`tasks.zones` +
`zones_extension`, с учётом `config.COMMON_ZONES` и вложенности
каталогов по правилу `zone_lock._paths_overlap`) либо в `tasks/<свой
id>/`; прочие пути (изменённые отслеживаемые и неотслеживаемые) в
коммит не попадают.

AC-2. Наличие хотя бы одного постороннего файла на шаге любого из
четырёх WIP-чекпоинтов пишет ровно одну запись журнала «посторонние
файлы в worktree: <список>» (по образцу записи «посторонние файлы в
каталоге планки», checkpoint.py:586), не по записи на файл.

AC-3. На чекпоинте перед подтяжкой main (`commit_pull_checkpoint`,
вызывается на входе в `verifying` и в `merge_gate`) посторонний файл
отказывает переходу целиком: подтяжка (`git merge`) не начинается,
задача остаётся в прежнем состоянии — в отличие от остальных трёх
WIP-чекпоинтов (AC-1/AC-2), где посторонний файл только журналируется.

AC-4. Отказ AC-3 несёт тот же перечень посторонних файлов, что запись
журнала AC-2, и именованную причину «посторонние файлы в worktree —
решение Оператора», которой останавливается `auto` вместо повторной
попытки.

AC-5. `commit_step_artifacts` переносит в артефактную ветку из
`tasks/<id>/` только файлы, допустимые белым списком `scripts/guard.py`
(`TASK_ROOT_ALLOWED_MD`, правила `acceptance_tests/` планки) и
`RETRO.md`, определяемые вызовом функций `guard` (не отдельной копией
правил); файл вне этого списка не попадает в автокоммит и пишет одну
запись журнала на шаг, не по записи на файл.

AC-6. Гейт зон перехода `in_dev -> verifying` (`fsm_advance._zones_gate`)
сверяет с зонами не только дифф коммитов (`git diff`), но и
неотслеживаемые файлы рабочего дерева (`git status --porcelain`);
неотслеживаемый файл вне заявленных зон отказывает переходу тем же
отказом «дифф трогает файлы вне заявленных zones…», что и закоммиченный
файл вне зон.

AC-7. `.gitignore` пульта несёт шаблоны `.git-commit-msg*.txt` и
рабочие файлы ролей первого уровня репозитория (`_*.txt`, `_*.md`) —
такие файлы не подхватывает ни один `git add -A`, включая запускаемый
самой ролью до чекпоинта.

AC-8. Существующие тесты `checkpoint` (`tests/test_timeout_checkpoint.py`,
`tests/test_step_autocommit.py`, `tests/test_checkpoint_external_step_artifacts.py`,
`tests/test_checkpoint_stray_acceptance_files.py`), `fsm_advance`/гейт

## Оценка объёма и деление

Сработавшие сигналы: «затронут инвариантный механизм» (зона
`orchestrator/checkpoint.py` несёт механизм инварианта docs/invariants.md
#30, зона `orchestrator/fsm_advance.py` — механизм инварианта #34);
«прогноз диффа не дан».

Обоснование монолита: шесть требований ТЗ — грани ОДНОГО класса бага
(`git add -A` без фильтра по зонам в общей `_commit_worktree_change`) и
его единственного противоядия — синхронного фильтра по зонам в
WIP-чекпоинтах (AC-1/AC-2/AC-3/AC-4) и в гейте зон (AC-6). Промежуточное
состояние после части требований небезопасно: только AC-1/AC-2 без
AC-3/AC-4 оставили бы чекпоинт перед подтяжкой журналировать посторонний
файл, но всё равно вливать его в main без отказа перехода — то самое
поведение, из-за которого класс бага повторился трижды (11.09
01M28NX43E). Только AC-6 (гейт зон видит неотслеживаемые файлы) без
AC-1 оставило бы WIP-чекпоинты по-прежнему коммитящими посторонний файл
неотфильтрованным `git add -A` в промежутке между шагами, до входа в
`in_dev -> verifying` — гейт зон и WIP-чекпоинт закрывают один и тот же
класс с двух разных сторон одного и того же перехода, раздельный мерж
восстановил бы дыру 06.09 (`.git-commit-msg.txt`/неотслеживаемая
фикстура) на той стороне, что ещё не смержена. Зоны задачи — 4 пути (2
модуля кода, `.gitignore`, `tests/`), критериев — 8, бюджет — $45 в
пределах рамки ТЗ: по объёму задача не требует деления, кроме сработавших
механических сигналов текстового упоминания инвариантных модулей и
отсутствия отдельной оценки диффа в КиБ, которую единый связанный
фикс размером в пределах рамки не оправдывает.

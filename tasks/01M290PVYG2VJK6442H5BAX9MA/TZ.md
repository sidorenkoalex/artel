# ТЗ: чекпоинты пульта коммитят только зоны задачи и tasks/<id>/: посторонние файлы — запись в журнал, на подтяжке — отказ; гейт зон видит неотслеживаемые файлы

Источник: копилка, три строки П1 одного класса — «мусор ревьювера доехал
бы до main» (11.09), «рабочие файлы роли в корне `tasks/<id>/` доезжают
до main» (06.09), «рабочий файл разработчика в корне кодовой ветки /
одноразовая фикстура `tasks/01M1TW74Z5…` доехала до main» (06.09).
Реестр регрессий §4: №18; задачи 01M1SAA01Y (белый список каталога
планки) и 01M1TNN4 (белый список корня `tasks/<id>/`) закрыли класс
только для этих двух каталогов.

Факты:
- 11.09, 01M28NX43E: reviewer оставил в корне worktree `_a.txt` (2431
  строка), `_b.txt`, `_regen_map_check.md`; команда уборки была склеена
  без `&&` и молча не сработала; WIP-чекпоинт пульта перед подтяжкой main
  (`checkpoint.commit_pull_checkpoint` → `_commit_worktree_change`,
  `git add -A`, checkpoint.py:733) закоммитил все три файла в кодовую

- 06.09, 01M1REVMB5: шесть черновиков reviewer в `tasks/<id>/` уехали
  автокоммитом артефактов шага в артефактную ветку и снимком поверх merge

  `git add -A` чекпоинта перед подтяжкой унёс её в main; найдена
  doctor'ом (orphans-dirs) 11.09.

Требуется:
1. Все чекпоинты пульта, делающие `git add -A` (`_commit_worktree_change` и вызывающие его: чекпоинт перед подтяжкой, таймаут, аварийный, пауза), коммитят только пути внутри зон задачи (`tasks.zones` + `zones_extension`, с учётом общих зон `config.COMMON_ZONES` и вложенности каталогов тем же правилом, что `zone_lock._paths_overlap`) и внутри `tasks/<свой id>/`; прочие изменённые и неотслеживаемые файлы в коммит не попадают, а перечисляются одной записью журнала «посторонние файлы в worktree: …» (по образцу «посторонние файлы в каталоге планки», checkpoint.py:586).
2. На чекпоинте перед подтяжкой main (вход в verifying и merge_gate) посторонний файл — не предупреждение, а отказ перехода с тем же перечнем: подтяжка не начинается, задача остаётся в текущем состоянии, `auto` останавливается именованной причиной «посторонние файлы в worktree — решение Оператора»; уборка — командой роли на следующем шаге либо Оператором.
3. Автокоммит артефактов шага (`commit_step_artifacts`) берёт из `tasks/<id>/` только файлы по белому списку guard (`TASK_ROOT_ALLOWED_MD`, `acceptance_tests/` по правилам планки, RETRO.md), прочее — та же запись журнала и не коммитится; критерий допустимости — функции guard, не независимая копия.
4. Гейт зон на `in_dev -> verifying` учитывает неотслеживаемые файлы worktree (`git status --porcelain`), не только дифф коммитов: файл вне зон — тот же отказ «файл вне зон», что и для закоммиченного.
5. `.gitignore` пульта: `.git-commit-msg*.txt` и шаблон рабочих файлов ролей в корне (`_*.txt`, `_*.md` в корне репозитория) — чтобы черновики не попадали даже в `git add -A` роли.
6. Тесты: чекпоинт с файлом вне зон — файл не в коммите, запись в журнале (мутация «add -A без фильтра» — красный); чекпоинт перед подтяжкой с посторонним файлом — отказ перехода; автокоммит артефактов с `_draft.md` в `tasks/<id>/` — файл не коммитится; неотслеживаемый файл вне зон на гейте зон — отказ; существующие тесты checkpoint, fsm_advance и guard — без ослабления.

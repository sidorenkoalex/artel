# Несколько проектов: мьютекс и очередь мержа по проекту

## Факты

Строка бэклога из разбора 18.10 «что прибито под артель» (окно тишины уже по проекту — 01M563947R, смержено).

- Мьютекс мержа (`orchestrator/merge_lock.py`: `acquire` :56, `release` :125) и очередь мержа (`orchestrator/merge_queue.py`: `_head_task_id` :41, `wait_for_window` :97, `queue_wait_minutes` :71) — одни на все проекты. Мерж задачи sled ждёт мержа задачи артели и наоборот; гейт мержа внешнего проекта ждёт CI его ветки до 3600 с и всё это время держит мьютекс, задерживая мержи артели.
- Мержи разных проектов идут в разные репозитории и разные клоны; общий ресурс между ними — только состояние пульта (БД) и, возможно, главная копия артели.

## Требуется

1. Мьютекс и очередь мержа разделены по проекту задачи (`target` из БД): мерж задачи одного проекта не ждёт мержа задачи другого; внутри одного проекта порядок и взаимное исключение прежние.
2. Аналитик сверяет по коду, что разделяют мержи разных проектов кроме мьютекса (главная копия артели, общие файлы журнала, `merge_after`, окно тишины, автокоммиты артефактной ветки, сдвиг пина), и что из этого требует общего исключения; найденное в зонах — в требования, вне зон — эскалация до SPEC.
3. Подсказки и тексты ожидания («мерж ждёт …», минуты очереди в `status`) называют держателя того же проекта; у артели при одном проекте тексты прежние — зафиксировать тестами до правки.
4. Мёртвый держатель и уборка записей очереди — прежние правила, применяемые внутри проекта.
5. Тесты детерминированы, без сети: две задачи разных проектов (артель и учебный внешний) входят в мерж одновременно — ни одна не ждёт другую; две задачи одного проекта — прежнее взаимное исключение и порядок.

Критерии приёмки:
- задачи разных проектов мержатся без ожидания друг друга;
- задачи одного проекта — прежнее взаимное исключение и порядок очереди;
- у артели тексты и исходы прежние.

Зоны: `orchestrator/merge_lock.py`, `orchestrator/merge_queue.py`, `orchestrator/fsm_merge_gate.py`, `tests/`.

Только чтение: `orchestrator/notes.py`, `orchestrator/store.py`, `orchestrator/catalog.py`, `orchestrator/pin.py`, `targets.yaml`, `docs/backlog.md`. Правка вне зон — эскалация до SPEC.

Не входит: мерж через PR; красный main внешнего проекта на гейте мержа; окно тишины (сделано).

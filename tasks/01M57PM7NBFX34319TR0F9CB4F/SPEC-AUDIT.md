## Пути обхода гейтов
- **Отклонение О-4.** Требование 3 и AC-6 (SPEC.md:53-56, 112-114) не
  говорят, как `touch_heartbeat` узнаёт «свою» строку. Сейчас сигнатура
  `touch_heartbeat(conn)` (`orchestrator/merge_lock.py:95`), и ни сессии,
  ни задачи в ней нет. Буквальное исполнение возможно по `os.getpid()`,
  по проекту задачи или по (sid, pid), и у вариантов разная устойчивость:
  - Если ключ — проект задачи, строка перехватчика продлевается, когда
    его строка проекта сменилась. При ключе (sid, pid) этого не бывает.
  - Приёмочный тест на AC-6 («вызванный держателем проекта A») навяжет
    один из интерфейсов (риск кода `тест-навязывает-устройство`).
  - Если сигнатура не меняется, ключ — только pid. Тогда строки двух
    проектов с одним pid вызывающего неразличимы. В тесте это одна
    процессная фикстура, в бою невозможно.
  SPEC стоит назвать ключ (рекомендация: процесс — session_id и pid, как у
  `release`).
- Перенос условия «без изменений» в «Не входит» (О-1) допускает
  нейтральную по утверждениям переделку `tests/test_merge_lock.py`
  (например, общий setUp с другим target). Гейт неослабления её не
  заметит, а условие Оператора будет нарушено.
- Других обходов не найдено. Ослабить взаимное исключение внутри
  проекта, не покраснев, нельзя: это ловят AC-3, AC-10 и прежние тесты
  `tests/test_merge_lock.py:63-114`. Ожидание через `wait_for_window` ловит
  AC-2.

## Вердикт
**concerns.** SPEC верно отражает ТЗ и ANSWER-1, факты о коде
подтверждены, каждый AC ловит правдоподобную мутацию. Отклонения
решаемы на гейте:

- **О-1.** Условие матрицы ANSWER-1 «тесты без изменений зелёные» вынесено
  в «Не входит» (SPEC.md:180-183) вместо требования. Ни одна проверка
  пульта не держит «без изменений»: `scripts/guard.py:1658-1680` ловит
  только потерю или смену утверждений.
- **О-2.** Закрытые помощники `merge_queue._head_task_id`,
  `_current_holder_id`, `_current_holder_label`
  (`orchestrator/merge_queue.py:41,48,58`) зовутся с одним `conn` в
  утверждениях `tests/test_merge_queue.py:77,83,89,95,101,149,160,210`.
  SPEC не требует сохранить этот вызов. Обязательный новый аргумент
  станет находкой гейта неослабления (`scripts/guard.py:1664`), которую
  «Меняемое поведение» не оформит. Решение Оператора: требование
  совместимости вызова либо условие неизменности
  `tests/test_merge_queue.py`.
- **О-3.** Матрица неполна:
  - doctor ослабляется не только в видимости. Авто-ack закрывает живой
    incident мёртвого держателя другого проекта:
    `orchestrator/doctor/lease_alerts.py:44-48` при выборе
    `orchestrator/doctor/leases.py:174`.
  - Нет строк про FIFO очереди по всему пульту
    (`orchestrator/merge_queue.py:41-45`; `tests/test_merge_queue.py:85-89`)
    и про `touch_heartbeat` (`orchestrator/merge_lock.py:95-122`):
    поведенческого теста на него на main нет, есть только мок
    `tests/test_main_ci_line.py:318`.
- **О-4.** Не задан ключ «своей» строки в `touch_heartbeat`
  (требование 3, AC-6; SPEC.md:53-56, 112-114;
  `orchestrator/merge_lock.py:95`). Это риск устройства, навязанного
  приёмочным тестом, и риск продления чужой (перехватившей) строки.
- **О-5 (незначительное).** «Материалы» (SPEC.md:192) не называют третий
  вызов `touch_heartbeat`: `orchestrator/fsm_merge_gate.py:1474`.

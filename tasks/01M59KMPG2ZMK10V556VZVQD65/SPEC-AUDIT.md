## Пути обхода гейтов
- **Е1 (первый визит) закрыт** треб. 8 и AC-19: до G2а-2 автогейт у правила не по умолчанию задачу не пропускает. Даже если `acceptance.run` на `.jsx`-планке «зелен» без исполненных тестов, в `merge_gate` автогейтом задача не попадёт.
- **Е4. Условие fail-closed записано двумя неравносильными формулами.** Треб. 8: «при правиле планки не по умолчанию (у проекта задачи есть компонент с командой не pytest)». По треб. 2 эти условия расходятся:
  - компонент с командой не pytest без `tests` получает правило-умолчание;
  - при отказе построения правило тоже умолчание.

  По первой формуле такой проект идёт прежним автогейтом. По второй (в скобках) — стоит у Оператора. Обхода гейта здесь нет: у правила-умолчания `.jsx` не видна, планка из одних `.jsx` «пуста» → Оператор (`fsm_autogate.py:263-265`). Но формула в скобках шире и при буквальном чтении задевает «у правила по умолчанию автогейт прежний побайтно». Записи `test_profile` (`targets.yaml:46`, `:84`) — на pytest, их не задевают ни та, ни другая формула.
- **Е5. Буквальное «только методами объекта правила» против области чтения артели.** Треб. 3 велит фильтровать пути в теле `_tests_writing_ac_state` «только методами объекта правила». AC-15 закрепляет у артели ветку перехода «все `.py`» (`orchestrator/fsm.py:667-668`) — сегодня это и `conftest.py`, и `_pult.py`, и вложенные `.py`. А `DEFAULT_PLANK_RULE.component_of` для этих имён — `None` (треб. 1, «всегда посторонние»).

  Фильтр `rule.component_of(...) is not None` у артели сузит область. AC-15 это поймает, но SPEC не говорит, как совместить: оставить `p.endswith(".py")` у правила-умолчания или дать правилу отдельный метод области чтения. Сторож разрешает оба варианта: `endswith` — не функция `guard`.
- Е2 — принятый Оператором остаточный риск, в «Не входит». Е3 (пометка `ci`) — без изменений, обхода нет.

## Вердикт
`concerns` — SPEC можно вести дальше. Все девять решений Оператора с гейта SPEC №1 перенесены, новые факты сходятся с кодом. Остались три мелких уточнения, их может снять Оператор на гейте:

1. **Б3. Форма исхода автогейта** (треб. 8, AC-19). «Не принято автогейтом» — не существующий исход. Прежний путь отказа: причина с префиксом «автогейт: », действие журнала «автогейт acceptance не пройден», задача остаётся в `acceptance` (`orchestrator/fsm_autogate.py:380-389`, `orchestrator/models.py:1001`). Уточнить, что исход — этот путь, иначе test_author закрепит несуществующий литерал.
2. **Е4. Условие fail-closed** (треб. 8). «Правило не по умолчанию» и «есть компонент с командой не pytest» расходятся у компонента не-pytest без `tests` и при отказе построения (треб. 2). Оставить одну формулу — «правило не по умолчанию».
3. **Е5. Фильтр ветки перехода у правила-умолчания** (треб. 3, последний пункт; AC-15). У артели ветка перехода читает все `.py` (`orchestrator/fsm.py:667-668`), а `DEFAULT_PLANK_RULE.component_of` отвергает `conftest.py`, `_pult.py` и вложенные пути (треб. 1). Уточнить, что у правила-умолчания прежний `endswith(".py")` сохраняется (сторож это допускает).

Замечание без отклонения: образец id в `preflight` и на ветке перехода по правилу (`orchestrator/preflight.py:253-254`, `orchestrator/fsm.py:667-674`) критерием на уровне места не закреплён. AC-18 проверяет функцию `scan_id_format_samples` — так сформулировано решение Оператора п. 3(е).

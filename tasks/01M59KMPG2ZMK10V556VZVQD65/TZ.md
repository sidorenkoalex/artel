Требуется:

1. **Правило планки.** В `scripts/guard.py` (без зависимостей пульта) — класс `PlankRule`: по компоненту — допустимые имена файлов первого уровня каталога планки, какие из них тестовые, вид метки критерия (`test_ac<n>_` либо `^AC-<n>: `) и синтаксис пометок (`#` либо `//`); методы `PlankRule.component_of(name)` — имя компонента файла планки или `None` (посторонний), `PlankRule.is_test(name)` — файл тестовый, `PlankRule.masks(component)` — маски `tests` компонента (все три вызывает G2а-2). Константа `DEFAULT_PLANK_RULE` — нынешнее правило побайтно. В `orchestrator/project_profile.py` — функция `plank_rule(target) -> guard.PlankRule`: артель (признак `is_artel`) — умолчание без чтения записи; запись `test_profile`, компонент без `tests` и компонент, чья команда — pytest (`acceptance.is_pytest_command`), — умолчание (принадлежность по `ACCEPTANCE_TESTS_ALLOWED_TOP_LEVEL`, не по маскам `tests`); иначе — по последнему сегменту масок `tests` (`frontend/src/**/*.test.jsx` → `*.test.jsx`), метка `^AC-<n>: `, пометки `//`; несколько подходящих компонентов — первый в порядке записи. Первым проверяется компонент `pult-vitest` без `tests` — отказ построения «у компонента <имя> нет tests — допустимые файлы планки не определены»: `plank_rule` возвращает правило-умолчание с причиной отказа; чекпоинт, автогейт и документы перед мержем берут умолчание (строже) и пишут причину в журнал; переход, `preflight` и `amend-tests` отказывают этим текстом. Запись внешнего проекта не прочитана — умолчание (строже), без исключения `TargetsError` наружу. `acceptance.is_pytest_command` импортируется внутри `plank_rule` (цикл импорта `project_profile -> store -> … -> acceptance`; тот же приём, что у ленивых импортов в `acceptance`). Запись с несколькими компонентами строится без отказа (`decide` не вызывается). Всегда посторонние: вложенный путь, `_pult.py`, `PASSPORT.md`, `conftest.py`; `.md` и `.txt` первого уровня — общие. `Profile` несёт `tests` и `plank_layout` (вне сравнения), заполняет их `_with_component_fields`.
2. **Ядро разбора с именами.** Функции `guard`, читающие планку, принимают правило необязательным параметром; без него — прежнее поведение и прежние области чтения артели, включая нынешнее расхождение (диск — `test_*.py`, ветка и предпроверка — все `.py`, `count_test_methods` — все `*.py`). Новое ядро получает пары (имя, текст), синтаксис файла — по правилу; долгоживущие тексты в G2а — синтаксис Python. Прежняя сигнатура `scan_ac_content` сохраняется (её зовёт `retro.py`). Имена функций `guard`, которые проверяет сторож предпроверки, сохраняются; новая функция ядра, вызванная в теле перехода, вызывается и в `preflight`.
3. **Метка `AC-<n>: `.** Тест критерия — вызов в начале строки (отступ допустим) `(it|test)(\.(concurrent|sequential))*(\.each\(…\))?\(\s*<литерал>`, литерал начинается строго с `AC-<n>: `; у `.each` литерал — первый аргумент второго вызова, таблица `.each` может быть многострочной; литерал — в `'`, `"` или обратных кавычках без `${`. Метка в `describe` критерий не покрывает. Пометка — `// AC-<n>: manual|skip|escalate|ci — причина` в начале строки; она же с отступом — отказ тем же текстом, что у `#`; `# AC-<n>: manual` в файле `.jsx` — не пометка. Подсказка «нет теста» у такого критерия называет форму `it('AC-<n>: …')`. У компонента с меткой `AC-<n>: ` трассируемость и маркер красноты — только по тестовым файлам, образец идентификатора — по всем файлам компонента в планке.
4. **Маркер красноты не-pytest файла** — в первом комментарии: подряд идущие строки `//` либо один `/* … */` до первой непустой строки кода. Текст отказа — прежний с «в первом комментарии файла» вместо «в докстринге модуля»; у артели — прежний побайтно.
5. **Чекпоинт.** Автокоммит отбрасывает посторонний файл планки по `plank_rule` проекта задачи: у `pult-vitest` `a.test.jsx` и `_util.jsx` идут в ссылку документов, `a.test.py` и `vitest.config.js` — посторонние с прежней записью журнала.
6. **Переход, предпроверка, `amend-tests`.** По правилу — трассируемость (диск и ветка) и маркеры красноты: выход из `tests_writing` (`fsm._tests_writing_ac_state`, оба пути), `preflight` (`_plank_py_files`, `_traceability`, красный маркер, образец идентификатора), `amend-tests` (рабочая копия, голова ветки, `_collect_and_run`: маркер красноты — по отдельному перечню тестовых файлов по правилу, `plank_files` для строк группы и долгоживущих не меняются). Строки группы и долгоживущие (`_test_files`, `acceptance_test_files`, `_groups`) — прежние, `test_*.py`.
7. **Сухой прогон приёмки, автогейт, сводка.** `acceptance-dry-run`: тестовые файлы по правилу, под файлом — имена тестов (у метки `AC-<n>: ` — литералы всех вызовов п. 3), пометки обоих синтаксисов. `fsm_autogate._plank_sources` читает файлы планки по правилу, пометки `manual`/`skip`/`ci` — обоих синтаксисов. `acceptance.summary` считает тесты и пометки по правилу, правило выводит сам по имени каталога задачи через `store` (приём `drop_from_code_copy`); вызывающий не меняется.
8. **Документы перед мержем.** `_task_docs_violations`: у проекта с правилом не по умолчанию посторонние файлы планки и пометки с отступом проверяются по правилу и при `guard_rules` = `False`; у артели и записей `test_profile` — как сейчас.
9. **У артели (`pult-pytest`) и у записей `test_profile` (sled сегодня) допустимые файлы, области чтения, разбор, тексты и вывод команд — прежние.** Аналитик перечисляет в SPEC тексты, закрепляемые тестами до правки: `EXTRANEOUS_ACCEPTANCE_FILE_REASON`, `STRAY_ACCEPTANCE_FILES_DETAIL_PREFIX`, `RESERVED_PLANK_HELPER_HINT`, состав `INPUT_FILTERS`, отказы `traceability_errors_from_content`, текст отказа маркера красноты, заголовки `acceptance-dry-run` («Тестовые файлы и методы», «AC-маркеры manual/skip/escalate»), причину автогейта «каталог приёмочных тестов пуст или отсутствует», строку сводки «приёмочные тесты: N тест(ов)…».
10. Тесты детерминированы, без сети и без Node: учебный проект с двумя компонентами (`junit-xml` на pytest и `pult-vitest`) — `plank_rule`, принадлежность файлов, чекпоинт, трассируемость, сухой прогон приёмки, автогейт, сводка, документы перед мержем; места через `decide` (выход из `tests_writing`, `preflight`, `amend-tests`) — на записи `components:` из одного компонента каждого вида; тест на каждую форму п. 3, включая многострочный `.each` и `# AC-n: manual` в `.jsx`.

Критерии приёмки:
- у компонента `pult-vitest` `a.test.jsx` с `it('AC-1: …')` проходит чекпоинт и покрывает AC-1; `test.each([...многострочно...])('AC-2: %s', …)` покрывает AC-2; `describe('AC-3: …')` AC-3 не покрывает; `// AC-4: manual — причина` — пометка, она же с отступом — отказ; `a.test.py` того же компонента — посторонний;
- у компонента `junit-xml` на pytest допустимые файлы и разбор — как у артели, `conftest.py` в планке — посторонний; `pult-vitest` без `tests` — отказ построения правила с текстом;
- `preflight`, `amend-tests`, `acceptance-dry-run`, автогейт, сводка и документы перед мержем видят `*.test.jsx` и пометки `//`; сторож предпроверки зелёный без правки;
- у артели перечисленные в SPEC тексты, области чтения и исходы прежние.

Решения по умолчанию (аналитику не спрашивать): помощники планки не-pytest компонента — `_<имя>.<расширение маски tests>` (`_util.jsx`); перечень `long_lived.sha256.txt` допустим у всех; маски `tests` с `**` берутся только по последнему сегменту, каталог планки плоский; пометка `ci` у не-pytest компонента — тот же смысл и та же проверка формулировки; сторож `tests/test_01m4p4zp37wv81410ytzhkqc8d_preflight.py` не правится — если правка понадобится, эскалация; правило записи с несколькими компонентами строится, хотя `decide` такой записи отказывает.

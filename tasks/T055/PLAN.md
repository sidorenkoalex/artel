# PLAN: Убрать рудимент посева артефактов в workspace

## Подход

`_seed_uncommitted_artifacts` (orchestrator/workspace.py:44-62) мертва с
T048: `copytree` не выполняется ни на одном живом пути, потому что
`config.TASKS/<id>` в main-копии больше не создаётся (`cmd_new` пишет
TZ/SPEC сразу в worktree). Убираем функцию, её единственный вызов из
`ensure()` и переписываем докстринги `ensure()`/модуля так, чтобы они не
упоминали снятую функцию и не описывали перенос незакоммиченных
артефактов главной копии — точечная правка одного файла, без изменения
наблюдаемого поведения.

Тест-спутник рудимента `tests/test_workspace.py::EnsureTest.
test_seeds_uncommitted_task_dir_into_a_fresh_worktree` удаляется целиком
по точечной амнистии Оператора (SPEC требование 6) — он проверял именно
удаляемое поведение (`copytree` в свежий worktree), другого предмета не
имеет.

## Шаги

1. `orchestrator/workspace.py`: удалить `_seed_uncommitted_artifacts`
   целиком (:44-62), убрать её вызов из `ensure()` (:84-85), переписать
   докстринг `ensure()` и докстринг модуля — без описания переноса
   незакоммиченных артефактов и без ссылки на снятую функцию.
2. `tests/test_workspace.py`: удалить
   `EnsureTest.test_seeds_uncommitted_task_dir_into_a_fresh_worktree`
   целиком (точечная амнистия, требование 6 SPEC).
3. Прогнать полный набор `tests/` — убедиться, что ни один другой тест
   не зацепил удаление (AC-4); при конфликте — эскалация, не правка.
4. При необходимости — регенерировать `docs/codebase-map.md`
   (`python3 scripts/codebase_map.py`), т.к. правился `orchestrator/*.py`.

## Влияние на систему

Правка ограничена `orchestrator/workspace.py` (удаление мёртвого кода и
актуализация докстрингов) и удалением одного теста-спутника мёртвого
поведения по точечной амнистии Оператора — оба действия прямо
санкционированы SPEC (требования 1, 2, 3, 6). Наблюдаемые поверхности
(`ensure()`/`cmd_workspace`/`cmd_new`, CLI-вывод, схема БД, журнал) не
меняются: `_seed_uncommitted_artifacts` уже не исполнялась ни на одном
живом пути (`copytree` не срабатывал за собственным guard'ом), поэтому
её удаление не меняет фактическое поведение системы — только убирает
код, который никогда не выполнялся. Остальные тесты `tests/test_workspace.py`
(idempotent, reuse existing branch, failure paths) продолжают проверять
живое поведение `ensure()` без изменений. Откат — `git revert` коммита
правки, функция и тест восстанавливаются из истории.

## Риски

Низкие — удаление мёртвого кода без побочных эффектов. Единственный
риск: если какой-то другой тест неявно зависел от побочного эффекта
`_seed_uncommitted_artifacts` — исключается прогоном полного набора
`tests/` (шаг 3); при обнаружении — эскалация, а не правка постороннего
теста (вне точечной амнистии).

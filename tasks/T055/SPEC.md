# SPEC: Убрать рудимент посева артефактов в workspace

## Контекст

Ревизия кодовой базы 28.08 (находка CR-2026-08-28-5, ★3,
docs/audits/code-revision-2026-08-28.md) установила, что
`workspace._seed_uncommitted_artifacts` (orchestrator/workspace.py:44-62,
единственный вызов — `ensure()`:84-85, ветка свежесозданной ветки) —
рудимент T045, переживший T048. Функция переносила в свежий worktree
то, что `cmd_new` оставлял некоммиченным в `tasks/<id>` главной копии,
но с T048 `cmd_new` пишет TZ/SPEC сразу в worktree ПОСЛЕ `ensure()` и
не трогает main ни на одном шаге. К моменту вызова `config.TASKS/<id>`
в main-копии не существует ни в одном живом пути, а `copytree` мёртв
за собственным guard'ом `if not src.is_dir(): return`. Докстринги
функции, `ensure()` и модуля описывают мир до T048.

## Требования

1. Удалить функцию `_seed_uncommitted_artifacts` из
   `orchestrator/workspace.py`.
2. Удалить единственный вызов `_seed_uncommitted_artifacts` из
   `ensure()`.
3. Привести докстринги `ensure()` и модуля `orchestrator/workspace.py`
   в соответствие миру T048: без описаний переноса незакоммиченных
   артефактов из главной копии и без ссылок на снятую функцию.
4. Поведение системы не меняется: наблюдаемые поверхности (CLI-вывод
   `new`/`workspace`/`run`, журнал, схема БД, имена файлов) — без
   изменений.
5. Правки — только в `orchestrator/workspace.py` (код и докстринги),
   тесты — при необходимости, карта кодовой базы — при необходимости
   регенерации. Никаких иных правок `workspace.py` (`ensure`/`remove`/
   пути) сверх удаления рудимента и актуализации докстрингов, никаких
   «попутных улучшений».
6. Точечная амнистия Оператора (гейт SPEC 28.08, правила T015): тест
   `tests/test_workspace.py::EnsureTest.
   test_seeds_uncommitted_task_dir_into_a_fresh_worktree` лочит ровно
   удаляемое поведение (тест-спутник рудимента, предмет мёртв с T048)
   и УДАЛЯЕТСЯ вместе с функцией — целиком, без переписывания.
   Любой ДРУГОЙ тест, который зацепит удаление, под амнистию не
   попадает: его конфликт — основание для эскалации, а не для правки.

## Критерии приёмки

AC-1. `_seed_uncommitted_artifacts` отсутствует в кодовой базе; grep по
имени `_seed_uncommitted_artifacts` по репозиторию — ноль вхождений.

AC-2. Докстринги `ensure()` и модуля `orchestrator/workspace.py`
приведены к миру T048: не описывают перенос незакоммиченных артефактов
главной копии в worktree и не упоминают снятую функцию.

AC-3. `cmd_new` работает как прежде: задача заводится, TZ/SPEC рождаются
в worktree, main не тронут (существующие тесты T048 зелёные).

AC-4. Все существующие тесты зелёные без ослаблений.

## Не входит

- Любые другие правки `orchestrator/workspace.py` (`ensure`/`remove`/
  пути) сверх удаления рудимента и актуализации докстрингов.
- «Попутные улучшения» любого рода.
- Правка/ослабление любых тестов сверх точечной амнистии требования 6
  (удаление test_seeds_uncommitted_task_dir_into_a_fresh_worktree
  целиком) — иной конфликт с тестом решает Оператор через эскалацию.

# ТЗ: воспроизводимый аудит usage и стоимости шага

Источник: решение Оператора в чате 07.10.2026 — подготовить задачи по итогам аудита расхода. Запись копилки: коммит 7a6f0dacda0b5cc39c02c06fb1624c31b526333e.

## Проблема и факты
Для 103 задач, созданных с 28.09, сумма записей agent cost совпадает со spent_usd с точностью до цента. Это проверяет суммирование, но не достоверность usage. Сохранённые логи ролей рендерят текст и команды, исходные счётчики не сохраняются. У таймаута нет итоговой цены CLI. Независимо подтвердить отсутствие задвоения токенов нельзя. Завершённые цены Claude берутся из CLI (это также не доказательство денежного списания по подписке), Codex — условные расчётные единицы пульта. Решение Оператора 07.10: ценовая модель Codex условная. Её нельзя выдавать за реальные расходы, расход подписочного лимита или использовать для вывода «Codex дешевле Claude в N раз». Основные метрики эффективности: токены по видам, число запросов при доступном учёте, длительность, повторы и качество завершённой задачи. Данные о лимитах аккаунта показываются отдельно, только при наличии достоверного источника; токены не конвертируются в процент лимита.

## Требуется
1. Для каждого нового запуска роли сохранять отдельный минимальный структурированный журнал аудита: задача, роль, идентификатор запуска и попытки, провайдер и модель, последовательность событий, вид события, предоставленные провайдером идентификаторы сообщения/запроса, исходные поля usage, нормализованные счётчики и итоговая цена CLI при наличии. Отсутствующие поля остаются отсутствующими, а не нулевыми. Идентификаторы не придумывать. Повтор одного сообщения должен быть виден аудитору.
2. Не сохранять содержимое промптов, ответов, аргументы и результаты инструментов, окружение или секреты. Хранилище — служебная область пульта вне git; роль не получает дополнительных прав. Вложенные агенты учитываются только при наличии явных событий провайдера; неполнота покрытия названа.
3. Запись по ходу потока обеспечивает пригодность уже записанного префикса после таймаута/обрыва. Итог фиксирует завершённость, источник стоимости и тариф, применённый именно к этому запуску. Незавершённая последняя строка не делает остальные события нечитаемыми. Сбой записи имеет именованный сигнал в журнале; не превращает неизвестный расход в ноль.
4. Штатная read-only команда аудита запуска: показывает суммы usage, повторы идентификаторов, отличие промежуточного накопления от финального usage, стоимость CLI отдельно от условного расчёта и отличие от учётного начисления пульта. Для Codex явно указано «условная стоимость; не денежное списание и не расход лимита подписки». Разные виды счётчиков не складываются автоматически: политика текущего провайдера указана. Частичный расход называется оценкой; отсутствие данных — неизвестностью. Для старого запуска без журнала выдаётся честное «проверка невозможна».
5. Хранилище имеет явный предел размера и согласованное с действующей retention удаление. Превышение предела не молчаливо; отчёт помечает неполноту. Конкретный предел и формат выбирает SPEC.

## Направление приёмки
Фикстуры обоих провайдеров: завершение, таймаут, обрыв, повтор сообщения, отсутствующий usage, отличие итогового usage от промежуточных сумм. Проверить воспроизводимость расчёта на фиксированном историческом тарифе, отсутствие двойного списания, обработку повреждённого хвоста/ошибки записи/лимита и отсутствие содержимого сообщений и секретов в журнале. Команда аудита не меняет БД, задачи и стоимость. Существующее списание сохраняется.

## Зоны и границы
Зоны: orchestrator/agent_log.py, orchestrator/providers/base.py, orchestrator/providers/claude.py, orchestrator/providers/codex.py, orchestrator/runner.py, orchestrator/spend.py, orchestrator/artel.py, orchestrator/prune.py, новый модуль orchestrator/usage_audit.py, tests/, docs/stack.md. SPEC обязан уточнить минимальные зоны и оценить деление.
Только чтение: защищённые пути, конфигурация моделей/ролей/гейтов, личные настройки и дома ролей.
Не входит: исправление текущей формулы списания, пересчёт истории, изменение тарифов, полноценный сырой JSON всех сообщений, новые полномочия ролей, ослабление гейтов.

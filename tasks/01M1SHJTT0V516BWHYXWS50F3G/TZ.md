# ТЗ: автогейт приёмки: критерий «существующие tests/ зелёные» исполняется по CI

# ТЗ: критерий «существующий набор tests/ остаётся зелёным» исполняется автогейтом приёмки по CI

Источник: бэклог 05.09 (docs/backlog.md, приоритет 2), статистика ручных
гейтов 05.09: из 13 ручных приёмок 12 сводились к одному критерию —
«существующие tests/ зелёные», который Оператор исполнял, глядя на
зелёный CI головы кодовой ветки. Ручной гейт дублирует CI: переход в
`verifying` уже требует голову ветки на origin, а CI ветки прогоняет
полный набор `tests/`.

Сегодня. Автогейт приёмки (`orchestrator/fsm_autogate.py`, ADR-0007,
`gates.yaml: acceptance: auto`) переводит задачу дальше только если ни
один критерий не помечен manual/skip; критерий про существующие тесты
тест-автор помечает `manual`, и задача уезжает на ручной гейт.

Требуется:
1. Новый маркер критерия в планке — `# AC-n: ci` (наряду с manual/skip/
   escalate): «критерий исполняется зелёным CI головы кодовой ветки».
   `scripts/guard.py::scan_acceptance_tests` распознаёт маркер; правило
   трассируемости «каждый AC получил тест или пометку» считает `ci`
   допустимой пометкой.
2. Автогейт приёмки считает критерий с пометкой `ci` исполненным, если
   CI головы кодовой ветки зелёный по данным, которые уже собирает
   `verifying` (`orchestrator/ci.py`; sha головы ветки совпадает со sha,
   для которого CI зелёный — иначе критерий НЕ исполнен, fail-closed).
   Пометка `ci` при отсутствии данных CI или красном/незавершённом CI —
   задача идёт на ручной гейт, как сегодня, с причиной в журнале.
3. Пометка `ci` допустима ТОЛЬКО для критериев, формулировка которых
   про существующие тесты (`tests/` зелёные, число тестов не уменьшилось
   и т.п.); `guard` отказывает планке, где `ci` стоит у критерия с иной
   формулировкой — эвристика по тексту критерия SPEC (ключевые слова
   «существующ», `tests/`, «зелён», «не ослаб»), fail-closed: не
   распознал — отказ с подсказкой пометить manual.
4. Ручной гейт приёмки: сводка (`docs/operator-gates.md`, п.4) остаётся
   — если задача всё же приехала на ручной гейт, критерий `ci` виден в
   сводке с результатом CI.
5. Приложением к PLAN (защищённый путь): строка в
   `skills/test-authoring.md` — когда ставить `ci` вместо `manual`.
6. Тесты: планка с `ci` и зелёным CI — автогейт проходит; с `ci` и
   красным/отсутствующим CI — ручной гейт с причиной; `ci` у критерия
   не про тесты — отказ guard; существующие тесты автогейта и guard
   зелёные без ослабления.

Зоны: orchestrator/fsm_autogate.py, orchestrator/ci.py, scripts/guard.py,
tests/.

Не входит: автогейт merge и SPEC (остаются ручными, решение Оператора
05.09); изменение политики `gates.yaml`; прогон тестов самим пультом.

Рамка: $35 (6 требований, 3 файла кода + тесты).

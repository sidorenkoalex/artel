# SPEC: A6 — гигиена стека

## Контекст

Первая задача фазы A (roadmap §2): перед мультитаргетным контуром
стек чистится от накопленных обходов. Сейчас: roles.yaml кодом
не читается — ROLE_SKILLS дублируется руками в config.py; парсер
frontmatter написан дважды (scripts/guard.py и orchestrator/
artifacts.py) и оба — рукописный split без типизации; у артефактов
нет версии схемы — расхождение форматов писатель/читатель
обнаруживается чужим сбоем, а не проверкой; промпт роли передаётся
через argv (лимиты длины, утечка в ps); guard не вызывается
оркестратором на переходах; merge_gate не проверяет статус CI кодом;
в merge зашит литерал "main" при существующем config.MAIN_BRANCH.

## Требования

1. roles.yaml читается кодом: карта роль → скилы берётся
   из roles.yaml, константа ROLE_SKILLS из config.py удаляется.
   Формат roles.yaml не меняется.
2. Единый парсер frontmatter: один модуль используется и guard'ом,
   и orchestrator/artifacts.py; значения типизируются (int/float/str);
   рукописные split-парсеры удаляются.
3. Во frontmatter артефактов вводится поле `schema_version` (целое,
   текущая версия — 1). Шаблоны в templates/ получают поле; guard
   проверяет: значение выше поддерживаемой версии — ошибка.
   Артефакты без поля (история Фазы 0, tasks/T001–T016) валидны
   как версия 1 — существующие файлы не редактируются.
4. Промпт роли передаётся агенту через stdin или временный файл,
   не через argv.
5. Оркестратор вызывает guard на переходах `advance` для артефактов,
   являющихся условием перехода; невалидный артефакт — отказ
   перехода с внятной ошибкой (не трейсбек).
6. merge_gate: перед merge код проверяет статус CI головного коммита
   ветки задачи (`gh`-CLI); не-зелёный CI — отказ merge. Инвариант
   закрепляется тестом в tests/test_invariants.py (тест на отказ).
7. Литерал "main" в merge-пути заменяется на config.MAIN_BRANCH.
8. В docs/triggers.md строка №2 (демонизация) получает числовой
   порог: 10 задач/неделю.

## Критерии приёмки

1. grep ROLE_SKILLS по orchestrator/ пуст; запуск роли берёт скилы
   из roles.yaml (юнит-тест: изменение roles.yaml меняет состав
   скилов без правки кода).
2. В репозитории один парсер frontmatter; guard и artifacts
   импортируют его; юнит-тест парсера покрывает типизацию
   и отсутствие frontmatter.
3. `scripts/guard.py --all` зелёный на текущем репозитории без
   правки исторических артефактов; артефакт с schema_version: 999
   отклоняется guard'ом (тест).
4. Строка запуска агента (runner) не содержит текста промпта
   в argv (тест или проверка кода команды запуска).
5. `advance` с испорченным артефактом (нет обязательной секции)
   отказывает в переходе и называет файл и причину (тест).
6. Тест инварианта: merge_gate при не-зелёном/неизвестном статусе
   CI не выполняет merge.
7. grep '"main"' по orchestrator/fsm.py в merge-пути пуст.
8. docs/triggers.md №2 содержит порог «10 задач/неделю».

## Не входит

- targets.yaml, колонка target, WAL, счётчик нумерации (A1).
- doctor и таблица alerts (A3) — сам счётчик задач/неделю здесь
  не реализуется, только порог в реестре триггеров.
- Роли test_author/analyst (A4/A5).
- Изменение формата или состава секций существующих артефактов.
- Новые внешние зависимости сверх YAML-парсера (PyYAML допустим).

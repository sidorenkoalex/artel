## Замечания

- **major — orchestrator/yamlmini.py:76-79 — `scalar()` снимает кавычки
  до среза комментария, поэтому значение в кавычках с комментарием на той
  же строке разбирается вместе с кавычками.** Проверка кавычек стоит на
  нераспарсенной строке: у `"ready"   # draft | ready | approved` первый
  символ `"`, последний — `d` из комментария, условие не срабатывает,
  дальше срезается комментарий и возвращается строка `"ready"` с кавычками.
  Прогнал: `yamlmini.frontmatter('---\ntask: "T017"  # к\nstatus: "ready"\n---\n')`
  → `{'task': '"T017"', 'status': 'ready'}`.
  Сценарий поломки: `templates/SPEC.md:5` поставляется строкой
  `status: draft        # draft | ready | approved` — комментарий на строке
  значения уже есть по шаблону; аналитик берёт значение в кавычки (обычная
  привычка в YAML) и получает `guard`: «недопустимый status '"ready"'»,
  а `fsm.cmd_advance` — «SPEC.md ещё не ready». Обе жалобы указывают на
  значение, а не на парсер, и с требованием 5 это уже не косметика,
  а отказ перехода. Тот же класс — те же кавычки на `type`, `author_role`,
  `task`; поле `budget_usd` спасено только тем, что `budget.py:31` снимает
  кавычки повторно у себя.
  Второе место того же класса — **молчаливый неверный разбор там, где
  модуль обещает громкий отказ**: `orchestrator/yamlmini.py:145` —
  потоковый список делится `inner.split(",")` без учёта кавычек, и
  `skills: [a, "b, c"]` даёт `['a', '"b', 'c"']`. Docstring модуля
  (`yamlmini.py:16-19`) и «Риски» PLAN обещают на неподдерживаемой
  конструкции `YamlError`, «а не молча половину разобранного» — здесь
  обещание не выполняется.
  Предложение: в `scalar()` при открывающей кавычке искать парную
  закрывающую и считать хвост за ней комментарием (наивный «срезать
  комментарий первым» сломает `title: "a # b"`); во `_value()` при кавычке
  внутри потокового списка — `YamlError` с номером строки. Оба случая —
  в `tests/test_yaml_parsing.py`, там для них уже есть готовые соседи
  (`ScalarTest.test_trailing_comment_is_cut`,
  `MappingTest.test_unsupported_shapes_refuse_loudly`).

- minor — tests/test_agent_prompt.py:152 — ассерт не проверяет того, что
  написано в его сообщении. `assertNotIn("-p", argv[argv.index("-p") + 1:],
  "после -p идёт флаг, а не промпт")` проверяет, что в хвосте нет второго
  `-p`. Сценарий: верни промпт в argv сразу после `-p` — этот ассерт
  пройдёт, тест спасёт только следующий цикл по словам; а при реальном
  падении сообщение отправит разбирающего не туда. Предложение:
  `self.assertTrue(argv[argv.index("-p") + 1].startswith("--"))`.

- minor — orchestrator/runner.py:139-155 — `open(prompt_path)` попал
  внутрь `try`, у которого `except FileNotFoundError` отчитывается «claude
  CLI не найден». Сценарий: файл промпта исчез между `write_text` и `open`
  (ручная уборка `.artel/logs`, внешний tmp-reaper) — Оператор читает
  «claude CLI не найден» и идёт чинить установку CLI вместо диска.
  Предложение: открыть файл до `try` либо оставить в `try` только `Popen`.

- minor — orchestrator/ci.py:26-30 — `subprocess.run(["gh", ...])` без
  `timeout`. Сценарий: `gh api` уходит в сетевой столл (VPN/прокси
  принимают соединение и молчат) — `artel.py approve` на `merge_gate`
  висит без вывода и без предела, тогда как у шага агента предел есть
  (`AGENT_TIMEOUT_SEC`). Предложение: `timeout=` константой в `config`,
  `subprocess.TimeoutExpired` → та же ветка «статус неизвестен», то есть
  отказ merge. Полнота класса: `gitcmd.git` (`gitcmd.py:14`) тоже без
  таймаута, но это предсуществующий код вне зоны T017 — называю, чтобы
  класс не выглядел закрытым наполовину; править его в этой задаче
  не требую (расширение зоны — дефект, при желании — отдельная задача).

# ANSWER-2: ответ Оператора

## Ответы

Ответы сессии при Операторе (права волны G) на QUESTIONS.md (батч после возврата аудита 1 из 2), 27.10.2026.

1. **A.** Локальный полный набор на мерже после приложений PLAN остаётся как есть — единственное названное исключение из правила «локально в режиме `ci` только тесты задачи»; в SPEC — в «Не входит» решением Оператора. (Для проектов с `target-human` приложения на мерже отказывают по ADR-0029 п. 1, так что исключение касается только проектов с `operator`.)
2. **A.** В режиме `ci` — те же три условия, что у артели (дерево гейта = дерево головы, свежесть относительно `origin/<base>`, без `--fresh-suite`); невыполненное условие — «неизвестно» с именованной причиной, не локальный прогон; `--fresh-suite` заново читает итог задания CI. «Неизвестно» `--accept-red` не принимает.
3. **A.** Кандидаты отчёта базы — коммит точки ответвления и его родители по git (`git rev-list --parents -n1`) с совпадающим деревом; поиска MR через хостинг нет. Не нашлось — отказ «нет отчёта базы».
4. **A.** Красный тест в отчёте головы без перепрогона — находка BROKEN («сломан правкой») с прежним действием отказа.
5. **A.** Утверждённая замена теста у компонента `ci` — отказ гейта с именованной причиной «замена теста не проверяема в режиме ci»; REPLACED_MISSING/REPLACED_NOT_GREEN по отчёту базы — как раньше.
6. **A.** В режиме `ci` доказательство `_proven` не используется: на мерже гейт заново читает отчёты базы и головы и сравнивает их; критерий — локальной выписки нет, отчёты прочитаны.
7. **A.** Компонент с `full_suite: ci`/`both` без `report` — отказ загрузки записи с именем поля `report`.

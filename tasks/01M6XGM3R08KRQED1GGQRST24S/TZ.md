# Поверхность решения и размер проверки в критериях SPEC — правила для analyst, аудитора, test_author и ревьювера (ADR-0032, этап 3)

## Факты

1. ADR-0032 (принят Оператором 08.11.2026, `e4de84a0`), пп. 1 и 3: критерий-правило (разбор входа, условие отказа, текст сообщения, выбор ветки) называет в тексте AC публичную функцию решения; связку команды с функцией держит критерий подключения по всем состояниям; каждый критерий несёт размер проверки (малый / средний / большой), большой — с обоснованием. Этап 3 — правила в скилах и шаблоне SPEC; кода пульта не трогает.
2. Правило «свойство без песочницы — модульным тестом» уже есть (`skills/test-authoring.md:192-196`), но держится только там, где SPEC назвал публичную функцию: тест пишется до кода и только через публичный интерфейс (`skills/test-authoring.md:3`, `:98`). Аналитик имя функции называть не обязан: «SPEC — не карта реализации» (`skills/spec-authoring.md:165`).
3. Проверка содержания SPEC — `scripts.guard.check_content(label, text)`; критерии раздела ищет `AC_ITEM` (`scripts/guard.py:166`), пункт без разметки вида `1. …` во всём разделе «Критерии приёмки» ловит `PLAIN_NUMBERED_ITEM` (`scripts/guard.py:169`) в функции `spec_ac_errors`. Сверка покрытия критериев тестами — `scripts.guard.traceability_errors_from_content(spec_text, meta, tested, markers)`. Строки «Поверхность решения: …» и «Размер проверки: …» внутри критерия под эти правила не попадают.
4. Скилы и шаблоны — защищённые пути (`no_paths` записи артели в `targets.yaml`): меняются только приложениями PLAN; прецедент — задача 01M5NHXJA3X7C66XTJN4J3E25W (ADR-0027, часть Б).
5. Тексты приложений ниже — дифф против `origin/main` `d87d7d7c`.

## Требуется

1. PLAN.md несёт Приложения 1–5 ниже без изменений текста; разработчик переносит их как есть.
2. Новый долгоживущий файл `tests/` закрепляет, что форма критерия по новым правилам совместима с проверками guard: SPEC, у критериев которого есть строки «Поверхность решения: …» и «Размер проверки: …» (в том числе «большой — <обоснование>»), проходит `check_content` так же, как без них; число критериев и сверка покрытия тестами `test_ac<n>_…` не меняются.
3. Ни одного изменения вне `tests/` (новые файлы) и приложений PLAN.

## Критерии приёмки

- Given ветка задачи на текущей базе с наложенными приложениями PLAN.md, When сравнить пять файлов приложений с результатом наложения Приложений 1–5 этого ТЗ на ту же базу, Then содержимое совпадает (размер проверки: средний — настоящий git во временной копии; факт задачи — разовая группа);
- Given текст SPEC в памяти с тремя критериями, у каждого — строка «Размер проверки» (малый, средний, «большой — <обоснование>»), у первого — строка «Поверхность решения: <модуль>.<имя>(<вход>) -> <выход>», When `check_content`, Then отказов нет и найдено ровно три критерия; та же SPEC без этих строк — тот же исход (Поверхность решения: scripts.guard.check_content(label, text) -> list; Размер проверки: малый);
- Given та же SPEC, где строка размера записана с ведущей цифрой и точкой (`1. Размер проверки: малый`), Then `check_content` отказывает как на пункте без AC-разметки — правила разбора не ослаблены (Поверхность решения: scripts.guard.check_content(label, text) -> list; Размер проверки: малый);
- Given та же SPEC и набор тестов `test_ac1_…`–`test_ac3_…`, When `traceability_errors_from_content`, Then каждый критерий покрыт, лишних и непокрытых нет (Поверхность решения: scripts.guard.traceability_errors_from_content(spec_text, meta, tested, markers) -> list; Размер проверки: малый);
- мутация «`PLAIN_NUMBERED_ITEM` срабатывает на строке, начинающейся со слова» — красная.

Безопасность тестов: тексты SPEC и тестов — строками в памяти; временная копия для первого критерия — во временном каталоге; каталоги задач и служебный каталог пульта не читаются и не пишутся; без сети.

Существующие тесты: правка не должна сделать красным ни один существующий тест; если краснеет тест, читающий шаблон SPEC или тексты скилов (например `tests/test_01m4rzbdfshnessbqreh5mky9b_role_templates.py`), — эскалация с именем теста, без правки.

Зоны: tests/

Приложением: skills/spec-authoring.md, templates/SPEC.md, skills/spec-audit.md, skills/test-authoring.md, skills/review-checklist.md

Только чтение: `docs/adr/0032-test-cost-and-growth.md`, `scripts/guard.py`, `tests/sandbox.py`, `tests/test_01m4rzbdfshnessbqreh5mky9b_role_templates.py`.

Не входит:
- правила guard о размерах тестов и метки `pytest.mark.size` (этап 4 ADR-0032);
- проверка guard'ом наличия строки «Размер проверки» в SPEC — проверяет аудитор SPEC;
- сводка числа больших проверок в выводе гейта SPEC — Оператор читает их в SPEC;
- правка кода пульта и существующих тестов;
- перевод существующих тестов на поверхность решения (этап 8).

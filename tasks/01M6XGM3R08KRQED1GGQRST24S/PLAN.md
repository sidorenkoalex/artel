## Подход

шаблоны — защищённые пути, поэтому правка идёт приложениями PLAN: разделы
«## Приложение 1» … «## Приложение 5» ниже перенесены из `TZ.md` задачи
байт в байт (скопированы программно от заголовка «## Приложение 1» до
конца ТЗ, не руками). Сторож совместимости формы критерия с guard —
долгоживущий файл `tests/test_01m6xgm3r08krqed1ggqrst24s_criterion_form.py`
(написал test_author, залочен перечнем сумм) — разработчиком не правится.
Новый файл `tests/` меняет карту — `docs/codebase-map.md` регенерирован
`python3 scripts/codebase_map.py` (требование 3, общая зона).

Проверено: все пять приложений, разобранные `scripts.guard.plan_appendices`,
проходят `git apply --check` на HEAD ветки `79dd269f` (база `d87d7d7c` +
только долгоживущий тест-файл, защищённых путей между ними нет).

## Влияние на систему
Меняются только тексты пяти защищённых файлов (через приложения, на мерже)
и карта. Код guard, гейты, лимиты и существующие тесты не трогаются;
правила разбора AC в `scripts/guard.py` не ослаблены — это держит AC-3/AC-5
долгоживущего файла. Шаблон SPEC получает две строки в образце критерия —
они не нумерованы и не размечены `AC-`, guard их не считает критериями
(AC-2 файла). Откат — revert merge-коммита задачи.

## Риски
- Существующий тест, читающий шаблон SPEC или скилы, может покраснеть на
  наложенных приложениях — проверено прогоном (шаг 3); при красноте —
  эскалация с именем теста, без правки.

## Предложения системе

+разработчик; тест на закрытое имя опираться не может.

+по одному на команду и класс исхода (успех, отказ): во **всех**
+состояниях задачи, где команда принимает это решение, исход команды и

+явно. Критерий подключения — средний (большой — с обоснованием).
+

+требования ТЗ, а не новое требование: правило «критерий, которого нет в
+ТЗ» их не касается.

## Вердикт
concerns — SPEC вести дальше можно, решения ниже за Оператором на гейте.

1. **Крупная причина reject теряется для аудитора с ложной подсказкой.** Треб. 4 и AC-4
   (SPEC.md, «Требования» п.4, AC-4) велят `_manifest_component`; для текста крупнее
   `CONTEXT_FILE_MAX_BYTES` (`orchestrator/config.py:519`) он отдаёт
   `context_package.render_component` (`orchestrator/context_package.py:38-44`):
   «читай {label} адресно инструментом чтения», а метка «Решение Оператора на гейте SPEC
   №k из n» — не путь, журнал БД аудитор файлом не прочтёт. SPEC не говорит, что аудитор
   получает вместо тела (например, указание на `artel.py log <id>` — команда в белом списке
   ролей, `orchestrator/artel.py:1816-1818`). Практический риск мал (причина >128 КиБ), но
   ТЗ п.3 этого не решает — решение за Оператором: принять как есть или уточнить.
2. **Оракул AC-5/AC-6 не определён.** «Побайтно совпадает с брифом, который строит код до
   изменения» (SPEC.md AC-5, AC-6): в долгоживущем тесте `tests/` кода «до изменения» нет;
   без указания оракула (зафиксированная сборка компонентов/эталон, отсутствие любой метки
   раздела и неизменность частей) критерий допускает тавтологию. Уточнение формулировки —
   на гейте или на шаге автора тестов.
3. **Треб. 4 «границы недоверенных данных» без критерия.** Ни один из AC-1…AC-7 не ловит
   компонент причины без `wrap_boundary` (`orchestrator/brief.py:395-396`): текст в брифе
   есть, порядок и дословность сохранены. Нужен критерий «тело каждого компонента внутри
   пары граничных маркеров `run_id` брифа» либо явное решение Оператора, что покрытие
   через обязательный `_manifest_component` достаточно.
4. **AC-2 не отличает треб. 2 от отбора по префиксу.** Отбор
   `actor == "operator"` + `startswith("возврат из spec_gate: ")` проходит AC-1…AC-4, хотя
   треб. 2 запрещает отбор по тексту. Сегодня эквивалентно правилу предыдущего состояния
   (единственный писатель — `orchestrator/fsm.py:1522-1524`); при желании закрыть — AC-2
   дополнить записью `state -> spec_writing` актора `operator` из другого предыдущего
   состояния с тем же префиксом.
5. **Строка матрицы на сужение проверки аудитора.** Правило скила (треб. 5) сужает то, что
   аудитор поднимает; это прямое решение Оператора (ТЗ п.4), но SPEC не фиксирует его
   строкой матрицы/«Не входит» — на гейте отметить, что сужение принято сознательно.

# ТЗ: ожидание зоны внутри пульта — `auto --wait-zone`, зависимость `after:` в SPEC, `escalated` держит зону

Источник: аудит обходных сценариев Оператора 06.09 (решение «заводи»).
За 05–06.09 внешний ожидатель зоны применялся 9 раз (сценарий
`zone_wait_auto.sh` сессии Оператора: опрос `status` раз в 90 секунд, при
свободной зоне — `auto`), потому что `auto` при отказе «ждёт зоны»
останавливается (`auto._run_zone_wait_refusal`) и цикл нужно
перезапускать руками после мержа держателя. Оба сбоя ожидателя — из
дыр самой механики: (а) `zone_lock.BLOCKING_STATES` не включает
`escalated`, и задача с уже начатым кодом на время эскалации (бюджет,
вопрос, конфликт подтяжки) отпускает зону — 06.09 07:43Z и 11:20Z две
пары задач начали править `doctor.py` параллельно, конфликт переехал на
подтяжку main; (б) порядок из ТЗ/SPEC («после мержа R2 и R3») пульт не
исполняет: зона-лок регулирует файлы, не зависимости — 06.09 «CI до
ревью» (01M1TQ0TRC) стартовала при свободном `fsm.py`, упёрлась в
залоченную планку R2 и эскалировала ($7.52 на разбор). Строки копилки
06.09 и бэклога («Ожидание зоны штатно в пульте», условие наступило:
R1 и №15 смержены).

Требуется:
1. `auto <id> --wait-zone` (и настройка по умолчанию в `config`, если
   Оператор захочет включить режим для всех): при отказе «ждёт зоны»
   цикл не останавливается, а ждёт с опросом `zone_lock.blocking_conflict`
   (интервал — константа `config.ZONE_WAIT_POLL_SEC`, порядок —
   `zone_lock.queue_order`), heartbeat lease обновляется, в журнал
   пишется одна запись на вход в ожидание («ждёт зоны <путь>: держит
   <id> (<state>)») и одна на выход («зона свободна через N мин, держал
   <id>»); потолок ожидания `config.ZONE_WAIT_MAX_SEC` — по истечении
   остановка цикла с именованной причиной (не эскалация). `status`
   показывает «ждёт зоны … N мин».
2. `escalated` считается занимающим состоянием, если в текущем
   пребывании у задачи был старт developer (то же правило, что для
   `in_dev…merge_gate`): `BLOCKING_STATES` дополняется, либо `_occupies`
   проверяет «старт developer после границы пребывания» независимо от
   состояния, кроме `done`/`killed`. Граница пребывания
   (`state -> tests_writing`) не меняется.
3. Поле SPEC `after: <id>[, <id>]` (guard: необязательное, список
   ULID существующих задач): предусловие первого шага developer — все
   перечисленные задачи в `done`/`killed`; иначе отказ «ждёт задачи
   <id> (<state>)» тем же механизмом и с тем же ожиданием (п.1), что
   зона. `new` переносит строку «Порядок: после …» из ТЗ в подсказку
   аналитику (не парсит ULID из прозы — аналитик заполняет `after:`
   сам); `doctor` — проверка циклов зависимостей между живыми задачами
   (`warn` с перечнем).
4. Тесты: (а) `auto --wait-zone` в песочнице с занятой зоной ждёт,
   после `done` держателя стартует developer, журнал несёт вход и выход
   с длительностью; потолок — остановка с причиной (мутация: потолок
   не действует — красный); (б) задача в `escalated` со стартом
   developer держит зону, без старта — нет; (в) `after:` — отказ до
   `done` зависимости, старт после; guard отказывает несуществующему
   ULID; doctor предупреждает о цикле A→B→A; (г) существующие
   `tests/test_zone_lock.py`, `tests/test_zones_gate.py`,
   `tests/test_auto*.py` зелёные без правки ассертов; каждый новый тест
   ловит заявленную мутацию.
5. `docs/operator-session.md` (раздел «Запуски и рабочие копии»,
   приложением к PLAN — документ вне защищённых путей правит
   разработчик): внешние ожидатели зон не нужны, режим `--wait-zone`.

Зоны: orchestrator/auto.py, orchestrator/zone_lock.py,
orchestrator/config.py, orchestrator/catalog.py, orchestrator/doctor.py,
scripts/guard.py, docs/operator-session.md, tests/.
Порядок: после мержа «CI до ревью» (01M1TQ0TRC, зона `auto.py`) и
разреза `doctor.py` (01M1TT9BPB) — сверить по `status`. Сигналы
деления сработают (≥5 файлов): ожидается либо монолит с обоснованием
(один узел ожидания для зон и зависимостей), либо нарезка «п.1+2 /
п.3» — решение аналитика, Оператор утвердит на гейте SPEC.

Не входит: разрез толстых файлов (01M1TT9BPB); замок на время шага
(рычаг 3 анализа 06.09, отдельный ADR).

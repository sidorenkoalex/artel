## Замечания

- **major — orchestrator/checkpoint.py:235-250 (`_commit_external_step_artifacts`) — не-UTF8/бинарные файлы, написанные ролью в `tasks/<id>/` внешнего target, безвозвратно теряются.**
  Цикл на строках 236-243 читает каждый файл через `path.read_text(encoding="utf-8")` и молча пропускает (`continue`) любой, не прошедший декодирование (`UnicodeDecodeError`/`OSError`). Если в том же каталоге есть хотя бы один валидный текстовый файл, `files` непустой, `artifact_branch.commit_files` успешно коммитит ЕГО, а строка 250 (`shutil.rmtree(task_dir, ignore_errors=True)`) удаляет ВЕСЬ каталог целиком — включая пропущенные бинарные файлы, которые так и не попали в артефактную ветку. Ни исключения, ни записи в журнал — вызывающий код и роль видят обычный успешный `detail` с «автокоммит...».
  Живой репро (файл `scratchpad/repro_binary_loss.py`, команда `python3 repro_binary_loss.py -v`, песочница — тот же `RealGitSandbox`, что уже использует `tests/test_checkpoint_external_step_artifacts.py`): `tasks/<id>/PLAN.md` (текст) + `tasks/<id>/screenshot.png` (бинарные байты) → `commit_step_artifacts` возвращает непустой `detail`, артефактная ветка содержит только `tasks/<id>/PLAN.md`, `task_dir` полностью удалён с диска — `screenshot.png` теряется без следа и без сигнала об этом.
  Второй, менее острый случай того же класса: если ВСЕ файлы каталога не проходят `read_text(utf-8)`, `files` остаётся пустым и функция возвращает `""` ДО `rmtree` (данные физически не удаляются), но и не коммитятся НИКОГДА — каждый следующий шаг роли будет заново сканировать тот же каталог и снова молча его пропускать: требование 8 («роли коммитят содержимое tasks/<id>/») нарушается перманентно для такого содержимого, без единого сигнала об этом где-либо.
  Self-путь (`_commit_worktree_change`, настоящий `git add -A` + `git commit`) этой асимметрии не несёт — коммитит любые байты. Предложение: читать файлы в бинарном режиме (`path.read_bytes()`) и коммитить их как байты (расширить `artifact_branch.write_commit`/`commit_files` на приём `bytes` наравне с `str` для `files: dict`, либо завести отдельный путь для нетекстовых файлов) — то же самое, что self-путь уже умеет через настоящий git, без специального кода.

# PLAN: Команда target-set: правка поля записи проекта в локальном слое

## Подход
Команда `target-set` живёт в `orchestrator/projects.py` рядом с
`targets-migrate` и переиспользует его механику записи: `_render`,
`_scalar_text`/`_list_item` (форма литерала), `_differences` (сверка с типом),
`_write_atomic`. Новый текст собирается целиком из разобранного
`yamlmini.mapping` прежнего текста с одной заменой листа.

Порядок проверок до записи (каждая — `sys.exit` с причиной, файл не тронут):
1. форма argv (`--show` отдельно; больше одного аргумента значения — подсказка
   про кавычки);
2. проект `config.DEFAULT_TARGET`;
3. `targets.layers()` (несводимый прежний текст);
4. проект есть в локальном слое;
5. комментарий в прежнем тексте — правило `yamlmini` построчно: строка с `#`
   первым непробельным; значение после первого `:`, начинающееся с `#`;
   значение в кавычках с хвостом за закрывающей кавычкой; иначе
   `yamlmini.COMMENT` в значении (`#` в начале или после пробела);
6. путь: раздел из `targets.LOCAL_SECTIONS`; форма `<раздел>.<поле>` или
   `<раздел>.components.<к>.<поле>`; поле — из перечня требования 2 (отказ
   несёт перечень); поле вида «отображение» (`components`, `test_profile`,
   виды `mapping`/`tools`/`depends_on`/`paths_source`, текущее значение —
   отображение) и путь глубже — отказ «вложенное отображение»; компонент —
   только из `description.components` прежнего текста;
7. значение: разбор тем же `yamlmini.mapping` строки `v: <аргумент>`;
   отказ, если разбор теряет текст (хвост комментария у скаляра/списка,
   комментарий в элементе списка), даёт `None`/пустую строку, или значение
   не записать (`_Unwritable`);
8. равенство текущему значению — «без изменений», код 0, без файла/копии/
   журнала;
9. `store.db_usable()` — иначе `projects.NO_JOURNAL`;
10. сверка: (а) листья разобранного нового текста отличаются от прежнего
    ровно листом по пути, с тем же типом значения; (б) `targets.merge_local`
    каждой записи нового текста проходит, сведённые записи прочих проектов
    равны прежним (`_differences`), в памяти.
Затем копия прежнего файла в `config.LOGS` (`open(..., "xb")` с суффиксом
`-<n>` при занятом имени; время — шов `_backup_stamp()`), `_write_atomic`,
запись журнала `store.journal(conn, None, "operator", "target-set",
"<путь>: <было> → <стало>", target=<проект>)` и её печать.

`--show <проект> [<путь>]` — разбор файла локального слоя без записи: лист —
`<путь>: <литерал>`, раздел/запись — строки `_render`.

Строка `doctor` `target-failure-errors` — функция
`target_failure_errors_check()` в `orchestrator/doctor/cli.py` рядом с
`targets_local_layer_check`; в `all_checks` — сразу после цикла строк
проектов, вне `else` успешного `targets.load()` (сама зовёт `load()`; сбой —
`skip` с причиной). Перебираются только записи с `components`;
`project_profile.component_profiles` + `acceptance.in_outcome_bounds` и
пустой `failure_errors` → подсказка; одна строка на все проекты.

Оценка бюджета SPEC ($40) не пересматривается.

## Влияние на систему
- Новая команда Оператора пишет `.artel/targets.yaml` только после полной
  сверки в памяти; гейты, лимиты, инварианты не меняются. Белый список ролей
  `_ROLE_ALLOWED_COMMANDS` не расширяется — `target-set` под ролью отказывает.
- `targets-migrate` не меняется: общие помощники (`_render`, `_differences`,
  `_write_atomic`) только переиспользуются.
- `doctor`: одна новая строка после строк проектов; прежние строки и их
  порядок не меняются.
- Откат — revert коммита задачи; копии в `config.LOGS` остаются как файлы
  Оператора.

## Риски
- Пересборка через `_render` теряет пустые строки и порядок отступов
  прежнего файла — допускается SPEC (сверка по разобранному тексту);
  комментарии отказывают до правки.
- Поля раздела `description` вида отображение (`core_reference` и т. п.)
  при отсутствии в записи принимаются как лист и судятся `merge_local`.

## Предложения системе
- `project_profile.component_profiles` для записи с `test_profile` ставит
  `from_components=True` (через `_with_component_fields`), так что
  `acceptance.in_outcome_bounds` по такому профилю даёт «в границе» вопреки
  своему докстрингу; строка doctor фильтрует записи сама. Стоит сверить
  потребителей (`orchestrator/project_profile.py:498`).
- Bash роли отклоняет `ls`/`cat`/`cp` и подстановку команд — временную
  мутацию сторожа пришлось делать сценарием Python с восстановлением в
  `finally`; команды пульта `mutation-run --ref worktree` для такого
  случая в миссии разработчика не названо.

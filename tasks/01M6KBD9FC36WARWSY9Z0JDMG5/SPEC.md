# SPEC: Команда target-set: правка поля записи проекта в локальном слое

## Контекст
Запись внешнего проекта живёт в локальном слое `.artel/targets.yaml`
(`targets.local_path`, `orchestrator/targets.py:191`; сведение слоёв —
`targets.layers`, `orchestrator/targets.py:250`; проверка значений —
`targets.merge_local`, `orchestrator/targets.py:444`). Команды пульта для
записи — только `target-init` (`orchestrator/projects.py:47`) и
`targets-migrate` (`orchestrator/projects.py:111`); команды, меняющей одно
поле записи, нет. Инцидент 04.11: задача стенда 01M6HWP40X94FYE7FS0N63VMCS
встала на выходе из `tests_writing` с отказом «честный FAIL_TO_PASS —
список «провал проверки» не задан у компонента app»
(`orchestrator/advance_gates/tests_writing.py:1300`), поле `failure_errors`
пришлось вписать в файл вручную (строка копилки 04.11, 8fa671cc). Нужна
команда правки поля с проверками и копией прежнего файла, и строка
`doctor`, которая заранее (до работы test_author) показывает компоненты в
границе отчёта без `failure_errors`.

## Требования

1. Команда `target-set <проект> <путь поля> <значение>`. Путь — через
   точку от записи проекта: `description.<поле>`,
   `description.components.<к>.<поле>`, `policy.<поле>`,
   `policy.components.<к>.<поле>`, `machine.<поле>`,
   `machine.components.<к>.<поле>`. Последний сегмент — поле.
   Значение — литерал подмножества `yamlmini`: строка, число,
   `true`/`false`, список `[a, b]`. Значение — ровно один аргумент `argv`
   после пути; аргументов значения больше одного (например, `[a, b]` без
   кавычек оболочка делит на `[a,` и `b]`) — отказ с подсказкой взять
   значение в кавычки.
2. Перечни допустимых полей:
   - разделы `description`, `policy`, `machine` — `targets.LOCAL_FIELDS`
     (`orchestrator/targets.py:349`);
   - `policy.components.<к>` — `targets.LOCAL_POLICY_SCOPES`
     (`orchestrator/targets.py:394`);
   - `description.components.<к>` — `targets.COMPONENT_FIELDS`
     (`orchestrator/targets.py:98`) без `LOCAL_POLICY_SCOPES`;
   - `machine.components.<к>` — `targets.LOCAL_MACHINE_COMPONENT_FIELDS`
     (`orchestrator/targets.py:395`).
3. Отказы `target-set` (с причиной, файл не записан):
   - проект `config.DEFAULT_TARGET` (его запись — в `targets.yaml`
     репозитория, правка — `doc-commit`);
   - проект, которого нет в локальном слое;
   - поле, которого нет в перечне раздела (требование 2), — причина несёт
     перечень допустимых полей;
   - путь во вложенное отображение (`env.X`, `tools.<инструмент>`,
     `depends_on`);
   - путь к компоненту (`description.components.<к>.<поле>`,
     `policy.components.<к>.<поле>`, `machine.components.<к>.<поле>`),
     которого нет в `description.components` записи прежнего текста (в том
     числе когда в `description` нет самого отображения `components`), —
     отказ «компонента <к> нет в записи; добавление компонентов не входит».
     Существование компонента определяет только `description.components`
     (как сверка `targets.merge_local`, `orchestrator/targets.py:539–549`):
     путь `policy.components.<к>.<поле>` или `machine.components.<к>.<поле>`
     для компонента, который есть в `description.components`, но без своего
     блока в `policy`/`machine` (или без отображения `components` в этом
     разделе), — не отказ: блок компонента создаётся с одним этим полем;
   - аргументов значения больше одного (требование 1) — отказ с подсказкой
     взять значение в кавычки;
   - значение, которое отвергает `targets.merge_local` (собственный
     проверяльщик значений не пишется);
   - значение, чей разбор `yamlmini` теряет часть текста аргумента
     (хвост комментария: аргумент `x # y` читается как `x`) или даёт пустое
     значение — `None` либо пустую строку (аргументы `""`, `~`, `null`);
   - в прежнем тексте файла есть комментарий по правилу разбора `yamlmini`
     (`orchestrator/yamlmini.py:35` — `#` в начале значения или после
     пробела; `orchestrator/yamlmini.py:126` — строка, чей первый
     непробельный символ `#`) вместе с правилом кавычек
     (`orchestrator/yamlmini.py:50`: кавычки снимаются раньше комментария;
     `yamlmini._unquote` — `orchestrator/yamlmini.py:66–87`),
     то есть любой комментарий, который пересборка через `projects._render`
     сотрёт: строка-комментарий с отступом и без, хвостовой комментарий
     после значения. `#` внутри кавычек значения (`title: "a # b"`) —
     не комментарий, отказа по этому правилу нет;
   - журнал недоступен (`store.db_usable()` ложно) — отказ до записи
     файла с текстом `projects.NO_JOURNAL`.
   Значение, равное текущему значению поля, — не отказ: команда печатает
   «без изменений», файл не пишется, копия не создаётся, записи журнала
   нет, код выхода 0.
4. Новый текст файла собирается целиком из разобранных данных через
   `projects._render` (`orchestrator/projects.py:252`).
5. Сверка в два шага до записи, иначе отказ без записи:
   (а) разобранное отображение нового текста отличается от прежнего ровно
   одним листом по указанному пути (сверка — по разобранному тексту, не по
   сведённой записи); (б) сведение слоя на новом тексте проходит без
   ошибки, сведённые записи прочих проектов равны прежним. Шаг (б)
   выполняется в памяти по образцу `projects._migrate_mismatches`
   (`orchestrator/projects.py:329–350`): разбор нового текста
   `yamlmini.mapping` и `targets.merge_local` каждой записи, сравнение с
   тем же сведением прежнего текста — без записи файла и без подмены
   `config`.
6. Перед записью прежний файл сохраняется копией в каталоге `config.LOGS` с
   уникальным именем `targets-<время UTC до секунд>[-<n>].yaml` (создание
   без перезаписи), путь копии печатается. Время для имени копии команда
   берёт только из функции-шва `projects._backup_stamp()` (без аргументов,
   возвращает текст времени UTC до секунд для имени копии) — подмена этой
   функции в тесте даёт «две правки в одну секунду». Запись нового текста —
   `projects._write_atomic` (`orchestrator/projects.py:353`).
7. После записи команда пишет в журнал пульта запись без задачи вызовом
   `store.journal(conn, None, "operator", "target-set", "<путь>: <было> →
   <стало>", target=<проект>)` (образец записи без задачи —
   `orchestrator/notes.py:414`, там без `target`; здесь `target`
   обязателен) и печатает её. Запись читается как
   «target-set: <путь>: <было> → <стало>»; `<было>` и `<стало>` — литерал
   `yamlmini` значения в той же записи, что пишет в файл `projects._render`
   (список — `[AssertionError]`); для поля, которого в записи прежнего текста
   нет, `<было>` — `(нет)`.
8. `target-set --show <проект> [<путь>]` печатает текущее значение поля или
   раздела из записи локального слоя, файл не записывается.
9. Строка `doctor` `target-failure-errors` — отдельной функцией, не в
   `project_entry_checks` (`orchestrator/doctor/project_checks.py:37`):
   одна строка с перечнем компонентов в границе отчёта (по
   `project_profile.component_profiles` и `acceptance.in_outcome_bounds`)
   с пустым `failure_errors` — `warn` с подсказкой, где значение в
   одинарных кавычках:
   `target-set <проект> description.components.<к>.failure_errors '[AssertionError]'`;
   таких нет — `ok`; локальный слой не загрузился — `skip` с причиной.
   Строка одна на все проекты (не по строке на проект). Место в
   `all_checks` (`orchestrator/doctor/cli.py:150–157`) — сразу после строк
   проектов (после цикла `for name, entry in declared.items()`), вне ветки
   `else` успешного `targets.load()`, так что `skip` достижим в настоящем
   `doctor`.
   Проверяются только записи с разделом `components:` (как
   `project_profile.with_tools`, `orchestrator/project_profile.py:434`);
   запись с `test_profile` (компонент `default`) не проверяется и `warn` не
   даёт.
10. `target-set` (в том числе `--show`) в `_ROLE_ALLOWED_COMMANDS`
    (`orchestrator/artel.py:2566`) не добавляется: под признаком роли отказ
    даёт `_refuse_if_role_restricted` (`orchestrator/artel.py:2614`).
    Команда названа в блоке команд справки `orchestrator/artel.py`.
11. Документация: `docs/operator-session.md` (раздел «Правки main только
    командами» — строка о `target-set` вместо ручной правки локального
    слоя), `docs/stack.md` (локальный слой проектов), `docs/codebase-map.md`.
12. Все тесты задачи работают с локальным слоем во временной песочнице
    (`config` подменён), никогда с настоящим локальным слоем.

## Критерии приёмки

AC-1. `target-set sandbox description.components.app.failure_errors [AssertionError]` во временном локальном слое песочницы меняет ровно это поле (разобранное отображение файла отличается от прежнего одним листом); `project_profile.component_profiles` после неё возвращает для компонента `app` новое значение `failure_errors`; копия прежнего файла лежит в `config.LOGS` песочницы под именем вида `targets-<время UTC до секунд>[-<n>].yaml`, её путь напечатан; в журнале пульта есть запись без задачи с `target=sandbox`, и она напечатана; при `failure_errors`, которого в записи прежнего текста не было, запись читается «target-set: description.components.app.failure_errors: (нет) → [AssertionError]».

AC-2. Вторая правка в ту же секунду (`projects._backup_stamp` подменена и возвращает одно и то же время) не затирает первую копию: в `config.LOGS` обе копии, первая байт в байт прежняя.

AC-3. Каждый из случаев — неизвестное поле, путь во вложенное отображение, неверное значение (отвергнутое `targets.merge_local`), проект `artel` (`config.DEFAULT_TARGET`), необъявленный в локальном слое проект, файл со строкой, начинающейся с `#`, недоступный журнал (`store.db_usable()` ложно), больше одного аргумента значения — даёт отказ с причиной, файл локального слоя байт в байт прежний, и копии в `config.LOGS` нет; отказ по неизвестному полю называет перечень допустимых полей, отказ по журналу — текст `projects.NO_JOURNAL`, отказ по лишним аргументам — подсказку взять значение в кавычки.

AC-4. Значение, которое `yamlmini` прочитал бы иначе, чем задано, — отказ, файл локального слоя байт в байт прежний (по образцу проверок `orchestrator/projects.py:275–304`). Примеры: значение `[1.5]` и, отдельным случаем, строка с кавычками обоих видов (`'` и `"`). Отдельными случаями — аргумент значения `x # y` (разбор `yamlmini` теряет часть текста) и аргумент `""` (пустое значение): отказ с причиной, файл локального слоя байт в байт прежний.

AC-5. Правка `machine.path` проходит: поле меняется, отказа нет.

AC-6. `target-set --show <проект> [<путь>]` печатает текущее значение поля или раздела записи локального слоя; файл локального слоя после неё байт в байт прежний, копии в `config.LOGS` не появляется.

AC-7. Под признаком роли `target-set` и `target-set --show` отказывают.

AC-8. Строка `doctor` `target-failure-errors` даёт `warn` с подсказкой `target-set <проект> description.components.<к>.failure_errors '[AssertionError]'` для компонента в границе отчёта без `failure_errors`, `ok` — после `target-set` этого поля, `skip` с причиной — при незагружаемом локальном слое; запись с `test_profile`, у которого задан `report`, `warn` не даёт; компонент без `report` с пустым `failure_errors` в перечень `warn` не входит; два компонента в границе отчёта без `failure_errors` — оба названы в одной строке. В выводе `all_checks` строка одна на все проекты и стоит сразу после строк проектов; при незагружаемом локальном слое она в `all_checks` есть со `skip`.

AC-9. Прежний текст файла с хвостовым комментарием после значения (`поле: значение  # …`) и, отдельным случаем, со строкой-комментарием с отступом — отказ с причиной, файл локального слоя байт в байт прежний, копии в `config.LOGS` не появляется. Прежний текст, где `#` стоит только внутри кавычек значения (`title: "a # b"`), — отказа по комментарию нет, правка другого поля проходит, значение `a # b` после неё прежнее.

AC-10. Путь к компоненту, которого нет в `description.components` записи (`description.components.<к>.<поле>`, `policy.components.<к>.<поле>`, `machine.components.<к>.<поле>`), в том числе при записи без отображения `components` в `description`, — отказ «компонента <к> нет в записи; добавление компонентов не входит», файл локального слоя байт в байт прежний. Путь `policy.components.<к>.<поле>` или `machine.components.<к>.<поле>` для компонента, который есть в `description.components`, но без своего блока в `policy`/`machine`, — не отказ: блок компонента создаётся с одним этим полем.

AC-11. Значение, равное текущему значению поля, — печать «без изменений», код выхода 0, файл локального слоя байт в байт прежний, копии в `config.LOGS` нет, новой записи журнала нет.

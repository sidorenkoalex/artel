# SPEC: Клон проекта получает ссылки документов задач; doctor не шумит на свежем клоне

## Контекст
После сдвига пина на этап 2 ADR-0021 клон проекта
(`orchestrator/workspace.py::ensure_clone`) заводится без ссылок
`refs/artifacts/*`: `git clone` их не приносит, отдельного fetch нет.
Ссылки появляются в клоне только после явных `docs <id>` /
`docs --fetch-all` (`orchestrator/docs_fetch.py`,
`orchestrator/artifact_branch.py::fetch_all_from_origin`). Поэтому
проверка `artifact-ref-sync` (`orchestrator/doctor/artifact_branches.py`)
на свежем клоне выдаёт по предупреждению на каждую закрытую задачу
(«голова (нет локально)»), хотя в origin ссылка совпадает с коммитом
закрытия (прецедент 04.10 — 12 ложных предупреждений). А
`_fix_unsent_closed_refs` молча пропускает закрытую задачу, если в клоне
нет её локальной ссылки, — коммит закрытия 854edaaa задачи
01M42NB9GKXNP74HAYEJ7C7CA8 жил только в git главной копии, и Оператор
досылал его в origin руками. Вдобавок в `doctor --fix` досылка идёт
раньше заведения клонов (`orchestrator/doctor/cli.py`).

## Требования

1. Когда `workspace.ensure_clone` ЗАВОДИТ клон (каталога клона не было —
   вызовы из `init`, `doctor --fix`, `new` и все прочие), после успешного
   `git clone` он приносит в клон все `refs/artifacts/*` из origin тем же
   узлом, что `docs --fetch-all` (`artifact_branch.fetch_all_from_origin`):
   локальная ссылка сдвигается только вперёд, без перезаписи. Неудача
   этого fetch не отменяет заведение клона и не превращает исход
   `ensure_clone` в отказ; причина неудачи выводится одной строкой.
   Поведение `ensure_clone` для уже существующего каталога клона не
   меняется.
2. `artifact-ref-sync` различает два случая для закрытой задачи с
   записью о коммите закрытия:
   - локальной ссылки в клоне нет, а в origin ссылка равна коммиту
     закрытия — это НЕ предупреждение и не строка на задачу. Решение
     SPEC: такие задачи не попадают в список проблем; их число
     называется в итоговой строке проверки вместе с подсказкой
     `docs --fetch-all` (одна строка на прогон, в том числе когда рядом
     есть настоящие предупреждения по другим задачам — тогда отдельной
     строкой статуса `ok`/информационной, не `warn`);
   - всё остальное (локальная голова есть и ≠ коммиту закрытия; в origin
     ссылки нет или она ≠ коммиту закрытия) — по-прежнему
     предупреждение по строке на задачу.
3. `_fix_unsent_closed_refs` для закрытой задачи, у которой ссылка в
   origin ≠ коммиту закрытия, а объекта коммита закрытия в клоне нет,
   ищет этот объект в git главной копии пульта (переходный период этапа
   2) и, найдя, досылает его в origin репозитория задачи продвижением
   ссылки `refs/artifacts/<id>` без force (отказ origin принять
   непродвигающий push — строка `[FIX]` с id задачи о том, что коммит не
   дослан). Объекта нет ни в клоне, ни в главной копии — строка
   предупреждения `[FIX]` с id задачи и коммитом закрытия, не молчание.
   Поиск в главной копии — только для задач target'а артели (ссылки
   внешних проектов вне их клона — вне задачи, см. «Не входит»); у задачи
   внешнего проекта без объекта в клоне — та же строка предупреждения.
   Прежнее поведение сохраняется: ссылка в origin уже равна коммиту
   закрытия — ничего не делается; локальная голова в клоне есть, объект
   есть, но голова ≠ коммиту закрытия — не досылается.
4. Порядок шагов `doctor --fix`: заведение клонов проектов
   (`_fix_project_clones`) выполняется ДО досылки закрытых ссылок
   (`_fix_unsent_closed_refs`); обе — до `all_checks`.
5. Тесты в `tests/` на требования 1–4 несут заявки «Ловит мутацию»;
   долгоживущие приёмочные тесты этой задачи (`tests/test_<id>_*.py`)
   засчитываются, дублировать их отдельными тестами не нужно.

## Критерии приёмки

AC-1. `ensure_clone(target)` при отсутствующем каталоге клона и origin,
несущем `refs/artifacts/<id>` для нескольких задач, после возврата без
причины отказа оставляет в клоне локальные `refs/artifacts/<id>` с теми же
sha, что в origin.

AC-2. Повторный `ensure_clone(target)` при существующем каталоге клона не
выполняет fetch ссылок документов и не меняет локальные
`refs/artifacts/*` (в том числе локальную ссылку, ушедшую вперёд origin).

AC-3. Если fetch `refs/artifacts/*` при заведении клона не удался,
`ensure_clone` возвращает путь клона без причины отказа, каталог клона
остаётся на месте, а в вывод попадает строка с причиной неудачи fetch.

AC-4. `check_artifact_ref_sync` для закрытой задачи без локальной ссылки
в клоне, у которой ссылка в origin равна коммиту закрытия, не выдаёт
`warn`-строку с id этой задачи; число таких задач и подсказка
`docs --fetch-all` присутствуют в одной строке результата проверки,
статус которой не `warn`.

AC-5. При нескольких закрытых задачах из AC-4 и одной задаче с настоящим
расхождением (ссылка в origin ≠ коммиту закрытия) `check_artifact_ref_sync`
выдаёт ровно одну `warn`-строку — по задаче с расхождением — и одну
строку-сводку по задачам из AC-4.

AC-6. `_fix_unsent_closed_refs` для закрытой задачи артели, у которой в
origin ссылки нет, в клоне нет объекта коммита закрытия, а в git главной
копии он есть, оставляет в origin `refs/artifacts/<id>`, равную коммиту
закрытия; досылка выполняется без force (непродвигающее обновление
ссылки в origin отклоняется и даёт строку `[FIX]` с id задачи о
недосланном коммите, ссылка в origin не меняется).

AC-7. `_fix_unsent_closed_refs` для закрытой задачи, чьего коммита
закрытия нет ни в клоне, ни в главной копии, а ссылка в origin ≠ ему,
печатает строку `[FIX]`, содержащую id задачи и коммит закрытия.

AC-8. `cmd_doctor(fix=True)` вызывает `_fix_project_clones` раньше
`_fix_unsent_closed_refs`, и оба — раньше `all_checks`.

AC-9. Тесты в `tests/`, покрывающие AC-1…AC-8, несут заявки «Ловит
мутацию».

## Оценка объёма и деление

Прогноз диффа: 25 КиБ (код — `orchestrator/workspace.py`,
`orchestrator/doctor/artifact_branches.py`, `orchestrator/doctor/cli.py`;
остальное — тесты и регенерация карты); это ниже половины потолка гейта
ёмкости.

Сработавший сигнал: «зона задевает механизм, на который опирается запись
в `docs/invariants.md`» — зона ТЗ задана каталогом `orchestrator/`
целиком, фактически правка ограничена тремя модулями выше; критериев 9,
бюджет — планка калибровки.

Предложение — **монолит**. Требования связаны одной цепочкой поведения
`doctor --fix` на свежем клоне: заведение клона приносит ссылки (тр. 1)
→ досылка закрытых ссылок видит их и опирается на главную копию для
недостающих объектов (тр. 3) → порядок шагов ставит заведение клона до
досылки (тр. 4) → сверка не шумит на оставшихся случаях (тр. 2).
Отдельно смерженный порядок шагов без тр. 1 ничего не меняет, а тр. 2
без тр. 1 маскирует подсказкой поведение, которое тр. 1 и устраняет;
каждая часть по отдельности — меньше одного шага разработчика при
накладных расходах на отдельный цикл задачи (~$25 планки на каждую).
Решение утверждает Оператор на гейте SPEC.

## Не входит

- Дополнение ссылками уже существующего клона (`ensure_clone` его не
  трогает; для него — подсказка `docs --fetch-all` из требования 2).
- Уборка старых каталогов `.artel/worktrees/`, `.artel/notes-work`,
  `workspace/`.
- Ссылки документов внешних проектов вне их клона (в том числе поиск их
  коммитов закрытия в главной копии).
- Сверка живых задач в `artifact-ref-sync` — без изменений.
- Правка путей только для чтения по ТЗ: docs/adr/, docs/roadmap.md,
  docs/backlog.md, docs/operator-session.md, templates/, skills/,
  CLAUDE.md, models.yaml, roles.yaml, scripts/guard.py,
  .github/workflows/ci.yml, conftest.py, tests/test_invariants.py,
  docs/invariants.md.
- Неослабление существующих тестов — держит гейт неослабления тестов
  пульта; полный зелёный `tests/` и CI ветки — держит пульт.

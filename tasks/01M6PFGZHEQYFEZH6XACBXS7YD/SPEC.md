# SPEC: reject --decision: отказ на нецифровом номере решения и форма --decision=<файл>

## Контекст
Независимая проверка приёмки задачи 01M6KB0SJHDA4D4GNEM7PGZ40P (копилка
04.11) нашла два дефекта, оба подтверждены по коду main:

- `orchestrator/spec_gate_decision.py:186-189` (`parse`) проверяет номер
  подраздела «### Решение <n>» через `str.isdigit()`, затем зовёт `int()`.
  Для надстрочных и прочих цифр Юникода `isdigit()` истинно, а `int()`
  падает: «### Решение ²» даёт `ValueError` с трассировкой вместо
  `DecisionError`. Полноширинные цифры («３») `int()` принимает, и отказ
  звучит как «не по порядку», хотя номер не из цифр 0–9.
- `orchestrator/artel.py:2653-2675` (`_cmd_reject`) распознаёт только
  `--decision <файл>` двумя аргументами. `--decision=<файл>` уходит в
  `fsm.cmd_reject` позиционной причиной: задача возвращается аналитику с
  текстом «--decision=<путь>» и предупреждением `fsm.SPEC_GATE_TEXT_WARNING`,
  файл решения не читается.

## Требования
1. Номер подраздела «### Решение <n>» в `spec_gate_decision.parse` — только
   цифры ASCII `0-9`. Любой другой номер, в том числе цифры Юникода вне
   ASCII (надстрочные, полноширинные, арабско-индийские), — `DecisionError`
   с прежним текстом нецифрового номера «номер подраздела «### Решение
   <номер>» — не целое», без трассировки; команда `reject --decision`
   завершается прежним отказом файла решения, задача остаётся в
   `spec_gate`, журнал — как у прочих отказов файла.
2. `reject <id> --decision=<файл>` равносильна `reject <id> --decision
   <файл>`: тот же разбор, те же проверки и те же отказы.
3. Значение формы с «=» проверяется тем же правилом, что значение формы
   через пробел: пустое значение (`--decision=`) и значение, начинающееся
   с `--` (`--decision=--x`), — прежний отказ «`--decision` без значения»
   до lease и журнала. Правило едино для обеих форм: пустой аргумент
   значения через пробел (`--decision ""`) — тот же отказ «без значения»
   до lease и журнала, а не вызов `fsm.cmd_reject`. Значение берётся по
   первому «=»: `--decision=a=b.md` — файл `a=b.md`.
4. Ключом считается только аргумент, равный `--decision`, или аргумент,
   начинающийся с `--decision=`. Два и более ключа в любой форме и в любом
   сочетании (`--decision <a> --decision <b>`, `--decision=<a> --decision
   <b>`, `--decision <a> --decision=<b>`, `--decision=<a> --decision=<b>`,
   `--decision --decision=<b>`) — отказ до lease и журнала, текст которого
   содержит фрагмент «ключ --decision повторён». Порядок проверок
   закреплён: сначала повтор ключа, затем отсутствие значения
   (требование 3), затем позиционная причина;
   для двух ключей через пробел это меняет прежний текст «не сочетается с
   позиционной причиной» на «повторён», сам отказ сохраняется. Сочетание
   одного ключа `--decision=<файл>` с позиционной причиной (в любом
   порядке) — отказ до lease и журнала с прежним текстом о несочетаемости,
   содержащим фрагмент «не сочетается с позиционной причиной».
5. Позиционная причина, не начинающаяся с `--decision`, разбирается как
   сейчас. Аргумент, который начинается с `--decision`, но не равен
   `--decision` и не начинается с `--decision=` (например, `--decisions`),
   ключом не считается и разбирается как сейчас — позиционной причиной.
6. Строку синтаксиса `reject` в справке команд можно дополнить формой с
   «=»; прежняя форма `reject <id> --decision <файл>` в справке остаётся.

Шов подмены и имена для тестов (из ТЗ): `orchestrator.artel._cmd_reject`,
`orchestrator.artel.DECISION_FLAG`, `orchestrator.fsm.cmd_reject`
(подменяется в тестах разбора аргументов),
`orchestrator.spec_gate_decision.parse`,
`orchestrator.spec_gate_decision.DecisionError`.

## Критерии приёмки
AC-1. `spec_gate_decision.parse` на файле решения, заголовок подраздела
которого «### Решение ²», поднимает `DecisionError`, текст которого
содержит «не целое», а не `ValueError`; намеренная мутация «возврат к
`isdigit()`» делает этот критерий красным.

AC-2. `spec_gate_decision.parse` на файлах с заголовком «### Решение ３» и
отдельно «### Решение ١» поднимает `DecisionError` с текстом «не целое»
(не «не по порядку» и не `ValueError`).

AC-3. `spec_gate_decision.parse` на файле с подразделами «### Решение 1» …
«### Решение 3» возвращает прежний результат (номера 1, 2, 3 и их поля).

AC-4. `_cmd_reject(["<id>", "--decision=<путь>"])` вызывает
`fsm.cmd_reject` с `decision_file="<путь>"` и пустой причиной — так же,
как `_cmd_reject(["<id>", "--decision", "<путь>"])`. Путь со знаком «=»:
`_cmd_reject(["<id>", "--decision=a=b.md"])` вызывает `fsm.cmd_reject` с
`decision_file="a=b.md"`.

AC-5. `_cmd_reject(["<id>", "--decision="])`, `_cmd_reject(["<id>",
"--decision=--x"])` и `_cmd_reject(["<id>", "--decision", ""])`
завершаются отказом с текстом «без значения»; `fsm.cmd_reject`
(подменён) не вызван.

AC-6. `_cmd_reject` на `["<id>", "--decision=<путь>", "причина"]` и
`["<id>", "причина", "--decision=<путь>"]` завершается отказом, текст
которого содержит «не сочетается с позиционной причиной»;
`fsm.cmd_reject` (подменён) не вызван. `_cmd_reject` на каждом из пяти сочетаний двух
ключей — `["<id>", "--decision", "<a>", "--decision", "<b>"]`, `["<id>",
"--decision=<a>", "--decision", "<b>"]`, `["<id>", "--decision", "<a>",
"--decision=<b>"]`, `["<id>", "--decision=<a>", "--decision=<b>"]`,
`["<id>", "--decision", "--decision=<b>"]` — завершается отказом, текст
которого содержит «ключ --decision повторён»; `fsm.cmd_reject` (подменён)
не вызван. Порядок проверок (требование 4): `["<id>", "--decision=",
"причина"]` — отказ с текстом «без значения» (не «не сочетается»);
`["<id>", "--decision=<a>", "--decision=", "причина"]` — отказ с текстом
«ключ --decision повторён»; в обоих случаях `fsm.cmd_reject` не вызван.

AC-7. `_cmd_reject(["<id>", "причина"])` и прежние формы с `--decision
<файл>` ведут себя как до задачи (те же аргументы `fsm.cmd_reject`, те же
отказы; для сочетаний двух ключей из AC-6 проверяется только сам отказ,
текст — по AC-6). `_cmd_reject(["<id>", "--decisions"])` вызывает
`fsm.cmd_reject` с причиной «--decisions».

AC-8. Сквозной случай во временной песочнице пульта (`tests/sandbox.py`):
задача на `spec_gate`, `reject <id> --decision=<файл>`, где `<файл>` —
абсолютный путь к корректному файлу по `templates/SPEC-GATE-DECISION.md`,
даёт тот же переход и ту же запись журнала, что форма через пробел;
предупреждения `SPEC_GATE_TEXT_WARNING` в выводе нет.

AC-9. Сквозной случай в той же песочнице: `reject <id> --decision <файл>`
с заголовком «### Решение ²» — отказ файла решения: ненулевой выход,
задача остаётся в `spec_gate`, число записей возврата в журнале задачи
прежнее (как `assert_refused` в
`tests/test_01m6kb0sjhda4d4gnem7pgz40p_decision_reject.py:178-185`), в
выводе нет `Traceback`; проброшенный из `parse` `ValueError` делает
критерий красным.

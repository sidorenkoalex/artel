# reject --decision: отказ на нецифровом номере решения и форма --decision=<файл>

## Факты

1. `orchestrator/spec_gate_decision.py:186-189` (`parse`) проверяет номер подраздела «### Решение <n>» через `str.isdigit()`, затем вызывает `int()`. Для надстрочных и прочих цифр Юникода `isdigit()` истинно, а `int()` падает: заголовок «### Решение ²» даёт `ValueError` с трассировкой вместо именованного отказа `DecisionError`. Полноширинные цифры («３») `int()` принимает, и отказ звучит как «не по порядку», хотя номер не из цифр 0–9.
2. `orchestrator/artel.py:2653-2675` (`_cmd_reject`) распознаёт только `--decision <файл>` двумя аргументами. Форма `--decision=<файл>` в список ключей не попадает и уходит в `fsm.cmd_reject` позиционной причиной: задача возвращается аналитику с текстом «--decision=<путь>» и одним предупреждением `fsm.SPEC_GATE_TEXT_WARNING` («решение без сверки следствий»), файл решения не читается.
3. Обе находки — независимая проверка приёмки задачи 01M6KB0SJHDA4D4GNEM7PGZ40P (копилка 04.11).

## Требуется

1. Номер подраздела «### Решение <n>» — только цифры ASCII `0-9`. Любой другой номер, в том числе цифры Юникода вне ASCII, — `DecisionError` «номер подраздела «### Решение <номер>» — не целое» (тот же текст, что сейчас у нецифрового номера), без трассировки; команда завершается прежним отказом файла решения, задача остаётся в `spec_gate`, журнал — как у прочих отказов файла.
2. `reject <id> --decision=<файл>` равносильна `reject <id> --decision <файл>`: тот же разбор, те же проверки и те же отказы.
3. `--decision=` с пустым значением — прежний отказ «`--decision` без значения» до lease и журнала. Сочетание формы с «=» с позиционной причиной или со вторым ключом `--decision` в любой форме — отказ до lease и журнала с прежним текстом о несочетаемости (для двух ключей — с указанием, что ключ повторён).
4. Позиционная причина, не начинающаяся с `--decision`, разбирается как сейчас.

Шов подмены и имена для тестов: `orchestrator.artel._cmd_reject`, `orchestrator.artel.DECISION_FLAG`, `orchestrator.fsm.cmd_reject` (подменяется в тестах разбора аргументов), `orchestrator.spec_gate_decision.parse`, `orchestrator.spec_gate_decision.DecisionError`.

Критерии приёмки:
- `parse` на файле, заголовок которого «### Решение ²» (и отдельно «### Решение ３», «### Решение ١»): `DecisionError` с текстом «не целое», не `ValueError`; намеренная ошибка «возврат к `isdigit()`» делает критерий для «²» красным;
- `parse` на файле с «### Решение 1» … «### Решение 3» — прежний результат;
- `_cmd_reject(["<id>", "--decision=<путь>"])`: `fsm.cmd_reject` вызван с `decision_file="<путь>"` и пустой причиной — так же, как для `["<id>", "--decision", "<путь>"]`;
- `["<id>", "--decision="]`: выход с отказом «без значения», `fsm.cmd_reject` не вызван;
- `["<id>", "--decision=<путь>", "причина"]`, `["<id>", "причина", "--decision=<путь>"]`, `["<id>", "--decision=<a>", "--decision", "<b>"]`: выход с отказом, `fsm.cmd_reject` не вызван;
- `["<id>", "причина"]` и прежние формы с `--decision <файл>` — прежнее поведение;
- сквозной случай в песочнице пульта: задача на `spec_gate`, `reject <id> --decision=<файл>` с корректным файлом по `templates/SPEC-GATE-DECISION.md` — тот же переход и та же запись журнала, что для формы через пробел; предупреждения `SPEC_GATE_TEXT_WARNING` нет;
- существующие тесты `reject` и файла решения зелёные без правки.

Безопасность тестов: временная песочница пульта (`tests/sandbox.py`); без сети и клиента модели; настоящие `tasks/` и `.artel/` не трогаются.

Существующие тесты: правка не должна сделать красным ни один существующий тест; если краснеет — эскалация с именем теста, без правки.

Зоны: `orchestrator/spec_gate_decision.py` (`parse`), `orchestrator/artel.py` (`_cmd_reject`), `docs/codebase-map.md`, `tests/` (долгоживущие файлы задачи).

Только чтение: `orchestrator/fsm.py`, `templates/SPEC-GATE-DECISION.md`, `docs/operator-gates.md`, `.artel/`, `tasks/`.

Не входит:
- форма `--ключ=значение` для прочих команд пульта;
- правка шаблона `templates/SPEC-GATE-DECISION.md` и текста справки команд, кроме строки синтаксиса `reject`, если её нужно дополнить формой с «=».

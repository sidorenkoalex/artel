# ANSWER-1: удаление тестов снятого механизма — с заменами; наложение отменяется для всех проектов

## Ответы

1. **A — с условиями.** Тесты механизма, который задача удаляет,
   удаляются вместе с ним. Удаление разрешено только при выполнении
   требований-замен ниже: независимая сверка Оператора 11.10 показала,
   что часть свойств этих тестов после изменения остаётся в пульте и без
   замен осталась бы без проверки — это было бы ослабление.

   Ослабление тестов разрешено: tests/test_fsm_retro.py, tests/test_main_ci_line.py::GuardAllLaunchTest::test_task_retro_does_not_hide_snapshot_violation, tests/test_plan_appendix.py::MergeAppendixTest::test_appendix_commit_precedes_the_artifact_snapshot
   Основание: ADR-0021 этап 4 / решение Оператора 11.10.2026 — механизм (наложение снимка и коммит RETRO в main) удаляется задачей; удаление только при тестах-заменах п.1а–1ж этого ответа.

   Расширение зон разрешено: orchestrator/snapshot.py

   В `test_plan_appendix.py` утверждение «есть коммит снимка» меняется на
   «коммита снимка нет» разделом «Меняемое поведение»; удаляется только
   `assertLess(applied[0], snapshot[0])`.

   SPEC обязан потребовать (каждое — отдельный критерий приёмки с тестом
   на настоящем git там, где сказано):
   а) Строка `fsm_postmerge.APPENDICES_RETRO_PREFIX` с путями применённых
      приложений PLAN попадает в `tasks/<id>/RETRO.md` коммита закрытия
      `refs/artifacts/<id>`, когда приложения были; без приложений текст
      RETRO прежний. Проверка — через `_cmd_approve_merge_gate`, RETRO
      читается из `refs/artifacts/<id>` на origin (требование 6 SPEC
      01M2YSHDKWFJN3XSJ618Z74FNF не должно перестать исполняться).
   б) RETRO закрытия несёт sha мержа задачи (не голову пульта), как
      сегодня `docs/retro/<id>.md`.
   в) Провал коммита закрытия по любой причине (нет ссылки, расхождение
      фиксации, git не ответил, исключение в `retro.build_done` или
      `retro.build_killed`) не отменяет переход и уборку задачи и поднимает
      инцидент с target этой задачи — по тесту на каждую причину (замена
      проверок «сбой → инцидент» из `test_fsm_retro.py`).
   г) Ликвидированная задача без RETRO на своей ссылке документов видна
      Оператору (инцидент или `doctor`), либо SPEC явно называет, что
      заменяет механизм долгов; молча RETRO не пропадает.
   д) Проверка посторонних файлов документов задачи идёт по дереву
      `refs/artifacts/<id>` на зафиксированной голове — до push и до
      коммита закрытия, без освобождения задачи по наличию
      `docs/retro/<id>.md` в main или `RETRO.md` в ссылке. Тест (замена
      удаляемого из `test_main_ci_line.py`): стенд, где такой файл есть,
      а посторонний файл всё равно даёт отказ мержа.
   е) Недоступная или нечитаемая ссылка документов на этой проверке —
      отказ мержа, а не пропуск проверки (строже нынешнего наложения,
      которое при сбое материализации проверяло пустой каталог).
   ж) Вместо удаляемого `assertLess`: коммит приложений PLAN стоит после
      коммита мержа и до коммита карты кодовой базы (если карта есть), и
      `guard --all` видит дерево уже с приложениями — перестановка
      `_apply_plan_appendices` за `_guard_all_or_refuse` или за
      вычисление sha для push даёт красный тест.

2. **B — по ADR-0021 п.4.** Наложение снимка `tasks/<id>/` на main
   отменяется для всех проектов, внешних тоже: в main проекта не должны
   попадать каталоги документов задач. Проверка п.1д действует для всех
   проектов. Требование 5 ТЗ читать как «прочее в мерже внешнего проекта
   не меняется» (карта, RETRO, `guard --all` — как сегодня, то есть у
   внешнего их нет). Ошибка в «Фактах» ТЗ — моя, ADR здесь главнее.
   Критерий: мерж задачи внешнего проекта в песочнице — в main проекта
   нет коммита снимка и каталога `tasks/<id>/`, посторонний файл
   документов задачи даёт отказ.

Бюджет задачи — $100 (решение Оператора 11.10); объём с заменами в него
укладывается.

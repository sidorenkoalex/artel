## Влияние на систему

- `role_env` — точка, которую зовут ВСЕ агентские шаги всех ролей
  (`run_agent_once`). Сужение PATH/переменных — поведенческое изменение с
  риском регресса: любой инструмент, которым реально пользуется роль внутри
  шага (например, `python3 -m unittest` из скилов) и который раньше находился
  через унаследованный PATH Оператора, обязан резолвиться и через манифест
  — иначе роль тихо потеряет доступ к нему в проде. В манифесте части 1 уже
  объявлены ровно `python3`/`git`/`gh`/`claude` — тот же набор, что называет
  требование 1 этой SPEC; сверх этого роли ничего не нужно (bash-скилы зовут
  только `git`/`python3`, `--allowedTools` в `role_cmd` и так ограничивает
  Bash этими двумя). Откат — вернуть `env = dict(os.environ)` одной строкой,
  git-история хранит прежнюю реализацию.
- Белый список переменных — тоже сужение периметра роли: любая переменная,
  на которую сегодня неявно полагается CLI `claude` (кроме уже названных
  SPEC) и которая не в списке, перестанет доходить до роли. Список собран из
  требования 2 SPEC буквально (HOME, CLAUDE_CONFIG_DIR, git-идентичность,
  токен роли, LANG/LC_*, TMPDIR, TERM) плюс `ANTHROPIC_API_KEY` — тот же
  альтернативный канал токена, что `role_env` уже поддерживает `setdefault`
  ниже по функции (не новая переменная, а перечисление уже используемой).
  Не расширяю список сверх этого — не входит в объём задачи (SPEC «Не
  входит»: смена CLI роли, права инструментов).
- Существующие тесты `role_env` (T019 `RoleEnvTest`, T020 инварианты)
  заменяются планкой T023 без ослабления — планка сама содержит
  `AC-14: manual` пометку (полный прогон `tests/` — дело CI, не шага), беру
  на слово test_author и прогоняю затронутые модули (`test_multitarget.py`,
  `test_multitarget_invariants.py`) напрямую в шаге.
- Снятие хука `bash_guard.py` полагается на «сторож зависших прогонов»
  (группа процессов, 01M1PNBSHR2PMFECMP7C204MF1) как замену безопасности —

  остаётся текстом `skills/coding-standards.md`, не enforced хуком — по

## Риски

- Реальный прогон роли на этой ветке (для ручной проверки) зависит от
  `shutil.which` в среде Оператора реально находящей `git`/`gh`/`claude` —
  если у Оператора один из них отсутствует в PATH, шаг других задач на этом
  пульте перестанет стартовать (AC-6/AC-8 — это ЦЕЛЬ задачи, не баг, но
  стоит явно предупредить при мерже).
- `check_role_home_diff` читает файлы побайтово рекурсивно — на большом
  дереве референса (сейчас 3 файла) это дёшево; если референс вырастет на
  порядки, стоимость проверки в `doctor` вырастет линейно — не предмет этой
  задачи.

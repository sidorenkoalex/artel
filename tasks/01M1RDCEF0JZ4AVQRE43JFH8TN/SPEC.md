# SPEC: объявленный стек пульта, часть 3 — окружение роли из манифеста, снятие временного хука

## Контекст
`orchestrator/runner.role_env` строит окружение роли копией `os.environ`
Оператора: весь его PATH (pyenv/shim'ы) и переменные его сессии. Роль
видит инструменты, которых у проекта нет (pytest из pyenv — 217 логов
шагов), а воспроизводимость шага зависит от машины Оператора. Временная
мера 05.09 — PreToolUse-хук `bash_guard.py`, отклоняющий полный прогон
`tests/` внутри шага, — симптоматическая и снимается этой задачей по
решению Оператора: инструмент, которого нет в мире роли, запрещать
незачем. Завершает серию «объявленный стек» (части 1–2, разбор 05.09,
роадмап §4 п.8).

## Требования
1. `role_env` строит PATH роли только из каталогов абсолютных путей
  объявленных в манифесте инструментов (`python3`, `git`, `gh`,
  `claude`), разрешённых через `shutil.which` ОДИН раз при старте шага
  в окружении пульта, а не копированием PATH Оператора. Интерпретатор
  роли — тот же `python3`, что у пульта (`sys.executable`), не первый
  `python3` из собранного PATH.
2. `role_env` передаёт роли переменные окружения только по явному
  белому списку (HOME, CLAUDE_CONFIG_DIR, git-идентичность, токен роли,
  LANG/LC_*, TMPDIR, TERM, переменные, нужные CLI `claude`) — список
  объявлен в манифесте, у каждой переменной есть причина. Остальные
  переменные `os.environ` Оператора роли не передаются.
3. Отсутствие любого объявленного инструмента (`shutil.which` не
  находит абсолютный путь) — шаг не стартует: попытка агента не
  запускается, в журнал шага пишется `agent run SKIPPED` с именованной
  причиной (по образцу уже существующей записи «окружение роли не
  подготовлено»), без тихого отката на PATH/переменные Оператора.
4. Временный хук снимается: удаляются
  `docs/reference/role-home/claude/hooks/bash_guard.py`, запись
  `hooks.PreToolUse` из `docs/reference/role-home/claude/settings.json`
  (поле `permissions.deny` остаётся без изменений) и
  `tests/test_role_bash_guard.py`; `docs/reference/role-home.md` не
  несёт больше упоминаний снятого хука.
5. `doctor` предупреждает (WARN, без автоправки), если развёрнутый
  `.artel/home/.claude/` отличается от референса
  `docs/reference/role-home/claude/` — с перечнем отличающихся файлов
  в тексте предупреждения.

## Критерии приёмки
AC-1. `role_env` строит PATH роли только из каталогов, где абсолютные
пути объявленных в манифесте инструментов (`python3`, `git`, `gh`,
`claude`) находит `shutil.which` — не копирует PATH Оператора целиком.

AC-2. Абсолютные пути инструментов разрешаются через `shutil.which`
ровно один раз при старте шага, в окружении пульта (до подмены HOME
роли).

AC-3. Интерпретатор роли — `sys.executable` пульта, не первый `python3`,
найденный в собранном PATH роли.

AC-4. `role_env` передаёт роли только переменные окружения из явного
белого списка (HOME, CLAUDE_CONFIG_DIR, git-идентичность, токен роли,
LANG/LC_*, TMPDIR, TERM, переменные CLI `claude`) — переменные
`os.environ` Оператора вне этого списка роли не передаются.

AC-5. Белый список переменных окружения роли объявлен в манифесте, у
каждой переменной в списке — причина, зачем она роли нужна.

AC-6. Отсутствие любого объявленного инструмента (`shutil.which` не
находит путь) — попытка агента не запускается.

AC-7. В этом случае в журнал шага пишется запись `agent run SKIPPED` с
именованной причиной по образцу «окружение роли не подготовлено».

AC-8. Отсутствие инструмента не приводит к тихому откату окружения роли
на PATH/переменные Оператора — шаг не подменяет источник окружения
запасным путём.

AC-9. Файл `docs/reference/role-home/claude/hooks/bash_guard.py`
удалён.

AC-10. Запись `hooks.PreToolUse` удалена из
`docs/reference/role-home/claude/settings.json`; поле
`permissions.deny` остаётся без изменений.

AC-11. Файл `tests/test_role_bash_guard.py` удалён.

AC-12. `docs/reference/role-home.md` не содержит упоминаний снятого
хука (`bash_guard.py`, `PreToolUse`).

AC-13. `doctor` выдаёт WARN с перечнем отличающихся файлов, если
развёрнутый `.artel/home/.claude/` отличается от референса
`docs/reference/role-home/claude/`; расхождение проверяется на
временном каталоге (не на реальном `.artel/home`), автоправки нет.

AC-14. Существующий набор `tests/` зелёный после изменений — включая
обновлённые без ослабления тесты `role_env` (критерий 8 T019,
инварианты T020, ADR-0003 п.14): проверка «остальное окружение роли
наследуется» заменяется проверкой белого списка, без потери покрытия
git-идентичности, HOME/CLAUDE_CONFIG_DIR и журналирования SKIPPED.

## Оценка объёма и деление
Сработавшие сигналы: число критериев приёмки (14, порог 10);
`budget_usd` (45, порог 30 — «типовая задача» по калибровке
skills/spec-authoring.md при таком числе критериев тянет к $45,
дальше — либо $70, либо деление). Сигнал «число затрагиваемых
модулей/файлов» (только `orchestrator/*.py`/`scripts/*.py` в тексте
SPEC — `orchestrator/runner.py`, `orchestrator/stack.py`,
`orchestrator/doctor.py`, порог 5) не сработал.

Задача делится на 2 самостоятельно мержимые части — по границам зон,
без взаимной зависимости кода (проверено: требования 4-5, снятие хука
и doctor-проверка, опираются на безопасность, которую даёт задача
«группа процессов», 01M1PNBSHR…, а не на требования 1-3 этой же
задачи; наоборот, требования 1-3 не зависят от требований 4-5). Обе
части по-прежнему ждут мержа «группы процессов» и части 1
(`orchestrator/stack.py`, задача 01M1RDCAFENSW2VVAPECHCVGMM) — это
условие старта кода для задачи целиком, не повод держать её монолитом.

- **Часть A — окружение роли из манифеста** (требования 1-3, AC-1..8,
  AC-14 в части, что касается `role_env`). Зоны: `orchestrator/
  runner.py`, `orchestrator/stack.py` (использование, не определение —
  манифест определяет часть 1), `tests/` (обновление тестов `role_env`
  T019/T020, новые тесты PATH/белого списка/SKIPPED/`sys.executable`).
  Самостоятельно мержима: меняет только сборку окружения и argv
  интерпретатора роли, не трогает курируемый слой `docs/reference/
  role-home/` — временный хук на месте, планка `tests/` вне этой части
  не задета.
- **Часть B — снятие временного хука и doctor-проверка референса**
  (требования 4-5, AC-9..13, AC-14 в части, что касается `tests/
  test_role_bash_guard.py`). Зоны: `docs/reference/role-home/`,
  `orchestrator/doctor.py`, `tests/` (удаление `test_role_bash_guard.
  py`, тест doctor-проверки на временном каталоге). Самостоятельно
  мержима: не трогает `role_env`/`orchestrator/stack.py`; безопасность
  снятия хука обеспечивает сторож зависших прогонов «группы процессов»
  (01M1PNBSHR…, уже прогоняет `tests/` смоуком), а не часть A этой
  задачи.

Порядок между частями не задан зависимостью — обе стартуют сразу после
общих условий выше; порядок в списке — по месту в названии задачи
(«окружение роли из манифеста» первым в заголовке).

Заведение подзадач под конкретные части — действие Оператора на этом

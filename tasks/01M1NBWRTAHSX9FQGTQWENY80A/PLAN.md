# PLAN: Ответы Оператора в брифе ревьювера

## Подход
Ревью-пакет (`orchestrator/review.py::review_package`) сегодня собирает
SPEC/PLAN/прошлый REVIEW/форму вердикта/stat/diff, но не читает
`tasks/<id>/ANSWER-n.md` — их получают только developer/analyst/
test_author через `brief.py`. Добавляем ревьюверу свой путь чтения ВСЕХ
`ANSWER-n.md` (не только последнего — SPEC AC-1): каждый батч ответа
Оператора — граница отдельного решения.

Ключевые решения:
- `ANSWER-n.md` живёт только в АРТЕФАКТНОЙ ветке задачи
  (`orchestrator/answer.py::cmd_answer` коммитит его туда), не в кодовой
  `branch`, которой читаются SPEC/PLAN/REVIEW — новая приватная
  `review._answer_rels(task_id, branch)` разрешает ветку тем же
  резолвером, что уже использует `brief.py` (`artifact_source.resolve`),
  и перечисляет файлы через `gitcmd.ls_tree_files` + числовую сортировку
  по `n` (текстовая сортировка сломала бы порядок «10» перед «2»).
- `review_package` получает новый обязательный параметр `conn` (нужен
  только для журналирования — ADR по sha256-фингерпринту компонента,
  SPEC требование 2/AC-2) — единственный вызывающий,
  `role_prompt.py::mission_brief_package`, уже держит `conn` под рукой,
  правка сигнатуры однострочная.
- Журналирование — прямой вызов `store.journal(conn, task_id, "reviewer",
  "бриф: компонент", ...)`, той же формы записи, что и `brief.py` для
  компонентов брифа других ролей (SPEC T075 AC-6), но НЕ через
  `brief._journal_component` (приватная функция чужого модуля — по
  ответу Оператора ANSWER-1 ссылка на SPEC T101 ошибочна и не
  применяется к этому пакету; прецедента cross-module вызова приватных
  функций в кодовой базе нет). Журналируются ТОЛЬКО новые ANSWER-
  компоненты (AC-2/AC-3) — существующие компоненты пакета правка не
  трогает.
- Компоненты ANSWER-n.md добавляются в список `parts` МЕЖДУ формой
  вердикта и stat-списком — как обычные элементы списка, участвующие в
  общем размере тела и делении на части `context_package.discipline`
  наравне с остальными (AC-4), без особого случая.
- Задача без файлов ANSWER-n.md — `_answer_rels` возвращает пустой
  список, цикл журналирования не выполняется ни разу, `parts` не
  получает новых элементов → пакет байт-в-байт как раньше (AC-5).
- AC-7 (`skills/review-checklist.md`): по ответу Оператора (ANSWER-2)
  правка залоченного скила АВТОРИЗОВАНА в рамках этой задачи (SPEC
  требование 4 писан по прямому ТЗ Оператора, ANSWER-2 подтверждает
  «реализовать в этой же задаче») — добавлена одна строка в пункт 6
  чеклиста («Системная целостность»), рядом с существующей оговоркой
  про ADR-0012 для правки зафиксированной планки, той же тематики.

## Шаги

1. `orchestrator/review.py`: параметр `conn` в `review_package`,
   `_answer_rels`, вставка ANSWER-компонентов в `found`/`parts` с
   журналированием sha256.
2. `orchestrator/role_prompt.py`: прокинуть `conn` в вызов
   `review.review_package`.
3. `skills/review-checklist.md`: одна строка AC-7 в пункте 6.
4. Юнит-тесты `tests/test_review_package.py`: `_answer_rels` (сортировка
   по числу/пустой список/сбой git/не-ANSWER файлы рядом), сборка
   пакета с несколькими ANSWER (порядок, журнал, отсутствие журнала для
   старых компонентов, регресс без ANSWER-файлов), правка существующих
   вызовов `review_package(...)` под новую сигнатуру.

## Влияние на систему
Затронуты `orchestrator/review.py` (сигнатура `review_package` — новый
обязательный первый параметр `conn`) и единственный вызывающий,
`orchestrator/role_prompt.py::mission_brief_package`, — других мест
вызова в кодовой базе нет (grep подтверждён). `skills/review-checklist.md`
— защищённый путь, правка авторизована прямым ТЗ Оператора этой задачи
и ANSWER-2 (не эскалация в обход, а исполнение полученного мандата).
Существующие компоненты ревью-пакета (SPEC/PLAN/REVIEW/форма/stat/diff)
не меняют формат, журналирование для них не добавляется (AC-3) — их
обработка байт-в-байт как раньше при отсутствии ANSWER-файлов (AC-5,
покрыто тестом-регрессом). Тесты и guard.py не ослаблены, приёмочные
тесты (залоченные, tasks/T023) не правились. Откат — реверт коммитов
этой задачи, точечный по трём затронутым модулям кода и одному скилу.

## Риски
Числовая сортировка `_answer_rels` полагается на суффикс `ANSWER-<n>.md`
целиком цифровой (`isdigit()`) — нестандартное имя (`ANSWER-1a.md`)
тихо игнорируется, а не эскалирует; это соответствует уже принятой
Оператором механике `brief.py` для остальных ролей (та же форма имени
файла), отдельного риска для этой задачи не вносит.

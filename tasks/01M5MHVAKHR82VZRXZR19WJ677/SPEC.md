## Требования

1. Тринадцать определений таблицы удаляются из своих модулей целиком (вместе
   с докстрингами). Импорты, которые после удаления становятся
   неиспользуемыми в этом модуле, удаляются; прочий код модулей не меняется.
   Уточнение Оператора на гейте SPEC 23.10.2026: удаляются только импорты,
   которые на main использовались исключительно удалёнными определениями;
   импорты, неиспользуемые уже на main (например, `config` в
   `orchestrator/fixation.py:37`), не трогаются. Удаление — именно удаление:
   не переименование и не `del` после определения.
2. Комментарии и докстринги в зонах задачи, которые называют удалённые имена
   как существующие (`orchestrator/gitcmd.py:242`, `:511` про `is_clean`;
   `orchestrator/fixation.py:95` про `external_code_sha`), переписываются без
   ссылки на удалённое имя, смысл комментария сохраняется. Комментарий
   `orchestrator/models.py:1580` («Вердикты ревью в `pair_verdicts`.»)
   уточняется: в `pair_verdicts` пишутся вердикты `return` и `approved`,
   константа есть только для `return` — её читает сверка пары. Абзацы
   `gitcmd.py:242`, `:511` и `fixation.py:95` не удаляются целиком: в каждом
   остаётся текст, называющий существующие имена (`head_sha`,
   `external_artifact_sha`) — уточнение Оператора на гейте SPEC 23.10.2026.
3. Тест (новый файл в `tests/`): для каждой из тринадцати пар «модуль — имя»
   модуль импортируется, и `hasattr(модуль, имя)` ложно; сообщение отказа
   называет модуль и имя. Для `scripts/core_reference.py` — `from scripts
   import core_reference`, как в `tests/test_core_reference.py`. На текущем
   коде — красный по всем тринадцати. Строка «Ловит мутацию»: возврат любого
   из удалённых определений.
4. Тест (тот же файл): разбор AST всех `*.py` в `orchestrator/` и `scripts/`
   не находит ни одного обращения к тринадцати именам: `ast.Name` с
   контекстом `ast.Load`, `ast.Attribute.attr`, `ast.alias.name`; цели
   присваиваний, определения функций и строковые константы не учитываются.
   На текущем коде — красный только по `retro_rel_path` (обращение из
   `retro_path`, `retro.py:264`); после удаления держит отсутствие висячих
   ссылок. Строка «Ловит мутацию»: обращение к удалённому имени в
   `orchestrator/` или `scripts/`.
5. Карта кодовой базы `docs/codebase-map.md` перегенерируется
   `scripts/codebase_map.py` по правилу соглашений.
6. Поведение пульта не меняется. Существующие тесты не правятся.

Тест требований 3–4 — один новый файл `tests/`; если его свойства держит
долгоживущий приёмочный тест автора тестов этой задачи
(`tests/test_01m5mhvakhr82vzrxzr19wj677_*.py`, ADR-0020), отдельный
дублирующий файл не нужен.

## Критерии приёмки

AC-1. Для каждой из тринадцати пар «модуль — имя» таблицы «Контекст» модуль
импортируется без ошибки (`scripts/core_reference.py` — как
`from scripts import core_reference`), и `hasattr(модуль, имя)` ложно;
сообщение отказа проверки называет модуль и имя. На коде main проверка
красна по всем тринадцати парам.

AC-2. Разбор AST всех файлов `*.py` под `orchestrator/` и `scripts/` не
находит ни одного обращения к тринадцати именам — ни `ast.Name` с контекстом
`ast.Load`, ни `ast.Attribute` с `attr`, равным имени, ни `ast.alias` с
`name`, равным имени; цели присваиваний, определения функций и строковые
константы не учитываются. На коде main проверка красна только по
`retro_rel_path` (обращение в `orchestrator/retro.py:264`).

AC-3. Ни один из одиннадцати изменяемых модулей кода (зоны задачи под
`orchestrator/` и `scripts/`) не импортирует на ветке имя, которое в базе
сравнения использовалось в этом модуле исключительно удалёнными
определениями таблицы. Прочие импорты модулей, в том числе неиспользуемые и
в базе (например, `config` в `orchestrator/fixation.py:37`), не трогаются:
множество импортированных имён модуля на ветке равно множеству в базе минус
имена, использовавшиеся в базе только удалёнными определениями. База

AC-4. Тексты `orchestrator/gitcmd.py` и `orchestrator/fixation.py` не содержат
слов `is_clean` и `external_code_sha` соответственно. Абзацы на месте прежних

## Оценка объёма и деление

Сработавший сигнал: число затрагиваемых файлов зоны ≥ 5 (одиннадцать модулей
кода, `docs/codebase-map.md`, `tests/`).

Материал для решения Оператора — **обоснование монолита**. Правка каждого
модуля — механическое удаление нескольких строк без изменения поведения;
суммарный дифф мал, ревью однородно. Деление по модулям возможно технически,
но AC-1 и AC-2 сформулированы ТЗ одним тестом на все тринадцать пар: часть
нарезки, удалившая лишь свою долю, оставила бы этот тест красным по
остальным парам, то есть каждая часть несла бы урезанную версию теста, а
полный тест появился бы только в последней. Кроме того, каждая часть
регенерировала бы `docs/codebase-map.md` — одна общая зона на все части,
которые не могли бы идти параллельно. Цена деления (≥ 3 полных конвейера
вместо одного) кратно выше цены самой правки. Бюджет задан ТЗ — $25.

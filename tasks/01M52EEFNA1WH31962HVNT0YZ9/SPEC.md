# SPEC: D0-2: раннер pytest-own в местах запуска — команда, workdir, чистое окружение, группа процессов

## Контекст
Часть 2 из 3 задачи D0 (родитель 01M52CQB468758M2NAA15C15ZE; основание —
ADR-0023, вторая поправка 16.10.2026). Часть 1 (01M52EEDEYV14658X8VFNHCW8K)
ввела в `project_profile.Profile` поля `runner`/`workdir`/`env`
(`orchestrator/project_profile.py:66-96`) и зафиксировала argv, `cwd` и
окружение восьми мест запуска pytest для артели
(`tests/test_01m52eedeyv14658x8vfnhcw8k_launch_places.py`). Сейчас места
запуска профиль не видят: команда всегда идёт с интерпретатором пульта,
плагинами `timeout`/`xdist`, окружением процесса пульта и `cwd` корня.
Эта часть учит восемь мест запуска раннеру `runner: pytest-own` —
команда профиля, рабочий каталог `workdir`, чистое окружение, снятие группы
процессов по таймауту, — не меняя поведения для `pult-pytest` (артели).

Восемь мест запуска: `acceptance.run`, `acceptance.collect`,
`acceptance.run_repeat`, `acceptance.run_plank`,
`acceptance._run_full_suite_now` без `observe`, он же с `observe`,
`acceptance._run_full_suite_to_log`, `two_sided._run_side`.

## Требования

1. Восемь мест запуска принимают профиль тем же каналом, что сегодня
   `command`; `two_sided.run` принимает профиль от вызывающего.
   `acceptance.acceptance_suite` (`acceptance.py:1807-1848`) берёт профиль
   проекта задачи сама и передаёт его полному набору.
2. При `runner: pytest-own` команда — команда профиля как есть, без
   интерпретатора пульта, без `-p timeout`/`-o timeout=…` и без
   `-n`/`-p xdist`; пульт дописывает к ней аргументы гейтов
   (`--collect-only -q`, `--junitxml`, `-o junit_logging=system-out`,
   `-p no:cacheprovider`) и аргументы конкретного места запуска.
3. При `runner: pytest-own` рабочий каталог прогона — `workdir`; в момент
   прогона `realpath` каталога `workdir` обязан остаться внутри дерева
   прогона, иначе — именованный отказ, прогон не запускается.
4. Пути профиля (`long_lived_dir`, долгоживущие пути, `workdir`)
   отсчитываются от корня репозитория и переводятся местом запуска в пути,
   верные из `workdir`: цель полного набора — `long_lived_dir`, а не
   `<корень>/tests` (в том числе когда вызывающий передаёт целью `tests`,
   как `suite_run.py:525,565`); прочие переданные вызывающим цели
   переводятся от корня репозитория к `workdir`.
5. Окружение прогона при `runner: pytest-own` — только: `PATH` пульта;
   временный `HOME` (новый на каждый прогон, удаляется после прогона, в том
   числе по таймауту и на исключении); `TMPDIR`; `LANG`/`LC_ALL` при их
   наличии; служебные переменные места запуска (`PYTHONPYCACHEPREFIX`,
   `PYTHONUNBUFFERED`, переменные плагина и отчёта двустороннего прогона);
   `test_profile.env`.
6. При `runner: pytest-own` каждое из восьми мест запуска запускает прогон
   в собственном сеансе и по таймауту и на любом исключении снимает всю
   группу процессов (как сегодня `acceptance.py:1324-1337`, `:1373-1391`) —
   в том числе точечные прогоны и путь `_run_full_suite_now` без `observe`
   (`:1343-1350`), которые сегодня группу не снимают. Снятие `-p timeout`
   у `pytest-own` принято Оператором 16.10.2026: замена — предел прогона и
   снятие группы процессов.
7. Ключ повторного использования итога полного набора (gate- и base-итог,
   `acceptance.py:1609-1640`, `:1740-1758`, `:1790-1792`) при
   `runner: pytest-own` учитывает `runner`, `workdir`, `env`; при
   `runner: pult-pytest` ключ не меняется ни на байт.
8. При `runner: pult-pytest` (артель) argv, `cwd` и окружение всех восьми
   мест запуска остаются прежними.
9. Тесты задачи детерминированы, без сети и без `uv`: учебный проект во
   временном каталоге с `runner: pytest-own` и командой-обёрткой,
   порождающей дочерний процесс.

## Критерии приёмки

AC-1. У артели (`runner: pult-pytest`) argv, `cwd` и окружение восьми мест
запуска не изменились: фиксация части 1
`tests/test_01m52eedeyv14658x8vfnhcw8k_launch_places.py` зелёная по обоим
путям команды (`command=None` и `command=[python3, -m, pytest]`).

AC-2. В каждом из восьми мест запуска тест учебного проекта с
`runner: pytest-own` не видит переменных окружения пульта вне перечня
требования 5 и видит переменные `test_profile.env`.

AC-3. В каждом из восьми мест запуска при `runner: pytest-own` `HOME`
прогона — временный каталог, созданный на этот прогон; после завершения
прогона и после прогона, оборванного таймаутом, этого каталога нет.

AC-4. В каждом из восьми мест запуска при `runner: pytest-own` argv —
команда профиля без интерпретатора пульта, без `-p timeout`, без `-n`, без
`-p xdist` (с дописанными пультом аргументами гейтов и места запуска), а
`cwd` — `workdir`.

AC-5. Полный набор при `runner: pytest-own` собирается из `long_lived_dir`,
переведённого в путь под `workdir`, — в том числе когда вызывающий передаёт
целью `tests`; прочие цели, переданные от корня репозитория, переводятся в
пути, верные из `workdir`.

AC-6. По таймауту в каждом из восьми мест запуска при `runner: pytest-own`
дочерний процесс команды-обёртки учебного проекта не остаётся жить.

AC-7. `workdir`, чей `realpath` выводит за пределы дерева прогона (ссылка
наружу), даёт именованный отказ, и прогон pytest не запускается.

AC-8. Итог полного набора, сохранённый при другом `runner`, другом
`workdir` или другом `env`, не засчитывается повторно (gate- и base-итог);
ключ итога при `runner: pult-pytest` прежний байт в байт.

жизни дочерних процессов. Ключ итога (требование 7) без смены команды не
наблюдаем.

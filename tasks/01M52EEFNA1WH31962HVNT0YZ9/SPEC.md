# SPEC: D0-2: раннер pytest-own в местах запуска — команда, workdir, чистое окружение, группа процессов

## Контекст
Это часть 2 из 3 задачи D0 (родитель 01M52CQB468758M2NAA15C15ZE; основание —
ADR-0023, вторая поправка 16.10.2026). Часть 1 (01M52EEDEYV14658X8VFNHCW8K)
ввела в `project_profile.Profile` поля `runner`/`workdir`/`env`
(`orchestrator/project_profile.py:66-96`) и зафиксировала argv, `cwd` и
окружение восьми мест запуска pytest для артели
(`tests/test_01m52eedeyv14658x8vfnhcw8k_launch_places.py`). Сейчас места
запуска профиль не видят. `acceptance._pytest_command`
(`acceptance.py:59-64`) берёт команду профиля, если она названа, иначе
команду пульта; первый элемент `python3` подменяет интерпретатором venv
пульта, а к любой команде дописывает `-p no:cacheprovider`, `-p timeout`,
`-o timeout=…`. Полный набор дописывает ещё `-n`/`-p xdist`. Прогон идёт
с окружением процесса пульта и `cwd` корня.
Эта часть учит восемь мест запуска раннеру `runner: pytest-own`:
команда профиля, рабочий каталог `workdir`, чистое окружение, снятие группы
процессов по таймауту. Поведение для `pult-pytest` (артели) не меняется.

Восемь мест запуска: `acceptance.run`, `acceptance.collect`,
`acceptance.run_repeat`, `acceptance.run_plank`,
`acceptance._run_full_suite_now` без `observe`, он же с `observe`,
`acceptance._run_full_suite_to_log`, `two_sided._run_side`.

## Требования

1. Места запуска с параметром `command` (`acceptance.run`, `collect`,
   `run_repeat`, а для полного набора — `run_full_suite` и `full_suite`)
   принимают профиль тем же каналом, что сегодня `command`. У мест без
   параметра `command` — `acceptance.run_plank` (`acceptance.py:923`) и
   `two_sided._run_side` (`two_sided.py:222-223`) — профиль передаётся
   новым необязательным параметром. `_run_full_suite_now` и
   `_run_full_suite_to_log` получают argv, который `run_full_suite`
   собрал по профилю. `two_sided.run` принимает профиль от вызывающего.
   `acceptance.acceptance_suite` (`acceptance.py:1807-1848`) берёт профиль
   проекта задачи сама и передаёт его полному набору. При
   `runner: pult-pytest` и при непрочитанном профиле `acceptance_suite`
   зовёт `full_suite` прежней формой (`full_suite(root, task_id)` /
   `full_suite(root, task_id, fresh=True)`), так что
   `tests/test_acceptance.py:437-458` остаётся зелёным без правки.
2. При `runner: pytest-own` команда — команда профиля как есть: без
   интерпретатора пульта, без `-p timeout`/`-o timeout=…` и без
   `-n`/`-p xdist`. Пульт дописывает к ней аргументы гейтов
   (`--collect-only -q`, `--junitxml`, `-o junit_logging=system-out`,
   `-p no:cacheprovider`) и аргументы конкретного места запуска.
3. При `runner: pytest-own` рабочий каталог прогона — `workdir`. В момент
   прогона `realpath` каталога `workdir` обязан остаться внутри дерева
   прогона. Иначе — именованный отказ запуска, и прогон не запускается.
   Такой отказ не считается красным прогоном (`FULL_SUITE_RED`). В
   полном наборе он даёт исход «не запущен» (`FULL_SUITE_NOT_STARTED`):
   без файла лога и без сохранения итога.
4. Пути профиля (`long_lived_dir`, долгоживущие пути, `workdir`)
   отсчитываются от корня репозитория. Место запуска переводит их в пути,
   верные из `workdir`. Цель полного набора — `long_lived_dir`, а не
   `<корень>/tests`, в том числе когда вызывающий передаёт целью `tests`
   (как `suite_run.py:525,565`). Прочие цели, переданные вызывающим от
   корня репозитория, переводятся от корня к `workdir`. Идентификаторы
   упавших тестов для `suite-run --failed` (`suite_run.py:564-565`)
   передаются без перевода: переводятся только пути, которые пульт
   получает от корня репозитория. При `runner: pytest-own` по
   `long_lived_dir` под `workdir` работают три места: предпроверка
   каталога тестов (`acceptance.py:1172-1174`), условие полного прогона
   `tuple(targets) == ("tests",)` (`:1193`) и вычистка целей `tests` при
   сборке base-ключа (`:1626`). При `runner: pult-pytest` эти три места не
   меняются.
5. Окружение прогона при `runner: pytest-own` состоит только из:
   - `PATH` пульта;
   - временного `HOME`: новый каталог на каждый прогон, удаляется после
     прогона, в том числе по таймауту и на исключении;
   - `TMPDIR`;
   - `LANG`/`LC_ALL`, если они заданы;
   - служебных переменных места запуска: `PYTHONPYCACHEPREFIX`
     (обязателен для каждого прогона `pytest-own`, ADR-0023),
     `PYTHONUNBUFFERED`, переменных плагина и отчёта двустороннего
     прогона;
   - `test_profile.env`.
6. При `runner: pytest-own` каждое из восьми мест запуска запускает прогон
   в собственном сеансе. По таймауту и на любом исключении оно снимает всю
   группу процессов (как сегодня `acceptance.py:1324-1337`, `:1373-1391`).
   Это касается и точечных прогонов, и пути `_run_full_suite_now` без
   `observe` (`:1343-1350`), которые сегодня группу не снимают. Снятие
   `-p timeout` у `pytest-own` Оператор принял 16.10.2026: замена — предел
   прогона и снятие группы процессов.
7. Ключ повторного использования итога полного набора (gate- и base-итог,
   `acceptance.py:1609-1640`, `:1740-1758`, `:1790-1792`) при
   `runner: pytest-own` учитывает `runner`, `workdir`, `env`. При
   `runner: pult-pytest` ключ не меняется ни на байт.
8. При `runner: pult-pytest` (артель) argv, `cwd` и окружение всех восьми
   мест запуска остаются прежними.
9. Тесты задачи детерминированы, без сети и без `uv`: учебный проект во
   временном каталоге с `runner: pytest-own` и командой-обёрткой,
   порождающей дочерний процесс.

## Критерии приёмки

AC-1. У артели (`runner: pult-pytest`) argv, `cwd` и окружение восьми мест
запуска не изменились: фиксация части 1
`tests/test_01m52eedeyv14658x8vfnhcw8k_launch_places.py` зелёная по обоим
путям команды (`command=None` и `command=[python3, -m, pytest]`).
`tests/test_acceptance.py:437-458` зелёный без правки: при пустой БД
`acceptance_suite` зовёт `full_suite(Path("/tmp"), "T001")`.

AC-2. В каждом из восьми мест запуска тест учебного проекта с
`runner: pytest-own`:
- не видит переменных окружения пульта вне перечня требования 5;
- видит переменные `test_profile.env`;
- видит `PYTHONPYCACHEPREFIX`.

AC-3. В каждом из восьми мест запуска при `runner: pytest-own` `HOME`
прогона — временный каталог, созданный на этот прогон. Этого каталога нет
после каждого из трёх исходов: прогон завершился, прогон оборван
таймаутом, на прогоне поднято исключение.

AC-4. В каждом из восьми мест запуска при `runner: pytest-own`:
- argv — команда профиля без интерпретатора пульта, с дописанными
  пультом аргументами гейтов и места запуска;
- в argv есть `-p no:cacheprovider`;
- в argv нет `-p timeout`, `-o timeout=…`, `-n`, `-p xdist`;
- `cwd` — `workdir`.

AC-5. Полный набор при `runner: pytest-own` собирается из
`long_lived_dir`, переведённого в путь под `workdir`, в том числе когда
вызывающий передаёт целью `tests`. Дальше при `pytest-own`:
- прочие цели, переданные от корня репозитория, переводятся в пути, верные
  из `workdir`;
- идентификаторы упавших тестов (`--failed`) передаются без перевода;
- отсутствие каталога `long_lived_dir` под `workdir` даёт исход «тестов
  нет», даже если `<корень>/tests` существует;
- вычистка целей при сборке base-ключа убирает `long_lived_dir`.

AC-6. В каждом из восьми мест запуска при `runner: pytest-own` дочерний
процесс команды-обёртки учебного проекта не остаётся жить ни после
таймаута, ни после исключения на прогоне.

AC-7. В каждом из восьми мест запуска поимённо (`acceptance.run`,
`acceptance.collect`, `acceptance.run_repeat`, `acceptance.run_plank`,
`acceptance._run_full_suite_now` без `observe`, он же с `observe`,
`acceptance._run_full_suite_to_log`, `two_sided._run_side`) `workdir`,
чей `realpath` выводит за пределы дерева прогона (ссылка наружу), даёт
именованный отказ запуска, и прогон pytest не запускается. В полном наборе
(`full_suite`) этот отказ даёт исход «не запущен», а не «красный», и не
оставляет ни файла лога, ни сохранённого итога.

AC-8. Итог полного набора, сохранённый при другом `runner`, другом
`workdir` или другом `env`, не засчитывается повторно (gate- и base-итог).
Ключ итога при `runner: pult-pytest` прежний байт в байт.

## Оценка объёма и деление

Сработал сигнал `budget_usd` ≥ $30 (40). Класс задачи — «до 10 критериев и
до 4 файлов»: 8 критериев, 3 зоны; рамка родителя $45.

Материал для решения Оператора — обоснование монолита. Задача уже
является частью нарезки родителя 01M52CQB468758M2NAA15C15ZE (часть 2 из 3).
Её зоны — два модуля мест запуска и `tests/`.

Разрез по местам запуска оставил бы промежуточное состояние с одним и тем
же профилем `pytest-own`, который запускается по-разному:
- в части мест — командой профиля в `workdir` с чистым окружением;
- в остальных — интерпретатором пульта в корне с окружением пульта.

Тогда гейты одной задачи (точечный прогон, полный набор, двусторонний
прогон) судили бы разные наборы тестов в разных окружениях.

Разрез по свойствам (команда / окружение / группа процессов) тоже не
даёт рабочей промежуточной точки. Команда профиля без `-p timeout` и без
его замены (предел + снятие группы) оставляет дочерние процессы обёртки
без предела жизни. Ключ итога (требование 7) без смены команды не
наблюдаем.

# SPEC: Ожидание занятой зоны по умолчанию для всех вызовов auto

## Контекст
Штатный режим ожидания занятой зоны внутри цикла `auto` в пульте есть
(SPEC 01M1VBEAWZW4EBZHKMGNBBK648), но заведён выключенным: настройка
`AUTO_WAIT_ZONE_DEFAULT = False` с оговоркой в комментарии «пока Оператор
явно не включит настройку». Из-за этого вызов `auto` без флага
`--wait-zone` при отказе занятости зоны останавливается причиной «ждёт
зоны» и задача стоит до следующей проверки Оператора. Прецедент волны
28.09: задача 01M3KE8ZJXFARS6KC441PCDCQV дописала приёмочные тесты и
встала на занятой зоне (её держала 01M3KE9FZ1YZS5WD5K9M8EKN37), цикл
перезапускала сессия ассистента вручную с флагом. Решение Оператора
28.09.2026 — включить настройку для всех вызовов `auto`.

## Требования

1. В `orchestrator/config.py` настройка получает значение
   `AUTO_WAIT_ZONE_DEFAULT = True`. Комментарий настройки называет дату и
   решение Оператора 28.09.2026 и основание: задача останавливается на
   занятой зоне без надзора, прецедент волны 28.09 (задача
   01M3KE8ZJXFARS6KC441PCDCQV). Прежняя оговорка «пока Оператор явно не
   включит настройку» в комментарии больше не действует.
2. Поведение при исчерпании потолка ожидания не меняется: истечение
   потолка останавливает цикл именованной причиной, задача остаётся в том
   же состоянии, эскалации нет.
3. Флаг `--wait-zone` команды `auto` сохраняется и остаётся допустимым:
   разбор аргументов его принимает, отказа на него нет, при включённой
   настройке он ничего не меняет.
4. Обратного способа (остановиться на занятой зоне для одного вызова)
   задача не заводит — он не укладывается в её зоны (обоснование и строка
   для бэклога — в «Не входит»).
5. Тест, чей сценарий опирается на прежнее значение по умолчанию
   (немедленная остановка `auto` на занятой зоне без флага), закрепляет
   это значение подменой настройки внутри своего сценария, а не
   значением из `orchestrator/config.py`; проверки таких тестов не
   ослабляются (методы и утверждения не удаляются, не переименовываются,
   пропусков не появляется).
6. Появляется тест: без флага `--wait-zone` и без подмены настройки отказ
   занятости зоны переводит цикл в ожидание (запись журнала входа в
   ожидание «ждёт зоны …»), а не в остановку.
7. Раздел `docs/operator-session.md` о занятой зоне сообщает: настройка
   включена решением Оператора 28.09.2026; ручной перезапуск цикла с
   `--wait-zone` больше не нужен; как видеть ожидающие задачи — `status`
   и журнал задачи.

## Критерии приёмки

AC-1. `orchestrator/config.py` несёт `AUTO_WAIT_ZONE_DEFAULT = True`, и
комментарий этой настройки содержит дату «28.09.2026», указание на
решение Оператора и основание — остановку задачи на занятой зоне без
надзора с прецедентом волны 28.09 (01M3KE8ZJXFARS6KC441PCDCQV); фразы
«пока Оператор явно не включит настройку» в нём нет.

AC-2. Отказ занятости зоны в цикле `auto`, вызванном БЕЗ флага
`--wait-zone` и БЕЗ подмены `config.AUTO_WAIT_ZONE_DEFAULT` в сценарии,
переводит цикл в ожидание: в журнале задачи есть запись входа в ожидание,
начинающаяся с «ждёт зоны » (`zone_lock.wait_enter_action`), и нет
остановки цикла причиной `config.AUTO_STOP_ZONE_WAIT`.

AC-3. Тот же цикл, вызванный С флагом `--wait-zone`, ведёт себя так же и
флаг остаётся допустимым: `auto <id> --wait-zone` разбирается без отказа
и доходит до `auto.cmd_auto(..., wait_zone=True)`.

AC-4. Исчерпанный потолок ожидания (`config.ZONE_WAIT_MAX_SEC`)
останавливает цикл именованной причиной «потолок ожидания зоны
исчерпан», задача остаётся в том состоянии, в котором ждала, и не уходит
в `escalated`.

AC-5. Ни один тест `tests/` не зависит от прежнего значения настройки
неявно: тест, чей сценарий требует немедленной остановки `auto` на
занятой зоне без флага, подменяет `config.AUTO_WAIT_ZONE_DEFAULT` на
`False` в самом сценарии; полный набор `tests/` зелёный, число тестовых
методов в изменённых файлах не уменьшилось и пропусков (`@skip`,
`skipTest`) в них не появилось.

AC-6. Раздел `docs/operator-session.md` о занятой зоне содержит все три
утверждения: настройка включена решением Оператора 28.09.2026; ручной
перезапуск с `--wait-zone` больше не нужен; ожидающие задачи видны через
`status` и журнал задачи.

## Оценка объёма и деление
Ни один сигнал «подозрения на большой объём» не сработал (`guard`
подтверждает: пустой список сигналов) — секция заполнена добровольно,
потому что зона задевает `tests/`.

- Прогноз диффа: 3 КиБ (одна строка значения и комментарий в
  `orchestrator/config.py`, абзац `docs/operator-session.md`, один новый
  тестовый метод и подмена настройки в затронутых сценариях) — ниже
  порога сигнала (половина `config.REVIEW_SNAPSHOT_DIFF_MAX_BYTES`,
  128 КиБ).
- Зона `tests/` адресована инвариантами 33, 35, 37, 38
  `docs/invariants.md`: задача меняет тесты только дописыванием сценария
  и подменой настройки внутри сценария, ни один из этих инвариантов не
  ослабляется.

Решение — **монолит**. Резать нечего: смена значения по умолчанию
атомарна, а обе оставшиеся части существуют только вместе с ней. Часть
«только тесты» без смены значения закрепляла бы сценарием поведение,
которого задача не вводит, и была бы мержима лишь как пустая правка;
часть «только документация» описывала бы Оператору включённую настройку,
которая в `orchestrator/config.py` ещё выключена, — промежуточное
состояние, где документ расходится с кодом. Объём — 3 файла зоны и
6 критериев приёмки, ниже порогов деления.

## Не входит

- Смена `ZONE_WAIT_POLL_SEC` и `ZONE_WAIT_MAX_SEC`: значения остаются
  прежними (90 секунд и 6 часов).
- Ожидание других причин остановки цикла — бюджет, лимит параллельных
  задач, пауза: они останавливают `auto` как раньше.
- Очередь задач на зону с приоритетами.
- Обратный способ остановиться на занятой зоне для одного вызова
  (`auto --no-wait-zone` и подобное). Он не укладывается в зоны задачи:
  разбор флага живёт в `orchestrator/artel.py` (`_CYCLE_FLAGS_AUTO`), а
  проброс параметра до ветки ожидания — в `orchestrator/auto.py`; оба
  пути в этой задаче только на чтение. Необходимости в нём тоже нет:
  у Оператора уже есть штатные выходы из ожидания — `run` (один шаг,
  отказывает на занятой зоне немедленно и настройкой не затронут),
  `zone-release <id>` (осознанное снятие), `stop`/`pause` живого цикла —
  и сам потолок `ZONE_WAIT_MAX_SEC`, который завершает ожидание без
  участия Оператора. Строка для бэклога: «`auto --no-wait-zone` — разовый
  отказ от ожидания занятой зоны; зоны: `orchestrator/artel.py`,
  `orchestrator/auto.py`».
- Правки в `orchestrator/auto.py`, `orchestrator/artel.py`,
  `orchestrator/zone_lock.py`, `docs/stack.md` (значения настройки не
  описывает), `tests/test_invariants.py`, `docs/backlog.md` — эти пути
  только на чтение.

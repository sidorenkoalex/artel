# ТЗ: Ожидание занятой зоны по умолчанию для всех вызовов auto

Источник: решение Оператора 28.09.2026. Прецеденты волны 28.09: задача
01M3KE8ZJXFARS6KC441PCDCQV дописала приёмочные тесты и остановилась с
причиной «ждёт зоны» (docs/stack.md держала 01M3KE9FZ1YZS5WD5K9M8EKN37);
цикл перезапускала сессия ассистента вручную с флагом `--wait-zone`.
Без ручного перезапуска задача стоит до следующей проверки Оператора.

Факты (origin/main на день заведения):
- `orchestrator/config.py`: `AUTO_WAIT_ZONE_DEFAULT = False` —
  настройка введена задачей 01M1VBEAWZW4EBZHKMGNBBK648 выключенной, с
  оговоркой в комментарии «пока Оператор явно не включит настройку»;
  соседние `ZONE_WAIT_POLL_SEC = 90` и `ZONE_WAIT_MAX_SEC = 6 * 3600`
  (потолок ожидания: по истечении цикл останавливается именованной
  причиной, задача остаётся `in_dev`).
- `orchestrator/auto.py` читает настройку в цикле: при отказе занятости
  зоны `if wait_zone or config.AUTO_WAIT_ZONE_DEFAULT` — ожидание вместо
  остановки; флаг `--wait-zone` команды `auto` делает то же для одного
  вызова.
- `docs/operator-session.md` (раздел о запусках) описывает включение как
  действие Оператора одной строкой.

Требуется:
1. `config.AUTO_WAIT_ZONE_DEFAULT = True`; комментарий настройки называет
   дату, решение Оператора 28.09.2026 и основание (остановка задачи на
   занятой зоне без надзора; прецедент волны 28.09).
2. Поведение при потолке `ZONE_WAIT_MAX_SEC` не меняется: истечение
   ожидания останавливает цикл именованной причиной, задача остаётся в
   прежнем состоянии, эскалации нет.
3. Флаг `--wait-zone` команды `auto` сохраняется и остаётся допустимым
   (ничего не меняет при включённой настройке, отказа на него нет).
   SPEC решает и обосновывает, нужен ли обратный способ — остановиться на
   занятой зоне для одного вызова; если нужен — только если он
   укладывается в зоны этой задачи без правки `orchestrator/auto.py`,
   иначе он называется в «Не входит» строкой для бэклога.
4. Тесты, опирающиеся на прежнее значение по умолчанию (немедленная
   остановка `auto` на занятой зоне без флага), закрепляют это значение в
   своём сценарии подменой настройки, а не полагаются на значение
   `config.py`; их проверки не ослабляются. Новый тест: без флага и с
   настройкой по умолчанию отказ занятости зоны переводит цикл в
   ожидание (запись журнала «ждёт зоны …»), а не в остановку.
5. `docs/operator-session.md`, раздел о занятой зоне: настройка включена
   решением Оператора 28.09.2026; ручной перезапуск с `--wait-zone`
   больше не нужен; как видеть ожидающие задачи (`status`, журнал).

Зоны: orchestrator/config.py, docs/operator-session.md, tests/.

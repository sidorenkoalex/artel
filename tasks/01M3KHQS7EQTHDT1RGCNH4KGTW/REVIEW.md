## Замечания

- **major — docs/operator-session.md:215-217 — перечень «разовый выход из
  ожидания» неверен в двух пунктах из трёх; Оператор получает рекомендацию,
  которая не работает именно в том режиме, который задача делает дефолтным.**
  - `stop` живого цикла ожидание НЕ прерывает: `_cmd_stop`
    (`orchestrator/artel.py:670-704`) шлёт только SIGTERM, обработчик
    (`orchestrator/auto.py:25-27`) ставит флаг `_stop_requested`, а
    проверяется он единственный раз — на границе между шагами
    (`orchestrator/auto.py:1015`). В цикле `_wait_for_zone`
    (`orchestrator/auto.py:124-153`) проверки нет. Проверено исполнением
    (проба ниже): с `_stop_requested = True` ожидание досыпает до потолка и
    возвращает «потолок ожидания зоны исчерпан», то есть до 6 часов, после
    чего цикл ещё и доигрывает полный шаг роли.
  - `run` на живом ожидающем цикле отказывает не «немедленно на занятой
    зоне», а раньше и по другой причине: цикл держит lease задачи и продлевает
    heartbeat на каждом опросе (`orchestrator/auto.py:132`), а
    `runner.cmd_run` идёт через `lease.run_locked`
    (`orchestrator/runner.py:160`) — чужая живая сессия даёт именованный
    отказ «подожди её» (`orchestrator/lease.py:33-35`). Пунктом «разового
    выхода» `run` работает только тогда, когда живого цикла нет — то есть
    когда и выходить не из чего.
  - `pause` ожидание тоже не прерывает: пауза проверяется внутри
    `runner.cmd_run` (`orchestrator/runner.py:288`), до которого цикл дойдёт
    лишь после освобождения зоны.
  - Сценарий поломки: Оператор видит задачу в ожидании чужой зоны, по
    документу даёт `stop <id>`, получает «SIGTERM отправлен» и считает цикл
    остановленным; процесс продолжает спать часами, держит lease (все
    команды под lease отказывают) и по освобождении зоны запускает ещё один
    полный шаг роли, который Оператор останавливал.
  - Предложение: оставить в перечне `zone-release <id>` (он действительно
    снимает ожидание на ближайшем опросе — маркер `RELEASE_ACTION` делает
    `zone_lock._occupies` истинной и `blocking_conflict` возвращает `None`,
    `orchestrator/zone_lock.py:349-367,409-410`) и мерж/kill держателя, а
    про `stop`/`pause` написать честно: они учитываются только после выхода
    из ожидания (`stop` — на ближайшей границе шагов, `pause` — на следующем
    `cmd_run`), про `run` — что живой цикл его не пустит по lease. Та же
    неточность есть в «Не входит» SPEC — формулировка документа правится в
    зонах задачи, расхождения с требованиями SPEC тут нет.

- **major — тексты прежнего дефолта остались по всему пульту; главный из них
  — операторский `help`.** Включение настройки сделало ложными описания,
  которые задача не тронула (все — вне её зон, поэтому нужен мандат
  Оператора на путь либо его решение отложить; молча оставить нельзя):
  - `orchestrator/artel.py:299-301` — модульный докстринг, который команда
    `help` печатает дословно (`orchestrator/artel.py:974` — `print(__doc__)`):
    «`auto` останавливает цикл причиной «ждёт зоны» без алерта буксования».
    Сценарий поломки: Оператор сверяется с `help`, делает вывод, что цикл
    на занятой зоне завершился и lease свободен, и не понимает, почему
    `run`/`stop` ведут себя иначе, — ровно та дезинформация, ради устранения
    которой задача и включает настройку.
  - `orchestrator/auto.py:546-547` — докстринг `cmd_auto`: «дефолт `False`
    не меняет сегодняшнее поведение (немедленная остановка)». После правки
    дефолт параметра `wait_zone=False` означает ровно противоположное.
  - `orchestrator/zone_lock.py:161-163` — докстринг `wait_minutes`:
    «`run`/`auto` без `--wait-zone` останавливаются немедленно и этой записи
    не оставляют». Для `auto` теперь ложно — запись входа оставляется всегда,
    на этом и держится новый тест.
  - `orchestrator/auto.py:126-128` и `:134` — подсказки остановки по потолку
    и по потере lease предлагают Оператору перезапуск `artel.py auto <id>
    --wait-zone`, хотя документ этой же задачи объявляет такой перезапуск
    ненужным (минорная часть того же класса).
  - Предложение: эскалировать батчем за мандатом на `orchestrator/artel.py`,
    `orchestrator/auto.py`, `orchestrator/zone_lock.py` (правка чисто
    текстовая, поведение не меняется) либо получить решение Оператора
    отложить их отдельной задачей; в PLAN «Влияние на систему» назвать этот
    класс явно.

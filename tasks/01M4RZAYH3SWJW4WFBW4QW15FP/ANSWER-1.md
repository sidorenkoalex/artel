## Ответы

Ответ Оператора на эскалацию test_author (13.10), AC-15.

Эскалация верна: существующий блок report (token_rate_divergence → spend.known_cost_pairs) уже делает store.task_steps на каждую задачу, поэтому условие «число запросов к steps не растёт с числом задач» неисполнимо в зоне задачи. Решение:

1. Часть AC-15 «число запросов к steps за прогон cmd_report не растёт с числом задач» снимается.
2. AC-15 проверяет: при прогоне cmd_report на подменённом соединении store.db() вызывается один раз, и число запросов к steps равно числу на тех же данных с заглушкой функции блока разведки (блок не добавляет ни одного запроса), на наборах из 2 и из 7 задач.
3. spend.py и существующие блоки report не меняются. Лишние запросы существующего блока — вне задачи.

Остальные критерии SPEC без изменений.

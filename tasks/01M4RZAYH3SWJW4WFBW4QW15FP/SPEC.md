# SPEC: Метрика разведки роли — команда `explore-stats` и блок в `report`

## Контекст
Решение Оператора 12.10.2026: план обогащения ролей знаниями, задача 1
из 4, часть «а» (метрика по уже записанным логам). Часть «б» (К-1б)
переводит строку лога на относительные формы `wt:`/`docs:`. До
обогащения ролей знаниями нужно измерить, сколько вызовов инструментов
шаг тратит на разведку (чтение и поиск) до первой правки и что именно
читает. Грубый замер 12.10 по 392 первым шагам developer: медиана 78–80
вызовов, 31 до первой правки кода (~38%), 76 шагов без правки кода.
Своей метрики у пульта нет; похожий подсчёт — только блок test_author
`report` (`report._tool_calls`), и обрезка пути до
`TOOL_ARGUMENT_LIMIT` = 100 символов (`providers/claude.py`) делает
сегодня большинство абсолютных путей нечитаемыми.

## Требования
1. Новый модуль `orchestrator/explore_metric.py` только читает: строки
   журнала, переданные вызывающим, и файлы логов. Ни записи в БД,
   журнал, логи и git, ни запуска агентов. Сводка — одна функция,
   принимающая строки журнала, текущий момент, число суток и роли (не
   соединение с БД); ею пользуются и команда (п. 7), и блок `report`
   (п. 8). У строки журнала она читает только `id, task_id, ts, actor,
   action, detail`, сама отбирает нужные действия (пп. 2, 5) и
   упорядочивает по `id`. Модуль не импортирует `report` и `artel`:
   регулярное выражение пути лога объявлено в нём самом тем же текстом,
   что `report._LOG_PATH_RE`.

   Контракт функции сводки (решение Оператора 13.10, О-5):
   `explore_metric.summarize(steps, now, days, roles)`, где `steps` —
   итерируемое строк журнала (доступ по ключу), `now` — текущий момент
   типа `datetime` (с часовым поясом UTC), передаётся вызывающим явно,
   сама функция часы не читает; `days` — целое число суток; `roles` —
   итерируемое имён ролей. Результат — словарь «роль → словарь
   показателей» с ключами:
   - `steps` — шагов; `first_runs` — из них первых прогонов;
     `codex_steps` — из них шагов Codex;
   - `median_calls` — медиана всех вызовов;
   - `median_to_code_edit` — медиана вызовов до первой правки кода;
     `no_code_edit` — шагов, где правка кода не наступила;
   - `median_to_write` — медиана вызовов до первой записи любого вида;
     `no_write` — шагов, где запись любого вида не наступила;
   - `share` — доля роли (п. 4), число от 0 до 1;
   - `no_boundary` — шагов без правки (граница роли не наступила);
   - `unrecognized_edits` — правок не распознано;
   - `outside_writes` — записей вне рабочей копии;
   - `logs_missing` — логов не найдено;
   - `top_reads` — до 10 пар `(путь, число)`; `truncated_reads` и
     `reads_total` — K и M строки «путь обрезан: K из M чтений»;
   - `top_searches` — до 10 пар `(искомая строка, число)`.
   Медиана и доля, для которых нет ни одного шага, — `None`. Топы
   упорядочены по убыванию числа, при равенстве — по строке. Для роли вне
   константы границ (п. 4) значение — словарь с единственным ключом
   `refusal`: текст отказа, называющий роль.
2. Выборка шагов — записи `agent run started`: роль = actor, лог = путь
   из текста записи (формат `report._LOG_PATH_RE`), время = полная метка
   `ts` формата `YYYY-MM-DD HH:MM:SSZ`; в период входят записи не старше
   N суток от переданного момента, граница включительно (запись ровно
   N суток назад входит). Берутся только записи задач из таблицы `tasks`
   — так же у команды и у блока `report` (решение Оператора 13.10, О-6).
   Логи по маске каталога не
   перебираются (журналы команд пульта `<id>-auto-<n>.log` и подобные в
   выборку не попадают). Запись без пути лога и путь к отсутствующему или
   нечитаемому файлу (`OSError`, каталог вместо файла) — счётчик «логов
   не найдено», без падения. Лог читается построчно с
   `errors="replace"`, как в `report._tool_calls`. Один и тот же путь
   лога учитывается один раз. Первый прогон роли в задаче — `<n>` = 1 в
   имени лога.
3. Разбор лога: вызов — строка с префиксом
   `providers/claude.py::TOOL_CALL_LINE_PREFIX` (константа, не литерал);
   имя — первое слово, аргумент — остаток. Правка — Edit, Write,
   MultiEdit, `file_change`; у `file_change` берётся значение ПЕРВОГО
   видимого поля `path` перечня (остальное и усечённый JSON не
   разбираются). Путь приводится к виду ОДНОЙ функцией нормализации,
   понимающей все формы:
   - `wt:<путь>` — путь в рабочей копии; `docs:<путь>` — документ задачи;
   - абсолютный путь с полным сегментом `/worktrees/<id задачи записи>/`
     (старая `.artel/worktrees/<id>/…` и текущая
     `.artel/projects/<проект>/worktrees/<id>/…` раскладки) — путь в
     рабочей копии после сегмента;
   - абсолютный путь с полным сегментом
     `/.artel/projects/<проект>/tasks/<id>/` — документ задачи;
   - иной путь — «вне рабочей копии» (временный каталог, главная копия).

   Класс правки: путь в рабочей копии непуст и не начинается с `tasks/`
   — правка кода; путь в рабочей копии на `tasks/` и документ задачи —
   запись документа; вне рабочей копии — запись вне рабочей копии.
   Значение длиной не меньше `TOOL_ARGUMENT_LIMIT` (усечённое), у
   которого остаток после сегмента пуст или короче 6 символов и
   совпадает с началом `tasks/`, либо полного сегмента не видно вовсе, —
   «правка не распознана»: правкой кода не считается и границей «первая
   правка кода» не служит, но служит границей «первая запись любого
   вида»; учитывается и отдельным счётчиком. Не усечённое значение с
   коротким остатком (`…/worktrees/<id>/t`) классифицируется обычным
   порядком.

   Уточнение (решение Оператора 13.10, О-1): длина значения меряется по
   аргументу строки вызова целиком — у `file_change` это весь аргумент
   JSON, а не извлечённое значение `path`. Усечённое значение формы `wt:`
   с путём длиной не меньше 6 символов, не начинающимся с `tasks/`, —
   правка кода; усечённое значение формы `docs:` — запись документа, не
   правка кода.
4. По шагу считаются: всего вызовов; вызовов строго до первой правки
   кода; вызовов строго до первой записи любого вида (правка кода, запись
   документа, вне рабочей копии, правка не распознана). Граница разведки
   роли — константа модуля: developer и test_author — первая правка
   кода; analyst, reviewer и spec_auditor — первая запись любого вида.
   Роль вне константы — именованный отказ. Шаг, где граница не
   наступила, — «шаг без правки»: в медианы «до границы» и в долю не
   входит. Доля роли = сумма вызовов до границы / сумма всех вызовов по
   шагам с границей. Медиана каждого события («до первой правки кода»,
   «до первой записи») считается по шагам роли, где это событие
   наступило; шаги, где оно не наступило, в эту медиану не входят и
   учитываются отдельным счётчиком «событие не наступило» по роли
   (решение Оператора 13.10, О-2).
5. Провайдер шага — из ближайшей следующей записи действий
   `retro.TOKEN_JOURNAL_ACTIONS` («agent cost KNOWN», «agent cost
   PARTIAL») той же задачи и роли (`provider=<имя>`), но не стоящей за
   следующей записью «agent run started» той же задачи и роли; записи
   нет — по именам вызовов: шаг с `command_execution` или `file_change` —
   Codex, иначе Claude. Шаги Codex дают число вызовов и границу, когда
   правка распознана (п. 3), но не дают чтений; их число выводится
   отдельно.
6. Топ чтений до границы — аргументы Read после нормализации п. 3: путь
   в рабочей копии — как есть, документ задачи —
   `<документы задачи>/<имя файла>` (сводится между задачами и
   раскладками), чтение вне рабочей копии — абсолютным путём как есть.
   Аргумент Read длиной не меньше `TOOL_ARGUMENT_LIMIT` в любой форме
   (абсолютной, `wt:`, `docs:`) — путь обрезан: в топ не идёт,
   учитывается строкой «путь обрезан: K из M чтений».
   Топ искомых строк до границы: значение вызова Grep как есть; в Bash —
   команда `grep`, `rg` или `git grep` в начале команды (начало строки
   или после `;`, `&&`, `||`, `|`, `(`, `$(`), первая такая в строке;
   шаблон — значение `-e`/`--regexp`, иначе первый аргумент без ведущего
   `-` (флаги `-A -B -C -m --include --exclude -f`, а у `rg` также `-t`,
   `--type`, `-g`, `--glob` забирают значение и шаблоном не считаются);
   внешние кавычки снимаются; шаблон, оборванный обрезкой строки (нет
   закрывающей кавычки или строка длиной не меньше `TOOL_ARGUMENT_LIMIT`
   кончается внутри шаблона), не учитывается. Grep и Bash суммируются в
   один топ. Команда поиска после `|` учитывается так же
   (`git ls-files | grep x` даёт искомую строку `x`).
7. Команда `explore-stats [--days N] [--role <роль>]` в
   `orchestrator/artel.py`: по умолчанию N = 7, роли developer,
   test_author, reviewer, analyst; spec_auditor — через `--role`. Вывод —
   текст, по роли: шагов (из них первых прогонов и шагов Codex), медиана
   всех вызовов, медиана до первой правки кода, медиана до первой
   записи, доля (п. 4), шагов без правки, правок не распознано, записей
   вне рабочей копии, логов не найдено, топ-10 файлов, «путь обрезан»,
   топ-10 искомых строк. Пустой период — «шагов за N суток нет», код
   выхода 0. Неизвестная роль, `--days` без значения, не целое или не
   больше нуля — именованный отказ. Команда — в таблице `artel.main` и в
   разделе «Команды:» справки; в `_ROLE_ALLOWED_COMMANDS` не
   добавляется. Журнал команда берёт тремя выборками
   `store.steps_of_action` — «agent run started» и действия
   `retro.TOKEN_JOURNAL_ACTIONS` — и сливает их по `id`; как и блок
   `report`, берёт только задачи из таблицы `tasks` (п. 2).

   Подписи строк вывода по роли (решение Оператора 13.10, О-5) —
   заголовок с именем роли, затем строки с подписями, в этом порядке:
   `шагов:` (с «первых прогонов:» и «Codex:» в той же строке),
   `медиана вызовов:`, `медиана до первой правки кода:`,
   `правка кода не наступила:`, `медиана до первой записи:`,
   `запись не наступила:`, `доля разведки:`, `шагов без правки:`,
   `правок не распознано:`, `записей вне рабочей копии:`,
   `логов не найдено:`, `топ-10 файлов:` (далее строки «число путь»),
   `путь обрезан: K из M чтений`, `топ-10 искомых строк:` (далее строки
   «число строка»). Неопределённые медиана и доля (`None`, п. 1)
   выводятся как «н/д». Числа строк — значения функции сводки п. 1.
8. `report`: блок «Разведка ролей (последние 7 дней)» в `_render` из
   функции сводки п. 1 по уже прочитанному `steps` — без нового запроса
   к БД; окно — своя константа 7 суток, `OPERATOR_WINDOW_DAYS` не
   меняется; остальные блоки отчёта не меняются. Текущий момент

   передаёт в функцию сводки; сам `_render` часы не читает. На тех же
   данных блок даёт те же числа, что команда с параметрами по умолчанию.
9. Тесты в `tests/` — новый файл, на синтетических логах и журнале
   песочницы (настоящие `.artel/logs` и `state.db` не читаются); каждый
   тест несёт заявку «Ловит мутацию:». Существующие тесты не меняются и

10. `docs/codebase-map.md` пересобирается запуском

## Критерии приёмки
AC-1. Модуль `orchestrator/explore_metric.py` не импортирует `report` и
`artel`; его функция сводки `summarize(steps, now, days, roles)`
принимает строки журнала, текущий момент типа `datetime`, число суток и
роли (не соединение с БД) и возвращает словарь «роль → показатели» с
ключами п. 1; читает у строки только `id,
task_id, ts, actor, action, detail`, сама отбирает действия и
упорядочивает по `id`; регулярное выражение пути лога модуля и
`report._LOG_PATH_RE` разбирают одну и ту же запись (путь с пробелом и
запятой) одинаково.

AC-2. Шаги берутся только из записей `agent run started` по пути лога из
их текста: лог `<id>-auto-1.log` с теми же строками вызовов, не названный
такой записью, в выборку не попадает; один и тот же путь лога
учитывается один раз; первый прогон определяется по `<n>` = 1 в имени
лога.

AC-3. Граница периода — полная метка `ts` (`YYYY-MM-DD HH:MM:SSZ`), не
дата: запись старше N суток от переданного момента, даже в ту же
календарную дату, в период не входит; запись ровно N суток назад входит
(граница включительно). Записи задач, которых нет в таблице `tasks`, не
входят ни в команду, ни в блок `report`.

AC-4. Запись `agent run started` без пути лога, путь к отсутствующему
файлу и путь к каталогу на месте файла не роняют сводку и команду и
учитываются счётчиком «логов не найдено».

AC-5. Нормализация пути: `wt:orchestrator/x.py` и абсолютный путь с
полным сегментом `/worktrees/<id>/` в обеих раскладках дают путь в
рабочей копии; путь в рабочей копии на `tasks/` (обе раскладки),
`docs:PLAN.md` и абсолютный путь с сегментом
`/.artel/projects/<проект>/tasks/<id>/` дают запись документа, не правку
кода; иной путь — запись вне рабочей копии. Правками считаются Edit,
Write, MultiEdit и `file_change` (у `file_change` — первое видимое поле
`path`).

AC-6. Правка с усечённым значением (длина не меньше
`TOOL_ARGUMENT_LIMIT`), у которой полного сегмента не видно (в том числе
`file_change` старой формы) или остаток после сегмента пуст либо короче
6 символов и совпадает с началом `tasks/` (например «tas»), — «правка не
распознана»: не правка кода, учтена отдельным счётчиком. Не усечённое
значение `…/worktrees/<id>/t` классифицируется обычным порядком (правка
кода), а не «не распознана». Длина меряется по аргументу строки вызова
целиком: усечённый `file_change` с коротким первым `path` в усечённом
JSON без полного сегмента — «не распознана», а не «вне рабочей копии».
Усечённое значение `wt:<путь>` (путь не меньше 6 символов, не на
`tasks/`) — правка кода; усечённое `docs:<путь>` — не правка кода.

AC-7. «До границы» — вызовы строго до первой правки кода (developer,
test_author) или первой записи любого вида (analyst, reviewer,
spec_auditor): сам граничный вызов в счёт не входит, вызов перед ним
входит; на шаге, где первой была запись документа, «до первой записи» и
«до правки кода» различаются. Нераспознанная правка — граница analyst и
не граница developer. Граница analyst, reviewer и spec_auditor не
берётся как правка кода.

AC-8. Роль вне константы границ даёт именованный отказ, не исключение.

AC-9. Шаг без наступившей границы не входит ни в медианы «до границы»
(ни нулём, ни полным числом вызовов), ни в долю; доля — отношение сумм
по шагам с границей, не среднее долей; медиана на наборе чётной длины —
медиана, не среднее. Медиана «до первой правки кода» и медиана «до
первой записи» каждая считается по шагам, где наступило своё событие,
независимо от границы роли (у analyst медиана до правки кода — по шагам
с правкой кода; у developer медиана до записи — по шагам с записью);
шаги без события учтены счётчиками `no_code_edit` и `no_write`.

AC-10. Провайдер шага берётся из ближайшей следующей записи «agent cost
KNOWN» или «agent cost PARTIAL» той же задачи и роли приоритетно над
именами вызовов (запись `provider=claude` при вызовах
`command_execution` даёт Claude); запись, стоящая за следующим «agent
run started» той же задачи и роли, провайдера не определяет; без записи
шаг с `command_execution` или `file_change` — Codex. Шаг Codex не даёт
чтений, число шагов Codex выводится отдельно.

AC-11. Топ чтений до границы: Read после границы в топ не попадает;
аргумент Read длиной `TOOL_ARGUMENT_LIMIT` - 1 — полный, длиной
`TOOL_ARGUMENT_LIMIT` — обрезан, в абсолютной форме и в форме `wt:`;
обрезанный путь в топ не идёт и учитывается строкой «путь обрезан: K из
M чтений»; чтение вне рабочей копии остаётся в топе абсолютным путём без
изменений; один файл из двух задач или двух раскладок (абсолютная и
`wt:`) даёт одну строку топа; документы задачи сводятся к
`<документы задачи>/<имя файла>`.

AC-12. Топ искомых строк до границы: внешние кавычки сняты; из Bash
берётся первая команда поиска (`grep`, `rg`, `git grep`) в строке, в том

AC-13. Команда `explore-stats` есть в таблице `artel.main` и в разделе

после прогона не вырос (ни одной записи в `state.db`), содержимое файлов
логов до и после прогона совпадает, git за время прогона не вызывается

AC-15. `report` несёт блок «Разведка ролей (последние 7 дней)»,

## Оценка объёма и деление
Сработавший сигнал: число критериев приёмки 15 ≥
`SPLIT_SIGNAL_AC_COUNT` (10). Файлов зоны вне общих зон
(`config.COMMON_ZONES`) — три (`orchestrator/explore_metric.py`,
`orchestrator/artel.py`, `orchestrator/report.py`); рамка Оператора $45
— ниже `SPLIT_SIGNAL_BUDGET_USD`.

Обоснование монолита (материал для решения Оператора):
- ТЗ — уже выделенная часть «а» плана К-1; ядро объёма — одна функция
  сводки модуля (AC-1…AC-12), на которую опираются оба потребителя.
- Техническая нарезка возможна только как «модуль + команда» и затем
  «блок `report`»; вторая часть — несколько строк в `_render` и два
  теста (AC-15), её отдельный цикл (analyst → test_author → developer →
  reviewer) стоит дороже самой правки.
- Свойство AC-15 «числа блока совпадают с командой на тех же данных»
  проверяется только при наличии обоих потребителей; в отдельной части
  оно переезжает во вторую задачу целиком, первая его не несёт.
- Обе части делят зоны `tests/` и `docs/codebase-map.md`, а
  `orchestrator/artel.py` уже занят двумя идущими задачами (очередь
  замка зон): деление удлиняет очередь, не снимая пересечения.

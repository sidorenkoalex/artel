# ТЗ: пульт не зависит от профиля оболочки — самовыбор интерпретатора при старте

Источник: копилка 05.09 (docs/backlog.md, приоритет 2), сессия
ассистента 05.09 после перезапуска контекста.

Фактура. `python3` из PATH зависит от профиля оболочки: pyenv
инициализируется только в `~/.zshrc`; в login-оболочке без
интерактивности (ассистент, cron, хуки) `python3` — системный 3.9, и
пульт падает `TypeError` из глубины импорта (`yamlmini`, аннотации
`Path | None`), а не именованным отказом. Манифест стека (стек ч.1,
`orchestrator/stack.py::REQUIRED_PYTHON = (3, 11)`, `_python_check`)
проверяет версию только в `doctor`; venv пульта `.artel/venv`
(P0, `venv-sync`) существует и содержит интерпретатор нужной версии; роли
уже получают PATH из манифеста (стек ч.3, `runner.role_env`).

Требуется:
1. Точка входа `orchestrator/artel.py` (и `python3 -m orchestrator.artel`)
   до любых импортов пульта, синтаксис которых требует 3.10+ (то есть
   в модуле, совместимом с 3.9: без `X | None`, без match), проверяет
   `sys.version_info` против `REQUIRED_PYTHON` (значение читать без
   импорта `stack.py`, если тот несовместим с 3.9 — например, вынести
   константу в маленький модуль-лаунчер или продублировать с тестом на
   равенство).
2. Интерпретатор ниже минимума: если `.artel/venv/bin/python`
   существует и его версия не ниже минимума — перезапуск того же
   вызова под ним (`os.execv`, те же аргументы и окружение, маркер
   переменной окружения против рекурсии); иначе — именованный отказ
   одной строкой: «нужен Python 3.11+, найден 3.9 (/usr/bin/python3);
   создай venv: artel.py venv-sync» с кодом выхода 2.
3. Интерпретатор не ниже минимума, но не из `.artel/venv` — работать
   как сегодня (без перезапуска), профили пользователя и PATH не
   трогаются; в журнал шага роли (там, где пишется «окружение: python=…»)
   ничего не добавлять.
4. `doctor`: проверка `python` в стеке дополняется строкой, каким
   интерпретатором запущен пульт и есть ли `.artel/venv` — как есть, без
   изменения статусов.
5. Тесты: запуск точки входа под подменённым «старым» интерпретатором
   (subprocess с фиктивным python, печатающим версию, либо подмена
   `sys.version_info` и `os.execv` в тесте) — перезапуск под venv с теми
   же аргументами и маркером; venv нет — именованный отказ и код 2;
   маркер уже стоит — отказ без рекурсии; современный интерпретатор —
   без перезапуска. Существующие тесты стека и doctor зелёные.

Зоны: orchestrator/artel.py, orchestrator/stack.py, orchestrator/doctor.py,
tests/.

Не входит: правка профилей оболочки Оператора; хуки и cron сами по себе;
изменение `venv-sync`; роли (у них PATH уже из манифеста).

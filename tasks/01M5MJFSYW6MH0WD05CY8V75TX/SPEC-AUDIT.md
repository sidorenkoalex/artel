## Пути обхода гейтов
- AC-3, проверка «до истечения предела», в нынешнем виде толкает разработчика разбирать неполную строку сразу после её появления, то есть нарушить SPEC 1. Иначе зафиксированный тест красный. Обратная лазейка — ослабить в тесте ожидание «до предела» — уже ослабление планки. Оба пути плохи, нужна правка сценария (отклонение 1).
- Ожидание потока у прогона базы: SPEC выполнимо только с правкой `run_full_suite` вне ограничения зон или с нарушением п. 2 решения Оператора (отклонение 2).
- Других путей не найдено.

## Вердикт
concerns. Факты SPEC о коде верны, решение Оператора №1 перенесено дословно, но два его пункта при переносе разошлись с кодом и выводом xdist. Решить это может только Оператор: правка аналитика упрётся в текст решения.

1. **AC-3: «строка быстрого теста есть в файле до истечения предела» невыполнима** (SPEC AC-3; SPEC треб. 1 «неполная последняя строка ждёт следующего чтения»; живой прогон на этом аудите — хвост лога без `\n` до завершения спящего теста). В сценарии «быстрый + спящий 30 с» у строки быстрого теста `\n` до обрыва не будет никогда, поэтому по SPEC 1 её запись возможна только при дочитывании после снятия группы. Источник — пример из прошлого аудита, принятый Оператором. Предложение: проверку «по мере появления» вести на строке, которую ЗАКРЫЛА следующая строка хода. Например, `config.FULL_SUITE_WORKERS` = 1 (порядок детерминирован) и тесты «быстрый 1, быстрый 2, спящий 30 с»: строка быстрого 1 есть в файле до истечения предела, строка быстрого 2 — после обрыва (хвост без `\n`). Дефолт при молчании: проверка «до предела» относится к первой закрытой строке хода, а не к последней.
2. **Ожидание потока у прогона базы `suite-run` входит в длительность** (SPEC треб. 3, AC-7; `suite_run.py:610–612` без `observed_full_suite`; `acceptance.py:2602, 2610, 2620`; ограничение зон ТЗ). У прогона без наблюдения длительность меряется в `run_full_suite` после возврата `_run_full_suite_to_log`, а поток по AC-7 должен быть остановлен до возврата. Варианты:
   - (а) требование «не входит в длительность» относится к прогонам под наблюдением (ветка `suite-run`); у базы допускается до +2 с к пределу 1500 с;
   - (б) разрешить в `run_full_suite` минимальную правку замера (вне нынешнего ограничения зон).

   Дефолт — (а).

Для сведения, не отклонение: AC-4 и AC-7 после мержа держит только планка (SPEC «Не входит»).

# ТЗ: Каталог моделей, ярусы ролей и запуск шага по ярусу

Родительская задача: 01M2ZZDP87DWKFJP4HAF59TES7 — Каталог моделей, ярусы ролей, локальный слой и тариф на модель
Зоны: models.yaml, orchestrator/models.py, orchestrator/roles.py, orchestrator/providers/, orchestrator/runner.py, orchestrator/stack.py, orchestrator/catalog.py, orchestrator/notes.py, orchestrator/doctor/, orchestrator/artel.py, orchestrator/config.py, docs/stack.md, docs/reference/models-local.example.yaml, tests/
Порядок: первая, без зависимостей
Рамка: $60

Часть 1 линии «три слоя данных о моделях» (план провайдеров ролей,
задача 2): модель роли перестаёт быть строкой в roles.yaml и становится
результатом цепочки «роль → ярус → модель → провайдер». Тариф в этой
части не трогается: курс по роли остаётся как есть и остаётся верным —
все четыре роли получают ярус `strong`, то есть ту же `claude-opus-5`,
на цены которой курс откалиброван 20.09.

Факты: модель роли сегодня — поле `model:` роли в roles.yaml
(`orchestrator/roles.py`), runner передаёт его флагом `--model` через
провайдера; вердикт совместимости — таблица `orchestrator/stack.py`
(одна запись, `claude-fable-5-1`), и `claude-opus-5` даёт «model
WARNING: модель не в таблице совместимости» на каждом шаге. Локальный
слой пульта `.artel/` создаёт `init` (`orchestrator/catalog.py`), в git
он не входит. Отказ до старта агента — `runner._refuse_before_start` и
`runner._resolved_role_model`. Строка `doctor` «провайдеры ролей: роль →
провайдер» и предполёт по провайдеру роли — `orchestrator/doctor/`.

Требуется:
1. Каталог `models.yaml` в корне репозитория (создаётся этой задачей):
   по провайдерам (`claude` сейчас; раздел `codex` добавит задача 4
   плана) — имя инструмента CLI, минимальная версия CLI провайдера,
   признак `cost_from_cli`, и модели: идентификатор, минимальная версия
   CLI для модели, прейскурант по четырём видам токенов за миллион
   (`list_price_usd_per_mtok`: input/output/cache_write/cache_read),
   дата прейскуранта, статус (`supported` | `experimental`). Стартовое
   содержимое — модели, которые роли использовали в журнале с 28.08:
   `claude-sonnet-5`, `claude-opus-5`, `claude-fable-5-1`; минимумы CLI
   — из сегодняшней таблицы совместимости `orchestrator/stack.py`;
   прейскурант `claude-opus-5` — из сегодняшней таблицы курса
   `orchestrator/config.py` (20.09), пересчитанный на миллион токенов;
   прочие цены — по публичному прейскуранту Anthropic, с датой.
2. Разбор каталога — новый модуль `orchestrator/models.py`: загрузка,
   схема, именованные ошибки: неизвестный провайдер, модель без
   прейскуранта, неполный прейскурант, ноль как цена.
3. `models.yaml` добавляется в список защищённых путей
   `orchestrator/config.py` и в допустимые пути `doc-commit`
   (`orchestrator/notes.py`, префикс `config:`). Гейт защищённых путей
   читает список главной копии на момент проверки, поэтому ветка,
   впервые создающая файл, переход проходит — это проверяется тестом.
4. Ярусы у ролей: поле `model_tier` agent-роли в roles.yaml из закрытого
   перечня `strong | standard | cheap` (`orchestrator/roles.py`). Поле
   `model` у роли больше не читается пультом и удаляется из roles.yaml
   тем же приложением, которым добавляется `model_tier`. Agent-роль без
   `model_tier` или с ярусом вне перечня — именованный отказ `run`/`auto`
   до старта агента и красная строка `doctor`.
5. Локальный слой `.artel/models.yaml` (вне git): `tiers:` — ярус →
   идентификатор модели из каталога; необязательный `overrides:` по
   модели — собственный тариф по четырём видам с `calibrated_at` и
   `source`; необязательное явное разрешение модели со статусом
   `experimental`. Разбор — тот же `orchestrator/models.py`. Шаблон
   кладёт `init` и `doctor --fix`, если файла нет: ярусы на
   `claude-opus-5`, без переопределений; существующий файл не
   перезаписывается.
6. Разрешение цепочки роль → ярус → модель → провайдер, минимум CLI,
   действующий тариф (переопределение, иначе прейскурант каталога) —
   функция `models.resolve_role(role)`, fail-closed на каждом звене
   (ярус без модели, модель не в каталоге, `experimental` без
   разрешения — именованный отказ до старта агента). Действующий тариф
   эта часть только ОТДАЁТ; его потребитель появится в части 2.
7. Runner и провайдеры: `runner._resolved_role_model` и
   `runner._refuse_before_start` берут модель через `models.resolve_role`;
   вердикт совместимости провайдера сверяет установленную версию CLI с
   минимумом модели из каталога — таблица совместимости вместе с
   предупреждением «модель не в таблице совместимости» удаляется из
   `orchestrator/stack.py` (модель не в каталоге — теперь отказ, не
   предупреждение). Инвариант «агент роли не стартует без явного
   `--model`» сохраняется тестом.
8. `doctor`: проверка «каталог моделей» (файл разобран, у каждой модели
   ярусов есть провайдер, минимум CLI и полный прейскурант), проверка
   «локальный слой» (файл есть, ярусы всех agent-ролей разрешаются,
   `experimental` разрешён явно); строка «провайдеры ролей» расширяется
   до «роль → ярус → модель → провайдер».
9. Команда `models` (только чтение, `orchestrator/artel.py` +
   `orchestrator/models.py`): таблица «провайдер, модель, статус,
   минимум CLI, прейскурант, действующий тариф и его источник, роли по
   ярусам»; отказ из окружения роли не нужен (чтение).
10. Документация: `docs/stack.md` — раздел «Модели: каталог, ярусы,
    тариф» (три слоя, цепочка разрешения, что делает Оператор при смене
    модели или цен; часть про историю тарифов допишет часть 2);
    `docs/reference/models-local.example.yaml` — шаблон локального слоя,
    тот же, что кладёт `init`.
11. Тесты (tests/): разбор каталога и локального слоя с именованными
    ошибками; разрешение цепочки и все отказы fail-closed; отказ
    `run`/`auto` до старта агента для роли без яруса и для модели вне
    каталога; `--model` всегда явный; `doctor` ok/fail по каждой новой

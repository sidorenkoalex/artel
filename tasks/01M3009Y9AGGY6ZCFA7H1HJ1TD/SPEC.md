# SPEC: Каталог моделей, ярусы ролей и запуск шага по ярусу

## Контекст
Модель роли сегодня — строка `model:` у роли в `roles.yaml`
(`orchestrator/roles.py`), которую `orchestrator/runner.py` передаёт
провайдеру флагом `--model`. Вердикт совместимости модели с CLI живёт
отдельной таблицей `orchestrator/stack.py` (одна запись,
`claude-fable-5-1`), поэтому `claude-opus-5` даёт «модель не в таблице
совместимости» на каждом шаге. Цен моделей в системе нет вовсе: курс
токенов задан по РОЛИ (`orchestrator/config.py`, калибровка 20.09 по
ценам `claude-opus-5`). Задача — часть 1 линии «три слоя данных о
моделях»: модель роли становится результатом цепочки «роль → ярус →
модель → провайдер», а каталог моделей `models.yaml` становится местом,
где живут провайдер, минимум версии CLI, прейскурант и статус модели.
Тариф в этой части только ОТДАЁТСЯ разрешением цепочки; его потребитель
и правка курса — часть 2 линии.

## Оценка объёма и деление

Сработавшие сигналы (сверено вызовом `guard.split_signal_names` на этом
файле): число затрагиваемых модулей/файлов зоны (порог 5) и число
критериев приёмки (19, порог 10). Прогноз диффа — 80 КиБ, ниже порога
сигнала; потолок задачи $50 — ниже порога сигнала по бюджету.

Решение — **монолит**. Что нельзя разрезать:

- Требования 5, 8, 9 и приложение к `roles.yaml` (требование 15)
  атомарны по мержу. Приложение удаляет поле `model` и добавляет
  `model_tier`; пульт применяет его на мерже задачи. `roles.yaml` без
  `model` в мерже, где `runner` ещё читает `model`, останавливает шаги
  всех четырёх ролей; `roles.yaml` с `model_tier` в мерже, где никто
  его не читает, — мёртвое поле. Промежуточного состояния, в котором
  конвейер работает, между этими двумя нет.
- Требование 10 удаляет из `orchestrator/stack.py` таблицу
  совместимости и её предупреждение. Замена (сверка установленной
  версии CLI с минимумом модели из каталога) обязана прийти тем же
  мержем, иначе предполёт шага на один мерж теряет проверку версии CLI
  — ту самую, ради которой таблица заведена (инцидент 19.09).
- Единственный технически возможный шов — «каталог + разбор +
  защищённый путь + документация» отдельно от «ярусы + разрешение +
  runner + doctor + `models`» — режет поперёк зоны
  `orchestrator/models.py` (загрузка, схема и `resolve_role` — один
  новый модуль) и зоны `tests/`: первая часть оставляет модуль
  дописываемым во второй, то есть зону разрезанной пополам, чего
  требует не допускать skills/spec-authoring.md. При этом сигнал объёма
  он не снимает: вторая часть остаётся в том же классе («≥5 файлов
  зоны»), а число шагов конвейера удваивается — два цикла ревью вместо
  одного при рамке ТЗ $60.

Потолок задачи в этом SPEC — $50 (дефолт оркестратора
`orchestrator/config.py::DEFAULT_BUDGET_USD`), ниже рамки ТЗ ($60):
инструкция шага разрешает роли ставить потолок только вниз от дефолта.
Класс задачи по калибровке скила («>10 критериев или ≥5 файлов зоны»)
— ~$70, поэтому потолок здесь заведомо тесный; поднять его до рамки ТЗ
вправе Оператор командой `budget`.

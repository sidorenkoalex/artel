# SPEC: Пробный период и приостановка пары набора

## Контекст
Часть 3 из 3 деления задачи 01M3Y9YCKBFRJ8T9HSD40Z3AQN («Набор моделей
отдельной задачи — new --set с допуском по ADR-0019 п.5»). Части 1–2 уже
в main: `model_sets.yaml` и допуск пар/набора (`models.set_admitted`,
`models.admitted_set_members`), правило вины отказа автогейта
(`models.autogate_refusal_blame`), набор в строке задачи (колонки
`tasks.model_set`/`tasks.model_set_members`), разрешение модели шага с
учётом задачи (`models.resolve_task_role`) и безусловная ручная приёмка
задачи с набором (`orchestrator/fsm_autogate.py:224-234`, временная до
этой части). Эта часть заменяет безусловную ручную приёмку пробным
периодом набора и вводит автоматическую приостановку пары набора — строго
по ADR-0019 п.5 (дополнение 30.09.2026: «первые три настоящие задачи
набора идут … с полной проверкой Оператора»; «допуск приостанавливается
… при двух возвратах ревью подряд … или при отказе автогейта по вине
роли допущенного набора в настоящей задаче — до разбора Оператором»).

Термины этого SPEC:
- **настоящая задача** — задача пульта, не канареечная (`is_canary = 0`);
- **пара набора** — пара «роль → модель» из записанного состава набора
  задачи (`tasks.model_set_members`), модель которой отличается от
  боевой модели роли; пара с боевой моделью допуска не требует (то же
  правило, что у `set_admitted` части 1) и не приостанавливается;
- **возврат ревью** — вердикт ревьювера `changes_requested`, переводящий
  задачу `review -> in_dev`; виновная роль возврата — `developer` (его
  работа возвращена), то есть возврат засчитывается паре набора задачи
  по роли `developer`;
- **отказ автогейта по вине роли** — отказ, который правило вины части 1
  (`autogate_refusal_blame`) относит к `роль`; виновная роль — та, что
  названа для этой причины в части 1 (`orchestrator/models.py`, перечень
  `_ROLE_BLAME_STARTS`): критерии `manual`/`skip` в планке — `test_author`;
  красный полный набор `tests/` и непройденный критерий `ci` —
  `developer`.

## Требования

1. Пробный период набора. Настоящая задача с набором, для которой число
   задач в состоянии `done` (настоящих), чей записанный состав набора
   совпадает с её записанным составом, меньше трёх, не проходит приёмку
   автогейтом: приёмка становится ручным гейтом Оператора с причиной
   «пробная задача набора <имя>, N из 3», где `<имя>` — имя набора задачи,
   N — число таких задач в `done` плюс один. Счётчик считается из БД на
   момент решения автогейта; в `model_sets.yaml` он не пишется.
2. Безусловная ручная приёмка задачи с набором (часть 2, п.6;
   `fsm_autogate.py:224-234`) снимается и заменяется правилом
   требования 1: задача набора, для которой таких задач в `done` три и
   больше, проходит приёмку автогейтом на общих условиях (как задача без
   набора).
3. Приостановка по возвратам ревью. Пара набора по роли `developer`
   переводится в «приостановлена», когда случается второй возврат ревью
   подряд по её вине:
   - второй возврат ревью в одной задаче, где `developer` шёл на этой
     паре; либо
   - возврат ревью в задаче, если предыдущая по времени настоящая задача,
     получившая вердикт ревью при `developer` на этой же паре, тоже
     получила возврат ревью.
   Одиночный возврат ревью (без такого предшественника) пару не
   приостанавливает. Возвраты, случившиеся до последнего снятия
   приостановки этой пары (требование 6), в «подряд» не засчитываются.
4. Приостановка по отказу автогейта. Отказ автогейта приёмки в настоящей
   задаче с набором, который правило вины части 1 относит к `роль`,
   переводит в «приостановлена» пару набора виновной роли (Контекст,
   «отказ автогейта по вине роли»). Отказ с виной `пульт/пул` или
   `не установлена` пару не приостанавливает. Отказ «пробная задача
   набора …» (требование 1) — не отказ по вине роли.
5. Запись и действие приостановки. Автоматическая приостановка пишется в
   БД пульта (не в `model_sets.yaml`), с журнальной записью задачи,
   которая её вызвала, и поднимает алерт Оператору, называющий роль,
   модель, набор, задачу и причину (возвраты ревью либо отказ автогейта с
   текстом). До снятия Оператором она перекрывает состояние пары в
   `model_sets.yaml` (в том числе `state: допущена`):
   - `new --set` с набором, содержащим автоматически приостановленную
     пару, — отказ, называющий пару и приостановку; задача не заводится;
   - задача, у которой пара приостановлена посреди работы, следующий шаг
     этой роли выполняет на боевой модели роли с записью в журнал задачи
     (роль, модель набора, боевая модель, причина); шага роли на
     приостановленной паре после приостановки нет.
6. Снятие приостановки. Команда Оператора
   `artel.py pair-resume <роль> <модель> "<решение>"` снимает
   автоматическую приостановку пары с записью в журнал (роль, модель,
   текст решения). После снятия пара снова в допуске (действует её
   состояние в `model_sets.yaml`), `new --set` с набором на ней не
   отказывает по приостановке. Команда для пары без автоматической
   приостановки — отказ с ненулевым кодом и понятным текстом, без записи
   в БД.
7. Документация: `docs/stack.md` описывает пробный период набора
   (требования 1–2) и приостановку пары (требования 3–6, включая команду
   снятия) — в разделах о наборах моделей задач.
8. Чистота прогона канарейки с ожидаемой эскалацией (решение Оператора
   02.10.2026 на гейте SPEC: ADR-0019 п.5 — «без эскалаций, кроме
   ожидаемой»). Прогон, в котором ожидаемая эскалация выполнена
   (`models.expected_escalation_met`), признаётся чистым только при
   `escalations = 1`; при `escalations > 1` он нечистый — правило чистоты
   части 1 (`orchestrator/models.py::unclean_reason`, сейчас засчитывает
   такой прогон чистым) возвращает причину, называющую число эскалаций.
   Остальные условия чистоты не меняются.
9. Сценарии критериев приёмки покрыты тестами в `tests/`.

## Критерии приёмки

AC-1. Настоящая задача с набором `S`, у которой в `done` ноль, одна или
две настоящие задачи с тем же записанным составом набора, на приёмке не
проходит автогейт: приёмка остаётся ручным гейтом Оператора, причина
содержит «пробная задача набора S, N из 3» с N = 1, 2, 3 соответственно.

AC-2. Счётчик пробного периода считается из БД по совпадению записанного
состава: задачи в состояниях кроме `done`, канареечные задачи и задачи с
другим составом (в том числе под тем же именем набора) не засчитываются;
`model_sets.yaml` после решения автогейта байт-в-байт прежний.

AC-3. Четвёртая настоящая задача набора (три задачи с тем же составом в
`done`) при выполненных общих условиях автогейта проходит приёмку
автогейтом; причины «приёмка задачи с набором только ручная» больше нет
ни для какой задачи.

AC-4. Второй возврат ревью в одной настоящей задаче, где `developer` шёл
на паре набора, переводит эту пару в «приостановлена» записью в БД и
поднимает алерт Оператору, называющий роль, модель, набор и задачу;
`model_sets.yaml` не меняется.

AC-5. Возврат ревью в задаче, чья предыдущая задача на той же паре
`developer` тоже получила возврат ревью, приостанавливает пару; одиночный
возврат ревью (одна задача, один возврат, предыдущая задача на паре без
возврата или её нет) пару не приостанавливает.

AC-6. После приостановки пары по возвратам ревью следующий шаг
`developer` той же задачи идёт на боевой модели роли, в журнале задачи —
запись с ролью, моделью набора, боевой моделью и причиной; шага
`developer` на приостановленной модели нет.

AC-7. Отказ автогейта приёмки в настоящей задаче с набором с виной `роль`
(например, красный полный набор `tests/` — роль `developer`; критерии
`manual`/`skip` — роль `test_author`) приостанавливает пару набора
виновной роли и поднимает алерт; отказ с виной `пульт/пул` (например,
«бюджет задачи исчерпан») и `не установлена` пару не приостанавливает.

AC-8. `new --set S`, где набор `S` содержит автоматически приостановленную
пару (в `model_sets.yaml` у неё `state: допущена`), — отказ с ненулевым
кодом, текст называет пару и приостановку; задача не заведена.

AC-9. `artel.py pair-resume <роль> <модель> "<решение>"` для
приостановленной пары снимает приостановку и пишет запись в журнал с
ролью, моделью и решением; после этого `new --set` с тем же набором
заводит задачу. Для пары без автоматической приостановки команда — отказ
с ненулевым кодом без записи в БД.

AC-10. После `pair-resume` одиночный новый возврат ревью на этой паре пару
не приостанавливает: возвраты до снятия в «подряд» не засчитываются.

AC-11. `docs/stack.md` описывает пробный период набора (три настоящие
задачи, счётчик из БД по составу, причина ручного гейта) и приостановку
пары (два триггера, запись в БД поверх `model_sets.yaml`, алерт, откат
шага на боевую модель, команда `pair-resume`).

AC-12. Строка `canary_runs` с вердиктом `green`, нулём итераций ревью, без
отказа автогейта по вине роли и выполненной ожидаемой эскалацией
(маркер задан, `actual_escalation = 1`, маркер совпал) признаётся чистой
при `escalations = 1` и нечистой при `escalations = 2` (и любом большем
числе): `unclean_reason` возвращает непустую причину с числом эскалаций,
`clean_run` — ложь, и такой прогон не засчитывается в допуск пары
(`pair_admission`). Тест ловит мутацию: escalations > 1 при выполненной
ожидаемой засчитан чистым.

Сработавшие сигналы: число файлов зоны ≥ 5 (десять файлов и `tests/`);
число критериев приёмки ≥ 10 (двенадцать).

**Обоснование монолита** (материал для решения Оператора). Задача уже
является частью 3 деления родителя 01M3Y9YCKBFRJ8T9HSD40Z3AQN с рамкой
$45, назначенной Оператором. Пробный период и приостановка сходятся в
одной точке — решении автогейта задачи с набором
(`fsm_autogate._autogate_conditions`): пробный период заменяет там
безусловный ручной отказ части 2, а отказ автогейта четвёртой и
последующих задач — второй триггер приостановки (требование 4). Нарезка
«пробный период» / «приостановка» дала бы промежуточное состояние, в
котором четвёртая задача набора уже проходит автогейт, а отказ автогейта
по вине роли пару ещё не приостанавливает, — ровно то, от чего ADR-0019
п.5 требует защиты («допуск приостанавливается … при отказе автогейта по
вине роли допущенного набора в настоящей задаче»). Альтернатива — нарезка
в обратном порядке (сначала приостановка, затем пробный период) мержима,
но удваивает шаги аналитика и ревью на одном и том же файле
`fsm_autogate.py`.

# ANSWER-1: ответ Оператора

## Ответы

1. R1-F1 — вариант Б. «Два возврата ревью подряд» (ADR-0019 п.5, требование 3) считаются по потоку вердиктов ревью пары в порядке времени: пара приостанавливается, когда два вердикта «возврат» идут подряд без вердикта «одобрено» между ними — в одной задаче или в соседних задачах пары. Цепочка R(P), A(P), R(Q) пару не приостанавливает; R(P), R(Q) и R(P), R(P) — приостанавливают. Добавить тест на цепочку R(P), A(P), R(Q) («Ловит мутацию: возврат одобренной предыдущей задачи засчитан в "подряд"»). Правило «возвраты до последнего снятия приостановки не засчитываются» сохраняется.

2. R1-F2 — сверка: отказ автогейта по вине роли приостанавливает пару, только если последний шаг этой роли в задаче шёл на модели пары (`_last_step_model(conn, task_id, role) == model`), как для возвратов ревью. Тест на сценарий отката шага на боевую модель.

3. R1-F3 — как предлагает ревьювер: таблицы пар заводятся миграцией (`migrate()`) и в фикстурах юнит-тестов с БД в памяти, а не `executescript` на каждом запросе, включая чтения.

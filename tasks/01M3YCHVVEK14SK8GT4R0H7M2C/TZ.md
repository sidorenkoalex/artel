# ТЗ: Пробный период и приостановка пары набора

Родительская задача: 01M3Y9YCKBFRJ8T9HSD40Z3AQN — Набор моделей отдельной задачи: new --set с допуском по ADR-0019 п.5
Зоны: orchestrator/fsm_autogate.py, orchestrator/store.py, orchestrator/schema.py, orchestrator/runner.py, orchestrator/models.py, orchestrator/catalog.py, orchestrator/artel.py, orchestrator/fsm.py, orchestrator/config.py, docs/stack.md, tests/
Порядок: после части 2
Рамка: $45

Часть 3 из 3 деления задачи «Набор моделей отдельной задачи — new --set с
допуском по ADR-0019 п.5». Опирается на части 1–2: `model_sets.yaml`,
проверка допуска, правило вины отказа автогейта (часть 1), набор в строке
задачи, разрешение модели с учётом задачи и безусловная ручная приёмка
задачи с набором (часть 2). Правила — строго по ADR-0019 п.5.

Только чтение (не менять): orchestrator/canary.py,
orchestrator/canary_drive.py, orchestrator/pin.py, models.yaml,
orchestrator/fsm_merge_gate.py, orchestrator/providers/, scripts/guard.py,
skills/, templates/, docs/adr/, docs/invariants.md,
tests/test_invariants.py, docs/backlog.md, tasks/, .artel/, .codex/.

Требуется:
1. Пробный период набора: первые три настоящие задачи НАБОРА не проходят
   приёмку автогейтом — приёмка становится ручным гейтом Оператора с
   причиной «пробная задача набора <имя>, N из 3». Счётчик считается из
   БД: задачи в `done`, чей записанный состав набора совпадает с набором;
   в `model_sets.yaml` счётчик не пишется. С этой части безусловная
   ручная приёмка задачи с набором (часть 2, п.6) заменяется этим
   правилом: четвёртая и последующие задачи набора проходят приёмку
   автогейтом на общих условиях.
2. Приостановка: два возврата ревью подряд по вине роли пары набора (в
   одной задаче или в двух задачах подряд; одиночный возврат — обычная
   работа) или отказ автогейта по вине роли пары в настоящей задаче (по
   правилу вины части 1) переводят пару в «приостановлена» и шлют алерт
   Оператору. Автоматическая приостановка пишется в БД (не в
   `model_sets.yaml`), перекрывает состояние пары в файле до разбора
   Оператором и снимается командой Оператора (имя выбирает SPEC) с
   записью в журнал. Новые задачи с приостановленной парой — отказ `new`.
3. Задача, у которой пара приостановлена посреди работы, ведётся дальше на
   боевой модели этой роли с записью в журнал; молчаливого продолжения на
   приостановленной паре нет.
4. Документация: в `docs/stack.md` — пробный период и приостановка.
5. Тесты в `tests/`: пробная задача набора не проходит приёмку
   автогейтом, четвёртая — проходит; два возврата ревью подряд
   приостанавливают пару, задача продолжает на боевой модели; отказ
   автогейта по вине роли приостанавливает пару, по вине пульта — нет;
   `new --set` с автоматически приостановленной парой — отказ; команда
   снятия приостановки возвращает пару в допуск с записью в журнал.
   Существующие тесты разрешения моделей, канарейки и автогейта не
   удаляются и не ослабляются.

Не входит: запись счётчика или автоматической приостановки в
`model_sets.yaml`; коммиты пульта в main из окна мержа; изменение чисел
допуска ADR-0019; возобновление допуска при смене версии модели у
провайдера.

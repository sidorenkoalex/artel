Пробелы:
- **Н-1. AC-20 («обращения») против треб. 5 («вызываются») и AC-22.**
  Треб. 5 (SPEC.md, абзац «Сеть») ограничивает *вызовы* `urllib`/
  `http.client` одной функцией транспорта. AC-20 ограничивает
  *обращения*. При этом AC-22 требует, чтобы `URLError`, поднятый
  подменённым транспортом, поймала функция адаптера вне транспорта.
  Буквальный сторож AC-20 («любая ссылка на `urllib` вне транспорта»)
  запрещает в функции запроса `except urllib.error.URLError`/`HTTPError`
  и `import urllib.request` на уровне модуля. Исполнимо всё равно: можно
  ловить `OSError` (`URLError` и `TimeoutError` — его подклассы) и читать
  код через `getattr(exc, "code", None)`, а импорт перенести в
  транспорт. Но автор теста и разработчик прочтут AC-20 по-разному, и
  дальше — эскалация «тест-навязывает-устройство». Нужно уточнить, что
  считать обращением: вызов (по треб. 5) или любую ссылку, включая
  `except` и импорт.
- **Н-2. Старшинство итогов GitLab не задано.** Для GitHub порядок
  проверки задан явно (треб. 2). Для GitLab треб. 6 перечисляет правила
  без старшинства, и при двух сработавших правилах итог не определён:
  - конвейер `running` (он ещё идёт, пока стадии не кончились) и задание
    `failed` без права падать: правило статуса конвейера даёт `running`,
    правило заданий — `red`;
  - `failed` вместе с `canceled` у заданий без права падать: `red` или
    `unknown`;
  - `failed` вместе с неполной выдачей.

  Слова «без `failed`» в AC-7 подразумевают для заданий «`red` старше
  `running`», но для статуса конвейера ничего не сказано. Ни один из
  вариантов не даёт `green`, поэтому инвариант 19 не задет. Разница в
  реакции `ci` (таблица треб. 10): `VERIFYING_RED` против
  `VERIFYING_RUNNING`/`NONE` — пульт либо отвечает сразу, либо ждёт.
  Тесты старшинство не закрепят.
- **Н-3. Итог `created`/`skipped`, которые не стоят за ручным заданием,
  не назван.** AC-5 и вторая половина AC-24 требуют только «не `green`».
  Какой это из итогов (`running`/`unknown`/`red`), не сказано, а от этого
  зависит вид в `ci`. Наблюдение для Б1: задание `when: on_failure`
  после успешного конвейера получает статус `skipped`, и такой конвейер
  по правилу ТЗ и ADR-0029 п. 8 никогда не будет `green`. Отклонением
  SPEC это не является — так написано в ТЗ.
- **Н-4. Строка срока токена: исход при ошибке HTTP/сети и для github не
  задан.** Треб. 11 и часть 2 п. 2 задают `skip` только «без токена». Для
  `check_base_branch` ошибка HTTP и сеть названы явно (`skip`), а для
  строки срока — нет. В тесте А0 :346 через подмену песочницы (треб. 15)
  строка получит «сеть недоступна», и её статус выберет разработчик.
  Тест А0 смотрит только `project-support-*`, поэтому не ломается. Для
  записей `forge: github` не сказано, выводится ли строка вообще: функции
  `forge` для github отказывают «не реализовано для github».

## Вердикт
**concerns.** Отклонения О-7…О-9 и замечания третьего аудита закрыты в
SPEC по решению гейта №2. Расхождений ТЗ и SPEC нет, факты с кодом
сходятся, ложного `green` по требованиям не найдено. Остались четыре
пробела в определённости. Все они не задевают инвариант 19 и решаются
строкой Оператора на гейте либо принятием как есть:

1. **Н-1 — AC-20 «обращения» против треб. 5 «вызываются» и AC-22.**
   Неясно, разрешён ли в функции запроса `except urllib.error.URLError`
   (SPEC.md: треб. 5, абзац «Сеть»; AC-20; AC-22). Предложение: AC-20
   проверяет *вызовы* и ссылки на функции/классы открытия соединения
   (`urlopen`, `Request`, `HTTPConnection`…) вне транспорта, а ссылки на
   классы исключений `urllib.error` вне транспорта разрешены. Либо
   явно: исключения ловятся через `OSError`.
2. **Н-2 — старшинство итогов GitLab** (треб. 6). Конвейер `running`
   вместе с заданием `failed` без права падать даёт по двум правилам
   `running` и `red`. Предложение: порядок «`red` → `unknown` →
   `running` → `none` → `green`», то есть задание `failed` без права
   падать даёт `red` при любом статусе конвейера, кроме неполной выдачи.
   Либо оставить выбор разработчику.
3. **Н-3 — итог `created`/`skipped`, которые не стоят за ручным
   заданием** (треб. 6, AC-5, AC-24): назвать его. Естественные варианты:
   `running` для `created` и `unknown` для `skipped`.
4. **Н-4 — строка срока токена** (треб. 11, часть 2 п. 2): исход при
   ошибке HTTP/сети (предложение: `skip` с причиной, как у
   `check_base_branch`) и выводится ли строка для `forge: github`.

Прежнее замечание, не блокирует: запрет правки `config.py` держит только
ревью (`COMMON_ZONES`, config.py:864).

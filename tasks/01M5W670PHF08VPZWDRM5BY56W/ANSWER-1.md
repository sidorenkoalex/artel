# ANSWER-1: ответ Оператора

## Ответы

Ответы сессии при Операторе (права волны G; решения Оператора по ADR-0029 от 26.10.2026) на QUESTIONS.md аналитика.

1. **A.** Белый список дополняется двумя парами только на чтение: `GET /projects/:id` (из ответа используются только `default_branch` и уровень доступа токена из `permissions`) и `GET /projects/:id/pipelines?ref=<ветка>` (последний конвейер ветки). «Участники» (`/members…`) — по-прежнему запрещены; запись — только создание MR, снятие черновика, исполнитель. Это уточнение ADR-0029 п. 8 «чтение конвейеров» в пределах только чтения.
2. **A.** Для `forge: github` `pipeline_status` оборачивает нынешнее чтение check runs `ci` без изменения поведения; остальные функции `forge` для `github` — именованный отказ «не реализовано для github», `gh` не вызывают. GitHub-потребители по-прежнему зовут `ci`/`github_adapter` напрямую.
3. **A.** `ci.head_sha` для GitLab остаётся локальным (`git rev-parse` в клоне); транспорт не вызывается. Формулировка ТЗ п. 3 в части `head_sha` уточняется так.
4. **A.** Все функции адаптера (включая п. 1) — в части 1; часть 2 (`doctor`, `forge-probe`) только потребляет; в зоны части 2 добавляется `orchestrator/doctor/__init__.py` (фасад). Рамки: часть 1 — $50, часть 2 — $25.
5. **A.** Пятый итог `unknown` с причиной: `canceled` у задания без права падать или у конвейера, неизвестный статус, неполная выдача (задания читаются постранично до конца, число сверяется с `X-Total`); `waiting_for_resource`/`preparing`/`scheduled` → `running`; `unknown` никогда не зелёный. Критерии на `canceled`, неизвестный статус, вторую страницу с `failed`.
6. **A.** «За ручным» — по стадиям (ручное задание в более ранней стадии того же конвейера), плюс задание не в `policy.ci_required_jobs`. Критерий: `created` не за ручным и вне списка — не `green`.
7. **A.** Ключ теста — `<classname>::<name>`; совпадение ключей в одном отчёте — `None` с причиной «неоднозначный идентификатор».
8. **A.** Явный контракт отображения итогов GitLab на виды `verifying_status`/`branch_status`/`status_kind`/`verifying_is_red`/`rerun_started`; `none` и `unknown` — не зелёные; отказ `trigger_rerun` для gitlab содержит «не запущен»; `main_line_status`/`find_run_id` — вид «неизвестно», не зелёный. Критерий таблицей.
9. **A.** Без полученного токена (нет слота, отказ, пустой слот, процесс роли) адаптер не делает запроса и отдаёт именованную причину; строки `doctor` для gitlab — `skip` с этой причиной. Тест А0 не меняется. Критерий: подменённый транспорт при отсутствии токена не вызван.
10. **A.** `check_run_workflow_run` для gitlab — именованный отказ, `gh` не вызывается.
11. **A.** Разрешена только смена заголовка префиксом `Draft: ` (наличие/отсутствие); иная смена `title` — отказ до транспорта.
12. **B.** Как в ADR-0029 п. 8: токен без срока — `warn` после порога числа задач проекта (константа `gitlab_adapter.TOKEN_NO_EXPIRY_TASKS_WARN = 10` — решение Оператора 25.10 «напомнить после 10 задач»).
13. **A.** Критерий на `job_result`: два задания с разными статусами — статус запрошенного; нет задания — именованная причина; несколько попыток — статус последней.

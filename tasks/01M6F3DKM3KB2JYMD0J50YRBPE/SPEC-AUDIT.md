Отклонения:
- **В1. Подтяжка внутри визита не покрыта.** `pull-main` меняет голову в
  `verifying` без нового входа в состояние (`orchestrator/pull_main.py:1-9,
  61-107`). Реализация, считающая отметки «после последней записи входа в
  `verifying`» без сверки sha отметки, проходит AC-11/AC-12/AC-13: в профиле
  `[human:a, human:b]` отметка `a` по X, `pull-main` → голова Y, новая
  запись «ждёт проверки … по sha Y», `verify-ok b Y` → `review` с проверкой
  `a`, выполненной на другой голове. ТЗ п. 3 и требование 3 называют
  подтяжку явно. Нужен критерий: после `verify-ok` по X `pull-main` даёт
  голову Y в том же визите — отметка по X не действует, `review` только
  после отметок по Y.
- **В2. Потолок ожидания CI у проекта с `verify` не покрыт.** Матрица
  (строка 1) пишет «для ожидания CI — остаётся», покрытие —
  `tests/test_verifying_ceiling.py`, но этот файл гоняет проекты без
  `verify`. Мутация «у проекта с непустым `verify` потолок не применяется
  вовсе» проходит все AC: AC-6 проверяет только ожидание отметки. Нужен
  критерий: проект с `verify: [human:stand]`, CI головы ждёт (или гейт по
  исходам ждёт отчёт), подменённое истечение потолка → `escalated`, как
  сейчас.
- **В3. `waiting_on` вне ожидания отметки не проверен.** AC-4 проверяет
  `operator` в ожидании; ни один AC не проверяет, что у проекта с `verify`
  при CI в ожидании (сценарий AC-9) `waiting_on` остаётся `ci`. Мутация
  «`waiting_on` = `operator` для любой задачи `verifying` проекта с
  непустым `verify`» (по профилю, без журнала) проходит. Достаточно
  дополнить AC-9 строкой «`waiting_on` — `ci`».
- **В4 (мелкое).** `verify: []` — по требованию 1 «пусто, поведение
  прежнее», критерия нет (AC-3 — только «без поля»). Мутация «пустой список
  — отказ загрузки» проходит.

## Вердикт

решение по пунктам ниже (каждый — добавка критерия или уточнение

# SPEC: Помощник общего состояния только для чтения со сторожем неизменности (ADR-0032, этап 5, часть а)

## Контекст
ADR-0032 п. 4 (принят 08.11.2026, `e4de84a0`): тесты, которые дорогое
состояние не меняют, делят одну фикстуру в своём файле. Фикстуру строит
только помощник. Он снимает отпечаток состояния до каждого теста и после
него. Если отпечатки расходятся, оставшиеся тесты фикстуры получают ошибку
«общее состояние загрязнено». Живые процессы общими не делаются. Эта
задача делает сам помощник и сторож. Правила guard и скилов, а также
перевод существующих тестов — следующие части.

От текста ADR-0032 п. 4 эта задача отступает в двух местах, и ни одно не
ослабляет проверки (Оператору их отмечает сессия как поправку к ADR):
- **место помощника** — `tests/sandbox.py`, а не `tests/fixtures.py`.
  Инвариант 42 (`tests/test_invariants.py:3466`,
  `SharedFixturesWrapSandboxClassesInvariantTest`) запрещает функциям
  модуля фикстур обращаться к `config`, `environ` и `setattr`, а сторожу
  они нужны;
- **время жизни песочницы** — модуль, а не класс. У тестов-функций
  (ADR-0027 п. 1) фикстура уровня класса строится заново на каждый тест.

Опорные места: `tests/sandbox.py` — `ALL_CONFIG_ATTRS` (`:91`),
`_REAL_RUN = subprocess.run` (`:941`), `TmpRootTest` (`:1605`,
`PATCHED_ATTRS = ALL_CONFIG_ATTRS` — `:1623`; подмена `subprocess.run` на
`SpyRun` — `:1705`), `RealGitSandbox` (`:1921`; создаёт БД в `setUp` —
`:1978`; `origin` во временном каталоге вне корня — `:2009`),
`OriginRealGitSandbox` (`:2040`; голый `origin` через `mkdtemp()` —
`:2050`), символьная ссылка `repo -> root` (`:1542-1559`). Жизненный цикл
фикстуры-переходника (создание, `setUp()`, уборка со сбором ошибок) —
`tests/fixtures.py::_sandbox` (`:42`) и `_run_cleanups` (`:20`). Пульт
зовёт `ps` полным путём `/bin/ps` (`orchestrator/acceptance.py:1675`,
`orchestrator/doctor/stale_cycles.py:49`): в `PATH` шага роли `/bin` нет.

Поведение pytest 9.1.1 (проверено Оператором). Ошибка в завершении
фикстуры даёт тесту исход «прошёл» и дополнительно «ошибку при
завершении»: в junit это элемент `<error>` у теста. Ошибка в подготовке
фикстуры следующего теста даёт «ошибку при подготовке», и тело теста не
исполняется. Хука в корневом `conftest.py` нет, файл защищён. Переменная
`PYTEST_CURRENT_TEST` меняется между подготовкой и завершением теста.
Фикстура `scope="module"` не может исполняться вокруг каждого теста;
фикстура уровня функции с уборкой через
`request.node.getparent(pytest.Module).addfinalizer` даёт песочницу на
модуль и сторожа на тест (опыт аудитора SPEC).

Чтение тоже может менять файлы песочницы. `git status` переписывает
индекс, если тот устарел. Соединение sqlite в режиме WAL создаёт файлы
`-wal` и `-shm`, и они остаются после закрытия соединения. Обращение к БД
пульта может создать файл БД. Под `pytest -n auto` песочница модуля
строится заново в каждом рабочем процессе, а при `--dist worksteal` — может
и несколько раз на одном рабочем; на корректность это не влияет. `psutil`
в окружении пульта нет. На macOS дочерние процессы перечисляются через
`ps -axo pid,ppid,command` с отбором по родителю.

## Требования

1. **Помощник.** `tests/sandbox.py` получает функцию
   `shared_readonly(sandbox_cls, build)`. Она возвращает фикстуру pytest.
   Файл присваивает её имени уровня модуля, например
   `seeded = shared_readonly(RealGitSandbox, build_seeded)`. Тест берёт
   фикстуру параметром и получает объект с двумя атрибутами: `sandbox`
   (экземпляр песочницы) и `built` (то, что вернул `build`).
   - Время жизни песочницы — модуль: песочница строится один раз на модуль
     (экземпляр `sandbox_cls`, его `setUp()`, затем `build(sb)`), а уборка
     идёт завершителем узла модуля. Тесту фикстура отдаётся на уровне
     функции и снимает отпечаток до теста и после него (требование 3).
   - Ошибки уборки собираются и роняют завершение модуля с текстом
     упавшего действия, как у `tests/fixtures.py::_sandbox`.
   - Утверждений в помощнике нет, кроме сторожа (ADR-0027 п. 3).
2. **Отпечаток.** `tests/sandbox.py` получает публичную функцию
   `shared_state_snapshot(sb) -> dict`, словарь частей:
   - БД пульта песочницы. Открывается только на чтение (`mode=ro`), берутся
     все таблицы, строки идут в порядке первичного ключа, значения всех
     столбцов. Если файла БД нет, часть имеет значение «нет», и файл не
     создаётся;
   - каждый репозиторий git в каталоге песочницы: ссылки (`for-each-ref`,
     все ссылки с их значениями), HEAD, индекс по `git ls-files -s` (не
     побайтно) и содержимое отслеживаемых файлов рабочего дерева. Кроме
     репозиториев под корнем песочницы, отпечаток берёт каждый репозиторий,
     на который указывает локальный адрес (путь или `file://`) удалённого
     репозитория у репозиториев песочницы, — так голый `origin` во
     временном каталоге вне корня входит в отпечаток;
   - файлы каталога песочницы: путь, размер, содержимое;
   - окружение процесса (имена и значения переменных), текущий каталог и
     значения атрибутов `config` из `PATCHED_ATTRS` класса песочницы;
   - дочерние процессы процесса теста: pid и команда, без самого процесса
     `ps`. Внуки, переданные `launchd`, не видны: это предел отпечатка, а
     не дефект.
3. **Закрытый перечень исключений.** Из окружения процесса исключается
   ровно переменная `PYTEST_CURRENT_TEST`. Из файлов каталога — ровно
   служебные каталоги git и файлы `*.db`, `*.db-wal`, `*.db-shm`,
   `*.db-journal`. Из атрибутов `config` из `PATCHED_ATTRS` — ничего. Иных
   исключений реализация не делает.
4. **Обход каталога.** Обход каталога песочницы не разыменовывает
   символьные ссылки. Репозиторий git учитывается один раз, по настоящему
   пути. Настоящий путь — `os.path.realpath`: для голого `origin` во
   временном каталоге на macOS это путь вида `/private/var/…`, а не
   `/var/…`, который хранит песочница.
5. **Настоящие команды.** Команды отпечатка исполняются настоящим запуском,
   мимо подмен песочницы: перечень процессов — `/bin/ps -axo
   pid,ppid,command` (или `shutil.which("ps") or "/bin/ps"`), git —
   настоящим `subprocess.run`, сохранённым в `tests/sandbox.py` как
   `_REAL_RUN`, а не подменяемым `subprocess.run`, который `TmpRootTest`
   заменяет на `SpyRun`.
6. **Сторож.** Отпечаток снимается перед каждым тестом, взявшим фикстуру,
   и после него. При расхождении завершение этого теста падает с ошибкой.
   Ошибка называет каждую изменившуюся часть ровно такими названиями:
   - «таблица <имя>»;
   - «ссылка <имя ссылки> репозитория <путь>»;
   - «HEAD репозитория <путь>»;
   - «индекс репозитория <путь>»;
   - «рабочее дерево репозитория <путь>: <путь файла>» — содержимое
     отслеживаемого файла репозитория;
   - «файл <путь относительно корня песочницы>» — файл каталога
     песочницы;
   - «переменная окружения <имя>»;
   - «атрибут config.<имя>»;
   - «текущий каталог»;
   - «процесс <pid> <команда>».

   <имя ссылки> — полное имя ссылки, как его печатает `git for-each-ref
   --format=%(refname)` (`refs/heads/<ветка>`, `refs/tags/<тег>`).
   «репозитория <путь>» — настоящий путь репозитория (`os.path.realpath`,
   требование 4). Правка отслеживаемого файла меняет обе части, «рабочее
   дерево репозитория …» и «файл …», и ошибка называет обе. Процессы
   сравниваются по паре pid и команда. После расхождения каждый следующий тест этой фикстуры в
   модуле получает ошибку при подготовке «общее состояние загрязнено
   тестом <имя>», и его тело не исполняется.
7. **Живой процесс не делится.** Если после `build(sb)` у процесса есть
   дочерние процессы, которых не было до `build`, построение фикстуры
   падает с ошибкой. Ошибка называет pid и команду каждого такого
   процесса. Уборка эти процессы убивает.
8. **Отпечаток не меняет состояние.** Два отпечатка подряд без действий
   между ними равны. Отпечаток песочницы без файла БД не создаёт файл БД.
9. **Метка размера.** Если этап 4 ADR-0032 (метка размера) попадёт в main
   раньше, чем эта задача выйдет из `tests_writing`, тестовые файлы задачи
   несут `pytestmark = pytest.mark.size("large")`. Файл, где есть только
   проверка отпечатка, несёт `medium`.

## Критерии приёмки

AC-1. Дано: модуль-образец во временном каталоге с фикстурой
`shared_readonly(RealGitSandbox, build)` и тремя читающими тестами. `build`
меняет время изменения отслеживаемого файла репозитория песочницы
(`os.utime`) без изменения содержимого, так что к первому тесту индекс
устарел. Каждый тест вызывает `git status` в репозитории песочницы
(первый `git status` переписывает индекс) и открывает БД пульта песочницы
на чтение. Действие: модуль прогоняется подпроцессом pytest с отчётом
junit. Итог: `build` исполнен ровно один раз (это видно по счётчику в
файле-метке, а не по `scope` фикстуры), все три теста прошли без ошибок,
обход каталога песочницы с символьной ссылкой `repo -> root` завершился.
(Размер проверки: большой — исход тестов, их порядок и ошибки подготовки и
завершения видны только в отдельном прогоне pytest.)

AC-2. Дано: модуль-образец с четырьмя тестами: читающий, загрязняющий и
два после него. Второй тест меняет состояние. Каждый способ — отдельный
случай, и у каждого своё ожидаемое название части из требования 6:
- новая строка в таблице БД пульта песочницы — «таблица <имя>»;
- изменённое значение в существующей строке таблицы БД пульта — «таблица
  <имя>»;
- новый коммит в репозитории песочницы — «ссылка refs/heads/<ветка>
  репозитория <путь>»;
- новая ветка и новый тег без сдвига HEAD — «ссылка refs/heads/<ветка>
  репозитория <путь>» и «ссылка refs/tags/<тег> репозитория <путь>»;
- отправка коммита в `origin` песочницы `OriginRealGitSandbox` — «ссылка
  <имя ссылки> репозитория <путь>», где путь — `os.path.realpath`
  каталога `origin` (тест сравнивает с `os.path.realpath` того же
  каталога, а не с хранимым песочницей путём `/var/…`);
- HEAD переключён на другую ветку без новых коммитов — «HEAD репозитория
  <путь>»;
- изменённый отслеживаемый файл добавлен в индекс без коммита — «индекс
  репозитория <путь>»;
- изменённый отслеживаемый файл — «рабочее дерево репозитория <путь>:
  <путь файла>»;
- отслеживаемый файл изменён правкой той же длины — «рабочее дерево
  репозитория <путь>: <путь файла>»;
- неотслеживаемый файл каталога песочницы изменён правкой той же длины —
  «файл <путь>»;
- новый файл в каталоге песочницы — «файл <путь>»;
- новая переменная окружения — «переменная окружения <имя>»;
- изменённое значение существующей переменной окружения — «переменная
  окружения <имя>»;
- удалённая существующая переменная окружения — «переменная окружения
  <имя>»;
- сменённый текущий каталог — «текущий каталог»;
- переприсвоенный атрибут `config` из `PATCHED_ATTRS` — «атрибут
  config.<имя>»;
- оставленный живой дочерний процесс — «процесс <pid> <команда>».

Итог для каждого случая, по отчёту junit: у второго теста есть элемент
`<error>`, в котором есть ожидаемое название части этого случая (другие
изменившиеся части тоже могут быть названы). У третьего и четвёртого тестов
есть `<error>` «общее состояние загрязнено тестом <имя второго>».
Файлов-меток, которые создало бы тело третьего или четвёртого теста, нет.
(Размер проверки: большой — то же обоснование.)

AC-3. Дано: `build` оставляет живой дочерний процесс, и этот процесс
пишет свой pid в файл-метку. Итог: ошибка построения фикстуры называет
pid этого процесса. Ни один тест модуля не исполнен. Процесса с pid из
файла-метки нет: тест проверяет это сразу по завершении подпроцесса
pytest и до того, как сам убивает группу процессов подпроцесса, — так
проверка видит уборку помощника (требование 7), а не уборку теста.
(Размер проверки: большой — то же обоснование.)

AC-4. Дано: песочница `RealGitSandbox`. Действие: два вызова
`shared_state_snapshot(sb)` подряд без действий между ними. Итог: отпечатки
равны. Дано: песочница `RealGitSandbox`, у которой тест удаляет файл БД
после `setUp()`. Итог: после снятия отпечатка файла БД нет.
(Поверхность решения: `tests.sandbox.shared_state_snapshot(sb) ->
dict`; размер проверки: средний.)

AC-5. Дано: уборка песочницы падает. Итог: завершение модуля — ошибка с
текстом упавшего действия. (Размер проверки: большой — то же обоснование.)

AC-6. Каждая из мутаций делает приёмочные тесты красными:
- «отпечаток не снимает таблицы БД»;
- «БД — только число строк таблицы»;
- «отпечаток не видит окружение процесса»;
- «окружение — только имена переменных»;
- «ссылки — только HEAD»;
- «файлы — путь и размер без содержимого» (краснеет на случае AC-2 с
  неотслеживаемым файлом той же длины);
- «загрязнение не переходит на следующие тесты»;
- «отпечаток читает индекс побайтно».

Безопасность тестов (из ТЗ и решений Оператора на гейте SPEC, обязательна
для всех критериев):
- модули-образцы, песочницы и голый `origin` лежат во временном каталоге
  (`tests.sandbox`); настоящие файлы репозитория не меняются;
- подпроцесс pytest запускается с явным путём файла, с `PYTHONPATH` на
  корень дерева, с пределом времени и в своей группе процессов; после
  каждого прогона подпроцесса (не только при обрыве) тест убивает его
  группу процессов целиком; в AC-3 — после проверки, что процесса с pid
  из файла-метки нет;
- дочерний процесс модуля-образца в случаях AC-2 и AC-3 имеет конечный
  срок жизни, не дольше 60 с; после теста процессов образца нет;
- приёмочные тесты проходят в шаге роли с её `PATH` (без `/bin`);
  команды модуля-образца, которых нет в `PATH` роли, вызываются полным
  путём (`/bin/sleep`);
- служебный каталог пульта и каталоги задач не читаются и не пишутся;
- сеть не используется.

## Не входит

- Правило guard, запрещающее фикстуры уровня модуля, класса и сессии вне
  помощника. Прослеживание помощника гейтом неослабления. Правило «тест с
  общей фикстурой других песочниц не берёт». Всё это — этап 5, часть б.
  Подмены `config` и окружения песочницы общей фикстуры держатся весь
  модуль, в том числе для тестов модуля без фикстуры. Эта задача так и
  оставляет.
- Правила о помощнике в скилах (часть б).
- Перевод существующих тестов на помощник и пилот (этап 6).
- Изменение `tests/fixtures.py`, `conftest.py` и инвариантов. Только для
  чтения: `docs/adr/0032-test-cost-and-growth.md`,
  `docs/adr/0027-pytest-style-tests.md`, `tests/fixtures.py`,
  `tests/test_invariants.py`, `conftest.py`, `orchestrator/config.py`,
  `orchestrator/store.py`, `orchestrator/acceptance.py`,
  `orchestrator/doctor/stale_cycles.py`, `skills/test-authoring.md`.
- Зелёный полный набор `tests/`, в том числе инварианты 37 и 42 — эту
  проверку держит пульт. Если покраснеет инвариант изоляции песочниц или
  модуля фикстур, это эскалация с именем теста, без правки (ТЗ).
- Поправка к тексту ADR-0032 о месте помощника и времени жизни песочницы.
  Её Оператору отмечает сессия, не эта задача.

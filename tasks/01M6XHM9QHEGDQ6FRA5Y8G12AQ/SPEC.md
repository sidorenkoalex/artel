# SPEC: Помощник общего состояния только для чтения со сторожем неизменности (ADR-0032, этап 5, часть а)

## Контекст
ADR-0032 п. 4 (принят 08.11.2026, `e4de84a0`): тесты, которые дорогое
состояние не меняют, делят одну фикстуру в своём файле. Фикстуру строит
только помощник. Он снимает отпечаток состояния до каждого теста и после
него. Если отпечатки расходятся, оставшиеся тесты фикстуры получают ошибку
«общее состояние загрязнено». Живые процессы общими не делаются. Эта
задача делает сам помощник и сторож. Правила guard и скилов, а также
перевод существующих тестов — следующие части.

От текста ADR-0032 п. 4 эта задача отступает в двух местах, и ни одно не
ослабляет проверки (Оператору их отмечает сессия как поправку к ADR):
- **место помощника** — `tests/sandbox.py`, а не `tests/fixtures.py`.
  Инвариант 42 (`tests/test_invariants.py:3466`,
  `SharedFixturesWrapSandboxClassesInvariantTest`) запрещает функциям
  модуля фикстур обращаться к `config`, `environ` и `setattr`, а сторожу
  они нужны;
- **уровень фикстуры** — модуль, а не класс. У тестов-функций (ADR-0027
  п. 1) фикстура уровня класса строится заново на каждый тест.

Опорные места: `tests/sandbox.py` — `ALL_CONFIG_ATTRS` (`:91`),
`TmpRootTest` (`:1605`, `PATCHED_ATTRS = ALL_CONFIG_ATTRS` — `:1623`),
`RealGitSandbox` (`:1921`). Жизненный цикл фикстуры-переходника (создание,
`setUp()`, уборка со сбором ошибок) — `tests/fixtures.py::_sandbox` (`:42`)
и `_run_cleanups` (`:20`).

Поведение pytest 9.1.1 (проверено Оператором). Ошибка в завершении
фикстуры даёт тесту исход «прошёл» и дополнительно «ошибку при
завершении»: в junit это элемент `<error>` у теста. Ошибка в подготовке
фикстуры следующего теста даёт «ошибку при подготовке», и тело теста не
исполняется. Хука в корневом `conftest.py` нет, файл защищён.

Чтение тоже может менять файлы песочницы. `git status` переписывает
индекс. Соединение sqlite в режиме WAL создаёт файлы `-wal` и `-shm`.
Обращение к БД пульта может создать файл БД. Под `pytest -n auto` фикстура
уровня модуля строится заново в каждом рабочем процессе, и на корректность
это не влияет. `psutil` в окружении пульта нет. На macOS дочерние процессы
перечисляются через `ps -axo pid,ppid,command` с отбором по родителю.

## Требования

1. **Помощник.** `tests/sandbox.py` получает функцию
   `shared_readonly(sandbox_cls, build)`. Она возвращает фикстуру pytest
   уровня модуля. Файл присваивает её имени уровня модуля, например
   `seeded = shared_readonly(RealGitSandbox, build_seeded)`. Тест берёт
   фикстуру параметром и получает объект с двумя атрибутами: `sandbox`
   (экземпляр песочницы) и `built` (то, что вернул `build`).
   - Песочница строится один раз на модуль: экземпляр `sandbox_cls`,
     его `setUp()`, затем `build(sb)`.
   - Песочница убирается в конце модуля. Ошибки уборки собираются и роняют
     завершение фикстуры с текстом упавшего действия, как у
     `tests/fixtures.py::_sandbox`.
   - Утверждений в помощнике нет, кроме сторожа (ADR-0027 п. 3).
2. **Отпечаток.** `tests/sandbox.py` получает публичную функцию
   `shared_state_snapshot(sb) -> dict`, словарь частей:
   - БД пульта песочницы. Открывается только на чтение (`mode=ro`), берутся
     все таблицы, строки идут в порядке первичного ключа. Если файла БД
     нет, часть имеет значение «нет», и файл не создаётся;
   - каждый репозиторий git в каталоге песочницы: ссылки (`for-each-ref`),
     HEAD, индекс по `git ls-files -s` (не побайтно) и содержимое
     отслеживаемых файлов рабочего дерева;
   - файлы каталога песочницы: путь, размер, содержимое. Служебные каталоги
     git и файлы БД (`*.db`, `*.db-wal`, `*.db-shm`, `*.db-journal`) не
     входят;
   - окружение процесса, текущий каталог и значения атрибутов `config` из
     `PATCHED_ATTRS` класса песочницы;
   - дочерние процессы процесса теста: pid и команда, без самого процесса
     `ps`. Внуки, переданные `launchd`, не видны: это предел отпечатка, а
     не дефект.
3. **Сторож.** Отпечаток снимается перед каждым тестом, взявшим фикстуру,
   и после него. При расхождении завершение этого теста падает с ошибкой.
   Ошибка называет каждую изменившуюся часть: таблицу, ссылку, путь,
   переменную, атрибут или процесс. После расхождения каждый следующий
   тест этой фикстуры в модуле получает ошибку при подготовке «общее
   состояние загрязнено тестом <имя>», и его тело не исполняется.
4. **Живой процесс не делится.** Если после `build(sb)` у процесса есть
   дочерние процессы, которых не было до `build`, построение фикстуры
   падает с ошибкой. Ошибка называет pid и команду каждого такого
   процесса. Уборка эти процессы убивает.
5. **Отпечаток не меняет состояние.** Два отпечатка подряд без действий
   между ними равны. Отпечаток песочницы без БД не создаёт файл БД.
6. **Метка размера.** Если этап 4 ADR-0032 (метка размера) попадёт в main
   раньше, чем эта задача выйдет из `tests_writing`, тестовые файлы задачи
   несут `pytestmark = pytest.mark.size("large")`. Файл, где есть только
   проверка отпечатка, несёт `medium`.

## Критерии приёмки

AC-1. Дано: модуль-образец во временном каталоге с фикстурой
`shared_readonly(RealGitSandbox, build)` и тремя читающими тестами. Каждый
тест вызывает `git status` в репозитории песочницы и открывает БД пульта
песочницы на чтение. Действие: модуль прогоняется подпроцессом pytest с
отчётом junit. Итог: `build` исполнен ровно один раз (это видно по счётчику
в файле-метке), все три теста прошли без ошибок. (Размер проверки:
большой — исход тестов, их порядок и ошибки подготовки и завершения видны
только в отдельном прогоне pytest.)

AC-2. Дано: тот же модуль-образец, но второй тест меняет состояние. Каждый
способ — отдельный случай: строка в таблице БД пульта песочницы; новый
коммит в репозитории песочницы; изменённый отслеживаемый файл; новый файл в
каталоге песочницы; новая переменная окружения; сменённый текущий каталог;
переприсвоенный атрибут `config` из `PATCHED_ATTRS`; оставленный живой
дочерний процесс. Итог для каждого случая, по отчёту junit: у второго
теста есть элемент `<error>` с названием изменившейся части. У третьего
теста есть `<error>` «общее состояние загрязнено» с именем второго теста.
Файла-метки, который создало бы тело третьего теста, нет. (Размер
проверки: большой — то же обоснование.)

AC-3. Дано: `build` оставляет живой дочерний процесс. Итог: ошибка
построения фикстуры называет pid этого процесса. Ни один тест модуля не
исполнен. После прогона процесса нет. (Размер проверки: большой — то же
обоснование.)

AC-4. Дано: песочница `RealGitSandbox`. Действие: два вызова
`shared_state_snapshot(sb)` подряд без действий между ними. Итог: отпечатки
равны. Дано: песочница без файла БД. Итог: после снятия отпечатка файла БД
нет. (Поверхность решения: `tests.sandbox.shared_state_snapshot(sb) ->
dict`; размер проверки: средний.)

AC-5. Дано: уборка песочницы падает. Итог: завершение модуля — ошибка с
текстом упавшего действия. (Размер проверки: большой — то же обоснование.)

AC-6. Каждая из мутаций делает приёмочные тесты красными: «отпечаток не
снимает таблицы БД», «отпечаток не видит окружение процесса», «загрязнение
не переходит на следующие тесты», «отпечаток читает индекс побайтно».

Безопасность тестов (из ТЗ, обязательна для всех критериев):
- модули-образцы и песочницы лежат во временном каталоге (`tests.sandbox`);
- подпроцесс pytest запускается с явным путём файла, с `PYTHONPATH` на
  корень дерева, с пределом времени и в своей группе процессов; при обрыве
  группа убивается целиком;
- служебный каталог пульта и каталоги задач не читаются и не пишутся;
- сеть не используется.

## Не входит

  помощника. Прослеживание помощника гейтом неослабления. Правило «тест с
  общей фикстурой других песочниц не берёт». Всё это — этап 5, часть б.
  Подмены `config` и окружения песочницы общей фикстуры держатся весь
  модуль, в том числе для тестов модуля без фикстуры. Эта задача так и
  оставляет.
- Правила о помощнике в скилах (часть б).

Отклонения:
- **В1. Мутация «файлы — путь и размер без содержимого» (AC-6, :200) маскируется частью git.** Содержимое отслеживаемого файла снимают две части сразу: «содержимое отслеживаемых файлов рабочего дерева» в части git (:87) и «файлы каталога песочницы» (:92). Обе называются одинаково — «файл <путь>» (:116). Оба случая AC-2 с правкой содержимого берут отслеживаемый файл (:160-161). Поэтому мутант, снявший содержимое только с части файлов, по-прежнему получает `<error>` «файл <путь>» через часть git, и AC-2 зелёный. Обратная мутация («часть git без содержимого») тоже выживает за счёт части файлов. Чтобы мутация из AC-6 была красной, нужен случай «неотслеживаемый файл (например, под игнорируемым `.artel/`) изменён правкой той же длины».
- **В2. У части «индекс» и у HEAD нет случая.** Требование 6 задаёт название «индекс репозитория <путь>» (:115-116), требование 2 — HEAD (:86). Ни один случай AC-2 не меняет только индекс (`git add` или `git rm --cached` без правки рабочего дерева) или только HEAD (`git checkout` другой ветки, `checkout --detach`). Мутации «индекс не снимается» и «HEAD не снимается» выживают: AC-1 проверяет только отсутствие ложного срабатывания на индексе, а новый коммит виден через `refs/heads/*`. В ТЗ таких случаев нет, поэтому это не потеря SPEC. Но заявленная часть отпечатка не покрыта ни одним критерием.
- **В3. «После прогона процесса нет» в AC-3 (:181) не отличает уборку помощника от уборки теста.** По «Безопасности» (:209-211) тест после каждого прогона убивает группу подпроцесса целиком. Процесс, порождённый `build`, остаётся в этой группе. Если тест проверяет жизнь pid после убийства группы, мутация «уборка не убивает процессы `build`» (требование 7, :125) зелёная. SPEC должен задать порядок: жизнь pid из ошибки проверяется сразу по выходу подпроцесса pytest и до убийства группы. Либо процесс образца уходит в свою сессию, и тогда группа его не задевает, а срок жизни ≤ 60 с остаётся страховкой.
- **В4. Форма «<имя ссылки>» не задана.** `for-each-ref` выдаёт `refs/heads/main`, короткое имя — `main` (:115, :154-159). Если тест ищет `ссылка refs/heads/main репозитория`, то реализация с коротким именем его не пройдёт, и наоборот. Это тот же класс, что В1 прошлого круга: риск эскалации `тест-навязывает-устройство`. Нужна одна строка: полное имя ссылки из `for-each-ref` (и `HEAD` для HEAD).

Красная фаза (тест до кода):
- `from tests.sandbox import shared_readonly` / `shared_state_snapshot` даёт `ImportError`: у файла AC-4 — ошибку сбора, у образцов AC-1..AC-3 и AC-5 — ошибку сбора в junit подпроцесса.
- Рекурсии и неограниченного порождения процессов нет. Подпроцесс ограничен временем, процесс образца — сроком ≤ 60 с (:212-213), группа подпроцесса убивается после каждого прогона.
- Меняющих команд против репозиториев пульта критерии не задают: все песочницы и `origin` лежат во временном каталоге.

# ТЗ: Помощник общего состояния только для чтения со сторожем неизменности (ADR-0032, этап 5, часть а)

# Помощник общего состояния только для чтения со сторожем неизменности (ADR-0032, этап 5, часть а)

## Факты

1. ADR-0032 п. 4 (принят 08.11.2026, `e4de84a0`): тесты, которые дорогое состояние не меняют, делят одну фикстуру в своём файле; фикстура строится только помощником; помощник до и после каждого теста снимает отпечаток (БД пульта, ссылки и деревья git песочницы, файлы её каталога, окружение процесса, текущий каталог, атрибуты `config` из `PATCHED_ATTRS`, дочерние процессы теста); при расхождении оставшиеся тесты фикстуры — ошибка «общее состояние загрязнено»; живые процессы общими не делаются.
2. Два отступления от текста ADR-0032 п. 4, оба без ослабления (их отмечает Оператору сессия как поправку к ADR):
   - **место помощника** — `tests/sandbox.py`, а не `tests/fixtures.py`: инвариант 42 (`tests/test_invariants.py:3466`, класс `SharedFixturesWrapSandboxClassesInvariantTest`) запрещает функциям модуля фикстур обращаться к `config`, `environ`, `setattr`, а сторожу они нужны; долгоживущие файлы и так берут помощники только из `tests.sandbox` (скил test_author, правило «помощники — только `tests/sandbox.py`»). Инвариант 42 не меняется;
   - **уровень фикстуры** — модуль, а не класс: у тестов-функций модуля (стиль pytest, ADR-0027 п. 1) фикстура уровня класса строится заново на каждый тест (проверено на pytest 9.1.1).
3. Классы песочниц — `tests/sandbox.py`: `TmpRootTest` (`PATCHED_ATTRS = ALL_CONFIG_ATTRS`, `:1623`, перечень — `:91`), `RealGitSandbox` и подклассы; жизненный цикл фикстуры-переходника (создать, `setUp()`, уборка с собранными ошибками) — `tests/fixtures.py::_sandbox` (`:42`) и `_run_cleanups` (`:20`).
4. Ошибка в завершении фикстуры pytest даёт тесту исход «прошёл» плюс «ошибка при завершении» (в отчёте junit — элемент `<error>` у теста), а не «провален»; ошибка в подготовке фикстуры следующего теста — «ошибка при подготовке», тело теста не исполняется (проверено на pytest 9.1.1). Хука в корневом `conftest.py` для иного исхода нет, файл защищён.
5. Чтение может менять файлы песочницы: `git status` переписывает файл индекса репозитория, соединение sqlite в режиме WAL создаёт файлы `-wal` и `-shm`, обращение к БД пульта может создать файл БД.
6. Полный набор идёт `pytest -n auto`: фикстура уровня модуля строится заново в каждом рабочем процессе, получившем тесты модуля, — на корректность это не влияет.
7. `psutil` в окружении пульта нет; на macOS перечень дочерних процессов — через `ps -axo pid,ppid,command` с отбором по родителю.

## Требуется

1. **Помощник** `shared_readonly(sandbox_cls, build)` в `tests/sandbox.py`. Возвращает фикстуру pytest уровня модуля, которую файл присваивает имени уровня модуля (`seeded = shared_readonly(RealGitSandbox, build_seeded)`); тест берёт её параметром и получает объект с атрибутами `sandbox` (экземпляр песочницы) и `built` (то, что вернул `build`).
   - Один раз на модуль: экземпляр `sandbox_cls` с `setUp()`, затем `build(sb)`; уборка песочницы — в конце модуля, ошибки уборки собираются и роняют завершение, как у `tests/fixtures.py::_sandbox`.
   - Утверждений в помощнике нет, кроме сторожа (ADR-0027 п. 3).
2. **Отпечаток** — публичная функция `shared_state_snapshot(sb)` в `tests/sandbox.py`, словарь частей:
   - БД пульта песочницы: открытие только для чтения (`mode=ro`), все таблицы, строки по порядку первичного ключа; нет файла БД — часть «нет», файл не создаётся;
   - каждый репозиторий git в каталоге песочницы: ссылки (`for-each-ref`), HEAD, индекс по `git ls-files -s` (не побайтно), содержимое отслеживаемых файлов рабочего дерева;
   - файлы каталога песочницы без служебных каталогов git и без файлов БД (`*.db`, `*.db-wal`, `*.db-shm`, `*.db-journal`): путь, размер, содержимое;
   - окружение процесса, текущий каталог, значения атрибутов `config` из `PATCHED_ATTRS` класса песочницы;
   - дочерние процессы процесса теста: pid и команда, без самого процесса `ps`. Внуки, переданные `launchd`, не видны — это предел отпечатка.
3. **Сторож.** Перед каждым тестом, взявшим фикстуру, и после него — отпечаток. Расхождение — ошибка при завершении этого теста с названием каждой изменившейся части (таблица, ссылка, путь, переменная, атрибут, процесс). После расхождения каждый следующий тест этой фикстуры в модуле — ошибка при подготовке «общее состояние загрязнено тестом <имя>», тело не исполняется.
4. **Живой процесс не делится.** Если после `build(sb)` у процесса есть дочерние процессы, которых не было до него, — ошибка построения фикстуры с их pid и командами; процессы убиваются уборкой.
5. Отпечаток не меняет состояние: два отпечатка подряд без действий между ними равны, и отпечаток песочницы без БД не создаёт файл БД.

## Критерии приёмки

- Given модуль-образец во временном каталоге с фикстурой `shared_readonly(RealGitSandbox, build)` и тремя читающими тестами, которые вызывают `git status` в репозитории песочницы и открывают БД пульта песочницы на чтение, When прогон модуля подпроцессом pytest с отчётом junit, Then `build` исполнен один раз (счётчик в файле-метке), все три теста прошли без ошибок (Размер проверки: большой — исход тестов, порядок и ошибки подготовки и завершения видны только в отдельном прогоне pytest);
- Given второй тест меняет состояние — отдельными случаями: пишет строку в таблицу БД пульта песочницы; создаёт коммит в репозитории песочницы; меняет отслеживаемый файл; создаёт файл в каталоге песочницы; ставит переменную окружения; меняет текущий каталог; переприсваивает атрибут `config` из `PATCHED_ATTRS`; оставляет живой дочерний процесс, — Then в отчёте junit у второго теста элемент `<error>` с названием изменившейся части, у третьего — `<error>` «общее состояние загрязнено» с именем второго, файла-метки, который создало бы тело третьего теста, нет (Размер проверки: большой — то же обоснование);
- Given `build` оставляет живой дочерний процесс, Then ошибка построения называет pid, ни один тест модуля не исполнен, процесса после прогона нет (Размер проверки: большой — то же обоснование);
- Given песочница `RealGitSandbox`, When два вызова `shared_state_snapshot(sb)` подряд без действий, Then отпечатки равны; Given песочница без файла БД, Then после отпечатка файла БД нет (Поверхность решения: tests.sandbox.shared_state_snapshot(sb) -> dict; Размер проверки: средний);
- Given уборка песочницы падает, Then завершение модуля — ошибка с текстом упавшего действия (Размер проверки: большой — то же обоснование);
- мутации «отпечаток не снимает таблицы БД», «отпечаток не видит окружение процесса», «загрязнение не переходит на следующие тесты», «отпечаток читает индекс побайтно» — красные.

Безопасность тестов: модули-образцы и песочницы — во временном каталоге (`tests.sandbox`); подпроцесс pytest — с явным путём файла, `PYTHONPATH` на корень дерева, пределом времени и в своей группе процессов, при обрыве группа убивается целиком; служебный каталог пульта и каталоги задач не читаются и не пишутся; без сети.

Существующие тесты: правка не должна сделать красным ни один существующий тест, в том числе инварианты 37 и 42; если краснеет инвариант изоляции песочниц или модуля фикстур — эскалация с именем теста, без правки.

Заметки: подмены `config` и окружения песочницы общей фикстуры держатся весь модуль, в том числе для его тестов без фикстуры — правило «тест с общей фикстурой других песочниц не берёт» входит в часть б. Если этап 4 ADR-0032 (метка размера) смержат раньше выхода этой задачи из `tests_writing`, файлам задачи нужна метка `pytestmark = pytest.mark.size("large")` (или `medium` для файла только с отпечатком).

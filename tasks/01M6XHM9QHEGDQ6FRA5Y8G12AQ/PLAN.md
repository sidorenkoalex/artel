# PLAN: Помощник общего состояния только для чтения со сторожем неизменности

## Подход
Весь код — в конце `tests/sandbox.py` (место помощника по SPEC, «Контекст»):

- `shared_state_snapshot(sb) -> dict` — вложенный словарь частей: `db`
  (`None` без файла БД, иначе {таблица: строки по первичному ключу/rowid}),
  `repos` ({настоящий путь: refs, HEAD, `ls-files -s`, содержимое
  отслеживаемых файлов}), `files` ({путь от корня: (вид, размер,
  содержимое)}), `env`, `cwd`, `config`, `processes`. БД открывается
  `sqlite3` с `mode=ro` (файл не создаётся). git — `_REAL_RUN` с
  `GIT_OPTIONAL_LOCKS=0` (чтение не пишет индекс), перечень процессов —
  `_REAL_POPEN` на `/bin/ps` (pid самого `ps` известен и исключается;
  зомби — завершённые процессы — не считаются живыми детьми).
  Обход — `os.walk(followlinks=False)`; символьная ссылка — файл с
  содержимым `readlink`; репозиторий — каталог с `.git` (или голый:
  `HEAD`+`objects`+`refs`), учитывается по `os.path.realpath`. Локальные
  адреса удалённых (`remote.*.url`: абсолютный/относительный путь,
  `file://`) добавляют репозитории вне корня (голый `origin`).
- `_shared_state_changes(before, after)` — перечень названий изменившихся
  частей ровно в словах требования 6.
- `shared_readonly(sandbox_cls, build)` — фикстура уровня функции, состояние
  на модуль (по `nodeid` узла `pytest.Module`): первая выдача строит
  песочницу (`setUp()` + `build`), сверяет детей процесса до/после,
  регистрирует уборку завершителем узла модуля (`addfinalizer`); каждая
  выдача снимает отпечаток до и после теста. Расхождение — ошибка
  завершения теста и метка загрязнения; следующая выдача — ошибка подготовки
  «общее состояние загрязнено тестом <имя>». Уборка — `tests.fixtures.
  _run_cleanups`/`_cleanup_message` (тот же текст, что у `_sandbox`) плюс
  убийство новых детей `build`.

Бюджет SPEC не пересматривается.

## Влияние на систему
Добавляются только новые функции в `tests/sandbox.py`; существующие
классы и функции песочницы не меняются, `tests/fixtures.py`, `conftest.py`
и инварианты не трогаются. `tests/sandbox.py` начинает импортировать
`pytest` (уже зависимость набора) и лениво — `tests.fixtures`. Откат —
revert коммита задачи.

## Риски
- Формат вывода `ps` на Linux CI (`-o pid=,ppid=,stat=,command=` есть и в
  procps).
- Зомби, не пожатые `subprocess`, между снимками — исключены по `stat`.

- `tests/test_invariants.py` — 88 passed; `tests/test_fixtures_plugin_conditional.py`,

- Временные мутации (код возвращён): «загрязнение не переходит»,
  «файлы без содержимого», «индекс побайтно», «ссылки — только HEAD»,
  «уборка не убивает процесс build» — каждая краснит свой тест.
- `ps` вызывается как `/bin/ps -A -ww -o pid=,ppid=,stat=,command=`:
  `-A` = `-ax` и на macOS, и в procps; `-ww` не обрезает команду; `stat`
  отсеивает зомби.

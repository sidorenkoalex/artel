# ТЗ: зависимости стека (P0) — файл закреплённых версий, venv пульта, установка в CI и у роли

Источник: роадмап §3, фаза S (решение Оператора 05.09 о полном
переходе на pytest). Стек пульта объявлен манифестом
`orchestrator/stack.py` (S1, 01M1RDCAFENSW2VVAPECHCVGMM) с правилом
«только стандартная библиотека» и пустым списком исключений. Переход на
pytest требует сторонних пакетов (pytest, pytest-timeout, pytest-xdist),
а значит — механизма, которым они попадают в окружение пульта, CI и
роли одинаково и воспроизводимо. Без него pytest снова окажется
«инструментом из окружения машины».

Требуется:
1. Файл закреплённых версий в корне репозитория (`requirements.lock`
   или эквивалент, формат `pip`): точные версии `pytest`,
   `pytest-timeout`, `pytest-xdist` и их транзитивных зависимостей.
   Список исключений манифеста (`orchestrator/stack.py`) получает эти
   пакеты с причиной у каждого; инвариант «только стандартная
   библиотека» пропускает импорты из списка исключений и по-прежнему
   падает на прочих.
2. Venv пульта: `.artel/venv`, создаётся командой пульта (`artel.py
   venv-sync` либо шаг `init`) средствами стандартной библиотеки
   (`python3 -m venv` + `pip install -r <файл>`), идемпотентно;
   интерпретатор venv — тот же `sys.executable` пульта (S1
   `REQUIRED_PYTHON`). `check_stack()` (S1) дополнительно сверяет
   установленные в venv версии с файлом закреплённых версий: расхождение
   — WARN с именами пакетов, отсутствие venv — WARN с командой создания.
3. CI: джоб `python` ставит зависимости из того же файла (`pip install
   -r`) после `setup-python` (S2); литералы версий в `ci.yml` не
   дублируются. `.github/workflows/ci.yml` — защищённый путь: правка
   диф-приложением в PLAN.md, `git apply --check` на чистом main.
4. Роль (S3, `role_env`): интерпретатор роли — python из `.artel/venv`,
   если venv существует и согласован с файлом; иначе шаг не стартует с
   `agent run SKIPPED` и именованной причиной (по образцу S3), без
   тихого отката на системный python.
5. Ничего из P1 (сам раннер pytest в пульте) не входит: пакеты только
   устанавливаются и проверяются, тесты по-прежнему гоняет unittest.
6. Тесты: файл закреплённых версий разбирается и согласован со списком
   исключений манифеста; `venv-sync` на временном каталоге создаёт venv
   и идемпотентен (второй вызов без изменений; сеть в тестах запрещена
   — установка пакетов подменяется, проверяется состав команды);
   `check_stack` даёт WARN на расхождении версий; `role_env` берёт
   интерпретатор venv и отказывает без него; существующий набор `tests/`
   зелёный.

Зоны: requirements.lock (новый), orchestrator/stack.py, orchestrator/
venv.py (новый), orchestrator/runner.py (role_env, только выбор
интерпретатора), tests/, PLAN.md (диф ci.yml приложением). Порядок: код
после мержа S1 (манифест) и S3 (`role_env`); SPEC и планка — сразу.
Не входит: раннер pytest (P1), параллельный прогон (P2), стиль тестов
(P3), контейнеризация, менеджеры зависимостей сверх pip/venv.

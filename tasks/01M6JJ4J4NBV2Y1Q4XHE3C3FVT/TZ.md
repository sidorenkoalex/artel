## Модель угрозы

Ошибочная команда роли, а не намеренный обход: механизм отклоняет прямой вызов git в перечисленных формах; обход через произвольный интерпретатор (`python3 -c` роли артели, абсолютный путь к git у Codex) — вне задачи, как в `docs/stack.md`, «Паритет безопасности роли».

## Требуется

1. **Граница подъёма git.** В окружении шага роли (оба провайдера, любой проект) `GIT_CEILING_DIRECTORIES` (или равный по действию механизм) не даёт git, запущенному из каталога внутри `<ROOT>/.artel`, который сам не репозиторий (сам `PROJECTS`, корень проекта, `tasks/`, каталог документов задачи, `knowledge/`, `logs/`, `epics/`), найти репозиторий пульта: отказ «not a git repository». Git в рабочей копии задачи и в клоне проекта работает как прежде. Потолок сравнивается с разрешённым путём (на macOS `/tmp` → `/private/tmp`).
2. **Отказ git в репозитории пульта и в чужой задаче.** Прямой вызов git шагом роли отклоняется до исполнения (ненулевой код, строка причины), если репозиторий или рабочее дерево, заданные явно (`-C`, `--git-dir`, `--work-tree`, `-c core.worktree=…`, `GIT_DIR`, `GIT_WORK_TREE`), разрешаются в репозиторий пульта `config.ROOT` или в рабочую копию другой задачи. Общий каталог `.git` собственной рабочей копии (в клоне) — допустим. Репозитории вне `config.ROOT` (временные каталоги тестов) не затрагиваются.
3. **Отказ `git clean`.** Прямой `git clean` шага роли с любыми флагами и путями отклоняется, если его репозиторий лежит внутри `config.ROOT` (репозиторий пульта, клоны и рабочие копии в `.artel`, включая свою). Покрываемые формы: подкоманда напрямую, псевдоним из конфигурации, раскрывающийся в `clean`, псевдоним с `!` (`-c alias.x='!…'` и из `.git/config` рабочей копии) — отказ любого `!`-псевдонима; `-c`, `--config-env`, `GIT_CONFIG_PARAMETERS`, `GIT_CONFIG_COUNT/KEY_n/VALUE_n`, задающие псевдоним, `core.worktree`, `core.pager`, `core.fsmonitor`. Строка отказа называет команду удаления из п. 4. Репозитории вне `config.ROOT` не затрагиваются.
4. **Команда пульта удаления файла задачи.** `artel.py` получает команду удаления файлов в пределах задачи (имя — на усмотрение SPEC), вносится в `_ROLE_ALLOWED_COMMANDS` с дополнением комментария над перечнем. Удаляет перечисленные файлы, только если каждый лежит после разрешения символических ссылок внутри рабочей копии задачи или каталога её документов; в каталоге документов — только файлы, которых нет в ветке артефактов задачи (созданные после последнего автокоммита), прочие — отказ. Каталог, путь вне двух корней, путь внутри `.git`, символическая ссылка наружу — отказ всей команды без частичного удаления. Под признаком роли задача берётся из `ARTEL_TASK`; другой id или признак роли без `ARTEL_TASK` — отказ. Вызов Оператора — с явным id любой задачи. Миссии ролей (`orchestrator/role_prompt.py`, там, где перечислены команды пульта для роли) называют эту команду.
5. **Различение вызовов.** Механизм пп. 2–3 не зависит от протокола конкретного CLI и одинаков для Claude и Codex. Вызовы git самого пульта не проверяются: диспетчер `artel.py` при запуске под признаком роли убирает механизм пп. 2–3 из окружения своего процесса и дочерних (граница п. 1 остаётся); маркер `ARTEL_PULT_GIT` освобождением не считается. `knowledge`, `suite-run`, `plank-run`, `mutation-run`, запущенные ролью, работают как прежде.
6. **PATH и прямой pytest.** Если механизм — обёртка git на PATH: её каталог — вторым элементом после `.artel/venv/bin`, раньше каталога git; `git --version` через неё совпадает с настоящим git; порядок, закреплённый тестами факта 5, не меняется. Прямой `pytest tests/<файл>` под окружением роли артели проходит как прежде; потеря ускорения `tests/direct_git.py` (если есть) — замер в SPEC.
7. **doctor.** Строка, проверяющая на собранном окружении роли (без запуска агента), что git из временного подкаталога `<ROOT>/.artel` (не в `tasks/`, удаляется после проверки) не находит репозиторий пульта и что `git clean` в репозитории пульта отклоняется; провал — `fail`. Проверка «без границы — `fail`» — подменой сборки окружения в тесте.
8. Документация: `docs/reference/role-home.md`, раздел «Паритет безопасности роли» `docs/stack.md`, `docs/codebase-map.md` (новые модули).
9. Дополнительно для Claude: строка `Bash(git clean:*)` в `deny` курируемого `docs/reference/role-home/claude/settings.json` (не единственный механизм; в рабочий HOME пульта Оператор переносит её руками после мержа, `docs/reference/role-home.md`).

Критерии приёмки (песочница пульта, подменённые процессы агента):
- окружение роли (Claude и Codex), cwd = каталог документов задачи, `tasks/`, корень проекта, сам `PROJECTS`: `git status` → «not a git repository»; в рабочей копии задачи и в клоне → успех;
- `git -C <ROOT> status`, `git --git-dir=<ROOT>/.git status`, `GIT_DIR=<ROOT>/.git git status`, `git -c core.worktree=<ROOT> status`, `git -C <рабочая копия чужой задачи> status` → отказ до исполнения; `git -C <своя рабочая копия> status` → успех;
- `git clean -n` и `git clean -fX -- <файл>` в своей рабочей копии и в репозитории пульта, `-c alias.cl=clean cl`, `-c alias.x='!git clean -fX' x`, псевдоним `cl = clean` в `.git/config` рабочей копии, `GIT_CONFIG_PARAMETERS` с псевдонимом → отказ; игнорируемые файлы песочницы на месте; `git clean -f` во временном репозитории вне `ROOT` → успех;
- воспроизведение инцидента: игнорируемый файл в корне песочницы пульта, роль выполняет `git -C <каталог документов задачи> clean -fX -- x.py` → отказ, файл на месте;
- команда удаления: свой файл рабочей копии и новый файл каталога документов — удалены; файл документов, уже лежащий в ветке артефактов, путь вне корней, `../`, ссылка наружу, каталог, путь в `.git`, чужой id, признак роли без `ARTEL_TASK` → отказ, ни один файл набора не удалён; вызов Оператора с id — успех;
- `knowledge`, `suite-run`, `plank-run`, `mutation-run`, запущенные из окружения роли, исполняются как прежде;
- прямой `pytest` долгоживущего теста артели, создающего временный репозиторий с `git clean`, под окружением роли — зелёный;
- строка `doctor` п. 7: исправное окружение — `ok`, подменённое без границы — `fail`.

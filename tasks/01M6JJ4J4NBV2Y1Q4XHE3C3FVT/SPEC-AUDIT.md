Отклонения:
- **В-1.** Проверка cwd из требования 2 (SPEC.md:50) для команды, отличной от
  `clean`, не покрыта ни одним критерием в той части ROOT, где потолок не
  действует (cwd = `<ROOT>` или `<ROOT>/docs`). Внутри `.artel` ненулевой код даёт
  и один потолок, поэтому AC-1(а) мутацию «механизм не проверяет cwd» не ловит.
  AC-4 ловит её только для `clean`. Правдоподобная мутация — cwd проверяется
  только у `clean`. Тогда `git reset --hard` с cwd `<ROOT>/docs` проходит, и все
  AC зелёные. Нужна форма вроде «cwd = `<ROOT>/docs`, `git reset --hard` → отказ,
  файл сохранил изменение».
- **В-2.** Цепочка `-C` (SPEC.md:51-52: «нескольких `-C` подряд, относительных —
  от предыдущего») не покрыта: в AC-2 все `-C` одиночные и абсолютные.
  Правдоподобные мутации — проверяется только первый `-C`, или относительный
  `-C` разрешается от исходного cwd. Пример: `git -C <своя копия> -C ../../..
  status` (итог — `<PROJECTS>/<проект>`, внутри ROOT) или `git -C <своя копия>
  -C <ROOT> status`. Обе мутации проходят AC-2.
- **В-3.** Разрешение символических ссылок перед проверкой (SPEC.md:53-54) не
  покрыто: нет формы `git -C <ссылка вне ROOT → ROOT> status`. Мутация
  `abspath` вместо `realpath` проходит все AC, если тестовая песочница задаёт
  `config.ROOT` и аргументы в одном (неразрешённом) виде. Для `task-rm` такой
  случай есть (AC-11), для механизма 2–3 — нет.

## Пути обхода гейтов
- Наблюдение, не отклонение. В исключении требования 2 «клон проекта и его
  подкаталоги» (SPEC.md:63-65) не сказано, чей это клон: проекта своей задачи
  или любого проекта в `PROJECTS`. При буквальном прочтении `git -C
  <PROJECTS>/<другой проект>/repo reset --hard` из шага чужого проекта проходит.
  Кроме того, подкаталоги общего `.git` включают служебные каталоги чужих
  рабочих копий (`<клон>/.git/worktrees/<чужая>`). С ними
  `GIT_DIR=<клон>/.git/worktrees/<чужая> git reset --hard` двигает индекс чужой
  задачи, а рабочим деревом берёт свой cwd. ТЗ допускает только «общий каталог
  `.git` собственной рабочей копии». Под модель угрозы (ошибочная команда) это
  маловероятно; уточнить формулировку можно на гейте одной строкой.
- Наблюдения визита 3 (нестрогое «содержит вызов git»; каналы
  `pager.<команда>`/хуки) в силе, держать на ревью.

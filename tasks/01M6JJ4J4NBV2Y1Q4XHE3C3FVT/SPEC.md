# SPEC: Граница git для ролей — git из каталогов пульта не доходит до репозитория пульта, отказ `git clean` и git в репозитории пульта, команда удаления файла задачи

## Контекст
Инцидент 04.11 (задача 01M6HWP40X94FYE7FS0N63VMCS, роль test_author): `rm`
роли недоступен, и роль, убирая свой временный файл, выполнила
`git -C <ROOT>/.artel/projects/<проект>/tasks/<id> clean -fX -- stubcheck.py`.
Каталог документов задачи — не репозиторий, git поднялся до репозитория
пульта (`config.ROOT`) и удалил игнорируемые файлы пульта (`.artel/models.yaml`,
`.artel/canary/`, `.artel/notes-pending/`, локальные каталоги проекта,
`.artel/home/.claude`). Каталоги области проекта лежат внутри репозитория пульта
(`config.PROJECTS`, `orchestrator/config.py:57`; `artifact_branch.docs_dir`).
Белый список роли Claude — `Bash(git:*)` (`orchestrator/providers/claude.py:45`,
`:114`) — пропускает любую подкоманду и любые `-C`/`--git-dir`/`--work-tree`/`-c`;
у Codex разрушительную часть закрывает песочница `workspace-write`
(`orchestrator/providers/codex.py:136`, `:437-444`), у Claude — ничто. Вдобавок
роль внешнего проекта не может удалить свой неотслеживаемый файл иначе как
`git clean -f <файл>`.

Модель угрозы — ошибочная команда роли, а не намеренный обход: механизм
отклоняет прямой вызов git в перечисленных формах; обход через произвольный
интерпретатор (`python3 -c` роли артели) и абсолютный путь к git — вне задачи
(`docs/stack.md`, «Паритет безопасности роли»).

## Требования

1. **Граница подъёма git.** В окружении шага роли (`runner.role_env`; оба
   провайдера — Claude и Codex; любой проект — артель и внешний)
   `GIT_CEILING_DIRECTORIES` или равный по действию механизм не даёт git,
   запущенному из каталога внутри `<ROOT>/.artel`, который сам не репозиторий
   (сам `config.PROJECTS`, корень проекта, `tasks/`, каталог документов задачи,
   `knowledge/`, `logs/`, `epics/`), найти репозиторий пульта: git завершается
   отказом «not a git repository». Git в рабочей копии задачи и в клоне проекта
   работает как прежде. Потолок сравнивается с разрешённым путём (на macOS
   `/tmp` → `/private/tmp`).
2. **Отказ git в репозитории пульта и в чужой задаче.** Прямой вызов git шагом
   роли отклоняется до исполнения (ненулевой код возврата, строка причины), если
   репозиторий или рабочее дерево, заданные явно — `-C`, `--git-dir`,
   `--work-tree`, `-c core.worktree=…`, переменные `GIT_DIR`, `GIT_WORK_TREE`, —
   разрешаются в репозиторий пульта `config.ROOT` или в рабочую копию другой
   задачи. Общий каталог `.git` собственной рабочей копии (в клоне проекта)
   допустим. Репозитории вне `config.ROOT` (например, временные каталоги тестов)
   не затрагиваются.
3. **Отказ `git clean`.** Прямой `git clean` шага роли с любыми флагами и путями
   отклоняется до исполнения, если его репозиторий лежит внутри `config.ROOT`
   (репозиторий пульта, клоны и рабочие копии в `.artel`, включая свою рабочую
   копию). Покрываемые формы:
   - подкоманда `clean` напрямую;
   - псевдоним из конфигурации, раскрывающийся в `clean`;
   - любой псевдоним с `!` — и заданный `-c alias.x='!…'`, и из `.git/config`
     рабочей копии: отказ любого `!`-псевдонима;
   - `-c`, `--config-env`, `GIT_CONFIG_PARAMETERS`,
     `GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_<n>`/`GIT_CONFIG_VALUE_<n>`, задающие
     псевдоним, `core.worktree`, `core.pager` или `core.fsmonitor`.
   Строка отказа называет команду удаления из требования 4. Репозитории вне
   `config.ROOT` не затрагиваются.
4. **Команда пульта удаления файла задачи.** `orchestrator/artel.py` получает
   команду `task-rm <id> <путь>…` (новый модуль `orchestrator/task_files.py`).
   - Команда вносится в `_ROLE_ALLOWED_COMMANDS` (`orchestrator/artel.py:2562`)
     с дополнением комментария над перечнем (что команда пишет и в каких
     пределах).
   - Удаляет перечисленные файлы, только если каждый после разрешения
     символических ссылок лежит внутри рабочей копии задачи `<id>` или каталога
     её документов (`artifact_branch.docs_dir`). В каталоге документов
     удаляются только файлы, которых нет в ветке артефактов задачи (созданные
     после последнего автокоммита); файл, лежащий в ветке артефактов, — отказ.
   - Каталог, путь вне двух корней (в том числе через `../`), путь внутри
     `.git`, символическая ссылка, ведущая наружу, — отказ всей команды: ни один
     файл набора не удаляется (без частичного удаления).
   - Под признаком роли (`ARTEL_ROLE`) задача берётся из `ARTEL_TASK`: `<id>`,
     отличный от `ARTEL_TASK`, и признак роли без `ARTEL_TASK` — отказ. Вызов
     Оператора (без признака роли) — с явным id любой задачи.
   - Миссии ролей (`orchestrator/role_prompt.py`, там, где перечислены команды
     пульта для роли) называют эту команду.
5. **Различение вызовов.** Механизм требований 2–3 не зависит от протокола
   конкретного CLI и одинаков для Claude и Codex. Вызовы git самого пульта не
   проверяются: диспетчер `artel.py` при запуске под признаком роли убирает
   механизм требований 2–3 из окружения своего процесса и дочерних (граница
   требования 1 остаётся). Маркер `ARTEL_PULT_GIT` (`orchestrator/gitcmd.py:25`)
   освобождением от механизма не считается. `knowledge`, `suite-run`,
   `plank-run`, `mutation-run`, запущенные ролью, работают как прежде.
6. **PATH и прямой pytest.** Если механизм — обёртка git на PATH: её каталог —
   вторым элементом PATH роли сразу после `.artel/venv/bin`, раньше каталога
   git; `git --version` через неё совпадает с выводом настоящего git; порядок
   PATH, закреплённый существующими тестами (`tests/test_providers.py:260`,
   `tests/test_multitarget.py:940`, `tests/test_codex_login_shell_path.py:199`,
   `tests/test_01m5kjne39phv9eawjchk7qdfs_direct_git.py:563-590`), не меняется.
   Прямой `pytest tests/<файл>` под окружением роли артели проходит как прежде.
   Если механизм отменяет ускорение `tests/direct_git.py` (git мимо обёртки
   xcrun), разработчик записывает в PLAN.md замер времени прямого `pytest`
   одного файла тестов под окружением роли до и после.
7. **doctor.** Новая строка `doctor` на собранном окружении роли (без запуска
   агента) проверяет, что git из временного подкаталога `<ROOT>/.artel` (не в
   `tasks/`, удаляется после проверки) не находит репозиторий пульта и что
   `git clean` в репозитории пульта отклоняется; провал любой части — `fail`.
8. **Документация.** Механизм и команда удаления описаны в
   `docs/reference/role-home.md`, в разделе «Паритет безопасности роли»
   `docs/stack.md`; новые модули — в `docs/codebase-map.md` (регенерация

## Критерии приёмки
Проверка — в песочнице пульта с подменёнными процессами агента: команды
исполняются под окружением, собранным `runner.role_env` для роли
соответствующего провайдера.

AC-1. Под окружением роли Claude и под окружением роли Codex `git status` с cwd,
равным каталогу документов задачи, `tasks/`, корню проекта и самому
`config.PROJECTS`, завершается ненулевым кодом с «not a git repository»; тот же
`git status` в рабочей копии задачи и в клоне проекта — успех (код 0).

AC-2. Под окружением роли `git -C <ROOT> status`,
`git --git-dir=<ROOT>/.git status`, `GIT_DIR=<ROOT>/.git git status`,
`git -c core.worktree=<ROOT> status` и `git -C <рабочая копия чужой задачи> status`
отклоняются до исполнения: ненулевой код и строка причины; `git -C <своя рабочая
копия> status` — успех.

AC-3. Под окружением роли `git clean -n` и `git clean -fX -- <файл>` в своей
рабочей копии и в репозитории пульта отклоняются; строка отказа называет команду
`task-rm`; игнорируемые файлы песочницы остаются на месте.

AC-4. Под окружением роли в своей рабочей копии отклоняются
`git -c alias.cl=clean cl`, `git -c alias.x='!git clean -fX' x`, вызов
псевдонима `cl = clean`, записанного в `.git/config` рабочей копии, и вызов
псевдонима, заданного через `GIT_CONFIG_PARAMETERS`; игнорируемые файлы
песочницы остаются на месте.

AC-5. Под окружением роли `git clean -f` во временном репозитории вне `ROOT` —
успех, неотслеживаемый файл удалён.

AC-6. Воспроизведение инцидента: в корне песочницы пульта лежит игнорируемый
файл; роль выполняет `git -C <каталог документов задачи> clean -fX -- x.py` —
отказ, игнорируемый файл на месте.

AC-7. `task-rm` под признаком роли с `ARTEL_TASK=<id>`: свой неотслеживаемый
файл рабочей копии и новый файл каталога документов (отсутствующий в ветке
артефактов) удалены, код 0.

AC-8. `task-rm` отклоняет набор, содержащий хотя бы один из: файл каталога
документов, уже лежащий в ветке артефактов задачи; путь вне двух корней; путь с
`../`, выводящий за корни; символическую ссылку, ведущую наружу; каталог; путь
внутри `.git`; — ненулевой код, и ни один файл набора (включая допустимые) не
удалён.

AC-9. `task-rm` под признаком роли с `<id>`, отличным от `ARTEL_TASK`, и под
признаком роли без `ARTEL_TASK` — отказ, файлы не удалены; вызов Оператора (без
признака роли) с явным id — успех.

AC-10. `task-rm` входит в `_ROLE_ALLOWED_COMMANDS`, и миссия роли, собранная
`orchestrator/role_prompt.py`, называет команду `task-rm`.

AC-11. `knowledge`, `suite-run`, `plank-run`, `mutation-run`, запущенные из
окружения роли, исполняются как прежде (тот же код возврата и результат, что без
механизма); маркер `ARTEL_PULT_GIT=1` в окружении роли не освобождает прямой
`git clean` в репозитории пульта от отказа.

AC-12. Прямой `pytest` долгоживущего теста артели, создающего временный
репозиторий и вызывающего в нём `git clean`
(`tests/test_01m3vfyp4rxby0bg8d3a0b18hd_pult_commit.py` или
`tests/test_01m41vtse5n15p5p2wzf4gf2bq_docs_command.py`), под окружением роли
артели — зелёный.

AC-13. Если механизм — обёртка на PATH: её каталог — второй элемент PATH роли
после `.artel/venv/bin`, раньше каталога git; `git --version` через обёртку
совпадает с выводом настоящего git.

AC-14. Строка `doctor` требования 7 на исправном окружении роли — `ok`; на
окружении, у которого сборка подменена в тесте так, что граница требования 1
отсутствует, — `fail`; временный подкаталог `<ROOT>/.artel` после проверки
удалён.

AC-15. `docs/reference/role-home/claude/settings.json` содержит в
`permissions.deny` строку `Bash(git clean:*)` и остаётся валидным JSON.

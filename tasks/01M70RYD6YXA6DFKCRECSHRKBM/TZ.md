# Команда suite-lock: внешний прогон под замком полных прогонов машины

## Факты

1. Замок полных прогонов машины — `orchestrator/suite_lock.py`: файл `config.LOGS/suite-run/lock.json` с pid держателя, взятие `O_EXCL` (`acquire`, `:93-115`), замок мёртвого процесса снимается и берётся заново; `release` (`:184-189`) снимает только замок текущего процесса. Виды держателя — `suite-run`, `гейт`, `notes` (`:27-29`); `describe` (`:352`) называет держателя словами.
2. Гейты и `notes` ждут замок не дольше `config.FULL_SUITE_LOCK_WAIT_SEC` = 1800 с (`orchestrator/config.py:273`; `acceptance._machine_lock`); не дождались — прогон не запускается, это отказ окружения гейта. `suite-run` берёт замок без ожидания и при занятом отказывает сразу (`orchestrator/suite_run.py:306-311`). Ожидание 1800 с рассчитано на два полных прогона по `FULL_SUITE_TIMEOUT_SEC` = 900 с (`config.py:258`, комментарий `:267-273`).
4. Остановка группы процессов уже есть — `liveness.terminate_process_group` (`orchestrator/liveness.py:118`); образец передачи замка дочернему процессу — `runner.py:2417-2456`, образец ожидания замка — `mutation_run._take_lock` (`:864-890`). Ролям доступны только команды белого списка `_ROLE_ALLOWED_COMMANDS` (`orchestrator/artel.py:2595-2598`).
5. Команды, которая держит замок на время произвольной команды Оператора (замер, ручной прогон набора, проба образа), нет. 07.11.2026 замер полного набора без замка совпал с автогейтом приёмки задачи 01M6TRM2EK и вызвал ложный отказ по таймауту (строка копилки `06a53f9da`); 08.11 замер взял замок сценарием напрямую через `suite_lock.acquire` (обход, строка копилки `f1b5079b2`).

## Требуется

1. Команда `artel.py suite-lock --reason "<основание>" [--limit <секунды>] -- <команда> [аргументы…]`.
2. Замок берётся без ожидания. Занят — отказ с описанием держателя (`describe`), код выхода не 0, команда не запускается.
3. Новый вид держателя `внешний`; запись замка: `task_id` — `null`, `run` — `null`, основание `reason` (переводы строк заменены пробелом, обрезано до 200 символов). `describe` такого держателя — «внешней команды «<основание>» (pid N)». Прежние виды и их тексты — без изменений.
4. Держатель — pid процесса команды `suite-lock`. Команда запускается дочерним процессом в своей группе процессов; `stdin` — `/dev/null` (только неинтерактивные команды), `stdout` и `stderr` наследуются; код выхода `suite-lock` — код команды.
5. Предел: `--limit` по умолчанию и не больше `config.FULL_SUITE_LOCK_WAIT_SEC − config.FULL_SUITE_TIMEOUT_SEC` (сейчас 900 с; решение Оператора эпика 08.11.2026: один гейт впереди плюс внешний прогон укладываются в ожидание второго гейта; полный набор на машине в этот предел не входит — для него команда не предназначена). Больший `--limit`, ноль, отрицательное или нечисловое значение — отказ до взятия замка. По истечении предела группа процессов команды останавливается `liveness.terminate_process_group` (`SIGTERM`, через 10 с — `SIGKILL`); сообщение называет предел; код выхода — 124.
6. Замок снимается на любом исходе: нормальное завершение, ошибка запуска команды (нет файла), истечение предела, `SIGINT`/`SIGTERM` самой `suite-lock` (группа команды останавливается тем же способом, код выхода `128 + номер сигнала`).
7. Пустая команда (нет `--`, ничего после `--`) и пустое `--reason` — отказ до взятия замка.
8. Команда регистрируется в таблице команд и в справке `artel.py` (докстринг, блок «Команды:»); в `_ROLE_ALLOWED_COMMANDS` не входит — роль её вызвать не может.

## Критерии приёмки

Тесты — в новом долгоживущем файле задачи. `config.LOGS` вычисляется от расположения модуля и окружением не подменяется, а `artel.py` из рабочей копии задачи отказывает: процесс `suite-lock` в тестах — дочерний `sys.executable -c`, который переназначает `config.LOGS` на временный каталог теста и зовёт точку входа `suite_hold`; запуск `artel.py` из теста не используется. Команда под замком — настоящий короткий процесс, без подмены `subprocess`.

- AC-1: свободный замок — во время работы команды файл замка содержит pid процесса `suite-lock`, вид `внешний` и основание; после завершения команды замка нет; код выхода равен коду команды (0 и 3 — отдельными случаями).
- AC-2: замок занят живым чужим процессом — отказ называет держателя, команда не запускалась (её файл-след не создан), чужой замок не тронут.
- AC-3: `describe` держателя вида `внешний` — текст с основанием и pid; тексты прежних видов не изменились (ловит общий текст для всех видов).
- AC-4: предел: `--limit 1` и команда, спящая 30 с, — команда и её дочерний процесс завершены не позже чем через 15 с, замок снят, код выхода 124 (ловит снятие замка без остановки команды и остановку только первого процесса группы).
- AC-5: `--limit` больше `FULL_SUITE_LOCK_WAIT_SEC − FULL_SUITE_TIMEOUT_SEC` (значения пределов подменены в тесте — граница считается от них, не литералом 900), `0`, `-5`, `x` — отказ до взятия замка (каждый случаем).
- AC-6: `SIGTERM` процессу `suite-lock` во время команды — не позже чем через 15 с команда и её дочерний процесс завершены, замок снят, код выхода 143.
- AC-7: команды нет (`--` без продолжения; несуществующий файл) — отказ, замок после вызова не существует.
- AC-8: гейт видит внешний держатель: `acceptance._machine_lock` при замке `внешний` у живого процесса ждёт и пишет ожидание с текстом `describe` (ловит вид, не читаемый ожиданием).
- AC-9: в окружении роли (`runner.in_role_environment()` истинно) вызов команды `suite-lock` — отказ «команда недоступна процессу роли», замок не взят.

Каждый тест — со строкой «Ловит мутацию: …».

Безопасность тестов: настоящий замок машины (`.artel/logs/suite-run/lock.json` главной копии) не читается и не меняется.

Существующие тесты: не меняются. Если существующий тест замка краснеет из-за нового вида — эскалация с именем теста.

Зоны: `orchestrator/suite_lock.py`, `orchestrator/artel.py`, новый модуль `orchestrator/suite_hold.py`, `tests/` (долгоживущие файлы задачи).

Только чтение: `orchestrator/acceptance.py`, `orchestrator/suite_run.py`, `orchestrator/config.py`, `orchestrator/liveness.py`, `orchestrator/runner.py`, `orchestrator/mutation_run.py`, `tests/test_suite_lock.py`, `tests/test_01m5m0kqpv0fj9nsmdcq3xb76w_help_registry.py`.

Не входит:
- ожидание замка (`--wait`) и очередь внешних прогонов;
- проверка простоя пульта (рабочих процессов, задач на гейтах) перед взятием;
- `SIGKILL` процесса `suite-lock`: замок мёртвого держателя снимается следующим `acquire`, а команда в своей группе может продолжить работу — принятый риск, Оператор не убивает `suite-lock` сигналом 9;
- правило «тяжёлые прогоны сессии — только под замком» в `docs/operator-session.md` (вносит Оператор).

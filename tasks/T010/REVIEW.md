## Замечания

- **minor — tests/test_invariants.py:196 (`FsmTest.run_command`) и :325
  (`AgentRunsOnlyFromRunTest.test_no_fsm_command_starts_an_agent`) —
  запуск агента отслеживается только через `Popen`, и синхронный запуск
  через `subprocess.run` свипом не ловится.** Свип наблюдает ровно один
  канал: `popen.assert_not_called()`. Второй канал уже под наблюдением —
  `SpyRun` (:74) пишет каждый вызов `subprocess.run` в `self.calls`, — но
  сверяется только по `git` (`git_subcommands()`, :85 фильтрует
  `c[0] == "git"`), поэтому чужая команда в этом списке никого не
  беспокоит.
  Сценарий поломки, воспроизведён замером в worktree: в ветку `in_dev`
  `cmd_advance` (artel.py:504, сразу после `set_state`) добавлен
  `subprocess.run(["claude", "-p", ...], capture_output=True)` — тот же
  автозапуск роли следующего шага, что и в мутации с `Popen`, только
  синхронный. Результат: `Ran 2 tests ... OK` — класс зелёный, инвариант
  сломан. Мутация с `Popen` при этом краснеет, так что дыра узкая: она
  открывается только на реализации, не переиспользующей `run_agent_once`
  (artel.py:645) — а любая, которая его переиспользует, ловится. Отсюда
  minor, а не major.
  Предложение на одну строку, без расширения объёма: в `run_command`
  после прогона (или в самом свипе рядом с `popen.assert_not_called()`)
  добавить `self.assertNotIn("claude", [c[0] for c in self.git_spy.calls])`
  — наблюдение за уже собираемыми данными, новых фикстур не нужно.

## Вердикт

**approved** — 0 blocker, 0 major.

Все три замечания итерации 2 закрыты по существу, а не по форме:
свип `AgentRunsOnlyFromRunTest` доведён до кода переходов и проверен
мутацией внутри ветки перехода; захардкоженный перечень команд признан
риском в PLAN и частично прикрыт сверкой `STATE_ROLE ⊆ FSM_STATES`,
которая сама проверена мутацией; ассерт контрольного merge-теста сведён
к содержанию инварианта без потери запретительной силы. Требование 3
SPEC — «пометить инварианты как неослабляемые» — теперь выполнено и по
букве (шапки, реестр), и по смыслу: за каждой строкой первой таблицы
docs/invariants.md стоит тест, краснеющий на реалистичном нарушении.

Оставшееся замечание — minor и мержу не мешает: канал `Popen` закрыт,
дыра открывается только на автозапуске в обход `run_agent_once`. Закрыть
можно одной строкой здесь же либо отдельной задачей вместе с механической
сверкой перечня команд (оба упираются в один и тот же риск из PLAN).

Отдельно стоит зафиксировать как результат задачи, а не только как её
артефакт: раздел PLAN «Мутационная проверка» и вывод «мутацию надо сажать
на путь, которого тест достигает нетривиально» — рабочий метод, которым
эта же ветка дважды нашла собственные тесты-декорации. Его место —
в правиле 3 «Как добавить инвариант» (docs/invariants.md), где он уже
записан.

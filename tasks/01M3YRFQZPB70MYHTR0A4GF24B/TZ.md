# ТЗ: Два нестабильных теста — циклы на старом коде в pin-update и повтор при отсутствии CLI

Источник: решение Оператора 02.10.2026; строки копилки 02.10 (П1
«Предсказанный риск сбылся: нестабильный долгоживущий тест 01M3Y75GCR
AC-3 … покраснил CI main», П2 «Нестабильный тест планки 01M3Y75GCR
AC-3», П2 «Нестабильный тест tests/test_agent_failure.py …», П2 «Обход:

Факты (пин 8fc6f941):
- `tests/test_01m3y75gcresc2kds9vprjk4ps_stale_cycles.py::
  PinUpdateSelectionTest::test_ac3_cycle_started_after_shift_is_not_named`
  за 02.10 трижды покраснил CI main на Linux-раннере (прогоны 37019693646,
  37029861705, 37030343176), локально на macOS не воспроизводился. Тест
  запускает цикл, сдвигает пин, через паузу `GAP_SEC = 1.5` запускает
  второй цикл и требует, чтобы второй не был назван «стартовавшим до
  сдвига». В красном прогоне второй цикл назван: время его старта из
  `ps -o lstart=` (`orchestrator/doctor/stale_cycles.py::
  process_start_time`, точность — секунда) оказалось не позже
  `pin_moment = datetime.now(timezone.utc)` (`orchestrator/pin.py:115`).
  Вероятные причины — усечение до секунды у `lstart` и расхождение
  `lstart` procps (считается от времени загрузки) с часами; точную
  устанавливает SPEC.
- `tests/test_agent_failure.py::CmdRunFailureTest::
  test_missing_cli_is_not_retried` упал 02.10 в полном наборе `tests/`
  (гейт полного набора `doc-commit` при `admit`, 1 failed, 3862 passed);
  отдельно — три зелёных прогона подряд, повтор полного набора —
  зелёный. Какое утверждение упало, лог не сохранил; зависимость от
  порядка тестов, общего каталога `config.LOGS` (`glob("*.prompt.txt")`
  ждёт ровно один файл) или времени — устанавливает SPEC.

Требуется:
1. Установить причину каждого из двух падений и записать её в SPEC с
   доказательством (воспроизведение: повтор теста N раз, порядок
   набора, подмена часов или вывода `ps`).
2. Устранить причину так, чтобы оба теста были детерминированы на macOS
   и Linux: исправление — в коде пульта, если причина в нём (например,
   сравнение времени старта процесса с моментом сдвига с учётом
   точности `lstart`), либо в изоляции теста (свои каталоги, подмена
   часов или `ps`), если причина в тесте.
3. Проверяемые свойства не ослабляются: тест AC-3 по-прежнему ловит
   мутации из своего докстринга (время старта не сравнивается с моментом
   сдвига; сравнение перевёрнуто), тест отсутствия CLI — отсутствие
   повтора при `FileNotFoundError`, задача остаётся в `in_dev`, промпт
   сохранён в файл рядом с логом. Правка утверждений
   существующих тестов — только по мандату Оператора («Ослабление тестов
   разрешено: …»), с эскалацией, где названы старое и новое утверждение.
4. Если исправление меняет поведение `pin-update` (перечень циклов на
   старом коде), цикл, стартовавший до сдвига, по-прежнему называется
   всегда; ложное «назван цикл, стартовавший после» допустимо только
   внутри названной в SPEC погрешности и описывается в `docs/stack.md`.
5. Тесты в `tests/`: для причины каждого падения — тест, детерминированно
   воспроизводящий её (подменой часов, вывода `ps` или порядка), красный
   на текущем коде и зелёный после исправления.

## Требования

1. Мутации «до»: для каждой из 19 заявок и для каждого из 21 теста без заявки (ему пишется заявка «Ловит мутацию» — правдоподобная мутация кода `orchestrator/merge_lock.py`, `orchestrator/merge_queue.py` или `orchestrator/store.py`, которую он ловит) — патч к коду `orchestrator/` в `tasks/<id>/mutation-<nnn>.diff` (номера подряд с 001; патч реализует ровно мутацию заявки; одинаковые по смыслу заявки — одна мутация со списком тестов). Таблица «до»: `mutation-run <id> --ref base --tests tests/test_merge_lock.py,tests/test_merge_queue.py,tests/test_merge_lock_by_project.py --copy-table --wait-lock 4` частями `--patches` не больше 25 патчей; отчёт части — повторными `mutation-run <id> --wait 5` до итоговой строки; вывод — в PLAN раздела «Мутации до» дословно, с шапкой и всеми строками, до старта следующей части. У каждой мутации «до» и «после» в PLAN — строка падения из лога прогона патча (файл:строка). Не доказательство (патч переписывается): «убита» ошибкой сбора, импорта, setup, исключением без падения утверждения, только утверждением подготовки или по таймауту pytest-timeout (`Timeout` в логе). Строка `raise AssertionError` в подмене паузы (by_project :105) считается строкой падения. Мутации пути взятия окна и цикла `wait_for_window` выбираются так, чтобы тест падал утверждением, а не зависал; патчи, после которых окно может не взяться, — отдельной частью не больше 8. Часть, оборванная пределом, — патчи переписываются и раскладываются по частям, а не прогоняются тем же набором. Мутация, проверяемая `ConcurrentAcquireTest`, обязана убиваться детерминированно; расхождение «убита / не убита» между «до», «после» и повтором — заявка переписывается, повторы до убийства запрещены. Не убитая никем — находка в PLAN. «Итог неизвестен», «патч не применяется», «патч трогает тесты», «не прогнана» — патч переписывается и прогоняется заново. Красный контроль — повтор тем же вызовом в следующем шаге; повторно красный — с `--workers 4`; и тогда красный — `escalate` с логом контроля, тесты и пределы не трогать. Ожидание замка — только `--wait-lock`; циклы и сценарии ожидания запрещены.
2. Временные файлы в рабочей копии не создаются (допустимо: файл первого уровня каталога документов задачи с расширением не `.md` и именем не `test_*`/`mutation-*` либо файл в `$TMPDIR`, созданный командой `python3`; копии `mutation-run-<n>.tsv` команды допустимы). К концу каждого шага `git status --porcelain` называет только новый `tests/test_merge_lock_module.py`, изменённый `tests/test_merge_queue.py`, удаление `tests/test_merge_lock.py` и `tests/test_merge_lock_by_project.py` и `docs/codebase-map.md` (только вывод генератора).
3. Свод: тесты `tests/test_merge_lock.py` и класса `LegacyTouchHeartbeatTest` — в новый `tests/test_merge_lock_module.py`; тесты прежнего `tests/test_merge_queue.py`, `WaitForWindowOtherProjectQueueTest` и `WaitTextsAnyOrderTest` — в `tests/test_merge_queue.py`, переписанный на месте; оба — в стиле pytest. Песочница — фикстура `tmp_root` из `tests/fixtures.py`; `setUp` каждого класса и `_QueueTestBase`/`_Base` — собственные фикстуры файла поверх `tmp_root` без утверждений (тело дословно без `super().setUp()`, `self.` заменено параметром; одинаковые тела — одна фикстура; общая часть `_Base` — в каждом из двух файлов своей фикстурой с одинаковым телом); имена фикстур не совпадают с фикстурами `tests/fixtures.py`. Атрибуты классов — константы модуля с теми же именами и литералами. `_alive_foreign_pid(self)` получает стенд (уборку `addCleanup` исполняет `_sandbox`). Методы классов без утверждений — функции модуля: первый параметр — стенд, тело дословно, `self.` заменено именем параметра, вызовы перенесённых помощников — вызовы функций; одинаковые по телу — одна функция; одноимённые с разным телом (`seed`) — с префиксом бывшего класса (`acquire_release_seed`, `process_ownership_seed`); перечень — в PLAN. Утверждения и проверяемые свойства не меняются: ожидания дословно, форма — `assert …` (ADR-0027); литерал остаётся литералом, константа — константой (равенство значений доводом не считается); голый `assertRaises(E)` → `pytest.raises(E)`; `assertIn(<текст>, str(ctx.exception))` → `assert <текст> in str(excinfo.value)` после блока, `match=` не используется (в файлах нет `assertRaisesRegex`); текст `msg=` — `pytest.fail(<текст>)` последней строкой блока либо вторым операндом `assert`; наборы `subTest` :67, :95, :130 — прежним циклом, ярлык — в тексте сообщения каждого утверждения подслучая; `raise AssertionError` в подмене паузы, потоки, барьеры и пределы ожидания `ConcurrentAcquireTest` — дословно; `unittest`, `sys.path.insert` (:17–18 файлов замка и очереди), неиспользуемые импорты и `if __name__ == "__main__"` не переносятся. Дубль удаляется только если (а) каждую его мутацию по таблице «до» убивает и другой сохраняемый тест и (б) каждый литерал и вид каждого утверждения удаляемого теста есть в сохраняемом; удалённые дубли — в PLAN. Тест, чью мутацию не убил никто, не удаляется (заявка переписывается на мутацию, которую он убивает, либо находка в PLAN). У каждой функции — «Ловит мутацию:».
4. Таблица «после»: `mutation-run <id> --ref worktree --tests tests/test_merge_lock_module.py,tests/test_merge_queue.py --copy-table --wait-lock 4` теми же диапазонами и тем же `--workers`; вывод — в PLAN «Мутации после» дословно; перед каждой частью — пустой вывод `git status --porcelain -- orchestrator/`. Для каждой мутации, убитой «до» тестом T, «после» её убивает функция, в которую перенесён T, тем же утверждением (та же нормальная форма guard; для `raise AssertionError` — тот же текст строки; соответствие — в PLAN); дерево `orchestrator/` ревизий обеих шапок совпадает, sha256 каждого патча совпадает; при подтяжке main с изменением `orchestrator/` «до» прогоняется заново. Под ролью адресно прогоняются только два файла модулей; время «до» и «после» — по контрольным прогонам `mutation-run`; число тестов и строк до и после — в PLAN.
5. `tests/test_merge_lock.py` и `tests/test_merge_lock_by_project.py` удаляются, `tests/test_merge_queue.py` переписывается (мандат — `answer` на эти три пути; удаление утверждения без переноса, ослабление сравнения, `skip`/`xfail`, подъём пределов не разрешены).
6. Независимая проверка (повтор `mutation-run`, сравнение утверждений по AST) — сессией при Операторе до approve на merge_gate.

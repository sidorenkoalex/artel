# ТЗ: `kill` при живом цикле — отказ с подсказкой `stop`, ликвидация только с `--yes`

Источник: копилка 11.09. `kill <id>` — ликвидация задачи: состояние
`killed`, артефактная ветка и worktree удаляются, снимок уходит в
`refs/artifacts/<id>`. При живом отвязанном цикле (`auto`/`run` с 11.09,
01M1TNMBY8) команда исполняется без подтверждения и без упоминания
`stop <id>` (штатная остановка цикла с доигровкой шага). 11.09
zones-extend (01M1VBEFR9) ликвидирована командой `kill`, когда нужна
была `stop`: $14.42 работы аналитика и test_author потеряны, задача
заведена заново.

Требуется:
1. `kill <id>` при живом lease (держатель — процесс на этом хосте, pid
   жив, heartbeat свежий — те же признаки, что у `doctor.check_leases`
   и `_cmd_stop`) без флага `--yes` отказывает именованным текстом:
   «[<id>] цикл жив (pid <pid>, шаг <роль> с <время>) — остановить
   цикл: artel.py stop <id>; ликвидировать задачу (ветка и worktree
   будут удалены): artel.py kill <id> --yes». Ничего не меняется, в
   журнал пишется запись отказа (`kill отклонён: цикл жив`).
2. `kill <id> --yes` — прежнее поведение целиком (снимок держателя до
   `run_locked`, `force=True`, SIGKILL, уборка), плюс строка журнала
   «kill подтверждён флагом --yes при живом цикле».
3. Без живого lease `kill <id>` работает как раньше, без флага —
   Оператор, останавливающий мёртвую или стоящую задачу, ничего нового
   печатать не обязан.
4. Подсказка «дальше:» у задачи, чей цикл ждёт зону или стоит на гейте,
   называет обе команды с назначением: «stop <id> — остановить цикл;
   kill <id> — ликвидировать задачу».
5. `docs/operator-session.md`: абзац «stop против kill» — назначение,
   последствия, флаг `--yes`.
6. Тесты `tests/test_kill_cleanup.py` / `tests/test_detached_cycle.py`:
   (а) живой lease без `--yes` — отказ, состояние и ветка не тронуты,
   процесс держателя не получает сигнала (мутация «kill игнорирует
   живой lease» — красная); (б) с `--yes` — ликвидация как раньше;
   (в) мёртвый lease без флага — ликвидация как раньше; (г)
   существующие тесты kill/cleanup зелёные без правки утверждений.

Зоны: orchestrator/cleanup.py, orchestrator/artel.py,
docs/operator-session.md, tests/.
Порядок: без зависимостей.

Не входит: интерактивный вопрос «да/нет» в терминале (пульт не
интерактивен); отмена ликвидации.

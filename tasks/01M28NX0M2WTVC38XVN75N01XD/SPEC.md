# SPEC: kill при живом цикле — отказ с подсказкой stop, ликвидация только с --yes

## Контекст

`kill <id>` ликвидирует задачу безусловно: состояние `killed`, снимок в
`refs/artifacts/<id>`, артефактная ветка и worktree удаляются. При живом
отвязанном цикле (`auto`/`run`, держатель lease жив на этом хосте) команда
сегодня исполняется без подтверждения и без упоминания штатной остановки
`stop <id>` (доигрывает текущий шаг). 11.09 задача zones-extend
(01M1VBEFR9) была ликвидирована командой `kill`, когда нужна была `stop`:
$14.42 работы аналитика и test_author потеряны, задача заведена заново.

## Требования

1. `kill <id>` при живом lease (держатель — процесс на этом хосте, pid
   жив, heartbeat свежий — те же признаки, что у `doctor.check_leases`
   и `_cmd_stop`) без флага `--yes` отказывает и ничего не меняет.
2. `kill <id> --yes` при живом lease выполняет прежнее полное поведение
   `kill`.
3. `kill <id>` без флага при отсутствии живого lease работает как
   раньше.
4. Подсказка «дальше:» задачи, чей цикл ждёт зону или стоит на ручном
   гейте, называет обе команды — `stop` и `kill` — с их назначением.
5. `docs/operator-session.md` несёт абзац «stop против kill».
6. Существующие тесты `tests/test_kill_cleanup.py`/
   `tests/test_detached_cycle.py` остаются зелёными без правки
   существующих утверждений.

## Критерии приёмки

AC-1. `kill <id>` без флага `--yes` при живом lease отказывает точным
текстом «[<id>] цикл жив (pid <pid>, шаг <роль> с <время>) — остановить
цикл: artel.py stop <id>; ликвидировать задачу (ветка и worktree будут
удалены): artel.py kill <id> --yes»; состояние задачи, артефактная ветка
и worktree не меняются, процесс-держатель lease не получает сигнала (ни
SIGTERM, ни SIGKILL), а в журнал задачи пишется запись действия «kill
отклонён: цикл жив».

AC-2. `kill <id> --yes` при живом lease выполняет прежнее полное
поведение `kill` целиком (состояние `killed`, снимок в
`refs/artifacts/<id>`, SIGKILL процессу-держателю, ликвидация
артефактной ветки и worktree) и дополнительно пишет в журнал задачи
строку «kill подтверждён флагом --yes при живом цикле».

AC-3. `kill <id>` без флага `--yes` при отсутствии живого lease
работает как раньше — без печати текста отказа AC-1 и без новой записи
в журнал.

AC-4. Подсказка «дальше:» у задачи, чей цикл ждёт зону, называет обе
команды: «stop <id> — остановить цикл; kill <id> — ликвидировать
задачу».

AC-5. Подсказка «дальше:» у задачи, чей цикл стоит на ручном гейте
(решение Оператора: `spec_gate`, `acceptance`, `merge_gate`,
`escalated`), называет те же обе команды тем же текстом.

AC-6. `docs/operator-session.md` несёт абзац «stop против kill» —
назначение каждой команды, последствия и флаг `--yes`.

AC-7. Существующие тесты `tests/test_kill_cleanup.py` и
`tests/test_detached_cycle.py` остаются зелёными без правки
существующих утверждений (новые тесты допускаются только добавлением).

# Ответ на вопросы аналитика

1. Вариант B. Зоны не меняются: SPEC закрывает только окно `orchestrator/canary.py:2333-2338`. Окно группы suite-run (`orchestrator/suite_run.py:801-810`: группа ведения снята до записи pid в `run.json`, сессия suite остаётся сиротой, уборка клона `canary.py:1236-1244` её не находит) — в «Не входит» SPEC с этим адресом. Отдельную строку бэклога заводит Оператор. Способ по вопросу 1 из контекста (отложенная доставка сигнала флагом с подъёмом внутри защищённого ожидания, без `pthread_sigmask`) принимается к SPEC; обоснование — как в контексте вопросов.

2. Вариант A. SIGINT в раннем окне даёт тот же исход, что SIGINT во время ожидания сегодня: группа ведения снята и дождана, клон и origin удалены, `KeyboardInterrupt` уходит наверх, строка прогона не пишется. Запись «оборвана сигналом <имя>», вердикт red и код `128 + номер` — только для SIGTERM и SIGHUP. Слова ТЗ «а также прерывание с терминала» в требовании 1 читаются так: процесс ведения не остаётся живым и каталоги удалены; запись исхода для SIGINT не вводится.

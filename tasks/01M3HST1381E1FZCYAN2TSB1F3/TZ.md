# ТЗ: Клон канарейки находит вход Codex: указатель связки ключей в доме роли клона

Источник: строка бэклога 27.09 «Канарейка на наборе Codex не найдёт
вход»; решение Оператора 27.09. Условие замера канарейки на моделях
Codex и пробного прогона ролей developer, test_author, reviewer на
Codex без риска для живого пульта. Линия провайдеров.

Факты (origin/main b21f01e6, после мержа 01M3HJQV2QV9BXNXSH3F8STAYH — флаг --template и подъём потолка):
- Эфемерный клон канарейки (`orchestrator/canary.py`: `tempfile.mkdtemp`, затем
  `catalog.cmd_init()`) переадресует `config.ROLE_HOME` в
  свой `.artel/home` (`_CLONE_CONFIG_ATTRS`); холодный старт клона
  разворачивает туда референс дома роли Codex
  (`docs/reference/role-home/codex/`).
- Вход ролей на Codex — по подписке ChatGPT: токены хранит сам CLI в
  системной связке ключей, которую ищет по указателю
  `$HOME/Library/Preferences/com.apple.security.plist`
  (`orchestrator/providers/codex.py::CodexProvider.environment`,
  docs/stack.md, раздел «Провайдер codex»). Указатель в главном доме
  роли ставит Оператор руками однократно; в доме клона его нет —
  `codex login status` с домом клона входа не найдёт, шаг роли набора
  `codex-*` упадёт авторизацией до первого токена.
- Пульт токены не читает и не пишет; указатель — файл настроек, не
  секрет. Проверка входа — `doctor.check_codex_chatgpt_auth`.

Требуется:
1. Прогон канарейки на наборе, где хотя бы одна роль исполняется
   провайдером Codex, переносит в дом роли клона указатель связки
   ключей из дома роли пульта — только файл указателя, без иных файлов
   `Library/`; способ (копия файла либо вызов системной команды с HOME
   клона) выбрать и обосновать в SPEC. На наборе по умолчанию и на
   наборах без Codex дом клона не меняется — поведение байт-в-байт
   прежнее.
2. Указателя в доме роли пульта нет — именованный отказ команды ДО
   клона с рецептом (`CODEX_AUTH_RECIPE`), а не падение шага в клоне.
3. До первого шага роли на Codex прогон проверяет вход домом клона тем
   же способом, что `doctor` (`codex login status` с парами авторизации);
   вход не подтверждён — отказ до траты шага, причина в отчёте прогона.
4. Изоляция клона не ослабляется: в дом клона не попадают файлы дома
   роли пульта, кроме указателя; токены и содержимое связки ключей
   пульт по-прежнему не читает; после прогона дом клона удаляется
   вместе с клоном.
5. Документация: docs/stack.md, раздел «Провайдер codex» — что делает
   прогон канарейки с указателем и что остаётся шагом Оператора.
6. Тесты (tests/): набор с ролью на Codex — указатель перенесён в дом
   клона; набор по умолчанию — дом клона без указателя; указателя в
   пульте нет — отказ до клона; вход не подтверждён — отказ до шага;
   существующие tests/test_canary.py, tests/test_canary_sets.py,
   tests/test_providers_codex.py зелёные, ни один не ослаблен.

Зоны: orchestrator/canary.py, docs/stack.md, tests/.

Только чтение (не менять): orchestrator/providers/codex.py,
orchestrator/doctor/, orchestrator/catalog.py,
docs/reference/role-home/codex/, orchestrator/pin.py, docs/backlog.md,
tests/test_invariants.py.

Не входит: автоматическая установка указателя в главном доме роли;
проверка остатка лимита подписки; засчитывание прогонов на наборах
Codex для сдвига пина.

# ТЗ: отказ push артефактной ветки в журнал и на повтор; doctor сверяет локальный ref с origin и CI артефактной ветки

Источник: инцидент 06.09 (копилка, строка от 06.09 «Push артефактной
ветки молчит при отказе»). `artifact_branch.push` — best-effort:
возвращает `False` без записи в журнал (задумано для `cmd_new` без
origin, SPEC требование 7, AC-8), и автокоммит шага роли
(`checkpoint.commit_step_artifacts`, строка `artifact_branch.push(task_id)`)
результат не смотрит. Фактура 06.09: после внешних коммитов Оператора в
`artifact/<id>` на origin три ветки живых задач разошлись — SPEC
аналитика 01M1TNN4TM остался в локальном ref, origin нёс пустой шаблон;
у 01M1NGFK3N (merge_gate) origin отставал от локального ref ещё раньше
(push не прошёл при сетевом сбое 05.09), никто не заметил. CI
артефактных веток семи задач был красный с 05:14Z по guard, и это ни на
что не повлияло: зелёность CI артефактной ветки нигде не читается.
Сведено вручную merge-коммитами и `git update-ref`.

Требуется:
1. Отказ push артефактной ветки — запись журнала задачи
   `push артефактной ветки FAILED` с причиной (stderr git, первые 300
   символов; отдельно различать «нет origin», «сеть», «non-fast-forward»)
   у каждого места вызова: автокоммит шага, чекпоинты таймаута/аварии/
   паузы, `cmd_new`, ANSWER Оператора. Best-effort для `cmd_new` без
   origin остаётся (заведение не отказывает), но запись в журнал есть.
2. Повтор: при следующем автокоммите той же задачи, если предыдущий
   push не прошёл, пульт пробует push снова и журналирует исход;
   non-fast-forward НЕ разрешается силой (`--force` запрещён) —
   запись журнала называет оба sha (локальный ref и origin) и подсказку
   Оператору «свести merge-коммитом» (приём 06.09).
3. `doctor`: проверка «артефактная ветка синхронна» для нетерминальных
   задач target artel — локальный ref `artifact/<id>` и
   `origin/artifact/<id>` совпадают; иначе `warn` с обоими sha и
   направлением расхождения (локальный отстаёт / origin отстаёт /
   разошлись). Без origin — `skip` с причиной.
4. `doctor`: проверка «CI артефактной ветки» для нетерминальных задач —
   последний прогон CI ветки `artifact/<id>` (через `gh run list`, как
   `verifying`) зелёный; красный — `warn` с sha и именем упавшей джобы.
   Без `gh`/сети — `skip`. Проверка информационная: гейты не блокирует
   (блокировка — отдельное решение, см. «Не входит»).
5. Тесты: (а) отказ push каждого вида даёт одну запись журнала с
   классифицированной причиной (песочница с локальным `origin` и
   заранее ушедшим вперёд ref — non-fast-forward; без origin — «нет
   origin»); (б) повтор push на следующем автокоммите после отказа;
   (в) `--force` не вызывается ни при каком отказе (мутация: повтор
   через `--force` — тест обязан поймать); (г) doctor `warn` в трёх
   направлениях расхождения и `ok` при совпадении; (д) существующие
   `tests/test_artifact_branch*.py`, `tests/test_checkpoint*.py`,
   `tests/test_doctor.py` зелёные без правки ассертов.

Зоны: orchestrator/artifact_branch.py, orchestrator/checkpoint.py,
orchestrator/doctor.py, orchestrator/catalog.py, tests/.
Порядок: после мержа белого списка каталога задачи (01M1TNN4TM,
зона `checkpoint.py`) и стоп-крана ч.2 (01M1THKRK8, зона `doctor.py`)
— сверить по `status`.

Не входит: блокирующий гейт по CI артефактной ветки; автоматическое
сведение разошедшихся веток; push кодовой ветки (другой путь, свои
записи).

# SPEC: отказ push артефактной ветки в журнал и на повтор; doctor сверяет локальный ref с origin и CI артефактной ветки

## Контекст
`artifact_branch.push` — best-effort: возвращает `False` без записи в
журнал (задумано для `cmd_new` без origin, требование 7 прежней задачи
T094, AC-8), и вызывающий код (автокоммит шага роли) результат не
смотрит. Инцидент 06.09: после внешних коммитов Оператора в
`artifact/<id>` на origin несколько веток живых задач разошлись
локальный ref/origin незамеченно, а CI артефактных веток был красным
несколько часов — ни то ни другое нигде не журналируется и не
проверяется `doctor`. Сведено вручную.

## Требования
1. Отказ push артефактной ветки — запись журнала задачи «push
   артефактной ветки FAILED» с причиной (stderr git, первые 300
   символов; отдельно различать «нет origin», «сеть», «non-fast-forward»)
   на каждом месте вызова: автокоммит шага, чекпоинты таймаута/аварии/
   паузы, `cmd_new`, ANSWER Оператора. Best-effort для `cmd_new` без
   origin остаётся (заведение не отказывает), но запись в журнал есть.
2. Повтор: при следующем автокоммите той же задачи, если предыдущий
   push не прошёл, пульт пробует push снова и журналирует исход;
   non-fast-forward НЕ разрешается силой (`--force` запрещён) — запись
   журнала называет оба sha (локальный ref и origin) и подсказку
   Оператору «свести merge-коммитом».
3. `doctor`: проверка «артефактная ветка синхронна» для нетерминальных
   задач target artel — локальный ref `artifact/<id>` и
   `origin/artifact/<id>` совпадают; иначе `warn` с обоими sha и
   направлением расхождения (локальный отстаёт / origin отстаёт /
   разошлись). Без origin — `skip` с причиной.
4. `doctor`: проверка «CI артефактной ветки» для нетерминальных задач —
   последний прогон CI ветки `artifact/<id>` (через `gh run list`, как
   `verifying`) зелёный; красный — `warn` с sha и именем упавшей джобы.
   Без `gh`/сети — `skip`. Проверка информационная: гейты не блокирует.
5. Тесты покрывают классификацию причины отказа push, повтор на
   следующем автокоммите, отсутствие `--force` ни при каком отказе
   (мутационно — подмена на `--force` обязана красить тест), три
   направления расхождения doctor + `ok` при совпадении; существующие
   `tests/test_artifact_branch*.py`, `tests/test_checkpoint*.py`,
   `tests/test_doctor.py` остаются зелёными без правки ассертов.

## Критерии приёмки

AC-1. Отказ push артефактной ветки пишет в журнал задачи запись «push
артефактной ветки FAILED» с причиной — первые 300 символов stderr git,
классифицированной как «нет origin» / «сеть» / «non-fast-forward» — на
каждом из мест вызова: автокоммит шага (включая чекпоинты таймаута,
аварийного завершения и `pause --now`), `cmd_new`, ANSWER Оператора.

AC-2. `cmd_new` без origin остаётся best-effort: отказ push не
прерывает заведение задачи, при этом запись в журнал по AC-1 всё равно
делается (не тихий `return False`, как сейчас).

AC-3. При следующем автокоммите той же задачи, если предыдущий push
не прошёл, пульт пробует push снова и журналирует исход повторной
попытки (успех или новый отказ по классификации AC-1).

AC-4. Push артефактной ветки не вызывается с `--force` ни при каком
отказе, включая non-fast-forward.

AC-5. Запись журнала об отказе push при non-fast-forward называет оба
sha — локальный ref артефактной ветки и `origin/artifact/<id>` — и
подсказку Оператору «свести merge-коммитом».

AC-6. `doctor` несёт проверку «артефактная ветка синхронна» для
нетерминальных задач target artel: сравнивает локальный
`artifact/<id>` и `origin/artifact/<id>`; `ok` при совпадении; `warn` с
обоими sha и направлением расхождения (локальный отстаёт / origin
отстаёт / разошлись) при несовпадении; `skip` с причиной, если origin
недоступен.

AC-7. `doctor` несёт проверку «CI артефактной ветки» для нетерминальных
задач target artel: зелёный последний прогон CI ветки `artifact/<id>`
(через `gh run list`) — `ok`; красный — `warn` с sha и именем упавшей
джобы; `gh`/сеть недоступны — `skip`; проверка информационная и не
блокирует ни один гейт.

AC-8. Существующие `tests/test_artifact_branch*.py`,
`tests/test_checkpoint*.py`, `tests/test_doctor.py` остаются зелёными
без правки существующих ассертов.

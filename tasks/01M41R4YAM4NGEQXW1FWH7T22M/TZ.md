# ТЗ: штатный локальный прогон планки в шаге роли; шаг роли не может удалить отслеживаемые файлы вне своих путей

Источник: копилка 03.10.2026 — пять случаев за день, когда роль удалила
весь отслеживаемый каталог задач рабочей копии кода и восстановила его
сама; три из них в одной задаче 01M41M6KGWA9PJ6G1KPDC6XY70 (test_author,
developer, reviewer). Решение Оператора 03.10.2026 «заводи ТЗ».

Факты (пин 0d120b67, сверка кода 03.10):
- С части (б1) ADR-0021 документы задачи живут в каталоге документов
  `.artel/projects/<проект>/tasks/<id>/`, вне рабочей копии кода; планку
  в рабочую копию кладёт только пульт на время прогона
  (`orchestrator/acceptance.py::plank_in_code_copy` →
  `materialize_from_branch` + `drop_from_code_copy`, уборка — только
  `tasks/<id>/`).
- Правила ролей велят гонять планку командой
  `python3 -m pytest tasks/<id>/acceptance_tests …` из рабочей копии
  (`skills/test-authoring.md`, раздел «Перед завершением»; ревьювер и
  разработчик — `skills/review-checklist.md`, `skills/coding-standards.md`).
  Команды пульта для такого прогона нет; в перечне команд, доступных
  роли (`orchestrator/artel.py::_ROLE_ALLOWED_COMMANDS`), её нет.
- Поэтому роли копируют планку из каталога документов в
  `tasks/<id>/acceptance_tests/` рабочей копии сами и убирают её
  сами — пять раз за 03.10 уборкой всего каталога задач
  (`shutil.rmtree("tasks")`).
- Каталог задач в main отслеживается git: 308 исторических каталогов,
  3192 файла (уборка по ADR-0018 не исполнена).
- Для ролей без мандата кода (test_author, reviewer) пульт после шага
  откатывает изменения вне `tasks/<id>/`
  (`orchestrator/checkpoint.py::_discard_out_of_mandate_changes`);
  для developer незакоммиченные изменения пульт коммитит за роль
  (`_commit_worktree_change`), и удаление исторических каталогов ушло
  бы в коммит ветки — остановил бы его только гейт зон на переходе.

Требуется:
1. Команда пульта для локального прогона планки в шаге роли (имя — в
   SPEC, например `artel.py plank-run <id> [файл]`): выкладывает планку
   задачи в рабочую копию кода роли тем же узлом, что пульт
   (`plank_in_code_copy` или его общий узел), гоняет её тем же раннером
   и таймаутом (`acceptance._pytest_command`), печатает итог pytest и
   код выхода, убирает выкладку — только `tasks/<id>/`, на зелёном,
   красном исходе и исключении. Источник планки: для test_author в
   `tests_writing` — текущий черновик каталога документов задачи (ещё
   не зафиксирован); для остальных ролей — зафиксированная планка
   ссылки документов. Аргумент файла — прогон одного файла планки.
2. Команда доступна процессу роли (перечень команд роли) и не меняет
   состояния задачи, БД, ссылок и журнала, кроме записи о прогоне, если
   SPEC её требует. Отказ на задаче без планки — именованный.
3. Правила ролей (`skills/test-authoring.md`, `skills/review-checklist.md`,
   `skills/coding-standards.md` и другие места, где описан прогон
   планки) называют эту команду единственным способом локального
   прогона планки; ручное копирование планки в рабочую копию и
   удаление каталогов рабочей копии для уборки — запрещены прямым
   текстом с причиной (случаи 03.10).
4. Шаг роли не может удалить отслеживаемые файлы вне своих путей
   незаметно: после шага любой роли удалённые отслеживаемые файлы вне
   путей, которые роли разрешено менять (`tasks/<id>/` и для developer —
   зоны задачи), восстанавливаются из HEAD и не попадают в коммит
   пульта; журнал задачи получает именованную запись с числом
   восстановленных файлов и первыми путями. Для developer это новое
   поведение; для test_author и reviewer — проверка, что существующий
   откат это уже делает, и та же запись в журнале. Удаления внутри зон
   developer не трогаются (их судят гейт зон и гейт сохранности тестов).
5. Тесты в `tests/` с заявками «Ловит мутацию»: команда выкладывает и
   убирает только `tasks/<id>/` (исторические каталоги на месте после
   прогона, в том числе после исключения внутри прогона); команда
   доступна роли; test_author в `tests_writing` гоняет черновик, а не
   зафиксированную планку; массовое удаление исторических каталогов
   шагом developer восстановлено и не закоммичено, журнал называет
   число; удаление внутри зон developer не восстанавливается.

Зоны: orchestrator/, tests/, docs/codebase-map.md.

Приложением: skills/test-authoring.md, skills/review-checklist.md,
skills/coding-standards.md (и другие файлы правил ролей, если SPEC их
назовёт; правила ролей защищены — правка только приложением к PLAN,
проверенным `git apply --check`).

Только чтение (не менять): docs/adr/, docs/roadmap.md, docs/backlog.md,
docs/operator-session.md, docs/invariants.md, templates/, targets.yaml,
models.yaml, roles.yaml, CLAUDE.md, scripts/guard.py,
scripts/ci_push_class.py, .github/workflows/ci.yml, requirements.lock.

Не входит: уборка исторического каталога задач из main (операторский
коммит по ADR-0018); часть (в) ADR-0021; изменение состава планки и
гейтов перехода; параллельный прогон (`-n`) в шаге роли.

# SPEC: prune — промпты и каталоги suite-run по правилу хранения логов, удаление брошенного notes-work

## Контекст
Команда `prune` (`orchestrator/prune.py`) убирает из `.artel/logs/` только
файлы `*.log` верхнего уровня (`_log_candidates`, `orchestrator/prune.py:57`,
`:65`). Промпты шагов `<id>-<роль>-<n>.prompt.txt` (на 23.10 — 3 943 файла,
430 МБ) и хозяйство `suite-run` `.artel/logs/suite-run/<id>/` (94 каталога,
351 МБ) под правило хранения не попадают. Рабочий репозиторий упразднённого
механизма `note` `.artel/notes-work` (103 МБ) кодом пульта не используется.
Находки ревизии CR-2026-10-22-9 и CR-2026-09-30-8. Задача вводит правило
хранения для этих видов, а не разовую чистку логов. Удаление необратимо,
поэтому все уточнения гейта SPEC (решения Оператора 23.10.2026, круг 1)
сделаны в сторону сохранения.

## Требования

1. **Промпты.** `prune._log_candidates` отбирает файлы верхнего уровня
   каталога логов пульта (`config.LOGS`) с окончанием `.log` или
   `.prompt.txt` по прежнему двойному правилу: старше
   `config.LOG_RETENTION_DAYS` по mtime И задача (часть имени до первого `-`)
   вне `_kept_task_ids`. Прочие файлы верхнего уровня (`*-state.db*` и т. п.)
   не отбираются.
2. **Каталоги `suite-run`.** Новая функция
   `prune._suite_run_candidates(conn) -> list[Path]` — подкаталоги
   `.artel/logs/suite-run/`, у которых одновременно:
   - `idgen.is_task_id_form(<имя>)` истинно (форма id задачи пульта или
     исторический `Tnnn`); подкаталог с любым другим именем
     (`pending-journal`, `tmp-x` и т. п.) не отбирается при любом возрасте;
   - задача вне `_kept_task_ids(conn)`: каталог открытой задачи и каталог
     одной из последних `config.LOG_RETENTION_KEEP_TASKS` закрытых не
     отбираются; задача, которой нет в БД, — вне множества;
   - самый свежий mtime среди всех файлов внутри (рекурсивно) старше
     `config.LOG_RETENTION_DAYS`; у каталога без файлов давность — mtime
     самого каталога;
   - замок `suite_lock.holder()` не за этой задачей;
   - в `<id>/run.json` нет живого `pid`: `pid` читается как целое из
     `run.json`, `pid` > 0 и `liveness._pid_alive(pid)` истинно — каталог не
     отбирается; нет `run.json`, он нечитаем, нет ключа `pid` или `pid` не
     целое — признака живого прогона нет (чтение `pid` то же, что в
     `_live_suite_run_in`, `orchestrator/doctor/orphans.py:58`).

   Файл `lock.json` и каталог `pending-journal/` не отбираются никогда.
   Удаление — каталог целиком, без перехода по символическим ссылкам;
   подкаталог-ссылка не отбирается.
3. **Каталоги упразднённых механизмов — отбор.** Константа
   `prune.ABOLISHED_DIRS = (".artel/notes-work",)` (пути относительно корня
   пульта) и новая функция `prune._abolished_candidates() -> list[Path]` —
   каталоги из константы, если путь существует и это каталог, а не
   символическая ссылка. Путь-ссылка не отбирается: ни ссылка, ни её цель
   не удаляются, переход по ссылке не выполняется. Условия давности нет.
4. **Каталоги упразднённых механизмов — сохранность работы.** Каталог
   удаляется целиком и только если он — корень собственного репозитория git
   и в нём нет несохранённой работы. Все вызовы git — локальные, без сети,
   через `gitcmd.in_repo`. Иначе каталог не удаляется и не входит в план
   удаления, отчёт печатает строку
   `  каталог упразднённого механизма <путь относительно корня пульта> оставлено: <причина>`.
   Причины:
   - «не собственный репозиторий» — в каталоге нет своего `.git` или
     `git rev-parse --show-toplevel` в нём не равен самому каталогу
     (сравнение разрешённых путей);
   - «git не ответил: <ошибка>» — любой вызов git проверки завершился
     ненулевым кодом; `<ошибка>` — текст ошибки git (stderr); пустой вывод
     такого вызова не считается признаком чистоты;
   - «незакоммиченные правки» — изменения отслеживаемых файлов (в индексе
     или рабочем дереве);
   - «неотслеживаемые или игнорируемые файлы» — в рабочем дереве есть
     неотслеживаемый или игнорируемый файл;
   - «коммиты вне origin» — есть коммит, достижимый из локальной ветки и
     недостижимый ни из одной ссылки `refs/remotes/origin/*` (ссылки других
     удалённых, не `origin`, сохранённым коммит не делают);
   - «непустой stash» — в репозитории есть хоть одна запись stash;
   - «отделённый HEAD» — HEAD не указывает на ветку.

   При нескольких причинах сразу печатается одна строка с первой из них по
   порядку перечня выше.
5. **Отчёт `cmd_prune`.** План и исполнение считаются одним расчётом (как
   сейчас). `_print_report` добавляет строки:
   - `  лог <имя>.prompt.txt будет удалён | удалён` (для промптов — та же
     форма, что у строк логов);
   - `  каталог suite-run <имя> (<N> файлов) будет удалён | удалён`;
   - `  каталог упразднённого механизма <путь относительно корня пульта> (<N> файлов) будет удалён | удалён`;

   `<N>` — число файлов внутри каталога рекурсивно. Сбой удаления каталога
   `suite-run` — строка `  каталог suite-run <имя> не удалён: <ошибка>`,
   каталога упразднённого механизма —
   `  каталог упразднённого механизма <путь> не удалён: <ошибка>`; удаление
   прочих кандидатов и прочих видов после сбоя продолжается.
   «нечего убирать» — только когда пусты все виды и нет строк «оставлено».
   Существующие строки отчёта (логи, диагностика канарейки, alerts) —
   прежние побайтно.
6. **Прежние виды.** Логи `*.log`, диагностика `.artel/canary/` и архивация
   alerts работают как прежде; уборка `kill`/`done` логи и хозяйство
   `suite-run` не трогает (инвариант 16 не меняется).
7. **`docs/retention.md`.** В раздел `.artel/logs/` — промпты `*.prompt.txt`
   и каталоги `.artel/logs/suite-run/<id>/` по тому же двойному правилу
   (давность — по самому свежему файлу каталога; `lock.json`,
   `pending-journal/` и каталог задачи, держащей замок, не убираются). Новый
   раздел «Каталоги упразднённых механизмов» (`.artel/notes-work` — целиком,
   `prune --execute`, без условия давности, только корень собственного
   репозитория без несохранённой работы). Новый раздел «Сессии ролей
   (`.artel/home/.claude/projects`)» — объём и темп роста, политики хранения
   пока нет, `prune` их не трогает, уборка — отдельная строка бэклога.
8. **Справка `orchestrator/artel.py`.** Абзац модульной строки документации
   о `prune` (строки 70–77) и строка перечня модулей `prune` (строка 625)
   дописаны: промпты, каталоги `suite-run`, каталоги упразднённых
   механизмов. Разбор команды и прочий код `artel.py` не меняются.
9. **Тесты** — детерминированные, без сети, в песочнице корня пульта
   (`tests/sandbox.py`, образец — `tests/test_prune.py`; mtime ставится

## Критерии приёмки

AC-1. Старый (старше `LOG_RETENTION_DAYS`) промпт `<id>-<роль>-<n>.prompt.txt`
задачи вне последних 20 закрытых входит в план сухого прогона строкой
`  лог <имя>.prompt.txt будет удалён` и удаляется `prune --execute` со строкой
`  лог <имя>.prompt.txt удалён`; свежий промпт и промпт задачи из последних 20
закрытых не отбираются (на текущем коде — красный: промпт не отбирается).
Старый файл верхнего уровня `.artel/logs/`, не оканчивающийся на `.log` или
`.prompt.txt` (например `x-state.db`), не отбирается и после `--execute` цел.

AC-2. Старый каталог `.artel/logs/suite-run/<id>/` закрытой задачи вне
последних 20: сухой прогон печатает `  каталог suite-run <id> (<N> файлов) будет удалён`
и не удаляет ни одного файла или каталога; `--execute` удаляет каталог
целиком со строкой `  каталог suite-run <id> (<N> файлов) удалён`. Каталог,
где хоть один файл (в том числе во вложенном подкаталоге) свежий, не
отбирается.

AC-3. Пустой каталог `.artel/logs/suite-run/<id>/` той же задачи отбирается
по mtime самого каталога: со старым mtime — удаляется `--execute`, со свежим
mtime — не отбирается и после `--execute` цел.

AC-4. Старый каталог `.artel/logs/suite-run/<id>/` открытой задачи и старый
каталог задачи из последних 20 закрытых не отбираются и после `--execute`
целы.

AC-5. Не отбираются и после `--execute` целы: каталог задачи, держащей замок
(`lock.json` с её id); старый каталог с `run.json`, где `pid` живого процесса;
`pending-journal/` и `lock.json` при любом возрасте; старый подкаталог с
именем не формы id задачи (`tmp-x`); подкаталог — символическая ссылка.

AC-6. Сбой удаления отобранного каталога `suite-run` при `--execute` даёт
строку `  каталог suite-run <id> не удалён: <ошибка>`, сбой удаления каталога
упразднённого механизма — строку
`  каталог упразднённого механизма .artel/notes-work не удалён: <ошибка>`; в
обоих случаях отобранный в том же прогоне старый лог (`*.log` или
`*.prompt.txt`) всё равно удалён со своей строкой «… удалён».

AC-7. `.artel/notes-work` — корень собственного репозитория git с чистым
рабочим деревом, без неотслеживаемых и игнорируемых файлов, без коммитов вне
`refs/remotes/origin/*`, с пустым stash и HEAD на ветке: сухой прогон
печатает `  каталог упразднённого механизма .artel/notes-work (<N> файлов) будет удалён`
и не удаляет его; после `--execute` каталога нет; повторный `--execute` при
отсутствии других видов печатает «нечего убирать».

AC-8. `.artel/notes-work` — символическая ссылка на каталог (в том числе на
чистый репозиторий из AC-7): не входит в план, после `--execute` ссылка и
содержимое её цели целы; при отсутствии других видов печатается «нечего
убирать».

AC-9. `.artel/notes-work` — каталог без своего `.git` внутри репозитория
пульта песочницы: отчёт печатает
`  каталог упразднённого механизма .artel/notes-work оставлено: не собственный репозиторий`;
после `--execute` каталог и его содержимое целы, «нечего убирать» не
печатается.

AC-10. Вызов git проверки `.artel/notes-work` завершается ненулевым кодом
(например, повреждённый `.git` собственного репозитория): отчёт печатает
строку, начинающуюся с
`  каталог упразднённого механизма .artel/notes-work оставлено: git не ответил: `;
после `--execute` каталог и его содержимое целы.

AC-11. `.artel/notes-work` с изменённым отслеживаемым файлом — строка
`  каталог упразднённого механизма .artel/notes-work оставлено: незакоммиченные правки`;
отдельно — с неотслеживаемым файлом и отдельно — с игнорируемым (по
`.gitignore`) файлом при прочих условиях AC-7 — строка
`… оставлено: неотслеживаемые или игнорируемые файлы`; во всех случаях после
`--execute` каталог и его содержимое целы, «нечего убирать» не печатается.

AC-12. `.artel/notes-work` с коммитом локальной ветки, которого нет ни в
одной ссылке `refs/remotes/origin/*`, — строка
`… оставлено: коммиты вне origin`; то же, когда этот коммит есть только в
ссылке другого удалённого (`refs/remotes/<не origin>/…`); после `--execute`
каталог и его содержимое целы.

AC-13. `.artel/notes-work` при прочих условиях AC-7 и непустом stash —
строка `… оставлено: непустой stash`; после `--execute` каталог и его
содержимое целы.

AC-14. `.artel/notes-work` при прочих условиях AC-7 и отделённом HEAD
(HEAD на коммите, а не на ветке) — строка `… оставлено: отделённый HEAD`;
после `--execute` каталог и его содержимое целы.

AC-15. `docs/retention.md` содержит: в разделе `.artel/logs/` — промпты
`*.prompt.txt` и каталоги `.artel/logs/suite-run/<id>/` с исключениями
`lock.json`, `pending-journal/` и каталога задачи, держащей замок; раздел
«Каталоги упразднённых механизмов» с `.artel/notes-work`; раздел «Сессии
ролей (`.artel/home/.claude/projects`)». Справка о `prune` в
`orchestrator/artel.py` (абзац модульной строки документации и строка
перечня модулей) называет промпты, каталоги `suite-run` и каталоги
упразднённых механизмов.

`SPLIT_SIGNAL_AC_COUNT` = 10); зона задевает механизм, на который опирается

функции-команды (`orchestrator/prune.py`: отбор, `_print_report`,
`cmd_prune`) и её документации. Нарезка по видам (промпты и `suite-run` /
`notes-work`) резала бы зону `orchestrator/prune.py`, `docs/retention.md` и
справку `artel.py` поперёк: обе части правили бы одни и те же функции и
строки отчёта («нечего убирать» зависит от всех видов сразу) и шли бы через
замок зоны последовательно. Рост критериев до 15 — от решений гейта SPEC
(раздельный критерий на каждую причину «оставлено»), а не от объёма кода.
Инвариант 16 не меняется (требование 6), а лишь подтверждается.

## Пути обхода гейтов
1. **notes-work без собственного `.git`.** `gitcmd.in_repo` — это
   `git -C <repo>` (gitcmd.py:385) с `cwd=config.ROOT` (gitcmd.py:185). Если в
   `.artel/notes-work` нет своего `.git` (репозиторий повреждён/частично
   удалён, или это просто каталог), git поднимется по дереву и ответит о
   репозитории ПУЛЬТА: `git status --porcelain` и `git log --branches --not
   --remotes` пульта. Главная копия пульта обычно чиста и без коммитов вне
   origin — оба вывода пусты, и требование 3 (SPEC.md:51–62), исполненное
   буквально, удалит каталог целиком без какой-либо проверки его содержимого.
   SPEC не требует убедиться, что каталог — корень собственного репозитория
   (например, `git -C <путь> rev-parse --show-toplevel` равен пути или
   существует `<путь>/.git`), иначе — «оставлено: <причина>». Тесты AC-6/AC-7
   строят notes-work настоящим репозиторием и эту дыру не поймают.
2. **«Коммиты вне origin» проверяются против всех remote, не только origin.**
   `--not --remotes` (SPEC.md:57) считает сохранённым коммит, лежащий на любом
   remote-tracking ref, в т. ч. устаревшем после удаления ветки на сервере;
   ветки вне `--branches` (stash, отделённый HEAD, `refs/notes`) не
   проверяются вовсе, игнорируемые `.gitignore` файлы `git status --porcelain`
   не показывает. ТЗ сам задал именно эти две команды — не отклонение SPEC
   от ТЗ, но Оператору стоит знать остаточный риск безвозвратного удаления
   (ТЗ, «Факты»: «пропали бы безвозвратно»).
3. **`is_task_id_form` принимает префиксы id** (idgen.py:59–60): подкаталог
   `suite-run/` с именем вроде `TMP`, `A1` или `ABC` проходит «форму id» и,
   раз задачи нет в БД, отбирается по одной давности. Правило задано ТЗ
   дословно; при нынешнем составе каталога (`<id>/`, `pending-journal/`)
   риск низкий — к сведению.

# ТЗ: Мандат Оператора на правку существующего теста — на гейте SPEC, без эскалации разработчика

Источник: «Предложения системе» PLAN задачи 01M4PMR5EVFK4KQDPWB1KEGM7V
(12.10): раздел SPEC «Ожидаемая краснота» с контейнерным значением заранее
обрекает задачу на эскалацию разработчика ради мандата, который Оператор
мог дать на гейте SPEC. Повторилось 12.10 у 01M4PMR5EV и 01M4PMQSYP.
Решение Оператора 12.10.2026 — заводить.

Факты (origin/main 8543e24e):
- `orchestrator/answer.py::cmd_answer` (~234-360) принимает файл ответа в
  `escalated`, в `INSTRUCTION_STATES = ("in_dev", "review")` (~194) и в
  `merge_gate` (только «Зависимости мержа:»); на `spec_gate` — общий отказ.
- Мандат тестов читается рубежами неослабления из ВСЕХ ANSWER-n ветки
  документов (`advance_gates/test_integrity.py::_answer_mandate` ~867,
  `advance_gates/mandate.py`), с отсечением файлов, чей последний коммит —
  автокоммит шага роли; правка рубежей не нужна.
- `approve` гейта SPEC (`fsm.py` ~1105) перезаписывает `merge_after`
  значением поля SPEC — мандат зависимостей на гейте SPEC не годится.
- После `answer` пересчитывается фиксация (`record_fixation` в
  `_commit_answer`): `approve <id> <sha>`, скопированный до мандата,
  откажет; голый `approve` сверяет сам.

Требуется:
1. `answer <id> <файл>` в состоянии `spec_gate` принимает только мандат
   тестов: файл обязан содержать хотя бы одну строку «Ослабление тестов
   разрешено:». Строки «Расширение зон разрешено:» и «Зависимости мержа:» на
   `spec_gate` — именованный отказ (зоны и зависимости задаются полями SPEC
   и reject). Файл без строки мандата тестов — именованный отказ (решения
   по SPEC передаются reject).
2. Прочее содержимое файла (раздел «## Матрица неослабления», строка
   «Независимая проверка:», свободный текст) допускается и проверяется
   теми же правилами формы, что в `in_dev` (`_read_checked_answer_file`,
   `_matrix_problems`) до коммита. Тот же рубеж окружения роли
   (`runner.in_role_environment` — отказ до чтения файла). Состояние задачи
   не меняется; запись журнала — в прежнем формате «ANSWER создан (мандат
   на ослабление тестов: …)».
3. Мандат, записанный на гейте SPEC, засчитывается рубежом неослабления на
   переходе `in_dev -> verifying` и на гейте мержа так же, как записанный в
   `in_dev`, в том числе после reject и последующего автокоммита шага
   аналитика.
4. Справка команды (`orchestrator/artel.py`) и `docs/operator-session.md`:
   мандат на гейте SPEC давать после вердикта аудита и перед approve; sha
   для approve копировать после мандата (или голый approve); мандат
   действует всю жизнь задачи — после reject и новой редакции SPEC его
   перечитать.
5. Тесты в `tests/` с заявками «Ловит мутацию»: ответ на `spec_gate` без
   строки мандата тестов принят; принята строка зон или зависимостей;
   мандат без матрицы принят; вызов из окружения роли принят; сквозной тест
   на настоящем коммите ANSWER в артефактную ветку — мандат с гейта SPEC
   засчитывается рубежом in_dev; ANSWER без строки мандата мандата не даёт.
   Существующие тесты не ослабляются.

Матрица неослабления (независимая проверка 12.10): новый канал — только
для Оператора и только для мандата тестов, с той же проверкой формы,
матрицы и независимой проверки; рубежи неослабления, зоны и зависимости
мержа не меняются.

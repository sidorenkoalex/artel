## Проверяемость критериев

| Критерий | Проверяем | Ловимая мутация |
|---|---|---|
| AC-1 | да | `_send` по-прежнему зовёт `_attempt_push` с проверкой `has_no_remote` (или признак передан, но игнорируется) — два вызова `git remote …` перед `push` |
| AC-2 | да | `_origin_configured` в `_send` заменён на `not has_no_remote` — при remote с другим именем идёт `push` и запись FAILED |
| AC-3 | да | признак «origin проверен» передан и из `push(task_id)` либо проверка снята из `_attempt_push` целиком — `git push` без remote, причина не `PUSH_REASON_NO_ORIGIN` |
| AC-4 | да | `_send` в `origin_sync_refusal` остаётся безусловным — `push` при совпадении |
| AC-5 | да | нет повторной сверки после досылки — отказ «расходится» со старым sha origin |
| AC-6 | да | досылка до первой сверки (прежний порядок) — `push` при недоступном origin |
| AC-7 | да | после неудачной досылки ветка сравнения меняется (например, `None` при `not remote`) |
| AC-8 | да | результат второй сверки не сравнивается — `None` либо текст «нет в origin» |
| AC-9 | да | досылка только при непустом `remote` — ссылка, которой нет в origin, не досылается |
| AC-10 | да | `if local != remote: _send(...)` без проверки `local` — `git push` несуществующей ссылки виден шпиону |
| AC-11 | да (проверка PLAN ревью) | счёт не снят или снят не на названном тесте |

Песочницы AC-6 (адрес `origin` на несуществующий путь: `get-url` отвечает,
`ls-remote` падает), AC-7 (bare-origin с отклоняющим хуком), AC-8 (расхождение
с отказом non-fast-forward) реализуемы на настоящем git — критерии не
требуют подмены кода.

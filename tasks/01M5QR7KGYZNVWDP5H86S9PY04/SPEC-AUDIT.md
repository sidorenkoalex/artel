# SPEC-AUDIT: Скорость пульта, git 1 — одна проверка origin при отправке документов и отправка в сверке с origin только при расхождении

## ТЗ и SPEC
Требования 1–4 ТЗ (TZ.md:29–32) перенесены в SPEC (SPEC.md:45–67) почти
дословно; зоны, ограничение зон по смыслу, «Только чтение» и «Не входит»
ТЗ отражены в SPEC.md:116–131. ANSWER-n нет, решений Оператора на гейте SPEC
нет. В SPEC нет требований сверх ТЗ.

Расхождения:
- Требование 5 ТЗ «Существующие тесты не правятся и остаются зелёными»
  (TZ.md:33) в SPEC урезано до «не правятся» (SPEC.md:68), а вторая
  половина вынесена в «Не входит» (SPEC.md:130) с пояснением «её держит
  пульт». По существу гейты пульта и так держат зелёный набор, но в SPEC
  требование ТЗ стало «не входит» — Оператору стоит подтвердить, что такая
  переформулировка допустима.
- Исход из требования 2 ТЗ «в origin нет ссылки — после досылки совпадает»
  (TZ.md:30) в SPEC требованием сохранён (SPEC.md:55–56), но отдельного
  критерия приёмки у него нет: тест-случаи (а)–(з) ТЗ (TZ.md:31) его не
  перечисляют, SPEC их перенёс как AC-1–AC-8. Подробнее — в «Проверяемости».

## Проверяемость критериев

| Критерий | Проверяем | Ловимая мутация |
|---|---|---|
| AC-1 | да, при шпионе на уровне `gitcmd.in_repo`/процессов | вторая проверка `has_no_remote` в пути `_send` оставлена. **Не ловит**, если шпион стоит только на `artifact_branch._git` (см. «Факты») — отклонение формулировки |
| AC-2 | да | `_send` без origin делает push. **Не ловит** замену `_origin_configured` на `has_no_remote` (репозиторий с remote, но без `origin`: раньше молча `False`, после мутации — push и запись FAILED) и появление новой записи журнала в `_send` без origin (требование 1: тексты журнала не меняются) — песочница AC-2 не уточнена |
| AC-3 | да | `push(task_id)` передаёт признак «origin проверен» / признак по умолчанию снимает проверку — `git push` вызывается |
| AC-4 | да | `_send` в `origin_sync_refusal` остаётся безусловным |
| AC-5 | да | досылка без повторной сверки (сравнение с первым `ls-remote` → «расходится»); `None` после успешного `_send` без `ls-remote` — ловится, если тест считает вызовы `ls-remote` |
| AC-6 | да | досылка идёт до первой сверки (прежний порядок) |
| AC-7 | да | текст отказа «нет в origin» изменён/потерян |
| AC-8 | да | после досылки отказ «расходится» подменён `None` или другим текстом |
| AC-9 | проверяется ревью PLAN, не тестом | — ; адрес теста ошибочен (см. «Факты») |

Пропуск: нет критерия «ссылки нет в origin, досылка удалась → `git push`, `None`» (требование 2, SPEC.md:55–56). Правдоподобная мутация «досылать только при `remote` непустом» (`if local and remote and local != remote`) проходит все AC: в AC-7 досылка и так неудачна, в AC-5 ссылка в origin есть; существующий `tests/test_artifact_ref_sync.py::test_absent_in_origin_is_refused` (:185) тоже запрещает push. После такой мутации первая отправка ссылки на гейте мержа/закрытии перестаёт досылать и даёт отказ.

## Зоны
Зоны `orchestrator/artifact_branch.py, docs/codebase-map.md, tests/` покрывают правку двух функций и новый файл тестов; карта — для регенерации (правка `orchestrator/`). Защищённых путей правка не трогает (`artifact_branch.py`, `tests/` вне `config.PROTECTED_PATHS`). Изменение `gitcmd.py` не требуется: признак передаётся параметром `_attempt_push`. Ограничение «в `tests/` только новые файлы» (SPEC.md:118–120) совместимо с существующими тестами: `tests/test_artifact_branch_server_retry.py:77,206` подменяют `has_no_remote` и останутся зелёными при неиспользуемой подмене; `tests/test_artifact_ref_sync.py:168–212` при новом порядке дают те же исходы. Песочница ролей не расширяется. Отклонений нет.

## Пути обхода гейтов
- AC-1 с шпионом только на `_git` выполняется буквально и без правки (вторая проверка `has_no_remote` не видна такому шпиону) — тест «зелёный по построению» на старом коде не будет красным; гейт красноты планки на `tests_writing` это поймает, только если тест действительно запускают на базе. Нужна формулировка шпиона на `gitcmd.in_repo` (или процессов).
- AC-9 на неверном адресе: счёт на `tests/test_01m5cjvb5b5v55pqqvr2qrhwzn_outcome_gate.py::Ac5PassToPassTest` формально выполняет AC-9, но не измеряет предмет задачи (там нет `origin_sync_refusal`/approve).
- Иных путей обхода не найдено: тексты отказов зафиксированы дословно в AC-6–AC-8, вызывающие не меняются.

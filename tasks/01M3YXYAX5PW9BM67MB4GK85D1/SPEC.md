# SPEC: Предполёт шага сверяет CLI и вход провайдера шага, а не провайдера роли

## Контекст
Часть 2 деления «Набор моделей отдельной задачи» (01M3YCHS4F08VTV6XX10VF92H3)
перевела шаг роли задачи с набором на модель набора: провайдер шага —
`runner._step_provider(t, role)` (`orchestrator/runner.py:492`), им уже
пользуются запуск шага и подсчёт стоимости. Предполёт шага при этом
вызывается без задачи — `doctor.preflight_checks(role, target)`
(`orchestrator/runner.py:357`, `orchestrator/doctor/preflight.py:684`), и
внутри него `providers.for_role(role)`, `check_model_provider_cli(role)`
(`preflight.py:328`), `check_token(role)`, проверки CLI и входа Codex, а
также склейка `provider_preflight_checks()` (`preflight.py:651`) выбирают
провайдера по роли и ярусу, то есть по боевому набору. Следствие: у задачи,
где набор переводит роль на модель другого провайдера, предполёт проверяет
CLI и вход боевого провайдера роли — ложный отказ, если его CLI на машине
нет, и пропуск проверки CLI и входа провайдера набора (шаг падает уже на
запуске агента). Цель — первая настоящая задача на наборе моделей с ролью
на Codex (`new --set`).

## Требования
1. Предполёт шага получает провайдера шага — того же, что
   `runner._step_provider` возвращает для этой задачи и роли, — и проверяет
   CLI, его версию и вход именно этого провайдера. Для задачи без набора
   поведение предполёта не меняется.
2. Нехватка CLI или входа провайдера набора — именованный отказ шага до
   запуска агента, без повтора, с указанием провайдера, роли и набора.
3. CLI и вход боевого провайдера роли, не участвующего в шаге, отказа шага
   не вызывают.
4. `doctor` (команда Оператора) по-прежнему проверяет провайдеров боевого
   набора и, дополнительно, провайдеров наборов задач в работе — тем же
   источником, что `models.live_task_set_providers` части 2; задачи в
   `done`/`killed` не учитываются.
5. Тесты в `tests/` закрывают сценарии критериев AC-1…AC-3 (последний —
   с пометкой «Ловит мутацию: предполёт по провайдеру роли, а не шага»).
6. `docs/stack.md` описывает предполёт шага задачи с набором.

## Критерии приёмки
AC-1. Задача с набором, переводящим роль на модель провайдера Codex: при
отсутствии CLI Claude и наличии CLI Codex (и его входа) предполёт шага этой
роли проходит — отказа «CLI не найден» по Claude нет, агент запускается.

AC-2. Та же задача с набором, переводящим роль на Codex, при отсутствии
CLI Codex: шаг отклонён до запуска агента (агент не запускается ни разу,
повтора нет), причина отказа называет провайдера (`codex`), роль и набор
задачи.

AC-3. Соседняя задача без набора (та же роль): предполёт проверяет
боевого провайдера роли — при отсутствии его CLI шаг отклонён с его
именем, поведение совпадает с поведением до задачи. Тест несёт пометку
«Ловит мутацию: предполёт по провайдеру роли, а не шага».

AC-4. Нехватка входа провайдера набора (CLI Codex есть, вход Codex не
выполнен) — именованный отказ шага до запуска агента, без повтора, с
указанием провайдера, роли и набора.

AC-5. `doctor` при задаче в работе, чей набор переводит роль на провайдера,
которого не требует боевой набор, выводит проверки CLI/входа этого
провайдера в дополнение к проверкам провайдеров боевого набора; та же
задача в `done` или `killed` такой добавки не даёт. Источник набора
провайдеров — `models.live_task_set_providers`.

AC-6. `docs/stack.md` содержит описание предполёта шага задачи с набором:
предполёт проверяет CLI, версию и вход провайдера шага (модели набора), а
не боевого провайдера роли; `doctor` дополнительно проверяет провайдеров
наборов задач в работе.

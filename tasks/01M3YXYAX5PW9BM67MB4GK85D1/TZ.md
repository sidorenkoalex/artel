# ТЗ: Предполёт шага сверяет CLI и вход провайдера шага, а не провайдера роли

Источник: «Предложения системе» REVIEW задачи 01M3YCHS4F08VTV6XX10VF92H3
(часть 2 деления «Набор моделей отдельной задачи»), то же предложение —
в её PLAN; строка бэклога 02.10 (П1); решение Оператора 02.10 — завести
сразу после мержа части 2. Цель — первая настоящая задача на наборе
моделей с ролью на Codex (`new --set`).

Факты (код части 2, смерженной перед заведением; номера строк аналитик
сверяет):
- Шаг роли задачи с набором идёт на модели набора: провайдер шага —
  `runner._step_provider(t, role)` (около `runner.py:492`), им уже
  пользуются запуск шага и подсчёт стоимости.
- Предполёт шага вызывается без задачи: `doctor.preflight_checks(role,
  target)` (`runner.py` около строки 357, 
  `orchestrator/doctor/preflight.py::preflight_checks` около строки 684). Внутри
  `check_model_provider_cli(role)` (около строки 328), `check_token(role)`,
  проверки CLI и входа Codex (`check_codex_cli_found`,
  `check_codex_cli_version`, `check_codex_chatgpt_auth`) и склейка
  `provider_preflight_checks()` выбирают провайдера по роли и ярусу, то
  есть по боевому набору.
- Следствие: у задачи, где набор переводит роль на модель другого
  провайдера, предполёт проверяет CLI и вход боевого провайдера роли —
  ложный отказ, если его CLI на машине нет, и пропуск проверки CLI и
  входа провайдера набора (шаг упадёт уже на запуске агента).

Требуется:
1. Предполёт шага получает провайдера шага (тот же, что
   `runner._step_provider` для этой задачи и роли) и проверяет CLI,
   его версию и вход именно этого провайдера. Для задачи без набора
   поведение не меняется.
2. Нехватка CLI или входа провайдера набора — именованный отказ шага до
   запуска агента, без повтора, с указанием провайдера, роли и набора.
   CLI и вход боевого провайдера роли, не участвующего в шаге, отказа не
   вызывают.
3. `doctor` (команда Оператора) по-прежнему проверяет провайдеров боевого
   набора и, дополнительно, провайдеров наборов задач в работе — тем же
   источником, что `models.live_task_set_providers` части 2; задачи в
   `done`/`killed` не учитываются.
4. Тесты в `tests/`: задача с набором, переводящим роль на Codex, — при
   отсутствии CLI Claude и наличии Codex предполёт проходит; при
   отсутствии CLI Codex — отказ шага с именем провайдера; соседняя задача
   без набора — проверяется боевой провайдер («Ловит мутацию: предполёт
   по провайдеру роли, а не шага»). Существующие тесты предполёта,
   `doctor` и запуска шага не удаляются и не ослабляются.
5. Документация: в `docs/stack.md` — предполёт шага задачи с набором.

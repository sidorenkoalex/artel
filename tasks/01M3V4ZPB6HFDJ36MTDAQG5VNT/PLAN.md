# PLAN: Отдельный подписочный профиль Codex канарейки

## Подход

Держать постоянный профиль канарейки вне боевого дома и клонов. На время прогона эксклюзивно блокировать профиль; перед каждой задачей восстанавливать курируемые файлы из референса проверяемого SHA и удалять историю и доверие предыдущей задачи. Передавать один адрес `CODEX_HOME` в проверку входа и процесс клона. Вход и токены обслуживает только Codex CLI через подписку ChatGPT и keyring; первоначальный вход остаётся действием Оператора.

Отказ «дефект пульта» (ANSWER-5 п.2) — выбран первый вариант: отказ при новой механике достижим и сохранён. Основание по коду: вход профиля проверяется окружением шага клона (`HOME`/`ZDOTDIR` клона + скопированный указатель связки ключей + `CODEX_HOME` профиля); если та же проверка с тем же `CODEX_HOME` профиля, но окружением пульта, проходит, расходятся только подготовленные пультом половины клона — это дефект пульта, повторный `codex login` его не чинит. Реализовано `canary._refuse_unless_profile_logged_in`: сравнение идёт с профилем, а не с боевым `CODEX_HOME` (иначе нарушился бы AC-10). Старый `_refuse_unless_clone_logged_in` остаётся для формы `codex_auth` без профиля. Описание обоих отказов возвращено в `docs/stack.md`; метод `test_section_names_both_refusals_of_the_run` восстановлен с прежним именем и шире содержимым (вход, дефект пульта, занятость). Две другие правки тестов покрыты мандатом ANSWER-5 п.1. По п.3: эксплуатационная проверка в `docs/stack.md` названа «набор с ролью Codex», набор `default` путём проверки профиля нигде не назван.

## Влияние на систему

Меняется только ветка канарейки с ролями Codex. Обычный дом роли, авторизация обычной задачи, предполёт и защитные гейты остаются действующими. Профиль блокируется на полный прогон, поэтому параллельные канарейки с Codex получают отказ до платного шага. Откат — revert одного коммита кодовой ветки; постоянный профиль при этом не удаляется.

## Риски

Реальный вход и платный прогон требуют отдельного действия Оператора и недоступны роли разработчика; синтетические тесты не доказывают состояние Keychain или действительность подписки.

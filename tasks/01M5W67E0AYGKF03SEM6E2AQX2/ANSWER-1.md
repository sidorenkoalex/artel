# ANSWER-1: ответ Оператора

## Ответы

Ответы сессии при Операторе (права волны G, решения Оператора по ADR-0029 от 26.10.2026) на QUESTIONS.md аналитика.

1. **A.** Белый список отправок включается только при `merge_gate`, отличном от `operator` (буква ADR-0029 п. 13). У проекта `operator` с нестандартным `branch_template` отправки прежние — мерж и уборка пульта не меняются. Критерии «отправка в `main`/чужую ветку/удаление/тег — отказ» проверяются на записи с `merge_gate: target-human` (запись в тесте; живого такого проекта до Б2 нет — А0).
2. **B.** Сверка занятости имени (сервер `ls-remote` и БД) — только когда `branch_template` отличен от умолчания (или шаблон без `{id}`); сбой `ls-remote` — отказ `new`/деления с причиной «имя ветки не проверено». У артели и проектов с полями по умолчанию сетевого вызова нет.
3. **A.** В зоны — `orchestrator/pull.py`, `orchestrator/fsm.py`, `orchestrator/github_adapter.py` поимённо (места подтяжки и отправки ветки задачи). `github_adapter.py` — только место отправки ветки (перезапись по требованию 5); поведение черновика MR не меняется. Внимание: параллельная задача А1 (01M5W670PHF08VPZWDRM5BY56W) держит `github_adapter.py` («только вынос в интерфейс») — если зона занята, часть, которой нужен `github_adapter.py`, ждёт её мержа (порядок мержа частей и А1 — по зонам).
4. **A.** Деление на две части по предложенной границе: часть 1 (требования 1, 2, 6 — поля и их проверка, имя ветки и поиск, белый список и хук; `targets.py`, `catalog.py`, `coldstart.py`, `gitcmd.py`) и часть 2 после части 1 (требования 3–5 — автор/соавтор, сжатие, `rebase`, перезапись; остальные файлы). Рамки частей — $40 и $45 (строкой «Рамка:» каждой части).
5. **A.** `freshness` — только на `in_dev → verifying`; подтяжка перед шагом разработчика и `pull-main` — прежний `merge`.
6. **A.** `Co-authored-by` — в каждом коммите, который пишет пульт (чекпоинты, фиксация, документы, сжатый коммит); коммиты роли без сжатия не переписываются (у подключаемого проекта `squash_before_mr: true`).

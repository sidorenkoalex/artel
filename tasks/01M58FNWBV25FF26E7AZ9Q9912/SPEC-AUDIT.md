## Пути обхода гейтов
1. **Ослабление вместо смены ожидания.** Без мандата разработчик может «починить» красный подслучай удалением кортежа `("не прочитан", unread)` из `tests/test_acceptance_suite_profile.py:71` и не добавить отрицательной проверки. Гейт неослабления должен это поймать. SPEC велит эскалировать (SPEC.md:106) — путь закрыт процедурно, но мандат нужно решить заранее.
2. **Форма отказа требования 9.** Разработчик выполнит его буквально, но `drop_from_code_copy` будет глотать любое исключение (`except Exception`). Тогда отказ не дойдёт ни до кого, кроме `acceptance_suite`, а широкий перехват скроет и другие сбои уборки. Либо наоборот: исключение роняет старт шага роли (`runner.py:1218`). SPEC не запрещает ни того, ни другого.
3. **Единственный компонент как обход правила own-runner.** Запись с одним элементом `components:` принимает `workdir`/`env` при `pult-pytest` (SPEC.md:26) и даёт PRESENT (SPEC.md:39). `test_profile` с теми же подполями отвергается (`targets.py:310-318`). `targets.yaml` защищён и пишется Оператором, поэтому это не обход роли, а молчаливо проигнорированная настройка.
4. **Единственный компонент с `repo` ≠ имени записи.** PRESENT, и прогон идёт по репозиторию записи — `repo` молча игнорируется (SPEC.md:29, :127). Замечание: ТЗ разрешает только проверку формы, но для одного компонента разумен отказ или UNREAD.
5. **AC-2 по подмножеству полей.** Реализация без проверок `knowledge`/`repo`/`report_args`/`select`/`failure_errors`/`layers`/`checks_local` пройдёт все критерии.
6. **AC-7 только на обратимость.** Формат, расходящийся с ADR-0026 п. 3, пройдёт критерий.

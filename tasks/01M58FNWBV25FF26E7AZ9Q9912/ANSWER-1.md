Ответы даны в пределах ТЗ: без мандатов на ослабление тестов и без новых файлов зоны.

1. **Вариант B.** `yamlmini.py` не меняется. `components:` — отображение «имя компонента → поля» (поле `name` берётся из ключа; отдельного `name` нет). `depends_on` — отображение «имя поставщика → поля» блоком (`via`, `paths`). `paths` и `depends_on.paths` — регулярные выражения одной строкой или потоковым списком без кавычек, запятых и `[...]`; выражение с недопустимым символом — громкий отказ формы с причиной. `install` и `checks_local` — одна команда потоковым списком. Форма черновика записи sled в ADR-0026 будет приведена к этой схеме на этапе 2 плана (запись пишет Оператор).

2. **Вариант C.** `profile_of` для записи с несколькими компонентами даёт UNREAD с причиной «запись проекта с несколькими компонентами исполняется после G1б»; запись с одним компонентом — PRESENT с его подполями. `_task_own_profile` (`orchestrator/acceptance.py`, файл уже в зонах; ограничение ТЗ «только ключ кэша» снимается для этой функции) на UNREAD отказывает с причиной, а не возвращает `None`. `suite_run.py` не трогается. Изменение исхода `_task_own_profile` для записей, профиль которых сегодня не прочитан, — строгость, не ослабление; перечислить в «Меняемое поведение» SPEC.

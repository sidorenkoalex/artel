# PLAN: Надзор эпика: перезапуск остановленных задач, места параллельности, завершение, answer при ожидании зоны

## Подход

Надзор эпика (`orchestrator/auto.py`, `_epic_view`/`_supervise`) перестаёт
держать задачу по одной записи «точки отсчёта» и разбирает исход каждого
запуска дочернего `auto` по журналу задачи.

- **Запуски по журналу.** Окно запуска — записи задачи от
  `EPIC_CHILD_LAUNCH_ACTION` до следующего запуска. Начало окна сдвигается
  на запись «auto старт» с тем же pid, если она легла раньше записи запуска
  (ANSWER-4 п.1: запись запуска пишется после `Popen`); начало окна
  последнего дочернего — точно, по `step_id` строки `epic_children`. Записи
  самого надзора (запуск, «вышел без записи об остановке», предел аварий) в
  разбор причины не входят.
- **Исход окна:** именованный отказ (новая запись отказа lease `auto` или
  `runner.UNSUPPORTED_PROJECT_ACTION`) → удержание до действия Оператора;
  старт и первая остановка «auto остановлен» → штатная остановка; запись
  «pause --now: процесс агента прерван» → выход после `pause --now`, не
  авария; иначе (нет старта, нет остановки, первая остановка «цикл
  оборван») — авария.
- **Штатная остановка** — правила прежние: гейт/эскалация/окончательное
  удержания не дают, иначе удержание до действия из `_operator_actions`
  после первой записи остановки (перечень прежний). Остановка потолком
  ожидания зоны или потерей lease в ожидании дополнительно снимается
  снятым ожиданием: задача в `in_dev`, `zone_lock.blocking_conflict` — нет
  конфликта; из таких задач одной очереди запускается первая по
  `zone_lock.queue_order`, очередь для неё не держат только задачи вне
  эпика, остановленные `stop`/паузой, на пределе аварий и с именованным
  отказом.
- **Авария:** опрос, заметивший выход, только запоминает его (память
  процесса надзора — ключ задача+pid, на старте пустая) и пишет прежнюю
  запись «вышел без записи об остановке»; со следующего опроса исход
  пересчитывается заново (ANSWER-4 п.2 — запись `pause --now` могла лечь
  позже) и авария засчитывается. Счёт аварий подряд — по журналу: аварии
  (позиция — «цикл оборван» либо запись надзора о выходе) и записи сброса
  (`epic retry`, `answer` кроме формы `zones-extend`, `approve`/`reject` —
  `state -> …` актора `operator` кроме подъёма бюджета, `amend-tests`,
  `resume`). Три подряд — предел: одна запись журнала задачи
  `EPIC_CRASH_LIMIT_ACTION` (актор надзора) и одна тревога `attention` на
  серию; иначе — перезапуск.
- Задача на паузе с дочерним не перезапускается.
- **Места `parallel`:** живой дочерний занимает место, только если задача
  не на гейте/в эскалации/в `verifying` и не ждёт зону
  (`zone_lock.wait_minutes`); глобальная оценка — прежняя (все живые).
- **Завершение:** открытый эпик без неокончательных задач — надзор жив и
  спит `EPIC_IDLE_POLL_SEC` (300 с); закрытый — завершается, как сейчас.
- **`auto <id>`:** запись «auto старт» несёт «, pid <pid>» и сессию цикла;
  отказ lease самого `auto` оставляет запись `AUTO_LEASE_REFUSED_ACTION`
  (распознаётся по флагу тела `run_locked`).
- **`resume`** (`pause.py`): задача не на паузе, первая остановка цикла
  после последнего «auto старт» — команда `stop` → запись `resume` актора
  `operator`.
- **`answer`** (`answer.py`): lease держит живой цикл задачи (pid и сессия
  последней записи «auto старт» совпадают с lease, `lease.foreign_live_lease`
  жив), задача в `in_dev`, вход в ожидание зоны открыт и шага роли после него
  нет — мандат принимается без lease, печатается подсказка указания.

Бюджет SPEC ($50) не пересматривается.

## Влияние на систему

- Инвариант 18 (надзор не проходит гейт): надзор по-прежнему не зовёт
  `approve`/`reject` и не пишет `state -> …`; гейт, эскалация и пауза
  задачу не перезапускают.
- Перечень `_operator_actions` не меняется; запись `resume` после `stop`
  носит прежнее имя «resume». Новые записи (предел аварий — актор надзора,
  отказ lease `auto`) под перечень не попадают.
- `lease.py`, `zone_lock.py`, `store.py`, `canary.py` не меняются;
  `zone_lock` только читается (`blocking_conflict`, `queue_order`,
  `_queue_members`, `wait_minutes`).
- Тесты меняются только по мандатам ANSWER-1 и ANSWER-3; прочие
  тесты файла надзора, `tests/test_pause.py` без правки.
- Откат — revert коммитов ветки задачи.

## Предложения системе

- `zone_lock._queue_members`/`_own_paths` надзор зовёт как приватные —
  публичного «состав очереди зоны задачи» в `zone_lock.py` нет (зона вне
  задачи); кандидат на вынос отдельной задачей.
- Сторож Bash отклоняет heredoc с f-строками («brace with quote») — правки
  и временные файлы только через Edit/Write; в скиле не описано.
- `pytest -n` на файлах стенда надзора даёт «node down» — стенд не годится
  для xdist; стоит пометить в докстринге стенда.

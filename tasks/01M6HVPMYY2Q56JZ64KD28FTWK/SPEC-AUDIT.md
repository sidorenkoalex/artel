## Пути обхода гейтов

- Надзор не вызывает `approve`/`reject`. Гейт, пауза и эскалация задачу не
  перезапускают (требование 12, AC-6). Пути мимо гейта нет.
- Имена новых записей не попадают в перечень и префиксы
  `_operator_actions` (требование 4; AC-3, AC-4). Записи пульта не снимут
  удержание сами.
- Требование 11 («ведёт себя как без цикла») — это путь `_cmd_answer` с
  его рубежом окружения роли. Лазейка возможна, только если исполнитель,
  обходя `run_locked`, пропустит этот рубеж. Это проверяет ревью.
- У `resume` после `stop` нет рубежа окружения роли. Но тот же эффект роли
  уже даёт `epic retry`, так что новой лазейки нет.
- М1 — не обход гейта, а обход предела аварий: голый `resume` при старой
  записи `stop` снимает предел без записи по смыслу требования 4. Но это
  всё равно действие Оператора.

## Вердикт

**concerns.** Отклонения мелкие, Оператор может закрыть их на гейте.

1. **М1 — «последняя остановка её цикла» не привязана к последнему циклу.**
   Где: SPEC.md, требование 2, и требование 4, фраза «Голый `resume` задачи
   не на паузе после аварии…»; код — pause.py:111-115.
   - Сценарий: `stop`, затем `resume` (запись), затем перезапуск и новая
     запись `AUTO_START`. Дальше три аварии вида (б) — после старта записи
     остановки нет, — и предел.
   - Последняя по журналу запись `AUTO_STOPPED` — всё ещё старая, `stop`.
     Если читать «последняя остановка» как последнюю запись остановки в
     журнале, голый `resume` пишет запись и сбрасывает счёт. Это
     противоречит требованию 4.
   - AC-3 проверяет голый `resume` без прежнего `stop`, поэтому такую
     мутацию не ловит.
   - Дефолт: «последняя остановка» — первая запись остановки после
     последней записи `AUTO_START_ACTION`; если её нет, `resume` журнала не
     пишет.
2. **М2 — именованная запись отказа lease пишется и вне эпика.** Где:
   SPEC.md, требование 3, первый пункт; код — auto.py:682-684.
   - Этот путь общий для любого `auto <id>`, а не только для дочернего.
     Отдельного признака «я дочерний» в нём нет.
   - Значит, запись в журнале появится и у ручного `auto` вне эпика, что
     выходит за ТЗ, «Не входит». Сама по себе запись безвредна: она не
     попадает под префиксы `_operator_actions`.
   - Варианты: (а) принять запись для любого `auto` и сказать об этом в
     SPEC — дефолт; (б) писать её только у дочернего надзора, через признак
     запуска.
3. **М3 — «сейчас не перезапустит» шире перечня в скобках.** Где: SPEC.md,
   требование 6, второй абзац.
   - Пусть первая по `queue_order` — задача эпика после аварии, которая
     ждёт следующего опроса (якорь паузы, требование 4). На этом опросе
     надзор её «сейчас не перезапустит». По букве общего правила очередь
     она не держит, и вторая запустится раньше первой.
   - Дефолт: очередь не держат только категории из скобок; задача на
     паузе аварии очередь держит.

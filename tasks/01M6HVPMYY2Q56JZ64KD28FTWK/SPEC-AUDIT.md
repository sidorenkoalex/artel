## Пути обхода гейтов

- Надзор не вызывает `approve`/`reject`. Гейт, пауза и эскалация задачу не
  перезапускают (требование 12, AC-6). Пути мимо гейта нет.
- Имена новых записей актора `operator` не попадают под перечень и
  префиксы `_operator_actions` (SPEC.md, требование 4; AC-3, AC-4). Записи
  пульта не снимут удержание сами.
- Требование 11: если `answer` при ожидании идёт полным путём `_cmd_answer`,
  рубеж окружения роли сохраняется (answer.py:286-287 для указания;
  `_cmd_answer` — для мандата). Лазейки нет, если исполнитель не пропустит
  этот рубеж, обходя `run_locked`. Это следует из «ведёт себя как без
  цикла», а ревью проверяет.
- `resume` после `stop` (требование 2): рубежа окружения роли у
  `cmd_resume` нет. Но роли уже доступен `epic retry` с тем же эффектом,
  так что новой лазейки нет. К гейтам Оператора это отношения не имеет.
- Буквальное выполнение требования 7 превышает `parallel` (В1). Это не
  обход гейта, а лимита: исполнитель, следующий SPEC.md:176-178, получит
  больше идущих шагов, чем `parallel`, и формально не нарушит SPEC.

## Вердикт

**concerns.** Отклонения по порядку важности.

1. **В1 — самовозобновление ждущих превышает `parallel`.** Где: SPEC.md:169-178
   (требование 7), AC-8 (SPEC.md:330); код — auto.py:204-238.
   - Живой дочерний, который ждёт зону, места не занимает. Механизма
     ожидания места в дочернем нет.
   - Когда зона освобождается, `_wait_for_zone` возвращает `None`, и цикл
     сам идёт к агентному шагу.
   - Сценарий AC-8, случай 1: две задачи ждут зону, `parallel` 2, третья
     запущена. Зона освободилась — идут три агентных шага при `parallel` 2.
   - Возврат № 1, п. 9 требует «parallel не превышается». Возврат № 2, п. 4
     сужает механизм до решения надзора. Противоречие между решениями
     Оператора SPEC не называет.

   Варианты:
   - (а) превышение принимается. Тогда в SPEC и матрице нужна фраза:
     «ждущий зону живой дочерний после освобождения продолжает шаг и может
     превысить `parallel` на число ждавших; новых запусков, пока
     `view.free` ≤ 0, нет»;
   - (б) не превышать. Тогда нужен механизм в дочернем: ожидание места
     после освобождения зоны в `auto.py`. Это противоречит возврату № 2,
     п. 4, и решать Оператору.

   Глобальный лимит не страдает: lease ждущей задачи держит место
   (требование 8).
2. **В2 — состав очереди зоны шире эпика.** Где: SPEC.md:157-163
   (требование 6), AC-7 (SPEC.md:316); код — zone_lock.py:523-548.
   - В очередь входят все `in_dev` задачи проекта с пересекающейся зоной, не
     только задачи эпика.
   - Первой по `queue_order` может оказаться задача вне эпика или другого
     эпика, у которой цикл остановлен потолком. Надзор её не перезапускает
     (SPEC.md, «Не входит»).
   - SPEC не говорит, держит ли такая задача очередь для задачи эпика,
     стоящей второй. Если держит, вторая ждёт до ручного действия, и это
     повторяет факт 2 ТЗ. Если нет — по какому правилу её пропускать.
   - То же для задачи очереди, которая держится по пределу аварий или по
     именованному отказу.

   Дефолт для ответа: правило «`stop`/пауза очередь не держат» расширяется
   на любую задачу очереди, которую этот надзор не перезапустит сейчас.
3. **В3 — `resume` при живом дочернем и чужая причина остановки.** Где:
   SPEC.md:66-67. `resume`, записанный при живом дочернем, засчитан «до
   того, как надзор обнаружил выход». Не сказано, относится ли это только к
   выходу после паузы. Пример: `pause`, затем `resume` при живом дочернем,
   затем дочерний останавливается лимитом шагов, а это остановка вне
   перечня, она держит. По букве SPEC задача перезапустится. Нужна оговорка:
   засчитывается, если первая запись остановки — остановка паузой
   (`config.AUTO_STOP_PAUSE`).
4. **В4 — «подряд» в пределе аварий.** Где: SPEC.md:123, 130-136. Счёт
   сбрасывает только действие из перечня сброса. Не сказано, прерывает ли
   серию промежуточный штатный выход. Пример: авария, перезапуск, штатная
   остановка «CI ветки красный», `ci-rerun` (не в перечне сброса), затем
   две аварии. Это «три подряд» или нет? Дефолт по букве SPEC — три, и
   стоит записать это явно.
5. **Ф1 — мелкое.** SPEC.md:127: ссылка auto.py:1242-1243 указывает на
   докстринг; запись — auto.py:1252-1258.

# QUESTIONS: target-set — запись и снятие ключа поля-отображения локального слоя

## Вопросы

Решения 2 и 3 гейта SPEC противоречий не несут и войдут в SPEC как есть
(AC-8 — неполное и лишнее число аргументов, `TARGET_SET_USAGE`, файл
побайтно прежний; AC-7 — текст отказа с перечнем допустимых полей, файл
побайтно прежний). Остался один вопрос — по решению 1.

Найденное расхождение. Решение 1 требует одновременно: (а) «строка-комментарий
в файле — отказ, файл побайтно прежний» (это же — ТЗ, требование 6: «отказы
прежней формы действуют и для новой … строка-комментарий в файле») и (б)
«комментарий слоя (строка `#` вне записи) после успешной записи `--key` и
`--drop-key` сохранён побайтно». По коду main (75ec08d4) эти два условия
несовместимы: `cmd_target_set` отказывает при любой строке, которую
находит `_comment_line` (`orchestrator/projects.py:424-428`, функция
`:507-527`), а она находит любую строку с `#` первым непробельным
символом — где бы та ни стояла. Опыт (вызов `projects._comment_line` на
вымышленном тексте, без записи файлов): `#` в начале файла → строка 1;
`#` между `targets:` и записью → 2; `#` в хвосте файла после записи → 4;
хвостовой `a: b  # …` → 3; без `#` → `None`. Успешной записи при строке
`#` в файле не бывает, поэтому критерий (б) нельзя ни выполнить, ни
проверить, не сняв отказ (а). Прежний тест закрепляет отказ (а) для
прежней формы: `tests/test_01m6kbd9fc36warwsy9z0jdmg5_target_set.py:284`
(`test_ac3_refusals_leave_file_and_no_copy`, случай со строкой-комментарием
в начале файла).

1. **Как понимать часть решения 1 о сохранности комментария слоя после успешной записи `--key`/`--drop-key`?**
   - A) Снять эту часть: AC-12 проверяет отказ на строке-комментарии (файл побайтно прежний), отказ на недоступном журнале, на проекте артели, на отсутствии записи в локальном слое и отказ новой сверки `--drop-key` на подменённой сборке текста; вместо «комментарий сохранён» — «после успешной записи `--key`/`--drop-key` все строки файла, кроме строк правимого поля, побайтно прежние» (на слое без комментариев).
     - ломается: ничего; формулировка решения 1 о комментарии в SPEC не попадает.
     - ослабляется: ничего — отказ на комментарии держится `orchestrator/projects.py:424-428` и остаётся для новых форм; сохранность прочих строк — свойство, которое тест проверяет на слое без `#`.
     - цена: без изменения бюджета; один круг аудита SPEC.
     - чьё решение: Оператор.
   - B) Сохранять комментарии при новых формах: для `--key`/`--drop-key` отказ на строке `#` вне записи снимается, такая строка переносится в новый текст побайтно; отказ на комментарии остаётся только для прежней формы и для `#` внутри записи.
     - ломается: требование 6 ТЗ («отказы прежней формы действуют и для новой … строка-комментарий в файле») для новых форм перестаёт действовать — нужна правка ТЗ; сборка текста уже не «целиком из разобранного» (`_render`), нужна новая механика переноса строк.
     - ослабляется: гарантия «пересборка не сотрёт комментарий — отказ» (`orchestrator/projects.py:424-428`) для новых форм заменяется механикой переноса, которой сейчас нет; сверка до записи должна учитывать перенесённые строки.
     - цена: заметно больше кода в `orchestrator/projects.py` и тестов; бюджет вероятно выше рамки $30 (до ~$45); риск третьей итерации ревью.
     - чьё решение: Оператор.
   - C) Под «комментарием слоя» имелся в виду не `#`, а что-то иное (например, значение с `#` без пробела перед ним — `a#b`, или `#` внутри кавычек значения), которое `_comment_line` комментарием не считает: AC-12 проверяет, что такая строка после успешной записи `--key`/`--drop-key` побайтно прежняя.
     - ломается: ничего.
     - ослабляется: ничего — правило `_comment_line` (`orchestrator/projects.py:507-527`) не меняется; прежние тесты уже держат его для прежней формы (`tests/test_projects_target_set.py:59`, `tests/test_01m6kbd9fc36warwsy9z0jdmg5_target_set.py:480`).
     - цена: без изменения бюджета.
     - чьё решение: Оператор.
   - дефолт: A — единственный вариант, совместимый с ТЗ (требование 6) и с первой половиной самого решения 1 без новой механики; при молчании AC-12 пишется по A, а C добавляется к нему случаем «значение `a#b` и `\"a # b\"` в другой записи после успешной записи `--key`/`--drop-key` побайтно прежние» (не противоречит ничему и закрывает возможный смысл решения).

# target-set: запись и снятие ключа поля-отображения локального слоя

## Факты

1. Команда `target-set <проект> <путь поля> <значение>` (`orchestrator/projects.py:386`, `cmd_target_set`) правит одно поле записи локального слоя `.artel/targets.yaml`: резервная копия, сборка текста, сверка до записи (`_target_set_mismatches`, `:658`), атомарная запись. Строка формы вызова — `TARGET_SET_USAGE` (`orchestrator/projects.py:370`).
2. Путь поля проверяет `_field_keys` (`orchestrator/projects.py:530-570`): путь во вложенное отображение — отказ «ведёт во вложенное отображение — его поля командой не правятся».
3. Значение разбирается `_argument_value` (`orchestrator/projects.py:583-602`) через `yamlmini` как скаляр или потоковый список; потоковых отображений `{…}` `yamlmini` не разбирает (`orchestrator/yamlmini.py:163-196`), значение `{a: b}` читается строкой.
4. Блочное вложенное отображение запись уже умеет: `_render` (`orchestrator/projects.py:254-274`) пишет `dict` блоком и отказывает ключам с `:`, переводом строки, ведущими `#`, `- `, `[`, кавычками и пробелами по краям.
5. Поле `machine.submodule_tokens` («путь подмодуля верхнего уровня → имя слота связки ключей», константа `SUBMODULE_TOKENS_FIELD`, `orchestrator/targets.py:356`) проверяется функцией `_submodule_tokens_error` (`orchestrator/targets.py:939`); добавлено задачей токенов подмодулей. Задать его командой пульта сейчас нельзя ни значением `{…}`, ни путём `machine.submodule_tokens.<ключ>` — оба отказа выше. Опыт 05.11: обе формы отказаны на внешнем проекте.
6. `_target_set_mismatches` для снятия листа не годится: опыт проверяющего ТЗ 05.11 — на вымышленной записи без листа в новом тексте функция падает `KeyError` на `new_leaves[target]`.

## Требуется

1. **Форма `--key`**: `target-set <проект> <раздел>.<поле> --key <ключ> <значение>` записывает один ключ поля-отображения строк. Допустимые поля — именованный перечень в `orchestrator/projects.py`; сейчас ровно `machine.submodule_tokens`. Поле вне перечня — отказ с перечнем допустимых. Если третий аргумент равен `--key` или `--drop-key`, это всегда новая форма; неверное число аргументов — отказ со строкой `TARGET_SET_USAGE`, файл не записан. Значение, равное строке `--key` или `--drop-key`, прежней формой больше не записывается — это единственное исключение из требования 7.
2. **Ключ дословно**: ключ берётся аргументом целиком, без деления по точке, и может содержать `/` и `.`. Ключ, который `_render` не может записать (п. 4 фактов), — отказ с именем ключа до записи файла.
3. **Значение** — скаляр тем же разбором, что сейчас (`_argument_value`); пустое значение — отказ; значение, которое отказывает `_submodule_tokens_error` при загрузке (число, список), — отказ с текстом этой проверки до записи.
4. **Поле отсутствует** — заводится отображение с одним ключом; ключ есть — значение заменяется; прочие ключи поля и прочие поля записи не меняются.
5. **Форма `--drop-key`**: `target-set <проект> <раздел>.<поле> --drop-key <ключ>` снимает ключ; последний ключ — снимается всё поле; ключа нет — отказ с именем ключа, файл не меняется.
6. **Тот же путь записи**: резервная копия и загрузка записи после правки — как у прежней формы. Для `--key` сверка до записи — `_target_set_mismatches` с ключами пути `[<раздел>, <поле>, <ключ>]`. Для `--drop-key` — новая функция сверки: разобранный текст отличается от прежнего ровно отсутствием листа `targets.<проект>.<раздел>.<поле>.<ключ>`, сведение `targets.merge_local` проходит, прочие записи сводятся как прежде; `_target_set_mismatches` и её поведение для прежней формы не меняются. Строка журнала и вывода: `<раздел>.<поле>[<ключ>]: <было или (нет)> → <значение>`, для `--drop-key` — `<раздел>.<поле>[<ключ>]: <было> → (нет)`. Ключ уже имеет то же значение — «без изменений», копии и записи журнала нет, как у прежней формы. Отказы прежней формы действуют и для новой: проект артели, записи нет в локальном слое, строка-комментарий в файле, журнал недоступен.
7. **Прежние формы не меняются**: `target-set <проект> <путь> <значение>` и отказ «вложенное отображение» для путей вида `machine.submodule_tokens.<ключ>` — побайтно прежние.
8. **Справка**: `TARGET_SET_USAGE` (`orchestrator/projects.py:370`) называет обе новые формы; строка справки `target-set` в `orchestrator/artel.py` — тоже, причём каждая альтернатива после ` | ` начинается словом `target-set`, а строки продолжения — с отступом больше двух пробелов (иначе краснеет `test_ac4_every_command_word_of_help_is_a_registry_key`). `docs/codebase-map.md` — повторной генерацией сценарием `scripts/codebase_map.py`.

Критерии приёмки:
- `--key` на записи без поля заводит `submodule_tokens` с ключами вида `a/b/c` (с косой чертой) и `a.b` (с точкой); `targets.target(<имя>)["submodule_tokens"]` равно ожидаемому отображению; прочие поля записи побайтно прежние;
- `--key` на существующем ключе заменяет значение, другой ключ поля цел;
- `--drop-key` снимает ключ; снятие последнего ключа снимает поле; отсутствующий ключ — отказ, файл побайтно прежний;
- ключ с `:`, с ведущим `#`, с пробелом по краю — отказ с именем ключа, файл не меняется;
- значение `123` или `[a, b]` при `--key` — отказ с текстом проверки `_submodule_tokens_error`, файл побайтно прежний;
- поле вне перечня (`policy.no_paths --key x y`) — отказ с перечнем допустимых полей;
- путь `machine.submodule_tokens.<ключ>` с `--key` — отказ;
- `--key` или `--drop-key` с неполным числом аргументов — отказ со строкой формы вызова;
- пустое значение — отказ;
- резервная копия создаётся при каждой записи `--key`/`--drop-key`; запись журнала — по формату требования 6; повтор того же значения — «без изменений», копии нет;
- прежняя форма `target-set` и отказ пути во вложенное отображение — тексты и поведение прежние (прежние тесты зелёные без правки).

Безопасность тестов: локальный слой и записи — вымышленные во временной песочнице, фикстура `initialized_tmp_root` (`tests.sandbox.InitializedTmpRootTest`); никогда — настоящий `.artel/targets.yaml`; ни имён, ни адресов реальных проектов.

Существующие тесты: правка не должна сделать красным ни один существующий тест; если краснеет — эскалация с именем теста, без правки.

Зоны: `orchestrator/projects.py` (`cmd_target_set`, `_field_keys`, `TARGET_SET_USAGE`, новые функции формы `--key`/`--drop-key` и новая функция сверки снятия ключа), `orchestrator/artel.py` (только строка справки `target-set`), `docs/codebase-map.md` (только генерацией), `tests/` (долгоживущие файлы задачи).

Только чтение: `orchestrator/targets.py`, `orchestrator/yamlmini.py`, `orchestrator/report.py` (одноимённая `_render` отчёта, с `projects._render` не связана), `scripts/codebase_map.py`, `tests/test_projects_target_set.py`, `tests/test_01m6kbd9fc36warwsy9z0jdmg5_target_set.py`, `tests/test_01m6kbd9fc36warwsy9z0jdmg5_doctor_failure_errors.py`, `tests/test_01m6p1z0zhvndywn3fzszwbcg3_submodule_tokens.py`, `tests/test_01m5m0kqpv0fj9nsmdcq3xb76w_help_registry.py`.

- правка полей слоя репозитория;
- правка настоящего локального слоя `.artel/targets.yaml` в тестах и при разработке.

# SPEC: target-set — запись и снятие ключа поля-отображения локального слоя

## Контекст
Команда `target-set <проект> <путь поля> <значение>` (`orchestrator/projects.py:386`,
`cmd_target_set`) правит одно поле записи локального слоя `.artel/targets.yaml`
(резервная копия, сборка текста, сверка `_target_set_mismatches` —
`orchestrator/projects.py:658`, атомарная запись). Поле-отображение
`machine.submodule_tokens` (`orchestrator/targets.py:356`,
`SUBMODULE_TOKENS_FIELD`; проверка `_submodule_tokens_error`,
`orchestrator/targets.py:939`) командой задать нельзя: значение `{…}`
`yamlmini` не разбирает (`orchestrator/yamlmini.py:163-196`), путь
`machine.submodule_tokens.<ключ>` отказывает `_field_keys`
(`orchestrator/projects.py:530-570`) как «вложенное отображение». Запись
блочного отображения `_render` (`orchestrator/projects.py:254-274`) уже
умеет. Сверка `_target_set_mismatches` для снятия листа не годится: на
тексте без листа падает `KeyError` на `new_leaves[target]`. Задача вводит
две новые формы команды — `--key` (запись ключа) и `--drop-key` (снятие
ключа) — для именованного перечня полей-отображений.

## Требования

1. **Форма `--key`.** `target-set <проект> <раздел>.<поле> --key <ключ> <значение>`
   записывает один ключ поля-отображения строк. Допустимые поля —
   именованный перечень в `orchestrator/projects.py`; сейчас в нём ровно
   `machine.submodule_tokens`. Поле вне перечня — отказ с перечнем
   допустимых полей. Если третий аргумент команды (после проекта и пути)
   равен `--key` или `--drop-key`, это всегда новая форма; неверное число
   аргументов новой формы — отказ со строкой `TARGET_SET_USAGE`, файл не
   записан. Значение, равное строке `--key` или `--drop-key`, прежней
   формой больше не записывается — это единственное исключение из
   требования 7.
2. **Ключ дословно.** Ключ берётся аргументом целиком, без деления по
   точке, и может содержать `/` и `.`. Ключ, который `_render` не может
   записать (`:`, перевод строки, ведущие `#`, `- `, `[`, кавычки, пробелы
   по краям), — отказ с именем ключа до записи файла.
3. **Значение** — скаляр тем же разбором, что у прежней формы
   (`_argument_value`); пустое значение — отказ; значение, которое
   отказывает `_submodule_tokens_error` при загрузке (число, список), —
   отказ с текстом этой проверки до записи файла.
4. **Поле отсутствует** — заводится отображение с одним ключом; ключ есть —
   значение заменяется; прочие ключи поля и прочие поля записи не
   меняются.
5. **Форма `--drop-key`.** `target-set <проект> <раздел>.<поле> --drop-key <ключ>`
   снимает ключ; снят последний ключ — снимается всё поле; ключа нет —
   отказ с именем ключа, файл не меняется.
6. **Тот же путь записи.** Резервная копия и загрузка записи после правки —
   как у прежней формы. Для `--key` сверка до записи —
   `_target_set_mismatches` с ключами пути `[<раздел>, <поле>, <ключ>]`.
   Для `--drop-key` — новая функция сверки: разобранный новый текст
   отличается от прежнего ровно отсутствием листа
   `targets.<проект>.<раздел>.<поле>.<ключ>`, сведение `targets.merge_local`
   проходит, прочие записи сводятся как прежде; `_target_set_mismatches` и
   её поведение для прежней формы не меняются. Строка журнала и вывода:
   `<раздел>.<поле>[<ключ>]: <было или (нет)> → <значение>`, для
   `--drop-key` — `<раздел>.<поле>[<ключ>]: <было> → (нет)`. Ключ уже имеет
   то же значение — «без изменений», резервной копии и записи журнала нет,
   как у прежней формы. Отказы прежней формы действуют и для новых: проект
   артели, записи нет в локальном слое, строка-комментарий в файле,
   журнал недоступен.
7. **Прежние формы не меняются.** `target-set <проект> <путь> <значение>` и
   отказ «вложенное отображение» для путей вида
   `machine.submodule_tokens.<ключ>` — побайтно прежние (с единственным
   исключением из требования 1).
8. **Справка.** `TARGET_SET_USAGE` (`orchestrator/projects.py:370`) называет
   обе новые формы; строка справки `target-set` в `orchestrator/artel.py`
   (около строки 197) — тоже, причём каждая альтернатива после ` | `
   начинается словом `target-set`, а строки продолжения — с отступом
   больше двух пробелов (иначе краснеет
   `test_ac4_every_command_word_of_help_is_a_registry_key`).
   `docs/codebase-map.md` обновляется только повторной генерацией
   `scripts/codebase_map.py`.
9. **Безопасность тестов.** Локальный слой и записи в тестах — вымышленные
   во временной песочнице, фикстура `initialized_tmp_root`
   (`tests.sandbox.InitializedTmpRootTest`); никогда — настоящий
   `.artel/targets.yaml`; ни имён, ни адресов реальных проектов.

## Критерии приёмки

AC-1. `--key` на записи без поля `submodule_tokens` заводит его с ключами вида `a/b/c` (с косой чертой) и `a.b` (с точкой); `targets.target(<имя>)["submodule_tokens"]` равно ожидаемому отображению; прочие поля записи побайтно прежние.

AC-2. `--key` на существующем ключе заменяет его значение, другой ключ поля цел.

AC-3. `--drop-key` снимает ключ; снятие последнего ключа снимает поле целиком; отсутствующий ключ — отказ с именем ключа, файл побайтно прежний.

AC-4. Ключ с `:`, с ведущим `#`, с пробелом по краю при `--key` — отказ с именем ключа, файл не меняется.

AC-5. Значение `123` или `[a, b]` при `--key` — отказ с текстом проверки `_submodule_tokens_error`, файл побайтно прежний.

AC-6. Поле вне перечня (`policy.no_paths --key x y`) — отказ с перечнем допустимых полей.

AC-7. Путь `machine.submodule_tokens.<ключ>` с `--key` — отказ, текст которого несёт перечень допустимых полей (`machine.submodule_tokens`); файл побайтно прежний.

AC-8. `--key` или `--drop-key` с неверным числом аргументов — и неполным (`--key <ключ>` без значения, `--drop-key` без ключа), и лишним (`--key <ключ> <значение> <лишний>`, `--drop-key <ключ> <лишний>`) — отказ, текст которого несёт строку формы вызова `TARGET_SET_USAGE`; файл побайтно прежний.

AC-9. Пустое значение при `--key` — отказ.

AC-10. Резервная копия создаётся при каждой записи `--key`/`--drop-key`; запись журнала и вывода — по формату требования 6 (`<раздел>.<поле>[<ключ>]: <было или (нет)> → <значение>`, для снятия — `… → (нет)`); повтор того же значения — «без изменений», резервной копии и записи журнала нет.

AC-11. Прежняя форма `target-set <проект> <путь> <значение>` и отказ пути во вложенное отображение (`machine.submodule_tokens.<ключ>` прежней формой) — тексты и поведение прежние.

AC-12. Отказы прежней формы действуют для `--key` и `--drop-key` (требование 6): строка-комментарий (`#` первым непробельным символом) в файле локального слоя, недоступный журнал, проект артели, отсутствие записи проекта в локальном слое — отказ, файл побайтно прежний, резервной копии нет. Если собранный новый текст отличается от прежнего не только отсутствием снимаемого листа (в тесте — подменённая сборка текста), `--drop-key` отказывает новой сверкой, файл побайтно прежний. После успешной записи `--key` и `--drop-key` на слое без строк `#` все строки файла, кроме строк правимого поля, побайтно прежние; значения `a#b` и `"a # b"` в другой записи слоя после успешной записи `--key`/`--drop-key` побайтно прежние.

модуль (`orchestrator/projects.py`) плюс одна строка справки
(`orchestrator/artel.py`) и регенерация карты. Разбор новой формы, перечень
полей, проверка ключа, сверка снятия и `TARGET_SET_USAGE` живут в одной
функции `cmd_target_set` и её помощниках; строка справки в `artel.py`
обязана совпадать по составу форм с `TARGET_SET_USAGE` (требование 8) и
без самой формы смысла не имеет. Разрезы по `--key`/`--drop-key` пришлись
бы поперёк одной зоны (`orchestrator/projects.py`) и дали бы две задачи,
правящие один и тот же разбор аргументов, — последовательный мерж без
выигрыша. Критериев много потому, что ТЗ перечисляет отказы по одному;
объём кода невелик.

# SPEC: Мандат Оператора на расширение зон доходит до коммита пульта

## Контекст
Коммит пульта за роль (автокоммит после шага developer, WIP-чекпоинты,
чекпоинт перед подтяжкой main) фильтрует застейдженные пути по зонам задачи
через `orchestrator/checkpoint.py::_zone_paths` — а тот читает только
`zones`, `zones_extension`, `config.COMMON_ZONES` и `tasks/<id>/`. Мандат
Оператора «Расширение зон разрешено: …» из `ANSWER-n.md` читает только гейт
зон (`orchestrator/advance_gates/zones.py::_answer_zones_mandate`). Итог —
расхождение: файл по мандату снимается со стейджа как «посторонние файлы в
worktree», гейт зон его в диффе не видит и пропускает переход, ревью
возвращает задачу (прецедент 04.10, мандат на `docs/operator-session.md`;
также 30.09 и 02.10) — лишние шаги developer и reviewer.

## Требования
1. Все места, фильтрующие пути коммита пульта по зонам задачи, считают
   путь, покрытый мандатом Оператора «Расширение зон разрешено» из
   `ANSWER-n.md` задачи, своим: автокоммит после шага developer
   (`commit_success_checkpoint` → `_commit_worktree_change`), WIP-чекпоинты
   после таймаута, аварийного завершения и `pause --now`, чекпоинт перед
   подтяжкой main (`commit_pull_checkpoint` и отказ «посторонние файлы в
   worktree — решение Оператора» в `orchestrator/pull.py`),
   `restore_out_of_bounds_deletions`, `pult_commit_failed_paths`.
2. Источник мандатов для этих мест — тот же, что у гейта зон: все
   `ANSWER-*.md` артефактной ветки задачи, с тем же правилом исключения
   ANSWER, последний коммит которого — автокоммит шага роли. Источник один:
   общий узел, который используют и гейт зон, и коммит пульта, а не копия
   разбора.
3. Гейт зон и коммит пульта не расходятся: путь, который гейт зон признал
   бы покрытым мандатом, коммит пульта не снимает; путь без мандата
   снимается (или, для чекпоинта перед подтяжкой, ведёт к отказу), как
   сейчас.
4. Требование раздела «## Расширение зон» в PLAN.md для перехода
   `in_dev -> review` сохраняется — гейт зон не ослабляется: если раздела
   нет, а файл по мандату закоммичен, переход получает прежний отказ «мандат
   есть, раздел PLAN не оформлен».
5. Запись журнала автокоммита называет пути, принятые по мандату, отдельно
   от путей зон.
6. Сценарии критериев AC-1–AC-5 покрыты тестами в `tests/` с заявками
   «Ловит мутацию». Долгоживущие приёмочные тесты автора тестов
   (`tests/test_<id>_*.py`) это требование закрывают — повторять то же
   свойство отдельным тестом не нужно.

## Критерии приёмки
AC-1. Задача с заявленными зонами и `ANSWER-n.md`, закоммиченным командой
`answer` и несущим строку «Расширение зон разрешено: <путь>»: файл
`<путь>` вне зон, изменённый в worktree шагом developer, попадает в коммит
автокоммита пульта после шага и не попадает в запись «посторонние файлы в
worktree».

AC-2. Та же задача без мандата на `<путь>` (ANSWER нет либо мандат на
другой путь): файл вне зон снимается со стейджа автокоммита и называется в
записи «посторонние файлы в worktree», как до изменения.

AC-3. `ANSWER-n.md` с той же строкой мандата, последний коммит которого —
автокоммит шага роли («<id>: артефакты шага …»), мандатом не считается:
файл вне зон снимается со стейджа автокоммита, как в AC-2.

AC-4. WIP-чекпоинт после таймаута шага ведёт себя так же: с мандатом из
ANSWER Оператора файл вне зон коммитится; без мандата и при ANSWER,
закоммиченном автокоммитом роли, — снимается со стейджа.

AC-5. Чекпоинт перед подтяжкой main ведёт себя так же: файл вне зон,
покрытый мандатом из ANSWER Оператора, не считается посторонним — отказа
«посторонние файлы в worktree — решение Оператора» нет, файл коммитится;
без мандата и при ANSWER, закоммиченном автокоммитом роли, — прежний отказ
перехода.

AC-6. Остальные места требования 1 — WIP-чекпоинты аварийного завершения
и `pause --now`, `restore_out_of_bounds_deletions`,
`pult_commit_failed_paths` — считают путь, покрытый мандатом из ANSWER
Оператора, путём зон задачи, а путь без мандата — вне зон, как сейчас.

AC-7. Для одного и того же состояния артефактной ветки (набор ANSWER и их
коммиты) множество путей мандата, которым пользуется гейт зон, и множество,
которым пользуется коммит пульта, совпадают: путь, признанный гейтом зон
покрытым мандатом, коммит пульта не снимает, и наоборот.

AC-8. Файл вне зон, закоммиченный автокоммитом по мандату, при отсутствии
раздела «## Расширение зон» в PLAN.md даёт на `advance` из `in_dev` прежний
отказ гейта зон «мандат есть, раздел PLAN не оформлен»
(`ZONES_MANDATE_WITHOUT_PLAN_REFUSAL_ACTION`); с разделом, совпадающим с
мандатом, переход проходит.

AC-9. Запись журнала автокоммита, принявшего хотя бы один путь по мандату,
называет такие пути отдельно от путей зон (по ней видно, какие файлы
вошли в коммит именно по мандату Оператора).

## Оценка объёма и деление
Сработавший сигнал: `budget_usd` ≥ $30 (рамка Оператора в ТЗ — $30).

Решение — монолит; материал для Оператора:
- Ядро задачи — один общий узел чтения мандатов, на который одновременно
  переводятся гейт зон и фильтр коммита пульта (требование 2: «источник
  один»). Часть «только узел + гейт зон» ничего не меняет в поведении и
  не закрывает прецедент; часть «только коммит пульта» без общего узла —
  копия разбора, прямо запрещённая ТЗ.
- Все места фильтра (требование 1) делят один `_zone_paths` в
  `orchestrator/checkpoint.py`: перевод части из них оставил бы систему с
  тем самым расхождением, которое задача устраняет (например, автокоммит
  принимает файл по мандату, а чекпоинт перед подтяжкой отказывает на нём
  переходу).
- Объём по зонам — `orchestrator/checkpoint.py`,
  `orchestrator/advance_gates/zones.py` (или `mandate.py`), возможно
  `orchestrator/pull.py`, плюс тесты; 9 критериев.

## Не входит
- Правило о разделе «## Расширение зон» PLAN в скиле разработчика — скилы
  правит Оператор отдельно (из ТЗ).
- Запись `zones_extension` командой `answer` (из ТЗ).
- Изменение формата мандата «Расширение зон разрешено: …» (из ТЗ).
- Ослабление гейта зон, в том числе безусловного отказа на защищённых
  путях: мандат на расширение зон по-прежнему не мандат на правку
  защищённого пути.
- Правка путей «только чтение» из ТЗ: docs/adr/, docs/roadmap.md,
  docs/backlog.md, docs/operator-session.md, templates/, skills/,
  CLAUDE.md, models.yaml, roles.yaml, scripts/guard.py,
  .github/workflows/ci.yml, conftest.py, tests/test_invariants.py,
  docs/invariants.md.
- «Существующие тесты не ослабляются» — её держит пульт (гейт
  неослабления тестов и зелёный полный набор `tests/`).

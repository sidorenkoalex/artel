# SPEC: G3а-1б — мандат на ослабление по идентификатору теста: маркер, запись ответа, матрица неослабления, независимая проверка

## Контекст
Вторая часть G3а-1 волны G по ADR-0026 (`docs/adr/0026-project-components-and-outcome-gates.md`, «Решение» п. 3 — элемент мандата: идентификатор теста компонента или путь файла; п. 6 — гейт неослабления по исходам). G3а-1а (смержена fe751fae) дала гейт исходов и мандат на файл и на `путь::имя`. Сейчас находку гейта исходов по конкретному тесту компонента (например, тест Vitest с пробелами, « > » и запятыми в имени) снять мандатом нельзя: прежний маркер `Ослабление тестов разрешено:` (`orchestrator/advance_gates/mandate.py:38`) делит строку по запятым, а пробел, двоеточие и « > » отклоняет (`mandate.py:223`, `refusals`).

Граница задачи одной фразой: новый маркер действует только на находки гейта исходов (компонент записи `components:` с полем `report`); прежние маркеры, их разбор, проверка, матрица и покрытие находок гейта по тексту, а у артели и при профиле без компонентов — и правила ячеек матрицы, остаются прежними побайтно.

## Требования

1. **Маркер.** Вводится маркер «Ослабление теста по идентификатору разрешено:» — ровно один идентификатор на строку: элемент — остаток строки после маркера со срезом пробелов по краям строки (как у `elements`, `mandate.py:73`), без деления по запятым. Разбор — отдельной функцией в `orchestrator/advance_gates/mandate.py`; прежний маркер `TEST_WEAKENING_MANDATE_MARKER` и функция `elements` не меняются. `refusals` (`mandate.py`), `_matrix_mandate_elements` и `_has_mandate_lines` (`orchestrator/answer.py`) и проверка чужих строк в файле матрицы `zones-extend` (`answer.py`, `_zones_extend_matrix`) обрабатывают новый маркер этой функцией; строка нового маркера в файле матрицы `zones-extend` — отказ, как строки прежних маркеров.
2. **Проверка при записи ответа.** Идентификатор нового маркера разбирается `parse_test_id` (`orchestrator/project_profile.py`); граница — `in_outcome_bounds` (`orchestrator/advance_gates/acceptance.py:213`) профиля решения задачи (`decide`), как правило прежнего мандата (`mandate.py:160-167`): идентификатор принимается только для компонента записи `components:` с полем `report`; у записи `test_profile` (в том числе `pytest-own` с `report`) — отказ; путь идентификатора — в области `weakening_scope` этого компонента. Идентификатор с обратной кавычкой или с «|» — отказ с причиной «такой тест покрывается мандатом на путь файла». Любое другое невыполненное условие (неразборчивый идентификатор, компонента нет в записи `components:`, нет `report`, запись `test_profile`, путь вне `weakening_scope`) — тоже отказ записи ответа. При любом отказе ANSWER не создаётся.
3. **Состояния и путь записи.** Новый маркер входит в `_has_mandate_lines`: файл с его строкой указанием (`_instruction_text`) не считается и идёт путём мандата под блокировкой задачи. Строка нового маркера принимается в `in_dev` и прочих состояниях инструкций, в `escalated` и на гейте SPEC (`_spec_gate_answer_text` принимает и строку нового маркера, не только прежний маркер тестов). Строка только с новым маркером — достаточное основание ответа в `in_dev`. Журнал приёма — отдельный вид в строке видов мандата действия «ANSWER создан (…)» (`kinds`, `answer.py:420-431`), рядом с прежними видами через «; »: текст «мандат на ослабление теста по идентификатору: «…»», каждый идентификатор в «»; вид прежнего маркера («мандат на ослабление тестов: …») его не включает. Вид нового маркера пишется в тех же состояниях, что прежний вид мандата тестов: в состояниях инструкций (`INSTRUCTION_STATES`, в том числе `in_dev`) и на гейте SPEC (`answer.py:386`, `:408`); в `escalated` — как прежний вид (сегодня прежний вид тестов там не пишется, `answer.py:374-376`).
4. **Матрица и независимая проверка.** Новый маркер входит в `MATRIX_MANDATE_MARKERS` (`mandate.py`, через функцию разбора требования 1) и в `_MANDATE_MARKERS` аудита SPEC (`orchestrator/advance_gates/spec_audit.py`). При строке нового маркера строка «Независимая проверка: <вердикт>» обязательна. Ячейка «Что меняется» для элемента нового маркера называет идентификатор целиком между парой одинарных обратных кавычек; сверка содержимого — побайтно. Ячейка «Чем покрыто после» при профиле компонента в границе гейта исходов (`in_outcome_bounds`, требование 2) признаёт, сверх прежнего правила, также:
   - идентификатор теста — стоящий между парой одинарных обратных кавычек, разбираемый `parse_test_id`, компонент идентификатора равен компоненту профиля (`profile.component`), путь идентификатора — в `weakening_scope` профиля;
   - путь — любой файл (расширение любое) в `weakening_scope` компонента, между парой одинарных обратных кавычек или отдельным токеном.
   Идентификатор в ячейке без пары обратных кавычек, неразборчивый, чужого компонента или с путём вне `weakening_scope`, как и путь вне `weakening_scope`, покрытием по этим правилам не признаётся. У артели и при профиле `None` решение по ячейке «Чем покрыто после» совпадает с прежним `_covered` (`mandate.py:402-417`) побайтно: идентификатор теста без пути `tests/…py` в ячейке — отказ, как и раньше. При непустом профиле вне границы `in_outcome_bounds` — запись `test_profile` (в том числе `pytest-own` с `report`) и компонент без `report` — правило «Чем покрыто после» прежнее (`_PY_PATH_RE`, `mandate.py:414-417`): идентификатор теста в ячейке покрытием не признаётся.
5. **Покрытие в гейте исходов.** В `orchestrator/advance_gates/outcome_integrity.py` — собственная функция сбора мандата: тот же перебор `ANSWER-n.md` ссылки документов, отбраковка через `zones._answer_commit_is_role_step_autocommit` (импорт; `zones.py` не правится). Элементы нового маркера — отдельный набор; находку они покрывают только точным равенством идентификатора (с `#n`), префиксное правило к ним не применяется. Подсказка отказа гейта исходов — своя, называет оба маркера (прежний и новый). `orchestrator/advance_gates/test_integrity.py` не меняется.
6. **Тесты** детерминированы и покрывают перечень критериев приёмки ниже; прежние тесты мандата, матрицы и `zones-extend` — без правок и зелёные.

## Критерии приёмки

AC-1. Запись ответа со строкой «Ослабление теста по идентификатору разрешено:» и идентификатором теста Vitest компонента записи `components:` с `report`, путь в `weakening_scope`, имя которого содержит пробел внутри, « > » и запятую, — принята; элемент — весь остаток строки после маркера со срезом пробелов по краям строки, не разделённый по запятым.

AC-2. Запись ответа с новым маркером и идентификатором теста pytest компонента записи `components:` с `report`, путь в `weakening_scope`, — принята.

AC-3. Запись ответа с новым маркером отказана, ANSWER не создан, для каждого случая: идентификатор не разбирается `parse_test_id`; компонента нет в записи `components:` проекта; компонент без поля `report`; профиль задачи — запись `test_profile` (в том числе `pytest-own` с `report`); путь вне `weakening_scope` компонента.

AC-4. Запись ответа с новым маркером и идентификатором, содержащим обратную кавычку или «|», отказана с причиной «такой тест покрывается мандатом на путь файла»; ANSWER не создан.

AC-5. Ответ в `in_dev`, содержащий только строку нового маркера без матрицы неослабления, — отказ, ANSWER не создан (файл не принят как указание).

AC-6. Ответ в `in_dev` со строкой нового маркера с идентификатором теста Vitest, имя которого содержит пробел внутри и « > », матрицей неослабления (ячейка «Что меняется» называет идентификатор целиком в одинарных обратных кавычках) и строкой «Независимая проверка: <вердикт>» — принят; ANSWER создан; журнальная запись приёма «ANSWER создан (…)» содержит отдельный вид «мандат на ослабление теста по идентификатору: «<идентификатор>»», не входящий в вид «мандат на ослабление тестов:».

AC-7. Ответ со строкой нового маркера и матрицей, но без строки «Независимая проверка:», — отказ, ANSWER не создан.

AC-8. Файл матрицы `zones-extend`, содержащий строку нового маркера, — отказ, как для строк прежних маркеров.

AC-9. Ответ на гейте SPEC, содержащий строку нового маркера (без прежнего маркера тестов), — принят; журнальная запись приёма «ANSWER создан (…)» содержит отдельный вид «мандат на ослабление теста по идентификатору: «<идентификатор>»», не входящий в вид «мандат на ослабление тестов:».

AC-10. Строка нового маркера в `ANSWER-n.md` задачи — сигнал аудита SPEC «б) мандат в ANSWER».

AC-11. ANSWER с мандатом нового маркера, закоммиченный автокоммитом шага роли, находку гейта исходов не снимает.

AC-12. Находка гейта исходов по тесту с `#n` снята мандатом нового маркера с тем же идентификатором (с `#n`) и не снята мандатом нового маркера на другой вариант того же теста (другой `#n` или без `#n`).

AC-13. Отказ гейта исходов с непокрытой находкой называет в подсказке оба маркера: «Ослабление тестов разрешено:» и «Ослабление теста по идентификатору разрешено:».

AC-14. Ячейка «Чем покрыто после» матрицы неослабления у артели и при профиле `None`: решение совпадает с прежним `_covered` (`mandate.py:402-417`) побайтно — ячейка с идентификатором теста без пути `tests/…py` (например, Vitest-идентификатор `web:src/a.test.ts::…` в одинарных обратных кавычках) отказана, ANSWER не создан; ячейка, которую прежний `_covered` принимал (например, с `tests/test_a.py`), принята, как и раньше.

AC-15. Ячейка «Что меняется» матрицы неослабления при строке нового маркера: идентификатор не назван, назван без пары одинарных обратных кавычек или отличается от элемента хоть одним байтом — отказ, ANSWER не создан.

AC-16. Ответ на гейте SPEC со строкой нового маркера отказан, ANSWER не создан, для каждого случая: нет матрицы неослабления; нет строки «Независимая проверка:»; идентификатор не разбирается `parse_test_id`.

AC-17. При профиле компонента в границе гейта исходов ячейка «Чем покрыто после», несущая только идентификатор теста между парой одинарных обратных кавычек, который разбирается `parse_test_id`, с компонентом профиля (`profile.component`) и путём в `weakening_scope`, — принята (в том числе Vitest-идентификатор с пробелом внутри и « > »). Та же ячейка отказана, ANSWER не создан, для каждого случая: идентификатор без пары одинарных обратных кавычек; идентификатор в кавычках не разбирается `parse_test_id`; компонент идентификатора не равен компоненту профиля; путь идентификатора вне `weakening_scope`.

AC-18. При профиле компонента в границе гейта исходов ячейка «Чем покрыто после», несущая только путь файла не `*.py` (например, `src/a.test.ts`) в `weakening_scope` компонента, — принята; та же ячейка с путём вне `weakening_scope` — отказана, ANSWER не создан.

AC-19. При непустом профиле вне границы гейта исходов (`in_outcome_bounds`) — для каждого случая: запись `test_profile`; запись `test_profile` `pytest-own` с `report`; компонент записи `components:` без `report` — ячейка «Чем покрыто после», несущая только идентификатор теста между парой одинарных обратных кавычек (без пути `*.py`), отказана, ANSWER не создан: правило ячейки прежнее (`_PY_PATH_RE`, `mandate.py:414-417`).

## Оценка объёма и деление

Сработавшие сигналы: число файлов зоны — 5 (четыре модуля и `tests/`); число критериев приёмки — 19 (≥ 10; AC-14…AC-16 дописаны решением Оператора на гейте SPEC №1, О-1; AC-17, AC-18 — решением на гейте SPEC №2, Н-2; AC-19 — решением на гейте SPEC №3, П-1); `budget_usd` — 35 (≥ $30).

**Обоснование монолита** (материал для решения Оператора; задача уже — вторая часть деления G3а-1 по решению Оператора 20.10). Маркер (требование 1), его проверка при записи (2), путь записи (3), матрица и независимая проверка (4) и покрытие в гейте исходов (5) — одна атомарная смена механики мандата:
- маркер без проверки при записи и без обязательной матрицы с независимой проверкой (2–4) дал бы канал ослабления в обход ADR-0022 — промежуточное состояние ослабляет инвариант;
- маркер, принимаемый при записи, но не покрывающий находку гейта исходов (5), бесполезен: ANSWER создаётся, а гейт всё равно отказывает;
- покрытие в гейте (5) без маркера не имеет входа.
Каждая часть по отдельности либо ослабляет защиту, либо не меняет поведения, поэтому самостоятельно не мержима.

## Не входит

- Гейт мержа по исходам, пакет ревьювера (`orchestrator/review.py`), `orchestrator/fsm_merge_gate.py` и прочее G3а-2.
- Мандат по идентификатору для гейта по тексту (слой python-ast покрывается прежним маркером `Ослабление тестов разрешено:`).
- Шаблоны `templates/` (документ ANSWER строит сама команда `answer`).
- Документ `docs/operator-gates.md` о новом маркере (G5).
- Правка `orchestrator/advance_gates/test_integrity.py`, `orchestrator/advance_gates/zones.py`, `orchestrator/project_profile.py`, `orchestrator/targets.py`, `orchestrator/reporters/pult_vitest_reporter.js`, `docs/adr/0026-project-components-and-outcome-gates.md` — только чтение.
- Смена подписей `elements`, `refusals`, `test_id`, `parse_test_id` и одноимённых `_names`, `_row_cells` и их вызывающих (`orchestrator/merge_after.py`, `orchestrator/catalog.py`, `orchestrator/tz_check.py`, `orchestrator/doctor/project_checks.py`, `orchestrator/stack.py`, `orchestrator/notes.py`, `orchestrator/reporters/outcome.py`, `orchestrator/acceptance.py`, `orchestrator/advance_gates/acceptance.py`, `orchestrator/advance_gates/two_sided.py`) — только чтение.
- Изменение поведения прежних маркеров, их разбора, проверки, матрицы и покрытия находок гейта по тексту; у артели и при профиле без компонентов — правил ячеек матрицы.
- Мандат по идентификатору на тест, чьё имя начинается или кончается пробелом: при построчном разборе и срезе пробелов по краям строки такой идентификатор необнаружим — его покрывает мандат на путь файла прежним маркером `Ослабление тестов разрешено:`.
- Зелёный полный набор `tests/` (в том числе прежние тесты мандата, матрицы и `zones-extend` без правок) — её держит пульт.

# SPEC: G3а-1б — мандат на ослабление по идентификатору теста: маркер, запись ответа, матрица неослабления, независимая проверка

## Контекст
Вторая часть G3а-1 волны G по ADR-0026 (`docs/adr/0026-project-components-and-outcome-gates.md`, «Решение» п. 3 — элемент мандата: идентификатор теста компонента или путь файла; п. 6 — гейт неослабления по исходам). G3а-1а (смержена fe751fae) дала гейт исходов и мандат на файл и на `путь::имя`. Сейчас находку гейта исходов по конкретному тесту компонента (например, тест Vitest с пробелами, « > » и запятыми в имени) снять мандатом нельзя: прежний маркер `Ослабление тестов разрешено:` (`orchestrator/advance_gates/mandate.py:38`) делит строку по запятым, а пробел, двоеточие и « > » отклоняет (`mandate.py:223`, `refusals`).

Граница задачи одной фразой: новый маркер действует только на находки гейта исходов (компонент записи `components:` с полем `report`); прежние маркеры, их разбор, проверка, матрица и покрытие находок гейта по тексту, а у артели и при профиле без компонентов — и правила ячеек матрицы, остаются прежними побайтно.

## Требования

1. **Маркер.** Вводится маркер «Ослабление теста по идентификатору разрешено:» — ровно один идентификатор на строку: элемент — остаток строки после маркера дословно, без деления по запятым. Разбор — отдельной функцией в `orchestrator/advance_gates/mandate.py`; прежний маркер `TEST_WEAKENING_MANDATE_MARKER` и функция `elements` не меняются. `refusals` (`mandate.py`), `_matrix_mandate_elements` и `_has_mandate_lines` (`orchestrator/answer.py`) и проверка чужих строк в файле матрицы `zones-extend` (`answer.py`, `_zones_extend_matrix`) обрабатывают новый маркер этой функцией; строка нового маркера в файле матрицы `zones-extend` — отказ, как строки прежних маркеров.
2. **Проверка при записи ответа.** Идентификатор нового маркера разбирается `parse_test_id` (`orchestrator/project_profile.py`); компонент идентификатора есть в записи проекта и имеет поле `report`; путь идентификатора — в области `weakening_scope` этого компонента. Идентификатор с обратной кавычкой, с «|», с пробелом по краям имени или с переводом строки — отказ с причиной «такой тест покрывается мандатом на путь файла». Любое другое невыполненное условие (неразборчивый идентификатор, компонента нет, нет `report`, путь вне `weakening_scope`) — тоже отказ записи ответа. При любом отказе ANSWER не создаётся.
3. **Состояния и путь записи.** Новый маркер входит в `_has_mandate_lines`: файл с его строкой указанием (`_instruction_text`) не считается и идёт путём мандата под блокировкой задачи. Строка нового маркера принимается в `in_dev` и прочих состояниях инструкций, в `escalated` и на гейте SPEC (`_spec_gate_answer_text` принимает и строку нового маркера, не только прежний маркер тестов). Строка только с новым маркером — достаточное основание ответа в `in_dev`. Журнал приёма — отдельная запись «мандат на ослабление теста по идентификатору:», каждый идентификатор в «».
4. **Матрица и независимая проверка.** Новый маркер входит в `MATRIX_MANDATE_MARKERS` (`mandate.py`, через функцию разбора требования 1) и в `_MANDATE_MARKERS` аудита SPEC (`orchestrator/advance_gates/spec_audit.py`). При строке нового маркера строка «Независимая проверка: <вердикт>» обязательна. Ячейка «Что меняется» для элемента нового маркера называет идентификатор целиком между парой одинарных обратных кавычек; сверка содержимого — побайтно. Ячейка «Чем покрыто после» признаёт также идентификатор теста или путь в области `weakening_scope` компонента — только при профиле компонента с `report`; у артели и при профиле `None` — прежнее правило (`_covered`, `mandate.py:402`) побайтно.
5. **Покрытие в гейте исходов.** В `orchestrator/advance_gates/outcome_integrity.py` — собственная функция сбора мандата: тот же перебор `ANSWER-n.md` ссылки документов, отбраковка через `zones._answer_commit_is_role_step_autocommit` (импорт; `zones.py` не правится). Элементы нового маркера — отдельный набор; находку они покрывают только точным равенством идентификатора (с `#n`), префиксное правило к ним не применяется. Подсказка отказа гейта исходов — своя, называет оба маркера (прежний и новый). `orchestrator/advance_gates/test_integrity.py` не меняется.
6. **Тесты** детерминированы и покрывают перечень критериев приёмки ниже; прежние тесты мандата, матрицы и `zones-extend` — без правок и зелёные.

## Критерии приёмки

AC-1. Запись ответа со строкой «Ослабление теста по идентификатору разрешено:» и идентификатором теста Vitest компонента с `report`, путь в `weakening_scope`, имя которого содержит пробел внутри, « > » и запятую, — принята; элемент — весь остаток строки, не разделённый по запятым.

AC-2. Запись ответа с новым маркером и идентификатором теста pytest компонента с `report`, путь в `weakening_scope`, — принята.

AC-3. Запись ответа с новым маркером отказана, ANSWER не создан, для каждого случая: идентификатор не разбирается `parse_test_id`; компонента нет в записи проекта; компонент без поля `report`; путь вне `weakening_scope` компонента.

AC-4. Запись ответа с новым маркером и идентификатором, содержащим обратную кавычку, «|» или пробел по краям имени, отказана с причиной «такой тест покрывается мандатом на путь файла»; ANSWER не создан.

AC-5. Ответ в `in_dev`, содержащий только строку нового маркера без матрицы неослабления, — отказ, ANSWER не создан (файл не принят как указание).

AC-6. Ответ в `in_dev` со строкой нового маркера, матрицей неослабления (ячейка «Что меняется» называет идентификатор целиком в одинарных обратных кавычках) и строкой «Независимая проверка: <вердикт>» — принят; ANSWER создан; журнал содержит запись «мандат на ослабление теста по идентификатору:» с идентификатором в «».

AC-7. Ответ со строкой нового маркера и матрицей, но без строки «Независимая проверка:», — отказ, ANSWER не создан.

AC-8. Файл матрицы `zones-extend`, содержащий строку нового маркера, — отказ, как для строк прежних маркеров.

AC-9. Ответ на гейте SPEC, содержащий строку нового маркера (без прежнего маркера тестов), — принят.

AC-10. Строка нового маркера в документе задачи распознаётся аудитом SPEC как маркер мандата (`_MANDATE_MARKERS`).

AC-11. ANSWER с мандатом нового маркера, закоммиченный автокоммитом шага роли, находку гейта исходов не снимает.

AC-12. Находка гейта исходов по тесту с `#n` снята мандатом нового маркера с тем же идентификатором (с `#n`) и не снята мандатом нового маркера на другой вариант того же теста (другой `#n` или без `#n`).

AC-13. Отказ гейта исходов с непокрытой находкой называет в подсказке оба маркера: «Ослабление тестов разрешено:» и «Ослабление теста по идентификатору разрешено:».

## Оценка объёма и деление

Сработавшие сигналы: число файлов зоны — 5 (четыре модуля и `tests/`); число критериев приёмки — 13 (≥ 10); `budget_usd` — 35 (≥ $30).

**Обоснование монолита** (материал для решения Оператора; задача уже — вторая часть деления G3а-1 по решению Оператора 20.10). Маркер (требование 1), его проверка при записи (2), путь записи (3), матрица и независимая проверка (4) и покрытие в гейте исходов (5) — одна атомарная смена механики мандата:
- маркер без проверки при записи и без обязательной матрицы с независимой проверкой (2–4) дал бы канал ослабления в обход ADR-0022 — промежуточное состояние ослабляет инвариант;
- маркер, принимаемый при записи, но не покрывающий находку гейта исходов (5), бесполезен: ANSWER создаётся, а гейт всё равно отказывает;
- покрытие в гейте (5) без маркера не имеет входа.
Каждая часть по отдельности либо ослабляет защиту, либо не меняет поведения, поэтому самостоятельно не мержима.

# PLAN: G3а-1б — мандат на ослабление по идентификатору теста

## Подход
Новый маркер `TEST_ID_MANDATE_MARKER = "Ослабление теста по идентификатору
разрешено:"` и его разбор `test_id_elements(line)` живут в
`orchestrator/advance_gates/mandate.py` рядом с прежними; `elements` и
прежний маркер не меняются. Разбор: `strip` строки, `startswith` маркера,
остаток со срезом пробелов — один элемент (`[]` — голый маркер, `None` — не
строка маркера). Диспетчер `line_elements(line, marker)` выбирает разбор по
маркеру — им пользуются все перечни маркеров (`refusals`,
`_matrix_mandate_elements`, `_has_mandate_lines`, аудит SPEC), так новый
маркер нигде не делится по запятым.

Проверка элемента при записи — отдельная `_test_id_refusal`: сначала
обратная кавычка/«|» (причина «такой тест покрывается мандатом на путь
файла»), затем `parse_test_id`, решение профиля задачи (`_task_decision`),
граница `in_outcome_bounds` (ленивый импорт из `advance_gates/acceptance`),
компонент = `profile.component`, путь в `weakening_scope`.

Матрица: новый маркер в `MATRIX_MANDATE_MARKERS` и `MANDATE_MARKERS` (через
это `zones-extend` отказывает строке нового маркера в файле матрицы).
`matrix_refusals` получает keyword-аргумент `test_ids` — элементы нового
маркера сверяются с «Что меняется» побайтно по span'ам между одинарными
обратными кавычками, а не токенами `_names`. «Чем покрыто после»: `_covered`
получает признак границы; в границе сверх прежнего правила признаются
идентификатор своего компонента в кавычках с путём в области и любой путь в
области (в кавычках или токеном); вне границы и у артели — ровно прежний код.

Гейт исходов: своя `_answer_mandates` (тот же перебор ANSWER, отбраковка
`zones._answer_commit_is_role_step_autocommit`) — прежние элементы и
отдельный набор идентификаторов; покрытие идентификатора — точное равенство
с `#n`; своя подсказка `_mandate_hint` с обоими маркерами.
`test_integrity.py`, `zones.py`, `project_profile.py` не меняются; публичный
`covering(cid, mandate)` сохраняет подпись.

## Шаги
1. `mandate.py`: маркер, `test_id_elements`, `line_elements`, проверка
   элемента в `refusals`, перечни маркеров, `matrix_refusals(test_ids=…)`,
   правило «Чем покрыто после» в границе.
2. `answer.py`: `_has_mandate_lines`, `_matrix_mandate_elements`/
   `_matrix_problems` (независимая проверка при любом из маркеров тестов),
   `_spec_gate_answer_text`, вид журнала в `in_dev`/`review` и `spec_gate`.
3. `spec_audit.py`: маркер в `_MANDATE_MARKERS`, распознавание
   `line_elements`.
4. `outcome_integrity.py`: сбор мандата, покрытие точным равенством,
   подсказка.
5. Юнит-тесты на свойства вне долгоживущих файлов задачи; карта кодовой базы.

## Влияние на систему
Механика мандата строже, не слабее: новый маркер принимается только с
проверкой идентификатора, матрицей и независимой проверкой; в гейте исходов
он снимает находку только точным равенством. Прежние маркеры, `elements`,
`_names`, `_covered` для артели и профиля вне границы исполняются тем же
кодом (ветвь нового правила стоит под `in_outcome_bounds`). Гейт по тексту
(`test_integrity`) новый маркер не читает — его находки им не снимаются.
Откат — revert merge-коммита задачи.

## Проект адресного оформления ответа

Для варианта 1A строка в штатном ANSWER Оператора:

```text
Ослабление тестов разрешено: tests/test_providers_codex.py::CuratedHomeTest::test_every_disabled_feature_is_false_in_the_curated_config
```

Обязательное ограничение рядом со строкой: только замена общего запрета true (:322–323) на контроль точного socket-исключения с сохранением всех feature assertions и покрытием каждого свойства матрицы. Нет разрешения удаления, переименования, skip/xfail, retries, повышения лимитов, скрытия входных данных или ослабления иных assertions. Иные миграции provider-тестов этой строкой не разрешаются: паритет, ENV и doctor должны сохраняться; если реализация потребует дополнительных изменений утверждений, нужен отдельный точный мандат, а не расширение данного по аналогии.

Для 2A достаточно явного разрешения подготовки перечисленных helpers и точных test zones без смены их assertions. Не предлагается машинный мандат на ослабление всего класса, файла или общего `tests/sandbox.py`. Новая проверка fail-closed остаётся независимой от положительной подготовки: без broker/при подмене/невалидном lease публичный новый full обязан отказывать без побочных эффектов; status/wait/разрешённый failed проверяются также после отключения канала. Подготовка положительной фикстуры не должна заранее создавать проверяемые результаты full.

## Предложения системе

Мандат по смыслу в ANSWER-3 и машинный префикс, который читает `test_integrity._answer_mandate`, разошлись: аудит выявил это до кода. Нужна ранняя сверка «точный assertion — формальный мандат — покрытие сохранённых свойств», без обхода гейта. При обязательном новом доверенном контексте инвентаризация должна включать setup положительных subprocess-фикстур, а не только их assertions.

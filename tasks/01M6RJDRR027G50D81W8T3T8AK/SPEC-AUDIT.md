# SPEC-AUDIT: Шаблон заголовка MR задачи внешнего проекта: policy.mr_title_template

## ТЗ и SPEC
Прямое соответствие: ТЗ «Требуется» 1 → SPEC требования 1 и 2 (умолчание
`{id}: {title}`); 2 → 3; 3 → 4; 4 → 5; 5 → 6. Критерии ТЗ разложены в
AC-1…AC-9 без потерь: три отказа загрузки → AC-3/AC-4/AC-5, `target-set`
→ AC-7/AC-8, путь `gh pr create` → AC-9. Условие ТЗ «существующие тесты
зелёные без правки» SPEC перенёс в «Не входит» (его держит пульт, при
покраснении — эскалация с именем теста), это совпадает с разделом ТЗ
«Существующие тесты». Зоны, перечень «только чтение», «Не входит» и
безопасность тестов перенесены дословно. Рамка: `budget_usd: 28` при
рамке ТЗ $30. ANSWER-n и решений Оператора на гейте SPEC нет.

Обратная сторона: требований сверх ТЗ в SPEC нет.

Расхождение по смыслу одно — ключ `{ref}`. ТЗ и SPEC (требование 3)
определяют его как «тот же ключ, что подставлен в имя ветки». Код
такого ключа не хранит: `catalog._branch_ref_key` (`orchestrator/catalog.py:642-662`)
вычисляет его только при `{ref}` в `branch_template` и только в `new`, а
в БД остаётся лишь имя ветки. Ссылок системы `ref_required` у задачи
может быть несколько: `new` с шаблоном ветки без `{ref}` принимает любое
их число (`catalog.py:580-610`), `link` добавляет ещё
(`catalog.py:732-770`), `link --remove` снимает любую, кроме последней.
Так что при шаблоне ветки без `{ref}` или при двух ссылках одной системы
требование 3 не говорит, какой ключ ставить (см. отклонение 1).

## Пути обхода гейтов
- AC-1 через подменённый `forge.open_mr`: исполнитель проверяет только аргумент `title`, а префикс `Draft: ` и его снятие остаются непроверенными, при том что SPEC «принят» (отклонение 2).
- AC-8 зелёный и без реализации поля (отклонение 5): на гейте неослабления по исходам он не отличает «отвергнуто проверкой значения» от «поле неизвестно».
- Требование 3 о ключе `{ref}`: «первая попавшаяся ссылка» и «последняя» одинаково формально выполняют SPEC. Тест AC-1 с одной ссылкой их не различает (отклонение 1).
- Подстановка цепочкой `replace`: название задачи, содержащее `{ref}` или `{id}`, подставится повторно, если `{title}` заменяется первым. SPEC порядка не задаёт, а `pull.commit_title` (`pull.py:938-939`) заменяет текст последним (отклонение 7, мелкое).

## Вердикт
`concerns` — SPEC можно вести дальше. Каждое отклонение снимается
уточнением Оператора на гейте, без возврата аналитику.

1. **Ключ `{ref}` при нескольких ссылках или шаблоне ветки без `{ref}` не определён.** SPEC, требование 3; ТЗ, «Требуется» 2; код — `orchestrator/catalog.py:580-610`, `:642-662`, `:732-770`. Предложение: «первая ссылка системы `ref_required` в порядке записи (`store.external_refs`, `store.py:751`), как `pull.commit_title`, `pull.py:926-939`».
2. **Развилка в AC-1 «подменённый `forge.open_mr` / транспорт адаптера» допускает форму теста, на которой Then не проверить:** префикс и снятие черновика живут в `gitlab_adapter.py:546-547, 554-562`. Нужна форма «через `gitlab_adapter.request` (транспорт) с сервером-дублёром, хранящим заголовок».
3. **У AC-9 неполны предусловия и не задана безопасная форма теста:** запись `forge: github` без гейта людей проекта (`github_adapter.py:140-144`), `ref_required` (иначе отказ по AC-5), коммит над базой (`:160-166`). Путь делает `git push -u origin` (`:171-172`), значит нужна песочница `RealGitSandbox` + `init_bare_origin` (образец `tests/test_draft_mr_commits.py:55-67`) или подмена `gitcmd`/`artifact_branch.send_pending`. Подмены `ci.gh` из раздела безопасности мало.
4. **В AC-7 неверно место копии:** «рядом сохранена копия» — на деле `config.LOGS/targets-<время>.yaml` (`projects.py:986-996`).
5. **AC-3…AC-5 и AC-8 не требуют полного имени `policy.mr_title_template` в тексте отказа так, чтобы его нельзя было спутать с отказом «неизвестное поле»** (`targets.py:539-541`, `projects.py:781-783`). AC-8 в нынешней формулировке зелёный до кода. Предложение: в AC-8 сверять текст отказа на `policy.mr_title_template` (форма `_check_delivery`, `targets.py:667-669`).
6. **Скрытое условие существующих тестов:** `tests/test_github_adapter.py::EnsureDraftMrTest` (`:36-56`, `conn = mock.Mock()`) краснеет, если ссылки задачи читаются при шаблоне без `{ref}`.

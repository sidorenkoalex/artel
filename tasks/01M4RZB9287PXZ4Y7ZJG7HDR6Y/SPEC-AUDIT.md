## Вердикт

`concerns` — SPEC можно вести дальше; три отклонения, решение за
Оператором на гейте.

1. **AC-4 не ловит мутацию «замена применена к `command`/`pattern`»**
   (`tasks/01M4RZB9287PXZ4Y7ZJG7HDR6Y/SPEC.md:142-145`; то же в п.6,
   SPEC:95-96, и для Codex `command_execution` в AC-5, SPEC:149-150).
   По п.2 (SPEC:49) заменяется только значение, абсолютное целиком;
   «абсолютный путь рабочей копии внутри команды» (`python3
   /…/.artel/worktrees/T/x.py`) не меняется даже при ошибочном вызове
   функции на `command`. Критерий надо уточнить: `command`/`pattern`/
   `command_execution.command`, которые САМИ являются абсолютным путём под
   `/.artel/worktrees/<id>/` с хвостом (например
   `/x/.artel/worktrees/T1/scripts/run.sh`; Grep с `pattern`, равным
   такому пути), в строке лога не меняются.
2. **AC-5 читается как «в одной строке заменены и `path` элемента, и
   `path` перечня»** (SPEC:146-150), но строка показывает только ОДИН
   ключ: `ITEM_ARGUMENT_KEYS` ставит `path` раньше `changes`
   (`orchestrator/providers/codex.py:279-280`), `_argument` берёт первый
   непустой (`codex.py:846-849`). Элемент с обоими ключами даёт строку
   только из `path`. Уточнить: замена применяется к тому из двух ключей,
   который стал ключевым аргументом строки; `changes` проверяется на
   элементе без `path`.
3. **Сокращение снимает префикс до `/.artel/` целиком, вместе с маркером
   пула `.artel-canary`**, по которому
   `orchestrator/doctor/canary_pool.py:73-83` ищет утечку в логах ролей
   (SPEC 01M1NEEWH5K1XPFRDGRMPYSBXJ, требование 13б). Сегодня это
   теоретический случай: внутри пула раскладки `.artel/` нет. SPEC
   (SPEC:49-62) и матрица ТЗ это свойство не называют. Вопрос к
   Оператору: принять как есть или потребовать, чтобы значение с
   `config.CANARY_POOL_DIRNAME` в пути не менялось (тест + строка AC-3).
   Требованием сверх ТЗ я это не считаю, пока Оператор не решит.

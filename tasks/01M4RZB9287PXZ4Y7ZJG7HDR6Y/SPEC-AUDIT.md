## Пути обхода гейтов
- AC-8 буквально: разработчик кладёт функцию в `base.py`, а провайдеры
  импортируют её привязкой `from .base import <имя>` — как сейчас
  импортируется всё из `base` (`claude.py:21`, `codex.py:43`). Подмена
  `base.<имя>` строк лога тогда не меняет. Тест AC-8 либо падает (если
  test_author угадал имя), либо, если автор тестов патчит атрибут модуля
  провайдера, проверку «одна функция» можно обойти копией функции в
  каждом провайдере. Нужно закрепить имя функции и вызов через атрибут
  модуля `base` (отклонение 1).
- Требование 5 («путь `wt:` — «н/д»») сегодня выполняется случайно:
  `_file_lines("wt:tests/x.py")` (`report.py:881-886`) ищет файл
  относительно cwd и почти всегда не находит. Тест, не создающий файл с
  именем `wt:…` относительно cwd, мутацию «`wt:` читается как путь» не
  поймает. На APFS «:» в имени допустим, поэтому тест реализуем.
  Отклонением SPEC не считаю — это вопрос качества планки, но test_author
  стоит указать.
- Других путей обхода гейтов не вижу: гейтов, лимитов и прав ролей задача
  не меняет, существующие тесты держит гейт неослабления.

## Вердикт
`concerns`. SPEC в целом соответствует ТЗ, факты о коде подтвердились.
Отклонения решаемы на гейте правкой формулировки Оператором:

1. **AC-8 непроверяем без имени функции и способа её вызова** —
   `SPEC.md:142-146`, требование 3 (`SPEC.md:62-71`). Тест «подмена
   функции в `base` меняет строки обоих» обязан знать имя атрибута
   `base`. SPEC его не задаёт, ТЗ тоже. Кроме того, провайдеры сейчас
   импортируют из `base` по имени (`orchestrator/providers/claude.py:21`,
   `orchestrator/providers/codex.py:43`), и при такой привязке подмена
   `base.<имя>` не действует. Без фиксации test_author выберет имя сам, а
   разработчик упрётся в `тест-навязывает-устройство`. Предложение
   Оператору: назвать функцию (например, `base.short_log_path`) и
   указать, что провайдеры вызывают её через модуль (`base.<имя>(…)`), а
   не через привязку `from .base import`.
2. **Комментарий `orchestrator/providers/base.py:60-64` не входит в
   требование 4** (`SPEC.md:72-75`). Комментарий утверждает, что формат
   строки лога — знание провайдера, «а не общее», а задача делает вид
   пути общим. Обоснование `orchestrator/providers/codex.py:305-309`
   («общий адрес…») тоже прямо опровергается новой функцией, но требование
   4 и AC-11 (`SPEC.md:157-160`) говорят только о «заморозке». Предложение:
   добавить в требование 4 комментарий `base.py:60-64` и обоснование
   `codex.py:305-309`.
3. **Место `path: 5` в AC-9 и требовании 6 не названо** — `SPEC.md:90`,
   `SPEC.md:150`. На уровне элемента `file_change` и внутри `changes`
   ветки кода разные (`orchestrator/providers/codex.py:846-849`).
   Предложение: явно потребовать оба случая.

Мелкое, не отклонение: AC-3 перечисляет «путь без хвоста» только для
`worktrees/<id>`. Для `projects/<p>/tasks/<id>` без хвоста правило общее
(требование 2), но примера нет. test_author стоит покрыть и его.

# PLAN: Авто-закрытие алертов doctor при исчезновении условия

## Подход
`check_orphans`/`check_backup_age` уже пересчитывают факт («дир без строки
БД», «ветка жива», «worktree сирота», «маркер бэкапа не посвежел») на
каждом прогоне — это и есть источник истины для авто-ack, отдельного
состояния заводить не нужно.

Для трёх под-проверок `check_orphans` алерт представляет конкретную
сущность (ветку/каталог/worktree), но `alerts` не хранит структурированный
идентификатор сущности — только свободный текст `message`. Вместо нового
поля/миграции схемы (расширение зоны задачи, SPEC этого не просит)
сущность разбирается обратно из уже детерминированного формата сообщения
(`raise_alert` в `check_orphans` сам же его и составляет, формат
стабилен) через `re`. Не распознанное сообщение (защита от будущего
дрейфа формата) считается «условие ещё в силе» — авто-ack не срабатывает,
что безопаснее ложного закрытия.

`check_backup_age` — единственный алерт на source (не per-сущность):
условие исчезло — маркер посвежел, проверка вернула не-fail; тогда
подтверждаются все открытые алерты этого source.

Новая функция `alerts.auto_ack(conn, alert_id)` — тонкая обвязка над
`store.ack_alert` с фиксированным `actor="doctor"` и текстом резолюции
«условие ушло, прогон doctor <дата>» (требование 6); `alerts.ack()`
(ручной путь Оператора) не трогается — раздельные функции, чтобы не
внести в ручной путь скрытую ветку по `actor` (принцип целостности,
AC-9).

Общий цикл «пройтись по открытым алертам source, закрыть те, чьё условие
не подтвердилось» — один приватный хелпер `doctor._auto_ack_gone(conn,
source, is_live)`, вызываемый из обеих проверок с разными предикатами
`is_live`. Дублировать цикл 4 раза — источник рассинхрона при следующей
правке.

Архитектурно решение не значимое (локальное расширение двух существующих
функций одного модуля), отдельный ADR не нужен.

## Шаги

1. `orchestrator/alerts.py`: `auto_ack(conn, alert_id)` — ack от имени
   `doctor` с резолюцией «условие ушло, прогон doctor <дата>» (требование 6).
2. `orchestrator/doctor.py`: хелпер `_auto_ack_gone(conn, source, is_live)`
   + предикаты для трёх сущностей `check_orphans` (branch/dir/worktree,
   разбор сообщения через `re`) и вызов авто-ack в `check_orphans`
   (требования 1-4, 7) и в `check_backup_age` (требования 1, 5, 7) —
   один MR, проверки меняются вместе, разносить по MR смысла нет.
3. Юнит-тесты в `tests/test_doctor.py` (расширение существующих классов
   `OrphansTest`/новый класс рядом): живое условие не подтверждается
   повторным прогоном (аналог AC-2/4/6/8, но как юнит, не только
   приёмочный тест), source вне списка не трогается (AC-10), не
   распознанное сообщение не подтверждается (случай, которого нет в
   приёмочных тестах — защитная ветка).

## Влияние на систему
Изменение локализовано в `orchestrator/alerts.py` (новая функция,
существующие `raise_alert`/`open_alerts`/`ack` не правятся) и
`orchestrator/doctor.py` (`check_orphans`, `check_backup_age` — логика
добавляется в конец каждой под-проверки, существующие блоки
`raise_alert`/`Check(...)` не меняются).

Рядом инвариант «дедуп `raise_alert` и ручной `ack` для живых условий не
меняются» (AC-9, `ManualAckAndDedupUnaffectedTest` в приёмочных тестах) —
не ослабляется: авто-ack — отдельная функция (`alerts.auto_ack`), не
правка `alerts.ack`/`raise_alert`; она читает открытые алерты и решает
per-запись, не трогая дедуп-ключ `(target, kind, source, message)`.

Существующие тесты `OrphansTest`/`AlertAckTest` (`tests/test_doctor.py`)
вызывают `check_orphans` один раз за тест — в момент вызова открытых
алертов того же source ещё нет, `_auto_ack_gone` проходит по пустому
списку, поведение и ассерты не меняются (проверено локальным прогоном
после реализации).

Откат — `git revert` коммита шага 2 (и 1, если делать отдельным
коммитом): `_auto_ack_gone`/`auto_ack` не участвуют в схеме БД и не
меняют формат уже записанных строк `alerts`, откат безопасен.

## Риски
Разбор сущности из `message` регэкспом — не идеальное решение (SPEC не
предлагает структурированное поле), связывает авто-ack с текущим текстом
сообщений `check_orphans`. Если формат сообщения когда-то поменяется
без синхронной правки регэкспа — авто-ack тихо перестанет находить
совпадения (безопасный отказ: алерт останется открытым, не будет
закрыт по ошибке) — риск в сторону "недо-ack", не "пере-ack".

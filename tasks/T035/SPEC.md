# SPEC: Авто-закрытие алертов doctor при исчезновении условия

## Контекст
В таблице `alerts` накопилось 19 открытых алертов без ack (18 x
`doctor.orphans.branch`, 1 x `doctor.backup_age`, ревизия
CR-2026-08-26-6). `doctor` исправно заводит инциденты, но никто их не
закрывает: новый настоящий инцидент тонет в старом шуме, канал `alerts`
перестаёт быть сигналом. Нужно, чтобы `doctor` сам закрывал алерт, когда
условие, которое его породило, при очередном прогоне фактически исчезло.

## Требования
1. При прогоне `check_orphans` (все три под-проверки: dirs, branches,
   worktrees) и `check_backup_age` система сравнивает открытые алерты
   соответствующего `source` с текущим результатом проверки.
2. Открытый алерт `source=doctor.orphans.branch`, представляющий
   конкретную ветку задачи, получает автоматический ack, если эта ветка
   при текущем прогоне больше не существует.
3. Открытый алерт `source=doctor.orphans.dir`, представляющий конкретный
   каталог задачи, получает автоматический ack, если для этого каталога
   при текущем прогоне уже есть строка в БД (каталог больше не сирота).
4. Открытый алерт `source=doctor.orphans.worktree`, представляющий
   конкретный worktree, получает автоматический ack, если этот worktree
   при текущем прогоне больше не существует.
5. Открытый алерт `source=doctor.backup_age` получает автоматический
   ack, если при текущем прогоне `check_backup_age` маркер бэкапа
   посвежел (проверка больше не проваливается).
6. Автоматический ack проставляет `ack_by=doctor` и `ack_resolution` в
   формате «условие ушло, прогон doctor <дата>».
7. Пока условие, представленное открытым алертом, остаётся в силе (ветка
   жива, каталог без строки БД, worktree существует, маркер бэкапа не
   посвежел), автоматический ack для этого алерта не происходит.
8. Заведение новых алертов (`raise_alert`), дедупликация среди открытых
   алертов и ручной `ack` (в т.ч. `cmd_alert_ack`) для живых условий
   поведение не меняют.
9. Открытые алерты source, не входящего в
   `{doctor.orphans.dir, doctor.orphans.branch, doctor.orphans.worktree,
   doctor.backup_age}`, при прогоне `doctor` авто-ack не получают.

## Критерии приёмки

AC-1. Открытый алерт `doctor.orphans.branch` для конкретной ветки задачи
получает автоматический ack (`ack_by=doctor`, `ack_resolution` вида
«условие ушло, прогон doctor <дата>»), когда эта ветка удалена и
`check_orphans` прогнан снова.

AC-2. Пока ветка, представленная алертом `doctor.orphans.branch`, жива,
повторный прогон `check_orphans` не проставляет ей ack.

AC-3. Открытый алерт `doctor.orphans.dir` для конкретного каталога
получает автоматический ack, когда для этого каталога появляется
строка в БД и `check_orphans` прогнан снова.

AC-4. Пока каталог, представленный алертом `doctor.orphans.dir`,
остаётся без строки БД, повторный прогон `check_orphans` не проставляет
ему ack.

AC-5. Открытый алерт `doctor.orphans.worktree` для конкретного worktree
получает автоматический ack, когда этот worktree удалён и
`check_orphans` прогнан снова.

AC-6. Пока worktree, представленный алертом `doctor.orphans.worktree`,
существует, повторный прогон `check_orphans` не проставляет ему ack.

AC-7. Открытый алерт `doctor.backup_age` получает автоматический ack,
когда очередной прогон `check_backup_age` находит маркер бэкапа
посвежевшим (проверка возвращает не-fail).

AC-8. Пока маркер бэкапа не посвежел (`check_backup_age` продолжает
проваливаться), повторный прогон не проставляет открытому алерту
`doctor.backup_age` ack.

AC-9. Ручной ack (`alerts.ack` / `cmd_alert_ack`) и дедупликация
открытых алертов (`raise_alert`) для живых условий работают как до этой
задачи — без изменений в поведении.

AC-10. Открытый алерт source, не входящего в
`{doctor.orphans.dir, doctor.orphans.branch, doctor.orphans.worktree,
doctor.backup_age}`, при прогоне `doctor` не получает автоматический
ack.

AC-11. Существующий набор тестов проходит зелёным без правок
существующих тестовых файлов.

## Не входит
- Изменение поведения дедупликации `raise_alert` или ручного `ack`
  Оператора для живых условий (см. AC-9) — принцип целостности,
  трогать нельзя.
- Авто-ack по возрасту алерта, по количеству открытых алертов или по
  любому иному признаку, не являющемуся фактическим исчезновением
  условия, проверенным самим `doctor` — прямой запрет ТЗ.
- Авто-ack для алертов source, не перечисленных в требовании 9 (в т.ч.
  `doctor.live_smoke`, `doctor.recovery.*`, `kind=threshold`,
  `kind=trigger`) — вне границ этой задачи.
- Обязательное изменение вывода `doctor`: строка-счётчик закрытых
  алертов в терминале допустима ТЗ, но не обязательна и не является
  критерием приёмки.

# ТЗ: Скилы и правила в бриф роли — из main, не из ветки задачи

Источник: анализ дефектов планки 02–03.09. Роль читает скилы
(skills/*.md) и CLAUDE.md из рабочей копии своей ветки, которая
отстаёт от main до подтяжки: правило, смерженное в main утром,
не действует на роль, стартовавшую днём по ветке, отведённой
раньше. Прецедент: обязательные заявки «Ловит мутацию» уехали
в main утром 02.09, планка задачи, писавшаяся днём, их не несла
(замечание R1-F3) — потребовалась правка залоченной планки по
ADR-0012.

Требуется:
1. Компоненты брифа роли, являющиеся ПРАВИЛАМИ системы (скилы из
   skills/, перечисленные в промпте запуска, и CLAUDE.md), читаются
   из main пульта (ветко-корректным чтением через git, приём
   инварианта 28), а не из рабочей копии ветки задачи. Артефакты
   задачи (SPEC/PLAN/TZ/ANSWER и прочее из tasks/<id>/) — как
   сейчас, из ветки задачи.
2. Fingerprint компонентов брифа в журнале (sha256 — существующая
   механика) продолжает писаться и отражает фактически прочитанное.
3. Роль, уже работающая в срезах через чекпоинты, при следующем
   шаге получает свежие правила — это ожидаемое поведение, не
   дефект; смена правил между срезами одной задачи не считается
   нарушением целостности (правила — не планка).
4. Тесты: скил, изменённый в main после отведения ветки, попадает
   в бриф в main-версии; артефакт задачи из ветки — в веточной
   версии; fingerprint соответствует прочитанному; существующие
   тесты зелёные.

Зоны: orchestrator/brief.py, orchestrator/role_prompt.py (при
необходимости), tests/. НЕ трогать зоны A7, пока не смержена
(она широкая — при пересечении по brief.py дождаться её мержа;
конфликт зон — эскалация).

Не входит: изменение состава скилов и брифов; чтение КОДА из main
(роль работает с кодом своей ветки — это её предмет).

Рамка: $15.

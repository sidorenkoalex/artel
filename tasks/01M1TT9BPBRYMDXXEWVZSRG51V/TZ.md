# ТЗ: разрез `orchestrator/doctor.py` на пакет проверок — снять узкое место очереди зон

Источник: анализ очереди зон 06.09 (решение Оператора «по
рекомендациям», рычаг 1). За 05–06.09: 27 задач ждали зону, 13
дождались старта developer через 69 минут по медиане (максимум 658),
суммарный простой 2862 минуты, 14 ждут до сих пор. Отказов по зоне
`orchestrator/doctor.py` — 11 из 31, это первый по частоте файл.
Причина: `doctor.py` на 1856 строк держит 24 функции `check_*` из 65
функций и 17 разделов (окружение шага, смоуки, recovery, авто-ack,
сироты, изоляция пула канарейки, свежесть ветки, lease, рекон,
сторож зависших прогонов, прочие, пин, уборка артефактных веток,
наблюдатель роста карты, команда doctor). Каждая задача, добавляющая
свою проверку на 50–100 строк, объявляет зоной весь файл и держит его
весь свой цикл. Механику зон (`zone_lock`, файл как единица) задача не
меняет: зона становится узкой сама, если проверки живут в отдельных
файлах.

Ограничение, от которого нельзя отступать: 51 имя вида `doctor.<имя>`
используется в `tests/` и планках, из них патчи коллаборантов —
`doctor.gitcmd` (32 употребления), `doctor.subprocess` (23),
`doctor.shutil` (12) — через `mock.patch.object(doctor, "gitcmd", …)`.
После разреза эти тесты обязаны проходить без правки: значит,
функции проверок, переехавшие в подмодули, обязаны брать коллаборантов
через фасад `orchestrator.doctor` в момент вызова (ленивое обращение к
атрибуту фасада), а не через собственный импорт при загрузке модуля —
иначе патч на фасаде подмодуль не увидит. Снаружи (`fsm`, `auto`,
`catalog`, `artel.py`) используются `doctor.recovery`,
`doctor.orphans`, `doctor.check_leases`, `doctor.task_counter`,
`doctor.hung_test_runs`, `doctor.check_map_growth`, `doctor.merge_lock`,
`doctor.live_smoke`, `doctor.leases`, `doctor.isolation_smoke`,
`doctor.cleanup`, `doctor.recovery_check`, `doctor.preflight_checks`,
`doctor.cmd_doctor` — все остаются доступными по прежним именам.

Требуется:
1. Пакет `orchestrator/doctor/` с `__init__.py`-фасадом, который
   экспортирует ВСЕ публичные имена сегодняшнего `doctor.py`
   (функции проверок, `all_checks`, `cmd_doctor`, `Check`, константы,
   коллаборанты `gitcmd`/`subprocess`/`shutil`/`store`/`config` и
   прочие имена, на которые ссылаются `tests/` и планки — перечень
   снять `grep -rho "doctor\.[a-zA-Z_]*"` по `tests/`, `tasks/*/acceptance_tests/`,
   `orchestrator/`, `scripts/`). `import orchestrator.doctor as doctor`
   и `from orchestrator import doctor` работают как раньше.
2. Разделы файла переезжают в подмодули по границам сегодняшних
   комментариев-разделителей (один раздел — один файл, имена по
   смыслу раздела: `env.py`, `smoke.py`, `recovery.py`, `autoack.py`,
   `orphans.py`, `canary_pool.py`, `freshness.py`, `leases.py`,
   `hung_runs.py`, `misc.py`, `pin.py`, `artifact_cleanup.py`,
   `map_growth.py`, `cli.py` — точные имена решает PLAN). Тело функций
   не переписывается: перенос, не рефакторинг логики.
3. Коллаборанты в подмодулях — через фасад в момент вызова (см.
   ограничение выше), единым приёмом на весь пакет, описанным в
   докстринге `__init__.py`; прямой `import subprocess`/`from
   orchestrator import gitcmd` в подмодуле проверки — дефект (тест на
   это см. п.6).
4. `all_checks` — в `__init__.py` или `cli.py`, порядок проверок и их
   набор прежние (инвариант: `doctor` без аргументов печатает те же
   проверки в том же порядке, что до разреза — сверка выводом на
   пустой БД до и после).
5. `docs/codebase-map.md` регенерируется штатно; `docs/invariants.md`,
   если называет `orchestrator/doctor.py` путём, обновляется на пакет;
   `COMMON_ZONES`/зоны не трогаются.
6. Тесты: (а) весь существующий `tests/` зелёный без правки ассертов и
   без правки целей `mock.patch` — это главный критерий; (б) тест
   «подмодуль проверки не импортирует коллаборантов напрямую»
   (сканирование `orchestrator/doctor/*.py` кроме `__init__.py` на
   `import subprocess`, `import shutil`, `from orchestrator import
   gitcmd` — именованный отказ; мутация: прямой импорт в одном
   подмодуле — тест обязан покраснеть); (в) тест «фасад экспортирует
   все имена из зафиксированного списка» (список — в тесте, снятый по
   п.1; мутация: удаление одного экспорта); (г) тест порядка
   `all_checks` (список имён проверок в порядке вызова до/после).
7. Планки закрытых задач не гоняются и не правятся; если планка живой
   задачи патчит `doctor.<имя>` и после разреза краснеет — эскалация с
   перечнем, не правка.

Зоны: orchestrator/doctor.py, orchestrator/doctor/, tests/, docs/invariants.md.
Порядок: ПОСЛЕ мержа всех задач, держащих или ждущих `doctor.py` на
момент старта (06.09: 01M1TQ0ZCY, 01M1TQ0X14, 01M1THKRK8, 01M1SHK3MD,
01M1R5B33C, 01M1SG9WPV) — перенос всего файла конфликтует с любой
их правкой; сверить по `status` перед стартом разработчика. Сигналы
деления сработают (≥5 файлов зоны, инварианты): ожидается обоснование
монолита — перенос разделов по одному оставил бы два источника
коллаборантов и двойной порядок `all_checks`.

Не входит: изменение логики проверок; изменение механики зон
(`zone_lock`); разрез `fsm_advance.py`/`fsm.py`/`guard.py` (следующие
кандидаты, по итогам этого разреза; `fsm_advance.py` уже режет R2).

# PLAN: Автокоммит артефактов шага учитывает .gitignore

## Подход
Единая точка правды — `.gitignore` пульта (`config.ROOT`), критерий тот
же, что у git: `git check-ignore` реальным разбором, не самодельный
список расширений (SPEC, требование 1). Новый примитив `gitcmd.
check_ignore(paths) -> set[str] | None` — один батч-вызов `git
check-ignore -v -z --stdin` на весь список путей шага (не по одному на
файл), путям не обязательно существовать на диске `config.ROOT`
(директорные правила вроде `__pycache__/` матчатся по строке пути, не
по факту наличия каталога — проверено вживую: `git check-ignore`
матчит `tasks/X/dropme/notes.txt` под правило `dropme/`, даже когда
такого файла нигде на диске нет). `None` — git не ответил, вызывающий
код деградирует тихо (не коммитит вслепую без фильтрации), тем же
принципом, что уже применяет остальной `checkpoint.py` (требование 6).

Три точки применения:

1. `checkpoint._commit_external_step_artifacts` (AC-1, AC-2, AC-3):
   собранные с диска файлы (`raw_files`) и уже существующие в
   артефактной ветке пути (`existing`) фильтруются ЧЕРЕЗ `check_ignore`
   ДО diff'а `existing - files`, симметрично для обоих направлений
   требования 2 — игнорируемый путь не участвует ни в добавлении/
   обновлении (отфильтрован из `files`), ни в кандидатах на удаление
   (отфильтрован из `existing`, поэтому никогда не появляется в
   `existing - files`). Старое правило удаления (последний коммит —
   автокоммит той же роли + frontmatter `type` в
   `_DELETABLE_ARTIFACT_TYPES`) не трогается — оно остаётся для
   настоящих артефактов (QUESTIONS.md), просто больше не единственная
   защита для `.pyc` (AC-3 «Красен до реализации»: раньше `.pyc`
   выживал случайно за счёт бинарного frontmatter, не по замыслу).

2. `fsm_advance.in_dev` (AC-4): лок acceptance_tests/ вместо голого
   `gitcmd.diff_paths` (да/нет) зовёт новый `gitcmd.diff_names` (список
   путей diff'а) и вычитает из него игнорируемые — если после вычитания
   список пуст, лок не считает это спором с тестом. git не ответил ни на
   diff, ни на check-ignore — fail-closed, тот же принцип ADR-0002, что
   уже несёт эта ветка кода.

3. `doctor.py`, новая `_fix_ignored_artifact_files` + флаг `--fix`
   (AC-5): проходит по живым (не `done`/`killed`) задачам, для каждой
   вычисляет игнорируемые пути в `tasks/<id>/` артефактной ветки и
   убирает их через `artifact_branch.commit_files(..., remove=...)` —
   плотницкая запись прямо в объектную базу `config.ROOT`, рабочее
   дерево/HEAD `main` не трогает по построению. Журналит только
   задачи, где реально что-то убрано.

## Шаги

1. `gitcmd.check_ignore` + `gitcmd.diff_names` — новые примитивы, без
   изменения поведения существующих.
2. `checkpoint._commit_external_step_artifacts` — фильтрация по
   `.gitignore` (AC-1, AC-2, AC-3).
3. `fsm_advance.in_dev` — лок acceptance_tests/ игнорирует игнорируемые
   пути diff'а (AC-4).
4. `doctor.py` + `artel.py` — команда `doctor --fix` (AC-5).
5. Юнит-тесты на все три точки + `gitcmd.check_ignore`/`diff_names`.

## Влияние на систему
Затронуты `checkpoint.py` (единственная точка автокоммита артефактов
шага — уже несёт requirement 8 «кодовая ветка свободна от артефактов»,
эта задача не меняет ЧТО коммитится по составу ролей/target, только
ЧТО именно из `task_dir` считается файлом-кандидатом) и `fsm_advance.
in_dev` (лок приёмочных тестов, инвариант 27 — механика лока не
меняется, только критерий «что считается разницей»; SPEC «Не входит»
явно исключает пересмотр самой механики). Оба места fail-closed при
неответившем git — не ослабление существующего поведения (там оно уже
было fail-closed для diff/git-first primitives), а такое же поведение
для новой git-операции.

`doctor --fix` — новое действие, но пишет только в артефактные ветки
(`refs/heads/artifact/<id>`), никогда в `main`/рабочее дерево пульта
(AC-5, третья проверка теста) — не нарушает принцип неприкосновенности
main.

Планка A7 (44 теста) и планка hotfix 01M1KT0792125J9ZNJNZJ86E9Q —
регрессионный щит (AC-6): оба места правки затрагивают код, который эти
планки уже покрывают (автокоммит артефактов, лок acceptance_tests/) —
проверено прогоном обеих планок реальным интерпретатором против текущего
кода.

Откат: правка локализована в трёх функциях (`checkpoint.
_commit_external_step_artifacts`, `fsm_advance.in_dev`,
`doctor.cmd_doctor`/новая `_fix_ignored_artifact_files`) плюс два новых
чистых примитива `gitcmd.py` — реверт коммита возвращает прежнее
поведение без остаточного состояния (новых таблиц/миграций схемы нет).

## Риски
`git check-ignore` — единственный источник критерия «игнорируется»;
если у пульта когда-нибудь появится `.gitignore` с правилами,
зависящими от текущего рабочего дерева (например, `!исключение`
внутри директории, которой нет на диске `config.ROOT`), сопоставление
может разойтись с тем, что видел бы git над РЕАЛЬНЫМ файлом на диске
этого же пути. Сегодняшний `.gitignore` пульта — плоский список
паттернов без такой зависимости; вживую проверено (см. «Подход»).

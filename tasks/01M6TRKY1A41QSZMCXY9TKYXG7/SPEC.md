# SPEC: Приёмка принимает итог CI для дерева кода — без условия свежести при мерже пультом, с приложениями PLAN (ADR-0031, этап 1)

## Контекст
Приёмка (автогейт `fsm_autogate._autogate_conditions` и `approve` в
`acceptance`) берёт полный набор через `acceptance.acceptance_suite`
(`orchestrator/acceptance.py:4080`) на дереве `appendix_tree.suite_tree` —
голова ветки с наложенными приложениями PLAN. Итог CI принимается только при
условиях `_ci_result_conditions` (`orchestrator/acceptance.py:4166-4185`):
дерево приёмки равно дереву головного коммита и голова содержит
`origin/<base>`. Оба условия гонят задачу в лишний локальный прогон на том же
дереве, что уже проверил CI: за 30 дней до 07.11.2026 — 94 локальных прогона
по причине «ветка не свежа относительно origin/main» и 28 задач с деревом,
отличным от головы (у 26 — приложения PLAN, которые CI ветки накладывает сам,
`scripts/plan_appendix_ci.py`). Для проекта с `merge_gate: operator` свежесть
и так держит `merge_gate` (`fsm_merge_gate._sync_main_or_wait`). ADR-0031,
этап 1 (принят Оператором 07.11.2026, `9d60fe8f`).

## Требования

1. **Свежесть.** Для проекта задачи с `merge_gate: operator` условие «голова
   содержит `origin/<base>`» в `_ci_result_conditions` не проверяется — ни в
   режиме `full_suite: local` (принятие итога `ci.accepted_full_suite`), ни в
   режимах `ci`/`both` (`_ci_job_run`). Для `merge_gate: target-human` —
   прежнее поведение побайтно (в `local` — локальный прогон с прежней
   причиной, в `ci`/`both` — «неизвестно» с прежней причиной).
2. **Приложения PLAN.** Итог CI принимается и при дереве приёмки, отличном от
   дерева головного коммита, если одновременно:
   а) дерево, полученное наложением тех же приложений PLAN (тот же узел
   `appendix_tree`, тот же PLAN) на чистое дерево головного коммита, равно
   дереву приёмки — то есть незакоммиченных правок нет;
   б) ссылка документов задачи `refs/artifacts/<id>` в `origin` не сдвигалась
   после начала прогона CI, итог которого принимается (иначе CI мог наложить
   другие приложения).
   Не удалось установить (а) или (б) — прежний путь (локальный прогон в
   `local`, «неизвестно» в `ci`/`both`) с причиной одной строкой.
3. **Журнал.** Запись журнала о принятом итоге CI называет основание
   принятия: «для дерева с приложениями PLAN» либо «без проверки свежести: её
   держит merge_gate». Прочие причины локального прогона и итога
   «неизвестно» — прежним текстом.
4. `merge_gate`, его подтяжка базы и полный прогон приложений PLAN к
   `tests/`, `.github/` и настройкам сбора
   (`fsm_merge_gate._full_suite_or_refuse`) — без изменений.
5. `approve --fresh-suite` — прежнее поведение: локальный прогон в `local`,
   перечитывание итога CI в `ci`.

## Критерии приёмки

AC-1. Given проект с `merge_gate: operator`, голова ветки не содержит
`origin/<base>` (база ушла одним коммитом), дерево приёмки равно дереву
головы, CI зелёный с исполненным полным набором, When приёмка, Then итог CI
принят, локальный прогон не вызван, запись журнала о принятии называет
основание «без проверки свежести: её держит merge_gate». Проверяется в
режиме `local` и в режиме `ci`.

AC-2. Given то же, что в AC-1, но при `merge_gate: target-human`, When
приёмка, Then прежний итог: в режиме `ci` — «неизвестно» с причиной «ветка
не свежа относительно origin/<base>», в режиме `local` — локальный прогон с
той же причиной.

AC-3. Given приложение PLAN, наложенное на дерево приёмки, рабочая копия без
незакоммиченных правок, ссылка документов задачи в `origin` не сдвигалась
после начала прогона CI, CI зелёный, When приёмка, Then итог CI принят,
локальный прогон не вызван, запись журнала называет основание «для дерева с
приложениями PLAN».

AC-4. Given приложение PLAN и ссылка документов задачи в `origin`, сдвинутая
после начала прогона CI (новое приложение), When приёмка, Then итог CI не
принят, причина — одной строкой.

AC-5. Given незакоммиченная правка в рабочей копии (с приложением PLAN или
без), When приёмка, Then итог CI не принят, причина «дерево гейта отличается
от дерева головного коммита» — прежним текстом.

AC-6. Given `approve --fresh-suite`, When приёмка, Then прежнее поведение:
локальный прогон в режиме `local`, перечитывание итога CI в режиме `ci`.

AC-7. Мутация «условие свежести осталось для `merge_gate: operator`» красит
хотя бы один тест критериев AC-1.

AC-8. Мутация «приложения PLAN не сверяются с моментом начала прогона CI»
(условие 2б снято) красит хотя бы один тест критерия AC-4.

Безопасность тестов (из ТЗ): вымышленные проекты и рабочие копии во
временной песочнице (`tests.sandbox`), голый `origin` во временном каталоге,
`gh`/`forge` — подмена; без сети; никогда — настоящий `.artel/targets.yaml` и
клоны проектов.

## Оценка объёма и деление

Сработавший сигнал: `budget_usd` ≥ $30 (зон — 4, критериев — 8, прочие
сигналы не срабатывают).

**Обоснование монолита.** Механика одна — набор условий принятия итога CI в
`_ci_result_conditions` и его два потребителя (`_acceptance_suite_run`,
`_ci_job_run`) в одном модуле `orchestrator/acceptance.py`; `ci.py` даёт
только чтение времени начала прогона CI. Требования 1 и 2 правят одну функцию
условий и одну запись журнала (требование 3); разрезанные, они дают две
задачи на один и тот же участок кода и на одни и те же существующие тесты
(`tests/test_01m4begqavvwchfcw6bebb0xvt_ci_acceptance.py`,
`tests/test_01m5xzskk8gzteca2kwafhe029_ci_full_suite.py`), без выигрыша в
ревью. Потолок $40 — класс «до 10 критериев и до 4 файлов зоны»
(`config.BUDGET_CALIBRATION_TABLE`), ниже рамки ТЗ $60. Решение о монолите —
за Оператором на гейте SPEC.

- Изменение `.github/workflows/ci.yml`, `targets.yaml`; правка настоящего
  локального слоя `.artel/targets.yaml` в тестах и при разработке.
- Приёмка проектов `merge_gate: target-human` — сверх сохранения прежнего
  поведения (требование 1).
- Правка модулей только для чтения: `orchestrator/appendix_tree.py`,
  `orchestrator/fsm_autogate.py`, `orchestrator/fsm.py`,
  `orchestrator/fsm_merge_gate.py`, `orchestrator/targets.py`,
  `orchestrator/artifact_branch.py`, `scripts/plan_appendix_ci.py`,
  `tests/sandbox.py`, `docs/adr/0031-test-runs-strategy.md`, `.github/`.
- `orchestrator/ci.py` — только чтение времени начала прогона CI, если его
  ещё нет; иных правок нет. `docs/codebase-map.md` — только генерацией
  `scripts/codebase_map.py`.
- Зелёный полный набор `tests/`, зелёный CI ветки, неизменность защищённых
  путей и непревышение бюджета — их держит пульт.
- Существующие тесты (из ТЗ): случаи «несвежая ветка — локальный прогон /
  неизвестно» для записи с `merge_gate: operator` меняют ожидание по
  требованию 1. Мандат Оператора из ТЗ: «Ослабление тестов разрешено:
  `tests/test_01m4begqavvwchfcw6bebb0xvt_ci_acceptance.py` (подслучай `stale`
  в `test_ac4_bad_ci_or_stale_branch_runs_local_suite`),
  `tests/test_01m5xzskk8gzteca2kwafhe029_ci_full_suite.py` (случаи несвежей
  головы в `test_ac9_*` и `test_ac10_fresh_suite_rereads_ci_without_local_run`)
  — только перевод этих случаев на новое ожидание либо на запись
  `target-human`; прочие утверждения, имена тестов и случаи не меняются».
  Любой другой красный тест — эскалация с именем теста, без правки. Строкой
  мандата для гейтов неослабления этот текст становится только в записи

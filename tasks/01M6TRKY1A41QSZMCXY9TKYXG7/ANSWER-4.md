# ANSWER-4: ответ Оператора

## Ответы

Основание: задачу ведёт сессия Оператора с правами волны G (решение Оператора 07.11.2026); ответ на эскалацию составителя тестов.

## Ответы

1. A — канал и текст публикации фиксируются. Сценарий `scripts/plan_appendix_ci.py` печатает ровно одну строку аннотации проверки: `::notice title=plan-appendix-docs::ref=<sha X или пусто>; outcome=<applied|no-plan|no-appendices|no-ref>; diffs=<h1,h2,… или пусто>` (`h` — шестнадцатеричный sha256 байтов UTF-8 текста `PlanAppendix.diff`, в порядке PLAN). Приёмка читает её вызовом `gh api repos/<owner>/<repo>/check-runs/<id>/annotations` у проверки `FULL_SUITE_JOB`, итог которой принимает, и отбирает аннотации с `title == "plan-appendix-docs"`; ни одной или больше одной — прежний путь. Тесты подменяют ответ этого вызова на границе `ci.gh`; поддельные варианты (AC-8, AC-16, AC-18) получаются правкой полей строки. AC-13 проверяет, что настоящий сценарий на голом origin песочницы печатает эту строку с верными полями.
2. B — оговорка AC-13 «а не копию правила хеширования в тесте» снимается: тест сам считает ожидаемый список по правилу требования 2 (sha256 hex байтов UTF-8 `PlanAppendix.diff` из `guard.plan_appendices` пульта). Так тест закрепляет записанную форму хеша и ловит её смену на любой из сторон, в том числе на обеих сразу. Имя функции приёмки выбирает разработчик.

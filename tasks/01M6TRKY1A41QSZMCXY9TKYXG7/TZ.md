# ТЗ: Приёмка принимает итог CI для дерева кода: без условия свежести при мерже пультом, с приложениями PLAN

# Приёмка принимает итог CI для дерева кода: без условия свежести при мерже пультом, с приложениями PLAN (ADR-0031, этап 1)

## Факты

1. Приёмка (автогейт `fsm_autogate._autogate_conditions` и `approve` в `acceptance`, `orchestrator/fsm.py:1683`) берёт полный набор через `acceptance.acceptance_suite` (`orchestrator/acceptance.py:4080`) на дереве `appendix_tree.suite_tree` — голова ветки с наложенными приложениями PLAN.
2. Итог CI принимается при условиях `_ci_result_conditions` (`orchestrator/acceptance.py:4166-4185`): дерево приёмки равно дереву головного коммита; голова содержит `origin/<base>`. Для `full_suite: local` у артели — затем `ci.accepted_full_suite` (`orchestrator/ci.py:1295`), иначе локальный прогон с записью «полный набор локально»; для `ci`/`both` — `_ci_job_run` (`orchestrator/acceptance.py:4243`), невыполненное условие — «неизвестно».
3. Условие свежести проверяется после условия равенства деревьев: при несвежей ветке локальный прогон идёт на том же дереве, что проверил CI. За 30 дней до 07.11.2026 — 94 локальных прогона по причине «ветка не свежа относительно origin/main».
4. CI ветки задачи накладывает приложения PLAN из `refs/artifacts/<id>` в `origin` перед тестами (`scripts/plan_appendix_ci.py`, тот же порядок, что ворота мержа). Дерево приёмки с приложениями не равно дереву головы — локальный прогон; за 30 дней — 28 задач, у 26 есть приложения PLAN.
5. Свежесть для проекта с мержем пультом (`merge_gate: operator`, `orchestrator/targets.py:615`) держит `merge_gate`: `fsm_merge_gate._sync_main_or_wait` под замком мержа подтягивает базу, если она ушла кодом, отправляет новую голову и ждёт её CI до мержа.
6. ADR-0031, этап 1 (принят Оператором 07.11.2026, `9d60fe8f`).

## Требуется

1. **Свежесть.** Для проекта с `merge_gate: operator` условие «голова содержит `origin/<base>`» в `_ci_result_conditions` не проверяется ни в режиме `local` (принятие `ci.accepted_full_suite`), ни в режимах `ci`/`both`. Для `merge_gate: target-human` — прежнее поведение побайтно.
2. **Приложения PLAN.** Итог CI принимается и при дереве приёмки, отличающемся от дерева головы, если одновременно: (а) дерево, полученное наложением тех же приложений PLAN (тот же узел `appendix_tree`, тот же PLAN) на чистое дерево головного коммита, равно дереву приёмки — незакоммиченных правок нет; (б) ссылка документов задачи `refs/artifacts/<id>` в `origin` не сдвигалась после начала прогона CI, итог которого принимается (иначе CI мог наложить другие приложения); не удалось установить (а) или (б) — прежний путь с причиной одной строкой.
3. **Журнал.** Запись о принятом итоге CI называет, что итог принят «для дерева с приложениями PLAN» либо «без проверки свежести: её держит merge_gate»; прочие причины локального прогона и «неизвестно» — прежним текстом.
4. `merge_gate`, его подтяжка и полный прогон приложений PLAN к `tests/`, `.github/` и настройкам сбора (`fsm_merge_gate._full_suite_or_refuse`) — без изменений.

## Критерии приёмки

- Given проект с `merge_gate: operator`, голова не содержит `origin/<base>` (база ушла одним коммитом), деревья равны, CI зелёный с исполненным полным набором, When приёмка, Then итог CI принят, локальный прогон не вызван, запись журнала называет причину принятия без проверки свежести;
- Given то же при `merge_gate: target-human`, Then прежний итог «неизвестно» с причиной «ветка не свежа»;
- Given приложение PLAN, наложенное на дерево приёмки, документы задачи не сдвигались после начала прогона CI, When приёмка, Then итог CI принят, локальный прогон не вызван;
- Given приложение PLAN и документы задачи сдвинуты после начала прогона CI (новое приложение), Then итог CI не принят, причина одной строкой;
- Given незакоммиченная правка в рабочей копии, Then итог CI не принят, причина «дерево гейта отличается от дерева головного коммита» — прежняя;
- Given `approve --fresh-suite`, Then прежнее поведение: локальный прогон в `local`, перечитывание итога в `ci`;
- мутация «условие свежести осталось для `operator`» и мутация «приложения не сверяются с моментом прогона CI» — красные.

Безопасность тестов: вымышленные проекты и рабочие копии во временной песочнице (`tests.sandbox`), голый `origin` во временном каталоге, `gh`/`forge` — подмена; без сети; никогда — настоящий `.artel/targets.yaml` и клоны проектов.

Существующие тесты: случаи «несвежая ветка — локальный прогон / неизвестно» для записи с `merge_gate: operator` меняют ожидание по требованию 1. Ослабление тестов разрешено: `tests/test_01m4begqavvwchfcw6bebb0xvt_ci_acceptance.py` (подслучай `stale` в `test_ac4_bad_ci_or_stale_branch_runs_local_suite`), `tests/test_01m5xzskk8gzteca2kwafhe029_ci_full_suite.py` (случаи несвежей головы в `test_ac9_*` и `test_ac10_fresh_suite_rereads_ci_without_local_run`) — только перевод этих случаев на новое ожидание либо на запись `target-human`; прочие утверждения, имена тестов и случаи не меняются. Любой другой красный тест — эскалация с именем теста, без правки.

Зоны: `orchestrator/acceptance.py`, `orchestrator/ci.py` (только чтение времени начала прогона CI, если его нет), `docs/codebase-map.md` (только генерацией), `tests/` (долгоживущие файлы задачи и случаи из «Существующие тесты»).

- изменение `merge_gate` и CI `main` после мержа (этап 2 ADR-0031);
- изменение `.github/workflows/ci.yml`, `targets.yaml`;
- приёмка проектов `target-human`.

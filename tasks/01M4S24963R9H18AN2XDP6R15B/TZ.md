Требуется:
1. Генератор `scripts/core_reference.py`: по набору исходных текстов
   (путь → текст), настройке проекта (п. 3) и sha источника строит текст
   справочника. Разбор — только `ast`: код проекта не импортируется и не
   исполняется (ни `import`/`importlib`, ни `exec`/`eval`/`compile` с
   исполнением); генератор импортирует только стандартную библиотеку, не
   модули пульта. Выход детерминирован: тот же вход — байт в байт тот же
   текст. Генератор не читает `config`: порог использования,
   `generator_sha256` и sha источника приходят параметрами
   `build(sources, setting, sha, *, min_uses, generator_sha256)`. Из
   командной строки: `python3 scripts/core_reference.py <корень дерева>
   <модуль>... [--constants-module <модуль> --constants <ИМЯ>...]
   [--min-uses N] [--sha <метка>]` (умолчания: 3 и «рабочее дерево»)
   печатает справочник по файлам диска в stdout и ничего не пишет на
   диск; тест держит равенство умолчания `--min-uses` и
   `config.CORE_REFERENCE_MIN_USES`. Набор файлов в этом режиме — обычные
   файлы (не символьные ссылки) `.py`, отслеживаемые git в корне (`git
   ls-files`); нет git — все `.py`, кроме каталогов с ведущей точкой,
   `__pycache__`, `node_modules`, `venv`. Режим предназначен для деревьев
   Оператора, не для чужих.
2. Содержимое — по каждому модулю настройки в её порядке, одна строка на
   запись. «Файлы коммита» — `.py`, отслеживаемые git в этом коммите; одно
   правило для подсчёта использования и поиска примеров:
   а) путь и первая строка docstring модуля;
   б) публичные (без ведущего `_`) функции верхнего уровня, включая
      `async def`, используемые не менее чем в
      `config.CORE_REFERENCE_MIN_USES` = 3 других файлах коммита
      (обращение `<модуль>.<имя>` или `from … <модуль> import <имя>`;
      `<модуль>` — имя файла без `.py`): имя, сигнатура как в коде
      (параметры, значения по умолчанию, аннотации, возвращаемый тип) и
      первая строка docstring, обрезанная до 100 символов с «…» (нет —
      ничего). Декораторы сигнатуру не меняют; при двух определениях
      одного имени верхнего уровня берётся последнее;
   в) публичные классы верхнего уровня по тому же правилу использования:
      имя, базовые классы, имена публичных методов одной строкой (без
      сигнатур и docstring);
   г) пример вызова к записи п. б — только вызов, целиком умещающийся в
      одну строку и не длиннее 80 символов; из подходящих по длине —
      первый по порядку «путь файла (посимвольная сортировка строк), затем
      номер строки»: вызов `<модуль>.<имя>(` в любом файле коммита, иначе
      `<имя>(` в файле, импортирующем имя из модуля, иначе `<имя>(` в
      самом модуле; подходящего нет — примера нет;
   д) константы — только перечнем имён из настройки и только из модуля
      констант настройки: имя, значение одной строкой (пробелы схлопнуты,
      длиннее 400 символов — обрезка с «…») и пояснение — комментарий в
      той же строке, иначе первое предложение сплошного блока
      комментариев непосредственно над присваиванием (до первого `.`, `:`
      или `;`, за которым пробел; не более 160 символов), иначе «без
      пояснения». Имя перечня не найдено — строка «нет в коммите».
   Модуль настройки отсутствует в коммите или не разбирается — в его
   разделе строка с причиной, остальные модули строятся. Любой файл
   коммита, не разобранный `ast` (`SyntaxError`, `ValueError`,
   `RecursionError`, `MemoryError`, не декодируется как UTF-8), сборку не
   роняет: в подсчёт использования не входит и считается в шапке.
   Шапка: `built_at_sha`, `generator_sha256` (п. 5), настройка (модули,
   модуль и имена констант, `CORE_REFERENCE_MIN_USES`), число
   неразобранных и пропущенных файлов, sha256 тела; строка для роли:
   справочник описывает код коммита `built_at_sha`, правки задачи после
   него не отражены, полный текст модуля — в рабочем каталоге.
3. Настройка — необязательное поле `core_reference` записи проекта в
   `targets.yaml`: `modules` (непустой список строк; каждая оканчивается
   на `.py`, относительная, без ведущего `/`, без пустых сегментов, `.`,
   `..` и обратных слэшей, без повторов), `constants_module`
   (необязательный, один из `modules`), `constants` (непустые
   идентификаторы Python без повторов; обязателен при `constants_module`
   и запрещён без него). `targets.check` проверяет поле тем же приёмом,
   что `test_profile`: отказ называет проект, поле и подполе; неизвестное
   подполе — отказ. Поле проекта читает новая `targets.core_reference(
   name)`: файл разбирается один раз, проверяется только запись `name`
   (сломанная чужая запись справочник этого проекта не отключает).
   Механизм не знает имён модулей артели: всё берётся из настройки.
4. Чтение исходников коммита — пакетно: один `git ls-tree -r -l -z <sha>`
   и один `git cat-file --batch` (не `gitcmd.show` на файл), `git -C <клон
   проекта>`, окружение `gitcmd.pult_env()`; `gitcmd.py` не меняется. Без
   checkout и без рабочего дерева. `<sha>` — 40 шестнадцатеричных знаков
   (голова ветки узнаётся `rev-parse`). В набор берутся только записи типа
   blob с режимом 100644 или 100755 и именем на `.py`: символьные ссылки
   (120000) и подмодули (160000) пропускаются и считаются в шапке.
   Пределы — константы `config`: `CORE_REFERENCE_MAX_FILES` = 2000,
   `CORE_REFERENCE_MAX_SOURCE_BYTES` = 32 МиБ,
   `CORE_REFERENCE_MAX_BLOB_BYTES` = 1 МиБ,
   `CORE_REFERENCE_MAX_LISTING_BYTES` = 64 МиБ (вывод `ls-tree` читается
   потоком, превышение — как сверх пределов). Число файлов, объём и
   размер blob проверяются по размерам из `ls-tree -l` ДО запуска
   `cat-file`; на вход `cat-file` идут только sha blob'ов в пределах;
   ответ разбирается по длине из строки `<sha> blob <размер>`, строка
   `missing` — файл пропущен и посчитан в шапке. Крупный blob
   пропускается и считается; сверх пределов числа файлов, объёма или
   вывода, по общему сроку — справочник не строится, исход п. 7. Срок
   `config.CORE_REFERENCE_GIT_TIMEOUT_SEC` = 60 — общий на всю сборку (оба
   вызова git и разбор): второму вызову передаётся остаток срока;
   `TimeoutExpired` и `OSError` — сбой источника. Тексты из кода
   (docstring, значения и комментарии констант, примеры вызовов)
   очищаются: символы категории Cc заменяются пробелом; строки делятся
   только по `\n`. Тесты берут настоящий git через `RealGitSandbox` /
   `network_guarded_real_run` (`TmpRootTest` подменяет `subprocess.run`).
5. Кэш — `.artel/projects/<проект>/knowledge/derived/core-reference.md`
   через `repo_context.projects_root()` в момент вызова; при `NO_AREA` —
   `off` (п. 6). Обоснование
   (повторить в PLAN одной строкой): карта лежит в `docs/codebase-map.md` git артели и
   коммитится после мержа — для внешнего проекта такой путь означал бы
   запись пульта в чужой репозиторий; `knowledge/` — дом производных
   знаний по ADR-0003 п.3а, вне git, не трогает диффы мержа, гейт
   ёмкости и сторож неизменности главной копии; `derived/` отделяет
   пересоздаваемое от курируемых файлов К-4а; файл можно удалить —
   следующая сборка восстановит. Запись атомарна (временный файл в том
   же каталоге и замена); файл читается один раз целиком, шапка и тело
   разбираются из одного прочтения. Кэш годен, только если совпадают
   `built_at_sha`, настройка из шапки, sha256 тела и `generator_sha256`
   — sha256 байт файла загруженного модуля генератора
   (`core_reference.__file__`), считанный при импорте модуля пультом: это
   байты исполняемого кода (долгий процесс `auto` не подменяет код на
   диске после `pin-update`), а не `config.ROOT / …` (в песочнице тестов
   корень подменён и файла там нет); иначе после правки генератора
   стухший текст при том же sha выдавался бы за свежий. Не совпало —
   сборка заново и перезапись.
6. Интерфейс для К-3б: `reference_cache.get_reference(conn, task_id, *,
   reason, sha=None)` → значение с полями `text` (содержимое файла кэша
   целиком — шапка и тело, как записано; К-3б считает по нему размер и
   sha256; или пусто),
   `note` (пометка для брифа или пусто), `state` — `off` (у проекта нет
   поля), `fresh` (собран сейчас), `cached` (кэш годен), `unverified`
   (источник не узнать, отдан кэш), `absent` (справочника нет). `sha=None`
   — голова ветки задачи в клоне проекта (коммит, не рабочее дерево);
   иначе — переданный коммит. `reason` — `brief` или `merge`. Каждая
   сборка — запись журнала задачи «справочник ядра: построен» (sha, байты,
   число записей, длительность, повод). Голову ветки не узнать (нет клона
   или ветки, git не ответил): есть кэш — `unverified` с пометкой «не
   сверен: <причина>, built_at_sha=…»; кэша нет — `absent` с пометкой.
   До чтения `targets.yaml`: область проектов `NO_AREA` — `off` без
   алерта, пометки и журнала (песочница тестов: кэш не читается и не
   пишется, git не зовётся). Читаемый `targets.yaml` без записи проекта
   — тоже `off`. Нечитаемый файл, запись без разбора поля, неверное поле
   — `absent` с пометкой и алертом (п. 7). Кэш, не являющийся обычным
   файлом или крупнее четырёх `CORE_REFERENCE_MAX_BLOB_BYTES`, считается
   испорченным (пересборка). `off` не даёт побочных эффектов (git,
   журнал, алерт). Функция не бросает исключений и не завершает процесс.
7. Сбои (модуль или имя константы не найдены, модуль не разобран,
   источник недоступен или сверх пределов п. 4, кэш не записан,
   `targets.yaml` не читается) — алерт вида `incident` по проекту задачи
   с источником `brief.core_reference` при `reason=brief` и
   `fsm.core_reference_regen` при `reason=merge`, плюс пометка в `note`.
   Текст алерта не содержит sha, времени и размеров (они — в журнал):
   например «справочник ядра: модуль <путь> не найден в коммите ветки
   задачи». Кэш не записан — текст отдаётся из памяти (`fresh`).
8. Тесты в `tests/` с заявками «Ловит мутацию», на временном
   `targets.yaml` и области проектов песочницы (настоящий `targets.yaml`
   и боевая `.artel/projects` не читаются и не пишутся), включая внешний
   проект с другим деревом (модули не в каталоге оркестратора):
   - генератор исполнил код проекта (верхний уровень модуля оставляет
     след на диске или падает — справочник собран, следа нет); генератор
     импортирует модуль пульта (проверка `ast` импортов самого
     `scripts/core_reference.py`);
   - пропали сигнатура, аннотация, значение по умолчанию, первая строка
     docstring, пример или пояснение константы; попали приватное имя,
     имя ниже порога использования, константа вне перечня, сигнатуры
     методов класса; пример не первый из подходящих или длиннее 80
     символов; при двойном определении взято первое;
   - выход недетерминирован;
   - перечень модулей или констант зашит, а не взят из настройки;
   - `targets.check`/`targets.core_reference` приняли неверное поле
     (каждый случай п. 3) или сломанная чужая запись отключила справочник
     проекта;
   - чтение по файлу вместо пакетного (число запусков git на сборку
     растёт с числом файлов); файл вне `git ls-files` или из каталога с
     ведущей точкой попал в разбор; крупный blob или превышение числа
     файлов не остановили сборку; неразобранный файл уронил сборку или
     не посчитан в шапке;

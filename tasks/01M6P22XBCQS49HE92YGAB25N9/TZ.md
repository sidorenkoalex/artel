# ТЗ: Раннер тестов внешнего проекта в контейнере Docker Compose

# Раннер тестов внешнего проекта в контейнере Docker Compose

Предусловие заведения: поправка Оператора 05.11.2026 к ADR-0023 («службы тестов доверенного проекта — Compose-файл проекта с перекрытием пульта») принята и закоммичена (77e9ca9c); без неё — эскалация.

## Факты

1. Раннер `pytest-own` (`orchestrator/targets.py:82-85`, `PROFILE_OWN_RUNNER_ONLY`; `orchestrator/acceptance.py:94-215`; ADR-0023, вторая поправка 16.10) запускает команду профиля в `workdir` дерева прогона с чистым окружением `_own_env` (:189-211): `PATH`, `LANG`/`LC_ALL`, `TMPDIR`, `test_profile.env`, свой `HOME` и `PYTHONPYCACHEPREFIX`.
2. Все места прогона профиля с отчётом (`report`) сходятся в `_report_run` (`orchestrator/acceptance.py:806-875`; argv — `_report_argv` :736-785, окружение — `_report_env` :626-633): прогон планки, сухой сбор, повторы `run_repeat`, полный набор, гейт неослабления по исходам (`orchestrator/advance_gates/outcome_integrity.py:420`, `:445`, `:736`), двусторонний прогон `two_sided._run_side_report`. Пути машины в argv — только `{path}` (отчёт) и `{pult_reporter}`; цели и `--ignore` даются от `workdir`; `--rootdir` в этой ветке не подаётся. Ключ сохранённого итога полного набора — `_report_suite_result_key` (:3069-3093).
3. Признание «своего» раннера: `project_profile.reported` (`orchestrator/project_profile.py:511-521`), `acceptance._own`, `test_integrity._own_profile` (`orchestrator/advance_gates/test_integrity.py:1651-1655`) проверяют только `pytest-own`; проверки полей записи (`orchestrator/targets.py:756`, `:767`, `:1096`, `:1258`) допускают `workdir`, `env` и `machine.path` только при `pytest-own`.
4. Окружение шага роли (`runner.role_env`, `orchestrator/runner.py:1246`) собирает `PATH` только из каталогов объявленных инструментов, `HOME` — свой; переменных `DOCKER_*` нет в `stack.ROLE_ENV_ALLOWLIST` (`orchestrator/stack.py:314`). Программа `docker` — вне этих каталогов: команды пульта прогона тестов из шага роли (`plank-run`, `suite-run`) Docker не найдут.
5. Проект, тесты которого требуют служб и запускаются в контейнере сервиса Compose-файла проекта, под `pytest-own` не исполним: голый pytest на машине не видит служб; команда `docker compose … run --rm <сервис> pytest` в профиле ломается — отчёт пишется по пути машины, которого нет в контейнере; свой `HOME` отрезает Docker от его конфигурации; подъём и снятие служб никто не делает.
6. Опыт 05.11 вне пульта на таком проекте (сервис тестов монтирует каталог кода `<каталог>` → `/var/app`, рабочий каталог контейнера `/var/app/src` = `workdir` записи): сборка образа сервиса — 177 с; `up -d --wait` служб — 6 с; один файл тестов — 22 с (~17 с — создание тестовой БД); полный набор `-n 8` — 176 с, 4601 passed; `--junitxml /var/app/.artel-report/<имя>.xml` пишется в смонтированный каталог и читается с машины; `classname` — от рабочего каталога контейнера, то есть от `workdir`, без перевода; `down -v --remove-orphans` — 1 с, остатков нет.

## Требуется

1. **Вид раннера** `runner: compose` (`PROFILE_RUNNERS`): поля — Compose-файл (путь в дереве), сервис тестов, файл окружения Compose и шаблон, из которого он копируется (пути в дереве), соответствие «каталог дерева → каталог в контейнере» (одна пара), команда pytest в контейнере (по умолчанию `pytest`). `compose` проходит те же проверки и ветки, что `pytest-own` (`reported`, `_own`, `_own_profile`, `PROFILE_OWN_RUNNER_ONLY`, `machine.path`), допустим и в `test_profile`, и в `components:`. Проверка при загрузке: пути — внутри дерева, без `..`; `report: junit-xml` обязателен; поля `install`, `tools`, `checks_local` (исполняются на машине; `orchestrator/fsm_merge_gate.py:948`) с `compose` — отказ загрузки с именем поля.
2. **Перекрытие пульта** (ADR-0023, поправка 05.11, п. 2): пульт собирает конфигурацию проекта (`docker compose -f <файл> --env-file <файл> config`), в собранной конфигурации снимает `ports` у каждого сервиса и ставит `internal: true` каждой сети, включая неявную `default`, и запускает стенд одним получившимся файлом во временном каталоге прогона (`-f <файл пульта>`, `--project-directory` — каталог Compose-файла проекта, чтобы относительные монтирования указывали в дерево). Сервис с `network_mode`, сеть с `external: true` или монтирование сокета Docker — отказ запуска с именем сервиса или сети; без перекрытия стенд не поднимается.
3. **Отчёт и пути**: отчёт — в `<каталог>/.artel-report/<прогон>.xml` под смонтированным каталогом дерева; pytest получает путь в контейнере по соответствию, пульт читает файл с машины; каталог отчётов убирается после прогона; `.artel-report` и файл окружения внесены в `info/exclude` дерева (как в `_link_deps`). Рабочий каталог контейнера — образ `workdir` по соответствию (`run -w`). Путь машины в аргументах места, не лежащий под смонтированным каталогом, — отказ запуска с именем пути.
4. **Изоляция и жизненный цикл**: имя проекта Compose — `artel-<id задачи строчными>-<прогон>` (только `[a-z0-9-]`); перед прогоном — `up -d --wait` служб, от которых зависит сервис; прогон — `run --rm`; после — всегда `down -v --remove-orphans` (у сервиса без `image:` — с `--rmi local`), в том числе по таймауту, отказу, исключению и снятию группы процессов; провал `up` — отказ прогона с выводом Compose, не красный исход тестов.
5. **Окружение Docker**: вызов `docker compose` получает конфигурацию Docker пульта явно (`DOCKER_CONFIG`, контекст или `DOCKER_HOST`) без остального `HOME`; подстановка `${…}` Compose не получает переменных пульта, кроме `DOCKER_*`; окружение pytest в контейнере — из Compose-файла и файла окружения проекта.
6. **Шаг роли** (ADR-0023, поправка 05.11, п. 3): для задачи проекта с профилем `compose` `runner.role_env` дописывает каталог программы `docker` в `PATH` и `DOCKER_CONFIG` (контекст) пульта явно и только при этом профиле; `stack.ROLE_ENV_ALLOWLIST` не меняется (он общий для всех ролей, `runner._allowlisted_env` :1186-1193); у прочих профилей и у артели окружение роли побайтно прежнее. Перечень разрешённых команд роли не меняется.
7. **Ключ итога**: смена Compose-файла, сервиса, перекрытия или соответствия каталогов меняет ключ сохранённого итога полного набора (`_report_suite_result_key`).
8. **Время**: предел прогона учитывает подъём и снятие служб (слагаемое записи или умолчание `config`); таймаут снимает и стенд (требование 4).
9. **`doctor`**: строка «забытые стенды пульта» — контейнеры и сети Compose с именем проекта `artel-*` без живого прогона: `warn` с именами, `--fix` снимает (`orchestrator/doctor/orphans.py`); строка проверки записи `compose` — Compose-файл и сервис есть в клоне, `docker compose version` отвечает и не ниже 2.0 (`fail` с версией).
10. **Документация**: `docs/codebase-map.md`; состав полей записи в ADR-0026 п. 1 — поправкой Оператора отдельно.

Критерии приёмки (обязательные тесты — без настоящего Docker: подмена вызова `docker compose` исполнителем, который записывает argv и окружение и пишет отчёт в смонтированный каталог дерева; один необязательный тест с настоящим Docker, пропускаемый при его отсутствии с именованной причиной):
- запись с `runner: compose` и полными полями загружается в `test_profile` и в `components:`; без `report: junit-xml`, с путём вне дерева, с `..`, с `install`/`tools`/`checks_local` — отказ загрузки с именем поля;
- прогон планки: argv — `docker compose --project-name artel-<id>-<…> --project-directory <каталог Compose-файла> -f <собранный файл пульта> run --rm -w <образ workdir> <сервис> pytest <цели> --junitxml <путь в контейнере> …`; путь отчёта в контейнере соответствует файлу под смонтированным каталогом; итог — по отчёту, прочитанному с машины; в собранном файле у каждой сети, включая `default`, — `internal: true`, ни у одного сервиса нет `ports`;
- Compose-файл с `network_mode` у сервиса, сетью `external: true` или монтированием сокета Docker — отказ запуска с именем;
- путь машины вне смонтированного каталога в аргументах места — отказ запуска с именем пути;
- `down -v --remove-orphans` с тем же именем проекта — при зелёном, красном исходе, таймауте и исключении; провал `up` — отказ прогона с текстом Compose, исход тестов не засчитан;
- два одновременных прогона (база и голова гейта неослабления) — разные имена проекта Compose; имя проекта — из id задачи строчными;
- двусторонний прогон и гейт исходов для `compose` идут веткой отчёта (`_report_run`): в argv нет `-p <плагин пульта>`, в окружении — нет `PYTHONPATH` пульта;
- окружение вызова `docker compose` несёт `DOCKER_CONFIG` пульта и не несёт `HOME` пульта и прочих его переменных;
- окружение шага роли: у профиля `compose` — каталог `docker` в `PATH` и `DOCKER_CONFIG`; у `pytest-own`, `pult-pytest` и артели — побайтно прежнее;
- смена Compose-файла, сервиса, перекрытия или соответствия каталогов меняет ключ итога полного набора;
- `doctor`: контейнеры `artel-*` без живого прогона — `warn` с именами (подмена ответа `docker ps`); запись `compose` без Compose-файла в клоне — `fail`;
- профили `pytest-own` и `pult-pytest` — argv и окружение прогонов побайтно прежние; прежние тесты раннеров — зелёные без правки.

Безопасность тестов: обязательные тесты — без настоящего Docker; необязательный тест с Docker — только вымышленный Compose-файл с образом из локального кэша, без сети, с `down -v` в `finally`; проекты вымышленные во временной песочнице; никогда — настоящий клон и настоящий локальный слой. В текстах тестов и ТЗ — ни имён, ни адресов реальных проектов.

Существующие тесты: правка не должна сделать красным ни один существующий тест; если краснеет — эскалация с именем теста, без правки.

Зоны: `orchestrator/targets.py`, `orchestrator/project_profile.py`, `orchestrator/acceptance.py`, `orchestrator/advance_gates/two_sided.py`, `orchestrator/advance_gates/test_integrity.py`, `orchestrator/runner.py` (только `role_env` для профиля `compose`), `orchestrator/doctor/project_checks.py`, `orchestrator/doctor/orphans.py`, `orchestrator/doctor/cli.py` (регистрация строк и `--fix`), `orchestrator/config.py` (только умолчание слагаемого времени подъёма), `docs/codebase-map.md`, `tests/` (долгоживущие файлы задачи).

Только чтение: `orchestrator/suite_run.py`, `orchestrator/mutation_run.py`, `orchestrator/advance_gates/outcome_integrity.py`, `orchestrator/reporters/outcome.py`, `orchestrator/fsm_merge_gate.py`, `orchestrator/stack.py`, `docs/adr/0023-*.md`, `docs/adr/0026-*.md`.

Не входит:
- сборка и кэш образов (сборку при необходимости делает Compose);
- мутационный прогон в контейнере (`mutation_run`) — если аналитик найдёт, что без него гейт мутаций не исполним, — эскалация с перечнем;
- правки ADR-0023 и ADR-0026 — Оператором;
- раннеры не на pytest; недоверенные проекты (D1б).

# SPEC: Codebase-map пульта автогеном

## Контекст

Роадмап §2 закладывает «codebase-map пульта автогеном — $15» как часть
брифа разработчика фазы A: карта нужна как машиночитаемый вход брифа
разработчика и среза для analyst, без блужданий по репозиторию.
ADR-0003 3б задаёт принцип свежести производных знаний: карта несёт
метку источника (`built_at_sha`) и никогда не выдаётся за актуальную
молча, если источник ушёл вперёд.

Место хранения карты ТЗ явно оставляет на решение analyst (со ссылкой
на ADR-0003 3а/3д). Решение: карта живёт в git-отслеживаемом файле
пульта — `docs/codebase-map.md`, а не в `.artel/` (целиком в
`.gitignore` пульта). Основание — само же ТЗ: генератор запускается
в CI после мержа в main и там же обязан ловить стухшую карту сверкой
`built_at_sha` с head; CI GitHub Actions пульта чекаутит только
git-историю репозитория и не видит `.artel/` (там нет remote и он не
коммитится, ADR-0003 3д) — персистентность и сверка между прогонами CI
возможна только для файла, закоммиченного в отслеживаемую историю.
Догфуд-исключение ADR-0003 3д (артефакты артели — в ветках задач
пульта, как в Фазе 0, до A7) касается первички задач (`tasks/<id>/`);
для производного знания уровня пульта, потребляемого его же CI,
аналогичная логика даёт тот же git-отслеживаемый дом — `docs/`, где
уже лежат `design.md`, `roadmap.md`, `adr/`.

## Требования

1. Скрипт детерминированно строит карту репозитория пульта: перебирает
   модули верхнего уровня (без рекурсии во вложенные директории)
   `orchestrator/*.py`, `scripts/*.py`, `tests/*.py`; никаких вызовов
   LLM в процессе генерации.
2. Для каждого модуля карта несёт: краткое назначение (первая строка
   docstring модуля; если docstring отсутствует — явная пометка
   «нет docstring», а не пропуск модуля), список его публичных функций
   верхнего уровня (имя не начинается с `_`) и связи импорта с другими
   модулями из того же перечня (кто из перечня импортирует этот модуль
   и кого импортирует он).
3. Выход генератора — один markdown-файл `docs/codebase-map.md`
   с YAML-frontmatter, несущим поле `built_at_sha` — git-sha HEAD
   пульта на момент генерации (ADR-0003 3б).
4. Формат файла — машинно-срезаемый: карта разбита на секции по
   модулям с единообразными машиночитаемыми заголовками, по которым
   можно программно вырезать срез одного модуля без парсинга всего
   документа.
5. Генератор запускается CI-джобом после мержа в main.
6. Провал генерации в CI-джобе (исключение, ненулевой код возврата
   скрипта) валит джоб — не проходит молча.
7. Стухшая карта детектируется CI-джобом (решение Оператора 25.08);
   «стухла» = между `built_at_sha` и head есть изменения отображаемых
   модулей перечня — не любое расхождение sha (см. AC-9); не требует
   ручной сверки «на глаз».

## Критерии приёмки

AC-1. Запуск генератора на дереве исходников пульта создаёт ровно один
markdown-файл `docs/codebase-map.md`.

AC-2. Frontmatter файла содержит поле `built_at_sha`, равное git-sha
HEAD пульта на момент запуска генератора.

AC-3. Файл несёт по одной секции на каждый `.py`-модуль верхнего
уровня `orchestrator/`, `scripts/`, `tests/` (без захода во вложенные
директории и без строгого требования к докстрингу — модуль без
docstring попадает в карту с пометкой «нет docstring»).

AC-4. Секция модуля содержит: краткое назначение (первую строку его
docstring или пометку «нет docstring»), список его публичных функций
верхнего уровня (имя не начинается с `_`) и список модулей из перечня
AC-3, с которыми есть связь импорта (кто из перечня импортирует этот
модуль, кого импортирует он).

AC-5. Повторный запуск генератора без изменений в дереве исходников
и без изменения git-sha HEAD даёт байт-в-байт идентичный вывод (кроме
поля `built_at_sha`, если сам HEAD изменился) — генерация не
обращается к LLM и не содержит недетерминированных элементов (порядок,
таймстемпы помимо `built_at_sha` и т.п.).

AC-6. Секции файла размечены единообразными машиночитаемыми
заголовками по модулю, позволяющими программно вырезать срез одного
модуля без разбора всего документа целиком.

AC-7. В CI (`.github/workflows/`) есть джоб, который запускает
генератор после мержа в main.

AC-8. Ненулевой код возврата генератора в этом джобе завершает джоб
неуспехом (red CI), не проходит молча.

AC-9. В CI-джобе (том же, что запускает генератор, — решение
Оператора 25.08; сверка при потреблении по ADR-0003 3б придёт
с задачей брифа) существует проверка стухшей карты: карта стухла,
если между `built_at_sha` закоммиченной `docs/codebase-map.md`
и текущим head есть изменения отображаемых модулей
(`orchestrator/*.py`, `scripts/*.py`, `tests/*.py`); стухшая карта
валит джоб. Сравнение sha на равенство не используется — структурно
невыполнимо: коммит, обновляющий карту, не может нести собственный
sha (находка ревью 25.08, итерация 1). Без визуального контроля.

## Не входит

- Семантические аннотации карты агентом/LLM по диффу (упомянуты
  в ADR-0003 3б как возможное будущее развитие гибридной схемы) — эта
  задача даёт только детерминированный скелет.
- Публикация карты во внешнюю ветку `artel` целевого — публикация следа
  отложена целиком (ADR-0003 п.3); карта живёт только в самом пульте.
- Карты для целевых проектов вне пульта (`.artel/projects/<target>/
  knowledge/`, ADR-0003 3а) — задача только про карту самого пульта.
- Сборка брифа разработчика, который потребляет эту карту как срез, —
  отдельная задача роадмапа §2 («Бриф разработчика — $25»).
- Изменение состава защищённых путей CI (`protected-paths` job) под
  новый файл `docs/codebase-map.md` — вне зоны, если такое изменение
  не требуется технически для прохождения генератора в CI.

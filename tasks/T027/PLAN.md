# PLAN: Codebase-map пульта автогеном

## Подход

Один самостоятельный скрипт `scripts/codebase_map.py`, запускаемый как
процесс (тот же паттерн, что `scripts/guard.py`): без импортов из
`orchestrator`, читает дерево от текущего рабочего каталога (не от
абсолютного пути пульта), не вызывает LLM. Точка входа и контракт запуска
зафиксированы приёмочным тестом (`tasks/T027/acceptance_tests/
test_codebase_map.py`, докстринг) — это не изобретение разработчика,
а уже залоченный вход, под который чинится код.

Разбор модулей — через `ast.parse` (статический анализ, без `exec`/
`import` целевых файлов: код задачи не должен исполняться при построении
карты чужого дерева). Для каждого модуля:
- назначение — первая строка `ast.get_docstring(tree)` или пометка
  «нет docstring» (буквально это словосочетание — так его ищет тест);
- публичные функции — `FunctionDef`/`AsyncFunctionDef` из `tree.body`
  (только верхний уровень, не `ast.walk`, иначе поймаем методы классов
  и вложенные def'ы), имя без `_` в начале, отсортированы по имени;
- связи импорта — `ast.walk` (импорт может быть под `if`/`try`, как в
  части модулей оркестратора) с разбором `Import`, `ImportFrom` уровня 0
  (абсолютный) и уровня 1 (`from . import x` — единственный вид
  относительного импорта, который вообще возможен без захода в
  подпакеты, раз карта не рекурсирует); связь резолвится только внутри
  перечня модулей карты (не сторонние библиотеки).

Порядок обхода: `orchestrator/*.py`, затем `scripts/*.py`, затем
`tests/*.py`, файлы внутри каждой директории — по имени. Порядок
фиксированный и не зависит от файловой системы (glob + `sorted`) —
основа детерминизма AC-5.

Формат вывода: YAML-frontmatter с единственным полем `built_at_sha`
(никаких таймстемпов — иначе AC-5 недостижим), затем по одной секции
`## <относительный/путь.py>` на модуль в порядке обхода. Уровень
заголовка одинаков у всех секций (AC-6): заголовок содержит полный
относительный путь — этого достаточно, чтобы имя файла (по которому режут
тесты и предполагаемый бриф-потребитель) встречалось ровно один раз и
попадание внутрь чужой секции было исключено программной резкой
по заголовку следующего уровня.

CI (предложение для Оператора — правка `.github/` вне права роли
`developer`, см. «Эскалация»): новый джоб `codebase-map` в
`.github/workflows/ci.yml`, ограничен
`if: github.ref == 'refs/heads/main'` (не трогает существующий триггер
`on: push: branches: [main, task/**]` — задача явно выводит правку
защищённых путей из зоны, если это не нужно технически, а джоб можно
добавить без правки триггера). Два шага без глушения ошибок
(без `continue-on-error`, `|| true`, `|| exit 0` — AC-8 это статически
проверяет по всему блоку джоба):
1. запуск генератора (`python3 scripts/codebase_map.py`) — нулевой код
   возврата не гарантирован конструкцией шага, GH Actions сам роняет джоб
   на ненулевом коде;
2. сверка: `built_at_sha` из **закоммиченной** версии карты (`git show
   HEAD:docs/codebase-map.md`, а не только что перезаписанного шагом 1
   файла в рабочей директории — иначе сверять было бы нечего) против
   `git rev-parse HEAD` этого же запуска; расхождение — `exit 1`.

Известное свойство этой сверки (см. «Риски»): она структурно не может
быть равенством для коммита, который САМ обновляет карту (git-sha
коммита нельзя вычислить заранее и вписать в его же дерево) — то есть
сверка будет валить джоб на любом пуше в main, где карта не была
перегенерирована в том же коммите. Это соответствует буквальному тексту
AC-9 и статической природе приёмочного теста (текстовый разбор YAML, не
симуляция реального прогона), но ограничивает практическую полезность
гейта до «всегда красный, пока кто-то вручную не перегенерит и не
закоммитит» — не входит в зону этой задачи чинить (частичная сверка при
потреблении карты — предмет задачи брифа разработчика, см. SPEC
«Материалы» и докстринг приёмочного теста).

## Влияние на систему

Веткой задачи затронуты только: новый `scripts/codebase_map.py`, новый
`tests/test_codebase_map.py`, новый (сгенерированный) `docs/codebase-map.md`
и артефакты `tasks/T027/`. `.github/`, `orchestrator/`, `gates.yaml`,
`roles.yaml`, `templates/`, `skills/` не тронуты — правка `.github/`
(джоб CI из требований 5–7) вынесена в предложение для Оператора выше
и не входит в diff этой ветки (см. «Эскалация»).

`docs/codebase-map.md` — новый файл в git-отслеживаемой истории пульта
(не `.gitignore`, не `.artel/`), консистентно с ADR-0003 3д и остальными
`docs/*.md`. Он не входит в защищённые пути `protected-paths`
(`^(gates\.yaml|roles\.yaml|\.github/|templates/|skills/|tests/test_invariants\.py|docs/invariants\.md)`)
и не требует их правки — задача этого не просит (SPEC «Не входит»).

Ни один существующий тест, гейт, лимит или guard не ослаблен и не удалён.
Обратимость: откат — `git revert` коммита ветки (два новых файла кода,
один сгенерированный markdown, артефакты задачи).

## Риски

- Сверка built_at_sha (шаг 2, AC-9) структурно не может быть «зелёной»
  для коммита, который сам обновляет карту (см. «Подход» выше) — джоб
  будет красным на большинстве пушей в main, пока карта не перегенерена
  отдельным последующим коммитом. Реализовано буквально по AC-9 и
  проходит залоченный приёмочный тест (статический текстовый разбор
  YAML); более мягкая семантика (например, сверка по дереву источников,
  а не по sha коммита) — вне зоны этой задачи, не предмет SPEC/AC.
- `ast.parse` падает на синкаксически битом `.py`-файле в перечне —
  исключение, ненулевой код возврата (это допустимый по требованию 6
  режим отказа генератора, не «тихий проход»).

## Эскалация

**Вопрос.** Требования 5–7 (AC-7, AC-8, AC-9) требуют нового джоба в
`.github/workflows/ci.yml`. Правка `.github/` — по `conventions-core`
(«Никогда: ... правка `gates.yaml` / `roles.yaml` / `.github/` /
`templates/` / `skills/` — эти пути меняет только Оператор отдельным
MR») и по прямому прецеденту этого же репозитория (`tasks/T010`,
требование 5 «CI: protected-paths на новые файлы» — тот же класс правки,
решено идентично: эскалация → коммит Оператора `0e44e01` в `main` вне
ветки задачи, ветка `.github/` не трогала, `tasks/T010/PLAN.md:141-146`)
— вне права роли `developer`. Прошу Оператора внести правку `ci.yml`
(вариант ниже) отдельным коммитом в `main`, аналогично `0e44e01`.

Предлагаемый джоб (раздел «Подход» выше содержит обоснование каждого
решения; текстовые паттерны сверены с локальными приёмочными тестами
`tasks/T027/acceptance_tests/test_codebase_map.py::CiWorkflowTest`,
AC-7..9 зелёные на этом тексте локально до коммита в CI):

```yaml
  codebase-map:
    name: Codebase-map пульта — генерация и сверка свежести
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Генератор карты (провал генерации валит джоб, AC-8)
        run: python3 scripts/codebase_map.py
      - name: Сверка built_at_sha закоммиченной карты с head (AC-9)
        run: |
          HEAD_SHA=$(git rev-parse HEAD)
          MAP_SHA=$(git show "HEAD:docs/codebase-map.md" 2>/dev/null | sed -n 's/^built_at_sha:[[:space:]]*//p' | head -1)
          if [ "$MAP_SHA" != "$HEAD_SHA" ]; then
            echo "::error::закоммиченный docs/codebase-map.md устарел: built_at_sha=$MAP_SHA, head=$HEAD_SHA. Перегенерируй python3 scripts/codebase_map.py и закоммить."
            exit 1
          fi
```

**Контекст.** Сделано в ветке `task/t027-codebase-map-pulta-avtogenom`:
`scripts/codebase_map.py` (генератор, AC-1..6 приёмочных тестов зелёные),
`tests/test_codebase_map.py` (юнит-тесты функций разбора), `docs/codebase-map.md`
(пример вывода на дереве пульта). `scripts/guard.py` на артефактах задачи —
чисто. Полный `tests/` — 518 тестов, 3 падения в `test_multitarget.py`
(`RoleEnvTest`, локальный `GIT_COMMITTER_EMAIL`) не от этой ветки,
воспроизводятся и на `main` без изменений этой задачи.

**Блокирует.** Требования 5, 6, 7 SPEC (AC-7, AC-8, AC-9) — без коммита
Оператора в `.github/workflows/ci.yml` эта часть SPEC не может быть
закрыта веткой задачи. После коммита Оператора в `main` ветка
перебазируется на него (по образцу `tasks/T010`), `.github/` из зоны
задачи исключается, PLAN.md переводится в `ready`.

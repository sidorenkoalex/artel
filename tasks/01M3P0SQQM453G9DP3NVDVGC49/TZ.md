# ТЗ: Долгоживущие файлы test_author: признаки различают временную копию и настоящий репозиторий, прогон в изолированной выгрузке, запрет пропусков (ADR-0020 п.2)

# ТЗ: Долгоживущие файлы test_author — признаки различают временную копию и настоящий репозиторий; прогон в изолированной выгрузке; запрет пропусков

Источник: решение Оператора 29.09.2026; ADR-0020, пункт 2 в редакции
Оператора deb76fd4 (origin/main, 29.09.2026; пин пульта на 9f80df46 —
редакция может отсутствовать в базе ветки, текст пункта 2 читать через
`git show origin/main:docs/adr/0020-long-lived-acceptance-tests-in-tests.md`). Наблюдение: задача
01M3NSZ4YWZW9SD5Y6H62ATGRV (ADR-0020, задача 3) — test_author пометил
все 7 файлов планки «Группа: разовый», объяснив это тем, что сценарии
строят ветку документов через `artifact_branch` и адресуют
`tasks/<id>/acceptance_tests/`, а это признаки, запрещённые
долгоживущему файлу. Долгоживущих файлов у задачи ноль.

Факты (origin/main):
- `scripts/guard.py::long_lived_sign_hits` отмечает признак `tasks/`
  у ЛЮБОЙ строковой константы, содержащей `tasks/`; признак «git-модуль»
  — у любого импорта `orchestrator.gitcmd` и `orchestrator.artifact_branch`;
  признак «git-вызов» — у любого вызова git через `subprocess`/`os.system`.
  Где указывает путь и какой репозиторий видит git, проверка не различает.
- `skills/test-authoring.md` (раздел о долгоживущем файле) повторяет
  запрет в той же безусловной форме: «ни литерала `tasks/`, ни
  идентификатора задачи, ни `gitcmd`/`artifact_branch`, ни вызова git
  через `subprocess`».
- Тесты пульта проверяют поведение, предмет которого — каталог задачи и
  ветки git (amend-tests, чекпоинт, гейты переходов). Такие тесты
  строят временную копию репозитория песочницей `tests/sandbox.py`
  (`config.ROOT`, `config.TASKS` и прочие из `ALL_CONFIG_ATTRS`
  подменены временным каталогом). Для них нынешние признаки делают
  группу «долгоживущий» недостижимой.
- Близкое различие уже есть в соседнем правиле:
  `scripts/guard.py::scan_artifact_disk_reads` отличает путь, отсчитанный
  от временного каталога (`self.tdir`, `tempfile`), от пути, якоренного
  на рабочую копию (`Path(__file__)`, `config.ROOT`/`config.TASKS`,
  литерал с началом `tasks/`).

Требуется:
1. Признаки долгоживущего файла запрещают привязку к настоящему
   репозиторию и к фактам задачи, а не упоминание путей и git как
   таковых:
   - номер задачи — запрещён, как сейчас;
   - путь `tasks/…`, отсчитанный от корня настоящего репозитория
     (`Path(__file__)` и его родители, `config.ROOT`/`config.TASKS` вне
     песочницы, относительный путь без явного временного каталога) —
     запрещён;
   - путь `tasks/…`, составленный от временного каталога (`self.tdir`
     классов `tests/sandbox.py`, `tempfile`), и строковый литерал
     `tasks/`, передаваемый публичной функции пульта как часть
     сценария в песочнице, — разрешены;
   - `gitcmd`/`artifact_branch` и вызовы git разрешены, когда тест
     работает в временной копии репозитория песочницы; запрещены
     обращения к истории и веткам настоящего репозитория: разница с
     базовой веткой (`gitcmd.diff_base`, `diff_base_source`,
     `merge-base`), ветка или артефактная ветка задачи по её номеру,
     git без указания каталога временной копии.
   Точную статическую формулировку каждого признака (какие формы кода
   считаются привязкой к временному каталогу) SPEC выводит из кода
   `tests/sandbox.py` и `scan_artifact_disk_reads` и перечисляет
   списком. Где статически различить нельзя, признак остаётся
   запрещающим, а SPEC называет такую форму.
2. Прочие признаки (sys.path, импорт вне перечня, закрытые имена, patch
   закрытого, `obj._x`, «Ловит мутацию» у каждого метода) не меняются.
   Поведение задач 01M3N0BWYQ9KHVN41Z4G72706R и
   01M3N3Z1ZHTGMSQZ4SNRYNJ2SJ (перечень сумм, гейт «только добавление»,
   сверка на переходах) не ослабляется.
3. Текст отказа по признаку `tasks/` и git называет, что именно
   запрещено (привязка к настоящему репозиторию), и как переписать
   (путь от `self.tdir` песочницы).
4. `skills/test-authoring.md`: раздел о долгоживущем файле — в
   соответствии с требованиями 1, 6 и 7, с одним образцом допустимого теста
   пульта в песочнице (ветка документов во временном каталоге). Правка
   скила — приложением к PLAN (защищённый путь, применяет пульт на
   мерже).
5. Тесты в `tests/`: для каждого признака требования 1 — пара
   «запрещённая форма даёт признак / разрешённая форма в песочнице не
   даёт», с заявкой «Ловит мутацию» у каждого метода. Отдельный тест:
   файл, строящий ветку документов в временной копии песочницы и
   проверяющий `tasks/<id>/acceptance_tests/` в ней, проходит проверку
   долгоживущего файла.
6. Проверка запуском. На выходе из `tests_writing` и на гейте мержа
   (после подтяжки `main`) пульт прогоняет долгоживущие файлы задачи в
   изолированной выгрузке кодовой ветки: `git archive` головы ветки во
   временный каталог — без `.git` и без `tasks/`; рабочий каталог и
   `HOME` — временные; `GIT_CEILING_DIRECTORIES` не пускает git к
   настоящему репозиторию. Падение или ошибка сбора там — отказ
   перехода с именем файла и метода и подсказкой «тест привязан к
   настоящему репозиторию — строй копию через tests/sandbox.py».
   Прогон касается только долгоживущих файлов задачи; прочий порядок
   прогонов не меняется. Где в коде выход из `tests_writing` и гейт
   мержа уже гоняют планку и перечень, SPEC находит по коду и встраивает
   прогон туда, не дублируя.
7. Запрет пропусков. Долгоживущий файл не содержит `skipTest`, `skipIf`,
   `skipUnless`, `unittest.skip`, `pytest.skip`, `pytest.mark.skip*`
   (новый признак проверки по тексту). Кроме того, отчёт прогона
   требования 6 разбирается: пропущенный тест долгоживущего файла —
   отказ перехода, даже если пропуск вызван через вспомогательную
   функцию.
8. Тесты в `tests/` на требования 6 и 7: долгоживущий файл, читающий
   настоящий репозиторий окольным путём, который проверка по тексту не
   ловит, отклоняется прогоном в выгрузке; честный файл на
   `tests/sandbox.py` проходит; файл с пропуском — отказ по тексту;
   пропуск через вспомогательную функцию — отказ по отчёту. У каждого
   метода «Ловит мутацию: …».
9. Проверка канарейкой — после мержа, вне задачи (сессия ассистента).

# ТЗ: Lease задачи: advisory-замок параллельных сессий

Lease задачи — advisory-замок параллельных сессий (строка P3, кластер «параллельные сессии»; решение Оператора 27.08).

Проблема: на пульте реально работают две и более сессии одновременно, и ничто не мешает двум сессиям мутировать одну задачу: инцидент 26.08 — перезапись tasks/T036/TZ.md сессией с устаревшим срезом дерева. Нужен именованный отказ вместо тихой гонки.

Что сделать: таблица leases (task_id, session_id, pid, hostname, heartbeat_ts) в state.db. Мутирующие команды CLI (run, auto, advance, approve, reject, kill, budget) перед работой берут lease своей задачи: свободна или свой lease — захват/продление heartbeat'ом; чужой ЖИВОЙ lease — именованный отказ («задачу ведёт сессия X с host Y, heartbeat N сек назад»); чужой ПРОТУХШИЙ (heartbeat старше порога, константа в config) — перехват с записью в журнал. Auto продлевает heartbeat на каждом шаге цикла. Завершение команды освобождает lease (а протухание страхует от смерти без освобождения).

Границы: lease — advisory-замок CLI, НЕ второй конечный автомат: истина состояния — FSM в tasks.state; lease не влияет на переходы, только на право сессии исполнять команды. Читающие команды (show, status, log) lease не требуют. Doctor: lease с мёртвым pid на этом host — алерт kind=incident (родня watchdog-исследованию). Никакие существующие гейты/инварианты не ослабляются.

Критерии приёмки (ориентир): (1) вторая сессия, зовущая мутирующую команду по задаче с чужим живым lease, получает именованный отказ, состояние задачи не меняется; (2) та же сессия (session_id совпал) работает без препятствий, heartbeat продлевается; (3) протухший lease перехватывается с записью в журнал; (4) завершение команды освобождает lease; (5) читающие команды работают без lease; (6) doctor заводит incident на lease мёртвого процесса; (7) существующий набор тестов зелёный.

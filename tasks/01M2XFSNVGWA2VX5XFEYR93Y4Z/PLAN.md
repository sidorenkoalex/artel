# PLAN: Гейт зон при выданном мандате без раздела PLAN: auto запускает developer вместо остановки

## Подход

Три точки правки, ровно по зонам SPEC; `orchestrator/brief.py` и
`orchestrator/fsm_advance.py` не трогаются (проверено чтением:
`store.refusal_history` отбирает записи по префиксу «переход отклонён»,
`brief.advance_refusal_history` вычитает только два литерала
`_ROLE_NOT_FINISHED_REFUSAL_ACTIONS` — новое действие в бриф попадает
без правки).

1. **Гейт зон различает причину** (`orchestrator/advance_gates/zones.py`).
   Мандат `_answer_zones_mandate` читается ВСЕГДА, когда есть файлы вне
   зон (сегодня — только внутри ветки `extension_paths is not None`).
   Существующая ветка исключения AC-3 остаётся дословно; после неё, если
   ВСЕ оставшиеся `out_of_zone` покрыты мандатом (та же формула префикса
   `_touches_zone`), гейт отказывает новым действием
   `ZONES_MANDATE_WITHOUT_PLAN_REFUSAL_ACTION` = «переход отклонён: гейт
   зон — мандат есть, раздел PLAN не оформлен»; в `detail` — те же файлы
   диффа и база сравнения, что в прежнем тексте, плюс перечень путей
   мандата и причина («раздел отсутствует» / «не совпадает с мандатом:
   в разделе …»); `hint` — «оформи раздел «## Расширение зон» в PLAN.md
   со строкой «Пути: <пути мандата>» …». Мандата нет или он покрывает не
   все пути — прежний отказ, текст/подсказка байт-в-байт (ветка кода не
   меняется).

2. **Классификация в `auto._pre_advance_step`** (`orchestrator/auto.py`).
   Новое действие в `in_dev` исключается из `other_class_refusal` (как
   уже исключено «дерево не на ветке задачи») — цикл возвращает `None`,
   роль запускается, стоп-кран «два одинаковых» на него не смотрит
   (AC-3). Защита от кружения (AC-5) — по журналу, не по флагу цикла:
   приёмочный тест AC-3 зовёт `_pre_advance_step` дважды подряд без шага
   роли и ждёт `None` оба раза, значит различать надо именно «был ли
   завершённый шаг роли МЕЖДУ предыдущим таким же отказом и текущим».
   Помощник `_role_step_between_repeated_refusals(rows, journaled_before,
   action, role)` идёт по журналу назад от текущего отказа до предыдущего
   отказа того же действия (граница — любая запись `state -> …`, как у
   `store.refusal_history`) и отвечает, встретилась ли между ними запись
   `agent run finished` роли. Встретилась — тот же `Stop`, что и сегодня
   у двух одинаковых отказов (`f"{refusal} — {hint}"`, hint «почини
   причину и повтори artel.py advance <id>»). Константа действия
   импортируется из `advance_gates.zones` (цикла импорта нет: `auto ->
   fsm -> fsm_advance -> advance_gates.zones` уже существует).
   `ROLE_NOT_FINISHED_REFUSAL_ACTIONS` не расширяется намеренно: его
   копия в `brief.py` фильтрует бриф, а новое действие роль ОБЯЗАНА
   прочитать (AC-4) — в комментарии к перечню это оговорено.

3. **Подсказка `zones-extend`** (`orchestrator/answer.py`): в ветке «раздел
   PLAN не совпадает» печать дополняется строкой «дальше: artel.py auto
   <id> — цикл сам запустит developer, тот оформит раздел». Запись
   журнала «раздел PLAN отсутствует — разработчик добавит на следующем
   шаге» и условие обновления `zones_extension` не меняются (её ждёт
   планка 01M287TPG0HAVXS8CHBCY679WN, AC-6).

Расхождение с SPEC в именовании перехода: SPEC говорит «переход
`in_dev -> review`», фактически с ADR-0015 гейт зон стоит на
`in_dev -> verifying` (docs/invariants.md, инвариант 36); планка задачи
моделирует переход своей мини-FSM в `review`, юнит-тест в
`tests/test_auto_cycle.py` проверяет выход из `in_dev` в `verifying`
настоящим `cmd_advance`. Бюджет SPEC (35) не пересматривается: три файла
кода, три файла тестов.

## Шаги

1. `orchestrator/advance_gates/zones.py`: константа
   `ZONES_MANDATE_WITHOUT_PLAN_REFUSAL_ACTION`, чтение мандата вне ветки
   `extension_paths`, новая ветка отказа с перечнем путей мандата и
   подсказкой про раздел PLAN.
2. `orchestrator/auto.py`: импорт константы, помощник
   `_role_step_between_repeated_refusals`, классификация в
   `_pre_advance_step` (класс требования 3 + `Stop` при повторе после
   шага роли), комментарии к `ROLE_NOT_FINISHED_REFUSAL_ACTIONS`.
3. `orchestrator/answer.py::_cmd_zones_extend`: подсказка «дальше:
   artel.py auto <id>».
4. Юнит-тесты: `tests/test_zones_gate.py` (класс
   `ZonesGateMandateWithoutPlanSectionTest`: раздел отсутствует / не
   совпадает / мандат покрывает не все / мандата нет — байт-в-байт
   прежний текст); `tests/test_auto_cycle.py` (класс
   `AutoRunsDeveloperOnMandateWithoutPlanSectionTest`: сценарий
   инцидента настоящим `cmd_advance` с мандатом на диске — один шаг
   developer, история с путями мандата в брифе, переход в `verifying`
   после оформленного раздела, `Stop` после шага без раздела, `Stop` без
   мандата без единого шага; плюс два прямых вызова `_pre_advance_step`
   без шага роли между ними); `tests/test_answer.py`
   (`test_plan_without_section_names_auto_as_the_next_command`).
5. `python3 scripts/codebase_map.py`, прогон планки задачи и трёх
   названных наборов, `scripts/guard.py` на PLAN.md, коммит.

## Влияние на систему

- Гейт зон (инвариант 34 docs/invariants.md) не ослабляется: дифф вне
  зон без совпадающего раздела PLAN по-прежнему ОТКАЗЫВАЕТ — меняется
  только имя действия и текст в одном подслучае (мандат покрывает всё).
  Безусловный отказ защищённого пути стоит ДО этой ветки и не тронут.
  Обновление `zones_extension` в БД происходит только там же, где и
  раньше (совпадающий раздел + мандат).
- Стоп-кран T038 «два подряд одинаковых отказа» для всех прежних
  действий работает как раньше (`AutoStopsOnRepeatedAdvanceRefusalTest`
  зелёный); для нового действия его заменяет журнальная проверка «шаг
  роли между отказами» — роль получает ровно один гарантированный шаг,
  дальше тот же `Stop`. Стоп-кран `AUTO_STALL_STEPS_LIMIT` считает шаг
  с новым отказом как холостой, как и любой другой.
- `brief.py`, `fsm_advance.py`, `store.py` не изменены; новое действие
  входит в бриф через существующий фильтр по префиксу.
- Дополнительный вызов `_answer_zones_mandate` (два-три git-вызова на
  артефактной ветке) появляется только на пути отказа гейта зон — на
  проходящем переходе без файлов вне зон вызовов не прибавляется.
- Откат — revert одного merge-коммита; схема БД и артефакты не
  затронуты.

## Риски

- Мандат, покрывающий пути через префикс директории (например `docs/`),
  засчитывается покрытием — та же формула, что уже применяет исключение
  AC-3 через `_touches_zone`; расширять её на «равенство строк» значило
  бы разойтись с существующим исключением.
- Мандат читается с артефактной ветки; в лёгких песочницах без git
  `ls_tree_files` отвечает `None` и мандат пуст — прежний путь отказа,
  никаких новых исключений.

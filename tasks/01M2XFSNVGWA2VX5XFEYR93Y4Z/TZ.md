# ТЗ: Гейт зон при выданном мандате без раздела PLAN: auto запускает developer вместо остановки

Источник: копилка docs/backlog.md, строка П1 13.09 «Отказ гейта зон при
уже выданном мандате оставляет задачу без движения». Решение Оператора
19.09: заводить сейчас, до волны 5.

Инцидент 13.09, задача 01M2CYQR03 (журнал пульта):
- 09:38 — ANSWER-1 Оператора несёт строку «Расширение зон разрешено:
  orchestrator/advance_gates/…» (мандат на семь файлов нового пакета).
- 10:13:20 — первый шаг developer закончен ($7.76); PLAN.md ещё без
  раздела «## Расширение зон».
- 10:13:21 и 10:13:22 — два подряд отказа «переход отклонён: гейт зон»
  одним текстом → auto остановлен: «почини причину и повтори advance».
- 10:14:52 — auto перезапущен: снова два отказа, снова остановка. Шаг
  developer не запускается ни разу.
- 11:13:58 — через час Оператор запустил роль командой `run`; developer
  за один шаг ($2.01) дописал раздел PLAN, дальше штатно.
  Потеря: час простоя задачи, ручной запуск, ложный «стоп-кран»
  двух одинаковых отказов, хотя причина лежит в артефакте роли.

Причина (по коду):
- `orchestrator/advance_gates/zones.py::_zones_gate`: исключение AC-3
  срабатывает только когда PLAN.md уже несёт раздел «## Расширение
  зон» с путями, покрытыми мандатом из ANSWER-*.md. Мандат есть, раздела
  нет — обычный отказ «гейт зон» без различия причины.
- `orchestrator/auto.py::_pre_advance_step`: в `in_dev` любой
  журналируемый отказ иного класса (кроме «дерево не на ветке»)
  считается требующим рук Оператора; два подряд одинаковых — `Stop`
  (SPEC T038), шаг роли не запускается. Отказ «мандат есть, раздела
  PLAN нет» устраняет именно роль (PLAN.md — её артефакт), то есть это
  класс требования 3 («роль ещё не закончила»), а не требования 4.
- `orchestrator/answer.py::_cmd_zones_extend` обновляет
  `zones_extension` только если раздел PLAN уже совпадает с путями;
  иначе журналирует «раздел PLAN отсутствует — разработчик добавит на
  следующем шаге», но следующий шаг auto не даёт (см. выше).

Требуется:
1. Гейт зон различает причину: если все пути вне зон покрыты мандатом
   Оператора из ANSWER-*.md (`_answer_zones_mandate`), а раздел
   «## Расширение зон» PLAN.md отсутствует или не совпадает — отказ
   журналируется отдельным именованным действием (например «переход
   отклонён: гейт зон — мандат есть, раздел PLAN не оформлен») с
   перечнем путей мандата и подсказкой роли «оформи раздел PLAN»; текст
   отказа без мандата не меняется.
2. `auto._pre_advance_step`: отказ этого действия в `in_dev` — класс
   требования 3: шаг developer запускается с историей отказов в брифе
   (как сегодня после reject ревью), стоп-кран «два подряд одинаковых
   отказа» на него не срабатывает. Отказ гейта зон без мандата ведёт
   себя как сегодня (Stop — решение Оператора).
3. Защита от кружения: если после шага developer тот же отказ «мандат
   есть, раздел PLAN не оформлен» повторился — вторая итерация идёт
   как сегодня (Stop по двум одинаковым отказам), роль получает ровно
   один гарантированный шаг на оформление раздела.
4. `answer._cmd_zones_extend`: подсказка после создания ANSWER без
   раздела PLAN называет команду продолжения `artel.py auto <id>`
   (цикл сам запустит developer), а не оставляет Оператора без
   следующего шага.
5. Тесты (tests/): сценарий инцидента — мандат в ANSWER, PLAN без
   раздела, auto в in_dev: шаг developer запускается, в брифе история
   отказа с путями мандата; после шага с разделом — переход в review;
   после шага без раздела — Stop как сегодня; без мандата — Stop без
   запуска роли как сегодня. Существующие `tests/test_zones_gate.py`,
   `tests/test_zones_approve.py`, `tests/test_auto_cycle.py` остаются
   зелёными.

Зоны: orchestrator/advance_gates/zones.py, orchestrator/auto.py,
orchestrator/answer.py, tests/.

Только чтение (не менять): orchestrator/brief.py (история отказов уже
попадает в бриф — проверить, что новое действие в неё входит; правка
brief.py — эскалация), orchestrator/fsm_advance.py (обёртки гейта не
меняются).

Не входит: запись раздела PLAN пультом из zones-extend (артефакт роли
пишет роль); сторож «задача в агентском состоянии без живого цикла N
минут» в doctor/watch — отдельное ТЗ (вторая часть той же строки
копилки); мандат на защищённые пути.

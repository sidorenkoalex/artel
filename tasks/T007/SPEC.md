# SPEC: Учёт стоимости шага и потолок бюджета

## Контекст
Поле tasks.budget_usd и колонка spent_usd существуют с первого дня,
но стоимость запусков не извлекается — spent_usd всегда 0.00, и потолок
бюджета не работает вовсе. По дизайну (docs/design.md §6 «Потолки»,
§10) бюджет — жёсткий лимит с алертом на 70%, а журнал шагов содержит
стоимость каждого запуска. После T005 `run` уже читает поток вывода
claude CLI — финальное событие потока содержит метаданные стоимости.

## Требования
1. По завершении запуска агента из его вывода извлекается стоимость
   шага в USD (и число токенов, если доступно) — из финального
   события потока claude CLI. Формат события изучить по фактическому
   выводу в .artel/logs/ (там лежат логи прошлых прогонов).
2. Стоимость шага пишется в журнал шагов (в detail записи
   «agent run finished») и прибавляется к tasks.spent_usd.
3. Если spent_usd после шага ≥ 70% budget_usd — предупреждение
   в консоль и запись в журнал.
4. Если spent_usd ≥ budget_usd — задача переводится в escalated
   с причиной «бюджет исчерпан»; последующий `run` по задаче
   блокируется, пока Оператор не поднимет бюджет или не закроет
   задачу. Механизм поднятия бюджета: команда `budget <id> <usd>`
   (пишет в журнал старое и новое значение, actor=operator).
5. Если стоимость извлечь не удалось (нет события, другой формат) —
   шаг НЕ считается проваленным: warning в журнал, spent_usd не
   меняется, поведение как сейчас.
6. Юнит-тесты в tests/ без реального CLI: парсинг стоимости из
   фейкового вывода, суммирование по шагам, предупреждение на 70%,
   эскалация и блокировка run при исчерпании, команда budget.

## Критерии приёмки
1. После агентного прогона `status` показывает ненулевой spent_usd,
   в `log <id>` у шага видна стоимость.
2. Задача с budget_usd меньше стоимости одного шага после прогона
   уходит в escalated, повторный `run` отказывается стартовать
   с внятным сообщением; `budget <id> <usd>` разблокирует.
3. `python3 -m unittest discover -s tests` зелёный, guard и CI зелёные.

## Не входит
- Разбивка стоимости по ролям в отдельном отчёте/дашборде.
- Изменение дефолтного бюджета задачи.
- Очистка каталога задачи при kill (отдельная задача).

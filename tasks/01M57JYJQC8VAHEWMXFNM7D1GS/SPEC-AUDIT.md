- Г1. Защищённый путь: `**/conftest.py` в `config.PROTECTED_PATHS`
  (orchestrator/config.py:763; формула `is_protected_path` :771-791 — по
  последнему компоненту в любом каталоге). Треб. 8 (SPEC.md:86-90) заказывает
  учебный проект с `backend/tests/conftest.py`. Если test_author положит
  учебный проект файлами в `tests/` (например
  `tests/fixtures/<проект>/backend/tests/conftest.py`), это правка
  защищённого пути — гейт зон откажет, а приложения PLAN SPEC не
  предусматривает. Такой файл к тому же собрал бы собственный прогон
  `tests/` артели. SPEC не требует создавать учебный проект во временном
  каталоге из кода теста; это надо записать явно.
- Г2. Невидимость остатка для git (треб. 4) при запрете лишних файлов в
  выкладке (треб. 2 «ровно те файлы») исключает `.gitignore` внутри каталога
  выкладки. Остаётся `info/exclude` общего каталога git клона проекта —
  запись в состояние клона вне рабочего дерева (общая для всех worktree
  проекта). SPEC механизм не называет — у разработчика две разумные
  реализации, и одна из них нарушает треб. 2.

## Пути обхода гейтов
- Е1. Загрязнение полного набора. Полный набор внешнего проекта идёт по
  самой рабочей копии (orchestrator/appendix_tree.py:241, :260 —
  `SuiteTree(wt, …)`), pytest собирает файлы с диска независимо от git.
  Выкладка (и её git-невидимый остаток) лежит внутри `long_lived_dir`, то есть
  внутри набора, который гоняет `run_full_suite`/`suite-run`. Сценарии:
  (а) роль запускает `suite-run` в фоне (suite_run.background) и параллельно
  `plank-run` — полный набор собирает файлы планки, красная до реализации
  планка красит «полный набор»; (б) обрыв прогона на `advance` оставил
  остаток, следующий гейт (не шаг роли — runner.py:1218 не звался) гоняет
  полный набор с планкой внутри, а `clean_tree_sha` (acceptance.py:1798)
  считает дерево чистым и сохраняет итог под sha коммита. Раньше планка
  лежала вне `workdir` и в набор не попадала. SPEC (треб. 3-5) этого не
  запрещает и критерия на это нет.
- Е2. Пустая проверка «планка не прогонялась» (М1): разработчик выполняет
  SPEC буквально, существующий тест остаётся зелёным, а свойство, которое он
  держал, больше не проверяется — тихое ослабление в обход
  `advance_gates/test_integrity.py` (тест не менялся).
- Е3. Подгонка существующих тестов (М2): если имя каталога выкладки без
  `acceptance_tests`, существующие тесты профиля красны, и разработчик
  «чинит» их правкой фильтров в tests/ — смена ожидания без раздела
  «Меняемое поведение» и без мандата.
- Е4. `long_lived_dir` вне `workdir`: SPEC (SPEC.md:48-56) не говорит, что

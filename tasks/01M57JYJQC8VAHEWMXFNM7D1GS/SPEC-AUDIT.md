## Пути обхода гейтов
- Е1. Сбой записи исключения не задан. Треб. 6 (SPEC.md:102-110) требует
  записи до выкладки, но не говорит, что делать, если `git rev-parse
  --git-path` не ответил или запись в `info/exclude` дала `OSError`.
  Реализация в духе соседнего `save_suite_result` (`except OSError: pass`,
  acceptance.py:1794-1795) выложит планку без исключения — файлы видны
  `changed_paths()`, гейту зон, а остаток после обрыва подберёт `git add -A`
  чекпоинта. Ни один AC сбой записи не моделирует. По ADR-0002
  (fail-closed) ожидаемо: отказ прогона без выкладки с текстом причины.
- Е2. Гонка дописывания общего файла. `info/exclude` общий для всех рабочих
  копий проекта (треб. 6); две задачи одного проекта, начавшие прогон
  планки одновременно, обе увидят «записи нет» и обе допишут — две
  одинаковые строки (AC-6: «ровно одна строка»). На шаге одной задачи AC-6
  это не ловит. Последствие безвредно для git (дубликат шаблона), но
  нарушает собственный инвариант SPEC «файл не растёт». Достаточно атомарной
  записи (запись+`replace` или замок) либо явного допуска Оператора.
- Е3. Конфиг проекта теперь действует на планку, в том числе `addopts`. При
  `--import-mode=importlib` в конфиге проекта каталог файла теста не
  попадает в `sys.path`, и `import _pult` планки (помощник рядом,
  треб. 2) падает; учебный проект AC-1/AC-4 с режимом по умолчанию этого не
  увидит. До правки планка внешнего проекта конфиг проекта не видела, так
  что это новое поведение. SPEC стоит назвать режим импорта риском в
  «Материалах» рядом с «import file mismatch» (SPEC.md:355-358) или решить,
  нужен ли критерий. Конфиг sled проверить не смог (каталог проекта
  недоступен на чтение из шага).

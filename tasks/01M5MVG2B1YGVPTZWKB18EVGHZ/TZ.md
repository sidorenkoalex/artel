# canary --parallel: строка «оборвана сигналом» не теряется у дочернего, тесты гонки говорят причину, GroupSignalTest не виснет

## Факты

Строка бэклога «Тесты Б-1б: зависание GroupSignalTest и непокрытая проверка имён» и две строки копилки 23.10 о неустойчивых тестах гонки SIGTERM. Мандат Оператора 23.10.2026 (дословно): «мандат на чинку двух тестов гонки SIGTERM и зависания GroupSignalTest без ослабления утверждений — даю» — покрывает правки существующих тестовых файлов (сообщения к утверждениям, помощники `run_cli` и `read_grandchild_pid`). Правка кода пульта `cmd_canary_run_task` (повтор записи, сообщение; код выхода при сбое записи — `128 + сигнал` вместо 1) — решение сессии при Операторе по правам волны G 23.10.2026. Сверено с `origin/main` 0c58e924; независимая проверка черновика 23.10 разобрала механику (25 прогонов каждого теста — гонка не воспроизвелась).

- Неустойчивые тесты: `tests/test_canary_parallel_protection.py::BaselineTest::test_parent_sigterm_leaves_canary_baseline_unchanged` (утверждение около строки 500; CI main, прогон 39913903312 на c5af4add — у `beta` исход `drive_failed` вместо «оборвана сигналом SIGTERM») и `tests/test_canary_parallel.py::StopTest::test_parent_sigterm_stops_children_and_skips_queue` (около строки 382; CI main, прогон 39954804501 — то же).
- `reach` в обоих файлах открывает канал на запись; открытие блокируется, пока дочерний не откроет канал на чтение в `hold()` внутри подменённого ведения, а ведение вызывается из `cmd_canary_run_task` уже после установки обработчика сигнала (`_interrupt_on_signal`) и записи реестра (`_write_child_record`). Гипотезы «обработчик не поставлен», «записи реестра нет», «ведение завершилось само» кодом исключены.
- `drive_failed` дочернему пишет родитель (`_finish_child` → `_report_child_failure`), когда дочерний завершился без своей строки прогона. После SIGTERM дочерний пишет строку «оборвана сигналом …» в ветке `except CanaryInterrupted` `cmd_canary_run_task` (`orchestrator/canary.py`, около :3760): `store.insert_canary_run(store.db(), …)` — открытие БД с миграцией и запись; оба дочерних пишут одновременно, ожидание блокировки SQLite — по умолчанию. Исключение в этой записи (например, «database is locked») завершает процесс без строки — вероятная причина; другая — снятие SIGKILL по сроку `PARALLEL_STOP_GRACE_SEC`. Различить их можно по выводу дочернего, который родитель печатает (`run.out`), но утверждения обоих тестов его в сообщение не выводят, и в журнале CI его нет.
- `GroupSignalTest` (`tests/test_canary_parallel_protection.py`, около :653): если внук не появился, общий помощник `run_cli` держит открытым дескриптор канала внука на запись до `thread.join()`, а `read_grandchild_pid` ждёт конца данных — тест висит до таймаута pytest; после закрытия дескриптора без внука `int(b"")` бросает `ValueError`.

## Требования

1. Диагностика (первым шагом): в двух неустойчивых тестах к утверждению о строках прогона добавляется сообщение — вывод родителя и дочерних (`run.out` / `out`). Утверждения и литералы не меняются; это дополнение сообщения, не ослабление.
2. Укрепление против одной гипотезы (настоящую причину покажет диагностика требования 1; если она окажется другой — эскалация, а не расширение задачи). Запись строки «оборвана сигналом …» дочерним в ветке `except CanaryInterrupted` `cmd_canary_run_task`: запись — через `store.insert_canary_run`, вызов `store.db()` — внутри каждой попытки; при `sqlite3.OperationalError` — не более 3 попыток подряд без `sleep` (ожидание — штатное ожидание блокировки соединения, 5 с); константа попыток — в коде. При любом исключении записи, которое не удалось преодолеть (включая не `OperationalError`), дочерний пишет в stderr «строка прогона не записана:» и полный стек (`traceback.format_exc()`) и выходит с кодом `128 + сигнал`. Родитель не меняется: эта строка попадает в его вывод через журнал дочернего, который печатает `_finish_child`; строка БД родителя — прежняя `drive_failed`. Остаточный риск (записывается в PLAN): SIGHUP во время повторов выбрасывает `CanaryInterrupted` из ветки — как и в текущем коде.
3. `GroupSignalTest`: в общем помощнике `run_cli` дескриптор канала внука на запись закрывается сразу после открытия (до `join`); `read_grandchild_pid` при пустых данных бросает `AssertionError("внук не появился")`. Утверждения теста не меняются. Известное ограничение (в PLAN): если согласующий поток не дошёл до открытия канала к концу работы родителя, неблокирующее открытие на запись падает и поток может висеть — от зависания защищает `timeout = 120` pytest.
4. Тесты (новый файл `tests/test_canary_child_row_write.py`, у каждого строка «Ловит мутацию:»):
   (а) внутри процесса: `cmd_canary_run_task` с подменами `_set_plan`, `_mark_owned_by_parent` (истина), `_run_one_task` (бросает `CanaryInterrupted(SIGTERM)`) и `store.insert_canary_run` (`side_effect`: первый вызов — `sqlite3.OperationalError("database is locked")`, затем настоящая запись) — строка «оборвана сигналом SIGTERM» записана, код выхода `128 + SIGTERM`;
   (б) то же, но сбой на всех попытках — код `128 + SIGTERM`, в перехваченном stderr «строка прогона не записана» и стек, попыток ровно 3; не `OperationalError` (например, `sqlite3.IntegrityError`) — одна попытка и то же сообщение;
   (в) `_finish_child` с поддельным дочерним (код 143, журнал со строкой «строка прогона не записана: …») — строка есть в выводе родителя, строка БД — `drive_failed`;
   (г) граница: `попытки × 3 × 5 + GROUP_TERMINATE_GRACE_SEC < PARALLEL_STOP_GRACE_SEC` (три ожидания блокировки на попытку: миграция в `store.db()`, обновление в `_ensure_canary_tables`, вставка);
   (д) `GroupSignalTest`-сценарий без внука (подмена `_GRANDCHILD` на сценарий, который сразу выходит) — `AssertionError` с «внук не появился» вокруг запуска; без срока по часам (от зависания — `timeout = 120`).
   На текущем коде (а), (б) красные (выход с кодом 1, строки нет), (в) зелёный, (г) красный (константы попыток нет), (д) красный по таймауту pytest. Мутация «дочерний не пишет строку «оборвана сигналом»» проверяется однократным прогоном тестов гонки в приёмке, не в долгоживущем файле. Генераторы нагрузки и серии повторных прогонов запрещены.
5. Прочие тесты обоих файлов не правятся; ни одно утверждение не удаляется и не ослабляется (матрица неослабления в SPEC — по каждому изменённому методу и помощнику `run_cli`).

Зоны: orchestrator/canary.py, tests/test_canary_parallel_protection.py, tests/test_canary_parallel.py, tests/test_canary_child_row_write.py, docs/codebase-map.md (перегенерация карты после правки `canary.py` по правилу соглашений)

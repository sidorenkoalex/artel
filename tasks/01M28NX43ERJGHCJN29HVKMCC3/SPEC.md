# SPEC: guard называет маркер AC-n с отступом, а не глотает его

## Контекст
`scripts/guard.py::AC_MARKER` заякорен на начало строки (`^#`): маркер
`# AC-n: manual|skip|escalate|ci`, поставленный с отступом (внутри тела
класса или функции), не распознаётся регуляркой — и никакой ошибки не
возникает. 11.09 при `amend-tests` (ADR-0014 ч.2, 01M1THKWFX) маркер
`# AC-7: manual` был поставлен с отступом вместо снятого метода —
каталог приёмки счёл AC-7 автоматически пройденным по трём оставшимся
методам, ручной проверки не потребовал. Guard обязан ловить этот случай
явно и отказывать, а не молчать.

## Требования

1. Guard при разборе `acceptance_tests/` находит строки, где текст
   `#\s*AC-(\d+):\s*(manual|skip|escalate|ci)` стоит НЕ в начале строки
   (перед `#` есть пробелы или табуляция), и считает это нарушением
   структуры с именованным текстом ошибки: «<файл>:<строка>: маркер
   '# AC-n: <вид>' с отступом не учитывается каталогом — вынеси в
   начало строки либо убери». Это отказ, не предупреждение: guard
   красный, переход `tests_writing -> in_dev` и команда `amend-tests`
   не проходят.
2. Тот же текст маркера внутри строкового литерала или докстринга
   (кавычки на той же строке до `#`, либо строка внутри тройных
   кавычек) нарушением не считается — существующий приём разбора
   докстрингов guard сохраняется; если guard не различает докстринг
   явно, допускается эвристика «строка начинается с отступа и `#`»
   (комментарий), а не любой текст, содержащий подстроку маркера.
3. Тесты (`tests/test_guard_ac_markers.py` либо существующий файл
   тестов маркеров) покрывают:
   а) маркер с отступом — именованный отказ с номером строки (мутация
      «отступ разрешён» — красная);
   б) маркер в начале строки — распознаётся как раньше (валидная
      пометка, не нарушение);
   в) упоминание «AC-2: manual» внутри докстринга/строкового литерала
      — не отказ;
   г) существующие тесты guard остаются зелёными без правки их
      утверждений.

## Критерии приёмки

AC-1. Guard при разборе `acceptance_tests/` находит строки, где текст
`#\s*AC-(\d+):\s*(manual|skip|escalate|ci)` стоит не в начале строки
(перед `#` есть пробелы или табуляция), и возвращает ошибку структуры
с текстом «<файл>:<строка>: маркер '# AC-n: <вид>' с отступом не
учитывается каталогом — вынеси в начало строки либо убери»; это отказ
guard — переход `tests_writing -> in_dev` и команда `amend-tests` на
таком дереве не проходят.

AC-2. Тот же текст маркера внутри строкового литерала или докстринга
(кавычки на той же строке до `#`, либо строка внутри тройных кавычек)
нарушением AC-1 не считается — существующий приём разбора докстрингов
guard сохраняется; допустима эвристика «строка начинается с отступа и
`#`» как признак комментария, но не срабатывание на произвольный текст,
содержащий подстроку маркера.

AC-3. Тесты `tests/test_guard_ac_markers.py` (либо существующий файл
тестов маркеров) покрывают: (а) маркер с отступом — именованный отказ
с номером строки, мутация «отступ разрешён» красная; (б) маркер в
начале строки — распознаётся как раньше, без отказа; (в) упоминание
«AC-2: manual» внутри докстринга/строкового литерала — без отказа;
(г) существующие тесты guard остаются зелёными без правки их
утверждений.

## Оценка объёма и деление

Сработавшие сигналы: «затронут инвариантный механизм» (зона задачи
включает `scripts/guard.py`, который называет строка docs/invariants.md
о том, что новые правила guard и гейтов действуют на живые задачи,
история не переписывается); «прогноз диффа не дан» (сопутствующий
сигнал — прогноз явно не указан).

Обоснование монолита: правка — одно неразрывное изменение одной
проверки маркеров (расширение `scripts/guard.py` детекцией отступа,
AC-1/AC-2) плюс её собственные юнит-тесты (AC-3, `tests/`). Разрезать
на 2-4 части нельзя без разрыва мержимости: детекция без теста
непроверяема (нечем подтвердить, что мутация «отступ разрешён» красная
— ровно то, что требует AC-3а), а тест без детекции красный по
построению — ни одна часть не мержима отдельно с зелёной планкой.

Пересечение с docs/invariants.md — не конфликт с этим инвариантом, а
его прямое применение: задача добавляет НОВОЕ правило детекции, которое
guard проверяет только вперёд, на переходах `tests_writing -> in_dev` и
`amend-tests` новых прогонов — существующие закрытые задачи (с
`docs/retro/<id>.md`) под это правило задним числом не подпадают,
backfill не требуется.

## Не входит

- Изменение формата самого маркера (`# AC-n: manual|skip|escalate|ci`)
  — правило разметки не меняется, меняется только требование к позиции
  в строке.
- Пометки внутри `tests/` (юнит-тестов оркестратора) — проверка на
  отступ касается только маркеров в `acceptance_tests/`.

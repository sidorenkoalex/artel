# ТЗ: Канарейка переживает эскалацию по бюджету и позволяет выбрать шаблон

Источник: строка копилки 27.09 «Канарейка красная не по вине
проверяемого кода»; решение Оператора 27.09. Прецедент: прогон
20260927T123258Z (шаблон canary-budget-percent-ambiguous, sha 1d9744d0)
отработал 15 шагов штатно, на третьем шаге разработчика расход $26.25
перешёл потолок задачи $25; пульт эскалировал по бюджету, канарейка
закрыла эскалацию синтетическим ANSWER, потолок не изменился, запуск
роли отказывал, после трёх проходов без прогресса задача снята —
вердикт прогона red, 85 минут. Задача вне линии провайдеров.

Факты (origin/main 1d9744d0):
- `orchestrator/canary.py::_sample_pool_templates` выбирает шаблоны
  `random.sample(files, k)` из пула (`~/.artel-canary`, четыре шаблона);
  выбрать шаблон командой нельзя. Стоимость прогона по шаблонам за
  20–27.09 — от $11.77 до $26.25.
- Эскалация в клоне закрывается синтетическим ANSWER
  Оператора-заглушки независимо от причины; эскалация «бюджет
  исчерпан» после него остаётся неисполнимой: потолок прежний,
  `auto` останавливается записью «run отказался стартовать», счётчик
  проходов без прогресса (orchestrator/canary.py:835–921) доводит до
  снятия задачи с причиной «задача не сходится».
- Потолок канареечной задачи приходит из SPEC аналитика клона (минимум
  $25 по скилу аналитика); рамка в шаблоне «canary-budget-percent-
  ambiguous» — $15. Бейзлайны шаблонов (`canary_baseline`) сняты
  06–13.09: $3.95–8.07, до смены модели ролей 19.09.
- Исходы прогона пишутся в `canary_runs` (outcome, verdict); зелёный
  прогон набора по умолчанию — условие `pin-update` (ADR-0013).

Требуется:
1. Выбор шаблона: `canary --k <N> --template <имя>[,<имя>…]` берёт
   названные шаблоны пула вместо случайных; имя — стабильное имя
   шаблона без расширения; неизвестное имя — именованный отказ до клона
   с перечнем доступных; число имён равно `--k` либо `--k` при флаге
   необязателен (выбрать в SPEC). Без флага поведение прежнее.
2. Эскалация по бюджету в клоне: причина прогона называется своим
   исходом, отличным от «задача не сходится», — например
   «исчерпан потолок задачи: $X из $Y на шаге <роль>» — и вердикт
   прогона отделяет «конвейер не сошёлся» от «шаблон не уложился в
   потолок». Годится ли такой прогон для `pin-update` — НЕ годится
   (условие ADR-0013 не ослабляется); меняется только диагноз.
3. Потолок канареечной задачи: способ не упираться в потолок на
   исправном конвейере — выбрать и обосновать в SPEC (кандидаты: потолок
   клона с запасом от бейзлайна шаблона; однократный подъём потолка
   синтетическим ответом в пределах заданного множителя, с записью в
   метриках прогона). Расход прогона по-прежнему ограничен сверху
   конечным числом, названным в коде.
4. Отчёт прогона печатает выбранные шаблоны в первой строке, до клона,
   чтобы Оператор видел, что запущено.
5. Документация: справка команды (orchestrator/artel.py) и
   docs/operator-session.md — флаг выбора шаблона и новый исход.
6. Тесты (tests/): выбор названного шаблона; отказ на неизвестное имя;
   прогон без флага выбирает как прежде (подмена случайного выбора);
   эскалация по бюджету даёт свой исход и не даёт зелёного вердикта;
   потолок по выбранному способу; существующие tests/test_canary.py,
   tests/test_canary_sets.py, tests/test_pin.py зелёные, ни один не
   ослаблен.

Зоны: orchestrator/canary.py, orchestrator/artel.py,
docs/operator-session.md, tests/.

Только чтение (не менять): orchestrator/pin.py (условие сдвига пина не
меняется), orchestrator/budget.py, orchestrator/auto.py,
orchestrator/pool_seal.py, canary/pool.sealed (пул и шаблоны не
правятся), docs/adr/, docs/backlog.md, tests/test_invariants.py.

Не входит: пересъём бейзлайнов; правка шаблонов пула; указатель связки
ключей Codex в клоне; ослабление условия `pin-update`.

Рамка: $40.

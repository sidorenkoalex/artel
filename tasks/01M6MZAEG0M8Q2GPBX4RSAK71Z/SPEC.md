# SPEC: Отчёт JUnit: путь теста в каталоге, имя которого начинается с точки

## Контекст
pytest в формате xunit2 (по умолчанию) не пишет атрибут `file`, и путь
теста восстанавливается из `classname` — точечного пути модуля. Каталог
планки внешнего проекта обязан начинаться с точки
(`orchestrator/plank_layout.py:151`, `LAYOUT_PARENT_NOT_HIDDEN`), поэтому
`classname` несёт две точки подряд: `tests..artel-plank.<id>.test_x`.
`_junit_location` (`orchestrator/reporters/outcome.py:106-133`, деление —
`:117`) и `_forge_location` (`orchestrator/reporters/outcome.py:256-268`,
деление — `:263`) делят `classname` по каждой точке: сегмент
`.artel-plank` теряет точку, файл не находится, путём записи становится
всё точечное имя (`:123-124`). Гейт сопоставляет записи с файлами планки
точным путём (`orchestrator/advance_gates/acceptance.py:251-257`,
`:335-348`), и «честный FAIL_TO_PASS» отказывает тестам планки, которые на
деле исполнены (случай 05.11; обход — `report_args` с
`-o junit_family=xunit1` в локальном слое проекта). Тесты пульта подают
поддельный отчёт с атрибутом `file`
(`tests/test_01m5aqh8m2dkbv30nby86j34a7_fail_to_pass.py:392`), поэтому
этот разбор не проверен.

## Требования

1. `_junit_location` и `_forge_location` делят `classname` по точкам так,
   что пустой сегмент (точка в начале `classname` или точка сразу после
   другой точки) не разделитель: точка присоединяется к следующему
   сегменту как начало имени каталога:
   `tests..artel-plank.<id>.test_x` → `tests/.artel-plank/<id>/test_x.py`,
   `.artel-plank.<id>.test_x` → `.artel-plank/<id>/test_x.py`. Имя
   каталога из двух и более точек в начале (`..x`) разбирается тем же
   правилом последовательно. Прочие `classname` (без пустых сегментов)
   разбираются как сейчас.
2. Путь записи при наличии атрибута `file` определяется как сейчас.

## Критерии приёмки

Имя скрытого каталога `<H>` в AC-1…AC-4 и AC-6 — каждое из двух имён:
литерал `.artel-plank` и второе, отличное от него имя, начинающееся с
одной точки (например, `.zq-plank` или случайное `.<6 букв>`). Критерий
выполнен, только если он выполнен для обоих имён; реализация с жёстко
заданной строкой `.artel-plank` краснеет (решение Оператора 2 на гейте
SPEC).

AC-1. Отчёт настоящего pytest (xunit2, без атрибута `file`) для файла
`tests/<H>/<id>/test_x.py` во временной песочнице разобран
`parse_junit` (→ `_junit_location`): запись получает путь
`tests/<H>/<id>/test_x.py` и имя — `name` отчёта без префикса модуля
(`test_ok`); гейт FAIL_TO_PASS (`file_records`) сопоставляет с файлом
планки именно эту запись, полученную разбором настоящего отчёта, а не
запись, собранную в тесте вручную; `plank_layout` внешнего проекта в
песочнице — `tests/<H>/<id>` для каждого из двух имён.

AC-2. То же для `_forge_location`: запись отчёта задания CI с тем же
`classname` при дереве файлов, содержащем путь `tests/<H>/<id>/test_x.py`,
получает путь `tests/<H>/<id>/test_x.py` и имя `test_ok`.

AC-3. Для файла `<H>/<id>/test_x.py` в корне песочницы (`classname`
начинается с точки) и `_junit_location` (отчёт настоящего pytest), и
`_forge_location` дают путь `<H>/<id>/test_x.py` и имя `name` отчёта без
префикса модуля.

AC-4. Для теста в классе `TestK` того же файла (`classname`
`tests.<H>.<id>.test_x.TestK`, то есть с двумя точками подряд перед
именем каталога, отчёт настоящего pytest) и `_junit_location`, и
`_forge_location` дают путь `tests/<H>/<id>/test_x.py` и имя
`TestK::test_…`.

AC-5. Прежний разбор сохранён: отчёт xunit1 (с атрибутом `file`) того же
файла, включая тест в классе, даёт путь из `file` и имя `TestK::test_…`;
`classname` без пустых сегментов — с классом теста (`tests.test_m.TestK`)
и с путём через `/` — даёт прежние путь и имя в `_junit_location` и
`_forge_location`.

AC-6. Имя каталога из двух и более точек в начале. Отчёт настоящего
pytest для файла `tests/..x/<id>/test_y.py` (`classname`
`tests...x.<id>.test_y`, три точки подряд) и для файла
`..x/<id>/test_y.py` в корне песочницы (`classname` `..x.<id>.test_y`):
`_junit_location` и `_forge_location` дают путь с каталогом `..x` (ровно
две точки) — `tests/..x/<id>/test_y.py` и `..x/<id>/test_y.py` — и имя
`test_ok`, для теста в классе — `TestK::test_…`. Каждая пустая часть
`classname` добавляет одну точку к началу следующей непустой части
(требование 1, «тем же правилом последовательно»). То же проверяется
для второго имени (`..` + имя второго скрытого каталога без точки, например
`..zq-plank`). Реализация, склеивающая только одну точку, на этих
`classname` файла не находит и краснеет.

## Постановка опыта (для автора тестов)

Правила безопасности и постановки опыта (решение Оператора 4 на гейте
SPEC; опыт аудитора SPEC и аналитика 05.11, pytest 9 во временном
каталоге):

- Корневой и вложенный случаи (AC-1/AC-3, AC-6) — в отдельных
  песочницах: два одноимённых `test_x.py` в одной песочнице без
  `__init__.py` дают ошибку сбора (import file mismatch) и пустой отчёт.
- Путь песочницы — через `resolve()` (macOS: `/var` → `/private/var`;
  нерезолвленный путь при `--rootdir` портит `file` в xunit1).
- Дочернему pytest передаётся путь к файлу, не к каталогу:
  `norecursedirs` по умолчанию `.*`, и каталог с точки не собирается
  (0 тестов).
- Дочернему pytest — `timeout`, пустой `PYTEST_ADDOPTS`,
  `-p no:cacheprovider`, без сети; без настоящих клонов проектов и
  локального слоя; настоящие файлы репозитория не меняются.
- AC-5 зелёный до кода — его тест помечается «Зелёный с рождения:»
  (метку в докстринге теста проверяет guard); AC-1…AC-4 и AC-6 красны до
  реализации.

## Не входит

- Снятие обхода `junit_family=xunit1` в локальном слое проекта — делает
  Оператор после мержа.
- Прочие форматы отчётов.
- Прочие разборщики `classname` (`_junit_node` и `_junit_file_times` в
  `orchestrator/acceptance.py`) — каталог на точку уже обрабатывают.
- Правка `orchestrator/plank_layout.py`, `orchestrator/acceptance.py`,
  `orchestrator/advance_gates/acceptance.py`,
  `orchestrator/advance_gates/tests_writing.py`,
  `tests/test_01m5aqh8m2dkbv30nby86j34a7_fail_to_pass.py` — только чтение.
- Зелёный набор существующих тестов `tests/` без их правки (критерий ТЗ
  «прежние тесты разбора отчётов зелёные без правки») — её держит пульт;
  покраснение существующего теста — эскалация с именем теста, без правки.

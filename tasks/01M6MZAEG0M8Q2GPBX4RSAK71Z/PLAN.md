# PLAN: Отчёт JUnit: путь теста в каталоге, имя которого начинается с точки

## Подход
Один закрытый помощник `_classname_parts(classname)` в
`orchestrator/reporters/outcome.py` делит точечный `classname` по точкам,
но пустую часть (точка в начале или точка за точкой) не считает
разделителем: каждая пустая часть добавляет одну точку к началу следующей
непустой части (`tests...x.id.t` → `tests`, `..x`, `id`, `t`). Им
заменяется `classname.split(".")` в `_junit_location` (`:117`) и
`_forge_location` (`:263`). Для `classname` без пустых частей результат
совпадает с `split(".")` — прежний разбор не меняется; ветка атрибута
`file` и ветка пути с `/` не трогаются (требование 2, AC-5). Имя каталога
нигде не задано литералом — правило общее для любого скрытого каталога.

## Шаги

## Влияние на систему
Затронут только разбор `classname` двух функций отчёта; гейт FAIL_TO_PASS
(`advance_gates/acceptance.py`) не меняется — он лишь начинает получать
верный путь для каталогов с точки. Для `classname` без пустых частей
поведение побайтно прежнее, поэтому существующие тесты разбора отчётов
остаются зелёными без правки. Гейты, лимиты, guard'ы не трогаются. Откат —
revert одного коммита.

## Риски
`classname`, оканчивающийся точкой (на практике pytest такого не пишет):
висящие точки присоединяются к последней части, файл не находится —
как и раньше, путём записи становится весь `classname`.

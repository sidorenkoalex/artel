# SPEC: Автокоммит артефактов роли и worktree-чекпоинт

## Контекст

Класс «роль завершила шаг rc=0, но не закоммитила артефакт» повторился
10 раз (REVIEW.md T041, T044, T045, T048, T051, T052 и далее; PLAN+код
T049) — каждый раз отказ advance, инцидент целостности и спасение
Оператором вручную (`git add && commit`). Спасённый Оператором артефакт
при этом неотличим от роль-произведённого — `author_role` лжёт о
происхождении (наблюдение ревьювера T052). Отдельно — инцидент T048
(28.08): при таймауте шага роль работала в worktree задачи, а
авточекпоинт T041 коммитил рабочее дерево пульта — реальный WIP
оставался незакоммиченным в worktree, а в main уезжал мусорный коммит с
посторонними untracked. Продуктовый код `commit_timeout_checkpoint`
(`orchestrator/runner.py`) уже worktree-осведомлён по итогам T048, но
приёмочный тест `tasks/T041/acceptance_tests/test_checkpoint_after_timeout.py`
пишет WIP по устаревшему адресу главной копии (`config.TASKS`) и падает
на текущем коде — адрес там не исправлен.

## Требования

1. Оркестратор по завершении агентного шага роли (rc=0), до
   advance-логики, коммитит незакоммиченные изменения в worktree задачи
   служебным коммитом с сообщением
   `<id>: артефакты шага <role> (автокоммит оркестратора)`; журнал
   несёт запись `actor=orchestrator`, тем же правом (авторство), каким
   оркестратор уже коммитит фиксации/чекпоинты.
2. Если роль уже закоммитила все свои изменения сама — автокоммит не
   создаёт пустой коммит и не пишет запись в журнал: нечего коммитить —
   автокоммит молчит.
3. `git add` автокоммита ограничен путями worktree задачи целиком (это
   её ветка) — никакого `add -A` по произвольному дереву и никаких
   операций над рабочим деревом пульта (урок инцидента T048 с .codex
   чужой сессии).
4. Чекпоинт таймаута шага (T041) остаётся worktree-осведомлённым: при
   таймауте чекпоинтится worktree задачи (`role_cwd`), рабочее дерево
   пульта не получает ни коммита, ни `add`. Семантика инварианта 30
   (чекпоинт только при таймауте с грязным деревом; провал по rc —
   нет) не меняется, меняется только адрес дерева при необходимости.
5. Существующие тесты чекпоинта T041 (`tests/test_timeout_checkpoint.py`,
   `tasks/T041/acceptance_tests/`) правятся только в части адреса
   дерева (главная копия → worktree задачи) и путей патчей — сценарии и
   остальные ассерты не меняются; прочие конфликты с существующими
   тестами вне этой правки — эскалация.
6. Деградация автокоммита без git — по существующим образцам (молча,
   шаг не падает).

## Критерии приёмки

AC-1. Шаг роли с незакоммиченными изменениями в worktree задачи
(rc=0) → после шага в ветке задачи появляется служебный коммит с
сообщением `<id>: артефакты шага <role> (автокоммит оркестратора)`,
журнал несёт запись `actor=orchestrator`; `advance` проходит без
инцидента целостности.

AC-2. Роль закоммитила все свои изменения сама → автокоммит не создаёт
пустой коммит.

AC-3. Таймаут шага с грязным worktree → чекпоинт коммитится В worktree
задачи; рабочее дерево пульта не получает ни коммита, ни `add`;
посторонние файлы вне worktree задачи не попадают в коммит.

AC-4. Провал шага по коду возврата (не таймаут) → чекпоинта нет
(инвариант 30).

AC-5. Все существующие тесты зелёные; допустимые правки тестов —
только адрес дерева чекпоинта (тесты T041) и пути патчей.

## Не входит

- Изменение advance/guard-логики: незакоммиченного артефакта после
  автокоммита не бывает, но сами проверки лока/фиксации остаются как
  есть.
- Автопуш ветки задачи в origin.
- Ретроактивная пометка старых спасённых Оператором артефактов.
- Лимитер параллельных задач (следующая задача очереди, не эта).

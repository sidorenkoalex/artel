# ТЗ: Автокоммит артефактов роли и worktree-чекпоинт

## Контекст

Две строки P3 роадмапа свёрткой (сама строка автокоммита предлагает
это), очередь Оператора п.2б, вторая предпосылка N=2.

1. «Автокоммит артефактов роли по завершении шага»: класс «роль
   завершила шаг rc=0, но не закоммитила артефакт» повторился 10 раз
   (REVIEW.md — T041, T044, T045, T048, T051, T052 и далее; PLAN+код —
   T049) — каждый раз отказ advance, инцидент целостности и спасение
   Оператором (`git add && commit` руками). Абзац в скилах
   («закоммить перед завершением») не работает. Попутный дефект
   процесса, отмеченный ревьювером T052: спасённый Оператором артефакт
   неотличим от роль-произведённого — author_role лжёт о
   происхождении.
2. «Чекпоинт T041 — worktree-осведомлённость»: инцидент T048 (28.08) —
   при таймауте шага роль работала в worktree задачи, а авточекпоинт
   T041 закоммитил рабочее дерево ПУЛЬТА: реальный WIP остался
   незакоммиченным в worktree, а в main уехал мусорный коммит с
   посторонними untracked (.codex чужой сессии, add -A вслепую).

## Решение (Оператор 28.08, очередь п.2б)

1. Автокоммит: оркестратор по завершении агентного шага (rc=0),
   ДО advance-логики, коммитит незакоммиченные изменения worktree
   задачи служебным коммитом — сообщение
   `<id>: артефакты шага <role> (автокоммит оркестратора)`,
   журнал actor=orchestrator, тем же правом, каким оркестратор уже
   коммитит фиксации/чекпоинты. Роль, закоммитившая сама, — ноль
   лишних коммитов (нечего коммитить — автокоммит молчит).
2. Add — ТОЛЬКО пути worktree задачи (урок инцидента T048 с .codex):
   никакого add -A по произвольному дереву; зона — worktree задачи
   целиком (это её ветка), но не рабочее дерево пульта.
3. Чекпоинт таймаута T041 становится worktree-осведомлённым: при
   таймауте шага чекпоинтится worktree задачи (role_cwd), в main-копии
   не коммитится ничего. Семантика T041 (инвариант 30: чекпоинт только
   при таймауте с грязным деревом; провал по rc — нет) сохраняется,
   меняется только адрес дерева.
4. Прозрачность происхождения: служебные коммиты оркестратора несут
   отличимое сообщение (см. п.1) — наблюдение ревьювера T052 о
   неотличимости спасённых артефактов закрывается для будущих случаев
   само собой: спасение Оператором больше не потребуется.
5. Инвариант 30 не ослабляется; тест T041, фиксирующий чекпоинт
   пульта, корректируется ТОЛЬКО в части адреса дерева (main-копия →
   worktree задачи) — это исправление инцидента T048 по решению
   Оператора, не ослабление; сценарии и остальные ассерты не меняются.

## Границы

- orchestrator/ (runner/fixation/workspace и смежные), тесты, карта.
- Существующие тесты: правка только адресов дерева в тестах чекпоинта
  T041 (см. п.5) и путей патчей; иные конфликты с тестами — эскалация.
- Деградация без git — по существующим образцам (молча, не падать).

## Не входит

- Изменение advance/guard-логики: незакоммиченного артефакта после
  автокоммита не бывает, но сами проверки лока/фиксации остаются.
- Автопуш ветки в origin.
- Ретроактивная пометка старых спасённых артефактов.
- Лимитер параллельных задач — следующая задача очереди.

## Приёмка (минимум)

- Шаг роли с незакоммиченными изменениями в worktree задачи (rc=0) →
  после шага в ветке задачи появляется служебный коммит с заданным
  сообщением, журнал несёт запись actor=orchestrator; advance проходит
  без инцидента целостности.
- Роль закоммитила сама → автокоммит не создаёт пустой коммит.
- Таймаут шага с грязным worktree → чекпоинт коммитится В worktree
  задачи; рабочее дерево пульта не получает ни коммита, ни add;
  посторонние файлы вне worktree задачи не попадают в коммит.
- Провал шага по rc (не таймаут) → чекпоинта нет (инвариант 30).
- Все существующие тесты зелёные; правки тестов — только адрес дерева
  чекпоинта и пути патчей.

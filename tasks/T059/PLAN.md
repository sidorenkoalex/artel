# PLAN: Автокоммит артефактов роли и worktree-чекпоинт

## Подход

Два независимых, но родственных изменения в `orchestrator/runner.py`:

1. **Автокоммит артефактов успешного шага** — новая функция
   `commit_step_artifacts(conn, task_id, role)`, вызываемая из
   `run_agent_once` сразу по получении `rc == 0` (до журналирования
   «agent run finished», симметрично тому, как таймаут-ветка сперва
   зовёт `commit_timeout_checkpoint`, потом журналит `TIMEOUT`).
   Реализация — почти буквальная копия `commit_timeout_checkpoint`
   (тот же порядок `add -A` → `diff --cached --quiet` → `commit`,
   та же служебная идентичность `fixation.FIXATION_AUTHOR_*`, тот же
   отказ молчанием на любом шаге), с двумя отличиями: сообщение коммита
   (`<id>: артефакты шага <role> (автокоммит оркестратора)`) и текст
   действия журнала (несёт слово «автокоммит» — по нему приёмочный тест
   ищет запись). Ограничение догфудом (`target ==
   config.DEFAULT_TARGET`) — тем же доводом, что уже есть в докстринге
   `commit_timeout_checkpoint`: для внешнего target собственная
   фиксация уже коммитит артефактный репозиторий целиком на переходе
   FSM (`fixation._fix_external`), а свой `workspace` внешний target
   вообще не коммитит (ADR-0003 §4) — новый механизм не решал бы для
   него никакой проблемы и создавал бы второй, лишний способ ошибиться.
   Задача не расширяет фиксацию на внешний target — это отдельная
   задача поверх многотаргетной архитектуры (SPEC «Не входит» этого же
   класса решения, унаследовано от T041/T048).

   Общий код с `commit_timeout_checkpoint` (add/diff/commit-триплет)
   вынесен в приватный хелпер `_commit_worktree_change(wt, message)` —
   обе функции отличаются только сообщением коммита, текстом действия
   журнала и моментом вызова; дублировать 15 строк git-обвязки ради
   этого не стоит (coding-standards: минимальная правка, но и не
   copy-paste дефекта на два места).

2. **Тесты чекпоинта T041 (требование 5)** — код `commit_timeout_checkpoint`
   уже worktree-осведомлён (T048); проверено прогоном:
   `tests/test_timeout_checkpoint.py` уже адресуется в worktree
   (`self.task_dir()`/`git_in_worktree`) и зелёный без правок. Дефект —
   только в `tasks/T041/acceptance_tests/test_checkpoint_after_timeout.py`:
   `write_wip` пишет в `config.TASKS / self.TASK` (диск main, каталог
   не существует — worktree с T045/T048), а ассерты читают `gitcmd.
   is_clean()`/`self.git(...)` без `repo=`/`-C` (снова main). Правится
   адрес дерева и путь WIP-файла на worktree задачи (`workspace.path`),
   по образцу уже рабочего `test_timeout_checkpoint.py` и приёмочного
   `tasks/T059/acceptance_tests/test_autocommit_and_checkpoint.py`
   (готового по этой же задаче) — сценарии, порядок вызовов и текст
   ассертов не меняются, только адрес.

## Шаги

1. `orchestrator/runner.py`: хелпер `_commit_worktree_change`,
   `commit_step_artifacts`, вызов из `run_agent_once` на успешном `rc`;
   юнит-тесты `tests/test_step_autocommit.py` по образцу
   `tests/test_timeout_checkpoint.py` (чистое дерево — молчание,

## Влияние на систему

Новый код живёт целиком внутри `orchestrator/runner.py`
(`run_agent_once`, успешная ветка) и не трогает `fsm.py`/`guard.py`/
advance-логику — SPEC явно выводит это за рамки задачи («Не входит»).
Автокоммит расширяет то же право авторства, каким оркестратор уже
коммитит фиксацию (`fixation.FIXATION_AUTHOR_*`) и чекпоинт таймаута —
не новое право, тот же держатель. Инвариант 30 (чекпоинт только по
таймауту с грязным деревом, не по rc-провалу) не тронут: автокоммит —
условие ровно противоположное (`rc == 0`), с чекпоинтом таймаута не
пересекается по условию срабатывания. Риск двойного коммита на одном
шаге (роль сама закоммитила, а следом сработал бы автокоммит) закрыт
тем же `diff --cached --quiet` == "нечего коммитить", каким уже
защищён чекпоинт (AC-2). Откат — ревёрт коммита правки `runner.py`,
поведение возвращается к прежнему (роль вручную спасается Оператором).

Тесты T041 правятся только адресом дерева (main → worktree) — тот же
класс правки, каким уже прошёл `tests/test_timeout_checkpoint.py`
(T048); он не ослабляет ни один существующий ассерт, только чинит
адрес, который перестал существовать после T045/T048.

## Риски

- `_commit_worktree_change` — новая точка дублирования git-вызовов
  между чекпоинтом и автокоммитом; в случае будущего расхождения их
  поведения (например, разное отношение к отказу git) хелпер придётся
  параметризовать или разъединить обратно — сознательный компромисс
  ради отсутствия copy-paste сейчас.
- Автокоммит на каждом успешном шаге — это дополнительный `git add -A`
  внутри worktree на каждом шаге системы (не только при таймауте, как
  раньше): по объёму это разовая операция на уже маленьком дереве
  `tasks/<id>` и веток кода, тот же профиль нагрузки, что и у
  чекпоинта, отдельного лимита не требует.

## Предложения системе
- `docs/invariants.md` не перечисляет автокоммит успешного шага (только
  инвариант 30 — чекпоинт таймаута) — после этой задачи стоит завести
  соседний инвариант «автокоммит на rc=0 не создаёт пустой коммит»,
  чтобы следующая задача класса «незакоммиченный артефакт» проверяла
  его тем же реестром, а не читала SPEC T059 напрямую.

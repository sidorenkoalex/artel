**Опыт 1 — форма AC-4** (git 2.50.1, временный каталог вне репозитория,
`timeout` у каждого запуска). Условия: статический `http.server` на
`127.0.0.1` с проверкой Basic по префиксу пути; два репозитория `--bare` после
`update-server-info`; `GIT_CONFIG_NOSYSTEM=1`, пустой `GIT_CONFIG_GLOBAL`,
`GIT_TERMINAL_PROMPT=0`; помощник по пути через `GIT_CONFIG_*`. Результаты:
- с `credential.useHttpPath=true` проходят `clone`, `submodule update --init
  --recursive` и `fetch --recurse-submodules`; помощник получает
  `path=grp/proj.git` и `path=grp/sub.git`;
- без `useHttpPath` — «Authentication failed for …/sub.git». Git повторяет
  клон подмодуля один раз («a second time») и останавливается, петли нет.

Форма AC-4 выполнима, и отказ «как сейчас» в ней воспроизводится.

**Опыт 2 — `GIT_ASKPASS` при отключённом терминале.** Условия: `git
credential fill` на хост, которому помощник ничего не отдаёт, при
`GIT_TERMINAL_PROMPT=0`, `GIT_CONFIG_NOSYSTEM=1`, пустом `GIT_CONFIG_GLOBAL` и
заданном `GIT_ASKPASS`. Результат: git **вызывает** программу `GIT_ASKPASS`
дважды (имя и пароль) и выдаёт её ответ как `username=`/`password=`, код 0.
`GIT_TERMINAL_PROMPT=0` выключает только терминал, но не askpass;
`SSH_ASKPASS` git использует так же, запасным путём. Отсюда отклонение 1
вердикта.

## Вердикт
concerns. Отклонения решаемы Оператором на гейте.

1. **В безопасной форме тестов не сказано снять `GIT_ASKPASS` и
   `SSH_ASKPASS`.**
   - Где: раздел безопасности (`SPEC.md:143-153`) называет
     `GIT_TERMINAL_PROMPT=0`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL` и
     `timeout` и утверждает, что «ни один тест не ждёт ввода».
   - Почему этого мало: опыт 2 показал, что при `GIT_TERMINAL_PROMPT=0` git
     всё равно вызывает программу `GIT_ASKPASS` (запасной путь —
     `SSH_ASKPASS`), когда помощник ничего не отдал.
   - Какие случаи задеты: все исходы «пусто» — AC-3 (`SPEC.md:191`, `:194`,
     `:205`) и AC-8 (`SPEC.md:273`).
   - Что будет: на машине с `GIT_ASKPASS` (терминал IDE ставит его сам) тест
     получит пароль askpass вместо пустоты либо будет ждать окна ввода до
     `timeout`.
   - Образец, на который ссылается SPEC, обе переменные снимает
     (`tests/test_01m545edths47hsb59akc1ez9c_project_token.py:226-229`), но
     сама SPEC этого не требует.
   - Дефолт: добавить в раздел безопасности «тест снимает `GIT_ASKPASS` и
     `SSH_ASKPASS` из окружения git-вызовов», как в образце. Исход «пусто» при
     этом — отсутствие строки `password=`; код возврата `git credential fill`
     может быть ненулевым («terminal prompts disabled»).
2. **AC-5 не ловит ранний `ok` «в `.gitmodules` нет адресов»
   (`orchestrator/doctor/project_checks.py:1378-1379`) при заданном поле.**
   - Треб. 5 (`SPEC.md:110-113`) явно снимает только ранний `ok` без файла
     (`:1372-1373`).
   - Путь поля при `.gitmodules` без адресов по треб. 5 тоже «не в
     `.gitmodules`», то есть должен давать `warn`. Мутация «второй ранний
     `ok` оставлен» проходит все AC.
   - Дефолт: считать этот случай `warn` «путь не в `.gitmodules`»; случай в
     AC-5 — по усмотрению Оператора. Пункт мелкий.

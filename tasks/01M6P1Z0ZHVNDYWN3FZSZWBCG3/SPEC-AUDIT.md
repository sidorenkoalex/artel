## Пути обхода гейтов
1. **Утечка токена подмодуля на чужой хост через `.gitmodules`.**
   `.gitmodules` клона меняют люди проекта (`merge_gate: target-human`).
   Если адрес пути из `submodule_tokens` в `.gitmodules` сменят на другой
   хост, буквальное SPEC.md:48-49 («запрос к адресу подмодуля из поля
   получает токен его слота») спорит с SPEC.md:52 («другой хост — ничего»).
   Порядок правил не задан. Исполнитель вправе сверять адрес целиком
   (хост берётся из `.gitmodules`) и отдать токен чужому хосту. Нужно
   правило: токен подмодуля — только при хосте записи; адрес подмодуля
   на другом хосте — отказ или `warn` в `doctor`.
2. **Пустой слот подмодуля вне `doctor` не задан.** SPEC.md:48-49
   запрещает отдавать токен проекта, но не говорит, что делает
   хостинговый вызов (клон, `fetch`, `_clone_submodules`) при пустом
   слоте подмодуля. Варианты: отказ всего вызова с именем слота, что
   ломает `fetch` проекта из-за подмодуля; помощник по адресу подмодуля
   не отдаёт ничего; слоты читаются лениво. Если слоты читать в
   `hosting_token`, затронуты и её прочие вызыватели — `gh` (ci.py:84),
   GitLab API (gitlab_adapter.py:234), срок токена
   (misc_checks.py:85). Ни один AC этот случай не закрепляет.
3. **`doctor` молчит у записи `merge_gate: operator`.** Требования 1 и 5
   (SPEC.md:40-42, :64-66) ставят `warn` «путь не в `.gitmodules`» в
   строку `project-submodules-<проект>`, а она заводится только для
   target-human (project_checks.py:70-75). `_clone_submodules` при этом
   работает для любой записи со `token_slot`. Запись github/operator с
   опечаткой в пути поля молча идёт токеном проекта, и `doctor` этого не
   покажет. Расширять строку ли — решает Оператор.
4. AC-5 в заданной форме (подмена `in_repo`) не видит пароль. Выполнив
   его буквально, можно сдать `doctor`, который пробует подмодуль токеном
   проекта (см. «Проверяемость»).

   песочницы должен нести `.git`: статический сервер не перенаправляет

6. SPEC.md:44-47: ни один AC не закрепляет разрешение относительного

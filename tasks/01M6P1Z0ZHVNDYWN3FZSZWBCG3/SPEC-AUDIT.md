## Вердикт
concerns. Отклонения мелкие, решаемы Оператором на гейте:

1. **Исход `doctor` при пустом слоте подмодуля из поля с адресом `http://` на
   хосте записи не задан однозначно.** Треб. 5 даёт два правила, применимых
   одновременно: «слот пуст — `fail` с именем слота»
   (`tasks/01M6P1Z0ZHVNDYWN3FZSZWBCG3/SPEC.md:106-107`) и «адрес `http://` на
   хосте записи — `warn`…» (`SPEC.md:113-116`). AC-5 (`SPEC.md:224`,
   `:230-233`) проверяет каждое отдельно. При этом `_clone_submodules` такой
   клон отказывает (треб. 4, `SPEC.md:94-97`), так что `warn` в `doctor` при
   нерабочем извлечении был бы ложным успехом. Для ssh вопрос снят строкой
   `SPEC.md:71-74` («слот не читается… `doctor` — `warn`»), для другого хоста
   исход `fail` в обоих чтениях. Дефолт: пустой слот у `http://` на хосте
   записи — `fail` с именем слота, в согласии с треб. 4; добавить случай в
   AC-5.
2. **AC-8 не покрывает отказ треб. 4 для адреса `http://` на хосте записи.**
   Первый случай — только `https://` (`SPEC.md:260-262`). Мутация «отказ
   только для `https://`» проходит все AC, хотя треб. 4 (`SPEC.md:94-97`)
   отказывает при любом не-ssh адресе на хосте записи, а треб. 2
   (`SPEC.md:68-70`) прямо относит `http://` к хосту записи. Дефолт: пятый
   случай AC-8 — `http://` на хосте записи, пустой слот, именованный отказ.
3. **Испорченная фраза в AC-2**: «…`orchestrator/gitcmd.py:198-201`);
   литералы / и равным значениям, которые даёт код origin/main 77e9ca9c…»
   (`SPEC.md:167-168`). Смысл восстановим: литералы равны значениям кода на
   77e9ca9c. Правка редакционная.

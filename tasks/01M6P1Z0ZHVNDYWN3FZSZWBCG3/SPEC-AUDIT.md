Проверено опытом во временном каталоге вне репозитория пульта, git 2.50.1
(Apple Git-155), у каждого запуска `timeout`:
- `GIT_CONFIG_NOSYSTEM=1` и `GIT_CONFIG_GLOBAL` на пустой файл убирают
  `credential.helper=osxkeychain` из
  `/Library/Developer/CommandLineTools/usr/share/git-core/gitconfig`.
  Утверждение решения №2.6 верно.
- При `credential.useHttpPath=true` (через `-c`) помощник получает:
  - на `url=https://h/g/p` — `path=g/p`;

- Если ни один помощник не ответил, `git credential fill` без

Неточность описания:
- Требование 5 и решение №2.4 называют `warn` для `http://` на хосте записи

  общая для «вид иной или другой хост»
  (`orchestrator/doctor/project_checks.py:1386-1389`). Её текст: «адрес …
  не на хосте записи …, токеном слота не проверяется», то есть для такого
  подмодуля он ложно называет хост чужим. AC-5 проверяет только статус
  `warn`, поэтому неверный текст останется (отклонение 7).
- Понятие «хост» в помощнике и в `doctor` разное (отклонение 3).

## Пути обхода гейтов
1. Токен подмодуля вписан в текст помощника (`GIT_CONFIG_VALUE_n`), а не в
   переменную окружения. AC-7 проверяет argv перехватом `subprocess.run`,
   а это argv только git, не порождённого git `sh -c <помощник>`. AC-3 и
   AC-8 при этом зелёные (`credential fill` пароль отдаст). Нарушение
   требования 2 («как у `HOSTING_CREDENTIAL_HELPER`») проходит гейт. Для
   токена проекта это закрыто `test_hosting_token_units.py:28` и
   `GIT_TRACE` в образце (`:632-636`), для подмодуля SPEC такого не требует.
2. Для клона без `.gitmodules`, но с полем `submodule_tokens`, `doctor` может
   вернуть прежний ранний `ok` «подмодулей нет»
   (`project_checks.py:1372-1373`) вместо `warn` «путь поля не в
   `.gitmodules`». AC-5 строит случай «путь не в `.gitmodules`» на
   существующем `.gitmodules` и такой пропуск не ловит.

## Вердикт
concerns. SPEC можно вести дальше, отклонения решаемы на гейте:

1. **AC-7 не ловит пароль подмодуля в тексте помощника**
   (SPEC, AC-7; требование 2). Добавить в AC-7: значения паролей песочницы
   отсутствуют во всех `GIT_CONFIG_VALUE_*` окружения вызова и в выводе
   `GIT_TRACE=1` `git credential fill`. Образец:
   `tests/test_hosting_token_units.py:28`,
   `tests/test_01m545edths47hsb59akc1ez9c_project_token.py:632-636`.
2. **Прямой `git credential fill` в AC-3, AC-5 и AC-8 может зависнуть.**
   Общий раздел безопасности требует `GIT_CONFIG_NOSYSTEM`/`GIT_CONFIG_GLOBAL`
   и `timeout` только для вызовов внутри `gitcmd.git`. `GIT_TERMINAL_PROMPT=0`
   задан только в AC-4. А случаи «пусто» (другой хост, пустой слот) —
   ровно те, где ни один помощник не отвечает и git идёт к `/dev/tty`
   (опыт выше). В интерактивном прогоне Оператора тест будет ждать ввода.
   Образец ставит и `GIT_TERMINAL_PROMPT=0`, и `timeout=60`
   (`tests/test_01m545edths47hsb59akc1ez9c_project_token.py:357-361`).
   Распространить оба на каждый git-вызов тестов задачи.
3. **«Другой хост» определён по-разному.** Помощник сравнивает `url_host`:
   netloc с портом, регистр как в адресе (`gitcmd.py:61-73`). `doctor`
   сравнивает `_remote_kind`: hostname без порта, нижний регистр
   (`project_checks.py:1331-1342`, :1381, :1386). Подмодуль из поля на том же
   имени хоста, но другом порту:
   - помощник считает хост чужим и токен не выдаёт;
   - `doctor` считает хост своим и ставит `fail` пробы `ls-remote`, а не
     `fail` «другой хост» с хостом требования 5.
   Требованиям 2, 4, 5 стоит назвать одно правило (по `url_host`).
4. **Требование 5 и AC-5 не говорят, что делать, если `.gitmodules` в
   клоне нет совсем, а поле задано**
   (`project_checks.py:1372-1373` — ранний `ok`). Это путь обхода 2.
   Уточнить: каждый путь поля при отсутствии файла — `warn`, и добавить
   случай в AC-5.
5. **AC-2 сравнивает с литералом «переменные `GIT_CONFIG_*`».** Под этот
   префикс попадают и требуемые же разделом безопасности
   `GIT_CONFIG_GLOBAL` (путь временной песочницы, не литерал) и
   `GIT_CONFIG_NOSYSTEM`. Уточнить: сравниваются `GIT_CONFIG_COUNT`,
   `GIT_CONFIG_KEY_n`, `GIT_CONFIG_VALUE_n` и `ARTEL_HOSTING_*`.
6. **AC-9 и перечень только чтения не называют два файла, которые
   закрепляют меняемые функции:**
   - `tests/test_push_hook_units.py:199-231` — сигнатура
     `hosting_env(env, token, host)`, ответ по хосту с портом,
     `_hosting_project` для `clone`;
   - `tests/test_push_hook_stand.py:606-660` — `carries_token` у `clone` и
     `submodule update`.
   По коду они не сломаются, если запись без поля останется прежней и
   позиционная сигнатура `hosting_env` сохранится. SPEC общей фразой «покраснел
   — эскалация» это покрывает, но явное имя убережёт разработчика от смены
   сигнатуры.
7. **Требование 5 называет текст `warn` для `http://` на хосте записи
   «прежним `warn` о виде адреса».** На деле прежний текст — «не на хосте
   записи» (`project_checks.py:1386-1389`), то есть ложный для такого
   подмодуля. Решить, нужен ли отдельный текст «адрес `http://`, токеном не
   проверяется». AC-5 проверяет только статус.

Ни одно отклонение не требует ответа Оператора до вердикта, эскалации нет.

# ТЗ: Отдельный токен для подмодулей внешнего проекта

# Отдельный токен для подмодулей внешнего проекта

## Факты

1. Хостинговый git-вызов внешнего проекта идёт с токеном слота `token_slot` записи: подкоманды `HOSTING_SUBCOMMANDS` (`orchestrator/gitcmd.py:42`), `submodule update` (:134-136), `clone` — только у записи с `token_slot` (`_clone_project`, :153-165); проект вызова — `_hosting_project` (:122-150). `hosting_token` (:168-189) читает слот, `hosting_env` (:192-210) ставит помощник `HOSTING_CREDENTIAL_HELPER` (:51-56), который отдаёт пароль на любой запрос `get` с хостом адреса записи (`ARTEL_HOSTING_HOST`), без учёта пути.
2. Подмодули клона извлекаются в одном месте — `workspace._clone_submodules` (`orchestrator/workspace.py:141-153`): `submodule update --init --recursive` тем же токеном слота проекта; рабочие копии задач подмодули не извлекают. Подмодуль в другом репозитории того же хоста, к которому у токена проекта нет доступа, не извлекается — клон не заводится («подмодули не извлечены: … HTTP Basic: Access denied»), `doctor --fix` строку `project-clones` не чинит.
3. Строка `doctor` `project-submodules-<проект>` (`orchestrator/doctor/project_checks.py:1361-1400`) заводится только для записи с `merged_by_project_people` (:70-75) и проверяет подмодули `ls-remote` тем же токеном проекта — для такого подмодуля `fail`; адрес `http://` даёт `warn` (`_remote_kind`, :1331-1342).
4. Опыт 05.11 вне пульта: клон проекта токеном проекта и извлечение подмодуля отдельным токеном (доступ к репозиторию подмодуля с правом только на чтение) проходят, если помощник учётных данных выбирает токен по адресу с путём (`credential.useHttpPath=true`). Запрос к адресу без `.git` после перенаправления хостинга приходит к помощнику как `path=<группа>/<проект>.git`.
5. Схема записи: `token_slot` — поле `machine` (`orchestrator/targets.py:41`, `LOCAL_FIELDS["machine"]` :366, плоская запись `_flatten` :796-810); поля для подмодулей нет. Описание `token_slot` вне ADR (ADR-0003, ADR-0021) отсутствует; `docs/codebase-map.md` создаётся сценарием `scripts/codebase_map.py`.

## Требуется

1. **Поле записи** `machine.submodule_tokens` — соответствие «путь подмодуля верхнего уровня в `.gitmodules` → имя слота связки ключей» (необязательное; нет поля — поведение прежнее). Поле — в `LOCAL_FIELDS["machine"]` и в плоской записи (`_flatten`). Проверка при загрузке: путь — непустая строка, слот — непустая строка; путь, которого нет в `.gitmodules` клона, — строка `doctor` (`warn`), не отказ загрузки.
2. **Выбор токена по адресу** — только для записи с `submodule_tokens`: адрес подмодуля из поля (из `.gitmodules` клона проекта `workspace.repo(<проект>)`, не рабочей копии; относительный адрес — разрешённый от `url` записи, как `doctor` `_resolve_submodule`) — его токен и никогда токен проекта; прочие адреса хоста записи — токен проекта, как сейчас; другой хост — ничего. Сравнение адресов — по `url_key` (без `.git` и завершающей косой черты), точное, не по префиксу. Значения токенов не попадают ни в argv git и помощника, ни в журнал, ни в вывод (как у `HOSTING_CREDENTIAL_HELPER` сейчас).
3. **`credential.useHttpPath=true`** ставится в окружение вызова только при наличии `submodule_tokens`; путь запроса помощнику сравнивается без учёта суффикса `.git`.
4. **Извлечение подмодулей** (`_clone_submodules`, единственное место) — с правилом требования 2; новых мест `submodule update` не добавлять.
5. **`doctor`**: `project-submodules-<проект>` проверяет подмодуль из `submodule_tokens` его токеном; слот пуст — `fail` с именем слота; путь не в `.gitmodules` — `warn` (требование 1).
6. **Процесс роли** — прежний отказ `hosting_token` (токены читает только сессия Оператора); для токенов подмодулей — то же правило.
7. **Документация**: комментарий поля в `orchestrator/targets.py`; `docs/codebase-map.md` — только повторной генерацией сценарием; правка ADR-0021 п. 2 — Оператор отдельно.

Критерии приёмки:
- запись с `submodule_tokens` загружается; без поля — поведение и окружение вызова побайтно прежние (сравнение `GIT_CONFIG_*` и argv с записью без поля; `useHttpPath` не выставлен);
- помощник учётных данных через `git credential fill` в окружении вызова (образец — `tests/test_01m545edths47hsb59akc1ez9c_project_token.py`): адрес подмодуля из записи — пароль слота подмодуля, не пароль проекта; адрес проекта, в том числе `path=<группа>/<проект>.git` у записи без `.git`, — пароль проекта; третий адрес того же хоста — пароль проекта; адрес с тем же префиксом, что у подмодуля (`<группа>/<подмодуль>-other.git`), — не пароль подмодуля; другой хост — пусто;
- клон вымышленного проекта с подмодулем во временной песочнице: локальный сервер на `127.0.0.1` — `http.server` со статической отдачей файлов (репозитории `--bare` после `update-server-info`) и проверкой пароля по префиксу пути, без `git http-backend`; два репозитория, разные пароли — клон и `submodule update --init --recursive` проходят; с одним `token_slot` без `submodule_tokens` — отказ, как сейчас;
- `doctor` `project-submodules`: запись с `merge_gate: target-human`, `https://`-адресом и подменой `gitcmd.in_repo` — сверка выданного на `ls-remote` пароля по адресу: подмодуль с токеном — `ok`; пустой слот подмодуля — `fail` с именем слота; путь записи, которого нет в `.gitmodules`, — `warn`;
- в процессе роли вызов с `submodule_tokens` — прежний именованный отказ без чтения связки ключей;
- значения паролей песочницы не встречаются ни в журнале пульта, ни в выводе команд, ни в argv дочерних процессов (перехват argv);
- прежние тесты зелёные без правки: `tests/test_hosting_token_units.py`, `tests/test_01m545edths47hsb59akc1ez9c_project_token.py`, `tests/test_doctor_gitlab_ci_file.py`, `tests/test_01m6ezxvfgh5z2876xwmqg35fp_gitlab_doctor_lines.py`.

Безопасность тестов: связка ключей — подмена `keychain.token`; хостинг — локальный HTTP-сервер на `127.0.0.1` во временной песочнице, без внешней сети; проекты вымышленные; никогда — настоящий клон и настоящий локальный слой. В текстах тестов и ТЗ — ни имён, ни адресов реальных проектов.

Существующие тесты: правка не должна сделать красным ни один существующий тест; если краснеет — эскалация с именем теста, без правки.

Зоны: `orchestrator/gitcmd.py` (помощник учётных данных и окружение хостингового вызова), `orchestrator/targets.py` (поле `submodule_tokens`, `LOCAL_FIELDS`, `_flatten`, проверка), `orchestrator/workspace.py` (`_clone_submodules`), `orchestrator/doctor/project_checks.py` (`check_submodules`), `docs/codebase-map.md` (только генерацией), `tests/` (долгоживущие файлы задачи).

Только чтение: `orchestrator/keychain.py`, `orchestrator/runner.py`, `orchestrator/doctor/cli.py`, `scripts/codebase_map.py`, `docs/adr/0003-*.md`, `docs/adr/0021-*.md`, `tests/test_hosting_token_units.py`, `tests/test_01m545edths47hsb59akc1ez9c_project_token.py`, `tests/test_doctor_gitlab_ci_file.py`, `tests/test_01m6ezxvfgh5z2876xwmqg35fp_gitlab_doctor_lines.py`.

Не входит:
- ssh-адреса подмодулей и подмодули на другом хосте;
- вложенные подмодули (`--recursive`): ключи поля — только пути верхнего уровня;
- токены подмодулей для отправки (`push`) — подмодули пульт не отправляет;
- срок токена подмодуля (строка `token-expiry`);
- правка ADR-0021 — Оператором.

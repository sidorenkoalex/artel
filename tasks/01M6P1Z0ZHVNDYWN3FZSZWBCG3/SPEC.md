# SPEC: Отдельный токен для подмодулей внешнего проекта

## Контекст
Хостинговый git-вызов внешнего проекта авторизуется токеном слота
`token_slot` записи: `gitcmd.hosting_token` (`orchestrator/gitcmd.py:168-189`)
читает слот, `gitcmd.hosting_env` (:192-210) ставит помощник
`HOSTING_CREDENTIAL_HELPER` (:51-56), который отдаёт пароль на любой
запрос `get` с хостом записи (`ARTEL_HOSTING_HOST`) без учёта пути.
Подмодули клона извлекаются в одном месте — `workspace._clone_submodules`
(`orchestrator/workspace.py:141-153`) — тем же токеном проекта. Подмодуль в
другом репозитории того же хоста, к которому у токена проекта нет доступа,
не извлекается: клон не заводится («HTTP Basic: Access denied»), `doctor
--fix` строку `project-clones` не чинит, строка `doctor`
`project-submodules-<проект>` (`orchestrator/doctor/project_checks.py:1361-1400`)
даёт `fail`. Опыт 05.11 вне пульта: клон токеном проекта и извлечение
подмодуля отдельным токеном (только чтение) проходят, если помощник
выбирает токен по адресу с путём (`credential.useHttpPath=true`); запрос к
адресу без `.git` после перенаправления хостинга приходит помощнику как
`path=<группа>/<проект>.git`. Поля записи для токенов подмодулей сейчас нет
(`orchestrator/targets.py:41`, `LOCAL_FIELDS["machine"]` :366, `_flatten`
:796-810).

## Требования

1. **Поле записи** `machine.submodule_tokens` — соответствие «путь
   подмодуля верхнего уровня в `.gitmodules` → имя слота связки ключей»,
   необязательное; нет поля — поведение прежнее. Поле объявлено в
   `LOCAL_FIELDS["machine"]` и переносится в плоскую запись (`_flatten`).
   Проверка при загрузке `targets`: путь — непустая строка, слот —
   непустая строка (иначе — отказ загрузки). Путь, которого нет в
   `.gitmodules` клона, — не отказ загрузки, а строка `doctor` `warn`
   (требование 5).
2. **Выбор токена по адресу** — только для записи с `submodule_tokens`:
   - адрес подмодуля из поля берётся из `.gitmodules` клона проекта
     `workspace.repo(<проект>)` (не рабочей копии задачи); относительный
     адрес (`./…`, `../…`) — разрешённый от `url` записи так же, как
     `doctor` `_resolve_submodule`;
   - запрос к адресу подмодуля из поля получает токен его слота и никогда
     токен проекта;
   - запрос к прочим адресам хоста записи получает токен проекта, как
     сейчас;
   - запрос к другому хосту не получает ничего;
   - сравнение адресов — по `url_key` (без `.git` и завершающей косой
     черты), точное, не по префиксу;
   - значения токенов не попадают ни в argv git и помощника, ни в журнал
     пульта, ни в вывод команд (как у `HOSTING_CREDENTIAL_HELPER` сейчас).
3. **`credential.useHttpPath=true`** ставится в окружение хостингового
   вызова только при наличии у записи `submodule_tokens`; путь запроса
   помощнику сравнивается без учёта суффикса `.git`. Запись без поля —
   окружение вызова прежнее.
4. **Извлечение подмодулей** — `_clone_submodules` (единственное место)
   идёт с правилом требования 2; новых мест вызова `submodule update` не
   добавляется.
5. **`doctor`**: строка `project-submodules-<проект>` проверяет подмодуль
   из `submodule_tokens` токеном его слота; слот пуст — `fail` с именем
   слота; путь поля, которого нет в `.gitmodules` клона, — `warn`.
6. **Процесс роли**: для записи с `submodule_tokens` действует прежний
   отказ `hosting_token` — именованный отказ без чтения связки ключей
   (токены проекта и подмодулей читает только сессия Оператора).
7. **Документация**: комментарий поля `submodule_tokens` в
   `orchestrator/targets.py`; `docs/codebase-map.md` меняется только
   повторной генерацией `scripts/codebase_map.py`.

## Критерии приёмки

Безопасность тестов (для всех критериев): связка ключей — подмена
`keychain.token`; хостинг — локальный HTTP-сервер на `127.0.0.1` во
временной песочнице, без внешней сети; проекты вымышленные; никогда —
настоящий клон и настоящий локальный слой; в текстах тестов — ни имён, ни
адресов реальных проектов.

AC-1. Запись с `machine.submodule_tokens` (путь → слот, непустые строки)
загружается `targets`, поле есть в плоской записи; запись с пустым путём
или пустым слотом в поле загрузкой отказывается.

AC-2. Для записи без `submodule_tokens` окружение и argv хостингового
вызова побайтно совпадают с прежними: сравнение переменных `GIT_CONFIG_*`
и argv с записью без поля, `credential.useHttpPath` не выставлен. Для
записи с полем `credential.useHttpPath=true` в окружении вызова есть.

AC-3. Помощник учётных данных через `git credential fill` в окружении
вызова записи с `submodule_tokens` (образец —
`tests/test_01m545edths47hsb59akc1ez9c_project_token.py`):
адрес подмодуля из записи — пароль слота подмодуля, не пароль проекта;
адрес проекта, в том числе `path=<группа>/<проект>.git` у записи с `url`
без `.git`, — пароль проекта; третий адрес того же хоста — пароль проекта;
адрес с тем же префиксом, что у подмодуля (`<группа>/<подмодуль>-other.git`),
— не пароль подмодуля; другой хост — пусто.

AC-4. Клон вымышленного проекта с подмодулем во временной песочнице:
локальный сервер на `127.0.0.1` — `http.server` со статической отдачей
файлов (репозитории `--bare` после `update-server-info`) и проверкой
пароля по префиксу пути, без `git http-backend`; два репозитория с разными
паролями. Запись с `token_slot` и `submodule_tokens` — клон и `submodule
update --init --recursive` (через `_clone_submodules`) проходят; запись с
одним `token_slot` без `submodule_tokens` — отказ, как сейчас.

AC-5. `doctor` `project-submodules-<проект>`: запись с `merge_gate:
target-human`, `https://`-адресом и подменой `gitcmd.in_repo`, сверяющей
выданный на `ls-remote` пароль по адресу: подмодуль с токеном своего слота
— `ok`; пустой слот подмодуля — `fail`, текст строки называет имя слота;
путь записи, которого нет в `.gitmodules` клона, — `warn`.

AC-6. В процессе роли хостинговый вызов для записи с `submodule_tokens` —
прежний именованный отказ `hosting_token`, `keychain.token` не вызывается
ни для слота проекта, ни для слотов подмодулей.

AC-7. Значения паролей песочницы (проекта и подмодуля) не встречаются ни
в журнале пульта, ни в выводе команд, ни в argv дочерних процессов
(перехват argv).

## Оценка объёма и деление

Сработавший сигнал: число файлов зоны ≥ 5 (`orchestrator/gitcmd.py`,
`orchestrator/targets.py`, `orchestrator/workspace.py`,
`orchestrator/doctor/project_checks.py`, плюс общие `docs/codebase-map.md`
и `tests/`). Прочие сигналы не сработали: критериев приёмки 7, бюджет $35
(ниже порога $60), слов-маркеров нет.

Прогноз диффа: 40 КиБ.

**Обоснование монолита** (материал для решения Оператора). Механика одна:
поле записи (`targets.py`) → выбор токена по адресу в помощнике и
окружении вызова (`gitcmd.py`) → его единственный потребитель
`_clone_submodules` (`workspace.py`) → проверка тем же правилом в `doctor`
(`project_checks.py`). Поле без помощника — мёртвая настройка, которую
`doctor` (требование 5) не может проверить токеном подмодуля; помощник без
поля не имеет входа. Единственный отделимый кусок — строка `doctor`
(требование 5, AC-5), но она опирается на ту же функцию выбора токена и
окружение `gitcmd` и без них не проверяема; отдельная подзадача ради
одной функции в одном файле удвоила бы фиксированную цену шагов
(analyst, аудит, test_author, ревью) при рамке ТЗ $35. Объём кода мал
(одно поле, одна ветка помощника, одна правка вызова, одна ветка
проверки) — нарезка не снижает риск, а добавляет промежуточное состояние
«поле есть, `doctor` его не видит».

## Не входит

- ssh-адреса подмодулей и подмодули на другом хосте.
- Вложенные подмодули (`--recursive`): ключи поля — только пути верхнего
  уровня.
- Токены подмодулей для отправки (`push`) — подмодули пульт не отправляет.
- Срок токена подмодуля (строка `doctor` `token-expiry`).
- Правка ADR-0021 п. 2 — делает Оператор отдельно.
- Новые места вызова `submodule update` (в том числе извлечение подмодулей
  в рабочих копиях задач).
- Зелёность прежних тестов без правки (`tests/test_hosting_token_units.py`,
  `tests/test_01m545edths47hsb59akc1ez9c_project_token.py`,
  `tests/test_doctor_gitlab_ci_file.py`,
  `tests/test_01m6ezxvfgh5z2876xwmqg35fp_gitlab_doctor_lines.py`) и всего
  набора `tests/` — её держит пульт (полный зелёный набор и рубеж
  неослабления); эти файлы — только чтение. Покраснел существующий тест —

# ТЗ: approve без набора sha (сверка фиксации механикой) и перечитывание budget_usd на гейте SPEC

Источник: бэклог 05.09 (docs/backlog.md, приоритет 2), две строки
свёрнуты в одну задачу — одна зона `orchestrator/fsm.py::_cmd_approve`.

Часть А. Сегодня `approve <id>` на гейтах требует, чтобы Оператор
повторил полный sha из подсказки (`fsm.py`, «approve требует sha —
зафиксирован …»): ритуал копирования, 05.09 Оператор набрал с опечаткой.
Смысл требования — подтвердить именно то состояние артефактов, которое
пульт зафиксировал (`tasks.fixed_sha`, `fixation.confirm_fixation`).

Требуется:
1. `approve <id>` без аргумента сам читает живой sha артефактов задачи
   (тем же источником, что печатает подсказку), сверяет с `fixed_sha` и
   чистотой рабочей копии/артефактной ветки: совпало — approve проходит
   и журналирует sha; разошлось — именованный отказ с обоими sha и
   подсказкой перепроверить артефакты. Явный `approve <id> <sha>`
   остаётся как осознанное подтверждение расхождения (прежняя
   семантика без изменений).
2. Все гейты, где approve сегодня требует sha (SPEC, приёмка, merge,
   эскалация) — единообразно; префиксы sha (01M1GHZTX9…) работают как
   прежде.
3. Правило «sha только копированием» уходит из `docs/operator-session.md`
   (правка документа — приложением к PLAN, применяет Оператор).

Часть Б. Бюджет из SPEC применяется при сдаче SPEC аналитиком
(`fsm_advance`, `budget.apply_spec_budget`, `spec_writing -> spec_gate`);
правка SPEC Оператором за гейтом (деление, смена рамки) и последующий
approve потолок не обновляют — Оператор выставляет `budget` руками
(наблюдатель карты 05.09: SPEC $35, потолок остался $45).

Требуется:
4. approve на `spec_gate` перечитывает `budget_usd` из SPEC (артефактная
   ветка, тем же чтением, что guard) и применяет его той же функцией
   `apply_spec_budget` с теми же границами, что действуют на момент
   мержа этой задачи (после ADR-0014 — до `ROLE_BUDGET_CAP`; до неё —
   только вниз от дефолта): потолок Оператора (`budget_source =
   operator`) не перебивается; запись в журнал, если потолок изменился.
5. Тесты: approve без sha при совпадении — проходит и журналирует sha;
   при расхождении — отказ с обоими sha, состояние не меняется; approve с
   явным sha — прежнее поведение; approve на SPEC после правки
   `budget_usd` — потолок обновлён; с потолком Оператора — не тронут.
   Существующие `tests/test_fsm*.py`, `tests/test_spec_budget.py`,
   планки 01M1GHZTX9… и T021 зелёные без ослабления.

Зоны: orchestrator/fsm.py, orchestrator/fixation.py,
orchestrator/fsm_advance.py, orchestrator/budget.py, tests/.

Не входит: автогейты; изменение самого правила фиксации (approve-по-sha
как принцип, T021) — только способ подтверждения; ADR-0014 сама по себе
(отдельная задача 01M1SHDCW7…; при пересечении в `budget.py` — часть Б
опирается на её функции как есть и не меняет границ).

Рамка: $30 (две части, зона fsm.py в очереди у трёх задач — деление на
А/Б допустимо, если аналитик сочтёт нужным).

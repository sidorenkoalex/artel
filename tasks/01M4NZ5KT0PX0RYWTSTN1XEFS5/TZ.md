# ТЗ: Правила аналитика — матрица последствий в вопросах и проверяемое «Меняемое поведение» (ADR-0022 п.4)

Факты (origin/main 3804ccc8, сверка 11.10):
- Шаблон `templates/QUESTIONS.md`: каждый вопрос — варианты и дефолт;
  матрицы последствий нет. guard для `questions` проверяет только раздел
  «Вопросы» и статус (`scripts/guard.py` ~104, «содержательность — не
  дело guard'а, только форма»).
- Скил `skills/spec-authoring.md` ~166–180: строка «Меняемого поведения» —
  `` - `tests/<файл>.py::<Класс>::<метод>`: `<было>` → `<стало>` (требование N) ``
  «с конкретными значениями, сверенными по коду main»; ослабление —
  только вопросом. Про смену вида утверждения и дословность «было» —
  ни слова.
- Разбор строки — `guard.parse_behavior_change_line` (~3590),
  `guard.behavior_change_items`; вид утверждения и пары значений —
  `guard` (~1292 `SIGN_OTHER_KIND`, ~1698 `literal_pair_keys`,
  ~1718 `value_pair_keys`).
- Аудитор SPEC (`skills/spec-audit.md`, раздел д) строит матрицу
  неослабления по «Меняемому поведению».

Требуется:
1. QUESTIONS аналитика по каждому варианту каждого вопроса несёт
   матрицу последствий: что ломается, что ослабляется (свойство и где
   оно держится сейчас, файл:строка), цена (деньги/время/объём), чьё
   решение (Оператор/роль). Форма — в `templates/QUESTIONS.md` и
   `skills/spec-authoring.md` (приложениями).
2. guard отказывает QUESTIONS.md `status: ready`, у которого хотя бы
   один вариант без четырёх пунктов матрицы (форма, не содержание;
   черновик `draft` — без отказа). Исторические QUESTIONS в ссылках не
   перепроверяются.
3. Скил аналитика называет правило: смена ВИДА утверждения
   (`assertIn` ↔ `assertNotIn`, `assertTrue` ↔ `assertFalse`,
   `assertEqual` → `assertIn` и т.п.), удаление, переименование, пропуск,
   смягчение — не «Меняемое поведение», а вопрос Оператору в батче с
   матрицей (мандат «Ослабление тестов разрешено» даёт Оператор).
   «Меняемое поведение» — только смена значения при том же виде
   утверждения.
4. «было» и «стало» в строке «Меняемого поведения» — дословные
   фрагменты кода Python (литерал или выражение из обратных кавычек), не
   слова. `approve` на гейте SPEC отказывает, если «было» не найдено
   дословно (с нормализацией пробелов) в теле названного метода в
   голове main репозитория задачи, — с именем метода и фрагментом;
   и если «было» и «стало» — утверждения разного вида (разбор тем же
   кодом guard, что у гейта неослабления). Причина отказа говорит, что
   делать: исправить строку либо вынести смену вопросом.
5. Проверка п.4 — тем же разбором, что у гейта неослабления
   (`guard`), без второй реализации; гейт неослабления на in_dev →
   verifying не меняется.
6. Аудитор SPEC в разделе д) проверяет п.3–4 (правка
   `skills/spec-audit.md` приложением).

Критерии приёмки (направление; планку пишет test_author):
- QUESTIONS ready без матрицы у варианта — отказ guard с номером вопроса
  и варианта; с полной матрицей — проход; draft — проход.
- `approve` гейта SPEC: «было» нет в теле метода main — отказ с именем
  метода; «было» есть, вид утверждения тот же — проход и запись
  «объявлена смена поведения тестов» как сегодня; разный вид — отказ.
- Мутация «approve не сверяет было с кодом» ловится; мутация «сверка
  вида утверждения отключена» ловится.
- Гейт неослабления (`test_integrity`) не изменён: существующие тесты
  гейта зелёные без правок.

Ослабления нет: существующие проверки (`_behavior_change_declaration`,
гейт неослабления, guard SPEC) не смягчаются; добавляются отказы
раньше по конвейеру. Смена поведения существующих тестов — только
разделом SPEC «Меняемое поведение» (инвариант 38).

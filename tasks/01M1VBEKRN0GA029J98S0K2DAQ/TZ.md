# ТЗ: команда `watch` — дозор событий журнала для сессии Оператора

Источник: аудит обходных сценариев Оператора 06.09 и контракт
`docs/operator-session.md` («Возобновление сессии», п. 4: поставить
дозор, решение Оператора 03.09). Сегодня дозор — python-сценарии сессии
(`watch_tasks.py`, `watch_spec_gate.py`): опрос `steps` раз в 30 секунд
по списку задач, печать строк журнала по регулярному выражению
(переходы, отказы, окончания шагов, бюджет, «ЖДЁТ»), выход по
терминальному состоянию. Сценарии живут вне репозитория, у каждой
сессии свои, список задач вшит при запуске (новую задачу приходится
добавлять перезапуском), формат строк не совпадает с `log`. Уведомления
собственных фоновых запусков дозор не заменяют: они знают только свою
сессию.

Требуется:
1. `artel.py watch [--tasks <id>[,<id>]] [--mine] [--all] [--events
   <класс>[,<класс>]] [--interval SEC] [--until <state>]`: поток строк
   журнала в формате `log` (ts, task, actor, action, detail) для
   выбранных задач с момента запуска, без буферизации (`flush` на
   каждую строку). Классы событий — именованные фильтры над `action`:
   `transitions` (state ->), `refusals` (переход отклонён…), `steps`
   (agent run started/finished), `gates` (ЖДЁТ ОПЕРАТОРА: spec_gate,
   acceptance, merge_gate, escalated), `budget`, `alerts`; по умолчанию
   `transitions,refusals,gates,steps`. `--mine` — задачи, у которых
   последний lease/`created` от этой сессии (`session_id` по правилам
   `lease.py`); `--all` — все нетерминальные. Новые задачи, заведённые
   после старта, подхватываются без перезапуска (перечитывание списка
   раз в интервал).
2. Выход: `--until <state>` для одной задачи (как ожидание гейта);
   иначе — пока есть нетерминальные задачи в выборке; код возврата 0.
   Строка «STATE=<state>» при смене состояния задачи — отдельным
   событием (для внешних наблюдателей вроде Monitor).
3. Не пишет в журнал, не берёт lease, не трогает состояние (чтение
   через своё соединение `store.db()`, каждая итерация — свежее чтение,
   чтобы не повторить дефект устаревшего снимка WAL).
4. Тесты: (а) в песочнице поток выдаёт события заданных классов и не
   выдаёт прочие (мутация: фильтр снят — красный); (б) задача, заведённая
   после старта, появляется в потоке при `--all`; (в) `--until` завершает
   с кодом 0 при достижении состояния; (г) команда не создаёт записей
   журнала и lease (сверка счётчиков до/после); (д) существующие тесты
   CLI зелёные.
5. `docs/operator-session.md`, п. 4 «Поставить дозор» (приложением):
   дозор — `artel.py watch --mine` фоновым процессом, сценарии сессии
   не нужны.

Зоны: orchestrator/artel.py, orchestrator/watch.py (новый),
orchestrator/store.py, docs/operator-session.md, tests/.
Порядок: без зависимостей; `store.py` — общая зона, конфликт текстовый.

Не входит: уведомления вне терминала (push, мессенджеры); `report`.

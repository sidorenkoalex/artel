## Пути обхода гейтов
1. **Ветвление по имени хостинга в `ci.py` без `Compare`.** AC-21
   (SPEC.md:350-358) и сторож А0 (`support_comparisons`, тест :453-470)
   смотрят только узел `ast.Compare`, у которого операнд — сам вызов
   функции `forge` или поле `forge`. Мимо обоих проходят:
   - `match forge.kind(t):` / `case "gitlab":` — узел `ast.Match`, не
     `Compare`;
   - `k = forge.kind(t)`, затем `if k == "gitlab":` — сторож А0 не видит
     «forge» в имени `k`, а AC-21 описан как сравнение результата вызова;
   - свой словарь в `ci.py` с ключами `"github"`/`"gitlab"`, проиндексированный
     результатом функции `forge`. Это второй реестр в обход требования 1
     («одним реестром в `forge.py`», SPEC.md:37-38).

   То же в `forge.py`: `match <значение>: case "gitlab":` обходит запрет
   «сравнений с литералами (`==`, `!=`)» (SPEC.md:354-355). Закрыть можно
   так: AC-21 запрещает литералы `"github"`/`"gitlab"` и
   `targets.FORGES[...]` в `ci.py` вообще (в любом узле), а в `forge.py`
   разрешает их только как ключи словаря-реестра.
2. **Пустое множество `failed_check_names` при красном итоге без упавших
   заданий.** Строка `red` таблицы (SPEC.md:172) даёт «имена упавших
   заданий без права падать». У конвейера `failed` при всех видимых
   `success` (AC-16) это пустое множество. Docstring функции (ci.py:1133-1137)
   прямо называет пустое множество на неизвестной красноте «ложью в пользу
   повтора». Сейчас вреда нет: `trigger_rerun` для gitlab отказывает.
   Риск — на шаге Б2. Малое замечание, перенесено с прошлого визита.

   пустое множество** (SPEC.md:172; ci.py:1133-1137). Малое, риск на Б2.

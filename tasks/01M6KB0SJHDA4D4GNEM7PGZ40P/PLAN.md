# PLAN: Возврат с гейта SPEC файлом решения

## Подход
Разбор файла решения — чистый модуль `orchestrator/spec_gate_decision.py`
без чтения файлов (требование 4): форма полей и заглушки шаблона зашиты
константами (`STUBS`), текст файла и тексты ANSWER-n передаёт вызывающий
код. `parse(text)` проверяет заголовок (`starts_with_header` — единое
правило требований 2, 5, 9), раздел «## Решения», номера «### Решение <n>»
подряд с 1 (запись номера сверяется буквально — «01» не «1»), каждое из
шести полей ровно один раз (метка — только в начале строки, значение —
до следующей метки или подраздела), непустоту, заглушку (раньше формы и
мандата) и форму поля. `prior_refusal` — ссылки «№k»/«№k.n» (требование
6), `mandate_refusal` — строки «мандат: …» тем же `mandate.line_elements`
по маркерам мандата тестов, что `answer` на `spec_gate`; ANSWER-n
читаются лениво, только при строке мандата. `numbered(reason)` — номера
«k.n» записи журнала, поданной файлом (заголовок + разбор формы, без
перепроверки ссылок и мандата).

`fsm`: `cmd_reject(..., *, decision_file=None)` — один
`lease.run_task_command`, ветвление внутри лямбды; при `None` тело
зовётся прежним `_cmd_reject(conn, tid, reason)`. В `_cmd_reject` отказ
`--decision` вне `spec_gate` — первым, до `awaiting_human`; на
`spec_gate` `_spec_gate_reject_text` читает файл, сверяет форму, ссылки
(номера — `spec_gate_prior_decisions` поверх `brief._spec_gate_reasons`,
`brief` импортируется по месту) и мандат (`_answer_texts` — ссылка
документов задачи), на отказе печатает перечень прежних решений
(`spec_gate_prior_block`). Прежняя форма — предупреждение, причина с
заголовком файла решения — отказ. Принятый текст уходит в журнал тем же
`store.set_state` с префиксом «возврат из spec_gate: » — бриф не меняется.

`artel._cmd_reject` разбирает ключ `--decision` явно (без значения, вместе
с позиционной причиной — отказ до lease). Подсказка `auto` на `spec_gate`
дописывает перечень прежних решений (`fsm.spec_gate_prior_block`, `brief`
в `auto` не импортируется), `config.AUTO_STOP["spec_gate"]` называет
`reject {id} --decision <файл>` и сохраняет `approve {id}{sha}`.

Бюджет SPEC ($45) не переоценивается: число файлов и шагов — как в SPEC.

## Влияние на систему
- `reject` в `acceptance`/`merge_gate`/`verifying`/`awaiting_human` без
  `--decision` не меняется: ветка `decision_file is not None` стоит
  первой и при `None` не срабатывает; `reject` без id теперь — именованный
  отказ вместо `IndexError`.
- Обвязка lease: в теле `cmd_reject` один `lease.run_task_command`, нет
  `store.db`, при `decision_file=None` — вызов тела без kwargs;
  `tests/test_lease_run_task_command.py`,
  `tests/test_01m5mhvrs39cdp5v4hbwy4k7wk_run_task_command.py` зелёные без
  правки (прогнаны, и через планку AC-10).
- Подсказка `auto` на `spec_gate`: `approve {id}{sha}` сохранён, перечень
  дописан отдельными строками после подсказки — `tests/test_auto_cycle.py`,
  `tests/test_spec_audit_gate.py`, `tests/test_git_fixation.py`,
  `tests/test_01m3ychs4f08vtv6xx10vf92h3_task_model_set.py` зелёные.
- Существующие тесты не правились; ни гейт, ни лимит, ни guard не
  ослаблен. Прогнаны также тесты reject/answer на spec_gate
  (`tests/test_fsm_spec_gate_reject.py`,
  `tests/test_01m4r4jdg8rh53znwm0xf90cfj_spec_gate_decisions.py`,
  `tests/test_01m4r4jqzex2mbdb195sbj8a7s_*`, awaiting-тесты и др.) — зелёные.
- Откат — revert merge-коммита задачи; приложения — отдельный коммит
  Оператора воротами мержа.

# Возврат с гейта SPEC файлом решения: обязательная сверка следствий решения Оператора

## Факты

1. `reject <id> "<причина>"` на `spec_gate` (`orchestrator/fsm.py:1890`, ветка `if state == "spec_gate"` в `_cmd_reject`) принимает свободный текст; единственная проверка — непустая причина (`orchestrator/fsm.py:1912`). Текст уходит в журнал с префиксом «возврат из spec_gate: » (строкой на `orchestrator/fsm.py:1919`, совпадает с `brief.SPEC_GATE_RETURN_PREFIX`, `orchestrator/brief.py:76`); бриф аналитика и аудитора несёт его разделом «Решения Оператора на гейте SPEC» с номерами «№k из n» (`brief._spec_gate_reasons`, `orchestrator/brief.py:1343`, `:1376`). Разбор аргументов команды — `orchestrator/artel.py:2675` (второй позиционный — причина).
2. Инцидент 04.11, задача 01M6JJ4J4NBV2Y1Q4XHE3C3FVT: десять кругов SPEC; около половины вызвано решениями Оператора на гейте — ложное утверждение о git, условие, невыполнимое в зонах, тест с меняющей командой вне дублёра, незаданный канал подстановки, противоречие двух решений; мандат на правку существующего теста подан текстом причины, а не строкой мандата в ANSWER.
3. `answer <id> <файл>` на `spec_gate` принимает только мандат тестов и проверяет форму строк мандата (`orchestrator/answer.py:239`, `_spec_gate_answer_text`); мандат действует всю жизнь задачи (справка `orchestrator/artel.py:541`).
4. Правило сверки для сессии Оператора — `docs/operator-session.md`, «Уроки 04.11», п. 1; правило аудитора — `skills/spec-audit.md`, раздел «Решения Оператора на гейте SPEC». Пульт их не проверяет.
5. Существующие тесты зовут `fsm.cmd_reject(task, reason)` и `fsm._cmd_reject(conn, task, reason)` позиционно (например, `tests/test_fsm_spec_gate_reject.py:65`); подсказку остановки `auto` на `spec_gate` проверяют вхождением строки (`tests/test_spec_audit_gate.py:49`).

## Требуется

1. `reject <id> --decision <файл>` на `spec_gate`. Ключ `--decision` разбирается явно (не как текст причины); позиционные сигнатуры `fsm.cmd_reject` и `fsm._cmd_reject` сохраняются, новый аргумент — именованный, по умолчанию `None`. Файл — по шаблону `templates/SPEC-GATE-DECISION.md` (текст — в приложении ниже): раздел «## Решения», в нём подразделы «### Решение <n>», у каждого шесть полей — «Текст», «Утверждения о коде и поведении», «Чем проверяется», «Существующие тесты», «Прежние решения», «Зоны». Пустое поле, поле не по форме (например, «Утверждения…» без `файл:строка`, «опыт:» или «нет»), оставленная заглушка шаблона «<…>», отсутствие раздела — отказ с именем решения и поля, состояние не меняется. Разбор не читает каталог шаблонов во время работы: форма зашита в модуле разбора.
2. Номера решений: решение n возврата k — «k.n» (k — номер возврата с гейта SPEC этой задачи, как «№k» в брифе). На отказе `reject` и в подсказке остановки `auto` на `spec_gate` пульт печатает перечень прежних решений задачи: номер «k.n» и текст поля «Текст» (для возврата текстом — первые 120 знаков, номер «k»), переносы строк свёрнуты. Поле «Прежние решения» ссылается на эти номера; ссылка на несуществующий номер — отказ.
3. Поле «Существующие тесты» с элементом «мандат: <строка>» — отказ `reject`, если такой строки мандата нет ни в одном ANSWER-n задачи, поданном до `reject` (тем же разбором строк мандата, что `answer`).
4. Текст файла решения целиком уходит в журнал тем же префиксом «возврат из spec_gate: »: устройство брифа аналитика и аудитора не меняется.
5. Прежняя форма `reject <id> "<причина>"` на `spec_gate` остаётся и печатает предупреждение «решение без сверки следствий — для сессии Оператора обязательна форма --decision». В остальных состояниях `reject` не меняется.

Критерии приёмки:
- `reject --decision` с полным файлом переводит задачу в `spec_writing`, текст в журнале с префиксом, бриф аналитика содержит его;
- каждое пустое или неверное по форме поле, заглушка шаблона, ссылка на несуществующий номер решения — отказ с именем решения и поля, состояние `spec_gate`;
- «мандат: …» без ANSWER-n с этой строкой — отказ; после `answer` с той же строкой — проходит;
- подсказка остановки на `spec_gate` и вывод отказа перечисляют прежние решения задачи с номерами «k.n» / «k»;
- прежняя форма текстом проходит с предупреждением;
- прежние тесты `reject` во всех состояниях и подсказок `auto` зелёные без правки.

Безопасность тестов: все проверки — командами пульта в песочнице (`TmpRootTest`), без порождения процессов сверх команд пульта и без меняющих команд против настоящего репозитория.

Зоны: `orchestrator/fsm.py`, `orchestrator/artel.py`, `orchestrator/auto.py` (подсказка остановки на `spec_gate`), `orchestrator/spec_gate_decision.py` (новый, разбор файла), `docs/operator-gates.md`, `docs/operator-session.md`, `docs/codebase-map.md`, `tests/` (долгоживущие файлы задачи).

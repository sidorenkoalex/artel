## Пути обхода гейтов

- **е1.** Хук в sh читает запись проекта, не зная, как её получить. По соглашению хука в нём только POSIX sh и git (`scripts/git-hooks/pre-push:10-11`). Шаблон ветки и `base` («из записи проекта клона», требование 1) живут в `targets.yaml` и локальном слое (`targets.merge_local`). Откуда хук их берёт и как узнаёт проект клона, SPEC не говорит. Не сказано и что делает хук, если запись не прочиталась или проект клона не определён. Хук, пропускающий отправку при непрочитанной записи, — тот же пропуск при сбое, который требование 8 закрывает в Python. Нужно явное «не прочитано — отказ» для клона под белым списком и пункт AC-1 на это.
- **е2.** В модели угроз названы только формы в самом вызове (`--no-verify`, `-c core.hooksPath=`). Постоянный `git config core.hooksPath <свой каталог>` в клоне или рабочей копии хук тоже не держит. Для отправок пульта его ловит сверка требования 2, после факта — строка `doctor` `fail`. Для отправки роли из оболочки — только `doctor`, и в модели угроз это не названо.
- **е3.** Часть 1 можно выполнить буквально, и смысл не удержится: тесты AC-9 с постоянной подменой сбоя проходят при нетронутом коде (в1, Б1, Б2).

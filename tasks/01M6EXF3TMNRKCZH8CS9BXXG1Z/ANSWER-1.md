# ANSWER-1: ответ Оператора

## Ответы

Ответ сессии при Операторе (права волны G) на батч вопросов аналитика Б2.3, 02.11.2026.

1. **Вопрос 1 — B:** запись `github` + `target-human` читается как сейчас; отказывают действия `new`/`run`/`auto`/`approve` через `unsupported_reason` с причиной «гейт мержа target-human не поддержан для хостинга github».
2. **Вопрос 2 — B (не дефолт):** `gitlab` + `operator` остаётся неподдержанным (причина «гейт мержа operator не поддержан для хостинга gitlab»): свой мерж и отправка `base` внешнего проекта на GitLab не проверены. `unsupported_reason` проверяет сочетание явным множеством поддержанных пар: `{("github","operator"), ("gitlab","target-human")}`.
3. **Вопрос 3 — A**, по мандату Оператора 26.10 на тесты, которые меняет ADR-0029, с условиями независимой проверки: (а) сторож закрепляет точное равенство кортежей `SUPPORTED_FORGES`/`SUPPORTED_MERGE_GATES` и множества поддержанных пар, не только членство; (б) отказ ac2–ac7 по-прежнему на обеих неподдержанных парах (`gitlab`+`operator`, `github`+`target-human`); (в) ac1 и ac7 — обе поддержанные пары, ac8 (`new` не отказывает) — и `gitlab`+`target-human`; (г) тексты причин двух неподдержанных пар различимы и сверяются точно.

Ослабление тестов разрешено: tests/test_01m5w27cy7k7nr9347nkd8f0nx_unsupported_project.py

4. **Вопрос 4 — A:** делить на 4 части по предложенной нарезке; порядок: часть 1 (отказ при сбое) → часть 2 (хук и сверки отправки; общий `gitcmd.py` — после части 1); часть 3 (`doctor` и `forge-probe`) — параллельно с 1–2 (зоны не пересекаются); часть 4 (открытие, тексты, документ инцидента, сторож A0) — последней, после 1–3. Рамки частей — по калибровке, сумма до .

5. **Добавка к части 3** (находки `doctor` по локальному стенду GitLab, 02.11): строки `doctor` проекта выбирают проверку по `forge` записи; для `gitlab` не применяются GitHub-проверки:
   - `project-base-protection-<имя>` — через `forge.protections` (API GitLab), не `gh` (сейчас skip «gh: Bad credentials (HTTP 401)»);
   - `project-ci-token-<имя>` — доступ токена к конвейерам через `forge.pipeline_status`/`branch_pipeline`, не GitHub Actions (сейчас FAIL «запуски Actions недоступны»);
   - `project-ci-pull-request-<имя>` — для gitlab заменяется проверкой `workflow`-правил `.gitlab-ci.yml` для шаблона ветки (п. 3 ТЗ), не поиском `pull_request` в `.github/workflows`.
   Критерий: запись `forge: gitlab` на подменённом `forge` — ни одна строка `doctor` не вызывает `gh`; строки дают ok/warn/skip по данным GitLab.

Независимая проверка: проверяющий сессии при Операторе 02.11 — «не ослабляет»: ac2 (new), ac3 (run), ac4 (auto), ac5/ac6 (approve) и ac7 (doctor) по-прежнему параметризованы по двум неподдержанным парам и проверяют отказ до клона/git/агента/слияния; проверка по сочетанию ловится обеими парами (реализация «по полям» их пропустила бы — тесты красные); условия (а)–(г) выше.

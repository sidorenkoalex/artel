## Требуется

1. **Запрет повторов.** В `_report_argv` у профиля с `from_components` и `report` при команде pytest пульт добавляет `-p no:rerunfailures -p no:flaky` к каждому прогону; `-p no:rerunfailures -p no:flaky` ставятся сразу за командой профиля (поле command записи), до аргументов подмножества, цели долгоживущих, `--ignore`, `-p no:cacheprovider` и `report_args`. Условие — то же, что `in_outcome_bounds` (`project_profile.reported(profile)` и `from_components`) при `is_pytest_command(head)`; тест сверяет условие с `in_outcome_bounds` на четырёх видах профиля: артель, `test_profile`, `test_profile` с `pytest-own` и `report`, компонент с `report`. В данные ключа `_report_suite_result_key` у такого профиля добавляется поле `"no_rerun_plugins": true`; у прочих профилей данные ключа прежние. Тест: ключ `test_profile` с `report` равен sha256 словаря прежнего состава (копия в тесте), ключ компонента — не равен. `targets.check` отказывает компоненту с `report`, в `command`, `report_args`, `select` или в значении `env.PYTEST_ADDOPTS` которого есть запрещённый аргумент. Запрещённым считается: элемент, равный `--reruns`, `--reruns-delay`, `--force-flaky`, `--max-runs` или начинающийся с одного из них и `=`; пара соседних элементов `-p`, `<имя>` и один элемент `-p<имя>`, где `<имя>` — `rerunfailures`, `pytest_rerunfailures`, `flaky` или `flaky.flaky_pytest_plugin`. Значение `env.PYTEST_ADDOPTS` разбивается по правилам командной строки POSIX (модуль shlex), к элементам применяется то же правило. Проверка — у компонента записи `components:` с `report`; запись `test_profile` не проверяется. `_pytest_command`, команды артели и `test_profile` — прежние побайтно.
2. **Переносы из приёмок:**
   - (11) одна константа `tests_writing.SPEC_GATE_PASSED_DETAIL`; `fsm.py` пишет деталь из неё (импорт из `advance_gates.tests_writing`); тест: константа равна детали записи перехода после сквозного `approve` на `spec_gate` и входит в `auto._LEGIT_FIRST_ENTRY_DETAILS` (`auto.py` не меняется), и в тексте `orchestrator/fsm.py` нет литерала «гейт SPEC пройден — приёмочные тесты до кода»;
   - (18) `outcome_integrity._gate` и `two_sided.run` пишут маркер владельца сразу за `mkdtemp`, до `git worktree add`. Маркер — новая константа `liveness.GATE_OWNER_MARKER = ".artel-gate-owner"`, запись `str(os.getpid())`. В `_temp_owner_alive` для `artel-outcome-*` и `artel-two-sided-*` — только `liveness.owner_alive(path, GATE_OWNER_MARKER)`; каталог без маркера — сирота. Проверка `orphans-temp` (без `--fix`) тоже называет такие каталоги — это ожидаемое изменение вывода `doctor`. `doctor --fix` в существующих `_orphan_temp_dirs`/`_fix_orphan_temp_dirs` убирает каталоги `artel-outcome-*` и `artel-two-sided-*` без живого владельца; `git worktree prune` выполняется в каждом клоне проекта (`_project_clones`) только если этим вызовом удалён хотя бы один такой каталог, иначе git не вызывается. Тесты уборки подменяют `_project_clones` на клон во временном каталоге теста и зовут `doctor._fix_orphan_temp_dirs()` напрямую, не `cmd_doctor(fix=True)`; новых имён в фасаде `doctor` нет. Исключение из границы: маркер пишется и у артели (вывод прежний);
   - (20) критерий: вне `in_outcome_bounds` ячейка «Чем покрыто после» только с путём не `*.py` (`src/a.test.ts`) в области — отказ; подслучаи: `test_profile`, `test_profile` с `runner: pytest-own` и `report`, компонент без `report`;
   - (21) при профиле в границе «Чем покрыто после» отдельным токеном или в кавычках признаёт только путь файла: полное совпадение с `[\w][\w./-]*\.\w+` и необязательным хвостом `:<число>`, путь — в `weakening_scope`; идентификатор своего компонента в обратных кавычках — покрытие, как прежде; «`src/`», «src/**», «src/a.test.ts::x» без компонента — не покрытие; прежнее правило путей `*.py` (`_PY_PATH_RE`, поиск внутри ячейки) не меняется; точка или иной знак сразу за путём делает токен не путём (не покрытие);
   - (22) `refusal_classes.OUTCOME_MERGE_PREPARE_ACTION = "merge отклонён: гейт неослабления по исходам — подготовка"`, ключ `REFUSAL_CLASSES` — «чинит Оператор»;
   - (23) `outcome_integrity.MERGE_REFUSAL_ACTION` и `MERGE_PREPARE_ACTION` берутся из `refusal_classes` (модуль остаётся без импортов пакета); тест равенства обеих пар.
3. Тесты детерминированы, без сети и без Node: аргументы команды по отчёту у компонента и прежняя команда у артели и `test_profile` побайтно; ключ итога с признаком запрета; каждая форма запрещённого аргумента в каждом поле `targets.check`; по тесту на каждый перенос; маркер владельца и уборка `doctor --fix` (живой владелец — каталог остаётся; мёртвый — каталог и запись выписки убраны). Существующие тесты без правок и зелёные.

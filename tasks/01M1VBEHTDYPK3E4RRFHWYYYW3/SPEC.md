# SPEC: команда `note` — строка в копилку/бэклог изолированным коммитом от origin/main

## Контекст
Правило проекта (CLAUDE.md, `docs/operator-session.md`, решение 06.09):
аномалия фиксируется в `docs/backlog.md` сразу, изолированным коммитом
с push, поскольку главная копия пульта стоит на пине (ADR-0013) и
коммитить документы из неё нельзя. Сейчас это исполняется 40-строчным
сценарием оболочки (scratch-worktree от `origin/main`, правка Python,
коммит, push с повторами, уборка) вручную на каждый заход — 12 заходов
за 06.09, два с осложнениями (сеть, потеря коммита при уборке
worktree). Нужна штатная команда пульта `note`, закрывающая тот же
сценарий без ручного воспроизведения оболочки.

## Требования
1. `artel.py note (копилка|бэклог|очередь) --text "<строка таблицы без
   внешних |>" [--task <id>]` берёт `origin/main` (fetch) и в эфемерном
   git-окружении (worktree/клон) вставляет `<строка>` первой сразу
   после строки-разделителя таблицы указанного раздела `docs/backlog.md`
   (разделы — как заголовки файла: «Копилка», «Бэклог», «Очередь
   Оператора»).
2. Число ячеек `<строка>` (по `|`) сверяется с числом ячеек
   строки-шапки таблицы раздела (текущие значения: 5 у копилки, 6 у
   бэклога, 3 у очереди — читается из фактической шапки, не жёстко
   закодированным списком); несовпадение — именованный отказ с
   указанием ожидаемого числа колонок, коммит не создаётся.
3. Успешная вставка коммитится сообщением `оператор: <раздел> —
   <первые 80 символов текста>` и пушится в `origin/main`.
4. Push, отклонённый как non-fast-forward, повторяется с новым fetch —
   до 3 раз.
5. Коммит никогда не теряется: сетевой отказ push либо исчерпание
   повторов non-fast-forward — коммит остаётся удержанным
   (`.artel/notes-pending/` либо локальная ветка `notes-pending`) для
   последующей отправки.
6. `doctor` предупреждает о наличии удержанных неотправленных заметок.
7. Повторный вызов `note` (в т.ч. `note --flush`, без `--text`) пытается
   допушить все ранее удержанные коммиты.
8. `note --append <подстрока-ключ> --text "<текст>"` находит
   существующую строку раздела по подстроке-ключу и дописывает `<текст>`
   в последнюю колонку найденной строки тем же механизмом (коммит,
   push, повтор, удержание); ровно ноль или больше одного совпадения —
   отказ без изменения файла (проверка числа колонок к `--append` не
   применяется — структура строки не меняется).
9. Успешная запись (вставка либо `--append`) добавляет в журнал пульта
   запись без `task_id`, actor `operator`: «заметка: <раздел> <sha>»
   — чтобы `report` считал частоту аномалий.
10. HEAD главной копии пульта не меняется командой `note` ни при каком
    исходе (пин, ADR-0013).
11. `docs/operator-session.md` правится приложением: правило «копилка
    сразу» описывается как исполняемое командой `note`, упоминания
    сценария со scratch-worktree снимаются.

## Критерии приёмки
AC-1. Вызов `note <раздел> --text "<строка>"` в песочнице с локальным
`origin` создаёт ровно один коммит, меняющий только `docs/backlog.md`;
строка на месте.

AC-2. Вставленная строка располагается первой сразу после
строки-разделителя таблицы выбранного раздела.

AC-3. Число колонок `--text` сверяется с числом колонок шапки таблицы
раздела; при несовпадении — отказ с указанием ожидаемого числа колонок,
коммит не создаётся (мутация: снятие проверки — отказ на 4 колонках
пропадает — тест красный).

AC-4. Коммит несёт сообщение `оператор: <раздел> — <первые 80 символов
текста>`.

AC-5. HEAD «главной копии» песочницы не меняется в ходе выполнения
`note` при успешном исходе.

AC-6. Push, отклонённый как non-fast-forward, повторяется с новым
fetch — до 3 раз.

AC-7. Сетевой отказ push (или исчерпание повторов non-fast-forward) —
коммит удерживается (`.artel/notes-pending/` либо ветка
`notes-pending`), не теряется; `doctor` выдаёт предупреждение о
удержанных заметках.

AC-8. Повторный вызов `note` (в т.ч. `note --flush`) допушивает
удержанный коммит — `doctor` перестаёт предупреждать после успешной
отправки.

AC-9. `note --append <подстрока-ключ> --text "<текст>"` меняет ровно
одну существующую строку раздела (дописывает текст в последнюю
колонку); ноль или более одного совпадения подстроки — отказ без
изменения файла.

AC-10. Успешная запись (вставка либо `--append`) добавляет в журнал
пульта запись без `task_id`, actor `operator`, вида «заметка: <раздел>
<sha>».

AC-11. `docs/operator-session.md` описывает правило «копилка сразу»
как исполняемое командой `note`; упоминания сценария со
scratch-worktree в тексте документа сняты.

AC-12. Существующие `tests/test_doctor.py` и существующие тесты CLI
пульта остаются зелёными после изменений.

## Не входит
- Правка роадмапа и ADR — остаются ручными документными коммитами.
- Автоматическое сведение дублей копилки — скил ревизии.
- Семантика `--task <id>` сверх приёма флага командой: ТЗ вводит флаг
  в сигнатуре CLI, но не определяет его эффект ни в одном из
  требований 1–5 (журнал явно без `task_id` — требование 3/9); флаг
  принимается, поведение сверх этого не специфицируется и не
  реализуется в этой задаче.
- Разрешение конфликтов слияния таблицы `docs/backlog.md` сложнее
  non-fast-forward с повтором (например, семантическое объединение
  правок) — вне сценария ТЗ.

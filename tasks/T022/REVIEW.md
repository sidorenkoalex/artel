## Замечания

- minor — `orchestrator/doctor.py:487-513` (`check_base_branch`) вызывается
  из `all_checks()` (`orchestrator/doctor.py:536-539`) для ВСЕХ объявленных
  в `targets.yaml` записей без исключения `config.DEFAULT_TARGET`, хотя
  SPEC требование 9 говорит про эту проверку явно: «для внешних target —
  сверка базовой ветки с targets.yaml». Реальный `targets.yaml` содержит
  запись `artel` (сам пульт, `forge: github`, `url: .../sidorenkoalex/
  artel`) — то есть боевой прогон `doctor` каждый раз дополнительно делает
  живой `gh repo view` для репозитория пульта, хотя эта проверка по тексту
  требования предназначена только для внешних целевых. Соседние проверки
  того же цикла корректно закрывают этот же класс: `check_remote_empty`
  (`doctor.py:474-476`, `if target == config.DEFAULT_TARGET: return
  Check(..., "skip", ...)`) и `recovery_check` (`doctor.py:347-348`, тот
  же паттерн, тест `RecoveryCheckTest::test_dogfood_is_out_of_scope`) —
  только `check_base_branch` не получил такого же исключения. Практическое
  последствие мягкое (для догфуда base и так `main`, `check_base_branch`
  никогда не заводит `alerts` и не возвращает `fail` — только `ok`/`warn`/
  `skip`, так что `doctor` не падает и не шлёт ложный инцидент), но это
  лишний сетевой вызов вне заявленного текстом требования 9 объёма и
  расхождение с образцом двух соседних проверок. Предложение: та же
  ранняя проверка `if name == config.DEFAULT_TARGET: return Check(...,
  "skip", "догфуд — вне объёма сверки forge-политики")`, что и в
  `check_remote_empty`/`recovery_check`.

- minor — `orchestrator/doctor.py:487-513` (`check_base_branch`) —
  тестами не покрыт вовсе: `grep -n "check_base_branch" tests/test_doctor.py`
  ничего не находит. Функция неявно исполняется внутри
  `DoctorCommandTest` через `all_checks()`, но там `shutil.which`
  замокан так, что `gh` никогда не находится (`doctor.py:493-495`
  `gh = shutil.which("gh")` → `None` → сразу `skip`) — единственная
  исполняемая ветка в тестах. Ветки `forge != "github"` (skip), успешного
  разбора `gh repo view` (ok при совпадении, warn при расхождении
  `targets.yaml` base с форджем) и таймаута/ошибки `gh` не задеты ни
  одним тестом — мутация в логике сравнения `remote_base != entry["base"]`
  (например, инвертировать условие) не будет поймана существующим
  набором. Не блокирую (соответствует критериям приёмки SPEC — п.9 явно
  не входит в перечень тестируемых критериев 1–8), но стоит закрыть
  вместе с предыдущим замечанием: тест на `check_base_branch` с
  подменённым `subprocess.run` (совпадение/расхождение веток) заодно
  зафиксирует и границу «внешний target».

Тесты и `guard.py --all` — зелёные (перепроверено локально в этой
итерации): `python3 scripts/guard.py --all` → «GUARD: ок (57 файлов)»;
`python3 -m unittest discover -s tests -p 'test_*.py'` → 445 тестов,
3 провала, все три — `test_multitarget.RoleEnvTest`
(`test_absent_identity_is_journalled_before_the_step`,
`test_env_carries_the_git_identity`,
`test_identity_already_in_the_environment_is_not_overridden`). Не регресс
этой ветки: воспроизведено во временном worktree `main` (`c3f47f7`) без
диффа T022 — та же тройка падений с теми же сообщениями (утечка ambient
`GIT_AUTHOR_NAME`/`GIT_AUTHOR_EMAIL`/`GIT_COMMITTER_EMAIL` машины, где
гоняются тесты).

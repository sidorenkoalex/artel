# SPEC: A3 — doctor: pre-flight, recovery-сверка, таблица alerts

## Контекст

Пятая задача фазы A (roadmap §2 A3). Сегодняшний инцидент T020
показал цену отсутствия pre-flight: регрессия auth в чистом HOME
обнаружилась тремя ретраями упавшего агента вместо секундной
проверки с именованной причиной (реестр отказов v5 №25). Сейчас
у системы нет ни проверки окружения перед шагом, ни recovery-сверки
после сбоя/восстановления, ни носителя алертов — пороги программы
(T019) пишут события в журнал, отдельной таблицы с ack нет.

## Требования

1. **Команда `doctor`** — прогон всех проверок ниже с итогом
   по каждой (ок / предупреждение / провал, с причиной и починкой);
   ненулевой код выхода при провалах.
2. **Pre-flight перед каждым шагом агента** (в runner, до запуска):
   быстрые проверки — CLI найден и его версия равна пину (п.5);
   токен роли добывается (keychain-цепочка T019); git-идентичность;
   диск не переполнен; для внешнего target — workspace и артефактный
   репо на месте. Провал = шаг не начинается с именованной причиной
   (по образцу существующих отказов runner), не три ретрая.
3. **Живой смоук CLI** (реестр v5 №25; из pre-flight НЕ вызывается —
   дорого; часть `doctor` и обязателен после изменения
   runner/config/roles/пина): минимальный реальный вызов `claude`
   из окружения роли (крошечный промпт), проверяется код возврата
   и наличие стоимости в финальном событии; результат в журнал.
4. **Recovery-сверка при старте оркестратора после сбоя** и явный
   `doctor --restore` после восстановления .artel/ из бэкапа:
   журнал БД ↔ файлы задач (git fsck артефактных репо, sha головы
   против зафиксированного T021); расхождение = алерт kind=incident,
   не молчаливая работа со стухшим состоянием.
5. **Пин версии CLI**: ожидаемая версия в конфиге пульта; doctor
   и pre-flight сверяют `claude --version` с пином; расхождение —
   предупреждение (обновление пина — осознанный шаг Оператора).
6. **Смоук изоляции обоих векторов** (ADR-0003 п.14): подложный
   маркер в project-слое (CLAUDE.md рабочего каталога) и в user-слое
   (HOME Оператора) не достигает окружения/промпта роли — прогоном
   `role_env` и сборки промпта, без реального CLI (живой вариант —
   в составе п.3 по флагу).
7. **Таблица alerts в БД** (kind: incident | threshold | trigger;
   сообщение, источник, ts, ack с решением): пороги программы T019
   переводятся с журнальных событий на alerts (kind=threshold);
   сироты и расхождения recovery — kind=incident; вычислимые
   триггеры docs/triggers.md (№1 SQLITE_BUSY, №2 задач/неделю) —
   kind=trigger, отдельная секция в выводе `status`/`doctor`;
   ack триггера обязан нести решение (docs/triggers.md, правила).
8. **Проверка сирот** (уровень 2 чистки v5): каталоги
   `projects/<target>/tasks/` без строки БД; локальные ветки task/*
   у задач в done/killed; worktree без живой задачи — алерт
   kind=incident.
9. **Прочие проверки doctor**: давность бэкапа .artel/ (>7 дней —
   алерт); «remote пуст» у артефактных репо (функция готова в T021 —
   подключить); для внешних target — сверка базовой ветки
   с targets.yaml (сверка merge-политики — по возможностям forge,
   иначе честный skip с причиной).

## Критерии приёмки

1. `doctor` на здоровом репо — все проверки ок, код выхода 0;
   на сломанном (нет токена в keychain-цепочке, версия CLI ≠ пин,
   сирота-каталог) — именованные провалы, код ≠ 0 (тесты
   с подменёнными keychain/CLI/ФС).
2. Тест: pre-flight ловит отсутствие токена до запуска агента —
   шаг не начат, причина в журнале содержит починку; ретраев нет.
3. Тест смоука изоляции: маркеры в project- и user-слое
   не достигают env и промпта роли; сломанная изоляция (маркер
   пролез) — провал смоука.
4. Тест: recovery-сверка ловит расхождение sha головы с журналом
   и грязный артефактный репо — алерт kind=incident.
5. Тест: пороги 70/90% программы создают строки alerts
   kind=threshold (перевод с журнальных событий); повторный прогон
   не дублирует алерт.
6. Тест: ack алерта kind=trigger без текста решения — отказ.
7. Тест сирот: каталог без строки БД, ветка done-задачи, worktree
   без задачи — три алерта kind=incident.
8. Живой смоук: команда существует, в тестах — с подменённым CLI;
   один ручной прогон настоящего смоука — manual-критерий приёмки
   Оператора (исполнить ДО approve acceptance).
9. Все существующие тесты и guard --all зелёные.

## Не входит

- Демон/поллер и health-check C0 (фаза C).
- Панель и отображение alerts сверх CLI-вывода (П2′/этап 2).
- Регресс-флаги report (вставка фазы B, отчёт v5 №2).
- Изменение механики бюджетов и фиксации (T019/T021 — потребители,
  не предмет).
- Флаги --setting-sources/--strict-mcp-config (B1a).

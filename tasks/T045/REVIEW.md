## Замечания

- blocker — процесс, не код — итерация 2 не содержит ни одного нового
  коммита относительно коммита вердикта итерации 1
  (`39fe0e948bf53778f0234ef0e7881a5cad738fe3` == текущий HEAD ветки,
  подтверждено `git log --all --grep=T045` и `git reflog --all` — правок
  по замечаниям прошлого ревью нет нигде). Ни один из пунктов
  `changes_requested` итерации 1 не устранён. Сценарий последствий:
  если это ревью аппрувить (или пропустить), в `main` уйдёт код с той же
  незащищённой lease'ом мутирующей командой `workspace <id>`, ради
  устранения класса которой и открыта задача T045 (SPEC «Контекст»:
  инциденты параллельных сессий) — то есть основной риск задачи останется
  неисправленным, а FSM отметит итерацию как пройденную. Предложение:
  вернуть задачу разработчику для фактического внесения правок из
  итерации 1 (замечания 1–3 ниже, дословно те же) до следующего
  ревью; не продвигать по гейту, пока диф не станет непустым.

- major (повтор замечания итерации 1, не устранено) —
  `orchestrator/workspace.py:117-125` (`cmd_workspace`) и
  `orchestrator/artel.py` (регистрация команды `workspace`) — новая
  мутирующая команда задачи по-прежнему не берёт lease перед работой, в
  отличие от всех остальных мутирующих команд задачи в системе
  (`run`/`auto`/`approve`/`reject`/`kill`/`budget`; SPEC T044
  требование 2). `cmd_workspace` вызывает `ensure()` напрямую, без
  какой-либо сериализации. Сценарий поломки (как в итерации 1):
  Оператор вызывает `artel.py workspace T050` в момент, когда
  параллельная сессия уже держит lease T050 и внутри `auto`/`run` сама
  вызывает `role_cwd` → `workspace.ensure` для той же задачи — гонка на
  `git worktree add [-b]`, невезучая сторона получает сырую ошибку git
  вместо «lease занят сессией X». Предложение прежнее: обернуть
  `cmd_workspace` тем же приёмом `lease.acquire`/`lease.release`
  (+ `session_id`), что и у `cleanup.cmd_kill`/`runner.cmd_run`.

- minor (повтор замечания итерации 1, не устранено) —
  `orchestrator/workspace.py:112` (`remove`) — при отказе `git worktree
  remove --force` с ненулевым кодом возврата, но пустым `stderr`,
  причина отчёта — пустая строка (`res.stderr.strip()[:200]` без
  запасного текста), в отличие от `ensure()` в этом же файле, где на
  тот же вырожденный случай есть фоллбэк `f"git worktree add вернул
  {rc}"`. Предложение прежнее: добавить тот же фоллбэк по returncode.

- minor (повтор замечания итерации 1, не устранено) —
  `orchestrator/cleanup.py:96-102` — комментарий у ветки `elif
  gitcmd.current_branch() == branch:` («Агент работает в этом же
  дереве (cmd_run: cwd=ROOT)...») по-прежнему описывает механизм,
  которого после T045 больше нет (`cmd_run` теперь работает в worktree,
  не в ROOT). Предложение прежнее: поправить на «Оператор мог руками
  зачекаутить ветку задачи в ROOT» (или аналогично), без изменения
  логики.

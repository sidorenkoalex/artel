# SPEC: Worktree-норма: рабочая поверхность на задачу

## Контекст
Сейчас все сессии и все роли работают в одной рабочей копии пульта
(`config.ROOT`). Инциденты 26–27.08: коммит правки роадмапа Оператором
ушёл в ветку T041 (дерево было переключено агентом); временный worktree
проверки создался внутри репозитория; два параллельных `auto` в одном
дереве — гарантированная авария, которая блокирует параллельные сессии
разных задач. Решение Оператора 27.08 (P3, кластер «параллельные
сессии»): рабочая поверхность на задачу — отдельный git worktree.

## Требования

1. Команда `workspace <id>` создаёт (или, если worktree уже есть, выдаёт
   путь существующего) git worktree задачи на её ветке в стандартном
   месте вне рабочей копии (`.artel/worktrees/<id>`); повторный вызов
   идемпотентен.
2. Агентные шаги задачи (`run`/`auto`) исполняются в worktree её
   задачи, не в главной копии: `role_cwd` указывает туда, ветка задачи
   живёт там.
3. Мутирующие команды задачи сверяют, что действуют в правильной
   рабочей поверхности (worktree своей задачи — для агентных шагов,
   главная копия на `main` — для команд оркестратора), и отказывают
   с подсказкой при несоответствии.
4. Главная копия — территория оркестратора: `cmd_new`, `merge_gate`
   (merge, карта, RETRO) работают в ней на `main`; агентные шаги туда
   не ходят.
5. `kill` и `done` убирают worktree задачи (существующая уборка
   расширяется).
6. Проверка сирот-worktree в `doctor` (A3) покрывает стандартное место
   (`.artel/worktrees/<id>`): легитимный per-task worktree известной
   задачи сиротой не считается.

## Критерии приёмки

AC-1. `workspace <id>` создаёт worktree на ветке задачи в стандартном
месте (`.artel/worktrees/<id>`) и печатает путь.

AC-2. Повторный вызов `workspace <id>` возвращает тот же путь без
ошибки (идемпотентность).

AC-3. Агентный шаг задачи исполняется в её worktree: рабочая копия
пульта остаётся на `main` и не переключается запуском `run`/`auto`.

AC-4. Два `auto` разных задач работают одновременно без пересечения
рабочих поверхностей (проверяется смоук-тестом в песочнице).

AC-5. `kill` убирает worktree задачи.

AC-6. `done` убирает worktree задачи.

AC-7. `merge_gate` по-прежнему работает в главной копии пульта на
`main` и остаётся единственным писателем `main`.

AC-8. Мутирующая команда задачи, действующая не в предназначенной ей
рабочей поверхности (worktree своей задачи — для агентных шагов,
главная копия на `main` — для команд оркестратора), отказывает
с подсказкой вместо выполнения.

AC-9. Проверка сирот-worktree в `doctor` не считает сиротой легитимный
per-task worktree в стандартном месте, принадлежащий известной задаче;
worktree вне этого соответствия по-прежнему считается сиротой.

AC-10. Существующий набор тестов проходит зелёным.

## Не входит

- Изменение `cmd_new`: создание ветки/worktree задачи при заведении —
  отдельная будущая задача («ТЗ в ветке», ADR-0005 п.9, явно «после
  T045»); в этой задаче `cmd_new` продолжает работать как раньше, в
  главной копии на `main`.
- Разъезд с брифом/картой кодовой базы — бриф по-прежнему собирает
  оркестратор, как и раньше (ТЗ, «Границы»).
- Нестандартная механика изоляции рабочих деревьев — используется
  штатный git worktree.
- Новые примитивы чтения/фиксации артефактов по веткам — используются
  существующие ветко-корректные примитивы `gitcmd` (T031), не
  дублируются.
- Правки `.gitignore` под `.artel/worktrees` — каталог `.artel` уже
  вне git целиком.
- Ослабление или снятие существующих инвариантов, тестов, гейтов,
  лимитов и guard-проверок.
- Распространение worktree-нормы на workspace внешних target
  (`.artel/projects/<target>/workspace/`) — и ТЗ, и инциденты касаются
  рабочей копии пульта (`config.ROOT`); других активных target до A7
  нет (ADR-0003 3д).

# ТЗ: Worktree-норма: рабочая поверхность на задачу

Worktree-норма сессий: рабочая поверхность на задачу (строка P3, кластер «параллельные сессии»; решение Оператора 27.08).

Проблема: одна рабочая копия пульта на все сессии и все роли. Инциденты 26-27.08: коммит правки роадмапа Оператором ушёл в ветку T041 (дерево было переключено агентом); временный worktree проверки создался внутри репозитория; два параллельных auto в одном дереве — гарантированная авария, что блокирует параллельные сессии разных задач.

Что сделать: (1) команда `workspace <id>` — создаёт (или выдаёт путь существующего) git worktree задачи на её ветке в стандартном месте вне рабочей копии (например .artel/worktrees/<id>); повторный вызов идемпотентен. (2) Агентные шаги задачи (runner) исполняются в worktree её задачи, не в главной копии: role_cwd указывает туда, ветка задачи живёт там. (3) Мутирующие команды задачи сверяют, что действуют в правильной поверхности, и отказывают с подсказкой при несоответствии. (4) Главная копия — территория оркестратора: cmd_new, merge_gate (merge, карта, RETRO) работают в ней на main; агентные шаги туда не ходят. (5) kill и done убирают worktree задачи (существующая уборка расширяется); doctor уже ловит сирот-worktree (A3) — сверить, что стандартное место покрыто.

Границы: механика git worktree стандартная; фиксация/чтения ветко-корректны с T031 — использовать существующие примитивы gitcmd; никакие инварианты не ослабляются; .artel/worktrees — вне git (гитигнор .artel уже покрывает). Разъезд с брифом/картой не меняется (бриф собирается оркестратором как раньше).

Критерии приёмки (ориентир): (1) `workspace <id>` создаёт worktree на ветке задачи в стандартном месте и печатает путь; повторно — тот же путь без ошибки; (2) агентный шаг задачи исполняется в её worktree: рабочая копия пульта остаётся на main и не переключается запуском run/auto; (3) два auto разных задач работают одновременно без пересечения поверхностей (смоук-тест песочницей); (4) kill убирает worktree задачи; done — тоже; (5) merge_gate по-прежнему работает в главной копии и остаётся единственным писателем main; (6) существующий набор тестов зелёный.

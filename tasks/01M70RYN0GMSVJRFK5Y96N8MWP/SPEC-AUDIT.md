## Факты против кода
- `tests/test_suite_lock.py:37-73` — метод `test_wait_reports_holder_once_per_holder_and_gives_up_at_limit`. Подтверждено: `:51` — `mock.patch.object(suite_lock, "POLL_SEC", 0.01)`; `:57` — предел 0.2; `:67-70` — смена держателя в `on_wait`; `:72-73` — второе ожидание и `assertEqual(calls, …)`; `:46-49` — строка «Ловит мутацию».
- `orchestrator/suite_lock.py:126` — `deadline = time.monotonic() + limit_sec` вычисляется до первого `acquire` (`:129`); проверка предела стоит после `on_wait` (`:136-138`). Подтверждено: если первый `acquire` и `on_wait` заняли больше 0,2 с по настоящим часам, функция возвращается без второго опроса. Значит, вероятная причина из ТЗ согласуется с кодом.
- «Атрибут `time` модуля целиком»: модуль пользуется `time.monotonic` (`:126`, `:136`), `time.sleep` (`:139`), `time.time` (`_fresh`, `:79`) и `time.time_ns` (`defer_journal`, `:238`). `defer_journal` тестом не вызывается, а `deliver_journal` (`:125`) часов не читает. Набора `monotonic`/`sleep`/`time` достаточно. Подтверждено опытом (ниже).
- Мутация (б): «исход `None`, файл переписан». Подтверждено опытом: без проверки живого держателя (`:105-106`) исход `None`, в файле замка `task_id` `T1`.
- «Глобальный `time.monotonic` — на нём таймер pytest-timeout». Опытом не проверено: чтение исходника плагина отклонила песочница. На POSIX метод по умолчанию у pytest-timeout — `signal` (`setitimer`), так что мотивировка сомнительна. Сам запрет верен по другой причине: глобальная подмена ломает `threading`/xdist. На исход не влияет, отклонения нет.
- Опыт (временный процесс `python3 -c`, `config.LOGS` во временном каталоге, `suite_lock.time` заменён объектом `Clock`: `monotonic` возвращает счётчик, `sleep` продвигает его и бросает исключение после 1000 вызовов):
  - исходный код, в обоих `on_wait` реальная пауза 0,3 с (больше предела) → зелёный, по 2 опроса в каждом ожидании;
  - мутация «`on_wait` на каждом опросе» → красный (`seen` = два держателя);
  - мутация «без предела» (снят `if remaining <= 0: return`) → красный, `RuntimeError` на 1001-м sleep за 0,08 с;
  - мутация «поверх держателя» → красный;
  - мутация «без предела и без паузы» (сняты и проверка предела, и `time.sleep`) → **зависание, процесс убит по таймауту 8 с**. См. D2.

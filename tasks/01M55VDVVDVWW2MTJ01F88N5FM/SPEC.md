# SPEC: Мандат на ослабление тестов внешнему проекту — проверка при записи по профилю проекта

## Контекст
Мандат Оператора на ослабление тестов — строка `Ослабление тестов разрешено:
<путь[::имя]>` в ANSWER-n.md (`docs/operator-session.md:81`). Команда
`answer` проверяет её до коммита (`orchestrator/answer.py:113-118` →
`mandate.refusals`), и элемент отказывается правилом
`orchestrator/advance_gates/mandate.py:159-165`: `in_weakening_scope(path)`
(`:103-111`) пропускает только `tests/**/*.py` — область артели. Гейт
неослабления при этом берёт область из профиля проекта задачи
(`test_integrity.py:1518`, `fsm_merge_gate.py:146`, `review.py:644` —
`decision.profile.in_weakening_scope`); у sled `weakening_scope:
[backend/tests/**/*.py]` (`targets.yaml:87`). Итог: у внешнего проекта
мандат на `backend/tests/…` отклоняется `answer`, хотя гейт такую находку
назвал бы, — находка гейта у внешнего проекта мандатом неснимаема.

Сверка по коду (требование 2 ТЗ):
- `mandate.refusals` из продакшена зовёт только `answer.py:113`, и там
  `conn`/`task_id` уже передаются.
- `test_integrity._in_scope` (`test_integrity.py:227-244`, зовёт
  `mandate.in_weakening_scope`) — только запасная область `_compare`
  (`:664`) при `scope=None`; все продакшен-вызовы рубежей передают
  область профиля. На пути задачи внешнего проекта её нет — правка не
  требуется.
- `mandate.matrix_refusals` (`answer.py:157` для `answer`, `answer.py:487`
  для `zones-extend`): ссылка на тест в ячейке «Чем покрыто после»
  распознаётся `_TEST_REF_RE` (`mandate.py:264`, `(?<![\w/])tests/…\.py`),
  и `backend/tests/test_y.py` ссылкой не считается — у внешнего проекта
  строка матрицы «свойство остаётся» с таким покрытием отказывает, если
  «Решение» не «ок при условии». Место в зоне задачи — требование 4.
- Проверки формы элемента (`_looks_like_path`, `_qualified_name_ok`,
  пробел, голый маркер) от проекта не зависят — правка не требуется.

Выбор поведения без определённого профиля (требование 1 ТЗ), по принципу
«проверка при записи отказывает ровно тому, что гейт заведомо не
засчитает»:
- задача не передана (`conn`/`task_id` нет) — сегодняшнее поведение
  (область артели, сегодняшний текст): так зовут узел юнит-тесты, и
  продакшен-вызова без задачи нет;
- `project_profile.decide` вернул отказ (контекст не разрешён, профиль не
  прочитан, у артели нет профиля) — гейт на том же решении отказывает
  переходу (`test_integrity.py:1509-1512`), мандат им не засчитывается
  ни при каком пути — именованный отказ элементу с причиной решения;
- профиля нет у внешнего проекта (`decision.skip`) — гейт не выполняется
  вовсе (`test_integrity.py:1513-1516`, `fsm_merge_gate.py:137-141`),
  мандат засчитывать нечему — именованный отказ элементу с причиной
  пропуска.
Сегодняшняя область артели для двух последних случаев отказывала бы
верному пути внешнего проекта текстом «вне области tests/**/*.py»,
который ложно указывает на ошибку пути, а не на профиль.

## Требования

1. Проверка элемента мандата ослабления при записи ответа
   (`mandate.refusals` / `_element_refusal`) при переданной задаче
   (`conn`, `task_id`) берёт область ослабления из профиля проекта задачи
   той же формулой, что гейт: `project_profile` → `Profile.in_weakening_scope`.
   Элемент вне области отказывается текстом, называющим область профиля
   проекта (маски `weakening_scope`).
2. Без задачи (`conn`/`task_id` не переданы) — сегодняшнее поведение:
   область `tests/**/*.py` и сегодняшний текст отказа. Решение профиля
   задачи — отказ (`Decision.refusal`) либо пропуск (`Decision.skip`) —
   элемент мандата ослабления отказывается именованной причиной, несущей
   текст этого решения (обоснование — «Контекст»).
3. У артели решения проверки мандата при записи и тексты отказов не
   меняются: путь вне области отказывается тем же текстом «путь вне
   области tests/**/*.py — гейт неослабления тестов другие пути не
   рассматривает», путь в области принимается. Это зафиксировано тестами
   до правки. Оговорка (решение Оператора 18.10): у артели в
   деградированном состоянии — `targets.yaml` не читается или у записи
   артели нет `test_profile`, и решение профиля — отказ — элемент
   мандата ослабления при записи отказывается по требованию 2 (именованной
   причиной решения профиля), а не принимается по области `tests/**/*.py`:
   в том же состоянии отказывают гейт перехода
   (`test_integrity.py:1509-1512`) и гейт мержа.
4. Проверка формы матрицы неослабления (`mandate.matrix_refusals`) в
   каналах `answer` и `zones-extend --matrix` для задачи с профилем
   проекта засчитывает ссылкой на тест в ячейке «Чем покрыто после»
   только путь `*.py`, лежащий в области ослабления профиля (за ним может
   стоять `:строка` или `::имя`), — вместо `tests/…`: у внешнего проекта
   путь `tests/…` вне его `weakening_scope` ссылкой на тест не считается.
   У артели и без задачи решения проверки матрицы прежние.
5. Тесты детерминированы и без сети: учебный внешний проект с
   `weakening_scope: [backend/tests/**/*.py]` и проект артели.

## Критерии приёмки

AC-1. У артели проверка мандата ослабления при записи прежняя: `answer`
задачи артели принимает `Ослабление тестов разрешено:
tests/test_x.py::T::test_a` и отказывает `backend/tests/test_x.py` с
текстом «путь вне области tests/**/*.py — гейт неослабления тестов другие
пути не рассматривает»; `mandate.refusals` без `conn`/`task_id` даёт те же
исходы и тексты.

AC-2. У учебного внешнего проекта с `weakening_scope:
[backend/tests/**/*.py]` `answer` принимает мандат
`backend/tests/test_x.py::T::test_a` и отказывает `tests/test_x.py` (вне
области проекта) текстом, называющим область проекта
`backend/tests/**/*.py`; ANSWER при отказе не создаётся.

AC-3. Мандат, принятый `answer` для задачи внешнего проекта, засчитывается
гейтом неослабления той же задачи: находка гейта на
`backend/tests/test_x.py::T::test_a` (например, удалённый метод) без
мандата отказывает переходу `in_dev -> verifying`, с этим мандатом —
покрыта и переходу не отказывает (сквозной тест).

AC-4. У задачи, чьё решение профиля — отказ (например, профиль проекта
не прочитан) или пропуск (внешний проект без `test_profile`), `answer` с
мандатом ослабления отказывает, и текст отказа несёт причину решения
профиля; ANSWER не создаётся.

AC-5. Проверка матрицы неослабления у задачи учебного внешнего проекта —
в каждом из двух каналов, `answer` и `zones-extend --matrix`, —
засчитывает покрытием ячейку «Чем покрыто после» со ссылкой
`backend/tests/test_y.py` (строка «свойство остаётся» с «Решение» без «ок
при условии» не отказывает) и не засчитывает ссылку `tests/test_y.py`
(та же строка с ней отказывает); у задачи артели в обоих каналах матрица
со ссылкой `backend/tests/test_y.py` отказывает, а со ссылкой
`tests/test_y.py` принимается — как сегодня.

AC-6. У задачи артели, чьё решение профиля — отказ (`targets.yaml` не
читается или у записи артели нет `test_profile`), `answer` с мандатом
ослабления `tests/test_x.py::T::test_a` отказывает, текст отказа несёт
причину решения профиля; ANSWER не создаётся.

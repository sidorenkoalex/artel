# Мандат на ослабление тестов внешнему проекту: проверка при записи по профилю проекта

## Факты

Строка копилки 17.10 (приоритет 1). Мандат Оператора на ослабление тестов даётся строкой `Ослабление тестов разрешено: <путь[::имя]>` в ANSWER-n.md (`docs/operator-session.md:81`). Команда `answer` проверяет строку до коммита (`orchestrator/answer.py:113-118` → `mandate.refusals`), и элемент мандата отказывается правилом `orchestrator/advance_gates/mandate.py:159-164`: `in_weakening_scope(path)` (`:103-111`) пропускает только пути `tests/**/*.py` — область артели.

Гейт неослабления тестов при этом уже берёт область из профиля проекта задачи (`test_profile.weakening_scope`): `advance_gates/test_integrity.py:1518`, `fsm_merge_gate.py:146`, `review.py:644` — `decision.profile.in_weakening_scope`. У sled `weakening_scope: [backend/tests/**/*.py]`.

Следствие: для задачи внешнего проекта строка `Ослабление тестов разрешено: backend/tests/…` отклоняется `answer` как «путь вне области tests/**/*.py», хотя гейт такую находку назвал бы; находка гейта неослабления у внешнего проекта неснимаема мандатом.

Отдельно проверить: место `test_integrity.py:238-244` (функция, зовущая `mandate.in_weakening_scope`) — кто её вызывает и на пути ли она задачи внешнего проекта.

## Требуется

1. Проверка элемента мандата ослабления при записи ответа (`mandate.refusals` / `_element_refusal`) использует область ослабления профиля проекта задачи (`project_profile` той же формулой, что гейт: `Profile.in_weakening_scope`), когда известна задача (`conn`, `task_id` уже передаются из `answer`). Без задачи или при отказе определения профиля — сегодняшнее поведение (область артели) либо именованный отказ; выбор аналитик обосновывает в SPEC по принципу «проверка при записи отказывает ровно тому, что гейт заведомо не засчитает».
2. Аналитик сверяет по коду все остальные вызовы `mandate.in_weakening_scope` и проверок формы мандата и матрицы неослабления (`mandate.matrix_refusals`, `answer.py:157`) на пути задачи внешнего проекта; найденное в зонах — в требования, вне зон — эскалация до SPEC.
3. У артели тексты отказов и решения проверки не меняются; зафиксировать тестами до правки.
4. Тесты детерминированы, без сети: учебный внешний проект с `weakening_scope: [backend/tests/**/*.py]` — `answer` принимает мандат `backend/tests/test_x.py::T::test_a` и отказывает `tests/test_x.py` (вне области проекта); у артели — прежние исходы.

Критерии приёмки:
- у артели проверка мандата при записи и её тексты прежние;
- у учебного внешнего проекта мандат на путь из его `weakening_scope` принимается, на путь вне области — отказ с текстом, называющим область проекта;
- мандат, принятый `answer` для внешнего проекта, засчитывается гейтом неослабления той же задачи (сквозной тест на находку гейта).

# QUESTIONS: Слежение за ценой набора тестов по отчёту junit CI main (ADR-0032, этап 1)

## Вопросы

Контекст батча: аудит SPEC вернул SPEC (возврат 1 из 2) с 11 отклонениями.
Часть из них — расхождение ТЗ с кодом или неопределённость, которую
аналитик сам не снимает (вопросы ниже). Остальные отклонения (вход и ключи
выхода `summarize`, простые выходы поверхностей вместо `tuple`/`SuiteReport`,
сверка состава полей `TestReport`, критерий «`migrate()` на БД без таблицы
её создаёт», равенство вывода команды выводу функции, отсутствие команды в

1. **`--record-latest`: «независимо от цвета прогона» против `forge.green_base_commit`.** `green_base_commit` (`orchestrator/forge.py:460-492`) читает только прогоны со `status=success` (`:467`): красный прогон `main` с исполненным заданием он не найдёт, и требование 5 ТЗ в его формулировке невыполнимо. Что делает `--record-latest`?
   - A) Записывает только последний зелёный коммит `main` с исполненным заданием — `green_base_commit` как есть, слова «независимо от цвета» из требования снимаются.
     - ломается: красный прогон `main` (в том числе с отчётом junit — артефакт выгружается при любом исходе, ТЗ факт 2) сводки не получает; рост набора в красной полосе `main` не виден до первого зелёного.
     - ослабляется: полнота ряда сводок ADR-0032 п. 6 («каждого прогона CI `main`»); `green_base_commit` и его вызов в `orchestrator/doctor/project_checks.py:580` — без изменений.
     - цена: ноль сверх текущего объёма.
     - чьё решение: Оператор.
   - B) Новая функция в `orchestrator/forge.py` (зона задачи): последний коммит `main`, у которого задание `ci.FULL_SUITE_JOB` завершено с любым заключением, кроме `skipped` (`success`, `failure`, `timed_out`, `cancelled`); незавершённые прогоны пропускаются. `green_base_commit` не меняется.
     - ломается: ничего существующего; добавляется ещё один публичный вызов GitHub API в `forge`.
     - ослабляется: ничего; `green_base_commit` (`forge.py:460`) и его потребитель `project_checks.py:580` — без изменений.
     - цена: +1 функция и +1 критерий с подменой `gh` (зелёный, красный, оборванный, `skipped` прогоны), ~+$3–5.
     - чьё решение: Оператор.
   - C) Параметр цвета у самого `green_base_commit`.
     - ломается: сигнатура существующей функции; риск задеть её проверку базы `doctor` (`project_checks.py:580`).
     - ослабляется: однозначность имени «green» — функция перестаёт быть только «зелёной».
     - цена: как B плюс сверка существующих тестов `green_base_commit`.
     - чьё решение: Оператор.
   - дефолт: B — сохраняет смысл ТЗ («независимо от цвета») и не трогает существующую функцию.

2. **Чем в `doctor` выражается уровень `alert` (ADR-0032 п. 6: «алерт — при 85 %»).** `doctor.Check` знает статусы `ok`/`warn`/`fail`/`skip` (`orchestrator/doctor/__init__.py:114`, `doctor/cli.py:285`); `fail` делает выход `doctor` ненулевым (`doctor/cli.py:361-364`). Отдельно есть таблица `alerts` (`orchestrator/alerts.py:93`, так поднимает алерт `suite-duration`: `doctor/suite_duration.py:67`).
   - A) `alert` → строка со статусом `fail`.
     - ломается: `doctor` завершается с кодом 1 при цене набора ≥ 85 % — это может остановить обходы и сценарии, ждущие зелёный `doctor`.
     - ослабляется: ничего; но «провал окружения» смешивается с «сигналом о цене».
     - цена: ноль сверх текущего объёма.
     - чьё решение: Оператор.
   - B) `alert` → строка со статусом `warn` с текстом «тревога» + алерт в таблице `alerts` (`kind="trigger"`, источник `suite.cost`, один открытый на проект через дедуп `raise_alert`); строка в реестре триггеров `docs/triggers.md` — зона задачи расширяется на `docs/triggers.md`.
     - ломается: ничего существующего; появляется новый открытый алерт, который Оператор подтверждает `alert-ack`.
     - ослабляется: ничего.
     - цена: +1 файл зоны (`docs/triggers.md`), +1 проверка в критерии doctor, ~+$2–3.
     - чьё решение: Оператор.
   - C) `alert` → строка `warn` с текстом «тревога», без записи в `alerts`.
     - ломается: ничего.
     - ослабляется: различимость 75 % и 85 % — только текстом строки, без носителя, который требует подтверждения.
     - цена: ноль.
     - чьё решение: Оператор.
   - дефолт: B — «алерт» в системе означает строку таблицы `alerts`, так же сделано у соседней проверки `suite-duration`.

3. **Попытка `skipped` для `--record <sha>`.** Для коммита только документов (ADR-0016) `forge._gh_check_run` отдаёт последнюю попытку даже если все попытки `skipped` (`orchestrator/forge.py:541-543`); у неё нет ни отчёта, ни осмысленного `job_seconds`. Что делает `--record <sha>`?
   - A) Не пишет запись: отказ с причиной «задание не исполнялось», код выхода ненулевой.
     - ломается: ничего.
     - ослабляется: ничего; ряд сводок не засоряется коммитами документов.
     - цена: +1 подпункт критерия команды.
     - чьё решение: Оператор.
   - B) Пишет запись без отчёта с причиной «задание не исполнялось» и пустым `job_seconds`.
     - ломается: такая запись может стать «последней сводкой» для строки CI `doctor` и для прироста — нужна оговорка, что она не в счёт.
     - ослабляется: ничего.
     - цена: +оговорка в правилах «последней» и «предыдущей» сводки.
     - чьё решение: Оператор.
   - дефолт: A — ТЗ (требование 4) говорит о хранении попытки без отчёта для обрыва по пределу, не для неисполненного задания.

4. **Какая запись — «предыдущая сводка» для прироста.** ТЗ: «последняя записанная, sha которой — предок текущего». Не определено: (а) «последняя» — по времени записи или ближайшая по линии `main`; (б) годится ли предыдущей запись без отчёта (обрыв, требование 4).
   - A) Ближайший по первой родительской линии `main` предок текущего sha среди записей С отчётом; записи без отчёта для прироста пропускаются.
     - ломается: ничего.
     - ослабляется: ничего.
     - цена: критерий с тремя записями (предок с отчётом, предок без отчёта, не предок).
     - чьё решение: Оператор.
   - B) Последняя по времени записи среди предков с отчётом.
     - ломается: при записи задним числом (`--record` старого sha) прирост считается против более позднего по времени, но более далёкого по истории коммита.
     - ослабляется: ничего.
     - цена: как A.
     - чьё решение: Оператор.
   - C) Ближайший предок любого вида; если у него нет отчёта — прирост «нет данных».
     - ломается: после каждого обрыва прирост следующей сводки пропадает.
     - ослабляется: непрерывность ряда прироста.
     - цена: как A.
     - чьё решение: Оператор.
   - дефолт: A.

# SPEC: Гейт неослабления: параметризованные тесты

## Контекст
Часть 3/3 задачи 01M56P60XS9AP4BH01YK35220D (её требования 7, 8, 10, 11 в
части параметризации и двустороннего прогона). Двусторонний прогон смены
ожидания ищет точный id узла (`orchestrator/advance_gates/two_sided.py::_verdict`,
two_sided.py:175-209; «узел не найден» — :187), а pytest отчитывает
параметризованный тест вариантами `::test_x[...]`, отсюда исход «узел не
найден»; у проекта sled параметризация в 61 файле. Изменения аргументов
`@pytest.mark.parametrize` у метода с прежним именем гейт неослабления не
видит: сравниваются утверждения (`guard.assertion_changes`, guard.py:1859),
а не декораторы параметризации; маркеры пропуска декоратора берутся по
последнему сегменту имени (`guard._decorator_skip_markers`, guard.py:676),
поэтому `pytest.param(..., marks=pytest.mark.skip)` внутри `parametrize`
не виден. Изменённое утверждение без объявления и мандата — находка с
отказом перехода (`orchestrator/advance_gates/test_integrity.py`, канал
`_evaluate` → `uncovered` (журнал) → `review_lines` (ревью-пакет)).
Литералы «Меняемого поведения» берутся только из утверждений
(`guard.method_literal_keys`, guard.py:4102).

## Требования
1. Двусторонний прогон находит параметризованный тест по базовому id
   (варианты `::test_x[...]` в отчёте pytest) и выносит вердикт по
   вариантам, существующим с обеих сторон прогона: «пройден»
   (`two_sided.PASSED`) — когда каждый такой вариант проходит прежний
   критерий стороны (падение на утверждении) на обеих сторонах; иначе —
   отказ с причиной, называющей id варианта. Нет ни одного варианта,
   общего для обеих сторон, — отказ с текстом причины, не `PASSED`
   (пустой набор общих вариантов прохода не даёт). Исход «узел не найден»
   для параметризованного теста, варианты которого есть в отчёте, не
   выдаётся.
2. Смена ожидания, доказываемая двусторонним прогоном, — смена литерала в
   утверждении тела метода; строку `parametrize` разделом «Меняемое
   поведение» объявить нельзя: литерал аргумента `parametrize` не
   принимается как «было» строки раздела.
3. Изменение аргументов параметризации у тестового метода, сохранившего
   имя, — находка тем же каналом, что изменённое утверждение без
   объявления: отказ перехода, который снимает только мандат Оператора,
   запись в журнале и строка в ревью-пакете. Находка — удаление варианта,
   изменение значений варианта (в том числе имён аргументов) и марка
   пропуска на варианте `pytest.param(..., marks=…)`. Находка возникает
   независимо от того, объявлена ли у этого же метода смена литерала в
   «Меняемом поведении»: объявление литерала изменение `parametrize` не
   покрывает.
4. Добавление нового варианта без удаления и изменения прежних — не
   находка и не отказ: запись в журнале и строка в ревью-пакете; мандат
   Оператора для него не нужен.
5. Параметризация сравнивается во всех формах, задающих варианты
   тестового метода: декоратор метода, декоратор класса,
   `pytestmark = pytest.mark.parametrize(...)` (или список с ней) на уровне
   модуля и в теле класса. Когда аргумент `parametrize` — имя, которому
   в том же модуле присвоено значение на уровне модуля (константа модуля,
   например `CASES = [...]`), сравнивается текст присвоенного значения:
   его изменение при прежнем тексте декоратора — изменение аргументов по
   требованиям 3-4.
6. У артели прежние исходы двустороннего прогона непараметризованных
   тестов фиксируются тестами до правки и не меняются: «пройден»,
   «зелёная — …», «пропуск (фаза …)», «ошибка сборки (collect)», «узел не
   найден» при соседе `::test_x_slow` без `::test_x`. Случай
   «`::test_x_slow` без `::test_x`» проверяется на синтетическом отчёте
   (записи отчёта, поданные в сопоставление без настоящего pytest) —
   решение Оператора на гейте SPEC, эскалации `тест-навязывает-устройство`
   он не требует.
7. Тесты детерминированы, без сети; поведение чужого стека проверяется на
   учебном проекте с `workdir: backend` и `weakening_scope:
   [backend/tests/**/*.py]`.
8. Строка инварианта 38 (`docs/invariants.md:68`) дополнена: находкой
   смены параметризации у метода с прежним именем (удаление варианта,
   смена значений, `pytest.param(..., marks=…)`; формы требования 5) и
   двусторонним прогоном параметризованного теста по общим вариантам.
   `docs/invariants.md` — защищённый путь: правка едет приложением к
   PLAN.md по образцу части 2 (коммит f7dbc9d9), решение Оператора на
   гейте SPEC.

## Критерии приёмки
AC-1. Двусторонний прогон смены литерала утверждения в теле параметризованного теста (`@pytest.mark.parametrize` с ≥2 вариантами, аргументы parametrize не меняются) выносит «пройден» (`two_sided.PASSED`), когда каждый вариант падает на утверждении на обеих сторонах, и отказ с id варианта в причине, когда хотя бы один вариант на одной из сторон не падает на утверждении (проверяется и для стороны базы, и для стороны головы); ни в одном случае причина не «узел не найден».
AC-2. Когда у параметризованного теста нет ни одного варианта, общего для обеих сторон прогона (варианты базы и головы не пересекаются), двусторонний прогон выносит отказ с непустым текстом причины, а не «пройден» (`two_sided.PASSED`).
AC-3. У артели исходы двустороннего прогона непараметризованного теста прежние (зафиксированы тестом до правки, проходят после неё): падение на утверждении на обеих сторонах — «пройден» (`two_sided.PASSED`); зелёная сторона — отказ «зелёная — …»; пропуск — «пропуск (фаза …)»; ошибка сборки — «ошибка сборки (collect)»; на синтетическом отчёте, где узла `::test_x` нет, а есть `::test_x_slow`, — «узел не найден», соседний узел с общим префиксом за `::test_x` не засчитывается.
AC-4. Изменение аргументов `@pytest.mark.parametrize` у тестового метода с прежним именем без мандата Оператора — находка с отказом перехода, запись в журнале и строка в ревью-пакете тем же каналом, что изменённое утверждение без объявления; так же — когда у этого метода одновременно изменён литерал утверждения и эта смена объявлена в «Меняемом поведении» (находка на `parametrize` остаётся); с мандатом Оператора на этот метод — проход.
AC-5. У метода с прежним именем удаление варианта из `@pytest.mark.parametrize`, изменение значений варианта и добавление варианту марки пропуска (`pytest.param(..., marks=pytest.mark.skip)`) — находка по AC-4, в том числе у метода с объявленной сменой литерала; добавление нового варианта при неизменных прежних — проход без отказа и без мандата, с записью в журнале и строкой в ревью-пакете.
AC-6. Удаление варианта и марка пропуска на варианте дают находку по AC-4 и когда параметризация задана декоратором класса, и когда — `pytestmark = pytest.mark.parametrize(...)` на уровне модуля, и когда — `pytestmark` в теле класса; и когда аргумент декоратора `@pytest.mark.parametrize("x", CASES)` при неизменном тексте декоратора ссылается на константу того же модуля `CASES = [...]`, у которой изменён текст присвоенного значения.
AC-7. Строка раздела «Меняемое поведение», чьё «было» — литерал, стоящий только в аргументах `@pytest.mark.parametrize` метода (не в его утверждениях и не в утверждениях помощников первого уровня), не принимается: литерал такого аргумента не входит в `guard.method_literal_keys` метода.
AC-8. PLAN.md несёт приложение к `docs/invariants.md`, которое применяется к дереву базы (`git apply --check`), и после наложения строка инварианта 38 (строка таблицы, начинающаяся с `| 38 |`) содержит подстроки `parametrize` и `pytest.param(`, а прежние формы пропуска (`@skip`/`@skipIf`/`@skipUnless`/`@expectedFailure`/`@pytest.mark.skip`/`skipif`/`xfail`, `pytest.skip(`, `имя-метка`, `pytestmark`, `allow_module_level=True`, `pytest.importorskip(`) в ней сохранены.

# SPEC: Гейт неослабления: параметризованные тесты

## Контекст
Часть 3/3 задачи 01M56P60XS9AP4BH01YK35220D (её требования 7, 8, 10, 11 в
части параметризации и двустороннего прогона; её AC-11…AC-14 — здесь
AC-1…AC-4). Двусторонний прогон смены ожидания ищет точный id узла
(`orchestrator/advance_gates/two_sided.py::_verdict`, строки 175-187), а
pytest отчитывает параметризованный тест вариантами `::test_x[...]` —
исход «узел не найден»; у проекта sled параметризация в 61 файле.
Изменения аргументов `@pytest.mark.parametrize` у метода с прежним именем
гейт неослабления не видит: сравниваются утверждения
(`guard.assertion_changes`), а не декораторы параметризации. Изменённое
утверждение без объявления и мандата — находка с отказом перехода
(`orchestrator/advance_gates/test_integrity.py`, канал `findings` →
журнал → `review_lines`). Литералы «Меняемого поведения» берутся только из
утверждений (`guard.method_literal_keys`).

## Требования
1. Двусторонний прогон находит параметризованный тест по базовому id
   (варианты `::test_x[...]` в отчёте pytest) и выносит вердикт по
   вариантам, существующим с обеих сторон прогона: «пройден»
   (`two_sided.PASSED`) — когда каждый такой вариант проходит прежний
   критерий стороны (падение на утверждении) на обеих сторонах; иначе —
   отказ с причиной, называющей id варианта; нет ни одного общего варианта
   — отказ. Исход «узел не найден» для параметризованного теста, варианты
   которого есть в отчёте, не выдаётся.
2. Смена ожидания, доказываемая двусторонним прогоном, — смена литерала в
   утверждении тела метода; строку `parametrize` разделом «Меняемое
   поведение» не объявить.
3. Изменение аргументов `@pytest.mark.parametrize` у тестового метода,
   сохранившего имя (в том числе удаление варианта и марка пропуска на
   варианте `pytest.param(..., marks=…)`), — находка тем же каналом, что
   изменённое утверждение без объявления: отказ перехода, который снимает
   только мандат Оператора, запись в журнале и строка в ревью-пакете.
4. У артели прежние исходы двустороннего прогона непараметризованных
   тестов фиксируются тестами до правки и не меняются: «пройден»,
   «зелёная — …», «пропуск (фаза …)», «ошибка сборки (collect)», «узел не
   найден» при соседе `::test_x_slow` без `::test_x`.
5. Тесты детерминированы, без сети; поведение чужого стека проверяется на
   учебном проекте с `workdir: backend` и `weakening_scope:
   [backend/tests/**/*.py]`.

## Критерии приёмки
AC-1. Двусторонний прогон смены литерала утверждения в теле параметризованного теста (`@pytest.mark.parametrize` с ≥2 вариантами, аргументы parametrize не меняются) выносит «пройден» (`two_sided.PASSED`), когда каждый вариант падает на утверждении на обеих сторонах, и отказ с id варианта в причине, когда хотя бы один вариант на одной из сторон не падает на утверждении; ни в одном случае причина не «узел не найден».
AC-2. У артели исходы двустороннего прогона непараметризованного теста прежние (зафиксированы тестом до правки, проходят после неё): падение на утверждении на обеих сторонах — «пройден» (`two_sided.PASSED`); зелёная сторона — отказ «зелёная — …»; пропуск — «пропуск (фаза …)»; ошибка сборки — «ошибка сборки (collect)»; узла `::test_x` в отчёте нет, а есть `::test_x_slow` — «узел не найден», соседний узел с общим префиксом за `::test_x` не засчитывается.
AC-3. Изменение аргументов `@pytest.mark.parametrize` у тестового метода с прежним именем и прежним телом без мандата Оператора — находка с отказом перехода, запись в журнале и строка в ревью-пакете тем же каналом, что изменённое утверждение без объявления; с мандатом Оператора на этот метод — проход.
AC-4. Удаление варианта из `@pytest.mark.parametrize` и добавление варианту марки пропуска (`pytest.param(..., marks=pytest.mark.skip)`) у метода с прежним именем — находка по AC-3.

## Оценка объёма и деление
Прогноз диффа: 40 КиБ (правка `two_sided._verdict` и сравнения
декораторов `parametrize` в `guard.py`/`test_integrity.py` плюс тесты на
учебном проекте; половина потолка гейта ёмкости —
`REVIEW_SNAPSHOT_DIFF_MAX_BYTES` 256 КиБ / 2 = 128 КиБ).

Сработавшие сигналы: число файлов зоны (маска `tests/` вместе с тремя
модулями); зона задевает механизм инварианта 38 `docs/invariants.md`
(гейт неослабления тестов: требование 3 добавляет к нему находку смены
`parametrize`, требование 1 меняет двусторонний прогон, на который
инвариант опирается).

Решение — **обоснование монолита**: задача уже есть часть 3/3 нарезки
родителя 01M56P60XS9AP4BH01YK35220D (рамка $25, 4 критерия), утверждённой
Оператором при approve родителя. Дальнейший разрез по требованиям 1 и 3
оставил бы одну из половин без сторожа: смена литерала в теле
параметризованного теста, доказанная прогоном по вариантам (требование 1),
без находки на смену аргументов `parametrize` (требование 3) открывает
обход — удалить «неудобный» вариант вместо правки утверждения и пройти
гейт; обратный порядок даёт находку без возможности штатно доказать смену
ожидания параметризованного теста. Обе половины трогают один узел
сравнения `test_integrity.py` и один файл `guard.py` под замком зоны.

## Пути обхода гейтов
1. **Косвенные аргументы.** `@pytest.mark.parametrize("x", CASES)`: варианты
   задаёт константа модуля `CASES = [...]`. Удалить «неудобный» вариант
   или навесить `pytest.param(..., marks=skip)` в `CASES` можно, не меняя
   текста декоратора. Требование 3 сравнивает «аргументы `parametrize` у
   метода», и при буквальном чтении (текст декоратора) находки нет. Тот же
   путь есть у `@pytest.mark.parametrize` на классе и у
   `pytestmark = pytest.mark.parametrize(...)`: требование говорит «у
   тестового метода». Есть он и у `@pytest.fixture(params=...)`, но это
   вне формулировки ТЗ. Вместе с требованием 1 («только общие варианты»)
   двусторонний прогон такой урезанный набор ещё и засчитывает. Это ровно
   тот обход, ради которого в разделе «Деление» обосновано единство
   требований 1 и 3. Отклонение 3.
2. **Вакуумный проход.** Ноль общих вариантов при агрегации «все прошли»
   (`"; ".join([]) or PASSED`, two_sided.py:393-395) даёт `PASSED`.
   Требование 1 это запрещает, но ни один AC этого не ловит. Отклонение 1.
3. **Совмещение с объявленной сменой.** Метод с объявленной сменой
   литерала и одновременно урезанным `parametrize`: реализация, которая
   сравнивает `parametrize` только у методов без изменённых утверждений,
   проходит AC-3/AC-4 («прежнее тело»). Отклонение 2.
4. **Объявление строки `parametrize` в «Меняемом поведении».** Сейчас
   закрыто кодом (guard.py:4102-4114), но тестом на требование 2 не
   закреплено. Отклонение 4.

## Вердикт
concerns. Отклонения, по убыванию веса:

1. **AC не ловит вакуумный проход** — требование 1 SPEC «нет ни одного
   общего варианта — отказ» не имеет критерия. AC-1 проверяет только ≥2
   общих варианта. Правдоподобная мутация — агрегация `all()`/пустой
   список причин → `PASSED` (two_sided.py:393-395). Нужна строка AC: «нет
   общих вариантов с обеих сторон — отказ, не `PASSED`». Решение на гейте:
   дописать AC или принять риск.
2. **AC-3/AC-4 ограничены методом «с прежним телом»** (SPEC, AC-3), хотя
   требование 3 таких ограничений не ставит. Не покрыт случай «объявленная
   смена литерала + изменённый `parametrize`» — ради него и обоснован
   монолит (SPEC, «Оценка объёма и деление»). Мутация — сравнение
   `parametrize` только у методов вне `cmp.changes`
   (test_integrity.py:1216-1222).
3. **Обход через косвенные аргументы `parametrize`** (константа модуля,
   декоратор класса, `pytestmark`). Требование 3 сформулировано как
   «изменение аргументов `@pytest.mark.parametrize` у тестового метода». Буквальная
   реализация по тексту декоратора их не видит, а требование 1 урезанный
   набор засчитывает. Оператору решить: принять как известный пробел (с
   записью в «Не входит») или уточнить требование 3 — сравнивать
   вычисляемый набор вариантов либо значения имён, на которые ссылается
   декоратор.
4. **Требование 2 без критерия:** запрет объявлять строку `parametrize` в
   «Меняемом поведении» держит только текущий код
   (`guard.method_literal_keys`, guard.py:4102-4114); AC его не закрепляет.
   Это малый вес: поведение уже есть, требование его не меняет.
5. **Инвариант 38 (docs/invariants.md:68)** — исчерпывающий перечень
   находок гейта неослабления. Требования 1 и 3 его меняют, но SPEC не

6. Малые: диапазон `_verdict` в SPEC (175-187/175-194) не совпадает с

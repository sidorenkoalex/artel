Часть задачи 01M56P60XS9AP4BH01YK35220D (требования 7, 8, 10, 11 её SPEC в
части параметризации и двустороннего прогона).

Факты: двусторонний прогон ищет точный id узла, у параметризованного
теста отчёт — `::test_x[...]` (`orchestrator/advance_gates/two_sided.py:175-187`)
→ «узел не найден»; у sled параметризация в 61 файле. Изменения
аргументов `@pytest.mark.parametrize` гейт не видит (`scripts/guard.py:1765-1768`).
Изменённое утверждение без объявления и мандата — находка с отказом
(`orchestrator/advance_gates/test_integrity.py:1105-1111`). Литералы
«Меняемого поведения» — только из утверждений (`guard.py:3834-3846`).

Требуется:
1. Двусторонний прогон находит параметризованный тест по базовому id;
   вердикт — по вариантам, существующим с обеих сторон, каждый проходит
   прежний критерий (падение на утверждении) на обеих сторонах; иначе
   отказ с id варианта; нет общих вариантов — отказ; не «узел не
   найден». Исход прохода — «пройден» (`two_sided.PASSED`). Смена
   ожидания — в утверждении тела метода.
2. Изменение аргументов `parametrize` у метода, сохранившего имя (в том
   числе удаление варианта и марка пропуска на варианте), — находка с
   отказом тем же каналом, что изменённое утверждение без объявления
   (снимает мандат Оператора), с записью в журнале и строкой в
   ревью-пакете.
3. У артели прежние исходы двустороннего прогона непараметризованных
   тестов фиксируются тестами до правки: «пройден», «зелёная — …»,
   «пропуск (фаза …)», «ошибка сборки (collect)», «узел не найден» при
   соседе `::test_x_slow` без `::test_x`.
4. Тесты детерминированы, без сети, на учебном проекте с `workdir:
   backend` и `weakening_scope: [backend/tests/**/*.py]`.

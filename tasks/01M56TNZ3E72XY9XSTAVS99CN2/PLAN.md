# PLAN: Гейт неослабления: параметризованные тесты

## Подход
Три правки в зонах задачи, одна сверка — общий узел сравнения
`test_integrity._compare`, которым живут оба рубежа и ревью-пакет.

- **Разбор параметризации — в `scripts/guard.py`** (единственный адрес
  ast-разбора тестов пульта): `guard.parametrize_variants(source)` →
  `{Класс::метод: (ParametrizeMark, …)}`. Марка опознаётся последним
  сегментом имени `parametrize` во всех формах требования 5: `pytestmark`
  модуля, декоратор класса, `pytestmark` тела класса, декоратор метода.
  `ParametrizeMark` — место марки (форма + порядковый номер), подпись
  (имена аргументов в нормальной форме `"k, v"` для строки и списка плюс
  прочие аргументы марки — `ids=`, `indirect=` …), тексты вариантов
  (`ast.unparse` элемента) и подмножество вариантов с маркой пропуска в
  `pytest.param(…, marks=…)`. Аргумент-имя, присвоенное на уровне модуля
  (`CASES = [...]`, и `CASES: list = [...]`), раскрывается до значения;
  импортированное имя — известный пробел SPEC («Не входит»).
  `method_literal_keys` не трогается: литералы `parametrize` в позиции
  литералов утверждений не входят (требование 2, AC-7 — зелёный с
  рождения, правило сохранено).
- **Сравнение — `test_integrity._parametrize_findings`**, вызывается в
  `_compare` для каждого файла диффа, у которого есть обе стороны. Для
  метода, живого в base и head: снятая марка, смена подписи, удалённый
  или изменённый вариант (сравнение мультимножеством значений, не по
  позиции), вариант с маркой пропуска, марка, появившаяся у прежнего
  метода, — `Finding` в `found` (тот же канал, что изменённое
  утверждение без объявления: отказ `in_dev → verifying`, эскалация
  мержа, снимает только мандат по `Finding.mandate_elements`). Находка
  стоит в `found` независимо от исхода утверждений метода, поэтому
  объявление литерала её не покрывает (требование 3). Те же находки —
  в новом поле `Comparison.reparametrized`, добавленные варианты при
  неизменных прежних — в `Comparison.grown`.
- **Журнал и ревью-пакет**: `_journal_pass` (общий для `uncovered`, гейта
  перехода и гейта мержа) пишет «изменена параметризация тестов» (с
  отметкой «покрыто мандатом ANSWER-n» тем же `_observation_lines`) и
  «добавлены варианты параметризации тестов»; `review_lines` добавляет по
  строке на каждую находку (с исходом «находка» либо отметкой мандата) и
  на каждое добавление («без находки»).
- **Двусторонний прогон** (`two_sided.run`): обе стороны прогоняются до
  вердикта, затем по каждому методу `_common_variants`: вариантов
  `<узел>[…]` нет ни на одной стороне — прежний вердикт по точному id
  (`_verdict` не менялся — все прежние исходы AC-3 сохранены; вариант —
  только id, продолженный ровно `[`, поэтому `::test_x_slow` вариантом
  `::test_x` не считается); есть — судятся варианты, общие обеим
  сторонам (`_side_verdict`): первый не упавший на утверждении называет
  себя в причине «вариант [id]: …»; общих нет — отказ «нет вариантов,
  общих обеим сторонам (…)», не `PASSED`. Сторона, чей прогон сорвался,
  отчёта не даёт — вторая судится по своим вариантам, отказ несёт
  причину сбоя стороны, как прежде.

Бюджет SPEC ($25) не переоценивается: число файлов и шагов совпало с
прогнозом SPEC.

## Влияние на систему
- Инвариант 38 (гейт неослабления) только усиливается: новая находка
  добавлена в `found`, ни одна прежняя проверка не снята и не ослаблена;
  находки, утверждения, храповик, мандат и послабление пропусков идут
  прежним кодом. Гейт мержа получает новую находку тем же узлом
  (`merge_gate_escalates` → `_evaluate`).
- Двусторонний прогон: для непараметризованного узла путь вердикта
  прежний (`_verdict`), меняется лишь порядок — обе стороны прогоняются до
  вердикта (прежде вердикт стороны выносился сразу после её прогона;
  число и состав прогонов pytest те же). Порядок строк отказа прежний
  (сторона, затем метод); новые строки — только для параметризованных
  методов. Наблюдение (`Outcome.sides`) сохраняет форму.
- Риск ложной находки: перенос варианта между формами (из декоратора
  метода в `pytestmark` класса) и переименование класса с параметризацией
  на классе читаются как снятая/добавленная марка — находка (fail-closed,
  снимает мандат).
- Откат — revert merge-коммита задачи; схема БД и форматы прежних записей
  журнала не меняются, новые действия журнала только добавляются.
- `docs/invariants.md` — защищённый путь: правка только приложением ниже.

## Риски
- Варианты сравниваются текстом `ast.unparse`: смена оформления без
  смены значения (`1` → `1.0`, `(1)` → `1`) — нормализуется самим
  `ast.unparse` для скобок, но `1` → `1.0` читается как смена значения —
  находка (fail-closed).

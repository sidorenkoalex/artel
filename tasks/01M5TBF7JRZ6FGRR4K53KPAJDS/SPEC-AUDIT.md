## Пути обхода гейтов

1. Перезапуск по кругу вместо остановки (связано с отклонением 1): задача,
   чей `auto` остановился на паузе/потолке задачи/стоп-кране/лимите шагов,
   по буквальному треб. 3 «готова» — надзор перезапускает её каждый опрос.
   Это обходит смысл остановки `auto` «до места, где нужен человек»
   (`auto.py` `cmd_auto`), плодит алерты `attention` (`alert=True` на
   main:orchestrator/auto.py:889, :902, :966) и делает треб. 8 недостижимым
   (процесс не завершится никогда).
2. Блокировка эпика без проверки живости (отклонение 2): буквальное
   треб. 1 выполнимо pid-файлом без сверки живого pid — после падения
   надзора `auto --epic` отказывает навсегда; AC-6 проверяет только живой
   процесс.
3. `epic stop` по lease детей (отклонение 4): ребёнок, уже спавненный, но
   ещё не взявший lease (lease берётся внутри дочернего процесса,
   `lease.run_locked`), сигнала не получит; надзор, остановленный позже
   детей, успевает перезапустить их. Буквально треб. 7 выполнено, смысл
   «эпик остановлен» — нет.

concerns — отклонения есть, все решаемы Оператором на гейте (выбор

1. **Готовность после не-гейтовой остановки `auto`** — SPEC треб. 3, 4, 8
   (tasks/01M5TBF7JRZ6FGRR4K53KPAJDS/SPEC.md, «Требования» п. 3–4, 8);
   main:orchestrator/auto.py:203, :714, :848-902, :939-967. Задача в

   (`paused`), стоп-крану, потолку задачи, лимиту шагов, отказу `advance`
   считается готовой → перезапуск по кругу, процесс не завершается.
   Вопрос Оператору: (A) задача, чей последний дочерний `auto` остановился
   не на гейте и не по `stop`, не перезапускается до нового действия
   Оператора по ней и для треб. 8 считается «ждёт Оператора»; (B)
   исключить из готовности явно `paused` и отказ потолка задачи, прочее
   перезапускать; (C) перезапускать с паузой. Рекомендация — A.
2. **Блокировка и журнал надзора не адресованы** — SPEC треб. 1, 7, 8,

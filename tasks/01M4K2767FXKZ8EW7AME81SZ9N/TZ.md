# ТЗ: Полный прогон tests/ — канарейка под замком машины, предел notes из профиля, сигнал «близко к пределу»

Источник: строки копилки 05.10–07.10 о времени полного прогона (предел
900 с у гейтов 05.10; канарейка и автогейт задачи одновременно 07.10;
нет сигнала роста времени прогона 07.10; канарейка на 73ce3329 дошла до
80% предела 06.10); очередь критичных 10.10, пункт 3; решение Оператора
10.10.2026 — одной задачей, после канарейки волны 10.10 (прогон 134
зелёный, пин dfb3afbd).

Факты (main dfb3afbd, сверка 10.10):
- Предел полного прогона артели уже 1500 с — `targets.yaml`
  (`full_suite_timeout_sec`), читается `project_profile` (~160);
  константа `config.FULL_SUITE_TIMEOUT_SEC = 900` (~212) — запасной
  источник «config».
- Замок полных прогонов машины `orchestrator/suite_lock.py`: файл
  `config.LOGS / "suite-run" / "lock.json"` (`path()`, ~38). Его берут
  гейты (`acceptance._machine_lock`, ~1190), `suite-run` и `notes`.
- Канарейка исполняет задачу в эфемерном клоне и переадресует пути
  `config` под клон (`orchestrator/canary.py::_CLONE_CONFIG_ATTRS`, ~458,
  среди них `LOGS`); значит, замок внутри клона — другой файл, и полный
  прогон автогейта канарейки идёт одновременно с прогонами задач главной
  копии (случай 07.10: 28 процессов xdist на 14 ядрах, оба прогона у
  предела). Исключения из переадресации — `_CLONE_EXEMPT_CONFIG_ATTRS`
  с причиной (~467), инвариант списка держит
  `tests/test_canary.py::CloneConfigAttrsInvariantTest`.
- `notes` гоняет полный прогон без предела профиля:
  `orchestrator/notes.py` ~1010 `acceptance.run_full_suite(work_dir)` →
  предел `config.FULL_SUITE_TIMEOUT_SEC` (900 с), источник «config».
- Метрики прогона уже считаются (`acceptance._suite_metrics`, ~279:
  `duration_seconds`, число тестов, нагрузка); сигнала о близости
  длительности к пределу нет — прецедент сигнала: наблюдатель роста карты
  `orchestrator/doctor/map_growth.py` (алерт `map.growth` в `status`).

Требуется:
1. Канарейка: полный прогон в клоне берёт тот же замок машины, что
   прогоны главной копии (один файл замка на машину), — ждёт и пишет
   ожидание так же, как гейты; прочие пути клона по-прежнему
   переадресуются. Инвариант списка путей клона продолжает держаться
   (новое исключение — с причиной).
2. `notes`: полный прогон берёт предел из профиля тестов проекта (как
   гейты), источник предела виден в выводе; без профиля — прежний
   запасной `config`.
3. Сигнал: полный прогон (гейт, `suite-run`, `notes`, канарейка), длившийся
   не меньше 80% своего предела, оставляет запись журнала задачи (у
   `notes` — строку вывода) «длительность близка к пределу» с
   длительностью, пределом, источником предела и нагрузкой, и алерт,
   видимый в `status` до подтверждения (по образцу `map.growth`:
   `alerts.raise_alert`, kind=trigger, строка нового триггера в
   `docs/triggers.md`). Порог — именованная константа. Исход прогона сигнал не меняет.
4. Ослабления нет: пределы не повышаются, замок не снимается раньше,
   отказ по истечению предела остаётся отказом.
5. Смена поведения существующих тестов — только разделом SPEC
   «Меняемое поведение» (инвариант 38).

Критерии приёмки (направление; планку пишет test_author):
- Замок, занятый прогоном главной копии: полный прогон в клоне канарейки
  ждёт его (запись ожидания), а не идёт параллельно; мутация «клон берёт
  свой файл замка» ловится.
- `notes` с профилем, где предел 1500: прогон получает 1500 и источник
  профиля; без профиля — 900 и «config».
- Прогон длительностью 85% предела (подменённые часы) — запись и алерт;
  70% — ни того, ни другого; красный прогон у предела — тоже сигнал, исход
  прежний.
- `status` показывает неподтверждённый алерт длительности; подтверждение
  его снимает.

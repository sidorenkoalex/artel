# SPEC: Конвенции внешнего проекта в брифе — из файла пульта, сверка дрейфа

## Контекст
Решение Оператора 25.10.2026 (бэклог П1, строки ee693e48 и 1f02aff4):
`CLAUDE.md`, `AGENTS.md` и прочие ИИ-настройки внешнего проекта пульт ролям
не передаёт. Сейчас `orchestrator/brief.py:45` `PROJECT_CONVENTIONS =
("CLAUDE.md", "AGENTS.md")` и `_read_project_conventions` (`:602`) кладут
текст обоих файлов корня базовой ветки клона в бриф каждой роли
(`_project_conventions_parts`, `:777`; потребители — бриф developer `:1252`,
spec_auditor `:1322`, analyst `:1623`, добавка test_author `:1661`, пакет
ревьювера `orchestrator/review.py:955`). У feedback `AGENTS.md` начинается
указанием «первой командой запусти ./harness/task.sh» — роль пульта получила
бы чужой процесс. Вместо этого конвенции проекта разбирает сессия при
Операторе в файл `.artel/projects/<имя>/conventions.md` локального слоя
пульта; бриф берёт текст оттуда, а `doctor` сверяет, не изменились ли
исходные файлы проекта с момента разбора. Сверки дрейфа сейчас нет.

## Требования
Всё ниже касается только задач внешних проектов (target не равен
`config.DEFAULT_TARGET`); бриф, пакет и миссии ролей артели не меняются.

1. **Источник конвенций.** В брифе каждой роли задачи внешнего проекта (бриф
   analyst, developer, spec_auditor, добавка test_author, пакет ревьювера —
   там же, где сейчас блок `PROJECT_CONVENTIONS`) конвенции проекта — один
   компонент с текстом файла `config.PROJECTS / <имя проекта> /
   "conventions.md"` локального слоя пульта, оформленный тем же `render`
   потребителя, что сейчас у файлов конвенций; подпись компонента называет
   `conventions.md` и проект. `CLAUDE.md` и `AGENTS.md` проекта в бриф не
   читаются ни с базовой ветки клона, ни из рабочей копии: ни их текста, ни
   пометок о них («файла нет», «не прочитаны») в брифе нет.
2. **Заголовок скрыт.** Если `conventions.md` начинается заголовком отметки
   разбора (требование 6), в бриф идёт только текст после заголовка;
   строк заголовка (ветка, коммит, пути и blob исходных файлов) в брифе нет.
   Файл без заголовка идёт в бриф целиком.
3. **Документы `knowledge`** единственного компонента записи `components:`
   (SPEC 01M5ENWB2XHZFRNQ3Q3PZSAH2T) — как сейчас, следом за компонентом
   `conventions.md`, с базовой ветки клона. Повторы убираются между
   элементами `knowledge`, как сейчас; путь `conventions.md` с путями дерева
   проекта не сравнивается. Базовая ветка клона читается только ради
   `knowledge`: сбой её чтения или неразрешимый проект дают пометку
   «конвенции проекта не прочитаны: <причина> — <элементы knowledge>, <где>»
   и запись журнала только при наличии `knowledge`; компонент
   `conventions.md` от состояния клона не зависит.
4. **Файла нет или не читается.** Нет `conventions.md`, это не обычный файл
   (каталог, символьная ссылка и т.п.), текст не в UTF-8 или чтение
   отвечает ошибкой ОС — бриф собирается без конвенций проекта и на месте
   компонента несёт строку «конвенции проекта не разобраны: <причина> —
   <путь файла>», где причина различает эти случаи («файла нет», «не обычный
   файл», «текст не в UTF-8», текст ошибки ОС); в журнал задачи —
   запись действия «бриф: конвенции проекта не разобраны» с той же причиной.
   Сборка брифа и старт шага роли этим не останавливаются.
5. **Предел размера** текста `conventions.md` (после снятия заголовка) — тот
   же, что сейчас у каждого файла конвенций у этого потребителя (пропуск
   компонента оформителем `render` сверх `config.CONTEXT_FILE_MAX_BYTES`).
6. **Формат заголовка отметки разбора** — блок в начале файла, тело
   которого между строками `---` разбирает `orchestrator/yamlmini.py::mapping`
   (плоский `frontmatter` вложенное `sources` не разбирает); sha и id blob —
   в двойных кавычках, чтобы шестнадцатеричная строка из одних цифр не
   разобралась числом:
   ```
   ---
   conventions_stamp: 1
   base_branch: <базовая ветка записи проекта>
   base_sha: "<40-символьный sha коммита базы на момент отметки>"
   sources:
     <путь файла в репозитории проекта>: "<40-символьный id blob git на base_sha>"
     ...
   ---
   ```
   Заголовок — блок от первой строки `---` до следующей строки `---`
   включительно; файл, первая строка которого не `---` или без
   `conventions_stamp`, — файл без заголовка.
7. **Команда отметки** `python3 orchestrator/artel.py conventions-stamp
   <проект> <файл>…` (модуль `orchestrator/conventions.py`): читает коммит
   `refs/heads/<base>` клона проекта без обращения к сети, для каждого
   названного файла — id его blob на этом коммите, и пишет заголовок
   требования 6 в начало `conventions.md` (`sources` — ровно названные
   файлы), заменяя прежний заголовок, если он был. Текст под заголовком
   остаётся побайтно прежним. Отказ с ненулевым кодом выхода и причиной в
   выводе, без изменения файла: проект `config.DEFAULT_TARGET` или
   неизвестный, клон или базовая ветка не читаются, файлы не названы,
   названный файл не обычный файл в дереве этого коммита, `conventions.md`
   нет или он не читается (требование 4).
8. **Дрейф в `doctor`.** Новая проверка `project-conventions`
   (`orchestrator/doctor/project_conventions.py`, вызов — в цикле по
   проектам `orchestrator/doctor/cli.py`) — по строке на каждый внешний
   проект записи `targets`:
   - заголовок есть и blob каждого файла `sources` на текущем коммите
     `refs/heads/<base>` клона совпадает с записанным — `ok`;
   - blob хоть одного файла отличается или файла в дереве нет — `warn`
     «конвенции проекта изменились с последнего разбора: <файлы>» с
     перечнем всех таких файлов;
   - `conventions.md` есть, заголовка нет — `warn` «нет отметки разбора»
     с путём файла и командой требования 7;
   - `conventions.md` нет — `warn` с путём файла и подсказкой шага разбора
     (ссылка на `docs/target-onboarding.md`);
   - файл не читается или клон/база не читаются — `warn` с причиной.
   Проверка `conventions.md` не меняет и в сеть не ходит; у
   `config.DEFAULT_TARGET` строки нет.
9. **Порядок подключения** — новый документ `docs/target-onboarding.md`:
   шаг разбора ИИ-настроек проекта как текста; что выбирается (стек,
   архитектура и слои, стиль кода, команды тестов и линтеров, миграции,
   именование); что отбрасывается (команды запуска обвязки, правила
   commit/push, роли, ревью, хуки, MCP, разрешения); куда пишется итог
   (`.artel/projects/<имя>/conventions.md`, смотрит Оператор); как ставится
   отметка (команда требования 7); что делать при предупреждении дрейфа
   (`doctor`, требование 8). Только описание порядка, без данных конкретных
   проектов.
10. **Миссии ролей** (следствие требования 1): строки миссий analyst и
    developer задачи внешнего проекта (`orchestrator/role_prompt.py:53`,
    `:121`) не называют «CLAUDE.md и AGENTS.md его базовой ветки» источником
    конвенций; они называют конвенции проекта из файла пульта. Фраза
    «конвенции проекта» в миссии developer сохраняется.

## Критерии приёмки
Песочница — учебный внешний проект (клон в области проектов песочницы)
с `CLAUDE.md` «ПРАВИЛО-ПРОЕКТА» и `AGENTS.md` «ПРАВИЛО-АГЕНТА» в базовой
ветке и в рабочей копии и с `conventions.md` «КОНВЕНЦИЯ-ПУЛЬТА» под
заголовком отметки в `config.PROJECTS / <проект>`.

AC-1. Бриф analyst, developer, spec_auditor, добавка test_author и пакет
ревьювера задачи песочного проекта содержат «КОНВЕНЦИЯ-ПУЛЬТА» и не
содержат ни «ПРАВИЛО-ПРОЕКТА», ни «ПРАВИЛО-АГЕНТА», ни значений
`base_sha` и blob из заголовка, ни строки `conventions_stamp`; у записи с
`knowledge` компонента текст элемента `knowledge` стоит в брифе после
«КОНВЕНЦИЯ-ПУЛЬТА» (требования 1–3).

AC-2. Без `conventions.md` (и отдельно: `conventions.md` — каталог;
текст не в UTF-8) бриф каждой из пяти точек AC-1 собирается без
исключения, несёт строку «конвенции проекта не разобраны: <причина> —
<путь>» с причиной своего случая и путём файла, не несёт «ПРАВИЛО-ПРОЕКТА»;
в журнале задачи — запись «бриф: конвенции проекта не разобраны» с той же
причиной; шаг роли стартует (`run` не отказывает по этой причине)
(требование 4).

AC-3. `conventions.md`, текст которого под заголовком крупнее
`config.CONTEXT_FILE_MAX_BYTES`, в брифе developer пропущен с той же
пометкой пропуска по размеру, что получал бы сейчас файл конвенций того
же размера (требование 5).

AC-4. Бриф analyst, developer, spec_auditor, добавка test_author и пакет
ревьювера задачи артели (`config.DEFAULT_TARGET`) побайтно равны эталону,
снятому с текущего кода main при том же `run_id` (требование «бриф ролей
артели не меняется»).

AC-5. Миссии analyst и developer задачи песочного проекта не содержат
«CLAUDE.md и AGENTS.md»; миссия developer содержит «конвенции проекта»
(требование 10).

AC-6. `conventions-stamp <проект> AGENTS.md CLAUDE.md` на песочнице: в
начале `conventions.md` заголовок требования 6 с `base_branch` записи,
`base_sha`, равным `git rev-parse refs/heads/<base>` клона, и blob каждого
файла, равным `git rev-parse <base_sha>:<файл>`; текст под заголовком
побайтно равен прежнему телу файла. После нового коммита в базу повторная
команда заменяет заголовок на новый `base_sha`, тело то же; файл без
заголовка получает заголовок, тело то же (требования 6, 7).

AC-7. `conventions-stamp` отказывает с ненулевым кодом и причиной, не
меняя `conventions.md` (побайтно), для: проекта `config.DEFAULT_TARGET`;
неизвестного проекта; вызова без файлов; файла, которого нет в дереве
коммита базы; отсутствующего `conventions.md` (требование 7).

AC-8. После `conventions-stamp <проект> AGENTS.md CLAUDE.md` строка
`project-conventions` проекта в `doctor` — `ok`; новый коммит в базовую
ветку песочницы, меняющий `AGENTS.md`, — `warn` с «конвенции проекта
изменились с последнего разбора» и `AGENTS.md`; вместо этого коммит,
меняющий другой файл (не из `sources`), — `ok`; коммит, удаляющий
`CLAUDE.md`, — `warn` с `CLAUDE.md`. `conventions.md` после каждого
прогона `doctor` побайтно прежний (требование 8).

AC-9. `doctor` для внешнего проекта с `conventions.md` без заголовка —
`warn` с «нет отметки разбора»; без `conventions.md` — `warn` со ссылкой
на `docs/target-onboarding.md`; для `config.DEFAULT_TARGET` строки
`project-conventions` нет (требование 8).

AC-10. `docs/target-onboarding.md` существует и содержит: шаг разбора
ИИ-настроек проекта как текста; каждое из выбираемых и каждое из
отбрасываемых требования 9; путь `.artel/projects/<имя>/conventions.md`;
команду `conventions-stamp`; действие при предупреждении дрейфа `doctor`
(требование 9).

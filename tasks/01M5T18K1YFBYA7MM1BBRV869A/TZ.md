# ТЗ: Конвенции внешнего проекта в брифе — из файла пульта, сверка дрейфа

# Конвенции внешнего проекта в брифе ролей — из файла пульта, а не из ИИ-настроек проекта; сверка дрейфа

## Факты

Решение Оператора 25.10.2026 (строка бэклога П1 1f02aff4, уточнение строки ee693e48): `CLAUDE.md`, `AGENTS.md` и прочие ИИ-настройки проекта пульт ролям не передаёт. При подключении проекта сессия при Операторе читает их как текст и выбирает только конвенции самого проекта (стек, архитектура и слои, стиль кода, команды тестов и линтеров, миграции, именование); всё о процессе и окружении агента (команды запуска обвязки, правила commit/push, роли, ревью, хуки, MCP, разрешения) отбрасывается. Итог — файл `.artel/projects/<имя>/conventions.md` в локальном слое пульта, его смотрит Оператор. Свои `CLAUDE.md`/`AGENTS.md` ролей и MCP — только из конфигурации пульта.

Сейчас:
1. `orchestrator/brief.py:45` `PROJECT_CONVENTIONS = ("CLAUDE.md", "AGENTS.md")`: `_read_project_conventions` (`:602`) читает оба файла корня базовой ветки клона внешнего проекта и кладёт их текст в бриф каждой роли (SPEC 01M5634E094QF7JX8HD3KSG4KN, требования 4–9; ревью — SPEC 01M56G7SB1PSR277BN4CHJBCQC). В feedback `AGENTS.md` начинается указанием «первой командой запусти ./harness/task.sh» — роль пульта получила бы чужой процесс.
2. Документы `knowledge` компонента (`_knowledge_of`, `_knowledge_parts`, SPEC 01M5ENWB2XHZFRNQ3Q3PZSAH2T) идут в бриф дополнением к `PROJECT_CONVENTIONS`.
3. Сверки «ИИ-настройки проекта изменились» нет.

## Требуется

Касается только внешних проектов (target не равен `config.DEFAULT_TARGET`); бриф ролей артели не меняется.

1. **Источник конвенций.** Для внешнего проекта бриф каждой роли (там же, где сейчас блок `PROJECT_CONVENTIONS`) несёт текст файла `.artel/projects/<имя>/conventions.md` локального слоя пульта; `CLAUDE.md` и `AGENTS.md` проекта в бриф не читаются ни из базовой ветки, ни из рабочей копии. Документы `knowledge` компонента — как сейчас, дополнением.
2. **Файла нет.** Нет `conventions.md` или он не читается (не UTF-8, не обычный файл) — бриф собирается без конвенций проекта с пометкой «конвенции проекта не разобраны: <причина> — <путь>», запись в журнал задачи; шаг роли не останавливается (как сейчас при отсутствии файла). Предел размера — тот же, что сейчас у блока конвенций.
3. **Отметка разбора.** В начале `conventions.md` — машиночитаемый заголовок: базовая ветка, коммит базы на момент разбора и список исходных файлов проекта, прочитанных при разборе, с их идентификаторами blob git на этом коммите. Формат заголовка — за аналитиком (frontmatter YAML или иной), в брифе роли заголовок не показывается. Команда пульта (имя — за аналитиком, например `conventions-stamp <проект> <файл>…`) пишет или обновляет заголовок по текущей базовой ветке клона, текст под заголовком не трогает.
4. **Дрейф.** `doctor` для каждого внешнего проекта с `conventions.md`: blob любого исходного файла из заголовка на текущей базовой ветке отличается от записанного или файл удалён — `warn` «конвенции проекта изменились с последнего разбора: <файлы>»; файла без заголовка — `warn` «нет отметки разбора»; нет `conventions.md` у внешнего проекта — `warn` с подсказкой шага разбора. `conventions.md` сам не меняется.
5. **Порядок подключения.** Документ `docs/target-onboarding.md` (новый): шаг разбора ИИ-настроек проекта как текста — что выбирается, что отбрасывается (списки из «Факты»), куда пишется итог, как ставится отметка, что делать при предупреждении дрейфа. Только описание порядка, без данных конкретных проектов.

Критерии приёмки:
- песочный внешний проект с `CLAUDE.md` «ПРАВИЛО-ПРОЕКТА» и `conventions.md` «КОНВЕНЦИЯ-ПУЛЬТА»: в брифе каждой роли есть «КОНВЕНЦИЯ-ПУЛЬТА», нет «ПРАВИЛО-ПРОЕКТА»; заголовок отметки в брифе не виден;
- без `conventions.md` — пометка «конвенции проекта не разобраны» в брифе и запись в журнале, шаг стартует;
- бриф артели (`DEFAULT_TARGET`) — без изменений (сверка с текущим выводом);
- после команды отметки `doctor` — `ok`; новый коммит в базовую ветку песочницы, меняющий `AGENTS.md` из заголовка, — `warn` с именем файла; коммит, меняющий другой файл, — `ok`;
- `docs/target-onboarding.md` есть и описывает шаг разбора.

Зоны: `orchestrator/brief.py`, `orchestrator/doctor/` (файл новой проверки — поимённо в SPEC), `orchestrator/artel.py` и модуль новой команды (поимённо в SPEC), `docs/target-onboarding.md`, `tests/` (долгоживущие файлы задачи).

Только чтение: `orchestrator/targets.py`, `orchestrator/reference_cache.py`, `orchestrator/workspace.py`, `orchestrator/config.py`, `docs/adr/0003-target-projects.md`.

Существующие тесты: требование 1 противоречит тестам, закрепляющим чтение `CLAUDE.md`/`AGENTS.md` проекта в бриф — `tests/test_01m5634e094qf7jx8hd3ksg4kn_external_brief.py`, `tests/test_01m56g7sb1psr277bn4chjbcqc_review_conventions.py`, возможно `tests/test_01m5enwb2xhzfrnq3q3pzsah2t_knowledge_brief.py`. Аналитик перечисляет в SPEC каждый затронутый тест и предлагаемую правку (замена источника конвенций на `conventions.md` при сохранении проверяемого свойства: блок конвенций есть, пометки при сбоях, предел размера); правка — только по мандату Оператора на гейте SPEC строкой ANSWER с матрицей неослабления. Иная правка существующих тестов — эскалация.

Порядок мержа: после задачи «ИИ-настройки внешнего проекта — полем записи, вне рабочей копии роли» (`merge_after` в SPEC), если зоны пересекаются по `orchestrator/doctor/`.

Не входит: сам разбор ИИ-настроек конкретных проектов и файлы `conventions.md` sled/feedback (делает сессия при Операторе); исключение обвязки из рабочей копии и `no_paths` (отдельная задача); MCP ролей; автоматическое изменение `conventions.md`.

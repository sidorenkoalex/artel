## Пути обхода гейтов
- О1 (связано с П1). `conventions-stamp`, проверяющий файл через
  `Path.is_file()` / `open()` по ссылке, при `conventions.md`-ссылке
  перепишет начало цели ссылки. Цель может лежать где угодно, например в
  файле клона проекта. Треб. 7 (SPEC.md:143) это запрещает, но AC-9 не
  проверяет. У брифа и `doctor` этот случай закрыт: AC-2 и AC-11.
- О2 (связано с М4). Исполнитель, читающий перечень буквально, «чинит»
  `test_ac9` тем, что оставляет в переборе один сценарий «контекст не
  разрешён». Утверждение `assertTrue(lines)` проходит, но три сценария
  нечитаемой базы теряют проверку. Это удаление проверки мимо мандата;
  ловит его только построчное ревью.
- Н2 (остаток Н1, мелкое). Решение 5 закрепило счёт N «на элемент». Не
  решено, входят ли в N покрытые обвязкой файлы не `*.md`, например
  `.mcp.json` или `harness/run.sh` в листинге `./`. Треб. 11 (SPEC.md:201)
  говорит «файлов, пропущенных фильтром обвязки». В AC-5 только `*.md`, и
  тест пропустит обе трактовки. По умолчанию естественно считать только
  `*.md`: остальные фильтр и так не показал бы.
- О3 (наблюдение, не отклонение). Команда отметки не требует, чтобы
  `sources` покрывал все файлы обвязки базы. Файл, появившийся после
  отметки, дрейфом не считается. ТЗ требует сверять только файлы заголовка.

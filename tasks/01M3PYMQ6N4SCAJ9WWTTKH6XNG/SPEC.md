# SPEC: Клон канарейки берёт модели из боевого слоя пульта; набор может перевести одну роль

## Контекст
Прогон канарейки без `--set` (`orchestrator/canary.py::_DEFAULT_SET_PLAN`)
оставляет локальный слой эфемерного клона шаблоном `models.LOCAL_TEMPLATE`,
а слой набора (`_clone_local_layer_text`) берёт ярусы, не названные набором,
тоже из шаблона. Боевой слой пульта (`.artel/models.yaml`) с 29.09 держит
`claude-opus-5-5` на всех ярусах, клон идёт на `claude-opus-5`: канарейка
для сдвига пина проверяет не боевой набор моделей (прогоны
20260929T142836Z/20260929T152203Z — $15.5/$15.4 при базовой линии $6.5).
Набор применяется сдвигом яруса целиком (`_roles_of_tiers`), а все четыре
агентские роли `roles.yaml` стоят на ярусе `strong` — набор, называющий
одну роль, переводит все четыре; замер «одна роль на проверяемой модели,
остальные на боевой» (этап 2 замера моделей) не собрать, потому что
переопределения модели одной роли в `models.py::resolve_role` нет. Подпись
«(код пина)» в сводке (`_sha_label`) после этапа 0 ADR-0021 вводит в
заблуждение: задачу ведёт код клона.

Термины: «агентская роль» — роль `roles.yaml` с `executor: agent`
(сегодня analyst, test_author, developer, reviewer); «слой пульта» —
`config.MODELS_LOCAL` главной копии; «слой клона» — локальный слой
эфемерного клона прогона.

## Требования

1. **Слой клона по умолчанию — боевой.** Прогон без `--set` и прогон с
   набором строят слой клона из слоя пульта: ярусы (`tiers:`), разрешения
   `experimental` для моделей этих ярусов, переопределения тарифа для
   моделей, на которых идут роли прогона (тем же приёмом, что сейчас для
   моделей набора), `role_providers:` пульта и раздел `role_models:`
   пульта (требование 2) вместе с разрешениями `experimental` и
   переопределениями тарифа его моделей. Раздел `canary_sets:` в слой
   клона не переносится. Слой пульта отсутствует или не разбирается —
   слой клона из шаблона `models.LOCAL_TEMPLATE`, как сейчас, и строка
   сводки прогона называет это прямо (источник «шаблон» и причина: слоя
   пульта нет / не прочитан).
2. **Модель одной роли — раздел `role_models:`.** Локальный слой
   получает необязательный раздел `role_models:` — карту «роль ->
   идентификатор модели каталога» (по образцу `role_providers:`, ключ —
   константа в `orchestrator/models.py` рядом с `ROLE_PROVIDERS_KEY`).
   `models.resolve_role` для роли с такой записью берёт модель из неё,
   минуя ярус; провайдер роли — из `role_providers:` слоя, иначе провайдер
   модели в каталоге. Модель записи вне каталога или `experimental` без
   разрешения в `allow_experimental:` — именованный отказ (подкласс
   `models.ResolutionError`, называющий роль и модель), как у яруса. Роль
   без записи разрешается как сейчас. Раздел — ручка Оператора того же
   рода, что ярусы и `role_providers:` (ADR-0017, пометка 29.09); `doctor`
   печатает по строке на каждую действующую запись раздела (роль и её
   модель из `role_models:`).
3. **Набор переводит только названные роли.** `canary --set <набор>`
   кладёт в слой клона записи `role_models:` (и `role_providers:`) ровно
   для ролей, названных набором, поверх слоя требования 1; остальные роли
   идут по слою пульта. Сдвиг яруса целиком как способ применения набора
   уходит: ярусы слоя клона — ярусы слоя пульта при любом наборе.
   Проверки набора сохраняются и считаются по ролям набора, отказы — до
   клона (до `git clone`, до строки в `tasks`, до обращения к origin):
   роль не читается в карте исполнителей, модель вне каталога, провайдер
   записи не совпадает с провайдером модели в каталоге, вход Codex для
   роли, идущей в слое клона провайдером Codex. Разрешение `experimental`
   для модели набора кладётся в слой клона, как сейчас. Отказ «набор даёт
   ярусу две разные модели» теряет предмет (слой клона больше не
   ключуется ярусом ради набора) и уходит вместе со сдвигом яруса.
4. **Сводка и запись прогона называют модели всех ролей.** Первая строка
   прогона, строка итога каждой задачи и поле `models_summary` строки
   `canary_runs` называют модель КАЖДОЙ агентской роли прогона в виде
   «analyst → <модель>, test_author → <модель>, …» — и для прогона без
   набора — вместе с источником: «слой пульта», «набор <имя>» или
   «шаблон». Подпись кода в строке итога задачи — коммит, сообщённый
   процессом клона: «код клона <sha>» вместо «(код пина)»; подпись «код
   пина» в выводе прогона канарейки не печатается.
5. **Базовая линия.** Сравнение с базовой линией по-прежнему ключуется
   парой (шаблон, набор). Базовая линия пары несравнима, если модели ролей
   прогона (сводка требования 4) отличаются от моделей последнего
   штатного прогона той же пары в `canary_runs` (строка без сводки
   моделей всех ролей — записанная до этой задачи — тоже даёт
   несравнимость). Для штатного прогона при несравнимой линии
   `_baseline_deviation_note`: отклонения не считает и алерт `threshold`
   не поднимает, перезаписывает базовую линию пары числами этого прогона и
   возвращает примечание-предупреждение, называющее причину (модели
   сменились); вердикт прогона от этого не меняется (предупреждение, а не
   красный прогон). Сравнимая линия — поведение прежнее.
6. **Тесты в `tests/`.** Новое поведение закрыто тестами (критерии ниже),
   в том числе «Ловит мутацию: слой клона из шаблона». Тесты, закрепляющие
   прежнее поведение («прогон без набора — слой клона шаблоном», «набор
   сдвигает ярус», подпись «код пина» в сводке прогона), переписываются под
   новое требование — не удаляются; перечень переписанных — в PLAN.

## Критерии приёмки

AC-1. Прогон без `--set` при читаемом слое пульта, где ярусы указывают
модели, отличные от шаблона: ярусы слоя клона равны ярусам слоя пульта
(а не шаблона); в слой клона перенесены разрешения `experimental` для
моделей этих ярусов, переопределения тарифа этих моделей, `role_providers:`
и `role_models:` пульта; раздела `canary_sets:` в слое клона нет. Тест
несёт пометку «Ловит мутацию: слой клона из шаблона».

AC-2. Слой пульта отсутствует или не разбирается: прогон не отказывает,
слой клона — шаблон `models.LOCAL_TEMPLATE`, а первая строка прогона
называет источник «шаблон» и то, что слой пульта не прочитан.

AC-3. Слой с записью `role_models: {<роль>: <модель каталога>}`:
`models.resolve_role(<роль>)` возвращает модель записи независимо от
модели яруса роли; провайдер — из `role_providers:` для этой роли, если
запись там есть, иначе провайдер модели в каталоге. Роль без записи
разрешается через ярус, как до задачи.

AC-4. Запись `role_models:` с моделью вне каталога — `resolve_role`
поднимает подкласс `models.ResolutionError`, текст которого называет роль
и модель; запись с моделью статуса `experimental` без разрешения в
`allow_experimental:` — такой же именованный отказ; с разрешением —
модель разрешается.

AC-5. `doctor` при слое с записями `role_models:` печатает по строке на
каждую запись, называющую роль и её модель из раздела; без раздела таких
строк нет.

AC-6. `canary --set <набор>` с набором, называющим одну роль: в слое
клона эта роль получает модель (и провайдера) набора, три прочие
агентские роли разрешаются в слое клона в те же модели, что в слое
пульта; ярусы слоя клона равны ярусам слоя пульта.

AC-7. Набор, называющий две роли одного яруса с разными моделями,
принимается: каждая роль получает в слое клона свою модель (отказа «две
разные модели ярусу» нет).

AC-8. Набор с ролью вне карты исполнителей, с моделью вне каталога или с
провайдером записи, не совпадающим с провайдером модели в каталоге, —
именованный отказ `canary` до эфемерного клона: `git clone` не
вызывается, строка в `tasks` не заводится.

AC-9. Набор, называющий одну роль на модели провайдера Codex, при
соседях по ярусу на провайдере `claude`: проверка входа Codex и перенос
указателя касаются ровно этой роли (перечень ролей Codex плана — только
она); при недоказанном входе — именованный отказ до клона, как сейчас.

AC-10. Первая строка прогона и строка итога задачи — как без набора, так
и с набором — называют модель каждой из агентских ролей прогона в виде
«<роль> → <модель>» и источник («слой пульта», «набор <имя>» или
«шаблон»); поле `models_summary` строки `canary_runs` этого прогона
несёт модели всех агентских ролей и источник (не пусто и для прогона без
набора).

AC-11. Строка итога задачи прогона несёт подпись «код клона <sha>», где
`<sha>` — коммит, сообщённый процессом клона (`head` его результата);
подписи «код пина» в выводе прогона канарейки нет, в том числе когда
проверяемый sha совпадает с HEAD главной копии.

AC-12. Штатный прогон пары (шаблон, набор), чья последняя штатная строка
`canary_runs` несёт другие модели ролей (или не несёт сводки моделей всех
ролей), при существующей базовой линии: алерт `threshold` не поднимается,
базовая линия пары перезаписана числами прогона, примечание сводки —
предупреждение о несравнимой базовой линии со сменой моделей, вердикт
прогона не меняется (штатный прогон остаётся `green`).

AC-13. Штатный прогон пары с теми же моделями ролей, что у последней
штатной строки пары: сравнение с базовой линией прежнее — отклонение сверх
`CANARY_DEVIATION_RATIO` поднимает алерт `threshold` и даёт прежнее
примечание, базовая линия не перезаписывается.

AC-14. Тесты `tests/`, закреплявшие прежнее поведение (слой клона
шаблоном без набора, сдвиг яруса набором, подпись «код пина» в сводке
прогона), переписаны под требования 1, 3, 4 и не удалены (число тестовых
методов в затронутых файлах не уменьшилось); перечень — в PLAN; полный
набор `tests/` зелёный.

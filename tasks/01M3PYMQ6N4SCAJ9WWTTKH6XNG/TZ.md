# ТЗ: Клон канарейки берёт модели из боевого слоя; набор может перевести одну роль

# ТЗ: Клон канарейки берёт модели из боевого слоя пульта; набор может перевести одну роль

Источник: решение Оператора 29.09.2026; строка бэклога 29.09 «Клон
канарейки берёт ярусы моделей из боевого локального слоя, а не из
шаблона» (П2); подготовка этапа 2 замера моделей (роль за ролью, опора —
боевая модель); строка копилки 29.09 о подписи «(код пина)».

Факты (пин 1d152a0b):
- `orchestrator/canary.py`: прогон без `--set` (`_DEFAULT_SET_PLAN`)
  оставляет локальный слой клона шаблоном `models.LOCAL_TEMPLATE`, а
  `_clone_local_layer_text` для набора берёт ярусы, не названные набором,
  тоже из шаблона (`models.local_template_layer().tiers`). Боевой слой
  пульта (`.artel/models.yaml`) с 29.09 держит `claude-opus-5-5` на всех
  ярусах, а клон идёт на `claude-opus-5` из шаблона. Прогоны
  20260929T142836Z и 20260929T152203Z — $15.5 и $15.4 при базовой линии
  $6.5; канарейка для сдвига пина проверяет не боевой набор моделей.
- Набор (`canary_sets:` в слое пульта) задан записями «роль -> провайдер,
  модель», но применяется сдвигом ЯРУСА целиком (`_roles_of_tiers`,
  `affected`): все четыре агентские роли в `roles.yaml` на ярусе
  `strong`, поэтому набор, называющий одну роль, переводит все четыре.
  Замер «одна роль на проверяемой модели, остальные на боевой» сегодня
  не собрать.
- Разрешение модели роли: `orchestrator/models.py::resolve_role` —
  «роль -> ярус (`roles.model_tier`) -> модель -> провайдер»; провайдер
  роли можно переопределить разделом `role_providers:` локального слоя
  (`orchestrator/roles.py::provider`; узаконено решением Оператора
  29.09.2026, ADR-0017, пометка к п.1). Переопределения модели одной
  роли нет.
- Подпись сводки «(код пина)» (`_sha_label`) после этапа 0 ADR-0021
  вводит в заблуждение: задачу ведёт код клона.

Требуется:
1. Слой клона по умолчанию — боевой. Прогон без `--set` и прогон с
   набором строят локальный слой клона из локального слоя ПУЛЬТА: ярусы,
   разрешения `experimental` для моделей этих ярусов, переопределения
   тарифа (как сейчас для моделей набора) и `role_providers:` пульта.
   Разделы, не нужные клону (`canary_sets:`), в слой клона не
   переносятся. Слой пульта отсутствует или нечитаем — слой клона из
   шаблона, как сейчас, и строка сводки прогона называет это прямо.
2. Модель одной роли. Локальный слой получает раздел «роль -> модель»
   (имя раздела выбирает SPEC; по образцу `role_providers:`):
   `resolve_role` для роли с такой записью берёт модель из неё, минуя
   ярус; провайдер — из `role_providers:` слоя, иначе провайдер модели в
   каталоге. Имя модели вне каталога или `experimental` без разрешения —
   именованный отказ, как у яруса. Раздел — ручка Оператора того же рода,
   что ярусы и `role_providers:` (ADR-0017, пометка 29.09); его
   действующие записи видит `doctor` строкой по каждой роли.
3. Набор переводит только названные роли. `--set <набор>` кладёт в слой
   клона записи раздела требования 2 ровно для ролей, названных набором,
   — остальные роли идут по боевому слою (требование 1). Сдвиг яруса
   целиком как способ применения набора уходит. Проверки набора (модель
   в каталоге, `experimental`, вход Codex для ролей на Codex, отказы до
   клона) сохраняются и считаются по ролям набора.
4. Сводка и запись прогона называют модель КАЖДОЙ агентской роли прогона
   (и для прогона без набора): «analyst → …, test_author → …, …», и
   источник («слой пульта», «набор <имя>», «шаблон»). Подпись кода —
   коммит, сообщённый процессом клона («код клона <sha>»), вместо «(код
   пина)».
5. Базовая линия: сравнение с базовой линией ключуется по набору, как
   сейчас; смена модели по умолчанию делает прежнюю базовую линию набора
   default несравнимой — первый прогон после мержа пишет новую
   (поведение `_baseline_deviation_note` для несравнимой линии SPEC
   определяет по коду: предупреждение, а не красный прогон).
6. Тесты в `tests/`: слой клона по умолчанию равен ярусам слоя пульта
   («Ловит мутацию: слой клона из шаблона»); набор с одной ролью меняет
   модель только этой роли, три прочие — модели слоя пульта; раздел
   «роль -> модель» в главном пульте разрешает модель роли и даёт отказ
   на модель вне каталога; сводка называет модели всех ролей и источник.
   Тесты, закрепляющие прежнее поведение («прогон без набора — слой
   клона шаблоном», AC-14 задачи 01M3FQ2Z2PY0E9T5F5WQ207NP5; «набор
   сдвигает ярус»), переписываются под новое требование — не удаляются;
   перечень — в PLAN.
7. Проверка на деле — после мержа, вне задачи (сессия ассистента):
   канарейка без набора на боевом слое, затем пробный набор с одной
   ролью.

# SPEC: plank-run работает в шаге роли — путь планки, который признаёт сторож роли

## Контекст
Команда `artel.py plank-run` (задача 01M41R4YAM4NGEQXW1FWH7T22M, слита
03.10.2026) передаёт pytest абсолютный путь планки
(`orchestrator/plank_run.py:139-141`: `str(tests_dir / selected)` либо
`str(tests_dir)`, где `tests_dir` — `<рабочая копия>/tasks/<id>/acceptance_tests`;
запуск — `acceptance.run_plank([target_arg], code_dir)` с `cwd=code_dir`).
Процесс pytest наследует окружение роли, и сторож роли
`conftest.py::pytest_configure` пропускает только позиционные пути, которые
`_is_targeted_path` признаёт целевыми (относительный путь ниже `tests/`
или путь с первым сегментом `tasks` и сегментом `acceptance_tests`).
Абсолютный путь начинается с пустого сегмента, поэтому первый же вызов
из шага роли (test_author задачи 01M41VH0Z3CQ0WY039SV1ERGMB, 03.10 21:47Z)
получил отказ «Сторож роли: полный прогон набора тестов внутри шага
запрещён». Тесты задачи 01M41R4YAM4NGEQXW1FWH7T22M подменяют
`subprocess.run` и настоящий сторож под окружением роли не исполняют.

## Требования
1. `plank-run` передаёт pytest путь планки в форме, которую признаёт
   сторож роли: относительный от рабочей копии кода путь
   `tasks/<id>/acceptance_tests` для всей планки и
   `tasks/<id>/acceptance_tests/<файл>` (с узлом `::тест`, если он назван)
   для одного файла.
2. Без окружения роли поведение `plank-run` не меняется: тот же исход,
   тот же состав прогоняемых тестов, тот же код выхода и итоговая строка.
3. Сквозной долгоживущий сторож в `tests/` с заявкой «Ловит мутацию»:
   `plank-run` под окружением роли, без подмены `subprocess.run`, на
   песочнице с настоящим `conftest.py` репозитория; прогон доходит до
   pytest и даёт его итог, а не отказ сторожа роли. Сторож краснеет при
   возврате абсолютного пути. Случаи: вся планка и аргумент одного файла.
4. Существующие долгоживущие тесты задачи 01M41R4YAM4NGEQXW1FWH7T22M
   (`tests/test_01m41r4yam4ngeqxw1fwh7t22m_plank_run.py`,
   `tests/test_plank_run_edges.py`) правятся только в объёме смены формы
   пути, с перечнем правок в PLAN. По сверке аналитика на пине d860c974
   ни одно их утверждение абсолютную форму аргумента не закрепляет:
   `test_01m41r4yam4ngeqxw1fwh7t22m_plank_run.py:262-267` сверяет только
   начало команды (`cmd[:3]`) и её хвост (`cmd[-6:]`), а не позиционный
   путь. Правка этих тестов поэтому не ожидается. Если разработчик всё же
   найдёт утверждение, которое закрепляет абсолютную форму, он называет
   тест и утверждение в PLAN; гейт сохранности тестов при необходимости
   решается мандатом Оператора.

## Критерии приёмки
AC-1. Под окружением роли (переменная роли задана) `plank-run <id>` без
аргумента файла, без подмены `subprocess.run`, на песочнице с настоящим
`conftest.py` репозитория доходит до pytest и печатает его итог (например,
«N passed»). В выводе нет отказа «Сторож роли: полный прогон набора тестов
внутри шага запрещён».

AC-2. То же для `plank-run <id> <файл>`: под окружением роли прогоняется
только названный файл планки, и печатается итог pytest, а не отказ сторожа
роли.

AC-3. Позиционный путь, который `plank-run` передаёт pytest, — относительный
от рабочей копии кода: `tasks/<id>/acceptance_tests` для всей планки,
`tasks/<id>/acceptance_tests/<файл>[::узел]` для одного файла.
`conftest._is_targeted_path` признаёт его целевым. Сторож AC-1/AC-2
краснеет, если вернуть абсолютную форму (`str(tests_dir …)`).

AC-4. Без окружения роли `plank-run` прогоняет тот же состав тестов, что
и до правки, для всей планки и для одного файла, с тем же кодом выхода и
итоговой строкой pytest. Существующие тесты
`tests/test_01m41r4yam4ngeqxw1fwh7t22m_plank_run.py` и
`tests/test_plank_run_edges.py` остаются зелёными. Если правится
какое-либо их утверждение, то только в объёме смены формы пути, и каждая
такая правка перечислена в PLAN с указанием теста и утверждения.

## Оценка объёма и деление
Сработавший сигнал: зона задевает механизм, на который опирается запись в
`docs/invariants.md`. Зоны `orchestrator/` и `tests/` взяты из ТЗ
каталогами целиком, поэтому формально покрывают инвариантные механизмы.
Фактическая правка — одна строка формирования аргумента в
`orchestrator/plank_run.py` плюс новый сквозной тест в `tests/`; карта
`docs/codebase-map.md` регенерируется.

Прогноз диффа: 8 КиБ

Обоснование монолита: правку кода и сквозной сторож нельзя разнести по
разным подзадачам. Сторож без правки красный: под окружением роли
`plank-run` сейчас получает отказ сторожа роли. Правка без сторожа
оставляет требование ТЗ 2 невыполненным и регрессию незакрытой.
Промежуточная часть либо красит набор `tests/`, либо мержится без
обязательной проверки. Объём — 4 критерия, одна функциональная правка.

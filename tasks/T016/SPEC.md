# SPEC: Актуализация design.md по итогам Фазы 0+

Фаза 0 выполнена и перевыполнена: часть механизмов, описанных как
«MVP» и «полная версия», уже реализована (auto, инварианты-тесты,

оркестратор стал модульным пакетом (T015). Документ — источник истины
архитектуры и должен отражать факт, не отставая от него.

## Требования
1. Инвентаризация расхождений в PLAN: таблица «раздел design.md →
   что описано → что реализовано → правка». Источники факта:
   docstring orchestrator/artel.py (карта модулей и механик),
   docs/invariants.md, docs/adr/*, tasks/T00*-T016 (SPEC'и done-задач),
   README.
2. Правки в design.md по итогам инвентаризации, минимум:
   - §12: Фаза 0 помечена выполненной (критерий «5 задач» достигнут,
     дата), список реализованного сверх плана Фазы 0 с указанием
     задач (T007 стоимость/потолок, T010 инварианты, T011 ревью-пакет,
     T012 бюджет из SPEC, T014 auto, T015 модульный пакет);
   - §4: механика budget_usd из SPEC (только понижение, инвариант 10);
   - §6: команда auto как реализованный предшественник демона;
     фактическая модель запуска Фазы 0 (CLI + auto, поллинг вместо
     вебхуков);
   - §7: отметить реализованные элементы наблюдаемости (журнал шагов
     с стоимостью/токенами, стриминг логов, размер ревью-пакета);
   - §11: стек Фазы 0 фактический (python stdlib + SQLite + claude CLI
     + GitHub Actions), модульная структура оркестратора.
3. Стиль правок: статусные пометки и уточнения в существующих
   разделах («Реализовано в Фазе 0, Txxx»), НЕ переписывание;
   исторические разделы-снапшоты (§15 конкурентный ландшафт) не
   трогать.
4. НЕ вносить: неутверждённые концепты (подключение целевых проектов
   /targets, пульт-приложение, ассистент Оператора) — они войдут
   отдельными ADR решением Оператора.
5. Diff задачи — только docs/design.md и артефакты tasks/T016/.

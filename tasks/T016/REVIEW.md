## Замечания

- **major — docs/design.md:61 (§2, строка «Оркестратор»)** — «ревью-пакет
  (SPEC, PLAN, прошлый REVIEW, стат-список и diff ветки) уходит в промпт
  шага **целиком**» — утверждение не соответствует коду сразу в двух
  частях. (а) У пакета два потолка: `config.py:43`
  `REVIEW_DIFF_MAX_LINES = 4000` и `config.py:51`
  `REVIEW_PACKAGE_MAX_BYTES = 400_000`; при превышении `review.py:75`
  `truncate_diff` и `review.py:90` `truncate_package` усекают содержимое
  и вклеивают пометку об усечении. (б) Пакет не заменяет чтение
  репозитория: промпт ревьювера прямо разрешает читать файлы сверх пакета
  точечно (`runner.py:44-45`).
  *Сценарий поломки:* design.md — источник, на который ссылается колонка
  «Откуда» реестра `docs/invariants.md`, и по нему сверяются следующие
  роли. Потолок пакета — лимит в смысле ADR-0002 (защита контекста шага,
  комментарий `config.py:40-50`); из источника истины он этой правкой
  исчезает, а вместо него зафиксировано обратное. Ближайшая задача,
  читающая §2 (например, «ревьювер должен видеть весь diff» или снятие
  усечения как «лишнего кода»), получит из документа неверную посылку —
  ровно тот класс, который PLAN назвал главным риском («пометка
  «реализовано» на механизме, которого нет»), только с обратным знаком.
  *Предложение:* «…уходит в промпт шага одним куском — под потолками
  4000 строк diff и 400 000 байт пакета, сверх которых пакет усекается
  с явной пометкой; файлы сверх пакета ревьювер читает точечно (T011)».
  Других мест этого класса — утверждение «реализовано/целиком» без
  подтверждения в коде — в diff нет: остальные проверены поимённо (раздел
  «Проверка фактических утверждений правки»).

- **minor — docs/design.md:64 и docs/design.md:503** — ссылка на ADR-0001
  там, где ADR-0001 заявленного факта не содержит. ADR-0001 (28 строк)
  фиксирует объём Фазы 0 (две роли-агента, SPEC и приёмка — Оператор,
  FSM-CLI на SQLite, гейты захардкожены manual) и два даунгрейда
  безопасности (общий токен, отсутствие branch protection). В нём нет ни
  слова про слияние фаз ревью в один прогон (строка 64: «гейт плана
  выполняется как фаза A чек-листа (ADR-0001)»), ни про отсутствие
  `docs/conventions/`, скила `codebase-map` и `incidents/` (строка 503).
  *Сценарий:* критерий приёмки 2 — прослеживаемость; читатель идёт
  по ссылке, факта не находит и не может отличить решение Оператора
  от того, что просто не делали. Остальные пять ссылок на ADR-0001
  (строки 95, 208, 397, 421, 474) подтверждены его текстом — класс
  ограничен этими двумя.
  *Предложение:* строка 64 — сослаться на факт кода («в FSM Фазы 0 нет
  состояния `plan_review`, см. §6») без ADR; строка 503 — для
  `codebase-map` источник есть внутри документа (§12, плановый пункт
  «codebase-map — статичный рукописный файл», отмеченный как несделанный),

# PLAN: Гейт неослабления тестов наблюдает изменённые утверждения внутри сохранённого метода

## Подход
Монолит (одна задача, один MR): режим — только наблюдение, переход и мерж
от нового кода не зависят. Бюджет SPEC ($40) не пересматривается.

- **Разбор и нормальная форма — `scripts/guard.py`** рядом с
  `test_skip_markers`, на том же сборщике `_collect_qualified_test_functions`:
  `test_assertions(source)` — `{Класс::метод: [(нормальная форма, исходный
  текст)]}` или `None`, если текст не разбирается (отличимо от «утверждений
  нет»); `changed_test_assertions(base, head)` — сравнение мультимножеств
  (`Counter`) по методам, живым по обе стороны. Утверждение: `ast.Assert`,
  вызов атрибута `assert*`/`fail`, `pytest.raises`/`pytest.warns`
  (`_is_assertion`), обход `ast.walk` по всему телу. Помощники первого
  уровня: `self.<имя>(…)` — метод того же класса, голое имя — функция модуля
  без `test_`; каждый вызов разворачивается один раз, без рекурсии.
  Нормальная форма — `ast.dump` копии узла после `_AssertionNormalizer`:
  `msg=` и часть `assert` после запятой отброшены, позиционный аргумент
  сверх обязательных — по таблице `ASSERTION_REQUIRED_ARGS` (методы с
  третьим не-сообщением, как `assertAlmostEqual`, в таблицу не включены);
  локальные имена (`_local_names`: Name в контексте записи, параметры кроме
  `self`, `except … as`, имена вложенных функций) — метка `<локальное имя>`;
  импортированное имя модуля как `.value` атрибута — метка `<импорт>`, голое
  импортированное имя не трогается.
- **Узел гейта — `orchestrator/advance_gates/test_integrity.py`.** Цикл по
  диффу вынесен в `_compare` (один проход git на обе цели: прежние находки
  и наблюдение); `findings()` сохраняет прежнюю форму возврата. Находка об
  утверждениях — тот же `Finding(path, Класс::метод, text, alias)`, текст
  «утверждения изменены в Класс::метод: <до трёх утверждений base>; и ещё
  N», каждое ≤120 знаков. Наблюдение пишет общий вход `uncovered` (его зовут
  оба рубежа): запись «изменены утверждения тестов (наблюдение)» с отметкой
  «покрыто мандатом ANSWER-n» по `Finding.mandate_elements`; неразбираемый
  файл или молчание git — запись «утверждения тестов: наблюдение не
  выполнено» с detail «наблюдение не выполнено: <причина>». В возврат
  `uncovered` находки об утверждениях не идут — узел отказа не меняется.
- **Вход ревьювера — `orchestrator/review.py`** (не `brief.py`: у
  ревьювера `brief_text` всегда `None`, SPEC «Материалы»): раздел
  «Изменённые утверждения тестов» после diff, обёрнутый границей
  недоверенных данных; без находок, у канарейки и внешнего target раздела
  нет. `brief.py` из зон не правился.
- **Приложения PLAN** — три диффа к защищённым путям (требования 7-9).

## Влияние на систему
- Инвариант 38 (гейт неослабления): узел отказа не менялся — `findings()`
  возвращает прежний кортеж, `uncovered` возвращает прежние находки;
  существующие тесты гейта и смоук `tests/test_fsm_advance_gate_smoke.py`
  зелёные без правки ассертов. Добавлены только записи журнала обычного
  уровня и раздел ревью-пакета.
- На молчании git прежняя реакция сохранена (fail-closed на переходе,
  fail-open на мерже); рядом добавлена запись «наблюдение не выполнено».
- `_answer_mandate` теперь читается и тогда, когда находок отказа нет, но
  есть находки об утверждениях (для отметки мандата) — только чтение.
- Ревью-пакет: раздел появляется только при находках; недекодируемый вывод
  git (`UnicodeDecodeError`) в наблюдении пакета гасится, как у
  `git_diff_part` (тест `test_undecodable_diff_does_not_kill_the_run`).
- Канарейка и внешний target: гейт перехода возвращается до узла, как
  раньше; гейт мержа для внешнего target не зовёт узел; ревью-пакет у них
  раздела не строит.
- Откат — revert одного merge-коммита; приложения к защищённым путям
  откатываются тем же revert.

## Риски
- Ложные находки наблюдения: функция модуля, переименованная из импорта
  в локальную (`from x import f` → своя `def f`), или помощник, вызванный
  не через `self.`/голое имя, — наблюдение их видит как смену утверждения.
  Цена — строка журнала, не отказ.
- Таблица `ASSERTION_REQUIRED_ARGS` неполна по определению; неизвестное
  имя сравнивает все аргументы (смена сообщения у него — находка).

## Предложения системе
- `scripts/guard.py` уже 3000+ строк и держит и валидацию артефактов, и
  ast-разбор тестов для гейтов; разбор тестов просится в отдельный модуль
  `scripts/test_ast.py` (отдельная задача-рефакторинг).
- В окружении шага нет `ls`/`cat`/`rm` в PATH оболочки инструмента, а
  `/bin/rm` требует подтверждения, которого в шаге никто не даст: временные
  файлы шага удаляются только обходом через `python3 -c "os.remove(…)"`
  (`.artel/home/.claude/settings.json`).

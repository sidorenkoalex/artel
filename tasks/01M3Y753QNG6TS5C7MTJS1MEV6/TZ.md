Требуется:
1. Определение утверждения тестового метода (в `scripts/guard.py`, рядом с
   `test_skip_markers`, на том же сборщике `_collect_qualified_test_functions`):
   а) оператор `assert <выражение>`;
   б) вызов, у которого вызываемое — атрибут с именем, начинающимся на
      `assert` или равным `fail` (`self.assertEqual(…)`, `self.fail(…)`,
      `mock.assert_called_once_with(…)`, собственный `self.assert_refused(…)`);
   в) вызов `pytest.raises(…)` и `pytest.warns(…)`.
   Утверждения собираются по всему телу метода на любой глубине (ветки,
   циклы, `with`, `subTest`, вложенные функции). Дополнительно — на ОДИН
   уровень — утверждения вспомогательных функций, которые метод вызывает:
   метода того же класса через `self.<имя>(…)` и функции уровня модуля по
   голому имени, если у этой функции нет префикса `test_`. Вспомогательные
   функции берутся из той же стороны сравнения (base — из base, head — из
   head).
2. Нормальная форма утверждения — ключ сравнения:
   а) структура синтаксического дерева без номеров строк и позиций
      (`ast.dump` без атрибутов позиции);
   б) аргумент сообщения отбрасывается: именованный `msg=`, у оператора
      `assert` — часть после запятой, у методов `unittest` с известным
      числом обязательных аргументов — позиционный аргумент сверх него
      (таблица методов — в коде, рядом с определением; у неизвестных
      имён сравниваются все аргументы);
   в) все локальные имена метода (параметры кроме `self`, цели
      присваивания, переменные циклов, `with … as`, `except … as`,
      переменные генераторов) заменяются одной меткой «локальное имя»;
   г) корень цепочки атрибутов, если это имя, связанное на уровне модуля
      инструкцией `import` или `from … import`, заменяется одной меткой
      «импорт» (`fsm._x(…)` и `ci_rerun._x(…)` совпадают; голое
      импортированное имя-константа не заменяется).
3. Сравнение base → head для каждого тестового метода, квалифицированное
   имя которого есть по обе стороны, — как мультимножеств нормальных
   форм. Находка — каждое утверждение base, которого в head меньше по
   числу вхождений. Это значит:
   - находка: удалённое утверждение; смена вида (`assertEqual` →
     `assertIn`/`assertTrue`, `assertRaisesRegex` → `assertRaises`,
     `assert` → `if`); любая смена аргумента, кроме сообщения (другое
     ожидаемое значение, другой атрибут `self.pult_home` → `self.clone_home`,
     укороченная подстрока);
   - не находка: добавленное утверждение; перестановка утверждений;
     переименование локальной переменной; смена текста сообщения;
     перенос утверждения во вспомогательную функцию первого уровня и
     обратно; смена модуля, через который вызвана функция (п. 2г);
     смена форматирования и комментариев.
   Ужесточение вида (например, `assertIn` → `assertEqual`) по этому
   правилу тоже находка: семантику «сильнее/слабее» программа не
   оценивает, решает Оператор мандатом.
4. Одна находка на метод, имя находки — квалифицированное имя метода
   (`Finding(path, name, text, alias)`, тот же класс, что у исчезнувшего
   метода): мандат `путь::Класс::метод` и мандат на путь файла снимают
   её штатно, без правки разбора мандата. Текст: «утверждения изменены в
   <Класс::метод>: <исходный текст утверждения base>» — до трёх
   утверждений, каждое не длиннее 120 знаков, остальные — «и ещё N».
   У исчезнувшего метода и у удалённого файла находка об утверждениях не
   добавляется (не дублировать уже названную потерю). Head или base не
   разбирается — утверждения не сравниваются (тот же отказоустойчивый
   приём, что `_parse_or_none`), остальные находки файла собираются как
   сейчас.
5. Режим этой задачи — НАБЛЮДЕНИЕ, не блокировка (решение Оператора
   02.10: сначала правило ревьювера и запись в журнал; блокировка —
   отдельной задачей по итогам наблюдения). Находки об утверждениях
   собираются отдельно от находок `_file_findings` и НЕ входят в узел
   отказа: на переходе `in_dev → verifying` и на гейте мержа они пишутся
   в журнал одной записью на задачу и рубеж — действие «изменены
   утверждения тестов (наблюдение)», detail — перечень находок в форме
   требования 4 и отметка «покрыто мандатом ANSWER-n» для покрытых
   мандатом. Переход и мерж от этих находок не зависят; молчание git или
   неразбираемый файл — запись «наблюдение не выполнено: <причина>», не
   отказ. Те же находки пульт кладёт в бриф ревьювера отдельным разделом
   «Изменённые утверждения тестов» (ревьювер решает по требованию 7).
   Канареечная задача и внешний target — без изменений.

# ТЗ: полный прогон тестов из шага роли — команда пульта с параллелью, базой сравнения и повтором упавших

Порядок: после 01M45FJVGQT1K0P8HDEXZX6HS7

Источник: копилка 04.10 «Полный прогон tests/ локально идёт 22.5 мин
последовательно…» (приоритет 2); прецедент 05.10 — этап 3 ADR-0021,
часть 1 (01M45FJVGQT1K0P8HDEXZX6HS7): три шага разработчика, два таймаута
по 45 минут, около 50 запусков pytest — роль сама делила набор на восемь
пачек (собственный сценарий `.runchunk.py` в корне рабочей копии) и
отдельной рабочей копией базы выясняла, что 16 падений есть и на main.
Решение Оператора 05.10: задача первым приоритетом, до части 2 этапа 3.

Факты (пин b9f3dba3, сверка кода 05.10):
- Пакет `pytest-xdist` в интерпретаторе роли есть: интерпретатор роли —
  venv пульта (`orchestrator/runner.py::_venv_interpreter_bin` ~942,
  `::role_env` ~968), xdist 3.8.0 стоит там по `requirements.lock`
  (`orchestrator/stack.py` ~84). Запись копилки 04.10 «pytest-xdist не
  установлен» к окружению роли не относится.
- Полный набор пульт гоняет одной функцией —
  `orchestrator/acceptance.py::run_full_suite` (~648-695: `-n
  config.FULL_SUITE_WORKERS -p xdist`, `FULL_SUITE_WORKERS = "auto"`,
  предел `config.FULL_SUITE_TIMEOUT_SEC = 900`), с разбором и логом —
  `::full_suite` (~698-720, `run_digest`, `_write_full_suite_log`).
  Замер 11.09: 438 с последовательно, 140 с при `-n 8`.
- Роли полный прогон запрещён дважды: сторожем `conftest.py`
  (`pytest_configure`, ~71-77: при `ARTEL_ROLE` в окружении — отказ,
  если среди аргументов нет пути ниже `tests/` или есть нецелевой) и
  текстом `skills/coding-standards.md` (~114-123: «Полный набор `tests/` в
  шаге НЕ запускай… его и так гоняет CI»). Сторож обходится перечислением
  всех файлов `tests/` — так и сделал разработчик 01M45FJVGQ.
- Окружение прогона пульта — `acceptance.py::_pytest_env` (~49-69):
  копия `os.environ` плюс `PYTHONPYCACHEPREFIX`; `ARTEL_ROLE` не
  снимается, поэтому прогон пульта, вызванный из процесса роли, сторож
  `conftest.py` отклонил бы.
- Кеш pytest выключен всеми прогонами пульта (`-p no:cacheprovider`,
  `_pytest_command` ~26-47) — повтор «только упавших» (`--lf`) роли
  недоступен.
- Команды, доступные процессу роли, — белый список
  `orchestrator/artel.py::_ROLE_ALLOWED_COMMANDS` (~1531-1533, там
  `plank-run`); образец команды прогона в шаге роли —
  `orchestrator/plank_run.py` (151 строка: выкладка, прогон, уборка,
  состояния пульта не меняет).
- Предел одного вызова инструмента у роли — 10 минут
  (`skills/coding-standards.md` ~107-108).
- Часть 1 этапа 3 (01M45FJVGQ, мерж до этой задачи) вводит профиль тестов
  проекта `test_profile` в `targets.yaml` с командой прогона `command` и
  доступ к нему через `repo_context` (её SPEC, требования 1-2, 6).
- `skills/`, `conftest.py`, `tests/test_invariants.py` — защищённые пути
  (`orchestrator/config.py::PROTECTED_PATHS`).

Требуется:
1. Команда пульта `suite-run <id>`: полный набор тестов проекта задачи в
   её рабочей копии (`workspace.path`) на текущем состоянии рабочего
   дерева, в переднем плане. Прогон — тем же узлом, что у пульта
   (`acceptance.run_full_suite`/`full_suite`, параллель `-n
   FULL_SUITE_WORKERS`), с командой из профиля тестов проекта (часть 1).
   Проект без профиля или с командой, к которой флаги параллели pytest
   неприменимы, — отказ с причиной, без прогона. Окружение прогона
   снимает `ARTEL_ROLE`: это прогон пульта, сторож `conftest.py` не
   меняется. Предел прогона по команде укладывается в 10 минут вызова
   роли с запасом (значение — решение SPEC, константа в
   `orchestrator/config.py`); на пределе — итог «прогон не уложился» с
   тем, что успело выполниться, а не тишина.
2. База сравнения. Команда сравнивает упавшие тесты с прогоном того же
   набора на базе задачи (`gitcmd.diff_base` её ветки) в отдельной
   временной рабочей копии клона проекта. Итог базы хранится в
   каталоге состояния пульта (`config.LOGS` или соседнем) по sha базы и переиспользуется всеми задачами с той же
   базой; второй прогон той же базы не идёт. Прогон базы, не уложившийся
   в предел, — итог «база не посчитана», сравнение не выдумывается.
3. Отчёт команды — коротко, для шага роли: число прошедших, упавших,
   пропущенных; упавшие разделены на «новые на ветке» и «падают и на
   базе»; новые сгруппированы по признаку ошибки (тип исключения и
   первая строка сообщения) с числом тестов в группе и тремя примерами;
   путь к файлу полного лога. Объём вывода ограничен (решение SPEC).
4. `suite-run <id> --failed` — повтор только тестов, упавших в прошлом
   прогоне этой задачи (перечень хранится пультом рядом с логом); нет
   прошлого прогона — отказ с подсказкой. Кеш pytest не включается.
5. Одновременно на машине идёт не больше одного прогона `suite-run`
   (вместе с прогоном базы): занято — отказ сразу с указанием, чей прогон
   идёт, без ожидания.
6. Команда в белом списке роли (`_ROLE_ALLOWED_COMMANDS`): состояния
   задачи не меняет, lease не берёт; пишет только лог, перечень упавших
   и итог базы в каталоге состояния пульта. Временные рабочие копии убирает на любом
   исходе.
7. Миссия роли разработчика (`orchestrator/role_prompt.py`) называет
   команду с полным путём к `artel.py` пульта, как у `plank-run`.
8. Приложением к PLAN — `skills/coding-standards.md`: вместо запрета
   полного набора — порядок: сначала затронутые модули, полный набор —
   только командой `suite-run` (не перечислением файлов `tests/` в
   обход сторожа), повтор — `--failed`; собственные сценарии деления
   набора на пачки запрещены.
9. `docs/codebase-map.md` — строка о новой команде.
10. Тесты в `tests/` с заявками «Ловит мутацию» на пп. 1–6, в том числе:
    прогон идёт в рабочей копии задачи и с параллелью; `ARTEL_ROLE`
    снят; падение, которое есть и на базе, попадает в «падают и на
    базе»; база той же sha считается один раз; `--failed` гоняет только
    перечень; второй одновременный вызов отказывает; команда доступна
    процессу роли. Существующие тесты не ослабляются.

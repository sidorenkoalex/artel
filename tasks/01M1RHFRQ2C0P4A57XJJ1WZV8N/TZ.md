# ТЗ: регрессия №13 — после замечаний ревью `auto` запускает разработчика, а не переход

Источник: два инцидента 05.09 сразу после мержа задачи «auto: переход
по готовым артефактам до запуска роли» (01M1R8B3ZKXQT0Z0G6QQQDV906).
Регрессия №12 (01M1R9YEK0…) и гейт ёмкости (01M1RA0N6F…): после
`review -> in_dev` с вердиктом changes_requested цикл `auto` делает
предварительный `advance`, гейт перехода видит PLAN `status: ready` и
код в ветке и пропускает задачу обратно в `review` без единого шага
developer. Ревьювер три раза подряд рецензирует байт-в-байт тот же код
(коммиты кодовой ветки между итерациями — только «подтяжка main»),
лимит ревью исчерпан, задача в escalated. Потери: две-три итерации
ревью на задачу ($1–3 каждая) и ручной разбор Оператора; все живые
задачи с замечаниями подвержены.

Требуется:
1. Предварительный `advance` в цикле `auto` не выполняется, если текущее
   пребывание задачи в `in_dev` началось переходом `review -> in_dev`
   (замечания ревью) и после этого перехода не было ни одного
   завершённого шага developer (запись `agent run finished` роли
   developer после записи `state -> in_dev`). В этом случае `auto`
   сразу запускает роль developer.
2. То же правило для любого возврата в состояние роли с непустым
   основанием переделки: `acceptance -> in_dev` (reject приёмки),
   `spec_gate -> spec_writing` (reject SPEC), `tests_writing` после
   отказа трассируемости — переход по готовым артефактам допустим
   только когда артефакт роли новее, чем причина возврата.
3. Гейт `in_dev -> review` (`fsm_advance`) не пропускает переход, если
   REVIEW.md текущей итерации имеет `status: changes_requested`, а
   кодовая ветка не получила ни одного коммита разработчика после
   коммита этого REVIEW.md (сверка по времени/sha, не по тексту) —
   второй рубеж независимо от `auto`: ручной `advance` Оператора тоже
   не должен возвращать неизменённый код на ревью.
4. Отказ обоих рубежей именован и журналируется («замечания ревью не
   отработаны: нет шага developer после итерации N»).
5. Тесты: сценарий «замечания → auto» запускает developer, а не
   advance; после завершённого шага developer advance проходит; ручной
   advance на неизменённом коде после changes_requested — отказ с
   причиной; существующие тесты `tests/test_auto_cycle.py`,
   `tests/test_advance_guard.py` и планка 01M1R8B3ZK… зелёные без
   ослабления.

Зоны: orchestrator/auto.py, orchestrator/fsm_advance.py, tests/.
Приоритет: критичный, впереди остальных задач зон auto.py/fsm_advance.py
(гейт ёмкости — в escalated, его код после этой задачи). До мержа
временная дисциплина Оператора: после замечаний ревью запускать
developer явно (`artel.py run <id>`), не `auto`.

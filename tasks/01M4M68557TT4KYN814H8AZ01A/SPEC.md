# SPEC: Этап 4 ADR-0021, часть B — исторические снимки для каталогов tasks/ без refs/artifacts

## Контекст
Оператор собирается убрать `tasks/*` из main (ADR-0018, условия уборки
`tasks/`; ADR-0021, этап 4). Сверка по origin/main 415f1de4 (11.10.2026):
в main 367 каталогов `tasks/<id>/`, у 101 из них нет ссылки
`refs/artifacts/<id>`: 93 задачи T001–T102 и 8 ранних задач с ULID. После
уборки документы этих задач можно было бы прочитать только из истории
main. Ссылки документов пишет только пульт, а команды, которая создала бы
ссылку из дерева main, нет: создать её сегодня можно только в обход пульта.
Задача добавляет такую команду Оператора. Ещё она включает созданные
снимки в сверку неизменности, которую делает `doctor`.

## Требования
1. Команда пульта для Оператора создаёт `refs/artifacts/<id>` для каждого
   каталога `tasks/<id>/` текущего `origin/main`, у которого этой ссылки
   нет ни локально, ни на origin. Дерево ссылки — содержимое
   `tasks/<id>/` из `origin/main` как есть. Коммит помечен как
   исторический снимок, источник — sha `origin/main`, из которого взято
   дерево. Созданная ссылка отправляется на origin.
2. У команды есть пробный режим. Он печатает перечень ссылок, которые
   были бы созданы, и ничего не записывает: ни ссылок (локально и на
   origin), ни записей журнала.
3. Существующие ссылки `refs/artifacts/<id>` (локальные и на origin)
   команда не меняет ни при каких условиях.
4. Если файл каталога `tasks/<id>/` в main новее, чем в существующем
   снимке этой задачи, команда только перечисляет его в отчёте строкой
   «путь, sha main, sha снимка» и не меняет ссылку. Решение по таким
   файлам принимает Оператор.
5. Повторный запуск идемпотентен: ссылку, созданную раньше, команда не
   создаёт второй раз и не переписывает.
6. Каждый созданный исторический снимок записывается в журнал `steps`.
   Запись несёт id задачи из имени каталога, target, отдельное действие
   журнала «исторический снимок» и коммит снимка. Для задачи, которой нет
   в таблице `tasks` (например, из T-серии), пишется такая же запись без
   строки задачи: у `steps` нет внешнего ключа на `tasks`, а строки в
   `tasks` для этой задачи не заводится. `doctor` сверяет ссылку с
   записанным коммитом снимка так же, как ссылку закрытой задачи
   сверяет с коммитом закрытия: голова ссылки локально и на origin
   совпадает с коммитом из журнала. Подмену ссылки `doctor` выдаёт
   тревогой.
7. Записи из требования 6 не вызывают у `doctor` ложных тревог. Это
   касается любых его проверок, включая сирот, счётчики задач и
   recovery-сверку журнала со ссылками.
8. После создания ссылок читатели документов находят документы
   исторической задачи через `refs/artifacts/<id>`, даже если в main нет
   `tasks/`.

## Критерии приёмки
AC-1. На песочнице в `origin/main` три каталога `tasks/<id>/`: у двух нет
ссылки `refs/artifacts/<id>`, у третьего ссылка есть. Команда создаёт
ровно две ссылки, локально и на origin. Дерево каждой совпадает с
`tasks/<id>/` из `origin/main`, коммит помечен как исторический снимок с
sha `origin/main`. Ссылка третьей задачи остаётся прежней.

AC-2. На той же песочнице пробный режим печатает перечень двух ссылок,
которые были бы созданы. Ни локально, ни на origin не появляется ни одной
ссылки `refs/artifacts/*`, в журнале `steps` нет новых записей.

AC-3. Повторный запуск команды после AC-1 создаёт ноль новых ссылок, и
головы всех трёх ссылок, локальные и на origin, не меняются.

AC-4. Есть каталог со снимком, в котором файл в main новее, чем в снимке.
Команда выводит строку отчёта с путём файла, sha main и sha снимка.
Голова ссылки этой задачи, локально и на origin, не меняется.

AC-5. После AC-1 `doctor` не выдаёт тревог о неизменности ссылок
документов, в том числе для исторической задачи без строки в таблице
`tasks`, и не выдаёт других тревог из-за записей журнала об исторических
снимках.

AC-6. После AC-1 голову исторической ссылки подменяют на другой коммит
(локально или на origin). `doctor` выдаёт тревогу о расхождении этой
ссылки.

AC-7. После AC-1 из `origin/main` песочницы убирают `tasks/`. Документ
исторической задачи читается через `docs_fetch`
(`orchestrator/docs_fetch.py`) из `refs/artifacts/<id>`.

AC-8. Мутацию «команда переписывает существующую ссылку
`refs/artifacts/<id>`» ловит хотя бы один из тестов AC-1, AC-3 или AC-4.

## Оценка объёма и деление
Сработавший сигнал: в зоне пять элементов (`orchestrator/artel.py`,
`orchestrator/snapshot.py`, `orchestrator/doctor/`,
`docs/codebase-map.md`, `tests/`).

Обоснование монолита. Делить нечего: команда (требования 1–5) и
журнальная запись со сверкой `doctor` (требования 6–7) — одна механика.
Без сверки снимки, которые создаёт команда, были бы ссылками, неизменность
которых никто не проверяет. Сверку без команды нечем наполнить и негде
проверить. `docs/codebase-map.md` и `tests/` входят в зону только как
следствие правки кода. Из кода меняются три места: точка входа CLI,
модуль снимков и проверка `doctor`. Бюджет — рамка ТЗ ($25).

## Не входит
- Запуск команды на настоящем репозитории: это делает Оператор после
  мержа.
- Удаление `tasks/*` из main и правка ссылок на `tasks/<id>/` в
  документах: это коммит Оператора.
- Отмена наложения снимка на main: это задача A,
  01M4M67SGNEYMN9F1C7XVX24XE. Порядка мержа с ней ТЗ не задаёт.
- Изменение существующих снимков, в том числе шести файлов в четырёх
  задачах, где main новее снимка. Они только попадают в отчёт
  (требование 4).
- Правка путей, которые ТЗ называет только для чтения:
  `orchestrator/fsm_merge_gate.py`, `orchestrator/fsm_postmerge.py`,
  `orchestrator/retro.py`, `orchestrator/cleanup.py`,
  `orchestrator/artifact_branch.py`, `orchestrator/docs_fetch.py`,
  `orchestrator/store.py`, `orchestrator/config.py`,
  `orchestrator/catalog.py`, `scripts/`, `.github/workflows/ci.yml`,
  `tests/test_invariants.py`, `docs/invariants.md`, `docs/adr/`,
  `docs/roadmap.md`, `docs/backlog.md`, `docs/operator-session.md`,
  `templates/`, `skills/`, `CLAUDE.md`, `models.yaml`, `roles.yaml`,
  `targets.yaml`, `tasks/`, `docs/retro/`, `.artel/`.
- Смена ожиданий существующих тестов `tests/`. Требования такой смены не
  предполагают, поэтому раздела «Меняемое поведение» нет. Если она
  понадобится, то только через этот раздел (инвариант 38), а значит,
  эскалацией к Оператору, а не правкой теста.

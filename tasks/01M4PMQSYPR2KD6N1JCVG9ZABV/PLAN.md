# PLAN: Вердикт CI на verifying и гейте мержа — по прогонам ветки задачи

## Подход
Фильтр проверок по головной ветке прогона — в `orchestrator/ci.py`, общий
для обоих читателей статуса:
- `_other_branch(check, index, branch)` — ветка прогона проверки из поля
  `head_branch` индекса `actions/runs`, только если прогон найден и ветка
  непустая и не `branch`; иначе "" (проверка остаётся в вердикте —
  требование 2: индекс не получен, прогона нет, связи нет, `head_branch`
  пуст/отсутствует, ветка только под `headBranch`).
- `_branch_checks` делит проверки коммита на свои и исключённые;
  `_excluded_phrase` — фраза «; вне вердикта — проверки прогонов других
  веток: <имя>=<заключение> (ветка <x>, <событие>, прогон <id>)», без
  разбираемых подстрок (требование 5).
- `verifying_status`/`branch_status` строят индекс прогонов на любом исходе
  (раньше — лениво, только на не-зелёном): без него чужие проверки не
  отделить. Запрос по-прежнему пропускается, если ни у одной проверки нет
  связки с прогоном (`_commit_workflow_runs`), — `test_unlinked_…` не
  меняется. Дальше весь прежний разбор (идущие, зависшие, красные,
  `_unexecuted_full_suite`, расхождение по событиям) — только по своим
  проверкам; фраза об исключённых дописывается к первой строке каждого
  исхода.
- Своих проверок нет: `verifying_status` идёт прежним путём «коммит без
  проверок» (вынесен в `_no_checks_by_branch`: `gh run list` по ветке →
  `VERIFYING_RUNNING`, иначе `VERIFYING_NONE`); `branch_status` — `False`
  с текстом «… — статус неизвестен», `status_kind` → "unknown"
  (требование 3).
- Красный исход: `_inherited_from_main` берёт `head_sha("main")` и
  `failed_check_names` вершины, пересекает имена с упавшими своими;
  совпадение — фраза «; красный унаследован от main <sha8>: <имена>» в обоих
  читателях, в `verifying_status` ещё `PULL_MAIN_HINT` («подтянуть main в
  ветку задачи: artel.py pull-main <id задачи>»). Нет sha / `None` от
  `failed_check_names` / пересечения нет — фразы нет, исход красный
  (требование 4). Опрос main — только на красном исходе.

Бюджет SPEC (30) не пересматривается.

## Риски
- Прогон с `head_branch` ветки задачи, но от другого репозитория (форк)
  будет засчитан — для артели форков нет.
- Индекс читает одну страницу `actions/runs` (`CI_RUNS_PER_PAGE`): прогон
  за её пределами не найден → проверка остаётся в вердикте (как требует
  SPEC), то есть возможен прежний ложный красный, не ложный зелёный.

## Предложения системе
- `tests/test_main_ci_line.py::FixesMainArgTest` красен в шаге роли
  (`artel.py approve` отказывает процессу роли): тесты, зовущие
  `artel.main`, стоит изолировать от `ARTEL_ROLE` окружения, иначе прогон
  затронутых модулей в шаге роли даёт ложные провалы.
- `orchestrator/suite_run.py`: отчёт `--wait` зелёного полного набора
  печатает «прошло: 1» — похоже на счёт прогонов, а не тестов; лог прогона
  под `.artel/logs/` роли читать не дано, сверить нечем.

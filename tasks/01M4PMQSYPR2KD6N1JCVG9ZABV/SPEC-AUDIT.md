## Вердикт
`concerns` — SPEC можно вести дальше; все отклонения на вердикт CI не
влияют (красный остаётся красным, исключается только доказанно чужое) и
решаются Оператором на гейте. Прежние отклонения 1, 2, 5 этой версией
закрыты, 3 закрыто по форме (остаток — п.1 ниже), 4 снято вместе с
фразой (остаток — п.3 ниже).

1. SPEC требование 4 / AC-6 — `ci.head_sha("main")` читает локальную
   `refs/heads/main` (ci.py:93-97), не вершину origin, которую пульт сам
   читает фетчем (fsm.py:156-179); вызов без `repo` у внешнего target —
   main клона артели (ci.py:93-94). Решение: принять локальную ссылку как
   есть либо уточнить — `head_sha("main", **_repo_kwargs(repo))` или
   `gitcmd.remote_branch_sha`.
2. SPEC требование 4 — подсказка без подстановки id против буквы ТЗ п.4
   «`pull-main <id>`»; id выводим из имени ветки, но Оператор выбор не
   подтверждал.
3. ANSWER-1 п.2, «учесть двойной вызов `branch_status`»
   (fsm_merge_gate.py:286, 334) — в SPEC не отражено; последствие — два
   лишних опроса вершины main на красном гейте мержа и фраза в обеих
   записях flake-rate (fsm_merge_gate.py:296-299).
4. AC-1 — «исключённые называются в тексте» проверяется только на
   зелёном исходе; на красном/идущем мутация «не названы» не ловится.

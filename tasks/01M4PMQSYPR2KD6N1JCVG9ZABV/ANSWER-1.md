## Ответы

Решение Оператора 12.10.2026.

1. **A.** Разработчик меняет в
   `tests/test_01m46d5zzqy7gbew5tbvq0p3zv_ci_event.py`, строка ~173
   (`FakeGitHub.add_run`), литерал данных `"head_branch": "main"` на
   `"task/x"`; утверждения и остальные строки файла не меняются. Оформить
   отдельным требованием SPEC и фразой в «Не входит», НЕ пунктом раздела
   «Меняемое поведение» (там только литералы утверждений). Это не
   ослабление: сегодня `ci.py` поле `head_branch` не читает, все мутации
   AC1-AC8 того файла ловятся и после правки (независимая проверка
   12.10: гейт неослабления находок не даёт, методы и утверждения те же).
   Ревьюверу — сверить, что разница по файлу ровно одна строка.

2. Фраза «красный унаследован от main <sha>» — в красном тексте обоих
   читателей (`verifying_status` и `branch_status`). Подсказка
   `pull-main <id>` — только в `verifying_status`: гейт мержа подтягивает
   main сам (`fsm_merge_gate.py` ~671). Учесть, что на красном исходе
   гейта мержа `branch_status` зовётся дважды.

3. (пропущено в вопросах, найдено независимой проверкой) Существующий
   метод `tests/test_ci_status.py::RunEventLabelTest::test_green_outcome_does_not_ask_workflow_runs`
   утверждает, что зелёный исход не запрашивает `actions/runs`. По
   требованиям 2-3 ТЗ зелёному вердикту нужен индекс прогонов (ветка
   прогона есть только в нём). Разрешена замена утверждения
   `assertFalse([c for c in calls if "actions/runs" in c], calls)` на два
   утверждения «ровно один запрос `actions/runs` в каждом вызове
   статуса»: число вызовов `gh` запоминается после `verifying_status`, и
   запросы `actions/runs` считаются отдельно до этой границы и после неё
   (`branch_status`) — `assertEqual(..., 1, calls)` для каждой части.
   Утверждения о зелёном исходе обоих читателей остаются без изменений.
   Заявка «Ловит мутацию»: прогоны коммита запрашиваются повторно в одном
   вызове статуса, либо читатель статуса не строит индекс прогонов и не
   отсекает проверки других веток (ноль запросов в его вызове). Метод
   `tests/test_ci_status.py::RunEventLabelTest::test_unlinked_check_runs_do_not_ask_workflow_runs`
   мандатом не затронут и остаётся зелёным без правки. Внести в SPEC
   требованием с этой заменой.

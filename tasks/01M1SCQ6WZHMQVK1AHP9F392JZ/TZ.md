# ТЗ: регрессия №15 — рубеж «замечания ревью не отработаны» сверяется с коммитом ревьювера, а не с последним коммитом REVIEW.md

Источник: инцидент 05.09 на задаче P0 (01M1REVEZ1HESMJ7AFD5A9MEJ8) после
мержа регрессии №13. Рубеж `fsm_advance._review_rework_gate_refuses`
сравнивает время последнего коммита `tasks/<id>/REVIEW.md` в
артефактной ветке с временем последнего коммита developer в кодовой
ветке. Но последний коммит REVIEW.md — автокоммит артефактов ШАГА
DEVELOPER (developer правит леджер замечаний в REVIEW.md, T100), и он
всегда новее коммита кода того же шага. Итог: штатный шаг developer
после замечаний (журнал: `agent run finished`, коммит кода 02223977) не
засчитан, `advance` отказал «замечания ревью не отработаны: нет шага
developer после итерации 1», Оператор провёл задачу в review мостом.
Класс: каждая задача с замечаниями ревью упирается в этот рубеж.

Требуется:
1. Опорное время рубежа — коммит артефактной ветки, сделанный шагом
   РЕВЬЮВЕРА (автокоммит «артефакты шага reviewer» с вердиктом
   `changes_requested` текущей итерации), либо запись журнала `agent run
   finished` роли reviewer этой итерации — не последний коммит,
   тронувший REVIEW.md. Правка developer'ом леджера замечаний в REVIEW.md
   опорное время не сдвигает.
2. Рубеж пропускает переход, если после опорного времени есть коммит
   developer в кодовой ветке ИЛИ запись `agent run finished` роли
   developer в журнале после записи `state -> in_dev` этого визита
   (согласовано с проверкой `auto._role_ran_after_return`, один источник
   истины для обоих рубежей — вынести в общую функцию).
3. Отказ рубежа называет оба времени (опорное и последнего коммита
   developer) и источник опорного времени.
4. Тесты: сценарий инцидента — коммит кода, затем автокоммит шага
   developer, тронувший REVIEW.md, — переход проходит; сценарий
   «ревьювер вернул, developer не запускался» — отказ как раньше;
   существующие тесты №13 (`tests/test_auto_cycle.py`, планка
   01M1RHFRQ2C0P4A57XJJ1WZV8N) зелёные без ослабления.

Зоны: orchestrator/fsm_advance.py, orchestrator/auto.py, tests/.
Приоритет: критичный (бьёт по каждой задаче с замечаниями). Порядок:
код после мержа регрессии №14 (fsm_advance.py) и R1 (auto.py) либо с
мандатом; планка сразу. До мержа — мост Оператора после проверки
журнала (шаг developer после возврата был).

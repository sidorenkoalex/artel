# ТЗ: Команда пульта mutation-run: прогон патчей мутаций против названных тестов во временной копии и таблица исходов

# Команда пульта `mutation-run`: прогон патчей мутаций против названных тестовых файлов во временной копии и таблица «мутация → исход»

## Факты

Строка бэклога «Периодическая консолидация тестов артели» (доказательство неослабления — множество убиваемых мутаций; решение Оператора 23.10.2026) и ADR-0027 п. 8. Аудит SPEC волны сведения 1а (01M5NNDYGQ8G6VFDEEXYBB0W3D, 24.10.2026) показал, что прогон мутаций нельзя исполнить внутри шага роли: сторож роли в корневом `conftest.py` (`pytest_configure`) роняет рабочие процессы xdist под `ARTEL_ROLE` (воспроизведено: «node down», «no tests ran»); шагу доступны только рабочая копия и каталог документов; около 70 мутаций последовательно не укладываются в `AGENT_TIMEOUT_SEC` = 2700 с (`orchestrator/config.py:132`). Команды пульта для такого прогона нет. Решение сессии при Операторе по правам волны G 24.10.2026: сначала команда, затем волны. Сверено с origin/main bee11bcc; независимая проверка черновика 24.10.

- Образец — `suite-run` (`orchestrator/suite_run.py`): фоновый прогон `cmd_suite_run` (:858); окружение фонового процесса — `os.environ` без `config.ARTEL_ROLE_ENV` (:921–922; `acceptance._pytest_env` (`orchestrator/acceptance.py:71`) копирует окружение целиком и признак роли сам не снимает); лог — в каталоге хозяйства `suite-run` `suite_lock.directory()/<id>/` (`config.LOGS/suite-run`, `orchestrator/suite_lock.py:40`; единственный каталог пульта, открытый шагу роли на Codex на запись); временная рабочая копия клона на sha — `suite_run._base_copy` (:553; префикс `artel-suite-base-`, маркер `liveness.SUITE_OWNER_MARKER`; эти копии знают уборка сирот `doctor/orphans.py` и сторож зависших прогонов `doctor/hung_test_watchdog.py`); замок прогона на машине — `suite_lock.acquire/hand/adopt/release`, файл `config.LOGS/suite-run/lock.json`; гейты других задач ждут замок не дольше `FULL_SUITE_LOCK_WAIT_SEC` = 1800 с.
- Прогон набора файлов — `acceptance.run_full_suite(copy, targets=…, extra=…, log=…, limit=…)`: `-n config.FULL_SUITE_WORKERS -p xdist`, снятие группы процессов по пределу, вход в уже взятый замок. Предел — `project_profile.full_suite_limit(target)` (`orchestrator/project_profile.py:379`; профиль проекта, иначе `config` — 900 с, `config.py:223`).
- Разбор junit-xml — `parse_junit` (`orchestrator/reporters/outcome.py:145`): падение утверждения — `failed`; ошибка setup — `error`; ошибка сбора — запись уровня файла (`file_level=True`). Узлы — `<компонент>:<путь>::<имя>`.
- Документы задачи попадают в `refs/artifacts/<id>` автокоммитом успешного шага (`checkpoint.commit_step_artifacts`); до конца шага они лежат в каталоге документов на диске (`artifact_branch.docs_dir(id, target)`); чтение ссылки — `artifact_branch.ls_tree`, `show`, `read_tree`. Незакоммиченные файлы рабочей копии переносятся во временную копию приёмом `appendix_tree._carry_uncommitted`.
- Команда регистрируется в словаре `table` функции `artel.main` и строкой блока «Команды:» докстринга `orchestrator/artel.py` (проверяет `tests/test_01m5m0kqpv0fj9nsmdcq3xb76w_help_registry.py`); роль её получает через `_ROLE_ALLOWED_COMMANDS` (`artel.py:2181`); тесты списков команд полного набора не перечисляют.

## Требования

1. `artel.py mutation-run <id> --ref <base|head|worktree> --tests <путь>[,<путь>…] [--patches <a>-<b>] [--wait <минуты>]`. Патчи — файлы `mutation-<nnn>.diff` каталога документов задачи на диске; если каталога нет — из `refs/artifacts/<id>`; `--patches` — диапазон номеров (по умолчанию все). `--ref base` — база ветки задачи (`gitcmd.diff_base`), `head` — закоммиченная голова кодовой ветки, `worktree` — HEAD рабочей копии задачи плюс её незакоммиченные файлы (`appendix_tree._carry_uncommitted`; рабочая копия только читается). `--tests` — явные пути файлов под `tests/` (каталог `tests/` целиком, пустой список, путь вне `tests/` — отказ без запуска: полный набор этой командой не гоняется).
2. Прогон — фоном, как `suite-run` (`--wait` до 9 минут, отчёт повторным вызовом); окружение — без `config.ARTEL_ROLE_ENV`. Временная копия — через `suite_run._base_copy` (префикс и маркер владельца прежние), убирается на любом исходе. Перед патчами — контрольный прогон без патча: красный — отказ всей команды «тесты красные без мутаций». Для каждого патча по очереди: отказ патчу, который трогает `tests/`, `conftest.py` или пути из `--tests` (исход «патч трогает тесты»); `git apply` (отказ — исход «патч не применяется»); прогон через `acceptance.run_full_suite` с `--continue-on-collection-errors` и junit-xml вне копии, предел — остаток предела профиля; затем `git reset --hard HEAD && git clean -ffdx`, `git status --porcelain` пуст — иначе отказ всей команды.
3. Исход мутации: «убита» — есть хотя бы одна запись `failed` (список узлов); «ошибка сбора, импорта или setup» — нет `failed`, есть `error` или запись уровня файла (не доказательство); «не убита» — все записи `passed`/`skipped`; «итог неизвестен» — отчёта нет, он не разобран или пуст при ненулевом коде возврата (не «не убита», инвариант 41); «оборвана по пределу»; «патч не применяется»; «патч трогает тесты». Таблица — `<id>-mutation-run-<n>.mutations.tsv` рядом с логом `<id>-mutation-run-<n>.log` в `suite_lock.directory()/<id>/`; шапка — источник патчей, sha ссылки или «каталог на диске», sha ревизии прогона, sha256 каждого патча; строка — номер, исход, узлы через запятую; строка пишется после каждой мутации. Свои файлы состояния `mutation-run.json`, `mutation-result.json` — не `run.json` прогона `suite-run`. Документы задачи, ветка и рабочая копия не меняются.
4. Замок — `suite_lock` (держатель описывается как `suite-run` задачи — принимается); номер прогона в замке — с префиксом `m` (`"m3"`), чтобы `adopt()` не спутал его с прогоном `suite-run` той же задачи. Предел профиля не поднимается; набор патчей делится `--patches` на части, укладывающиеся в предел.
5. Команда разрешена роли (`_ROLE_ALLOWED_COMMANDS`), регистрируется в `table` и строкой блока «Команды:» докстринга. Таблица — свидетельство, не гейт: доказательство неослабления на гейте — прогон сессии при Операторе на зафиксированном наборе патчей (sha ссылки и sha256 в шапке).
6. Тесты (новый файл в `tests/`, в стиле pytest — ADR-0027; имена `test_ac<n>_…`; у каждой функции — «Ловит мутацию:»; без ожидания по часам — фоновая часть вызывается в процессе теста напрямую или ожидание помощниками `tests/sandbox.py`; `config.FULL_SUITE_WORKERS` = 2): (а) проект песочницы с модулем и тестом, два патча — один ломает функцию, другой меняет комментарий — первая «убита» с именем узла, вторая «не убита»; (б) синтаксическая ошибка в модуле — «ошибка сбора, импорта или setup»; (в) патч не применяется; патч трогает `tests/` — свои исходы; (г) красный контроль — отказ команды; (д) `--tests tests`, пустой список, путь вне `tests/` — отказ без запуска; (е) временная копия убрана после прогона и после исключения, рабочая копия задачи и главная копия не меняются; (ж) в проекте песочницы свой `conftest.py`-сторож, роняющий процессы под `ARTEL_ROLE`; вызывающий процесс с `ARTEL_ROLE=developer` — прогон с xdist проходит; (з) обрыв по пределу (подмена прогона второго патча исходом «предел») — таблица содержит строку первой мутации и «оборвана по пределу»; (и) `--ref worktree` видит незакоммиченный тестовый файл рабочей копии; (к) `--patches 2-2` прогоняет только второй патч; шапка таблицы несёт sha256 патчей.
7. Существующие тесты не правятся и остаются зелёными.

Зоны: orchestrator/mutation_run.py, orchestrator/artel.py, docs/codebase-map.md, tests/

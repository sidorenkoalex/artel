## Пути обхода гейтов
- О-6 (мелкое). Перечень «трогает тесты» (требование 6) закрыт:
  `conftest.py`, `pyproject.toml`, `pytest.ini`, `setup.cfg`, `tox.ini`.
  pytest читает и иные файлы конфигурации (скрытый `.pytest.ini`, в новых
  версиях — `pytest.toml`), а также подхватывает `sitecustomize.py`/`*.pth`
  интерпретатора. Патч на такой файл (например, `addopts` с
  `-W error`) красит тесты без изменения кода — ложное «убита», то есть
  раздутое множество убиваемых мутаций — ровно то, что доказательство
  неослабления должно не допускать. Также не названы заголовки
  `copy from/copy to` (требование 6 говорит только о переименовании).
  Смягчение: таблица — свидетельство, не гейт (требование 12), доказательство
  на гейте — прогон сессии при Операторе. Предложение: определять пути
  патча по `git apply --numstat -z`/`--summary` (все пути, включая copy/rename)
  и проверять базовое имя по перечню, дополненному `.pytest.ini`,
  `pytest.toml`.
- О-7 (мелкое, формулировка). Требование 1: «путь нормализуется относительно
  корня копии», а AC-5 требует отказа до замка и до копии. Буквальное
  исполнение «проверять в копии» нарушает AC-5; проверка существования должна
  идти по дереву ревизии (`ls-tree` на sha `base`/`head`; для `worktree` — диск
  рабочей копии с незакоммиченными). Иначе возможна проверка по диску рабочей
  копии при `--ref base`: файл есть на диске, но нет в базе → контроль «тестов
  нет» вместо отказа без запуска.
- Иных путей обхода не найдено: контроль красный отсекает прогон под сторожем
  роли без снятия признака (все рабочие упадут на контроле); «итог неизвестен»
  не засчитывается в «не убита»; предел профиля на всю команду не даёт держать
  замок дольше 900 с.

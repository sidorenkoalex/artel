# SPEC: команда пульта `mutation-run` — прогон патчей мутаций против названных тестовых файлов во временной копии и таблица «мутация → исход»

## Контекст
Доказательство неослабления при консолидации тестов артели — множество
убиваемых мутаций (строка бэклога «Периодическая консолидация тестов
артели», решение Оператора 23.10.2026; ADR-0027 п. 8). Внутри шага роли
прогон мутаций не исполним: сторож роли в корневом `conftest.py`
(`pytest_configure`) роняет рабочие процессы xdist под `ARTEL_ROLE`
(«node down», «no tests ran»). Шагу доступны только рабочая копия и
каталог документов. Около 70 мутаций последовательно не укладываются в
`AGENT_TIMEOUT_SEC` = 2700 с (`orchestrator/config.py:132`). Команды
пульта для такого прогона нет. Задача добавляет её по образцу `suite-run`
(`orchestrator/suite_run.py`): фоновый прогон, окружение без признака
роли, временная копия клона, замок `suite_lock`, лог и таблица исходов
в каталоге хозяйства `suite-run`.

## Требования

1. Команда `artel.py mutation-run <id> --ref <base|head|worktree> --tests <путь>[,<путь>…] [--patches <a>-<b>] [--wait <минуты>]`.
   - Патчи — файлы `mutation-<nnn>.diff` каталога документов задачи на
     диске (`artifact_branch.docs_dir(id, target)`). Если этого каталога
     нет, патчи берутся из `refs/artifacts/<id>`.
   - `--patches` задаёт диапазон номеров; по умолчанию прогоняются все
     патчи.
   - `--ref base` — база ветки задачи (`gitcmd.diff_base`).
   - `--ref head` — закоммиченная голова кодовой ветки задачи.
   - `--ref worktree` — HEAD рабочей копии задачи плюс её незакоммиченные
     файлы (приём `appendix_tree._carry_uncommitted`). Рабочая копия при
     этом только читается.
   - `--tests` — явные пути файлов под `tests/`. Каталог `tests/` целиком,
     пустой список или путь вне `tests/` — отказ без запуска: полный набор
     этой командой не гоняется.
2. Прогон идёт фоном, как у `suite-run`: `--wait` — не больше 9 минут,
   отчёт — повторным вызовом команды. Окружение фонового прогона не
   содержит `config.ARTEL_ROLE_ENV`.
3. Временная копия создаётся через `suite_run._base_copy` (префикс
   `artel-suite-base-` и маркер владельца `liveness.SUITE_OWNER_MARKER`
   прежние). Она убирается на любом исходе, в том числе при исключении.
4. Перед патчами выполняется контрольный прогон названных тестов без
   патча. Если он красный, вся команда отказывает с текстом «тесты красные
   без мутаций».
5. Патчи прогоняются по очереди. Для каждого патча:
   - Патч, который трогает `tests/`, `conftest.py` или пути из `--tests`,
     не применяется; его исход — «патч трогает тесты».
   - Иначе патч применяется `git apply`. При отказе исход — «патч не
     применяется».
   - Применённый патч прогоняется через `acceptance.run_full_suite` с
     `--continue-on-collection-errors` и junit-xml вне копии. Предел
     прогона — остаток предела профиля
     (`project_profile.full_suite_limit(target)`).
   - После прогона выполняются `git reset --hard HEAD && git clean -ffdx`.
     Если затем `git status --porcelain` не пуст, вся команда отказывает.
6. Исход мутации определяется по разбору junit-xml (`reporters/outcome.parse_junit`):
   - «убита» — есть хотя бы одна запись `failed`; к исходу прилагается
     список таких узлов;
   - «ошибка сбора, импорта или setup» — записей `failed` нет, но есть
     `error` или запись уровня файла. Этот исход не считается
     доказательством;
   - «не убита» — все записи `passed`/`skipped`;
   - «итог неизвестен» — отчёта нет, он не разобран или пуст при
     ненулевом коде возврата. Такой исход никогда не засчитывается как «не
     убита» (инвариант 41);
   - «оборвана по пределу»;
   - «патч не применяется»;
   - «патч трогает тесты».
7. Таблица исходов — файл `<id>-mutation-run-<n>.mutations.tsv` рядом с
   логом `<id>-mutation-run-<n>.log` в `suite_lock.directory()/<id>/`.
   - Шапка таблицы несёт источник патчей, sha ссылки документов (или
     «каталог на диске»), sha ревизии прогона и sha256 каждого патча.
   - Строка таблицы — номер патча, исход и узлы через запятую.
   - Строка пишется сразу после каждой мутации.
8. У команды свои файлы состояния — `mutation-run.json` и
   `mutation-result.json`. Файл `run.json` прогона `suite-run` она не
   использует. Документы задачи, её ветка и рабочая копия командой не
   меняются.
9. Команда берёт замок `suite_lock`; держатель описывается как `suite-run`
   задачи, это принимается. Номер прогона в замке несёт префикс `m`
   (например `"m3"`), чтобы `suite_lock.adopt()` не спутал его с прогоном
   `suite-run` той же задачи. Предел профиля не поднимается: набор патчей,
   не укладывающийся в предел, делится на части аргументом `--patches`.
10. Команда разрешена роли (`_ROLE_ALLOWED_COMMANDS`,
    `orchestrator/artel.py:2181`). Она регистрируется в словаре `table`
    функции `artel.main` и строкой блока «Команды:» докстринга
    `orchestrator/artel.py`. Таблица — свидетельство, не гейт: никакой
    гейт пульта её не читает.
11. Тесты команды лежат в новом файле `tests/`, написанном в стиле pytest
    (ADR-0027):
    - имена функций — `test_ac<n>_…`;
    - у каждой функции есть строка «Ловит мутацию:»;
    - нет ожидания по часам: фоновая часть вызывается в процессе теста
      напрямую, либо ожидание идёт помощниками `tests/sandbox.py`;
    - `config.FULL_SUITE_WORKERS` = 2.

## Критерии приёмки

AC-1. В проекте песочницы с модулем и тестом прогоняются два патча: первый ломает функцию модуля, второй меняет только комментарий. В таблице у первого стоит исход «убита» с именем упавшего узла, у второго — «не убита».

AC-2. Патч, вносящий синтаксическую ошибку в модуль, получает исход «ошибка сбора, импорта или setup», а не «убита» и не «не убита».

AC-3. Патч, который не применяется `git apply`, получает исход «патч не применяется». Патч, который трогает файл под `tests/`, получает исход «патч трогает тесты» и не применяется.

AC-4. Если контрольный прогон без патча красный, команда отказывает целиком с текстом «тесты красные без мутаций», и ни один патч не прогоняется.

AC-5. `--tests tests`, пустой список `--tests` и путь вне `tests/` — каждый вызов отказывает без запуска прогона: временная копия не создаётся, замок не берётся.

AC-6. После прогона временная копия `artel-suite-base-…` убрана. Она убрана и после исключения посреди прогона. Рабочая копия задачи и главная копия после команды не изменились: `git status --porcelain` и HEAD те же, что до вызова.

AC-7. В проекте песочницы лежит свой `conftest.py`-сторож, роняющий процессы под `ARTEL_ROLE`. Команда вызывается процессом с `ARTEL_ROLE=developer` — прогон с xdist (`config.FULL_SUITE_WORKERS` = 2) проходит, и исходы мутаций получены.

AC-8. Прогон второго патча подменён исходом «предел». Таблица содержит строку первой мутации с её исходом и строку второй с исходом «оборвана по пределу».

AC-9. С `--ref worktree` прогон видит незакоммиченный тестовый файл рабочей копии задачи: тест, названный в `--tests`, существует только незакоммиченным и прогоняется.

AC-10. `--patches 2-2` прогоняет только второй патч: в таблице одна строка, с номером 2.

AC-11. Шапка таблицы `<id>-mutation-run-<n>.mutations.tsv` несёт sha256 каждого прогнанного патча, источник патчей, sha ссылки (или «каталог на диске») и sha ревизии прогона. Таблица лежит рядом с логом `<id>-mutation-run-<n>.log` в `suite_lock.directory()/<id>/`.

AC-12. Отчёт junit-xml отсутствует, не разобран или пуст при ненулевом коде возврата — исход мутации «итог неизвестен», не «не убита».

AC-13. Номер прогона `mutation-run`, записанный в замке `suite_lock`, несёт префикс `m`. Команда пишет свои файлы состояния `mutation-run.json`/`mutation-result.json` и не создаёт и не меняет `run.json` прогона `suite-run` той же задачи.

AC-14. `mutation-run` значится в словаре `table` функции `artel.main`, в строке блока «Команды:» докстринга `orchestrator/artel.py` и в `_ROLE_ALLOWED_COMMANDS`.

## Оценка объёма и деление
Сработавшие сигналы:
- число критериев приёмки ≥ 10 — их 14;
- зона, возможно, задевает механизм, на который опирается запись
  `docs/invariants.md`: запись 41 — «итог неизвестен» не равен «не убита»;
  команда потребляет этот механизм, сам механизм не меняется.

Предлагаемое решение — монолит. Что нельзя разрезать:
- Весь код задачи — один новый модуль `orchestrator/mutation_run.py`
  плюс три строки регистрации в `orchestrator/artel.py`. Регистрация без
  модуля указывает на несуществующую команду, а модуль без регистрации
  недостижим из CLI и из роли.
- Тесты по ТЗ лежат новым файлом `tests/` и проверяют поведение этого же
  модуля. Тесты без модуля красные, модуль без тестов не проходит
  приёмку.
- Части фонового прогона связаны по данным: разбор аргументов, копия на
  ref, контроль, цикл патчей с откатом, таблица и замок пишут общие файлы
  состояния и таблицу. Ни один из этих кусков сам по себе не даёт
  работающей команды.

Решение принимает Оператор на гейте SPEC.

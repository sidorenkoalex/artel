# PLAN: команда пульта `mutation-run` — прогон патчей мутаций против названных тестовых файлов во временной копии и таблица «мутация → исход»

## Подход
Новый модуль `orchestrator/mutation_run.py` по образцу `suite_run.py`;
из образца переиспользуются как есть (без правки «только чтение»
модулей): `suite_run._base_copy` (временная копия, префикс и маркер
владельца прежние), `suite_run._profile_command`, `_db`, `_read_json`,
`_write_json`, `_alive`; `appendix_tree._carry_uncommitted`;
`acceptance.run_full_suite`/`full_suite_outcome`;
`reporters/outcome.parse_junit`; `suite_lock.acquire/hand/adopt/release`.

- Передний план (`cmd_mutation_run`): разбор аргументов → профиль
  (только раннер пульта: не multi, `runner` = `pult-pytest`,
  `_profile_command` даёт список команды, иначе «профиль проекта не
  поддержан командой mutation-run») → набор патчей (каталог документов
  на диске, иначе коммит `refs/artifacts/<id>`; пустой — «патчей мутаций
  нет») → `--patches` → sha ревизии (`base` — `gitcmd.diff_base`, `head` —
  голова ветки в клоне, `worktree` — HEAD рабочей копии) → `--tests` по
  дереву ревизии (`ls-tree`; для `worktree` — `ls-files --cached --others
  --exclude-standard` + файл на диске). Всё это — до замка и копии.
  Затем `suite_lock.acquire` без ожидания (занят — отказ с держателем),
  лог `<id>-mutation-run-<n>.log`, `hand` с номером `m<n>`, фоновый
  `Popen` с окружением без `ARTEL_ROLE`, `mutation-run.json`; `--wait` —
  тем же вызовом или `mutation-run <id> --wait N`.
- Фон (`background`): `adopt` замка `m<n>`, копия на sha, перенос
  незакоммиченных (`worktree`), коммит-основа в копии (своя
  идентичность, хуки отключены, `--allow-empty`), шапка таблицы
  (источник, sha ссылки, sha ревизии, sha256 каждого патча), контроль,
  цикл патчей: «трогает тесты» по всем путям патча (оба пути
  rename/copy) → `git apply` → прогон с `-vv
  --continue-on-collection-errors --junitxml=<вне копии>` → исход →
  строка таблицы → `git reset --hard <основа>` + `git clean -ffdx` +
  проверка `git status --porcelain`. Предел профиля — на всю команду:
  каждому прогону остаток от старта (`ceil`), обрыв — «оборвана по
  пределу», дальше — «не прогнана (предел)». Отчёт в
  `mutation-result.json` на любом исходе, замок и временный каталог
  отчётов снимаются в `finally`, копия — контекстом `_base_copy`.
- Исход (`classify`): `failed` не уровня файла → «убита» с узлами;
  `error`/уровень файла → «ошибка сбора, импорта или setup»; отчёта нет /
  не разобран / пуст / ненулевой код без падений → «итог неизвестен»;
  иначе «не убита». Контроль зелёный только при «не убита».

Бюджет SPEC (45) не пересматривается: один модуль и строки регистрации.

## Влияние на систему
- Белый список роли пополнен одной командой; список остаётся закрытым по
  умолчанию. Команда пишет только в каталог хозяйства `suite-run`
  (лог, прогонные логи `-control`/`-pNNN`, таблица, `mutation-run.json`,
  `mutation-result.json`, `mutation-background.log`) и во временную копию
  клона; БД только читает (`suite_run._db` с откатом на `mode=ro`).
- Сторож роли в `conftest.py` не тронут: признак роли снимается только
  в окружении фонового процесса команды.
- Замок `suite_lock` общий: прогон держит его не дольше предела профиля
  на всю команду (предел не поднимается), гейты ждут его как прежде.
- Инвариант 40: коммит-основа делается только в отсоединённой временной
  копии клона проекта, ветки/ссылки/HEAD главной копии и рабочей копии
  задачи не меняются (AC-6). Инвариант 41: «итог неизвестен» никогда не
  «не убита» (AC-12, AC-4).
- Ни один существующий тест, гейт, лимит не меняется. Откат — revert
  merge-коммита: модуль новый, правка `artel.py` — только регистрация.

## Риски
- Разбор путей патча свой (заголовки `diff --git`, `---`/`+++`,
  rename/copy): кавыченные пути с экранированием разбираются
  упрощённо; при сомнении правило шире (имена конфигов pytest — в любом
  каталоге), то есть патч скорее отклоняется, чем прогоняется.
- Фоновый процесс после конца отдаёт замок раньше, чем передний план
  перепишет его на pid фона (тот же порядок, что у `suite-run`): в замке
  остаётся мёртвый pid, `acquire` снимает такой замок как брошенный.

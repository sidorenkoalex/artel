# SPEC: `mutation-run` — ожидание свободного замка машины (`--wait-lock`) и копия таблицы исходов в каталоге документов задачи (`--copy-table`)

## Контекст
`mutation-run` при занятом замке полных прогонов машины отказывает сразу
(`orchestrator/mutation_run.py:791–795`, `suite_lock.acquire(task_id, None)`),
ожидания свободного замка нет. Роли волн сведения тестов (01M5PCB66D,
01M5PHK9K0) обходили это временными сценариями повтора в рабочей копии и
такими же сценариями переносили таблицу исходов из `.artel/logs/suite-run/`
(роли на Claude закрыт) в документы задачи — оба раза пульт останавливал
цикл отказом «посторонние файлы». Отчёт `--wait` уже печатает таблицу
(01M5P2BHX6), копии таблицы в каталоге документов задачи
(`artifact_branch.docs_dir(id, target)`, открыт роли) нет. Задача даёт
команде штатное ожидание замка и штатную копию таблицы по явному флагу
`--copy-table` (ANSWER-1, п. 1: без флага каталог документов, как и сейчас,
не меняется).

Копия таблицы — справочная (ANSWER-1, п. 4): она лежит в каталоге, открытом
роли на запись, и автокоммитом шага уходит в `refs/artifacts/<id>`, поэтому
доказательством исходов мутаций не является. Доказательство исходов —
основная таблица в `.artel/logs/suite-run/` (`_table_path`) и отчёт
`--wait`.

Задача сужает требование 10 SPEC 01M5NPKPWFEWTYMBYWVR797AM6 («документы,
ветку и рабочую копию задачи не меняет»): с флагом `--copy-table` команда
пишет в каталог документов задачи на диске один файл —
`mutation-run-<n>.tsv`; ссылку документов, ветку и рабочую копию
по-прежнему не меняет (ANSWER-1, п. 2).

## Требования

1. Флаг `--wait-lock <минуты>` команды `mutation-run`: значение — целое от
   0 до `config.SUITE_RUN_MAX_WAIT_MIN` включительно; без флага — 0, то есть
   прежнее поведение (отказ сразу при занятом замке, прежний текст).
2. При `--wait-lock N` (N > 0) и занятом замке команда печатает одну строку
   о начале ожидания с держателем замка и ждёт его освобождения не дольше N
   минут, проверяя замок не чаще одного раза в 10 с. Замок освободился в
   срок — прогон стартует как обычно. Срок вышел — прежний отказ с
   держателем и словами «ожидание N мин истекло».
3. Замок освободился, но взять его не удалось (его успел взять другой
   прогон), а срок `--wait-lock` не вышел — ожидание продолжается до срока с
   тем же шагом опроса; отказ — только когда срок вышел (ANSWER-1, п. 5).
4. Ожидание не берёт замок и не создаёт файлов прогона (журнал, таблица,
   файл прогона). Прерывание ожидания SIGINT (`KeyboardInterrupt`) — выход
   без прогона и без файлов прогона, замок не взят. Обработчик SIGTERM не
   ставится: SIGTERM держится поведением Python по умолчанию (ANSWER-1, п. 6).
5. Неверное значение `--wait-lock` (флаг без значения, отрицательное число,
   больше `config.SUITE_RUN_MAX_WAIT_MIN`, не целое) — отказ без запуска
   прогона с указанием формата.
6. Сумма значений `--wait-lock` и `--wait` в одном вызове не больше
   `config.SUITE_RUN_MAX_WAIT_MIN`; больше — отказ без запуска прогона с
   указанием предела (ANSWER-1, п. 3).
7. Флаг `--copy-table` (без значения). С ним после записи шапки и после
   каждой записанной строки основной таблицы (`_table_path(task_id, run_no)`)
   команда обновляет файл `mutation-run-<n>.tsv` (n — номер прогона) первого
   уровня каталога документов задачи на диске
   (`artifact_branch.docs_dir(id, target)`), побайтно равный основной
   таблице на этот момент — в том числе у прогона, оборванного по пределу.
8. Без флага `--copy-table` каталог документов задачи командой не меняется
   (как сейчас).
9. С флагом `--copy-table`, но без каталога документов задачи на диске —
   копия не пишется, прогон не падает, отчёт `--wait` говорит об этом одной
   строкой.
10. Ссылка `refs/artifacts/<id>`, ветка задачи и её рабочая копия командой
    не меняются (копия пишется только файлом на диске).
11. Отчёт `--wait` и повторный вызов отчёта после конца прогона, запущенного
    с `--copy-table`, дополнительно печатают путь копии таблицы.
12. Разбор прочих аргументов, исходы мутаций, основная таблица, замок
    машины и пределы не меняются; `scripts/guard.py` не меняется — имя
    `mutation-run-<n>.tsv` уже не посторонний файл первого уровня
    `tasks/<id>/`.
13. Строка блока «Команды:» докстринга `orchestrator/artel.py` и справка
    команды (`USAGE` модуля `orchestrator/mutation_run.py`) называют
    `--wait-lock` и `--copy-table`.
14. Комментарий к `_ROLE_ALLOWED_COMMANDS` (`orchestrator/artel.py:2185–2188`)
    говорит, что `mutation-run` с флагом `--copy-table` пишет копию таблицы
    исходов в каталог документов задачи, а ссылку документов, ветку и
    рабочую копию задачи не меняет, и называет сужение требования 10 SPEC
    01M5NPKPWFEWTYMBYWVR797AM6 этой задачей (ANSWER-1, п. 2).
15. Тесты — новый файл в `tests/`, в стиле pytest (ADR-0027), у каждой
    тестовой функции — «Ловит мутацию:»; без ожидания по часам: время и сон
    подменяются, фоновая часть команды вызывается в процессе теста.
    Тесты копии таблицы вызывают команду с `--copy-table`. Существующие
    тесты не правятся.

## Критерии приёмки

AC-1. Замок машины занят чужим прогоном и освобождается до истечения
`--wait-lock N`: команда печатает строку о начале ожидания с держателем
замка, затем прогон стартует как обычно.

AC-2. Замок занят весь срок `--wait-lock N`: команда завершается отказом,
текст которого называет держателя замка и содержит «ожидание N мин
истекло»; файлов прогона (журнал, таблица, файл прогона) не создано.

AC-3. Во время ожидания замок проверяется не чаще одного раза в 10 с (по
подменённым часам/сну): между соседними проверками проходит не меньше 10 с.

AC-4. Взятие замка (подменённый `acquire`) один раз отказывает после того,
как замок стал свободен, затем удаётся, срок не вышел: команда не
отказывает, ожидание продолжается, прогон стартует.

AC-5. Во время ожидания замок командой не берётся и файлов прогона не
создаётся; прерывание ожидания SIGINT (`KeyboardInterrupt` из подменённого
сна) завершает команду без прогона и без файлов прогона, замок не взят.

AC-6. Отказ без запуска прогона: `--wait-lock` без значения, с
отрицательным значением, со значением больше
`config.SUITE_RUN_MAX_WAIT_MIN`, с нецелым значением — текст отказа
указывает формат; сумма `--wait-lock` и `--wait` больше
`config.SUITE_RUN_MAX_WAIT_MIN` — текст отказа указывает предел.

AC-7. Без `--wait-lock` при занятом замке — отказ сразу, без ожидания, с
прежним текстом («отказ — на машине уже идёт прогон … повтори после его
конца»).

AC-8. После завершённого прогона с `--copy-table` в каталоге документов
задачи на диске есть файл первого уровня `mutation-run-<n>.tsv` (n — номер
прогона), побайтно равный основной таблице прогона.

AC-9. У прогона с `--copy-table`, оборванного по пределу, копия
`mutation-run-<n>.tsv` побайтно равна основной таблице и содержит строки,
записанные до обрыва.

AC-10. Прогон с `--copy-table` без каталога документов задачи на диске:
копия не создаётся, прогон завершается без падения, отчёт `--wait`
сообщает об отсутствии копии одной строкой.

AC-11. Прогон без `--copy-table`: имена и байты файлов каталога документов
задачи после прогона те же, что до него; файла `mutation-run-<n>.tsv` в
нём нет.

AC-12. Прогон с `--copy-table` не меняет `refs/artifacts/<id>`, ветку
задачи и её рабочую копию (sha ссылки и ветки, состояние рабочей копии до
и после равны).

AC-13. Отчёт `--wait` и повторный вызов отчёта после конца прогона,
запущенного с `--copy-table`, печатают путь копии таблицы
`mutation-run-<n>.tsv`.

AC-14. `guard.is_extraneous_task_root_file("mutation-run-3.tsv")`
возвращает ложь.

AC-15. Строка блока «Команды:» докстринга `orchestrator/artel.py` и `USAGE`
модуля `orchestrator/mutation_run.py` содержат `--wait-lock` и
`--copy-table`.

## Оценка объёма и деление
Сработавшие сигналы: число критериев приёмки ≥ 10 (15); `budget_usd` ≥ $30
($35 — бюджет из ТЗ, ниже ориентира калибровки ~45 для класса «до 15
критериев, до 7 файлов»).

Материал для решения Оператора — обоснование монолита: вся механика обеих
частей (ожидание замка и копия таблицы) живёт в одном файле зоны
`orchestrator/mutation_run.py`; прочие зоны — строки докстринга и
комментарий `orchestrator/artel.py`, регенерация карты и новый файл тестов.
Нарезка по границам зон невозможна: каждой из двух частей нужен свой кусок
того же файла, деление разрезало бы зону поперёк, а две подзадачи с одной
зоной шли бы строго последовательно через замок зоны, удваивая шаги
analyst/аудита/ревью без выигрыша. Объём диффа мал (один модуль плюс тесты).

# SPEC: `mutation-run` — ожидание свободного замка машины (`--wait-lock`) и копия таблицы исходов в каталоге документов задачи

## Контекст
`mutation-run` при занятом замке полных прогонов машины отказывает сразу
(`orchestrator/mutation_run.py:791–795`, `suite_lock.acquire(task_id, None)`),
ожидания свободного замка нет. Роли волн сведения тестов (01M5PCB66D,
01M5PHK9K0) обходили это временными сценариями повтора в рабочей копии
и переносили таблицу исходов из `.artel/logs/suite-run/` (роли на Claude
закрыт) в документы задачи такими же сценариями — оба раза пульт
останавливал цикл отказом «посторонние файлы». Отчёт `--wait` уже печатает
таблицу (01M5P2BHX6), но копии таблицы в каталоге документов задачи
(`artifact_branch.docs_dir(id, target)`, открыт роли) нет. Задача даёт
команде штатное ожидание замка и штатную копию таблицы.

## Требования

1. Флаг `--wait-lock <минуты>` команды `mutation-run`: значение — целое от
   0 до `config.SUITE_RUN_MAX_WAIT_MIN` включительно; без флага — 0, то есть
   прежнее поведение (отказ сразу при занятом замке).
2. При `--wait-lock N` (N > 0) и занятом замке команда печатает одну строку
   о начале ожидания с держателем замка и ждёт его освобождения не дольше N
   минут, проверяя замок не чаще одного раза в 10 с. Замок освободился в
   срок — прогон стартует как обычно. Срок вышел — прежний отказ с
   держателем и словами «ожидание N мин истекло».
3. Ожидание не берёт замок и не создаёт файлов прогона (журнал, таблица,
   файл прогона). Прерывание ожидания сигналом SIGINT или SIGTERM — выход
   без прогона и без файлов прогона.
4. Неверное значение `--wait-lock` (флаг без значения, отрицательное число,
   больше `config.SUITE_RUN_MAX_WAIT_MIN`, не целое) — отказ без запуска
   прогона с указанием формата.
5. Копия таблицы: после записи шапки и после каждой записанной строки
   основной таблицы (`_table_path(task_id, run_no)`) команда обновляет файл
   `mutation-run-<n>.tsv` (n — номер прогона) первого уровня каталога
   документов задачи на диске (`artifact_branch.docs_dir(id, target)`),
   побайтно равный основной таблице на этот момент — в том числе у прогона,
   оборванного по пределу.
6. Нет каталога документов задачи на диске — копия не пишется, прогон не
   падает, отчёт `--wait` говорит об этом одной строкой.
7. Ссылка `refs/artifacts/<id>`, ветка задачи и её рабочая копия командой
   не меняются (копия пишется только файлом на диске).
8. Отчёт `--wait` и повторный вызов отчёта после конца прогона
   дополнительно печатают путь копии таблицы.
9. Разбор прочих аргументов, исходы мутаций, основная таблица, замок
   машины и пределы не меняются; `scripts/guard.py` не меняется — имя
   `mutation-run-<n>.tsv` уже не посторонний файл первого уровня
   `tasks/<id>/`.
10. Строка блока «Команды:» докстринга `orchestrator/artel.py` и справка
    команды (`USAGE` модуля `orchestrator/mutation_run.py`) называют
    `--wait-lock`.
11. Тесты — новый файл в `tests/`, в стиле pytest (ADR-0027), у каждой
    тестовой функции — «Ловит мутацию:»; без ожидания по часам: время и сон
    подменяются, фоновая часть команды вызывается в процессе теста.
    Существующие тесты не правятся.

## Критерии приёмки

AC-1. Замок машины занят чужим прогоном и освобождается до истечения
`--wait-lock N`: команда печатает строку о начале ожидания с держателем
замка, затем прогон стартует как обычно.

AC-2. Замок занят весь срок `--wait-lock N`: команда завершается отказом,
текст которого называет держателя замка и содержит «ожидание N мин
истекло»; файлов прогона (журнал, таблица, файл прогона) не создано.

AC-3. Во время ожидания замок проверяется не чаще одного раза в 10 с
(по подменённым часам/сну): между соседними проверками проходит не меньше
10 с.

AC-4. Во время ожидания замок командой не берётся и файлов прогона не
создаётся; прерывание ожидания SIGINT или SIGTERM завершает команду без
прогона и без файлов прогона.

AC-5. `--wait-lock` без значения, с отрицательным значением, со значением
больше `config.SUITE_RUN_MAX_WAIT_MIN` и с нецелым значением — отказ без
запуска прогона, текст отказа указывает формат.

AC-6. Без `--wait-lock` при занятом замке — отказ сразу, без ожидания, с
прежним текстом («отказ — на машине уже идёт прогон … повтори после его
конца»).

AC-7. После завершённого прогона в каталоге документов задачи на диске
есть файл первого уровня `mutation-run-<n>.tsv` (n — номер прогона),
побайтно равный основной таблице прогона.

AC-8. У прогона, оборванного по пределу, копия `mutation-run-<n>.tsv`
побайтно равна основной таблице и содержит строки, записанные до обрыва.

AC-9. Каталога документов задачи на диске нет: копия не создаётся, прогон
завершается без падения, отчёт `--wait` сообщает об отсутствии копии одной
строкой.

AC-10. Прогон с записью копии не меняет `refs/artifacts/<id>`, ветку задачи
и её рабочую копию (sha ссылки и ветки, состояние рабочей копии до и после
равны).

AC-11. Отчёт `--wait` и повторный вызов отчёта после конца прогона печатают
путь копии таблицы `mutation-run-<n>.tsv`.

AC-12. `guard.is_extraneous_task_root_file("mutation-run-3.tsv")` возвращает
ложь.

AC-13. Строка блока «Команды:» докстринга `orchestrator/artel.py` и
`USAGE` модуля `orchestrator/mutation_run.py` содержат `--wait-lock`.

## Оценка объёма и деление
Сработавшие сигналы: число критериев приёмки ≥ 10 (13); `budget_usd` ≥ $30
($35 — бюджет из ТЗ, ниже ориентира калибровки ~45 для класса «до 15
критериев, до 7 файлов»).

Материал для решения Оператора — обоснование монолита: вся механика обеих
частей (ожидание замка и копия таблицы) живёт в одном файле зоны
`orchestrator/mutation_run.py`; прочие зоны — строка докстринга
`orchestrator/artel.py`, регенерация карты и новый файл тестов. Нарезка по
границам зон невозможна: каждой из двух частей нужен свой кусок того же
файла, деление разрезало бы зону поперёк, а две подзадачи с одной зоной
шли бы строго последовательно через замок зоны, удваивая шаги analyst/
аудита/ревью без выигрыша. Объём диффа мал (один модуль плюс тесты).

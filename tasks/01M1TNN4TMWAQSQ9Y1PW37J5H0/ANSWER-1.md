Белый список AC-1 действует для файлов `*.md` первого уровня
`tasks/<id>/`: допустимы только `SPEC.md`, `PLAN.md`, `REVIEW.md`,
`TEST_REPORT.md`, `QUESTIONS.md`, `TZ.md`, `ANSWER-<n>.md`; любой другой
`*.md` — «посторонний файл в каталоге задачи» (это и есть класс инцидента
06.09: копии карты кодовой базы `_head_map.md` и подобные, guard
краснеет на них из-за отсутствия frontmatter). Файлы с любым другим
расширением на первом уровне (`*.patch`, `*.png`, `*.bin`, `*.html`,
`*.txt` и прочие) — вложения: допускаются без ограничений имени, как
требуют залоченные `tests/test_checkpoint_external_step_artifacts.py::
test_binary_file_is_not_lost` и `::test_all_files_binary_still_commits_and_clears_the_dir`.
Каталог `acceptance_tests/` — по своим правилам (01M1SAA01Y). Скрытые
файлы и каталоги (`.`-префикс) и `__pycache__/` — посторонние.

Следствия для критериев: AC-1/AC-2 — «посторонний файл» = `*.md` вне
списка, скрытый файл/каталог, `__pycache__/`; вложения не-`.md`
проходят молча. AC-3 (`mockup.html`) снимается: файл становится
законным вложением, отдельного решения в PLAN не требуется. AC-4/AC-5
(автокоммит) — тот же критерий: `.md` вне списка не коммитится и
журналируется, вложения коммитятся как сегодня. AC-9 — существующие
тесты про бинарные вложения остаются зелёными без правки. Планка
пишется по этой формулировке; правка залоченных тестов (вариант B) не

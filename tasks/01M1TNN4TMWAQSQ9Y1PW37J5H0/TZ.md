# ТЗ: рабочие файлы роли не доезжают до артефактной ветки и main — белый список каталога задачи, guard до снимка

Источник: инцидент 06.09 (копилка, строка от 06.09 «Рабочие файлы роли
в корне `tasks/<id>/` доезжают до main»). Ревьювер задачи
01M1REVMB50SND1KJ3CYQMV2ST сохранил в `tasks/<id>/` пять копий карты
кодовой базы (`_head_map.md`, `_head_map_clean.md`, `_main_map.md`,
`_main_map_clean.md`, `_regen_clean.md`, по 100 КБ) и пустой
`_regen_out.txt` — рабочие файлы сравнения, не артефакты. Дальше три
штатных шага сработали как задуманы и вместе покрасили main:

1. `checkpoint.commit_step_artifacts` собирает содержимое `tasks/<id>/`
   без разбора имён и уносит в артефактную ветку
   (`artifact_branch.commit_files`, коммит cd52c308).
2. CI артефактной ветки (guard `--all --artifact-branch`) покраснел
   сразу — «нет frontmatter». Зелёность CI артефактной ветки конвейер
   нигде не требует, красный никто не увидел.
3. Шаг «снимок артефактной ветки поверх merge»
   (`fsm_merge_gate`, `artifact_branch.materialize_task_dir` →
   `git add -A -- tasks/<id>` → commit → push) перенёс каталог на main
   как есть (e5d43547). Guard на main запустился после push: main
   красный на трёх коммитах подряд, approve наблюдателя 01M1RFVWV6
   упёрся в красный CI после подтяжки, ре-ран подтвердил.

Снято руками Оператора коммитом f29d97f2. Черновики остались в
артефактной ветке 01M1REVMB5 и разошлись в артефактные ветки пяти задач,
созданных до удаления (унаследованы от main при создании ветки) — их CI
красный по той же причине.

Задача 01M1SAA01YRRTWAVADT2F81RRQ закрыла тот же класс только для
каталога планки (`ACCEPTANCE_TESTS_ALLOWED_TOP_LEVEL` в guard,
`_is_stray_acceptance_test_file` в checkpoint); корень `tasks/<id>/`
остался без белого списка.

Фактический набор имён первого уровня в `tasks/*/` на origin/main:
`SPEC.md`, `PLAN.md`, `REVIEW.md`, `TZ.md`, `ANSWER-<n>.md`,
каталог `acceptance_tests/`, приложения к PLAN (`*.patch` — два случая,
`mockup.html` — один). Шаблоны `templates/` добавляют `TEST_REPORT.md`
и `QUESTIONS.md`.

Требуется:
1. Белый список корня каталога задачи, одно место (`scripts/guard.py`,
   по образцу `ACCEPTANCE_TESTS_ALLOWED_TOP_LEVEL`): `SPEC.md`,
   `PLAN.md`, `REVIEW.md`, `TEST_REPORT.md`, `QUESTIONS.md`, `TZ.md`,
   `ANSWER-<n>.md`, `acceptance_tests/`, приложения `*.patch`. Всё прочее
   — «посторонний файл в каталоге задачи», именованная ошибка guard в
   режиме `--all` (с `--artifact-branch` и без), не попытка разбора
   файла как артефакта с frontmatter. Существующий `mockup.html` на main
   — либо в список исключений с указанием задачи, либо удаляется
   Оператором приложением (решение — в PLAN).
2. Автокоммит артефактов шага (`checkpoint.commit_step_artifacts` и
   чекпоинты таймаута/аварии/паузы, идущие тем же путём) переносит в
   артефактную ветку только файлы из белого списка п.1; посторонние
   файлы в коммит не попадают, шаг роли не проваливается, в журнал
   пишется одна запись с перечнем отброшенных путей (по образцу
   «посторонний файл в каталоге планки» из 01M1SAA01Y). Один источник
   истины для списка — функция guard, checkpoint её импортирует, не
   копирует.
3. Шаг снимка поверх merge гоняет guard на `tasks/<id>/` в scratch-репо
   ДО `git push` на main. Красный guard — отказ мержа с именованной
   причиной (файлы и нарушения) и задача остаётся на `merge_gate`;
   main не трогается. Отказ журналируется тем же классом, что прочие
   отказы merge_gate.
4. Тесты: (а) guard называет посторонний файл в корне каталога задачи в
   обоих режимах и молчит на полном штатном наборе имён, включая
   `ANSWER-7.md` и `x.patch`; (б) автокоммит с посторонним файлом в
   `tasks/<id>/` кладёт в артефактную ветку только артефакты и
   журналирует отброшенные пути; чекпоинт таймаута — тот же фильтр;
   (в) снимок поверх merge с посторонним файлом в артефактной ветке —
   отказ до push, main без изменений (песочница по образцу
   `tests/sandbox.py`); (г) существующие `tests/test_guard*.py`,
   `tests/test_checkpoint*.py`, `tests/test_fsm_merge_gate*.py` зелёные
   без правки ассертов. Каждый тест обязан ловить заявленную мутацию
   (белый список расширен на `*` / фильтр снят / guard после push).
5. Скилы (приложением к PLAN, защищённые пути не трогать): в скилах
   ревьювера и разработчика строка «рабочие файлы — только во временном
   каталоге сессии; в `tasks/<id>/` пишутся только артефакты по
   шаблону, остальное автокоммит отбрасывает».

Зоны: scripts/guard.py, orchestrator/checkpoint.py,
orchestrator/fsm_merge_gate.py, tests/.

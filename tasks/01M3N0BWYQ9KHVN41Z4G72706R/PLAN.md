# PLAN: Приёмочные тесты двух групп — строка группы и проверки долгоживущих файлов на выходе из tests_writing

## Подход

Одна точка правды — `scripts/guard.py`, новая секция «Две группы
приёмочных тестов» (после `scan_artifact_disk_reads`):

- `GROUP_LINE` — единственное выражение строки группы
  (`^[^\S\n]*Группа:[^\S\n]*(\S*)`, `re.M`; якорь начала строки, чтобы
  «Группа:» внутри фразы докстринга не считалась строкой), значения —
  `GROUP_VALUES` (`долгоживущий`, `разовый`). Разбор —
  `plank_file_group(source) -> (группа, ошибка)` по докстрингу модуля
  (`ast`): нет строки, неизвестное значение, две разные строки — ошибка.
  Вызывающие функции читают `GROUP_LINE` глобалом в момент вызова —
  подмена в `guard` действует на все места (AC-9).
- `group_line_errors_from_files`, `plank_has_group_lines`,
  `acceptance_test_files(tdir)` (файлы `acceptance_tests/**/test_*.py`
  с меткой относительно `tdir`, как у `scan_artifact_disk_reads`).
- `long_lived_sign_hits(source, task_id)` — один проход `ast.walk` с
  картой привязок импортов (`import a.b as x` → `x: a.b`), по девяти
  признакам требования 3 в формулировке списка (`SIGN_*`); перечень
  «импорт вне перечня» — `sys.stdlib_module_names` ∪ `orchestrator`/
  `scripts`/`tests` ∪ `stack.THIRD_PARTY_EXCEPTIONS` (тот же, что у
  `StdlibOnlyImportsInvariantTest`). Признак 9 исключает корни `self`/
  `cls`/`super()` и имена, привязанные импортом из стандартной
  библиотеки или `tests`.
- `long_lived_errors_from_files(files, task_id)` — только файлы
  `Группа: долгоживущий`: ошибки признаков (`<файл>:<строка>: признак
  «<признак>» — <почему>`) и методы без заявки через
  `test_functions_without_mutation_claim(None, source)` — тот же узел,
  что `_mutation_claim_gate`; «Зелёный с рождения» он не принимает.

Подключение:

- `orchestrator/advance_gates/tests_writing.py::_tests_writing_test_groups_gate`
  — область `target == config.DEFAULT_TARGET` (канарейка не
  исключается), файлы — `acc_tdir` (тот же каталог, что сухой сбор),
  действие «переход отклонён: группы приёмочных тестов»; подсказка
  «исправь файл планки и повтори artel.py advance <id>» — и в `hint`, и
  в `detail` (журнал видит её, AC-11).
- `orchestrator/fsm_advance.py::tests_writing` — гейт первым элементом
  того же `_run_gates`, что сухой сбор (до субпроцесса pytest). Сухой
  сбор не тронут — применяется ко всем файлам, включая долгоживущие.
- `orchestrator/amend.py` — `_group_line_errors` в обоих путях
  (`_cmd_amend_tests` и `--from-branch`, класс ошибки закрыт целиком),

Признаки «tasks/» и «номер задачи» проверяются по всем строковым
литералам, включая докстринги, — буква требования 3 («строковый
литерал»); докстринг долгоживущего файла не ссылается на задачу.

## Риски

- Признак «номер задачи»/«tasks/» ловит и докстринги: долгоживущий файл
  не может сослаться на SPEC своей задачи в тексте. Это буква
  требования 3; если Оператор сочтёт это лишним — ослабление отдельным
  решением.
- «Пост-мерж» в `amend-tests` определяется по строкам группы в локе:
  планка «после правила» всегда их несёт (гейт иначе не пропустил бы),
  старая — нет; единственная серая зона — лок, сделанный вне пульта с
  частичной разметкой, он проверяется как новый (строже, не слабее).

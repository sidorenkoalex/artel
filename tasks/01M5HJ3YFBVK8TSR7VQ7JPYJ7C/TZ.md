Граница: задача только добавляет один новый файл долгоживущих тестов в `tests/`, исполняющий три названных пути на неизменённом коде пульта.

## Требуется

1. **Н1, рабочая копия.** Задача проекта с компонентом `pult-vitest` (правило планки не по умолчанию) в `in_dev` с локом; планка — файл с меткой `.test.jsx`, `.md` и пустой файл перечня (`guard.render_long_lived_manifest({})`); долгоживущих файлов нет. Фикстурная проверка: `long_lived_manifest` из `orchestrator/advance_gates/acceptance.py` для задачи возвращает `({}, "")`. Случаи, каждый — отдельным тестовым методом:
   - (а) годная правка файла с меткой — проход: вывод без «amend-tests: отказ», `tests_locked_sha` сдвинут и равен голове ссылки документов, записей «правка планки» на одну больше, голова кодовой ветки прежняя; второй прогон — в варианте без файла перечня вовсе (ветка `if not listed`, `orchestrator/advance_gates/acceptance.py:84`), с тем же исходом;
   - (б) файл с меткой с запретом (числовой литерал в аргументах `it`) — отказ «строка группы:» и строка «… — запрещено в тексте планки» (`guard.PLANK_BAN_TAIL`);
   - (в) файл с меткой без строки группы — отказ «строка группы:»;
   - (г) изменён только `.md`, неизменённый файл с меткой несёт запрет — отказ «строка группы:» с `guard.PLANK_BAN_TAIL`;
   - (д) нарушенная трассируемость — отказ «трассируемость AC нарушена:»;
   - (е) удалён единственный файл с меткой, покрывавший критерий, — отказ «трассируемость AC нарушена:».
   Файл с меткой в этих случаях называется не `test_*` (имя, например, `<случайное>.test.jsx`); это проверяется фикстурно. Отказ проверяется по префиксу группы и по имени файла с меткой в тексте отказа. Отказ: голова ссылки документов, голова кодовой ветки, `tests_locked_sha` и число записей «правка планки» прежние; вывод и последняя запись журнала «amend-tests отклонён» начинаются с префикса группы.

# PLAN: Бриф разработчика: вход роли одним документом

## Подход

Новый лист пакета `orchestrator/brief.py` (тот же слой, что `review.py` —
собирает вход роли, SQL не пишет, зовёт `store`/`alerts` по имени,
ADR-0003 3ж). Он не заменяет `review.review_package` (другая роль, другой
контракт — журналирует размер, не хэш компонентов, SPEC «Материалы»), а
добавляет параллельный механизм для developer/analyst.

Три функции:
- `component_hash(text) -> str` — `hashlib.sha256(...).hexdigest()`
  содержимого компонента (требование 8); формат не диктуется SPEC, но
  обязан меняться вместе с содержимым — sha256 это гарантирует
  структурно, не таблицей соответствий.
- `fresh_map_text(conn, task_id) -> str` — читает `docs/codebase-map.md`
  из `config.ROOT` (не из ветки задачи: карта — общий для пульта
  артефакт, не файл конкретной задачи), парсит `built_at_sha` из
  frontmatter, сверяет диапазон `built_at_sha..HEAD` по
  `orchestrator/*.py`, `scripts/*.py`, `tests/*.py` тем же вызовом,
  которым уже пользуется CI-джоба `codebase-map` (`git diff --name-only
  <base> HEAD -- <пути>`, `.github/workflows/ci.yml`, tasks/T027) —
  переиспользование способа сверки, не копия чужого кода. Сама сверка не
  ответила (`returncode != 0` — git отказал, а не «расхождений нет»;
  `_stale_paths` возвращает `None`, тем же приёмом, что уже кодирует
  `gitcmd.diff_paths`) → тот же путь, что и провал регенерации ниже:
  алерт и пометка, без молчаливого доверия карте (REVIEW T028 итерация 1,
  замечание major — `returncode != 0` раньше сворачивался в пустой
  список, то есть «расхождений нет», один и тот же класс отказа git
  трактовался по-разному для сверки и для регенерации). Расхождение
  непусто → `subprocess.run(["python3", "scripts/codebase_map.py"],
  cwd=config.ROOT)` до сборки брифа, регенерированный файл читается в
  память, затем рабочее дерево `config.ROOT` немедленно возвращается к
  закоммiченному состоянию (`gitcmd.git("checkout", "--", MAP_REL)`) —
  до того, как агент роли получает управление (требование 5, 6, AC-5).
  Без этого возврата регенерация оставляла бы `docs/codebase-map.md`
  незакоммиченным ровно в том рабочем дереве, которое `runner.role_cwd`
  отдаёт агенту developer/analyst как cwd и которое агент коммитит
  целиком по своей миссии — правка вне зоны задачи утекала бы в её ветку
  без её ведома (REVIEW T028 итерация 1, blocker). Возврат не удался →
  отдельный алерт (`brief.codebase_map_restore`) — тихо оставить рабочее
  дерево пульта грязным запрещает тот же принцип; уже прочитанный текст
  карты при этом всё равно используется для брифа. Регенерация упала
  (rc≠0) → молчаливая сборка со стухшей картой запрещена (требование 7):
  `alerts.raise_alert` (`kind="incident"`, дедуп по (target, kind,
  source, message) уже встроен в `alerts.py`) и явная текстовая пометка
  перед текстом карты — использованный `built_at_sha` и пути расхождения
  (список из того же `git diff --name-only`, не отдельный запрос — одна
  точка правды). Расхождения нет → карта как есть, без пометки
  (требование 6, AC-6).
- `developer_brief(conn, task_id) -> str` и `analyst_map_component(conn,
  task_id) -> str` — собирают текст компонентов (`tasks/<id>/SPEC.md` из
  `config.TASKS`, `docs/codebase-map.md` через `fresh_map_text`,
  `CLAUDE.md` из `config.ROOT`) и на каждый компонент кладут отдельную
  строку в журнал шага (`store.journal`, actor — роль шага) с
  `component_hash` — воспроизводимость шага без отдельной таблицы
  (требование 8, 9, AC-8, AC-9). Карта — файл целиком, без среза по зоне
  задачи (требование 4: при факте 687 строк/~30 КБ полное включение
  дешевле поддержки среза — SPEC уже посчитал и решил, PLAN не
  пересчитывает).

`orchestrator/runner.py` (`cmd_run`): для `role == "developer"` —
`brief_text = brief.developer_brief(conn, task_id)`; для `role ==
"analyst"` — `brief_text = brief.analyst_map_component(conn, task_id)`,
добавка к уже существующему входу `TZ.md` (требование 9 — TZ.md как был,
агент читает его сам, только карта подключается новым механизмом). Блок
`--- БРИФ РОЛИ ---` клеится в промпт ПОСЛЕ блока `--- СКИЛЫ РОЛИ ---` —
тем же местом, где сегодня клеится `--- РЕВЬЮ-ПАКЕТ ---` у reviewer:
скилы остаются отдельным, не потревоженным блоком (требование 3, AC-4).
Мисcия developer правится текстуально («SPEC, карта и конвенции — в
БРИФЕ РОЛИ ниже», без инструкции «прочитай сам» — требование 2); миссия
analyst получает одну добавленную фразу про карту, инструкция читать
`TZ.md` самому не убирается (SPEC «Не входит»: остальной вход и скилы
analyst не меняются).

`reviewer`/`test_author` не трогаются (SPEC «Не входит»).

## Шаги

1. `orchestrator/brief.py` (новый модуль) + подключение в
   `orchestrator/runner.py` (`cmd_run`, роли `developer` и `analyst`) +
   юнит-тесты `tests/test_brief.py` на сами функции модуля (не дублируют
   приёмочные — те гоняют `cmd_run` целиком, юниты бьют по
   `component_hash`/`fresh_map_text`/сборке компонентов по отдельности).
2. **Обнаружено на прогоне полного `tests/`.** Пять предсуществующих
   файлов держат песочницы с `config.ROOT`, подменённым на пустой tmp-
   каталог (или с полным моком `subprocess.Popen`, что бьёт по общему
   с `gitcmd.git` модульному объекту `subprocess`) и гоняют `cmd_run` для
   роли `developer`/`analyst` — до этой задачи она ни разу не читала
   `docs/codebase-map.md`/`CLAUDE.md`/`tasks/<id>/SPEC.md` и не звала
   `gitcmd.git`, поэтому пробел не был виден. Правка — только фикстуры
   (файлы-заглушки `docs/codebase-map.md`/`CLAUDE.md`/`SPEC.md` рядом с
   уже копируемыми `skills/`/`templates/`, где такого файла не было; в
   одном месте — подмена `gitcmd.git` там, где `Popen` замокан целиком),
   ни одна проверка/ассерт не ослаблена: `tests/test_review_package.py`
   (`FakeGit` — свой ответ на `--name-only`, отдельный от ревью-пакетного
   `--stat`/полного diff; `test_developer_step_has_no_package` —
   уточнён список ожидаемых git-вызовов, а не расширен на «любой»),
   `tests/test_doctor.py`, `tests/test_git_fixation.py`,
   `tests/test_multitarget.py`, `tests/test_multitarget_invariants.py`.
   Подробности — «Влияние на систему».
3. Прогон приёмочных тестов `tasks/T028/acceptance_tests/` (залочены,
   tasks/T023 — не правятся, все 11 зелёные), полного `tests/` (526
   тестов; 3 несвязанных предсуществующих падения на локальном
   `GIT_COMMITTER_EMAIL` окружения — воспроизводятся и на `main`, не от
   этой ветки), `scripts/guard.py --all` (ок, 70 файлов); коммит,
   `PLAN.md` → `status: ready`.
4. **Правки по REVIEW.md итерации 1 (changes_requested).** Blocker —
   `_regenerate_map` теперь читает регенерированный текст в память и
   сразу восстанавливает рабочее дерево `config.ROOT` (`git checkout --
   docs/codebase-map.md`), не оставляя его незакоммиченным в cwd агента
   developer/analyst; отказ восстановления — отдельный алерт
   (`brief.codebase_map_restore`), не тихая грязь. Major — `_stale_paths`
   возвращает `None` (не `[]`) при отказе самой git-команды сверки
   свежести, `fresh_map_text` ведёт этот случай тем же путём алерта и
   пометки, что и отказ регенерации, а не молчаливым доверием карте.
   Minor — формулировка риска ниже поправлена по факту нового поведения.
   Новые/изменённые юнит-тесты — `tests/test_brief.py`
   (`test_failed_freshness_check_marks_the_text_and_raises_an_alert`,
   `test_regeneration_restores_the_working_tree_after_reading`,

## Влияние на систему

Новый файл `orchestrator/brief.py` — без побочного мандата за пределами
своей роли: читает `docs/codebase-map.md`/`CLAUDE.md`/`SPEC.md`, пишет в
журнал шага (`store.journal`) и в `alerts` (уже существующие,
рассчитанные на именно такой сценарий таблицы, ADR-0003 §3б, tasks/T022).
Регенерация карты зовёт тот же `scripts/codebase_map.py`, что и CI-джоба
`codebase-map` (tasks/T027) — не новый генератор, не изменение его
контракта (SPEC «Не входит»); он пишет `docs/codebase-map.md` на диск в
`config.ROOT` (свой контракт, tasks/T027), поэтому `_regenerate_map`
сразу после чтения результата в память восстанавливает файл до
закоммiченного состояния (`git checkout --`) — это происходит до того,
как `runner.cmd_run` запускает агента роли (`run_agent_once`), так что
рабочее дерево, которое агент получает как cwd и коммитит целиком, к
старту агента не несёт правки карты вне зоны его задачи. Отказ этого
восстановления заводит отдельный алерт (`brief.codebase_map_restore`),
а не остаётся незамеченной грязью (REVIEW T028 итерация 1, blocker).
Правка `orchestrator/runner.py` — только сборка промпта (новый блок, две
ветки роли); существующие ветки `test_author`/`reviewer` и общий каркас
попыток/бюджета/pre-flight не тронуты.

Новый вызов `gitcmd.git`/чтение `docs/codebase-map.md`/`CLAUDE.md`/
`tasks/<id>/SPEC.md` для роли developer/analyst — до этой задачи такого
не было, поэтому пять предсуществующих файлов песочниц (`config.ROOT`
подменён на пустой tmp-каталог без этих файлов, либо `subprocess.Popen`
замокан целиком и бьёт по общему с `gitcmd.git` модульному объекту
`subprocess`) не доходили до этого пути и падали в полном прогоне
`tests/` (ENOENT на чтении, либо `ValueError` из-за `Popen`-подмены на
реальном git-вызове — см. шаг 2). Правка каждого — добавление
файлов-заглушек `docs/codebase-map.md`/`CLAUDE.md`/`SPEC.md` туда, где
фикстура уже копирует `skills/`/`templates/` для тех же целей (тот же
приём, не новый), плюс в одном месте (`test_multitarget.py`,
`test_step_does_not_start_without_the_layer`) — подмена `gitcmd.git`
рядом с уже существующей подменой `Popen`. Ни одна проверка не снята и
не ослаблена: единственное содержательное изменение ассерта —
`tests/test_review_package.py::test_developer_step_has_no_package`,
где список ожидаемых git-вызовов дополнен новым (сверка свежести карты)
вместо расширения на «любой» — тест по-прежнему проваливается на
`show`/ветко-диффе, которых для роли developer быть не должно.
`tests/test_agent_prompt.py` и `tests/test_analyst_role.py`
(предсуществующие) правки не потребовали: их `config.ROOT` не подменён,
поэтому читают настоящие `docs/codebase-map.md`/`CLAUDE.md` пульта, а
`gitcmd.git` — заглушкой с пустым diff (расхождений не находит, не
регенерирует). Обратимость: `git revert` коммита ветки — новый файл
кода, две точки подключения в `runner.py`, тесты (включая пять
точечных правок фикстур), артефакты задачи.

## Риски

- `docs/codebase-map.md` без `built_at_sha` в frontmatter (файл руками
  испорчен) — `fresh_map_text` в этом случае считает базой пустую
  строку; `git diff --name-only "" HEAD -- <пути>` падает с `fatal: bad
  revision ''` (rc=128), не возвращает пустой дифф — исправлено REVIEW
  T028 итерация 1 (замечание minor: прежняя формулировка риска ошибочно
  утверждала эквивалентность пустому диффу). После правки major-замечания
  этот же отказ git идёт путём «сверка не ответила»: `_stale_paths`
  возвращает `None`, `fresh_map_text` заводит алерт и помечает карту
  неактуальной с `built_at_sha=—` — то есть вырожденный случай больше не
  риск, а штатно обработанная ветка (не «карта молча выдаётся как
  свежая», как было в итерации 1).
- Регенерация зовёт `git checkout --` для отката правки рабочего дерева
  (см. «Подход», «Влияние на систему») — на репозитории с чужими
  незакоммиченными изменениями именно этого файла откат стёр бы их. Не
  риск для реального пульта: `docs/codebase-map.md` — файл, который
  правит только сам генератор (руками — не по конвенции, автогенерация,
  tasks/T027), сторонних незакоммиченных правок этого пути в штатном
  цикле не бывает.

# ТЗ: Бриф разработчика: вход роли одним документом

Бриф разработчика — по роадмапу §2 («Бриф разработчика — $25»).

Суть: сейчас разработчик получает миссию + SPEC и сам ходит по репо
за контекстом (повторные чтения — «трение»). Хочу, чтобы оркестратор
собирал вход роли одним документом — брифом: SPEC задачи + срез
codebase-map по зоне задачи (карта есть — docs/codebase-map.md,
секции машинно-срезаемы, T027) + конвенции (skills роли и так идут
в промпт — не дублировать, но если есть проектные конвенции сверх
скилов, реши, где их место).

Важное из ADR-0003 3б (принцип свежести): при сборке брифа — ленивая
сверка карты: если карта стухла относительно зоны задачи (диффом
модулей, как в CI-джобе T027), собирать бриф со стухшей картой молча
нельзя — честная пометка в брифе или регенерация, реши по цене.

Хэши компонентов брифа (SPEC, срез карты, конвенции) — в журнал БД:
шаг должен быть воспроизводим (диагностический перепрогон из P3
потом обопрётся на это).

Какой срез карты давать (весь файл мал — может, целиком дешевле,
чем резать?) — посчитай и реши сам, по фактическому размеру карты.

Про analyst: у него по A5 вход «срез карты» задуман, но не подключён.
Если влезает в бюджет без раздувания — подключи тем же механизмом;
если нет — явно напиши в «Не входит», отдельной задачей.

Бюджет — класс $25.

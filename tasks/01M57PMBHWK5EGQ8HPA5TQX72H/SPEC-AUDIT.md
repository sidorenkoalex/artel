# SPEC-AUDIT: Несколько проектов: проект в report и алерты пульта в наблюдении внешнего проекта

## ТЗ и SPEC
Из ТЗ в SPEC:

- ТЗ п.2 (алерты пульта всем наблюдениям, «оповещено» по наблюдению) → треб. 4, AC-5. Что такое «алерт уровня пульта» (`target` NULL), решил ANSWER-1 п.1 (A).
- ТЗ п.3 (сверка смешения проектов) → треб. 2 (панель алертов), 8 (смешение под `DEFAULT_TARGET` уходит в бэклог), «Не входит» (merge-окно, обычный `watch`). Я проверил `status` по коду (`catalog.py:937-991`): держатели зоны уже берутся по проекту (`catalog.py:869-871`), стоп-кран намеренно общий (`catalog.py:878-888`), секция триггеров уже печатает target (`catalog.py:990`). Пропусков в `status` нет.
- ТЗ п.4–5 → треб. 6–7, AC-7.
- ANSWER-1 п.3 и п.4 → треб. 1 и 5.

Расхождения:
1. **ANSWER-1 п.3 «везде, где строка — задача» исполнен не полностью.** Треб. 1 (SPEC.md:27-34) перечисляет пять мест вывода. Шестое пропущено: строки блока «Шаги test_author» начинаются с id задачи (`report.py:965`, `step["task"]` из `report.py:857`). В «Не входит» этого блока тоже нет. Строки «Разведки ролей» id задачи не несут (`report.py:975-983`), к ним вопроса нет.
2. **Противоречие внутри SPEC: треб. 4 против треб. 6 / AC-7 для `watch`.** ТЗ исходило из того, что алерты пульта «видны только наблюдению артели». На деле алерты с `target` NULL сейчас не видит ни одно наблюдение, в том числе наблюдение артели (`watch.py:303-306`: `None` нет в `targets`). Значит, по треб. 4 в базе только с задачами артели дозор начнёт печатать новые строки алертов NULL (с `-` по треб. 5). А треб. 6 и AC-7 (SPEC.md:55-57, 81) требуют, чтобы текст `watch` у артели был прежним, и не оговаривают алерты NULL. Если эталон AC-7 содержит алерт NULL, треб. 4 и AC-7 выполнить одновременно нельзя.
3. Требований сверх ТЗ и ANSWER-1 в SPEC нет. Треб. 2 (панель алертов) выведено из ТЗ п.3 и в зоне `report.py`.

## Пути обхода гейтов
1. **Тихая вложенная разметка вместо решения по тесту.** Исполнитель может выполнить треб. 1 буквально через `<span class="tile-project">[<span>sled</span>]</span>`. Тогда `project_label.py:126` остаётся зелёным, а гейт неослабления ничего не увидит. Это не ослабление, но выбор, который SPEC должен сделать явно. Обратный путь — переписать `:126` на `f"[{self.project}]"`. Это смена ожидания без объявления, и её остановят только на `in_dev → verifying`.
2. **AC-7 на базе без алертов NULL.** Если фикстура эталона `watch` не содержит алерта NULL, AC-7 и AC-5 оба зелёные. Тогда изменение вывода `watch` у артели, прямо запрещённое треб. 6, проходит незамеченным. Нужно либо признать его в SPEC, либо запретить.
3. **AC-4 только на артели.** Разбивка может срабатывать при единственном внешнем проекте или при смеси «артель + NULL», и AC-4 этого не заметит (см. таблицу проверяемости).
4. **Метка только в пяти перечисленных местах.** Строки test_author (`report.py:965`) остаются без метки, и формально треб. 1 выполнено, хотя ANSWER-1 п.3 говорит «везде».

## Вердикт
**concerns.** SPEC в целом верен коду и ТЗ. Все ссылки на код подтвердились, зоны достаточны, защищённые пути не задеты. Остаются отклонения, которые Оператор может снять на гейте (или вернуть SPEC аналитику):

1. **Конфликт с долгоживущим тестом плитки.** `tests/test_01m563e1sh9sb63s2mw4a9b82n_project_label.py:126` ждёт элемент с текстом ровно `<проект>`, а треб. 1 (SPEC.md:33-34) меняет текст на `[<проект>]`. SPEC не называет этот тест, не выбирает «вложенная разметка или мандат на правку теста» и не имеет раздела «Меняемое поведение». Через этот раздел смену и нельзя оформить: «было» — имя `self.project`, а не литерал.
2. **Треб. 4 / AC-5 против треб. 6 / AC-7 для `watch`.** Алерт NULL сейчас не доставляется и наблюдению артели (`watch.py:303-306`). Новая доставка меняет текст `watch` у базы только с задачами артели, а SPEC.md:55-57, 81 запрещают это без оговорки.
3. **Пропуск в треб. 1.** Строки «Шаги test_author» несут id задачи без метки (`report.py:965`), а ANSWER-1 п.3 требует метку «везде, где строка — задача». Блок не попал ни в треб. 1, ни в «Не входит» (SPEC.md:101-117).
4. **Неоднозначности AC-3 (SPEC.md:73).** Не задано, как считать окно «за последние 10 задач» по проекту: окно на деле — записи, `report.py:58, 362`. Не задано, куда в агрегатах идут задачи с `target` NULL.
5. **AC-4 (SPEC.md:75) не требует базы одного внешнего проекта.** Мутация «`DEFAULT_TARGET` всегда в счёте проектов» не ловится.
6. **AC-2 / треб. 2 (SPEC.md:35-38) молчат об алертах с `target` = id задачи внешнего проекта** (`attention`, `alerts.py:116-120`).
7. **Побочное изменение `observe events` не названо.** Правка `_observation_events` в `watch.py` меняет и вывод `observe events` (`artel.py:1132-1133`), а SPEC этого не называет и не проверяет.
8. Мелочь. Признак «сразу за id» в AC-1 (SPEC.md:69) для плитки (два `<span>`) неоднозначен: отрендеренный текст или сырая подстрока.

Пункты 1–2 требуют решения до кода. Пункты 3–8 можно снять одной строкой Оператора на гейте или уточнением аналитика.

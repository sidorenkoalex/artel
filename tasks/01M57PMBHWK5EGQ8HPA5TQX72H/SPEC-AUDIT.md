## Пути обхода гейтов
- Метка `[None]` у NULL-задачи в пяти строках report (кроме плитки) проходит AC-1 буквально (см. AC-1 выше) — смысл треб. 1 «у NULL прежний вид» не закреплён тестом.
- Треб. 2 (SPEC.md:47-50) метит алерт, «чей `target` — имя внешнего проекта», не называя источник множества имён: `{tasks.target}` выборки, `targets.yaml` или «не форма id задачи» (`idgen.is_task_id_form`). AC-2 даёт фикстуру с задачей `sled`, поэтому все три реализации проходят его, но различаются на алерте проекта без задач в БД (например `doctor/project_checks` по только что заведённому проекту) и на алерте по id задачи, удалённой `prune`/с id старой формы `T0NN`. Исполнитель выбирает интерпретацию сам.
- Иных путей обхода не нашёл: эталон AC-8 фиксируется планкой test_author до `in_dev`, поэтому снять его «после правки» исполнитель не может; доставку по разу держат повторные циклы AC-5.

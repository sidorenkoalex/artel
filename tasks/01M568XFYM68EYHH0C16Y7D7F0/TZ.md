# kill задачи внешнего проекта: уборка ветки и PR в его репозитории

## Факты

Строка бэклога 18.10 «kill и уборка задачи внешнего проекта в его репозитории», разбор «что прибито под артель». Решение Оператора 18.10: документы задачи (`refs/artifacts/<id>`, в том числе RETRO со стоимостью) публикуются в репозиторий проекта как сейчас, переключатель не нужен. `kill` (`orchestrator/cleanup.py:185-216`, `cleanup_killed_task`) убирает только рабочую копию, каталог задачи и локальную ветку в клоне проекта; ветка `task/<id>-…` в `origin` проекта и черновой PR (`github_adapter.ensure_draft_mr`, `:114-200`) остаются — в чужом репозитории их видят люди проекта (пример: sledproject/sled#17 у задачи 01M55SKHZ293CCAK0N7T4H7ZMR). Удаления веток в `origin` и закрытия PR в пульте нет (поиск по коду). Тексты `kill` называют `config.MAIN_BRANCH`, а не базу проекта (`cleanup.py:178, 212`).

## Требуется

1. `kill` задачи внешнего проекта после сегодняшней уборки закрывает её черновой PR в репозитории проекта (с комментарием «задача ликвидирована в пульте: <id>») и удаляет ветку задачи в `origin` проекта — токеном проекта (`ci.gh(..., repo=<url проекта>)` для PR, git-пуш удаления через механизм токена `gitcmd`, как остальные операции пульта с хостингом проекта). `refs/artifacts/<id>` не удаляются (решение Оператора — публикация документов как есть).
2. Любой сбой (нет PR, gh или git не ответили, нет токена) — запись «оставлено: <что> — <причина>» в журнал уборки, `kill` не отменяется и не падает (как сегодня: kill switch срабатывает всегда).
3. У артели поведение `kill` не меняется (PR и ветки артели — как сейчас); зафиксировать тестами до правки. Тексты `kill` для внешнего проекта называют базу проекта.
4. Тесты детерминированы, без сети: учебный внешний проект с bare-репозиторием как `origin` и подставным `gh` — после `kill` ветки задачи в `origin` нет, `gh pr close` вызван с репозиторием проекта и токеном слота; сбой `gh` — запись «оставлено», kill завершён; у артели — прежние вызовы.

Критерии приёмки:
- `kill` внешней задачи закрывает её PR и удаляет ветку в репозитории проекта, документы задачи остаются;
- сбой уборки не мешает `kill`;
- у артели `kill` прежний.

Зоны: `orchestrator/cleanup.py`, `tests/`.

Только чтение: `orchestrator/ci.py`, `orchestrator/github_adapter.py`, `orchestrator/gitcmd.py`, `orchestrator/workspace.py`, `orchestrator/repo_context.py`, `docs/backlog.md`. Правка вне зон — эскалация до SPEC.

Не входит: уборка `refs/artifacts/*` внешнего проекта; уборка задач, ликвидированных до этой задачи (sledproject/sled#17 и т. п. — вручную); kill задач артели.

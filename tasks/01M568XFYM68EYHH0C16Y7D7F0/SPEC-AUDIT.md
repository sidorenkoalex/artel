## Проверяемость критериев

| Критерий | Проверяем | Ловимая мутация |

| AC-1 | да | пуш удаления не делается / удаляется не та ветка; удаление `refs/artifacts/<id>` локально или в `origin` (`push --delete` с refspec артефактов, `--prune`/`--mirror`). Предусловие «опубликованы до kill» закрывает вакуумную проверку. |

- **З-1 (замечание к AC-6).** `http.lowSpeedLimit/lowSpeedTime` действуют только на HTTP(S)-транспорт git; bare-`origin` по пути/`file://` (AC-1) их не задействует. «Молчащий `origin`» AC-6 возможен только как локальный HTTP-сервер, принимающий соединение и не отвечающий (требование 9 это допускает: «локальным подставным хостингом»). SPEC это прямо не называет — тест-автор выведет из механизма; для реальных проектов по ssh-URL предел пуша не действует (выбор средства — решение Оператора №3, механизм токена `gitcmd` рассчитан на HTTPS-помощник, `gitcmd.py:39-41`). Не отклонение, к сведению.
- Способ распознать «срабатывание предела времени пуша» (текст curl «Operation too slow» / замер времени) SPEC не навязывает — поведение задано AC-4/AC-6 с обеих сторон, этого достаточно.

## Пути обхода гейтов
- Буквальное выполнение AC-6 на bare-`origin` по пути невозможно (нет «молчащего» file-транспорта), так что подмена HTTP-сервера на быстрый отказ провалит проверку «не ответил» — обход не проходит.
- Вызов `gh`/`git push` мимо `ci.gh`/`gitcmd` (прямой `subprocess`) ловят AC-2 (`GH_TOKEN`) и AC-5 (запуск при пустом слоте).
- Привязка новой функции к `cleanup_killed_task` вместо `won` ловится AC-9(а,б).
- Предел пуша литералом ловится AC-6 (подмена `config.GH_TIMEOUT_SEC`).
Других путей не найдено.

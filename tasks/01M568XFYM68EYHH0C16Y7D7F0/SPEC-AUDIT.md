Отклонение 1 (AC-6, требование 3): SPEC не задаёт ни значения предела
ожидания git-пуша, ни места, где тест его уменьшает (SPEC.md:54-59,
SPEC.md:90). Граница AC-6 — «сумма пределов этих двух операций плюс 10 с»;
предел `gh` известен (`config.GH_TIMEOUT_SEC`, подменяем), предел git
появится только в коде разработчика. Планка пишется до кода: test_author
либо не может вычислить границу, либо угадывает имя константы, которую
подменяет («тест вправе уменьшить пределы»), — тест, навязывающий
устройство (skills/escalation-rules.md). Без уменьшения предел git
неизвестен, и время прогона теста не ограничено ничем, кроме выбора
разработчика. Решение на гейте: назвать предел (например, «`lowSpeedTime`
= `config.GH_TIMEOUT_SEC`, `lowSpeedLimit` = 1» — тогда тест уменьшает
оба одной подменой) либо имя модульной константы `cleanup.py`.

Отклонение 2 (мелкое; требование 6, AC-3..AC-6): «журнал уборки» не
определён — не сказано, пишется ли запись уборки в репозитории в ту же
запись `store.journal(..., "уборка", …)` (cleanup.py:213), отдельной
записью с тем же action или с другим action. Существующий помощник читает
последнюю запись action='уборка' (tests/test_kill_cleanup.py:162-168);
планка, выбравшая один вариант, отвергнет корректную реализацию на
другом. Также не задан текст «<что>» для PR (SPEC.md:87, :89 — «<PR>»):
AC-5 требует различить записи «по PR и по ветке», а различить их тест
может только по имени ветки (у обеих) или по слову, которого SPEC не
фиксирует.

## Пути обхода гейтов
- Ветвление по `forge: github` вместо «не артель»: артель сама `forge:
  github` — закрыто AC-7.
- Вызов уборки из `cleanup_killed_task` (проще всего, но задевает деление
  и повторный kill) — закрыто AC-9(а,б).
- Классификация «не ответил» по любому ненулевому коду — закрыто AC-3/AC-4.
- Предел git, заданный так, что AC-6 формально не проверить (отклонение
  1): разработчик выбирает большой `lowSpeedTime`, а тест, не зная его,
  ставит щедрую границу — смысл решения Оператора №1(2) «не вешает kill»
  держится только выбором разработчика.
- Предел `-c http.lowSpeed*` действует только на HTTP(S)-транспорт;
  `origin` по ssh зависнет без предела. Решение Оператора №1(2) этот способ
  разрешило прямо, токен хостинга идёт через credential helper (HTTPS),
  поэтому не отклонение — остаточный риск для сведения Оператора.
- Замечание (не отклонение): песочница подставляет токен слота
  (tests/sandbox.py:656-661) и снимает признак роли, `gh` резолвится как
  есть (tests/sandbox.py:134-138) — существующие тесты kill внешних задач
  (например tests/test_multitarget_invariants.py:469,
  tests/test_01m41ab597b330p2rcxcmvrzpe_docs_ref_refixation.py:829) после
  правки запустят настоящий `gh pr close --repo file:///nonexistent/…` или
  `http://localhost/…` — быстрый отказ, запись «оставлено», без внешней
  сети; требование 9 говорит только о новых тестах.

# SPEC: kill задачи внешнего проекта — уборка ветки и PR в его репозитории

## Контекст
`kill` (`orchestrator/cleanup.py:185`, `cleanup_killed_task`) убирает только
рабочую копию, каталог задачи и локальную ветку в клоне проекта. Ветка
`task/<id>-…` в `origin` внешнего проекта и черновой PR, заведённый
`github_adapter.ensure_draft_mr`, остаются — в чужом репозитории их видят
люди проекта (пример: sledproject/sled#17 у задачи
01M55SKHZ293CCAK0N7T4H7ZMR). Удаления веток в `origin` и закрытия PR в пульте
нет. Тексты `kill` называют `config.MAIN_BRANCH`
(`orchestrator/cleanup.py:211`), а не базу проекта. Решение Оператора 18.10:
документы задачи (`refs/artifacts/<id>`, в том числе RETRO) публикуются в
репозиторий проекта как сейчас, переключатель не нужен.

## Требования
1. `kill` задачи внешнего проекта, помимо нынешней уборки, закрывает черновой
   PR задачи в репозитории проекта с комментарием
   «задача ликвидирована в пульте: <id>» — через `ci.gh(..., repo=<url
   проекта>)` токеном проекта.
2. `kill` задачи внешнего проекта удаляет ветку задачи в `origin` проекта
   git-пушем удаления через механизм токена `gitcmd` (как остальные операции
   пульта с хостингом проекта).
3. `refs/artifacts/<id>` при `kill` внешней задачи не удаляются — ни
   локально, ни в `origin` проекта.
4. Любой сбой уборки в репозитории проекта (нет PR, `gh` или `git` не
   ответили / вернули ошибку, нет токена) даёт запись
   «оставлено: <что> — <причина>» в журнал уборки; `kill` не отменяется, не
   падает исключением, задача переходит в `killed`.
5. У артели поведение `kill` не меняется: PR и ветки артели — как сейчас,
   прежние вызовы. Это фиксируется тестами до правки кода.
6. Тексты `kill` для задачи внешнего проекта называют базу проекта, а не
   `config.MAIN_BRANCH`.
7. Тесты детерминированы и без сети: учебный внешний проект с
   bare-репозиторием в роли `origin` и подставным `gh`.

## Критерии приёмки
AC-1. После `kill` задачи учебного внешнего проекта (bare-репозиторий как `origin`, подставной `gh`) ветки задачи `task/<id>-…` в `origin` проекта нет.
AC-2. При `kill` задачи внешнего проекта подставной `gh` получает вызов закрытия PR (`gh pr close`) с репозиторием проекта, с комментарием «задача ликвидирована в пульте: <id>» и с токеном слота проекта в окружении.
AC-3. После `kill` задачи внешнего проекта `refs/artifacts/<id>` остаётся и в клоне, и в `origin` проекта.
AC-4. Сбой подставного `gh` (ненулевой код возврата или отсутствие PR) при `kill` внешней задачи даёт в журнале уборки запись «оставлено: <что> — <причина>», задача в состоянии `killed`, `kill` завершается без исключения.
AC-5. Сбой удаления ветки в `origin` (git-пуш отказал) или отсутствие токена проекта при `kill` внешней задачи даёт в журнале уборки запись «оставлено: <что> — <причина>», задача в состоянии `killed`, `kill` завершается без исключения.
AC-6. `kill` задачи артели не вызывает закрытия PR и не удаляет ветки в `origin` — набор вызовов `gh`/`git` к хостингу тот же, что до правки (тест зафиксирован до правки кода).
AC-7. Тексты `kill` для задачи внешнего проекта (в том числе «перейди на … и повтори kill») называют базу проекта, а не `config.MAIN_BRANCH`.

самостоятельная ценность, а часть «код» без них нарушает требование 5.

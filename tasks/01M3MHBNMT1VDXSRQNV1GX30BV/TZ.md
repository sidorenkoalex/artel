# ТЗ: Синтетический ответ канарейки на эскалацию — без ссылки на чужую задачу и с содержанием

Источник: решение Оператора 28.09.2026 по итогам этапа 1 замера канарейки
на моделях двух провайдеров (ADR-0019); строка копилки 28.09 (коммит
029718bd).

Факты (origin/main 029718bd):
- `orchestrator/canary.py::_pass_escalated_with_synthetic_answer` на любую
  эскалацию задачи прогона пишет командой `answer` один и тот же текст:
  «Синтетический ответ прогона канарейки (заглушка Оператора, SPEC
  01M1NEEWH5K1XPFRDGRMPYSBXJ, требование 6): вариант A — продолжай штатным
  путём.» Номер — задача, которая ввела механизм; в тексте ответа роли он
  читается как ответ по другой задаче. «Вариант A» в вопросах роли может
  не существовать.
- Прогон 20260928T165337Z (набор `m-gpt-6-luna`): аналитик четыре раза
  подряд повторил один и тот же вопрос и отверг ответ как относящийся к
  другой задаче; предохранитель «3 повторных эскалаций подряд» закрыл
  задачу исходом «не сошлась». Прогон 20260928T162501Z (`m-gpt-5-6-sol`):
  тот же ответ закрыл эскалации автора тестов и ревьювера, приняв за
  Оператора смысловое допущение.
- Предохранитель повторных эскалаций и учёт эскалаций в строке прогона
  (`canary_runs`, маркер `canary-expect-escalation` шаблона) —
  `orchestrator/canary.py`.

Требуется:
1. Текст синтетического ответа не называет номер никакой задачи, кроме
   задачи прогона, и не ссылается на «вариант A» или иной вариант, которого
   роль могла не предлагать. Происхождение механизма (SPEC
   01M1NEEWH5K1XPFRDGRMPYSBXJ, требование 6) остаётся в докстринге и
   комментариях кода, не в тексте для роли.
2. Текст ответа говорит роли по существу: Оператора в прогоне канарейки
   нет; решение по вопросу принимает сама роль в пределах ТЗ и SPEC
   задачи, выбирает наименее рискованное толкование и записывает его как
   допущение в свой артефакт (раздел, который шаблон артефакта роли
   отводит под допущения или риски, — SPEC называет раздел по `templates/`);
   повторная эскалация по тому же вопросу не получит другого ответа.
   Текст один для всех ролей; SPEC решает, нужен ли в нём номер задачи
   прогона и роль.
3. Поведение предохранителя повторных эскалаций, учёт эскалаций в строке
   прогона и вердикт по маркеру шаблона не меняются.
4. `docs/stack.md`, раздел о канарейке (если синтетический ответ там
   описан): текст приведён к новому; если не описан — одно предложение о
   том, что отвечает канарейка на эскалацию.
5. Тесты (`tests/`): текст ответа не содержит номера задачи, отличного от
   задачи прогона (проверка — регулярным выражением идентификатора задачи
   пульта, а не литералом прежнего номера); текст содержит указание
   «решение за ролью в пределах ТЗ» и «записать допущение» (якорями,
   которые SPEC называет); предохранитель повторных эскалаций срабатывает
   как прежде. Корень и пути — через общие помощники `tests/sandbox.py`.

Зоны: orchestrator/canary.py, docs/stack.md, tests/.

Только чтение (не менять): orchestrator/answer.py, orchestrator/fsm.py,
templates/, skills/, tests/test_invariants.py, docs/backlog.md.

Не входит: правка шаблонов пула канарейки (вне git); ответ канарейки,
различающий вопросы по содержанию; смена порога предохранителя;
изменение правил ролей об эскалации.

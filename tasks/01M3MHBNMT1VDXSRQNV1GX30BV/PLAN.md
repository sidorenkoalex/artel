# PLAN: Синтетический ответ канарейки на эскалацию — без ссылки на чужую задачу и с содержанием

## Подход

Текст ответа перестаёт быть литералом в теле
`orchestrator/canary.py::_pass_escalated_with_synthetic_answer` и
становится ОДНОЙ константой модульного уровня, собранной из четырёх
именованных констант-якорей (требование 6). Собранная, а не переписанная
рядом с якорями строка — единственный способ выполнить AC-3 честно:
якорь физически один экземпляр, тест адресует его именем константы, а
расхождение «якорь поправили, текст забыли» невозможно по построению.

Четыре якоря — дословные формулировки требования 6 SPEC:

| Константа | Значение | Утверждение требования 4 |
|---|---|---|
| `_SYNTHETIC_ANSWER_NO_OPERATOR` | «Оператора в этом прогоне нет» | (а) |
| `_SYNTHETIC_ANSWER_ROLE_DECIDES` | «решение по вопросу принимаешь ты — в пределах ТЗ и SPEC задачи» | (б) |
| `_SYNTHETIC_ANSWER_WRITE_ASSUMPTION` | «запиши выбранное толкование допущением в свой артефакт» | (в) |
| `_SYNTHETIC_ANSWER_SAME_ANSWER_AGAIN` | «повторная эскалация по тому же вопросу получит этот же ответ» | (г) |

Имена — с ведущим подчёркиванием: константы не читаются за пределами
`canary.py` (кроме тестов), и это идиома самого модуля
(`_CEILING_EXHAUSTED_REASON`, `_DEV_RETRY_ACTION`). Форма `NAME.isupper()`
сохранена — планка адресует их через пространство имён модуля.

Место констант — верхний блок литералов модуля, рядом с
`MARK_EXPECT_ESCALATION_*`: все модульные литералы `canary.py` живут там
одним блоком, а не по месту единственного употребления.

Происхождение механизма (SPEC 01M1NEEWH5K1XPFRDGRMPYSBXJ, требование 6)
переезжает из текста ответа в докстринг функции — требование 3,
проверяется AC-6 отдельно от текста (`docs_and_comments` планки берёт
докстринг и комментарии БЕЗ строковых литералов тела).

Адрес допущения — раздел «## Риски» с оговоркой про шаблон, который его
не несёт (требование 5). Проверено по `templates/*.md`: «Риски» несёт
только `templates/PLAN.md`, поэтому текст называет именно его и ни одного
другого заголовка `## …` не упоминает — AC-4 краснеет на любом выдуманном
разделе.

Ветка `escalated` цикла `_drive_task` (счётчик `escalation_cycles`,
развилка бюджетной эскалации перед ним, порог
`config.CANARY_MAX_ESCALATION_CYCLES`) не трогается ни строкой —
требование 7, «Не входит» SPEC.

Потолок задачи из SPEC ($25) не переоценивается: правка — одна константа
текста, четыре константы якорей, одно предложение документа и один файл
тестов, ровно та оценка, из которой SPEC исходил.

## Шаги

1. **Текст ответа константами модуля** (`orchestrator/canary.py`):
   четыре константы-якоря + собранная из них
   `_SYNTHETIC_ANSWER_TEXT` в верхний блок литералов; тело
   `_pass_escalated_with_synthetic_answer` пишет в файл ответа эту
   константу вместо прежнего литерала; номер SPEC механизма — в
   докстринг функции.
2. **Предложение о синтетическом ответе** в `docs/stack.md`, раздел
   «### Набор ролей канарейки: `canary_sets:` и `canary --set`» —
   последним абзацем раздела, называя решение за ролью и запись
   допущения (требование 8, AC-9).
3. **Юнит-тесты** `tests/test_canary_synthetic_answer.py`: отсутствие
   идентификатора задачи, все четыре якоря, адрес раздела допущения,
   единственность текста на любом `escalated_from`, неизменность
   предохранителя. Корень и пути — `tests/sandbox.SchemaConnTmpRootTest`;
   каждый тест несёт строку «Ловит мутацию:».
4. Регенерация `docs/codebase-map.md` (`python3 scripts/codebase_map.py`)
   — правятся `*.py` под `orchestrator/` и `tests/`.
5. **Итерация 2 — замечания REVIEW.md итерации 1.** R1-F1: обобщённая
   половина AC-4 («любой названный текстом раздел `## …` существует в
   `templates/*.md`») переезжает из одной лишь залоченной планки в
   `tests/test_canary_synthetic_answer.py::test_assumption_addressed_to_
   existing_template_section` — планку после мержа не гоняет ни один
   джоб. R1-F2: второе предложение абзаца `docs/stack.md` сужается до
   смысловых эскалаций и называет бюджетную ветку отдельно (однократный
   подъём потолка, счётчик не двигается, исход «потолок исчерпан»).
   R1-F3: номер SPEC механизма читается из докстринга ВМЕСТЕ с
   комментариями тела функции — требование 3 и AC-6 допускают обе формы.
   Код `orchestrator/canary.py` шаг не трогает: ни одно из трёх замечаний
   не о нём.

Один MR: текст, предложение документа о нём и тесты на него — одна смена
механики, порознь не мержимы с зелёной планкой («Монолит» SPEC).

## Влияние на систему

**Что затрагивается за пределами правки.** Текст ответа уходит в
`orchestrator/answer.py::cmd_answer` и оседает телом `ANSWER-n.md`
артефактной ветки канареечной задачи. Оттуда его читают две механики:
`orchestrator/advance_gates/mandate.py` (строки мандата Оператора
«Расширение зон разрешено:», «Ослабление тестов разрешено:») и сама роль.
Новый текст ни одной строки мандата не несёт — проверено дословным
сравнением с `mandate._ZONES_MANDATE_MARKER`/
`mandate.TEST_WEAKENING_MANDATE_MARKER`; расширения прав роль из этого
ответа не получает, как и не получала из прежнего.

**Инварианты, гейты, лимиты рядом — и почему не ослабляются.**
`config.CANARY_MAX_ESCALATION_CYCLES` и ветка `escalated` цикла
`_drive_task` не редактируются; это же сторожит залоченная планка
(`test_escalation_cap_unchanged.py` сверяет значение порога с ТОЧКОЙ
РАСХОЖДЕНИЯ ветки и требует, чтобы ни одно ожидание
`DriveTaskEscalationCapTest`/`test_canary_budget_ceiling.py` не исчезло).
Учёт эскалаций (`_escalation_notes`, `_task_metrics`) и вердикт по
маркеру шаблона — не в диффе. Ни один существующий тест не ослабляется и
не удаляется: прежний текст ответа ни одним тестом `tests/` не
зафиксирован (SPEC, «Материалы»), поэтому правка ничьих ожиданий не
задевает. `templates/`, `skills/`, `roles.yaml`, `gates.yaml`,
`.github/` — только чтение.

**Как откатить.** Revert одного merge-коммита: дифф — три файла
(`orchestrator/canary.py`, `docs/stack.md`,
`tests/test_canary_synthetic_answer.py`) плюс регенерированная
`docs/codebase-map.md`, ни схемы БД, ни формата артефактов, ни состояния
на диске правка не создаёт.

## Риски

- Текст ответа читает МОДЕЛЬ роли, и его действенность (роль
  продолжает работу вместо повторной эскалации) юнит-тестом не
  проверяется — её покажет только следующий замер канарейки. Тесты
  закрывают наблюдаемые свойства текста (нет идентификатора, нет
  «варианта», якоря на месте, адрес допущения существует), не поведение
  модели на нём.
- Оговорка требования 5 («шаблон твоего артефакта такого раздела не
  несёт») останется верной, пока `templates/PLAN.md` — единственный
  шаблон с разделом «## Риски». Появление такого раздела в других
  шаблонах оговорку не сломает (она останется просто избыточной), а
  исчезновение его из `templates/PLAN.md` покраснит
  `test_assumption_addressed_to_existing_template_section` в `tests/` —
  то есть отслеживается механически, а не на честном слове. Сторож
  живёт именно в `tests/`, а не только в планке: планку после мержа не
  гоняет ни один джоб `.github/workflows/`, а править её нельзя (лок
  приёмочных тестов) — итерация 1 ревью поймала здесь ровно эту посылку
  (R1-F1).

## Предложения системе

- `orchestrator/canary.py` уже несёт девять согласованных литералов
  чужих модулей (`_ACCEPTANCE_TESTS_REFUSAL_ACTION`,
  `_BUDGET_ESCALATION_DETAIL_MARK`, `_AUTO_STOPPED_ACTION` и др.) —
  каждый со своим абзацем «почему копия, а не импорт». Класс
  «согласованный литерал вместо публичного имени» повторился достаточно
  раз, чтобы стоить отдельной задачи: одно место на пульте, где живут
  устойчивые части `action`/`detail` журнала, и импорт вместо копии.
- Класс «свойство кода сторожит только планка задачи» (R1-F1): планка
  залочена и после мержа не гоняется ни одним джобом, поэтому критерий,
  обобщающий свойство КОДА (а не факт этой задачи), обязан иметь
  двойника в `tests/`. Сегодня это правило узнаётся из скила ревьювера
  итерацией позже, чем пишется PLAN — ему место в
  `skills/coding-standards.md` и `skills/test-authoring.md`.

### Разбор diff тестов (главная проверка требования 3)

Diff в ревью-пакете усечён (4000 строк из 6127), поэтому тесты я сверял не по
нему, а по содержимому из git — покрытие полное, усечение проверку не сузило.

Метод: обе версии каждого теста нормализуются AST — квалификатор модуля
стирается (`config.LOGS` → `LOGS`, `Name(artel)` → `MOD`), импорты из
`orchestrator` отбрасываются, — после чего деревья сравниваются. Расхождение
означало бы правку сценария или ассерта.

Результат: за вычетом адресов расходятся только строковые литералы
docstring'ов, называющие местоположение функции — `artel.git` → `gitcmd.git`
(`test_agent_failure.py:31`, `test_auto_cycle.py:63`, `test_review_freshness.py`,
`test_step_cost.py`), `orchestrator.artel.slugify` → `orchestrator.catalog.slugify`
(`test_slugify.py:1`), `artel.now` → `store.now` и `artel.py` → `artifacts.py`
(`test_invariants.py`). Ни одного изменённого ассерта, сценария или `subTest`.

Формально docstring — не «строка импорта» и не «цель патча», то есть буква
требования 3 чуть уже сделанного. Считаю правку допустимой и не выношу
замечанием: это тот же класс «ссылка на модуль», который SPEC явно разрешил
для реестра в `docs/invariants.md`, а несделанная правка оставила бы тесты
врущими о местоположении кода. Последствия для проверяемого — нулевые.

Отдельно: в `test_auto_cycle.py` удалён однострочный хелпер
`AutoCycleTest.patch`, обёртка над `patch_object(artel, …)`. После разбивки
единственного модуля-владельца не существует, и все его вызовы стали
`patch_object(<модуль-владелец>, …)` — это и есть смена цели патча. Тела
тестов не тронуты.

Счётчики защищённых путей до/после: `docs/invariants.md` — 18 нумерованных
инвариантов, 33 строки таблиц; `test_invariants.py` — 27 тест-методов,
58 ассертов, 11 `subTest`, 0 skip. Все совпадают. По всем изменённым тестам:
237 тест-методов и 556 ассертов до и после.

### Системная целостность (ADR-0002)

Главный риск такого переезда — тест, который зеленеет вхолостую, потому что
подмена больше не доходит до кода. Проверил двумя способами.

1. `from .X import name` в пакете нет ни разу — все 12 внутренних импортов
   вида `from . import …`, то есть правило 1 PLAN выдержано без исключений.
2. Мутации в изолированном worktree, каждая откачена (все пять роняют тесты,
   то есть проверки живые):

| Мутация | Результат |
|---|---|
| гейт свежести вердикта снят (`artifacts.py`) | 8 падений |
| лимит ревью ослаблен `>=` → `>` (`fsm.py`) | 1 падение |
| блокировка по бюджету снята (`budget.py`) | 8 падений |
| `config.LOGS` скопирован по имени в `agent_log.py` | 9 падений + 2 ошибки |
| лимит `AUTO_MAX_STEPS` снят (`auto.py`) | 3 падения |

Отдельно проверил инвариант 12 (merge только из merge_gate): тест подменяет
`gitcmd.subprocess.run`, а merge живёт в `fsm`. Убедился, что
`gitcmd.subprocess is fsm.subprocess is subprocess` — объект один, подмена из
`gitcmd` реально перехватывает вызов из `fsm`, шпион не ослеп.

Ни один тест, гейт, лимит или guard не ослаблен и не удалён. Заявленная в
PLAN зона совпадает с фактическим diff.

Побочный вывод по CI: шаг `py_compile orchestrator/artel.py scripts/guard.py`
новые модули не компилирует, но `unittest discover` их импортирует, поэтому
синтаксическая ошибка в любом модуле по-прежнему валит CI. Job
`protected-paths` даст warning на `docs/invariants.md` и `test_invariants.py` —
это ожидаемо: правки согласованы SPEC, прошедшим гейт Оператора, а в Фазе 0
job и так деградирует до предупреждения.

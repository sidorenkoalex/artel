# ANSWER-1: ответ Оператора

## Ответы

1. A + C, как предложено: класс шаблона (быстрый/средний/трудный) —
   раздел шаблонов в `model_sets.yaml`, заполняет Оператор; шаблон без
   записи в «средний» и «трудный» не засчитывается и называется в
   перечне недостающего. «Неясность ТЗ» для analyst — по строке прогона
   (`expected_escalation` задан, `actual_escalation = 1`,
   `marker_mismatch = 0`).

2. A: чистый прогон — `verdict = green`, `review_iterations = 0`, нет
   эскалаций, кроме ожидаемой, `autogate_refusal` пуст или отнесён к
   пульту/пулу. Условие «без повтора developer» не проверяется; сводка
   команды допуска прямо пишет «повторы developer: нет данных».
   `orchestrator/canary.py` не трогать.

3. A: делить на три подзадачи в предложенном порядке — (1)
   `model_sets.yaml` и команда допуска; (2) набор задачи: `new --set`,
   разрешение модели и стоимость с учётом задачи, видимость,
   `set-models`; (3) пробный период и приостановка. Рамки частей и их
   зоны — в разделе «Деление» SPEC, с учётом ответов 4 и 5 ниже
   (условие трудного класса для набора целиком — в части 1 или 3, на
   усмотрение аналитика, с обоснованием). Часть 2 до мержа части 3 не
   должна позволять `new --set` вести задачу без пробного периода: либо
   часть 2 требует ручную приёмку для любой задачи с набором, пока нет
   части 3, либо порядок частей это исключает — выбрать и записать в
   SPEC.

4. B, не A: в `model_sets.yaml` — только решения Оператора (роль,
   модель, дата, основание, состояние, выставленное командой допуска).
   Пульт этот файл сам не коммитит. Счётчик пробных задач считается из
   БД (задачи в `done`, чей записанный состав набора содержит пару или
   набор). Автоматическая приостановка пишется в БД и перекрывает
   состояние файла до разбора Оператором; снимается командой Оператора.
   Основание: автоматические коммиты пульта в main из окна мержа —
   источник прошлых красных main и расхождения файла с состоянием.

5. B: работать строго по ADR-0019 п.5. ТЗ в этой части ошибочно слабее
   ADR и уступает ему. Набор допущен, если допущена каждая его пара,
   отличная от боевой, И набор целиком прошёл зелёный прогон канарейки
   на шаблоне трудного класса (класс — по ответу 1). Пробный период и
   его счёт — по набору («первые три настоящие задачи набора»), а не по
   паре. Правила приостановки — как в ADR. `docs/adr/` не менять.

6. A: при отзыве допуска пары задача в работе ведётся дальше на боевой
   модели этой роли с записью в журнал — то же правило, что при
   приостановке.

7. B: `set-models` разрешён только в `spec_gate`, `acceptance`,

   состояниях — отказ с перечнем допустимых.

# PLAN: П4: design-system + скил ui-standards

## Подход

Источник — РЕАЛЬНАЯ фактура стиля из двух артефактов
(`tasks/T080/mockup.html`, `orchestrator/report.py`), не изобретение с
нуля (SPEC требование 1). Сверил их построчно: базовые токены палитры
(`--bg`/`--panel`/`--border`/`--text`/`--muted`/`--accent`/
`--accent-soft`) и типографика в обоих совпадают дословно — это готовый
фундамент стандарта. Главное расхождение — то, что называет AC-2:
`mockup.html` кодирует состояния борда цветом через токены
`--ok`/`--warn`/`--danger`/`--killed` и классы `.col.<state>`,
`report.py` этих токенов и классов не несёт вовсе (ни в `:root`, ни в
`_STYLE`, ни в разметке `_board_html`/`_tile_html`). Нашёл ещё три
расхождения помельче при построчной сверке `_STYLE` против макета:
ширина колонки борда (значение, 168px vs 200px), состав свойств
`.col-head` (структурное — набор CSS-свойств правила), и присутствие
баннера/шапки-с-действиями/кнопок только в макете (не расхождение
стандарта, а следствие разного назначения read-only отчёта против
интерактивного макета).

Требование 4 SPEC и AC-7 задают чёткую границу того, что можно
исправить в `report.py` диффом этой задачи: только ЗНАЧЕНИЯ уже
существующих CSS-объявлений внутри уже существующих правил `_STYLE`, ни
одного нового/удалённого селектора или свойства, ни строчки кода вне
`_STYLE`. Из четырёх найденных расхождений этому критерию отвечает
ровно одно — ширина колонки борда (`min-width`/`flex` уже существуют в
правиле `.col`, меняется только число). Остальные три (цветовое
кодирование состояний, состав свойств `.col-head`, отсутствующие в
report.py интерактивные элементы) требуют добавления CSS-свойств/
селекторов и/или правки функций рендера — структурное изменение,
согласно AC-7 не применяется этой задачей, а фиксируется в
`docs/design-system.md` как норма для отдельной будущей задачи.
Проверил вручную: применение любого из этих трёх диффом сегодня либо
добавляет новые кастом-свойства в `:root` (для трёх токенов состояний,
которых там сейчас нет), либо добавляет CSS-свойства в существующее
правило (`.col-head`), либо трогает Python-код рендера вне `_STYLE`
(класс состояния в HTML тайла) — любой из трёх падает на
`test_ac7_code_outside_style_block_is_unchanged` или
`test_ac7_no_css_selector_or_property_added_or_removed`
(`tasks/T096/acceptance_tests/test_ac7_report_py_cosmetic_only.py`).

`docs/design-system.md` пишется одним компактным документом (палитра,
типографика, раскладка, состояния FSM, принципы самодостаточности,
источники, расхождения+нормы, граница «только светлая тема» — обе
`mockup.html` и `report.py` не содержат `prefers-color-scheme`, проверено
grep'ом обоих файлов). `skills/ui-standards.md` — новый файл в
`skills/` по мандату SPEC требование 3 / прецедент tasks/T093 —
инструкция роли: читать design-system.md, три запрета (CDN, сборка,
демоны этапа 1), явный чек «file:// без сети».

## Шаги

1. Написать `docs/design-system.md` по факту обоих источников: палитра
   (общие токены + токены состояний из mockup.html), типографика,
   раскладка борда/карточек/панелей, таблица состояний FSM с цветовым
   кодированием (норма mockup.html), принципы самодостаточности,
   явные ссылки на оба источника, раздел расхождений с предложенной
   нормой для каждого (включая обязательный минимум AC-2 — токены
   `--ok`/`--warn`/`--danger`/`--killed` и классы `.col.*`), явную
   фиксацию границы «только светлая тема» (AC-3).
2. Написать `skills/ui-standards.md` (новый файл, мандат SPEC
   требование 3): чтение design-system.md, запреты CDN/сборки/демонов
   этапа 1, чек file:// без сети (AC-4).
3. Применить единственное косметическое расхождение, укладывающееся в
   допуск AC-7, к `orchestrator/report.py`: ширина колонки борда
   `.col { min-width: 168px; flex: 0 0 168px; }` (было 200px) — только
   значения существующих объявлений внутри существующего правила `.col`,
   ни один селектор/свойство не добавлены и не удалены, код вне
   `_STYLE` не тронут. Отдельный юнит-тест на это значение НЕ заводится:
   `tasks/T096/acceptance_tests/test_ac8_no_new_ui_or_stage2.py`
   замыкает дифф задачи точным списком путей, `tests/*.py` в нём нет —
   правка `tests/test_report.py` красит AC-8 (проверено на практике:
   первая попытка добавить `StyleBoardColumnWidthTest` дала
   `AssertionError` с `tests/test_report.py` в списке лишних путей).
   Норма и мотивация значения — уже задокументированы содержательно в
   `docs/design-system.md` (раздел «Расхождения», пункт 2); механическое
   покрытие значения даёт сам приёмочный `test_ac7_report_py_cosmetic_only.py`
   (сравнивает `_STYLE` дословно с merge-base).
4. Прогнать `python3 scripts/guard.py --all`, полный `tests/` (без
   изменений в нём) и приёмочные `tasks/T096/acceptance_tests/` — все
   восемь AC зелёные.

## Влияние на систему

Диф ограничен четырьмя путями: два новых файла (`docs/design-system.md`,
`skills/ui-standards.md` — мандат на последний см. SPEC требование 3,
прецедент tasks/T093), одна косметическая правка значения внутри
`_STYLE` `orchestrator/report.py` (не задевает ни одну функцию рендера,
ни один существующий CSS-селектор/свойство — механически проверено
приёмочным `test_ac7_report_py_cosmetic_only.py`), артефакты
`tasks/T096/*`. `tests/` диффом НЕ затрагивается (см. шаг 3 — попытка
завести юнит-тест на значение `.col` красит локальный AC-8, объём
задачи её не допускает). Ни один существующий тест, гейт, лимит, guard
или инвариант не ослаблен и не удалён — только добавления и одно
числовое значение внутри уже существующего CSS-правила. `roles.yaml`/
`gates.yaml`/`templates/`/`.github/` не тронуты. `tasks/T080/mockup.html`
не тронут (AC-6). Диф правит `orchestrator/report.py` (`*.py`), поэтому
`docs/codebase-map.md` регенерируется этим же шагом командой
`python3 scripts/codebase_map.py` (скил conventions-core) — публичные
функции/сигнатуры модуля не меняются (правка внутри строкового литерала
`_STYLE`), изменение карты — только `built_at_sha`. Откат — `git revert`
коммита(ов) этой задачи: оба новых файла удаляются, значение `.col` в
`report.py` возвращается к 200px.

## Риски

- Токены `--ok`/`--warn`/`--danger`/`--killed` и классы `.col.<state>`
  остаются недостающими в `orchestrator/report.py` до отдельной будущей
  задачи — борд `report` пока визуально не отличает состояния цветом,
  как это делает утверждённый макет. Явно зафиксировано нормой и
  причиной (AC-7) в `docs/design-system.md`, не потеряно.

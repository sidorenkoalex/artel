# ТЗ: П4 — design-system и скил ui-standards

Источник: роадмап §3 «Панель», этап 1, строка П4 ($25, «до первых
UI-задач»). Фактура стиля уже существует: утверждённый макет
`tasks/T080/mockup.html` и живой `orchestrator/report.py` (T092) —
П4 систематизирует её в переиспользуемый стандарт.

Требуется:
1. `docs/design-system.md` — компактный стандарт UI-поверхностей
   пульта: палитра (включая тёмную/светлую тему, если макет её нёс),
   типографика, раскладка борда/карточек/блоков, состояния FSM
   и их цветовое кодирование, принципы (самодостаточный HTML, без
   JS-фреймворков и сборки, без внешних ресурсов).
   Источник — РЕАЛЬНЫЕ макет T080 и report T092, не изобретение
   с нуля; расхождения между ними — выявить и предложить норму.
2. Новый скил `skills/ui-standards.md` — инструкция роли для будущих
   UI-задач (report-доработки, панель Г0+): читает design-system,
   правила самодостаточности, запреты (CDN, сборка, демоны в этапе 1),
   чек «открывается file:// без сети».
3. Мандат на защищённый путь: `skills/ui-standards.md` — НОВЫЙ файл
   в no_paths-каталоге `skills/`; мандат выдаётся Оператором на
   spec_gate по механике T093, ограничен ровно этим одним файлом.
   Существующие скилы не трогать.
4. Привести `orchestrator/report.py` к зафиксированному стандарту
   ТОЛЬКО если расхождения косметические и локальные (класс
   «цвет/отступ»); структурные изменения report — вне объёма,
   отдельной задачей.

Не входит: демон/панель этапа 2; правки макета T080 (исторический
артефакт); новые UI-поверхности.

Рамка: $25.

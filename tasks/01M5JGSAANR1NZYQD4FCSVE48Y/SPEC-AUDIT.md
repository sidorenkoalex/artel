## Пути обхода гейтов
1. **Чужая планка у задачи вне границы.** Задача на компоненте Y без
   `report` (вне границы), test_author кладёт файл планки, который правило
   относит к X с `report`. Гейт FAIL_TO_PASS не добавляется вовсе
   (`fsm_advance.py:609` — `in_outcome_bounds(profile)` профиля задачи),
   до `criterion_files` дело не доходит. Требование 4 и AC-19 выполнены
   буквально (у задачи в границе), а файл X проходит без проверки. AC-19
   и AC-28 случай «Y вне границы, X в границе» не называют.
2. **Пакет ревьювера без строк потребителя.** Если компонент задачи вне
   границы, а потребитель в границе прогнан гейтом, фильтр
   `review.py:691` (`in_outcome_bounds(profile)` профиля задачи) вернёт
   `None`, и строк гейта потребителя в пакете не будет. Формулировка
   «фильтр заменяется только сменой источника» этот случай не решает.
   AC-18 проверяет только задачу в границе.
3. **Зона-каталог против `paths`-регэкспа.** «Путь зон задевает
   компонент» для каталога зоны (`frontend/src/`) против регэкспа `paths`
   (`^frontend/src/app/`) не определён: `re.search` по строке каталога
   может не совпасть. Исход fail-closed (отказ «не задевают ни одного»),
   обхода нет, но AC-1 поведение не закрепляет, и разработчик и
   test_author могут понять его по-разному.

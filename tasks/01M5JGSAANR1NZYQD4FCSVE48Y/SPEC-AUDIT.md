## Пути обхода гейтов

1. **`_external_helpers` на `decide`.** Если разработчик буквально пройдёт таблицу, `test_integrity.py:1299` останется на `decide`. Тогда гейт текста у задачи на компоненте судит внешние помощники в области по умолчанию, без отказа и без записи. Это ослабление без отказа.
2. **Мандат без условия границы.** Самая короткая реализация AC-13/AC-14 — «годен любой компонент записи». Она проходит все критерии и расширяет мандат на компоненты без `report`, где находку гейт исходов вообще не создаёт. Вред ограничен, но это расширение сверх решения 1-А.
3. **Долгоживущий файл чужого компонента** (`advance_gates/acceptance.py:288-289`) по-прежнему молча выпадает из FAIL_TO_PASS: требование 4 называет только файлы планки. На практике это держит гейт зон: файл чужого компонента в зонах даёт отказ «несколько компонентов». Исключение — маска `test_support` одного компонента, совпадающая с путём под другим компонентом.
4. **Проверка требования 4 привязана к границе.** Гейт FAIL_TO_PASS собирается только при `in_outcome_bounds(profile)` задачи (`fsm_advance.py:613`). Если проверку чужого файла встроить туда, у задачи на компоненте без `report` чужой файл планки пройдёт молча. Требование 4 («проверяется каждый файл планки») этого не уточняет, и учебный проект AC-22 этот случай не покрывает: оба его компонента в границе.
5. **Иных обходов не найдено.** Выбор компонента по зонам держит гейт зон; путь диффа вне компонентов расширяет выбор гейта до всех (`project_profile.py:453-454`); на мерже `_profile_refusal_exit` идёт первым.

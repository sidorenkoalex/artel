## Пути обхода гейтов
1. **Канарейка и гейт исходов по диффу.** Требование 3 для записи из
   нескольких компонентов задаёт границу только условием
   `in_outcome_bounds` профиля каждого компонента. У записи из одного
   компонента канарейку отсекает `_bounds` (`outcome_integrity.py:1017`),
   на мерже — `:1094`. Если реализовать буквально, гейт канарейки на
   такой записи начнёт исполняться либо писать запись пропуска. Это не
   ослабление, а расхождение с решением круга 3, п. 3 («у канарейки гейт
   исходов не исполняется»). Обхода проверки нет.
2. **Зона-каталог нового каталога.** Если под зоной-каталогом на базе нет
   файлов (каталог создаёт сама задача), компонент не задет, `decide_task`
   отказывает. Исход fail-closed, так и решено в круге 3, п. 7. Обхода нет,
   это заметка для Оператора: такую задачу ТЗ должно описывать зоной-файлом
   или зоной уже существующего каталога.

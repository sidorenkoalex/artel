# PLAN: G5а — документы `knowledge` компонента в брифе ролей внешнего проекта

## Подход
Вся правка — внутри `orchestrator/brief.py`, в `_project_conventions_parts`
и её помощниках; пять потребителей (developer, аудитор SPEC, аналитик,
test_author, пакет ревьювера) получают поведение без правки вызывающих
(требование 10).

- `_knowledge_of(target)` — `(имя компонента, элементы)` либо `None`:
  `project_profile.decide(target).profile` есть и `from_components`, затем
  `project_profile.components(target)` ровно из одного компонента с полем
  `knowledge`. `targets.TargetsError` из любого из двух вызовов — `None`
  (прежний вывод, сборка не падает; требование 9). Импорт
  `project_profile` — внутри функции: модуль тянет `acceptance` →
  `suite_lock` → `knowledge_cards` → `brief`, на уровне модуля это
  круговой импорт; зов — атрибутом модуля, его подменяют тесты.
- Состав дерева — новый помощник `_tree_entries` на `ls-tree -z`
  (`--literal-pathspecs`, имена без кавычек и escape — требование 3);
  на него же переведён листинг корня для `PROJECT_CONVENTIONS` — для
  ASCII-имён вывод тот же побайтно.
- Порядок: прежние куски `PROJECT_CONVENTIONS` (тексты и пометки не
  тронуты), затем элементы `knowledge` в порядке записи. Множество
  «показанных» путей пополняется до `render` (пропуск по размеру внутри
  `render` его не меняет); пути с пометкой туда не попадают. Элемент
  сводится к пути дерева `posixpath.normpath` (`./CLAUDE.md` → `CLAUDE.md`),
  признак каталога — «/» на конце записи.
- Элемент-файл: `ls-tree -z <sha> -- <путь>`; запись `blob` с режимом
  100644/100755 — `show`; `tree` — пометка «каталог — элемент-каталог
  пишется с «/» на конце»; 120000/160000 — «не обычный файл»; пусто —
  «файла нет»; сбой git / не UTF-8 — прежняя пометка «не прочитаны».
- Элемент-каталог: тот же `ls-tree` без `-r` определяет вид пути
  (`tree` / иное — «не каталог» / пусто — «файла нет»), затем
  `ls-tree -r -z`. Обычные `*.md` по пути, минус уже показанные, затем
  предел `KNOWLEDGE_DIR_MAX_FILES = 20`; M — число отобранных после
  повторов и предела, k — номер в этом отборе (номер сохраняется и у
  файла, чтение которого не удалось, — пометка «документ <k>» ссылается
  на тот же отсчёт). Строки «показаны первые …», «пропущено не обычных
  файлов: <n>» (n — все символьные ссылки и подмодули под каталогом),
  «файлов *.md нет» — после кусков каталога, путей из листинга не несут.
  Путь файла каталога — только первой строкой тела («путь: <путь>»),
  внутри границы.
- База не прочитана — одна прежняя пометка, перечень — `PROJECT_CONVENTIONS`
  и элементы `knowledge` (требование 8).

Оценка SPEC (25 USD) не пересматривается: один модуль, тесты уже
написаны test_author.

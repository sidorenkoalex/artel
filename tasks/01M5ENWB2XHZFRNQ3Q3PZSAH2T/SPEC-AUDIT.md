# SPEC-AUDIT: G5а — документы `knowledge` компонента в брифе ролей внешнего проекта

Круг 3. Решения Оператора на гейте SPEC (круги 1 и 2) прямо снимают
находки прошлых кругов: состав через `ls-tree -z`, фикстуры AC-10 с
`knowledge`, пути из листинга каталога только внутри границы, пометка

поднимаются. Ниже — только остаточные мелкие отклонения.

## Вердикт
**concerns.** Блокирующих отклонений нет. Остались мелкие
неоднозначности, которые Оператор может решить на гейте одной строкой
каждую:

1. **Каталог, все `*.md` которого убраны дедупом**
   (SPEC.md:73-86, AC-4 SPEC.md:172-176). Пример: элемент `./` или пара
   `docs/` + `docs/sub/`; `repo_paths` такие пути пропускает,
   targets.py:555-558. Строка «файлов *.md нет» задана только для
   каталога «без единого `*.md`». Для каталога, где `*.md` есть, но все
   уже показаны (M=0), вывод не задан: молчание, строка «файлов *.md
   нет» или иная строка. Не задано и то, считаются ли в N строки
   предела повторы: SPEC.md:75 говорит лишь, что повторы «убираются до
   отсчёта предела». Дефолт при молчании: M=0 — без строки; N — после
   дедупа.
2. **Документ каталога крупнее `CONTEXT_FILE_MAX_BYTES`**
   (SPEC.md:112-114). Путь файла живёт только первой строкой тела.
   `_manifest_component`/`render_component` (brief.py:472-473,
   context_package.py:25-37) и `artifact_part` (review.py:190-197) тело
   крупного компонента не выводят, а заголовок велит «читай <label>
   адресно». У файла каталога label — не путь, и роль не узнает, какой
   документ пропущен. Кроме того, строка «путь: …» входит в текст:
   size/sha256 описи в заголовке перестают совпадать с блобом файла.
   Это расходится с замыслом описи, context_package.py:33-35. Дефолт
   при молчании: принять как есть — документы `*.md` крупнее 128 КиБ
   редки.
3. **AC-7 зависит от окружения** (SPEC.md:199-201). Ложное «файла нет»
   без `-z` возникает лишь при `core.quotePath=true`, а это дефолт git.
   `gitcmd.pult_env` (gitcmd.py:147-157) этот ключ не задаёт. В
   окружении, где глобальный конфиг ставит `core.quotePath=false`, тест
   AC-7 пройдёт и на коде без `-z`. Требование 11 о детерминизме тестов
   (SPEC.md:138) это покрывает лишь косвенно. Дефолт при молчании:
   test_author изолирует глобальный конфиг git в тесте AC-7, например
   `GIT_CONFIG_GLOBAL` на пустой файл.
4. Форма строки «файла нет» для элемента `knowledge` не задана
   (SPEC.md:98). Неясно, какое `where` в ней стоит: «корень ветки …» у
   прежних или «knowledge компонента …» по образцу подписи. ТЗ форму
   тоже не фиксирует, так что это мелочь. Дефолт при молчании: «где» по
   образцу подписи элемента.

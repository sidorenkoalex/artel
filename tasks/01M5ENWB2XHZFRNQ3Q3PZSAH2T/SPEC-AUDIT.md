## Пути обхода гейтов
- **Тавтологичный эталон AC-9.** ТЗ и SPEC требуют эталон, «снятый с кода пина», но не говорят прямо, что это литерал в тесте. Тест, который снимает «эталон» вызовом той же `_project_conventions_parts` в момент прогона, буквально «снят» и ничего не ловит. Ревьювер это увидит, но в SPEC стоит одна фраза: эталон — зафиксированный литерал (или файл фикстуры) из тестов.
- **Дедуп по строке пути.** `repo_paths` пропускает `./CLAUDE.md`, `docs//a.md`, `docs/./` (`orchestrator/targets.py:555-558` отсекает только ведущий `/` и `..`). Буквальная реализация «путь уже показан» сравнением строк выведет `CLAUDE.md` второй раз. Найти тот же путь через `ls-tree` git при этом сумеет. Критерий AC-6 такой случай не проверяет.
- **Утечка имени через причину сбоя.** Если переиспользовать `_clone_git`, его причина — это stderr git (`orchestrator/brief.py:545-547`). Для `show <sha>:<путь>` stderr содержит путь файла. Пометка «конвенции проекта не прочитаны: <причина>» о файле из элемента-каталога вынесет имя из чужого листинга вне границы, а AC-2 этот путь не проверяет (отклонение 1).

## Вердикт
**concerns.** Решения Оператора круга 1 перенесены полностью, ссылки на код верны. Остались отклонения, которые Оператор может снять на гейте одной фразой.

1. **Сбой git и не-UTF-8 у файла из элемента-каталога.**
   - Требование 6 (SPEC.md:89) велит «прежнюю пометку» с записью журнала. Прежняя форма несёт путь: `f"{rel}: текст не в UTF-8"`, `f"{rel}: {reason}"` (`orchestrator/brief.py:578-583`), а причина `_clone_git` — stderr git с путём (`orchestrator/brief.py:545-547`).
   - Требование 7 (SPEC.md:101) запрещает путь из листинга каталога в пометках и журнале.
   - Форма пометки для такого файла не задана: например, «<элемент>, документ <k>: текст не в UTF-8», без stderr. Критерия на этот случай нет: AC-6 (SPEC.md:168) проверяет «прежнюю пометку», AC-2 (SPEC.md:138) — путь без сбоя.
   - Нужна форма пометки и сюда же — проверка в AC-2 или AC-6.
2. **«документ <k> из <M>»** (SPEC.md:98, :141): не сказано, что такое M при превышении предела — 20 (показано) или N (всего после дедупа). Разработчик и test_author могут прочитать по-разному.
3. **Сравнение путей при дедупе** (SPEC.md:52): не сказано, сравниваются строки записи или нормализованные пути дерева (`./CLAUDE.md`). `orchestrator/targets.py:555-558` такие элементы допускает.
4. **Эталон AC-9** (SPEC.md:183): не сказано, что эталон — литерал или фикстура в тесте, а не вызов кода в момент прогона. Без этого возможен тавтологичный тест.
5. **Мелочь, не блокирует.** «Текст которого включён в бриф выше» (SPEC.md:52) у developer и в пакете ревьювера пересекается с пределом размера: файл крупнее `CONTEXT_FILE_MAX_BYTES` текстом не включается (`orchestrator/brief.py:453`). Решение о дедупе принимается до `render`. На практике вреда нет: повторный кусок тоже был бы пропущен по размеру, но формулировка неточна.

Предлагаемые дефолты на гейте: 1 — пометка о файле каталога без пути и без stderr git, вида «конвенции проекта не прочитаны: каталог <элемент>, документ <k>: <класс причины>»; 2 — M = числу показанных; 3 — сравнивать пути дерева, как их вернул `ls-tree`; 4 — эталон — литерал в тесте.

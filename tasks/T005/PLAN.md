# PLAN: Лог агента в файл по ходу шага

## Подход

`cmd_run` сейчас зовёт `subprocess.run` без пайпов: вывод агента идёт
прямо в терминал Оператора и нигде не сохраняется (orchestrator/artel.py:352).
Чтобы получить и файл, и консоль, нужен пайп + собственная перекачка строк
(«tee»): `subprocess.Popen(stdout=PIPE, stderr=STDOUT, bufsize=1)` и цикл
`for line in proc.stdout`, который пишет строку и в `sys.stdout`, и в
лог-файл, открытый с построчной буферизацией (`buffering=1`). Именно
построчный режим даёт критерий приёмки 1 — `tail -f` видит строки до
конца шага.

Ключевые решения:

- **stderr сливаем в stdout** (`stderr=subprocess.STDOUT`), а не читаем
  вторым потоком: SPEC требует обе струи в одном файле, а порядок строк
  при слиянии на уровне ОС сохраняется без синхронизации в Python.
- **Перекачка — в отдельном потоке, ожидание процесса — в основном.**
  `for line in proc.stdout` блокируется, пока агент молчит, поэтому
  таймаут шага нельзя мерить внутри цикла: сегодняшние 30 минут
  (`subprocess.run(timeout=1800)`) выродились бы в «ждём вечно, если
  агент замолчал». Поток качает строки, основной делает
  `proc.wait(timeout=AGENT_TIMEOUT_SEC)` и убивает процесс по таймауту —
  наблюдаемое поведение таймаута то же, что и было.
- **Номер прогона N — из имён существующих файлов**, а не из БД: лог
  живёт в `.artel/logs/`, состояние прогонов уже есть на диске, лишняя
  колонка в схеме не нужна. Файл создаётся (`touch`) сразу при выборе
  имени — чтобы `tail -f` можно было запустить, не дожидаясь первой
  строки агента.
- Путь логов — модульная константа `LOGS` рядом с `DB`/`TASKS`, чтобы
  тесты подменяли её так же, как подменяют остальные пути (mock.patch.object).

Архитектурно значимого решения нет — ADR не требуется.

## Шаги

1. `orchestrator/artel.py`: константы `LOGS`, `AGENT_TIMEOUT_SEC`; функции
   `new_agent_log(task_id, role)` (каталог, инкремент N, touch) и
   `stream_to_log(stream, log_path)` (построчно в консоль и в файл);
   перевод `cmd_run` с `subprocess.run` на `Popen` + поток перекачки,
   печать пути лога и запись пути в журнал при старте шага.
2. `tests/test_agent_log.py`: юнит-тесты на имя файла с инкрементом,
   построчность записи и на `cmd_run` целиком (фейковый процесс).
   Правка `tests/test_review_freshness.py:188` — тест мокал
   `subprocess.run`, теперь мокает `Popen`.

Оба шага — один MR: тест на `cmd_run` не существует без нового `cmd_run`.

## Риски

- Строка без `\n` в конце (агент завис на промпте) не появится в логе,
  пока не придёт перевод строки, — итератор строк отдаёт хвост только
  при закрытии пайпа. Для наблюдаемости шага этого достаточно: агент
  пишет вывод строками; посимвольное чтение усложнило бы код без
  выигрыша по SPEC.
- Перекачка в отдельном потоке пишет в `sys.stdout` параллельно с
  основным потоком. В `cmd_run` основной поток в это время только ждёт
  процесс и ничего не печатает, а поток join-ится до печати итога, так
  что перемешивания строк нет.
- Незакрытый `.artel/logs/` растёт без ротации. Вне зоны задачи (SPEC
  «Не входит» про это молчит) — при необходимости отдельная задача.

# G3а-2а: гейт исходов на гейте мержа, пакет ревьювера, двусторонний прогон по имени ошибки

## Факты

Третья часть G3а волны G по ADR-0026 (`docs/adr/0026-project-components-and-outcome-gates.md`, «Решение» п. 6: гейт неослабления по исходам — на выходе из `in_dev` и на гейте мержа; двусторонний прогон — «упал на проверке» по имени ошибки из отчёта). Решения Оператора 20.10: гейт исходов на выходе из `in_dev` сделан G3а-1а (fe751fae), мандат по идентификатору — G3а-1б (идёт параллельно; обе задачи правят `orchestrator/advance_gates/outcome_integrity.py` — эта заводится после мержа G3а-1б); ошибки уровня файла, «новый модуль», запрет плагинов повторов pytest и переносы из приёмок — G3а-2б; записи по тестам в кэше итога — вне волны (бэклог). ## Требуется

1. **Запись пройденного гейта** `PASSED_ACTION` дополняется строкой `голова <sha40>; база <sha40>; ключ <ключ компонента>; мандат <отпечаток набора покрывших элементов>` после строки чисел (ключ компонента — `_report_suite_result_key` по дереву головы; отпечаток — sha256 отсортированных элементов мандата, покрывших находки, или «нет»). Прежние записи без этой строки доказательством не являются.
2. **Гейт исходов на маршруте мержа** — после того, как `_sync_main_or_wait` вернула «свежий main», и до `_acceptance_locks_refuse`. База — sha main, против которого шла сверка свежести (`_origin_main_sha`), а не повторный `diff_base`: `_checkouts` получает базу параметром (вызов на выходе из `in_dev` — прежний). Цель задачи и признак канарейки на мерже — из БД (`store.task_target`, строка задачи). Доказательство без прогона — запись `PASSED_ACTION` с той же головой, той же базой, тем же ключом компонента и тем же отпечатком мандата (текущего набора, покрывающего находки той записи); тогда — запись журнала «гейт исходов: доказан для головы <sha7> и базы <sha7>». Иначе — прогон.
3. **Исходы на мерже.** Находка без мандата, включая «сломан правкой», — `escalated` с текстом находок, действие журнала «merge отклонён: гейт неослабления по исходам», класс «чинит Оператор» в `REFUSAL_CLASSES`. Сбой подготовки (выписка, «не начат», таймаут, прочее исключение) — отказ без push, задача остаётся на `merge_gate` с подсказкой «повтори artel.py approve»; пропуска нет. `_full_suite_or_refuse` по дереву с применёнными приложениями — прежний (двойной прогон при приложениях — принятая цена). Гейт на мерже идёт под замком очереди мержа: до двух полных наборов плюс перепрогоны — ожидаемая задержка очереди.
4. **Пакет ревьювера.** Для профиля в границе раздел «Изменённые утверждения тестов» есть всегда и дополняется строками гейта исходов для текущей головы (по записи `PASSED_ACTION` с этой головой): числа тестов базы и ветки, находки, покрытые мандатом (идентификатор и ANSWER), «нестабилен и на базе», перепрогоны; записи нет — строка «гейт исходов для головы <sha7> не исполнялся». Вне границы — прежнее условие и текст побайтно.
5. **Двусторонний прогон по имени ошибки.** В `_run_side_report` для профиля в границе «упал на проверке» — только запись, для которой классификатор провала проверки даёт пусто; `failed` с другим именем, `error`, таймаут — «упал не на проверке» с видом; `passed` с повтором на любой стороне — не доказательство (сбой стороны с видом «повтор»). Классификатор `two_sided.py` берёт из `tests_writing.py` отложенным импортом, без переноса; поведение гейта FAIL_TO_PASS не меняется. Вне границы — прежнее побайтно.
6. **Утверждённое правило G3а-1а:** запись `passed` с повтором на перепрогоне базы — красная база, «нестабилен и на базе», находки нет (решение Оператора 20.10). Критерий.
7. Тесты детерминированы, без сети и без Node (учебный проект с компонентом `junit-xml` на подменённом раннере, сторона — по метке выписки): мерж — находка → `escalated` и действие журнала; сбой подготовки → задача на `merge_gate`, push не сделан; доказательство для той же четвёрки — без прогона; другая база, другой ключ компонента, отозванный мандат — прогон; прежняя запись без строки sha — прогон; база мержа — sha сверки свежести; пакет ревьювера — строки для головы, «не исполнялся», раздел у компонента без Python; двусторонний — `failed` с именем вне списка не «на проверке», `passed` с повтором — сбой стороны; правило п. 6. `tests/test_component_report_gates.py` — единственная правка: подмена нового шага в списке подмен помощника `merge`, без изменения утверждений; прочие существующие тесты (в том числе тесты планки G3а-1а, сверяющие числа записи `PASSED_ACTION` подмножеством) — без правок и зелёные.

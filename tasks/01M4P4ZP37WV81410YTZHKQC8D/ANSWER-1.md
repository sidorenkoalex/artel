Решение Оператора 11.10.2026.

7. **C.** Задача — только предпроверка `preflight`. Общий итог полного
   набора у `suite-run` и гейтов (пункты 5–6 ТЗ в части итога) из
   задачи исключается целиком: при любом из вариантов вопроса 1 итог,
   полученный процессом роли, создаёт риск обхода гейта полного набора
   (SPEC-AUDIT Е1, Е2), а свойство «гейт берёт только свои записи»
   (`tests/test_01m48wt5x7zc7332drh85vy19d_suite_reuse.py::SuiteReuseTest::test_ac12_suite_run_record_is_not_gate_result`)
   сохраняется без изменений. `orchestrator/suite_run.py` и
   `orchestrator/acceptance.py` — только чтение. В «Не входит» SPEC —
   строка об этом. `budget_usd` — по калибровке, не выше 50.

1, 2, 6. Сняты ответом 7.

3. **A.** Предпроверка зовёт те же публичные ядра `guard.*`
   (трассируемость, маркер красноты, образец id, `check_content`);
   `orchestrator/fsm.py` не меняется; сторож сверяет, что предпроверка и
   переход зовут одно ядро; сверка незакоммиченного результата шага —
   «не проверяется».

4. **A для `code_copy`** (только наличие уже заведённой копии и её
   ветка, ничего не заводя; нет копии — отказ тем же текстом);
   **B для `test_groups`** («не проверяется предпроверкой: требует
   выкладки планки»).

5. **A.** Общая точка — объявленный реестр шагов выхода (имя,
   вызываемое, признак «исполняется предпроверкой» либо причина «не
   проверяется»); обёртки `_*_gate_refuses` остаются с прежними именами
   и сигнатурами; `tests/test_zones_gate.py`,
   `tests/test_capacity_gate.py`, `tests/test_fsm_review_rework_gate.py`,
   `tests/test_fsm_advance_gate_smoke.py` не правятся и остаются
   зелёными.

и итога полного набора (они уходят вместе с ответом 7): журнал не

`materialize_from_branch`); работа при БД только на чтение и под
песочницей Codex; вывод `in_dev` предупреждает о проверке без

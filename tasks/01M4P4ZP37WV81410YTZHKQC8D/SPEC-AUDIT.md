## Пути обхода гейтов
Гейт перехода обойти нельзя: переход сам проверяет всё заново, а
preflight только советует. Ниже — места, где буквальное исполнение SPEC
расходится с её смыслом.

- **О3.** Подсчёт вызовов несимметричен. Правило подсчёта для
  `preflight.py` — «обращение `guard.<имя>`» (SPEC.md:177–179). Оно
  захватывает константы. Для перехода сказано «зовёт» (SPEC.md:167–176).
  - preflight повторяет строку ошибки перехода
    (`tests_writing.py:454–457`) через `guard.GROUP_LONG_LIVED`, а сторож
    считает у перехода только вызовы. Тогда правильная реализация
    краснит сторож.
  - Обход для разработчика — захардкодить «долгоживущий». Тогда сторож
    не поймает, что константа в guard сменилась.
  - Сторож заставит preflight звать `guard.acceptance_test_files`, но
    SPEC его не называет. Эта функция рекурсивна (`guard.py:2898`).
    Вызвать её на каталоге документов без последующего фильтра — и
    вложенный файл попадёт в проверку строки группы. AC-2 поймает это,
    только если у вложенного файла тестового набора нет строки группы.

# SPEC: G2а-2 — выкладка планки компонента по `plank_layout` и `plank-run` по правилу планки

## Контекст
Вторая половина G2а волны G (ADR-0026, «Решение» п. 5; «Порядок исполнения», строка G2а). Правило планки уже построено G2а-1: `project_profile.plank_rule(target)` возвращает `guard.PlankRule` (`refusal`, `owns`, `component_of`, `is_test`, `masks` — `scripts/guard.py:2620`), `Profile` несёт поля `tests` и `plank_layout` (`orchestrator/project_profile.py:104-108`); эта задача правило вызывает и не меняет. Сегодня выкладка планки есть только у `runner: pytest-own` под `long_lived_dir/.artel-plank` (`orchestrator/acceptance.py:1172-1282`, подкаталог `acceptance_tests`); признак выкладки — `runner`, а не команда (`_own`, `orchestrator/acceptance.py:121`). Компонент `pult-vitest` с `workdir` обязан нести `runner: pytest-own` (`orchestrator/targets.py:421-428`) и потому сегодня получает выкладку под `long_lived_dir/.artel-plank` (фикстура `tests/test_01m590gjaf0edv4nbc4c99mfvh_report_outcome.py:557-585`); компонент без `runner: pytest-own` выкладки не получает, и его планка гонится из `tasks/<id>/acceptance_tests` рабочей копии. `plank-run` проверяет наличие тестов и `[файл]` только по маске `test_*.py` (`orchestrator/plank_run.py:61-77`, `:186-195`). Шаблон `plank_layout` запись проверяет лишь на `<id>` в любом сегменте (`orchestrator/targets.py:493-510`), так что форма пути при прогоне не гарантирована.

## Требования

1. **Отказ правила.** Правило планки проекта задачи с непустым `refusal` (например компонент `pult-vitest` без `tests`) — отказ подготовки прогона и `plank-run` с этим текстом; прогон не запускается, исход не зелёный.
2. **Выкладка по `plank_layout`.** У профиля с полем `plank_layout` файлы планки его компонента на время прогона копируются прямо в `<plank_layout>` рабочей копии кода — без подкаталога `acceptance_tests`; `<id>` подставляется как `task_id` как есть (как в `_layout_root`, `orchestrator/acceptance.py:1196`). Файл компонента: у правила по умолчанию — `rule.owns(name)`, иначе `rule.component_of(name) == profile.component`. Общие файлы (`guard.SHARED_PLANK_FILE`) и файлы `.md`/`.txt` в выкладку не кладутся. Помощник `_pult.py` кладётся только у компонента с командой pytest (`acceptance.is_pytest_command`), у прочих — нет.
3. **Форма `plank_layout`.** Подготовка отказывает (прогон не запускается, исход не зелёный) с дословными текстами:
   - в `plank_layout` есть сегмент «.», «..» или пустой сегмент (например `a/./<id>`, `.artel-plank/../src/<id>`): «plank_layout должен быть нормализованным путём без «.» и «..»»; остальные проверки этого списка, в том числе «родитель с точки», идут по нормализованному пути;
   - последний сегмент `plank_layout` (до подстановки `task_id`) не равен в точности «<id>»: «<id> должен быть последним сегментом plank_layout»;
   - путь вне `workdir` компонента (пустой `workdir` — корень репозитория), сверка по `realpath`, как в `_own_cwd` (`orchestrator/acceptance.py:214-229`): «plank_layout вне рабочего каталога компонента <имя>»;
   - последний сегмент перед `<id>` (родитель) не начинается с точки (`.artel-plank` — допустим, `src` — нет): «родитель <id> в plank_layout должен быть скрытым каталогом (имя с точки)»; так шаблон `/<родитель>/` в `info/exclude` не прячет файлы кода;
   - в родителе `<id>` есть отслеживаемые git файлы (`git ls-files` не пуст): «в каталоге <родитель> есть отслеживаемые git файлы — выкладка спрятала бы их».
4. **Скрытие и уборка выкладки.** До записи файлов в `info/exclude` клона дописывается шаблон `/<родитель <id>>/` от корня репозитория — тем же замком, что `_exclude_pattern` (`orchestrator/acceptance.py:1211`). Уборка выкладки — в `finally` прогона на любом исходе и в `drop_from_code_copy` (`orchestrator/acceptance.py:1907`): `drop_from_code_copy` убирает остаток выкладки `plank_layout` (файлы и каталог `<id>`; родитель — если после этого он пуст) и не трогает файлы кода в родителе и вне его.
5. **Порядок правил выкладки.** Правила применяются в таком порядке:
   - поле `plank_layout` задано — выкладка по `plank_layout` (требования 2–4);
   - не задано, и команда компонента — pytest (`acceptance.is_pytest_command`), — прежняя выкладка под `long_lived_dir` побайтно (тот же путь, те же файлы, прежний `LAYOUT_OUTSIDE_NOTE`);
   - не задано, команда — не pytest, профиль — компонент из поля `components:` записи проекта с `report`, отличным от `pult-pytest`, и в планке есть файлы этого компонента по правилу (выкладка файлов планки компонента), — отказ подготовки «у компонента <имя> нет plank_layout — выкладка планки не определена».
   Случай решается по команде, а не по `runner`: профиль `pult-vitest` с `runner: pytest-own` без `plank_layout` подпадает под третий случай. Записи `test_profile` третьим случаем не задеваются никогда — у них прежнее поведение (требование 9). Отказ третьего случая не возникает там, где файлы планки компонента не выкладываются, — эти пути прежние побайтно: `plank-run` долгоживущего файла (`orchestrator/plank_run.py:221-229`) и прогон только `extra` без файлов планки (`orchestrator/acceptance.py:1337-1339`). Проверка требования 6 («файлов компонента в планке нет») идёт после этого отказа.
6. **Цели прогона.** Цели `run` (`orchestrator/acceptance.py:1283`), `collect` (`:1460`), `run_plank` (`:1951`) — выложенные файлы компонента; у `pult-vitest` — через `select` (`_subset_args`, `:688`). Если файлов компонента в планке нет (только `.md`/`.txt`) — у `run`/`collect` тот же исход, что «планка не заведена»; у `plank-run` — прежний отказ, с маской `tests` компонента у правила не по умолчанию (требование 8).
7. **Исключение остатка выкладки.** `--ignore` добавляется только при команде pytest (`acceptance.is_pytest_command`). У компонента `runner: pytest-own` с `plank_layout` и командой pytest — `--ignore=<plank_layout до <id>>` вместо `--ignore=<long_lived_dir>/.artel-plank` в `_report_argv` (`orchestrator/acceptance.py:719`, флаг — `:752-754`) и в полном наборе `pytest-own` (`:2307-2311`); путь до `<id>` переводится к рабочему каталогу компонента тем же приёмом, что `_own_target` (`orchestrator/acceptance.py:753-754`, `:2310-2311`). У pytest-компонента без `runner: pytest-own` `--ignore` — как сейчас, без изменений (`orchestrator/acceptance.py:745`, `:750-754`); у `pult-vitest` и у любого `pytest-own` с командой не pytest флага нет. Остаток в этих случаях убирает `drop_from_code_copy`.
8. **`plank-run` по правилу.** Наличие тестов и выбор `[файл]` в `plank-run` — по `plank_rule` проекта задачи: у правила по умолчанию (`rule.masks()` пуст — артель и запись из одного pytest-компонента) текст отказа прежний побайтно, с маской `test_*.py`; маска `tests` компонента в тексте отказа — только у правила не по умолчанию. `[файл]::узел` у компонента, чья команда не pytest, — отказ «узел :: у компонента <имя> не поддерживается; передай файл». Сводка итога («итог pytest: …») не меняется.
9. **Прежнее поведение артели и `test_profile`.** У артели (`pult-pytest`) и у записей `test_profile` (sled сегодня) выкладка, аргументы прогонов, тексты и вывод `plank-run` — прежние. Тестами до правки закрепляются (значения — по main `c2dc427f`):
   - `LAYOUT_OUTSIDE_NOTE` (`orchestrator/acceptance.py:1177`): «long_lived_dir профиля «{lld}» лежит вне workdir «{workdir}» — планка идёт прежним путём из tasks/<id>/acceptance_tests, без выкладки»;
   - отказы `_exclude_pattern` (`orchestrator/acceptance.py:1211-1239`): «отказ {what}: git не назвал info/exclude рабочей копии {code_root} ({detail}) — pytest не запускался» и «отказ {what}: {path} не записан ({exc}) — pytest не запускался», у выкладки `pytest-own` — с `what` = «выкладки планки» и шаблоном `**/.artel-plank/`;
   - отказы `plank-run` (`orchestrator/plank_run.py:186-195`): «<head>: отказ — планки нет: в источнике (<source>) нет файлов test_*.py; pytest не запускался» и «<head>: отказ — файла <файл> нет в планке (<source>); в ней: <имена через запятую>»;
   - argv полного набора `pytest-own` с выкладкой (`orchestrator/acceptance.py:2307-2313`): цели с `long_lived_dir` вместо `tests` и `--ignore=<long_lived_dir>/.artel-plank` (через `_own_target`); то же `--ignore` в `_report_argv` (`:752-754`).
10. **Тесты.** Детерминированы, без сети и без Node: учебный проект с двумя компонентами (`junit-xml` на pytest и `pult-vitest` с подменённым раннером, пишущим заранее заданный отчёт) проверяет выкладку каждого компонента, отказы требований 1, 3, 5 и argv требования 7; сквозные `run`, `collect`, `plank-run` — на записях `components:` из одного компонента каждого вида. Пути `run`, `collect`, `run_plank` с `plank_layout` закрываются новыми тестами этой задачи, по одному на каждую функцию. Существующие `test_ac11_unknown_is_never_green_at_any_place` и `test_ac16_node_modules_read_only_shared_and_substitution_refused` (`tests/test_01m590gjaf0edv4nbc4c99mfvh_report_outcome.py:898`, `:1454`) не меняются: они проверяют профили без `plank_layout` и остаются верными.

## Критерии приёмки

AC-1. Прогон планки компонента `pult-vitest` идёт из `<plank_layout>` внутри `workdir` компонента (файлы компонента лежат прямо в `<plank_layout>`, без подкаталога `acceptance_tests`, и переданы раннеру через `select`); выкладка не видна `git status` рабочей копии и убрана после красного исхода, после зелёного исхода и после исключения в прогоне.

AC-2. Выкладка компонента содержит только его файлы планки: общие файлы (`guard.SHARED_PLANK_FILE`) и `.md`/`.txt` в неё не попадают; помощник `_pult.py` есть в выкладке компонента `junit-xml` на pytest и отсутствует в выкладке `pult-vitest`.

AC-4. AC-5. AC-6. У компонента `junit-xml` на pytest с `runner: pytest-own`, непустым `workdir` и `plank_layout` полный набор и прогон по отчёту (`_report_argv`) получают `--ignore=` с путём до `<id>` (родителем), переведённым к рабочему каталогу компонента (как в `_own_target`), и не получают `--ignore=…/.artel-plank`; то же у компонента `runner: pytest-own` без `report` с командой pytest и `plank_layout` в ветке полного набора `pytest-own` (`orchestrator/acceptance.py:2307-2311`); у pytest-компонента без `runner: pytest-own` аргументы `--ignore` прежние; у `pult-vitest` и у `pytest-own` с командой не pytest флага `--ignore` нет.

# SPEC: G2а-2 — выкладка планки компонента по `plank_layout` и `plank-run` по правилу планки

## Контекст
Вторая половина G2а волны G (ADR-0026, «Решение» п. 5; «Порядок исполнения», строка G2а). Правило планки уже построено G2а-1: `project_profile.plank_rule(target)` возвращает `guard.PlankRule` (`refusal`, `owns`, `component_of`, `is_test`, `masks` — `scripts/guard.py:2620`), `Profile` несёт поля `tests` и `plank_layout` (`orchestrator/project_profile.py:104-108`); эта задача правило вызывает и не меняет. Сегодня выкладка планки есть только у `runner: pytest-own` под `long_lived_dir` (`orchestrator/acceptance.py:1172-1282`, подкаталог `acceptance_tests`); компонент `pult-vitest` выкладки не получает, и его планка гонится из `tasks/<id>/acceptance_tests` рабочей копии — вне `workdir` компонента. `plank-run` проверяет наличие тестов и `[файл]` только по маске `test_*.py` (`orchestrator/plank_run.py:61-77`, `:186-195`). Шаблон `plank_layout` запись проверяет лишь на `<id>` в любом сегменте (`orchestrator/targets.py:493-510`), так что форма пути при прогоне не гарантирована.

## Требования

1. **Отказ правила.** Правило планки проекта задачи с непустым `refusal` (например компонент `pult-vitest` без `tests`) — отказ подготовки прогона и `plank-run` с этим текстом; прогон не запускается, исход не зелёный.
2. **Выкладка по `plank_layout`.** У профиля с полем `plank_layout` файлы планки его компонента на время прогона копируются прямо в `<plank_layout>` рабочей копии кода — без подкаталога `acceptance_tests`; `<id>` подставляется как `task_id` как есть (как в `_layout_root`, `orchestrator/acceptance.py:1196`). Файл компонента: у правила по умолчанию — `rule.owns(name)`, иначе `rule.component_of(name) == profile.component`. Общие файлы (`guard.SHARED_PLANK_FILE`) и файлы `.md`/`.txt` в выкладку не кладутся. Помощник `_pult.py` кладётся только у компонента с командой pytest (`acceptance.is_pytest_command`), у прочих — нет.
3. **Форма `plank_layout`.** Подготовка отказывает с текстом (прогон не запускается, исход не зелёный), если: `<id>` — не последний сегмент `plank_layout`; путь вне `workdir` компонента (пустой `workdir` — корень репозитория); в родителе `<id>` есть отслеживаемые git файлы (`git ls-files` не пуст).
4. **Скрытие и уборка выкладки.** До записи файлов в `info/exclude` клона дописывается шаблон `/<родитель <id>>/` от корня репозитория — тем же замком, что `_exclude_pattern` (`orchestrator/acceptance.py:1211`). Уборка выкладки — в `finally` прогона на любом исходе и в `drop_from_code_copy` (`orchestrator/acceptance.py:1907`).
5. **Без `plank_layout`.** Компонент, чья команда не pytest, с отчётом и без `plank_layout` — отказ подготовки с текстом «у компонента <имя> нет plank_layout — планку выложить некуда». `pytest-own` без `plank_layout` — прежняя выкладка под `long_lived_dir` и прежний `LAYOUT_OUTSIDE_NOTE`.
6. **Цели прогона.** Цели `run` (`orchestrator/acceptance.py:1283`), `collect` (`:1460`), `run_plank` (`:1951`) — выложенные файлы компонента; у `pult-vitest` — через `select` (`_subset_args`, `:688`). Если файлов компонента в планке нет (только `.md`/`.txt`) — у `run`/`collect` тот же исход, что «планка не заведена»; у `plank-run` — прежний отказ, с маской `tests` компонента.
7. **Исключение остатка выкладки.** У компонента с `plank_layout` и командой pytest — `--ignore=<plank_layout до <id>>` вместо `--ignore=<long_lived_dir>/.artel-plank` в `_report_argv` (`orchestrator/acceptance.py:719`, флаг — `:752-754`) и в полном наборе `pytest-own` (`:2307-2311`); у `pult-vitest` флага нет, остаток убирает `drop_from_code_copy`.
8. **`plank-run` по правилу.** Наличие тестов и выбор `[файл]` в `plank-run` — по `plank_rule` проекта задачи: у артели отказ «нет файлов test_*.py» прежний; у компонента — с маской `tests` компонента. `[файл]::узел` у компонента, чья команда не pytest, — отказ «узел :: у компонента <имя> не поддерживается; передай файл». Сводка итога («итог pytest: …») не меняется.
9. **Прежнее поведение артели и `test_profile`.** У артели (`pult-pytest`) и у записей `test_profile` (sled сегодня) выкладка, аргументы прогонов, тексты и вывод `plank-run` — прежние. Тестами до правки закрепляются (значения — по main `c2dc427f`):
   - `LAYOUT_OUTSIDE_NOTE` (`orchestrator/acceptance.py:1177`): «long_lived_dir профиля «{lld}» лежит вне workdir «{workdir}» — планка идёт прежним путём из tasks/<id>/acceptance_tests, без выкладки»;
   - отказы `_exclude_pattern` (`orchestrator/acceptance.py:1211-1239`): «отказ {what}: git не назвал info/exclude рабочей копии {code_root} ({detail}) — pytest не запускался» и «отказ {what}: {path} не записан ({exc}) — pytest не запускался», у выкладки `pytest-own` — с `what` = «выкладки планки» и шаблоном `**/.artel-plank/`;
   - отказы `plank-run` (`orchestrator/plank_run.py:186-195`): «<head>: отказ — планки нет: в источнике (<source>) нет файлов test_*.py; pytest не запускался» и «<head>: отказ — файла <файл> нет в планке (<source>); в ней: <имена через запятую>»;
   - argv полного набора `pytest-own` с выкладкой (`orchestrator/acceptance.py:2307-2313`): цели с `long_lived_dir` вместо `tests` и `--ignore=<long_lived_dir>/.artel-plank` (через `_own_target`); то же `--ignore` в `_report_argv` (`:752-754`).
10. **Тесты.** Детерминированы, без сети и без Node: учебный проект с двумя компонентами (`junit-xml` на pytest и `pult-vitest` с подменённым раннером, пишущим заранее заданный отчёт) проверяет выкладку каждого компонента, отказы требований 1, 3, 5 и argv требования 7; сквозные `run`, `collect`, `plank-run` — на записях `components:` из одного компонента каждого вида.

## Критерии приёмки

AC-1. Прогон планки компонента `pult-vitest` идёт из `<plank_layout>` внутри `workdir` компонента (файлы компонента лежат прямо в `<plank_layout>`, без подкаталога `acceptance_tests`, и переданы раннеру через `select`); выкладка не видна `git status` рабочей копии и убрана после красного исхода, после зелёного исхода и после исключения в прогоне.

AC-2. Выкладка компонента содержит только его файлы планки: общие файлы (`guard.SHARED_PLANK_FILE`) и `.md`/`.txt` в неё не попадают; помощник `_pult.py` есть в выкладке компонента `junit-xml` на pytest и отсутствует в выкладке `pult-vitest`.

AC-3. Правило планки с непустым `refusal` — отказ подготовки прогона и `plank-run` с текстом этого `refusal`; прогон не запускается, исход не зелёный.

AC-4. `plank_layout` вне `workdir` компонента, с `<id>` не последним сегментом, с отслеживаемыми git файлами в родителе `<id>` — каждый случай даёт отказ подготовки с текстом; прогон не запускается, исход не зелёный.

AC-5. Компонент, чья команда не pytest, с отчётом и без `plank_layout` — отказ подготовки с текстом «у компонента <имя> нет plank_layout — планку выложить некуда»; исход не зелёный.

AC-6. У компонента `junit-xml` на pytest с `plank_layout` полный набор и прогон по отчёту (`_report_argv`) получают `--ignore=<родитель <id>>` и не получают `--ignore=…/.artel-plank`; у `pult-vitest` флага `--ignore` нет.

AC-7. Планка, в которой у компонента нет своих файлов (только `.md`/`.txt`), даёт у `run`/`collect` тот же исход, что «планка не заведена»; `plank-run` в этом случае отказывает с маской `tests` компонента.

AC-8. `plank-run` у компонента `pult-vitest` видит файлы `*.test.jsx` планки как тесты (не отказывает «нет файлов test_*.py») и принимает их как `[файл]`; на `[файл]::узел` отказывает текстом «узел :: у компонента <имя> не поддерживается; передай файл».

AC-9. У артели (`pult-pytest`) и у записи `test_profile` перечисленные в требовании 9 тексты (`LAYOUT_OUTSIDE_NOTE`, отказы `_exclude_pattern`, отказы `plank-run` «нет файлов test_*.py» и «файла … нет в планке»), argv полного набора `pytest-own` и `_report_argv` с `--ignore=<long_lived_dir>/.artel-plank`, выкладка под `long_lived_dir/.artel-plank/<id>/acceptance_tests` и исходы прогонов — прежние.

Прогноз диффа: 45 КиБ (из них около двух третей — тесты учебного проекта с двумя компонентами).

**Обоснование монолита** (материал для решения Оператора): ТЗ уже является второй частью деления G2а (первая — G2а-1, в main). Выкладка по `plank_layout` (требования 2–4), исключение её остатка из полного набора (требование 7) и цели прогона (требование 6) — одна механика: выкладка без `--ignore` оставляет в полном наборе pytest-компонента чужие файлы планки после обрыва, а `--ignore` без выкладки не имеет предмета; цели `run`/`collect`/`run_plank` без выкладки указывали бы на несуществующие файлы. `plank-run` по правилу (требование 8) опирается на ту же выкладку — отдельно мержить её можно, но она займёт отдельную задачу с теми же тестами учебного проекта и не уменьшит основную.

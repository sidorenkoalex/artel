## Пути обхода гейтов
1. **Сегмент `.` проходит проверку «родитель — скрытый каталог».** `_template_path_error` запрещает `..` и пустые сегменты, но не `.` (`orchestrator/targets.py:498-501`). Пример: `plank_layout: web/build/./<id>`:
   - родитель `.` «начинается с точки» — проверка требования 3 пройдена;
   - путь внутри `workdir` по `realpath`;
   - `git ls-files web/build/.` пуст, если `build` не отслеживается;
   - шаблон `/web/build/./` в `info/exclude` git не нормализует, и он не совпадёт ни с одним путём.

   Итог: выкладка видна `git status`, а чекпоинт `git add -A` унесёт её в ветку. Это нарушает AC-1, хотя каждый пункт требования 3 выполнен буквально. Нужна проверка по нормализованному пути (или запрет сегмента `.`) и шаблон от нормализованного родителя.
2. **«`<id>` — последний сегмент» не определено для `<id>` внутри сегмента** (`.../x-<id>`) и для `<id>` в нескольких сегментах. Буквальное исполнение может пропустить `.artel-plank/<id>-old` (родитель — тот же скрытый каталог, `<id>` — «в последнем сегменте»). Тогда уборка «каталога `<id>`» по требованию 4 и AC-10 не определена. Достаточно уточнить: «последний сегмент равен `<id>`».
3. **Область отказа «нет plank_layout» (требование 5) не ограничена прогоном выложенной планки.** Сегодня выкладка есть только при наличии планки: `run`/`collect` — `own if plank_present(tests_dir) else None` (`orchestrator/acceptance.py:1349-1350`, `:1507-1508`), `run_plank` — только с `task_id` (`:1976-1977`). Буквальное «отказ подготовки» для любого прогона компонента сломало бы:
   - `plank-run <долгоживущий файл>` у `pult-vitest` — `run_plank` без `task_id`, `orchestrator/plank_run.py:221-229`;
   - прогон только долгоживущих файлов `extra` при пустой планке (`:1337-1339`).

   Порядок требования 5 и требования 6 («файлов компонента нет — исход „планка не заведена“») тоже не задан. Нужно: третий случай требования 5 действует, только когда есть что выкладывать (планка с файлами компонента и `task_id`), иначе — прежний путь.
4. **Отказ `plank-run` «с маской `tests` компонента» (требование 8, AC-7) не определён у записи с одним pytest-компонентом.** Правило такой записи — умолчание (`orchestrator/project_profile.py:482-488`), `masks()` у умолчания пуст (`scripts/guard.py:2668-2672`). Исполнитель может напечатать пустую маску. Достаточно сказать: у правила по умолчанию текст прежний, «нет файлов test_*.py».

# SPEC-AUDIT: G2а-2 — выкладка планки компонента по `plank_layout` и `plank-run` по правилу планки

## ТЗ и SPEC
Пункты ТЗ 1–7, критерии приёмки, решения по умолчанию и «Не входит» перенесены в SPEC (требования 1–10, AC-1..AC-9, «Не входит»). ANSWER-n.md и решений Оператора на гейте SPEC нет. Требований сверх ТЗ нет.

Перенос в одном месте неполный. ТЗ п. 1 и SPEC требование 2 задают выкладку «у профиля с полем `plank_layout`», а ТЗ п. 2 и SPEC требование 5 называют два случая без `plank_layout`. Ни ТЗ, ни SPEC не говорят, какое правило старше, когда профиль попадает под оба случая (подробно — отклонение 1 в «Фактах против кода»). Ошибка пришла из ТЗ, но SPEC её не разрешил, а повторил («Контекст», SPEC.md:16).

Не подтвердилось:
1. **«Компонент `pult-vitest` выкладки не получает, и его планка гонится из `tasks/<id>/acceptance_tests` … вне `workdir`»** (SPEC.md:16, повтор ТЗ) — неверно для компонента с `workdir`.
   - У единственного компонента поле `workdir` допустимо только при `runner: pytest-own` (`orchestrator/targets.py:73`, `:421-428`).
   - `_own()` (`orchestrator/acceptance.py:121-124`) смотрит только на `runner`, вид отчёта не учитывает.
   - Поэтому `run`/`collect` (`:1341`, `:1349-1350`, `:1499`, `:1507-1508`) и `run_plank` (`:1970`, `:1976-1977`) уже сегодня выкладывают планку такого `pult-vitest` под `<long_lived_dir>/.artel-plank/<id>/acceptance_tests`, когда `long_lived_dir` лежит внутри `workdir`. Учебная фикстура main так и устроена: `tests/test_01m590gjaf0edv4nbc4c99mfvh_report_outcome.py:557-585` (`runner: pytest-own`, `workdir: web…`, `long_lived_dir: web…/src`).
   - Следствие — коллизия в требовании 5 (SPEC.md:28): для `pult-vitest` с `runner: pytest-own` без `plank_layout` верны обе ветки. Ветка «команда не pytest» требует отказа, ветка «`pytest-own` без `plank_layout`» — прежней выкладки. Разработчик выберет одно из двух.
2. **Требование 7 и AC-6: `--ignore=<plank_layout до <id>>`** (SPEC.md:30, :49) — не сказано, от какой базы считается путь.
   - В нынешнем `--ignore` путь от корня переводится к `workdir` функцией `_own_target` (`orchestrator/acceptance.py:753-754`, `:2310-2311`), потому что pytest запущен из `workdir`.
   - Если записать `plank_layout` в `--ignore` буквально, от корня (например `fe/src/.artel-plank` при `workdir: fe`), pytest игнорирует несуществующий путь. Остаток выкладки тогда собирается полным набором, а тест, сверяющий argv с тем же буквальным литералом, остаётся зелёным.
3. **Требование 7: «в `_report_argv` … вместо `--ignore=<long_lived_dir>/.artel-plank`»** — сегодня флаг ставится только при `own` (`runner: pytest-own`; `orchestrator/acceptance.py:745`, `:750-754`).
   - Возможен компонент `junit-xml` на pytest без `runner` (в корне, пустой `workdir`) с `plank_layout`. SPEC не говорит, получает ли он `--ignore`.
   - Если реализовать флаг только на месте прежнего, то есть при `own`, остаток выкладки такого компонента попадёт в его полный набор. AC-6 этого не поймает, если его фикстура будет с `runner: pytest-own`.

## Пути обхода гейтов
1. **Шаблон `info/exclude` прячет будущий код.** `plank_layout` вида `frontend/src/generated/<id>` проходит все три проверки требования 3, если каталога `frontend/src/generated/` ещё нет: `git ls-files` пуст. В общий `info/exclude` клона ложится `/frontend/src/generated/`, и шаблон не убирается — требование 4 убирает только файлы. Если любая задача этого проекта потом создаст код в этом каталоге, чекпоинт (`git add -A`) его не увидит, и код молча не попадёт в ветку. Отказ при подготовке ловит только уже отслеживаемые файлы. Нужна либо уборка шаблона, либо требование к имени родителя (как узкое `.artel-plank` сегодня). Решение за Оператором.
2. **Буквальный `--ignore` от корня** (отклонение 2 в «Фактах против кода»): AC-6 выполнен буквально, а остаток выкладки собирается полным набором компонента с `workdir`.
3. **Планка без файлов компонента зелёная.** Требование 6 и AC-7 приравнивают её к «планка не заведена», а у `run` это зелёный исход (`orchestrator/acceptance.py:1338-1339`). Если тест компонента назван не по маске (например `test_x.py` у `pult-vitest`), файл посторонний для правила, и `run` на рубеже приёмки зелёный. Риск сдерживают проверка посторонних файлов планки по правилу на выходе `tests_writing` из G2а-1 (`orchestrator/fsm.py:643`) и запрет автогейта для правила не по умолчанию (`fsm_autogate._plank_rule_refusal`). Отдельной находкой это не поднимаю, но после G2б (снятие запрета автогейта) риск станет прямым.

## Вердикт
**concerns.** SPEC ведом дальше, а отклонения может решить Оператор на гейте правкой формулировок.

1. Неверный факт и коллизия правил: SPEC.md:16 и требование 5 (SPEC.md:28). `pult-vitest` с `runner: pytest-own` уже получает выкладку под `long_lived_dir` (`orchestrator/acceptance.py:121-124`, `:1187-1193`; `orchestrator/targets.py:73`, `:421-428`). Для такого профиля без `plank_layout` верны и «отказ», и «прежняя выкладка» — нужен порядок правил.
2. База пути `--ignore`: требование 7 и AC-6 (SPEC.md:30, :49) не требуют перевода к `workdir` (`_own_target`, `orchestrator/acceptance.py:753-754`, `:2310-2311`). Буквальное исполнение проходит AC и не исключает остаток.
3. `--ignore` у pytest-компонента без `runner: pytest-own`: требование 7 (SPEC.md:30) против `orchestrator/acceptance.py:745`, `:750-754` — случай не определён.
4. Уборку остатка `plank_layout` в `drop_from_code_copy` (требование 4, SPEC.md:27) не проверяет ни один AC. Для `pult-vitest` без `--ignore` это единственная защита.
5. Матрица: `tests/test_01m590gjaf0edv4nbc4c99mfvh_report_outcome.py:898-948` (`test_ac11`) и `:1454-1483` (`test_ac16`) останутся зелёными, но потеряют предмет проверки для `run`/`collect`/`run_plank`. SPEC не требует обновить их фикстуры (`tests`, `plank_layout`) и не заводит замену.
6. Шаблон `/<родитель <id>>/` навсегда остаётся в общем `info/exclude`. Без ограничения на имя родителя он прячет от чекпоинта будущие файлы кода в этом каталоге (требования 3–4, SPEC.md:26-27).
7. AC-4 (SPEC.md:47) не задаёт тексты трёх отказов и не уточняет, сверяется ли «вне `workdir`» по `realpath`, как у `_own_cwd` (`orchestrator/acceptance.py:214-229`).

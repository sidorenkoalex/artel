# SPEC-AUDIT: G2а-2 — выкладка планки компонента по `plank_layout` и `plank-run` по правилу планки

Четвёртый аудит, после третьего возврата с гейта SPEC (решение Оператора №3, пункты 1–3). Сверка — по рабочему каталогу: голова ветки `f039c1ad`, в `orchestrator/`, `scripts/`, `tests/` с main `c2dc427f` изменений нет (`git log c2dc427f..HEAD` по этим путям пуст).

## ТЗ и SPEC
Решения Оператора №1 и №2 остались в SPEC. Решения №3 перенесены:
- п. 1: третий случай — компонент `components:` «с заданным полем `report` (`junit-xml` или `pult-vitest`)»; компонент без `report` и `test_profile` не задеваются. Где: требование 5, AC-5. Отклонение 1 прошлого аудита снято.
- п. 2: требование 2 ограничено профилем «с полем `report`»; строка в «Не входит» (SPEC.md:81). Отклонение 2 прошлого аудита снято, но см. отклонение 1 ниже.
- п. 3: пути без выкладки идут первыми, отказ правила — только при выкладке (требование 1); AC-3 дополнен случаем «правило с отказом + прогон только `extra`». Отклонение 3 прошлого аудита снято в объёме решения.

Требования ТЗ п. 1–7, критерии ТЗ и решения по умолчанию ТЗ отражены (требования 1–10, «Не входит»). Требований сверх ТЗ и решений Оператора нет.

Расхождение:
1. **Компонент `runner: pytest-own` без `report` с `plank_layout`: требования противоречат друг другу.**
   - Требование 2 и строка «Не входит» (SPEC.md:81, решение №3 п. 2) выводят из задачи «профиль компонента без `report`» — его `plank_layout` не читается.
   - Требование 5, первый пункт («поле `plank_layout` задано — выкладка по `plank_layout`»), оговорки про `report` не имеет.
   - Требование 7 и AC-6 (решение №2 п. 1) требуют у «компонента `runner: pytest-own` без `report` с командой pytest и `plank_layout`» `--ignore=<plank_layout до <id>>` в ветке полного набора `orchestrator/acceptance.py:2299-2313`. Эта ветка — как раз профиль `pytest-own` без `report` (компонент с `report` уходит раньше, `:2288-2291`).
   - Строка «Не входит» в скобках называет `runner: pult-pytest`. Её можно прочесть двумя способами: (а) все компоненты без `report`; (б) только `runner: pult-pytest`. При прочтении (а) выкладка такого профиля остаётся под `long_lived_dir/.artel-plank`, а AC-6 убирает `--ignore=…/.artel-plank` и ставит `--ignore` на родителя `<id>`. Тогда остаток выкладки после обрыва попадёт в полный набор pytest. При прочтении (б) непонятно, что делать с профилем `pytest-own` без `report`: он не попадает ни в требование 2, ни в «Не входит».
   - Решает Оператор: выкладка по `plank_layout` есть у `pytest-own` без `report` (требование 2 расширить на него) либо нет (тогда случай из AC-6 и требования 7 убрать).

## Факты против кода
Подтвердились (адреса не сдвинулись, код с прошлого аудита не менялся):
- `PlankRule` с `refusal`, `owns`, `component_of`, `is_test`, `masks`, `is_default` — `scripts/guard.py:2620-2672`. Правило с отказом — умолчание: `components` пуст (`guard.py:2627-2629`), поэтому `owns`/`is_test` идут по `test_*.py`.
- Отказ построения у `pult-vitest` без `tests` — `orchestrator/project_profile.py:473-477`.
- `_own` выбирается по `runner` — `orchestrator/acceptance.py:120-123`. `_layout_mode` возвращает «» не у `pytest-own` — `:1187-1193`.
- Прогон только `extra` — `:1337-1339`. `plank-run` долгоживущего файла — `orchestrator/plank_run.py:221-229`. Тексты отказов `plank-run` — `:186-195`. `LAYOUT_OUTSIDE_NOTE` и `_exclude_pattern` — `orchestrator/acceptance.py:1172-1239`. Тексты совпадают дословно.

Не подтвердилось:
2. **SPEC.md:81 («Не входит»): «(`runner: pult-pytest`) … выкладка прежняя под `long_lived_dir`».** По коду у профиля `pult-pytest` выкладки нет совсем. `_own` даёт `None` для любого `runner`, кроме `pytest-own` (`orchestrator/acceptance.py:120-123`), а `_layout_mode(None)` — «» (`:1191-1192`). Планка такого профиля идёт прежним путём из `tasks/<id>/acceptance_tests`. Формулировка повторяет решение №3 п. 2. На поведение она не влияет, потому что строка стоит в «Не входит». Но разработчик может прочесть её как требование «класть планку `pult-pytest` под `long_lived_dir`». Достаточно уточнить на гейте: «прежнее поведение».

## Пути обхода гейтов
Прежние обходы закрыты: сегмент «.», «<id>» внутри сегмента, отказ на путях без выкладки, пустая маска у умолчания, порядок отказа правила и прогона `extra`.

Остались:
3. **Выкладка без `--ignore` у `pytest-own` без `report` (отклонение 1, прочтение (а)).** Исполнитель выполняет буквально требование 2 и «Не входит» — выкладка остаётся под `.artel-plank`. Порядок между ними не задан. Оба исхода не зелёные, различается только текст. Тест на текст одного из них красит реализацию другого прочтения. Пункт решается одной строкой на гейте.

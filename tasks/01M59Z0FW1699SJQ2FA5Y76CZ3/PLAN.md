# PLAN: G2а-2 — выкладка планки компонента по `plank_layout` и `plank-run` по правилу планки

## Подход
Правка в двух модулях зоны (`orchestrator/acceptance.py`, `orchestrator/plank_run.py`),
правило планки (`project_profile.plank_rule`) только вызывается.

- `acceptance._plank_plan(tests_dir, command)` — решение по планке до прогона,
  в порядке требований 1 и 5: планки нет (только помощник) или канал — не
  профиль проекта → прежний путь; `refusal` правила проекта → отказ;
  профиль не из `components:` с `report` → прежний путь; задан
  `plank_layout` → выкладка файлов компонента (нет файлов — «планка не
  заведена», требование 6); не задан и команда pytest → прежняя выкладка
  под `long_lived_dir` побайтно; иначе есть файлы компонента → отказ «у
  компонента <имя> нет plank_layout — …», нет файлов → «не заведена».
  Файл компонента: правило по умолчанию — `rule.owns`, иначе
  `rule.component_of(name) == profile.component`; общие файлы и `_pult.py`
  правило не относит к компоненту, помощник докладывается только у команды
  pytest.
- `_layout_check(profile, code_root)` — пять отказов формы требования 3 в
  порядке списка, дословными текстами; `workdir` по `realpath`, отслеживаемые
  файлы — `git ls-files -- <родитель>`.
- `_component_layout` — контекст выкладки: проверка формы, шаблон
  `/<родитель>/` в `info/exclude` прежним `_exclude_pattern` (тем же
  замком) до записи файлов, копия файлов прямо в `<plank_layout>`, уборка
  каталога `<id>` и опустевшего родителя в `finally`. Цели: у pytest —
  каталог выкладки, у прочих — тестовые файлы выкладки (`select` через
  прежний `_subset_args`).
- `run`/`collect`/`run_plank` зовут `_plank_plan` и общий `_laid_plank`
  (новая выкладка либо прежний `_plank_layout` без изменений); пути без
  файлов планки (только `extra`, долгоживущий файл `plank-run`) решаются
  прежним кодом до правила.
- `drop_from_code_copy` убирает остаток выкладки `plank_layout` (только
  при годной форме), прежняя уборка `.artel-plank` — как была.
- `_report_argv` (и ветка `pytest-own` полного набора — для полноты) у
  профиля с `report` и `plank_layout` исключает родителя `<id>`
  (`--ignore=` через `_own_target`) вместо `.artel-plank`.
- `plank-run`: отказ `refusal` правила, наличие тестов и `[файл]` по
  правилу (у правила по умолчанию — прежний код и тексты побайтно, у
  прочих — маска `tests` компонента в тексте), отказ узлу `::` у
  компонента с командой не pytest.

Оценка SPEC (35 $) не пересматривается.

## Влияние на систему
Прежние пути (артель, `test_profile`, компоненты без `report`, pytest-
компоненты без `plank_layout`) идут прежним кодом: `_plank_plan` для них
возвращает «прежний путь» и `_plank_layout`/`_layout_target` не менялись.
Лок планки и фиксация (инварианты 25, 27) не затронуты — меняется только
место копии на время прогона. Новые отказы делают исход не зелёным, ни
один гейт не ослаблен. `drop_from_code_copy` удаляет только каталог
`<plank_layout>` с подставленным id задачи после проверки формы (родитель
без отслеживаемых файлов) и родителя — только `rmdir` пустого. Откат —
revert merge-коммита.

## Риски
- `info/exclude` клона копит по строке `/<родитель>/` на компонент — файл
  общий, строки не дублируются (проверка под `flock`).
- `drop_from_code_copy` теперь читает `targets.yaml` и зовёт `git ls-files`
  у проектов с `plank_layout` — только у них.

# SPEC: Стоп-кран auto по повторному отказу advance

## Контекст

Инцидент T035 (26.08): цикл `auto` (`orchestrator/auto.py`) повторил
платный агентный шаг 11 раз подряд при одном и том же детерминированном
отказе `advance` («переход отклонён: рабочая копия артефактов грязная») —
причина отказа вне зоны агента (незакоммиченный файл Оператора), прогон
агента её не лечит. Сгорело ~$9. Строка беклога P3.

Сегодня `cmd_auto` останавливается немедленно только на отказе guard'ом
структуры артефакта (`fsm.cmd_advance` вернул `True`, SPEC T034,
требование 2). Прочие отказы `advance` (грязная копия, стухший вердикт
ревью, красные приёмочные тесты, непокрытые AC, лок приёмочных тестов,
дерево не на ветке задачи и т.п.) не отличаются циклом от «агент ещё не
довёл артефакт» — `cmd_auto` просто зовёт `cmd_run` заново.

## Требования

1. `orchestrator/auto.py`, `cmd_auto`: цикл останавливается, если два
   ПОДРЯД шага (`run`+`advance`) не сменили состояние задачи И на обоих
   `advance` записал в журнал (`store.journal`, actor `fsm`) запись с
   действием (полем `action`), начинающимся с «переход отклонён», причём
   текст этого поля `action` совпадает на обоих шагах дословно.
2. Остановка — тем же по характеру способом, что и существующие
   остановки `auto_stop`: запись в журнал и вывод Оператору, называющие
   причину отказа (переиспользуется текст, которым отказ уже записан
   `fsm.cmd_advance` в журнал) и подсказку «почини причину и повтори
   `artel.py advance <id>`».
3. Правило не подменяет и не сужает существующую немедленную остановку
   на отказе guard'ом структуры артефакта (`fsm.cmd_advance` вернул
   `True`) — та остановка срабатывает на первом же отказе, как и сейчас;
   новое правило — дополнительная остановка для случаев, когда
   `cmd_advance` вернул `False`, но перед этим записал в журнал отказ
   («переход отклонён: ...» с текстом, отличным от guard'а).
4. Шаг без смены состояния, на котором `advance` НЕ записал в журнал
   отказ (агент ещё работает: артефакт-условие не в статусе `ready`,
   PLAN не готов и т.п.) — правило этот шаг не считает частью серии
   отказов; поведение цикла для такого шага не меняется.
5. Два подряд отказа `advance` с РАЗНЫМ текстом `action` (например,
   один раз «переход отклонён: рабочая копия артефактов грязная», затем
   «переход отклонён: трассируемость AC») цикл по этому правилу не
   останавливают.
6. `config.AUTO_MAX_STEPS` и его комментарий («шаг, не сдвинувший
   состояние, законен») не меняются — остаются верхней защитой цикла
   независимо от нового правила.

## Критерии приёмки

AC-1. Два подряд шага `auto` без смены состояния задачи, на обоих из
которых `advance` отказал и записал в журнал действие «переход
отклонён: ...» с одинаковым текстом действия, — цикл `auto`
останавливается на втором из этих шагов; задача остаётся в том же
состоянии, в котором была перед первым из двух шагов; остановка
называет причину отказа (текст записи журнала) и подсказку «почини
причину и повтори `artel.py advance <id>`».

AC-2. Шаги `auto` без смены состояния задачи, на которых `advance` НЕ
записал в журнал отказ «переход отклонён: ...» (агент ещё работает,
артефакт-условие не в статусе `ready`), не останавливают цикл по этому
правилу — цикл продолжает вызывать `cmd_run`, как и до этой задачи.

AC-3. Два подряд отказа `advance` с разным текстом действия «переход
отклонён: ...» не останавливают цикл по этому правилу.

AC-4. Все существующие тесты `tests/test_auto_cycle.py` (и прочие
существующие тесты пакета) остаются зелёными без правки их сценариев
и ассертов.

## Не входит

- Изменение немедленной остановки цикла на отказе guard'ом структуры
  артефакта (SPEC T034, требование 2) — она сохраняется как есть,
  срабатывает на первом же отказе.
- Изменение `config.AUTO_MAX_STEPS`, его значения или комментария —
  верхняя защита цикла не трогается этой задачей.
- Обработка отказов `advance`, никак не журналируемых (`print` без
  `store.journal`, например «SPEC.md ещё не ready») — по требованию 4
  такие шаги не входят в серию отказов, других изменений для них нет.
- Изменение содержимого или формата самих сообщений об отказе внутри
  `orchestrator/fsm.py` — правило переиспользует их текст как есть, не
  переписывает их.
- Любая правка `gates.yaml`/`roles.yaml`/`targets.yaml`/`.github/`/
  `templates/`/`skills/` — эти пути меняет только Оператор.

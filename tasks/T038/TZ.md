# ТЗ: Стоп-кран auto по повторному отказу advance

Стоп-кран auto по повторному отказу advance (строка беклога P3, инцидент T035 26.08).

Проблема: auto повторил платный агентный шаг 11 раз подряд при одном и том же детерминированном отказе advance («рабочая копия артефактов грязная») — сгорело ~$9. Прогон агента такой отказ в общем случае не лечит: причина вне зоны агента (незакоммиченный файл Оператора).

Что сделать: цикл auto (orchestrator/auto.py) останавливается, если два ПОДРЯД шага не сменили состояние задачи И advance оба раза отказал с одинаковой причиной (текст записи журнала «переход отклонён ...» совпадает). Остановка — с внятной подсказкой: причина отказа и что сделать Оператору (причина уже пишется в журнал — переиспользовать её текст).

Границы: осознанное правило «шаг без смены состояния законен» (комментарий к config.AUTO_MAX_STEPS: агент не довёл PLAN — следующий прогон продолжит) СОХРАНЯЕТСЯ — стоп-кран срабатывает только при повторном ОТКАЗЕ advance с той же причиной, а не при любом топтании на месте. AUTO_MAX_STEPS остаётся верхней защитой. Ничего не ослабляется: это дополнительная остановка, не пропуск гейта.

Критерии приёмки (ориентир): (1) два подряд шага auto без смены состояния с одинаковой причиной отказа advance → цикл останавливается, задача остаётся в своём состоянии, подсказка называет причину; (2) шаги без смены состояния БЕЗ отказа advance (агент ещё работает, PLAN не ready) цикл не останавливают — прежнее поведение; (3) отказы advance с РАЗНЫМИ причинами подряд цикл не останавливают по этому правилу; (4) существующие тесты auto зелёные без правок сценариев.

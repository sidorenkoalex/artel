# SPEC: ADR-0021, этап 1 (в) — команда чтения документов задачи, отмена CI на `artifact/**`, уборка веток `artifact/**`

## Контекст
Части (а), (б1), (б2) этапа 1 ADR-0021 слиты: документы задачи живут в
`refs/artifacts/<id>` репозитория её проекта, пушей в `artifact/**` пульт
больше не делает. Остались три хвоста. Первый: читатели вне конвейера
(`show <id>`, `retro_corpus`) видят только локальные ссылки, а команды,
подтягивающей ссылку из `origin`, нет: на второй машине или после
чистого клона документы закрытых задач им недоступны. Второй: CI всё ещё
запускается на `artifact/**` и держит для этого режим
`scripts/guard.py --artifact-branch`, `scripts/ci_push_class.py` хранит
под него отдельный класс, а первый инвариант 36 требует такого прогона.
Третий: в `origin` артели остались 229 веток `artifact/**`, в главной
копии — 5 локальных веток `artifact/*`. Источник — ADR-0021 пп. 3, 4, 12,
13 (этап 1).

## Требования

1. **Команда `artel.py docs <id> [файл]`.** Команда подтягивает ссылку
   `refs/artifacts/<id>` из `origin` репозитория задачи через узел
   `orchestrator/artifact_branch.py`. Репозиторий — артели или внешнего
   проекта, по target задачи. С аргументом файла команда печатает файл
   `tasks/<id>/<файл>` из подтянутой головы. Без аргумента она печатает
   перечень файлов документов задачи.
   - Исторические снимки читаются так же. Это ссылки закрытых задач,
     созданные до части (а).
   - Если ссылки нет ни в `origin`, ни локально, команда даёт именованный
     отказ (называет задачу и причину) с ненулевым кодом возврата.
   - Подтягивание не теряет локальных коммитов. Отсутствующая локальная
     ссылка создаётся. Локальная ссылка, которая является предком головы
     `origin`, сдвигается вперёд. Локальную ссылку с коммитами, которых
     нет в `origin`, команда не перезаписывает и называет расхождение.
     Это прямое следствие ADR-0021 п.3: локальная ссылка — источник истины
     живой задачи, её отправка в `origin` может отставать до следующего
     перехода.
2. **`artel.py docs --fetch-all`.** Команда пакетно подтягивает все
   `refs/artifacts/*` из `origin`. Для каждого репозитория (артели и
   каждого внешнего проекта с клоном) это один вызов git. Команда печатает
   число принесённых ссылок (их не было локально) и число обновлённых.
   Правило «не терять локальных коммитов» из требования 1 действует и
   здесь.
3. **Доступ процесса роли — решение SPEC: недоступна.** `docs`, как и
   команда уборки из требования 9, в перечень
   `orchestrator/artel.py::_ROLE_ALLOWED_COMMANDS` не входит. Процесс роли
   получает отказ диспетчера тем же закрытым по умолчанию путём, что и
   прочие меняющие команды. Обоснование:
   - команда ходит в сеть и переписывает локальные `refs/artifacts/*`, в
     том числе ссылку живой задачи, коммит которой зафиксирован пультом
     (`orchestrator/fixation.py`, сверка сдвига ссылки);
   - роли документы своей задачи и так доступны: каталог документов
     материализуется пультом из головы ссылки на старте каждого шага
     (ADR-0021 п.7);
   - `plank-run` в перечне — команда без сети и без записи в ссылки, это
     не прецедент для `docs`.
4. **`show <id>` без локальной ссылки.** Если локальной
   `refs/artifacts/<id>` нет, `show` называет команду `docs <id>` как
   способ подтянуть документы. Тихий пустой вывод полей артефактов не
   допускается.
5. **`retro_corpus` не меняет поведения.** Он по-прежнему работает только
   с локальными ссылками, без сети. Его модульный докстринг называет
   `docs --fetch-all` как способ наполнить корпус. Тот же текст виден в
   секции `orchestrator/retro_corpus.py` файла `docs/codebase-map.md`
   после регенерации `scripts/codebase_map.py`: карта берёт первую строку
   докстринга.
6. **CI на пуше документов отменяется.** Делается это так:
   - приложение к PLAN для `.github/workflows/ci.yml` убирает
     `artifact/**` из `on.push.branches` и убирает развилку
     `GUARD_ARGS="--all --artifact-branch"` задания `guard` (на `main`
     остаётся вызов `--all`);
   - условия заданий, которые ссылаются на `refs/heads/artifact/`, тоже
     убираются как мёртвые;
   - `scripts/ci_push_class.py` теряет класс `artifact/`: пуш в ветку
     `artifact/<x>` классифицируется общим правилом не-`main` ветки.
7. **Режим `--artifact-branch` в `scripts/guard.py` убирается** вместе с
   ключом командной строки. Убираются параметр
   `check_content(..., artifact_branch_mode)` и функции режима
   (`_artifact_branch_report`, `basic_frontmatter_errors`,
   `is_draft_lenient`, `DRAFT_LENIENT_TYPES`, `ARTIFACT_BRANCH_FLAG`), если
   они больше нигде не нужны. Модульный докстринг и комментарии, которые
   описывают режим, правятся. Поведение `guard.py <файлы>` и
   `guard.py --all` без флага не меняется.
8. **Кто проверяет сданные артефакты после снятия режима.** Ниже перечень
   по коду пина d860c974. Все проверки, которые выполнял режим, уже
   исполняются гейтами пульта отказом перехода, причём строже режима:
   черновики проверяются полностью, без понижения до предупреждения.
   Нового гейта задача не вводит, существующие гейты не ослабляются.

   | Артефакт / проверка | Где исполняется | Исход |
   |---|---|---|
   | `SPEC.md` (полная структура) | выход `spec_writing`, `orchestrator/fsm_advance.py::spec_writing` → `fsm.guard_refuses` | отказ перехода |
   | `QUESTIONS.md` | выход `spec_writing`, `fsm_advance.py` (вызовы `guard_refuses` для QUESTIONS) | отказ перехода |
   | `PLAN.md` | выход `in_dev`, `fsm_advance.py::in_dev` → `guard_refuses` | отказ перехода |
   | `REVIEW.md` | выход `review`, `fsm_advance.py::review` → `guard_refuses` | отказ перехода |
   | `acceptance_tests/`: трассируемость AC, маркер AC-n с отступом, маркеры красноты, образцы формата id | выход `tests_writing`, `fsm.py` (`acceptance_traceability_errors`/`scan_indented_ac_markers`, `scan_redness_markers`, `scan_id_format_samples`) | отказ перехода |
   | `acceptance_tests/` после `amend-tests` | `orchestrator/amend.py` (`acceptance_traceability_errors`, ветвевой путь `_branch_traceability_errors`) | отказ команды |
   | посторонние файлы `acceptance_tests/` и корня `tasks/<id>/` | фильтр автокоммита `orchestrator/checkpoint.py` (`_is_stray_acceptance_test_file`, `_is_extraneous_task_root_file`); гейт мержа `fsm_merge_gate._guard_task_root_or_refuse` | не попадают в ссылку; отказ мержа |
   | все `tasks/<id>/*.md` дерева мержа целиком, включая черновики, посторонние файлы и маркеры с отступом (то, что CI делал `--all`) | гейт мержа `fsm_merge_gate._guard_all_or_refuse` (`guard.py --all` без режима) | отказ мержа |
   | `TZ.md`, `ANSWER-n.md` | пишут команды пульта `new`/`answer`; структура проверяется тем же `guard.py --all` гейта мержа | отказ мержа |

   Единственное, что режим делал мягче полной проверки, — понижал
   нарушения содержания черновика до предупреждения. Эта мягкость
   исчезает вместе с режимом. Проверки, которая исполнялась бы только в
   режиме и больше нигде, нет.
9. **Разовая уборка веток `artifact/**` — команда
   `artel.py artifact-branches-cleanup [--execute]`.**
   - Без флага команда работает как предпросмотр. Она перечисляет ветки
     `artifact/**` в `origin` артели и локальные ветки `artifact/*`
     главной копии и ничего не удаляет.
   - С `--execute` команда перед удалением сверяет: у каждой задачи из
     перечня (id из имени ветки) есть `refs/artifacts/<id>` в `origin`.
     Если ссылки не хватает, команда называет такие задачи и не удаляет
     ничего, ни в `origin`, ни локально.
   - Если сверка прошла, команда удаляет ветки и в `origin`, и в главной
     копии.
   - Исполняет уборку Оператор после мержа, канарейки и сдвига пина, не
     эта задача.
10. **Инварианты — приложением к PLAN** для `docs/invariants.md` и

    - `CiJobsByPushClassInvariantTest` перестаёт требовать от `guard`
      неисключения `refs/heads/artifact/` и проверяет `ci.yml` после
      приложения из требования 6.
    - Второй инвариант под номером 36 (порядок состояний FSM) получает
      следующий свободный номер сквозной нумерации. Ссылки на него в

11. **Постоянные тесты в `tests/`** с заявкой «Ловит мутацию:» в
    докстринге покрывают девять сценариев ТЗ:
    - `docs` подтягивает версию `origin`, которая новее локальной;
    - `docs` без локальной ссылки;
    - `--fetch-all` приносит ссылку, которой нет локально;
    - чтение исторического снимка;
    - `docs` для внешнего проекта читает его `origin`;
    - `show` без локальной ссылки называет `docs`;
    - предпросмотр уборки ничего не удаляет;
    - уборка отказывает при задаче без ссылки в `origin`;

    ADR-0021 (режим `--artifact-branch`, класс `artifact/`, инвариант 36).
    Перечень изменённых и удалённых тестов приводится в PLAN.

## Критерии приёмки

AC-1. Пусть `origin` задачи несёт голову `refs/artifacts/<id>` новее
локальной, и в этой голове файл `tasks/<id>/<файл>` изменён. Тогда
`artel.py docs <id> <файл>` печатает содержимое файла из головы `origin`,
а локальная ссылка после команды равна голове `origin`.

AC-2. Пусть локальной `refs/artifacts/<id>` нет, а в `origin` она есть.
Тогда `artel.py docs <id> <файл>` печатает файл из головы `origin`, и
локальная ссылка после команды существует и равна ей.

AC-3. `artel.py docs <id>` без аргумента файла печатает перечень файлов
документов задачи в подтянутой голове ссылки и не печатает содержимое
файлов.

AC-4. Исторический снимок — ссылка закрытой задачи, созданная до части
(а): один коммит без родителя с деревом `tasks/<id>/`. `artel.py docs
<id> <файл>` читает из него файл так же, как из ссылки живой задачи.

AC-5. Для задачи внешнего проекта `artel.py docs <id> <файл>` подтягивает
ссылку из `origin` репозитория этого проекта, а не из `origin` артели, и
печатает файл из неё.

AC-6. Если `refs/artifacts/<id>` нет ни в `origin`, ни локально,
`artel.py docs <id>` завершается ненулевым кодом и печатает именованный
отказ, который называет задачу и отсутствие ссылки. Пустого вывода с
кодом 0 нет.

AC-7. Пусть локальная `refs/artifacts/<id>` несёт коммит, которого нет в
`origin`. Тогда ни `artel.py docs <id>`, ни `artel.py docs --fetch-all`
её не перезаписывают: после команды она указывает на прежний коммит, и
вывод называет расхождение с `origin`.

AC-8. `artel.py docs --fetch-all` приносит из `origin` ссылку
`refs/artifacts/<id>`, которой не было локально, и печатает число
принесённых и число обновлённых ссылок. Для каждого репозитория
выполняется ровно один вызов `git fetch`.

AC-9. Процесс роли получает отказ диспетчера `orchestrator/artel.py` на
`docs <id>`, `docs --fetch-all` и `artifact-branches-cleanup` (с флагом и
без). `_ROLE_ALLOWED_COMMANDS` не содержит ни `docs`, ни
`artifact-branches-cleanup`.

AC-10. `artel.py show <id>` для задачи без локальной
`refs/artifacts/<id>` печатает подсказку, которая называет команду
`docs <id>`.

AC-11. Модульный докстринг `orchestrator/retro_corpus.py` и его секция в
`docs/codebase-map.md` называют `docs --fetch-all`. `retro_corpus`
по-прежнему читает только локальные `refs/artifacts/*`, без сетевых
вызовов git.

AC-12. `scripts/ci_push_class.py::classify("push",
"refs/heads/artifact/<x>", …)` не выделяет артефактную ветку в отдельный
класс. Исход совпадает с исходом для любой другой не-`main` ветки, и
причина не называет артефактную ветку.

AC-13. `scripts/guard.py` не знает режима `--artifact-branch`. Вызов с
этим ключом не печатает сводку «сдано N / черновиков M / нарушений K» и
не понижает нарушение содержания черновика до предупреждения: черновик
SPEC с нарушением содержания даёт код 1. `check_content` не принимает
параметр `artifact_branch_mode`.

AC-14. PLAN несёт приложение к `.github/workflows/ci.yml`. После него
`on.push.branches` не содержит `artifact/**`, задание `guard` не содержит
развилки `--artifact-branch`, ни одно условие задания не ссылается на
`refs/heads/artifact/`. Приложение проходит `git apply --check` на
чистом дереве, это подтверждено в PLAN.

AC-15. PLAN несёт приложение к `docs/invariants.md` и
`tests/test_invariants.py`, проходящее `git apply --check`. После его
применения:
- в таблице нет двух инвариантов с одним номером;
- первый инвариант 36 не требует прогона CI на `artifact/**`, называет
  замену гейтами переходов и задание `python-min` наравне с `python`;
- бывший второй инвариант 36 несёт новый номер;
- `CiJobsByPushClassInvariantTest` зелёный на `ci.yml` после приложения
  AC-14.

AC-16. `artel.py artifact-branches-cleanup` без флага перечисляет ветки
`artifact/**` в `origin` артели и локальные ветки `artifact/*` главной
копии и не удаляет ни одной ветки: множества веток в `origin` и локально
до и после команды совпадают.

AC-17. `artel.py artifact-branches-cleanup --execute` при задаче из
перечня, у которой нет `refs/artifacts/<id>` в `origin`, завершается
отказом, который называет такие задачи, и не удаляет ни одной ветки ни в
`origin`, ни локально.

AC-18. `artel.py artifact-branches-cleanup --execute` при ссылках
`refs/artifacts/<id>` в `origin` у всех задач перечня удаляет все ветки
`artifact/**` в `origin` и все локальные ветки `artifact/*` главной
копии. Ссылки `refs/artifacts/*` при этом не трогаются.

AC-19. Каждый из девяти сценариев требования 11 закрыт постоянным тестом
в `tests/`, в докстринге которого есть строка «Ловит мутацию:».

## Оценка объёма и деление

Сработали сигналы:
- 19 критериев приёмки (порог `SPLIT_SIGNAL_AC_COUNT` = 10);
- больше пяти файлов зоны: `orchestrator/artel.py`, новый модуль команды,
  `orchestrator/catalog.py`, `orchestrator/retro_corpus.py`,
  `scripts/guard.py`, `scripts/ci_push_class.py`, тесты, карта;
- зона задевает механизм, на который опирается запись
  `docs/invariants.md` (инвариант 36, ADR-0016).

По калибровке (больше 15 критериев либо 8 и более файлов) задача целиком
— класс ~$85 либо деление, а рамка Оператора — $45.

Предлагается **нарезка на две подзадачи**. Граница проходит между двумя
независимыми механиками ТЗ. Первая — снятие CI и режима guard (`scripts/`
и приложения к защищённым путям). Вторая — новые команды пульта
(`orchestrator/`). Ни одна часть не опирается на код другой.

1. **Отмена CI на документах и режима `--artifact-branch`**
   (требования 6, 7, 8, 10; AC-12…AC-15). Часть мержима сама по себе.
   Пушей в `artifact/**` пульт уже не делает, поэтому снятие триггера,
   класса `ci_push_class` и режима guard не оставляет непроверенным ни
   один путь: перечень требования 8 показывает, что все проверки
   исполняют гейты. Инвариант и его тест меняются тем же мержем, что и
   `ci.yml` (ADR-0021 п.12). Идёт первой: она меньше и снимает
   двойной номер 36 в реестре.
2. **Команда `docs`, подсказка `show`, уборка веток `artifact/**`**
   (требования 1–5, 9, 11; AC-1…AC-11, AC-16…AC-19). Часть мержима сама
   по себе: новые команды ничего не меняют в конвейере и CI. Уборку
   исполняет Оператор вручную после мержа, канарейки и `pin-update`.
   Идёт второй только ради последовательности общих зон `tests/` и
   `docs/codebase-map.md`, зависимости по коду нет.

Если Оператор предпочтёт не делить (последняя часть этапа 1, деление
добавит ещё одного аналитика на подзадачу), требования и критерии выше
полны для одной задачи. Тогда нужна строка решения Оператора о монолите и
пересмотр рамки по калибровке.

## Деление

### Отмена CI на документах и режима guard --artifact-branch

Зоны: scripts/guard.py, scripts/ci_push_class.py, tests/, docs/codebase-map.md
Порядок: первая, без зависимостей
Рамка: $25

Источник: ADR-0021 (принят 29.09.2026), пп. 4, 12, 13 (этап 1); часть (в)

### Команда docs, подсказка show и уборка веток artifact/**

Зоны: orchestrator/, tests/, docs/codebase-map.md

SPEC задачи-родителя 01M41VCKTEB1SRTD2VW4X2Y6HM (требования 1–5, 9, 11).

Факты (пин d860c974):
- документы задачи живут в `refs/artifacts/<id>` репозитория её проекта,
  чтение — узлом `orchestrator/artifact_branch.py`;
- `artel.py show <id>` (`catalog.cmd_show` → `_artifact_frontmatter`)
  читает только локально;
- `orchestrator/retro_corpus.py` — только локальные `refs/artifacts/*`,
  без сети;
- команды, подтягивающей ссылку из `origin`, нет;
- в `origin` артели 229 веток `artifact/**`, в главной копии — 5
  локальных `artifact/*`;
- `doctor/artifact_branches.py` читает `refs/artifacts/*` в `origin`
  одним `ls-remote`.

Требуется:
1. `artel.py docs <id> [файл]`:
   - команда подтягивает `refs/artifacts/<id>` из `origin` репозитория
     задачи (артель или внешний проект — по target) узлом
     `artifact_branch`;
   - с аргументом печатает `tasks/<id>/<файл>` из подтянутой головы, без
     аргумента — перечень файлов документов;
   - исторические снимки (ссылки закрытых задач до части (а)) читаются
     так же;
   - нет ссылки ни в `origin`, ни локально — именованный отказ с
     ненулевым кодом;
   - локальная ссылка с коммитами, которых нет в `origin`, не
     перезаписывается, расхождение называется.
2. `artel.py docs --fetch-all` подтягивает все `refs/artifacts/*` из
   `origin` одним вызовом git на репозиторий (артель и каждый внешний
   проект с клоном). Печатает число принесённых и обновлённых ссылок.
   Правило «не перезаписывать локальные коммиты» действует и здесь.
3. `docs` и `artifact-branches-cleanup` процессу роли недоступны (не
   входят в `_ROLE_ALLOWED_COMMANDS`). Причины: команды ходят в сеть и
   переписывают локальные ссылки, в том числе ссылку живой задачи с
   зафиксированным коммитом; роли документы своей задачи материализует
   пульт.
4. `show <id>` без локальной `refs/artifacts/<id>` называет команду
   `docs <id>`.
5. `retro_corpus` поведения не меняет. Его докстринг и секция в
   `docs/codebase-map.md` называют `docs --fetch-all` как способ
   наполнить корпус.
6. `artel.py artifact-branches-cleanup [--execute]`:
   - без флага — предпросмотр: перечисляет ветки `artifact/**` в
     `origin` артели и локальные `artifact/*` главной копии, ничего не
     удаляет;
   - с `--execute` сначала сверяет, что у каждой задачи из перечня есть
     `refs/artifacts/<id>` в `origin`; при нехватке называет задачи и не
     удаляет ничего;
   - иначе удаляет ветки в `origin` и локально;
   - исполняет Оператор после мержа, канарейки и `pin-update`.
7. Постоянные тесты в `tests/` с «Ловит мутацию:» на девять сценариев
   (требование 11 SPEC родителя).

# ТЗ: ADR-0021, этап 1 (в) — команда чтения документов задачи, отмена CI на artifact/**, уборка веток artifact/**

Источник: ADR-0021 (принят 29.09.2026), пункты 3, 4, 12, 13, этап 1;
ADR-0016 в редакции ADR-0021; часть (в) из заявки деления задачи
01M3Z2DMQRD0BD7AARFVTCVVG8; решение Оператора 02.10.2026 о локальных
ветках `artifact/*`; решение Оператора 03.10.2026 «готовь ТЗ части (в)».
Последняя часть этапа 1: части (а), (б1), (б2) слиты.

Факты (пин d860c974, сверка кода 04.10 после мержей 01M41M6KGWA9PJ6G1KPDC6XY70 и 01M41R4YAM4NGEQXW1FWH7T22M):
- Документы задачи живут в `refs/artifacts/<id>` (часть (а)), вне рабочей
  копии кода (часть (б1)); ссылка внешнего проекта — в его репозитории,
  чтение одним узлом `artifact_branch` (часть (б2)). Пушей в
  `artifact/**` пульт больше не делает.
- В `origin` артели — 229 веток `artifact/**`, 230 ссылок
  `refs/artifacts/*`; в главной копии — 5 локальных веток `artifact/*`.
- CI: `.github/workflows/ci.yml` запускается на push в
  `["main", "task/**", "artifact/**"]`; задание guard на ветке
  `artifact/*` зовёт `scripts/guard.py --all --artifact-branch` (режим
  понижает нарушения содержания черновика до предупреждения).
  `scripts/ci_push_class.py:116` относит `artifact/` к отдельному классу.
- Инвариант 36 в `docs/invariants.md` занят дважды: первый — «прогон CI
  существует для каждого пуша в `main`, `task/**`, `artifact/**`»,
  второй — порядок состояний `in_dev → verifying → review → …`.
- Переходы пульта уже прогоняют guard по сданному артефакту
  (`fsm_advance`, `advance_gates/*` импортируют `scripts.guard`).
- Читатели документов вне конвейера: `artel.py show <id>`
  (`catalog.cmd_show` → `_artifact_frontmatter`) читает только локальную
  ссылку; `orchestrator/retro_corpus.py` — только локальные
  `refs/artifacts/*` (`for-each-ref`, сети нет). Команды, подтягивающей
  ссылку документов из `origin`, нет; пакетного подтягивания нет. На
  второй машине или после чистого клона документы закрытых задач
  недоступны этим читателям.
- `doctor/artifact_branches.py` уже читает `refs/artifacts/*` в `origin`
  одним вызовом (`ls-remote`).

Требуется:
1. Команда `artel.py docs <id> [файл]`: подтягивает ссылку документов
   задачи из `origin` её репозитория (узел `artifact_branch`, артель и
   внешний проект) и печатает файл из подтянутой головы; без аргумента
   файла — перечень файлов документов задачи. Исторические снимки
   (закрытые задачи до части (а)) читаются так же. Нет ссылки в `origin`
   и локально — именованный отказ.
   Доступна ли команда процессу роли (перечень
   `orchestrator/artel.py::_ROLE_ALLOWED_COMMANDS`, туда уже входит
   `plank-run`) — решение SPEC с обоснованием: команда ходит в сеть и
   обновляет локальные ссылки.
2. `artel.py docs --fetch-all`: пакетно подтягивает все
   `refs/artifacts/*` из `origin` (для ретроспектив и ревизий), одним
   вызовом git на репозиторий; печатает число принесённых и обновлённых
   ссылок.
3. Читатели вне конвейера: `show <id>` при отсутствии локальной ссылки
   называет команду `docs <id>` (подсказка, не тихий пустой вывод);
   `retro_corpus` своё поведение (только локальные ссылки, без сети) не
   меняет — в его докстринге и в `docs/codebase-map.md` назван
   `docs --fetch-all` как способ наполнить корпус.
4. CI на пуше документов отменяется: `artifact/**` исключается из
   триггеров `.github/workflows/ci.yml` (приложением к PLAN), развилка
   guard для `artifact/*` в CI убирается; `scripts/ci_push_class.py`
   теряет класс `artifact/`.
5. Режим `--artifact-branch` в `scripts/guard.py` убирается вместе с
   ключом командной строки: пушей черновиков в CI больше нет, сданные
   артефакты проверяют гейты переходов. SPEC перечисляет, какой гейт
   какой артефакт проверяет; если проверка черновика, которую делал
   режим, нигде больше не исполняется и нужна — SPEC называет это, и
   она переводится на гейт перехода (отказ перехода, не предупреждение).
   Существующие гейты не ослабляются.
6. Разовая уборка веток `artifact/**` — командой пульта с
   предпросмотром по умолчанию (`artel.py artifact-branches-cleanup`
   или иное имя — в SPEC): предпросмотр перечисляет ветки `origin` и
   локальные ветки главной копии и ничего не удаляет; удаление — явным
   флагом. Перед удалением сверка: у каждой задачи из перечня есть
   `refs/artifacts/<id>` в `origin`; при нехватке — команда называет
   задачи и не удаляет ничего. Исполняет Оператор после мержа, канарейки
   и сдвига пина, не задача.
7. Инварианты — приложением к PLAN, проверенным `git apply --check`:
   первый инвариант 36 — снятие проверки CI на `artifact/**` с заменой
   (и в той же строке — задание `python-min`, которое после задачи
   01M41M6KGWA9PJ6G1KPDC6XY70 держит `CiJobsByPushClassInvariantTest`
   наравне с `python`; замечание её ревью)
   гейтом (решение по ADR-0002 в ADR-0021 п.12); второй инвариант под
   номером 36 получает новый номер (сквозная нумерация, ссылки на него в
   `tests/test_invariants.py` и коде поправлены тем же приложением или
   кодом задачи).
8. Тесты (`tests/`, постоянные сторожа с заявками «Ловит мутацию»):
   `docs` подтягивает версию `origin`, новее локальной; `docs` без
   локальной ссылки; `--fetch-all` приносит ссылку, которой нет
   локально; чтение исторического снимка; `docs` для внешнего проекта
   читает его `origin`; `show` без локальной ссылки называет `docs`;
   предпросмотр уборки ничего не удаляет; уборка отказывает при задаче
   без ссылки в `origin`; уборка удаляет ветки `origin` и локальные.
   Существующие тесты не ослабляются; меняются только в объёме, прямо
   требуемом ADR-0021, — с перечнем в PLAN.

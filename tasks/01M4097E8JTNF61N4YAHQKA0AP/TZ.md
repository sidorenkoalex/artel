# ТЗ: ADR-0021, этап 1 (б) — документы вне рабочей копии кода, доступ ролей, упразднение репозитория фиксации

зелёная):
- Часть (а) (01M3Z2DMQRD0BD7AARFVTCVVG8) перевела документы задачи на одну
  ссылку `refs/artifacts/<id>`: запись одним узлом со сверкой прежнего
  значения (`orchestrator/artifact_branch.py::commit_files`), отправка
  после каждого коммита и повтор на `set_state` (`send_pending`), закрытие
  коммитом RETRO без снимка, отказ гейта мержа и `kill` при расхождении с

- Документы по-прежнему выкладываются ВНУТРЬ рабочей копии кода:
  `runner.role_cwd` → `artifact_branch.materialize_task_dir` пишет весь

  `acceptance.materialize_from_branch()` пишет `acceptance_tests/` в
  рабочую копию кода из `fsm_advance`, `advance_gates/acceptance`,
  `advance_gates/tests_writing`, `amend`, `pull`.
- Ссылка физически живёт в `config.ROOT` и отправляется в `origin` пульта
  для любого target (`orchestrator/artifact_branch.py`, докстринг модуля).
  До части (а) снимок закрытия внешнего target уходил в `origin` его
  рабочей копии (`snapshot._target_workspace`). ADR-0021 п.3: документы
  задачи живут в репозитории самого проекта. Внешних задач в базе 0.
- Репозиторий фиксации области проекта (ADR-0003 п.15) жив кодом:
  `orchestrator/fixation.py` (`_fix_external`, `_read_external`),
  `orchestrator/projects.py::init_artifact_repo`; после части (а)
  фиксация документов уже читает голову ссылки, но код и создание
  репозитория остались. Инвариант 25 в `docs/invariants.md` ещё упоминает
  «грязную копию» (ANSWER-1, вопрос 3: снять в этой части).
- Шаг роли: claude — `orchestrator/providers/claude.py`, codex —
  `orchestrator/providers/codex.py`; флаги `--add-dir`/`writable_roots`
  в коде не встречаются. Установлены claude 2.1.283 и codex-cli 0.157.1;
  закреплённые минимальные версии — `min_cli_version` в `models.yaml`.
- Уроки части (а): шаг developer на крупной правке дважды упёрся в потолок
  45 минут (`AGENT_TIMEOUT_SEC`); diff кода подошёл к потолку гейта
  ёмкости 262144 байт; тесты, запускающие CLI пульта отдельным процессом,
  краснеют в шаге роли из-за унаследованного `ARTEL_ROLE` — свою красноту
  проверять с `env -u ARTEL_ROLE`.

Требуется:
1. Каталог документов задачи — `.artel/projects/<проект>/tasks/<id>/` для
   любого проекта, включая артель до этапа 2 (ADR-0021 п.2: этап 2 адрес
   не переносит). Пульт выкладывает туда документы из `refs/artifacts/<id>`
   перед шагом роли и забирает правки роли оттуда автокоммитом шага.
2. Каталог роли — рабочая копия кода задачи; каталог документов открыт
   роли на запись дополнительно: claude — `--add-dir <каталог документов>`;
   codex — доступный для записи каталог песочницы `codex exec`. SPEC
   проверяет поддержку на закреплённых версиях обоих клиентов
   (`codex exec --add-dir`, при отсутствии — ключ
   `sandbox_workspace_write.writable_roots`) и фиксирует способ; ни один
   способ не поддержан — эскалация, не обход.
3. `acceptance_tests/` выкладывается в рабочую копию кода только на время
   прогона и убирается после — при зелёном, красном исходе и сбое прогона;
   прочие документы в рабочей копии кода не лежат никогда.
4. Защита документов и закреплённых тестов от роли — гейты пульта (сверка
   с зафиксированным коммитом ссылки, перечень сумм, отметка автокоммита),
   не права доступа (ADR-0021 п.7); существующие гейты не ослабляются.
5. Репозиторий фиксации области проекта упраздняется
   (`fixation._fix_external`, `_read_external`, родственные,
   `projects.init_artifact_repo`) вместе с потребителями: зафиксированное
   состояние документов — коммит ссылки.
6. Ссылка документов внешнего проекта живёт в репозитории самого проекта и
   отправляется в его `origin` (ADR-0021 п.3); ссылка артели — в git
   главной копии пульта, как сейчас. Сверка с `origin` на гейте мержа и
   `kill`, досылка и проверки `doctor` части (а) работают с репозиторием
   задачи, а не всегда с пультом.
7. `docs/stack.md`: таблица паритета безопасности роли и описание
   провайдеров отражают каталог документов на запись у обоих провайдеров.
8. Инварианты — приложением к PLAN: 21 (часть: каталог роли плюс каталог
   документов задачи на запись) и 25 (часть: репозиторий фиксации
   упразднён; снять «грязную копию»). Приложение проверено
   `git apply --check`.
9. Тесты (`tests/`, постоянные сторожа с заявками «Ловит мутацию»):
   документы не лежат в рабочей копии кода вне прогона; `acceptance_tests/`
   убирается после прогона при любом исходе; команда шага каждого
   провайдера открывает каталог документов на запись; правка роли в
   каталоге документов попадает в ссылку; репозиторий фиксации не
   создаётся и не читается; ссылка внешнего проекта уходит в `origin`
   проекта, а не пульта. Существующие тесты не ослабляются; меняются только
   в объёме, прямо требуемом ADR-0021, — с перечнем в PLAN.

# SPEC: Сведение тестов, волна 1а — тесты копилки, бэклога и окна тишины в `tests/test_notes_module.py` с доказательством мутациями

## Контекст
Строка бэклога «Периодическая консолидация тестов артели вместе с переводом
старых тестов на pytest» (решение Оператора 23.10.2026). ADR-0027 п. 8 и
ADR-0020 п. 8: перевод и удаление старых тестов идут волнами консолидации,
доказательство — множество убиваемых мутаций, мандат Оператора по путям и
независимая проверка мутаций. Это пробная волна 1а по `orchestrator/notes.py`
(порядок волн: note → outcome → merge → suite-run → остальные; волна 1б —
`doc-commit` — идёт после этой задачи).

Файлы волны: `tests/test_notes.py` (43 теста, 17 со строкой «Ловит мутацию»,
26 без неё), `tests/test_notes_apply.py` (13/13),
`tests/test_notes_row_format.py` (16/16),
`tests/test_01m563947r26nzw2tjekm36qrd_note_window_project.py` (8/8) — 80
тестов, 54 строки «Ловит мутацию», 1728 строк. Импортов из этих файлов в
другие тестовые файлы нет. Последний файл — долгоживущий приёмочный файл
задачи в `done`; перечень сумм `long_lived.sha256.txt` после мержа не
сверяется (ADR-0020 п. 6). Для него применяется ветвь ADR-0020 п. 8
«удаление без замены долгоживущим тестом — решением Оператора»; решение
записано строкой матрицы `ANSWER-1.md`, свойства файла переносятся в
`tests/test_notes_module.py`.

Общие фикстуры — `tests/fixtures.py` (ADR-0027, часть А1): `tmp_dir`,
`tmp_root`, `initialized_tmp_root`, `real_git`, `origin_real_git`,
`light_transition`. Аналога `SchemaTmpRootTest` (его берут
`tests/test_notes.py` и `tests/test_notes_row_format.py`) там нет — фикстура
объявляется в новом файле (ADR-0027 п. 2). Помощники песочниц с
утверждениями фикстурами не становятся (ADR-0027 п. 3) — переносятся
функциями модуля, которые вызывает тест.

Удаление четырёх файлов и смену вида тестов разрешает мандат Оператора
`tasks/<id>/ANSWER-1.md` (строка «Ослабление тестов разрешено:» с четырьмя
путями, матрица неослабления). Мандат по пути снимает находки обоих гейтов:
гейта неослабления (`orchestrator/advance_gates/test_integrity.py`,
`_answer_mandate`) и гейта по исходам
(`orchestrator/advance_gates/outcome_integrity.py`, исходы «исчез»).

Прогон мутаций внутри шага роли не исполним (сторож роли в `conftest.py`
роняет воркеры xdist под `ARTEL_ROLE`; около 70 мутаций не укладываются в
`AGENT_TIMEOUT_SEC` = 2700 с; записи вне рабочей копии и каталога документов
у шага нет). Поэтому прогоны идут командой пульта `mutation-run`
(`orchestrator/mutation_run.py`, смержена в main 24.10, задача
01M5NPKPWFEWTYMBYWVR797AM6): временная копия клона вне рабочей копии ветки,
фоновый процесс без признака роли, таблица `.mutations.tsv` с колонками
«номер / исход / узлы». Guard пропускает в каталоге документов задачи только
файлы первого уровня (кроме `acceptance_tests/`) — патчи и копии таблиц
лежат первым уровнем.

## Требования

1. Мутации до правки. Для каждой строки «Ловит мутацию» четырёх файлов волны
   и для каждого из 26 тестов `tests/test_notes.py` без такой строки (ему
   пишется строка «Ловит мутацию» — правдоподобная мутация, которую он
   ловит) готовится патч к коду `orchestrator/` в
   `tasks/<id>/mutation-<nnn>.diff` — файлом первого уровня каталога
   документов задачи: один патч — одна мутация, номера подряд. Строки,
   одинаковые по смыслу, — одна мутация со списком заявивших её тестов.
2. Прогон «до». Роль мутации вручную не прогоняет. Прогон — командой пульта
   `artel.py mutation-run <id> --ref base --tests <четыре исходных файла>`;
   набор при необходимости делится `--patches <a>-<b>` под предел шага.
   Для каждой мутации — полный список убивающих тестов. Мутация с исходом
   «ошибка сбора, импорта или setup» — не доказательство (патч
   переписывается). Мутация, не убитая никем, — находка в PLAN, не в
   доказательство. Копия таблицы `.mutations.tsv` «до» прикладывается к
   PLAN файлом первого уровня каталога документов задачи.
3. Свод: тесты четырёх файлов переносятся в новый файл
   `tests/test_notes_module.py` в стиле pytest: функции модуля, `assert`,
   фикстуры из `tests/fixtures.py` и собственные фикстуры файла (в том числе
   замена `SchemaTmpRootTest`), помощники с утверждениями — функции модуля.
   - Ожидание исключения: там, где исходный тест проверял текст исключения
     (`assertIn(X, str(exc))`, `assertRaisesRegex`), — `pytest.raises(E,
     match=re.escape(<текст>))`; голый `assertRaises(E)` →
     `pytest.raises(E)` без `match`.
   - `subTest` по литеральному набору → `pytest.mark.parametrize`
     литералами. Перебор по константам кода (`config.NOTE_SILENCE_WINDOW_STATES`,
     `OUTSIDE_WINDOW` и т. п.) литералами не замораживается:
     `parametrize` по самой константе
     (`@pytest.mark.parametrize("state", config.NOTE_SILENCE_WINDOW_STATES)`)
     либо прежний цикл в теле функции. Итерации, связанные общим состоянием,
     и случайный выбор — прежним циклом в теле функции.
4. Утверждения и проверяемые свойства при своде не меняются: ожидаемые
   значения переносятся дословно, сравнения не ослабляются (равенство не
   заменяется вхождением, точный текст — подстрокой, точное число —
   неравенством).
5. Дубль удаляется только при двух условиях: (а) каждую его мутацию по
   таблице «до» убивает и другой сохраняемый тест; (б) каждый литерал и вид
   каждого утверждения удаляемого теста есть в утверждениях сохраняемого
   теста, убивающего те же мутации. Удалённые дубли перечисляются в PLAN
   вместе со своими мутациями. Тест, чью заявленную мутацию не убил никто,
   не удаляется: его строка «Ловит мутацию» переписывается на мутацию,
   которую он убивает (со своим патчем), либо тест помечается находкой в
   PLAN.
6. У каждой функции нового файла — строка «Ловит мутацию:».
7. Прогон «после» — командой пульта
   `artel.py mutation-run <id> --ref worktree --tests tests/test_notes_module.py`
   на том же наборе патчей (при необходимости — частями `--patches <a>-<b>`).
   Каждая мутация, убитая «до», убита «после». Копия таблицы `.mutations.tsv`
   «после» прикладывается к PLAN файлом первого уровня каталога документов
   задачи. Число тестов, строк и время адресного прогона до и после — в PLAN.
8. Таблицы — формат `mutation-run` без изменений. Узлы «до» —
   `tests/<файл>::<Класс>::<метод>`, узлы «после» —
   `tests/test_notes_module.py::<функция>[<вариант>]`.
9. Четыре исходных файла удаляются. Объём мандата — требования 3–7: перенос
   с дословными ожиданиями и удаление дублей по таблице мутаций; удаление
   утверждения без переноса, ослабление сравнения, `skip`/`xfail`, подъём
   пределов не разрешены.
10. Ограничение зон по смыслу: в `tests/` — только удаление четырёх файлов
    волны и новый `tests/test_notes_module.py`; `tests/fixtures.py` и
    `tests/sandbox.py` не меняются; код `orchestrator/` не меняется (мутации —
    только во временной копии `mutation-run`).
11. Независимая проверка (сессия при Операторе) повторяет `mutation-run` на
    зафиксированном наборе патчей до approve на merge_gate; без неё мерж не
    одобряется.

## Критерии приёмки

AC-1. В каталоге документов задачи первым уровнем лежат патчи
`mutation-<nnn>.diff` с номерами подряд, без пропусков; каждый патч меняет
только файлы `orchestrator/` и несёт ровно одну мутацию. Каждая строка
«Ловит мутацию» четырёх исходных файлов и каждый из 26 тестов
`tests/test_notes.py` без такой строки сопоставлены в PLAN мутации; строки,
одинаковые по смыслу, сопоставлены одной мутации со списком заявивших её
тестов.

AC-2. К PLAN первым уровнем каталога документов задачи приложена копия
таблицы `mutation-run` «до» (`--ref base`, тесты — четыре исходных файла) в
формате команды без изменений; узлы — `tests/<файл>::<Класс>::<метод>`.
Каждая мутация набора есть в таблице; ни одна не засчитана убитой при
исходе «ошибка сбора, импорта или setup». Мутации, не убитые никем,
перечислены в PLAN находками и в доказательство не входят.

AC-3. Файл `tests/test_notes_module.py` есть на ветке; тесты в нём — функции
модуля в стиле pytest: в файле нет классов-наследников `unittest.TestCase`,
нет `subTest`; замена `SchemaTmpRootTest` объявлена фикстурой этого файла;
помощники с утверждениями — функции модуля, а не фикстуры. Каждый
`pytest.raises` с `match` несёт `re.escape(...)` и стоит только там, где
исходный тест проверял текст исключения; на месте голого `assertRaises(E)` —
`pytest.raises(E)` без `match`. Перебор по константе кода задан
`parametrize` по самой константе либо циклом в теле функции, не списком
литералов.

AC-4. Ожидаемые значения перенесённых тестов совпадают с исходными
дословно; ни одно сравнение не ослаблено: равенство не заменено
вхождением, точный текст — подстрокой, точное число — неравенством.

AC-5. У каждой тестовой функции `tests/test_notes_module.py` есть строка
«Ловит мутацию:».

AC-6. Каждый тест исходных файлов, не перенесённый в новый файл, перечислен
в PLAN удалённым дублем вместе со своими мутациями; каждую из этих мутаций
по таблице «до» убивает и другой сохраняемый тест, и каждый литерал и вид
каждого утверждения удалённого теста есть в утверждениях сохраняемого
теста, убивающего те же мутации. Тест, чью заявленную мутацию не убил
никто, не удалён.

AC-7. К PLAN первым уровнем каталога документов задачи приложена копия
таблицы `mutation-run` «после» (`--ref worktree`, тесты —
`tests/test_notes_module.py`) в формате команды без изменений; узлы —
`tests/test_notes_module.py::<функция>[<вариант>]`. Каждая мутация есть в
обеих таблицах; у каждой мутации, убитой «до», в таблице «после» исход
«убита» и назван убивший узел.

AC-8. PLAN называет число тестов, число строк и время адресного прогона до
и после свода.

AC-9. Файлов `tests/test_notes.py`, `tests/test_notes_apply.py`,
`tests/test_notes_row_format.py`,
`tests/test_01m563947r26nzw2tjekm36qrd_note_window_project.py` на ветке нет.

AC-10. В `tests/test_notes_module.py` нет `skip`/`xfail`, и пределы тестов
(таймауты, допуски, пороги) не подняты относительно исходных файлов.

AC-11. Diff ветки против её базы (база ветки задачи) в `tests/` — только
удаление четырёх файлов AC-9 и новый `tests/test_notes_module.py`;
`tests/fixtures.py`, `tests/sandbox.py` и всё под `orchestrator/` не
изменены.

1б (`doc-commit`). Внутри 1а свод и удаление неделимы: удаление исходных
файлов без нового файла теряет покрытие, новый файл без удаления оставляет

свод (например, по одному исходному файлу) потребовал бы своего мандата,
своего набора мутаций и своей независимой проверки на каждую часть. Зона —
один новый файл и четыре удаления в `tests/` плюс регенерация карты; резать
её поперёк по смыслу нечего.

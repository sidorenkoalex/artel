## Пути обхода гейтов
1. **Сторож роли и xdist.** Буквально исполнить `-n auto -p xdist` в шаге
   можно, только сняв `ARTEL_ROLE` в окружении подпроцесса pytest (сценарий
   на `python3` это позволяет). Это обход сторожа `conftest.py:80-86`. Другой
   путь — тихо прогнать последовательно и написать в PLAN «xdist».
2. **Дубли по выбранным самим мутациям.** Для 26 тестов без строки
   «Ловит мутацию» мутацию выбирает тот же исполнитель, который потом
   объявляет дубли (SPEC-1, SPEC-5). Мутацию, которую убивает и соседний
   тест, легко подобрать — и тест «по таблице» удаляется вместе с
   утверждениями, которые ни одна мутация не проверяла. «При тех же
   утверждениях» (SPEC.md:71-73, AC-6 SPEC.md:119-122) не определено, а
   значит, не держит. Держит только независимая проверка (SPEC-10).
3. **Пустой `match=`.** Буква AC-3 («ожидание исключения —
   `pytest.raises(..., match=…)`») на голом `assertRaises(SystemExit)`
   исполняется `match=""`/`match=".*"`. Форма соблюдена, проверки нет.
4. **Регэксп вместо подстроки.** `assertIn(notes.PRIORITY_FORM_EXAMPLE,
   str(cm.exception))` (`tests/test_notes_row_format.py:151`, `:233`) →
   `match=notes.PRIORITY_FORM_EXAMPLE` без `re.escape`: текст
   `orchestrator/notes.py:203` несёт `..` и скобки, регэксп совпадёт с иным
   текстом или не совпадёт с верным. Сравнение меняется незаметно для AC-4.
5. **Копия с мутациями в ветке.** Временная копия под `tests/` будет
   закоммичена WIP-чекпоинтом (`checkpoint.py:1843`). AC-11 это поймает, но
   только после факта.

## Вердикт
**concerns** — SPEC ведома дальше. Отклонения решаемы Оператором на гейте
SPEC (уточнение требований 2, 3 или строка ANSWER), возврат аналитику не
обязателен.

1. **Исполнимость `-n auto -p xdist` под ролью** — SPEC.md:55-57,
   SPEC.md:99-101. Сторож `conftest.py:80-86` роняет воркеры xdist в шаге
   роли (воспроизведено: «node down» ×70, «no tests ran»). Нужно решение:
   прогон «до» без xdist в шаге (≈12.7 с на прогон × число мутаций) либо
   прогон «до» вне шага, сессией Оператора. Иначе исполнитель либо отступит
   от AC-2, либо обойдёт сторожа (путь обхода 1).
2. **Место временной копии не названо** — SPEC.md:55-56, SPEC.md:86. Шагу
   доступны только рабочая копия и каталог документов. Подкаталог второго —
   посторонний файл (`scripts/guard.py:3027-3048`), копия под `tests/`
   уходит в ветку чекпоинтом (`orchestrator/checkpoint.py:1843`). Факт ТЗ о
   guard в SPEC потерян.
3. **AC-3 `pytest.raises(..., match=…)` против AC-4 «утверждения не
   меняются»** — SPEC.md:63, SPEC.md:108, SPEC.md:112-114. Голых
   `assertRaises(SystemExit)` без проверки текста много:
   `tests/test_notes.py:91`, `:111`, `:115`, `:136`, `:140`, `:157`, `:173`,
   `:177`, `:181`, `:221`, `:225`, `:229`, `:233`, `:237`, `:451`;
   `tests/test_notes_apply.py:125`. `match` для них — либо новое ожидание
   (свойство меняется), либо пустой шаблон (пути обхода 3). Для
   `assertIn(X, str(exc))` не сказано про `re.escape` (путь обхода 4).
   Предложение: `match=` только там, где исходник проверял текст, и с
   `re.escape(...)`; голый `assertRaises` → `pytest.raises(SystemExit)` без
   `match`.
4. **«`parametrize` литералами вместо `subTest`» против «свойства не
   меняются»** — SPEC.md:63, SPEC.md:107, SPEC.md:67. Циклы по
   `config.NOTE_SILENCE_WINDOW_STATES` и `OUTSIDE_WINDOW`
   (`tests/test_01m563947r26nzw2tjekm36qrd_note_window_project.py:49`,
   `:147`, `:188`, `:313`) проверяют «каждое состояние окна, какое есть в
   коде». Литералы замораживают набор. Кроме того, итерации связаны
   состоянием одной задачи (`:146-151`, `:313-318`), а случайный выбор
   (`:166`, `:196`, `:283`) литералом не выражается. Нужно решение
   Оператора: допускается ли для таких циклов цикл в теле функции (как
   сейчас) или `parametrize` по имени константы кода.
5. **Критерий дубля не определён** — SPEC.md:71-73, SPEC.md:119-122.
   Нужно определение, проверяемое механически, например: «литералы и вид
   каждого утверждения удаляемого теста есть у теста, убивающего те же
   мутации». Иначе удаление по самостоятельно выбранным мутациям проходит
   (путь обхода 2). Не сказано и о судьбе теста, чью заявленную мутацию не
   убил никто: переносится ли он с ложной строкой «Ловит мутацию:»
   (SPEC.md:58-60, SPEC.md:74).
6. **Формат таблиц PLAN не задан** — AC-1 (SPEC.md:92-97), AC-2
   (SPEC.md:99-103), AC-6, AC-7 (SPEC.md:124-126), AC-8. Не задана форма
   номера мутации и идентификатора теста (`путь::Класс::метод` «до»,
   `путь::функция[вариант]` «после»). Не сказано, повторяет ли планка
   прогоны мутаций. Без этого AC-2/AC-6/AC-7 проверяемы только по форме, и
   выдуманный список убийц пройдёт планку.
7. **ADR-0020 п. 8 для долгоживущего файла** — SPEC.md:15-17, SPEC.md:27-29.

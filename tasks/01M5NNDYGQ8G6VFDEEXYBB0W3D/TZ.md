# Сведение тестов, волна 1а (пробная): тесты копилки, бэклога и окна тишины (`orchestrator/notes.py`) — в один файл модуля в стиле pytest с доказательством множеством убиваемых мутаций

## Факты

Строка бэклога «Периодическая консолидация тестов артели вместе с переводом старых тестов на pytest» (поглощает «Объявленное сведение тестов» и «Сведение однотипных тестовых методов» — решение Оператора 23.10.2026). ADR-0027 п. 8 и ADR-0020 п. 8: перевод и удаление старых тестов — волнами консолидации, доказательство — множество убиваемых мутаций, мандат Оператора по путям и независимая проверка мутаций. Порядок волн (решение Оператора 23.10.2026): note (пробная) → outcome → merge → suite-run → остальные модули; мандат Оператора 23.10.2026 (дословно): «Волна сведения тестов по note; после бери все остальные модули в работу - даю мандат». Пробная волна по note делится на 1а (эта задача) и 1б (`doc-commit`: `tests/test_doc_commit.py`, `tests/test_doc_commit_suite_gate.py`, `tests/test_01m3y75x6k2zmd85971tcwv41e_held_base.py`, `tests/test_doc_commit_held_base.py`, `tests/test_01m4s0jvb85w9ty1esgnbh97fp_doc_commit.py`, `tests/test_notes_batch_flush_edges.py` — после этой задачи). Мандат на эту задачу выдаётся командой `answer` на гейте SPEC (строка с маркером и четырьмя путями через запятую, «Основание:», «## Матрица неослабления», «Независимая проверка:»).

## Требования

1. Мутации до правки. Для каждой строки «Ловит мутацию» четырёх файлов и для каждого из 26 тестов без строки (ему пишется строка «Ловит мутацию» — правдоподобная мутация, которую он ловит) — патч к коду `orchestrator/` в `tasks/<id>/mutation-<nnn>.diff` (один патч — одна мутация, номера подряд). Строки, одинаковые по смыслу, — одна мутация со списком заявивших её тестов. Прогон «до» — сценарием во временной копии вне рабочей копии ветки (мутации не попадают в ветку), исходные четыре файла, `-n auto -p xdist`: для каждой мутации — полный список убивающих тестов. Мутация, «убитая» ошибкой импорта или сбора, — не доказательство (патч переписывается). Мутация, не убитая никем, — находка в PLAN, не в доказательство. Таблица «мутация → убивающие тесты до» — в PLAN.
2. Свод: тесты четырёх файлов — в новый файл `tests/test_notes_module.py` в стиле pytest: функции модуля, `assert`, `pytest.raises(..., match=…)`, `parametrize` литералами вместо `subTest`, фикстуры из `tests/fixtures.py` и собственные фикстуры файла (в том числе замена `SchemaTmpRootTest`), помощники с утверждениями — функции модуля. Утверждения и проверяемые свойства не меняются: ожидаемые значения переносятся дословно, сравнения не ослабляются (равенство не заменяется вхождением, точный текст — подстрокой, точное число — неравенством). Дубль — тест, все мутации которого убивают и другие сведённые тесты при тех же утверждениях, — удаляется; удалённые дубли перечисляются в PLAN вместе со своими мутациями. У каждой функции нового файла — строка «Ловит мутацию:».
3. Прогон «после» — тот же сценарий на новом файле; вправе остановиться на первом убийстве (`-x`), начиная с перенесённых убийц. Каждая мутация, убитая «до», убита «после»; таблица «после» называет убивший тест. Число тестов, строк и время адресного прогона до и после — в PLAN.
4. Четыре исходных файла удаляются (мандат — командой `answer` на гейте SPEC; объём — требования 2–3: перенос с дословными ожиданиями и удаление дублей по таблице мутаций; удаление утверждения без переноса, ослабление сравнения, `skip`/`xfail`, подъём пределов не разрешены).
5. Независимая проверка (сессия при Операторе) повторяет прогон мутаций на ветке; без неё мерж не одобряется.

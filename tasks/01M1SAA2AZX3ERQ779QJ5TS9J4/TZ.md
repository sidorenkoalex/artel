# ТЗ: бриф роли после возврата цитирует причину возврата первым пунктом

Источник: бэклог 05.09 (`docs/backlog.md`). Трижды за день developer
после `reject` с подробной причиной (стек ч.3 — красный CI на раннере;
регрессия №13 — красная планка родительской задачи; канарейка ч.2 —
утечка изоляции тестов) отвечал «менять нечего»: причина возврата лежит в
журнале (`detail` записи `state -> in_dev`), а бриф её не несёт или несёт
неявно. Двигали задачу только ANSWER-n Оператора — $2 и итерация на каждый
случай.

Требуется:
1. Бриф роли developer (и любой роли, чей визит состояния начался
   возвратом с основанием: `review -> in_dev`, `reject` из
   acceptance/verifying/merge_gate, возврат из escalated по ANSWER)
   открывается разделом «Причина возврата» с дословным `detail`
   последней записи `state -> <текущее состояние>` журнала и, для
   `verifying`-reject, перечнем упавших джобов/тестов из той же записи.
2. Раздел стоит до SPEC/PLAN/REVIEW и снабжён требованием: «шаг без
   правки, закрывающей причину, не засчитывается» — согласовано с
   рубежом №13 (`in_dev -> review` не пропускает неизменённый код) и
   с задачей путей брифа (шаг без обязательного артефакта — failed).
3. Для первого визита состояния (без возврата) раздел отсутствует —
   бриф не меняется.
4. Тесты: бриф после `review -> in_dev` содержит текст замечаний
   ревью; после `reject` из verifying — текст причины с именами
   упавших тестов; после `escalated -> in_dev` по ANSWER — причину
   эскалации и ссылку на ANSWER-n; первый визит — раздела нет;
   существующие тесты брифа зелёные.

Зоны: orchestrator/brief.py, tests/. Порядок: сразу за задачей «пути в
брифе» (01M1RQ12JVHE3PQYDFV1XPSTQ3, та же зона) — планка сразу, код после
её мержа. Не входит: изменение формата журнала, новые состояния FSM.

Рамка: $15.

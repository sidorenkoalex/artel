# SPEC: Изоляция тестов от настоящего репозитория: артефактная ветка из песочницы

## Контекст
Наблюдение 03.09: в главной копии пульта накопилось 276 веток
`artifact/01m1…` без задачи в БД — по четыре на каждый прогон набора
тестов (69 прогонов с 01:12 03.09). Источник —
`tests/test_review_package.py::PreviousVerdictShaTest`: класс
подменяет `DB`/`TASKS`/`LOGS`/`WORKTREES` и `gitcmd.git`, но не
`config.ROOT`; `cmd_new` коммитит ТЗ в артефактную ветку через
`artifact_branch.commit_files` → `write_commit(config.ROOT, …)`,
который зовёт `subprocess.run` напрямую, мимо `gitcmd` и его подмены —
запись уходит в настоящий git пульта. Тот же приём (`git` в обход
`gitcmd`) есть в `snapshot.py`/пине. Тест не имеет права писать в
настоящий репозиторий пульта ни одной командой — это инвариант
изоляции (ADR-0002, принцип целостности; SPEC T048), и он должен быть
закреплён кодом, а не дисциплиной авторов тестов.

## Требования

1. Инвариант-тест: прогон набора тестов не меняет набор ссылок
   (`refs/heads/*`, `refs/artifacts/*`) и объектов настоящего
   репозитория пульта — снимок `git for-each-ref` до и после полного
   прогона совпадает. Механика — обе: проверка в `tests/sandbox.py`
   на уровне базового класса и отдельный сторож в CI (шаг workflow
   сравнивает ссылки до/после `unittest`).
2. Общая точка подмены: `artifact_branch.write_commit`, `commit_files`,
   `snapshot`, пин — все прямые вызовы `subprocess.run` с
   `cwd=config.ROOT` идут через один модуль (`gitcmd` либо новый
   тонкий слой), который песочница тестов подменяет одним патчем;
   `tests/sandbox.py` подменяет его по умолчанию для всех наследников
   базовых классов.
3. `PreviousVerdictShaTest` и все тесты, заводящие задачи через
   `cmd_new` без подмены `ROOT`, переведены на песочницу требования 2;
   проверка — `grep` по `tests/` и `tasks/*/acceptance_tests/` (в т.ч.
   `tasks/T029/acceptance_tests/test_incremental_diff.py`).
4. Уборка: служебное действие пульта (`doctor --fix` либо команда)
   удаляет ветки `artifact/<id>`, для которых нет задачи в БД, — с
   перечислением удалённого в вывод и записью в журнал алертов
   (`kind=incident`, одна запись на уборку); только по явному вызову
   Оператора, не автоматически. Ветки живых задач не трогаются.
5. Защищённые пути `.github/workflows/ci.yml` (сторож требования 1),
   `docs/invariants.md` (новая запись об инварианте) и
   `tests/test_invariants.py` (инвариант-тест требования 1) остаются
   в объёме задачи, но поставляются разработчиком как unified-diff-
   приложения к PLAN.md (`git apply --check` на чистом дереве перед
   сдачей, `conventions-core`); Оператор применяет их отдельно после
   `merge_gate` этой задачи (ANSWER-1).

## Критерии приёмки

AC-1. Прогон полного набора тестов не меняет набор ссылок
(`refs/heads/*`, `refs/artifacts/*`) настоящего репозитория пульта:
снимок `git for-each-ref` до и после прогона совпадает.

AC-2. Инвариант-тест из AC-1 красный на тесте, который пишет в
настоящий репозиторий пульта напрямую (мутация: прямой
`subprocess.run(["git", "update-ref", …], cwd=config.ROOT)`), и
зелёный после перевода `PreviousVerdictShaTest` и всех прочих тестов,
заводящих задачи через `cmd_new` без подмены `ROOT`, на общую точку
подмены.

AC-3. Все прямые вызовы `subprocess.run` с `cwd=config.ROOT` в
`artifact_branch.write_commit`, `commit_files`, `snapshot` и пине идут
через единый модуль, который `tests/sandbox.py` подменяет одним
патчем по умолчанию для всех наследников базовых классов.

AC-4. Служебное действие пульта, вызванное явно Оператором, удаляет
ветки `artifact/<id>`, для которых нет задачи в БД, перечисляет
удалённое в вывод и делает ровно одну запись `kind=incident` в журнал
алертов на весь прогон уборки; ветки живых задач не удаляются, и без
явного вызова Оператора уборка не запускается.

AC-5. Существующий набор тестов проходит зелёным без ослабления
существующих тестов, гейтов, лимитов и инвариантов.

## Не входит

- Изменение механики артефактной ветки и снапшотов (M1/A7).
- Удаление веток живых задач.
- Шифрование или перенос песочницы вне репозитория (канарейка v2 —
  отдельное ТЗ).
- Прямая правка защищённых путей (`.github/workflows/ci.yml`,
  `docs/invariants.md`, `tests/test_invariants.py`) в ветке задачи —
  эти три файла поставляются только как unified-diff-приложения к
  PLAN.md (ANSWER-1), не как коммиты в ветку задачи.

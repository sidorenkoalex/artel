# ТЗ: Изоляция тестов от настоящего репозитория: артефактная ветка из песочницы

# ТЗ: изоляция тестов от настоящего репозитория — запись артефактной ветки из песочницы

Источник: наблюдение 03.09. В главной копии пульта лежат 276 веток
`artifact/01m1…` с единственным коммитом «<id>: ТЗ Оператора (sha
предыдущего вердикта)» — по четыре на каждый прогон набора тестов
(69 прогонов с 01:12 03.09), задач с такими id в БД нет, до origin
ветки не дошли. Источник — `tests/test_review_package.py::
PreviousVerdictShaTest` (заведение через `catalog.cmd_new`, строка
~1001): класс подменяет `DB`/`TASKS`/`LOGS`/`WORKTREES` и `gitcmd.git`,
но не `config.ROOT`; после A7 `cmd_new` коммитит ТЗ в артефактную
ветку через `artifact_branch.commit_files` → `write_commit(config.ROOT,
…)`, который зовёт `subprocess.run` напрямую, мимо `gitcmd.git` и его
подмены, — запись уходит в настоящий git пульта. Тот же приём (`git`
в обход `gitcmd`) есть в `snapshot.py`/пине; аналогичная утечка
возможна у любого теста, не подменившего `ROOT` и `subprocess.run`
вместе.

Суть: тест не имеет права писать в настоящий репозиторий пульта ни
одной командой — это инвариант изоляции (ADR-0002, принцип
целостности; SPEC T048 требование об изоляции `cmd_new`), и он
должен быть закреплён кодом, а не дисциплиной авторов тестов.

Требуется:
1. Инвариант-тест (в духе `tests/test_invariants.py`): прогон
   набора тестов не меняет набор ссылок (`refs/heads/*`,
   `refs/artifacts/*`) и объектов настоящего репозитория пульта —
   снимок `git for-each-ref` до и после полного прогона совпадает.
   Механика на выбор аналитика: проверка в `tests/sandbox.py` на
   уровне базового класса, отдельный сторож в CI (шаг workflow
   сравнивает ссылки до/после `unittest`), либо оба.
2. Общая точка подмены: `artifact_branch.write_commit`,
   `commit_files`, `snapshot`, пин — все прямые вызовы `subprocess.
   run` с `cwd=config.ROOT` идут через один модуль (`gitcmd` либо
   новый тонкий слой), который песочница тестов подменяет одним
   патчем; `tests/sandbox.py` подменяет его по умолчанию для всех
   наследников базовых классов.
3. `PreviousVerdictShaTest` и все тесты, заводящие задачи через
   `cmd_new` без подмены `ROOT`, переведены на песочницу требования
   2; проверить `grep` по `tests/` и `tasks/*/acceptance_tests/`
   (в т.ч. `tasks/T029/acceptance_tests/test_incremental_diff.py`).
4. Уборка: служебное действие пульта (`doctor --fix` либо команда)
   удаляет ветки `artifact/<id>`, для которых нет задачи в БД, — с
   перечислением удалённого в вывод и записью в журнал алертов
   (kind=incident, одна запись на уборку); только по явному вызову
   Оператора, не автоматически. Ветки живых задач не трогаются.
5. Тесты: инвариант требования 1 красный на тесте, пишущем в
   настоящий репозиторий (мутация: прямой `subprocess.run(["git",
   "update-ref", …], cwd=config.ROOT)`), зелёный после перевода;
   уборка требования 4 удаляет только сиротские ветки; существующие
   тесты зелёные без ослабления.

Зоны: tests/sandbox.py, tests/test_review_package.py,
tests/test_invariants.py, orchestrator/artifact_branch.py,
orchestrator/gitcmd.py, orchestrator/snapshot.py, orchestrator/
doctor.py, .github/workflows/ci.yml (сторож — мандат этим ТЗ),
docs/invariants.md (новый инвариант). Конфликт зон с hotfix
01M1KT0792125J9ZNJNZJ86E9Q и задачей автокоммита/.gitignore
(artifact_branch.py, doctor.py): стартовать после их мержа; до
мержа — только SPEC.

Не входит: изменение механики артефактной ветки и снапшотов (M1/A7);
удаление веток живых задач; шифрование или перенос песочницы вне
репозитория (канарейка v2 — отдельное ТЗ).

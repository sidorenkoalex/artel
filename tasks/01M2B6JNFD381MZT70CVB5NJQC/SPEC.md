# SPEC: Гейт зон: собственный каталог задачи и уборка планки после подтяжки

## Контекст
Выход `in_dev` (`orchestrator/fsm_advance.py`) на переходе `in_dev -> review`
сначала подтягивает main (`fsm._pull_main_or_escalate`), затем звонит
гейт зон (`_zones_gate`). Подтяжка (`orchestrator/pull.py`,
`_materialize_and_run_plank`) после успешного merge материализует планку
задачи (`tasks/<task_id>/acceptance_tests/`) НА МЕСТЕ, в worktree, через
`acceptance.materialize_from_branch`, гоняет её и оставляет файлы в
worktree неотслеживаемыми. Довесок гейта зон, считающий неотслеживаемые
файлы worktree диффом вне зон (01M290PVYG, AC-6), не знает исключения
«собственный каталог задачи», которое уже применяет
`checkpoint._zone_paths` к WIP-чекпоинтам, — и отказывает переход, считая
материализованную планку файлами вне заявленных зон. 12.09 это дало
четыре ложных отказа на четырёх задачах волны 3, каждый — стоп-кран
`auto` и ручной обход Оператора (docs/backlog.md, строка П1 12.09).
Отказ воспроизводится только когда подтяжку на этом выходе выполняет сам
`pull.evaluate` (ветка была не свежа) — если ветку уже подтянул шаг
developer, материализации до гейта нет и ложного отказа тоже нет.

## Требования
1. Довесок неотслеживаемых файлов worktree в гейте зон (`_zones_gate`,
   `orchestrator/fsm_advance.py`) не считает путями вне зон файлы под
   `tasks/<task_id>/` — собственным каталогом задачи, тем же правилом,
   что `checkpoint._zone_paths` (`orchestrator/checkpoint.py`) уже
   применяет к WIP-чекпоинтам. Правило «каталог задачи — своя зона» —
   единый источник, которым пользуются оба места, без изменения
   поведения `checkpoint`. Неотслеживаемые файлы worktree ВНЕ
   `tasks/<task_id>/` по-прежнему считаются путями вне зон — сегодняшнее
   поведение (01M290PVYG, AC-6) сохраняется байт-в-байт.
2. `pull._materialize_and_run_plank` после прогона приёмочных тестов
   убирает материализованный каталог `tasks/<task_id>/acceptance_tests/`
   из worktree, если до материализации этого каталога там не было (файлы,
   лежавшие в worktree до материализации, не трогает). Источник истины
   планки остаётся артефактная ветка задачи — диск нужен ей только на
   время прогона.
3. Пропуск неотслеживаемых путей под `tasks/<task_id>/` гейтом зон не
   журналируется отдельной записью (это штатное поведение). Уборка
   материализованного каталога планки после подтяжки не создаёт новую
   запись журнала, если убирать нечего.
4. Тесты (`tests/test_zones_gate.py` либо соседний файл гейта,
   `tests/test_pull.py`) покрывают:
   а) worktree с неотслеживаемым `tasks/<task_id>/acceptance_tests/
      test_x.py` и коммиченным диффом строго в заявленных зонах — гейт
      зон переход пропускает;
   б) неотслеживаемый файл вне `tasks/<task_id>/` (файл кода вне
      заявленных зон) — прежний отказ гейта зон сохраняется;
   в) после исхода `Pulled` на стенде с bare origin (по образцу
      существующих тестов `pull`) каталог `tasks/<task_id>/
      acceptance_tests/` в worktree отсутствует, а прогон приёмочных
      тестов на материализованной планке фактически состоялся;
   г) существующие тесты гейта зон, `checkpoint` и `pull` проходят без
      ослабления.

## Критерии приёмки
AC-1. Гейт зон (`_zones_gate`) не считает путём вне зон неотслеживаемый
файл под `tasks/<task_id>/` — единым правилом с `checkpoint._zone_paths`,
без изменения поведения `checkpoint`: worktree с неотслеживаемым
`tasks/<task_id>/acceptance_tests/test_x.py` и коммиченным диффом строго
в заявленных зонах — переход `in_dev -> review` гейт зон пропускает.

AC-2. Неотслеживаемый файл ВНЕ `tasks/<task_id>/` (файл кода вне
заявленных зон) по-прежнему считается путём вне зон и вызывает отказ
гейта зон — сегодняшнее поведение (01M290PVYG, AC-6) сохраняется
байт-в-байт.

AC-3. `pull._materialize_and_run_plank` после прогона приёмочных тестов
убирает материализованный каталог `tasks/<task_id>/acceptance_tests/` из
worktree, если до материализации этого каталога там не было; файлы,
лежавшие в worktree до материализации, не трогает. Источник истины
планки остаётся артефактная ветка задачи.

AC-4. После исхода `Pulled` (подтяжка main через `pull.evaluate` на
стенде с bare origin) каталог `tasks/<task_id>/acceptance_tests/` в
worktree отсутствует, при этом прогон приёмочных тестов на
материализованной планке фактически состоялся.

AC-5. Пропуск неотслеживаемых путей под `tasks/<task_id>/` гейтом зон не
создаёт отдельной записи журнала. Уборка материализованного каталога
планки после подтяжки не создаёт новую запись журнала, если убирать
нечего.

AC-6. Существующие тесты гейта зон (`tests/test_zones_gate.py`),
`checkpoint` (в т.ч. `tests/test_checkpoint_zone_filter.py`) и `pull`
(`tests/test_pull.py`) проходят без ослабления — ни один существующий
тест не удалён и не смягчён.

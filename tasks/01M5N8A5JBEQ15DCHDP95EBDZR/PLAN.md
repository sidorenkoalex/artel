# PLAN: Сброс удержанных записей копилки, бэклога и doc-commit — одним пушем

## Подход
`_flush_pending` (`orchestrator/notes.py`) делит удержанные записи на две
группы: правки конфигурации (`_suite_gate_applies`) и все остальные.
Остальные уходят новым помощником `_flush_batch`: каждая попытка —
fetch+checkout свежего `origin/main` (`_fresh_main`), затем по порядку
`_pending_paths()` каждая запись строится прежними `_build_*`
(`_build_on_batch`) поверх головы пакета и коммитится своим коммитом
(`_commit_on_batch`, прежнее сообщение и идентичность), затем один
`push`. Отказ push — перестройка пакета целиком заново через `_build_*` от
свежего origin (не rebase/cherry-pick), не больше `MAX_PUSH_ATTEMPTS`.
Правки конфигурации — после пакета прежним `_attempt` по одной (с гейтом
набора); попутный сброс пропускает их прежней строкой.

Точка отсчёта сверки передаётся параметром `ref` (по умолчанию
`FETCH_HEAD` — путь `_run` не меняется) в `_build_doc_commit`,
`_build_apply`, `_content_already_in_origin`, а также в вызываемые из
`_build_apply` `_foreign_base_refusal`/`_foreign_backlog_commits` (диапазон
`<known>..FETCH_HEAD` иначе считался бы не от головы пакета). `known`:
первая вошедшая в пакет запись — `_known_origin_main` до fetch сброса,
запись k > 1 — голова пакета перед ней в первом построении; словарь
`knowns` хранит эти значения на время перестроек. `base_blob` `--apply`
первого построения живёт в самом `request` до конца сброса.

После успешного push по каждой записи пакета в порядке: файл удержания
удаляется, `_journal_commit` со sha её коммита, строка вывода
(`_sent_line`: `<путь> закоммичен в origin/main: <sha>`,
`docs/backlog.md заменён заготовкой в origin/main: <sha>`,
`заметка (<раздел>) отправлена в origin/main: <sha>`). Отказ построения
записи печатается прежней строкой `удержанная запись не отправлена: …`,
запись выбывает из сброса и остаётся удержанной.

Бюджет SPEC ($25) не пересматривается: один модуль, тесты написаны автором
тестов.

## Влияние на систему
- Путь одной новой записи `_run`, `--now`, окно тишины, тексты удержания и
  отказов не меняются: новые параметры сверок имеют прежнее умолчание
  `FETCH_HEAD`; `_fetch_and_build`, `_commit_and_push`, `_attempt` не
  тронуты (`_attempt` по-прежнему отправляет правки конфигурации с гейтом
  полного набора).
- Пиновая сверка не ослаблена: `known` первой записи — голова клона до
  fetch сброса (проверено временной мутацией `known = head` — оба теста
  AC-11 красные, код возвращён).
- Существующие тесты `tests/` не правились; долгоживущий файл задачи не
  правился.
- Откат — revert коммита задачи: формат файлов удержания не менялся,
  удержанные записи совместимы в обе стороны.

## Риски
- Коммит записи пакета может не создаться (git отказал) — запись выбывает
  из сброса со строкой `удержанная запись не отправлена: коммит записи <id>
  не создан`, правка снимается с индекса и дерева (`reset` +
  `_restore_tree`), пакет идёт дальше.
- Исчерпание попыток печатает одну строку без sha; записи остаются
  удержанными.

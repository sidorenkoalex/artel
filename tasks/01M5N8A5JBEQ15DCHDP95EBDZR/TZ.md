# Сброс удержанных записей копилки, бэклога и doc-commit отправляет их одним пушем

## Факты

Строка бэклога 23.10 «Сброс удержанных записей (note --flush, doc-commit --flush) — одним пушем». Сверено с `origin/main` 2b187a3d.

- Удержанные окном тишины записи (`note`, `doc-commit`, заготовки бэклога) лежат файлами в `.artel/notes-pending/` и отправляются `notes._flush_pending` (`orchestrator/notes.py:1270`): явно (`note --flush`, `doc-commit --flush`) или попутно в начале следующего `note`/`doc-commit` вне окна. Для каждой записи по очереди зовётся `_attempt(request)` → `_run` → `_fetch_and_build` и `_commit_and_push` (около :1201 — `git push -q origin …`): одна запись — один коммит и один push.
- Прецедент 23.10: шесть удержанных записей ушли шестью пушами за 15 с (18afb9a8 … 84c784aa). CI на документный пуш main пропускает полный набор, только если завершённый прогон CI родителя зелёный (`scripts/ci_push_class.py:120–131`); у каждого из шести родителя CI ещё шёл — «нет данных о родителе — тесты идут», шесть полных наборов по ~17 мин вместо одного. Итог корректен, лишняя — трата раннеров и очередь CI, которую ждут `approve` и `pin-update`.
- Запись, отправка которой заводит прогон полного набора (`_suite_gate_applies`, правка конфигурации), попутно не отправляется (:1295–1300).

## Требования

1. `_flush_pending` строит коммиты всех удержанных записей, готовых к отправке, последовательно в рабочем репозитории заметок (каждая — своим коммитом с прежним сообщением, прежней валидацией и сверкой по базе) и отправляет их одним `push`. Порядок коммитов — порядок удержания (как сейчас перебирает `_pending_paths()`).
2. Записи с `_suite_gate_applies` (правка конфигурации) отправляются, как сейчас, по одной, после пакета остальных; их правила (прогон набора, попутный пропуск) не меняются.
3. Отказ валидации одной записи не рушит пакет: запись остаётся удержанной, причина печатается (как сейчас), остальные идут в пакет. При non-fast-forward пакет перестраивается от свежего `origin/main` целиком, не более `MAX_PUSH_ATTEMPTS` попыток; файлы удержания удаляются только после успешного push и только у записей, вошедших в отправленный пакет.
4. Вывод: по каждой записи — прежняя строка с sha её коммита; один push.
5. Окно тишины, тексты удержания, `--now`, отправка одной новой записи вне удержания — без изменений.
6. Тесты (новый файл в `tests/`, у каждого — «Ловит мутацию:»; песочница с локальным bare-origin, без сети): (а) три удержанные записи (копилка, бэклог, doc-commit) → `note --flush` делает ровно один push (шпион на `gitcmd`/запуск `git push`), в origin три коммита в порядке удержания, файлов удержания нет; (б) одна из трёх не проходит валидацию — две ушли одним push, третья осталась удержанной, причина напечатана; (в) origin ушёл вперёд между построением и push — пакет перестроен, в origin все три коммита поверх чужого, push успешный; (г) удержанная правка конфигурации — отдельной отправкой после пакета, прежним путём; (д) попутный сброс в начале `note` вне окна — тоже одним push.
7. Существующие тесты не правятся и остаются зелёными.

Зоны: orchestrator/notes.py, docs/codebase-map.md, tests/

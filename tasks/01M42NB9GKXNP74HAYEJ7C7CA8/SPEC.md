## Контекст
Задача 01M41VTQJ9DSX64NFMFAF9W53B прошла три лишних шага developer и две
эскалации ради мандата на тесты снимаемого механизма (копилка 04.10.2026,
П2; решение Оператора 04.10.2026 «1 и 2»). Две причины. Первая:
элемент мандата `путь::Класс` сейчас не покрывает находки о методах этого
класса (`orchestrator/advance_gates/test_integrity.py::Finding.mandate_elements`

ANSWER-1 с `tests/test_guard_artifact_branch_mode.py::IsDraftLenientTest`
получил отказ по 12 методам двух классов. Вторая: в `in_dev`/`review`
команда `answer` (`orchestrator/answer.py::_cmd_answer`) принимает только
файл с мандатом расширения зон, файл с мандатом тестов отклоняется — уточнить
мандат тестов можно только новой эскалацией developer (полный шаг роли).

## Требования
1. Элемент мандата тестов вида `путь::Класс` покрывает находки гейта
   сохранности тестов о самом классе и о любом его методе
   (`путь::Класс::метод`). Элемент `путь::Класс::метод` покрывает только
   находку об этом методе. Элемент-путь файла покрывает все находки файла,
   как сейчас. Правило действует везде, где гейт сохранности тестов сверяет
   находки с мандатом (переход `in_dev -> verifying` и гейт мержа).
2. Запись журнала «разрешено ANSWER-n» при покрытии находок мандатом
   называет покрытые находки, как сейчас (в том числе покрытые через
   элемент-класс).
3. `answer <id> <файл>` в состояниях `in_dev` и `review` принимает файл,
   несущий строку мандата тестов («Ослабление тестов разрешено: …»): строка
   разбирается и проверяется тем же разбором и проверкой, что в
   `escalated`; рубеж «вызов из окружения роли — отказ» действует так же,
   как сейчас для мандата зон. При приёме ANSWER-n коммитится в ссылку
   документов задачи, состояние задачи не меняется, журнал получает запись
   с элементами мандата тестов.
4. `answer <id> <файл>` в `in_dev`/`review` с файлом без маркеров мандата
   (ни зон, ни тестов) — прежний отказ, ANSWER не создаётся. Приём файла с
   мандатом расширения зон в этих состояниях не меняется.
5. Подсказка гейта сохранности тестов при отказе
   (`test_integrity._mandate_hint`) называет обе формы доставки мандата:
   команда `answer` в `in_dev` и команда `answer` в `escalated`.
6. Свойства требований 1, 3 и 4 держат тесты в `tests/`, каждый — с
   заявкой «Ловит мутацию». Долгоживущие приёмочные тесты автора тестов
   (`tests/test_01m42nb9gkxnp74hayej7c7ca8_*.py`) этими тестами и
   засчитываются; повторять их отдельными тестами `tests/` не требуется.

## Критерии приёмки

AC-1. Находки гейта сохранности тестов об исчезнувших методах класса `A`
файла `tests/x.py` покрыты мандатом с элементом `tests/x.py::A`: переход
не отказывает по этим находкам, журнал «разрешено ANSWER-n» называет их.

AC-2. Мандат с элементом `tests/x.py::A` не покрывает находки об
исчезнувших методах другого класса `B` того же файла: гейт отказывает по
находкам класса `B`.

AC-3. Мандат с элементом `tests/x.py::A::m1` покрывает находку о методе
`A::m1` и не покрывает находку о методе `A::m2` того же класса: гейт
отказывает по `A::m2`.

AC-4. `answer <id> <файл>` для задачи в `in_dev` с файлом, несущим строку
«Ослабление тестов разрешено: …», завершается успешно: ANSWER-n
закоммичен в ссылку документов задачи, состояние задачи осталось `in_dev`,
в журнале — запись, называющая элементы мандата тестов.

AC-5. `answer <id> <файл>` для задачи в `in_dev` с файлом без маркеров
мандата отказывает с прежним текстом «answer доступна только для задачи в
состоянии escalated», ANSWER не создаётся, состояние не меняется.

AC-6. `answer <id> <файл>` для задачи в `in_dev` с файлом, несущим строку
мандата тестов, вызванная из окружения роли (`runner.in_role_environment()`
истинно), отказывает; ANSWER не создаётся.

AC-7. Текст отказа гейта сохранности тестов (подсказка `_mandate_hint`)
называет доставку мандата командой `answer` и в состоянии `in_dev`, и в
состоянии `escalated`.

# ТЗ: Дедупликация liveness-хелперов и lease-обвязки

## Контекст

Ревизия 28.08, находки CR-2026-08-28-3 (★4) и CR-2026-08-28-4
(docs/audits/code-revision-2026-08-28.md), очередь Оператора п.2б
роадмапа. Контур параллельности T044–T053 писался разными прогонами
конвейера и наплодил дубли:

- CR-3: `_age_seconds` — lease.py:44 и merge_lock.py:28 (байт-в-байт);
  `_pid_alive` — doctor.py:535 и merge_lock.py:34 (байт-в-байт,
  докстринг второй копии сам ссылается на первую). Три места знают
  формат heartbeat_ts (`strptime` формата store.now()) — менять формат
  страшно; следующий замок склонирует четвёртую копию.
- CR-4: связка resolve_session_id → acquire → отказ → try/finally
  release-если-fresh повторена 8 раз: fsm.py (advance, approve,
  reject), runner.py (run), auto.py (auto), budget.py (budget),
  cleanup.py (kill), workspace.py (workspace); две вариации отказа
  (sys.exit против print+return). Девятая команда сегодня копирует
  восьмую копию.

## Решение (Оператор 28.08, «по рекомендации» ревизии + очередь п.2б)

Одна задача класса «рефакторинг» (правила T015 из скила ревизии):

1. CR-3: единственные определения `_age_seconds` и `_pid_alive` — в
   одном модуле (естественное место — orchestrator/lease.py либо новый
   маленький orchestrator/liveness.py — выбор за developer в PLAN);
   merge_lock.py и doctor.py переходят на импорт. Дедупликация только
   идентичных кусков.
2. CR-4: обвязка lease мутирующих команд сворачивается в одну точку —
   контекст-менеджер (или эквивалент) в lease.py с параметром
   поведения отказа (sys.exit против print+return); все 8 вызывателей
   переходят на него. Семантика каждого вызывателя сохраняется
   в точности: тот же текст отказа, тот же канал (exit-код/печать),
   release только для fresh, поведение kill (инвариант 14) не
   меняется.

## Границы (правила ТЗ класса «рефакторинг», T015)

- Поведение не меняется. Наблюдаемые поверхности: CLI-вывод и тексты
  отказов всех 8 команд, журнал, схема БД, вывод doctor — байт-в-байт.
  Зелёность всех существующих тестов = неизменность поведения.
- Тесты: сценарии и ассерты не меняются; допустимы только импорты и
  пути патчей (mock.patch.object адресует новый дом хелперов) —
  ревьюер сверяет по диффу.
- Никаких попутных улучшений; только перечисленные переносы.
- PLAN: таблица переносов (что, откуда, куда) + откат revert'ом
  одного merge; смоук до/после: полный прогон unittest с фиксацией
  «числа равны, все зелёные».
- Только orchestrator/, тесты (импорты/пути патчей), карта.

## Приёмка (минимум)

- `_age_seconds` и `_pid_alive` определены ровно по одному разу;
  grep по репозиторию это подтверждает (вне tasks/*/acceptance_tests).
- Обвязка lease: acquire/release зовутся из одной общей точки;
  8 команд переходят на неё; grep прямых пар acquire+release по
  вызывателям — ноль остаточных копий.
- Полный набор тестов зелёный, число тестов не уменьшилось.
- Тексты отказов lease и вывод doctor не изменились (существующие
  тесты, сверяющие тексты, зелёные без правок ассертов).

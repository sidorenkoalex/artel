# SPEC: lease — перехват мёртвого держателя на своём хосте без ожидания порога протухания

## Контекст
Факт 11.09: два цикла мержа (01M28NWK5X, 01M28NX43E) были прерваны,
чтобы уступить merge-окно соседней сессии; возобновить `approve` пульт
не давал 32 минуты — «задачу ведёт сессия … — подожди её», хотя pid
держателя на этом же хосте был проверяемо мёртв, а `doctor` показывал
`[FAIL] leases: … lease сессии … мёртв`. Снято операторской командой
`release <id>`.

Причина — в `lease.acquire` (`orchestrator/lease.py`): при возрасте
heartbeat не старше `config.LEASE_STALE_AFTER_SEC` (7200 с) чужой lease
того же hostname отказывает всегда; проверка `liveness._pid_alive`
стоит ПОСЛЕ порога и сейчас влияет только на текст причины перехвата, а
не на факт перехвата. Живость держателя на своём хосте проверяема
мгновенно, но не используется как самостоятельное основание перехвата.

## Требования

1. Перехват без ожидания порога: если hostname держателя lease
   совпадает со своим и `liveness._pid_alive(pid)` держателя даёт
   `False`, `lease.acquire` перехватывает lease сразу — независимо от
   возраста heartbeat относительно `config.LEASE_STALE_AFTER_SEC`. Запись
   журнала — та же, что уже пишет текущий перехват по протуханию
   (событие «lease перехвачен», формат `orchestrator/lease.py:104-108`),
   с прежним session_id и pid держателя.
2. `config.LEASE_STALE_AFTER_SEC` остаётся единственным основанием
   перехвата в двух случаях, поведение которых не меняется: (а) чужой
   ДРУГОЙ hostname при свежем heartbeat — pid там непроверяем, отказ
   всегда, независимо от живости/мёртвости pid; (б) свой hostname при
   свежем heartbeat, но ЖИВОЙ pid держателя — отказ. В обоих случаях
   отказ по-прежнему именованный: session_id держателя, hostname,
   числовой возраст heartbeat — «подожди её».
3. Гонка двух перехватчиков одного и того же мёртвого lease: только
   один перехват засчитывается; второй вызывающий получает именованный
   отказ «lease уже перехвачен сессией …» — не выполняет повторную
   запись и не создаёт вторую запись журнала о перехвате.
4. `doctor` (проверка leases, `orchestrator/doctor/leases.py`) в строке
   о мёртвом держателе на своём хосте подсказывает, что следующий
   `approve`/`auto` перехватит lease сам и `release <id>` для этого
   больше не нужен. `orchestrator/doctor/leases.py` не входит в зоны
   этой задачи — занят задачей очереди мержа 01M28VZ8Q1. Если для этого
   требования нужна правка именно в этом файле, оформи её приложением
   (unified-диф) к PLAN.md, не прямой правкой в рамках этой задачи.
5. Существующие тесты `lease` (`tests/test_lease.py`) и `doctor`
   (в части проверки leases) — без ослабления: не удаляются и не
   смягчаются условия существующих сценариев.

## Критерии приёмки

AC-1. Чужой lease на СВОЁМ hostname с мёртвым pid держателя
(`liveness._pid_alive` → `False`) перехватывается немедленно, даже
если heartbeat моложе `config.LEASE_STALE_AFTER_SEC`.

AC-2. Перехват из AC-1 пишет запись журнала «lease перехвачен» тем же
текстом/форматом, что и существующий перехват по протуханию, с
причиной «pid держателя мёртв (pid <pid>)» и указанием прежнего
session_id и pid держателя.

AC-3. Чужой lease на СВОЁМ hostname с ЖИВЫМ pid держателя при
heartbeat моложе порога — отказ «подожди её» (именует session_id,
hostname, числовой возраст heartbeat), поведение не меняется.

AC-4. Чужой lease ДРУГОГО hostname при heartbeat моложе порога —
отказ независимо от живости/мёртвости pid держателя (pid чужого host
не проверяется), поведение не меняется.

AC-5. `config.LEASE_STALE_AFTER_SEC` остаётся единственным основанием
перехвата в сценариях AC-3 и AC-4 — перехват по протуханию (heartbeat
старше порога) не меняется ни для своего, ни для чужого hostname.

AC-6. Гонка двух перехватчиков одного и того же мёртвого lease:
успешен только один перехват; второй вызывающий получает именованный
отказ «lease уже перехвачен сессией …», не создавая вторую запись
журнала о перехвате.

AC-7. `doctor`, строка о мёртвом держателе lease на своём хосте,
содержит подсказку, что следующий `approve`/`auto` перехватит lease
сам и `release <id>` для этого больше не требуется.

AC-8. Тест на перехват из AC-1 ловит мутацию «проверка живости pid
выполняется после порога, не как условие немедленного перехвата» —
красный, если немедленный перехват своего мёртвого держателя убрать,
оставив прежнее поведение (отказ до истечения порога).

AC-9. Существующие тесты `tests/test_lease.py` и тесты `doctor` в
части проверки leases проходят без ослабления — ни один существующий
сценарий не удалён и не смягчён.

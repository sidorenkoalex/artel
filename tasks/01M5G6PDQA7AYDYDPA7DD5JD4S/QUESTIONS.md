1. **Тело `test_ac1_outcome_carries_relative_assertion_location` во вспомогательный метод: гейт неослабления теряет 5 утверждений.**
   ТЗ п. 3 требует: «тело метода — во вспомогательном методе с параметром
   зерна». Тело зовёт `self.git(...)` пять раз
   (`tests/test_01m4nz5w9ztkgtw7dgzqgmp2gp_two_sided_observation.py:609–611`,
   `:615–616`); `RealGitSandbox.git` несёт
   `self.assertEqual(res.returncode, 0, …)` (`tests/sandbox.py:1956–1959`).
   Гейт учитывает свои утверждения метода и помощников ПЕРВОГО уровня, каждый
   вызов отдельно (`scripts/guard.py:1892–1914`, `:1957–1962`). После
   переноса `self.git` становится помощником второго уровня: учёт 9 → 4,
   пять LOST (проверено аудитором вызовом `guard.changed_test_assertions`).
   Мандата на этот метод нет (ANSWER-1 — только метод kill), гейт `in_dev ->
   verifying` откажет.
   - A) Мандат строкой ANSWER: `Ослабление тестов разрешено: tests/test_01m4nz5w9ztkgtw7dgzqgmp2gp_two_sided_observation.py::OutcomeLocationTest::test_ac1_outcome_carries_relative_assertion_location`; тело целиком переезжает в помощник по букве ТЗ п. 3.
     - ломается: ничего в поведении теста; гейт по этому методу перестаёт считать пять проверок кода возврата git.
     - ослабляется: учёт гейтом проверки «каждая команда git подготовки фикстуры успешна» (`tests/sandbox.py:1956–1959` через вызовы `:609–616`); во время прогона проверка остаётся — `self.git` по-прежнему утверждает, но будущая правка помощника пройдёт гейт без мандата.
     - цена: нет сверх текущего; одна строка ANSWER.
     - чьё решение: Оператор (мандат на ослабление).
   - B) Без мандата: в помощник с параметром зерна переезжает генерация литералов, `two_sided.run` и все утверждения метода; подготовка репозитория (запись файлов, пять `self.git`, `self.checkout`) остаётся в теле каждого тестового метода — и метода со случайным зерном, и теста на зерне 189949286 (общая часть подготовки — без `self.git` внутри помощника). Требование 8 SPEC формулируется так: «утверждения метода и вызовы `self.git` стоят в учёте гейта на первом уровне, учёт по методу не меньше прежнего (9)».
     - ломается: буква ТЗ п. 3 «тело метода — во вспомогательном методе» выполняется частично (подготовка git остаётся в методах).
     - ослабляется: ничего — гейт по методу полный (`scripts/guard.py:1957–1962`).
     - цена: около десяти повторённых строк подготовки во втором методе; разработчику — чуть больше работы, аудиту — ещё одна проверка учёта.
     - чьё решение: Оператор (отступ от формы ТЗ п. 3).
   - C) Без переноса тела: метод со случайным зерном берёт литералы из функции генерации; отдельного сквозного «теста на зерне 189949286» нет — падавшее зерно закрывает тест генерации (AC-11: неравенства для 0…19999 и четырёх названных зёрен).
     - ломается: из ТЗ п. 3 выпадает «тест на зерне: сценарий метода выполняется с зерном 189949286 и зелёный».
     - ослабляется: ничего в существующих тестах; не появляется новый сквозной прогон падавшего зерна (корень — совпадение литералов — держит тест генерации).

     - чьё решение: Оператор (сужение ТЗ п. 3).

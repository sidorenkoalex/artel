## Пути обхода гейтов
1. **Атомарность повтора `run_stamp` — мимо цели.** Требование 1 (и п.1
   ТЗ) задаёт имя файла записи «`run_stamp` и pid», требование 3 и AC-6 —
   отказ исключительным созданием «файла записи реестра». Два разных
   процесса, стартовавших в одну секунду, получат одинаковый `run_stamp`,
   но разные имена файлов — `O_EXCL` у них не столкнётся никогда, оба
   прогона пойдут и смешают строки `canary_runs` одного `run_stamp` (ровно
   то, что ломает отбор файла результата по требованию 9). AC-6
   выполняется буквально тестом, заранее создавшим файл с именем
   собственного pid. Решение №6 Оператора внесено дословно — расхождение
   сидит между ним и именем файла из ТЗ.
2. **Точное равенство времени старта.** «Время старта совпало с
   записанным» (требование 2) при одном помощнике `ps lstart` на macOS
   стабильно; на Linux `lstart` выводится из `btime` + тиков, и сам модуль
   закладывает погрешность до 2 с (`stale_cycles.py:34-36`,
   `_LSTART_SPAN`). Расхождение на секунду между записью и сверкой — по
   букве «другое время старта»: запись живого прогона удаляется, окно и
   запрет мержа снимаются (fail-open). Пульт сейчас на darwin — риск
   низкий, но допуск не задан.
3. (наблюдение) Запись пишется «до первого клона», обработчик сигналов
   ставится на `canary.py:2858`. Запись, созданная до `with
   _interrupt_on_signal()`, при SIGTERM в этом промежутке не снимается
   `finally`, но процесс мёртв — функция чтения её уберёт со строкой
   журнала. Самозалечивается; разработчику — ставить запись внутри
   области обработчика или в `try/finally`, охватывающем её.

## Вердикт
`concerns` — все шесть решений гейта №1 внесены, адреса верны, зоны
достаточны, ослаблений нет. Отклонения, решаемые Оператором на гейте:

1. **Исключительное создание не ловит повтор `run_stamp` двумя
   процессами** — SPEC.md требование 1 («имя — `run_stamp` и pid») против
   требования 3 и AC-6 («файл записи реестра создаётся исключительным
   созданием»). Варианты: (а) отдельный файл-метка с именем только из
   `run_stamp`, создаётся `O_EXCL` вместе с записью и снимается вместе с
   ней (имя записи по ТЗ сохраняется); (б) имя записи — только
   `run_stamp` (расходится с п.1 ТЗ); (в) принять: повтор ловится только
   внутри одного процесса. Дефолт аудитора — (а), AC-6 дополнить
   сценарием «второй процесс с тем же `run_stamp` — отказ».
2. **Допуск сверки времени старта не задан** — требование 2, AC-5:
   «совпало» при погрешности источника до 2 с на Linux
   (`orchestrator/doctor/stale_cycles.py:34-36`). Дефолт: равенство с
   допуском `_LSTART_SPAN` либо принять точное равенство (пульт на macOS).
3. (мелкое) **`doc-commit --now` не существует** — требование 10, AC-15
   («`doc-commit` (включая `--now`/`--flush`)»), разбор
   `orchestrator/notes.py:1462-1474`. Читать как «`note --now`/`--flush`,
   `doc-commit --flush`».
4. (мелкое) **Отказ `--during-canary` без основания у обходов окна** —
   требование 8, AC-13 говорят только «с непустым основанием идут прежним
   путём»; текст отказа для `note`/`doc-commit`/`pool-seal` с пустым
   основанием и поведение пустого флага без живого прогона не заданы
   (для `approve` образец — `_fixes_main_arg`, `artel.py:1752`). Дефолт —
   тот же образец `_fixes_main_arg` и для обходов, при любом прогоне.

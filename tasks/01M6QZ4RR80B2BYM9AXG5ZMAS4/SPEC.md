# SPEC: target-set — замена блока профиля или компонента из файла

## Контекст
Команда `target-set` (`orchestrator/projects.py:395`, `cmd_target_set`) правит
записи локального слоя `.artel/targets.yaml` по одному листу: значение —
скаляр или потоковый список (`_argument_value`, `:686`), путь проверяет
`_field_keys` (`:633`), форма `--key`/`--drop-key` (`_target_set_key`) пишет
ключ поля-отображения из `KEY_FIELDS` (`:380`). `_field_keys` отказывает любому
пути в `description.test_profile` и его подполях («вложенное отображение»,
`:659-672`) и компоненту, которого нет в записи (`NO_COMPONENT`, `:382`).

Перевод записи с раннера `pytest-own` на `compose`
(`targets.PROFILE_RUNNER_COMPOSE`, `orchestrator/targets.py:100`) требует
одновременно сменить `runner`, добавить поля `COMPOSE_REQUIRED` (`:110`) и
`report: junit-xml`, снять поля `COMPOSE_FORBIDDEN` (`:115`); `_check_compose`
(`orchestrator/targets.py:1239`) отказывает каждому промежуточному состоянию,
поэтому правка по одному листу невозможна, а ручная правка слоя запрещена
контрактом сессии (`docs/operator-session.md`, инцидент 04.11). Нужна форма,
заменяющая блок `test_profile` или компонента целиком из файла, через общий
путь записи `target-set` (`_target_set_load`, `_rendered`, сверка до записи,
`_backup_copy`, `_target_set_write`).

`yamlmini` не разбирает потоковые отображения `{…}`, блочные разбирает
(`yamlmini.mapping`); `_render` (`orchestrator/projects.py:254-274`) пишет
`dict` блоком и отказывает ключам, которые не записать.

## Требования

1. **Новая форма**: `target-set <проект> <путь блока> --from-file <файл>`.
   Третий аргумент `--from-file` — всегда новая форма; если при этом число
   аргументов не равно четырём — отказ со строкой `TARGET_SET_USAGE`, слой не
   записан.
2. **Путь блока** — ровно один из двух видов:
   - `description.test_profile`;
   - `description.components.<имя>` — компонент, который в записи уже есть,
     или новый (имя — непустая строка, которую `_render` может записать
     ключом).

   Имя компонента — ровно один сегмент: путь делится по точке, и вид
   `description.components.<имя>` — ровно три сегмента. Путь из четырёх и
   более сегментов (`description.components.<к>.<поле>`) с `--from-file` —
   отказ (без этого правила `_render`, пропускающий точку в ключе,
   `orchestrator/projects.py:260-263`, завёл бы компонент с точкой в имени).
   Любой другой путь — отказ с перечнем двух допустимых видов; слой не
   записан. Имя компонента, которое `_render` не может записать ключом
   (`orchestrator/projects.py:260-263`: пустое — путь
   `description.components.`, с `:`, с ведущим `#` и прочие случаи отказа
   ключу в `_render`), — тот же отказ с перечнем двух допустимых видов
   пути, до сборки текста слоя, а не отказ сборки `_rendered`
   (`orchestrator/projects.py:480-486`); слой побайтно прежний. Текст
   каждого отказа пути содержит литерал перечня целиком:
   `допустимые пути блока: description.test_profile, description.components.<имя>`.
3. **Файл** — блочное отображение подмножества `yamlmini`: содержимое блока
   без ключа пути (первая строка — поле блока, например `runner: compose`).
   Отказ с причиной, слой не записан, если: файл не прочитан или не UTF-8
   (отказ текстом причины, не трассировкой); файл пуст (пустой текст или
   только пустые строки) — отказ до сборки текста слоя, текст отказа
   содержит слово «пуст»; ошибка разбора `yamlmini` (в том числе файл со
   списком вместо отображения — `yamlmini.mapping` отдаёт только `dict` или
   поднимает `YamlError`, отдельной ветки «не отображение» нет); разобранное
   отображение пустое; в файле есть комментарий — строка целиком из
   комментария или хвостовой комментарий после значения
   (`runner: compose  # x`, который `yamlmini` молча отбрасывает); признак
   комментария — тот же, что `_comment_line` (`orchestrator/projects.py:610-628`); в файле повторён ключ на
   одном уровне отображения, на любом уровне вложенности (`yamlmini` молча
   оставляет последнее значение — тот же класс потерь, что у комментария) —
   отказ с именем ключа и номером строки второго вхождения (счёт строк
   файла с 1); повтором считается только одно имя ключа у одного и того же
   родительского отображения — одно имя у разных родителей (ключ верхнего
   уровня и ключ вложенного отображения, одинаковое подполе у двух
   вложенных отображений) не повтор; значение содержит то, что
   `_render` не записывает, — отказ сборки с прежним текстом `_rendered`
   (`orchestrator/projects.py:485-486`, слова «не записать»).
4. **Замена целиком**: значение по пути блока заменяется разобранным
   отображением целиком — поля, которых нет в файле, из блока уходят.
   Прочие поля записи и прочие записи слоя не меняются — по разобранным
   значениям (`yamlmini.mapping` текста слоя до и после: всё, кроме листов
   под путём блока, равно), а не побайтно: новая форма пересобирает слой
   целиком через `_render` (`orchestrator/projects.py:254-274`). «Слой
   побайтно прежний» — только для случаев отказа, где файл не
   переписывается. Порядок компонентов значим: заменённый компонент
   остаётся на своём месте среди `description.components`, новый
   добавляется в конец, порядок прочих компонентов не меняется — по
   `list(description.components)` разобранного слоя до и после записи
   (равенство словарей порядка не видит).
5. **Сверка до записи** — новая функция рядом с `_target_set_mismatches`
   (поведение `_target_set_mismatches` для прежних форм не меняется): все
   изменённые, добавленные и снятые листы разобранного нового текста лежат
   под `targets.<проект>.<путь блока>`; «лежит под путём блока» — кортеж
   ключей листа начинается кортежем (`targets`, `<проект>`, затем сегменты
   пути блока), не строковый префикс: при пути блока
   `description.components.app` лист `description.components.app2.<поле>`
   под путём блока не лежит; значение по этому пути после разбора
   равно значению файла (`_differences`); `_merge_mismatches` проходит —
   сведённая запись проекта годна для `targets.merge_local`, сведённые
   записи прочих проектов равны прежним. Отказ любой из проверок — текст
   причины (в том числе отказ `merge_local`, например правил `compose`),
   слой побайтно прежний, копии нет. Сверка не сводится к
   `_merge_mismatches`: собранный текст, меняющий лист вне пути блока или
   дающий под путём блока значение, отличное от файла, отказывается, даже
   если сведение проходит. Новая форма собирает текст слоя только через
   `projects._render` (прямо или через `_rendered`, который зовёт `_render`,
   `orchestrator/projects.py:480-486`) — это шов подмены сборки в AC-10:
   сборка всего слоя — вызов `_render` с отступом 0, пустым префиксом и
   отображением, у которого есть ключ `targets`; рекурсивные вызовы
   (`:268`) и пробные вызовы вида `_render({key: None}, 0, "")` (`:550`)
   идут тем же `_render`. Реализация вправе делать пробные вызовы `_render`
   для проверки писуемости имени компонента.
6. **Тот же хвост**: копия прежнего файла и запись журнала — через
   `_target_set_write`. Строка журнала и вывода:
   `<путь блока>: блок из <файл> (листов было <N> → стало <M>)`, для нового
   компонента — `было (нет)`. `<файл>` — аргумент `--from-file` дословно,
   как дан в командной строке, без разрешения пути; относительный путь
   файла читается от текущего каталога процесса, не от `config.ROOT` и не
   от каталога локального слоя. N и M — число листов блока в разобранном
   локальном слое до и после записи по тому же правилу, что
   `projects._leaves` (`orchestrator/projects.py:751-758`: список — один
   лист). Блок уже равен значению файла — вывод «без
   изменений», копии и записи журнала нет. Отказы `_target_set_load`
   (проект артели, записи нет в слое, строка-комментарий в слое) действуют
   и для новой формы; недоступный журнал — отказ до записи, как у прежней
   формы.
7. **Прежние формы не меняются**: `target-set <проект> <путь> <значение>`,
   `--key`, `--drop-key`, `--show` и их тексты отказа — побайтно прежние,
   включая отказ «вложенное отображение» для
   `description.test_profile.<поле>` и `NO_COMPONENT` для прежней формы.
   Исключение одно: вшитая в отказы прежних форм строка `TARGET_SET_USAGE`
   (`orchestrator/projects.py:413-414`, `:518-519`, `:581-582`) — хвост
   отказа, и он дополняется новой формой по требованию 8; текст отказа без
   этого хвоста — побайтно прежний.
8. **Справка**: `TARGET_SET_USAGE` (`orchestrator/projects.py:370`) и строки
   справки `target-set` в `orchestrator/artel.py` (`:197-200`) называют новую
   форму; каждая альтернатива начинается словом `target-set`, строки
   продолжения — с отступом больше двух пробелов (иначе краснеет
   `tests/test_01m5m0kqpv0fj9nsmdcq3xb76w_help_registry.py::…::test_ac4_every_command_word_of_help_is_a_registry_key`).
   `docs/codebase-map.md` — только повторной генерацией
   `scripts/codebase_map.py`.

## Оценка объёма и деление

Сработавшие сигналы: число критериев приёмки ≥ 10 (AC-1…AC-11); число
упомянутых модулей ≥ 5 — в тексте названы
`orchestrator/projects.py`, `orchestrator/artel.py`, `orchestrator/targets.py`,
`orchestrator/yamlmini.py`, `scripts/codebase_map.py`. Из них правятся только
два файла кода (`orchestrator/projects.py` — новая форма и сверка блока;
`orchestrator/artel.py` — только строки справки) плюс генерация карты и
долгоживущие тесты задачи (общие зоны); `orchestrator/targets.py`,
`orchestrator/yamlmini.py`, `scripts/codebase_map.py` — только чтение.

Прогноз диффа: 20 КиБ

Обоснование монолита: новая форма `--from-file` (разбор, сверка, запись) и
её справка — одна функция команды; часть со справкой без формы
назвала бы несуществующий вызов, форма без справки — расходится с
`TARGET_SET_USAGE`, которым сама же отказывает (требование 1). Делить
нечего по зонам: весь код — в одном файле `orchestrator/projects.py`.

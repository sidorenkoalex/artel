# PLAN: target-set — замена блока профиля или компонента из файла

## Подход
Новая ветка `cmd_target_set` (`orchestrator/projects.py`): третий аргумент
`--from-file` — функция `_target_set_block(rest)`. Порядок проверок:
число аргументов (ровно четыре, иначе `TARGET_SET_USAGE`) → вид пути блока
(`description.test_profile` или `description.components.<имя>` ровно из
трёх сегментов, имя проверяется пробным `_render({имя: None}, 0, "")` —
отказ с литералом перечня до сборки) → чтение файла блока (`_block_file`:
OSError/UnicodeDecodeError — текстом; пустой — «пуст»; комментарий —
`_comment_line`; разбор `yamlmini.mapping`; повтор ключа у одного
родителя — `_duplicate_key` по стеку отступов, номер строки с 1; пустое
отображение) → `_target_set_load` → сравнение с текущим блоком («без
изменений») → `store.db_usable` → замена значения по пути в копии данных
(присваивание по существующему ключу сохраняет место компонента, новый —
в конец) → `_rendered` → сверка `_target_set_block_mismatches` →
`_target_set_write` со строкой `<путь>: блок из <аргумент> (листов было
<N> → стало <M>)`.

Сверка блока — новая функция рядом с `_target_set_mismatches`: все
изменённые листы лежат под кортежем `("targets", <проект>, *ключи пути)`
(префикс кортежа, не строки); значение по пути равно файлу
(`_differences`); для компонента — порядок имён компонентов равен
ожидаемому; затем `_merge_mismatches`. Аргумент `--from-file` в журнале —
дословно, файл читается `Path(arg)` от текущего каталога процесса.

Бюджет SPEC не пересматривается.

## Влияние на систему
Прежние формы `target-set` не меняются: новая ветка перехватывает только
`rest[2] == "--from-file"`, прежние функции сверки и `_field_keys` не
тронуты; хвост `TARGET_SET_USAGE` в их отказах дополнен (требование 7).
Запись идёт тем же хвостом `_target_set_write` (копия, атомарная запись,
журнал); сверка строже `_merge_mismatches`, не слабее. Гейты, лимиты,
тесты не ослабляются. Откат — revert коммита задачи.

## Риски
- Повтор ключа ищется собственным проходом по строкам файла (у `yamlmini`
  нет такого режима, править его вне зоны): проход идёт уже после
  успешного разбора и отсутствия комментариев, поэтому строки — только
  пары «ключ: значение» с корректными отступами.
- Своих тестов в `tests/` не добавлено: поведение целиком покрыто
  долгоживущим файлом задачи (37 тестов) и планкой (AC-10). Проверка
  порядка ключей родителя в сверке блока (защита «заменённый компонент
  ушёл в конец» на уровне сверки, а не только сборки) видна только через
  подмену `_render`, которой в `tests/` нет места.

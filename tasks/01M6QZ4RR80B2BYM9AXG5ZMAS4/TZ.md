# target-set: замена блока профиля или компонента из файла

## Факты

1. Команда `target-set` (`orchestrator/projects.py:395`, `cmd_target_set`) правит записи локального слоя `.artel/targets.yaml` по одному листу: значение — скаляр или потоковый список (`_argument_value`, `:686`), путь проверяет `_field_keys` (`:633`). Форма `--key`/`--drop-key` (`_target_set_key`) пишет ключ поля-отображения строк из перечня `KEY_FIELDS` (`:380`).
2. `_field_keys` отказывает любому пути в `description.test_profile` и его подполях («ведёт во вложенное отображение — его поля командой не правятся»: `nested` для `targets.PROFILE_FIELD`, `:667-672`) и компоненту, которого нет в записи (`NO_COMPONENT`, `:382`, «добавление компонентов не входит»).
3. Перевод записи с раннера `pytest-own` на раннер `compose` (`targets.PROFILE_RUNNER_COMPOSE`, `orchestrator/targets.py:100`) требует одновременно сменить `runner`, добавить пять полей `COMPOSE_REQUIRED` (`:110-111`) и `report: junit-xml`, снять поля `COMPOSE_FORBIDDEN` (`:115`). Проверка `_check_compose` (`orchestrator/targets.py:1239`) отказывает и полю `compose_*` без `runner: compose`, и `runner: compose` без всех обязательных полей: ни одна последовательность правок по одному листу не проходит через промежуточные состояния. Опыт 06.11: перевести запись внешнего проекта на compose командой пульта нельзя, а ручная правка слоя запрещена контрактом сессии (`docs/operator-session.md`, раздел о локальном слое, инцидент 04.11).
4. Потоковых отображений `{…}` `yamlmini` не разбирает (`orchestrator/yamlmini.py`); блочное отображение разбирает (`yamlmini.mapping`), а `_render` (`orchestrator/projects.py:254-274`) пишет `dict` блоком и отказывает ключам, которые не записать.
5. Общий путь записи уже есть: загрузка с отказами (`_target_set_load`, `:444`; проект артели, записи нет в слое, строка-комментарий в слое), сборка (`_rendered`), сверка до записи (`_target_set_mismatches`, `:761`: ровно один изменённый лист и `_merge_mismatches`, `:813`), копия прежнего файла (`_backup_copy`, `:839`), атомарная запись и журнал (`_target_set_write`). Сведение записи — `targets.merge_local` (`orchestrator/targets.py:486`).

## Требуется

1. **Новая форма**: `target-set <проект> <путь блока> --from-file <файл>`. Третий аргумент `--from-file` — всегда новая форма; число аргументов не равно четырём — отказ со строкой `TARGET_SET_USAGE`, слой не записан.
2. **Путь блока** — ровно один из двух видов:
   - `description.test_profile`;
   - `description.components.<имя>` — компонент, который в записи уже есть, или новый (имя — непустая строка, которую `_render` может записать ключом).
   Любой другой путь — отказ с перечнем двух допустимых видов; слой не записан.
3. **Файл** — блочное отображение подмножества `yamlmini`: содержимое блока без ключа пути (первая строка — поле блока, например `runner: compose`). Отказ с причиной, слой не записан: файл не прочитан или не UTF-8; ошибка разбора `yamlmini`; разобранное значение — не отображение или пустое; строка-комментарий в файле (тот же признак, что `_comment_line`, `:610` — комментарий не переносится и молча потерялся бы); значение, которое `_render` не записывает.
4. **Замена целиком**: значение по пути блока заменяется разобранным отображением целиком — поля, которых нет в файле, из блока уходят. Прочие поля записи и прочие записи слоя не меняются.
5. **Сверка до записи** — новая функция рядом с `_target_set_mismatches` (её поведение для прежних форм не меняется): все изменённые, добавленные и снятые листы разобранного нового текста лежат под `targets.<проект>.<путь блока>`; лист по этому пути после разбора равен значению файла (`_differences`); `_merge_mismatches` проходит — сведённая запись проекта годна для `targets.merge_local`, сведённые записи прочих проектов равны прежним. Отказ любой из проверок — текст причины (в том числе отказ `merge_local`, например правила `compose`), слой побайтно прежний, копии нет.
6. **Тот же хвост**: копия прежнего файла и запись журнала — через `_target_set_write`. Строка журнала и вывода: `<путь блока>: блок из <файл> (листов было <N> → стало <M>)`, для нового компонента — `было (нет)`. Блок уже равен значению файла — «без изменений», копии и записи журнала нет. Отказы `_target_set_load` действуют и для новой формы; недоступный журнал — отказ до записи, как у прежней формы.
7. **Прежние формы не меняются**: `target-set <проект> <путь> <значение>`, `--key`, `--drop-key`, `--show` и их тексты отказа, включая отказ «вложенное отображение» для `description.test_profile.<поле>` и `NO_COMPONENT` для прежней формы, — побайтно прежние.
8. **Справка**: `TARGET_SET_USAGE` (`orchestrator/projects.py:370`) и строки справки `target-set` в `orchestrator/artel.py` (`:197-200`) называют новую форму; каждая альтернатива начинается словом `target-set`, строки продолжения — с отступом больше двух пробелов (иначе краснеет `test_ac4_every_command_word_of_help_is_a_registry_key`). `docs/codebase-map.md` — повторной генерацией сценарием `scripts/codebase_map.py`.

## Критерии приёмки

- Given вымышленная запись с `test_profile` раннера `pytest-own` и файл блока с `runner: compose`, всеми полями `COMPOSE_REQUIRED`, `workdir` под левой частью `compose_mount` и `report: junit-xml`, When `target-set <проект> description.test_profile --from-file <файл>`, Then `targets.target(<проект>)["test_profile"]` равно отображению файла, поля прежнего профиля, которых нет в файле, сняты, прочие разделы записи и прочие записи побайтно прежние; создана копия прежнего файла и запись журнала по формату требования 6;
- Given тот же файл без `compose_mount`, When команда, Then отказ с текстом проверки `compose` про отсутствующее поле, слой побайтно прежний, копии нет;
- Given запись с компонентами, When `--from-file` на новый компонент `description.components.<новое имя>`, Then компонент добавлен, прочие компоненты целы; на существующий компонент — заменён целиком;
- Given путь `policy.no_paths`, `description.test_profile.runner` или `machine.submodule_tokens` с `--from-file`, When команда, Then отказ с перечнем допустимых видов пути;
- Given файл с ошибкой разбора, пустой, со списком вместо отображения, со строкой-комментарием или несуществующий, When команда, Then отказ с причиной, слой побайтно прежний;
- Given повтор той же команды на уже применённом файле, Then «без изменений», копии и записи журнала нет;
- Given `--from-file` без файла или с лишним аргументом, Then отказ со строкой формы вызова;
- прежние формы `target-set` (значение, `--key`, `--drop-key`, `--show`) — тексты и поведение прежние; прежние тесты зелёные без правки.

Безопасность тестов: локальный слой, записи и файлы блоков — вымышленные во временной песочнице, фикстура `initialized_tmp_root` (`tests.sandbox.InitializedTmpRootTest`); никогда — настоящий `.artel/targets.yaml`; ни имён, ни адресов реальных проектов; без Docker и сети.

Существующие тесты: правка не должна сделать красным ни один существующий тест; если краснеет — эскалация с именем теста, без правки.

Зоны: `orchestrator/projects.py` (`cmd_target_set`, `TARGET_SET_USAGE`, новые функции формы `--from-file` и новая функция сверки блока), `orchestrator/artel.py` (только строки справки `target-set`), `docs/codebase-map.md` (только генерацией), `tests/` (долгоживущие файлы задачи).

Только чтение: `orchestrator/targets.py`, `orchestrator/yamlmini.py`, `scripts/codebase_map.py`, `tests/test_projects_target_set.py`, `tests/test_01m6kbd9fc36warwsy9z0jdmg5_target_set.py`, `tests/test_01m6phs9xqtppz73v80acgszjs_target_set_key.py`, `tests/test_01m5m0kqpv0fj9nsmdcq3xb76w_help_registry.py`, `tests/sandbox.py`, `docs/operator-session.md`.

Не входит:
- разбор потоковых отображений `{…}` в `yamlmini`;
- снятие блока целиком (`test_profile` или компонента) и переход записи с `test_profile` на `components`;
- замена блоков вне `description` и правка слоя репозитория;
- правка настоящего локального слоя `.artel/targets.yaml` в тестах и при разработке.

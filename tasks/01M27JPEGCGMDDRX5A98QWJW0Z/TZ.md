# ТЗ: защищённые пути — единый список, гейт зон отказывает всегда, CI падает

Источник: копилка 11.09 (приоритет 2), решение Оператора 11.09
«инварианты правит только Оператор». Сегодня защищённые пути живут двумя
списками, и ни один не блокирует правку ролью:
- `config.PROTECTED_PATHS` = gates.yaml, roles.yaml, .github/, templates/,
  skills/ — используется только в `fsm_merge_gate`: конфликт слияния по
  защищённому пути уходит в `escalated` вместо `in_dev`;
- регулярное выражение задания CI «Enforcement, конфиги системы меняет
  только Оператор» (`.github/workflows/ci.yml`, job `protected-paths`)
  шире: плюс targets.yaml, CLAUDE.md, tests/test_invariants.py,
  docs/invariants.md — но даёт `::warning`, не fail.
Факт 11.09: developer задачи 01M1SHJX22 правил строку инварианта 25 в
`docs/invariants.md` по требованию SPEC; остановил только гейт зон, и лишь
потому, что файл не был назван в зонах. Будь он в зонах — правка
инварианта ролью прошла бы все гейты и мерж.

Требуется:
1. Единый источник списка — `config.PROTECTED_PATHS`, дополненный:
   docs/invariants.md, tests/test_invariants.py, docs/adr/, CLAUDE.md,
   targets.yaml. Семантика префикса — как сейчас
   (`fsm_merge_gate._touches_protected_path`).
2. Гейт зон на переходе `in_dev -> verifying` (`fsm_advance`, проверка
   диффа против базы сравнения) отказывает, если дифф трогает защищённый
   путь, НЕЗАВИСИМО от `zones`, `zones_extension` и мандата «Расширение
   зон разрешено» — мандат защищённые пути не покрывает. Текст отказа
   именованный: «защищённый путь <путь> — правит только Оператор
   коммитом в main; предложи правку приложением к PLAN (unified-дифф)».
3. Гейт мержа (`fsm_merge_gate`) отказывает в мерже ветки, чей дифф
   против базы трогает защищённый путь, — не только при конфликте:
   переход в `escalated` с тем же именованным текстом.
4. Задание CI `protected-paths` читает список из `config.PROTECTED_PATHS`
   (python-однострочник, не дублирующее регулярное выражение) и на
   событии pull_request ПАДАЕТ, не предупреждает. `.github/` —
   защищённый путь: правка ci.yml оформляется приложением к PLAN.md
   (unified-дифф, проверенный `git apply --check`), применяет Оператор.
5. Тесты: гейт зон отказывает по защищённому пути при наличии раздела
   «Расширение зон» и мандата (мутация «мандат покрывает» — красный);
   гейт мержа отказывает без конфликта; список содержит пять добавленных
   путей; существующие тесты защищённых путей без ослабления.

Зоны: orchestrator/config.py, orchestrator/fsm_advance.py,
orchestrator/fsm_merge_gate.py, tests/. Приложением (защищённый путь,
применяет Оператор): .github/workflows/ci.yml. Зоны fsm_advance.py и
fsm_merge_gate.py сейчас заняты (approve без sha 01M1SHJX22, B2 в очереди)
— стартовать после их освобождения. Не входит: разделение токенов
(PAT) для CI; правка самих инвариантов и ADR; docs/operator-session.md.

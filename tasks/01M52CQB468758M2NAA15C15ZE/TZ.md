# ТЗ: D0: внешний доверенный проект без песочницы — профиль чужого стека и чистое окружение тестов

# D0: внешний доверенный проект без песочницы — профиль чужого стека и чистое окружение тестов

## Факты

Основание — ADR-0023, «Поправка 16.10.2026 (вторая): до D1а — внешний доверенный проект без песочницы». Песочница (D1а, SPEC 01M51YKZNES22DZQY13D3QKF89) отложена; внешний доверенный проект (sled) исполняет тесты на хосте, как артель. Эта задача делает так, чтобы пульт вообще мог гонять тесты чужого стека, и убирает утечку окружения пульта в эти тесты.

Сейчас:
- `_pytest_command` (`orchestrator/acceptance.py:35-65`) всегда ставит интерпретатор venv пульта и `-p timeout`; полный набор берёт `<корень>/tests` (`:1172`) и дописывает `-n … -p xdist` (`:1176`). У sled тесты в `backend/tests`, запуск `uv run pytest`, плагинов `pytest-timeout` и `pytest-xdist` нет;
- `_pytest_env` (`acceptance.py:69-89`) передаёт тестам копию всего окружения пульта;
- точечные прогоны (`acceptance.run`, `collect`, `run_repeat`, `run_plank`) идут через `subprocess.run(timeout=…)`, который на таймауте снимает только прямого потомка; `uv run` порождает дочерний python, который остался бы жить;
- команда профиля доходит до прогонов параметром `command` (например, `advance_gates/acceptance.py:169`, `fsm_merge_gate.py:965-967`, `suite_run.py:525,565`), но автогейт приёмки и `approve` на acceptance зовут полный набор без команды профиля (`acceptance.acceptance_suite`, `acceptance.py:1847-1848`; строка бэклога 07.10, `docs/backlog.md:185`);
- двусторонний прогон (`advance_gates/two_sided.py:227-235`) строит команду и окружение теми же `_pytest_command` и `_pytest_env`;
- `test_profile` (`orchestrator/targets.py:41-53`) не знает подполей `runner`, `workdir`, `env`; носитель профиля — `project_profile.Profile` (`orchestrator/project_profile.py:63-85`).

Требуется:

1. Подполя `test_profile`, все необязательные; профиль артели без них остаётся правильным и ведёт себя как сейчас:
   - `runner`: `pult-pytest` (по умолчанию, сегодняшнее поведение) | `pytest-own`;
   - `workdir`: каталог прогона относительно корня репозитория; `targets.check` проверяет синтаксис (относительный, без `..`); в момент прогона `realpath` обязан остаться внутри дерева прогона, иначе именованный отказ;
   - `env`: блочное отображение строк (новый вид `mapping`; `yamlmini` не меняется); имена из точного перечня секретов (`secret_env_names` провайдеров, `GITHUB_TOKEN`, `GH_TOKEN`) — отказ проверки, сверка по точному имени.
   Подполя доходят до потребителей полями `project_profile.Profile`. Поле `sandbox` в этой задаче не вводится (вторая поправка ADR-0023, п.4).

2. `runner: pytest-own`: команда профиля как есть, без интерпретатора пульта, `-p timeout` и `-n/-p xdist`; пульт по-прежнему дописывает свои аргументы гейтов (`--collect-only -q`, `--junitxml`, `-o junit_logging=system-out`, `-p no:cacheprovider`) и аргументы, которые сегодня дописывает конкретное место запуска. Рабочий каталог — `workdir`. Все пути профиля (`long_lived_dir`, долгоживущие пути, `workdir`) отсчитываются от корня репозитория; пульт переводит их в пути, верные из `workdir`. Полный набор берёт каталог из `long_lived_dir`, а не `<корень>/tests`.

3. Чистое окружение при `pytest-own`: тесты получают только `PATH` пульта, временный `HOME` (новый каталог на прогон, удаляется после), `TMPDIR`, `LANG`/`LC_ALL` при наличии, служебные переменные, которые сегодня ставит место запуска (`PYTHONPYCACHEPREFIX`, `PYTHONUNBUFFERED`, переменные плагина и отчёта двустороннего прогона), и `test_profile.env`. Остальное окружение пульта, в том числе токены и переменные провайдеров, не передаётся. При `pult-pytest` окружение прежнее.

4. Таймаут при `pytest-own`: каждое место запуска идёт в собственном сеансе и по таймауту и на любом исключении снимает всю группу процессов (как сегодня полный набор, `acceptance.py:1324-1337`, `:1373-1391`). При `pult-pytest` поведение прежнее.

5. Один источник команды профиля: автогейт приёмки, `approve` на acceptance, гейт мержа, `suite-run`, `plank-run`, `preflight`, `acceptance-dry-run`, `amend-tests`, двусторонний прогон и прогоны `pull` получают одни и те же `command`, `runner`, `workdir`, `env` профиля проекта задачи — через тот же канал, которым сегодня передаётся `command` (например, `Profile` вместо списка). Для прогонов без задачи и для артели — сегодняшнее поведение.

6. Ключ повторного использования итога полного набора (gate- и base-итог, `acceptance.py:1609-1640`, `:1740-1758`, `:1790-1792`; `suite_run.py:511,533`) при `pytest-own` учитывает `runner`, `workdir` и `env`; при `pult-pytest` не меняется ни на байт.

7. До правки зафиксировать тестами argv, `cwd` и окружение каждого места запуска для артели (`acceptance.run`, `collect`, `run_repeat`, `run_plank`, два пути `_run_full_suite_now`, `_run_full_suite_to_log`, `two_sided._run_side`) и держать их неизменными.

8. Тесты детерминированы, без сети и без `uv`: учебный проект во временном каталоге с `runner: pytest-own` и командой, которая запускает pytest интерпретатором тестов через обёртку-скрипт, порождающий дочерний процесс.

Критерии приёмки:
- у артели argv, `cwd` и окружение всех восьми мест запуска не изменились;
- учебный проект с `pytest-own`: тест, читающий `os.environ`, не видит ни одной переменной пульта вне перечня п.3; `HOME` — временный каталог; полный набор собирается из `long_lived_dir` под `workdir` без `-n` и `-p xdist`;
- по таймауту точечного прогона учебного проекта дочерний процесс обёртки не остаётся жить;
- автогейт приёмки, `approve` на acceptance и гейт мержа запускают набор учебного проекта той же командой и в том же каталоге, что `suite-run`;
- `targets.check` отказывает `env` с именем секрета и `workdir` с `..` или абсолютным путём; итог полного набора с другим `workdir` или `env` не засчитывается.

Зоны: `orchestrator/acceptance.py`, `orchestrator/targets.py`, `orchestrator/project_profile.py`, `orchestrator/advance_gates/two_sided.py`, `orchestrator/advance_gates/acceptance.py`, `orchestrator/fsm_merge_gate.py`, `orchestrator/suite_run.py`, `orchestrator/plank_run.py`, `orchestrator/pull.py`, `orchestrator/amend.py`, `orchestrator/notes.py`, `orchestrator/fsm.py`, `orchestrator/fsm_autogate.py`, `tests/`. В вызывающих модулях — только передача профиля вместо команды, без изменения логики гейтов. Только чтение: `docs/backlog.md`, `targets.yaml`. Правка вне зон — эскалация до SPEC.

Не входит: поле `sandbox` и любая песочница (D1а); запись sled в `targets.yaml` и меры круга 1 (D2); отдельный исполнитель команды `install` — зависимости ставит команда профиля; стенд с базами данных (D1б); Codex на внешних проектах.

Рамка: $50. Набор моделей — по умолчанию.

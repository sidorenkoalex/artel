# Ускорение тестов suite_run без ослабления: уборка без ожидания своего процесса, меньшие пределы, шаг опроса из config, проверка процессов вместо пауз

## Факты

1. `tests/test_01m462qaceh29rprd2rzhghqfm_suite_run.py` — самый дорогой файл набора: 26 тестов, 326 с в CI (прогон `42503643843`, `a8ff5c70`). Исследование 09.11 (`memory`-отчёт сессии, сводка ниже) нашло, куда уходит время.
2. **Уборка ждёт собственный процесс.** `stop_everything` (`tests/test_01m462qaceh29rprd2rzhghqfm_suite_run.py:409-423`) собирает `pid` и `ppid` записей обёртки и до 20 с ждёт их смерти; `os.getpid()` исключён только при добивании (`:418`), не в ожидании (`:415`). В ac13 (`:862-892`) гейт вызывается в процессе теста — ожидание идёт полные 20 с. Пробная правка в одну строку — 24,1 → 5,2 с.
3. **Пределы времени произвольной величины.** `FootprintTest.TIMEOUT_SEC = 15` (`:1290`, ac24 `:1360-1408`), `BaseTimeoutTest.TIMEOUT_SEC = 15` (`:962`, ac16 база `:974-999`), `TimeoutTest.TIMEOUT_SEC = 15` (`:771`, ac11 `:774-810`), ac16 гейт — `FULL_SUITE_TIMEOUT_SEC = 5` (`:1001-1026`). Значение должно быть только больше времени быстрой части прогона (в CI ≈1–1,5 с).
4. **Шаг опроса 1 с.** `orchestrator/suite_run.py:81` (`_POLL_SEC = 1.0`), опрос в `_wait` (`:1062-1101`) и `wait_request` (`:953`); около 28 отчётных вызовов файла теряют в среднем по 0,5 с. Тест уже задаёт свои значения `config` в копии `config.py` (`FULL_SUITE_WORKERS`, `FULL_SUITE_TIMEOUT_SEC`, `:209-213`).
5. **Паузы «ничего не запустилось позже».** `assert_no_run` (`:497`, 3 с — ac3, ac4), ac20 (`:1229`, 3 с), ac9 (`:741`, 2 с), ac21 (`:1266`, 2 с). Фоновый процесс заводится до возврата команды (`orchestrator/suite_run.py:1174-1178`) — если он есть, он виден в момент проверки. Паузы ac8 (`:709`, ожидание до разрешения) и ac6 (`:640`, свойство «процесс жив через время») — механизм свойства, не трогаются.
6. Мандат Оператора 08.11.2026 на перевод существующих тестов (дословно: «общий мандат, но с проверками/матрицами неослабления и то же множество мутаций, все прежние состояния, независимая проверка»); поручение 09.11: «по результатам исследования заводи задачи с имеющимися правами в порядке очереди».

## Требуется

1. **Шаг опроса из config.** Константа `config.SUITE_RUN_POLL_SEC` (1.0) вместо `suite_run._POLL_SEC`; её же читает опрос `mutation-run --wait` (`orchestrator/mutation_run.py:861`, сейчас читает `suite_run._POLL_SEC`); поведение пульта по умолчанию не меняется. Тест задаёт её в копии `config.py` так же, как `FULL_SUITE_WORKERS` (0.1).
2. **Уборка без ожидания своего процесса.** В `stop_everything` после цикла сбора — `pids.discard(os.getpid())`: из ожидания исключается только сам процесс теста; ни один записанный обёрткой потомок не отбрасывается.
3. **Меньшие пределы.** `TIMEOUT_SEC` у `FootprintTest`, `BaseTimeoutTest` и `TimeoutTest` — ровно 8 с; предел гейта ac16 — ровно 3 с. Разрешённое усиление: в ac24 для исходов, кроме «предел», утверждается, что в итоге нет «не уложился» — так исходы «зелёная», «красная», «исключение» на медленном CI не превращаются молча в «предел».
4. **Проверка процессов вместо пауз.** В `assert_no_run` (ac3, ac4), ac9, ac20, ac21 пауза заменяется проверкой сразу после возврата команды: нет живого процесса, в argv которого (`/bin/ps -axww -o pid=,command=`) есть id проверяемой задачи (для ac21 — id задачи B), путь каталога пробы или корень песочницы; журналы обёртки и `conftest.py` пусты (как в прежнем утверждении после паузы). Фоновый процесс `suite-run` — `[sys.executable, "-c", _CHILD, task_id, run_no, mode]` (`orchestrator/suite_run.py:84`, `:1175`): id задачи в его argv есть, корня песочницы — нет.
5. Утверждения тестов и проверяемые свойства не меняются; меняются только перечисленные константы, уборка и способ ожидания.

## Мандат

Ослабление тестов разрешено: tests/test_01m462qaceh29rprd2rzhghqfm_suite_run.py

Пояснение мандата: по общему мандату Оператора 08.11 на перевод тестов (ADR-0032 п. 9) — только изменения пп. 2–4 «Требуется»: исключение своего pid из ожидания в `stop_everything`, значения `TIMEOUT_SEC` и предела гейта ac16, замена пауз проверкой процессов в `assert_no_run`, ac9, ac20, ac21, значение `SUITE_RUN_POLL_SEC` в копии `config.py`. Утверждения, проверяемые свойства и состав тестов не меняются.

## Критерии приёмки

- Given копия `config.py` теста с `SUITE_RUN_POLL_SEC`, When прогон файла, Then все тесты зелёные, а `orchestrator/suite_run.py` по умолчанию опрашивает с шагом `config.SUITE_RUN_POLL_SEC` = 1.0 (Поверхность решения: orchestrator.config.SUITE_RUN_POLL_SEC; Размер проверки: малый);
- Given ветка задачи, When прогон мутаций по таблице: «итог гейта ищется по id задачи» (ac13), «уборка копии базы после разбора, не в `finally`» (ac24), «итог базы сохраняется и при таймауте» (ac16 база), «`full_suite` сохраняет итог и при таймауте» (ac16 гейт), «разбор вывода только по итоговой строке» и «исход предела не отличается от красного» (ac11), «без профиля — откат на pytest пульта» (ac3), «флаги параллели дописываются к любой команде профиля» (ac4), «`--wait` без прогона сам запускает прогон» (ac9), «`--failed` гонит весь набор» (ac20), «замка нет — второй прогон стартует» (ac21) и отдельно для ac3, ac9, ac20, ac21 — «отказ печатается после запуска фонового процесса» (`sys.exit` отказа ниже `Popen`: код выхода ненулевой, фон уже идёт — именно это держала пауза), Then каждая мутация убита и на базе, и на ветке — множество убиваемых мутаций не меньше прежнего. Патчи мутаций пишет разработчик файлами `tasks/<id>/mutation-<nnn>.diff` вне строк, которые меняет задача (иначе — по патчу на каждую ревизию); прогоны — `artel.py mutation-run <id> --ref base --tests tests/test_01m462qaceh29rprd2rzhghqfm_suite_run.py` и то же с `--ref head` (Размер проверки: большой — прогон мутаций);
- Свидетельство на приёмке (не тест): в отчёте junit CI ветки у файла 26 элементов `testcase` без `skipped` и сумма времени не больше 290 с (оценка исследования — около 250 с).

Безопасность тестов: прежняя у файла — песочницы во временных каталогах, процессы в своих группах; без сети.

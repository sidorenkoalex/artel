# SPEC: Ускорение тестов suite_run без ослабления — уборка без ожидания своего процесса, меньшие пределы, шаг опроса из config, проверка процессов вместо пауз

## Контекст
`tests/test_01m462qaceh29rprd2rzhghqfm_suite_run.py` — самый дорогой файл
набора: 26 тестов, 326 с в CI (прогон `42503643843`, `a8ff5c70`). Время
уходит на четыре вещи:
- `stop_everything` (`:409-423`) до 20 с ждёт смерти собственного
  процесса теста. `os.getpid()` исключён только при добивании (`:418`), а
  в ожидании (`:415`) нет; в ac13 (`:862-892`) это полные 20 с.
- пределы `TIMEOUT_SEC = 15` у `FootprintTest` (`:1290`),
  `BaseTimeoutTest` (`:962`), `TimeoutTest` (`:771`) и
  `FULL_SUITE_TIMEOUT_SEC = 5` гейта ac16 (`:1017`) взяты с большим
  запасом над быстрой частью прогона (≈1–1,5 с в CI).
- шаг опроса `orchestrator/suite_run.py:81` `_POLL_SEC = 1.0` (опрос
  `:953`, `:1101`) тест задать не может.
- паузы «ничего не запустилось позже»: `assert_no_run` (`:497`, 3 с —
  ac3, ac4), ac20 (`:1229`, 3 с), ac9 (`:741`, 2 с), ac21 (`:1266`, 2 с).
  Фоновый процесс при этом заводится до возврата команды
  (`orchestrator/suite_run.py:1174-1178`) и виден сразу.

Задача снимает эти потери, не меняя прежних утверждений и проверяемых
свойств. Перевод существующих тестов идёт по мандату Оператора
(`ANSWER-1.md`, раздел «Мандат») — см. «Материалы».

## Требования

   со значением `1.0`. `orchestrator/suite_run.py` опрашивает (`_wait` и
   `wait_request`) с шагом `config.SUITE_RUN_POLL_SEC` вместо собственной
   `_POLL_SEC`. Опрос `mutation-run --wait`

   читает ту же `config.SUITE_RUN_POLL_SEC`. Поведение пульта по
   умолчанию не меняется (шаг 1 с).

   (`tests/test_01m462qaceh29rprd2rzhghqfm_suite_run.py:209-213`) задаёт
   `SUITE_RUN_POLL_SEC = 0.1` так же, как задаёт `FULL_SUITE_WORKERS` и
   `FULL_SUITE_TIMEOUT_SEC`.

   выполняется `pids.discard(os.getpid())`: из ожидания исключается только
   сам процесс теста, ни один записанный обёрткой потомок не

4. `TIMEOUT_SEC` у `FootprintTest`, `BaseTimeoutTest` и `TimeoutTest` —

8. Прежние утверждения тестов, проверяемые свойства и состав тестов файла

9. Кроме названного файла, ни один существующий тест не краснеет. Если

`suite_run.py` и `mutation_run.py`, правки одного тестового файла, карта).

Материал для решения о монолите. Перенос шага опроса в `config`
(требование 1) и его установка в копии `config.py` теста (требование 2) —
одна смена: без константы в `config` копия теста задаёт имя, которое
никто не читает, а `mutation_run.py` без правки ссылается на удалённую
`suite_run._POLL_SEC` и падает. Правки тестового файла (требования 3–7)
идут по одному мандату на один файл и проверяются одной таблицей
мутаций AC-10 на базе и ветке. Деление требований на части удвоило бы
прогон мутаций, самую дорогую проверку задачи, и не уменьшило бы риск.
Объём кода мал, зона кода — два модуля.

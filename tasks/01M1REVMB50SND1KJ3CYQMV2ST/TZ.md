# ТЗ: эскалация «конфликт подтяжки main» называет конфликтные файлы

Источник: бэклог 05.09 (`docs/backlog.md`). `fsm.pull` при неудачном
`git merge` пишет в detail эскалации `merge.stderr`, а git печатает
«CONFLICT (content): Merge conflict in <файл>» и «Automatic merge
failed» в stdout — эскалация приходит с пустой причиной («конфликт
подтяжки main в ветку …: »). Оператор 05.09 трижды воспроизводил
слияние руками, чтобы узнать список файлов (канарейка ч.1, группа
процессов, переход до роли); все три конфликта были аддитивными.

Требуется:
1. При конфликте подтяжки detail эскалации содержит список конфликтных
   файлов (`git diff --name-only --diff-filter=U` до `merge --abort`),
   первые строки stdout git (ограничить, как сейчас stderr — 500
   символов) и stderr, если он не пуст. Формат: одна строка «конфликтные
   файлы: a, b, c», затем хвост вывода.
2. Тот же список попадает в вывод `run`/`auto` («-> escalated (…)»),
   чтобы Оператор видел его без `artel.py log`.
3. Автоматическое разрешение карты (`_auto_resolve_map_conflict`, T067)
   и остальное поведение подтяжки не меняются; `merge --abort` по-
   прежнему выполняется до записи эскалации.
4. Тесты: конфликт в одном файле кода — detail несёт имя файла и строку
   CONFLICT из stdout; конфликт «карта + файл» — авторазрешение не
   срабатывает, detail несёт оба имени; пустой stdout/stderr — detail
   без пустых хвостов; существующие тесты подтяжки (T051/T052/T053/T067)
   зелёные без ослабления.

Зоны: orchestrator/fsm.py (только `pull` и его помощники), tests/.
Порядок: код после мержа регрессии №12 (01M1R9YEK0…, зона fsm.py);
SPEC и планка — сразу. Не входит: автоматическое разрешение
аддитивных конфликтов (наблюдение копилки, отдельное решение).

Рамка: $10.

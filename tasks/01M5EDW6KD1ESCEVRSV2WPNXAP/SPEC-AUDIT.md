## Пути обхода гейтов
1. Подделка признака (б) у Python. «`detail` несёт
   `ModuleNotFoundError: No module named '<M>'`» читается как поиск
   подстроки. Тогда файл планки с
   `raise RuntimeError("ModuleNotFoundError: No module named 'pkg.new'")`
   засчитается, хотя импорта P в нём нет. AC-7 («ошибка другого вида»)
   такую реализацию не ловит: пример теста без подстроки проходит и у неё.
   Цена обхода невысока (ветка всё равно требует зелёных тестов, AC-11),
   но формулировка должна требовать итоговую строку исключения (последняя
   строка `E   ModuleNotFoundError: …` трассировки), а не подстроку.
2. Засчитанный файл не обязан проверять P: достаточно импортировать новый
   модуль из зон, а тесты файла могут быть тривиально зелёными на ветке
   (`assert True`). Честный FAIL_TO_PASS по такому файлу не доказывает
   красноты проверки. Это принятая цена ADR-0026 п. 5 («засчитывается как
   красный, если… все тесты на ветке зелёные»), отдельного отклонения нет.
   Отмечено, чтобы Оператор видел остаток риска на гейте.
3. Сопоставление по stem (`tests_writing.py:818`): если имя долгоживущего
   файла совпадает со stem файла планки (`tests/test_x.py` и
   `acceptance_tests/test_x.py`), запись сбора долгоживущего файла
   припишется файлу планки. Если SPEC не требует полного точечного пути,
   засчитывание по чужой записи возможно (отклонение 4).
4. Обрезка `detail` до 2000 символов (ТЗ п. 1). Строка
   `ModuleNotFoundError` у pytest стоит в конце трассировки, поэтому длинная
   цепочка импорта даст ложный отказ, а не обход. Это ужесточение, отмечено
   для пробы на sled.

## Пути обхода гейтов
1. AC-3 в нынешней редакции. Чтобы его выполнить, исполнитель может
   запустить гейт FAIL_TO_PASS и для `test_profile`
   (`fsm_advance.py:613`). Тогда отказы начнутся у профиля вне границы —
   это нарушение «Границы задачи». Другой путь — написать тест, который
   зовёт `_file_level_findings` напрямую, мимо гейта: критерий «пройден»,
   а поведение перехода не проверено. Оба исхода плохие (отклонение 1).
2. Отклонение 2. Если `_file_level_findings` не расширить, незасчитанная
   ошибка модуля Vitest всё равно отклонит переход («теста нет в отчёте»).
   Отказ остаётся, но теряется вид находки, по которому test_author
   понимает причину. Обхода гейта нет, есть подмена текста отказа; AC-10
   это ловит.
3. Обрезка `detail` до первых 2000 символов (требование 1) при чтении
   последней непустой строки (требование 2 (б)). Если трассировка длиннее,
   итоговая строка `ModuleNotFoundError` отрежется. Это ложный отказ, а не
   обход (ужесточение). Остаток проверяется пробой на sled.
4. Засчитанный файл с тривиально зелёными тестами на ветке — принятая
   цена (решение Оператора, «Не входит»), не поднимается.

## Вердикт
concerns. Отклонения (Оператор может снять каждое на гейте):

1. **AC-3, вторая фраза** (решение Оператора п. 7) противоречит коду и
   «Границе задачи». Гейт FAIL_TO_PASS для `test_profile` не добавляется
   (`orchestrator/fsm_advance.py:613-617`) и возвращает `None`
   (`orchestrator/advance_gates/tests_writing.py:903-904`). Прежней находки
   `FILE_LEVEL_FINDING` у `test_profile` нет, и при сохранении границы её
   не получить. Предложение: «запись `test_profile` с `report: junit-xml`
   при выполненных (а) и (б) — гейт FAIL_TO_PASS не применяется (переход
   без его отказа и без находки), записи журнала о засчитывании нет, пакет
   без строки засчитывания». Это расхождение между решением п. 7 и
   границей ТЗ, выбирает Оператор.
2. **Требования 1–2 / AC-8, AC-10: находка уровня файла у Vitest.** После
   требования 1 у файла Vitest с ошибкой модуля появится запись в
   `by_file` (`orchestrator/advance_gates/acceptance.py:328-341`). Второе
   правило (`tests_writing.py:820-823`) перестанет срабатывать, а первое
   (`:813-814`) запись Vitest не узнаёт. Требования не говорят, что
   незасчитанная запись `file_level` любого отчёта даёт
   `FILE_LEVEL_FINDING`. Это вытекает только из AC-8 и AC-10. Стоит
   назвать в «Требованиях» 1, а слова «второе правило остаётся запасным»
   уточнить: для файла без записей вовсе.
3. **Требования 2 (б) / AC-7: «`P/index`» читается двояко.** Буквально —
   «разрешённый спецификатор равен P + `/index`», для файла P это
   бессмысленно. По смыслу — «спецификатор + `/index` равен P без
   расширения» (P = `…/index.ts`). Не описан и спецификатор с явным
   расширением (`./new.ts`, разрешённый равен P, а не «P без
   расширения»): засчитывать его или нет. Нужна однозначная формулировка.

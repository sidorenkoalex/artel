## Замечания

- major — orchestrator/advance_gates/tests_writing.py:931-937 (`_missing_import_path`, ветка Vitest) вместе с :950-952 (`_absent_in_base`) — элемент `zones:`, который на самом деле каталог, записанный без завершающего `/` (`frontend/src/comp`), засчитывается «новым модулем». У зоны без расширения `stem == zone`, и `resolved == zone` совпадает со спецификатором каталога `../../comp`. Дальше `gitcmd.ls_tree_files` вызывается с `-r` и возвращает ФАЙЛЫ под каталогом (`['frontend/src/comp/a.js']`), так что проверка `path not in listed` истинна и для каталога, СУЩЕСТВУЮЩЕГО в базе. Сценарий: SPEC с `zones: frontend/src/comp` (каталог есть в базе, `index` нет), файл планки импортирует `../../comp` и падает с `Failed to resolve import "../../comp" from …`. Гейт пишет «ошибка уровня файла засчитана красным: новый модуль frontend/src/comp …» и не даёт находки уровня файла. По SPEC здесь должна быть прежняя находка: требование 2 (а) — «элементы-каталоги не считаются», «отсутствующий в дереве `diff_base`». Это ослабление гейта честного FAIL_TO_PASS. Воспроизведено: пробой `_missing_import_path(..., ["frontend/src/comp"])` → `frontend/src/comp` (с `/` на конце → `None`) и временным git-репо, где `ls_tree_files("HEAD", "frontend/src/comp")` → `['frontend/src/comp/a.js']`, `absent=True`. Тест AC-8 «каталог» этого не ловит: он проверяет только Python и только зону с `/` на конце. Предложение: в `_absent_in_base` считать P отсутствующим, только если в `listed` нет ни самого P, ни путей с префиксом `P + "/"`. Если в базе P — каталог, это не засчитывание. Можно дополнительно не принимать зону, оканчивающуюся на `/`. Добавить в `tests/` тест разработчика (не повтор долгоживущего): Vitest, зона-каталог без `/`, каталог есть в базе, — находка уровня файла, записи журнала нет.
- minor — orchestrator/advance_gates/tests_writing.py:1115-1121 — записи «ошибка уровня файла засчитана красным» пишутся до сбора остальных находок, то есть и при отказе гейта. Каждая повторная попытка `advance` добавляет записи. Пакет их схлопывает (`dict.fromkeys`), но журнал копит повторы, а строка пакета может называть засчитывание из попытки, после которой файл уже переписали. SPEC это допускает («каждое засчитывание пишет запись»), поэтому оставлено на усмотрение: можно писать записи журнала только при успешном проходе гейта.

# PLAN: G3а-2б-1 — ошибка уровня файла в отчёте и «новый модуль» в честном FAIL_TO_PASS

## Подход
- Носитель: `CaseResult` получает в КОНЕЦ два поля со значениями по
  умолчанию (`file_level: bool = False`, `detail: str = ""`) — позиционное
  построение прежних записей не сдвигается.
- `parse_junit`: запись с `message="collection failure"` у `<error>`/
  `<failure>` — `file_level=True`, `detail` — текст элемента `[:2000]`;
  `id`/`outcome`/`failure` считаются прежним кодом.
- `parse_vitest`: запись `file_level: true` — исход `error` всегда (имя
  ошибки из `failure_errors` не делает её провалом проверки), `failure` —
  `error_name`, `detail` — `error_message`.
- Отчётчик Vitest: после тестов модуля — запись уровня файла, если
  `mod.errors()` не пуст (первая ошибка: `name`, `message`).
- Гейт честного FAIL_TO_PASS: после прогона — `_counted_new_modules`:
  для каждой записи `file_level` находит файл задачи (Vitest — по пути
  записи через `file_records`; JUnit — по ПОЛНОМУ точечному пути файла от
  `workdir`), отбрасывает долгоживущие и с маркером, проверяет (б) —
  чистая функция по `detail` и зонам `zones:` опорного SPEC (буквальное
  равенство пути), затем (а) — `ls-tree` дерева `diff_base` кодовой
  ветки (ветки нет — HEAD рабочей копии прогона); git не ответил — отказ
  подготовки. Засчитанные записи не дают находки уровня файла; «теста нет в
  отчёте» подавляется по критериям, у которых все файлы засчитаны; на
  каждое засчитывание — запись журнала `FILE_LEVEL_COUNTED_ACTION`.
- `_file_level_findings`: любая незасчитанная запись `file_level` (и
  прежнее правило `collection failure`) — находка; имя у Vitest — имя
  файла задачи по пути, у JUnit — прежнее правило последнего сегмента;
  второе правило (файл Vitest без записей) не тронуто.
- `outcome_integrity.compare`: записи `file_level` из карт базы и ветки
  исключены.
- `review._outcome_gate_lines`: в границе — строки «ошибка уровня файла
  засчитана красным: <деталь>» по различным деталям журнала задачи.
- Перенос 15: у отказа FAIL_TO_PASS `hint` пуст — подсказка печатается
  только из детали (там «\nдальше: …» остаётся для брифа test_author).
  Перенос 10 уже держит `_check_failure_kind` (`junit-xml`: `failed` с
  `TypeError` при `[AssertionError]` — не провал проверки), правки нет —
  закрепляет долгоживущий тест.

## Влияние на систему
- Вне границы (`in_outcome_bounds` ложно — артель, `test_profile`) гейт
  FAIL_TO_PASS не вызывается, раздел пакета ревьювера прежний; новые поля
  `CaseResult` — в конце со значениями по умолчанию, прежние вызывающие не
  меняются.
- Усиление: компонент `pult-vitest` с ошибкой модуля получает запись
  `error` — итог «красный» вместо «неизвестно» (требование 6).
- Гейты не ослабляются: засчитывание узкое (зона буквально, путь
  отсутствует в базе, итоговая строка/форма сообщения), сбой git — отказ,
  не засчитывание; проверка ветки `branch_criterion_problems` не тронута.
- Откат — revert коммита задачи.

  прогон до отказа (`orchestrator/acceptance.py`, класс «таймаут под
  нагрузкой как отказ кода»).

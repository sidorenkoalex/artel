## Пути обхода гейтов
- Буквальное исполнение AC-7 допускает реализацию, которая печатает «взаимная блокировка с
  <держатель> по merge_after» для ЛЮБОЙ задачи, ждущей занятую зону (без проверки, что
  держатель зависит от ждущей), либо проверяет связь в любую сторону: все AC зелёные, а
  `doctor` выдаёт ложную взаимную блокировку с советом `answer … «Зависимости мержа: …»`
  обычному ожиданию — Оператор снимет чужие зависимости мержа по ложной подсказке.
  Существующие тесты этого не ловят: в tests/ `check_zone_waits` проверяется только
  test_01m4jc5b3tyfcvy51rkz1am1vf_zone_queue_start.py:328–344 (подстроки очереди, без
  отрицания «взаимная блокировка»).
- Набор «прямых» состояний держателя для вида `answer` (требование 3, SPEC.md:50–52) проверен
  только на `merge_gate`; реализация с набором {`merge_gate`} проходит AC-7, а держателю в
  `in_dev`/`review`/`escalated` (где `answer` с мандатом принимается, answer.py:400–414)
  напечатает ложную оговорку «после перехода держателя в merge_gate».

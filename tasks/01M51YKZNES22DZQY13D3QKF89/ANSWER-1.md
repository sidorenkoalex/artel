Решение Оператора 16.10.2026: по всем пяти вопросам — вариант A (дефолт аналитика). 1. A. В зоны добавляется `orchestrator/project_profile.py`: в `Profile` — поля `runner`, `workdir`, `env`, `image`, `sandbox`. Вызывающие модули не меняются. `acceptance.py` выводит проект и задачу из `cwd` по раскладке `.artel/projects/<проект>/worktrees/<id>`, полный набор — из своего `task_id`. Каталог вне раскладки у проекта с `required` — именованный отказ, прогона на хосте нет.
2. A. Гейт мержа входит в п.6 без правки `fsm_merge_gate.py`: `full_suite(root, task_id)` сам берёт `command`, `runner`, `workdir` профиля по задаче. AC-12 распространяется на гейт мержа.
3. A. `image` обязателен только при `sandbox: required` и наличии `test_profile`; запись без профиля проходит проверку. Записи артели в фикстурах и запись внешнего проекта в `external_flow` получают `sandbox: off`; путь `required` покрывают новые тесты с подставным `docker`. Утверждения существующих тестов не меняются — меняются только входные строки фикстур. Ослабление сквозного сценария (путь `required` проверяется модульно, не сквозным тестом) назвать в SPEC явно. Мандат на ослабление тестов этим ответом не выдаётся: если гейт неослабления отметит правку фикстур, решение — на гейте.
4. A. Том `artel-<проект>-cache` и переменные `XDG_CACHE_HOME`, `UV_CACHE_DIR` входят в контейнер прогона уже в D1а-1; в D1а-2 — установка, полный набор, п.6 и `doctor`. Рамки частей прежние.

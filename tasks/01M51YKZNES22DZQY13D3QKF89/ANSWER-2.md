4. **Не A. Путь прогона выбирается по проекту задачи, а не по каталогу.**
   - Основной признак — задача прогона: явный параметр либо единый контекст задачи, который ставит точка входа гейта или команды, знающая задачу; для полного набора — `suite_lock.my_task_id()` (ответ 5). Раскладка `cwd`/`tdir` (`.artel/projects/<проект>/worktrees/<id>`) — только запасной признак, когда контекста задачи нет.
   - Если контекст задачи есть и проект задачи `required` — только контейнер, в каком бы каталоге ни шёл прогон: рабочая копия, временная копия базы или временное дерево гейта (`advance_gates/plan_appendix.py:58`, `appendix_tree.py:272`, `fsm_merge_gate.py:191`, `advance_gates/two_sided.py:300`). Монтируется каталог прогона по тому же пути.
   - Путь артели — только когда проект задачи — артель либо контекста задачи нет и каталог вне `.artel/projects/`. Контекст задачи есть, а проект не определён — именованный отказ.
   - Каждое боевое место запуска кода проекта и каждый боевой вызывающий, через который идёт прогон задачи, покрыт тестом: при задаче внешнего `required`-проекта прогон не идёт на хосте (подставной `docker` или именованный отказ), в том числе при прогоне во временном каталоге вне `.artel/projects/`.
   - Зоны: разрешаю добавить минимальный набор вызывающих, которым нужно поставить контекст задачи или передать задачу, — перечислить в SPEC поимённо. Правка в них — только постановка контекста или передача задачи, без изменения логики гейтов. Если набор выводит часть за рамку, деление на большее число частей допускается.

     - ослабляется: ничего.
     - цена: 0 файлов сверх ТЗ, +1 утверждение в AC-12.
     - чьё решение: Оператор.
   - B) Нет: гейт мержа остаётся на «только `command`», это отдельная задача.

3. **Нужен ли `image` записи с `sandbox: required` без `test_profile`, и что делать с фикстурами `tests/` без поля `sandbox`?** `targets.load` проверяет все записи
   файла (`orchestrator/targets.py:99-100`). Без решения первая запись без
   `image` роняет загрузку во всех сценариях песочницы: 27 файлов `tests/`
   используют фикстуры `tests/sandbox.py` — `_PROJECT_TARGET_ENTRY` `:1057-1065`,
   `ARTEL_TEST_PROFILE` `:1071-1079`, `artel_target_entry` `:1098-1104`,
   `declared_without_profile` `:1118-1130`. Ещё есть
   `tests/test_01m45fjvgqt1k0p8hdexzx6hs7_test_profile.py:107-121` (`base_entry`
   без `sandbox` и без профиля, `:31-34`) и
   `tests/test_01m484rnv3qbdy3b0m16j916zp_external_flow.py:45-61` (запись без
   `sandbox`, профиль без `image`).
   - A) `image` обязателен только при `required` **и** наличии `test_profile`; запись без профиля проходит проверку. Записи артели в фикстурах (`ARTEL_TEST_PROFILE`/`artel_target_entry`) получают `sandbox: off`, как в боевом `targets.yaml:43`. Записи внешних проектов с профилем (`external_flow`) получают `sandbox: off`, а путь `required` покрывают новые тесты с подставным `docker` (п.8 ТЗ). Утверждения существующих тестов не меняются, меняются только входные строки фикстур.
     - ломается: ничего; `test_profile.py:107-121` остаётся зелёным без правки (`base_entry` без профиля проходит).
     - ослабляется: сквозной сценарий внешнего проекта (`external_flow.py:346-474`) пойдёт хостовым путём `off`, а у настоящих внешних проектов этот путь станет нетипичным. Путь `required` в сквозном сценарии не проверяется, только модульно.
     - цена: правка строк фикстур в 2 файлах, ~0.
     - чьё решение: Оператор (меняется вход долгоживущего теста чужой задачи).
   - B) Как A, но `external_flow` переводится на `required` с подставным `docker` в песочнице, который исполняет команду на хосте и пишет argv.
     - ломается: ничего по утверждениям; подставной `docker`, исполняющий pytest на хосте, — новая механика в `tests/sandbox.py`.
     - ослабляется: ничего.
     - цена: +~$6–10 (механика подставного исполнителя и прогоны), рост планки D1а-2.
     - чьё решение: Оператор.
   - C) `image` обязателен при `required` всегда, даже без `test_profile`.
     - ломается: `test_profile.py:107-121` — `targets.check(name, base_entry(name))` начнёт отказывать; это смена вида ожидания (успех → `TargetsError`), разделом «Меняемое поведение» она не оформляется.
     - ослабляется: долгоживущий тест 01M45FJVGQT1K0P8HDEXZX6HS7 (утверждение «запись без профиля годна»), нужен мандат «Ослабление тестов разрешено».
     - цена: мандат и правка теста чужой задачи.
     - чьё решение: Оператор.
   - дефолт: A — ни одно утверждение существующих тестов не меняется, «Меняемое поведение» не нужно; ослабление сквозного сценария назову в SPEC явно.

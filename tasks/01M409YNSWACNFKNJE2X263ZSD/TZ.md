Факты (пин 7b23d1f0):
- Ссылка `refs/artifacts/<id>` физически живёт в `config.ROOT` и
  отправляется в `origin` пульта для любого target
  (`orchestrator/artifact_branch.py`, докстринг модуля). До части (а)
  снимок закрытия внешнего target уходил в `origin` его рабочей копии
  (`snapshot._target_workspace`). ADR-0021 п.3: документы задачи живут в
  репозитории самого проекта. Внешних задач в базе 0.
- Часть (а) добавила отправку после каждого коммита и повтор на
  `set_state` (`send_pending`), отказ гейта мержа и `kill` при
  расхождении с `origin`, проверки `doctor`, сторожа в
  `tests/test_artifact_ref_sync.py` — всё на репозитории пульта.
- Репозиторий фиксации области проекта (ADR-0003 п.15) жив кодом:
  `orchestrator/fixation.py` (`_fix_external`, `_read_external`),
  `orchestrator/projects.py::init_artifact_repo`; фиксация документов уже
  читает голову ссылки, но код и создание репозитория остались.
  Инвариант 25 в `docs/invariants.md` ещё упоминает «грязную копию».

Требуется:
1. Репозиторий фиксации области проекта упраздняется
   (`fixation._fix_external`, `_read_external`, родственные,
   `projects.init_artifact_repo`) вместе с потребителями: зафиксированное
   состояние документов — коммит ссылки.
2. Ссылка документов внешнего проекта живёт в репозитории самого проекта
   и отправляется в его `origin` (ADR-0021 п.3); ссылка артели — в git
   главной копии пульта, как сейчас. Сверка с `origin` на гейте мержа и
   `kill`, досылка и проверки `doctor` части (а) работают с репозиторием
   задачи, а не всегда с пультом.
3. Защита документов — гейты пульта; существующие гейты не ослабляются.
4. Инвариант 25 (часть: репозиторий фиксации упразднён; снять «грязную
   копию») — приложением к PLAN, проверено `git apply --check`.
5. Тесты (`tests/`, постоянные сторожа с заявками «Ловит мутацию»):
   репозиторий фиксации не создаётся и не читается; ссылка внешнего
   проекта уходит в `origin` проекта, а не пульта; сверка с `origin` на
   гейте мержа, в `kill` и в `doctor` для внешнего проекта читает
   репозиторий проекта. Существующие тесты не ослабляются; меняются
   только в объёме, прямо требуемом ADR-0021, — с перечнем в PLAN (гейт
   неослабления тестов пропускает их только с мандатом Оператора в
   ANSWER-n.md).

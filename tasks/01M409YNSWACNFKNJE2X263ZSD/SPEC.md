# SPEC: ADR-0021, этап 1 (б2) — упразднение репозитория фиксации и ссылка внешнего проекта

## Контекст
Часть (б2) деления задачи 01M4097E8JTNF61N4YAHQKA0AP (ADR-0021, этап 1),
идёт после мержа части (б1). Ссылка документов `refs/artifacts/<id>` сейчас
физически живёт в `config.ROOT` и отправляется в `origin` пульта для любого
target (`orchestrator/artifact_branch.py`); отправка после коммита, повтор
на `set_state` (`send_pending`), отказ гейта мержа и `kill` при расхождении
с `origin` и проверки `doctor` части (а) тоже работают только с репозиторием
пульта. ADR-0021 п.3 требует, чтобы документы задачи жили в репозитории
самого проекта. Одновременно репозиторий фиксации области проекта
(ADR-0003 п.15) жив кодом — `orchestrator/fixation.py` (`_fix_external`,
`_read_external`), `orchestrator/projects.py::init_artifact_repo`, — хотя
фиксация документов уже читает голову ссылки; инвариант 25 в
`docs/invariants.md` ещё упоминает «грязную копию». Внешних задач в базе 0.

## Требования
1. Репозиторий фиксации области проекта упраздняется:
   `fixation._fix_external`, `fixation._read_external`, родственные им
   функции и `projects.init_artifact_repo` удаляются вместе с их
   потребителями. Зафиксированное состояние документов задачи — коммит
   ссылки `refs/artifacts/<id>`.
2. Ссылка документов задачи ВНЕШНЕГО проекта живёт в git-репозитории самого
   проекта и отправляется в `origin` этого проекта (ADR-0021 п.3). Ссылка
   документов задачи артели — в git главной копии пульта и в его `origin`,
   как сейчас.
3. Механика части (а) — досылка (`send_pending`, отправка после коммита),
   сверка с `origin` на гейте мержа и в `kill`, проверки `doctor` — работает
   с репозиторием задачи (репозиторием проекта для внешней задачи,
   репозиторием пульта для задачи артели), а не всегда с репозиторием
   пульта.
4. Защита документов задачи — гейты пульта; существующие гейты не
   ослабляются.
5. Правка инварианта 25 `docs/invariants.md` (часть: репозиторий фиксации
   упразднён; формулировка «грязная копия» снимается) и, при
   необходимости, `tests/test_invariants.py` — приложением к PLAN.md в виде
   unified-диффа, применимость которого подтверждена прогоном
   `git apply --check`.
6. Постоянные тесты в `tests/` (сторожа с заявками «Ловит мутацию»)
   покрывают требования 1–3. Существующие тесты не ослабляются; меняются
   только в объёме, прямо требуемом ADR-0021, с перечнем изменённых тестов
   в PLAN.md (гейт неослабления тестов пропускает их только с мандатом
   Оператора в ANSWER-n.md).

## Критерии приёмки
AC-1. Ни один путь пульта (заведение проекта/target, фиксация документов на
переходе FSM, чтение зафиксированного состояния, `approve` без явного sha)
не создаёт репозиторий фиксации области проекта: после прохождения этих
путей для внешнего target каталог репозитория фиксации
(`config.PROJECTS/<target>` как git-репозиторий фиксации) не появляется.

AC-2. Фиксация и чтение зафиксированного состояния документов задачи
(внешней и артели) не читают репозиторий фиксации области проекта:
зафиксированное состояние документов — sha коммита головы ссылки
`refs/artifacts/<id>`.

AC-3. В `orchestrator/` нет функций `fixation._fix_external`,
`fixation._read_external` и `projects.init_artifact_repo`, и нет их
вызовов.

AC-4. Коммит документов задачи внешнего проекта создаёт/двигает ссылку
`refs/artifacts/<id>` в git-репозитории этого проекта, а не в
`config.ROOT`; ссылка документов задачи артели по-прежнему создаётся в git
главной копии пульта.

AC-5. Отправка ссылки документов (после коммита и досылкой
`send_pending`) для задачи внешнего проекта уходит в `origin` репозитория
проекта и не уходит в `origin` пульта; для задачи артели — в `origin`
пульта.

AC-6. Сверка ссылки документов с `origin` на гейте мержа для задачи
внешнего проекта читает репозиторий проекта и его `origin`: расхождение
ссылки проекта с `origin` проекта даёт отказ гейта мержа, а состояние
ссылки в репозитории пульта на исход не влияет.

AC-7. Сверка ссылки документов с `origin` в `kill` для задачи внешнего
проекта читает репозиторий проекта и его `origin` (расхождение там
отказывает `kill` так же, как для задачи артели), а не репозиторий пульта.

AC-8. Проверки `doctor` части (а) о синхронности ссылок документов с
`origin` для задачи внешнего проекта читают репозиторий проекта и его
`origin`, а не репозиторий пульта.

AC-9. Для задачи артели исходы досылки, сверки на гейте мержа, в `kill` и
в `doctor` не меняются относительно текущего поведения (существующие
сторожа `tests/test_artifact_ref_sync.py` и смежные зелёные без
ослабления).

AC-10. PLAN.md несёт приложение — unified-дифф к `docs/invariants.md`
(инвариант 25: репозиторий фиксации упразднён, без формулировки «грязная
копия»), и, если требуется, к `tests/test_invariants.py`; в PLAN.md
подтверждено, что `git apply --check` по каждому приложению проходит на
чистом дереве.

AC-11. Постоянные тесты в `tests/`, добавленные задачей, проверяют AC-1,
AC-2, AC-4–AC-8 и каждый тестовый метод несёт заявку «Ловит мутацию»;
каждый изменённый существующий тест перечислен в PLAN.md с обоснованием
пунктом ADR-0021.

## Оценка объёма и деление
Сработавшие сигналы: число затрагиваемых модулей/файлов зоны ≥ 5
(`orchestrator/fixation.py`, `orchestrator/projects.py`,
`orchestrator/artifact_branch.py`, `orchestrator/fsm_merge_gate.py`,
`orchestrator/cleanup.py`, `orchestrator/doctor/artifact_branches.py`,
`orchestrator/doctor/misc_checks.py`, потребители в `checkpoint.py`/
`fsm.py`/`fsm_advance.py`, тесты); число критериев приёмки ≥ 10 (11);
`budget_usd` ≥ $30; зона задевает механизм, на который опирается
инвариант 25 `docs/invariants.md`.

**Обоснование монолита.** Задача уже является частью (б2) деления
родителя 01M4097E8JTNF61N4YAHQKA0AP с рамкой Оператора $40 (TZ.md).
Требования 1 и 2–3 меняют один и тот же ответ — «в каком git-репозитории
живёт зафиксированное состояние документов задачи target»: упразднение
репозитория фиксации переводит фиксацию внешнего target на голову ссылки,
а ссылка внешнего target по требованию 2 переезжает в репозиторий
проекта. Нарезка «сначала упразднить репозиторий фиксации, потом
перенести ссылку» оставила бы промежуточное состояние, в котором
фиксация внешнего target читает ссылку в репозитории пульта — то самое
расположение, которое ADR-0021 п.3 отменяет, и инвариант 25 пришлось бы
править дважды. Обратный порядок оставил бы живым репозиторий фиксации
рядом с ссылкой в репозитории проекта — два источника зафиксированного
состояния. Решение (монолит или дальнейшая нарезка) — за Оператором на
гейте SPEC.

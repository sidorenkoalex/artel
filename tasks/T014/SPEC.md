# SPEC: Команда auto — цикл до ближайшего гейта

## Контекст
Жизненный цикл задачи — чередование агентских шагов и механических
команд Оператора: run → подождать → advance → run… В этих командах нет
решений (их принимает FSM по артефактам), но дёргает их человек — это
утомительно и ошибкоопасно: дважды за историю Оператор запускал run
вместо advance и получал лишний платный прогон ревьювера (T006, T011).
Решения Оператора (approve/reject на гейтах) при этом должны остаться
ручными — по политике §4.

## Требования
1. Команда `auto <id>`: в цикле выполняет логику run и advance
   (существующие функции, без дублирования их кода), пока задача
   в агентских состояниях (in_dev, review). Останавливается и
   завершает процесс, когда состояние становится: ручным гейтом
   (spec_gate, acceptance, merge_gate), escalated, done, killed —
   либо когда run отказался стартовать (бюджет).
2. При остановке печатает: итоговое состояние, причину остановки
   и следующую команду Оператора (например «acceptance — проведи
   приёмку: approve/reject»).
3. **auto никогда не вызывает approve/reject** и не имеет пути мимо
   гейтов: это инвариант — закрепить тестом (новый пункт в реестре
   docs/invariants.md со ссылкой; сам тест — в отдельном модуле
   tests/, НЕ в test_invariants.py: реестр и защищённый модуль правит
   только Оператор, дополнение реестра согласовано этим SPEC,
   прошедшим гейт Оператора).
4. Защита от бесконечного цикла: максимум шагов за один вызов auto
   (константа, например 30); по достижении — остановка с сообщением
   (не эскалация: задача остаётся в текущем состоянии).
5. Старт и остановка auto журналируются (actor=operator, причина
   остановки в detail).
6. Консольный вывод цикла — сводка переходов и пути к логам агентов
   (живой вывод агентов уже стримится в .artel/logs, дублировать
   не нужно).
7. Юнит-тесты в tests/ (без реального CLI, подменой run):
   остановка на каждом из гейтовых/терминальных состояний, остановка
   по бюджетному отказу, лимит шагов, отсутствие вызовов
   approve/reject из auto, журналирование старта/остановки.

## Критерии приёмки
1. `auto <id>` на задаче в in_dev доводит её до acceptance (через
   ревью с итерациями, если будут) и останавливается с подсказкой —
   без единого ручного advance/run (проверимо на следующей задаче
   конвейера; в этой — юнит-тестами).
2. Тест «auto не проходит гейты» есть, реестр инвариантов дополнен
   строкой со ссылкой на него.
3. `python3 -m unittest discover -s tests` зелёный, guard и CI зелёные.

## Не входит
- Демон, вебхуки, параллельные задачи (MVP §6).
- Автоматический запуск auto после approve (Оператор вызывает сам).
- Уведомления в телеграм.

# ТЗ: Очередь зоны решает старт

Родительская задача: 01M4JASKTKX6XYG5P2SACJYJH7 — Порядок старта в очереди зоны
Зоны: orchestrator/zone_lock.py, orchestrator/catalog.py, orchestrator/doctor/, docs/codebase-map.md, tests/
Порядок: после части 1
Рамка: $40

Сегодня первый шаг разработчика пускает только занятость зоны:
`orchestrator/zone_lock.py::blocking_conflict` (~398) и `claim` (~459)
решают по `_occupies` (~349); ожидающие задачи, `queue_order` (~567) и
`merge_after` не учитываются. `queue_position` (~590) считает
конкурентами только задачи с ТОЧНО тем же путём (`conflict[0] == path`,
~609) — вложенные зоны попадают в разные очереди. `cmd_zone_reorder`
(~617) печатает «переставлена», в том числе без аргументов, но старт не
решает. Случаи 05.10: взаимная блокировка части 3 и части 2 этапа 3;
после мержа 01M462QACE зону взяла задача на позиции 4.

Требуется:
1. Зону, которую никто не держит, получает первая по очереди задача среди
   ожидающих пересекающуюся зону (с учётом вложенности путей,
   `_paths_overlap`, ~204); остальные получают именованный отказ «ждёт
   очереди зоны: впереди <id>».
2. Порядок очереди: ручной `zone-reorder` главнее; без него — зависимость
   раньше зависящей задачи (топологический порядок по `merge_after`),
   затем нынешние ключи. Задача, у которой незавершённая зависимость
   `merge_after` ждёт пересекающуюся зону, зону не получает (отказ «ждёт
   зону ради зависимости <id>»).
3. Ожидающая задача, которая сама не может стартовать (цикл не идёт,
   пауза, эскалация, отказ «ждёт зону ради зависимости»), очередь не
   держит.
4. `queue_position`, `status` и `doctor` показывают ту же очередь, что
   решает старт; `zone-reorder` без аргументов — отказ с подсказкой.
5. Смена поведения существующих тестов — только разделом SPEC «Меняемое
   поведение» (инвариант 38).

Критерии приёмки (направление): перестановка `zone-reorder` меняет, кто
стартует первым, в том числе при вложенных зонах; цепочка из трёх задач
с `merge_after` на одной зоне проходит без взаимной блокировки —
зависимость стартует раньше зависящей; ожидающая задача на паузе или без
живого цикла очередь не держит; `status`/`doctor` показывают тот же
порядок, что решает старт.

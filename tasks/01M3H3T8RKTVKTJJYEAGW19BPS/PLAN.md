# PLAN: Команда ci-rerun в отдельном модуле пульта

## Подход

Задача класса «рефакторинг»: перенос, не улучшение. Шесть функций
команды переезжают из `orchestrator/fsm.py` в новый
`orchestrator/ci_rerun.py` дословно — тексты отказов, порядок и тексты
записей журнала, коды выхода, обращения к `gh` не тронуты ни символом.
Вместе с функциями переезжают шесть констант команды
(`CI_RERUN_ACTION`, `CI_RERUN_REFUSED_ACTION`, `CI_RERUN_REASON_MARKER`,
`CI_RERUN_OUTCOME_GREEN/RED/UNKNOWN`) со своими комментариями: они —
часть того же блока и вне команды нигде не читаются (grep по
`orchestrator/`, `tests/`: только `fsm.py` и
`tests/test_ci_rerun_command.py`). `config.CI_RERUN_WAIT_SEC` — чужая
константа, остаётся в `orchestrator/config.py`.

Ключевое решение — **как замкнуть импорт**. Новый модуль нуждается в
двух именах `fsm.py`: `VERIFYING_STATUS_ACTION` (требование 4) и
`_origin_main_sha` (требование 5); оба SPEC оставляет в `fsm.py`
(«Не входит: попутные улучшения `orchestrator/fsm.py`»). При этом AC-3
требует в `fsm.py` алиас — модульного уровня, `is`-идентичный объект, не
обёртку, — то есть `fsm.py` обязан импортировать новый модуль на уровне
модуля. Симметричный модульный импорт `fsm` в `ci_rerun.py` замкнул бы
цикл, и порядок «`ci_rerun` первым» (ровно так его импортирует
`tests/test_ci_rerun_command.py`: `from orchestrator import ci,
ci_rerun, fsm, store`) давал бы `ImportError`. Поэтому:

- `orchestrator/ci_rerun.py` на уровне модуля импортирует только
  `ci, config, lease, store` — замыкание их модульных импортов
  (`ci, config, gitcmd, lease, liveness, schema, session, store`)
  до `fsm` не доходит, проверено разбором AST;
- `fsm` импортируется ОТЛОЖЕННО, внутри `_last_red_status_sha` и
  `_cmd_ci_rerun` — тем же приёмом, которым сам `fsm.py` зовёт
  `fsm_advance` (`fsm.py:566`) и `fsm_merge_gate` (`fsm.py:949`);
- `fsm.py` держит `from .ci_rerun import cmd_ci_rerun` (`fsm.py:36`) с
  комментарием о сроке снятия — одна волна.

Отложенный импорт — ещё и условие AC-4: подмена
`mock.patch.object(fsm, "_origin_main_sha", …)` (существующий тест,
`tests/test_ci_rerun_command.py:254`) работает только при обращении
через модуль в момент вызова; импорт по имени её бы сломал.

Потолок задачи не переоценивается: объём PLAN совпал с оценкой SPEC
(`budget_usd: 25`), поле во frontmatter оставлено закомментированным
(его здесь нет).

## Смок до/после

Оба вызова прогнаны временным сценарием из рабочего каталога с
подменённым `artel._refuse_if_worktree` (инвариант T056 отказывает
любому запуску `artel.py` из git-worktree до таблицы команд) и свежей
схемой БД во временном `.artel/`; сценарий и его вывод удалены после
сверки и в git не попали. Абсолютный путь корня из трейсбеков снят —
он у «до» и «после» один и тот же.

**Вызов 1 — `artel.py ci-rerun` без аргументов.** Код выхода `1` до и
после; вывод совпадает построчно, кроме одной строки — той самой, что
меняет задача (эхо исходника в трейсбеке):

```
  До:    "ci-rerun": lambda: fsm.cmd_ci_rerun(rest[0], _reason_arg(rest)),
  После: "ci-rerun": lambda: ci_rerun.cmd_ci_rerun(rest[0], _reason_arg(rest)),
```

Остальное тождественно до байта: `Traceback (most recent call last)` ->
`orchestrator/artel.py", line 950, in main` -> `orchestrator/artel.py",
line 937, in <lambda>` -> `IndexError: list index out of range`. Номера
строк `artel.py` сохранены намеренно: `ci_rerun` вписан в существующий
кортеж импорта без прибавления строк.

**Вызов 2 — `artel.py ci-rerun 01MNETAKOYZADACHI00000000` (несуществующий
id).** Код выхода `1` до и после; вывод побайтно одинаков:

```
Задача 01MNETAKOYZADACHI00000000 не найдена. `status` покажет существующие.
```

Разность файлов «до»/«после» (`git diff --no-index`) — ровно две строки
вызова 1, приведённые выше.

## Влияние на систему

**Что затрагивается за пределами правки.** Наблюдаемое поведение
команды `ci-rerun` — нет: тексты отказов, коды выхода, тексты и порядок
записей журнала, обращения к `gh` перенесены дословно (сверка AST с
версией «до», AC-1 зелён). Справка `artel.py` и разбор `--reason` не
тронуты (AC-2 зелён, `_reason_arg` сверен с версией «до»; изменена
только ссылка на модуль в его докстринге). Внешние вызовы
`fsm.cmd_ci_rerun` продолжают работать через алиас.

**Инварианты и гейты рядом.** Ничего не ослаблено: гейты `merge_gate`,
`verifying`, guard'ы и лимиты не тронуты. Инвариант 19 («неизвестный
статус не зелёный») переехал внутри `_ci_rerun_outcome`/`_cmd_ci_rerun`
как есть. Инвариант T056 (`_refuse_if_worktree`) не тронут — он снят
только в одноразовом сценарии смока, который удалён.

**Тесты.** `tests/test_ci_rerun_command.py`: сценарии и ассерты не
изменены, изменены только импорты и квалификаторы подмен (AC-4 зелён);
добавлен один тест тождества алиаса. Строки 84/100/111 вышли за 79
символов — переносить их нельзя: AC-4 сверяет исходник тела с версией
«до» с точностью до квалификатора модуля, переформатирование его бы
сломало. Линтера в CI нет (`.github/workflows/ci.yml`), длина строки
ничего не красит.

**Как откатить.** Revert одного merge-коммита: изменение целиком в
четырёх файлах плюс новый модуль, внешних состояний (БД, ветки, алерты)
не трогает.

**Прогоны.** `tests/test_ci_rerun_command.py` — 14 passed.
`tests/test_ci_status.py`, `tests/test_invariants.py`,
`tests/test_fsm_advance_gate_smoke.py`,
`tests/test_artel_role_restricted_commands.py`,
`tests/test_cmd_approve_dispatch.py` — 152 passed, 244 subtests.
Планка задачи — 18 passed, 60 subtests; красны только два метода AC-5,
читающие этот PLAN.md из артефактной ветки, куда его несёт автокоммит
шага. Полный набор `tests/` — дело CI (скил coding-standards).

## Риски

- **Порядок импорта.** Если будущая правка вернёт `from . import fsm`
  на уровень модуля в `ci_rerun.py`, цикл замкнётся и `from orchestrator
  import ci_rerun` первым даст `ImportError`. Защита — комментарий в
  докстринге модуля и в `fsm.py` у алиаса; отдельного теста на это нет.
- **Алиас переживёт волну.** `fsm.cmd_ci_rerun` — временное имя; если
  его не снять, в пульте останутся два адреса одной команды. Пометка о
  сроке стоит у самой инструкции (`fsm.py:27-36`), AC-3 её требует.

  вместо команды пульта — не молча»). Адрес: `orchestrator/artel.py`
  (`_refuse_if_worktree`) + `skills/coding-standards.md`, раздел про
  класс «рефакторинг».

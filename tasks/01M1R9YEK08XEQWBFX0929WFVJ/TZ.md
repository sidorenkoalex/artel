# ТЗ: приёмка и мерж читают артефакты из артефактной ветки (регрессия нового контура №12, остатки №9)

Источник: наблюдения 05.09. После мержа регрессии №9 роли берут
артефакты из артефактной ветки, но два места пульта всё ещё читают
диск и кодовую ветку: (1) `approve` на гейте приёмки гоняет планку
`tasks/<id>/acceptance_tests` из worktree — при отсутствии каталога
(роли его чистят после шага) прогон даёт «Ran 0 tests / NO TESTS RAN»,
и пульт трактует это как красную планку с эскалацией «приёмочные тесты
красные после подтяжки main» (задача 01M1QHQ277…, обход — ручная
материализация Оператором); (2) мерж переносит `tasks/<id>` в main из
кодовой ветки, а CI кодовой ветки гоняет guard по её копии артефактов —
копия отстаёт от артефактной ветки (SPEC без секции «Оценка объёма» у
01M1PP0VYR… красил CI; обход — ручная синхронизация Оператором).

Требуется:
1. Прогон планки на `approve` гейта приёмки (и любой другой прогон
   планки пультом) берёт `acceptance_tests/` из артефактной ветки во
   временный каталог (как уже делает автогейт, `acceptance.
   materialize_from_branch`), не из worktree; результат «0 тестов» —
   именованный отказ «планка не найдена в источнике», не краснота.
2. На мерже `tasks/<id>` в main попадает из артефактной ветки (снимок
   на момент approve merge_gate), а не из кодовой ветки; копия
   `tasks/<id>` в кодовой ветке, если она есть (legacy), не влияет на
   результат и при расхождении журналируется предупреждением.
3. CI кодовой ветки (`ci.yml`, джоб guard) не валидирует `tasks/<id>`
   кодовой ветки live-задач как источник истины: либо джоб пропускает
   `tasks/<id>` веток `task/**` (источник — артефактная ветка,
   проверяемая своим прогоном), либо пульт при пуше синхронизирует
   копию — выбор аналитика; правка `ci.yml` диффом-приложением.
4. Тесты: approve приёмки с пустым `tasks/<id>` в worktree и планкой в
   артефактной ветке — зелёный; расхождение копии и артефактной ветки
   при мерже — в main попадает артефактная версия; существующие тесты
   (№6 автогейт, №9 материализация, T053 мерж) зелёные без ослабления.

Зоны: orchestrator/fsm.py (approve acceptance), orchestrator/acceptance.py,
orchestrator/fsm_merge_gate.py, orchestrator/fsm_postmerge.py,
.github/workflows/ci.yml (диффом), tests/. Пересечение с B2 ТЗ-1
(fsm_merge_gate, acceptance) — согласовать порядок: эта задача меньше,
идёт первой. Не входит: материализация в брифах ролей (сделано №9).

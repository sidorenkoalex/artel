# SPEC: Тесты не выходят в сеть: перехват сетевых git-команд в песочнице, локальные фикстуры, инвариант

## Контекст
Сверка свежести (01M1NBWPKNBXP9ZXXQDJM7AXPJ, регрессия №5) делает
настоящий `git fetch <url target'а>` перед сравнением с origin/main. В
фикстурах `tests/test_coldstart.py`, `tests/test_git_fixation.py`,
`tests/test_branch_freshness_gate.py` адреса target'ов вида
`https://example.invalid/...`: при обрыве сети DNS-запрос ждёт
таймаута резолвера (у git нет своего таймаута на DNS) — полный прогон
`tests/` висел минуты на `git fetch -q https://example.invalid/sled
main`. Тест, чей исход зависит от состояния сети, — дефект изоляции
того же класса, что инвариант 33 (docs/invariants.md) — тесты не
пишут в настоящий репозиторий, — только про чтение сети, а не запись.

## Требования

1. Единая точка подмены `gitcmd` (изоляция, инвариант 33,
   01M1KVGD18P9H5WR7VM8TGPV1T) в песочнице `tests/sandbox.py::TmpRootTest`
   перехватывает сетевые git-команды — `fetch`, `push`, `ls-remote`,
   `clone` с адресом, не являющимся локальным путём (`file://`,
   абсолютный путь) — и возвращает мгновенный именованный отказ (rc≠0,
   stderr «сеть в тестах запрещена: <команда> <адрес>») без обращения
   к сети. Тесты, которым нужен успешный fetch/push, поднимают
   локальный bare-репо и работают с ним по пути (так уже делают
   git-фикстуры T048/T053) — перехват их не блокирует.
2. Фикстурные адреса target'ов в `tests/test_coldstart.py`,
   `tests/test_git_fixation.py`, `tests/test_branch_freshness_gate.py`
   заменить на заведомо локальные и быстро отказывающие
   (`file:///nonexistent/...` либо `http://127.0.0.1:9/...`); ассерт на
   текст адреса (`tests/test_branch_freshness_gate.py:592`) переписать
   под новый адрес, не ослабляя саму проверку («remote — url записи
   target'а, не хардкод origin пульта»).

   `tests/test_doctor.py` и `tests/test_multitarget.py` несут те же
   фикстурные адреса вида `https://example.invalid/...` (обнаружено
   при подготовке SPEC, grep по `tests/`) — TZ называет зоной ещё и
   «остальные tests/»: структурный тест требования 3 сканирует ВЕСЬ
   `tests/**/*.py`, так что без изменения (или обоснованного
   исключения) эти два файла краснят его наравне с тремя названными.
   Обработать их тем же способом, что и три названных файла, либо
   внести в именованную константу исключений с обоснованием, — решение
   между «поправить» и «внести в исключения» на усмотрение разработчика
   (оба варианта закрывают требование 3/4 без ослабления).
3. Инвариант (docs/invariants.md, новая строка) и структурный тест в
   `tests/test_invariants.py`: файлы `tests/**/*.py` не содержат
   адресов `http(s)://<DNS-имя>` кроме `localhost`/`127.0.0.1`; список
   допустимых исключений — именованная константа с обоснованием на
   каждую строку. `docs/invariants.md` и `tests/test_invariants.py` —
   защищённые пути: поставляются unified-diff-приложением к PLAN.md
   для Оператора (`git apply --check` на чистом дереве перед сдачей,
   conventions-core), не коммитом в ветку задачи — тот же порядок, что
   ANSWER-1 задачи 01M1KVGD18P9H5WR7VM8TGPV1T.
4. Тесты: перехват возвращает отказ без сети (проверка — подмена
   резолвера/адрес несуществующего хоста и замер: команда завершается
   быстрее секунды); локальный bare-репо по-прежнему проходит через
   перехват; структурный тест красный на фикстуре с DNS-именем;
   существующие тесты зелёные без ослабления.

## Критерии приёмки

AC-1. `TmpRootTest`-песочница (`tests/sandbox.py`) перехватывает
вызовы `fetch`/`push`/`ls-remote`/`clone` с адресом, не являющимся
локальным путём (`file://` или абсолютный путь), и возвращает
мгновенный отказ (rc≠0, stderr «сеть в тестах запрещена: <команда>
<адрес>») без обращения к сети.

AC-2. Тот же вызов с локальным bare-репозиторием (адрес — `file://`
либо абсолютный путь) не перехватывается и проходит как раньше — без
изменений в поведении локальных git-фикстур (T048/T053).

AC-3. Адреса target'ов в `tests/test_coldstart.py`,
`tests/test_git_fixation.py`, `tests/test_branch_freshness_gate.py`
заменены на заведомо локальные и быстро отказывающие
(`file:///nonexistent/...` либо `http://127.0.0.1:9/...`).

AC-4. Ассерт на текст адреса в `tests/test_branch_freshness_gate.py`
(проверка «remote — url записи target'а, не хардкод origin пульта»)
переписан под новый адрес и продолжает проверять то же самое, не
ослаблен.

AC-5. `tests/test_doctor.py` и `tests/test_multitarget.py` не краснят
структурный тест из AC-6 — их адреса вида `https://example.invalid/...`
либо заменены тем же способом, что в AC-3, либо внесены в именованную
константу исключений требования 3 с обоснованием на каждую строку.

AC-6. Новый структурный тест в `tests/test_invariants.py` проверяет:
ни один файл `tests/**/*.py` не содержит адреса вида
`http(s)://<DNS-имя>`, кроме `localhost`/`127.0.0.1`; допустимые
исключения перечислены именованной константой с обоснованием на
каждую строку.

AC-7. Новая строка в `docs/invariants.md` описывает инвариант «тесты
не читают сеть по DNS-имени» со ссылкой на структурный тест требования
AC-6, который его кодирует.

AC-8. Правка `docs/invariants.md` и `tests/test_invariants.py`
(AC-6, AC-7) поставляется unified-diff-приложением к PLAN.md для
Оператора, с подтверждённым `git apply --check` на чистом дереве —
не коммитом в ветку задачи.

AC-9. Тест перехвата из AC-1 подтверждает: обращение к адресу с
DNS-именем (например, несуществующий домен либо адрес, у которого
подменён резолвер) завершается быстрее секунды и без сетевого
DNS-резолва.

AC-10. Структурный тест из AC-6 красный на синтетической фикстуре,
содержащей DNS-имя (доказательство, что тест действительно ловит
нарушение, а не декорация — тот же приём проверки мутацией, что и у
остальных инвариантов docs/invariants.md).

AC-11. Существующий набор тестов проходит зелёным без ослабления
существующих тестов, гейтов, лимитов и инвариантов.

## Оценка объёма и деление

Сработавшие сигналы:
- число затрагиваемых файлов зоны ≥ 5 (`tests/sandbox.py`,
  `tests/test_coldstart.py`, `tests/test_git_fixation.py`,
  `tests/test_branch_freshness_gate.py`, `tests/test_invariants.py`,
  `docs/invariants.md`, плюс `tests/test_doctor.py`/
  `tests/test_multitarget.py` — требование 2);
- число критериев приёмки ≥ 10 (11 AC);
- зона задевает механизм, на который опирается запись в
  `docs/invariants.md` (требование 3/инвариант 34).

**Обоснование монолита.** Задача — один атомарный механизм: точка
перехвата сетевых git-команд (требование 1) не проверяема отдельно от
её непосредственных потребителей — фикстур с DNS-адресами (требование
2) и структурного теста/инварианта, которые доказывают, что класс
дефекта закрыт навсегда, а не залатан точечно (требование 3). Разрезание
оставило бы небезопасное промежуточное состояние: перехват без
обновления фикстур ничего не меняет по факту (адреса всё ещё DNS,
просто пока не встретились с новым кодом отдельного PR), а фикстуры
без перехвата и инварианта — точечный патч без защиты от рецидива
(ровно тот сценарий, который делает наблюдение 05.09 инвариантом, а не
разовым фиксом). Рамка Оператора — $10 (типовой мелкий фикс): overhead
на 2–4 подзадачи (отдельные SPEC/PLAN/REVIEW циклы) не окупается при
таком бюджете и такой тесно связанной механике.

## Не входит

- Таймауты сетевых команд в самом пульте (`gitcmd.git` в бою, вне
  тестовой песочницы) — только тестовая изоляция.
- Изменение механики сверки свежести (01M1NBWPKNBXP9ZXXQDJM7AXPJ) —
  меняются только тестовые адреса и точка перехвата в песочнице, не
  логика `fsm`/`gitcmd`.
- Применение диффа-приложения к `docs/invariants.md`/
  `tests/test_invariants.py` в реальный main — готовит и проверяет
  (`git apply --check`) разработчик, применяет Оператор отдельно после
  `merge_gate` (тот же порядок, что ANSWER-1 01M1KVGD18P9H5WR7VM8TGPV1T).
- Уборка существующих осиротевших сущностей (ветки/логи) — не предмет
  этой задачи.

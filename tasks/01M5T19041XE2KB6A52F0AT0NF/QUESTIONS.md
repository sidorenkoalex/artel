# QUESTIONS: ИИ-настройки внешнего проекта — полем записи, вне рабочей копии роли

## Вопросы

Контекст сверки по коду. Перечень защищённых путей проекта, по которому
сверяют все гейты, собирается в одном месте:
`orchestrator/repo_context.py:106` `protected_paths(ctx)`. У внешнего
проекта это `ctx.no_paths` из `resolve`, `:96`. Эту функцию вызывают
`advance_gates/zones.py:265`, `fsm.py:1188`, `fsm_merge_gate.py:108,272,973`,
`github_adapter.py:193`, `appendix_tree.py:263`,
`advance_gates/plan_appendix.py:169` и `catalog.py:236`. `runner.py` по
`no_paths` не сверяет. Формула сверки одна: `config.is_protected_path`
(`orchestrator/config.py:789`).

1. **Где действующий список обвязки объединяется с `no_paths` (требование 2)? От этого зависит существующий тест `tests/test_project_protected_paths.py::ProjectPerimeterTest::test_external_perimeter_is_its_no_paths`.** Сейчас тест ждёт `protected_paths(resolve("vnesh")) == ("zz/",)`. Если обвязка попадёт в `protected_paths`, тест покраснеет. В утверждении стоит литерал-контейнер (кортеж), поэтому раздел SPEC «Меняемое поведение» эту смену не оформит (`skills/spec-authoring.md`: только скалярные литералы). Нужен мандат Оператора на правку теста.
   - A) Обвязка входит в результат `protected_paths(ctx)` для внешнего проекта (одна точка, все гейты получают её автоматически). Мандат на правку теста: ожидание `("zz/",)` → `("zz/",)` ∪ стандартные маркеры, вид утверждения `assertEqual` прежний.
     - ломается: `test_external_perimeter_is_its_no_paths` меняет ожидаемый кортеж; Draft MR в `github_adapter.py:199` называет источником перечня `no_paths проекта … в targets.yaml` (`_protected_paths_source`, `:96-101`), и текст источника придётся уточнить
     - ослабляется: ничего, перечень только расширяется; свойство «у артели перечень = `config.PROTECTED_PATHS`» держится в `repo_context.py:119` и не меняется
     - цена: малая правка, зоны SPEC: `orchestrator/repo_context.py`, `orchestrator/github_adapter.py`, правка одного теста
     - чьё решение: Оператор (мандат на тест)
   - B) `protected_paths` не меняется. Новая функция действующего `no_paths`, все девять мест вызова выше переводятся на неё.
     - ломается: ничего из существующих тестов
     - ослабляется: свойство «один перечень на все места сверки» (докстринг `repo_context.py:107-109`, SPEC 01M45FK56DWMNBRKA1VWM12H19, требование 1): появляются два перечня, и пропущенное место вызова тихо теряет обвязку
     - цена: зоны вырастают до ~12 файлов (`zones.py`, `fsm.py`, `fsm_merge_gate.py`, `github_adapter.py`, `appendix_tree.py`, `plan_appendix.py`, `catalog.py` и др.), класс бюджета ~85 или деление
     - чьё решение: Оператор
   - дефолт: A — одна точка сверки, перечень только шире, правка теста только смена значения.

2. **Как сверять стандартный маркер `**/.claude/` (каталог `.claude/` на любой глубине, требование 1), если `orchestrator/config.py` в ТЗ «только чтение»?** Единая формула `config.is_protected_path` (`config.py:806-814`) знает два вида записей: маску `**/<имя>`, которая сверяется только по ПОСЛЕДНЕМУ компоненту пути, и префикс. Под маску `**/.claude/` путь `frontend/.claude/rules/x.md` не попадёт: его последний компонент `x.md`. `**/CLAUDE.md` и `**/AGENTS.md` формула сверяет уже сейчас. Обычный `no_paths` тоже не может назвать вложенный `.claude/`, так что «поведение как у любого `no_paths`» для этого маркера формулой не выражается.
   - A) Разрешить правку `orchestrator/config.py`: `is_protected_path` дополнительно понимает маску `**/<каталог>/` (путь содержит компонент `<каталог>` на любой глубине). Прежние записи сверяются как раньше.
     - ломается: формула общая с артелью и с джобом CI `scripts/ci_protected_paths.py`; у артели в `PROTECTED_PATHS` (`config.py:776-782`) нет записей `**/<каталог>/`, поэтому её перечень сверяется как раньше
     - ослабляется: ничего; новая форма записи только расширяет охват
     - цена: +1 файл зоны (`orchestrator/config.py`), +1–2 критерия
     - чьё решение: Оператор (снять «только чтение» с `config.py`)
   - B) Отдельный предикат обвязки для проверок задачи; `config.is_protected_path` не трогается.
     - ломается: ничего
     - ослабляется: свойство «ЕДИНАЯ формула всех мест сверки» (докстринг `config.py:790-792`): у обвязки появляется своя формула, и места сверки по `config.is_protected_path` (их 16) вложенный `.claude/` не увидят, пока их не переведут на новый предикат
     - цена: правка всех мест сверки, зоны как в 1-B
     - чьё решение: Оператор
   - C) Сузить стандартный маркер: в запрет правки идёт только корневой `.claude/` вместе с `**/CLAUDE.md`, `**/AGENTS.md`, `.mcp.json`. Вложенный `.claude/` только исключается из рабочей копии (sparse-checkout его выражает) и только проверяется в `knowledge`.
     - ломается: правка `sub/.claude/x` в ветке задачи проходит гейты, в отличие от требования 2 ТЗ
     - ослабляется: запрет правки вложенной обвязки, которого сейчас нет нигде (у sled — только руками в `no_paths` локального слоя)
     - цена: без роста объёма
     - чьё решение: Оператор
   - дефолт: A — одна формула на все места; для артели правка ничего не меняет.

3. **Что показывает `doctor` (проверка `target-wrapper`) у артели (`DEFAULT_TARGET`)?** ТЗ ставит общую оговорку «у артели поведение не меняется», а требование 5 меняет смысл проверки. Сейчас проверка одна для любого target (A7, требование 2, AC-2; тест `tests/test_doctor.py::TargetWrapperCheckTest::test_artel_uses_the_generic_path_not_a_dogfood_skip` требует, чтобы у артели не было `skip`). Рабочие копии артели обвязку не исключают (критерий ТЗ «у артели рабочая копия полная»), поэтому новая логика дала бы у артели постоянный `warn` на каждой рабочей копии.
   - A) У артели проверка остаётся прежней инвентаризацией клона (warn/ok по маркерам), новая логика работает только у внешних проектов.
     - ломается: ничего; `test_artel_uses_the_generic_path_not_a_dogfood_skip` остаётся зелёным (не `skip`)
     - ослабляется: свойство «единая логика для любого target» из докстринга `preflight.py:520-522`: появляется ветвление по артели
     - цена: без роста объёма
     - чьё решение: Оператор
   - B) У артели `ok` с пояснением «рабочие копии пульта полные по замыслу (ADR-0003 п.14)», без перечня по рабочим копиям.
     - ломается: ничего из тестов
     - ослабляется: у артели пропадает информационное предупреждение о её обвязке в клоне (`preflight.py:531-534`)
     - цена: без роста объёма
     - чьё решение: Оператор
   - дефолт: A — буквально «у артели поведение не меняется».

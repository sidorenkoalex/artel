## Пути обхода гейтов

- Е1. Роль внешнего проекта держит `Bash(git:*)`
  (`orchestrator/providers/claude.py:122`). Внутри шага она может вернуть
  обвязку на диск: `git sparse-checkout disable`,
  `git checkout HEAD -- .claude`, `git show HEAD:CLAUDE.md`. Тр. 9
  закрывает главный вектор — CLI роли на старте шага не видит обвязку в
  cwd, потому что `ensure` перед каждым шагом (`runner.py:1206`) приводит
  шаблоны к текущему списку и убирает неотслеживаемое. Чтение обвязки
  внутри шага ТЗ сознательно вывело из объёма («ограничение чтения»).
  Исполнить harness роль не может: `python3` у внешнего проекта разрешён
  только для `artel.py`. Факт ТЗ «роли разрешён `Bash(python3:*)`»
  устарел. Не отклонение — к сведению Оператора.
- Е2. Зона ТЗ/SPEC `harness` без `/` при `agent_wrapper: [harness/]`
  (как и при `no_paths: [harness/]`) проходит пометку зон: формула
  префиксная (`config.py:812`). Тр. 7 распространяет сверку «каталог без
  `/`» только на маски `**/<каталог>/`. Правку файлов `harness/x.py` всё
  равно отклонит гейт зон на `in_dev → verifying` (AC-10) — отказ
  поздний, но не обход. Поведение «как у `no_paths`» требует ТЗ п.2. Не
  отклонение.
- Е3. Мандат ANSWER-1 пофайловый, а гейт неослабления снимает в
  названных файлах любую находку (`advance_gates/test_integrity.py`).
  Объём «остальное не меняется» держит ревью, не машина. Повод Оператору
  сверить дифф четырёх файлов на гейте мержа целиком (перенесено из
  прошлого аудита, по-прежнему в силе).

Других путей выполнить SPEC буквально в обход гейта не нашёл: `./`-обход
`knowledge` закрыт нормализацией (тр. 8, AC-14), устаревшие исключения —

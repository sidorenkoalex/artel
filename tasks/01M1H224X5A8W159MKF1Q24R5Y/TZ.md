# ТЗ: A7: артель как внешний target — пин версии, шаг обновления, внешний флоу

# ТЗ: A7 — артель как внешний target

Источник: роадмап §3 фаза B (строка A7: «stage0/stage1 (пин + шаг
обновления в doctor), защищённые пути с подсветкой в MR, тест
"merge не меняет запущенную версию"»); ADR-0003 (решение 23.08:
«догфуд живёт текущей механикой ДО A7, затем — обычный внешний
target»; после A7 первичка задач артели — `.artel/projects/artel/`
вне git, в репо артели артефакты новых задач не попадают — «чистый
B»); ADR-0004 (задачи панели идут через A7 без второго репо);
решение Оператора 01.09 (V7-Q2: порядок M1 → A7 — внешний флоу
стоит на механике M1; уборка исторических tasks/ — после обоих).
Предпосылки готовы: M1 смержен (артефактная ветка, ULID,
self-target-механика — AC-18 M1), B1b смержен (GitHub-адаптер,
Draft-MR, verifying — T079).

Суть: снять с артели статус «особый случай догфуда» — она
подключается в targets.yaml и живёт тем же внешним флоу, что любой
целевой проект. Ключевая новая механика — отделение ЗАПУЩЕННОЙ
версии системы от её main: конвейер, меняющий собственный код, не
должен менять код, которым исполняется, посреди работы.

Требуется:
1. Артель объявляется обычным target в targets.yaml (forge github,
   свой url, token_slot, no_paths, merge_gate=operator). Особые
   ветки «догфуд — особый случай» в doctor и прочих местах
   (target-layout, target-wrapper, remote-empty, base-branch,
   recovery — сегодняшние skip'ы) переводятся на общую логику
   внешнего target; где общая логика к самому себе неприменима —
   явное решение в SPEC, не молчаливый skip.
2. Новые задачи артели идут внешним флоу: первичка артефактов —
   `.artel/projects/artel/` вне git пульта (механика M1/Б₃:
   артефактная ветка пульта при жизни, снапшот в
   `refs/artifacts/<id>` артели при закрытии); в кодовые ветки
   и main артели артефакты новых задач не попадают. Исторические
   tasks/ не трогаются (уборка — отдельной задачей после A7,
   решение V7-Q2).
3. Stage0 — пин запущенной версии: версия оркестратора, которой
   исполняются команды, фиксируется явным пином на sha (решение
   Оператора 02.09: пин через sha, не тэг и не отдельный чекаут-
   каталог; как именно sha-пин применяется при запуске команд —
   решение исполнителя в SPEC); мерж задачи в main артели НЕ меняет
   запущенную версию. Обязательный тест: «merge не меняет запущенную
   версию» — после мержа в main работающий конвейер продолжает
   исполняться пином.
4. Stage1 — шаг обновления: doctor показывает расхождение
   пин ↔ main артели (информационно) и печатает точную операторскую
   команду обновления пина; сам не обновляет (обновление —
   операторское действие). Обновление пина журналируется.
5. Защищённые пути: изменения protected-paths в MR задачи артели
   подсвечиваются в Draft-MR (комментарий/чек-лист адаптера —
   способ выбирает исполнитель), не только предупреждением в CI.
6. Тесты: задача артели проходит полный внешний флоу end-to-end
   (заведение → артефактная ветка → Draft-MR → verifying →
   merge_gate) без записи артефактов в кодовые ветки; пин
   неизменности запущенной версии при мерже; doctor-расхождение
   пин/main и команда обновления; общая target-логика вместо
   догфуд-skip'ов; существующие тесты зелёные.

Зоны: targets.yaml (мандат этим ТЗ), orchestrator/config.py,
catalog.py, doctor.py, github_adapter.py, workspace.py,
artifact_branch.py/snapshot.py (следом за M1), tests/.
ЗАПУСКАТЬ ПОСЛЕ разгрузки волны 2г (наблюдаемость, push-guard,
границы данных, линт-до-лока): зоны doctor.py/catalog.py заняты
наблюдаемостью, fsm-зоны — push-guard'ом и линтом-до-лока.
Конфликт зон — эскалация.

Не входит: Д1 (нейтральное имя системы — следующим шагом, «тихое
окно после A7»); M2 (sync с origin); уборка исторических tasks/;
разделение PAT и branch protection (триггер №24, этап 2 панели);
публикация артефактов в ветку `artel` целевых (отложено ADR-0003).

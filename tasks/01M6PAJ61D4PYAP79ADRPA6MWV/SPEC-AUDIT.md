## Пути обхода гейтов
- Правило перекрытия работает по выводу `config`, не по исходному файлу;
  обходы сокета (`driver_opts`, `volumes_from`, `secrets`/`configs`,
  сокет контекста) закрыты отказами (треб. 5). Путь через `extends`/
  `include` разрешается самим `config` до проверки — закрыт тем же.
- Константа правила перекрытия в ключе итога (треб. 10) — правка правила
  без смены константы оставила бы старый итог; держится только
  дисциплиной «любая правка правила меняет константу», тестом не
  закрепляется полностью (AC-15 ловит смену константы, не забытую смену).
  Принимаемо: такой же приём уже в ключе итога; отмечаю, не отклонение.
- Обхода через `compose_task_id`: исполнитель мог бы использовать прежний
  `task_id` и для имени, и для раскладки — запрещено решением №5.1 и
  AC-9 («раскладки нет»).

## Вердикт
concerns — одно отклонение, решаемое Оператором на гейте:

1. **Канал id для имени проекта у `plank-run` планки (не долгоживущего
   файла) не задан.** SPEC треб. 3 (решение шестого круга 1) вводит у
   `run_plank` `compose_task_id` и велит `plank_run.py` передавать его
   только в вызов долгоживущего файла (`plank_run.py:267-269`). Вызов
   планки `plank_run.py:283-286` передаёт лишь `task_id`, а у `compose`
   прогон идёт `_run_plank_reported` → `_report_run`
   (`acceptance.py:2090`, :2103) — по треб. 3 без id это отказ запуска.
   SPEC не говорит, служит ли `task_id` `run_plank` (при отсутствии
   `compose_task_id`) источником имени проекта, или `plank_run.py` должен
   передать `compose_task_id` и в `:283`. При буквальном чтении «прежний
   `task_id` смысла не меняет» обычный `plank-run` планки `compose` будет
   отказывать; AC-3 («прогон планки профиля `compose`») и AC-9 («прогон
   планки») это место не называют явно. Варианты для Оператора: (а)
   `run_plank` берёт id имени из `compose_task_id`, иначе из `task_id`
   (дефолт — не требует правки `plank_run.py` сверх решения №5.1); (б)
   `plank_run.py` передаёт `compose_task_id` в оба вызова. Разработчик
   может выбрать (а) сам, но SPEC этого не фиксирует.

Прочие разделы — без отклонений; пункты прежних визитов (места вне зон
без id, `_rerun`, смысл `task_id` у `run_plank`) закрыты решениями №4,
№5.

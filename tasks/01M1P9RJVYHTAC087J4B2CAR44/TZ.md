# ТЗ: инкрементальный дифф ревью после A7 — база из истории кодовой ветки (регрессия нового флоу A7 №10)

Источник: наблюдение 04.09. С переводом пульта на внешний target
(A7, 01M1H224X5A8W159MKF1Q24R5Y) запись журнала «sha зафиксирован»
несёт голову фиксационного репозитория `.artel/projects/artel`
(например `00e32aaf…`, коммит «fixation: artel»), а не коммит кодовой
ветки задачи. `orchestrator/review.py` (T029, инкрементальный дифф
поздних итераций) берёт предпоследнюю такую запись базой диффа
`git diff <base>...<ветка>`; git в кодовом репозитории этот объект не
находит («Invalid symmetric difference expression»), пакет уходит
ревьюверу с пометкой «diff не собран», `строк diff 0`. Так у всех
задач волны с итерации 2 (журналы 01M1NBWPKN…, 01M1NWCM3T…,
01M1NBWTSX…): ревьювер восстанавливает дифф сам через git — лишние
токены и риск ревью не того диффа.

Требуется:
1. База инкрементального диффа — sha кодовой ветки задачи на момент
   вынесения предыдущего вердикта: брать из истории кодовой ветки
   (коммит, на котором стояла ветка при входе в `review` прошлой
   итерации) либо из отдельной колонки/записи журнала с sha кодовой
   ветки, — выбор аналитика; фиксационный sha внешнего target для
   диффа не использовать.
2. При невозможности определить базу (первая итерация, sha не
   распознан) — полный дифф к main, как сейчас; в пометке пакета
   называть причину.
3. Пометка «diff не собран» — алерт Оператору (`kind=warning`, авто-
   ack по исчезновению), а не тихая строка журнала: пустой дифф на
   итерации > 1 — дефект пакета, не норма.
4. Тесты: у задачи внешнего target на итерации 2 база — коммит
   кодовой ветки, дифф непустой; фиксационный sha в базу не попадает;
   при отсутствии базы — полный дифф с причиной; алерт при «не
   собран»; существующие тесты (T029, review_package) зелёные без
   ослабления.

Зоны: orchestrator/review.py, orchestrator/fixation.py (только чтение
sha кодовой ветки, если понадобится новая функция), orchestrator/
store.py (если колонка), tests/. Не входит: смена формата ревью-
пакета; лимиты ёмкости пакета.

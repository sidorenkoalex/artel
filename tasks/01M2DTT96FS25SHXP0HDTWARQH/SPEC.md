# SPEC: Модель роли из roles.yaml — флаг --model в команде запуска и модель в журнале шага

## Контекст
Сегодня `runner.role_cmd` собирает команду `claude -p …` без флага модели,
`ANTHROPIC_MODEL` в окружении роли не задаётся — все шаги всех ролей идут на
дефолте CLI (Sonnet 5, 100 % событий с 28.08, копилка 06.09). Данные недели
06–13.09 показывают разную цену ошибки по ролям (developer — 70 % задач с
повторным шагом, переделки $461/нед.; reviewer — 5 промахов на 68 задач)
— решение Оператора 13.09: developer и reviewer переводятся на Opus 5,
остальные явно закрепляются на Sonnet 5. Эта задача — первый, минимальный
слой из строки бэклога «Явная модель роли, своя в каждом пульте» (П2, $70):
поле модели в `roles.yaml`, чтение его кодом, флаг `--model` в команде шага
и видимость факта в журнале.

## Требования
1. `roles.yaml` несёт у каждой agent-роли (`analyst`, `test_author`,
   `developer`, `reviewer`) необязательное поле `model` — точный
   идентификатор модели CLI. Правка вносится ТОЛЬКО unified diff'ом,
   приложенным к `PLAN.md` (защищённый путь, применяет Оператор):
   `developer` и `reviewer` — `claude-opus-5`, `analyst` и `test_author` —
   `claude-sonnet-5`.
2. `orchestrator/roles.py` несёт функцию `model(role) -> str | None`:
   значение поля `model` роли, `None` если поле не задано; нечитаемое
   значение (не строка, пустая строка) — `RolesError`, тем же приёмом, что
   `skills()`.
3. Команда шага роли (argv, собираемая в `orchestrator/runner.py`) несёт
   флаг `--model <идентификатор>`, если `roles.model(role)` задан; если не
   задан — команда как сегодня, без флага.
4. Когда `roles.model(role)` не задан, в журнал шага пишется предупреждение
   «модель роли не задана — дефолт CLI» одной записью на шаг — это не
   останавливает шаг.
5. Запись журнала «agent run started» несёт `model=<идентификатор>` либо
   `model=дефолт CLI`, если поле не задано; записи «agent cost KNOWN» и
   «agent cost PARTIAL» несут тот же `model=`.
6. `status`/`report` этой задачей не меняются. Канарейка использует тот же
   `runner`, что и обычные задачи, — прогон канарейки не должен ломаться
   отсутствием поля `model` у роли, отдельная правка `orchestrator/canary.py`
   не требуется.

## Критерии приёмки

AC-1. `orchestrator/roles.py` несёт функцию `model(role: str) -> str | None`:
возвращает значение поля `model` роли из `roles.yaml`, `None` — если поле у
роли не задано.

AC-2. `model()` бросает `RolesError` (тот же приём, что `skills()`), если
поле `model` роли присутствует, но не является непустой строкой (не строка,
пустая строка).

AC-3. Команда шага роли несёт флаг `--model <идентификатор>` ровно один раз,
когда `roles.model(role)` задан; остальные флаги команды идут в прежнем
порядке, без изменений.

AC-4. Когда `roles.model(role)` не задан, команда шага не несёт флаг
`--model` (как сегодня), и в журнал шага пишется ровно одна запись
предупреждения «модель роли не задана — дефолт CLI» на шаг; шаг не
останавливается и не проваливается из-за отсутствия поля.

AC-5. Запись журнала «agent run started» несёт `model=<идентификатор>`,
если поле задано, либо `model=дефолт CLI` — если не задано.

AC-6. Записи журнала «agent cost KNOWN» и «agent cost PARTIAL» несут тот же
`model=<идентификатор|дефолт CLI>`, что и «agent run started» того же шага.

AC-7. `status`/`report` не изменены этой задачей; прогон канарейки
(`orchestrator/canary.py`) не ломается отсутствием поля `model` у роли —
канарейка использует тот же `runner`, без отдельной правки `canary.py`.

AC-8. Тесты `tests/` покрывают: `roles.model` читает заданное поле и
возвращает `None`, если поле не задано; `RolesError` — на нечитаемом
значении поля; команда шага с заданным полем несёт `--model X` ровно один
раз, в прежнем порядке остальных флагов; без поля — флага нет, и есть
запись предупреждения; запись журнала «agent run started» содержит
`model=`. Существующие тесты `orchestrator/runner.py` (101 патч по именам
модуля) не меняют ассертов.

AC-9. Unified diff на `roles.yaml`, приложенный к `PLAN.md`, задаёт
`model: claude-opus-5` для ролей `developer` и `reviewer`, `model:
claude-sonnet-5` — для `analyst` и `test_author`; диф проходит `git apply
--check` на чистом дереве (skills/conventions-core.md).

## Пути обхода гейтов
- AC-1 буквально выполним подменой `targets.target`/`gitcmd._project_entry` в тесте без загрузки слоя. Тогда пропуск поля в `_flatten` останется незамеченным, и в живой записи поле молча не будет действовать (мёртвая настройка, которую SPEC сам называет причиной монолита). - Реализация формы ключа как «без пробела» (`\S+`) выполняет AC-4 буквально, но нарушает требование 2. Отклонение п.3.
- Слой репозитория `targets.yaml` — плоская запись без проверки неизвестных полей (`check`, targets.py:890-…). Значение `commit_trailer`, положенное туда (doc-commit), `pult_message` прочтёт без проверки формы. Так сейчас ведёт себя и `co_author`, ТЗ говорит только о локальном слое, путь доступен только Оператору. Отклонением не считаю.

2. **AC-1 допускает проверку без загрузки записи** (SPEC.md:57). Если тест подкладывает запись подменой, пропуск поля в `_flatten`/`DELIVERY_POLICY_FIELDS` (targets.py:855-859) остаётся незамеченным. 3. **AC-4 не закрепляет класс символов ключа и отказ «не строка»** (SPEC.md:63 против SPEC.md:41-44). Мутация `\S+` и пропуск нестрокового значения проходят все три варианта AC-4. Предложение: добавить в AC-4 варианты «ключ с символом вне `[A-Za-z0-9-]` (например, `Key_1: x` или кириллица)» и «значение не строка (список)». 4. Неоднозначность, некритично: форма `<Ключ>: <значение>` не говорит, допустимо ли пустое значение после «: » (`"Key: "` читается yamlmini строкой `'Key: '`) и ключ, начинающийся с `-`. 5. Неточности строк (SPEC.md:28-29): `LOCAL_FIELDS` — targets.py:391-410, `co_author` — targets.py:721-726. Несущественно.

# SPEC: Служебная строка коммитов пульта по записи проекта: policy.commit_trailer

## Контекст
Каждый коммит пульта получает последним абзацем сообщения служебную строку
`PULT_ACTOR_TRAILER = "Artel-Actor: orchestrator"` (`orchestrator/gitcmd.py:544`);
её дописывает `pult_message` (`orchestrator/gitcmd.py:585-593`) после строки
`policy.co_author`. Пульт по этой строке решений не принимает
(`orchestrator/gitcmd.py:539-543`). Коммиты пульта уходят в репозитории
внешних проектов (ветки задач, `refs/artifacts/*`), и строка с именем пульта
видна людям проекта в истории. Нужна возможность заменить или убрать её
полем записи проекта, не трогая умолчание.

Вызовы `pult_message`: `orchestrator/pull.py:473`, `:556`, `:1107`,
`orchestrator/checkpoint.py:1887`, `orchestrator/artifact_branch.py:371`,
`orchestrator/amend.py:806`, `orchestrator/snapshot.py:277`. Все, кроме
`orchestrator/snapshot.py`, передают проект задачи; `snapshot.py:281` передаёт
`config.DEFAULT_TARGET` — запись артели, которая живёт только в `targets.yaml`
репозитория (`merge_local` отказывает ей в локальном слое), поэтому
исторические снимки этой задачей не затрагиваются и сохраняют
`Artel-Actor: orchestrator`. Правка одного `pult_message` покрывает все
коммиты пульта по проекту задачи. Поля доставки раздела `policy` и их проверка — `orchestrator/targets.py`
(`LOCAL_FIELDS` `:391-411`, `DELIVERY_POLICY_FIELDS` `:424-428`,
`_check_delivery` `:664-…`, образец строкового поля — `co_author` `:721-727`).
Команда `target-set` (`orchestrator/projects.py::cmd_target_set`) правит любое
поле, известное `LOCAL_FIELDS`, и сводит результат через `targets.merge_local`;
разбор аргумента `Harness-Actor: orchestrator` проверен: `yamlmini` читает его
строкой, `_literal` пишет в кавычках, обратное чтение даёт ту же строку.

## Требования

1. Локальный слой записи проекта принимает новое необязательное поле
   `policy.commit_trailer` — строку. Непустое значение — ровно одна строка
   вида `<Ключ>: <значение>`, где ключ — только `[A-Za-z0-9-]+` (латинские
   буквы, цифры и `-`, без пробелов), а значение после «: » непустое;
   значение из одних пробелов считается пустым (как `.strip()` у
   `co_author`, `orchestrator/gitcmd.py:590`).
   Пустая строка (ровно `""`) — допустимое значение «служебной строки нет»;
   значение поля целиком из одних пробелов (например `"   "`) пустым не
   считается — это отказ по требованию 2.
2. Любое иное значение поля (не строка — например, число или список;
   несколько строк; значение целиком из одних пробелов, например `"   "`;
   строка без «: », например `NoColon` или `Key:v` (двоеточие без
   следующего пробела «: » не заменяет); ключ с пробелом или иным символом вне
   `[A-Za-z0-9-]`, например `Key_x: v`; пустое или пробельное значение после
   «: », например `"Key: "` или `"Key:   "`) — отказ загрузки записи (`TargetsError`), текст отказа называет
   поле `policy.commit_trailer`.
3. `pult_message` для проекта, в записи которого есть поле, пишет его
   значение вместо `PULT_ACTOR_TRAILER` на том же месте: при заданном
   `policy.co_author` последний абзац сообщения — строка `co_author`, следом
   (в том же абзаце, следующей строкой) значение поля, и это последняя
   строка сообщения — как сейчас с `PULT_ACTOR_TRAILER`
   (`orchestrator/gitcmd.py:588-593`).
4. При пустом значении поля служебной строки в сообщении нет; строка
   `co_author`, если задана, остаётся последним абзацем сообщения; если и её
   нет — к сообщению не добавляется пустой абзац.
5. Для проекта без поля (и при `project=None`) сообщение `pult_message`
   побайтно прежнее: умолчание `PULT_ACTOR_TRAILER` не меняется.
6. Поле записывается командой `target-set <проект> policy.commit_trailer
   <значение>` штатным путём этой команды (копия прежнего слоя перед записью).
7. Существующие тесты, включая
   `tests/test_01m5wdb7jy0vjghvkcaba2qc5t_rewrite_flow.py` (`:76`,
   `TRAILER = "Artel-Actor: orchestrator"`), остаются зелёными без правки;
   если существующий тест краснеет — эскалация с именем теста, без его
   правки.

## Критерии приёмки

AC-1. Given вымышленная запись проекта с `policy.commit_trailer: "Harness-Actor: orchestrator"` в файле вымышленного локального слоя во временной песочнице, загруженная штатным путём локального слоя (`targets.load` со сведением записи), а не подложенная подменой записи, When коммит пульта (чекпоинт, подтяжка, документы задачи), Then последний абзац сообщения коммита — строка `Harness-Actor: orchestrator`, подстроки `Artel-Actor` в сообщении нет; пропуск поля при сведении записи (`_flatten`, `DELIVERY_POLICY_FIELDS`, `orchestrator/targets.py:855-859`) делает этот критерий красным. При заданном в той же записи `policy.co_author` последний абзац сообщения — ровно две строки: строка `co_author`, следом строка `Harness-Actor: orchestrator`, и она — последняя строка сообщения; мутации «служебная строка перед `co_author`» и «служебная строка отдельным абзацем после `co_author`» делают этот критерий красным.

AC-2. Given запись с `policy.commit_trailer: ""`, When `pult_message`, Then служебной строки в сообщении нет; при заданном `policy.co_author` последний абзац сообщения — строка `co_author`; при незаданном `policy.co_author` сообщение — первая строка и тело без пустого завершающего абзаца (сообщение не оканчивается пустым абзацем) и без служебной строки.

AC-3. Given запись без поля `policy.commit_trailer`, When `pult_message`, Then сообщение побайтно совпадает с прежним (последняя строка — `Artel-Actor: orchestrator`, после строки `co_author`, если она задана).

AC-4. Given значение `policy.commit_trailer` из двух строк, или без «: » (образцы `NoColon` и `Key:v`; мутация «проверять `:`, а не `: `» делает критерий красным на `Key:v`), или целиком из одних пробелов (`"   "` — отказ, а не «служебной строки нет»), или с пробелом в ключе, или с символом ключа вне `[A-Za-z0-9-]` (`Key_x: v`), или не строка (число, список), или с пустым значением после «: » (`"Key: "`), или со значением из одних пробелов после «: » (`"Key:   "`), When загрузка записи локального слоя, Then отказ `TargetsError`, текст которого содержит `policy.commit_trailer` — для каждого из этих значений. Случай «две строки» проверяется вызовом `targets.merge_local(<имя>, <запись-словарь>)` (из файла слоя значение из двух строк недостижимо: блочная запись `|` даёт отказ разбора, `\n` в кавычках остаётся буквальным); прочие случаи — загрузкой файла вымышленного локального слоя.

AC-5. `target-set <проект> policy.commit_trailer "Harness-Actor: orchestrator"` на вымышленном локальном слое записывает поле в раздел `policy` записи проекта, перед записью сохраняет копию прежнего слоя, и запись после правки загружается со значением `Harness-Actor: orchestrator`.

## Оценка объёма и деление

Прогноз диффа: 12 КиБ

Сработавший сигнал — число затрагиваемых модулей/файлов: guard считает
пути, упомянутые в тексте SPEC (вызовы `pult_message` в пяти модулях только
чтения названы в «Контексте» и «Не входит»). Правятся же два модуля кода
(`orchestrator/gitcmd.py`, `orchestrator/targets.py`), карта — только
генерацией, плюс долгоживущий тест задачи.

Обоснование монолита: поле `policy.commit_trailer` без чтения его в
`pult_message` — мёртвая настройка (проверка загрузки есть, эффекта нет), а
чтение в `pult_message` без поля в `LOCAL_FIELDS` недостижимо — запись с полем
не загрузится. Части по отдельности не дают проверяемого поведения ни одного
критерия AC-1…AC-5 целиком; объём (два модуля, ~12 КиБ) не оправдывает
деления.

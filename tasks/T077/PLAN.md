# PLAN: Guard называет точную причину отказа

## Подход

Ревизия текстов пользовательских сообщений `scripts/guard.py` без
изменения самих правил (какие структуры принимаются/отклоняются).
Каждое сообщение отказа, порождаемое правилами из требования 1 SPEC
(секции/статусы, `schema_version`, обязательные frontmatter-поля,
поле `task`, AC-разметка, трассируемость AC↔тест, маркер красноты,
секция «Проверено исполнением»), проверяется по фактуре «мог бы агент
починить нарушение по одному этому тексту, не читая guard.py» и
переписывается по образцу `review_evidence_errors` (T072): причина +
действие.

Единственное изменение логики (не только текста) — обязательные
секции: сейчас заголовок на неверном уровне (`### Критерии приёмки`)
неотличим от полного отсутствия заголовка, оба дают одно и то же
сообщение «отсутствует обязательная секция». Чтобы сообщение могло
назвать НЕВЕРНЫЙ УРОВЕНЬ (AC-2), `check_content` обязан различить эти
два случая — для этого достаточно посчитать заголовки всех уровней
(`^#{1,6}\s+...`), а не только `##`, и сравнить уровень найденного
заголовка с секцией. Это не смягчение правила (секция всё ещё
обязана быть на уровне `##`, иначе — нарушение) — только более точная
диагностика причины уже существующего отказа.

Сообщения без явного АС-критерия (schema_version, unknown type,
поле task, дублирующиеся AC-номера, "пометка на критерий, которого
нет в SPEC", "тест на критерий, которого нет в SPEC") тоже
переписываются по тем же двум правилам SPEC (называть форму целиком +
действие) — Оператор читает их на приёмке той же фактурой (докстринги
test_ac3/test_ac4 в acceptance_tests/, SPEC требование 1 — не только
восемь протестированных категорий).

Существующие подстроки-ассерты в `tests/test_guard_schema.py`,
`tests/test_acceptance_tests_flow.py`, `tests/test_analyst_role.py`,
`tests/test_invariants.py`, `tests/test_yaml_parsing.py` и локальных
`acceptance_tests/` других задач (T064, T072) — сверены построчно
(grep по каждой затрагиваемой подстроке) перед правкой: новые тексты
сохраняют эти подстроки (например, «недопустимый status», «AC-2»,
«Не входит», «Проверено исполнением», «маркера», «frontmatter»,
«status», «Вопросы», «повторяются», «не размечены AC-n») и добавляют к
ним недостающие детали формы + глагол действия, не удаляя старое.

## Влияние на систему

Меняются только тексты сообщений и (для AC-2) точность диагностики
причины уже существующего отказа секции на неверном уровне — набор
принимаемых/отклоняемых артефактов не меняется: артефакт с заголовком
не на уровне `##` отклонялся до правки и отклоняется после, разница
только в тексте объяснения. Синхронно правятся существующие тесты
текста сообщений (не удаляются — AC-5, проверяется отдельным
приёмочным тестом на дифф тестовых методов к main). Внешние
потребители `scripts/guard.py` (`orchestrator/fsm.py`,
`orchestrator/acceptance.py`, `orchestrator/canary.py`,
`orchestrator/retro.py`, `orchestrator/version.py`) читают возвращаемые
строки как есть и печатают/логируют их — не парсят по регэкспу,
проверено grep'ом импортов из codebase-map. Откат — `git revert`
коммита правки, тексты возвращаются к прежним, поведение (что
принимается/отклоняется) не затронуто откатом.

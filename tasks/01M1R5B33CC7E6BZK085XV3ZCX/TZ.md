# ТЗ: репозиторный контекст target для git/gh-слоя (B2, ТЗ-1 исследования 04.09)

Источник: это исследование (§2.2, §4.3 класс Б); ADR-0003 п.4 и п.6
(workspace — эфемерный клон целевого; merge в целевой — только
оркестратор через адаптер); роадмап §3 B1b (Draft-MR-флоу, первый
прогон — на артели; второй — на sled) и §4 п.2г (реестр регрессий,
класс «локальная копия вместо источника истины»).

Суть: все операции над кодом задачи (push, MR, CI, свежесть, diff,
merge, RETRO) исполняются в репозитории ЦЕЛЕВОГО задачи, а не в
репозитории пульта. Сегодня `gitcmd.git` и `ci.gh` привязаны к
`config.ROOT`; для self это верно, для любого другого target — нет.

Требуется:
1. Понятие «репозиторный контекст target» в одном модуле: путь клона
   (`config.ROOT` для self; `.artel/projects/<t>/workspace` иначе),
   адрес форджа (`targets.yaml.url`), базовая ветка. Все точки
   таблицы §4.3 (класс Б) переводятся на него; SPEC НАЧИНАЕТСЯ с
   реестра этих точек (по образцу M1), каждая — с указанием, что
   читалось и что читается теперь.
2. `ci.gh` принимает контекст: `--repo <url>` для `pr create/ready/
   comment`, `api repos/<owner>/<repo>/…`, `run list`; `ci.head_sha`
   и `check_runs` — по клону целевого.
3. Сверка свежести и подтяжка (`_pull_main_or_escalate`) — против
   `origin/<base>` репозитория целевого: задача сверки свежести
   01M1NBWPKNBXP9ZXXQDJM7AXPJ смержена 05.09 и сверяет против
   origin/main пульта — здесь она параметризуется по target (remote и
   базовая ветка из контекста), поведение для self не меняется.
4. Merge для внешнего target с `merge_gate: operator`: scratch-worktree
   и push `refs/heads/<base>` — в клоне целевого; для внешнего target
   после мержа НЕ регенерируется карта и НЕ коммитится RETRO в main
   (правило «в пульте — только кухня пульта»; RETRO — в снапшоте).
5. Гейт ёмкости diff и diff ревью-пакета — из клона целевого; для
   внешнего target гейт больше не пропускается.
6. Тесты: end-to-end на ДВУХ настоящих git-репозиториях в песочнице
   (пульт + целевой с локальным bare-origin): задача внешнего target
   проходит `new → in_dev → review (diff непустой) → merge_gate → done`
   с merge в origin целевого и без единого коммита в main пульта;
   существующие тесты зелёные; инвариант «тесты не пишут в настоящий
   репозиторий» (01M1KVGD18P9H5WR7VM8TGPV1T) — предусловие.

Зоны: orchestrator/gitcmd.py, ci.py, github_adapter.py, fsm.py,
fsm_advance.py, fsm_merge_gate.py, fsm_postmerge.py, review.py,
acceptance.py, doctor.py (branch-freshness), tests/sandbox.py, tests/.
Регрессии №5/№6/№8 смержены 04–05.09. Пересечения с живыми задачами
на 05.09: fsm_advance.py (зоны части 2 и 3), doctor.py (группа
процессов, канарейка ч.1, зоны часть 2) — код стартует после их
мержа, до мержа — SPEC и планка (test_author).

Не входит: клон и ветка задачи (ТЗ-2); `target-human`/`awaiting_human`
(C1); карта кодовой базы целевого (ТЗ-4); контейнер (ТЗ-6).

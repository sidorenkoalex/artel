## Пути обхода гейтов
1. Буквальное прочтение требования 2 («`repo_context.resolve` по `target`
   задачи возвращает `None`») без проверки `is_artel` первым переводит
   задачу артели с пустой/NULL колонкой `target` в «проект задачи не
   определён»: окно остаётся открытым, но текст удержания артели меняется
   — нарушение требования 3, которое AC-3 на стендах с явным
   `DEFAULT_TARGET` не ловит. Вердикт п.1.
2. Тесты AC-1/AC-2 могут подменить `repo_context.resolve` моком вместо
   записи в `config.TARGETS` песочницы — тогда «разрешённость в
   `targets.yaml`» реально не проверяется. AC-1/AC-2 говорят «разрешённого
   в `targets.yaml`», что направляет на реальную запись; отдельным
   отклонением не считаю.
3. Широкий `except` вокруг определения проекта, возвращающий `None`
   (окно закрыто), ловится AC-4 (ожидание — открытое окно с причиной).

разработчиком без правки смысла SPEC:

1. Неоднозначность для задачи/держателя артели с пустой или NULL колонкой
   `target`: требование 1 (`SPEC.md`, «пустая колонка — артель»,
   соответствует `orchestrator/repo_context.py:172-173`) расходится с
   буквальной формулой требования 2 («`repo_context.resolve` по `target`
   задачи возвращает `None`» — для `""`/`None` это так:
   `repo_context.py:87,90-93`, `orchestrator/targets.py:120-124`; колонка
   nullable — `orchestrator/schema.py:115`). AC-3 не называет этот случай,
   поэтому мутация, меняющая текст удержания для такой задачи артели, не
   ловится. Предлагаемое прочтение для гейта: принадлежность артели
   решается `is_artel(строка задачи)` первым, `resolve` — только для
   не-артели; тест AC-3 дополнительно со строкой задачи с пустым
   `target`.

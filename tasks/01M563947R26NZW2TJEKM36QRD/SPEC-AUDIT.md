## Проверяемость критериев

| Критерий | Проверяем | Ловимая мутация |
|---|---|---|
| AC-1 | да | фильтр по проекту в цикле по задачам не добавлен / добавлен не для всех пяти состояний (тест по каждому состоянию) → окно открыто, `note` удержан |
| AC-2 | да | держатель мьютекса проверяется без проекта своей задачи → текст «держатель merge-окна жив…» вместо `None` |
| AC-3 | да | сравнение `task["target"] == DEFAULT_TARGET` вместо `is_artel` (NULL/'' → не артель → `resolve` → `None` → текст «не определён»); любая правка текстов удержания (точное сравнение текста) |
| AC-4 | да | неизвестный проект молча считается артелью (через `store.task_target`) → текст без подстроки; неизвестный считается внешним → `None` |
| AC-5 | да | `resolve` до проверки состояния (неразрешаемая задача в `done` открывает окно) |

Пробел: все AC-1/AC-2 сформулированы «при отсутствии других триггеров»,
AC-3 — для одиночной задачи артели/одиночного держателя. Сочетание не
покрыто ни одним критерием: мутация «внешний держатель → `return None`
досрочно» (вместо перехода к перебору задач) либо «первая внешняя задача
в цикле → `return None`/`break`» проходит AC-1…AC-5, хотя требование 1
(«окно открывают только: (а)… (б)…» — условие ИЛИ) нарушено: задача
артели в `in_dev` при живом держателе внешнего проекта окна не откроет.
См. вердикт, п.1.

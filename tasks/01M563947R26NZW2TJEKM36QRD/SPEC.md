# SPEC: Окно тишины note и doc-commit — только по задачам артели

## Контекст
Окно тишины (`orchestrator/notes.py:266-282`, `_silence_window_reason`)
удерживает запись `note`/`doc-commit` в `origin/main` артели, пока жив
держатель мьютекса мержа или любая задача стоит в
`config.NOTE_SILENCE_WINDOW_STATES` (`orchestrator/config.py:509`). Смысл
окна (`config.py:498-509`) — не толкать main артели под точки сверки
свежести и пуш мержа артели. Перебор задач (`notes.py:279-281`) идёт по
`store.all_tasks` без фильтра по проекту, а держатель мьютекса
учитывается независимо от проекта своей задачи: задача sled
01M55SKHZ293CCAK0N7T4H7ZMR в `verifying` своего репозитория 17–18.10
удерживала все записи копилки и бэклога (их отправлял `note --flush`);
так же окно открывает мерж задачи внешнего проекта, который в main
артели не пушит.

## Требования

1. Окно тишины открывают только: (а) задача проекта артели в состоянии
   из `config.NOTE_SILENCE_WINDOW_STATES`; (б) живой держатель мьютекса
   мержа, чья задача — задача артели. Принадлежность артели определяется
   тем же признаком, что у остальных потребителей —
   `repo_context.is_artel` по колонке `target` задачи (пустая колонка —
   артель). Задачи внешних проектов — ни в состояниях окна, ни как
   задача держателя мьютекса — окна не открывают. Текст причины
   удержания для артели прежний.
2. Проект задачи неизвестен — запись проекта не разрешается
   (`repo_context.resolve` по `target` задачи возвращает `None`), а для
   держателя мьютекса также строки его задачи нет в БД (расширение ТЗ
   п.2 — решение аналитика, принято Оператором на гейте SPEC 18.10) —
   окно открыто (осторожный исход). Текст удержания в этом случае
   называет id задачи (для держателя мьютекса — id задачи держателя) и
   причину «проект задачи не определён». Неизвестный проект не
   приравнивается к артели: исход, при котором держатель без строки
   задачи или задача с неразрешаемым проектом молча считается задачей
   артели (например, через `store.task_target`, возвращающий
   `config.DEFAULT_TARGET` для отсутствующей строки) и окно держится
   прежним текстом без этой причины, требованию не удовлетворяет.
   Проект проверяется только у задач в состояниях
   `NOTE_SILENCE_WINDOW_STATES` (и у задачи живого держателя): задача с
   неразрешаемым проектом вне этих состояний окна не открывает.
3. У артели поведение окна и тексты удержания не меняются; это
   фиксируется тестами, написанными до правки `_silence_window_reason`
   (они зелены и до, и после неё).
4. Тесты детерминированы и без сети и покрывают: задача внешнего
   проекта в `verifying` — `note` пушит сразу; задача артели в
   `in_dev` — удерживает; живой держатель мьютекса с задачей внешнего
   проекта — не удерживает; с задачей артели — удерживает.

## Критерии приёмки

AC-1. Задача внешнего (разрешённого в `targets.yaml`) проекта в любом
состоянии из `config.NOTE_SILENCE_WINDOW_STATES` при отсутствии других
триггеров окна не удерживает запись `note`/`doc-commit`: `note` пушит в
`origin/main` сразу, `_silence_window_reason()` возвращает `None`.

AC-2. Живой держатель мьютекса мержа, чья задача — задача внешнего
(разрешённого) проекта, при отсутствии других триггеров окна не
удерживает запись `note`/`doc-commit`.

AC-3. У артели окно прежнее: задача артели в `in_dev` (и в любом
другом состоянии `NOTE_SILENCE_WINDOW_STATES`) удерживает запись, живой
держатель мьютекса с задачей артели удерживает запись, тексты причины
удержания совпадают с текстами до правки
(`задача <id> в состоянии <state>`, `держатель merge-окна жив (сессия
<session>, задача <id>)`).

AC-4. Задача с неразрешаемым проектом в состоянии окна, а также живой
держатель мьютекса, проект задачи которого не разрешается или строки
задачи которого нет в БД, окно открывают; текст удержания
(`_silence_window_reason()`) в каждом из трёх случаев содержит id
задачи (для держателя — id его задачи) и подстроку «проект задачи не
определён». Реализация, где такой случай молча считается задачей артели
и текст этой подстроки не содержит, критерию не удовлетворяет.

AC-5. Задача с неразрешаемым проектом в состоянии вне
`config.NOTE_SILENCE_WINDOW_STATES` (например, `done` или `killed`) при
отсутствии других триггеров окна окна не открывает:
`_silence_window_reason()` возвращает `None`, `note` пушит в
`origin/main` сразу.

## Оценка объёма и деление

Сработавший сигнал — «число затрагиваемых модулей/файлов»: guard
считает упоминания `orchestrator/*.py` по всему тексту SPEC, а SPEC
называет модули только для чтения (`config.py`, `store.py`,
`merge_lock.py`, `repo_context.py`) и вне зоны (`merge_queue.py`).
Правится один модуль — `orchestrator/notes.py` (одна функция
`_silence_window_reason`) — плюс тесты в `tests/`.

Прогноз диффа: 12 КиБ

Обоснование монолита: правка — один фильтр по проекту в одной функции и
его тесты; резать нечего — тесты фиксации поведения артели (требование
3) без самой правки не несут смысла отдельной задачи, а правка без
тестов нарушает требование 4. Промежуточного состояния нет.

  эскалация.

  живости держателя (`merge_lock._holder_is_dead`).

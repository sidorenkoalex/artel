# PLAN: Окно тишины note и doc-commit — только по задачам артели

## Подход
Правится одна функция `orchestrator/notes.py::_silence_window_reason`.
Принадлежность задачи определяет новый помощник `_task_project(row)`:
`repo_context.is_artel(row)` первым (пустой/NULL `target` — артель),
`repo_context.resolve(row["target"])` — только для не-артели; исход —
«артель» / «внешний» / «не определён». Для держателя мьютекса строка
задачи берётся из `tasks` (`conn.execute`, не `store.get_task` — тот
`sys.exit`'ит, и не `store.task_target` — тот подставляет артель для
отсутствующей строки); строки нет — «не определён».

Порядок: живой держатель — артель → прежний текст; не определён → текст
с id задачи держателя и «проект задачи не определён»; внешний — не
возвращаем, идём к перебору задач. Перебор `store.all_tasks` по
состояниям окна: внешняя задача пропускается (не досрочный `None`),
артель → прежний текст, не определён → текст с id и причиной. Задачи вне
`NOTE_SILENCE_WINDOW_STATES` проект не проверяют (AC-5).

## Влияние на систему
Затронут только выбор триггера окна тишины `note`/`doc-commit`; набор
`NOTE_SILENCE_WINDOW_STATES`, признак живости `merge_lock._holder_is_dead`,
обход окна `--flush`/`--now` не меняются. Для артели тексты и исход
прежние — существующие тесты `SilenceWindowReasonTest` не правятся.
Неизвестный проект — окно открыто (осторожный исход). Откат — revert
одного коммита.

## Риски
`targets.yaml` сломан → внешние задачи становятся «не определён» и
держат окно, как до правки (осторожно, не хуже прежнего).

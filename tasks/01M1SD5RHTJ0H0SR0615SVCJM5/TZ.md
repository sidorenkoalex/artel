# ТЗ: R7 — `fsm_merge_gate._cmd_approve_merge_gate` разобрать на шаги

Источник: роадмап §3, фаза R, пункт R7. `orchestrator/fsm_merge_gate.py::
_cmd_approve_merge_gate` — 177 строк одной функции: мьютекс окна мержа,
подтяжка, ожидание CI, защищённые пути, сам merge, публикация снапшота,
уборка веток и worktree, RETRO, журнал. Каждая задача про мерж (№5, №12,
push-guard) правила этот клубок.

Правила фазы R: поведение не меняется; смоук байт-в-байт; тесты без
правки утверждений; защиты и инварианты не трогаются (инвариант 19 и
мьютекс merge-окна — «не трогать: защита»).

Требуется:
1. Функция разбирается на именованные шаги с явным входом/выходом:
   захват мьютекса окна мержа; подтяжка main и проверка свежести;
   ожидание/сверка CI; проверка защищённых путей; выполнение merge и
   push; публикация снапшота артефактов и RETRO; уборка (ветки,
   worktree); журнал и печать. `_cmd_approve_merge_gate` — короткая
   композиция шагов; порядок шагов и все условия отказа сохраняются
   буквально.
2. Исходы шагов — явные значения (`ok`, `refused(<причина>)`,
   `escalate(<причина>)`), без флагов и глубоко вложенных условий.
3. Тексты журнала, отказов и печати сохраняются буквально — их сверяют
   существующие тесты merge_gate и планки задач №5, №12, push-guard.
4. Смоук байт-в-байт: три записанных сценария (штатный мерж, отказ по
   красному CI, отказ по защищённому пути) на песочнице с фейковым git
   дают тот же журнал и вывод до и после.
5. Существующие тесты `tests/test_fsm_merge_gate*.py`,
   `tests/test_branch_freshness_gate.py` и планки задач 01M1NBWPKN…,
   01M1GS5HZ1…, 01M1R9YEK0… зелёные без правки утверждений.

Зоны: orchestrator/fsm_merge_gate.py, tests/. Свободны (№14 смержена).
Не входит: изменение поведения мержа, правки fsm.py/fsm_advance.py.

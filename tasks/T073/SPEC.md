# SPEC: Retention-политика и команда prune

## Контекст

Хвосты жизненного цикла задач сегодня не убираются: ветки task/*
остаются после done (29.08 Оператор руками удалил 18 веток задач
T050–T067, к вечеру появилась новая от T069), doctor честно красит их
как orphan-инциденты, и класс воспроизводится с каждой закрытой
задачей. Политики хранения логов/алертов нет вовсе. Роадмап, P3-строка
«Retention-политика» ($25).

## Требования

1. Одностраничник `docs/retention.md` — политика хранения по видам
   данных:
   - `.artel/logs/` — 90 дней И N последних задач (prune исполняет
     оба лимита разом); N зафиксирован именованной константой конфига
     со значением 20 (ответ Оператора 29.08, tasks/T073/TZ.md);
   - ветки task/* пульта — удаление при переходе в done; merge
     остаётся без squash — история мержа в main полная;
   - alerts старше 90 дней — переносятся в архивную таблицу, не
     удаляются;
   - worktree задачи — уборка при переходе в done/killed;
   - report-страница (П2', когда появится) перегенерируется на
     месте, истории отчётов не хранится;
   - журнал БД и артефакты гейтов — вечны, retention их не касается;
   - premod-очередь (не существует до C3) — упомянута как будущая
     строка политики, без реализации.
2. Переход задачи в состояние `done` убирает её ветку task/* и
   worktree задачи — оркестратором, тем же правом, каким он уже
   убирает их при `kill` (T008/T045); след уборки — в журнале задачи.
3. Команда `prune` исполняет остальную часть политики из требования 1
   (лимиты `.artel/logs/`, архивация alerts): по умолчанию — dry-run,
   ничего не удаляет и не архивирует, только показывает план; реальное
   исполнение — только по явному флагу. В обоих режимах — отчёт: что
   будет/было удалено или заархивировано.
4. Текст уточнения инварианта 16 («история переживает задачу, не
   эпоху») — подготовлен как артефакт задачи (в SPEC/PLAN/REVIEW): чем
   именно операторская команда `prune` отличается от автоматической
   уборки при kill/done, из-за чего инвариант 16 (логи не трогает
   уборка задачи) и появление `prune` не противоречат друг другу.
   Принятие ADR с этим текстом — право Оператора, вне объёма этой
   задачи; ADR-файл в `docs/adr/` этой задачей не создаётся и не
   правится. Сами инварианты (`docs/invariants.md`,
   `tests/test_invariants.py`) и любые существующие тесты в этой
   задаче не ослабляются и не правятся.

## Критерии приёмки

AC-1. Переход задачи в состояние `done` убирает её ветку task/* и
worktree задачи.

AC-2. После перехода в `done` `doctor` не отмечает orphan-инцидент по
уже закрытой задаче (проверки ветки/worktree для неё зелёные).

AC-3. Уборка ветки и worktree при переходе в `done` оставляет запись
в журнале задачи.

AC-4. Команда `prune`, вызванная без флага реального исполнения
(dry-run по умолчанию), не удаляет и не архивирует ничего и выводит
план предстоящих действий.

AC-5. Команда `prune` с явным флагом исполнения удаляет из
`.artel/logs/` только то, что одновременно старше 90 дней И выходит
за пределы N последних задач, где N = 20 (значение читается из
именованной константы конфига).

AC-6. Команда `prune` с явным флагом исполнения переносит alerts
старше 90 дней в архивную таблицу и не удаляет их.

AC-7. И dry-run, и реальное исполнение `prune` выводят отчёт с
перечнем того, что будет удалено/заархивировано (dry-run) или было
удалено/заархивировано (исполнение).

AC-8. `docs/retention.md` существует и описывает политику для каждого
вида данных из требования 1: `.artel/logs/` (90 дней И N=20 последних
задач, со ссылкой на константу конфига), ветки task/* (удаление при
done, merge без squash), alerts (архив старше 90 дней), worktree
задачи (уборка при done/killed), report-страница (перегенерация на
месте, без истории отчётов), журнал БД и артефакты гейтов (вечны).

AC-9. `docs/retention.md` упоминает premod-очередь как будущую строку
политики, без её реализации в этой задаче.

AC-10. В артефактах задачи подготовлен текст уточнения инварианта 16
(«история переживает задачу, не эпоху») для последующего принятия
Оператором отдельным ADR; сама задача не создаёт и не правит файл в
`docs/adr/`.

AC-11. Существующие тесты, включая `tests/test_invariants.py`, после
изменений остаются зелёными; `docs/invariants.md` и тексты инвариантов
этой задачей не отредактированы.

## Не входит

- Реализация premod-очереди — она не существует до C3; в
  `docs/retention.md` только упоминание как будущей строки политики.
- Принятие ADR-уточнения инварианта 16 — решение Оператора, файл в
  `docs/adr/` эта задача не создаёт.
- Уборка чужих (не-task) веток пульта и любых данных вне видов,
  перечисленных в требовании 1.
- Любые изменения журнала БД, артефактов гейтов и истории main —
  они не трогаются никогда.
- Ослабление или правка `docs/invariants.md` и `tests/test_invariants.py`.

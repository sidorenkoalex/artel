# ТЗ: retention-политика и команда prune

## Контекст

Роадмап, P3-строка «Retention-политика» ($25). Сегодня хвосты
жизненного цикла задач не убираются: ветки task/* остаются после done
(29.08 Оператор руками удалил 18 веток задач T050–T067, к вечеру
появилась новая от T069), doctor честно красит их как orphan-инциденты,
и класс воспроизводится с каждой закрытой задачей. Политики хранения
логов/алертов нет вовсе.

## Что нужно

1. Одностраничник docs/retention.md — политика хранения по видам
   данных:
   - `.artel/logs/` — 90 дней И N последних задач (prune исполняет
     оба лимита);
   - ветки task/* пульта — удаление при done (merge остаётся без
     squash — история мержа в main полная);
   - alerts старше 90 дней — архивная таблица (не удаление);
   - worktree задачи — уборка при done/killed;
   - report-страница (П2', когда появится) перегенерируется на месте,
     истории отчётов нет;
   - журнал БД и артефакты гейтов — вечны.
2. Уборка ветки и worktree при переходе в done — оркестратором,
   тем же правом, каким он уже убирает их при kill (T008/T045);
   след в журнале.
3. Команда `prune` — исполняет остальную политику (логи, архив
   алертов); dry-run по умолчанию, реальное исполнение — явным флагом;
   отчёт, что будет/было удалено.
4. Формулировка уточнения инварианта 16 («история переживает задачу,
   не эпоху») — ПОДГОТОВИТЬ текст ADR-уточнения в артефакте задачи;
   принятие ADR — право Оператора, не этой задачи. Сами инварианты
   и их тесты в этой задаче не ослабляются и не правятся.

## Границы

- premod-очередь — не существует до C3: строку политики про premod
  не реализовывать, только упомянуть в docs/retention.md как будущую.
- Принятие ADR-уточнения инварианта 16 — за Оператором (вне объёма
  реализации; подготовленный текст — артефакт).
- Уборка чужих (не-task) веток и любых данных вне перечисленных
  видов — вне объёма.
- Журнал БД, артефакты гейтов, история main — не трогаются никогда.

## Критерии приёмки (ориентир для SPEC)

- Переход задачи в done убирает её ветку и worktree; doctor после
  этого не видит orphan по закрытой задаче; след уборки — в журнале.
- `prune` без флагов ничего не удаляет и показывает план; с флагом —
  исполняет политику логов/алертов по docs/retention.md.
- docs/retention.md существует и покрывает все виды данных из
  требования 1; текст ADR-уточнения инварианта 16 подготовлен.
- Существующие тесты (включая инварианты) зелёные и не ослаблены.

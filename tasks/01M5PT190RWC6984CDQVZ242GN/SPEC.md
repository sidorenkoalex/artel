## Требования

1. Мутации. Для каждой из 26 заявок «Ловит мутацию» файла волны готовится
   патч к коду `orchestrator/` в файле `tasks/<id>/mutation-<nnn>.diff`;
   номера идут подряд. Одинаковые по смыслу заявки — одна мутация со
   списком тестов. В PLAN у каждой мутации — её заявка (заявки) и что
   меняет патч.
2. Таблица «до» — команда `mutation-run <id> --ref base --tests
   tests/test_01m590gjaf0edv4nbc4c99mfvh_report_outcome.py` частями
   `--patches` не больше 15 патчей. Вывод `--wait` каждой части переносится
   в PLAN, раздел «Мутации до», дословно, с шапкой и всеми строками — до
   старта следующей части.
3. Доказательством не считается мутация, «убитая» только ошибкой сбора,
   импорта, setup (`ERROR at setup`) или только утверждением подготовки:
   методы подготовки песочницы из «Контекста» (`profile`, `records_of`,
   `by_id`, `table`, `accepted_major`, `cache_flag`) и `key_case` (:971).
   Такой патч переписывается так, чтобы падало утверждение теста; такие
   узлы роль отмечает в PLAN.
4. Мутация, которую не убил ни один тест, — находка в PLAN. Исход «оборвана
   по пределу» или «не прогнана (предел)» — ни убитая, ни выжившая:
   перепрогон меньшим диапазоном на той же ревизии; патч, доводящий тест до
   предела, переписывается. Занятый замок — повторить в следующем шаге, не
   эскалировать.
5. Временные файлы (сценарии, выгрузки, черновики) в рабочей копии не
   создаются вовсе — ни вне зон, ни в `tests/`. Допустимы только:
   - файл первого уровня каталога документов задачи с расширением не `.md`
     и именем не `test_*` и не `mutation-*` (он попадает в `refs/artifacts`);
   - файл в `$TMPDIR`, созданный командой `python3`.

   К концу каждого шага `git status --porcelain` рабочей копии называет
   только пути требований 6–8.
6. Песочница. Строки 54–606 исходного файла — 50 операторов верхнего
   уровня, по порядку, включая неиспользуемые песочницей импорты, —

   песочницы, в том числе с утверждениями, остаются в ней без изменений.

## Критерии приёмки

AC-1. В каталоге документов задачи первым уровнем лежат патчи
`mutation-<nnn>.diff`, номера идут подряд без пропусков. Каждый патч меняет
только файлы под `orchestrator/`. В PLAN каждая из 26 заявок «Ловит
мутацию» файла волны сопоставлена мутации; одинаковые по смыслу заявки —
одной мутации со списком тестов. У каждой мутации в PLAN названы её заявка
(заявки) и что меняет патч.

AC-2. В PLAN есть раздел «Мутации до» с выводом `mutation-run` (`--ref base`,
тесты — `tests/test_01m590gjaf0edv4nbc4c99mfvh_report_outcome.py`),
перенесённым дословно, с шапкой и всеми строками. Каждая часть `--patches`
— не больше 15 патчей, вывод каждой части перенесён. В таблице есть каждая
мутация набора.

AC-3. Ни одна мутация не засчитана доказательством, если её убили только
ошибка сбора, импорта, setup (`ERROR at setup`) или только утверждение
подготовки (`profile`, `records_of`, `by_id`, `table`, `accepted_major`,
`cache_flag`, `key_case`). Такие узлы отмечены в PLAN для таблиц «до» и
«после».

AC-4. Мутации, которые «до» не убил никто, перечислены в PLAN находками и в
доказательство не входят. Ни одна мутация с исходом «оборвана по пределу»
или «не прогнана (предел)» не засчитана ни убитой, ни выжившей.

AC-5. В рабочей копии нет временных файлов (сценариев, выгрузок,
черновиков): `git status --porcelain` рабочей копии к концу шага называет
только пути требований 6–8. В каталоге документов задачи нет
подкаталогов, кроме `acceptance_tests/`, а файлы первого уровня с
расширением не `.md`, кроме патчей `mutation-<nnn>.diff`, не называются
`test_*` и `mutation-*`.

AC-6. Файл `tests/report_outcome_sandbox.py` есть на ветке, тестов

Обоснование монолита (материал для решения Оператора на гейте SPEC).

- вынос песочницы без свода тестов оставляет две копии песочницы; свод без
  выноса ломает импорт `tests/test_component_report_gates.py` и защищённого
  `tests/test_invariants.py`;

## Пути обхода гейтов
1. **Ослабленный тест при живой мутации.** Требование 14 и AC-16
   (SPEC.md:222–237, :345–350) проверяют лишь, что мутация, убитая «до»,
   убита «после» — любым тестом. Таблица `mutation-run` называет узлы-убийцы
   (`orchestrator/mutation_run.py:387–390`), но SPEC не требует, чтобы
   тест-носитель заявки (или его сохранённый наследник) был среди
   убийц «после». Исполнитель может ослабить тест A при своде; мутацию A
   «после» убьёт соседний тест B, AC-16 зелёный, а «Ловит мутацию:» у A
   (AC-14 — только наличие строки) стала ложной. Условие (а) дедупликации
   (п.12) опирается на узлы «до», для «после» аналогичного условия нет.
   Ловится только независимой проверкой п.18 (вручную).
2. **«Дословно» без механики.** AC-12 не задаёт способа сверки для
   планки; при отсутствии нормализатора `self.assertEqual(x, 3)` →
   `assert x >= 3` проходит все механические AC. Смягчено п.18 (сравнение
   утверждений по AST при Операторе) — до approve на merge_gate.
3. **Мандат на путь целиком** снимает с гейта неослабления все находки по
   файлу волны: удаление теста без переноса гейт не остановит. В SPEC это
   закрыто только AC-15 (перечень дублей в PLAN) и п.18 — путь известен
   ТЗ, отдельно не отклонение.

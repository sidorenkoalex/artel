# ТЗ: CI быстрее — проверка на минимальной версии Python отдельным параллельным заданием; песочница FsmTest не сорит в каталог задач корня запуска

Источник: замер Оператора 03.10.2026 по прогону CI `main` (задание
«Синтаксис и тесты оркестратора» — 314 с, из них весь `tests/`
параллельно 193 с и `tests/test_invariants.py` на минимальной версии
Python в один процесс 110 с, последовательно в том же задании);
решение Оператора 03.10.2026 «ок по рекомендациям».

Факты (пин a5df6f64):
- `.github/workflows/ci.yml`, задание `python` (`needs: changes`):
  шаги по порядку — версия Python из манифеста (`scripts/stack_ci.py`),
  зависимости из `requirements.lock`, `py_compile`, снимок ссылок,
  `pytest tests -n auto -p timeout -p xdist -o timeout=120`, сверка
  ссылок после прогона, затем минимальная версия Python
  (`scripts/stack_ci.py --min`), установка зависимостей и
  `pytest tests/test_invariants.py -p timeout -o timeout=120` — без
  `-n auto`, в один процесс.
- Остальные задания CI идут 8–12 с; время прогона CI определяет задание
  `python`. Задача проходит CI ветки 1–4 раза и CI `main` после мержа.
- Локально `tests/test_invariants.py` — около 116 с в один процесс и
  около 48 с с `-n auto` (замер автора тестов 01M409YKM3, 03.10).
- `tests/test_stack_ci.py` проверяет `scripts/stack_ci.py` (в том числе
  `--min`). Файл `.github/workflows/ci.yml` защищён
  (`config.PROTECTED_PATHS`): правка — только приложением к PLAN.

Требуется:
1. Проверка `tests/test_invariants.py` на минимальной объявленной версии
   Python выносится в отдельное задание CI, которое идёт параллельно с
   заданием полного `tests/` (те же условия запуска, что у задания
   `python`, включая `needs: changes` и его условие пропуска для пушей
   без кода, если оно есть).
2. В этом задании `tests/test_invariants.py` гоняется параллельно
   (`-n auto -p xdist`) с тем же таймаутом отдельного теста; если на
   минимальной версии Python `-n auto` даёт нестабильность — SPEC
   называет это, и задание остаётся последовательным (п.1 сохраняется).
3. Покрытие и строгость не меняются: тот же набор тестов, та же
   минимальная версия из манифеста, те же зависимости из
   `requirements.lock`, та же сверка ссылок для полного прогона; ни
   один шаг не удаляется и не становится необязательным; задание
   красит прогон CI так же, как сейчас красит шаг.
4. Правка `.github/workflows/ci.yml` — приложением к PLAN, проверенным
   `git apply --check`; если какой-то тест или код пульта читает
   структуру `ci.yml` (имена заданий, шаги) — он поправлен в объёме
   переноса, с перечнем в PLAN.
5. В PLAN — оценка времени задания `python` до и после по замерам CI
   ветки задачи (имена и длительности заданий из прогона ветки).
6. Песочница `FsmTest` в `tests/test_invariants.py` подменяет
   `config.TASKS` временным каталогом (как уже подменяет `DB`, `LOGS`,
   `WORKTREES`, `PROJECTS`): сейчас `self.tdir = config.TASKS / <ULID>`
   лежит в настоящем каталоге задач корня запуска и убирается только
   `addCleanup` — прерванный прогон (таймаут шага роли, таймаут теста,
   Ctrl+C) оставляет каталог задачи песочницы в рабочей копии кода. Случай
   03.10: таймаут шага developer задачи 01M41AB597B330P2RCXCMVRZPE в
   18:13Z оставил каталог задачи 01M41FFG8P1GFYHJJXD76AS4QQ, гейт зон отказал
   переходу. Утверждения тестов не меняются. Правка — приложением к
   PLAN. Сторож в `tests/` (заявка «Ловит мутацию»): песочница
   `FsmTest` не пишет в каталог задач корня запуска.

Зоны: tests/, scripts/stack_ci.py, docs/codebase-map.md.

Приложением: .github/workflows/ci.yml, tests/test_invariants.py.

Только чтение (не менять): orchestrator/, docs/adr/, docs/roadmap.md,
docs/backlog.md, docs/operator-session.md, templates/, targets.yaml,
models.yaml, roles.yaml, CLAUDE.md, scripts/guard.py,
scripts/ci_push_class.py, requirements.lock.

Не входит: ускорение отдельных медленных тестов (отдельный разбор по
замеру `--durations`); смена раннера, кэш зависимостей; отмена CI на
`artifact/**` (часть (в) ADR-0021).

# SPEC: Бюджет задачи из SPEC по классу

## Контекст
Бюджет задачи сейчас — только дефолт (единый для всех классов задач)
с ручными поднятиями по ходу: T008/T010/T011 вставали на стоп-кране
по 1–3 раза за цикл. Аналитик при постановке видит класс задачи
(мелкий фикс / фича / тестовый слой) и может выставить бюджет сразу.
Ирония учтена: у этого SPEC бюджет уже задан во frontmatter — задача
включит его в работу.

## Требования
1. Frontmatter SPEC.md поддерживает опциональное поле `budget_usd`
   (число > 0, НЕ выше дефолта оркестратора). Оркестратор применяет его
   при переходе spec_writing → spec_gate: значение пишется в
   tasks.budget_usd, в журнал — «бюджет из SPEC: $X (дефолт $Y)».
   Значение выше дефолта НЕ применяется: warning в журнал и консоль
   («поднятие потолка — только командой budget», инвариант 10),
   остаётся дефолт. Понижение класса задачи — автоматически,
   поднятие — только Оператор командой `budget`.
2. Поле отсутствует — поведение как сейчас (дефолт), без записей.
3. Невалидное значение (не число, ≤ 0) — warning в журнал и консоль,
   остаётся дефолт; задача НЕ блокируется.
4. Повторный advance/переход не применяет бюджет повторно и не
   перетирает поднятия, сделанные командой `budget` (ручное поднятие
   всегда сильнее значения из SPEC).
5. Подсказка аналитику: в templates/SPEC.md — закомментированное поле
   с ориентирами классов (мелкий фикс ~$15 / типовая задача ~$25 /
   тестовый слой или широкий рефакторинг ~$50).
6. Юнит-тесты в tests/: применение из SPEC, отсутствие поля,
   невалидные значения, неперетирание ручного поднятия.

## Критерии приёмки
1. Задача с `budget_usd: 25` в SPEC после advance имеет бюджет $25,
   запись в журнале есть (проверимо на самой T012).
2. Невалидное значение даёт warning и дефолт (юнит-тест).
3. `budget <id> <usd>` после применения из SPEC работает как раньше,
   и повторный advance его не перетирает (юнит-тест).
4. `python3 -m unittest discover -s tests` зелёный, guard и CI зелёные.

## Не входит
- Автоматическое определение класса задачи (решает аналитик).
- Изменение дефолта, семантики потолка и алерта 70%.
- Команда auto (следующая задача).

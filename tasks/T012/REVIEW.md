## Замечания

- **blocker — orchestrator/artel.py:740 и orchestrator/artel.py:780-782 —
  значение `budget_usd` выше `DEFAULT_BUDGET_USD` применяется как есть;
  сужение по варианту (б), выбранному Оператором, в коде отсутствует.**
  - Требование 1 SPEC (`tasks/T012/SPEC.md:20-27`) после правки аналитика:
    «число > 0, **НЕ выше дефолта оркестратора** … Значение выше дефолта
    НЕ применяется: warning в журнал и консоль («поднятие потолка — только
    командой budget», инвариант 10), остаётся дефолт».
  - Фактически проверено запуском на песочнице (временная БД, `cmd_init` →
    `cmd_new` → SPEC с `budget_usd: 500` → `cmd_advance`):
    ```
    DEFAULT_BUDGET_USD = 50.0
    [T001] бюджет из SPEC: $500.00 (дефолт $50.00)
    budget_usd = 500.0 | source = spec | state = spec_gate
    журнал: бюджет из SPEC | $500.00 (дефолт $50.00)
    ```
    Ни warning, ни отката к дефолту. Потолок задачи поднят в 10 раз
    значением, которое пишет агент-аналитик, — ровно то, что инвариант 10
    (`docs/invariants.md:37`) и `gates.yaml budget_increase: manual`
    запрещают и что Оператор закрыл вариантом (б).
  - Полнота класса — все места, которые чинятся вместе:
    - `orchestrator/artel.py:740` — единственная валидация значения
      (`value is None or value <= 0`), верхней границы нет. Порогу место
      здесь либо отдельной веткой в `apply_spec_budget` перед записью;
      причина отказа должна отличаться от `'X' — не сумма в долларах`,
      иначе Оператор не поймёт, что число корректно, но выше потолка.
    - `orchestrator/artel.py:780-782` — сама запись в `tasks.budget_usd`;
      до неё должна стоять проверка порога.
    - `orchestrator/artel.py:22-25` — модульный docstring описывает
      механизм без ограничения («`budget_usd` в frontmatter SPEC
      применяется к задаче один раз»); после сужения он вводит в
      заблуждение.
    - `templates/SPEC.md:6-9` — подсказка аналитику ориентирами 15/25/50
      порог не называет. При `DEFAULT_BUDGET_USD = 50.0` верхний ориентир
      ровно на границе, и стоит сказать словами, что выше дефолта нельзя,
      — иначе аналитик узнает о правиле только из warning.
    - `tasks/T012/PLAN.md` «Риски», третий пункт — вынесен отдельным
      замечанием ниже.
  - Граница: SPEC говорит «НЕ выше», то есть `value == DEFAULT_BUDGET_USD`
    применяться должно (сравнение `>`, не `>=`). Сравнивать нужно именно с

    (`artel.py:760`): в `.artel/state.db` живы задачи с потолком $5–$10 от
    прежних дефолтов, и сравнение с `old` отвергло бы у них разрешённое

  - Ослаблений тестов, гейтов, лимитов и guard-проверок в diff по-прежнему

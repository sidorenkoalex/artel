## Пути обхода гейтов
- **О-1 (Ф-1).** Тест AC-3 на учебной задаче без зон (или с зонами,
  покрывающими `backend/tests`) зелёный, а живая задача sled с зонами,
  скажем, `backend/src/` теряет файл роли на зонном фильтре — критерий
  выполнен буквально, цель ТЗ («чекпоинт коммитит файл, написанный по
  профилю») — нет.
- **О-2 (Ф-2).** Разработчик реализует «профиль, а при его отсутствии —
  умолчания артели»: AC-1..AC-4 на учебном проекте с профилем зелёные,
  а внешний проект без `test_profile` (`Decision.skip`) получает сегодняшнее
  поведение, проект с нерешённым контекстом — коммит по `tests/` в обход
  отказа, который держит гейт (fail-closed, ADR-0002).
- **О-3 (П-1).** Подстановка профиля только в `checkpoint.py:376` и
  `runner.py:1338-1345` проходит планку, оставляя `:384`, `:412`, `:497`,
  `runner.py:1319` на умолчаниях — требования 2-3 выполнены частично.
- **О-4.** Зона `orchestrator/runner.py` — файл целиком; ограничение
  ANSWER-1 «остальной runner.py не меняется» гейт зон не держит, только
  ревью.

## Вердикт
concerns — SPEC вести можно, решения за Оператором на гейте SPEC:

1. **Ф-1** (`orchestrator/checkpoint.py:424-425,1550,1731`,
   `orchestrator/config.py:803`): зонный фильтр коммита пульта не назван.
   Нужно решение: (а) требование — зоны задачи внешнего проекта покрывают
   `long_lived_dir`, а AC-3 задаёт учебной задаче такие зоны и проверяет
   отказ с внятной записью журнала при непокрытом каталоге; либо (б)
   требование — для test_author чекпоинт считает `long_lived_dir` профиля
   своей зоной (как `tests/` артели в `COMMON_ZONES`), с критерием на
   задаче с зонами вне `backend/tests`.
2. **Ф-2** (`orchestrator/project_profile.py:140-159`,
   `orchestrator/fsm_advance.py:516-530`): не задано поведение задания,
   чекпоинта и проверки артефакта при `Decision.refusal`/`Decision.skip`.
   Дефолт, согласованный с гейтом: при `refusal` — не коммитить вслепую
   (как при молчании git, `checkpoint.py:408-415`), при `skip` — умолчания
   артели не подставлять для внешнего проекта.
3. **П-1** (SPEC, «Критерии приёмки»): части требований 2-3 без критерия —
   сверка с базой (`checkpoint.py:384`), право удаления (`:497`), текст
   журнала (`:412`) и текст отказа (`runner.py:1319`) у внешнего проекта.
   Предложение: расширить AC-3 (удаление своего закоммиченного файла в
   `backend/tests` доезжает до ветки) и AC-4 (текст отказа называет
   `backend/tests/test_<id>_`).
4. **О-4** — замечание без действия: сужение зоны `runner.py` до двух
   функций держит только ревью.

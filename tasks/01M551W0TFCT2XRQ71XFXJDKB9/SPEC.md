## Требования

1. Задание роли test_author (пункты 2а и 5) и developer (пункт 3)
   (`orchestrator/role_prompt.py`) называет каталог долгоживущих тестов и
   префикс имени долгоживущего файла задачи по профилю проекта задачи
   (`long_lived_dir`, `long_lived_name`) — тем же источником профиля, что
   гейт выхода из `tests_writing` (`project_profile.for_task`).
2. Чекпоинт шага test_author (`orchestrator/checkpoint.py`): отбор
   кандидатов в свои файлы, сверка с деревом базы ветки, право удаления
   своих файлов (`_role_may_delete`) и текст записи журнала о неотобранных
   своих файлах используют каталог и шаблон того же профиля проекта
   задачи.
3. Зонный фильтр коммита пульта на чекпоинте test_author считает зоной
   роли только её собственные долгоживущие файлы — по каталогу и шаблону
   профиля проекта задачи (`long_lived_dir` + префикс задачи), так же, как
   `tests/` артели покрыт `config.COMMON_ZONES`. `config.COMMON_ZONES` не
   меняется; чужой путь в каталоге долгоживущих тестов проекта (без
   префикса задачи) по-прежнему откатывается (решение Оператора 17.10,
   Ф-1 вариант (б)). Это требование — страховка коммита чекпоинта, не
   признание таких путей гейтом зон: гейт зон в этой задаче не меняется
   (решение Оператора 17.10, Ф-3 вариант (а)). Правило зон: задача
   внешнего проекта, где test_author пишет долгоживущие файлы, включает
   каталог `long_lived_dir` профиля проекта в свои `zones:` — иначе
   закоммиченный чекпоинтом файл роли отклонит гейт зон на выходе из
   `in_dev` (`orchestrator/advance_gates/zones.py:274-276` — у внешнего
   проекта `COMMON_ZONES` не применяются).
4. Проверка обязательного артефакта шага test_author
   (`orchestrator/runner.py`, `_missing_required_artifact` и
   `_has_own_long_lived_test`) и текст её отказа берут каталог и шаблон
   долгоживущего файла из того же профиля проекта задачи. Остальной
   `orchestrator/runner.py` не меняется (ANSWER-1).
5. Решение профиля без профиля (`project_profile.Decision`, решение
   Оператора 17.10, Ф-2):
   - `Decision.refusal` — чекпоинт test_author не коммитит свои файлы, а
     проверка обязательного артефакта не засчитывает долгоживущий файл
     вслепую; каждое место пишет запись журнала с причиной (как при
     молчании git, `checkpoint.py:408-415`); задание роли каталог
     долгоживущих тестов не называет;
   - `Decision.skip` (внешний проект без `test_profile`) — умолчания
     артели (`tests/`, `test_<id>_<name>.py`) не подставляются: абзаца о
     долгоживущих файлах в задании роли нет, отбор своих файлов чекпоинтом
     пуст, проверка обязательного артефакта долгоживущий файл не
     засчитывает.
6. Для артели (профиль без отличий от значений по умолчанию) текст
   задания test_author и developer, отбор и коммит долгоживущих файлов
   чекпоинтом и текст отказа проверки артефакта test_author не меняются ни
   на байт; это зафиксировано тестами до правки.
7. Тесты детерминированы, без сети, на учебном внешнем проекте с
   `long_lived_dir: backend/tests` (вне корня).
8. Правка защищённого `skills/test-authoring.md` — готовым текстом в
   разделе «Материалы» этого SPEC; вносит её Оператор командой
   `doc-commit` после мержа.

## Критерии приёмки

AC-1. У артели задание test_author и задание developer прежние байт в байт
(префикс `tests/test_<id>_`, каталог `tests/`), а чекпоинт test_author
по-прежнему коммитит новый файл роли `tests/test_<id>_<имя>.py` и
откатывает правку вне мандата, как до задачи.

AC-2. У учебного внешнего проекта с `long_lived_dir: backend/tests`
задание test_author называет `backend/tests/test_<id>_` (и каталог
`backend/tests/`), задание developer — тот же префикс.

AC-3. У учебного внешнего проекта с `long_lived_dir: backend/tests`
чекпоинт test_author коммитит в кодовую ветку новый файл роли
`backend/tests/test_<id>_<имя>.py`, а файл `tests/test_<id>_<имя>.py` в
корне (не по профилю) откатывает. Правка файла базы ветки с префиксом
задачи в `backend/tests/` новым файлом роли не считается и откатывается;
удаление своего закоммиченного файла `backend/tests/test_<id>_<имя>.py`
в `tests_writing` доезжает до кодовой ветки; запись журнала о
неотобранных своих файлах называет каталог `backend/tests/`, а не
`tests/`.

AC-4. У учебной задачи внешнего проекта с `long_lived_dir: backend/tests`
и зонами вне этого каталога (например, `backend/src/`) чекпоинт
test_author коммитит в кодовую ветку файл роли
`backend/tests/test_<id>_<имя>.py`, а чужой путь в `backend/tests/` (без
префикса задачи) откатывает; `config.COMMON_ZONES` не изменён.

AC-5. У учебного внешнего проекта с `long_lived_dir: backend/tests` шаг
test_author с планкой только из долгоживущего файла
`backend/tests/test_<id>_<имя>.py` (без файлов в `acceptance_tests/`) не
получает отказа «нет обязательного артефакта», а текст этого отказа (без
планки) называет `backend/tests/test_<id>_`; у артели поведение и текст
этого отказа прежние.

AC-6. При `Decision.refusal` по проекту задачи чекпоинт test_author не
коммитит долгоживущий файл роли, проверка обязательного артефакта не
засчитывает его, и каждое место пишет запись журнала с причиной;
задание роли каталог долгоживущих тестов не называет.

AC-7. У учебного внешнего проекта без `test_profile` (`Decision.skip`)
задание test_author и developer не содержит абзаца о долгоживущих
файлах (ни `tests/`, ни `tests/test_<id>_`), чекпоинт test_author не
отбирает своими файл `tests/test_<id>_<имя>.py` — отбор пуст, а проверка
обязательного артефакта шага test_author не засчитывает файл
`tests/test_<id>_<имя>.py` (шаг с планкой только из такого файла, без
файлов в `acceptance_tests/`, получает отказ «нет обязательного
артефакта»).

AC-8. SPEC содержит готовый текст правки раздела о долгоживущих файлах
`skills/test-authoring.md`: вместо буквального `tests/` — каталог
долгоживущих тестов проекта, названный в задании роли; правила для артели
по смыслу не меняются.

## Оценка объёма и деление

Сработавшие сигналы (по отказу guard): число затрагиваемых модулей/файлов
зоны (`tests/` — каталог), зона задевает механизм, на который опирается
запись `docs/invariants.md` (чекпоинт шага), прогноз диффа не был дан.

Прогноз диффа: 35 КиБ (три модуля по 5-30 строк правки — подстановка
профиля вместо умолчаний, своя зона test_author в зонном фильтре, ветки
refusal/skip — плюс тесты на учебном проекте в `tests/`).

Обоснование монолита: правка — одна подстановка одного источника
(профиль проекта задачи) в три места одного пути шага test_author:
задание называет каталог, чекпоинт коммитит файл из него, проверка
артефакта шага его видит. Нарезка по модулям оставляет внешний проект в
промежуточном нерабочем состоянии: задание без чекпоинта велит писать в
`backend/tests/`, а чекпоинт такой файл откатывает (хуже сегодняшнего —
роль теряет работу по прямому указанию); чекпоинт без проверки артефакта
коммитит файл, но шаг кончается отказом «нет артефакта». У артели каждая
часть ничего не меняет, поэтому выигрыша от деления нет. Объём мал
(8 критериев, потолок $25 по решению Оператора, ANSWER-1).

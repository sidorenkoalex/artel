## Пути обхода гейтов
- **П-1 (Ф-1).** По букве тр. 8 разработчик может выбрать хостинг строкой
  `entry["forge"] == "github"` или `forge.hosting(name) == "github"` в
  `doctor/project_checks.py`. AC-6 проходит, сторож `test_ac21` файл не
  читает. Обходится смысл ADR-0029 п. 8 (хостинг — только реестром).
  Замена: в AC-6 вариант «подменённый реестр, где реализация под другим
  ключом читает отчёт, — строка есть; запись `github` с реализацией без
  `job_test_report` — строки нет». Расширять сторож — путь хуже: файл
  сторожа в мандатах SPEC не значится.
- **П-2.** Предел `CI_REPORT_ARCHIVE_MAX_BYTES` по букве тр. 5 («по
  фактически полученным байтам») выполняется и так: `subprocess.run(…,
  capture_output=True)` читает весь вывод `gh` в память, а длина
  сравнивается с пределом потом. AC-3 («фактические байты больше предела»)
  такую реализацию пропускает. Скачивание при этом ничем не ограничено,
  кроме предела времени, — а именно это и требует ТЗ тр. 3. Замена: в AC-3
  подменная `gh` выдаёт поток заметно больше предела без конца (или до
  предела времени), и причина должна называть размер, а не время.
- **П-3 (следствие решения №1.2 и ТЗ тр. 1).** Пусть у коммита есть только
  check run, пропущенный условием. Так бывает в окне между `push` (набор
  пропущен, ADR-0016) и появлением прогона `pull_request`. Тогда:
  `pipeline_status` — зелёный (`ci.py:27`, `skipped` ∈ `GREEN`);
  `job_result` — `skipped`; `_ci_report` даёт сразу непроходящую
  негодность (`outcome_integrity.py:1091-1093`: `skipped` нет в
  `_CI_PENDING_STATUSES`), то есть эскалацию вместо ожидания, а приёмка —
  «неизвестно». Правило «пропущенный не считается, если есть исполненный»
  перенесено из ТЗ верно, но случая «исполненного ещё нет» SPEC не задаёт.
  Это не обход, а риск ложной эскалации после этапа 4б. Решает Оператор:
  оставить, как есть, или считать одиночный `skipped` ожидающим.

## Вердикт
`concerns` — SPEC можно вести дальше; три пункта решает Оператор на гейте:

   случай «поток больше предела без конца → причина о размере».
3. **П-3** — одиночный check run `skipped` (окно push → pull_request,
   `ci.py:27`, `outcome_integrity.py:1091-1093`) даёт эскалацию вместо
   ожидания. Поведение SPEC не задано. Решение Оператора: оставить или
   отнести к ожидающим.

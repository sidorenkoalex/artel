# ТЗ: механика зон — машиночитаемые зоны задачи, проверка занятости на старте кода, сверка диффа с зонами

Источник: решение Оператора 04.09 (волна из десяти задач с
пересечениями по checkpoint.py/doctor.py/gitcmd.py/ci.yml держалась
паузами и очередью мержей вручную; копилка роадмапа §4 «механики зон
в конвейере нет»). Сегодня зоны — текст в ТЗ/SPEC; ревьювер сверяет
дифф с ними глазами; конвейер не знает, какие зоны заняты другими
живыми задачами.

Требуется:
1. Машиночитаемые зоны: поле `zones:` во frontmatter SPEC — список
   путей и масок (файлы/каталоги); guard требует поле (новая версия
   схемы SPEC); analyst заполняет из ТЗ; при approve на гейте SPEC
   зоны сохраняются в БД задачи. Поле согласуется с задачей «Оценка
   объёма и деление» (01M1KS8K9RXWHX2PW3ZKB0P903), которая уже
   структурирует зоны для сигналов деления, — одно поле на обе
   механики.
2. Общие зоны вне конфликта — именованный список в config: пути,
   которые трогают все задачи и конфликты у которых текстовые
   (`orchestrator/config.py`, `docs/codebase-map.md`, `tests/`,
   `roles.yaml`); пересечение по ним не считается.
3. Проверка занятости на старте кода: перед первым шагом developer
   (`in_dev`) зоны задачи сверяются с зонами всех задач в кодовой
   фазе (in_dev … merge_gate). Пересечение — именованный отказ
   «зона <путь> занята задачей <id> (<состояние>)»; `auto`
   останавливается с причиной «ждёт зоны» без алерта буксования,
   `status`/`doctor` показывают ожидание; когда занявшая задача
   смержена или убита, следующий `auto`/`run` проходит. Оператор
   может снять ожидание явной командой с записью в журнал
   (осознанный риск).
4. Сверка по факту: переход in_dev → review отклоняется, если дифф
   ветки к main трогает файлы вне заявленных зон и вне общего списка,
   кроме случая, когда PLAN содержит раздел расширения зон с
   основанием (ANSWER Оператора с мандатом, как сегодня) — тогда
   расширение записывается в БД и переход проходит; отказ называет
   файлы.
5. Порядок: очередь на занятую зону — по времени approve SPEC;
   Оператор может переставить командой. Ревьювер по-прежнему
   сверяет содержательно (чек-лист), механика — формальная.
6. Тесты: guard требует поле; отказ старта developer при пересечении
   и проход после мержа занявшей; общие зоны не конфликтуют; отказ
   перехода в review при файлах вне зон и проход при расширении с
   основанием; существующие тесты зелёные без ослабления.

Зоны: templates/SPEC.md, scripts/guard.py, orchestrator/store.py
(схема), orchestrator/catalog.py или fsm.py (сохранение при approve),
orchestrator/fsm_advance.py (старт in_dev, переход в review),
orchestrator/auto.py, orchestrator/doctor.py, skills/spec-authoring.md,
tests/. Старт — после мержа задачи «Оценка объёма и деление» (общие
зоны: templates/SPEC.md, guard.py, skills/spec-authoring.md); до
мержа — только SPEC.

Не входит: автоматическое переупорядочивание задач; зоны для внешних
target (после B2); механика родительских задач.

# PLAN: approve --note на гейте SPEC — указание Оператора для test_author и ревьювера

## Подход
Один писатель и один читатель записи журнала.

- `orchestrator/artel.py`: `--note <файл>` разбирает `_approve_note_kwargs`
  (нет значения или значение `--…` — `sys.exit` с «approve отклонён» до
  lease); позиции флага и значения входят в `_approve_reason_indices`, так
  что `_approve_sha_arg` и флаги без значения их не видят. Без флага —
  прежний вызов `fsm.cmd_approve` без нового аргумента (приём
  `_approve_as_epic_kwargs`). Справка `approve` называет `--note <файл>`.
- `orchestrator/fsm.py`: `cmd_approve(…, note=None)` до lease зовёт
  `_spec_gate_note_text` — состояние `spec_gate`, размер файла в байтах
  (`len(read_bytes()) > config.CONTEXT_FILE_MAX_BYTES` — отказ), чтение
  (`OSError`/`UnicodeDecodeError`), пустота после `strip()`, строки четырёх
  маркеров `mandate.MANDATE_MARKERS` (подсказка по виду маркера), заголовок
  файла решения, путь `approve` (деление, `skip_tests`, без AC-разметки —
  `_spec_gate_note_path_refusal`, чтением SPEC как `_as_epic_goal`/
  обработчик: ветка-источник при `foreign`, иначе frontmatter с диска).
  Все отказы — `sys.exit` без записей. Под lease `_cmd_approve` повторяет
  проверку состояния и пути (тот же текст отказа), текст указания доезжает
  до `_approve_spec_gate` через `partial`; запись
  `SPEC_GATE_NOTE_ACTION` от `operator` — сразу после успешного
  `store.set_state(… "tests_writing" …)`. Без флага `partial` и вызовы —
  прежние.
- `orchestrator/brief.py`: `spec_gate_note(conn, task_id)` — последняя
  запись действия указания от `operator` с id больше последней
  `state -> spec_gate`; `_spec_gate_note_component` — раздел «Указание
  Оператора на гейте SPEC» с `SPEC_GATE_NOTE_PREAMBLE` перед границей,
  журнал через `_journal_component`; в `test_author_answer_component` —
  после причины возврата и ANSWER, до конвенций.
- `orchestrator/review.py`: та же функция, часть сразу после цикла
  ANSWER-n, своя `SPEC_GATE_NOTE_PREAMBLE`, запись «бриф: компонент» от
  `reviewer`; ключи словаря прежние.
- `docs/operator-gates.md` — описание флага; карта регенерирована.
- `orchestrator/role_prompt.py` не меняется: он уже зовёт
  `brief.test_author_answer_component` (`role_prompt.py:116`), раздел
  приходит через неё.

## Шаги
1. artel.py: разбор `--note`, исключение из sha, справка.
2. fsm.py: константа, проверки до lease и под lease, запись после перехода.
3. brief.py/review.py: `spec_gate_note`, раздел брифа, часть пакета.
4. Документация, карта, прогон долгоживущего файла задачи, планки и
   тестов соседних модулей; свой сторож формы вызова без флага —
   `tests/test_approve_note_call_shape.py` (обе заявленные мутации
   проверены временной правкой — тесты красные).

Итог прогонов: долгоживущий файл задачи — 25 passed; планка

пакет ревьювера, справка, `reject --decision`, гейт SPEC, карта) —
зелёные.

## Влияние на систему
Новый параметр `cmd_approve` только именованный, по умолчанию `None`; без
флага диспетчер его не передаёт, `_cmd_approve` и `_approve_spec_gate`
зовутся с прежними аргументами — закрепляющие тесты диспетчера и lease не
меняются. Действие записи новое и не начинается с `state -> `: выборки
переходов (`_previous_state_name`, гейты мандатов) запись не видят;
ANSWER, мандаты и `_spec_gate_reasons` её не читают. Гейты, лимиты, guard
не трогаются. Откат — revert merge-коммита.

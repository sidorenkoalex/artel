# ТЗ: Пересечение зон при заведении и аддитивные конфликты документов при подтяжке main

Источник: строка копилки 26.09 «Волна из трёх задач заведена с общей
зоной docs/operator-session.md … параллельность потеряна» и кандидат
бэклога «аддитивные конфликты» (docs/backlog.md); решение Оператора
27.09 — одной задачей. Прецедент 26–27.09: три задачи волны (01M3FQ2V,
01M3FQ3J, 01M3FQ2Z) правили один раздел docs/operator-session.md; замок
зон выстроил их в очередь (две задачи с готовыми планками ждали зону
около часа), а затем подтяжка main в третью дала конфликт по
docs/operator-session.md и docs/codebase-map.md и эскалацию с платным
шагом разработчика на разрешение. Задача вне линии провайдеров.

Факты (origin/main c88e23f0 и позже):
- `new --tz` (orchestrator/catalog.py::cmd_new) классифицирует пути ТЗ
  (зоны / не входит / только чтение / приложением) и отказывает по
  неклассифицированному пути; пересечение зон новой задачи с зонами
  задач в полёте при `new` не проверяется. Замок зон
  (orchestrator/zone_lock.py: `blocking_conflict`, `_paths_overlap`,
  `_shared_zone`, `_own_paths`, `_is_common_zone`; занимающие состояния
  `BLOCKING_STATES` = in_dev … merge_gate) срабатывает только на входе в
  in_dev — то есть после SPEC и планки, когда потрачено $10–25.
- Подтяжка main (orchestrator/pull.py::evaluate → `_run_merge` →
  `_handle_merge_failure`): единственное автоматическое разрешение —
  карта кодовой базы, и только когда `_conflicting_files(wt) ==
  [MAP_REL]` (`_auto_resolve_map_conflict`, :272); любой другой набор
  конфликтных файлов — эскалация с меткой
  `PULL_CONFLICT_ROLE_STEP_MARKER` (в in_dev/acceptance/merge_gate),
  возврат `approve` → шаг разработчика. Конфликт 27.09: обе стороны
  ДОБАВЛЯЛИ соседние пункты в один список контракта сессии; ни одна
  строку не меняла и не удаляла. `.gitattributes` в репозитории нет.
- `_doc_only_main_advance` (pull.py:379) уже различает «main ушёл
  вперёд только документами».

Требуется:
1. Предупреждение о пересечении зон при `new`: после классификации путей
   команда сверяет `Зоны:` ТЗ с зонами (`zones` + `zones_extension`)
   задач в занимающих состояниях и в spec_writing … tests_writing (те,
   что займут зону позже), тем же способом, что `zone_lock._paths_overlap`
   (общие зоны `config.COMMON_ZONES` не считаются); при пересечении
   печатает предупреждение с id задач, состоянием и общим путём и пишет
   его в журнал новой задачи. Отказом это НЕ становится (волна может
   сознательно идти последовательно); флаг строгого режима в этой
   задаче не заводится (orchestrator/artel.py — зона задачи 01M3FQ3J в
   полёте). Способ и порядок сверки — в SPEC.
2. Та же сверка в `status`: строка задачи в spec_writing …
   tests_writing, чья зона занята задачей в BLOCKING_STATES, получает
   пометку «зона занята: <id>» — Оператор видит будущую очередь до того,
   как она случится.
3. Аддитивный конфликт документов при подтяжке main: если все
   конфликтные файлы — документы (`docs/**`, `*.md`) и для каждого
   конфликт аддитивный (в конфликтных блоках обе стороны только
   добавляют строки относительно базы слияния, ни одна не меняет и не
   удаляет базовые строки), пульт сливает сам: обе добавки сохраняются
   в порядке «main, затем ветка» (обосновать порядок в SPEC), карта
   кодовой базы — как сегодня, перегенерацией; итог коммитится тем же
   коммитом подтяжки с записью журнала «аддитивный конфликт слит:
   <файлы>». Конфликт с изменением или удалением базовых строк, или в
   не-документе — прежняя эскалация с меткой. Способ определения
   аддитивности (разбор блоков `<<<<<<<`/`=======`/`>>>>>>>` против
   `git merge-file`/базы слияния, либо повторный merge с `-X` стратегией
   только для документов) — выбрать и обосновать в SPEC; свойство
   «ни одна строка базы не потеряна» обязательно и проверяется тестом.
4. Карта кодовой базы в наборе конфликтных файлов вместе с документами
   не блокирует автоматику: карта перегенерируется, документы сливаются
   по требованию 3; сегодняшнее условие `files == [MAP_REL]` расширяется.
5. Документация: docs/stack.md (раздел о подтяжке main и о `new`) —
   предупреждение о пересечении зон, что сливается само, что
   эскалирует. docs/operator-session.md, docs/operator-gates.md и
   orchestrator/artel.py НЕ правятся этой задачей (см. «Только
   чтение»).
6. Тесты (tests/): предупреждение `new` при пересечении с задачей в
   in_dev и в tests_writing, молчание без пересечения и по общим зонам;
   пометка в `status`; аддитивный конфликт
   двух документов сливается с сохранением всех строк обеих сторон и
   базы (реальный git в песочнице `tests/sandbox.py::RealGitSandbox`);
   конфликт с изменённой базовой строкой — эскалация как прежде;
   конфликт в `.py` — эскалация; карта плюс документ — слито;
   существующие tests/test_pull.py, tests/test_fsm_map_conflict_autoresolve.py,
   tests/test_fsm_merge_conflict_note.py, tests/test_zone_lock.py,
   tests/test_zones_gate.py, tests/test_catalog_new_race.py,
   tests/test_catalog_tz_path_check.py зелёные, ни один не ослаблен.

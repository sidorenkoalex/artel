# SPEC: объявленный стек пульта, часть 2 — CI на объявленной версии Python

## Контекст
Часть 1 («манифест стека», отдельная задача) вводит `orchestrator/
stack.py` — единственный источник объявленной версии Python пульта.
Сегодня CI (`.github/workflows/ci.yml`) запускает джобы `python3` без
`actions/setup-python`: фактическая версия определяется образом
`ubuntu-latest`, меняется вместе с ним и не совпадает ни с локальной
версией разработки (3.13), ни с версией, объявленной в манифесте.
Зелёный CI сегодня ничего не говорит о том, какая версия Python
реально поддерживается — задача делает CI явным потребителем манифеста
части 1.

Эта задача — часть 2 разбора 05.09 (копилка роадмапа §4 п.8),
продолжение части 1. Зависимость по коду прямая: код этой задачи
импортирует `orchestrator/stack.py`, которого в этой ветке ещё нет —
он появится после мержа части 1. Планка (SPEC, приёмочные тесты)
пишется сразу; сам код (`scripts/stack_ci.py`, правка `ci.yml`) —
только после мержа части 1 в main.

## Требования

1. Все джобы CI, исполняющие Python (`guard`, `python`,
   `codebase-map`, прочие с `python3`), используют `actions/
   setup-python` с версией, прочитанной из манифеста части 1: значение
   читается из `orchestrator/stack.py` первым шагом джоба (`python3 -c
   "from orchestrator import stack; print(stack.python_version_string())"`)
   и передаётся дальше через output шага либо переменную окружения;
   литерал версии Python внутри `ci.yml` не дублируется.
2. Джоб `python` дополнительно запускает `python3 -m unittest
   tests.test_invariants` в матрице из двух версий — минимальной
   объявленной в манифесте части 1 и текущей стабильной, — обе версии
   тоже читаются из манифеста (не литералом в `ci.yml`), чтобы падение
   на нижней границе поддержки было видно в CI.
3. Правка `.github/workflows/ci.yml` — защищённый путь: она
   оформляется unified-диф-приложением в `PLAN.md`, применимость
   которого разработчик подтверждает прогоном `git apply --check` на
   чистом `main` (skills/conventions-core.md); применяет сам диф
   Оператор. Всё, что можно вынести из `ci.yml` в скрипт репозитория
   (чтение версии манифеста, формирование значения для `setup-python`),
   выносится в новый `scripts/stack_ci.py`, чтобы диф-приложение к
   `ci.yml` оставалось минимальным.
4. `scripts/stack_ci.py` печатает версию Python в формате, который
   принимает `actions/setup-python` (значение `python-version`).
   `tests/test_stack_ci.py` сравнивает вывод `scripts/stack_ci.py` с
   манифестом `orchestrator/stack.py` и падает при расхождении.
   Существующий набор тестов (`tests/`) остаётся зелёным.

## Критерии приёмки

AC-1. Все джобы `.github/workflows/ci.yml`, исполняющие `python3`
(`guard`, `python`, `codebase-map` и любые прочие такие джобы), перед
использованием Python выполняют шаг `actions/setup-python`, версия для
которого получена из `orchestrator/stack.py` (вызовом `python3 -c
"from orchestrator import stack; print(stack.python_version_string())"`
на первом шаге джоба) и передана через output шага либо переменную
окружения — не литералом версии в `ci.yml`.

AC-2. Джоб `python` содержит дополнительный шаг/матрицу, запускающую
`python3 -m unittest tests.test_invariants` на двух версиях Python:
минимальной объявленной в манифесте части 1 и текущей стабильной,
обеих полученных из манифеста (не литералом в `ci.yml`).

AC-3. `scripts/stack_ci.py` существует, выполняется без ошибок и
печатает версию Python в формате, принимаемом `actions/setup-python`
в качестве `python-version`.

AC-4. `tests/test_stack_ci.py` содержит тест, сравнивающий вывод
`scripts/stack_ci.py` с версией из `orchestrator/stack.py`, и падает
при их расхождении.

AC-5. `PLAN.md` задачи несёт unified-диф правки `.github/workflows/
ci.yml`, реализующей требования 1–3, как приложение; в `PLAN.md`
зафиксировано, что `git apply --check` этого дифа на чистом `main`
проходит без ошибок.

AC-6. Диф-приложение к `ci.yml` не содержит логики чтения манифеста
или формирования вывода для `setup-python` сверх минимально
необходимого вызова `scripts/stack_ci.py` — вся такая логика вынесена
в `scripts/stack_ci.py`.

AC-7. Полный прогон `python3 -m unittest discover -s tests` зелёный.

## Не входит

- Смена раннера CI (`ubuntu-latest` остаётся).
- Кеширование зависимостей/окружения Python в CI.
- Публикация артефактов CI.
- Сама правка `orchestrator/stack.py` и решения части 1 (манифест
  стека) — эта задача только читает готовый манифест.
- Применение дифа к `.github/workflows/ci.yml` в реальном коммите —
  это делает Оператор по диф-приложению из `PLAN.md` (защищённый путь).

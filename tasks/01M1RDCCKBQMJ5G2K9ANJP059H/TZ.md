# ТЗ: объявленный стек пульта, часть 2 — CI на объявленной версии Python

Источник: разбор 05.09 (копилка роадмапа §4 п.8), продолжение части 1
«манифест стека». CI (`.github/workflows/ci.yml`) сегодня запускает
`python3` раннера без `setup-python`: версия меняется с образом
`ubuntu-latest` и не совпадает ни с локальной (3.13), ни с объявленной
в манифесте. Зелёный CI при этом ничего не говорит о поддерживаемой
версии.

Требуется:
1. Все джобы CI, исполняющие Python (`guard`, `python`, `codebase-map`,
   прочие с `python3`), используют `actions/setup-python` с версией из
   манифеста части 1: значение читается из `orchestrator/stack.py`
   первым шагом джоба (`python3 -c "from orchestrator import stack;
   print(stack.python_version_string())"`) и передаётся через output
   шага либо переменную окружения; литерал версии в ci.yml не
   дублируется.
2. Джоб `python` дополнительно запускает `python3 -m unittest
   tests.test_invariants` на МИНИМАЛЬНОЙ объявленной версии и на
   текущей стабильной (матрица из двух значений), чтобы падение на
   нижней границе было видно.
3. `.github/workflows/ci.yml` — защищённый путь: правка оформляется
   диф-приложением в PLAN.md с `git apply --check` на чистом main;
   применяет Оператор. Всё, что можно вынести из ci.yml в скрипт
   репозитория (чтение версии, вывод стека), выносится в
   `scripts/stack_ci.py`, чтобы приложение было минимальным.
4. Тесты: `scripts/stack_ci.py` печатает версию в формате, который
   принимает `setup-python`; манифест и скрипт согласованы (тест
   сравнивает); существующий набор зелёный.

Зоны: scripts/stack_ci.py (новый), tests/test_stack_ci.py, PLAN.md
(диф ci.yml как приложение). Зависит от части 1 (импорт
`orchestrator/stack.py`): планка и SPEC пишутся сразу, код — после её
мержа. Не входит: смена раннера, кеширование, публикация артефактов CI.

Рамка: $10.

# SPEC: Автогейт приёмки видит долгоживущие файлы планки

## Контекст

Автогейт приёмки собирает разовые файлы планки только из
`tasks/<id>/acceptance_tests/*.py` артефактной ветки. Поэтому задача с
полностью долгоживущей зелёной планкой получает отказ «каталог приёмочных
тестов пуст или отсутствует» и ждёт Оператора. Тот же неполный набор
используется в перечне пометок записи «приёмка: что проверит approve».

## Требования

1. Каталог планки для автогейта приёмки и для перечня пометок записи
   «приёмка: что проверит approve» состоит из разовых файлов
   `tasks/<id>/acceptance_tests/*.py` артефактной ветки и файлов из
   перечня долгоживущих, прочитанных с кодовой ветки задачи тем же
   источником, что и прогон планки на переходе `in_dev`. Пометки
   `manual`, `skip`, `ci` и `escalate` ищутся во всех этих файлах.
2. Отказ «каталог пуст» возникает только при отсутствии и разовых
   файлов, и записей перечня долгоживущих. Если запись перечня есть, но
   названный ею файл не читается с ветки задачи, автогейт отказывает
   именованным сообщением с путём файла, а не сообщением о пустом
   каталоге и не молчаливым пропуском.
3. Для задачи без перечня долгоживущих файлов поведение автогейта не
   меняется; существующие тесты автогейта остаются зелёными без правок.
4. Тесты в `tests/` покрывают полностью долгоживущую зелёную планку,
   пометку `manual` в долгоживущем файле, нечитаемый файл из перечня и
   перечисление пометок долгоживущих файлов в записи «приёмка: что
   проверит approve».

## Критерии приёмки

AC-1. Для автогейта приёмки и для записи «приёмка: что проверит approve»
набор файлов планки включает разовые файлы
`tasks/<id>/acceptance_tests/*.py` артефактной ветки и файлы из перечня
долгоживущих, прочитанные с кодовой ветки задачи тем же источником, что
прогон планки на переходе `in_dev`; пометки `manual`, `skip`, `ci` и
`escalate` ищутся во всём объединённом наборе.

AC-2. Отказ «каталог пуст» возникает только когда отсутствуют и разовые
файлы, и записи перечня долгоживущих. Если запись перечня есть, но её файл
не читается с кодовой ветки задачи, автогейт отказывает именованным
сообщением, содержащим путь этого файла, без сообщения о пустом каталоге
и без молчаливого пропуска.

AC-3. Для задачи без перечня долгоживущих файлов поведение автогейта не
меняется: существующие тесты автогейта проходят без правок.

AC-4. В `tests/` есть проверки четырёх сценариев: полностью
долгоживущая зелёная планка проходит автогейт; `manual` в долгоживущем
файле вызывает отказ с номером AC; нечитаемый файл из перечня вызывает
именованный отказ; запись «приёмка: что проверит approve» перечисляет
пометки долгоживущих файлов. Проверка первого сценария несёт пометку
«Ловит мутацию: каталог только из acceptance_tests/».

## Оценка объёма и деление

Сработавшие сигналы: в ТЗ названы более пяти связанных модулей и файлов,
а также механизм, на который опирается `docs/invariants.md`. Прогноз
диффа: до 8 КиБ.

**Обоснование монолита.** Изменение набора файлов автогейта и его
наблюдаемая проверка неразделимы: тест без изменения набора будет
красным, а изменение без всех четырёх сценариев AC-4 оставит регрессию
долгоживущей планки непроверенной. Две зоны составляют одну связку:
`orchestrator/fsm_autogate.py` определяет поведение, а `tests/` доказывает
его для полностью долгоживущей планки, пометок и ошибки чтения. Отдельно
мержить любую часть значит оставить либо красную проверку, либо изменение
без заданного доказательства.

## Не входит

- Критерий «полный `tests/` зелёный» с пометкой `skip` или `manual`.
- Критерий `ci` в канарейке.
- Сохранение причины отказа автогейта в канарейке.
- Изменение путей только для чтения: `orchestrator/advance_gates/`,
  `orchestrator/acceptance.py`, `orchestrator/gitcmd.py`,
  `orchestrator/artifact_source.py`, `orchestrator/fsm.py`,
  `orchestrator/fsm_advance.py`, `orchestrator/canary.py`,
  `orchestrator/config.py`, `scripts/guard.py`, `skills/`, `templates/`,
  `docs/adr/`, `docs/invariants.md`, `tests/test_invariants.py`,
  `docs/backlog.md`, `tasks/`.

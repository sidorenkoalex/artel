# SPEC: RETRO — полное первое предложение сути, killed из ТЗ

## Контекст
Аудит 27.08 (роадмап, строка P3 «Качество RETRO-экстракта „Суть“»)
показал, что детерминированный экстрактор «Сути» в
`orchestrator/retro.py` наивен: у done-задач Фазы 0 суть сводится к
названию-пустышке, у killed — к шаблонной заглушке SPEC, а у T042
первое предложение контекста обрезано по запятой вместо точки.
`_first_context_line` берёт дословно первую непустую строку раздела
«Контекст», а не первое предложение, поэтому обрезка идёт по границе
строки/запятой, а не по границе предложения.

## Требования

1. Извлечение «Сути» done-задачи берёт из раздела «Контекст» SPEC
   полное первое предложение — обрезка по границе предложения (точка),
   а не по границе строки или запятой.
2. Извлечение «Сути» killed-задачи, для которой в журнале `kill`
   сохранён текст `TZ.md` (SPEC T048, требование 5/6), берёт первое
   предложение этого ТЗ. Если текст ТЗ в журнале отсутствует —
   действует прежний фолбэк (текущее поведение `build_killed`).
3. Извлечение остаётся детерминированным кодом без LLM (решение
   Оператора 26.08 по RETRO остаётся в силе).
4. Правка `orchestrator/retro.py` регенерирует `docs/codebase-map.md`
   тем же коммитом (конвенция репозитория).

## Критерии приёмки

AC-1. «Суть» в RETRO done-задачи — полное первое предложение раздела
«Контекст» SPEC.md: обрезка происходит по точке (границе предложения),
даже если предложение в исходнике SPEC переносится через несколько
строк или содержит запятые до точки.

AC-2. «Суть» в RETRO killed-задачи, для которой в журнале `kill`
сохранён текст `TZ.md`, — первое предложение этого ТЗ (обрезка по
точке, тем же правилом, что AC-1).

AC-3. «Суть» в RETRO killed-задачи без сохранённого в журнале текста
`TZ.md` строится прежним фолбэком (поведение, действовавшее до этой
задачи, не меняется).

AC-4. Полный существующий набор тестов пакета остаётся зелёным.

AC-5. Каталог `docs/retro/` не изменяется этой задачей (уже
сгенерированные RETRO-файлы задним числом не переписываются).

## Не входит

- LLM-суммаризация «Сути» — извлечение остаётся детерминированным
  кодом.
- Изменение структуры или шаблона RETRO-файла.
- Изменение формата адресации RETRO (`merge-sha:путь`).
- Переписывание уже существующих файлов в `docs/retro/`.

# PLAN: RETRO — полное первое предложение сути, killed из ТЗ

## Подход
Точечная правка `orchestrator/retro.py`: заменить извлечение «Сути» по
границе строки/запятой на извлечение по границе предложения, не трогая
остальную вёрстку RETRO и killed-фолбэк без ТЗ в журнале.

Итерация 1 (отклонена ревью, blocker) резала по первой встреченной
точке без разбора её роли — на реальных SPEC.md репозитория это ломается
систематически (пути/расширения файлов, даты `ДД.ММ`, сокращения,
номера пунктов), не как редкий крайний случай — мотивирующий пример
самого этого SPEC.md (T042) резался после первого слова. Правило
уточнено: точка — граница предложения, только если сразу после неё
конец текста, либо пробел, а первый непробельный символ после пробела —
заглавная буква (или пробелов до конца текста больше нет). Точка, за
которой сразу (без пробела) идёт любой символ — цифра, строчная буква,
любой другой непробельный символ (`27.08`, `codebase-map.md`, `п.5`,
`т.е.`) — границей не считается, поиск продолжается со следующей точки.
Не полная NLP-сегментация (SPEC её не требует), но проходит мотивирующий
пример SPEC и не режет внутри путей/дат/сокращений с точкой.

Вводится одна новая функция `_first_sentence(text)` — схлопывает пробелы
и переносы строк в один пробел, обрезает по первой точке-границе
предложения по правилу выше (или отдаёт весь текст, если такой точки
нет). Она общая для двух источников:
- `_first_context_sentence(spec_text)` — раздел «Контекст» SPEC для
  done-«Сути» (требование 1), заменяет использование
  `_first_context_line` в `build_done`;
- прямое применение к `tz_text` из журнала `kill` для killed-«Сути»
  (требование 2), заменяет удалённую `_tz_gist_line`.

`_first_context_line` (дословная первая строка) остаётся как есть и
используется ТОЛЬКО в фолбэке `build_killed` без ТЗ в журнале —
поведение этого пути не меняется (требование 3, AC-3).

Никакого нового источника данных или структуры RETRO — детерминизм
(требование 3 SPEC) не нарушается: тот же вход даёт тот же байт-в-байт
результат, вопрос только в правиле обрезки строки.

## Шаги

## Влияние на систему
Меняется только `orchestrator/retro.py` (сигнатуры публичных функций
`build_done`/`build_killed`/`parse_total_cost`/`retro_path`/
`retro_rel_path` не тронуты — потребители `orchestrator/budget.py` и
`orchestrator/fsm.py` вызывают их как раньше). Внутренние функции
`_first_context_line`/`_tz_gist_line` — приватные (`_`-префикс), вне
модуля не импортируются (сверено `docs/codebase-map.md`), их
переименование/удаление не задевает другие модули.

Единственный внешний риск — уже сгенерированные `docs/retro/*.md`:
задним числом они не переписываются (требование 4/AC-5, приёмочный тест
`tasks/T063/acceptance_tests/test_retro_suite_and_docs_untouched.py`
проверяет дифф ветки против main). Новое правило действует только для
RETRO будущих задач.

Гейты/лимиты/инварианты не ослабляются: правка сужает эвристику
извлечения текста, не трогает guard, FSM, лимиты бюджета или
приёмочный контур. Откат — `git revert` коммита правки, отдельного
состояния для отката не требуется.

## Риски
Уточнённое правило (точка-конец-предложения = пробел+заглавная буква
или конец текста после неё) не полная NLP-сегментация: сокращение,
после которого сразу пробел и заглавная буква (например, «...г. Москва»
в середине предложения) даст ложную границу раньше смысловой. Такой
случай реже, чем изначальный класс (пути/даты/номера пунктов — самый
частый источник точек в SPEC.md репозитория), но не исключён полностью.
Не в объёме этой задачи (SPEC не просит распознавание сокращений с
заглавной буквы после точки), при необходимости — отдельная задача.

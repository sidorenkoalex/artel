# PLAN: Подметалка minor T017–T031

## Подход

Батч из десяти адресных правок ревью (T017, T018, T019, T025, T027,
T031) плюс синхронизация README/roadmap — один MR, без общего
рефакторинга: каждый адрес правится минимально, на месте, тем же
идиомом, что уже принят в модуле рядом.

Решения, где SPEC допускал выбор:

- **Требование 3 (`ci.check_runs`, дедупликация vs формулировка).**
  Выбрана формулировка (без дедупликации по `id`): реальный дедуп
  по `id` требует, чтобы каждая запись `check_runs` несла уникальный
  `id`, а хелпер `run()` существующего `tests/test_ci_status.py` его
  не проставляет — почти все фикстуры модуля (`run("guard")`,
  `green_page()`) используют записи без `id`, и наивный дедуп по
  `run.get("id")` схлопывает их все в одну запись, ломая 10 из 22
  существующих тестов модуля (проверено экспериментально). Правка
  всех фикстур существующего теста ради этого — цена выше, чем
  снятие безусловной формулировки из комментария рядом со сверкой
  `len(runs) != total`: комментарий переписан так, что явно называет
  сверку небезоговорочной (не гарантирует отсутствие дублей),
  поведение `check_runs` не меняется. AC-5 закрепляет именно этот
  выбор.
- **Требование 8 (`codebase_map`, исключить vs пометить).** Выбрано
  полное исключение `orchestrator/__init__.py` из списков
  «Импортирует»/«Импортируется» других модулей (не отдельная
  пометка): единственный потребитель карты, `orchestrator/brief.py`,
  встраивает текст карты целиком и не разбирает эти списки построчно
  (сверено чтением `brief.py` — компонент журналируется хэшем всего
  текста), поэтому исключение ничего не ломает и не требует нового
  формата пометки.

## Шаги

1. `orchestrator/yamlmini.py`, `_value()`: закрывающая скобка
   потокового списка ищется как первая `]` после `[` (не `rfind`),
   вторая `[` до неё — `YamlError` (требование 1, AC-1, AC-2).
2. `orchestrator/fsm.py`, `cmd_advance`: возвращает `bool` — `True`
   только когда переход отклонён именно `guard_refuses()`; остальные
   ветки (успех, отказ по другой причине) — `False`.
   `orchestrator/auto.py`, `cmd_auto`: при `True` от `cmd_advance`
   цикл останавливается тем же по характеру способом, что штатный
   отказ guard'а вне цикла — не зовёт `cmd_run` повторно (требование
   2, AC-3, AC-4).
3. `orchestrator/ci.py`, `check_runs`: комментарий у сверки
   `len(runs) != total` переписан — не называет её безусловной
   гарантией отсутствия дублей по `id` (требование 3, AC-5); выбор
   обоснован в «Подходе».
4. `tests/test_ci_status.py`, `PaginationTest`: патчеры `serve()`
   собираются в `self._serve_patches` и останавливаются в начале
   каждого следующего `serve()` (а не только в `addCleanup` класса) —
   не копятся между итерациями `subTest` (требование 4, AC-6).
5. `orchestrator/runner.py`, предупреждение о git-идентичности:
   список `absent` строится по всем именам из `GIT_IDENTITY` (author
   И committer), не только по паре `GIT_AUTHOR_*` (требование 5,
   AC-7, AC-8).
6. `orchestrator/store.py`, `SCHEMA`: колонка `target` в `tasks`
   и `steps` получает тот же `DEFAULT '{config.DEFAULT_TARGET}'`,
   что уже стоит в `migrate()` — свежая и мигрированная БД дают
   одинаковую схему колонки (требование 6, AC-9).
7. `orchestrator/artel.py`, `_tz_arg`: возврат `-> str | None`
   (требование 7, AC-10).
8. `scripts/codebase_map.py`, `build_modules`: `orchestrator/__init__.py`
   исключён как цель зависимости из списков «Импортирует»/
   «Импортируется» любого модуля (требование 8, AC-11); тем же шагом
   — регенерация `docs/codebase-map.md` (конвенция: правка `.py`
   в scripts/ требует свежей карты тем же коммитом).
9. Докстринг-маркер «НЕОСЛАБЛЯЕМЫЕ ТЕСТЫ (ADR-0002)» с упоминанием
   инварианта 28 — в `tests/test_gitcmd_branch_reads.py`
   и `tasks/T031/acceptance_tests/test_branch_correct_reads.py`
   (требование 9, AC-12).
10. `README.md`, раздел «Текущая фаза»: фаза A названа закрытой
    со ссылкой на T033, число ролей конвейера — четыре (analyst,
    test_author, developer, reviewer); раздел не переписан целиком
    (требование 10, AC-13).
11. `docs/roadmap.md`: строка беклога «Подметалка minor» (P3) удалена
    (требование 11, AC-14).

## Влияние на систему

Затронуты семь модулей `orchestrator/` (yamlmini, fsm, auto, ci,
runner, store, artel), один скрипт (codebase_map.py) и три
документа/теста вне acceptance_tests (README.md, docs/roadmap.md,
tests/test_ci_status.py) плюс два докстринга-маркера. Каждая правка
— адрес конкретного замечания ревью, поведение вне названного адреса
не меняется:

- `cmd_advance` меняет СИГНАТУРУ (был `-> None`, стал `-> bool`), но
  ни один существующий вызывающий код не читает возврат
  (`artel.py:156` — CLI, `auto.py` — читает только в новом месте,
  тесты через `self.capture(fsm.cmd_advance, ...)` — возврат
  отбрасывается редиректом stdout) — грепом подтверждено, что других
  мест вызова нет.
- Правка `store.SCHEMA` — только `DEFAULT` литерал у уже существующей
  колонки; свежая БД получает то же значение, что раньше проставляла
  только `migrate()` (существующие строки без target уже деградируют
  на чтении к `config.DEFAULT_TARGET`, см. `task_target`) — сужения
  или потери данных нет.
- Требование 3 сознательно НЕ меняет фактическое поведение
  `check_runs` (обоснование выбора — «Подход»): существующий
  инвариант 19 (docs/invariants.md) и кодирующие его тесты
  `test_ci_status.PaginationTest`/`test_invariants.MergeNeedsGreenCiTest`
  не задеты — прогнаны без изменений и остаются зелёными.
- Требование 8 не меняет `render()` в части заголовков модулей,
  публичных функций или сгенерированного назначения — только состав
  двух списков зависимостей; `docs/codebase-map.md` регенерирован
  тем же коммитом (конвенция).
- `tests/test_gitcmd_branch_reads.py` и
  `tasks/T031/acceptance_tests/test_branch_correct_reads.py`: правка
  — только докстринг модуля (маркер), ни один тестовый метод,
  ассерт или фикстура не тронуты — прогнаны без изменений.
- Ни один существующий тест не удалён и не ослаблен (AC-15 приёмки
  это же и проверяет сравнением с `main`); три существующих провала
  `tests/test_multitarget.py::RoleEnvTest` (реальный git-конфиг
  машины разработчика просачивается в `git_identity()` — читает
  `~/.gitconfig` вне мока) воспроизведены и на немодифицированной
  ветке (`git stash` + прогон) — вне зоны этой задачи, не внесены
  этой правкой.
- Откат: `git revert` коммита(ов) этой задачи — правки локальны
  к перечисленным файлам, миграций данных и необратимых операций
  нет.

## Риски

- Требование 3 оставляет исходный класс дефекта («дубль страницы
  API может маскировать неполноту») нечиненым по существу — только
  документированным как небезусловная гарантия. Если `gh api`
  когда-нибудь реально начнёт отдавать дублирующиеся страницы (не
  наблюдалось), сверка полноты может пропустить неполный ответ. Цена
  устранения (переписать фикстуры `tests/test_ci_status.py` под
  уникальные `id`) признана непропорциональной вероятности сценария
  на момент задачи — решение Оператора при ревью может пересмотреть
  выбор.

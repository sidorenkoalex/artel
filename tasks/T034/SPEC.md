# SPEC: Подметалка minor T017–T031

## Контекст
Строка беклога P3 «Подметалка minor» копит десять мелких замечаний
ревью задач T017–T031: адрес каждого известен, поведение системы
каждым исправлением меняется не сверх описанного. Задача проходит
их одним батчем, не переписывая систему вокруг.

## Требования

1. `orchestrator/yamlmini.py`, `_value()`: закрывающая скобка
   потокового списка ищется без захвата `]`, стоящего внутри
   хвостового комментария (ревью T017); вложенный потоковый список
   (`[a, [b]]`) отказывает `YamlError`, а не разбирается молча
   элементом-строкой.
2. `orchestrator/auto.py`, `cmd_auto`: отказ `advance` guard'ом
   (`fsm.guard_refuses`) останавливает цикл `auto` — не запускает
   `cmd_run` повторно для того же состояния — тем же по характеру
   способом, что штатная остановка на гейте: журнал, вывод, подсказка
   «почини артефакт и повтори» (ревью T017).
3. `orchestrator/ci.py`, `check_runs`: сверка `len(runs) != total`
   защищена от маскирования дублями записей при повторе страницы API
   — либо дедупликацией записей по `id` перед сверкой, либо (если
   решение — не дедуплицировать) снятием из соответствующего
   комментария-гарантии формулировки, называющей сверку полноты
   безусловной. Выбор — по цене реализации, фактически выбранное
   поведение закреплено тестом (ревью T018).
4. `tests/test_ci_status.py`, `serve()`: патчеры внутри `subTest`-цикла
   останавливаются (`stop()`) до конца каждого подтеста, а не стекают
   до `tearDown` класса (ревью T018).
5. `orchestrator/runner.py`, предупреждение о git-идентичности перед
   стартом шага (`absent = [...]` около «git-идентичность роли не
   задана»): список отсутствующих переменных строится по полному
   набору `GIT_IDENTITY` (author и committer), а не только по паре
   `GIT_AUTHOR_*` — сценарий «`GIT_AUTHOR_*` экспортированы, `git
   config` не задан» (нет committer-идентичности) печатает
   предупреждение, а не проходит молча до `rc=128` на коммите
   (ревью T019).
6. `orchestrator/store.py`: определение колонки `target` в `SCHEMA`
   (создание свежей БД, таблицы `tasks`/`steps`) и в `migrate()`
   (`add_column(..., "target", "TEXT DEFAULT '...'")`) приведены
   к одному виду — свежая и мигрированная БД дают одинаковую схему
   колонки `target` (ревью T019).
7. `orchestrator/artel.py`, `_tz_arg`: type-hint возврата соответствует
   фактическому типу (функция возвращает `None`, когда флага `--tz`
   нет) (ревью T025).
8. `scripts/codebase_map.py`: шум связей импорта для
   `orchestrator/__init__.py` в сгенерированной карте устранён —
   либо `__init__.py` исключён из списков «Импортирует»/«Импортируется»
   у каждого модуля, либо помечен в карте отдельно от прочих
   зависимостей. Решение согласовано с тем, как карту читает
   `orchestrator/brief.py` (единственный код-потребитель карты на
   момент задачи) (ревью T027).
9. Модули, кодирующие инвариант 28 реестра (`docs/invariants.md`,
   строка 28) — `tests/test_gitcmd_branch_reads.py` и
   `tasks/T031/acceptance_tests/test_branch_correct_reads.py` — несут
   в докстринге модуля шапку-маркер «НЕОСЛАБЛЯЕМЫЕ ТЕСТЫ (ADR-0002)»
   с явным упоминанием номера 28, по образцу шапки в
   `tests/test_acceptance_tests_flow.py` (ревью T031).
10. `README.md`, раздел «Текущая фаза»: приведён в соответствие
    с фактом на момент задачи — фаза A закрыта критерием задачи T033;
    ролей конвейера четыре (analyst, test_author, developer, reviewer);
    команды `version` и `doctor` существуют в CLI. Правка точечная,
    раздел не переписывается целиком.
11. Строка беклога «Подметалка minor» (P3, `docs/roadmap.md`) удалена
    этой же задачей.
12. Ни один из десяти адресов не меняет поведение системы сверх
    описанного в требованиях 1–10 выше; ни один существующий тест,
    гейт, лимит, guard или инвариант не ослабляется и не удаляется
    (принцип целостности, ADR-0002). Каждое исправление, меняющее
    наблюдаемое поведение, покрыто тестом.

## Критерии приёмки

AC-1. `yamlmini.mapping()`/`_value()` на значении вида потокового
списка с хвостовым комментарием, содержащим символ `]` (например,
`key: [a, b]  # см. функцию foo()]`), разбирает список `[a, b]` и не
включает часть комментария в его элементы и не роняет разбор ошибкой
там, где список составлен корректно.

AC-2. `yamlmini.mapping()`/`_value()` на значении с вложенным
потоковым списком (например, `key: [a, [b]]`) отказывает `YamlError`
с номером строки, а не возвращает словарь со строкой `"[b]"` в
качестве элемента.

AC-3. Если `advance` внутри цикла `auto` отклоняет переход guard'ом
(отказ структуры артефакта-условия), цикл `auto` останавливается на
этом шаге — не вызывает `cmd_run` повторно для того же состояния —
и печатает и журналирует остановку с той же по смыслу подсказкой, что
и у отказа guard'а вне цикла («почини артефакт и повтори»).

AC-4. Для состояния задачи, не относящегося к отказу guard'ом
(например, артефакт-условие ещё не в статусе `ready`), поведение
цикла `auto` не меняется — цикл продолжает запускать `cmd_run`, как
и до этой задачи.

AC-5. `ci.check_runs`: тест закрепляет фактически выбранное поведение
сверки полноты пагинации при дублирующейся странице ответа API — либо
результат с дублями по `id` не считается ложно неполным/ложно полным
благодаря дедупликации, либо (при альтернативном выборе) комментарий
рядом со сверкой `len(runs) != total` в `ci.py` не называет её
безусловной гарантией полноты. Ровно один из двух вариантов
реализован и закреплён тестом.

AC-6. `tests/test_ci_status.py`: после выполнения `serve()` внутри
итерации `subTest`, вызванные им патчеры остановлены — следующая
итерация того же теста не наследует моки предыдущей (проверяется тем,
что число активных патчей не растёт от итерации к итерации).

AC-7. `runner.role_env`/окружение шага: если в окружении процесса
роли заданы `GIT_AUTHOR_NAME` и `GIT_AUTHOR_EMAIL` (например, через
экспортированные переменные), а `git config user.name`/`user.email`
не заданы (`GIT_COMMITTER_*` отсутствуют), предупреждение о
незаданной git-идентичности печатается и журналируется перед стартом
шага.

AC-8. Для окружения, где git-идентичность (обе пары, author и
committer) присутствует полностью, предупреждение не печатается —
поведение не изменилось относительно состояния до этой задачи.

AC-9. Схема колонки `target` (тип и `DEFAULT`) в таблицах `tasks` и
`steps` совпадает для БД, созданной свежей через `SCHEMA`, и БД,
созданной без колонки `target` и прогнанной через `migrate()`.

AC-10. Type-hint возврата `artel.py: _tz_arg` допускает `None`
(соответствует фактическому возврату функции при отсутствии флага
`--tz`).

AC-11. Сгенерированный `docs/codebase-map.md` (`scripts/codebase_map.py`)
не перечисляет `orchestrator/__init__.py` как обычный узел в списках
«Импортирует»/«Импортируется» модулей карты наравне с прочими —
модуль исключён из этих списков или явно помечен как особый случай.

AC-12. Модули `tests/test_gitcmd_branch_reads.py` и
`tasks/T031/acceptance_tests/test_branch_correct_reads.py` содержат
в докстринге модуля маркер «НЕОСЛАБЛЯЕМЫЕ ТЕСТЫ (ADR-0002)» с прямым
упоминанием номера инварианта 28.

AC-13. Раздел README «Текущая фаза» называет фазу A закрытой
(со ссылкой на критерий задачи T033), называет число ролей конвейера
равным четырём и не противоречит существованию команд `version` и
`doctor` в CLI.

AC-14. В `docs/roadmap.md` строки беклога «Подметалка minor» (раздел
P3) больше нет.

AC-15. Ни один тест из существующих (`tests/*.py`) не удалён и не
ослаблен (не превращён в `skip`, не потерял проверяемые утверждения)
в ходе исправления пунктов 1–10; каждое исправление, наблюдаемо
меняющее поведение (AC-1, AC-2, AC-3, AC-5, AC-7, AC-9), покрыто новым
или изменённым тестом.

## Не входит

- «Пагинация CI-гейта» — отдельная строка беклога P3 (`merge_gate`
  читает только первую страницу ответа `gh`, 30 проверок) — другой
  дефект, другая задача; этой задачей не трогается.
- Любое поведение системы, не названное в требованиях 1–10 —
  рефакторинг, новые фичи, изменение архитектуры модулей вне
  перечисленных адресов.
- Разделение токенов ролей, правка `gates.yaml`/`roles.yaml`/
  `targets.yaml`/`.github/`/`templates/`/`skills/` — эти пути меняет
  только Оператор отдельным MR (conventions-core).
- Полная переработка раздела README «Текущая фаза» или прочих
  разделов README сверх точечной сверки со статусом (требование 10).
- Прочие строки беклога P3, кроме «Подметалка minor» (требование 11).
- Ревизия структуры `docs/invariants.md` или добавление новых
  инвариантов сверх шапки-маркера у двух названных модулей
  (требование 9).

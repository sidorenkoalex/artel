## Замечания

- minor — README.md:15 — заголовок раздела остаётся «## Текущая фаза: A
  (мультитаргетный контур)», хотя текст ниже теперь называет фазу A
  закрытой (требование 10 выполнено по существу — тела раздела
  достаточно, само требование не просило переименовывать заголовок, и
  SPEC «Не входит» явно исключает полную переработку раздела) —
  заголовок и тело секунду читаются как противоречащие друг другу.
  Предложение: при следующей правке этого раздела (не обязательно
  сейчас) сменить заголовок на «## Фаза A (мультитаргетный контур) —
  закрыта» или аналогично, раз фаза более не текущая.

- major, вне SPEC — `docs/codebase-map.md` (шаг 8 PLAN, конвенция
  «регенерируй карту тем же коммитом») — CI-джоб `.github/workflows/
  ci.yml:63-79` («закоммиченная карта не стухла») сравнивает
  `built_at_sha` закоммиченной карты с текущим `HEAD` и красит main,
  если между ними менялся хоть один `orchestrator/*.py`, `scripts/*.py`
  или `tests/*.py`. `built_at_sha` регенерируется скриптом ДО
  коммита (`git rev-parse HEAD` = родитель), поэтому сразу после
  коммита, который одновременно правит .py-файлы И карту «тем же
  коммитом», этот же коммит гарантированно попадает в diff и красит
  джоб. Воспроизведено буквально командой джоба (`git show
  HEAD:docs/codebase-map.md` → `built_at_sha`, `git diff --name-only
  $base HEAD -- ...`) на текущей ветке: после мержа в main список
  «стухших» файлов — 10 (все семь модулей orchestrator/, сам
  scripts/codebase_map.py, оба правленных tests/*.py из этой задачи).
  **Важно: это НЕ новый дефект этой задачи** — тот же расчёт на
  текущем main (`built_at_sha=a50105f...` из карты коммита `9c92a82`
  против `git diff a50105f 9c92a82 -- ...`) уже сегодня даёт 2 стухших
  файла (`orchestrator/fsm.py`, `tests/test_git_fixation.py`) — то
  есть джоб потенциально уже красный на main ДО этой задачи, T034 лишь
  расширяет тот же класс пре-существующего разрыва (2 файла → 10).
  Живой статус самого GitHub Actions джоба не проверен (`gh run list`
  недоступен в песочнице ревью — сетевой вызов заблокирован
  разрешениями). Правка механики самого CI-джоба (сверка сама по себе
  структурно не может требовать равенства sha — это признано в
  комментарии джоба) — вне требований 1–10 этой SPEC и вне «Подметалки
  minor», решение не в компетенции этой задачи. Не блокирует T034
  (тот же паттерн уже применялся во всех задачах T017–T033, ни диффом,
  ни PLAN не заявлено иное), но Оператору стоит проверить фактический
  статус джоба `codebase-map` на main после этого мержа и, если он
  красный, завести отдельную строку в `docs/roadmap.md` (симметрично
  тому, как эта же задача сама возникла из накопленных minor).

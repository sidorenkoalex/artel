# ТЗ: amend-tests отправляет кодовую ветку задачи в origin; verifying не ждёт до потолка коммита, которого нет в origin

Источник: бэклог — строка «amend-tests пушит кодовую ветку задачи»
(приоритет 2) и строка копилки 02.10 (задача 01M3Y75C9T, коммит 54e1cbc0,
20 минут простоя); свежий прецедент 04.10.2026 (задача
01M446X1B7FB8JDMYFP5APWTVE: правка долгоживущего теста закоммичена в
кодовую ветку коммитом 47c0eeb2 и не отправлена в origin). Решение
Оператора 05.10 «заводи вторую волну».

Факты (пин 1d2229b7, сверка кода 05.10):
- Режим правки из рабочей копии с непустым перечнем лока —
  `orchestrator/amend.py::_amend_with_long_lived` (~662-746): (а) коммит
  долгоживущих файлов в кодовую ветку (`_commit_long_lived` ~504-518,
  `git commit` в рабочей копии задачи), (б) коммит планки и перечня в
  ссылку документов (`_commit_plank`), (в) сдвиг `tests_locked_sha`.
  Отправки кодовой ветки в origin нет ни на одном шаге; ссылку документов
  отправляет сам узел записи (`artifact_branch.commit_files`, ADR-0021
  п.3). Сбой после (а) — `_recovery_exit` (~520-527) с путём
  восстановления `amend-tests <id> --from-branch`.
- Режим без перечня (`_cmd_amend_tests` ~530-651) кодовую ветку не
  трогает: правка уходит только в ссылку документов.
- Режим `--from-branch` (`_cmd_amend_tests_from_branch` ~825-946,
  `_check_code_head_long_lived` ~949-980) кодовую ветку не коммитит, но
  проверяет и узаконивает её голову; при незакоммиченной правке
  подсказывает «закоммить правку» — то есть ручной локальный коммит,
  который тоже не попадает в origin.
- Этап 2 ADR-0021: рабочая копия задачи — `.artel/projects/<проект>/
  worktrees/<id>` (`workspace.path` ~123-127), клон проекта —
  `workspace.task_repo` (~61-64); ветка рабочей копии и клона общая.
- Узел «голова ветки в origin» уже есть и работает от клона проекта:
  `orchestrator/github_adapter.py::ensure_head_in_origin` (~187-228) —
  сверяет точный sha локальной и удалённой головы, при расхождении
  делает `git push -u origin <ветка>`, журналирует «push (голова не в
  origin)» или «push FAILED (голова не в origin)», после успешной
  отправки заводит черновик запроса на слияние
  (`_ensure_draft_mr_after_publish` ~232). Его зовут рубеж
  `in_dev -> verifying` (`advance_gates/tests_writing.py::
  _origin_push_gate` ~33-51, вызов в `fsm_advance.py::in_dev` ~618, не
  для канареечной задачи) и каждый `approve` на `merge_gate`
  (`fsm_merge_gate.py` ~590-612).
- `fsm_advance.py::verifying` (~307-353) опрашивает
  `ci.verifying_status` (`orchestrator/ci.py` ~326-361); коммит, которого
  нет в origin, даёт исход «проверок нет» с текстом «голова ветки не в
  origin … подсказка: git push -u origin <ветка>» (~344-347) — ожидание,
  не остановка. Эскалация — только по потолку
  `config.VERIFYING_CEILING_SEC` = 5400 с (~277), отсчёт от входа в
  состояние (`fsm._verifying_elapsed_seconds(t["updated_at"])`).
  `auto._advance_verifying_poll` (~507-535) останавливает цикл только на
  красном CI.
- Прецедент 04.10 (журнал задачи 01M446X1B7FB8JDMYFP5APWTVE): 21:09:08
  «правка планки» (код 47c0eeb2); 21:09:24 «голова ветки не в origin —
  GitHub не нашёл коммит 47c0eeb2 (HTTP 422)»; обход Оператора — `stop`
  -> `reject` из verifying с причиной «код менять не нужно» -> `advance`
  (рубеж `_origin_push_gate` отправил ветку, 21:11:02) -> `auto`. Побочный
  эффект обхода: повторный проход `in_dev -> verifying` с прогоном
  приёмочных тестов.

Требуется:
1. `amend-tests`, закоммитивший правку в кодовую ветку
   (`_amend_with_long_lived`, `long_changed` не пуст), сразу после
   коммита (а) и до записи (б) отправляет голову кодовой ветки в origin
   тем же узлом `github_adapter.ensure_head_in_origin` (второго способа
   отправки не заводить). Канареечная задача — без отправки, тем же
   исключением, что у `_origin_push_gate`.
2. Отказ отправки — именованный: ненулевой код, текст называет причину
   из узла отправки, `tests_locked_sha` не сдвигается, ссылка документов
   не меняется; журнал — запись «amend-tests прерван» (как
   `_recovery_exit`) с путём восстановления: починить доступ к origin и
   повторить `amend-tests <id> --from-branch --reason «…»`.
3. `amend-tests --from-branch`, узаконивающий голову кодовой ветки с
   расхождением долгоживущих файлов (`long_diverged` не пуст), перед
   сдвигом лока тем же узлом сверяет и при необходимости отправляет
   голову кодовой ветки в origin; отказ — как в п.2. Без расхождения
   долгоживущих файлов (правка только планки) кодовая ветка не
   трогается, обращения к origin нет.
4. Режим без перечня лока (`_cmd_amend_tests`, правка только планки) не
   меняется: кодовую ветку он не коммитит и в origin её не отправляет.
5. Состояние `verifying`: если `ci.verifying_status` распознал «голова
   ветки не в origin», шаг `verifying` не ждёт до потолка. SPEC выбирает
   один из двух вариантов и обосновывает: (а) отправка головы тем же
   узлом `ensure_head_in_origin` с записью в журнал, затем обычное
   ожидание CI; (б) остановка цикла `auto` с именованной причиной и
   подсказкой команды пульта (не ручного `git push`). Остальные исходы
   `verifying` (зелёный, «проверки идут», «проверок нет» по другой
   причине, красный, потолок) не меняются.
6. Текст подсказки «git push -u origin <ветка>» в `ci.verifying_status`
   заменяется подсказкой, соответствующей выбранному в п.5 варианту.
7. Тесты в `tests/` с заявками «Ловит мутацию»: `amend-tests` с правкой
   долгоживущего файла в задаче в `in_dev` и в `verifying` — после
   команды голова кодовой ветки равна голове в origin (песочница с
   голым репозиторием в роли origin); отказ отправки — `tests_locked_sha`
   и ссылка документов не сдвинуты, сообщение называет причину и путь
   восстановления; `--from-branch` с локальной незапушенной головой —
   голова в origin; правка только планки — обращения к origin нет;
   канареечная задача — без отправки; `verifying` с головой вне origin —
   поведение п.5. Существующие тесты не ослабляются.

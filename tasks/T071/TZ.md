# ТЗ: Ветко-корректное чтение SPEC в approve

# ТЗ: ветко-корректное чтение SPEC в approve — последний inline-читатель

## Контекст

Роадмап, P3-строка «Ветко-корректные чтения статусов — закрыта T047;
остаток CR-2026-08-28-10». T047 завела общий узел
`_read_branch_text_or_refuse` (fsm.py), через который проходят чтения
артефактов задач с ВЕТКИ задачи (а не с диска рабочей копии) для
spec_writing/review/in_dev — класс ошибок «читаем не ту версию
артефакта, когда рабочую копию двигают параллельные сессии» закрыт
для этих путей.

## Проблема

Остался последний непереведённый читатель: inline-чтение SPEC в пути
`approve`/`spec_gate` (fsm.py, район ~918 на момент ревизии 28.08) идёт
мимо общего узла. Содержательное отличие этого пути от узла — только
реакция на отказ: sys.exit против print+return. Пока читатель живёт
отдельно, он не получает исправлений/гарантий узла и остаётся местом,
где класс ошибки может воспроизвестись.

## Что нужно

Перевести это чтение на общий узел `_read_branch_text_or_refuse`,
сохранив текущее наблюдаемое поведение пути approve/spec_gate
(тексты отказов и коды выхода могут быть приведены к единообразию
узла, если это не меняет решений FSM — зафиксировать выбор в PLAN).
После перевода inline-чтений артефактов мимо узла в fsm.py остаться
не должно.

## Границы

- Только путь approve/spec_gate и общий узел; другие модули не трогать.
- Ослабление проверок узла запрещено (принцип целостности).

## Критерии приёмки (ориентир для SPEC)

- Чтение SPEC в approve/spec_gate идёт через общий узел; сценарий
  «SPEC читается с ветки задачи, а не с диска» покрыт тестом для
  этого пути (образцы — тесты T047).
- Поведение отказов пути не ухудшено (внятное сообщение, задача не
  ломается).
- Полный тестовый набор зелёный.

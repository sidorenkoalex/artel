# ТЗ: Роль запускается по абсолютному пути из манифеста, модель роли сверяется с версией CLI до старта агента

Источник: копилка docs/backlog.md — строка П1 06.09 «Runner зовёт
инструменты роли по имени через PATH» и строка П2 19.09 «Модель роли не
сверяется с возможностями установленного CLI». Обе живут в
orchestrator/runner.py и orchestrator/stack.py — одно ТЗ. Решение
Оператора 19.09: заводить сейчас.

Инциденты:
- 06.09, планка отвязки циклов (01M1NWCHVT): подставной `claude` планки
  затенён настоящим из /opt/homebrew/bin — каталог инструмента `gh`
  стоит в PATH роли раньше; любой одноимённый бинарник в каталоге другого
  инструмента подменит объявленный.
- 19.09, 01M2XFSJ1Z и 01M2XFSE8G: после смены модели developer/reviewer на
  `claude-fable-5-1` шаг developer падал за 0 токенов «API Error: 400
  Claude Code 2.1.236 does not support this model; version 2.1.251 or
  newer is required» — три попытки с паузами 120 с, класс «системный
  кандидат», впереди эскалация; причина известна до запуска агента.
  Обход: stop циклов, обновление CLI Оператором (2.1.267), перезапуск.

Причина (по коду):
- `runner._resolve_declared_tools` резолвит объявленные инструменты
  манифеста (`stack.DECLARED_TOOLS`) через `shutil.which` один раз;
  `_role_path_dirs` собирает PATH роли из каталогов этих инструментов в
  порядке манифеста; но `role_cmd()` начинается с литерала `"claude"` —
  бинарник ищется по PATH роли в момент запуска, а не берётся из
  `resolved["claude"]`.
- `stack.REQUIRED_TOOLS["claude"]` — `ToolRequirement((1, 0, 0), …)`:
  минимальная версия без связи с моделями ролей; `stack.check_stack`
  печатает строку на инструмент, о моделях `roles.yaml` не знает.
- `runner._prepare_step` читает `roles.model(role)` и передаёт
  `--model`; проверки «модель принимается установленным CLI» нет;
  `failure_classification.classify_attempt_failure` относит текст «API
  Error:» к классу «системный кандидат» с минутным бэкоффом и повторами
  (`config.AGENT_ATTEMPTS`), хотя отказ «does not support this model»
  детерминирован и повторами не лечится.

Требуется:
1. Запуск роли по абсолютному пути: argv[0] команды шага —
   `resolved["claude"]` из резолва манифеста (тот же, из которого
   собирается PATH роли), не литерал `claude`. PATH роли для дочерних
   процессов (git, python3) не меняется. `role_cmd()` остаётся
   единственным источником argv для запуска и для офлайн-сверки
   `doctor.isolation_smoke` — сверка не ослабляется (сравнение по
   абсолютному пути либо по базовому имени — решение аналитика с
   обоснованием в SPEC).
2. Таблица «модель → минимальная версия CLI» в `orchestrator/stack.py`
   рядом с манифестом (например `MODEL_MIN_CLI_VERSION = {"claude-fable-5-1":
   (2, 1, 251)}`; состав таблицы — приложением Оператора в SPEC/PLAN,
   код читает таблицу). Неизвестная таблице модель — не отказ.
3. Предполётная проверка модели в `runner._prepare_step` (после чтения
   `roles.model`): если модель есть в таблице и установленная версия
   CLI (`claude --version`, уже разбирается `stack._tool_check`) ниже
   минимальной — именованный отказ шага ДО запуска агента, без попыток и
   без эскалации: запись журнала «модель роли не поддерживается CLI:
   <модель> требует claude ≥ X, установлен Y», auto останавливается с
   подсказкой «обнови CLI либо смени model роли в roles.yaml». Модель не
   в таблице — одна запись предупреждения «модель не в таблице
   совместимости» на шаг, запуск как сегодня.
4. Класс провала «модель не поддерживается CLI» в
   `orchestrator/failure_classification.py`: текст «does not support this
   model» — отдельный класс без повторов (следующие попытки не
   запускаются, пауз нет), исход шага — тот же именованный отказ, что и в
   требовании 3 (покрывает модели вне таблицы).
5. `stack.check_stack` (вывод `doctor`/`version`): по строке на каждую
   agent-роль с полем `model` в `roles.yaml`: «модель роли developer
   claude-fable-5-1: CLI 2.1.267 ≥ 2.1.251 — ok», FAIL при заниженной
   версии, WARN для модели вне таблицы.
6. Тесты (tests/): argv[0] шага — абсолютный путь резолва; сценарий
   затенения (подставной `claude` в каталоге, стоящем в PATH роли позже
   каталога другого инструмента с настоящим `claude`) — роль запускает
   объявленный бинарник; модель ниже версии CLI — отказ без запуска
   агента, без записей «agent run retry», без `state -> escalated`;
   модель вне таблицы — предупреждение и запуск; текст «does not support
   this model» в выводе попытки — без повторов; строки `check_stack` по
   ролям. Существующие `tests/test_runner_role_model.py`,
   `tests/test_stack.py`, `tests/test_stack_ci.py` остаются зелёными.

Зоны: orchestrator/runner.py, orchestrator/stack.py,
orchestrator/failure_classification.py, tests/.

Только чтение (не менять): orchestrator/roles.py (`model()` как есть),
orchestrator/config.py (`AGENT_ATTEMPTS` не меняется),
orchestrator/doctor/ (печать `check_stack` уже общая, новых проверок
doctor не заводить), orchestrator/version.py.

Приложением: roles.yaml (не менять; защищённый путь — модели ролей
задаёт Оператор).

Не входит: ярусы моделей и `.artel/models.yaml` (бэклог, строка 2);
сухой платный вызов CLI для проверки модели; изменение
`AGENT_ATTEMPTS` и пауз для прочих классов; обновление CLI пультом.

# PLAN: Ревью-пакет вместо свободного чтения репозитория

## Подход

Вход ревьювера собирает оркестратор и кладёт в промпт шага целиком —
агент больше не добывает контекст обходом репозитория. Ключевые решения:

- **Пакет — чистая функция от задачи и ветки.** `review_package()`
  (orchestrator/artel.py:432) возвращает `{text, chars, diff_lines,
  truncated}`: текст для промпта и размеры для журнала. Никакой записи,
  никакого состояния — поэтому сборка проверяется юнитом без CLI и без
  реального git (требование 6).
- **Порядок частей фиксирован**: задача → SPEC → PLAN → прошлый REVIEW
  (только если файл есть) → стат-список → diff. Ревьювер ориентируется
  в пакете по постоянной структуре, а тест сравнивает индексы маркеров,
  а не всю простыню.
- **Молчание не выдаётся за пустоту.** Отсутствующий артефакт даёт
  `(файла нет)`, упавший git — `(не собран: <причина>)`
  (artifact_part:388, git_diff_part:404). Тихо показать ревьюверу
  «изменений нет» вместо не собранного diff — это выпрошенный вслепую
  аппрув, худший из возможных исходов правки про экономию.
- **Потолок diff — защита контекста шага, а не проверка размера MR.**
  `REVIEW_DIFF_MAX_LINES = 4000` (artel.py:81); за потолком в пакет идёт
  начало diff плюс пометка с обоими числами и прямым указанием, что сам
  размер — повод для замечания (truncate_diff:418). Усечение стат-списка
  не трогает: список файлов остаётся полным, то есть ревьювер видит весь
  объём изменения, даже когда содержимое показано частично.
- **Размер входа — в журнал до первой попытки агента** (cmd_run:706), а
  не после: запись «сколько было на входе» должна стоять рядом с
  «agent run started», чтобы стоимость прогона соотносилась с ней в
  `log <id>` без арифметики по времени.
- **Права не трогаем.** `--allowedTools` у ревьювера остаётся тем же,
  что у разработчика; миссия прямо разрешает точечное чтение файлов и
  запуск проверок, когда без них замечание не доказать. Пакет сужает
  блуждание, а не полномочия (требование 4, «Не входит»).

Отдельный ADR не нужен: ни одна защита, лимит или гейт не меняется —
добавляется сборка входа и запись в журнал.

## Шаги

Один шаг = один MR: пакет без миссии бессмыслен, миссия без пакета лжёт
агенту про его вход.

1. **Ревью-пакет в промпте ревьювера и его размер в журнале.**
   - `REVIEW_DIFF_MAX_LINES`, `artifact_part`, `git_diff_part`,
     `truncate_diff`, `review_package`, `package_note` в
     orchestrator/artel.py;
   - ветка reviewer в `cmd_run`: новая миссия (работа от пакета,
     точечное чтение с называнием причины, права не сужены), запись
     `ревью-пакет собран` в журнал, пакет в хвосте промпта отдельным
     разделом `--- РЕВЬЮ-ПАКЕТ ---`;
   - юнит-тесты tests/test_review_package.py: состав и порядок пакета,
     прошлый REVIEW только на итерациях, отсутствующий PLAN и молчащий
     git, усечение с пометкой, размер в журнале до старта агента,
     неизменные права шага, разработчик без пакета.

## Влияние на систему

**Что затронуто за пределами правки.** Единственная точка изменения
поведения — ветка `role == "reviewer"` в `cmd_run`. Шаг разработчика не
меняется вовсе (тест `test_developer_step_has_no_package`), FSM, гейты,
бюджет, уборка и мерж не тронуты.

**Инварианты и защиты рядом — и почему они не ослаблены.**

- Инвариант 1 (docs/invariants.md, «оркестратор не думает»): сборка
  пакета — детерминированный код без LLM, агента по-прежнему запускает
  только `run`. `AgentRunsOnlyFromRunTest` зелёный без правок.
- Инвариант 11 (журнал пишется всегда): запись только добавлена —
  `ревью-пакет собран` перед `agent run started`; ни одна прежняя запись
  не убрана.
- Инвариант 8/9 (бюджет): деньги считаются как раньше; сборка пакета
  бесплатна и происходит после проверки `budget_block`, то есть за
  потолком шаг по-прежнему не начинается.
- Инвариант 12 (merge только из merge_gate): пакет зовёт git только на
  чтение (`diff`, `diff --stat`); свип `MergeOnlyFromMergeGateTest`
  остался зелёным.
- Права ревьювера (`--allowedTools`) не сужены — это прямое требование 4
  SPEC и одновременно защита от деградации качества ревью (T010: право
  исполнять проверки — доказанная ценность). Тест это фиксирует, чтобы
  сужение нельзя было внести незаметно.

**Правки в существующих тестах — и почему это не ослабление.** В
песочницах трёх модулей (test_agent_failure, test_review_freshness,
test_step_cost) `artel.git` подменён на `fake_git`: шаг ревью теперь
обращается к git, а временного репозитория в этих песочницах нет.
Изменены только фикстуры — ни один ассерт не удалён, не смягчён и не
заскипан, число тестов не уменьшилось (174 против 156, из них 19
новых, минус ноль). Подмена идёт в ту же сторону, что и правило
test_invariants: настоящий git в юнит-тестах не исполняется.

**Откат.** Одним revert коммита: пакет — аддитивная ветка в `cmd_run`,
внешних схем и данных не заводит, миграций БД нет, формат журнала
не меняется (новая запись со своим `action`, старые читаются как
раньше).

## Риски

- **Критерий приёмки 3 (прогон дешевле $2.4) может не подтвердиться на
  T011.** Пакет убирает блуждание по репозиторию, но не длину самого
  diff: правка вышла на ~1.5k строк вместе с тестами и артефактами, и
  весь этот объём теперь идёт в промпт гарантированно, а раньше попадал
  бы туда лишь частично. Ожидание — экономия за счёт исчезнувших
  Glob/Grep/Read-циклов; если журнал покажет иное, причина в размере
  входа, и следующий ход — не ослабление пакета, а разговор про потолок
  (константа `REVIEW_DIFF_MAX_LINES`) и размер MR.
- **Пакет прячет от ревьювера остальной репозиторий.** Смягчено
  миссией: точечное чтение прямо разрешено, причина называется в
  замечании — то есть недостаточность пакета становится наблюдаемой в
  REVIEW, а не молчаливой. Если она окажется системной, это вход в
  следующую задачу (состав пакета), а не повод снимать ограничение.
- **Двойной расход на diff при усечении**: стат-список и начало diff
  дублируют информацию о файлах. Сознательно: полный список файлов —
  единственное, по чему ревьювер судит об объёме изменения, когда
  содержимое показано частично.

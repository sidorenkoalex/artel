## Замечания

- **major — orchestrator/artel.py:450 (`git_diff_part`) — недекодируемые
  байты в diff роняют `run` трейсбеком: `UnicodeDecodeError` закрыт для
  артефактов (:419) и оставлен на пути diff, то есть на самой большой части
  пакета.** Итерация закрывала ровно этот класс ошибки, но только в
  `artifact_text`. `git()` (:1030) ловит `OSError`, а декодирование живёт
  внутри `subprocess.run(..., text=True)` (:1037) и бросает
  `UnicodeDecodeError` — не `OSError`. `artifact_text` это учитывает (:419),
  `git_diff_part` — нет; глобального перехвата в файле тоже нет (единственный
  `except Exception` — :390, в перекачке лога).

  Сценарий поломки — обычный коммит, а не порча данных. git считает файл
  бинарным по NUL-байту в первых 8 КБ; текстовый файл в cp1251/latin-1 без
  NUL под это не подпадает, и git выкладывает его байты в diff как текст.
  Воспроизвёл на временном репозитории в песочнице (рабочее дерево не
  тронуто): ветка добавляет один файл со строкой
  `caf\xe9 na\xefve r\xe9sum\xe9 stra\xdfe`, NUL в файле нет,
  `git diff --stat` показывает `latin.txt | 1 +`, а вызов даёт

  ```
  >>> git_diff_part на ветке с latin-1 файлом:
     ИСКЛЮЧЕНИЕ: UnicodeDecodeError -> 'utf-8' codec can't decode byte 0xe9 in position 127
  >>> review_package целиком:
     ИСКЛЮЧЕНИЕ: UnicodeDecodeError -> 'utf-8' codec can't decode byte 0xe9 in position 127
     последний кадр в artel.py: line 1037, in git
  ```

  Последствия хуже, чем у закрытого минора про артефакт. В `cmd_run` сборка
  стоит **до** записи в журнал (:800), поэтому `run <id>` в состоянии `review`
  падает питоновским стеком, не оставив ни строки в `log <id>`: задача висит в
  `review`, повторный `run` падает так же, а причина — в одном файле ветки,
  который ничем себя не выдаёт. Это прямо противоположно принципу, который
  PLAN объявляет своим («молчание не выдаётся за пустоту», у каждого сбоя
  названа причина): `git_diff_part` обещает в docstring, что не ответивший git
  становится частью пакета с причиной, и для этого случая обещание не
  выполняется. Досягаемость: артефакты пишет сам оркестратор и они всегда
  UTF-8 — а diff покрывает любой файл, которого коснулся разработчик, поэтому
  поверхность здесь несопоставимо шире, чем у уже закрытого минора; именно
  поэтому оцениваю как major, хотя класс ошибки тот же.
  Предложение: обернуть вызов в `git_diff_part` так же, как в `artifact_text`
  (`except UnicodeDecodeError` → `(не собран: <причина>)`, причина уедет в
  `not_collected` и в журнал существующим путём). Правка `git()` целиком
  (`errors="replace"`) шире зоны задачи — это чужой хелпер, им пользуются
  уборка и мерж. Тест: заставить `FakeGit` бросать `UnicodeDecodeError` —
  сейчас фейк на такое не способен, поэтому дефект и не виден набору.

- **minor — tests/test_review_package.py:582 — docstring теста противоречит
  собственной фикстуре: обещает, что подмены `ROOT` не требуется, а `setUp`
  (:495–512) её как раз делает.** `test_worktree_fallback_is_journaled`
  говорит: «этот файл лежит в рабочем дереве репозитория всегда, так что
  подмены `ROOT` тест не требует». На итерации 3 `setUp` подменил `ROOT` на
  песочницу и копирует туда `skills/` и `templates/` — откат читает
  `templates/REVIEW.md` из копии, а не «из рабочего дерева репозитория».
  Сценарий: следующий, кто будет чистить фикстуру, прочитает этот docstring,
  сочтёт `copytree` для `templates/` лишним и снесёт его — тест упадёт, и
  упадёт не там, где его сломали. Предложение: переписать второй абзац под
  фактическую фикстуру (файл есть в песочнице, потому что `setUp` его туда
  копирует) — правка комментария, кода не касается.

- **minor — tasks/T011/PLAN.md, «Влияние на систему» — счёт тестов не
  сходится сам с собой: «192 против 156 на main, из них 37 новых, минус
  ноль».** 156 + 37 = 193, а в ветке 192. Пересчитал по `git show <ref>:<файл>`
  для всех модулей `tests/`: на `main` 155, в ветке 192, новых в
  test_review_package.py — 37; 155 + 37 = 192 сходится. Прошлое ревью тоже
  считало 155. Сценарий: это единственное место, где «ни один тест не
  потерян» выражено числом, и Оператор проверяет принцип целостности именно
  по нему; расхождение на единицу заставляет пересчитывать всё вручную и
  выглядит как потерянный тест. Предложение: 156 → 155.

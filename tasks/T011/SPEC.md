# SPEC: Ревью-пакет вместо свободного чтения репозитория

## Контекст
Прогон ревьювера стоит $2.4–3.6 и до 2.2M токенов: миссия говорит
«тебе доступны только SPEC, PLAN и diff», но технически агент свободно
читает репозиторий и делает это широко. Основной расход — блуждание
по файлам, не относящимся к diff. При этом качество ревью терять
нельзя: право исполнять проверки (тесты, мутанты — как в T010) —
доказанная ценность, его не трогаем.

## Требования
1. Перед запуском ревьювера оркестратор собирает **ревью-пакет** и
   включает его в промпт целиком: заголовок задачи; SPEC.md; PLAN.md;
   текущий REVIEW.md (если есть, для итераций); список изменённых
   файлов со статистикой (`git diff --stat main...<branch>`); полный
   diff (`git diff main...<branch>`).
2. Пакет ограничен: если diff больше разумного потолка (например
   4000 строк — константа), в промпт идут стат-список и усечённый diff
   с явной пометкой об усечении; сам факт гигантского diff — сигнал
   ревьюверу для замечания о размере изменения.
3. Миссия ревьювера переписывается: работать от пакета; читать файлы
   репозитория сверх пакета — точечно и только когда это нужно для
   проверки конкретного замечания (с называнием причины в REVIEW,
   раздел «Замечания» это уже позволяет); скилы роли остаются
   в промпте как сейчас.
4. Права и инструменты ревьювера не сужаются: запуск тестов и
   исполняемые проверки (включая мутационные) остаются доступными.
5. Размер собранного пакета (символы/строки diff) пишется в журнал
   шагов при старте ревью — чтобы стоимость прогона можно было
   соотносить с размером входа.
6. Юнит-тесты в tests/: сборка пакета (все части на месте, порядок
   стабилен), усечение большого diff с пометкой, запись размера
   в журнал. Без реального CLI.

## Критерии приёмки
1. В промпте ревьювера (проверяется юнит-тестом сборки) присутствуют
   SPEC, PLAN, стат-список и diff; при diff > потолка — усечение
   с пометкой.
2. В `log <id>` у старта ревью виден размер пакета.
3. Фактический эффект: ревью-прогон этой же задачи (T011) дешевле
   среднего исторического ($2.4+) — проверяется по журналу после
   прогона; если нет — в PLAN/REVIEW должно быть объяснение почему
   (это наблюдение приёмки, не автотест).
4. `python3 -m unittest discover -s tests` зелёный, guard и CI зелёные.

## Не входит
- Сужение инструментов/прав ревьювера (allowedTools не меняется).
- Изменение миссии и контекста разработчика.
- Кэширование пакета между итерациями.

# ТЗ: Удержанный doc-commit сверяется с базой, на которой собран; команда снять одну удержанную запись

Источник: строка копилки 02.10 (П2) «Удержанный doc-commit, собранный до правки файла задачей, после pin-update ушёл в main и стёр чужие строки»; решение Оператора 02.10.

Факты (origin/main 28b09389; номера строк аналитик сверяет):
- `doc-commit` в окне тишины удерживает запись: `orchestrator/notes.py::_hold_pending` (около строки 255) пишет JSON `{kind, path, content, message}` в `.artel/notes-pending/`. Базы, на которой собран `content`, запись не хранит.
- При отправке `_build_doc_commit` (около строки 648) сравнивает blob пути в свежем `FETCH_HEAD` с blob в HEAD главной копии (пин) и отказывает «файл изменился в origin после пина — сначала pin-update».
- 02.10: запись `docs/operator-session.md` собрана в 11:10Z на версии файла 0915d6bc. Затем задача 01M3VFYP4RXBY0BG8D3A0B18HD добавила в файл 24 строки. Пока пин отставал, отправка отказывала; после `pin-update` на голову с этими строками пин и origin совпали, сверка прошла, и запись ушла коммитом 28b09389 — 21 строка задачи стёрта. Восстановлено трёхсторонним слиянием и повторным `doc-commit` (6704ef12) после второго `pin-update`.
- Новая запись того же пути заменила удержанную, но удержанная успела уйти первой при оппортунистической отправке. Команды снять одну удержанную запись нет (`note --drop` относится к строкам бэклога).

Требуется:
1. Удержанная запись `doc-commit` хранит blob-sha пути, на котором собрано содержимое (база: blob в HEAD главной копии в момент вызова; для нового файла — отметка «файла не было»).
2. При отправке удержанной записи blob пути в свежем `origin` сверяется с сохранённой базой; не совпал — именованный отказ «файл изменился в origin после сборки записи (база <sha>, origin <sha>) — собери заново от origin», запись остаётся удержанной, остальные записи отправляются. Прежняя сверка с пином сохраняется для немедленной (неудержанной) отправки.
3. Новая команда `note --pending` перечисляет удержанные записи (id файла, вид, путь или раздел, время, первые 80 знаков); `note --drop-pending <id>` снимает одну удержанную запись с записью в журнал (какая, кем). Обе — команды Оператора (отказ из-под роли, как у `note`).
4. Записи, удержанные до этой задачи (без базы), при отправке сверяются по-старому и печатают предупреждение «база не сохранена».
5. Тесты в новом файле `tests/test_doc_commit_held_base.py`, каждый с «Ловит мутацию: …»: сценарий 02.10 (запись собрана, файл изменён в origin, пин сдвинут) — отказ, файл в origin не тронут; база совпала — отправка; новый файл; `--pending` перечисляет; `--drop-pending` снимает одну запись и пишет журнал; старая запись без базы — предупреждение.

Зоны: orchestrator/notes.py, orchestrator/artel.py, tests/test_doc_commit_held_base.py, docs/codebase-map.md.

Только чтение (не менять): orchestrator/store.py, orchestrator/config.py, orchestrator/merge_lock.py, остальные файлы tests/, skills/, docs/adr/, docs/invariants.md, tests/test_invariants.py, tasks/.

Не входит: правка docs/operator-session.md (описание команд — отдельно Оператором); формат каталога .artel/notes-pending/ кроме нового поля базы; автоматическое слияние удержанного содержимого с новой версией origin; изменение окна тишины.

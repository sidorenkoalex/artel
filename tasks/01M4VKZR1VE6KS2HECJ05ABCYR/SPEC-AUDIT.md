# SPEC-AUDIT: Допуск нескольких пар и правка набора одним коммитом

Повторный аудит после возврата SPEC с гейта (решение Оператора №1: О-1,
О-2, О-3). ANSWER-n.md у задачи нет.

## ТЗ и SPEC
ТЗ → SPEC:
- ТЗ п.1 (несколько пар; одна пара — байт в байт) → SPEC треб. 1, AC-1, AC-2.
  Форма выбрана (повтор позиционной пары) — ТЗ это разрешает.
- ТЗ п.2 (сверка всех пар, сводка по каждой, отказ с перечнем по каждой,
  всё или ничего, `--revoke` одной записью) → треб. 2, AC-2, AC-3, AC-4.
  Отклонение по проверяемости «по каждой недобравшей паре» — см. К-1.
- ТЗ п.3 (`--set`, создание набора, прочие роли не меняются, отказ при
  недопущенной паре) → треб. 3, AC-5, AC-6.
- ТЗ п.4 (один коммит, один прогон гейта, сообщение — все пары и набор,
  общее `--basis`) → треб. 4, AC-2, AC-5.
- ТЗ п.5 (справка) → треб. 5, AC-9. ТЗ называет `ADMIT_USAGE` «строкой в
  orchestrator/artel.py», в коде константа в orchestrator/models.py:1054;
  SPEC верно называет оба места (models.py:1054, artel.py:177, 252-260).
- ТЗ п.6 (шесть групп тестов) → треб. 6, все шесть перечислены.
- Матрица ТЗ (числа ADR-0019 п.5 по каждой паре; гейт полного набора на
  итоговом дереве; набор не ссылается на недопущенную пару) → треб. 2, 4, 3.

Решение Оператора на гейте SPEC №1:
- О-1 (приостановка пультом в отказе `--set`, тест на приостановленную
  пару, отсылка «в смысле пункта (а)») — отражено: треб. 3 называет
  `pair_suspension_refusal` и строки models.py:1244-1247, 1263-1264;
  AC-6 случай (2) — приостановленная пара, в том числе названная в вызове.
- О-2 (ноль пар — отказ разбора с `ADMIT_USAGE`) — отражено: треб. 1, AC-7
  (включая `--set` без пар).
- О-3 (две пары одной роли при `--set`) — отражено отдельным AC-8.

SPEC → ТЗ: сверх ТЗ — только отказ «две пары одной роли при `--set`» и
отказ «ноль пар» (оба — решение Оператора №1) и исключение пар с боевой
моделью из проверки набора (следует из действующего `set_admitted`,
models.py:1260-1262). Новых требований без источника нет.

## Проверяемость критериев

| Критерий | Проверяем | Ловимая мутация |
|---|---|---|
| AC-1 | да | смена текста сводки/отказа/сообщения коммита для одной пары (например «допуск пар …» вместо «допуск пары …»); лишняя строка stdout |
| AC-2 | да | коммит на каждую пару (два вызова `doc_commit_content`); основание только у первой пары; сообщение без второй пары |
| AC-3 | частично | ловит запись прошедших пар при недоборе другой; НЕ ловит выход по первой недобравшей паре с перечнем только её и без сводки остальных — в AC одна недобравшая пара (К-1) |
| AC-4 | да | `--revoke` только первой пары; коммит на пару |
| AC-5 | да | перезапись набора целиком (теряются прочие роли); набор отдельным вызовом `doc_commit_content`; сообщение без имени набора |
| AC-6 | частично | ловит пропуск `pair_suspension_refusal` (случай 2); случай (1) не обязывает, чтобы недопущенная пара была ролью набора, НЕ названной в вызове — мутация «проверять только названные пары» проходит (К-2) |
| AC-7 | да | молчаливое отбрасывание лишнего аргумента; `--set` без пар пишет пустой/ничего не меняющий коммит |
| AC-8 | да | «последняя пара роли побеждает» в наборе вместо отказа |
| AC-9 | да | справка/`ADMIT_USAGE` без `--set` или без повтора пары |
| (нет AC) | нет | исключение пар с боевой моделью из проверки набора (треб. 3) не проверяется: мутация «требовать запись `pairs:` и для боевой модели» не ловится ни одним AC (К-3) |

## Пути обхода гейтов
- Сверка набора до записи могла бы смотреть исходный документ (без пар
  этого вызова) или итоговый — SPEC говорит «после записи» (треб. 3), AC-6
  (2) ловит случай названной допущенной, но приостановленной пары. Обход
  «проверять только названные пары» не закрыт AC — К-2.
- «Одна запись» могла бы исполняться коммитом с прогоном только на первой
  правке и `--accept-red` — `cmd_admit` флагов обхода гейта не передаёт
  (models.py:1891-1893), SPEC новых не вводит; путь не открыт.
- `admit --revoke --set <имя> …` — комбинация в SPEC не оговорена; по
  треб. 3 пары не-боевых моделей после снятия не допущены → отказ, т.е.
  набор на приостановленную пару не пишется. Обхода нет; комбинация
  тестом не закреплена (замечание, не отклонение).

## Вердикт
concerns — все три пункта решения Оператора №1 отражены (треб. 1, 3;
AC-6, AC-7, AC-8); остаются отклонения проверяемости, решаемые на гейте:

- К-1. SPEC.md:35-39 (треб. 2: «перечень недостающего по каждой
  недобравшей паре», сводка «по каждой паре») против SPEC.md:80-83
  (AC-3: одна недобравшая пара). Мутация «выход на первой недобравшей
  паре» (models.py:1872-1875 в цикле как есть) проходит AC-3, если
  недобравшая пара в вызове одна; при недобравшей первой паре не
  печатается и сводка второй. Предложение: в AC-3 две недобравшие пары
  (обе названы в перечне) и сводка по каждой паре вызова до отказа.
- К-2. SPEC.md:94-101 (AC-6 случай (1)) не требует, чтобы недопущенная
  пара была ролью существующего набора, не названной в вызове; при
  `--revoke --set` или подходящем тесте мутация «проверять только пары
  вызова» проходит, а ТЗ п.3 и матрица ТЗ («набор не может сослаться на
  недопущенную пару») касаются всех пар набора после записи.
  Предложение: в AC-6 (1) — роль набора вне вызова с недопущенной парой.
- К-3. SPEC.md:52-53 «Пары с боевой моделью роли проверку не проходят,
  как и сейчас» двусмысленно («не проходят проверку» читается и как
  «проваливают»); по коду (models.py:1261-1262) такие пары из проверки
  исключены. AC на это нет — мутация «требовать `pairs:` и для боевой
  модели» не ловится. Предложение: переформулировать «из проверки
  исключены» и добавить случай в AC-5 (пара/роль набора на боевой модели
  без записи `pairs:` — запись проходит).

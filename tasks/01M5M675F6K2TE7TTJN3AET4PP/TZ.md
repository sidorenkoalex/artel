## Требуется

1. Уборка ссылки вместе с веткой: в `cleanup.cleanup_merged_remote` у задачи артели (признак проекта задачи из repo_context, как в соседней `cleanup_project_remote`) после исхода «ветка origin <ветка>: удалена» или «ветка origin <ветка>: нет — удалять нечего» пульт снимает ссылку `refs/remotes/origin/<ветка>` главной копии, если она есть: чтение её sha (`rev-parse --verify --quiet refs/remotes/origin/<ветка>`); ссылка считается существующей, только если вывод — ровно 40 шестнадцатеричных знаков; пустой вывод, иной вывод или код возврата не 0 — ссылки нет. Затем `update-ref -d refs/remotes/origin/<ветка> <sha>` — только локальные вызовы git в корне пульта, без сети, и только через `gitcmd.in_repo` (прямой `subprocess` не допускается). Исход — отдельная запись журнала задачи с действием `cleanup.MAIN_COPY_REF_ACTION = "уборка: ссылка главной копии"` и деталью «ссылка главной копии origin/<ветка>: убрана» либо «ссылка главной копии origin/<ветка>: оставлено — <причина>»; та же строка печатается с отступом в два пробела после исхода ветки. Ссылки нет — ни записи, ни строки вывода. Исход ветки «оставлено» — ссылка не трогается. Перед снятием ссылки (и здесь, и в `prune`) пульт проверяет, что её sha влит в `refs/remotes/origin/main` главной копии: `merge-base --is-ancestor <sha> refs/remotes/origin/main` локально, без сети; код 0 — ссылка снимается, иначе (не предок или git не ответил) — исход «ссылка главной копии origin/<ветка>: оставлено — не влита» (или «— git не ответил: <ошибка>»), ссылка цела. Любое исключение уборки ссылки — исход «оставлено» с причиной; мерж и запись «уборка» не срываются. У внешнего проекта и на пути `kill` — без изменений.
2. Новая функция модуля `cleanup.drop_main_copy_tracking_ref(branch: str) -> str | None` выполняет шаг требования 1 и возвращает строку исхода (`None` — ссылки нет); её же зовёт `prune` (требование 3).
3. `prune`, вид «ссылки origin/task главной копии»: перечень ссылок даёт `for-each-ref refs/remotes/origin/task/` корня пульта (через `gitcmd.in_repo`); если этот вызов не удался — вид считается пустым: строки отчёта нет, удалять нечего, `ls-remote` не вызывается. Кандидаты — ссылки из перечня, у которых в `origin` нет ветки `refs/heads/task/…` с тем же именем и ветка не принадлежит незакрытой задаче (колонка `branch` задачи в состоянии, отличном от `done`/`killed`). Состав веток `origin` читает новая функция `prune._origin_task_heads() -> tuple[set[str] | None, str]` одним вызовом `ls-remote origin "refs/heads/task/*"` из корня пульта с пределом времени (`-c http.lowSpeedLimit=1 -c http.lowSpeedTime=<GH_TIMEOUT_SEC>`, тот же приём предела, что у пуша удаления ветки в cleanup.py); `None` и причина — git не ответил или вернул ошибку: вид пропускается строкой отчёта «ссылки origin/task главной копии: пропущено — <причина>», ничего не удаляется. Ссылок `refs/remotes/origin/task/*` в главной копии нет — `ls-remote` не вызывается, строки нет. Исполнение — `cleanup.drop_main_copy_tracking_ref` по каждой; ссылка, чей sha не влит в `refs/remotes/origin/main` (требование 1), остаётся строкой отчёта `  ссылка главной копии origin/<ветка> оставлено — не влита` и в план снятия не входит.
4. `prune`, вид «бесхозные каталоги .artel/worktrees»: кандидаты — элементы каталога `WORKTREES`, которые являются каталогами (не символическими ссылками), чьё имя не равно id незакрытой задачи пульта и чей путь (сравнение по `Path.resolve()`) не входит ни в `workspace.registered_paths(<корень пульта>)`, ни в `workspace.registered_paths()` (клон артели). Если любой из двух перечней пуст (git не ответил) — вид пропускается строкой «каталоги .artel/worktrees: пропущено — git worktree list не ответил», ничего не удаляется. Каталога `WORKTREES` нет или в нём нет ни одного кандидата по признакам имени и типа — `git worktree list` не вызывается, строки нет. Удаление — каталог целиком, без перехода по символическим ссылкам.
5. Отчёт `prune` (тот же расчёт для плана и исполнения): строки `  ссылка главной копии origin/<ветка> будет убрана | убрана` и `  каталог .artel/worktrees/<имя> (<N> файлов) будет удалён | удалён`; сбой одного кандидата — строка с причиной, остальные продолжаются. «нечего убирать» — только когда пусты все виды и нет строк «пропущено». Прежние строки отчёта — побайтно.
6. `docs/retention.md`: в раздел «Ветки `task/*` пульта» — ссылка отслеживания главной копии снимается вместе с удалением ветки после мержа (требование 1), оставшиеся — `prune`; в раздел «Worktree задачи» — прежнее место `.artel/worktrees/` и правило уборки бесхозных каталогов командой `prune` (требование 4).
7.

# SPEC: Ссылки origin/task главной копии — уборка в pin-update; бесхозные каталоги .artel/worktrees — уборка командой prune

## Контекст
Находка ревизии кода 22.10 CR-2026-10-22-10. После мержа ветка задачи удаляется в `origin`
пушем из клона проекта задачи (`orchestrator/cleanup.py:356` `cleanup_merged_remote`), и
этот пуш снимает ссылку отслеживания только в клоне. В главной копии (корень пульта) ссылки
`refs/remotes/origin/task/*` копятся: на 23.10 их 11, все у закрытых задач, ни одной из этих
веток в `origin` нет. Кроме того, в прежнем месте рабочих копий `.artel/worktrees/`
(`orchestrator/config.py:110`, `WORKTREES`) лежат 242 бесхозных каталога, ни один не
зарегистрирован в `git worktree list`.

Решение Оператора на гейте SPEC 23.10 (круг 1): git главной копии меняет только `pin-update`
(инвариант 40, `docs/invariants.md:70`, не меняется). Поэтому ссылки origin без ветки на
origin снимает `pin-update` после успешного сдвига пина. Ни мерж, ни `prune` git главной
копии не трогают. `prune` получает один новый вид — бесхозные каталоги `.artel/worktrees`.

## Требования
1. `pin.cmd_pin_update` после успешного сдвига пина выполняет в главной копии
   `git remote prune origin` через `gitcmd`:
   - уборка — последнее действие команды, когда пин уже сдвинут (после записи журнала
     «pin обновлён» и отчёта о циклах на коде старше пина);
   - при успехе печатается строка исхода «ссылки origin без ветки на origin сняты: N», где
     N — число строк вывода git, содержащих `[pruned]`;
   - если git не ответил или вернул ошибку, печатается строка предупреждения «уборка ссылок
     origin не выполнена: <причина>»;
   - сбой уборки сдвиг пина не отменяет и код выхода команды не меняет;
   - при любом отказе `pin-update` (fetch, канарейка, CI, `merge --ff-only`) уборка не
     вызывается;
   - отдельного предела времени у вызова нет: действует общий порядок вызова `gitcmd`.
2. `prune`, вид «бесхозные каталоги .artel/worktrees»:
   - кандидаты — элементы каталога `WORKTREES`, которые:
     - являются каталогами (не символическими ссылками);
     - имеют имя, не равное id незакрытой задачи пульта (состояние не `done`/`killed`);
     - имеют путь (сравнение по `Path.resolve()`), не входящий ни в перечень рабочих копий
       главной копии (корня пульта), ни в перечень рабочих копий клона артели
       (`git worktree list`, как в `workspace.registered_paths`);
   - если хотя бы один из двух перечней не получен (git не ответил или вернул ошибку), вид
     пуст: ничего не удаляется, печатается строка «каталоги .artel/worktrees: пропущено —
     git worktree list не ответил»;
   - перечень, полученный от git, допустим и пустым;
   - если каталога `WORKTREES` нет или в нём нет ни одного кандидата по признакам имени и
     типа, `git worktree list` не вызывается и строки вида нет;
   - каталоги `.artel/worktrees` без `.git` удаляются без проверки несохранённой работы
     (решение ТЗ п. 4, подтверждено Оператором 23.10);
   - удаляется каталог целиком, без перехода по символическим ссылкам. Используется
     существующий `_remove_dirs`, без дублирования.
3. Отчёт `prune` строится одним расчётом для плана и для исполнения:
   - строка кандидата — `  каталог .artel/worktrees/<имя> (<N> файлов) будет удалён | удалён`;
   - при сбое удаления каталога — строка `  каталог .artel/worktrees/<имя>: не удалён —
     <причина>`, остальные кандидаты продолжаются;
   - «нечего убирать» печатается, только когда все виды пусты и нет строки «пропущено»;
   - прежние строки отчёта остаются побайтно прежними.
4. `docs/retention.md`:
   - раздел «Ветки `task/*` пульта» — ссылки отслеживания `origin` главной копии, ветки
     которых в `origin` больше нет, снимает `pin-update` (`git remote prune origin`), не
     `prune`;
   - раздел «Worktree задачи» — прежнее место `.artel/worktrees/` и правило уборки бесхозных
     каталогов командой `prune` (требование 2). Фраза «`prune` этого вида не касается»
     заменяется этим правилом.
5. Тесты — детерминированные, без внешней сети:
   - на настоящем git: bare-`origin` и главная копия песочницы, по образцу
     `AutoOriginSandbox`/`RealGitSandbox` из `tests/sandbox.py`;
   - разрешённые подмены: `workspace.registered_paths`, `gitcmd.in_repo`, а также запуск
     git и проверки канарейки/CI в `pin` (шпион — для критерия «уборка не вызвана»).

## Критерии приёмки

AC-1. Песочница с bare-`origin`, где у главной копии есть `refs/remotes/origin/task/<x>`,
ветки которой в bare-`origin` нет, и `refs/remotes/origin/task/<y>`, чья ветка в
bare-`origin` есть. После успешного `pin-update`:
- ссылки `refs/remotes/origin/task/<x>` нет;
- `refs/remotes/origin/task/<y>` и `refs/remotes/origin/main` на месте;
- напечатана строка «ссылки origin без ветки на origin сняты: 1»;
- пин сдвинут.

AC-2. Подменённый сбой `git remote prune origin` (git не ответил или вернул ошибку) при
`pin-update`:
- пин сдвинут, запись журнала «pin обновлён» есть;
- напечатана строка «уборка ссылок origin не выполнена: <причина>»;
- код выхода 0.

AC-3. Отказ `pin-update` по канарейке (нет зелёного прогона): шпион фиксирует, что
`remote prune` не вызван.

AC-4. `prune` без `--execute`: бесхозный каталог в плане строкой
`  каталог .artel/worktrees/<имя> (<N> файлов) будет удалён`, ничего не удалено.
После `prune --execute` каталог удалён, строка «удалён». При обоих прогонах остаются целы:
- каталог с именем незакрытой задачи;
- рабочая копия, зарегистрированная в главной копии;
- рабочая копия, зарегистрированная в клоне артели;
- символическая ссылка в `.artel/worktrees/` (и её цель).

AC-5. Сбой удаления одного каталога при `prune --execute`: строка
`  каталог .artel/worktrees/<имя>: не удалён — <причина>`, остальные кандидаты удалены.

AC-6. Перечень рабочих копий не получен (подмена `gitcmd.in_repo` отвечает сбоем на
`worktree list`):
- не получен перечень главной копии, а каталог зарегистрирован в перечне клона артели —
  каталог не удалён, строка «каталоги .artel/worktrees: пропущено — git worktree list не
  ответил»;
- то же при неполученном перечне клона артели;
- ни один каталог вида не удалён, «нечего убирать» не печатается.
Мутация «пропуск только при обоих неполученных перечнях» даёт красный тест.

AC-7. Пустые виды `prune`:
- каталога `WORKTREES` нет и, отдельным случаем, в нём нет кандидатов по имени и типу —
  `git worktree list` не вызван, строки вида нет;
- на песочнице без логов и каталогов `prune` по-прежнему печатает «нечего убирать».

AC-8. `docs/retention.md`:
- раздел «Ветки `task/*` пульта» называет снятие ссылок отслеживания `origin` главной копии
  командой `pin-update` (`git remote prune origin`);
- раздел «Worktree задачи» называет прежнее место `.artel/worktrees/` и уборку бесхозных
  каталогов командой `prune`;
- фразы «`prune` этого вида не касается» в документе нет.

## Оценка объёма и деление
Сработавший сигнал — «число затрагиваемых модулей/файлов». Сигнал даёт маска каталога
`tests/` в зонах. Фактически меняются два модуля кода (`orchestrator/pin.py`,
`orchestrator/prune.py`) и один документ (`docs/retention.md`), а также добавляются новые
файлы тестов в `tests/`. Существующие тесты не правятся. Зона `orchestrator/pin.py` задевает
механизм инварианта 40 (`docs/invariants.md:70`): правка остаётся внутри `pin-update`,
которому инвариант и разрешает менять git главной копии (матрица ANSWER-1). Остальные
сигналы не срабатывают: 8 критериев приёмки, `budget_usd` 25, слов-маркеров объёма нет.

Прогноз диффа: 25 КиБ.

Нарезка возможна по границе `pin.py` (требование 1) / `prune.py` + `docs/retention.md`
(требования 2–4). Обе части малы, а две подзадачи удвоили бы постоянную цену шагов
(аналитик, автор тестов, ревью). Бюджет ТЗ ($25) рассчитан на одну задачу; требование 4
описывает обе части одним документом.

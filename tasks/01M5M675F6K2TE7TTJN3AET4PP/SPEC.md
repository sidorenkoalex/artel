# SPEC: Ссылки origin/task главной копии и бесхозные каталоги .artel/worktrees — уборка вместе с веткой и командой prune

## Контекст
Находка ревизии кода 22.10 CR-2026-10-22-10. После мержа ветка задачи удаляется в `origin`
пушем из клона проекта задачи (`orchestrator/cleanup.py:356` `cleanup_merged_remote` →
`:329` `_merged_remote_outcome` → `:260` `_delete_origin_branch`). Этот пуш снимает ссылку
отслеживания только в клоне. В главной копии (корень пульта) — отдельном репозитории с
тем же `origin` — ссылки `refs/remotes/origin/task/*` копятся: на 23.10 их 11, все у
закрытых задач. Кроме того, в прежнем месте рабочих копий `.artel/worktrees/`
(`orchestrator/config.py:110`, `WORKTREES`) лежат 242 бесхозных каталога, и ни один не
зарегистрирован в `git worktree list`. Задача: снимать ссылку главной копии вместе с
удалением ветки после мержа, а оставшиеся ссылки и бесхозные каталоги убирать командой
`prune`.

## Требования
1. В `cleanup.cleanup_merged_remote` у задачи артели (признак проекта задачи берётся из
   `repo_context`, как в `cleanup_project_remote`) после исхода ветки «ветка origin
   <ветка>: удалена» или «ветка origin <ветка>: нет — удалять нечего» пульт снимает ссылку
   `refs/remotes/origin/<ветка>` главной копии, если она есть:
   - sha ссылки читается командой `rev-parse --verify --quiet refs/remotes/origin/<ветка>`.
     Ссылка существует, только если вывод — ровно 40 шестнадцатеричных знаков. Пустой
     вывод, иной вывод или код возврата не 0 означают, что ссылки нет;
   - перед снятием проверяется, что sha влит: `merge-base --is-ancestor <sha>
     refs/remotes/origin/main` главной копии. Код 0 — ссылка снимается. Не предок —
     исход «ссылка главной копии origin/<ветка>: оставлено — не влита». Git не ответил —
     исход «ссылка главной копии origin/<ветка>: оставлено — git не ответил: <ошибка>».
     В обоих случаях ссылка цела;
   - снятие — `update-ref -d refs/remotes/origin/<ветка> <sha>`;
   - все вызовы git — только локальные, в корне пульта, без сети и только через
     `gitcmd.in_repo` (прямой `subprocess` не допускается);
   - исход пишется отдельной записью журнала задачи с действием
     `cleanup.MAIN_COPY_REF_ACTION = "уборка: ссылка главной копии"` и деталью «ссылка
     главной копии origin/<ветка>: убрана» либо «ссылка главной копии origin/<ветка>:
     оставлено — <причина>». Та же строка печатается с отступом в два пробела после
     строки исхода ветки;
   - ссылки нет — нет ни записи, ни строки вывода;
   - исход ветки «оставлено» — ссылка не трогается;
   - любое исключение уборки ссылки даёт исход «оставлено» с причиной; мерж и запись
     «уборка» при этом не срываются;
   - у внешнего проекта и на пути `kill` поведение не меняется.
2. Шаг требования 1 выполняет новая функция модуля
   `cleanup.drop_main_copy_tracking_ref(branch: str) -> str | None`. Она возвращает строку
   исхода, а `None` — когда ссылки нет. Её же зовёт `prune` (требование 3).
3. `prune`, вид «ссылки origin/task главной копии»:
   - перечень ссылок даёт `for-each-ref refs/remotes/origin/task/` в корне пульта (через
     `gitcmd.in_repo`). Если этот вызов не удался, вид пуст: строки отчёта нет, удалять
     нечего, `ls-remote` не вызывается;
   - кандидаты — ссылки из перечня, у которых в `origin` нет ветки `refs/heads/task/…` с
     тем же именем и чья ветка не принадлежит незакрытой задаче (колонка `branch` задачи в
     состоянии, отличном от `done`/`killed`);
   - состав веток `origin` читает новая функция
     `prune._origin_task_heads() -> tuple[set[str] | None, str]`. Она делает один вызов
     `ls-remote origin "refs/heads/task/*"` из корня пульта с пределом времени
     `-c http.lowSpeedLimit=1 -c http.lowSpeedTime=<GH_TIMEOUT_SEC>` — тот же приём, что у
     пуша удаления ветки в `cleanup.py`. Если git не ответил или вернул ошибку, функция
     возвращает `None` и причину. Тогда вид пропускается строкой отчёта «ссылки
     origin/task главной копии: пропущено — <причина>», и ничего не удаляется;
   - если ссылок `refs/remotes/origin/task/*` в главной копии нет, `ls-remote` не
     вызывается и строки нет;
   - исполнение — `cleanup.drop_main_copy_tracking_ref` по каждой ссылке. Ссылка, чей sha
     не влит в `refs/remotes/origin/main`, в план снятия не входит и остаётся строкой
     отчёта `  ссылка главной копии origin/<ветка> оставлено — не влита`.
4. `prune`, вид «бесхозные каталоги .artel/worktrees»:
   - кандидаты — элементы каталога `WORKTREES`, которые:
     - являются каталогами (не символическими ссылками);
     - имеют имя, не равное id незакрытой задачи пульта;
     - имеют путь (сравнение по `Path.resolve()`), не входящий ни в
       `workspace.registered_paths(<корень пульта>)`, ни в `workspace.registered_paths()`
       (клон артели);
   - если любой из двух перечней пуст (git не ответил), вид пропускается строкой
     «каталоги .artel/worktrees: пропущено — git worktree list не ответил», и ничего не
     удаляется;
   - если каталога `WORKTREES` нет или в нём нет ни одного кандидата по признакам имени и
     типа, `git worktree list` не вызывается и строки нет;
   - удаляется каталог целиком, без перехода по символическим ссылкам. Используется
     существующий `_remove_dirs`, без дублирования.
5. Отчёт `prune` строится одним расчётом для плана и для исполнения. Строки отчёта:
   - `  ссылка главной копии origin/<ветка> будет убрана | убрана`;
   - `  каталог .artel/worktrees/<имя> (<N> файлов) будет удалён | удалён`.

   Сбой одного кандидата даёт строку с причиной, остальные кандидаты продолжаются.
   «нечего убирать» печатается, только когда пусты все виды и нет строк «пропущено».
   Прежние строки отчёта остаются побайтно прежними.
6. `docs/retention.md`:
   - в раздел «Ветки `task/*` пульта» — ссылка отслеживания главной копии снимается вместе
     с удалением ветки после мержа (требование 1), оставшиеся убирает `prune`;
   - в раздел «Worktree задачи» — прежнее место `.artel/worktrees/` и правило уборки
     бесхозных каталогов командой `prune` (требование 4).
7. Тесты — детерминированные, без внешней сети:
   - на настоящем git: bare-`origin` и главная копия песочницы, по образцу
     `AutoOriginSandbox`/`RealGitSandbox` из `tests/sandbox.py` и `MergedRemoteSandbox`;
   - для сценария мержа главная копия (корень пульта) — отдельный репозиторий от клона
     артели `.artel/projects/<проект>/repo`. Оба смотрят в один bare-`origin`, а ссылка
     главной копии заведена через `fetch`. `MergedRemoteSandbox` с клоном, равным корню,
     для этого не годится: там красный случай не воспроизводится;
   - разрешённые подмены: `prune._origin_task_heads`, `workspace.registered_paths`,
     `gitcmd.in_repo`, `cleanup.drop_main_copy_tracking_ref`.

## Критерии приёмки

AC-1. Мерж задачи артели на песочнице, где главная копия — отдельный от клона артели
репозиторий с общим bare-`origin` и с `refs/remotes/origin/<ветка>`, заведённой через
`fetch`. После `cleanup_merged_remote`:
- ссылки `refs/remotes/origin/<ветка>` в главной копии нет;
- запись журнала «уборка» одна и прежняя («ветка origin <ветка>: удалена»);
- есть запись с действием `MAIN_COPY_REF_ACTION` («уборка: ссылка главной копии») и
  деталью «ссылка главной копии origin/<ветка>: убрана», та же строка напечатана с
  отступом в два пробела после строки исхода ветки;
- HEAD главной копии и её `refs/remotes/origin/main` не сдвинулись.

На текущем коде критерий красный: ссылка остаётся.

AC-2. Исход ветки «оставлено» (голова вне смерженного main): ссылка главной копии на месте,
записи `MAIN_COPY_REF_ACTION` нет.

AC-3. Ссылка главной копии указывает на коммит, которого нет в `refs/remotes/origin/main`
главной копии:
- в `cleanup_merged_remote` исход «ссылка главной копии origin/<ветка>: оставлено — не
  влита», ссылка цела;
- в `prune` строка `  ссылка главной копии origin/<ветка> оставлено — не влита`, и после
  `prune --execute` ссылка цела.

AC-4. Отсутствие ссылки определяется верно:
- `rev-parse` вернул код 0 с пустым выводом (заглушка в духе `SpyRun`) — ссылки нет:
  `update-ref` не вызывается, записи `MAIN_COPY_REF_ACTION` и строки вывода нет;
- ссылки в главной копии нет — записи и строки нет;
- у задачи внешнего проекта ссылка главной копии с тем же именем не трогается.

AC-5. Исключение внутри уборки ссылки главной копии (в том числе git не ответил на
`merge-base`) даёт исход «оставлено» с причиной («— git не ответил: <ошибка>» для
`merge-base`). Мерж и запись «уборка» не срываются, ссылка цела.

AC-6. `prune` без `--execute`:
- устаревшая ссылка закрытой задачи в плане строкой
  `  ссылка главной копии origin/<ветка> будет убрана`;
- бесхозный каталог в плане строкой
  `  каталог .artel/worktrees/<имя> (<N> файлов) будет удалён`;
- ничего не удалено.

После `prune --execute` эти ссылка и каталог удалены, строки «убрана»/«удалён». При обоих
прогонах остаются целы:
- ссылка незакрытой задачи;
- ссылка ветки, которая есть в `origin`;
- каталог с именем незакрытой задачи;
- зарегистрированная рабочая копия;
- символическая ссылка в `.artel/worktrees/`.

Сбой удаления одного кандидата даёт строку с причиной, остальные кандидаты обрабатываются.

AC-7. Сбои источников в `prune`:
- `ls-remote` (`prune._origin_task_heads`) не ответил — строка «ссылки origin/task главной
  копии: пропущено — <причина>», ни одна ссылка не удалена;
- `workspace.registered_paths` вернул пустой перечень — строка «каталоги .artel/worktrees:
  пропущено — git worktree list не ответил», ни один каталог не удалён;
- при наличии строки «пропущено» «нечего убирать» не печатается.

AC-8. Пустые виды `prune`:
- `for-each-ref` в корне пульта не удался — строки вида ссылок нет, ничего не удалено,
  `ls-remote` не вызван;
- ссылок `refs/remotes/origin/task/*` нет — `ls-remote` не вызван, строки нет;
- каталога `WORKTREES` нет и, отдельным случаем, в нём нет кандидатов по имени и типу —
  `workspace.registered_paths` не вызван, строки вида нет;
- на песочнице без логов, ссылок и каталогов `prune` по-прежнему печатает «нечего
  убирать».

AC-9. `docs/retention.md`:
- раздел «Ветки `task/*` пульта» называет снятие ссылки отслеживания главной копии вместе с
  удалением ветки после мержа и уборку оставшихся ссылок командой `prune`;
- раздел «Worktree задачи» называет прежнее место `.artel/worktrees/` и уборку бесхозных
  каталогов командой `prune`.

## Оценка объёма и деление
Сработавший сигнал — «число затрагиваемых модулей/файлов». Сигнал даёт маска каталога
`tests/` в зонах. Фактически меняются два модуля кода (`orchestrator/cleanup.py`,
`orchestrator/prune.py`) и один документ (`docs/retention.md`), а также добавляются новые
файлы тестов в `tests/`. Существующие тесты не правятся (ТЗ, требование 7). Остальные
сигналы не срабатывают: 9 критериев приёмки, `budget_usd` 25, слов-маркеров объёма в
тексте нет.

Прогноз диффа: 40 КиБ.

Нарезка возможна только по границе «уборка при мерже» (`cleanup.py`, требования 1–2) /
«`prune`» (`prune.py`, `docs/retention.md`, требования 3–6). Вторая часть напрямую
вызывает `cleanup.drop_main_copy_tracking_ref` первой. Каждая часть несла бы собственную
песочницу «главная копия + отдельный клон + bare-origin». Две подзадачи удвоили бы
постоянную цену шагов (аналитик, автор тестов, ревью) при общем объёме кода в двух
модулях. Бюджет ТЗ ($25) рассчитан на одну задачу.

Материал для решения Оператора — монолит: общая функция снятия ссылки и проверка
«влит в origin/main» — одна механика для обоих путей. Решение о монолите принимает
Оператор на гейте SPEC.

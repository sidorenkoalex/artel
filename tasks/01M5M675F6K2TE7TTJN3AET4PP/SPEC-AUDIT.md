- **Ф-2. ## Пути обхода гейтов
- **О-1 (Ф-1).** Исполнитель выполняет требование 1 буквально: `merge-base` против `refs/remotes/origin/main` главной копии без fetch. В тесте AC-1 он заводит ссылку главной копии fetch'ем после push мержа — AC-1 зелёный. На живом пульте после каждого мержа получится «оставлено — не влита», и цель «снимать ссылку вместе с веткой» не достигается. Что сверять (`merged_sha` из аргумента `cleanup_merged_remote`, объект которого есть только в клоне; локальный fetch главной копии из клона; иное), решает Оператор — ТЗ здесь прямо требует «локально, без сети».
- **О-2 (Ф-3, AC-9).** Требование 6 и AC-9 выполняются дописанным абзацем, а `docs/retention.md:112` «`prune` этого вида не касается» остаётся — документ сам себе противоречит, AC-9 проверяет только наличие нового правила.
- **О-3 (П-1).** `ls-remote` в `_origin_task_heads` без предела времени проходит все AC — `prune` может зависнуть на молчащем хостинге.
- **О-4 (AC-7).** Пропуск вида каталогов только когда пусты оба перечня `registered_paths` проходит AC-7, если тест опустошает оба вызова сразу. При пустом одном перечне каталог, зарегистрированный в нём, будет удалён — это рабочая копия, её удалять нельзя.
- **О-5.** Сухой прогон `prune` не может звать `drop_main_copy_tracking_ref` (она снимает ссылку). Исход «не влита» для плана исполнитель считает собственным `merge-base` в `prune.py`, а исполнение — внутри `drop_…`. SPEC.md:87 («одним расчётом») и :69–72 вместе не говорят, как свести эти два места. Расхождение плана и факта ловит только AC-3 на одном исходе. Кроме того, строка исхода `drop_…` («ссылка главной копии origin/<ветка>: убрана», с двоеточием) и строка отчёта `prune` («ссылка главной копии origin/<ветка> убрана», без двоеточия, SPEC.md:88) различаются: перевод исхода в строку отчёта не задан, для исхода «оставлено — git не ответил» в `prune` формат строки не назван (SPEC.md:91 «строка с причиной»).
- **О-6.** SPEC.md:92: печатается ли «нечего убирать», если в отчёте есть только строки «оставлено — не влита», не сказано. Текущий `_print_report` после «нечего убирать» выходит (`orchestrator/prune.py:249–252`) — строка «оставлено» тогда потерялась бы. AC-3 требует её напечатать, значит исполнитель вынужден решить сам. Прежний приём (`abolished_left` — непустой отчёт, `prune.py:249–250`) подсказывает ответ «не печатается», но SPEC его не фиксирует.

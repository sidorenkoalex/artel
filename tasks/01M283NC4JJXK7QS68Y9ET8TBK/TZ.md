# ТЗ: выход шага developer при грязном дереве: WIP-коммит кода пультом за роль

Источник: бэклог П1 (docs/backlog.md), слово Оператора 06.09 «заведи с
ближайшим приоритетом». Три случая за 05–06.09: developer «путей брифа»
(01M1RQ12JV…) и дважды developer P1a (01M1TKP6AA…) заканчивали ход с rc=0,
оставив код незакоммиченным (фоновый прогон тестов, «жду уведомления»):
PLAN со `status: ready` уходил в артефактную ветку, а код доезжал до
ветки только мостом Оператора.

Сверено с кодом 11.09: по rc=0 `orchestrator/runner.py` зовёт
`checkpoint.commit_step_artifacts`, который переносит в артефактную ветку
ТОЛЬКО `tasks/<id>/`; код developer вне `tasks/<id>/` остаётся
незакоммиченным в worktree. WIP-чекпоинты кода есть лишь для таймаута
(`commit_timeout_checkpoint`), rc≠0 и обрыва потока
(`commit_abnormal_checkpoint`) и `pause --now`. Дальше переход
`in_dev -> verifying` отказывает по грязной копии с текстом «PLAN.md не
закоммичен» (вводит в заблуждение: незакоммичен код, PLAN уже в
артефактной ветке), цикл буксует, код спасает Оператор руками.

Требуется:
1. После шага developer с rc=0 и грязным worktree (изменения вне
   `tasks/<id>/`) пульт коммитит код сам — тем же путём и с теми же
   фильтрами мандата, что WIP-чекпоинт таймаута (`orchestrator/checkpoint.py`,
   только догфуд, только если есть что коммитить, тихая деградация без git).
   Сообщение коммита: `<id>: код закоммичен пультом за роль developer —
   шаг завершён с незакоммиченным кодом`. Запись журнала
   `actor=orchestrator`, действие «код закоммичен пультом за роль», в
   `detail` — список файлов и число строк (как у чекпоинтов).
2. Для остальных ролей поведение не меняется: откат WIP вне мандата,
   как сейчас. Чистое дерево — ни коммита, ни записи в журнале.
3. Скил разработчика (`skills/coding-standards.md`): правило «ход
   заканчивается коммитом кода; незакоммиченный код пульт закоммитит сам
   и запишет в журнал как дефект шага, не как норму». Запрет фоновых
   прогонов в скиле уже есть (раздел «Тесты») — не дублировать.
4. Тесты: шаг developer rc=0 с грязным деревом → коммит с этим
   сообщением и запись журнала есть (мутация «проверка пропущена» —
   красный); чистое дерево → коммита и записи нет; роль без мандата кода
   с грязным деревом → прежний откат. Существующие тесты — без
   ослабления ассертов.

Зоны: orchestrator/runner.py, orchestrator/checkpoint.py,
skills/coding-standards.md, tests/.

Не входит: `orchestrator/fsm.py` (отказ по грязной копии остаётся второй
линией, не править), `orchestrator/pull.py`, `orchestrator/auto.py`;
класс «рабочие файлы роли в корне `tasks/<id>/` доезжают до main через
`git add -A` чекпоинта» (копилка П1 11.09) — отдельная задача.

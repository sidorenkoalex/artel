# SPEC: answer и zones-extend отказывают мандату без матрицы неослабления (ADR-0022 п.4)

## Контекст
Правило «перед мандатом — матрица неослабления» (`docs/operator-gates.md`,
раздел «Матрица неослабления», решение Оператора 11.10.2026; ADR-0022 п.4)
держится только дисциплиной сессии Оператора. Прецедент
01M4M67SGNEYMN9F1C7XVX24XE: рекомендация мандата на удаление трёх тестов
пропустила пять свойств, оставшихся без покрытия, — их нашла лишь
независимая проверка. Сегодня `answer` (`orchestrator/answer.py::_cmd_answer`,
`_read_checked_answer_file`) принимает файл со строкой мандата
«Ослабление тестов разрешено:» / «Расширение зон разрешено:» без всякой
матрицы, а `zones-extend` (`answer.cmd_zones_extend`) сам собирает ANSWER с
мандатом зон из списка путей, без файла Оператора. Задача делает наличие и
форму матрицы механической проверкой обоих каналов; содержание матрицы
механика не проверяет.

## Требования

Термины, общие для требований 1–5:
- **Строка мандата** — строка файла, которая после `strip` начинается с
  маркера «Ослабление тестов разрешено:» или «Расширение зон разрешено:»
  (то же правило, что `mandate.elements`). Строка «Зависимости мержа:» в
  требованиях 1–4 строкой мандата не считается.
- **Элементы мандата** — объединение элементов ВСЕХ строк мандата файла
  (каждой строки каждого из двух маркеров, а не первой строки маркера). У
  мандата тестов элемент — путь `tests/**/*.py` целиком либо
  `путь::Класс` / `путь::Класс::метод` (форма `mandate.py:159-171`); у
  мандата зон — путь файла или каталога. У `zones-extend` элементы — пути
  его аргумента.
- **Раздел матрицы** — строки от заголовка `## Матрица неослабления` до
  следующего заголовка уровня 1 или 2 (`# `, `## `) либо до конца файла.
  **Таблица матрицы** — первая markdown-таблица раздела: строка
  заголовков, строка-разделитель (`|---|…`), строки данных.
- **Строка данных** — строка таблицы после разделителя, в которой хотя бы
  одна ячейка непуста. Номер строки данных — её порядковый номер в
  таблице, первая строка после разделителя — 1.
- **Нормализация ячейки** — `strip`, снятие markdown-выделения (`*`, `_`,
  `` ` ``) по краям слов, сравнение без учёта регистра, «ё» = «е».

1. `answer` отказывает файлу ответа, в котором есть хотя бы одна строка
   мандата, если в файле нет раздела матрицы, или таблица раздела не
   несёт ровно пять столбцов, заголовки которых по порядку начинаются с
   «Что меняется», «Какое свойство сейчас держит», «Остаётся ли свойство
   после изменения», «Чем покрыто после», «Решение» (канон
   `docs/operator-gates.md:61`), или в таблице нет ни одной строки данных.
   Проверка действует в каждом состоянии, в котором `answer` принимает
   файл со строкой мандата: `escalated`, `in_dev`, `review` и `merge_gate`
   (там — файл со строкой «Зависимости мержа:» и строкой мандата). Файл
   без строк мандата — только со строкой «Зависимости мержа:» или
   указание Оператора — проходит `answer` так же, как до задачи.
2. Каждый элемент мандата назван хотя бы в одной строке данных в столбце
   «Что меняется» — иначе отказ, текст которого перечисляет все
   неназванные элементы. «Назван» значит: элемент стоит в ячейке
   отдельным токеном — с обеих сторон его ограничивает начало/конец
   ячейки, пробельный символ или один из символов `` ` `` `,` `;` `(` `)`
   `«` `»`, — и токен совпадает с элементом посимвольно (для элемента
   мандата зон — без учёта `/` на конце у обоих). Вхождение подстрокой
   элемент не называет: `…::A::m2` не называет `…::A::m`, строка о
   `tests/test_a.py::A::m` не называет элемент-файл `tests/test_a.py`,
   строка о `tests/test_a.py` не называет зону-каталог `tests/`.
3. Для каждой строки данных: если ячейка «Остаётся ли» — «остаётся», а
   ячейка «Чем покрыто» — «не покрыто», то ячейка «Решение» обязана
   начинаться с «ок при условии» и нести после этих слов непустой
   перечень замен; иначе отказ, текст которого называет номер строки
   данных. Значения после нормализации:
   - «Остаётся ли» — «не остаётся», только если ячейка начинается с
     «нет», «не остаётся» или «исчезает»; любое другое значение (в том
     числе «да», «остаётся», «Да, остаётся (переезжает)», пустая ячейка,
     «—») — «остаётся»;
   - «Чем покрыто» — «покрыто», только если ячейка содержит ссылку на
     тест: путь вида `tests/<…>.py` (за ним может стоять `:строка` или
     `::имя`); любое другое значение (в том числе «не покрыто», «нет»,
     пустая ячейка, «—», ссылка только на AC-n) — «не покрыто»;
   - перечень замен — текст ячейки «Решение» после слов «ок при условии»
     без разделителей (`:`, `—`, `-`, `,`, `;`, `.`, пробельные символы);
     пусто — перечня нет.
4. Если среди строк мандата есть хоть одна строка «Ослабление тестов
   разрешено:», файл обязан нести строку, которая после `strip`
   начинается с `Независимая проверка:` и после двоеточия несёт непустой
   текст (вердикт), — иначе отказ. Файлу, где строки мандата — только
   «Расширение зон разрешено:», эта строка не требуется.
5. `zones-extend` принимает файл матрицы аргументом `--matrix <файл>`; без
   него — отказ. К файлу применяются требования 1–3 с элементами
   мандата — путями аргумента `zones-extend`; требование 4 не
   применяется. Файл, в котором есть строка любого маркера мандата
   («Расширение зон разрешено:», «Ослабление тестов разрешено:»,
   «Зависимости мержа:»), — отказ: мандат `zones-extend` — только мандат
   зон, собранный пультом из аргумента (требование 8; иначе строка
   мандата тестов из файла попала бы в ANSWER мимо `mandate.refusals`, а
   гейт неослабления засчитывает мандат из всех ANSWER —
   `orchestrator/advance_gates/test_integrity.py:855-876`). В созданный
   ANSWER из файла переносится только раздел матрицы — текст файла вне
   раздела в ANSWER не попадает.
6. Отказ по требованиям 1–5 происходит до записи ANSWER и до коммита в
   ссылку документов задачи (ссылка не сдвигается); текст отказа называет,
   чего не хватает, и ссылается на `docs/operator-gates.md` «Матрица
   неослабления».
7. Проверка формы матрицы (требования 1–3) — одна функция, общая для
   `answer` и `zones-extend`; содержание матрицы (верность названных
   свойств) механикой не проверяется.
8. Ослабления нет: существующие проверки строк мандатов
   (`mandate.refusals`, запрет мандата из окружения роли и из автокоммита
   роли, инвариант 38) не меняются; задача только добавляет отказы.

## Критерии приёмки

AC-1. `answer` с файлом, где есть строка «Ослабление тестов разрешено:», но
нет раздела `## Матрица неослабления`, — отказ: ANSWER не создан, голова
ссылки документов задачи не сдвинулась. Сценарий проходит отдельно для
задачи в `escalated` и для задачи в `in_dev` (требования 1, 6).

AC-2. `answer` с файлом, где есть строка «Расширение зон разрешено:», а
раздел матрицы отсутствует, либо в таблице раздела нет одного из пяти
канонических заголовков, либо в таблице только заголовки и разделитель
(ни одной строки данных), — отказ, ANSWER не создан. Каждый из трёх
вариантов проходит для задачи в `escalated` и для задачи в `in_dev`;
вдобавок задача в `merge_gate` с файлом «Зависимости мержа: нет» +
«Расширение зон разрешено: <путь>» без раздела матрицы — отказ, ANSWER не
создан (требование 1).

AC-3. `answer` с файлом мандата тестов, несущим полную матрицу (пять
канонических столбцов, строки на все элементы мандата) и строку
`Независимая проверка: <вердикт>`, проходит, как до задачи: ANSWER создан и
закоммичен в ссылку документов (требования 1, 4).

AC-4. Неназванный элемент мандата — отказ, текст которого содержит имя
элемента, при нескольких неназванных — все их имена. Сценарии: (а) элемент
не упомянут в таблице вовсе; (б) элемент стоит во ВТОРОЙ строке мандата
того же маркера («Расширение зон разрешено:» дважды), и таблица называет
только элементы первой строки; (в) элемент мандата тестов — файл целиком
`tests/<…>.py`, таблица называет только `tests/<…>.py::Класс::метод` того
же файла (требование 2).

AC-5. Вхождение подстрокой элемент не называет: мандат на
`tests/<…>.py::A::m` при таблице, где в «Что меняется» есть только
`tests/<…>.py::A::m2`, — отказ с именем `…::A::m`; мандат зон на
каталог `tests/` при таблице, где в «Что меняется» есть только
`tests/<…>.py`, — отказ с именем `tests/`. Мандат зон на `tests/` при
ячейке «`tests`» — проход (требование 2).

AC-6. Строка данных с «остаётся» и «не покрыто», чьё «Решение» не
начинается с «ок при условии» или не несёт после этих слов перечня замен
(«ок при условии», «ок при условии:» без текста), — отказ, текст которого
содержит номер этой строки данных. Отказ происходит при каждом из значений
«Чем покрыто»: «не покрыто», пустая ячейка, «—», «AC-3»; и при каждом из
значений «Остаётся ли»: «да», «Да, остаётся (переезжает)», пустая ячейка.
Проход: «Остаётся ли» — «исчезает» при «не покрыто» и «ок»; «Чем покрыто»
— `tests/test_x.py:12` при «ок»; «Решение» — «ок при условии: тест-замена
X» при «не покрыто» (требование 3).

AC-7. Мандат «Ослабление тестов разрешено:» с полной матрицей, но без
строки `Независимая проверка:` (или с пустым вердиктом после двоеточия), —
отказ; мандат «Расширение зон разрешено:» с полной матрицей без этой
строки — проход (требование 4).

AC-8. `zones-extend <id> <пути>` без `--matrix` — отказ, ANSWER не создан;
с `--matrix <файл>`, где матрица называет все пути, — ANSWER создан и несёт
таблицу матрицы из файла; с `--matrix <файл>`, где матрица не называет
один из путей, — отказ с именем этого пути, ANSWER не создан (требования
2, 5).

AC-9. `zones-extend --matrix <файл>`: файл, где вне раздела матрицы стоит
строка «Ослабление тестов разрешено: tests/<…>.py», — отказ, ANSWER не
создан; то же для такой строки внутри раздела матрицы и для строки
«Зависимости мержа: …». Файл с полной матрицей и произвольным абзацем
текста вне раздела — ANSWER создан, несёт раздел матрицы и не несёт
текста этого абзаца (требование 5).

AC-10. Текст каждого отказа по матрице (AC-1, AC-2, AC-4–AC-9) ссылается на
`docs/operator-gates.md` и «Матрица неослабления» (требование 6).

AC-11. Указание без строк мандатов (в `in_dev`) и файл только со строкой
«Зависимости мержа:» без матрицы (в `escalated` и в `merge_gate`) проходят
`answer` с тем же исходом, что до задачи (требование 1).

AC-12. Мутация «проверка матрицы отключена» (общая функция проверки формы
всегда возвращает «годно») ловится: хотя бы один сценарий AC-1/AC-8
краснеет, причём одновременно в канале `answer` и в канале `zones-extend`
(требование 7).

AC-13. Строка мандата, которой `mandate.refusals` отказывал до задачи
(например, элемент с пробелом или путь вне `tests/**/*.py` в мандате
тестов), получает тот же отказ и при полной матрице в файле (требование 8).

## Оценка объёма и деление

Сработавшие сигналы: `budget_usd` ≥ $30 (рамка ТЗ — $35); число
критериев приёмки ≥ 10 (13); число файлов зоны ≥ 5 (по разметке ТЗ:
`answer.py`, `mandate.py`, `artel.py`, `docs/codebase-map.md`, `tests/`);
зона задевает механизм, на который опирается запись в `docs/invariants.md`
(инвариант 38 — мандат только Оператором; требование 8 его не меняет).

Материал для решения Оператора — обоснование монолита: требование 7
предписывает одну функцию проверки формы, общую для `answer` и
`zones-extend`. Разрезать задачу по каналам значит либо завести функцию
в первой части и подключить её ко второму каналу позже — тогда между
мержами `zones-extend` остаётся обходом нового отказа (мандат зон без
матрицы проходит через `zones-extend`, но не через `answer`), то есть
правило держится в одном канале из двух; либо дублировать проверку, что
прямо противоречит требованию 7. Реальный код-объём мал: одна функция
разбора раздела и её вызов в двух местах плюс аргумент `--matrix` в CLI;
число критериев раздуто сценариями приёмки (правила сопоставления
требований 2–3), а не зонами.

## Не входит

- Та же проверка для `approve` на гейте SPEC при разделе «Меняемое
  поведение» — второй шаг строки бэклога, отдельная задача (граница ТЗ).
- Проверка содержания матрицы (верность названных свойств, файл:строка,
  существование тестов-замен, верность вердикта независимой проверки) —
  только форма (граница ТЗ, требование 7).
- Проверка `mandate.refusals` для путей аргумента `zones-extend` — ТЗ её
  не требует; поведение команды в этой части прежнее.
- Правка документов Оператора — doc-commit Оператора после мержа (граница
  ТЗ). В том числе: правило 6 канона (`docs/operator-gates.md:85-86`, «в
  ANSWER идут её выводы», не матрица) после мержа противоречит механике
  (матрица обязана стоять в файле `answer` и переносится в ANSWER
  `zones-extend`) — снять противоречие должен тот же doc-commit; описание
  `zones-extend` для Оператора (`docs/operator-session.md`) — туда же.
- Правка `orchestrator/fsm_advance.py`, `orchestrator/advance_gates/test_integrity.py`,
  `orchestrator/fsm.py`, `scripts/guard.py`, `tests/test_invariants.py`,
  `docs/invariants.md`, `docs/adr/`, `docs/operator-session.md`,
  `docs/backlog.md`, `skills/`, `templates/`, `CLAUDE.md`, `roles.yaml`,
  `.artel/` — по ТЗ только чтение.
- Смена ожиданий существующих тестовых методов `tests/`: существующие
  сценарии, подающие `answer` файл с мандатом или зовущие `zones-extend`,
  получают матрицу (строку `Независимая проверка:` для мандата тестов,
  `--matrix` для `zones-extend`) в своих входных данных — утверждения этих
  методов не меняются. Метод, чьё утверждение пришлось бы менять, —
  эскалация разработчика, не тихая правка.
- Зелёный полный набор `tests/`, зелёный CI ветки, неизменность
  защищённых путей и непревышение бюджета — их держит пульт.

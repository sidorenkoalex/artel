# SPEC: answer и zones-extend отказывают мандату без матрицы неослабления (ADR-0022 п.4)

## Контекст
Правило «перед мандатом — матрица неослабления» (`docs/operator-gates.md`,
раздел «Матрица неослабления», решение Оператора 11.10.2026; ADR-0022 п.4)
держится только дисциплиной сессии Оператора. Прецедент
01M4M67SGNEYMN9F1C7XVX24XE: рекомендация мандата на удаление трёх тестов
пропустила пять свойств, оставшихся без покрытия, — их нашла лишь
независимая проверка. Сегодня `answer` (`orchestrator/answer.py::_cmd_answer`,
`_read_checked_answer_file`) принимает файл со строкой мандата
«Ослабление тестов разрешено:» / «Расширение зон разрешено:» без всякой
матрицы, а `zones-extend` (`answer.cmd_zones_extend`) сам собирает ANSWER с
мандатом зон из списка путей, без файла Оператора. Задача делает наличие и
форму матрицы механической проверкой обоих каналов; содержание матрицы
механика не проверяет.

## Требования

1. `answer` отказывает файлу ответа, в котором есть строка мандата
   «Ослабление тестов разрешено:» или «Расширение зон разрешено:», если в
   файле нет раздела `## Матрица неослабления` с таблицей канонических пяти
   столбцов (сверка по заголовкам: «Что меняется», «Какое свойство сейчас
   держит …», «Остаётся ли свойство после изменения», «Чем покрыто после …»,
   «Решение» — канон `docs/operator-gates.md`) и хотя бы одной строкой
   данных. Файл только со строкой «Зависимости мержа:» и указание без строк
   мандатов проходят `answer` так же, как до задачи.
2. Каждый элемент мандата (метод теста мандата «Ослабление тестов
   разрешено:»; путь зоны мандата «Расширение зон разрешено:») назван хотя
   бы в одной строке данных таблицы в столбце «Что меняется» — иначе отказ,
   текст которого перечисляет все неназванные элементы.
3. Строка данных, в которой столбец «Остаётся ли» — да/остаётся, а столбец
   «Чем покрыто» — «не покрыто» (без ссылки на тест), обязана иметь в
   столбце «Решение» «ок при условии» и непустой перечень замен; иначе
   отказ, текст которого называет номер этой строки таблицы.
4. Для мандата «Ослабление тестов разрешено:» файл обязан нести строку
   `Независимая проверка: <вердикт>` с непустым вердиктом — иначе отказ.
   Для мандата «Расширение зон разрешено:» эта строка не требуется.
5. `zones-extend` принимает файл матрицы аргументом `--matrix <файл>`; без
   него — отказ. К файлу применяются раздел и проверки требований 1–3 (с
   элементами мандата — путями, переданными `zones-extend`); матрица из
   файла попадает в созданный ANSWER.
6. Отказ по требованиям 1–5 происходит до записи ANSWER и до коммита в
   ссылку документов задачи (ссылка не сдвигается); текст отказа называет,
   чего не хватает, и ссылается на `docs/operator-gates.md` «Матрица
   неослабления».
7. Проверка формы матрицы — одна функция, общая для `answer` и
   `zones-extend`; содержание матрицы (верность названных свойств)
   механикой не проверяется.
8. Ослабления нет: существующие проверки строк мандатов
   (`mandate.refusals`, запрет мандата из окружения роли и из автокоммита
   роли, инвариант 38) не меняются; задача только добавляет отказы.

## Критерии приёмки

AC-1. `answer` с файлом, где есть строка «Ослабление тестов разрешено:», но
нет раздела `## Матрица неослабления`, — отказ: ANSWER не создан, голова
ссылки документов задачи не сдвинулась (требования 1, 6).

AC-2. `answer` с файлом, где есть строка «Расширение зон разрешено:», но
раздел матрицы отсутствует, либо в таблице раздела не все пять
канонических заголовков, либо нет ни одной строки данных, — отказ, ANSWER
не создан (требование 1).

AC-3. `answer` с файлом мандата тестов, несущим полную матрицу (пять
канонических столбцов, строки на все элементы мандата) и строку
`Независимая проверка: <вердикт>`, проходит, как до задачи: ANSWER создан и
закоммичен в ссылку документов (требования 1, 4).

AC-4. Элемент мандата (метод теста или путь зоны), не названный ни в одной
строке столбца «Что меняется», — отказ, текст которого содержит имя этого
элемента; при нескольких неназванных — все их имена (требование 2).

AC-5. Строка таблицы «остаётся» + «не покрыто» без «ок при условии» в
«Решение» или без перечня замен — отказ, текст которого содержит номер этой
строки (требование 3).

AC-6. Мандат «Ослабление тестов разрешено:» с полной матрицей, но без
строки `Независимая проверка:` (или с пустым вердиктом), — отказ; мандат
«Расширение зон разрешено:» с полной матрицей без этой строки — проход
(требование 4).

AC-7. `zones-extend <id> <пути>` без `--matrix` — отказ, ANSWER не создан;
с `--matrix <файл>`, где матрица называет все пути, — ANSWER создан и несёт
таблицу матрицы из файла; с `--matrix <файл>`, где матрица не называет
один из путей, — отказ с именем этого пути (требования 2, 5).

AC-8. Текст каждого отказа по матрице (AC-1, AC-2, AC-4–AC-7) ссылается на
`docs/operator-gates.md` и «Матрица неослабления» (требование 6).

AC-9. Указание без строк мандатов и файл только со строкой «Зависимости
мержа:» (без матрицы) проходят `answer` с тем же исходом, что до задачи
(требование 1).

AC-10. Мутация «проверка матрицы отключена» (общая функция проверки формы
всегда возвращает «годно») ловится: хотя бы один сценарий AC-1/AC-7
краснеет, причём одновременно в канале `answer` и в канале `zones-extend`
(требование 7).

AC-11. Строка мандата, которой `mandate.refusals` отказывал до задачи
(например, несуществующий метод теста), получает тот же отказ и при полной
матрице в файле (требование 8).

## Оценка объёма и деление

Сработавшие сигналы: `budget_usd` ≥ $30 (рамка ТЗ — $35); число
критериев приёмки ≥ 10 (11); число файлов зоны ≥ 5 (по разметке ТЗ:
`answer.py`, `mandate.py`, `artel.py`, `docs/codebase-map.md`, `tests/`);
зона задевает механизм, на который опирается запись в `docs/invariants.md`
(инвариант 38 — мандат только Оператором; требование 8 его не меняет).

Материал для решения Оператора — обоснование монолита: требование 7
предписывает одну функцию проверки формы, общую для `answer` и
`zones-extend`. Разрезать задачу по каналам значит либо завести функцию
в первой части и подключить её ко второму каналу позже — тогда между
мержами `zones-extend` остаётся обходом нового отказа (мандат зон без
матрицы проходит через `zones-extend`, но не через `answer`), то есть
правило держится в одном канале из двух; либо дублировать проверку, что
прямо противоречит требованию 7. Реальный код-объём мал: одна функция
разбора раздела и её вызов в двух местах плюс аргумент `--matrix` в CLI;
число критериев раздуто сценариями приёмки, а не зонами.

## Не входит

- Та же проверка для `approve` на гейте SPEC при разделе «Меняемое
  поведение» — второй шаг строки бэклога, отдельная задача (граница ТЗ).
- Проверка содержания матрицы (верность названных свойств, файл:строка,
  существование тестов-замен) — только форма (граница ТЗ, требование 7).
- Правка документов Оператора: `docs/operator-gates.md` и прочие —
  doc-commit Оператора после мержа (граница ТЗ).
- Правка `orchestrator/fsm_advance.py`, `orchestrator/advance_gates/test_integrity.py`,
  `orchestrator/fsm.py`, `scripts/guard.py`, `tests/test_invariants.py`,
  `docs/invariants.md`, `docs/adr/`, `docs/operator-session.md`,
  `docs/backlog.md`, `skills/`, `templates/`, `CLAUDE.md`, `roles.yaml`,
  `.artel/` — по ТЗ только чтение.
- Смена ожиданий существующих тестовых методов `tests/`: существующие
  сценарии, подающие `answer` файл с мандатом или зовущие `zones-extend`,
  получают матрицу (и строку `Независимая проверка:` для мандата тестов) в
  своих входных данных — утверждения этих методов не меняются. Метод, чьё
  утверждение пришлось бы менять, — эскалация разработчика, не тихая
  правка.
- Зелёный полный набор `tests/`, зелёный CI ветки, неизменность
  защищённых путей и непревышение бюджета — их держит пульт.

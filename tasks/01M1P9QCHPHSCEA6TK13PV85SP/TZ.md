# ТЗ: механика зон, часть 3 — сверка диффа с зонами при переходе in_dev → review

Родитель: 01M1NKVPD2A79PQ6K0JVV1B2Q1 «Механика зон» (SPEC на гейте
04.09: решение о делении на три части; эта — часть 3). Источник
требований — ТЗ родителя, требование 4. Зависит от части 1 (поле
`zones:` в БД, общий список зон в `orchestrator/config.py`);
независима от части 2. Старт кода — после мержа части 1, до мержа —
только SPEC.

Требуется:
1. Переход `in_dev → review` отклоняется, если дифф ветки задачи к
   main трогает файлы вне заявленных в `zones` путей и вне общего
   списка. Отказ называет конкретные файлы вне зон.
2. Исключение: PLAN несёт раздел расширения зон с обоснованием,
   подкреплённым мандатом Оператора (ANSWER с явным согласием на
   расширение) — расширение записывается в БД задачи, переход
   проходит.
3. Реализация — отказ на существующем переходе по образцу действующих
   отказов `advance` (лок планки, свежесть), не новое состояние FSM;
   отказ доносится до следующего запуска роли по действующей механике
   (T078).
4. Тесты: отказ при файлах вне зон с перечислением файлов; проход при
   расширении с основанием и запись расширения в БД; общие зоны не
   считаются; существующий набор `tests/` зелёный без ослабления.

Зоны: orchestrator/fsm_advance.py (переход in_dev → review),
orchestrator/store.py (запись расширения), tests/.

Не входит: занятость зоны на старте кода (часть 2); ревью по
содержанию (ревьювер сверяет по чек-листу как прежде).

# ANSWER-1: ответ Оператора

## Ответы

Ответ на эскалацию test_author по AC-3 — вариант (b), уточнённый.

1. Формат в PLAN.md: раздел `## Расширение зон` со строкой
   `Пути: <путь1>, <путь2>` (тот же формат списка через запятую, что
   поле `zones:` части 1) и обоснованием свободным текстом ниже.
2. Мандат Оператора: в любом `tasks/<id>/ANSWER-n.md` задачи есть
   строка, начинающаяся с маркера `Расширение зон разрешено:` и далее
   список путей через запятую. Код сверяет буквально: каждый путь из
   раздела PLAN обязан входить в список хотя бы одного такого маркера;
   пути вне мандата — отказ перехода с их перечнем. Разбор — только
   этой строки по префиксу, свободный текст ANSWER не анализируется.
3. Колонка БД: `tasks.zones_extension TEXT` — список путей через
   запятую, записывается при успешном переходе `in_dev -> review`;
   NULL — расширения не было. Миграция `add_column`, как у `zones`.
4. Отказ AC-1 после расширения считает зоной объединение `zones` и
   `zones_extension`.

AC-3 переформулировать в планке под эти три параметра; SPEC править
не нужно — формулировка AC-3 остаётся, конкретика зафиксирована этим
ANSWER (канал ADR-0012).

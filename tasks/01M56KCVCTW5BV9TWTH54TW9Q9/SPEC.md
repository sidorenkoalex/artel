# SPEC: Окружение шага роли внешнего проекта: PATH, сводка и логи suite-run

## Контекст
PATH роли состоит только из каталогов объявленных инструментов
(`orchestrator/runner.py::_role_path_dirs`). Прогон `pytest-own`
наследует PATH вызывающего процесса (`orchestrator/acceptance.py::_own_env`:
`_OWN_INHERITED_VARS = ("PATH", "LANG", "LC_ALL")`). Поэтому `suite-run`
из шага роли на sled 01M55SKHZ293CCAK0N7T4H7ZMR дал 201 ложное падение
(`FileNotFoundError: 'bash'` — 196, `'date'` — 5). Гейты пульта этого не
видят: они гоняют набор из своего процесса с полным PATH. Кроме того,
разбор итоговой строки pytest (`acceptance._RUN_CATEGORY`) не знает слова
`deselected`. На строке sled «201 failed, 4309 passed, 1156 skipped,
4 deselected, 13 warnings in 52s» он взял хвост «13 warnings in 52s» и
показал «прошло: 0, упало: 0». И наконец: если исполняемого файла команды
профиля нет, `FileNotFoundError` в `acceptance.run`/`collect`/`run_plank`
не перехвачен, и пользователь видит трейсбек вместо отказа.

## Требования

1. PATH прогона `pytest-own` во всех местах запуска профиля (всё, что
   идёт через `acceptance._place_env` → `_own_env`, включая двусторонний
   прогон `advance_gates/two_sided.py`) собирается так, в порядке
   приоритета:
   (а) PATH вызывающего процесса, как сегодня;
   (б) каталог исполняемого файла первой команды профиля `command[0]`:
   для абсолютного пути — его каталог, иначе каталог, который находит
   поиск по PATH вызывающего;
   (в) `/usr/bin`, `/bin`, `/usr/sbin`, `/sbin`.
   Каталог из (б) и (в) добавляется в конец, только если его ещё нет в
   PATH, повторов нет. `PATH`, заданный в `test_profile.env`, по-прежнему
   перекрывает собранное значение (явное решение Оператора в
   `targets.yaml`). Результат одинаков для прогона из процесса пульта и
   из шага роли.
   Обоснование порядка (ANSWER-1, ответ 3 — вариант A): у процесса пульта
   PATH уже содержит каталог `command[0]` и системные каталоги, поэтому
   прогоны гейтов не меняются. У роли первыми остаются каталоги
   объявленных инструментов, и интерпретатор пульта не затеняется.
   Добавки в хвосте закрывают `bash`/`date` и не перехватывают уже
   найденные команды. PATH самого процесса роли (`runner.role_env`) не
   меняется.
2. Разбор итоговой строки прогона (`acceptance.run_summary_line` и всё,
   что считает по ней «прошло/упало/пропущено», в том числе
   `suite-run`) узнаёт категорию `deselected` наряду с уже известными
   `xfailed`/`xpassed`. На строке sled из «Контекста» берётся вся
   итоговая строка, и счёт выходит такой: прошло 4309, упало 201,
   пропущено 1156.
3. Если исполняемого файла команды профиля нет (`FileNotFoundError` при
   запуске), места запуска профиля в `orchestrator/acceptance.py` (в том
   числе `run`, `collect`, `run_repeat`, `run_plank`, полный прогон)
   завершают прогон именованным отказом с текстом «команда профиля <имя>
   не найдена», где <имя> — `command[0]`. Трейсбека нет.
4. У артели (профиль `pult-pytest`) argv, окружение и `cwd` прогонов не
   меняются. Это свойство закрепляется тестом до правки кода.

## Критерии приёмки

AC-1. Учебный проект с профилем `pytest-own` прогоняется зелёным при
урезанном PATH «как у роли», в котором нет `/usr/bin` и `/bin`, а есть
только каталог интерпретатора. Команда профиля — обёртка, которая
вызывает `bash` и `date` по имени. Прогон идёт и через
`acceptance.run_plank`, и через полный прогон набора. Падений
`FileNotFoundError` по `bash`/`date` нет.

AC-2. PATH, который получает прогон `pytest-own`, начинается с PATH
вызывающего без изменений. Затем идёт каталог `command[0]` (если его не
было), затем те из `/usr/bin`, `/bin`, `/usr/sbin`, `/sbin`, которых не
было, в этом порядке, без повторов. Если `test_profile.env` задаёт
`PATH`, прогон получает ровно это значение.

AC-3. `acceptance.run_summary_line` на выводе, который заканчивается
строкой «201 failed, 4309 passed, 1156 skipped, 4 deselected, 13 warnings
in 52s», возвращает всю эту строку. `suite_run.parse` на том же выводе
даёт прошло 4309, упало 201, пропущено 1156.

AC-4. Профиль `pytest-own`, чья первая команда указывает на
несуществующий исполняемый файл, во всех местах запуска профиля в
`orchestrator/acceptance.py` даёт отказ прогона с текстом «команда
профиля <имя> не найдена» (<имя> — `command[0]`). `FileNotFoundError`
наружу не выходит.

AC-5. У проекта артели (профиль `pult-pytest`) argv, окружение (в том
числе `PATH`) и `cwd` прогонов те же, что до правки. Тест, который это
проверяет, зелёный и на main до правки, и на ветке после неё.

## Оценка объёма и деление

Прогноз диффа: 20 КиБ

Сработал сигнал «число затрагиваемых модулей/файлов». Guard считает
пути, упомянутые в тексте SPEC. Большинство из них стоят здесь как
адреса только для чтения или как исключённые из задачи («Не входит»,
«Материалы»). Правится один модуль, `orchestrator/acceptance.py`, плюс
тесты в `tests/`.

Обоснование монолита: все три правки сидят в одном модуле
`orchestrator/acceptance.py` (`_own_env`, `_RUN_CATEGORY`, обработка
запуска в местах профиля), и у каждой меньше десятка строк. Деление по
зонам невозможно: зона кода одна, и любая часть резала бы её поперёк.
При этом каждая подзадача стоила бы не меньше минимальной планки $25,
то есть всего больше, чем вся задача. Промежуточного нерабочего
состояния нет, но выигрыша от деления тоже нет. Решение — за
Оператором на гейте SPEC.

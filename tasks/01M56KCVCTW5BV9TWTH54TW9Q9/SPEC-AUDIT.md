Не вполне точно:
- **Отклонение 3 (мелкое).** В обосновании требования 1 сказано: «у процесса пульта PATH уже содержит каталог `command[0]` и системные каталоги, поэтому прогоны гейтов не меняются». Для относительного `command[0]` с `/` (например `.venv/bin/pytest` от `workdir`) его каталога в PATH пульта нет. PATH пульта, запущенного не из login-shell, может не иметь и `/usr/sbin`/`/sbin`. Тогда PATH прогонов гейта всё-таки получает хвост. Это безвредно: добавка в конце ничего не затеняет. Но формулировка «не меняются» неверна. Верно: «наличие каталогов (б)/(в) одинаково, существующий префикс PATH сохраняется».

## Пути обхода гейтов
1. **Отклонение 1: `suite-run` теряет имя команды.** Буквально требование
   3 выполняется: `run_full_suite` вернёт `прогон не начат: команда
   профиля uv не найдена`. Но `suite_run._run` (`suite_run.py:581-594`)
   строит отчёт роли через `render`. Для исхода `FULL_SUITE_NOT_STARTED`
   он печатает только заголовок «прогон не начат» и «прошло: 0, упало:
   0, пропущено: 0» (`suite_run.py:428-441`), текст вывода в отчёт не
   идёт. Лог `_run_full_suite_to_log` уже открыт `"wb"` до `Popen`
   (`acceptance.py:1591-1593`): при отказе он пуст, к нему дописывается
   только приложение упавших. И роль на Claude этот лог всё равно не
   прочтёт — требование 4 ТЗ исключено. Сегодня тот же сбой даёт отчёт
   «прогон оборван исключением пульта FileNotFoundError: … 'uv'»
   (`suite_run.py:622-627`), то есть имя роль видит. После правки — нет.
   AC-5/AC-6 проверяют только вывод `run_full_suite`, поэтому эту потерю
   не ловят. Варианты для Оператора:
   - (A) пустить в зоны `orchestrator/suite_run.py` (только `render`):
     для «прогон не начат» печатать первую строку вывода, плюс критерий
     на отчёт `suite-run`;
   - (B) не править: имя видно на гейтах и в `plank-run`
     (`orchestrator/plank_run.py:193`), а для `suite-run` вынести в
     отдельную строку бэклога вместе с исключённым требованием 4;
   - (C) писать текст отказа в лог прогона (в зоне `acceptance.py`). Роли
     на Claude это не поможет, пока не сделано требование 4.
2. **Широкий перехват (мелкое).** Можно обернуть в `except
   FileNotFoundError` всё тело места, включая `open(log, "wb")`
   (`acceptance.py:1591`) или `tempfile`. Тогда отсутствующий каталог
   лога или временный сбой ФС будет назван «команда профиля <имя> не
   найдена», а полный прогон уйдёт в некешируемый «не начат» вместо
   исключения. AC-5 этого не запрещает. Ограничить перехват запуском
   процесса (`Popen`/`_run_in_session`) — пожелание к плану, не к SPEC.
3. AC-7 без перечня мест — см. отклонение 2.

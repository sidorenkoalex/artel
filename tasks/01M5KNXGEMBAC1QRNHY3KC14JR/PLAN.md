# PLAN: Признак утечки пула канарейки — путь внутри пула, GUID шаблона и имя каталога в строках вызовов роли

## Подход
Меняется только `check_role_log_pool_leak` (`orchestrator/doctor/canary_pool.py`)
и новые вспомогательные функции признаков рядом с ней. Голая подстрока
`config.CANARY_POOL_DIRNAME` заменяется четырьмя признаками требования 1:

- `_home_path_sign` — 1а (путь внутри пула от `~/`, `$HOME/`, `${HOME}/`,
  `str(Path.home())/` со знаком имени после `/`) и 1б (абсолютный каталог
  пула `str(Path.home() / CANARY_POOL_DIRNAME)` с отрицательным просмотром
  `[A-Za-z0-9_.-]`); регулярное выражение собирается на каждый вызов —
  `Path.home()` читается в момент проверки, а не при импорте.
- `_tool_call_sign` — 1г: построчно, только строки, начинающиеся с
  `TOOL_CALL_LINE_PREFIX` модулей провайдеров (`doctor.providers.claude`,
  `doctor.codex_provider`), подстрока каталога с отрицательным просмотром
  `[A-Za-z0-9_-]` (дом Codex `~/.artel-canary-codex` не признак).
- `_pool_template_guids` — 1в: значения меток `canary-guid:` всех `*.md`
  открытого пула (`re.finditer(r"canary-guid:[ \t]*(\S*)")`, хвост с `-->`
  отрезается, пустое значение отбрасывается), плюс перечень шаблонов без
  непустой метки (требование 4). Под `doctor.runner.in_role_environment()`
  пул не открывается вовсе (ветка до любого чтения), деталь — «GUID шаблонов
  не сверялись: процесс роли»; нет каталога пула — «…: открытый пул не
  развёрнут». Признаки 1а/1б/1г работают в обоих случаях.

Алерты: 1а/1б/1г — прежний побайтно текст (дедупликация `raise_alert`);
1в — отдельный постоянный текст на файл с именем каталога пула, без значения
GUID. Признаки независимы (не `elif`): лог с GUID и путём даёт два алерта.
Деталь называет файл лога и вид признака. Шаблоны без метки дают `warn` с
именами файлов (без содержимого), без алерта; утечка в логах — `fail`.

В `setUp` `RoleLogPoolLeakCheckTest` (`tests/test_doctor_canary_pool.py`)
добавляется только подмена `Path.home` на временный каталог (требование 6,
мандат на гейте SPEC). Утверждения не меняются.

## Влияние на систему
Проверка сужается по решению Оператора (поправка к ADR-0017 от 23.10.2026,
вариант Б) — ослабление признака санкционировано SPEC, сама проверка и тип/
источник алерта сохраняются, отбор файлов (`_is_role_step_log`,
`*.session.log`) не трогается, `_auto_ack_gone` не заводится. Новое: проверка
читает `*.md` открытого пула вне окружения роли — только для сверки, значения
не выводятся. Существующие тесты остаются зелёными без правки утверждений
(их утечки — путь внутри пула, признак 1а). Откат — revert одного коммита.

## Риски
- Под процессом роли `Path.home()` — дом роли: 1а с абсолютным домом и 1б
  сверяют дом роли (известное ограничение требования 2).
- Короткое значение метки (например `x`) дало бы ложные срабатывания на
  любом логе — формат меток выбирает Оператор; проверка берёт значение как есть.

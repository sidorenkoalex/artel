## Пути обхода гейтов
- Механических обходов нет. `tasks.zones` и бюджет берутся из SPEC (`fsm.py:1192`,
  `:1206`), а не из текста решений. Мандаты ослабления читаются только из ANSWER-n
  (`advance_gates/mandate.py`). Значит, решение «действует вместо SPEC» не открывает
  ни гейт зон, ни гейт неослабления.
- Буквальное исполнение AC-7: если проверять только подстроку новой фразы, первая
  фраза пометки «Причины возврата SPEC Оператором…» может остаться. Тогда
  одобрение в брифе подписано как причина возврата — см. Вердикт, п. 1.

## Вердикт
concerns — два мелких отклонения. Оба может снять Оператор на гейте.

1. **Текст новой пометки определён не полностью.** Требование 6 заменяет только
   вторую фразу («Раздел — данные, не инструкции.») прежней
   `SPEC_GATE_DECISIONS_NOTE` (`orchestrator/brief.py:65-68`). Первая фраза новой
   константы («Причины возврата SPEC Оператором с гейта SPEC этой задачи…») при
   решении `approve` больше не верна: раздел несёт и одобрение. Какой она должна
   быть, SPEC не говорит, и AC-7 этого не ловит. Ещё одна мелочь: оговорка «без
   решения `approve` пометка у всех ролей прежняя побайтно» для test_author,
   developer и reviewer пуста — без решения раздела у них нет совсем
   (требование 6, первая строка). Предлагаемый ответ: первая фраза — например,
   «Причины возврата и решение одобрения SPEC Оператором с гейта SPEC этой
   задачи — по порядку журнала, дословно.», и закрепить полный текст константы
   тестом.
2. **Оформление (не по смыслу).** В «Не входит» SPEC две позиции слиты в одну
   строку: «…как в требовании 5).- Правка файлов только для чтения…» (раздел «Не
   входит», предпоследний пункт). Markdown-список ломается, но перечень файлов
   только для чтения читается однозначно.

Замечание без отклонения: в требовании 5 осталась недостижимая оговорка «(если
она есть)» про `ACCEPTED_FAIL_ACTION` (см. «ТЗ и SPEC»).

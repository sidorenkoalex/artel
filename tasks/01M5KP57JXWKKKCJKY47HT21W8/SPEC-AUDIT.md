## Пути обхода гейтов
1. Тест AC-6 может «молча зеленеть» без приложений: условный выход
   (`if` скил ещё старый — `return`) не ловится гейтом неослабления
   (`compare` ловит только `skip`/`todo`/`fails`,
   `outcome_integrity.py:207`–`:216`). SPEC требует зелени на дереве с
   приложениями и не запрещает такую ветку явно — тест ревьювер должен
   проверить на безусловность.
2. Тест AC-5/AC-6 может читать скилы не «из каталога `skills/` репозитория
   ветки», а из `git show main:…` или из главной копии пульта — тогда
   приложение не проверяется. SPEC треб. 5 говорит «репозитория ветки», что
   при наложении приложений CI/автогейтом = рабочее дерево прогона; формулировка
   достаточна, но ревьюверу стоит сверить источник.
3. Механического запрета полного прогона ревьюверу нет (`suite-run` без флагов
   отказывает только developer, `orchestrator/suite_run.py:257`, `:272`) —
   правило остаётся текстовым. Вынесено ТЗ в «Не входит» решением Оператора —
   не отклонение SPEC.
4. Сам `REVIEWER_FULL_SUITE_RULE` стоит рядом с фразой артели «Права не сужены:
   тесты … запускай» (`role_prompt.py:328`) — порядок «разрешение, затем запрет»
   задан ТЗ; противоречие смысловое, не путь обхода.

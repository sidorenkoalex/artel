## Пути обхода гейтов
1. **AC-8 может пропускаться всегда** (SPEC.md:121–122, :205–207). Условие
   пропуска — любой `OSError` при сборке. Но `role_env()` бросает `OSError`
   и при неготовом venv: настоящий `check_stack` (runner.py:1013–1017).
   Тест без заглушки `check_stack` в рабочей копии или клоне без
   `.artel/venv` пропустится с текстом «venv не готов». Текст причины в
   пропуске есть, так что требование SPEC формально выполнено, но тест-замена
   свойства «PATH роли находит инструменты» не идёт ни разу. Если же тест
   работает вне песочницы, он читает настоящий keychain и создаёт каталог
   конфига роли (providers/claude.py:221, :226–230).
2. **Подмена `shutil.which`, не смотрящая на `path`** (SPEC.md:64–66,
   :163–165). Подмена, которая возвращает `/usr/bin/git` при любом
   аргументе, проходит при коде, где запасной путь или поиск идёт по
   `os.environ`. Требование ТЗ «строго по `environ["PATH"]`, без запасного
   пути» тогда тестом не проверяется.

## Вердикт
`concerns`. Отклонения круга 1 (пп. 1–7) решение Оператора №1 сняло, и SPEC
их перенёс. Осталось два новых пункта. Оба решаются уточнением на гейте, без
возврата аналитику.

1. **AC-8: изоляция и пропуск** (SPEC.md:110–122, :197–207;
   orchestrator/runner.py:1013–1017, :1092; orchestrator/providers/claude.py:221,
   :226–230). Нужно уточнить два места:
   - тест PATH роли работает в песочнице с `isolate_keychain_and_role` и
     заглушкой `stack.check_stack`, например наследник `TmpRootTest`
     (tests/sandbox.py:1619, :1643);
   - пропуск допустим только при отказе «объявленный инструмент не найден в
     PATH» (runner.py:924–925), а не при любом `OSError`.

   Без первого тест читает настоящий keychain и пишет в `.artel/home`. Без
   второго он может пропускаться всегда (venv).
2. **Подмена `shutil.which` должна сверять `path`** (SPEC.md:64–66, :163–165;
   ТЗ, требование 1, «строго по `environ["PATH"]`»). В модульных случаях
   подмена отвечает в зависимости от переданного `path`, либо тест проверяет,
   что `path == environ["PATH"]`. Иначе мутация «`shutil.which("git")` без
   `path=`» (запасной поиск по `os.environ`) остаётся зелёной.

Остальное сверено и расхождений не имеет: ТЗ↔SPEC↔решение, адреса кода,
зоны, матрица, признаки линта долгоживущих файлов.

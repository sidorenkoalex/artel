## Пути обхода гейтов
1. Зона `tests/` целиком. Красный существующий тест можно «починить» правкой
   помощника в `tests/sandbox.py` или вызовом в другом файле, не меняя
   утверждений: гейт неослабления по утверждениям этого не увидит. Красным
   может стать, например, тест с подпроцессом в окружении роли без
   `/usr/bin` (строка матрицы 3). Запрет — только словами требования 3
   (SPEC.md:54–58). Нужна сверка на ревью: дифф `tests/` = ровно три пути.
2. AC-7(а) выполним без проводки `tests/__init__.py`: тест может сам вызвать
   `prefer_direct_git(os.environ)` (или через `setUpClass`), после чего
   «каталог раньше `/usr/bin`» верно независимо от `tests/__init__.py`. AC-6
   тогда проверяется только наличием атрибута, который мутация «`DIRECT_GIT_DIR
   = None` без вызова» сохраняет. SPEC не запрещает тесту менять
   `os.environ["PATH"]` до утверждения (а) (SPEC.md:146–158).
3. Отрицательные случаи AC-1…AC-4 можно написать так, что функция ничего не
   делает сразу по нескольким причинам. Например, `platform="linux"` при PATH
   без `/usr/bin`: тест зелёный и при удалённой проверке платформы. SPEC не
   требует, чтобы каждый отрицательный случай отличался от положительного
   ровно одним условием (SPEC.md:59–76, :114–134).
4. AC-5 опирается на настоящий `/usr/bin/git`: `shutil.which(..., path=…)`
   должен вернуть `/usr/bin/git`. Есть ли этот файл, решает машина
   (ubuntu-latest — да, macOS — обёртка). SPEC не говорит, допустима ли
   подмена `shutil.which` или пропуск без `/usr/bin/git`. Исполнитель может
   «детерминировать» случай пропуском — тогда положительный случай в CI не
   проверяется.

## Вердикт
`concerns`: SPEC можно вести дальше, но перед `tests_writing` Оператору стоит
решить следующее.

1. **AC-8 предписывает закрытые имена в долгоживущем файле**
   (SPEC.md:93–101, :159–165). Обращение `runner._resolve_declared_tools()` /
   `runner._role_path_dirs(...)` в `tests/test_<id>_*.py` — признак
   «закрытый атрибут» (scripts/guard.py:3921–3923), импорт этих имён —
   «закрытое имя» (:3836–3838). Выход из `tests_writing` откажет
   (orchestrator/advance_gates/tests_writing.py:384, :509). SPEC упоминает
   соседний признак «git-вызов» (SPEC.md:86–87), а этот — нет. Выполнимо
   через публичные `runner.declared_tool_path` (orchestrator/runner.py:929)
   и `runner.role_env()` (:1091–1113, PATH = `venv_bin` + каталоги
   инструментов), отказ ловится как `OSError`. Нужна оговорка в AC-8.
2. **AC-8 буквально ложен для `python3`** (SPEC.md:160–161).
   `_role_path_dirs` кладёт каталог `sys.executable`, а не каталог `which`
   (orchestrator/runner.py:947–955). Если «каталог каждого объявленного
   инструмента» понимать как `dirname(_resolve_declared_tools()[name])`, тест
   красный на исправном коде. Нужно исключить `python3` или сверять его с
   `sys.executable`. Вместе с п. 1 AC-8 слабо ловит мутации: его утверждения
   тавтологичны сборке PATH роли из того же `which`.
3. **Отрицательные случаи без изоляции условия** (SPEC.md:59–76, :114–134):
   нет требования, чтобы каждый отрицательный случай AC-1…AC-4 отличался от
   положительного (AC-5) ровно одним условием. Без этого мутации «убрана
   проверка платформы / `X_OK` / `normpath`» проходят («Пути обхода», п. 3).
4. **Условия пропуска AC-7 не учитывают «первый git — не `/usr/bin/git`»**
   (SPEC.md:146–149). На машине, где git из Homebrew (`/opt/homebrew/bin/git`
   существует) или из `DEVELOPER_DIR` стоит раньше `/usr/bin`, функция по
   требованию 1 ничего не делает, а AC-7(а) красный, не пропуск. Так
   продиктовано ТЗ. Решение за Оператором: оставить (PATH пульта
   фиксирован) или добавить условие пропуска.
5. **AC-7(а) не проверяет проводку `tests/__init__.py`**, если тест сам
   вызывает функцию над `os.environ` (SPEC.md:146–158; «Пути обхода»,
   п. 2). Стоит добавить, что тест не меняет `os.environ["PATH"]` и что
   `tests.DIRECT_GIT_DIR` либо равен вставленному каталогу, либо равен `None`
   при уже вставленном каталоге.
6. **Неточные адреса**: `orchestrator/runner.py:905` →
   `_resolve_declared_tools` на :907 (SPEC.md:95, :246);
   `scripts/guard.py:3849` — строка признака в `_call_signs`, а
   `_is_git_command` — на :3767 (SPEC.md:87). Смысл верен.
7. **Положительный случай AC-5 зависит от настоящего `/usr/bin/git`**
   (SPEC.md:59–62, :135–141; «Пути обхода», п. 4). Не сказано, разрешена ли
   подмена `shutil.which`.

Остальное — ТЗ↔SPEC, зоны, матрица, адреса тестов и пределов — сверено и
расхождений не имеет (бюджет $25 против $20 обоснован полом калибровки).

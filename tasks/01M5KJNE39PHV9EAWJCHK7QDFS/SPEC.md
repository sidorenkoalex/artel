# SPEC: Полный набор tests/: git в процессах тестов — напрямую, без системной обёртки xcrun

## Контекст
На машине пульта `/usr/bin/git` — системная обёртка macOS (xcrun), которая
находит каталог инструментов разработчика (`xcode-select -p` —
`/Library/Developer/CommandLineTools`) и запускает оттуда настоящий git
(версия, `--exec-path` и конфигурация — те же). PATH пульта ставит `/usr/bin`
раньше `/opt/homebrew/bin`, полный набор получает копию окружения пульта
(`orchestrator/acceptance.py:71` `_pytest_env`, `:145` `_place_env`), поэтому
каждый `git` в тестах идёт через обёртку: 52–85 мс против 11–18 мс напрямую,
экономия 80–140 мс на запуск. Попарные замеры 23.10: файл
`tests/test_01m5jgsaanr1nzyqd4fcsve48y_outcome_components.py` — 40,9 с против
78,1 с, тест AC-10 `outcome_prior` — в 2,1–2,6 раза быстрее. Оценка — 230–530 с
длительности набора на загруженной машине при пределе 1500 с
(`targets.yaml:53`). Задача — вставить каталог настоящего git в PATH процессов
тестов (только тестов: PATH боевого пульта не меняется).

## Требования

1. Новый модуль `tests/direct_git.py` с функцией
   `prefer_direct_git(environ, platform=sys.platform, developer_dir=None) -> str | None`,
   где `developer_dir` — функция без аргументов, возвращающая каталог
   разработчика или `None` (тип `Callable[[], str | None] | None`):
   - работает только при `platform == "darwin"`; иначе ничего не меняет и
     возвращает `None`;
   - в `environ` нет `PATH` — ничего не меняет; поиск `git` — строго по
     `environ["PATH"]` (`shutil.which("git", path=…)`), без запасного пути;
   - первый найденный `git` после `os.path.normpath` равен `/usr/bin/git`;
     иначе ничего не меняет (git уже найден не через обёртку);
   - каталог разработчика: `developer_dir()`, если функция передана; иначе
     `environ["DEVELOPER_DIR"]`, если задан; иначе вывод `xcode-select -p`
     (таймаут 5 с); ошибка, таймаут, пустой вывод — ничего не меняет,
     исключение наружу не выходит;

     каталог `<каталог разработчика>/usr/bin` вставляется в `environ["PATH"]`
     непосредственно перед первым элементом, который после

     пустые) и их порядок не меняются; если этот каталог уже стоит раньше

## Критерии приёмки

AC-1. Модуль `tests/direct_git.py` существует и экспортирует
`prefer_direct_git(environ, platform=sys.platform, developer_dir=None)`; при
`platform`, отличном от `"darwin"`, вызов не меняет `environ` и возвращает
`None` (требование 1).

AC-2. Если в `environ` нет `PATH`, либо первый `git`, найденный
`shutil.which("git", path=environ["PATH"])`, после `os.path.normpath` не
равен `/usr/bin/git` (другой каталог с git стоит раньше `/usr/bin`), либо
элемента `/usr/bin` в PATH нет, — `environ` не меняется, исключения нет,
возвращено `None` (требование 1).

AC-3. Каталог разработчика берётся в порядке: результат переданной
`developer_dir()`; иначе `environ["DEVELOPER_DIR"]` — и тогда `xcode-select`
не вызывается (подмена `subprocess.run` фиксирует отсутствие вызова); иначе
вывод `xcode-select -p` с таймаутом 5 с. Ошибка `xcode-select`, его таймаут
или пустой вывод — `environ` не меняется, исключение наружу не выходит,
возвращено `None` (требование 1).

AC-4. Если `<каталог разработчика>/usr/bin/git` отсутствует или существует,
но не исполняем, — `environ` не меняется, возвращено `None` (требование 1).

AC-5. При исполняемом `<каталог разработчика>/usr/bin/git` и первом git
`/usr/bin/git` каталог `<каталог разработчика>/usr/bin` вставлен в
`environ["PATH"]` непосредственно перед первым элементом, равным после
`os.path.normpath` `/usr/bin`; прочие элементы (в том числе пустые) и их
порядок не изменились; функция вернула вставленный каталог. Повторный вызов
на том же `environ` не меняет PATH и возвращает `None` (требование 1).

AC-6. `tests/__init__.py` при импорте пакета `tests` вызывает
`prefer_direct_git(os.environ)` и сохраняет результат в атрибуте пакета
`tests.DIRECT_GIT_DIR`; другой правки этого файла нет (требование 2).

AC-7. На машине с обёрткой (платформа `darwin`, есть `/usr/bin/git`, в
каталоге из `xcode-select -p` есть исполняемый `usr/bin/git`; иначе тест
пропускается, `tests.DIRECT_GIT_DIR` условием пропуска не служит) в процессе
теста: (а) в `os.environ["PATH"]` каталог `<каталог разработчика>/usr/bin`
стоит раньше первого элемента, равного после `os.path.normpath` `/usr/bin`;
(б) git, найденный `shutil.which("git", path=os.environ["PATH"])`, и
`/usr/bin/git`, вызванные по абсолютным путям, дают тот же вывод
`--version`, `--exec-path` и `config --get init.defaultBranch`; (в) для
`python3`, `bash`, `sh`, `node`, `gh`, `claude`, `codex`, `uv` поиск по
текущему PATH и по PATH без элемента каталога разработчика даёт один и тот
же файл либо пару «`/usr/bin/<имя>` — `<каталог разработчика>/usr/bin/<имя>`»
(требование 4).

AC-8. В процессе теста каталоги PATH шага роли (`orchestrator/runner.py`
`_role_path_dirs` от `_resolve_declared_tools`) содержат каталог каждого
объявленного инструмента; `shutil.which("git", path=<PATH роли>)` находит
исполняемый git, который даёт тот же вывод `--version`, что `/usr/bin/git`
(оба по абсолютным путям); если `_resolve_declared_tools()` отказывает, тест
пропускается с текстом отказа в причине пропуска (требование 4).

AC-9. PLAN.md содержит замеры на одной машине с загрузкой (`uptime`) у
каждого прогона, попеременно «база — ветка — база — ветка», для
`tests/test_01m5j0jyw3gzsshhk3tycytq3j_outcome_prior.py::Ac10EmptyPriorSetTest`,
`tests/test_01m5jgsaanr1nzyqd4fcsve48y_outcome_components.py` и одного файла
наследников `TmpRootTest`, и число запусков git на тест AC-10, подсчитанное

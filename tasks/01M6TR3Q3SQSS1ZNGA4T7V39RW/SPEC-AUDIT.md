## Факты против кода

- `_account_step` — `runner.py:1762` (вызов), `:2055` (определение); после
  него `_finish_*` `:1766-1781`. Подтверждено.
- Профиль прогона задачи: компонент задачи — ровно один (несколько —
  отказ `SEVERAL_COMPONENTS`, `project_profile.py:384-385`), выбор —
  `for_task_target` (`:267-278`); раннер — поле компонента (`:509`).

  `_compose_report_run` (`acceptance.py:1421`); путь полного набора зовёт его
  в том же процессе (`_report_run` `:1476-1494`, `components_full_suite`
  `:4053-4077`) — в дочернем прогоне метка равна pid дочернего прогона.
  Подтверждено.

  по нему (AC-3, AC-15) возможен. Подтверждено.
- `doctor/orphans.py:339-343` — образец `docker ps -a --filter label=…
  --format {{json .}}`. Подтверждено.

Неточности:
- **Б2. «Раннер `pytest`»** (SPEC.md:36, :85, :312, :373, :379-382) — такого
  раннера нет: `PROFILE_RUNNERS` = `pult-pytest`, `pytest-own`, `compose`
  (`targets.py:98-102`). Смысл («не `compose`») понятен, но AC-26 требует
  «подменённый pytest вызван прежним путём» / «не вызван»: у `pult-pytest`
  pytest — интерпретатор venv пульта (`acceptance._pytest_command`,
  `stack.pytest_python_executable()`), подменой в PATH он не ловится;
  ловится только у `pytest-own` (команда профиля). Тест AC-26 выполним, если
  вымышленный компонент — `pytest-own` с командой-заглушкой; SPEC этого не
  говорит.
- AC-3 (SPEC.md:204-207) называет образцом добора pid по `run.json`
  `tests/test_01m462qaceh29rprd2rzhghqfm_suite_run.py:409-423`, но
  `stop_everything` там добирает pid **по файлу вызовов** заглушек (`pid`,
  `ppid`), не по `run.json`. Вызовы `docker` фона идут в своих сессиях
  (`acceptance.py:898-901`) — снятие группы фона по pid из `run.json` их не
  задевает; добор по файлу вызовов (как в образце) нужен и здесь. Мелкое.
- Прежние мелкие ссылки не изменились: AC-17 → `suite_lock.py:240-247`
  (фактически отказ досыла — `:227-228`, `:248-249`).

Опыт (временный процесс, предел 20 с, без репозиториев пульта): ребёнок
Python в `process_group=0` — своя группа (`pgid == pid`), та же сессия, что
у родителя; `os.kill(pid, SIGINT)` — `KeyboardInterrupt`, `finally`
исполнен, код −2. Подтверждает треб. 13 («сигнал доходит») и записку №1.5.
Прежняя находка Б1 (унаследованный SIG_IGN) больше не ведёт к оставленному
стенду: по треб. 13 исполнитель ждёт, снимает группу и всегда делает поиск и
явный `down`.

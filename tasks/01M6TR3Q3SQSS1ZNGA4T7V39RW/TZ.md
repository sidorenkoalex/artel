# ТЗ: Прогоны в контейнере по запросу роли: plank-run и suite-run для проекта с раннером compose

# Прогоны в контейнере по запросу роли: plank-run и suite-run для проекта с раннером compose (ADR-0023, пятая поправка 07.11.2026)

## Факты

1. Прогон с раннером `compose` в процессе роли — отказ до любого вызова `docker`: `COMPOSE_ROLE_REFUSAL` (`orchestrator/acceptance.py:817-818`), проверка `runner.in_role_environment()` в `_compose_report_run` (`:1330-1342`). Признак роли — маркер `ARTEL_ROLE` или `HOME`, равный дому роли (`orchestrator/runner.py:1364-1376`).
2. `plank-run <id>` (`orchestrator/plank_run.py:164`, вызовы `acceptance.run_plank` `:269-289`) и `suite-run <id>` (`orchestrator/suite_run.py:860`) — в перечне команд роли (`orchestrator/artel.py:2590-2593`). `suite-run` запускает отвязанный процесс, снимая только `ARTEL_ROLE` (`orchestrator/suite_run.py:916-930`), поэтому дом роли остаётся, и Compose отказывает; итог роль забирает `--wait` (не дольше `config.SUITE_RUN_MAX_WAIT_MIN`), состояние — в `_state_dir` (запись в него открыта и роли Codex в песочнице).
3. Шаг роли ведёт процесс пульта `runner.run_agent_once` (`orchestrator/runner.py:1700`): запускает агента и ждёт его `proc.wait(timeout=config.AGENT_TIMEOUT_SEC)` (`:1997`); этот процесс — вне окружения роли.
4. Опыт 06.11 (строки копилки 06.11): на первой задаче проекта с раннером `compose` все три роли получили код 4 «раннер compose в шаге роли не исполняется»; тесты сданы неисполненными.
5. ADR-0023, пятая поправка 07.11.2026 (принята Оператором, `ec099fb0`): запросы до песочницы ОС при условиях её пп. 2-4.

## Требуется

1. **Запрос.** `plank-run <id> [<файл>]` и `suite-run <id> [--failed]` в процессе роли для задачи проекта с раннером `compose`: `docker` не вызывается; команда записывает запрос (вид — планка с указанным файлом или без, полный набор, повтор упавших; id задачи; время) в хозяйство пульта задачи и печатает «запрос принят, итог — `<команда> --wait <минуты>`». Правила `suite-run` для разработчика (новый полный прогон — отказ) — прежние. У прочих профилей и вне шага роли поведение команд — прежнее побайтно.
2. **Исполнитель.** Процесс пульта, ведущий шаг роли этой задачи (`run_agent_once`), пока шаг идёт, берёт запросы задачи по одному и исполняет их прежними узлами (`acceptance.run_plank` / путь полного набора `suite-run`) в своём окружении, на рабочей копии задачи с незакоммиченными правками. Полный набор — под общим замком полных прогонов (`suite_lock`); занятый замок — итог «прогон не начат: замок занят <держатель>». Итог пишется туда, откуда его читает `--wait`, в прежнем формате отчёта команды.
3. **Что исполнитель не принимает:** запрос другой задачи; запрос без шага роли этой задачи в полёте; файл планки вне долгоживущих файлов задачи и её `acceptance_tests`; любые поля запроса сверх вида, файла и id. Отказ — итогом запроса с причиной, `docker` не вызывается.
4. **Пределы.** Один исполняемый запрос задачи за раз, следующий — в очередь (не больше 3 в очереди, сверх — отказ при записи). Предел времени прогона — прежний для вида прогона; шаг роли, завершившийся раньше итога, — прогон снимается тем же путём, что прерванный прогон гейта, итог «прерван: шаг роли завершён».
5. **Журнал.** Запись журнала задачи «прогон по запросу роли: <вид>, итог <…>» (через отложенную запись `suite_lock.defer_journal`, если пишет процесс без права записи в БД).

## Критерии приёмки

- Given вымышленный проект с раннером `compose` (подменённый `docker`) и процесс с признаком роли, When `plank-run <id>`, Then подменённый `docker` не вызван в процессе роли, запрос записан, вывод называет `--wait`; When исполнитель (процесс пульта без признака роли) берёт запрос, Then `docker` вызван исполнителем, итог читается `plank-run <id> --wait` в прежнем формате;
- Given запрос с чужим id задачи, с файлом вне файлов задачи или с лишним полем, Then исполнитель отказывает итогом с причиной, `docker` не вызван;
- Given занятый замок полных прогонов, When запрос полного набора, Then итог «прогон не начат: замок занят»;
- Given шаг роли завершён до итога прогона, Then прогон снят, итог «прерван: шаг роли завершён», стенд Compose снят;
- Given четыре запроса подряд, Then четвёртый — отказ при записи;
- Given разработчик и `suite-run <id>` без флагов, Then прежний отказ;
- проекты без `compose` и вызовы вне шага роли — поведение `plank-run` и `suite-run` прежнее; прямой прогон `compose` в процессе роли — прежний отказ `COMPOSE_ROLE_REFUSAL`; существующие тесты — зелёные без правки.

Безопасность тестов: вымышленные проекты и рабочие копии во временной песочнице (`tests.sandbox`), `docker` — подмена программы в PATH теста, без настоящего Docker и сети; процессы исполнителя и роли — с пределом времени и снятием группы процессов; никогда — настоящий `.artel/targets.yaml` и клоны проектов.

Существующие тесты: правка не должна сделать красным ни один существующий тест; если краснеет — эскалация с именем теста, без правки.

Зоны: `orchestrator/plank_run.py`, `orchestrator/suite_run.py`, `orchestrator/runner.py` (исполнитель на время шага роли), `orchestrator/acceptance.py` (только вызов узлов из исполнителя, без изменения отказа `COMPOSE_ROLE_REFUSAL`), `orchestrator/suite_lock.py` (если нужна отложенная запись журнала), `docs/codebase-map.md` (только генерацией), `tests/` (долгоживущие файлы задачи).

Только чтение: `docs/adr/0023-role-step-sandbox.md`, `orchestrator/artel.py`, `orchestrator/config.py`, `orchestrator/stack.py`, `tests/sandbox.py`, `tests/test_01m6paj61d4pyap79adrpa6mwv_compose_run.py`, `.artel/targets.yaml` (не читать в тестах).

Не входит:
- доступ роли к Docker в любом виде;
- произвольные команды или образы в контейнере по запросу роли;
- песочница ОС шага роли (B3);
- линтер проекта в шаге роли (отдельная строка копилки);
- правка настоящего локального слоя `.artel/targets.yaml` в тестах и при разработке.

## Требуется

1. **Метка без записи.** `live_runs()` не меняется: читает только записи. Метки без записи читает новая функция. `live_run_note` сверяет сначала записи (с их прежней уборкой), затем метки, у которых не осталось ни одной записи того же `run_stamp`. Метка, рядом с которой есть запись того же `run_stamp` (живая или убираемая прежним `_drop_live_record`), новой логикой не трогается. Для метки без записи: pid в метке жив — прогон живой, причина «идёт канарейка <run_stamp> (запись реестра отсутствует)»; окно тишины, отказ мержа (прогон считается прогоном набора по умолчанию — набор неизвестен, безопасная сторона) и отказ обходов окна держатся. Метка пустая или не читается и моложе 60 с по времени правки — прогон живой (метка только что создана: `_live_run_record` пишет pid после `O_EXCL`); старше 60 с — метка убирается строкой журнала пульта `LIVE_RUN_SWEPT_ACTION`. Pid мёртв — метка убирается той же строкой. Отказ повтора `run_stamp` при оставшейся метке — прежний.
2. **Команда `canary live`** (строка бэклога 286). Без аргументов печатает реестр: по записи — `run_stamp`, pid, `parent_pid` и шаблон (если есть в записи), sha7, набор, время начала, возраст, остаток до потолка; по метке без записи — `run_stamp`, pid и возраст по времени правки; пусто — «живых прогонов канарейки нет». Мёртвые записи и метки убираются прежним путём чтения реестра (п. 1).
3. **Снятие записи.** `canary live --drop <run_stamp> "<основание>"` снимает только: (а) запись старше `CANARY_DRIVE_TIMEOUT_SEC`; (б) запись, у которой время старта процесса не определилось при записи или при сверке; (в) метку без записи. Снимаются все такие записи этого `run_stamp` и его метка; процессы не сигналятся. Иначе — отказ «canary live: прогон <run_stamp> жив (pid <pid>, возраст <ч>) — снимать нечего; дождись итога или используй --during-canary у конкретной команды». Строку журнала пульта без задачи пишет `operator` новой константой действия; деталь — имена удалённых файлов и основание. Если процесс прогона жив, вывод команды и деталь журнала несут «процесс <pid> жив — прогон продолжается без защиты окна». `<run_stamp>` — по шаблону `^\d{8}T\d{6}Z$`, иначе отказ до чтения каталога реестра. Отказы: `--drop` без `run_stamp`; пустое основание (по образцу `_fixes_main_arg`); лишние аргументы `canary live`; записей и метки с таким `run_stamp` нет — «canary live: прогона <run_stamp> в реестре нет». Под ролью обе формы `canary live` отказывают прежним механизмом `_role_allowed_command` (разрешённой подкоманда не становится). Справка называет подкоманду.
4. **Реестр в `doctor`.** Проверка `canary-live`: живых прогонов нет — `ok` «живых прогонов канарейки нет»; есть — `ok` со списком «<run_stamp> на <sha7>, pid <pid>, возраст <ч>»; запись старше `CANARY_DRIVE_TIMEOUT_SEC` или метка без записи старше `CANARY_DRIVE_TIMEOUT_SEC` по времени правки — `warn` с подсказкой `canary live --drop <run_stamp> "<основание>"`. Метка без записи — в списке с пометкой «запись реестра отсутствует» и возрастом. Уборка мёртвых записей и меток — прежним путём чтения реестра, допустима и в `doctor` без `--fix`.
5. **Изоляция тестов реестра** (строка бэклога 287 и перенос 2 из гейта SPEC части А). Классы тестов, вызов которых доходит до `_refuse_during_canary` при `is_artel(ctx)` и корне пульта в config (атрибут ROOT), равном настоящему корню пульта, а также `CmdCanaryTemplateSelectionTest`, не читают и не пишут настоящий реестр: песочница `ALL_CONFIG_ATTRS` или подмена пути реестра. Перечень таких классов разработчик приводит в отчёте. Класс в защищённом пути (`tests/test_invariants.py`) — эскалация, не правка. Для `CmdCanaryTemplateSelectionTest` — подмена `canary._live_dir` на временный каталог в `setUp`. Это добавление изоляции: существующие утверждения не меняются и не удаляются. Тест-шпион сравнивает путь `_live_dir()` при обращении каждого класса из перечня с корнем, снятым до подмен (`Path(orchestrator.__file__).resolve().parents[1]`): путь не лежит под ним.
6. Тесты детерминированы, без сети, без настоящих ролей и без ожидания по часам; время правки метки задаётся `os.utime`. Метка без записи: живой pid — `note` удержан, `approve` на `merge_gate` отказ, `note --now` отказ, причина с «(запись реестра отсутствует)»; пустая метка моложе 60 с — живой прогон, старше — убрана со строкой журнала; мёртвый pid — убрана со строкой журнала; метка рядом с записью того же `run_stamp` новой логикой не тронута; `live_runs()` по-прежнему отдаёт только записи. `canary live`: показ записи, метки без записи (с возрастом) и пустого реестра. `--drop`: каждый из случаев (а), (б), (в) снимается, строка журнала `operator` с основанием, процесс не получил сигнала, при живом процессе — «процесс <pid> жив — прогон продолжается без защиты окна»; живая свежая запись с определённым временем старта — отказ «снимать нечего»; отказы неверного `run_stamp` (каталог реестра не читался), отсутствующего `run_stamp`, пустого основания, лишних аргументов, неизвестного `run_stamp`, под ролью. `doctor`: `ok` пустой, `ok` со списком, `warn` для старой записи и для старой метки без записи. Изоляция п. 5 — тест-шпион. Без метки без записи — прежнее поведение `note`, `doc-commit`, `approve` и вывод `canary`; существующие тесты (в том числе `tests/test_canary_live_registry_units.py`) без правок утверждений и зелёные.

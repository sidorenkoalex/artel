# ТЗ: Эвристики ошибок агента — классы отказов и бэкофф

Источник: роадмап P3, строка «Эвристики ошибок агента»; фактуры:
27.08 (T043, auth 403 посреди шага) и 31.08 (сетевой провал
~40 мин, Connection refused до API: T075–T078 сожгли по 3 попытки
за секунды и эскалировали — четыре ручных возврата Оператором,
минутный бэкофф переждал бы).

Научить runner различать классы ошибок агентного шага вместо
одинаковых секундных ретраев:

1. Транзиентное СИСТЕМНОЕ (403/лимит окна, сетевой отказ до API):
   минутный бэкофф (порядка минут, не секунд) с потолком попыток
   ЛИБО сразу эскалация с подсказкой «doctor live-smoke, потом
   approve» — выбор обосновать в SPEC.
2. Session limit подписки: не ретраить вовсе — ждать reset;
   счётчик таких событий в alerts (связка с триггером №15).
3. Обрыв до финального события потока = стоимость $0: алерт
   spend.unknown_cost обязан открываться и здесь (промежуточных
   usage-событий может не быть вовсе — подслучай (в) фактуры 27.08).
4. Красный CI перед передачей dev ре-ранится 1 раз (flake-детект);
   flake-rate — в метрики журнала.

Границы: чекпоинт WIP при rc-обрыве (подслучай (б)) — ВНЕ объёма,
остаётся в P3 отдельной строкой. Инвариант 3 (числовой лимит
циклов, после лимита — Оператор) не ослаблять: бэкофф меняет паузы
между попытками, не число попыток. Оценка рамки: $15–25 (роадмап).

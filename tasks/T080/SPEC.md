# SPEC: П1: макет панели — артефакт UX

## Контекст

Роадмап §3 «Панель» открывает этап 1 без демона задачей «П1 (макет
панели)» — параллельная, ещё не запущена; ADR-0004 п.7 фиксирует её
как «интерактивный макет артефактом ДО кода», предваряющий П2′
(`artel report`) и этап 2 (Г0+). Сейчас у панели нет ни одного
визуального черновика — решение по UX нечем принимать. Нужен
статический макет-артефакт, который Оператор утвердит на гейте, без
демона, API и кода панели.

## Требования

1. Артефакты задачи содержат один самодостаточный HTML-файл (или
   набор HTML-скетчей), открываемый локально без сервера, демона,
   БД-доступа, JS-фреймворков и шагов сборки — только разметка/стили.
2. Макет показывает борд задач по состояниям FSM.
3. Макет показывает карточку задачи с полями: статус, бюджет/расход,
   итерации ревью, lease.
4. Макет показывает блок алертов.
5. Макет показывает очередь гейтов Оператора — spec_gate и
   merge_gate, каждый с кнопками approve/reject.
6. Макет показывает кнопку pause.
7. Данные в макете — статические примеры, списанные с реального
   status/ретро текущего пульта (анонимизация не нужна, репозиторий
   приватный).

## Критерии приёмки

AC-1. В артефактах задачи (`tasks/T080/`) присутствует один
самодостаточный HTML-файл или набор HTML-файлов-скетчей: каждый
открывается локально (`file://`) без сервера, демона или сборки.

AC-2. Ни один из HTML-файлов макета не содержит обращений к БД
оркестратора, HTTP-вызовов к API, подключений JS-фреймворков/библиотек
(React, Vue и т.п.) и шагов сборки (bundler, npm build и подобных) —
только HTML-разметка и CSS-стили (inline или локальные, без внешних
сетевых ресурсов).

AC-3. Макет содержит борд задач: канбан-раскладку, где колонки
соответствуют состояниям конечного автомата задачи (FSM), а не
произвольным человеческим статусам.

AC-4. Макет содержит карточку задачи с отображением полей: статус,
бюджет/расход, итерации ревью, lease.

AC-5. Макет содержит блок алертов.

AC-6. Макет содержит очередь гейтов Оператора с записями для
spec_gate и merge_gate, у каждой записи — кнопки approve и reject.

AC-7. Макет содержит кнопку pause.

AC-8. Данные, показанные в макете (борд, карточка, алерты, очередь
гейтов), — статические примеры, списанные с реального status/ретро
текущего пульта, а не синтетические заглушки-плейсхолдеры.

## Не входит

- Демон панели, `artel report`, HTTP API, WebSocket — сама механика
  read-проекции (П2′ и этап 2 роадмапа, не эта задача).
- Доступ макета к БД оркестратора (`state.db`) — только статические
  примеры данных.
- Код панели (пакет `panel/`, сервер, роутинг).
- Рабочая логика кнопок: approve/reject/pause в макете ничего не
  вызывают — только визуальное представление (следствие «без демона,
  без API» границы ТЗ).
- JS-фреймворки, библиотеки и любые шаги сборки.
- Утверждение UX Оператором — процесс гейта задачи, не критерий
  содержимого артефакта.

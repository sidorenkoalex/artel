# PLAN: П1: макет панели — артефакт UX

## Подход

Один самодостаточный HTML-файл `tasks/T080/mockup.html` — inline
CSS, без `<script>`, без внешних ресурсов, без обращений к БД/API.
Один файл, а не набор скетчей: все обязательные блоки (борд, карточка,
алерты, очередь гейтов, pause) образуют один связный экран пульта —
дробить на страницы без навигации (которую SPEC явно исключает —
это код панели) только всё усложнило бы.

Данные (AC-8) — не выдумка, а реальные идентификаторы/суммы,
взятые из `docs/retro/*.md` и форматов реального вывода
(`orchestrator/catalog.py::cmd_status`, `orchestrator/budget.py`,
`orchestrator/retro.py`):

- **T075** «ANSWER-артефакт: канал ответа Оператора на эскалацию»
  (`docs/retro/T075.md`) — budget_usd=50 (`tasks/T075/SPEC.md`
  frontmatter на момент выполнения), итог $32.69, ревью 1 итерация,
  5 эскалаций (последняя — конфликт подтяжки main), 18 приёмочных
  тестов.
- **T078** «Отказ advance доносится до следующего запуска роли»
  (`docs/retro/T078.md`) — budget_usd=25, итог $10.66, ревью
  0 итераций, 1 эскалация (агент не отработал за 3 попытки), 6
  приёмочных тестов.
- **T063** «RETRO: полное первое предложение сути, killed — из ТЗ»
  (`docs/retro/T063.md`) — budget_usd=15, итог $13.79, ревью
  1 итерация, 4 эскалации (конфликт подтяжки main), 4 приёмочных
  теста.
- **T068** «B1a: изоляция обвязки целевого — MCP-вектор»
  (`docs/retro/T068.md`) — killed (kill switch), $0.00, без эскалаций
  (артефакты сняты при kill — `cleanup.drop_killed_task`, поэтому
  budget_usd из SPEC уже недоступен, в карточке не указывается число,
  которого нет).
- **T080** — эта самая задача: `tasks/T080/SPEC.md` budget_usd=25,
  состояние `in_dev` в макете буквально верно на момент написания
  (роль developer выполняет этот шаг прямо сейчас).

Карточки размечены как исторический срез («на момент …», где число
не финальное — T075/T078/T063 проходили через `review`/`escalated`
до итогового `done`), а не как утверждение о текущем live-состоянии
БД — SPEC прямо исключает доступ макета к `state.db` («Не входит»),
статика неизбежно замороженный снимок.

Борд — все 10 канонических состояний FSM
(`orchestrator/config.py:192-213`, `_html_utils.CANONICAL_FSM_STATES`)
колонками; подпись колонки — точное имя состояния (`spec_writing`,
`spec_gate`, …) в отдельном узле без потомков, чтобы
`_html_utils.node_state_label` находило подпись, плюс человекочитаемая
расшифровка рядом (не в том же узле, чтобы не портить `own_text`
при разборе AC-3).

Очередь гейтов — по одной записи на `spec_gate` и `merge_gate`
(ровно те два гейта, что требует AC-6; `acceptance` в gates.yaml
автопроходит и в очередь ручных решений не входит), у каждой —
кнопки approve/reject (визуальные, без `onclick` — SPEC «Не входит»:
«рабочая логика кнопок… ничего не вызывает»).

## Влияние на систему

Артефакт — один новый HTML-файл в `tasks/T080/`, ничего в
`orchestrator/`, `scripts/`, `tests/` не меняется — codebase-map
регенерации не требует (правило скила — только при правке `*.py`
в этих каталогах). Кода панели, демона, API нет — инвариант границы
импортов `panel/` (ADR-0004 п.1) не затрагивается, потому что пакета
`panel/` эта задача не создаёт. Приёмочные тесты `tasks/T080/
acceptance_tests/` (T023, залочены test_author) не менялись — код
макета подгоняется под них, а не наоборот. Гейты/лимиты/guard —
не трогаются. Откат — удаление одного файла.

## Риски

- Данные, реальные на момент написания макета (числа из `docs/
  retro/*.md`), устареют по мере роста истории пульта — это ожидаемо
  для статического артефакта (SPEC явно фиксирует «статические
  примеры», не live-проекцию); П2′ (`artel report`) заменит их
  живыми данными на этапе 1 демона.

# SPEC: Предпосылка теста fetch базы рабочей копии не зависит от версии git

## Контекст
CI `main` красный на двух тестах
`tests/test_01m42nbcadgsgtcbzb8nkbvdvh_workspace_fetch.py`:
`LockedTrackingRefTest::test_ac3_ensure_succeeds_with_locked_tracking_ref`
и `TrackingRefUntouchedTest::test_ac4_ensure_fetch_does_not_move_tracking_ref`
(перезапуск CI main 2e3d25ae, прогон 40417365334, попытка 2, 31.10.2026;
тот же коммит зелёный 26.10). Образ раннера сменил git 2.55.0 → 2.56.0
(локально git 2.50 — файл зелёный). Падает предпосылка
`WorkspaceFetchSandbox.advance_origin` (`:56-70`), до кода пульта: голова
`origin` сдвигается `git push` по пути bare-репозитория, а git 2.56 при пуше
по пути, совпадающему с адресом `origin`, обновляет ссылку отслеживания
`refs/remotes/origin/<MAIN_BRANCH>` — проверка «ссылка отслеживания не
сдвинулась» (`:67-69`) падает. Красный CI `main` блокирует CI веток всех
задач (01M5XZ9Z68V75VXF5Z66C708T4 эскалирована по этой причине).

## Требования

1. `advance_origin` сдвигает голову `origin` на 1–3 коммита, не используя
   git пульта (`self.root`) для отправки: коммиты создаются и ссылка
   `refs/heads/<MAIN_BRANCH>` обновляется в самом bare-репозитории
   (`git --git-dir <origin> commit-tree` / `update-ref`).
2. Предпосылки `advance_origin` остаются прежними: голова `origin` сдвинута
   (проверка через `origin_head`), ссылка отслеживания пульта
   `refs/remotes/origin/<MAIN_BRANCH>` — на прежнем коммите
   (`tracking_before`); `advance_origin` по-прежнему возвращает новую
   голову `origin`.
3. Все проверки AC-3, AC-4, AC-5 файла
   (`test_ac3_ensure_succeeds_with_locked_tracking_ref`,
   `test_ac4_ensure_fetch_does_not_move_tracking_ref`,
   `test_ac5_unavailable_remote_named_refusal_without_branch`) — без
   изменений; число тестов и утверждений `assert*` в файле не уменьшается.
4. Описание сценария в строке документации модуля и строке документации
   метода `advance_origin` — по новому способу сдвига головы `origin`
   (вместо «пушем по пути bare-репозитория»).
5. Код пульта не меняется.

## Критерии приёмки

AC-1. Файл `tests/test_01m42nbcadgsgtcbzb8nkbvdvh_workspace_fetch.py` зелёный локально и в CI ветки задачи (раннер с git 2.56) — все три теста проходят.

AC-2. `advance_origin` не вызывает `git push` (и иную отправку) из git пульта: коммиты создаются и `refs/heads/<MAIN_BRANCH>` обновляется командами git с `--git-dir` bare-репозитория `origin`; сдвиг — на 1–3 коммита (из `self.rng`); строки документации модуля и метода `advance_origin` описывают этот способ, упоминания пуша по пути как способа сдвига в них нет.

AC-3. Предпосылки `advance_origin` (голова `origin` сдвинута; ссылка отслеживания пульта на прежнем коммите) и все проверки тестов AC-3, AC-4, AC-5 файла сохранены без изменений.

AC-4. Мутация «fetch базы по имени `origin` с обновлением ссылок отслеживания» в `workspace._fetched_base` краснит тесты AC-3 и AC-4 файла, тест AC-5 остаётся зелёным — как до правки.

AC-5. Число тестов и число утверждений (`assert*`) в файле не уменьшились относительно `main`.

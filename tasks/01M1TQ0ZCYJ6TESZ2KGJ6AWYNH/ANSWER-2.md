# ANSWER-2: решение по AC-2 и легализация правки планки (R2-F1, R2-F2)

## Ответы

1. **AC-2 переинтерпретирован решением Оператора 06.09 (возврат из
   verifying, запись журнала 10:07:44Z)**: запись «артефактная ветка от
   локального main: <причина>» пишется ТОЛЬКО когда remote `origin`
   существует, а `git fetch origin main` не удался (сеть, отказ origin).
   Репозиторий без remote `origin` (песочницы тестов, локальные копии)
   — молча локальный `main`, без записи: иначе любой первый коммит
   артефактной ветки в песочнице без origin красит существующие
   `tests/test_doctor_fix_ignored_artifacts.py` (три теста, AC-8) —
   зафиксировано CI b2c58faf. Формулировка AC-2 читается с этим
   уточнением; SPEC не переписывается (правка SPEC за гейтом — тем же
   каналом ANSWER, ADR-0005). R2-F1 закрыт этим пунктом.

2. **Правка планки `test_ac7_journal_records_fallback_reason.py`
   (коммит 2da2eb9e) легализована по ADR-0012**: содержание правки —
   ровно пункт 1 (сценарий «origin есть, fetch падает» вместо «origin
   нет»), спора с тестом нет. `amend-tests` эту правку не видит (команда
   читает только незакоммиченный worktree, правка уже в артефактной
   ветке — наблюдение в копилке 06.09), поэтому `tests_locked_sha`
   сдвинут Оператором прямой правкой БД `3ffa8655 → 2da2eb9e` с записью
   журнала «правка планки» 10:31:12Z. R2-F2 закрыт этим пунктом;
   повторно править планку не нужно.

3. **R2-F3** (прямая проверка отсутствия записи журнала при
   отсутствии origin в `test_ac2_local_main_fallback_parent.py`) —
   доработка планки разработчиком не допускается (лок). Проверку
   разрешаю добавить в `tests/` (общий набор, зона `tests/`), не в
   `acceptance_tests/`; планка остаётся как есть.

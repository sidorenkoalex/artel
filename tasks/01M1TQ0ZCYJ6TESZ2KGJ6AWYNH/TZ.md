# ТЗ: артефактная ветка новой задачи заводится от origin/main, а не от пина

# ТЗ: артефактная ветка новой задачи заводится от origin/main, а не от пина

Источник: инцидент 06.09. `artifact_branch.commit_files` при первом
коммите берёт родителя из `gitcmd.branch_head_sha(<локальный main>)`
(`artifact_branch.py`, строки ~118–121) — то есть от пина главной
копии (ADR-0013: HEAD главной копии = пин запущенной версии, он по
построению отстаёт от origin/main). Каталог `tasks/` в артефактной
ветке наследуется целиком от этого родителя. 06.09 черновики ревьювера,
уже удалённые с origin/main коммитом f29d97f2, оказались в артефактных
ветках двух задач, заведённых после удаления (01M1TNMBY8, 01M1TNN4TM):
ветки взяли `tasks/` от пина 603efe92, где файлы ещё были. CI обеих
веток красный по guard с первого пуша. Тот же механизм разнесёт любой
мусор или устаревший артефакт из пина по каждой новой задаче, пока пин
не обновлён.

Требуется:
1. Родитель первого коммита артефактной ветки — голова `origin/main`
   (после `git fetch origin main`, без изменения HEAD главной копии:
   пин не двигается). Если origin недоступен (нет сети/нет origin,
   песочницы) — как сегодня, локальный `main`, с записью в журнал
   задачи «артефактная ветка от локального main: <причина>».
2. Для внешнего target (клон целевого) — родитель по тому же правилу
   для origin целевого; поведение с `parent` при повторных коммитах
   (`branch_head_sha(branch)`) без изменений.
3. `doctor`: в проверке «артефактная ветка синхронна» (если она уже
   есть, задача журнала push; иначе — отдельная проверка) — `warn`,
   если родитель первого коммита артефактной ветки живой задачи не
   является предком `origin/main` (ветка заведена от устаревшего
   пина с расхождением).
4. Тесты: (а) в песочнице с локальным `origin`, ушедшим вперёд от
   `main`, первый коммит артефактной ветки имеет родителем голову
   `origin/main`, и `tasks/` в ветке — состояние origin, не пина;
   (б) без origin — родитель локальный `main` и запись журнала с
   причиной; (в) HEAD главной копии после `new` не изменился
   (мутация: `git pull` вместо `fetch` — тест обязан поймать);
   (г) существующие `tests/test_artifact_branch*.py`,
   `tests/test_catalog*.py` зелёные без правки ассертов.

Зоны: orchestrator/artifact_branch.py, orchestrator/catalog.py,
orchestrator/gitcmd.py, tests/.
Порядок: после мержа задачи журнала push (пересечение по
`artifact_branch.py`) — либо вместе с ней, если разработчик той задачи
сочтёт проще; сверить по `status`.

Не входит: обновление пина; пересоздание уже заведённых веток; уборка
`tasks/` в существующих артефактных ветках.

Рамка: $15.

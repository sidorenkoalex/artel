# SPEC: Трение конвейера: список защищённых путей в CI, карта в гейте ёмкости, калибровка бюджета

## Контекст

Разбор трения конвейера 21.09 по итогам двух волн (шесть задач 20–21.09,
$319, 11 поднятий потолка, 3 эскалации по бюджету) назвал три
независимых источника трения.

Первый: ввод нового защищённого пути невозможен ни одним путём. Джоб
`protected-paths` (`.github/workflows/ci.yml`, строка 247) собирает
список однострочником `python3 -c "from orchestrator import config; …"`,
то есть из кода ВЕТКИ PR, а гейты пульта
(`orchestrator/advance_gates/zones.py`,
`orchestrator/advance_gates/plan_appendix.py`,
`orchestrator/fsm_merge_gate.py`) читают тот же список в главной копии.
Ветка, которая создаёт файл и тем же изменением вносит его в список,
красит собственный PR; провести путь приложением к PLAN тоже нельзя —
гейт приложений сверяется со списком главной копии, где пути ещё нет
(следствие 20.09, задача 01M3009Y9A и `models.yaml`:
`orchestrator/config.py`, строки 605–618).

Второй: гейт ёмкости меряет сгенерированную карту.
`orchestrator/advance_gates/capacity.py` исключает из меры артефакты
задачи (`:!tasks/<id>/`), но не `docs/codebase-map.md`, которую
ревьювер построчно не читает — она приходит ему отдельным компонентом
пакета (`orchestrator/context_package.py`). Факт 21.09: diff кода
286 927 байт при потолке 262 144, из них 47 987 байт (17 %) — карта;
обходом Оператор временно поднял потолок до 320 000
(`orchestrator/config.py`, строка 454).

Третий: калибровочная таблица `config.BUDGET_CALIBRATION_TABLE`
(читает `orchestrator/budget.py::recommended_budget_usd`) обрывается на
уровне «всё остальное»: и задача с 5 зонами, и задача с 14 получают
одну рекомендацию $70. По 108 задачам сентября (состояние done, зоны
сняты) таблица завышает для типовых задач (медиана 1–3 зон $16.72
против $35) и занижает для крупных (80-й перцентиль 8+ зон $82.80
против $70) — отсюда 11 поднятий потолка и 3 эскалации за 20–21.09.

## Требования

1. Джоб `protected-paths` берёт список защищённых путей из БАЗЫ
   сравнения PR (`$BASE_SHA`), а не из ветки: источник — значение
   `PROTECTED_PATHS` в тексте `orchestrator/config.py` базы. Единый
   источник списка сохраняется — собственного перечня или regex
   защищённых путей джоб не несёт.
2. Логика выбора списка и сверки его с изменёнными файлами живёт
   python-модулем репозитория `scripts/ci_protected_paths.py` (stdlib),
   джоб зовёт его — тем же приёмом, каким вынесен классификатор пуша
   `scripts/ci_push_class.py` (ADR-0016, `.github/workflows/ci.yml`,
   строки 176–186). Обоснование выбора способа (ТЗ, требование 1
   оставляет его аналитику): правка `.github/` идёт приложением к PLAN
   и применяется пультом на мерже, то есть текста нового джоба в ветке
   задачи нет ни в один момент её жизни — логика, оставленная в yaml,
   недоступна тестам ветки (ТЗ, требование 5) в принципе. Модуль в
   ветке и тестируем, и остаётся единственным местом этой логики.
   Список при этом берётся из базы, а не импортом `orchestrator.config`
   ветки, — подмена списка в ветке на результат сверки не влияет.
3. Список базы не прочитан (файла в базе нет, git не ответил, значение
   не разбирается) — джоб падает с явным сообщением о причине
   (fail-closed, ADR-0002: неизвестный статус — это «нельзя»). Молчаливо
   зелёного исхода на нечитаемой базе нет.
4. Ветка, впервые создающая файл и вносящая его в список тем же
   изменением, джоб не красит. Ветка, правящая путь, уже защищённый в
   базе, — красит, как сегодня, с перечислением путей-нарушителей.
5. Гейт ёмкости `orchestrator/advance_gates/capacity.py` исключает из
   меры `docs/codebase-map.md` тем же приёмом, каким исключает
   `tasks/<id>/` (pathspec `:!`), и называет объём исключённой карты в
   тексте отказа отдельной цифрой — рядом с цифрой артефактов задачи.
   Сбой git на этой второй мере отказ не отменяет: объём карты в этом
   случае назван «неизвестен», а не вымышленным числом; карты в диффе
   нет — цифра 0 байт, решение гейта прежнее. Порог
   `REVIEW_SNAPSHOT_DIFF_MAX_BYTES` не меняется.
6. `config.BUDGET_CALIBRATION_TABLE` получает четвёртый уровень и
   пересмотренные нижние уровни. Предложение аналитика по фактам
   сентября (уровень — 80-й перцентиль своей группы, округлённый до
   $5); решение о конкретных значениях — Оператора на гейте SPEC:

   | файлов зоны | 80-й перцентиль факта | уровень | макс. критериев приёмки | макс. файлов зоны |
   |---|---|---|---|---|
   | 1–3 | $24.43 | $25 | 5 | 3 |
   | 4 | $39.50 | $40 | 10 | 4 |
   | 5–7 | $44.61 | $45 | 15 | 7 |
   | 8+ | $82.80 | $85 | не ограничен | не ограничен |

   Ось критериев приёмки первых двух уровней сохранена как сегодня
   (5 и 10); граница 15 третьего уровня — интерполяция аналитика:
   выборка сентября разложена по файлам зон, оси критериев приёмки в
   ней нет.
7. Комментарий над таблицей в `orchestrator/config.py` несёт дату
   пересчёта (21.09.2026), выборку (108 задач сентября в состоянии
   done со снятыми зонами) и правило выбора уровня (80-й перцентиль
   факта своей группы, не медиана). `BUDGET_CALIBRATION_FLOOR_USD` не
   меняется.
8. `skills/spec-authoring.md` (строки 30–37) повторяет числа калибровки
   прозой («~35 / ~45 / ~70») — вопреки допущению ТЗ о том, что скил
   ссылается только на имя константы. Числа приводятся к новой таблице
   приложением к PLAN (ТЗ предусматривает этот исход: «если
   потребуется — приложением»).
9. `docs/adr/0014-budget-default-and-role-cap.md` этой задачей не
   правится (ТЗ, требование 4 оставляет решение аналитику):
   п.7 решения ADR числа не называет, а прямо делегирует их таблице
   `config.BUDGET_CALIBRATION_TABLE` и полу
   `config.BUDGET_CALIBRATION_FLOOR_USD` — пересчёт значений идёт в
   рамках уже принятого решения, дата/выборка/правило живут
   комментарием над самой таблицей (требование 7).
10. Тесты в `tests/`: сценарии выбора списка джобом, мера гейта
    ёмкости с картой и без неё, рекомендация по каждому уровню новой
    таблицы и пол рекомендации. Существующие
    `tests/test_protected_paths_gate.py`, `tests/test_capacity_gate.py`,
    `tests/test_spec_budget.py`, `tests/test_invariants.py` остаются
    зелёными; перечень обновлённых ожиданий — в PLAN.
11. Приложения к PLAN (защищённые пути, применяет пульт на мерже):
    `.github/workflows/ci.yml` — джоб `protected-paths`;
    `skills/spec-authoring.md` — числа калибровки. Каждое приложение
    применяется на чистом дереве (`git apply --check`).

## Критерии приёмки

AC-1. Дан текст `orchestrator/config.py` базы, в котором пути X нет в
`PROTECTED_PATHS`, и список изменённых веткой файлов, содержащий X:
логика джоба нарушений не находит (джоб зелёный).

AC-2. Дан текст `orchestrator/config.py` базы, в котором путь X уже в
`PROTECTED_PATHS`, и список изменённых веткой файлов, содержащий X:
логика джоба находит нарушение, называет X и даёт ненулевой код
возврата.

AC-3. Результат сверки определяется текстом `orchestrator/config.py`
базы, а не списком `PROTECTED_PATHS` ветки: при списке ветки, отличном
от списка базы, ответ совпадает с ответом по списку базы.

AC-4. Текст `orchestrator/config.py` базы не прочитан или значение
`PROTECTED_PATHS` из него не разбирается: логика сообщает о причине и
даёт ненулевой код возврата (зелёного исхода на нечитаемой базе нет).

AC-5. Гейт ёмкости на ветке, diff которой содержит изменение
`docs/codebase-map.md`, сравнивает с потолком объём diff БЕЗ карты:
переход, у которого код без карты укладывается в
`config.REVIEW_SNAPSHOT_DIFF_MAX_BYTES`, а вместе с картой превышает
его, гейт пропускает.

AC-6. Текст отказа гейта ёмкости называет объём исключённой
`docs/codebase-map.md` отдельной цифрой в байтах — рядом с цифрой
исключённых артефактов `tasks/<id>/`.

AC-7. Карты в diff ветки нет — цифра карты в отказе «0 байт
(изменений нет)», а решение гейта (отказ либо пропуск) совпадает с
решением до этой задачи; git не ответил на меру карты — цифра карты
«неизвестен», отказ по превышению потолка кодом остаётся в силе.

AC-8. `budget.recommended_budget_usd` по новой таблице отвечает: (5
критериев приёмки, 3 файла зоны) — $25; (10, 4) — $40; (15, 7) — $45;
(20, 9) — $85. Ответ на любом входе не ниже
`config.BUDGET_CALIBRATION_FLOOR_USD`.

AC-9. Комментарий над `BUDGET_CALIBRATION_TABLE` в
`orchestrator/config.py` содержит дату пересчёта 21.09.2026, выборку
(задачи done сентября со снятыми зонами) и правило выбора уровня по
80-му перцентилю.

## Оценка объёма и деление

Сработавшие сигналы: число затрагиваемых модулей/файлов (в тексте SPEC
упомянуто больше пяти путей вида `orchestrator/*.py` — считая читателей
списка и генератор карты, которые задача только читает); возможен
сигнал «затронут инвариантный механизм» (зона задевает
`orchestrator/config.py`). Прогноз диффа: 14 КиБ — вшестеро ниже
половины потолка гейта ёмкости.

Решение — **монолит**, три правки одной задачей, как и заводило ТЗ.
Честно: части технически разрезаемы — каждая из трёх правок мержима
сама по себе с зелёной планкой, атомарной смены механики между ними
нет. Не режу по цене: фактический объём — три файла зоны (по 10–40
строк правки в каждом), один новый модуль stdlib и тесты, тогда как
каждая подзадача несёт свою фиксированную цену цикла (аналитик,
test_author, разработчик, две итерации ревью ≈ $15–20 сверх кода), то
есть деление на три стоило бы втрое против рамки $45 на всю задачу.
Сигнал числа файлов сработал по счётчику УПОМЯНУТЫХ путей, а не по
числу правимых: правятся три модуля и `tests/`. Решение — за
Оператором на гейте SPEC.

Отдельно к сведению Оператора: при 9 критериях приёмки и 5 путях зоны
действующая калибровка даёт ориентир $70, поэтому гейт SPEC покажет
предупреждение «рамка ниже калибровки: $45.00 против ~$70.00».
Оставляю $45 — это рамка ТЗ и она же соответствует фактическому объёму
правок; по новой таблице (требование 6) ориентир для этой задачи —
$45, ровно рамка.

- Автоматическое поднятие потолка задачи без команды Оператора —
  бюджет остаётся его решением (ADR-0014).
- Исключение из гейта ёмкости иных сгенерированных файлов, кроме
  `docs/codebase-map.md`.
- Правка остальных джобов `.github/workflows/ci.yml`, кроме
  `protected-paths`.
- Проверка утечки пула канарейки и уборка осиротевших веток —
  отдельные строки копилки 21.09.
- Изменение `config.BUDGET_CALIBRATION_FLOOR_USD` и порогов сигналов
  объёма (`config.SPLIT_SIGNAL_BUDGET_USD` и соседние): задача
  пересчитывает только уровни таблицы, хотя новый верхний уровень $85

- Правка `docs/adr/0014-budget-default-and-role-cap.md` (обоснование —
  требование 9).
- Правка читателей списка защищённых путей:

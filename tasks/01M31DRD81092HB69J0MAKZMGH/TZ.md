# ТЗ: Трение конвейера: список защищённых путей в CI, карта в гейте ёмкости, калибровка бюджета

Источник: разбор трения конвейера 21.09 по итогам двух волн (шесть
задач 20–21.09, $319, 11 поднятий потолка, 3 эскалации по бюджету).
Строки копилки 20.09 «CI-джоб protected-paths читает список из ветки
PR», 21.09 «Правка кода Оператором в main — только обходом» (кандидат
«гейт ёмкости не считает docs/codebase-map.md») и 21.09 «Задача,
вводящая новый конфигурационный файл, стоит вдвое против калибровки».
Три независимых источника трения, лечатся тремя небольшими правками.

Факты:

1. Ввод нового защищённого пути невозможен ни одним путём.
   Джоб `protected-paths` (`.github/workflows/ci.yml`, ~строка 247)
   считает список так: `PROTECTED=$(python3 -c "from orchestrator import
   config; …")` — то есть из кода ВЕТКИ PR (checkout HEAD), затем
   `git diff --name-only "$BASE_SHA"...HEAD | grep -E "^($PROTECTED)"`.
   Гейты пульта (`orchestrator/advance_gates/zones.py::_protected`,
   `orchestrator/advance_gates/plan_appendix.py`,
   `orchestrator/fsm_merge_gate.py::_protected_path_diff_gate`) читают
   `config.PROTECTED_PATHS` ГЛАВНОЙ КОПИИ. Следствие 20.09
   (01M3009Y9A, `models.yaml`): ветка, которая создаёт файл и в том же
   коммите вносит его в список, красит собственный PR на создании
   файла; провести файл приложением к PLAN тоже нельзя — гейт
   приложений сверяется со списком главной копии, где пути ещё нет.
   Обход: внесение в список перенесено в следующую задачу, подтест
   залоченной планки исправлен `amend-tests`, потеряны возврат из
   verifying и шаг developer.

2. Гейт ёмкости меряет сгенерированную карту.
   `orchestrator/advance_gates/capacity.py` считает
   `git diff <база>...<ветка> -- . ':!tasks/<id>/'` и сравнивает с
   `config.REVIEW_SNAPSHOT_DIFF_MAX_BYTES`. Артефакты задачи исключены
   (требование AC-1 предшественника), а `docs/codebase-map.md` — нет.
   Факт 21.09 (01M3009Y9A): diff кода 286 927 байт при потолке 262 144,
   из них 47 987 байт (17 %) — карта, которую генерирует
   `scripts/codebase_map.py` и которую ревьювер построчно не читает
   (она приходит ему отдельным компонентом пакета, `orchestrator/
   context_package.py`). Обход: Оператор временно поднял потолок до
   320 000 прямым коммитом (d9e08a11), с обязательством вернуть
   262 144 после мержа 01M3009Y9A.

3. Калибровочная таблица обрывается на «всё остальное».
   `config.BUDGET_CALIBRATION_TABLE` = ((35, 5 AC, 3 файла), (45, 10,
   4), (70, None, None)); читает `orchestrator/budget.py::
   recommended_budget_usd`; ADR-0014 п.7. Верхний уровень один и тот
   же и для задачи с 5 зонами, и для задачи с 14 — рекомендация $70 в
   обоих случаях. Факт по 108 задачам сентября со снятыми зонами
   (состояние done):

   | файлов зон | задач | медиана | 80-й перцентиль | максимум |
   |---|---|---|---|---|
   | 1–3 | 44 | $16.72 | $24.43 | $74.41 |
   | 4 | 31 | $23.71 | $39.50 | $55.51 |
   | 5–7 | 27 | $32.89 | $44.61 | $59.90 |
   | 8+ | 6 | $66.88 | $82.80 | $141.21 |

   То есть для типовых задач таблица завышает (медиана 1–3 зон $16.72
   против рекомендации $35), а для крупных занижает (медиана 8+ зон
   $66.88, 80-й перцентиль $82.80 против той же рекомендации $70).
   Следствие: 11 поднятий потолка и 3 эскалации по бюджету за 20–21.09;
   каждая эскалация — остановка цикла до команды Оператора.

Требуется:

1. Джоб `protected-paths` считает список защищённых путей из БАЗЫ
   сравнения PR, а не из ветки: `git show "$BASE_SHA":orchestrator/
   config.py` во временный файл и разбор его же python-однострочником
   (либо иной способ, дающий список базы, — выбор аналитика,
   обосновать в SPEC). Так ветка, впервые создающая файл и вносящая его
   в список, проходит, а любая следующая задача, правящая уже
   защищённый путь, отказывается как сегодня. Единый источник списка
   (`config.PROTECTED_PATHS`, не отдельный regex в yaml) сохраняется.
   `.github/` — защищённый путь: правка идёт приложением к PLAN.
2. Гейт ёмкости исключает из меры `docs/codebase-map.md` тем же
   приёмом, каким исключает `tasks/<id>/` (pathspec `:!`), и называет
   исключённый объём в тексте отказа отдельной строкой — как сегодня
   называет объём артефактов задачи. Порог `REVIEW_SNAPSHOT_DIFF_MAX_
   BYTES` этой задачей НЕ меняется.
3. Калибровочная таблица получает четвёртый уровень для крупных задач
   и пересмотренные нижние уровни по фактам сентября (числа — предложение
   аналитика на основании таблицы из «Фактов», решение о конкретных
   значениях принимает Оператор на гейте SPEC; ориентир: уровни
   выбираются по 80-му перцентилю факта своей группы, не по медиане,
   чтобы рекомендация покрывала типовой разброс). Комментарий над
   таблицей несёт дату пересчёта, выборку (задачи done сентября со
   снятыми зонами) и правило выбора уровня. `BUDGET_CALIBRATION_FLOOR_
   USD` не меняется.
4. Документация: `docs/adr/0014-budget-default-and-role-cap.md`
   получает абзац «Пересчёт 21.09» с той же выборкой и правилом —
   защищённый путь, приложением к PLAN. Если аналитик сочтёт, что
   правка ADR не требуется (таблица меняется в рамках уже принятого
   решения), — обосновать в SPEC и не заводить приложение.
5. Тесты (tests/): джоб — проверка логики выбора списка на уровне,
   доступном тестам (сценарий «путь создан и внесён в список одной
   веткой — джоб не падает»; «путь уже в списке базы и правится веткой
   — падает»); гейт ёмкости — карта не входит в меру, её объём назван
   в отказе, поведение без карты в диффе прежнее; калибровка —
   рекомендация по каждому уровню новой таблицы, включая крупный,
   и пол рекомендации. Существующие `tests/test_protected_paths_gate.py`,
   `tests/test_capacity_gate.py` (если есть; иначе — тесты гейта в
   существующем наборе), `tests/test_budget*.py`, `tests/test_ci_workflow*.py`
   остаются зелёными; перечень обновлённых ожиданий — в PLAN.

Зоны: orchestrator/advance_gates/capacity.py, orchestrator/config.py,
orchestrator/budget.py, tests/.

Приложением: .github/workflows/ci.yml (джоб protected-paths),
docs/adr/0014-budget-default-and-role-cap.md (абзац о пересчёте, если
аналитик сочтёт нужным) — защищённые пути, применяет пульт на мерже.

Только чтение (не менять): orchestrator/advance_gates/zones.py и
orchestrator/advance_gates/plan_appendix.py (читатели списка — не
меняются), orchestrator/fsm_merge_gate.py, orchestrator/context_package.py
(карта приходит ревьюверу отдельным компонентом — основание исключения),
scripts/codebase_map.py (генератор карты), orchestrator/gitcmd.py
(`diff_base`, `diff_names` как есть), skills/spec-authoring.md
(ссылается на имя константы, числа не повторяет — правка не требуется;
если потребуется — приложением), docs/backlog.md (источник),
docs/research/providers-codex-plan.md, tasks/ (артефакты задач),
.artel/ (локальный слой пульта вне git), .github/ и docs/adr/ (кроме
названных приложением файлов — не меняются), orchestrator/ (модули вне
перечисленных выше — не меняются).

Не входит: изменение самого потолка REVIEW_SNAPSHOT_DIFF_MAX_BYTES
(его временный подъём до 320 000 возвращает Оператор после мержа
01M300A14K); автоматическое поднятие потолка задачи без команды
Оператора (бюджет остаётся его решением, ADR-0014); исключение из
гейта ёмкости иных сгенерированных файлов кроме карты; правка
остальных джобов CI; проверка утечки пула канарейки и уборка
осиротевших веток (отдельные строки копилки 21.09).

Рамка: $45.

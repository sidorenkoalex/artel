# ТЗ: Цикл auto останавливается, если после его старта сдвинут пин

Источник: строка копилки 02.10 (П2) «Живой цикл auto после pin-update
продолжает работать на старом коде»; разбор копилки после ревизии 02.10.

Факты (origin/main):
- 02.10 задача 01M3XTF5506GF43HD51ECE230T эскалировала в 10:06Z из
  процесса auto pid 2063, запущенного в 08:27 — до мержа
  01M3XTF1CEBXT4J7P0EKG5J342 (исправление зацикливания эскалации) и до
  сдвига пина на 393172e4. Цикл исполнял старый код: после ANSWER-1 и
  approve он повторил эскалацию (10:14Z), понадобился ANSWER-2.
- Пин — HEAD главной копии; сдвиг пина и откат пишутся в журнал `steps`
  у псевдозадачи `config.PIN_UPDATE_JOURNAL_TASK_ID` («PIN-UPDATED»,
  `config.py:229`): записи «pin обновлён» и «pin откатан» (`pin.py:73-75`,
  `:100`) со временем `ts`.
- Цикл `_cmd_auto` (`orchestrator/auto.py:1052`) пишет «auto старт»
  (`:1062`) и проверяет команду `stop` в верхней части каждой итерации
  (`:1090`) и на каждом опросе ожидания зоны (`_wait_for_zone`,
  `:188`). Сдвиг пина не проверяется нигде; ни lease, ни запись «auto
  старт» не хранят, на каком коде запущен цикл. `pin-update` и `doctor`
  о живых циклах, запущенных до пина, не сообщают.
- Задача в работе 01M3SF7DPFGEZ7VYEGGXGTX49E держит `orchestrator/pin.py`,
  `orchestrator/doctor/`, `orchestrator/artel.py` — эта задача их не
  трогает: проверка целиком в модуле цикла.

Требуется:
1. На границе между шагами (там же, где проверка `stop`, `auto.py:1090`)
   и на каждом опросе ожидания зоны (`_wait_for_zone`) цикл проверяет,
   есть ли в журнале запись «pin обновлён» или «pin откатан» у
   `PIN_UPDATE_JOURNAL_TASK_ID` с идентификатором записи больше, чем
   последняя такая запись на момент старта цикла (момент старта
   фиксируется до первой итерации). Сравнение — по идентификатору записи
   журнала, не по времени и не по HEAD: локальные коммиты в главной копии
   (копилка, doc-commit) остановку не вызывают.
2. При найденном сдвиге цикл завершается штатно, как по `stop`: задача
   остаётся в своём состоянии, начатый шаг не прерывается, lease
   снимается `lease.run_locked`, эскалации нет. Запись «auto остановлен»
   через `auto_stop` с причиной, называющей старый и новый sha из
   записи журнала пина, и подсказкой перезапуска
   `cycle_hint.launch_text(conn, task_id, "auto", …)`; алерт Оператору
   поднимается (остановка без его команды).
3. Запись «auto старт» дополняется sha HEAD главной копии на момент
   старта (`gitcmd.head_sha()`) — для разбора по журналу.
4. Канареечная задача ведёт себя так же (журнал пина клона канарейки свой;
   отдельной ветки кода для канарейки нет).
5. Тесты в `tests/` (по образцу `tests/test_auto_cycle.py`, проверки
   `_stop_requested` на границе шагов, около `:1326-1377`), каждый с
   «Ловит мутацию: …»:
   а) запись «pin обновлён» появилась во время шага → цикл остановлен на
      следующей границе, состояние задачи прежнее, причина называет оба
      sha, алерт поднят («Ловит мутацию: проверка убрана с границы
      шагов»);
   б) запись появилась во время ожидания зоны → ожидание прервано тем же
      исходом («Ловит мутацию: проверка только в верхней части цикла»);
   в) запись «pin обновлён», сделанная ДО старта цикла, остановки не
      вызывает («Ловит мутацию: сравнение с нулём вместо отметки
      старта»);
   г) локальный коммит в главной копии без записи журнала пина остановки
      не вызывает («Ловит мутацию: сравнение по HEAD»);
   д) запись «pin откатан» останавливает так же, как «pin обновлён»;
   е) запись «auto старт» содержит sha HEAD.
6. Существующие тесты не ослабляются и не удаляются; полный набор
   `tests/` зелёный.

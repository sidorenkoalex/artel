# QUESTIONS: Предупреждение операторских команд при чужом живом lease

## Вопросы

1. **ТЗ (требование 1) утверждает, что перечисленные операторские команды
   «по дизайну не блокируются lease» и «ВЫПОЛНЯЮТСЯ как раньше» при
   чужом живом lease — это неверно для 5 из 7 команд списка.**
   Проверено по коду: `approve` (`orchestrator/fsm.py::cmd_approve`),
   `reject` (`cmd_reject`), `budget` (`orchestrator/budget.py::cmd_budget`),
   `kill` (`orchestrator/cleanup.py::cmd_kill`) и `answer`
   (`orchestrator/answer.py::cmd_answer`) уже проходят через
   `lease.run_locked(..., on_refusal="exit")` (дефолт) — при чужом
   ЖИВОМ lease это `sys.exit()` с именованным отказом ДО вызова тела
   команды: она физически не исполняется, не «выполняется как раньше».
   Только `pause` (`orchestrator/pause.py::cmd_pause`) и `release`
   (`orchestrator/release.py::cmd_release`) сегодня не берут lease вовсе
   и исполняются безусловно — только для них предупреждение «до
   выполнения, не блокируя» технически достижимо без изменения текущей
   защиты.
   Буквальное требование 1 для остальных пяти команд означает снять их
   существующий хард-блок (`on_refusal="exit"` → выполнение с
   предупреждением вместо отказа) — это ослабление защиты, введённой
   T044 специально для предотвращения параллельных мутирующих циклов,
   и по духу ADR-0002 (принцип целостности) требует ADR Оператора, а не
   тихого решения на этапе SPEC/разработки. Это же прямо пересекается
   с границей самого ТЗ «Не входит: ... изменение механики lease».

   Варианты:
   A) Предупреждение — только для `pause`/`release` (единственных двух
      команд, которые СЕГОДНЯ исполняются безусловно). Для `approve`/
      `reject`/`budget`/`kill`/`answer` поведение не меняется: чужой
      живой lease по-прежнему отказывает команде целиком (текущий
      именованный отказ уже называет держателя, возраст heartbeat —
      функционально близко к предупреждению, только с отказом вместо
      выполнения). SPEC явно фиксирует это ограничение объёма в «Не
      входит» и ссылается на находку здесь.
   B) Требование 1 применяется буквально ко всем 7 командам: для
      `approve`/`reject`/`budget`/`kill`/`answer` `on_refusal` меняется
      так, чтобы при чужом живом lease печаталось предупреждение и
      выполнение ПРОДОЛЖАЛОСЬ (не `sys.exit`) — то есть хард-блок T044
      для операторских команд снимается. SPEC явно отмечает это как
      ослабление существующей защиты и требует ADR Оператора отдельным
      пунктом критериев приёмки (не тихой правкой).
   — дефолт: **A** — минимальное прочтение, не трогающее существующую
   защиту без явного решения Оператора; если Оператор промолчит,
   задача реализуется только для `pause`/`release`.

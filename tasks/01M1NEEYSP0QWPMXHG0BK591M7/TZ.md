# ТЗ: Предупреждение операторских команд при чужом живом lease

Источник: инцидент 02.09.2026 — ассистентская сессия диагностировала
задачу в `verifying` и рекомендовала действие по её ветке (push),
не увидев, что задачу в этот момент активно ведёт другая сессия
с живым lease. Замок от параллельных МУТИРУЮЩИХ циклов уже есть
(advisory lease T044: второй `run`/`auto` отвергается с именем
держателя), видимость держателя в `status` добавляет задача
«Наблюдаемость сессий» (01M1GCHKG8DDK4DCZWCE3DYKWC, AC-11).
Непокрытым остаётся слой ОПЕРАТОРСКИХ команд: они по дизайну
не блокируются lease (и не должны), но исполняются молча — без
сигнала «ты вмешиваешься в задачу, которую прямо сейчас ведёт
другая сессия».

ЗАПУСКАТЬ ПОСЛЕ мержа задачи «Наблюдаемость сессий» — использует
её единый session_id и не должна пересекаться с её зоной
(lease.py, catalog.py, cleanup.py, release.py).

Требуется:
1. Операторские команды, изменяющие задачу или её ход (`approve`,
   `reject`, `budget`, `release`, `kill`, `pause`, `answer`), при
   ЧУЖОМ живом lease у задачи (heartbeat свежий, pid адресуем,
   session_id не равен текущей сессии) печатают предупреждение до
   выполнения: держатель (session_id), возраст heartbeat, роль/шаг,
   если известны. Команда ВЫПОЛНЯЕТСЯ как раньше — предупреждение
   информирует, не блокирует и не спрашивает подтверждения.
2. Собственный живой lease текущей сессии и мёртвый/протухший чужой
   предупреждения не вызывают (для мёртвого свой сигнал уже есть —
   doctor и рекон наблюдаемости).
3. Предупреждение дублируется событием журнала задачи (тем же
   журнальным API, с session_id) — постфактум видно, что
   вмешательство было предупреждённым.
4. Read-only команды (`status`, `log`, `show`, `doctor`) предупреждение
   не печатают — наблюдение двумя сессиями штатно и безвредно.
5. Тесты: предупреждение при чужом живом lease у каждой команды из
   списка; отсутствие предупреждения при своём/мёртвом lease и у
   read-only команд; команда исполняется несмотря на предупреждение;
   событие журнала пишется; существующие тесты зелёные.

Зоны: точки входа перечисленных операторских команд
(orchestrator/fsm.py — approve/reject, budget.py, release.py,
cleanup.py, pause.py, answer.py), общий хелпер проверки чужого lease
(рядом с lease.py/liveness.py, не меняя их механику), tests/.
Конфликт зон с ещё не смерженными задачами — эскалация.

Не входит: блокировка или подтверждение операторских команд (только
предупреждение); изменение механики lease и лимитера; регистрация
read-only наблюдателей задачи.

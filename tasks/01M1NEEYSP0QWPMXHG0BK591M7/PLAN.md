# PLAN: Предупреждение при чужом живом lease (pause, release)

## Подход

Общий хелпер в `orchestrator/lease.py` (уже даёт `liveness`/`config`/
`session`/`store` — естественное место, без нового модуля):

- `foreign_live_lease(conn, task_id, session_id)` — строка `leases`, если
  она принадлежит ДРУГОЙ сессии и «жива»: heartbeat не старше
  `config.LEASE_STALE_AFTER_SEC` И `liveness._pid_alive(pid)` — иначе
  `None`.
- `warn_foreign_live(conn, task_id, session_id)` — печатает предупреждение
  (держатель + числовой возраст heartbeat) и дублирует его отдельной
  записью `store.journal(..., session_id=row["session_id"])` — SPEC,
  требование 3, явно требует identity ДЕРЖАТЕЛЯ, не текущей сессии.

Оба вызывающих места (`pause.cmd_pause`, `release.cmd_release`) зовут
`lease.warn_foreign_live` ПЕРВОЙ строкой после `resolve_task_id` — до
веток "уже на паузе"/"lease не заведён": предупреждение о том, что
задачу ведёт другая сессия, верно независимо от того, оказывается ли
сама команда no-op.

**Живость без различения host.** `catalog._lease_holder_suffix` и
`lease.acquire` для ЧУЖОГО host трактуют неадресуемый pid как «жив»
(неопределённость там безопаснее в сторону «не перехватывать чужой
активный lease» / «не показывать ложно мёртвым»). Здесь цель другая:
предупреждение обязано указывать на РЕАЛЬНО проверяемый процесс, поэтому
`foreign_live_lease` проверяет `liveness._pid_alive(pid)` НАПРЯМУЮ, без
допущения «чужой host = жив». Это совпадает с буквальным условием SPEC
(«pid адресуем» — адресуем ИМЕННО отсюда, вызывающим процессом) и
сохраняет зелёным существующий `tests/test_release.py::
test_journals_former_holder_with_numeric_heartbeat_age` (чужой host,
`pid=424242` — заведомо невалидный на этой ОС, поэтому не «адресуем» и
предупреждение не добавляет вторую запись журнала, которую тест не
ожидает).

**Роль/шаг не добавлены.** Требование 1 упоминает «роль/шаг — если
известны» как опциональное поле. Единственный источник роли текущего
шага (`runner.step_role`) живёт в `orchestrator/runner.py`, который сам
импортирует `pause`/`lease` — обратный импорт создал бы цикл. Поле
явно необязательное («если известны»), AC-3 к тому же явно сужает состав
для `release` до «держатель, возраст heartbeat» без роли — решение:
не добавлять роль/шаг вовсе, минимальным составом, покрывающим все AC.

## Шаги

1. `orchestrator/lease.py`: `foreign_live_lease` + `warn_foreign_live` с
   докстрингами (ссылка на эту задачу).
2. `orchestrator/pause.py`: `cmd_pause` зовёт `lease.warn_foreign_live`
   первой строкой; обновление модульного докстринга (описание больше не
   актуально — «pause вовсе не читает leases»).
3. `orchestrator/release.py`: `cmd_release` зовёт `lease.warn_foreign_live`
   первой строкой; обновление модульного докстринга (аналогично).
4. Юнит-тесты: `tests/test_lease.py` (новые функции в изоляции —
   свой/чужой/мёртвый/протухший, содержимое detail), `tests/test_pause.py`
   и `tests/test_release.py` (интеграция предупреждения в команду, включая
   регресс — без чужого живого lease вывод не меняется).
5. Прогон `tasks/.../acceptance_tests/`, полного `tests/`, `scripts/
   guard.py` на артефактах, регенерация `docs/codebase-map.md`.

## Влияние на систему

- Новый импорт `lease` в `pause.py` не создаёт цикла: `lease.py`
  импортирует только `config`/`liveness`/`session`/`store` — ни один из
  них не зависит от `pause`. `release.py` уже импортирует `store`/
  `liveness`, добавляется только `lease`.
- Вывод `pause`/`release` меняется ТОЛЬКО в новом случае (чужой живой
  lease) — байт-в-байт совпадает с текущим при своём/отсутствующем/
  мёртвом/протухшем lease (AC-4, AC-5 приёмочных тестов проверяют это
  явно). Существующая защита T044 пяти команд (`approve`/`reject`/
  `budget`/`kill`/`answer` через `lease.run_locked(..., on_refusal=
  "exit")`) не трогается — хелпер не вызывается ни из одной из них.
- Новая запись журнала — аддитивная (ровно одна лишняя запись поверх уже
  существующей), не меняет формат/содержимое прежних записей `pause`/
  `pause: pause`/`resume`/`lease снят Оператором`.
- `docs/codebase-map.md` будет перегенерирован тем же коммитом (правка
  `*.py` в `orchestrator/`, conventions-core).
- Откат: удалить два новых вызова `lease.warn_foreign_live` из `cmd_pause`/
  `cmd_release` и сами функции из `lease.py` — поведение возвращается к
  сегодняшнему без следов (аддитивное изменение, ничего не заменено).

## Риски

- `pause.cmd_pause_now` в ветке «host вне объёма» (`orchestrator/
  pause.py::cmd_pause_now`, строки 195-205) сам журналирует «pause --now:
  host вне объёма», а затем зовёт `cmd_pause(task_id)` — если чужой lease
  на этой ветке технически проходит проверку `foreign_live_lease`
  (pid оказался адресуем локально, хотя host помечен другим — искусственный
  случай, воспроизводимый только когда тестовый процесс с реальным локальным
  pid намеренно помечен чужим hostname, как делает `tests/test_pause_now.py::
  test_other_host_refuses_interrupt_and_leaves_process_untouched`), в журнал
  добавится ВТОРАЯ, отчасти дублирующая запись. Не покрыто ни одним AC
  этой SPEC (`pause --now` не входит в её объём), ни один существующий
  тест не проверяет точное число записей в этой ветке — оставлено как
  есть, не устраняется в рамках этой задачи.

# QUESTIONS: auto: детекция буксования цикла и алерты Оператору

## Вопросы

1. **Требование 3б («алерт авто-закрывается при следующем успешном
   переходе задачи») — каким механизмом и в каких зонах.** «Зоны»
   ТЗ ограничивают задачу файлами `orchestrator/auto.py`,
   `orchestrator/alerts.py`, `orchestrator/config.py` (только
   константа порога) и `tests/`. Но общие переходы состояния задачи
   (`store.set_state`) вызываются не только изнутри `auto` — так же
   переходит задача при ручном `artel.py advance`/`approve`/`reject`
   Оператора (`orchestrator/fsm.py`, `orchestrator/fsm_advance.py`),
   которые в «Зонах» не названы. Буквальное «на любом успешном
   переходе задачи» требует хука в `fsm.py`/`fsm_advance.py` —
   пересечение зон, для A7 в этом же ТЗ прямо названное поводом для
   эскалации («конфликт зон — эскалация»). — варианты:
   A) авто-закрытие живёт целиком внутри `orchestrator/auto.py` —
   алерт закрывается, когда СЛЕДУЮЩИЙ вызов `auto` для этой задачи
   застаёт её уже в другом состоянии (переход произошёл — не важно,
   каким путём), без правок `fsm.py`/`fsm_advance.py`/`store.py`;
   переход, случившийся между вызовами `auto` целиком через ручной
   `advance`/`approve` без последующего `auto`, закрытие алерта не
   получает, пока `auto` не позовут снова;
   B) закрытие на ЛЮБОМ успешном переходе независимо от того, кто его
   вызвал (`auto`, ручной `advance`, `approve`, `reject`) — требует
   расширения зон на `fsm.py`/`fsm_advance.py` (или `store.py`) —
   дефолт в этом случае неприменим, нужно явное решение Оператора о
   расширении зон.
   — дефолт: A (закрытие проверяется изнутри `auto.py` на следующем
   его же вызове для задачи — остаётся в объявленных зонах, не
   расширяет их без решения Оператора).

2. **Требование 3а — исчерпывающий ли список поводов для алерта.**
   Формулировка называет пять примеров («эскалация, стоп-кран, порог
   холостых, лимит шагов, красный CI»), но в `orchestrator/auto.py`
   есть ещё как минимум три СУЩЕСТВУЮЩИХ пути остановки цикла не на
   гейте, ни один из них не совпадает буквально ни с одним из пяти:
   пауза (`config.AUTO_STOP_PAUSE`, auto.py:225-228 — остановка по
   `artel.py pause`), общий отказ `run` стартовать без перехода в
   escalated — бюджет/лимит параллельных задач (auto.py:229-231,
   текст «run отказался стартовать»; эскалация по бюджету — ОТДЕЛЬНЫЙ
   случай, уже покрыт AUTO_STOP_BUDGET внутри «эскалации» и сюда не
   относится), и структурный отказ guard'а артефакта (SPEC T034,
   auto.py:249-253, немедленная остановка, отличная от стоп-крана
   T038). — варианты:
   A) список из пяти — исчерпывающий; пауза/общий отказ `run`
   стартовать (бюджет-до-старта, лимит параллельных задач)/структурный
   отказ guard'а алерт НЕ поднимают (пауза — действие самого Оператора,
   он и так знает; остальные два — не встречались в перечисленных
   инцидентах 02-03.09);
   B) правило общее — алерт поднимает КАЖДАЯ остановка `auto` не на
   гейте, включая эти три, пятёрка — только примеры, не исчерпывающий
   список.
   — дефолт: A (буквально по перечню ТЗ; пауза — заведомо не
   «незаметное буксование», Оператор её ставит сам).

3. **Требование 2 — текст остановки, когда у последнего из N шагов
   нет класса отказа.** Шаблон «цикл не сходится: N шагов без
   перехода, последний отказ: <класс>» предполагает класс на
   последнем шаге. Но серия из N шагов может целиком состоять из
   шагов, на которых `advance` НЕ журналировал отказ вовсе (агент ещё
   «работает» — артефакт-условие не в статусе `ready` и т.п., T038
   требование 4) — ровно форма инцидента «линт-до-лока — 19 шагов при
   несостоявшейся эскалации роли», названного поводом для этой же
   задачи. В этом случае подставлять в `<класс>` нечего. — варианты:
   A) хвост «, последний отказ: <класс>» опускается целиком, когда на
   последнем из N шагов класс отказа отсутствует — сообщение «цикл не
   сходится: N шагов без перехода»;
   B) фиксированная заглушка вида «последний отказ: (нет — агент
   продолжал работу)» вместо пропуска хвоста.
   — дефолт: A (короче и не льёт в лог пустую подстановку; факт «нет
   класса» и так виден по отсутствию хвоста).

# ТЗ: База сравнения джоба защищённых путей — первый родитель merge-коммита PR

# ТЗ: Проверка защищённых путей в CI — база сравнения по merge-коммиту PR, а не по устаревшей base.sha события

Источник: копилка 11.10, приоритет 1 («Ложный красный джоб „Enforcement,
конфиги системы меняет только Оператор“ у задачи 01M4M67SGN…», прогон
38124848279, PR #259). Решение Оператора 12.10.2026 — заводить.

Факты (origin/main 3a1be8b0):
- Джоб `protected-paths` (`.github/workflows/ci.yml` ~290-318) запускается
  только на `pull_request`, передаёт `BASE_SHA` =
  `github.event.pull_request.base.sha` и вызывает
  `python3 scripts/ci_protected_paths.py`.
- `scripts/ci_protected_paths.py`: `main()` (~147) читает `BASE_SHA`,
  `base_protected_paths(base_sha)` (~123) берёт перечень
  `PROTECTED_PATHS` из текста `orchestrator/config.py` базы,
  `changed_files(base_sha)` (~135) — `git diff --name-only <base>...HEAD`.
- `actions/checkout` на событии `pull_request` выгружает merge-коммит PR
  (`refs/pull/N/merge`): HEAD — коммит с двумя родителями, первый родитель
  — текущая вершина целевой ветки, второй — голова ветки PR.
- `base.sha` события фиксируется при открытии или обновлении PR и
  устаревает: если после этого Оператор коммитит в main защищённый путь
  (случай 11.10: 9002a77d, `docs/adr/0022-handoff-audit.md`), дифф
  `<base.sha>...HEAD` включает этот коммит main как изменение PR, и джоб
  красный у всех открытых PR. Повтор прогона (`ci-rerun`) несёт тот же
  payload события и не лечит; закрыть и открыть PR тоже не помогло.

Требуется:
1. HEAD считается merge-коммитом PR, только если одновременно: у HEAD
   ровно два родителя; переменная `BASE_SHA` не пуста и является предком
   `HEAD^1`; второй родитель `HEAD^2` равен `pull_request.head.sha` из
   файла события `GITHUB_EVENT_PATH` (переменная окружения раннера,
   правки `ci.yml` не требует). Тогда база сравнения — `HEAD^1`: и
   перечень защищённых путей, и дифф берутся от неё. Если хотя бы одно
   условие не выполнено — прежнее поведение с `BASE_SHA` (оно строже), и
   вывод называет, какое условие не выполнено. Пустой `BASE_SHA` — по-
   прежнему красный джоб с кодом 2 при любой форме HEAD
   (`tests/test_protected_test_settings.py::CiScriptRunsAsScriptTest`
   остаётся зелёным без правки).
2. Выбор базы — в `scripts/ci_protected_paths.py`; `.github/workflows/ci.yml`
   не меняется. Вывод джоба называет использованную базу и её источник
   («первый родитель merge-коммита PR» либо «BASE_SHA события»).
3. Отказ закрытый (fail-closed, ADR-0002) сохраняется: нечитаемый первый
   родитель, файл события, перечень или дифф — красный джоб с названной
   причиной либо откат на более строгую базу `BASE_SHA`, но не зелёный по
   умолчанию.
4. Свойство «ветка, которая создаёт файл и тем же изменением вносит его в
   перечень, свой PR не красит» (SPEC 01M31DRD81092HB69J0MAKZMGH) и
   свойство «PR, меняющий защищённый путь базы, — красный» сохраняются.
5. Тесты в `tests/` на временном git-репозитории; скрипт запускается с
   явным окружением без переменных `GITHUB_*` раннера, файл события —
   временный. Сценарии:
   - случай 11.10 (коммит в main защищённого пути после base.sha, PR его
     не трогает) — зелёный;
   - PR, меняющий защищённый путь, — красный при обеих формах HEAD;
   - HEAD — слияние main в ветку задачи (второй родитель не голова PR из
     файла события), защищённый путь изменён в более раннем коммите
     ветки — красный (прежняя база `BASE_SHA`);
   - нечитаемый первый родитель или файл события — откат на `BASE_SHA` с
     названной в выводе причиной, вердикт тот же, что у прежней проверки
     (защищённый путь в диффе от `BASE_SHA` — красный).
   Заявки «Ловит мутацию»: на возврат к `BASE_SHA` при merge-коммите PR;
   на взятие второго родителя вместо первого; на удаление сверки второго
   родителя с головой PR. Существующие тесты скрипта не ослабляются;
   смена текста вывода — разделом SPEC «Меняемое поведение».

Матрица неослабления (сверено до завода, независимая проверка 12.10):
новая база берётся только при доказанном merge-коммите PR (п. 1), иначе
прежняя, более строгая; перечень берётся из первого родителя — вершины
целевой ветки, той же доверенной стороны, что и base.sha, только свежее; дифф `HEAD^1...HEAD` у merge-коммита — ровно
изменения PR относительно текущей цели; изменения PR, видимые прежней
проверкой, остаются видимыми; уходят только коммиты main, сделанные после
base.sha, которые изменениями PR не являются.

# PLAN: База сравнения джоба защищённых путей — первый родитель merge-коммита PR

## Подход
Выбор базы — новая функция `merge_first_parent(base_sha)` в
`scripts/ci_protected_paths.py`; `ci.yml` не меняется (требование 3).
Условия проверяются по порядку, первое невыполненное возвращается текстом
причины:
1. `git rev-list --parents -n 1 HEAD` — ровно два родителя (сбой git —
   невыполненное условие);
2. `git merge-base --is-ancestor BASE_SHA HEAD^1` — код 0 «предок», 1 «не
   предок», любой иной (128 на несуществующем sha) или исключение —
   невыполненное условие с названной причиной (требование 4);
3. `pull_request.head.sha` из файла `GITHUB_EVENT_PATH` (`_event_head_sha`:
   не задан / не читается / не JSON / не та форма / нет sha — причина);
4. `HEAD^2 == pull_request.head.sha`.

Все выполнены — база `HEAD^1` (sha), источник «первый родитель
merge-коммита PR»; иначе база `BASE_SHA`, источник «BASE_SHA события», и
выводится строка с невыполненным условием. Пустой `BASE_SHA` проверяется
ДО выбора базы — код 2 при любой форме HEAD (требование 2). После выбора
перечень и дифф читаются прежними `base_protected_paths`/`changed_files`
от выбранной базы (им добавлен параметр `label` — источник в тексте
причины, по умолчанию `BASE_SHA`, прежние вызовы не меняются); их сбой —
код 2 без отката на `BASE_SHA` (требование 4). Строка «база сравнения:
<sha> (<источник>)» печатается всегда до чтения перечня — значит, и при
кодах 0/1 (требование 3, AC-8).

Бюджет SPEC (40) не пересматривается: правка в одном файле.

## Влияние на систему
- Джоб `protected-paths` (инвариант «Защищённые пути», `docs/invariants.md`)
  не ослабляется: `HEAD^1` берётся только при доказанном merge-коммите PR
  (сверка `HEAD^2` с головой PR из события отсекает слияние main в ветку
  задачи); во всех прочих случаях — прежняя база `BASE_SHA` с прежним
  вердиктом; любая ошибка git/события при проверке условий ведёт к
  `BASE_SHA` (более широкий дифф), а сбой чтения от доказанного `HEAD^1` —
  к коду 2 (fail-closed, ADR-0002).
- Перечень по-прежнему из базы, не из HEAD — свойство SPEC
  01M31DRD81092HB69J0MAKZMGH сохранено (AC-10).
- Существующие тесты не изменены (добавлен один класс).
- Откат — revert коммита задачи: поведение возвращается к базе `BASE_SHA`.

## Риски
- На событиях не `pull_request` (push) `GITHUB_EVENT_PATH` указывает на
  payload без `pull_request` — откат на `BASE_SHA`, т.е. прежнее поведение.
- Неглубокий чекаут (`fetch-depth: 1`) без `BASE_SHA` в истории: проверка
  предка падает → откат на `BASE_SHA`, далее как прежде (код 2 при
  нечитаемой базе) — поведение не хуже прежнего.

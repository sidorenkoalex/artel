# Ответ Оператора на QUESTIONS.md (22.10.2026)

1. **C.** У компонента без поля `tests` роль масок `tests` играет перечень файлов полного отчёта базы (включая записи ошибок уровня файла): в C входят пути каждой записи `diff_name_status(база, голова)`, кроме `A` (у `R` — прежний путь), которые есть среди файлов отчёта базы; пути под масками `test_support` и файлы утверждённых замен — по-прежнему. Это и есть «строгая альтернатива» п. 2 ТЗ; фраза п. 8 «компонент без `tests` — C только из `test_support`» — ошибка ТЗ, в SPEC не переносится; критерий п. 8 для компонента без `tests` — «C — изменённые файлы ветки, присутствующие в отчёте базы». Буквальное «все файлы отчёта базы» (вариант B) не принимается: прогон неизменённых файлов ничего не добавляет. До SPEC — опись существующих методов (учебные проекты `junit_project` и прочие без `tests`), чьи сценарии правят или удаляют существующий тестовый файл и получат третью выписку, с утверждениями о числе и составе прогонов, которые покраснеют. Если такие есть — эскалация с перечнем «путь::Класс::метод» и матрицей неослабления (мандат даёт Оператор). Если нет — SPEC без мандата.

2. **A.** Сбой `diff_name_status(база, голова)` (None) или `git diff -M -U0 база голова` — отказ подготовки (`_Prepare`, действие `PREPARE_REFUSAL_ACTION`), не пустой C и не ноль находок. Критерий: подменённый сбой каждого из двух диффов даёт отказ подготовки.

3. **A.** «Профиль задачи в границе гейта исходов» в автогейте — та же граница, что у ядра: `_bounds(t["is_canary"], t["target"])` не `None` (профиль в `in_outcome_bounds` и задача не канарейка). У канарейки при правиле не по умолчанию — прежний текст отказа. Критерий на канарейку.

# PLAN: G3б-2 — гейт неослабления по исходам: прежние версии, строгий режим, исключения в коде, заменяемые тесты; автогейт по правилу планки

## Подход
Всё новое поведение гейта живёт в ядре `_judge`
(`orchestrator/advance_gates/outcome_integrity.py`) — оба рубежа
(`in_dev -> verifying`, окно мержа) идут через него, вне границы
`_bounds` ядро не зовётся, поэтому артель и `test_profile` не меняются.

- **Профиль.** `Profile` получает поля `test_support`, `layers`, `paths`
  (вне сравнения), `_with_component_fields` их переносит (`paths` — через
  `_regexes`, строка → кортеж из одного выражения); новый `layers_of`.
  `targets._check_component_rules` отказывает чужому слою и `python-ast` у
  команды не pytest.
- **Набор C и третья выписка.** После сравнения: `diff_name_status(база,
  голова)` (сбой — `_Prepare`) и `git diff -M -U0` (сбой — `_Prepare`).
  C — не-`A` записи (у `R` — прежний путь), являющиеся тестовым файлом
  компонента (маски `tests`, без них — файлы записей полного отчёта базы)
  или путём `test_support`, плюс файлы утверждённых замен компонента,
  которые есть в отчёте базы. Непустой C — выписка головы
  `scratch/prior` (`worktree add --detach`, в `trees` — уборка тем же
  `finally`), `git checkout <база> -- :(literal)<пути C>`, удаление файлов
  `A` под масками `tests`/`test_support` (без `tests` — под
  `weakening_scope`). Прогон: путь `test_support` в C — полный набор
  (`components_full_suite`, `fresh=True`), иначе `_report_run` файлов C.
  Судятся `PASS_TO_PASS` базы с файлом в прогоне; красный (всё, что не
  `in_pass_to_pass`) — перепрогон `_rerun` со сторонами (прежние версии,
  база), отдельная история; классификация по правилу `_redness`.
  Находка прежних версий не добавляется к идентификатору с находкой
  прежнего вида.
- **Замены.** `mandate.approved_replacements`, отфильтрованные по
  компоненту профиля: находки «не найден», «не зелёный на базе», «замена
  не нужна», строка «заменён по SPEC». Замена снимает только «исчез» и
  «прежняя версия красная…» своего идентификатора (после мандата
  `_covering_pair`), элемент `замена:<id>→AC-<n>`, источник «замена SPEC →
  AC-<n>».
- **Строгий режим** — нет `python-ast` в `layers_of`: каждая не-`A` запись
  тестового файла или `test_support`; при `python-ast` — только не-`.py`
  под `test_support`. Покрытие — новая `_path_covering` (элемент прежнего
  маркера, равный пути).
- **Исключения в коде** — разбор добавленных строк `diff -M -U0` по
  счётчикам ханков (номер по голове, двоичные и переименования без правки
  без ханков), файлы компонента по `paths` (без них — любые), кроме
  тестовых файлов (старый или новый путь), `test_support` и, у компонента
  без `tests`, файлов `A` под `weakening_scope` с записями в отчёте головы.
  Вывод git читается байтами и декодируется с заменой — недекодируемый
  текст не роняет гейт.
- **Находки и доказательство.** Новые виды — в `_KINDS`, `_RANK` (4–10),
  `_finding_id` (граница — « — » с исходами своего вида; разбор отдаёт и
  вид). Отпечаток — элементы покрытия плюс `замена:…` всех утверждённых
  замен компонента; `_proven` пересчитывает покрытие по виду находки.
  Порядок строк записи: счёт, доказательство, «прежние версии: файлов n;
  прогонов m» (m — прогоны на стороне прежних версий), «нестабилен и на
  базе», «заменён по SPEC», покрытые. Подсказка при находке нового вида
  называет мандат на путь.
- **Мандат на путь** (`mandate._weakening_scope_refusal`): у профиля в
  `in_outcome_bounds` годен путь области, путь под `tests`/`test_support`
  или путь под `paths` (без `paths` — любой).
- **Автогейт.** `_plank_rule_refusal(rule, t)` при правиле не по
  умолчанию снимает отказ, если `outcome_integrity._bounds(is_canary,
  target)` не `None` (отложенный импорт); `_autogate_conditions` при правиле
  не по умолчанию читает пометки по правилу, при умолчании — прежние
  вызовы побайтно.

Бюджет SPEC ($75) не пересматривается.

## Влияние на систему
- Гейт исходов ужесточается только в границе `in_outcome_bounds` (не
  канарейка); вне её `_gate` не зовётся — артель и `test_profile` прежние.
  Существующие пороги и находки не ослабляются: прежние виды, их порядок,
  действие отказа и строка счёта прежние, новые находки только
  добавляются.
- Мандат на путь (требование 6) расширяет годность элемента только в
  границе — матрица неослабления SPEC, решение Оператора; вне границы
  правило и тексты прежние.
- Автогейт (требование 10): отказ «до G3б» снимается только в границе
  ядра `_bounds`; канарейка и прочие — прежний текст; при правиле по
  умолчанию вызовы прежние.
- Новый git-вызов `diff -M -U0` в гейте; сбой — отказ подготовки
  (fail-closed). Третья выписка — в том же `scratch` с маркером владельца,
  уборка в прежнем `finally`.
- Откат — revert merge-коммита задачи.

## Риски
- Время гейта: третья выписка добавляет прогон файлов C и перепрогоны
  красных — только при изменённых тестах/поддержке.
- Ложная находка «исключение в коде» на новом модуле кода под
  `weakening_scope` у компонента без `tests` — принятая цена (ANSWER-2),
  снимается мандатом на путь.

## Предложения системе
- `gitcmd.git` читает вывод `text=True` строгим декодированием: дифф с
  текстом не в utf-8 роняет вызывающего `UnicodeDecodeError` (класс T011).
  Здесь `diff -U0` читается байтами в самом гейте; `gitcmd` стоит дать
  вариант с `errors="replace"` для диффов содержимого.
- `pytest -n` в worktree задачи падает «node down» — скил coding-standards
  мог бы прямо сказать гонять затронутые файлы без xdist.

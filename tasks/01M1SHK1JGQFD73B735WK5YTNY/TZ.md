# ТЗ: стоп-кран волны: класс отказа у нескольких задач подряд останавливает циклы всем

# ТЗ: межзадачный стоп-кран волны — один класс отказа у нескольких задач подряд останавливает циклы всем

Источник: копилка 05.09 (docs/backlog.md, приоритет 2), сравнение с
курсом harness_ru, кандидат с трижды наблюдавшимся отказом: 31.08
сетевой провал (~40 мин Connection refused: четыре задачи T075–T078
сожгли по три попытки и эскалировали), 04.09 обрыв сессии, 05.09 восемь
таймаутов шагов подряд. Каждый раз отказы одного класса шли по задачам
по очереди, каждая задача переживала его самостоятельно, Оператор
возвращал их руками.

Сегодня. Классификация отказов попытки есть
(`orchestrator/failure_classification.py`: 1a auth, 1b сеть, обрыв
потока, system_candidate, session_limit; `TRANSIENT_SYSTEM_CLASSES`),
бэкофф и эскалация — на уровне одной задачи (T082). Сторож зависших
прогонов тестов (`doctor`, группа процессов 01M1PNBSHR…) ловит
зависший pytest/unittest, но не серию таймаутов шагов по разным задачам.
Алерты — таблица `alerts` (`kind=incident|threshold|warning|attention`).

Требуется:
1. Счётчик класса отказа по волне: при отказе попытки/шага пульт пишет
   класс отказа (уже классифицированный) в журнал задачи; функция
   (`orchestrator/alerts.py` или новый модуль) считает по журналу число
   РАЗНЫХ задач с отказом одного класса за окно
   `config.WAVE_BREAKER_WINDOW_SEC` (по умолчанию 15 мин); классы —
   `TRANSIENT_SYSTEM_CLASSES` плюс «таймаут шага»; порог —
   `config.WAVE_BREAKER_TASKS` (по умолчанию 3).
2. Срабатывание: алерт `kind=incident` «стоп-кран волны: класс <класс> у
   N задач за M минут» (дедуп на открытый алерт того же класса) и
   ПАУЗА новых агентных шагов для ВСЕХ задач target: `run`/`auto` перед
   стартом агентного шага видят открытый алерт стоп-крана и
   останавливаются штатно (тем же приёмом, что `pause`: идущие шаги не
   прерываются, `approve`/`reject`/`budget`/`status` работают). Причина
   — в выводе и журнале каждой затронутой задачи один раз.
3. Снятие: `alert-ack <id>` открытого алерта стоп-крана снимает паузу
   (решение Оператора после проверки `doctor live-smoke`); повторное
   срабатывание того же класса после ack — новый алерт. Автоматического
   снятия нет (решение Оператора — как для эскалаций).
4. `doctor` показывает открытый стоп-кран первым пунктом; `status` —
   пометкой у затронутых задач. Сторож зависших прогонов тестов не
   дублируется: его срабатывания в счётчик не входят (иной класс).
5. Тесты: три задачи с отказом класса 1b за окно — алерт открыт, четвёртая
   задача не стартует шаг с причиной; две задачи — не срабатывает;
   отказы разных классов не суммируются; ack снимает паузу; идущий шаг
   не прерывается; окно и порог читаются из `config`. Существующие
   тесты бэкоффа/эскалации (T082) и `pause` зелёные без ослабления.

Зоны: orchestrator/alerts.py, orchestrator/auto.py, orchestrator/runner.py,
orchestrator/doctor.py, orchestrator/config.py, tests/.

Не входит: автоматический перезапуск после снятия; изменение бэкоффа
одной задачи (T082); прерывание идущих шагов; внешние target (стоп-кран
на target self; параметризация target — если дёшево, иначе назвать в
«Не входит» SPEC).

Рамка: $40 (5 файлов кода; деление допустимо: счётчик+алерт / пауза в
run-auto).

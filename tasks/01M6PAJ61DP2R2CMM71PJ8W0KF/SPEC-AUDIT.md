## Пути обхода гейтов
- Буквальное выполнение «разбор `Labels` — строка `ключ=значение` через запятую»
  (SPEC.md:157-160) наивным `dict(p.split("=",1) …)` проходит AC-4 (метки теста без
  запятых в значениях), но роняет `doctor` на машине Оператора: фильтр
  `label=com.docker.compose.project` берёт все стенды Compose машины, а
  `com.docker.compose.project.config_files` у проекта с несколькими `-f` — список
  через запятую (Д1).
- Сборщик может писать в имя версии секунды/мс вместо нс (AC-1 требует лишь
  `.v<…>`, SPEC.md:289) — строка `doctor` сочтёт свежую версию идущей сборки старой и
  удалит её, обойдя защиту решения №3.1 (Д2).
- Доступ роли к Docker — обход command-allowlist и запретов роли (Д4); принят ADR, но
  в объёме ВМ, а не файловой системы Оператора.

## Вердикт
concerns — SPEC вести можно, отклонения решаемы Оператором на гейте:

- **Д1** (SPEC.md:157-160, AC-4 SPEC.md:295): разбор поля `Labels` не задан для
  значений с запятой; AC-4 не содержит чужого стенда Compose с меткой вида
  `com.docker.compose.project.config_files=/a.yml,/b.yml`. Предложение: в треб. 14 —
  фрагмент без `=` не роняет разбор (относится к значению предыдущей метки или
  отбрасывается), в AC-4 — такой чужой контейнер в ответе `docker ps`, строка не падает.
- **Д2** (SPEC.md:68-70, AC-1 SPEC.md:289, AC-2 SPEC.md:291): единица времени в
  имени версии не закреплена критерием сборки; связку «сборка пишет нс — `doctor`
  читает нс» не проверяет ни один AC. Предложение: в AC-1/AC-2 — число в имени
  версии между `time.time_ns()` до и после вызова `role_env`.
- **Д3** (SPEC.md:104, 212, 234; AC-1/4/5): `start_new_session=True` — требование без
  утверждения; тест может сверить `os.getpgid(<записанный pid>) != os.getpgrp()`
  (или pgid == pid). Безопасность красной фазы не затронута (снятие группы условно).
- **Д4** (SPEC.md:119-123, треб. 13; `docs/adr/0023-role-step-sandbox.md:1318-1323`):
  ADR принимает «полную власть над виртуальной машиной Docker»; Docker Desktop по
  умолчанию делит с ВМ `/Users` (опытом не проверено), так что роль `docker run
  -v /Users/…:/h` читает/пишет файлы Оператора, `.artel/` пульта и путь пула
  канарейки в обход `permissions.deny` и `role_git`. Вопрос Оператору: принят ли риск
  в этом объёме (без правки SPEC — фиксация в ADR) или нужен отказ/предупреждение.
- **Д5** (AC-6 SPEC.md:299, треб. 17 SPEC.md:270-281): предел пробы Docker и вызова
  `docker compose version` в необязательном тесте не задан (в части 1 — 10 с); зависший
  Docker Desktop подвесит тест. Предложение: проба и утверждение — с пределом
  `runner.DOCKER_CALL_TIMEOUT_SEC`.
- **Д6** (SPEC.md:178-194, 211-215): не заданы (а) исход для записи
  `compose_role_dir()`, имя которой не разбирается ни в одну из трёх форм
  (`.tmp-abc`, посторонний файл), (б) идёт ли уборка записей `compose_role_dir()`
  при «Docker не отвечает» — исполнитель выберет сам.
- **Д7** (SPEC.md:150-151, AC-4): живость «по `lease.process_alive`» не проверяется
  отличимо от «pid жив»: в AC-4 нет стенда с живым pid и чужим `artel.run-host` или
  временем старта раньше старта процесса. Ошибка в безопасную сторону (стенд не
  снимается), низкая важность.

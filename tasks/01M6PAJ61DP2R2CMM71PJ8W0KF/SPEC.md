## Критерии приёмки

AC-1. `runner.role_env` для задачи с профилем `compose` (в `test_profile` или в одном из компонентов) и провайдера `claude`: последний элемент `PATH` — `<compose_role_dir()>/<id>/bin` под подменённым `config.ROOT` песочницы, в нём ровно одна запись — ссылка `docker` на найденную программу; `DOCKER_CONFIG` — `<…>/<id>/config`, содержимое `config.json` равно `{}` при вымышленной конфигурации пульта с `credsStore`, `auths` и `cliPluginsExtraDirs`; в `config/cli-plugins/` ровно одна запись — ссылка `docker-compose`; `DOCKER_HOST` — значение пульта, без него — ответ подменённого `docker context inspect`. Подменённый `docker context inspect`: зависание (`exec sleep <n>`; тест снимает записанный pid, группу — только если её номер не равен `os.getpgrp()`) — отказ старта за предел `runner.DOCKER_CALL_TIMEOUT_SEC` (по умолчанию 10, тест вправе подменить на 1), ненулевой код — отказ, пустой или не `unix://` адрес — отказ; отказ — экземпляр `OSError`, в нём текст вызова, пустого `DOCKER_HOST` в окружении роли нет. Окружение вызова подменённого `docker context inspect` — ровно переменные требования 6: нет `HOME` пульта и переменной-метки, выставленной тестом в `os.environ`. Провайдер `codex` — отказ (`OSError`) с текстом «раннер compose в песочнице Codex не поддержан», каталог задачи не собран. При каждом из этих отказов `role_env` исход `run_agent_once` — `skipped` с текстом отказа, в журнале задачи — запись «agent run SKIPPED» с текстом отказа, агент не запущен.

AC-2. Повторная сборка каталога задачи: `<compose_role_dir()>/<id>` — ссылка на новый каталог версии, прежний каталог версии удалён, посторонние записи, подложенные в `bin/` и `cli-plugins/` после прошлой сборки, отсутствуют. При подменённом кортеже системных каталогов дополнений: дополнение есть только в системном каталоге песочницы — `cli-plugins/docker-compose` — ссылка на него; дополнения нет ни в `DOCKER_CONFIG` пульта, ни в каталогах кортежа — `role_env` поднимает `OSError` с именем; без найденного `docker` — `OSError` с именем.

AC-3. У `pytest-own`, `pult-pytest`, артели, вызова без проекта и при непрочитанной записи проекта окружение `role_env` побайтно прежнее, исключения нет, каталог задачи не создаётся; `stack.ROLE_ENV_ALLOWLIST` не изменён.

AC-4. `doctor`, строка «забытые стенды пульта» — функция строки и функция её починки вызываются через фасад `doctor`, в песочнице с подменённым `config.ROOT`; ответ `docker ps`/`docker network ls` подменён, метки в нём — строка `ключ=значение` через запятую: контейнеры и сети проекта формы `artel-<id строчными, 26 знаков>-<8 hex>` с тройкой меток `artel.run-*`, мёртвой по `lease.process_alive`, — `warn` с именами, починка зовёт `down --remove-orphans` с их именем проекта, без `-v`; стенд живого прогона, проект `artel-foo` и проект правильной формы без меток живого прогона в `warn` не попадают, починка `down` для них не зовёт; каталог `<compose_role_dir()>/<id>` задачи в `done`/`killed` или без строки — `warn` с путём, починка удаляет ссылку и её каталог версии, каталог живой задачи на месте; обход и починка видят только каталог песочницы; без проекта `compose` — `skip`, `docker` не вызван, каталоги задач не удалены и починкой; сломанный слой проектов (вымышленный слой в песочнице) — `warn` «слой проектов не прочитан», прочие строки `doctor` печатаются, починка ничего не снимает и не удаляет; починка при `conn=None` — ни одного вызова `docker`, ни одного удалённого каталога (каталог задачи песочницы при проекте `compose` на месте); подменённый `docker ps` зависает (`exec sleep <n>`, предел `runner.DOCKER_CALL_TIMEOUT_SEC` подменён на 1; тест снимает записанный pid, группу — только если её номер не равен `os.getpgrp()`) или возвращает ненулевой код — `warn` «Docker не отвечает», строка завершается за предел. У каждого вызова подменённого `docker` строки и её починки (`ps`, `network ls`, `compose down`) в окружении нет `HOME` пульта и переменной-метки, выставленной тестом в `os.environ`; `PATH` вызова — ровно каталог подменённого `docker` и `_OWN_SYSTEM_PATH_DIRS`.

AC-5. `doctor`, строка записи `compose`: нет `compose_file` или `compose_env_template` в клоне — `fail`; `config --services` вызван с `--env-file` на шаблон окружения из клона; сервиса нет в ответе `config --services` — `fail` с именем сервиса; подменённый `config` отказывает из-за файла, которого нет в клоне, — `warn` с текстом Compose, не `fail`; `docker compose version` не отвечает или ниже 2.1.1 (например, 2.0.1) — `fail` с найденной версией; 2.1.1 и выше — не `fail`; подменённый `docker` зависает (`exec sleep <n>`, предел `runner.DOCKER_CALL_TIMEOUT_SEC` подменён на 1; тест снимает записанный pid, группу — только если её номер не равен `os.getpgrp()`) или возвращает ненулевой код — `fail` с текстом вызова, строка завершается за предел. У каждого вызова подменённого `docker` строки (`config --services`, `compose version`) в окружении нет `HOME` пульта и переменной-метки, выставленной тестом в `os.environ`.

AC-6. Необязательный тест с настоящим Docker этой части утверждает: `docker compose version` в окружении шага роли (песочница `DOCKER_CONFIG` со ссылкой на дополнение) отвечает версией не ниже 2.1.1. Тест пропускается с именованной причиной при каждом из условий: Docker не отвечает; дополнение Compose не найдено ни в `DOCKER_CONFIG` песочницы, ни в системных каталогах дополнений; выставлена переменная `CI`.

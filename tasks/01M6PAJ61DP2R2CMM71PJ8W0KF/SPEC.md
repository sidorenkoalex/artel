# SPEC: Окружение роли и doctor для compose

## Контекст
Часть 2 деления задачи 01M6P22XBCQS49HE92YGAB25N9 «Раннер тестов внешнего
проекта в контейнере Docker Compose». Часть 1 (01M6PAJ61D4PYAP79ADRPA6MWV)

`compose` доступ к Docker через собранный пультом каталог задачи

дословно. Номера требований 12–17 сохранены; ссылки «требование 1–11» в
тексте ниже — на требования SPEC родителя (часть 1), в том числе
«окружение требования 6» — окружение вызова `docker` вне процесса роли,

## Критерии приёмки

AC-1. `runner.role_env` для задачи с профилем `compose` (в `test_profile` или в одном из компонентов) и провайдера `claude`: последний элемент `PATH` — `<compose_role_dir()>/<id>/bin` под подменённым `config.ROOT` песочницы, в нём ровно одна запись — ссылка `docker` на найденную программу; `DOCKER_CONFIG` — `<…>/<id>/config`, содержимое `config.json` равно `{}` при вымышленной конфигурации пульта с `credsStore`, `auths` и `cliPluginsExtraDirs`; в `config/cli-plugins/` ровно одна запись — ссылка `docker-compose`; `DOCKER_HOST` — значение пульта, без него — ответ подменённого `docker context inspect`. Подменённый `docker context inspect`: зависание (`exec sleep <n>`, группа процессов снимается тестом в `finally`) — отказ старта за предел `runner.DOCKER_CALL_TIMEOUT_SEC` (по умолчанию 10, тест вправе подменить на 1), ненулевой код — отказ, пустой или не `unix://` адрес — отказ; в отказе — текст вызова, пустого `DOCKER_HOST` в окружении роли нет. Окружение вызова подменённого `docker context inspect` — ровно переменные требования 6: нет `HOME` пульта и переменной-метки, выставленной тестом в `os.environ`. Провайдер `codex` — отказ с текстом «раннер compose в песочнице Codex не поддержан», агент не запускается.

AC-2. Повторная сборка каталога задачи убирает посторонние записи, подложенные в `bin/` и `cli-plugins/` после прошлой сборки; без найденного `docker` или дополнения Compose `role_env` поднимает `OSError` с именем.

AC-3. У `pytest-own`, `pult-pytest`, артели, вызова без проекта и при непрочитанной записи проекта окружение `role_env` побайтно прежнее, исключения нет, каталог задачи не создаётся; `stack.ROLE_ENV_ALLOWLIST` не изменён.

AC-4. `doctor`, строка «забытые стенды пульта» — функция строки и функция её починки вызываются через фасад `doctor`, в песочнице с подменённым `config.ROOT`: контейнеры и сети `artel-*` без меток или с мёртвой тройкой — `warn` с именами (ответ `docker ps`/`docker network ls` подменён); починка зовёт `down -v --remove-orphans` с их именем проекта и не зовёт для стенда живого прогона; каталог `<compose_role_dir()>/<id>` задачи в `done`/`killed` или без строки — `warn` с путём, починка удаляет, каталог живой задачи на месте; обход и починка видят только каталог песочницы; без проекта `compose` — `skip`, `docker` не вызван, каталоги задач не удалены и починкой; починка при `conn=None` — ни одного вызова `docker`, ни одного удалённого каталога (каталог задачи песочницы при проекте `compose` на месте); подменённый `docker ps` зависает (`exec sleep <n>`, предел `runner.DOCKER_CALL_TIMEOUT_SEC` подменён на 1) или возвращает ненулевой код — `warn` «Docker не отвечает», строка завершается за предел. У каждого вызова подменённого `docker` строки и её починки (`ps`, `network ls`, `compose down`) в окружении нет `HOME` пульта и переменной-метки, выставленной тестом в `os.environ`; `PATH` вызова — ровно каталог подменённого `docker` и `_OWN_SYSTEM_PATH_DIRS`.

AC-5. `doctor`, строка записи `compose`: нет `compose_file` или `compose_env_template` в клоне — `fail`; сервиса нет в ответе `config --services` — `fail` с именем сервиса; `docker compose version` не отвечает или ниже 2.1.1 (например, 2.0.1) — `fail` с найденной версией; 2.1.1 и выше — не `fail`; подменённый `docker` зависает (`exec sleep <n>`, предел `runner.DOCKER_CALL_TIMEOUT_SEC` подменён на 1) или возвращает ненулевой код — `fail` с текстом вызова, строка завершается за предел. У каждого вызова подменённого `docker` строки (`config --services`, `compose version`) в окружении нет `HOME` пульта и переменной-метки, выставленной тестом в `os.environ`.

AC-6. Необязательный тест с настоящим Docker этой части — `docker compose version` в окружении шага роли (требование 17) — пропускается с именованной причиной при каждом из условий: Docker не отвечает; нужного образа нет в локальном кэше по `docker image inspect`; выставлена переменная `CI`; в его вымышленном Compose-файле, если он есть, у каждого сервиса `pull_policy: never`.

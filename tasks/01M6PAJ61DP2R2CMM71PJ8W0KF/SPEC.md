## Критерии приёмки

AC-1. У задачи с профилем `compose` (в `test_profile`; в одном из компонентов) окружение `runner.role_env` побайтно равно окружению той же вымышленной записи с профилем `pytest-own` (временный дублёр записи проекта в песочнице, настоящие файлы не меняются); у `pytest-own`, `pult-pytest`, артели, вызова без проекта и при непрочитанной записи проекта окружение `role_env` побайтно прежнее, исключения нет; `stack.ROLE_ENV_ALLOWLIST` не изменён.

AC-2. `doctor`, строка «забытые стенды пульта» — функция строки и функция её починки вызываются через фасад `doctor`, в песочнице с подменённым `config.ROOT`; ответ `docker ps`/`docker network ls` подменён, метки в нём — строка `ключ=значение` через запятую: контейнеры и сети проекта формы `artel-<id строчными, 26 знаков>-<8 hex>` с тройкой меток `artel.run-*`, мёртвой по `lease.process_alive` (мёртвый pid; живой pid со временем `artel.run-started` раньше старта этого процесса), — `warn` с именами, починка зовёт `down --remove-orphans` с их именем проекта, в argv `down` нет ни `-v`, ни `-f`, рабочий каталог вызова — пустой временный каталог; стенд живого прогона (живой pid этого хоста и время `artel.run-started` не раньше старта процесса), проект `artel-foo` и проект правильной формы без единой метки живого прогона в `warn` не попадают, починка `down` для них не зовёт; чужой контейнер Compose с меткой `com.docker.compose.project.config_files=/a.yml,/b.yml` в ответе `docker ps` — строка не падает, в `warn` его нет, `down` для него не зовётся; стенд правильной формы с каждым из трёх видов порчи меток (нет одной метки; `artel.run-pid` не число; `artel.run-started` не в формате `store.now()`) — `warn` «метки стенда не разобраны» с именем проекта Compose, починка `down` для него не зовёт, строка не падает. Адрес демона не `unix://` (подменённый `docker context inspect` отвечает `tcp://…` при не заданном `DOCKER_HOST`; `DOCKER_HOST=tcp://…` в окружении пульта) — `skip` «демон Docker не локальный», `down` не вызван. Строка не входит в список `check_orphans`, исходы `check_orphans` прежние. Без проекта `compose` — `skip`, `docker` не вызван ни строкой, ни починкой; сломанный слой проектов (вымышленный слой в песочнице) — `warn` «слой проектов не прочитан», прочие строки `doctor` печатаются, починка ничего не снимает; починка при `conn=None` при проекте `compose` — ни одного вызова `docker`; подменённый `docker ps` зависает (`exec sleep <n>`, предел `DOCKER_CALL_TIMEOUT_SEC` подменён на 1) или возвращает ненулевой код — `warn` «Docker не отвечает», строка завершается за предел.

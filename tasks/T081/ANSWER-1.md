# Ответ Оператора на эскалацию T081 (решение 31.08.2026)

Эскалация ложная, вопроса по существу нет: действующий (ещё не
починенный этой задачей) сканер guard прочитал маркерные строки
из ИСХОДНИКОВ твоих же тестов (`test_ac1_*`: литерал «AC-9:
escalate…», `test_ac2_*`: литерал «AC-5: escalate…») как настоящие
пометки эскалации — ровно тот класс дефекта, что описан в SPEC.

Что сделать:

1. Перепиши маркерные литералы в исходниках своих приёмочных
   тестов конкатенацией по образцу T075 (коммит 7cb7e25):
   `"AC-9: esca" + "late — …"` — чтобы текстовый сканер не видел
   паттерна в исходнике; создаваемые тестами файлы-фикстуры при
   этом содержат маркер естественной строкой (конкатенация — только
   в исходном коде теста).
2. Фикс по SPEC НЕ расширять: текстовый сканер остаётся текстовым,
   AST-разбор в объём не входит; конвенция конкатенации в исходниках
   тестов, тестирующих сканер, — принятая цена.
3. Фактуру «фильтр имён файлов не покрывает маркерные литералы
   внутри test_*.py» занеси в секцию «Предложения системе» своего
   артефакта — кандидат в будущую строку P3, решение по ней за
   Оператором.

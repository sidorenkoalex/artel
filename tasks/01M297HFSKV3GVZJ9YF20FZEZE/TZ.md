# ТЗ: база ветки задачи — origin/main, а не локальный пин; doctor и new видят непушенные коммиты главной копии

Источник: инцидент 11.09 (копилка П1 «непушенный коммит на пине множит
конфликты подтяжки», решение Оператора 11.09 «заведи»). Цепочка:
документный коммит 0fc0638e сделан прямо в главной копии, push
отклонён, коммит остался на пине; семь веток задач волны заведены от
локального `main` (`workspace.py::ensure`, база `config.MAIN_BRANCH`) и
унаследовали его; то же содержимое попало в origin/main другим
коммитом; ветка pytest-xdist (01M291M2Z7) внесла 0fc0638e в origin/main
через свой merge — у остальных веток появились две точки расхождения, и
подтяжка конфликтовала по docs/backlog.md даже там, где ветка файл не
трогала. Итог: семь эскалаций, семь шагов роли на разрешение ($1–3
каждый), один reject с повторным CI и ревью. `doctor` расхождения не
видел.

Требуется:
1. База кодовой ветки задачи — вершина origin/main, не локальный `main`: `workspace.ensure` перед `git worktree add -b` делает `git fetch origin <MAIN_BRANCH>` и заводит ветку от `origin/<MAIN_BRANCH>` (для внешнего target — от базы target по `targets.yaml`, тем же источником, что `fsm._origin_main_source`); при отказе fetch — именованный отказ шага «база ветки недоступна: fetch origin не удался», не молчаливый откат на локальный main. Исполняемый код пульта остаётся пином (ADR-0013), меняется только база кода задачи.
2. Проверка `doctor` «pin-unpushed»: HEAD главной копии обязан быть предком origin/<MAIN_BRANCH> (после fetch); иначе FAIL с перечнем непушенных коммитов (sha и первая строка) и подсказкой «документные коммиты — только через `note`; выровнять пин: `pin --to <предок>` + `pin-update <sha>`». Сетевой отказ fetch — WARN «сверка с origin невозможна», не OK.
3. Та же сверка на входе `new`: при непушенных коммитах на пине — предупреждение с тем же перечнем в выводе команды (задача заводится, ветка по требованию 1 всё равно стартует от origin), запись в журнал задачи «пин расходится с origin: N коммитов».
4. Тесты: ветка новой задачи стартует от origin/main, а не от локального main, когда они расходятся (мутация «база config.MAIN_BRANCH» — красный); отказ fetch — именованный отказ, ветка не заведена; `doctor` FAIL на непушенном HEAD и OK при совпадении; WARN при отказе fetch; `new` печатает предупреждение при расхождении; существующие тесты workspace, doctor, catalog — без ослабления.

Зоны: orchestrator/workspace.py, orchestrator/doctor/, orchestrator/catalog.py (new), tests/.
Приложением к PLAN (правит Оператор): docs/operator-session.md — два правила: «документные коммиты в main только через `note`, прямой `git commit` в главной копии запрещён» и «содержимое непушенного коммита не переносить новым коммитом — либо сам коммит после выравнивания пина, либо ничего».

Не входит: `pin-update`/`pin --to` и гейт свежести канарейки; подтяжка main в ветку (`pull.py`); разрешение уже возникших перекрёстных конфликтов; pre-commit hook главной копии (локальная настройка, не код репозитория).

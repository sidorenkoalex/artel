## Пути обхода гейтов
- **Е1. Запись наблюдения как ложное доказательство на гейте мержа.**
  Гейт мержа пропускает метод исхода 7а по записи «двусторонний прогон
  пройден» для головы (`_proven_addresses`, `test_integrity.py:1104-1105,
  1117-1121`, разбор `:1029-1041`). Сейчас разбор фильтрует точное
  действие `TWO_SIDED_PASSED_ACTION` (`:1036`, `:109`), а SPEC даёт
  наблюдению своё действие — риск низкий, но держится только на этом
  совпадении: исполнитель, переиспользовав для наблюдения хвост
  `_test_integrity_gate` (`:1360-1365`, запись «пройден» при пустых
  `refusals`), даст гейту мержа «доказательство» по необъявленному методу.
  Нужен критерий: наблюдение не пишет «двусторонний прогон пройден» и
  не меняет «доказанность» для гейта мержа и ревью-пакета
  (`review_lines`, `test_integrity.py:1236-1256`).
- **Е2. Обход теста-шпиона вместо решения Г1.** Шпион узнаёт прогон по
  `pytest` + `.py::` в argv и `git … worktree add`
  (`tests/…declared_change.py:280-287`). Исполнитель, буквально держась
  «тесты без правок», может звать pytest наблюдения без id узла
  (`-k`, `--pyargs`, файл со списком узлов) или заводить деревья иначе
  (`git archive`) — тест зелёный, его смысл (нет прогонов при находке)
  нарушен молча. Закрывается решением по Г1.
- **Е3. Пропуск наблюдения по «записи в журнале».** Ключ повтора —
  только sha головы (требование 3). Запись о сбое/«не прогнан: предел»
  тоже блокирует повтор на той же голове; это данные, не гейт, но
  Оператору стоит знать: исход наблюдения по голове фиксируется первым
  проходом, каким бы он ни был. Отклонением не считаю.

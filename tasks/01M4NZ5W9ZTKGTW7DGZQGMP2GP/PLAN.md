# PLAN: Наблюдение неослабления — двусторонний прогон каждого изменённого метода и замер расхода test_author

## Подход
Только наблюдение и отчёт, вердикт гейта неослабления не меняется.

- `two_sided.py`: плагин pytest пишет для упавшего узла место утверждения —
  последний кадр трассировки «вне библиотек» (файл внутри `--rootdir`
  стороны, не под `site-packages` и не под каталогом stdlib), путь
  относительно корня дерева стороны, номер и текст строки. Для
  `self.assert*` и голого `assert` это строка в файле узла
  (`unittest/case.py` — stdlib); для помощника другого файла — строка
  помощника (AC-1 и долгоживущий тест `test_ac1_*` требуют именно её).
  `Outcome` получает поле `sides` ({адрес: {сторона: {исход, путь, строка,
  текст}}}) с умолчанием `None`; `refusals`/`results` не меняются.
  `run` получает необязательный `deadline` (monotonic): таймаут стороны —
  `min(TWO_SIDED_PYTEST_TIMEOUT_SEC, остаток)`, исчерпанный остаток —
  исход стороны «не прогнан: предел». Гейт `run` зовёт без `deadline` —
  его таймаут прежний (читается из `config` в момент вызова).
- `test_integrity.py`: `_observe` вызывается в `_test_integrity_gate`
  сразу после `_journal_pass` и до ветвления по `ev.rest` (после выхода по
  `is_canary`). Под флагом `config.TWO_SIDED_OBSERVATION`; методы
  `ev.cmp.changes` с `base_source != head_source`; повтор на том же sha
  головы пропускается по записи журнала («голова <sha>; …»). Каждый метод
  — отдельный `two_sided.run` с общим `deadline` (предел
  `config.TWO_SIDED_OBSERVATION_LIMIT_SEC = 600`); запись «двусторонний
  прогон (наблюдение)»: голова, база, адрес, текстовый вердикт
  (`ev.outcomes`), вид и признаки, длительность, по каждой стороне — исход,
  признак «в изменённых строках» (по диффу base/head метода через
  `difflib`, строка стороны «новая на базе» — с изменёнными строками
  head-версии, «старая на ветке» — base-версии; кадр не в файле метода или
  вне тела метода — «неприменимо»), место. Любое исключение наблюдения
  перехватывается внутри `_observe` и пишется записью с причиной; вызов
  `two_sided.run` гейта вне этого перехвата. `TWO_SIDED_PASSED_ACTION`
  наблюдение не пишет; `merge_gate_escalates`, `uncovered`, `review_lines`
  не трогаются.
- `report.py`: две новые панели. «Шаги test_author» — по записям журнала
  шага («agent run started» → «прогон pytest» → «agent cost KNOWN» →
  «agent run finished») за окно `OPERATOR_WINDOW_DAYS`: стоимость, токены,
  вызовы инструментов по видам из строк `· <Инструмент> <аргумент>` лога,
  число и суммарное время прогонов pytest, Write/файлы/строки отдельно
  для `tests/` (сегмент `tests/` видимого пути) и `acceptance_tests/`
  (сегмент, начинающийся с `acceptance`); путь, достигший предела обрезки
  (`TOOL_ARGUMENT_LIMIT` провайдера Claude), и отсутствующий файл — «н/д»;
  провайдер не Claude — Write/файлы/строки «н/д». Без git.
  «Двусторонний прогон (наблюдение)» — таблица «класс текстового вердикта ×
  исход и признак каждой стороны → число записей»; классы с правилом
  старшинства «покрыто мандатом».
- `config.py`: `TWO_SIDED_OBSERVATION = True`,
  `TWO_SIDED_OBSERVATION_LIMIT_SEC = 600`. `tests/sandbox.py`: одна строка
  `config.TWO_SIDED_OBSERVATION = False` с комментарием рядом с подменой
  `config.MODELS_LOCAL`.

Сверка с SPEC, требование 1: «последний кадр в файле узла, иначе последний
вне библиотек» и «последний кадр вне библиотек» совпадают во всех случаях,
кроме помощника другого файла, вызванного из теста, — там AC-1 и
зафиксированный долгоживущий тест требуют строку помощника; реализовано
по ним.

## Шаги
1. `config.py`, `tests/sandbox.py` — флаг и предел.
2. `two_sided.py` — место утверждения в плагине, `Outcome.sides`, `deadline`.
3. `test_integrity.py` — `_observe` и признак «в изменённых строках».
4. `report.py` — раздел test_author и сводка наблюдения.
5. Карта `scripts/codebase_map.py`, прогон долгоживущих файлов задачи,

## Влияние на систему
Гейт неослабления (инвариант 38) не ослабляется: наблюдение стоит между
`_journal_pass` и ветвлением, его исключения перехвачены внутри, его
результат гейтом не читается; запись «пройден» пишет только прежний код.
Гейт мержа и ревью-пакет не меняются. Стоимость: до 600 с дополнительных
прогонов pytest на переходе `in_dev -> verifying` (по два дерева на метод);
выключается флагом `config.TWO_SIDED_OBSERVATION`. `report` по-прежнему без
git, провайдеры не меняются. Откат — revert merge-коммита.

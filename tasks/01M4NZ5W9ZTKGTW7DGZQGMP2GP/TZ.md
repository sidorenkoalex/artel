# ТЗ: Наблюдение неослабления: двусторонний прогон каждого изменённого метода и замер test_author (шаг 0)

# ТЗ: Наблюдение неослабления — двусторонний прогон каждого изменённого метода и строка упавшего утверждения (шаг 0 порядка работ по тестам)

Источник: очередь Оператора 11.10 «Порядок работ по тестам конвейера»,
шаг 0; разбор механики тестов 11.10 и его независимая проверка;
решение Оператора 11.10.2026 — вести в волне. Прецедент приёма «сначала
наблюдение, потом отказ» — задача 01M3Y753 (02.10).

Цель: данные для решения Оператора об уровнях строгости гейта
неослабления (шаг 4): где текстовый вердикт и двусторонний прогон
расходятся, падает ли новая версия на изменённом утверждении или на
предусловии. Поведение гейта не меняется.

Факты (origin/main, сверка 11.10; код пульта совпадает с пином):
- Двусторонний прогон `orchestrator/advance_gates/two_sided.py`
  вызывается только из `test_integrity.py` ~1353 на in_dev → verifying,
  только для методов, чья смена совпала с объявленной в «Меняемом
  поведении» (`ev.expectation`, ~1106–1115, ~1350).
- Деревья: `git worktree add --detach` базы (merge-base) и головы во
  временном каталоге, head-версия файла теста кладётся в дерево базы,
  base-версия — в дерево головы, pytest по узлам метода (~227–256);
  уборка в `finally` (~275).
- Плагин `_PLUGIN_SOURCE` (~50–90) пишет JSONL с `exception`,
  `assertion`, `timeout`, `in_setup`; номер строки упавшего утверждения
  не пишется, хотя доступен (`tb.tb_lineno` последнего кадра или
  `report.longrepr.reprcrash`). `_verdict` (~128–162).
- `_test_integrity_gate` (~1324–1365): после `_evaluate` и
  `_journal_pass` на руках `ev.cmp.changes` (все изменённые методы,
  `MethodChange`, ~453–473), `ev.cmp.base`, `ev.outcomes[адрес]`
  (текстовый вердикт), `m.change.kind`/`signs`. В `changes` есть
  вызывающие вне диффа с `base_source == head_source` — для них прогон
  бессмыслен.
- Предел `config.TWO_SIDED_PYTEST_TIMEOUT_SEC = 300` на прогон; время
  прогона не журналируется.
- Стоимость шага роли: «agent run finished», «agent cost KNOWN»
  (`runner.py` ~1680–1821, `spend.py`); вызовы pytest внутри шага —
  «прогон pytest» (`agent_log.py` ~221); лог шага `.artel/logs/<id>-<роль>-N.log`
  со строками `· <Инструмент> <аргумент>` без меток времени.

Требуется:
1. Плагин двустороннего прогона записывает для упавшего узла путь и
   номер строки последнего кадра теста (место утверждения) и текст
   этой строки; `Outcome` отдаёт их наружу. Вердикт двустороннего
   прогона и его использование гейтом не меняются.
2. Наблюдение: на in_dev → verifying, после текстового вердикта и до
   ветвления по нему, для КАЖДОГО изменённого метода с
   `base_source != head_source` (не только объявленного) — двусторонний
   прогон и запись в журнал действием «двусторонний прогон
   (наблюдение)»: адрес метода, текстовый вердикт (`ev.outcomes`), вид
   изменения (`kind`, `signs`), исход каждой стороны (утверждение /
   зелёный / иная причина), путь и строка упавшего утверждения, входит
   ли эта строка в изменённые строки метода (по диффу base/head
   метода), длительность.
3. Наблюдение не влияет на вердикт и переход: исключение, таймаут,
   сбой git — запись в журнал с причиной, переход идёт как без
   наблюдения. Повторный advance на том же sha головы не гоняет
   наблюдение заново (по записи в журнале).
4. Включение — флаг `config` (по умолчанию включено), предел времени
   на всё наблюдение одного перехода — `config` (по умолчанию 600 с;
   исчерпан — оставшиеся методы записываются «не прогнан: предел»).
   Канарейка — наблюдение выключено.
5. Замер расхода test_author без новой телеметрии: команда `report`
   (или отдельный раздел существующего отчёта) по задачам за период
   выводит для шагов test_author: стоимость, токены, число вызовов
   инструментов по видам (из лога шага), число прогонов pytest и их
   суммарное время (из журнала), число созданных файлов `tests/` и
   строк. Только чтение.
6. Сводка наблюдения: тот же отчёт выводит по записям п.2 таблицу
   «текстовый вердикт × исход двустороннего прогона × строка в
   изменённых», чтобы через 1–2 недели Оператор видел расхождения.

Критерии приёмки (направление; планку пишет test_author):
- Изменённый, но не объявленный метод получает запись наблюдения с
  исходами сторон и строкой утверждения; вердикт гейта прежний (отказ
  по находке остаётся отказом).
- Сбой наблюдения (подменённый pytest падает/таймаут) не меняет исход
  перехода; запись с причиной есть.
- Строка упавшего утверждения совпадает с номером строки assert в
  файле теста; признак «в изменённых строках» верен для изменённого и
  неизменённого утверждения.
- Повторный advance на той же голове наблюдение не повторяет.
- Отчёт выводит расход test_author и сводку наблюдения по записям.
- Существующие тесты гейта неослабления и двустороннего прогона зелёные
  без правок.

Ослабления нет: вердикт и отказы гейта неослабления не меняются;
добавляются запись в журнал и отчёт.

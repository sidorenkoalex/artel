# ТЗ: WIP-чекпоинт после таймаута — только зона роли, артефакты — в артефактную ветку

Источник: инциденты 03–04.09. (1) Hotfix 01M1KT0792125J9ZNJNZJ86E9Q:
шаг test_author оборвался по таймауту, WIP-чекпоинт (`checkpoint.py`,
`git add -A` + commit в кодовую ветку) закоммитил не только тесты, но и
временную заглушку реализации в `orchestrator/answer.py`/`runner.py`
(23 строки), которую роль делала для обязательной проверки планки;
следующий шаг застал заглушку в голове ветки, ревьювер вынес
замечание (R2-F1). (2) Тот же чекпоинт кладёт `tasks/<id>/` в кодовую
ветку, хотя после A7 артефакты живут в артефактной ветке: следующий
шаг роли видит каталог удалённым/устаревшим, роли «восстанавливают»
его `git checkout`, SPEC/PLAN расходятся между ветками (задачи
01M1KCSTBYF1CRJBSY4P6VYQEA, 01M1HNNHDMP2C1AJTH5QF1BTN2).

Требуется:
1. WIP-чекпоинт после таймаута коммитит в кодовую ветку только пути,
   на которые у роли есть мандат кода: developer — всё, кроме
   `tasks/<id>/`; test_author и analyst — ничего в кодовую ветку
   (их результат — только артефакты). Изменения вне мандата не
   коммитятся, а откатываются (`git checkout -- <пути>`), с записью в
   журнал, какие пути и сколько строк отброшено.
2. Содержимое `tasks/<id>/` рабочего каталога при таймауте
   переносится в артефактную ветку тем же автокоммитом, что и при
   штатном завершении шага (`_commit_external_step_artifacts`), с
   пометкой «WIP после таймаута» в сообщении, — не в кодовую ветку.
3. Сообщение WIP-коммита и запись в журнал называют роль и причину
   (таймаут), чтобы developer/reviewer видели происхождение.
4. Тесты: таймаут test_author с правками в `orchestrator/` — код
   откачен, тесты в артефактной ветке, журнал; таймаут developer —
   код закоммичен, `tasks/<id>/` в артефактной ветке; существующие
   тесты зелёные без ослабления.

Зоны: orchestrator/checkpoint.py, orchestrator/runner.py (вызов при
таймауте), tests/. Конфликт зон с задачей 01M1KVG3KSCY47HWXWF5HM0E76
(checkpoint.py) — стартовать после её мержа; до мержа — только SPEC.

Не входит: изменение таймаута шага и ретраев; перефиксация
таймаут-чекпоинта (копилка роадмапа, отдельно).

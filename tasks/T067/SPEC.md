# SPEC: Авторазрешение конфликта карты при подтяжке

## Контекст

Роадмап §4 п.2а, строка P3 «Подтяжка: авторазрешение конфликта
docs/codebase-map.md регенерацией». 28.08 зафиксировано шесть
конфликтов подтяжки за день при параллельности N>1 — все ТОЛЬКО в
`docs/codebase-map.md`, все разрешены Оператором одинаково: `checkout
--theirs` → `scripts/codebase_map.py` → `add` → `commit`. Карта —
генерируемый файл, функция от кода; каждая ветка регенерирует свой
снимок, main несёт снимок соседей — контентный конфликт гарантирован,
даже когда по коду конфликтов нет вообще. Правильное разрешение не
выбирается, а вычисляется: карта слитого дерева. Прецедент уже в
системе — T042 научила оркестратор чинить карту тем же приёмом на
`merge_gate -> done`.

## Требования

1. При конфликте `git merge` внутри `_pull_main_or_escalate`
   (`orchestrator/fsm.py`, T051) — единственной функции механики
   подтяжки, вызываемой из всех точек сверки (`in_dev -> review`,
   `acceptance -> merge_gate`, и внутри окна `merge_gate` по T053) —
   оркестратор смотрит список конфликтующих файлов (`git diff
   --name-only --diff-filter=U`). Если этот список состоит РОВНО из
   `docs/codebase-map.md` и ничего больше, оркестратор разрешает
   конфликт сам, не эскалируя.
2. Авторазрешение: взять любую сторону конфликта по файлу карты
   (`git checkout --theirs docs/codebase-map.md`), регенерировать
   карту генератором `scripts/codebase_map.py` НА СЛИТОМ дереве
   worktree задачи, `git add docs/codebase-map.md`, завершить
   merge-коммит. Подтяжка после этого считается успешной — тот же
   исход, что и подтяжка без конфликта, дальнейший путь (приёмочные
   тесты и переход дальше) не меняется.
3. Журнал задачи получает запись об авторазрешении: actor=orchestrator,
   файл (`docs/codebase-map.md`), способ (регенерация генератором
   карты).
4. Список конфликтующих файлов содержит `docs/codebase-map.md` вместе
   с любым другим файлом, либо не содержит карту вовсе — поведение
   прежнее (T051/T052 байт-в-байт): `git merge --abort`, эскалация
   с диагностикой конфликта, ветка задачи остаётся в состоянии до
   подтяжки, main не изменяется.
5. Регенерация карты при авторазрешении завершается ненулевым кодом
   возврата генератора → `git merge --abort`, эскалация — тем же путём,
   что и обычный (не авторазрешаемый) конфликт; полусмерженное
   состояние (незавершённый merge, застейдженная правка карты) не
   остаётся.
6. Логика авторазрешения не дублируется по точкам вызова — она живёт
   в `_pull_main_or_escalate` (или её прямом внутреннем подвызове),
   той же единственной функции, что уже сегодня обслуживает и
   `in_dev -> review`/`acceptance -> merge_gate`, и, с T053, вызов
   внутри окна `merge_gate`.
7. В песочницах тестов без реального git (`fake_git` и аналогичные
   заглушки) поведение деградирует по тому же образцу, что и остальная
   часть `_pull_main_or_escalate` из T051.

## Критерии приёмки

AC-1. Конфликт подтяжки, где единственный конфликтующий файл —
`docs/codebase-map.md`: оркестратор не эскалирует, а завершает merge
сам — merge-коммит создан, содержимое карты соответствует регенерации
на слитом дереве (повторный прогон `scripts/codebase_map.py` не даёт
диффа), подтяжка возвращает тот же исход, что и подтяжка без
конфликта (штатное продолжение — приёмочные тесты и переход дальше),
эскалации не происходит.

AC-2. В сценарии AC-1 в журнал задачи попадает запись об
авторазрешении конфликта карты: actor=orchestrator, файл
`docs/codebase-map.md`, способ разрешения (регенерация).

AC-3. Конфликт подтяжки, где конфликтующие файлы — `docs/codebase-map.md`
и хотя бы один другой файл: оркестратор ведёт себя как до этой задачи —
`git merge --abort`, задача переходит в `escalated` с диагностикой
конфликта (перечень файлов), ветка задачи остаётся в состоянии до
подтяжки, main не изменяется.

AC-4. Конфликт подтяжки, среди файлов которого `docs/codebase-map.md`
не встречается вовсе: поведение полностью прежнее (T051), байт-в-байт.

AC-5. Регенерация карты при авторазрешении (сценарий AC-1) завершается
ненулевым кодом возврата: оркестратор выполняет `git merge --abort`,
задача переходит в `escalated`, ветка задачи остаётся в состоянии до
подтяжки — полусмерженного состояния (незавершённый merge, застейдженная
правка) не остаётся.

AC-6. Авторазрешение работает одинаково независимо от того, из какой
точки вызвана подтяжка (`in_dev -> review`, `acceptance -> merge_gate`,
внутри окна `merge_gate` по T053) — общей функцией, без дублирования
логики между точками вызова.

AC-7. В песочницах тестов без реального git сверка/авторазрешение
молча пропускается — тот же вырожденный случай деградации, что
у остальной части `_pull_main_or_escalate`.

AC-8. Все существующие тесты пакета остаются зелёными; ни один
существующий тест, гейт, лимит, guard-проверка или инвариант (ADR-0002)
не ослаблены.

## Не входит

- Авторазрешение любых файлов, кроме `docs/codebase-map.md`.
- patch-id-фиксация approve (устойчивость вердикта к чистому rebase) —
  отдельная строка роадмапа P3, эта задача её не трогает.
- Изменение генератора карты (`scripts/codebase_map.py`).
- Изменение эскалационных путей T051/T052 для конфликтов, не
  сводящихся к чистому случаю «только карта» — они остаются
  байт-в-байт.
- Правки main напрямую — авторазрешение целиком живёт в worktree
  ветки задачи, как и вся механика подтяжки T051.
- Файлы вне `orchestrator/` (`fsm.py` и смежные модули), тестов и
  карты кодовой базы.

# kill: удаление ветки задачи в origin проекта под белым списком отправки

## Факты

1. `kill` задачи внешнего проекта удаляет ветку задачи в origin (`cleanup_project_remote`, `orchestrator/cleanup.py:284`; `_delete_origin_branch`, `:265-281`) вызовом `_bounded` (`:258-262`), который добавляет перед `push` глобальные опции `-c http.lowSpeedLimit=1 -c http.lowSpeedTime=<config.GH_TIMEOUT_SEC>` — предел времени отправки.
2. Отправка в проект под белым списком (`targets.push_whitelisted`) проходит `_whitelist_refusal` (`orchestrator/gitcmd.py:975-990`): перед `push` разрешена только глобальная опция `-C`, прочие — отказ «глобальная опция git <опция> перед push».
3. Опыт 06.11 (строка копилки 06.11): `kill` задачи проекта `target-human` вывел «ветка origin task/…: оставлено — отказ: отправка отказана (проект …): глобальная опция git -c перед push». Ветки в origin в тот раз не было; при существующей ветке она осталась бы в origin после `kill`.

## Требуется

1. Удаление ветки задачи в origin при `kill` проходит белый список отправки проекта и удаляет ветку, сохраняя предел времени вызова: предел задаётся не глобальной опцией `-c` перед `push`, а способом, который белый список пропускает и не ослабляет (например, ограничение времени процесса вызова, как у прочих отправок пульта, или опция, уже разрешённая белым списком).
2. Белый список отправки (`_whitelist_refusal`) не расширяется: разрешённые глобальные опции, флаги и переменные окружения — прежние.
3. Проекты не под белым списком и проект артели — поведение `kill` прежнее; тексты исходов «удалена» / «оставлено — <причина>» прежние.

## Критерии приёмки

- Given вымышленный проект под белым списком (`target-human`) с веткой задачи в origin-дублёре (локальный голый репозиторий), When `kill` задачи, Then ветки в origin нет, вывод «ветка origin <ветка>: удалена»;
- Given origin, который принял соединение и молчит (подменённый транспорт), When `kill`, Then удаление обрывается в пределах прежнего предела времени, вывод «оставлено — <причина>», `kill` завершён;
- Given глобальная опция `-c` перед `push` в отправке проекта под белым списком, Then прежний отказ «глобальная опция git -c перед push» (белый список не ослаблен);
- проект артели и проект без белого списка — `kill` как прежде; существующие тесты — зелёные без правки.

Безопасность тестов: вымышленные проекты, origin — локальный голый репозиторий во временной песочнице (`tests.sandbox`), без сети; никогда — настоящий `.artel/targets.yaml` и клоны проектов.

Существующие тесты: правка не должна сделать красным ни один существующий тест; если краснеет — эскалация с именем теста, без правки.

Зоны: `orchestrator/cleanup.py` (`_bounded`, `_delete_origin_branch`), `docs/codebase-map.md` (только генерацией), `tests/` (долгоживущие файлы задачи).

Только чтение: `orchestrator/gitcmd.py`, `orchestrator/targets.py`, `orchestrator/config.py`, `tests/sandbox.py`, `tests/test_kill_cleanup.py`.

Не входит:
- изменение белого списка отправки;
- закрытие черновых MR при `kill` (`_close_project_pr`);
- прочие вызовы `_bounded`, кроме удаления ветки при `kill`, если они не проходят белый список (назвать в «Предложениях системе», если найдены).
- правка настоящего локального слоя `.artel/targets.yaml` в тестах и при разработке.

# SPEC: kill — удаление ветки задачи в origin проекта под белым списком отправки

## Контекст
`kill` задачи внешнего проекта удаляет ветку задачи в `origin`
(`cleanup_project_remote`, `orchestrator/cleanup.py:284`;
`_delete_origin_branch`, `:265-281`) вызовом `_bounded` (`:258-262`),
который ставит перед `push` глобальные опции `-c http.lowSpeedLimit=1 -c
http.lowSpeedTime=<config.GH_TIMEOUT_SEC>` — предел времени отправки. У
проекта под белым списком отправки (`targets.push_whitelisted`) отправку
проверяет `_whitelist_refusal` (`orchestrator/gitcmd.py:975-990`): перед
`push` разрешена только глобальная опция `-C`, прочие — отказ «глобальная
опция git <опция> перед push». Опыт 06.11: `kill` задачи проекта
`target-human` вывел «ветка origin task/…: оставлено — отказ: отправка
отказана (проект …): глобальная опция git -c перед push» — существующая
ветка осталась бы в `origin` после `kill`.

## Требования
1. При `kill` задачи проекта под белым списком отправки удаление ветки
   задачи в `origin` проходит белый список и удаляет ветку.
2. Удаление ветки при `kill` сохраняет предел времени вызова, равный
   прежнему (`config.GH_TIMEOUT_SEC`, читается в момент вызова); у
   проекта под белым списком предел задаётся не глобальной опцией `-c`
   перед `push`, а способом, который белый список пропускает и не
   ослабляет (например, ограничение времени процесса вызова, как у прочих
   отправок пульта, или опция, уже разрешённая белым списком). Сработавший
   предел — исход «оставлено — <причина>», `kill` при этом завершается.
3. Белый список отправки (`_whitelist_refusal`) не расширяется:
   разрешённые глобальные опции, флаги и переменные окружения — прежние.
4. Проекты не под белым списком и проект артели — поведение `kill`
   прежнее; тексты исходов «ветка origin <ветка>: удалена» / «ветка origin
   <ветка>: оставлено — <причина>» прежние.

## Критерии приёмки
AC-1. Given вымышленный проект под белым списком (`merge_gate:
target-human`) с веткой задачи в origin-дублёре (локальный голый
репозиторий во временной песочнице), When `kill` задачи, Then ветки
задачи в origin нет и вывод несёт «ветка origin <ветка>: удалена».

AC-2. Given вымышленный проект под белым списком, origin которого принял
соединение и молчит (подменённый транспорт), When `kill` задачи, Then
удаление ветки обрывается в пределах прежнего предела времени
(`config.GH_TIMEOUT_SEC`), вывод несёт «ветка origin <ветка>: оставлено —
<причина>», задача в `killed`.

AC-3. Given отправка проекта под белым списком с глобальной опцией `-c`
перед `push`, Then отправка отказана прежним текстом «глобальная опция git
-c перед push» (белый список не ослаблен).

AC-4. Given проект артели и вымышленный проект без белого списка
(`merge_gate: operator`), When `kill` задачи, Then исход уборки ветки в
origin и его текст — как до правки (у проекта без белого списка ветка
удалена с выводом «ветка origin <ветка>: удалена»; у артели удаление
ветки в origin не выполняется).

## Не входит
- Изменение белого списка отправки (`_whitelist_refusal`, разрешённые
  опции/флаги/переменные окружения).
- Закрытие черновых MR при `kill` (`_close_project_pr`).
- Прочие вызовы `_bounded`, кроме удаления ветки при `kill` (например,
  `ls-remote` в `_origin_branch_head`, `orchestrator/cleanup.py:357`):
  если найдены не проходящие белый список — назвать в «Предложениях
  системе» PLAN, не править.
- Правка настоящего локального слоя `.artel/targets.yaml` и клонов
  проектов в тестах и при разработке.
- Правка `orchestrator/gitcmd.py`, `orchestrator/targets.py`,
  `orchestrator/config.py`, `tests/sandbox.py`, `tests/test_kill_cleanup.py`
  — только чтение.
- Полный зелёный набор `tests/` без правки существующих тестов — её держит
  пульт; покраснел существующий тест — эскалация с его именем, без правки.

# Артель

Мультиагентная система доведения запроса Оператора до продакшена.
Конвейер ролей-агентов (аналитик → разработчик → ревьювер → верификатор),
управляемый детерминированным конечным автоматом; роли общаются
материальными артефактами в git, автономия дозируется политикой гейтов.

Полный дизайн: [спека (16 разделов)](docs/design.md) — роли, скилы,
runtime, политика гейтов, конкурентный ландшафт, карта исполнителей.

## Текущая фаза: 0 (MVP-минус)

Цель — первый замкнутый цикл «запрос → смерженный MR», критерий выхода:
**5 реальных задач прошли цикл**. Осознанно урезано:

- Роли-агенты только две: **разработчик** и **ревьювер**.
  SPEC пишет Оператор, он же делает приёмку перед мержем.
- Оркестратор — CLI (`orchestrator/artel.py`): FSM в SQLite, поллинг CI,
  все гейты ручные и захардкожены (gates.yaml — справочный).
- Один общий токен на все роли (см. ADR-0001) — слоты раздельные,
  разделение PAT — при выходе из Фазы 0.

## Структура

```
templates/     шаблоны артефактов (SPEC, PLAN, REVIEW, TEST_REPORT)
skills/        скилы ролей (процедурные знания, подключаются к промптам)
tasks/<id>/    артефакты задач — шина обмена между ролями
docs/adr/      архитектурные решения
scripts/       guard.py — валидатор структуры артефактов
orchestrator/  artel.py — FSM-оркестратор Фазы 0
sandbox/       Dockerfile песочницы агента
gates.yaml     политика гейтов (Фаза 0: справочно, всё manual)
roles.yaml     карта исполнителей и слоты токенов
```

## Быстрый старт

```bash
# токен (Фаза 0: один на все роли, кладётся в keychain)
security add-generic-password -a artel -s artel-token -w '<PAT>'

python3 orchestrator/artel.py init
python3 orchestrator/artel.py new "Краткое название задачи"
# → создаст tasks/<id>/ из шаблонов; заполни SPEC.md и:
python3 orchestrator/artel.py approve <id>        # гейт SPEC
python3 orchestrator/artel.py auto <id>           # цикл до ближайшего гейта
python3 orchestrator/artel.py status
```

## Инварианты (не нарушаются ни в одной фазе)

1. Всё детерминированное — код и пайплайны, не LLM. Оркестратор не думает.
2. Каждая передача между ролями — файл в `tasks/<id>/`, не контекст чата.
3. У каждого цикла — числовой лимит; после лимита — Оператор, не ретрай.
4. Молчание ≠ согласие: ручной гейт не «автопроходит» по таймауту.
5. Потолок задачи = её денежный бюджет; журнал шагов пишется всегда.

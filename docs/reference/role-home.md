# Референс слоя ролей `.artel/home`

Минимальный слепок курируемого HOME, с которым запускается процесс
роли (`orchestrator/runner.role_env`, ADR-0003 п.14). Живёт в
репозитории пульта, чтобы холодный старт (SPEC T049, ADR-0005 п.5) не
зависел от бэкапа эфемерного `.artel/`: `init` разворачивает это
поддерево в `.artel/home/`, если каталог там ещё не существует
(`orchestrator/catalog._deploy_role_home_reference`, требование 9).

## Структура

```
docs/reference/role-home/
  claude/CLAUDE.md          -> .artel/home/.claude/CLAUDE.md  (переименовывается при деплое)
  claude/settings.json      -> .artel/home/.claude/settings.json  (deny-список роли)
```

`settings.json` несёт `permissions.deny` — часть периметра роли (пул
канарейки и клонирование, SPEC 01M1NEEWH5K1XPFRDGRMPYSBXJ, требование
13а). Полный прогон набора тестов внутри шага (голый `pytest`, `pytest
tests`, `pytest .`) и три команды диспетчера (`init`, `doctor
--restore`, `canary pool-seal`) отклоняются не отсюда, а признаком
процесса роли в окружении (`ARTEL_ROLE`/`ARTEL_TASK`,
`orchestrator/runner.py::role_env`) — читает его сам CLI: корневой
`conftest.py` (гейт сбора pytest) и `orchestrator/artel.py` (гейт трёх
команд диспетчера). Механизм LLM-независим (SPEC
01M2B6K3EM7F2J72RC2F520Y2K), в отличие от снятого этой же задачей
клиентского PreToolUse-хука `hooks/bash_guard.py`, работавшего только
через протокол Claude Code. Проверяется `tests/test_conftest_role_guard.py`
и тестами диспетчера `orchestrator/artel.py`.

Деплой референса происходит ТОЛЬКО при отсутствии `.artel/home`
(холодный старт). На уже работающем пульте изменения референса в
`.artel/home/.claude/` не попадают сами — Оператор копирует их руками
(так 05.09 обнаружилось, что deny-список канарейки на этом пульте не
был развёрнут).

Каталог референса называется `claude/`, БЕЗ ведущей точки — в самом
репозитории, чтобы не путать инструментарий (IDE, агентские харнессы),
который трактует `.claude/` как служебный каталог настроек. Деплой
(`_deploy_role_home_reference`) сам переименовывает его в `.claude/`
при копировании в `.artel/home/`.

## Граница git роли и `task-rm`

`deny` несёт `Bash(git clean:*)` (SPEC 01M6JJ4J4NBV2Y1Q4XHE3C3FVT,
требование 9) — дополнительно к механизму, а не вместо него. Сам механизм
живёт не в доме роли, а в окружении шага (`runner.role_env`, оба
провайдера): потолок `GIT_CEILING_DIRECTORIES`, равный корню пульта, и
обёртка git `orchestrator/role_bin/git` (проверка —
`orchestrator/role_git.py`) вторым элементом PATH. Обёртка отклоняет git в
репозитории пульта и его каталогах, в рабочей копии другой задачи и
`git clean` (с псевдонимами, `!`-псевдонимами, pager/fsmonitor, вызывающими
git) в своей рабочей копии; подробности — `docs/stack.md`, «Паритет
безопасности роли». Строка `doctor` — `role-git-boundary`.

Убрать свой временный файл роль может командой пульта
`python3 <ROOT>/orchestrator/artel.py task-rm <id> <путь>…`: только файлы
рабочей копии своей задачи и новые файлы каталога её документов (которых
нет в ссылке документов), без каталогов и `.git`; один недопустимый путь —
отказ всей команды.

Ручной шаг Оператора после мержа: на работающем пульте перенести строку
`"Bash(git clean:*)"` из `docs/reference/role-home/claude/settings.json` в
`permissions.deny` файла `.artel/home/.claude/settings.json` — деплой
референса сам этого не сделает (см. выше).

## Что здесь и чего здесь нет

- Есть: минимальный `CLAUDE.md`, объясняющий сам механизм («это HOME
  пульта, курируемый для роли, а не личный `~/.claude` Оператора») —
  не инструкция роли на конкретную задачу (та приходит промптом,
  `orchestrator/brief.py` + `skills/*.md`).
- Нет секретов: токен подписки роль получает из keychain пульта
  (`orchestrator/keychain.py`) переменной окружения
  (`CLAUDE_CODE_OAUTH_TOKEN`), git-идентичность — тоже переменными
  окружения (`role_env`). Ни то, ни другое сюда не пишется. Проверено
  ручным грепом по дереву референса:
  `grep -rEi "token|secret|api[_-]?key|password" docs/reference/role-home/`
  — совпадений нет (SPEC T049, требование 10).

## Курирование

Оператор может расширять `.artel/home` по ходу работы (например,
добавить нужный ролям MCP-конфиг). Такие изменения живут только в
самом `.artel/home` — эфемерном каталоге — и теряются вместе с ним.
Если добавленное должно пережить холодный старт, тот же материал (без
секретов — они остаются в keychain) переносится и сюда, в референс,
обычным PR с ревью кода, как любая другая правка репозитория.

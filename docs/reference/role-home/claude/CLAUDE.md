# Курируемый HOME роли (не HOME Оператора)

Этот файл — часть референса `docs/reference/role-home/` (репозиторий
пульта). `init` разворачивает поддерево референса в `.artel/home/`,
если этот каталог ещё не существует (SPEC T049, требование 9;
ADR-0003 п.14): каталог `claude/` референса становится `.claude/` в
развёрнутом слое (`orchestrator/catalog._deploy_role_home_reference`) —
имя без точки в самом репозитории, чтобы не путать инструментарий,
трактующий `.claude/` как служебный каталог настроек агента.

`.artel/home` — HOME процесса роли на время шага
(`orchestrator/runner.role_env`), НЕ личный `~/.claude` Оператора: роль
не наследует его CLAUDE.md, хуки его плагинов и его MCP — это была бы
конфиг-инъекция (ADR-0003 п.14). Задача роли на конкретный шаг
приходит промптом (`orchestrator/brief.py` + `skills/*.md`), не этим
файлом — здесь только объяснение самого механизма, не инструкция роли.

`.artel/home` эфемерен (ADR-0005 п.3): его потеря — штатный сценарий,
`init` пересобирает каталог из этого референса. Аутентификация роли не
живёт ни в этом файле, ни где-либо ещё в `.artel/home` — токен
подписки приходит переменной окружения из keychain пульта
(`orchestrator/keychain.py`), git-идентичность — из `role_env` тем же
путём. Секретов в этом референсе нет и не должно быть: правки сюда
проходят обычный ревью кода, как и любой другой файл репозитория.

Оператор может курировать содержимое `.artel/home` по ходу работы
(например, добавить нужный ролям MCP-конфиг) — тогда стоит перенести
изменение и в этот референс (`claude/` здесь → `.claude/` там), иначе
следующий холодный старт вернёт пульт к минимуму. Подробнее —
`docs/reference/role-home.md`.

Никогда: чтение путей под каталогом пула канарейки (`~/.artel-canary`),
команды `git clone`/`gh repo clone`/`git remote add` на репозиторий
пула — `settings.json` этого референса несёт запрещающие правила
`permissions.deny`, отказывающие CLI в этом до исполнения (SPEC
01M1NEEWH5K1XPFRDGRMPYSBXJ, требование 13). Этот абзац — текстовое
напоминание, не замена того отказа.

# Курируемый дом роли (не дом Оператора)

Этот файл — часть референса `docs/reference/role-home/` (репозиторий
пульта). `init` разворачивает поддерево референса в `.artel/home/`
РОВНО ТОГДА, когда этого каталога ещё нет целиком (ADR-0003 п.14,
`orchestrator/catalog._deploy_role_home_reference`): каталог `codex/`
референса становится `.codex/` в развёрнутом слое — имя без точки в
самом репозитории, чтобы не путать инструментарий, трактующий `.codex/`
как служебный каталог настроек агента. На пульте, где `.artel/home` уже
существует, `init` не доводит слой до референса ничем: расхождение
называет жёлтой строкой `doctor` (`codex-role-home`), а закрывает его
Оператор — порядок описан в `docs/stack.md`, раздел «Провайдер codex».

`.artel/home/.codex` — значение `CODEX_HOME` процесса роли на время шага
(`orchestrator/providers/codex.py::environment`), НЕ личный `~/.codex`
Оператора: роль не наследует ни его `config.toml`, ни его MCP-серверы,
ни его правила — это была бы конфиг-инъекция. Повод не теоретический:
живой запуск 0.155.1 с пользовательским конфигом Оператора позвал
MCP-сервер `cua_repl` («Computer Use») и попытался открыть браузер на
машине Оператора.

Задача роли на конкретный шаг приходит промптом
(`orchestrator/brief.py` + `skills/*.md`), не этим файлом — здесь только
объяснение самого механизма, не инструкция роли. Файлы политики команд
`.rules` шагу не достаются вовсе: команда шага несёт `--ignore-rules`.
На `AGENTS.md` этот флаг не распространяется, поэтому файл, который ты
сейчас читаешь, роли действительно виден.

`.artel/home` эфемерен (ADR-0005 п.3): его потеря — штатный сценарий,
`init` пересобирает каталог из этого референса. Поэтому ничего, что
нельзя потерять, здесь не живёт — и та же изоляция продублирована
флагами самой команды шага: выключение сети песочницы, политика
подтверждений «никогда» и выключение одиннадцати функций 0.155.1 стоят и
в соседнем `config.toml`, и в argv, который собирает
`orchestrator/providers/codex.py`.

## Интерпретатор и PATH, которые видит шаг

PATH шага собирает пульт (`orchestrator/runner.py::role_env`), а не
оболочка машины: первым каталогом стоит `.artel/venv/bin` — интерпретатор
пульта, дальше каталоги объявленных манифестом инструментов (`git`, `gh`,
`codex`). Внутри шага голый `python3` и `pytest` — это `.artel/venv/bin/
python3` и `.artel/venv/bin/pytest`, ровно те же, что видит шаг на
провайдере по умолчанию. Искать другой интерпретатор перебором
(`python3.13`, `/usr/bin/python3`) не нужно и не следует: системный
`/usr/bin/python3` на этой машине — 3.9, и `python3 scripts/guard.py` на
нём падает на аннотациях с `|`.

Держится это двумя курируемыми половинами, потому что команды шага
исполняет оболочка ВХОДА (`/bin/zsh -lc`), а она в macOS читает
`/etc/zprofile` с `path_helper` — тот ставит системные каталоги В НАЧАЛО
PATH, оставляя каталоги пульта в хвосте:

- соседний `.zshenv` этого же дома роли снимает опцию `GLOBAL_RCS`, и
  оболочка входа перестаёт читать глобальные файлы (`/etc/zprofile`,
  `/etc/zshrc`, `/etc/zlogin`) — PATH, собранный пультом, доходит до
  команды в исходном порядке. Читается этот файл потому, что окружение
  шага несёт `ZDOTDIR` на `.artel/home/.codex`;
- `shell_environment_policy` соседнего `config.toml` с `inherit = "all"`
  (и та же пара флагом самой команды шага) доносит до команды всё
  окружение процесса роли — при `core` CLI отбрасывает `ZDOTDIR` вместе с
  git-идентичностью роли, и первая половина не срабатывает вовсе.

Перед каталогами роли CLI ставит собственные каталоги-псевдонимы
(`<CODEX_HOME>/tmp/arg0/…` и каталог установки `codex`) — ни `python3`, ни
`pytest`, ни `git`, ни `gh` в них не лежат.

Авторизация роли — **вход по подписке ChatGPT**, и в этом файле её тоже
нет. Токены того входа хранит и продлевает сам Codex CLI в системной
связке ключей (`cli_auth_credentials_store = keyring`, способ входа
задан принудительно — `forced_login_method = chatgpt`; обе пары стоят и в
соседнем `config.toml`, и флагом самой команды шага). Пульт эти токены не
читает и не пишет: вход выполняет Оператор однократно, руками.

Ни личного входа Оператора (его `auth.json` в `~/.codex`), ни ключей API
роль не получает: ключ не приходит шагу ни переменной окружения, ни
слотом keychain — белый список окружения роли таких имён не несёт вовсе,
и офлайн-смок `doctor` (`codex-isolation-smoke`) краснеет, если любое из
них в окружении шага всё же оказалось. git-идентичность приходит из
`orchestrator/runner.role_env`. Секретов в этом референсе нет и не должно
быть: правки сюда проходят обычный ревью кода, как и любой другой файл
репозитория.

Оператор может курировать содержимое `.artel/home/.codex` по ходу
работы — тогда стоит перенести изменение и в этот референс (`codex/`
здесь → `.codex/` там), иначе следующий холодный старт вернёт пульт к
минимуму, а `doctor` до тех пор будет называть расхождение жёлтой
строкой. Подробнее — `docs/stack.md`, раздел «Провайдер codex»
(`docs/reference/role-home.md` описывает только дом провайдера по
умолчанию и про `.codex`/`CODEX_HOME` не знает).

# Роадмап Артели

Нормативный план работ. Решения и их обоснования зафиксированы в ADR
(ADR-0001 — рамка Фазы 0; ADR-0002 — принцип целостности; ADR-0003 —
целевые проекты, якоря п.1–18 и 3а–3к; ADR-0004 — пульт и ассистент,
якоря п.1–9) — здесь они не пересказываются, только применяются.
Отложенные механизмы — `docs/deferred/` (publication, spaces,
prod-loop, executors); триггеры их возврата — `docs/triggers.md`;
история аудитов — `docs/audits/README.md`.

## 1. Где мы

Фаза 0 завершена: 13 задач полного цикла «запрос → смерженный MR»
на самом пульте. Работает: FSM-оркестратор (модульный пакет
`orchestrator/`), роли developer/reviewer, ревью-пакет с потолками,
учёт стоимости и жёсткие бюджеты (SPEC понижает, поднимает только
Оператор), 18 инвариантов кодированы тестами (`docs/invariants.md`),
`auto` до ближайшего гейта, kill с уборкой, принцип целостности
во всех слоях. ADR-0003/0004 приняты; A-спайк допущений пройден
(фактура — в ADR-0003 «Проверенные допущения»). Активная фаза — A:
вывод конвейера на мультитаргетный контур. Рабочий цикл Оператора:
`new` → SPEC → `advance`/`auto` → гейты `approve`/`reject`.

## 2. Фаза A — активная

Порядок внутри фазы: A6 первой (машинные поля нужны всем остальным),
затем A1+A2+A2b+A3+A4+A5 конвейером; бриф/карта/инкрементальный
дифф — в этой же фазе; A7 выполняется в начале фазы B (после B1b —
адаптер нужен раньше артели как его клиента). П1 (макет панели) —
параллельно, вне конвейера.

- **A6. Гигиена стека — $25.** Настоящий YAML-парсер: roles.yaml
  читается кодом (ROLE_SKILLS перестаёт дублироваться руками)
  и frontmatter артефактов с типизацией; **единый парсер frontmatter
  на guard и artifacts** (один код, не два починенных);
  **`schema_version` во frontmatter + проверка совместимости
  guard'ом** — расхождение форматов писатель/читатель детектится
  на своём шаге. Промпт роли через stdin/файл вместо argv; guard
  вызывается оркестратором в `advance`; проверка статуса CI кодом
  в merge_gate (+инвариант-тест); литерал "main" в merge →
  `config.MAIN_BRANCH`; строка триггера демонизации
  в docs/triggers.md (№2).
- **A1. Мультитаргет в конфиге/БД/CLI — $25.** targets.yaml с записью
  artel; структура `.artel/projects/` (ADR-0003 3д); колонка target
  в единой БД, персистентный счётчик нумерации per-target (ADR-0003
  3ж); `PRAGMA journal_mode=WAL`; консолидация SQL в store.py; пороги
  суммарного расхода программы 70%/90% от стоп-лосса (§5) → алерт;
  отдельный контролируемый HOME/CLAUDE_CONFIG_DIR ролей (ADR-0003
  п.14).
- **A2. Инварианты мультитаргета + изоляция workspace (тесты) — $25.**
- **A2b. Git-первичка артефактов — $15.** `git init
  projects/<target>/` (workspace/, logs/ — .gitignore), коммит
  оркестратором на каждом переходе FSM, sha в журнал; **approve
  с привязкой к sha**; сверка на гейтах И при старте каждого шага
  (ADR-0003 пп.15, 17); doctor-проверка «remote пуст».
- **A3. doctor — $25.** Pre-flight окружения перед каждым шагом (cli
  auth, токены, git/worktree, диск); recovery-сверка журнал ↔ файлы
  (git fsck + sha головы) при старте; restore-режим после
  восстановления из бэкапа; **таблица alerts** (kind:
  incident|threshold|trigger; trigger — отдельная секция, ack
  с решением — docs/triggers.md); пин версии CLI + смоук-тест
  изоляции обоих векторов (project И user: подложные маркеры
  не достигают роли — ADR-0003 п.14); сверка базовой ветки
  и merge-политики целевого с targets.yaml; давность бэкапа .artel/
  (>7 дней → алерт); **проверка сирот**: каталоги
  `projects/<target>/tasks/` без строки БД, локальные ветки task/*
  у задач в done/killed, worktree без задач — алерт kind=incident.
- **A4. Роль test_author — приёмка до кода — $25.** Состояние
  `tests_writing` между spec_gate и in_dev: приёмочные тесты
  в `tasks/<id>/acceptance_tests/` только из критериев SPEC (AC-n);
  **лок** merge-путём, спор разработчика с тестом = эскалация; правка
  залоченного теста = правка SPEC = только Оператор; критерий
  пересмотра лока: в среднем >1 эскалации на задачу по первым 5 →
  механика меняется на «правка теста через ревью». Трассируемость:
  критерий без теста и без пометки manual/skip = невалидный артефакт
  (guard); сводка кейсов — из collect-only, второй документ
  не заводится; manual-критерии — в карточку гейта acceptance; скип
  стадии — явным полем SPEC; неисполнимость критериев = эскалация.
- **A5. Роль analyst — SPEC внутри конвейера — $15.** Состояние
  spec_writing исполняет analyst: вход — ТЗ Оператора свободным
  текстом (сохраняется артефактом) + срез карты; выход — SPEC
  по шаблону (AC-n, класс бюджета, no_paths, поле skip) + один батч
  вопросов с вариантами и дефолтами. spec_gate без изменений —
  Оператор редактор, не автор. Шаблон SPEC с AC-n — общий объём с A4.
- **Бриф разработчика — $25** (оркестратор собирает вход роли одним
  документом: SPEC + срез карты + конвенции; хэши компонентов брифа —
  в журнал) + **codebase-map пульта автогеном — $15** (генератор в CI
  после мержей, провал = алерт) + **инкрементальный дифф ревью —
  $25** (поздние итерации получают дифф от прошлой, полный —
  по запросу): выполняются в фазе A — главный вклад в метрику
  «трение» до того, как она обязана быть хорошей.

**Критерий выхода A:** догфуд-задача полного цикла проходит через
новый контур (targets.yaml, target в БД, hash-фиксация на гейтах,
doctor перед шагами, залоченные тесты test_author, SPEC от analyst
по свободному ТЗ) без ручных обходов. После первых 5 задач фазы A —
пересчёт экономики (§5) и перефиксация бейзлайна канарейки К3 (§3).

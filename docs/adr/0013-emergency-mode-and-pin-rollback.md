# ADR-0013: аварийный режим самохостинга — сломанная запущенная версия, откат пина, легализация hotfix

Статус: принят. Дата: 03.09.2026. Решение Оператора.

## Контекст

Конвейер чинит и переделывает собственный код. После мержа A7
(01M1H224X5A8W159MKF1Q24R5Y) запущенная версия получила три регрессии
нового флоу (маршрут analyst, канал ANSWER, перенос удалений
артефактов): планка из 44 тестов проверяла полный флоу без эскалации.
Новые задачи не могли стартовать analyst, ответы Оператора не
доходили. Механика самозащиты (пин запущенной версии, stage0 A7)
на этот мерж не подействовала: сам мерж A7 шёл ещё старой механикой
и сдвинул рабочую копию. Штатного порядка действий на случай
«запущенная версия сломана» не существовало — лечение шло
импровизацией (мосты записей без чекаута, SPEC Оператора).

## Решение

Три части, применяются вместе.

### 1. Профилактика: сломанный main не становится запущенной версией

Обновление пина запущенной версии (stage1 A7, команда обновления
пина) допускается ТОЛЬКО после зелёного прогона канарейки (К3 v2:
эфемерный клон вне корня, типовая задача полным циклом; ТЗ
.artel/tz/tz-canary-v2-pin-gate.md). Роадмап §3 уже задаёт К3 по
триггеру «первое обновление пина CLI» — триггер сработал 03.09
(пин CLI обновлён без прогона): первый прогон канарейки v2 —
немедленный долг, он же бейзлайн К3.

Канарейка обязана проходить полный цикл С ЭСКАЛАЦИЕЙ и ответом
(QUESTIONS → ANSWER → возврат) и с маршрутом analyst — ровно те
пути, которые планка A7 не покрыла.

### 2. Лечение: аварийный режим

Если запущенная версия не способна вести задачу (не заводит, не
запускает роли, не принимает ответы) — Оператор объявляет
аварийный режим. В нём допускаются действия мимо конвейера:

- **откат пина** на предыдущую зелёную версию одной командой
  (см. часть 3) — первое действие, до всякого разбора;
- **hotfix прямо в main** (код, не только конфиг) — только когда
  откат невозможен или недостаточен; условия: полный прогон
  `tests/` зелёный до пуша; коммит с префиксом `hotfix(аварийный
  режим):` и ссылкой на этот ADR; запись в журнал (alerts,
  kind=incident) с описанием поломки.

Аварийный режим обязан закрываться **легализацией**: в течение
следующего рабочего дня заводится задача конвейера, которая добавляет
тесты на дефект (планка) и проводит hotfix через ревью постфактум.
Без легализации аварийная правка — открытый инцидент в doctor.

Если запущенная версия сломана ЧАСТИЧНО (как 03.09 — только маршрут
analyst), аварийный режим не объявляется: hotfix идёт конвейером с
SPEC Оператора (запасной путь «SPEC пишет Оператор» существует для
этого), мосты — только записи в артефакты по журналу.

### 3. Откат пина

Команда обновления пина умеет и откат: `pin --to <sha>` возвращает
запущенную версию на указанный (по умолчанию — предыдущий зелёный)
коммит; действие журналируется с прежним и новым sha и причиной.
Откат — операторское действие, не автоматика; doctor показывает
расхождение пин ↔ main как и при обычном отставании.

## Ограничители

- Аварийный режим не отменяет инварианты 12 и 19 для ОБЫЧНЫХ мержей:
  hotfix мимо конвейера — исключение, помеченное и легализуемое, не
  новый путь в main.
- Откат пина не откатывает main: история остаётся, откатывается
  только запущенная версия.
- Триггер К3 «обновление пина CLI» дополняется: «обновление пина
  версии оркестратора» — канарейка обязательна и там, и там.

# ADR-0001: Объём и компромиссы Фазы 0

Дата: 2026-08-19. Статус: принят.

## Контекст
Полный дизайн (docs/design.md) описывает 5+ ролей, policy-движок,
верификатора со стендом. Адверсариальное ревью показало: это месяцы
обвязки для одного мейнтейнера — система рискует умереть недостроенной.

## Решение
Фаза 0 = MVP-минус: две роли-агента (разработчик, ревьювер), SPEC и
приёмка — Оператор, FSM-CLI на SQLite, гейты захардкожены manual.
Критерий выхода: 5 реальных задач прошли цикл «запрос → смерженный MR».

## Принятые даунгрейды безопасности (осознанно, решение Оператора)
1. **Один токен на все роли** (fallback `artel-token` в keychain) вместо
   отдельных PAT. Слоты раздельные с первого дня (roles.yaml) — разделение
   не потребует изменений кода. Следствие: аппрув-метка технически может
   быть самоаппрувом; до разделения токенов гейт merge — только manual.
2. **Branch protection отсутствует**: приватный репозиторий на GitHub Free
   (защита веток — только public или Pro). Enforcement = CI-джоба +
   мерж оркестратором; второй физической линии нет.

## Условия пересмотра
Выход из Фазы 0 (5 задач смержено) → обязательны: отдельные fine-grained
PAT по слотам; решение по branch protection (Pro / public / остаёмся на
CI-enforcement с фиксацией риска).

# ADR-0016: Проверки CI по классу пуша — job пропускается условием, прогон существует всегда

Статус: принят (решение Оператора 06.09.2026, «аппрув» в сессии). Дата: 06.09.2026. Инициатор —
Оператор (сессия 06.09, наблюдение «не для всех коммитов нужно
прогонять тесты», строка копилки fc8769a3). Класс по ADR-0002 —
изменение гейта (CI): решение только Оператора, защищённый путь
`.github/`. Вступает в силу с правкой `ci.yml` Оператором; условие
старта — после мержа задачи «CI до ревью» (01M1TQ0TRCZPRZX22C4084NCPB,
ADR-0015), которая меняет ту же механику ожидания CI.

## Контекст

Workflow `ci.yml` запускается на каждом пуше в `main`, `task/**` и
`artifact/**` и на pull request. Шесть job'ов; по времени значим один:

| job | Что проверяет | Где запускается сегодня | Время |
|---|---|---|---|
| `guard` | frontmatter и секции артефактов `tasks/<id>/` | все пуши (на `task/**` выходит сразу, см. комментарий в job) | < 1 мин |
| `python` | компиляция, полный набор `tests/`, сторож ссылок, `test_invariants` на минимальном Python | все пуши | ~7 мин |
| `codebase-map` | карта кодовой базы свежа | только `main` | < 1 мин |
| `canary-guid-leak` | дифф не вносит GUID канарейки в `skills/`, `templates/`, `docs/` | все пуши и PR | < 1 мин |
| `id-format-greplint` | дифф не парсит формат id вне `idgen.py` | только PR | < 1 мин |
| `protected-paths` | дифф не трогает защищённые пути (фаза 0 — предупреждение) | только PR | < 1 мин |

Прогоны за 06.09.2026 (`gh run list`, 100 последних):

| Класс пуша | Прогонов | Что в нём меняется | Может ли `python` что-то найти |
|---|---|---|---|
| `artifact/**` | 49 | только `tasks/<id>/`: автокоммит артефактов шага, ANSWER Оператора; родитель ветки — `origin/main` на момент заведения, код с тех пор не меняется (`artifact_branch.commit_files`, `checkpoint.py`: код вне `tasks/<id>/` в артефактную ветку не попадает) | нет — код тот же, что у родителя |
| `task/**` | 32 | коммиты разработчика, подтяжка main, правки после ревью | да — именно этот sha ждут `verifying`, `merge_gate`, автогейт приёмки |
| `main`, мерж пульта | часть из 19 | merge + снимок артефактной ветки + карта + RETRO, один push явным sha (`fsm_merge_gate._push_merged_main`) | формально дубль ветки задачи после подтяжки; оставляем как якорь «main зелёный» |
| `main`, документный коммит Оператора | большинство из 19 | `docs/backlog.md`, `docs/roadmap.md`, `docs/adr/` | нет — код не менялся |
| `main`, кодовый коммит Оператора | единицы | `orchestrator/*.py`, `tests/`, конфиги | да (06.09: коммит в `config.py` без регенерации карты — `codebase-map` красный, `python` зелёный) |

Итог: около 60 из 100 прогонов гоняют семиминутный `python` на дереве,
где он не может дать нового результата. Репозиторий публичный, минуты
бесплатны — цена в очереди GitHub (3–5 минут перед каждым прогоном,
`docs/adr/0015`), которую делят все ветки; с ADR-0015 каждая итерация
ревью ждёт эту очередь. Копилка 05.09: 12 из 13 протоколов ручной
приёмки — дубль CI; здесь дубль на уровне самого CI.

Ограничение со стороны пульта: `ci.verifying_status` и
`ci.branch_status` (`orchestrator/ci.py`) читают check-runs sha
головы кодовой ветки; «ни одной проверки» — исход «проверок нет вовсе»
(`verifying`) и «статус неизвестен, мержить нельзя» (`merge_gate`,
инвариант 19). Значит, пуш, для которого прогона НЕТ, вешает задачу
до потолка ожидания (60 минут в `merge_gate`). При этом `ci.GREEN =
{"success", "skipped", "neutral"}`: job, пропущенный условием,
существует как check-run со статусом `skipped` и считается зелёным.
Отсюда форма решения.

## Решение

1. **Триггеры не сужаются.** `on.push.branches` остаётся `main`,
   `task/**`, `artifact/**`; фильтры `paths` / `paths-ignore` на уровне
   workflow запрещены: каждый пуш в эти ветки обязан давать прогон,
   иначе ожидание CI в пульте не завершается. Это новый инвариант
   (п. 5).
2. **Пропуск — условием на job, не на workflow.** Job, которому на
   данном классе пуша нечего проверять, объявляет `if:` и остаётся в
   прогоне со статусом `skipped`. Ни одна проверка не снимается с
   класса пуша, где она способна что-то найти. Матрица:

   | job | `task/**` | `artifact/**` | `main`, код | `main`, только документы | PR |
   |---|---|---|---|---|---|
   | `guard` | как сегодня (ранний выход) | **идёт** | идёт | идёт (снимок `tasks/` живёт в main) | идёт |
   | `python` | **идёт** | пропуск | **идёт** | пропуск | идёт |
   | `codebase-map` | — | — | идёт | идёт (свойство дерева, а не коммита: стухшая карта остаётся видимой) | — |
   | `canary-guid-leak` | идёт | пропуск (`skills/`, `templates/`, `docs/` там не меняются) | идёт | идёт | идёт |
   | `id-format-greplint`, `protected-paths` | — | — | — | — | как сегодня |

   На `task/**` условий не добавляется вовсе: это единственный класс,
   чей sha ждёт пульт на трёх переходах.
3. **Класс пуша определяется в самом прогоне, fail-closed.**
   `artifact/**` — по имени ссылки (`startsWith(github.ref,
   'refs/heads/artifact/')`), без диффа. «Документный коммит main» —
   отдельный служебный job `changes` на `main`: список файлов
   `git diff --name-only <github.event.before>...HEAD`; документный =
   все пути под `docs/**` или `tasks/**` либо `*.md` в корне. Любая
   неопределённость — нет базы (нулевой `before`, принудительный пуш,
   база не в чекауте), ошибка диффа, событие `pull_request` —
   трактуется как «код менялся»: `python` идёт. `.github/**`,
   `requirements.lock`, `scripts/**`, `*.yaml`, `*.py` — код. Тот же
   приём базы, что у `canary-guid-leak`.
4. **Пульт не меняется.** `ci.GREEN` уже содержит `skipped`; полнота
   ответа по `total_count` (инвариант 19) сохраняется — пропущенный
   job входит в перечень check-runs. Ни `orchestrator/ci.py`, ни
   FSM правок не требуют; это проверяется на первом же
   `artifact/**`-пуше живой задачи после правки: `status` задачи в
   `verifying`/`merge_gate` не должен показать «проверок нет вовсе».
5. **Новый инвариант** (`docs/invariants.md`, кодируется тестом в
   `tests/test_invariants.py`): в `.github/workflows/ci.yml` секция
   `on.push` не содержит ключей `paths` и `paths-ignore`; job `python`
   не несёт условия, исключающего `refs/heads/task/`; job `guard` не
   несёт условия, исключающего `refs/heads/artifact/`. Тест читает
   YAML файла и проверяет структуру, не текст.
6. **Наследование итога родителя** (дополнение 11.09.2026,
   01M28NWK5X10J139Z8TD69HFAC; копилка 11.09 «Main красный, а CI main
   зелёный»). П.3 в исходной редакции присваивал документному пушу
   `main` `code=false` безусловно — это маскировало красный CI
   родительского коммита: операторский коммит, уронивший тест, и два
   следующих документных коммита поверх него все получали зелёную
   плашку, хотя код с тех пор не прошёл проверку ни разу. Job `changes`
   (логика вынесена в `scripts/ci_push_class.py`) для документного пуша
   в `main` присваивает `code=false` только если последний завершённый
   прогон workflow `ci` для коммита `before` на ветке main
   (`gh api repos/{owner}/{repo}/actions/runs?head_sha=<before>&branch=main`)
   закончился `conclusion == success`. Отсутствие прогона для `before`,
   `conclusion != success` или ошибка запроса к API — `code=true`, тот
   же fail-closed, что и остальная классификация п.3: документный
   коммит поверх красного или неизвестного main всегда получает
   собственный прогон `python`, а не наследует чужую зелёную плашку.

## Последствия

- Плюс: около 60 % семиминутных прогонов исчезают из очереди GitHub;
  короче ожидание в `verifying` и `merge_gate` для веток задач, что
  прямо снижает цену ADR-0015 («каждая итерация ревью ждёт CI»).
- Плюс: `artifact/**` получает ровно ту проверку, ради которой
  создавался триггер (SPEC T094, требование 7) — `guard`.
- Минус: два условия и один служебный job в `ci.yml`; ошибка в
  определении класса пуша страхуется правилом fail-closed (сомнение —
  прогон идёт), а не молчаливым пропуском.
- Минус: документный коммит Оператора в `main` больше не
  «перепроверяет» код main. Это не потеря: дерево кода в таком коммите
  совпадает с родительским, чей прогон уже есть; `codebase-map` на
  документных коммитах остаётся и продолжает показывать стухшую карту.
- Ослабления по ADR-0002 нет: на каждом классе пуша сохранена каждая
  проверка, способная на нём что-то найти; рубежи пульта (`verifying`,
  `merge_gate`, автогейт приёмки) читают тот же sha той же ветки, что
  и сегодня.
- Ограничение раскатки (живая проверка 06.09, прогон 34044318851,
  задача 01M1TKP269): GitHub исполняет workflow из дерева пушнутой
  ветки, а артефактная ветка несёт `.github/` с момента заведения
  задачи (родитель — `origin/main` на тот момент,
  `artifact_branch._new_branch_parent`). На `artifact/**` решение
  действует только для задач, заведённых после коммита раскатки
  5875c47f; артефактные ветки живых на тот момент задач гоняют
  старый `ci.yml` до своего закрытия. Править их снаружи нельзя
  (внешний push в артефактную ветку живой задачи ломает автокоммит
  роли, инцидент 06.09) — раскатка на этом классе постепенная.
  На `main` и `task/**` действует с первого пуша после раскатки
  (`task/**` получает новый `ci.yml` подтяжкой main).
- Смежный дубль, вне объёма этого ADR: автогейт приёмки гоняет полный
  набор `tests/` локально в worktree (`acceptance.run_full_suite`,
  ADR-0007 п. 3в) на том же sha, для которого `verifying` уже получил
  зелёный CI (ADR-0009). Снятие или сохранение локального прогона —
  отдельное решение по ADR-0007; здесь не трогается.

## Раскатка

1. `ci.yml` — правка Оператора (защищённый путь, ADR-0001/0002):
   условие на `python` и `canary-guid-leak` для `artifact/**`, job
   `changes` и условие на `python` для документных пушей `main`.
2. Инвариант п. 5 — строка в `docs/invariants.md` и тест в
   `tests/test_invariants.py`: тем же коммитом Оператора либо задачей
   конвейера с зонами `tests/test_invariants.py`, `docs/invariants.md`.
3. Проверка на живой задаче (п. 4): первый `artifact/**`-пуш и первый
   документный коммит `main` после правки — прогон существует, `python`
   в статусе `skipped`, `status` задач в `verifying`/`merge_gate` без
   «проверок нет вовсе». Результат — строкой в копилке.
4. Строка копилки fc8769a3 снимается после п. 3.

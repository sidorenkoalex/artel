# ADR-0026: Компоненты проекта, отчёт тестов пульта и гейты по исходам

Статус: принят Оператором 19.10.2026 (редакция 3 — по итогам двух пар независимых ревью 19.10: исполнимость против кода пульта; замысел — неослабление и обходы). Решения Оператора: вопросы 1–10 — по рекомендациям, вопрос 11 — вариант A; бюджет волны ~$315–405. Не исполнен. Основание — решения Оператора 18–19.10: подключить монорепозиторий sled целиком (backend и frontend); среда — вариант A (инструменты на машине пульта, Node 22 через nvm ставит Оператор; тесты с PostgreSQL и docker, сквозные тесты и сборку проверяет CI sled). Схема рассчитана на проект из нескольких репозиториев (раздел «Расширяемость»), исполняется монорепозиторий. Дополняет ADR-0021 (профиль тестов проекта), ADR-0022 (матрица неослабления), ADR-0023 (вторая поправка 16.10).

## Решение

1. **Компоненты проекта.** Запись проекта несёт `components:`; прежнее `test_profile` читается как один компонент (запись артели и прежние записи не меняются). Поля: `name`; `repo` (по умолчанию — репозиторий записи); `workdir`; `command`; `report` — формат итога: `pult-pytest` (артель, как сейчас), `junit-xml` (pytest-подобные раннеры, у которых провал и ошибка различимы), `pult-vitest` (свой отчётчик пульта, п. 4); `report_args`; `select`; `env`; `full_suite_timeout_sec`; `tools`; `install`; `paths`; `depends_on` (`via: paths | files | contract`); `tests`; `test_support`; `long_lived` (с каталогом); `plank_layout`; `knowledge`; `layers`; `checks_local`. Все шаблоны — от корня своего репозитория.
2. **Выбор компонентов.** Задача затрагивает компоненты, чьи `paths` или `test_support` задевают зоны задачи, и их потребителей по `depends_on`; гейты — то же по диффу ветки. Дифф, не задевший ни одного компонента (`docs/`, `.claude/`, корневые файлы), запускает **все** компоненты, а не даёт зелёный итог. Гейты читают только `depends_on`, не зная его вида.
3. **Идентификаторы.** Зоны задачи и `no_paths` — пути от корня репозитория; в монорепозитории формат зон прежний, префикс `<repo>:` появляется только у проекта с несколькими репозиториями. Через компонент — только идентификаторы тестов и элементы мандатов: `<компонент>:<путь файла от корня репозитория>::<полное имя>[#<порядковый номер при повторе>]`; повтор имени внутри файла — находка гейта планки. `#1` — у первого вхождения имени, которое само кончается на `#<цифры>`; повтором считается номер от 2 (поправка 25.10.2026). У артели формы прежние.
4. **Итог тестов у компонентов с `report` ≠ `pult-pytest` — только из отчёта.**
   - `pult-vitest` — отчётчик пульта: файл вне репозитория проекта, подключается `--reporter=<путь пульта>`; по каждому тесту — идентификатор, состояние, имя ошибки, признак таймаута, падение хука (какого), `mode` (`skip`/`todo`/`only`), флаг `fails`, число повторов. Список имён ошибок, засчитываемых как провал проверки, — в записи компонента (`failure_errors`); для Vitest — `AssertionError` (включая `expect`), `TestingLibraryElementError`, `JestExtendError` и `HtmlElementTypeError` (вопрос 10, пересмотр 22.10.2026 по пробе 2.2); отчётчик передаёт настоящий класс ошибки, а не обобщённое `Error`; `TypeError`, `ReferenceError`, таймаут и падение хука — не провал проверки.
   - Окружение Vitest фиксирует пульт: `CI=true`; `node_modules/.bin/vitest run --config vitest.config.js --allowOnly=false --update=false --retry=0`; `--expect.requireAssertions` (подтверждается пробой); кэш результатов выключен (`--no-cache`, поправка 25.10.2026: в Vitest 4 нет `--cacheDir`); каталог кэша Vite — только из `vitest.config.js` проекта.
   - Код возврата без разборчивого отчёта — «неизвестно», не зелёный (новый инвариант 41, п. 12). Ключ кэша итога — по компоненту: дерево, `tools`, файлы блокировки, команда.
   - Сторож зависших тестов, сводки прогонов и итоговая строка узнают команды компонентов.
   - **У артели (`pult-pytest`) разбор итога, тексты и исходы прежние** — закрепляются перечнем текстов в тестах до правки.
5. **Приёмка — честный `FAIL_TO_PASS`.**
   - Планка — на фреймворке компонента; каталог планки принимает файлы по шаблону `tests`; критерий — метка строго `^AC-<n>: ` (у pytest — `test_ac<n>_`), одна метка на тест; в тексте планки запрещены `.fails`, `.skipIf`, `.runIf`, `.only`, `vi.setConfig`, `retry` и `timeout` в параметрах теста.
   - На базе прогоняются файлы планки из ветки (выкладка `plank_layout`; импорты — относительно выкладки, это в задании test_author). Каждый тест `AC-<n>` обязан быть в отчёте и упасть **на проверке** (имя ошибки из утверждённого списка). Ошибка уровня файла (импорт нового модуля) засчитывается как красный только если зоны задачи объявляют этот модуль новым и все тесты `AC-<n>` файла на ветке присутствуют и зелёные; показывается отдельной строкой. Пропуск, `todo`, отсутствие теста, таймаут, падение хука — отказ гейта планки.
   - На ветке каждый тест `AC-<n>` — зелёный, без повторов.
   - Текстовые требования («Ловит мутацию:» в комментарии над тестом, «Группа:», маркер `AC-n:`) — по тексту; осмысленность — ревьювер.
6. **Гейт неослабления по исходам** — у компонентов с `report` ≠ `pult-pytest`; на переходе `in_dev → review` и на гейте мержа:
   - `PASS_TO_PASS`: тесты, зелёные на базе, зелёные на ветке; повторов внутри прогона нет (`--retry=0`); красный на ветке прогоняется ещё дважды и на ветке, и на базе — красный хотя бы раз при трижды зелёной базе — находка «нестабилен после правки», решает Оператор;
   - прежние версии изменённых или удалённых файлов `tests` и `test_support` (из базы, единым набором) против кода ветки — зелёные, кроме **заменяемых тестов** (п. 7);
   - сравнение отчётов базы и ветки: исчезнувший идентификатор, «прошёл → пропущен», `todo`, `fails`, рост числа пропусков — находка;
   - **строгий режим** (компонент без языкового слоя): любая правка существующего файла `tests` или `test_support` — находка, нужен мандат;
   - **исключения в коде**: в диффе нетестовых файлов компонента строки `v8 ignore`, `istanbul ignore`, `c8 ignore`, `eslint-disable`, ветвление по `import.meta.env.MODE`, `process.env.VITEST`, `NODE_ENV` — находка, нужен мандат;
   - элемент мандата — идентификатор теста компонента или путь файла (п. 3);
   - слой `python-ast` (нынешние `scripts/guard.py`, `test_integrity.py`) у Python-компонентов работает как сейчас, поверх проверки по исходам;
   - двусторонний прогон: «упал на проверке» — по имени ошибки из отчёта (п. 4), не плагином pytest;
   - `doctor`: файлы, достижимые по импортам из тестов, но не из точки входа приложения и не попавшие под `test_support`, — предупреждение «файл поддержки вне шаблона».
7. **Заменяемые тесты** — законная смена поведения без мандата на каждый тест.
   - Перечень пишет аналитик в SPEC: идентификатор прежнего теста → критерий `AC-<n>`, который его заменяет, и причина (смена поведения по ТЗ); строки — в матрице неослабления (ADR-0022). Оператор утверждает перечень на гейте SPEC — утверждённая замена служит мандатом на правку этих тестов.
   - Гейт планки сверяет: каждый заменяемый тест сопоставлен тесту `AC-<n>` планки.
   - Гейт неослабления сверяет на деле: прежняя версия заменяемого теста на коде ветки обязана быть **красной** (иначе замена не нужна — находка); не заявленный тест, покрасневший на ветке, — находка.
8. **Установка зависимостей — пульт, не роль.** `npm ci --ignore-scripts` один раз на версию `package-lock.json`; разрешённые пересборки (`npm rebuild <пакет>` после `npm ci` с проверкой целостности) — список в `install`, ведёт Оператор. `node_modules` и кэш npm принадлежат пульту и подключаются к рабочей копии роли и прогонам гейтов только для чтения. Новая зависимость — эскалация (закрыт `package.json`).
9. **Закрытые пути frontend** (`no_paths` sled; вопросы 4, 6): уже закрытые `frontend/package.json`, `frontend/package-lock.json`, `frontend/vitest.config.js` и добавляемые `frontend/vitest.config.*`, `frontend/vitest.workspace.*`, `frontend/vite.config.*`, `frontend/playwright.config.*`, `frontend/eslint.config.js`, `frontend/jsconfig.json`, `frontend/.env*`, `frontend/src/test-setup.js`, `frontend/.nvmrc`, `**/.npmrc`.
10. **Локальные проверки** (`checks_local`, вопрос 5): `npm run lint`. Пороги покрытия, сборка и сквозные тесты — CI sled (вопрос 11, вариант A): задача, переносящая или удаляющая файл с порогом покрытия в закрытом `vitest.config.js`, эскалирует, строку порога правит Оператор.
11. **Бриф без привязки к языку.** Документы `knowledge` компонента идут в бриф; задание test_author и скилы — по фреймворку компонента; карта кода Python — слой Python-компонента.
12. **Новый инвариант 41** «неизвестный или неразобранный местный итог тестов не зелёный; повторы внутри прогона компонентов с отчётом пульта запрещены»: строка в `docs/invariants.md` и проверка в `tests/test_invariants.py` — защищённые пути, коммит Оператора приложением к PLAN G1б.
13. **Задачи frontend на sled — только после слияния G3б**: до него гейт неослабления frontend неполон.

## Расширяемость на несколько репозиториев

Единица пульта — компонент; репозиторий — его свойство. Компоненты, отчёт, приёмка, гейт неослабления, мандаты и бриф одинаковы при любом числе репозиториев. От числа репозиториев зависят:

| | Монорепозиторий (исполняется) | Несколько репозиториев (позже) |
|---|---|---|
| Ветки задачи | одна ветка, один мерж | ветка в каждом затронутом репозитории; эпик с подзадачами и `merge_after` |
| Зоны, `no_paths`, `knowledge` | пути от корня репозитория | `<repo>:<путь>` |
| Связь компонентов | `depends_on` вида `paths`, `files` | `contract`; `files` — рабочая копия соседа |
| Атомарность | один коммит | гейт совместимости: ветка поставщика против `main` всех потребителей и наоборот |
| Рабочая копия роли | одна | по репозиторию; соседние — только чтение |

## Инварианты и что не ослабляется

- Новый инвариант 41 (п. 12); инвариант 19 (CI перед мержем) — без изменений.
- Артель: разбор итога, тексты и исходы гейтов прежние — закреплены перечнем текстов в тестах до правки; новые проверки — только у компонентов с `report` ≠ `pult-pytest`.
- Python-компоненты: слой `python-ast` сохраняет все нынешние проверки; проверка по исходам — сверху.
- Мандат, матрица неослабления и независимая проверка (ADR-0022) — прежние; утверждённая замена теста (п. 7) — вид мандата.
- `no_paths`, `merge_gate`, список ошибок «провал проверки», список пересборок, заменяемые тесты — решения Оператора.

## Цена

- Лишние прогоны: тесты базы и прежние версии на коде ветки; трёхкратный прогон красных.
- Строгий режим frontend — больше мандатов на правки существующих тестов и помощников.
- Отчётчик пульта для Vitest — свой код, зависящий от API отчётчиков Vitest 4.

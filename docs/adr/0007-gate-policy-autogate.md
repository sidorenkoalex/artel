# ADR-0007: Политика гейтов — автогейт по условиям, начиная с acceptance

Дата: 2026-08-28. Статус: принят (решение Оператора).

## Контекст
Статистика 65 прохождений ручных гейтов: reject — 0 за всю историю;
медиана ожидания решения 1–3 минуты; содержательные находки Оператора
концентрируются на spec_gate (правки SPEC на гейте — T053, T065,
амнистии тестов), тогда как acceptance и merge_gate за всю историю не
дали ни одной находки сверх уже пойманного тестами и CI — роль
Оператора там свелась к «подтвердить зелёное». При N=5 частота таких
подтверждений становится главным потребителем внимания Оператора.
Архитектура предвидела конфигурируемость гейтов: gates.yaml (решение
аудита v5, вариант (б)) и строка «профиль эскалаций → автогейт до C2»
(аудит состояния 27.08).

## Решение
1. Инвариант 7 переформулируется: ручной гейт проходит approve/reject
   Оператора ЛИБО автогейт по политике gates.yaml — при выполнении
   ВСЕХ условий политики для данного гейта. Инвариант 18 сохраняет
   смысл «auto не принимает решений»: автогейт — не решение auto-цикла,
   а исполнение заранее объявленной Оператором политики; путь автогейта
   кодируется отдельно и логируется отличимо (журнал: actor=autogate).
2. Политика — per-гейт в gates.yaml; дефолт каждого гейта — manual.
   Смена политики — правка gates.yaml, права на неё только у Оператора
   (файл в PROTECTED). Kill-switch: возврат manual одной правкой.
3. Первый (и пока единственный) автоматизируемый гейт — **acceptance**.
   Условия автопрохода (все обязательны, иначе гейт остаётся ручным
   и ждёт Оператора как раньше):
   а) приёмочные тесты задачи существуют, среди них 0 manual-критериев
      и 0 skip;
   б) полный прогон приёмочных задачи зелёный;
   в) полный набор tests/ зелёный (тем же прогоном, в worktree ветки);
   г) бюджет задачи не превышен ~~и программные пороги A1 не пробиты~~ (условие порогов A1 удалено ADR-0010, исполнено T085 01.09 — пороги стали отчётными вехами)
      этим шагом;
   д) вердикт ревью — approved текущей итерации (уже гарантируется
      переходом review -> acceptance, условие фиксируется явно).
4. merge_gate остаётся ручным до внедрения детекторов деградации
   (фаза B: посев мутаций, детектор ослабления тестов) — без них
   автономный путь в main не имеет второй пары глаз на ослабление
   планки. Решение о его автогейте — отдельным пересмотром этого ADR.
5. spec_gate остаётся ручным без горизонта автоматизации: единственный
   гейт, где человек проверяет «то ли делаем»; статистика находок
   подтверждает его ценность.

## Раскатка
- gates.yaml: секция политики гейтов (acceptance: auto | manual,
  дефолт auto после мержа задачи-исполнителя; остальные: manual).
- Задача конвейеру: автогейт acceptance по условиям п.3 (T066).
- docs/invariants.md, строка 7 — новая формулировка (вносит Оператор
  при мерже задачи-исполнителя).
- Каждый автопроход: запись в журнале actor=autogate с перечнем
  выполненных условий; status/show отличают автопройденный гейт.

## Последствия
Оператор перестаёт быть узким местом на механическом гейте; внимание
концентрируется на spec_gate и эскалациях. Цена: путь «зелёное, но
неправильное» (тесты прошли, а поведение вне тестов деградировало)
теперь ловится только ревью и будущими детекторами — принятый риск,
смягчение: kill-switch + журнальная отличимость + merge_gate остаётся
ручным (последняя дверь в main под человеком).

# ADR-0015: CI кодовой ветки до ревью, а не после

Статус: принят. Дата: 06.09.2026 (approve SPEC задачи 01M1TQ0TRCZPRZX22C4084NCPB). Инициатор — Оператор (сессия
06.09, команда «заводи все» по анализу причин). Вступает в силу с
мержем задачи, реализующей таблицу переходов; решение подтверждается
на гейте SPEC этой задачи.

## Контекст

Порядок состояний сегодня: `in_dev -> review -> verifying ->
acceptance -> merge_gate`. Ревьювер видит код до прогона общего набора
`tests/` на CI: сквозные инварианты (SQL только в `store.py`,
стандартная библиотека, сеть в тестах и т.п.) живут в `tests/`, а
планка задачи их не покрывает по построению. Итог по журналу 05–06.09:

| Факт | Значение |
|---|---|
| эскалаций «приёмочные тесты красные после подтяжки main» | 18 у 10 задач |
| ревью, одобривших код, который затем упал в `verifying` | наблюдатель 01M1RFVWV6: approved итерации 2, красный инвариант в `verifying`, возврат, итерация 3 за $5.55 |
| подтяжка main | делается при входе в `review`; голова после подтяжки ещё не проверена CI, ревьювер читает дифф, в котором чужие коммиты main |

Ревью стоит $1.5–5.5 за итерацию, лимит три итерации на задачу. Каждая
итерация по коду, который не прошёл CI, сгорает впустую и приближает
эскалацию «лимит ревью исчерпан» (3 за двое суток).

## Решение

1. Порядок состояний: `in_dev -> verifying -> review -> acceptance ->
   merge_gate`. `verifying` ждёт зелёный CI головы кодовой ветки,
   как сегодня; `review` начинается только с зелёного CI.
2. Подтяжка main (`fsm._pull_main_or_escalate`), прогон планки после
   подтяжки, гейт зон, гейт ёмкости и лок планки исполняются на
   переходе `in_dev -> verifying` (там, где сегодня стоят на
   `in_dev -> review`). Голова, которую проверяет CI, — уже
   подтянутая.
3. Возврат из ревью (`changes_requested`) ведёт в `in_dev`, оттуда
   снова через `verifying`: каждая итерация ревью читает код с
   зелёным CI.
4. Ревью-пакет несёт строку статуса CI (sha головы, число проверок,
   ссылка на прогон) — ревьювер не гадает, проверен ли код.
5. `merge_gate` по-прежнему подтягивает main и ждёт CI перед мержем
   (ADR-0013, флоу A7) — это второй, финальный рубеж; первый рубеж
   переносится перед ревью.

## Последствия

- Плюс: итерации ревью не тратятся на код с красными инвариантами;
  ревьювер видит дифф от подтянутой головы; эскалации «планка красная
  после подтяжки main» уходят с ручного гейта в штатный `verifying`.
- Минус: каждая итерация ревью ждёт CI (очередь GitHub 3–5 минут,
  прогон 1–2 минуты). Цена в минутах, не в деньгах ролей.
- Инварианты: `docs/invariants.md` — записи про порядок гейтов
  обновляются задачей; ослабления нет, все рубежи сохранены, один из
  них передвинут раньше.
- Тесты FSM с явным порядком состояний правятся в задаче; планки
  закрытых задач не гоняются (принцип «история не переписывается»).

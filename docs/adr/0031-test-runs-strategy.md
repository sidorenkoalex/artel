# ADR-0031: Стратегия прогонов тестов — один полный прогон на дерево кода

Статус: принят 07.11.2026, не исполнен. Решение Оператора 07.11.2026 («и на это ок» — к порядку задач разбора прогонов тестов). Класс по ADR-0002 — изменение гейтов: решение только Оператора. Дополняет ADR-0015 (CI до ревью), ADR-0016 (проверки CI по классу пуша), ADR-0026 (компоненты проекта и гейты по исходам), ADR-0029 (проект с гейтом мержа людьми проекта); пересматривает требование свежести ветки на приёмке из SPEC 01M4BEGQAVVWCHFCW6BEBB0XVT. Пятая поправка ADR-0023 (прогоны по запросу роли) — часть этой стратегии, принята отдельно.

## Контекст

Наблюдение за 30 дней по журналу пульта (до 07.11.2026):

- Приёмка артели: локальный полный набор — 157 раз, итог CI принят — 97 раз. Причины локального прогона: «ветка не свежа относительно `origin/main`» — 94; «дерево гейта отличается от дерева головного коммита» — 28 задач, из них у 26 есть приложения PLAN; прочие (CI не ответил, проект не опознан, свежий прогон по флагу) — около 35.
- Условие свежести проверяется после условия «дерево приёмки равно дереву головы»: при несвежей ветке локальный прогон гоняет то же дерево, которое уже проверил CI, слияние с новой базой он не проверяет. Отставание чаще всего — документные коммиты `main` (журнал подтяжек: «свежесть: N документных коммитов main без подтяжки»).
- Локальный полный набор артели — 13–16 мин на машине пульта, занятой ролями; красные локальные итоги в просмотренных записях — превышение предела 1500 с под нагрузкой, занятый замок, гонки временных каталогов, окружение машины; дефекта задачи, пропущенного CI, среди них нет.
- CI `main` после мержа: зелёный — 126, «не дождался за 18 мин» — 65 (прогон CI идёт 20–27 мин), красный — 7 (по логам — тесты со случайным зерном и тесты, зависящие от GitHub). Всё ожидание держит замок мержа.
- У артели нет проверки «тесты задачи красные до кода»: запись артели — `test_profile`, а не компонент с `report`; гейт исходов по каждому тесту у неё тоже не действует.

## Решение

1. **Итог полного набора принадлежит дереву кода, а не шагу конвейера.** Дерево кода — голова ветки плюс приложения PLAN, без документов задачи. Если для дерева есть доказанный итог (CI головы, наложивший те же приложения, либо сохранённый итог локального прогона того же дерева), ни приёмка, ни мерж это дерево повторно не прогоняют.
2. **Один источник полного набора на проект** — поле `full_suite` компонента: `ci` по умолчанию для проектов с CI (артель — тоже), `local` — для проектов без CI, `both` — только по явному решению Оператора.
3. **Свежесть относительно базы — в одном месте.** Для проектов, где мержит пульт (`merge_gate: operator`), — подтяжка и CI новой головы на `merge_gate` под замком мержа (как сейчас). Для проектов с гейтом людей проекта (`target-human`) — подтяжка на `in_dev → verifying` (`policy.freshness`, ADR-0029) и правила MR проекта; поведение приёмки у них не меняется. Приёмка свежесть не проверяет там, где её держит `merge_gate`.
4. **Уровни прогона — от дешёвого к дорогому, каждый ловит своё:** шаг роли — тесты задачи и затронутых модулей (секунды); `in_dev → verifying` — планка (минута); CI — полный набор один раз на дерево; приёмка и мерж — чтение итогов; после мержа — CI `main` без ожидания под замком.
5. **Гейт сравнивает исходы по каждому тесту, а не цвет задания** — по отчёту junit базы и головы (ADR-0026). Артель переходит на запись компонента с `report` и `full_suite: ci`; вместе с этим у неё включаются гейт исходов и «красные до кода».
6. **Цвет `main` после мержа сверяет следующий мерж.** Мерж не держит замок ради исхода CI `main`; следующий мерж, если CI `main` ещё идёт, ждёт его исхода сам (сегодня идущий CI сверку проходит — `_refuse_if_main_red`), красный — прежний отказ.

## Последствия

- Локальных полных прогонов на приёмке артели — порядок 15–30 в месяц вместо 157; освобождается порядка 25–30 часов машины в месяц; каждый мерж держит замок примерно на 18 мин меньше.
- Ложные отказы приёмки из-за нагрузки машины уходят вместе с лишними локальными прогонами.
- После этапа 4б CI артели — единственный источник полного набора, как у внешних проектов: код гейтов один, различаются поля записи.

# ADR-0018: Артефакты смерженной задачи — по ссылке, приёмочные тесты после мержа не исполняются

Статус: принят. Дата: 27.09.2026. Решение Оператора. Подтверждает
ADR-0005, пункт 7 (решение 31.08.2026), и дополняет ADR-0012: тот
описывает правку приёмочных тестов задачи В РАБОТЕ, этот — их судьбу
ПОСЛЕ мержа.

## Контекст

Приёмочные тесты задачи пишутся до кода, фиксируются и принимают задачу
на автогейте. После мержа их не исполняет никто: CI гоняет набор
`tests/`, автогейт — приёмочные тесты текущей задачи.

Артефакты задачи лежат в трёх местах: ветка `artifact/<id>` (задача в
работе), ссылка `refs/artifacts/<id>` (снимок при закрытии) и каталог
`tasks/<id>/` в `main` (копия снимка, накладывается при мерже). ADR-0005,
пункт 7, постановил: исторические каталоги `tasks/` убираются одним
операторским коммитом, новые в `main` не попадают. Уборка не исполнена;
наложение снимка на `main` введено позже задачей
01M1R9YEK08XEQWBFX0929WFVJ и с тем решением расходится. На 27.09 в `main`
253 каталога задач, 2646 файлов.

Прецеденты 27.09. Приёмочные тесты задачи 01M3FQ2Z2PY0E9T5F5WQ207NP5
утверждают, что у команды `canary` ровно один новый параметр; задача
01M3HJQV2QV9BXNXSH3F8STAYH добавила флаг `--template`, и 28 тестов из 43
стали красными при исправной функции. Один тест задачи
01M3GKJFN90ATK2KECNDZXPPP6 покраснел от нового вида вердикта канарейки.
Роль править чужие зафиксированные тесты не вправе.

Замер 27.09 по девяти смерженным задачам: из 164 тестов, добавленных
разработчиком в `tests/`, 102 повторяют приёмочные тесты задачи.

## Решение

1. Артефакты смерженной задачи хранятся по ссылке `refs/artifacts/<id>`.
   В `main` они не попадают (ADR-0005, пункт 7, подтверждён).
2. Приёмочные тесты смерженной задачи не исполняются пультом, CI и
   ролями и не чинятся. Их покраснение от последующего развития системы
   дефектом не является. С ADR-0020 (29.09.2026) пункт действует только
   для разовых приёмочных тестов — фактов именно этой задачи;
   долгоживущие приёмочные тесты пишутся сразу в `tests/` ветки задачи и
   после мержа исполняются как обычная часть `tests/`.
3. За целость системы после мержа отвечают набор `tests/` и инварианты
   (`docs/invariants.md`, `tests/test_invariants.py`).
4. Наложение снимка артефактной ветки на `main` при мерже отменяется
   задачей. До её мержа действует нынешний порядок.
5. Приёмочные тесты задачи В РАБОТЕ живут по ADR-0012 без изменений.
6. Приёмочные тесты смерженных задач из главной копии пульта не
   запускаются: часть наборов пишет в настоящий каталог `tasks/`
   (инцидент 27.09, строка копилки).

## Следствия

- `skills/test-authoring.md` — запрет утверждений о полном составе
  параметров публичной функции и о состоянии системы «на сегодня»;
  `skills/review-checklist.md` — проверка, что свойство, которое должно
  оставаться верным после мержа, проверено тестом `tests/`. Правки скилов
  идут задачей 01M3HWXCGHYPMA5BPV7BMBBD9X, приложением к защищённым
  путям.
- Условия уборки каталога `tasks/` из `main`, в порядке исполнения:
  ретроспектива в снимке несёт верный исход и счётчики (строки копилки
  27.09); вторая копия для каталогов, у которых нет ни снимка, ни ветки;
  сверка снимков с `origin`; правка ссылок на `tasks/<id>/` в скилах,
  `docs/invariants.md` и `docs/design-system.md`; полный прогон `tests/`
  перед коммитом уборки.
- Судьба приёмочных тестов-свойств после мержа решена ADR-0020
  (29.09.2026): долгоживущие приёмочные тесты пишутся сразу в `tests/`
  ветки задачи; перенос копированием отклонён.
- Приёмочные тесты 01M3FQ2Z2PY0E9T5F5WQ207NP5 и
  01M3GKJFN90ATK2KECNDZXPPP6 остаются как есть.

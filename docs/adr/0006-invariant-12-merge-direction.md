# ADR-0006: Инвариант 12 — запрет по направлению, не по подкоманде

Статус: принят, исполнен. Дата: 28.08.2026. Решение Оператора.

## Контекст
T051 «Сверка свежести ветки до гейта» (`docs/roadmap-history.md`,
§4 п.2а; контур параллельности) требует от оркестратора актуализировать отставшую
ветку задачи ДО выноса на гейт: влить main в ветку merge-коммитом
и прогнать приёмочные тесты, чтобы approve видел только свежий срез.
Developer T051 корректно эскалировал: инвариант 12 в прежней
формулировке («git merge выполняет только `approve` из merge_gate —
другого пути в системе нет») буквально запрещает любой `git merge`
вне merge_gate, хотя защищать он был призван main — направление
«ветка задачи → main» мимо гейтов (design §2: единственное право
записи оркестратора — merge прошедшего гейты MR). Обходные пути
(git-плумбинг вместо порцелейна; вариант (б) эскалации) отвергнуты:
обход буквы неослабляемого теста — ровно то поведение, которое
ADR-0002 запрещает ролям, и Оператору не к лицу.

Попутная находка: свип `MergeOnlyFromMergeGateTest` определял
подкоманду как `argv[1]` и потому не увидел бы merge, выполненный
через `git -C <path> merge ...` (форма `gitcmd.in_repo`), — буква
была уже, чем намерение, в обе стороны.

## Решение
Инвариант 12 сужается до своего намерения — защиты main:

1. **В main мержит только `approve` из merge_gate.** Ни одна другая
   команда ни из одного состояния не вливает ветку задачи (или что бы
   то ни было) в main. Это ядро инварианта, оно не ослаблено.
2. **Единственный разрешённый merge вне гейта — актуализация ветки
   задачи от main** (сверка свежести, T051): выполняется в worktree
   задачи (`git -C <worktree>`), вливает `main` в ветку, ветку задачи
   в аргументах не упоминает, main не изменяет ни одним байтом
   (согласуется с ADR-0005 п.9: писатель main — оркестратор в окне
   merge_gate).
3. Свип теста переписывается с `argv[1]` на нормализацию argv
   (пары `-C <path>` / `-c <kv>` пропускаются): дыра «merge через
   `-C` невидим» закрыта. Проверка вне гейта: каждый merge обязан
   быть в `-C`-форме, содержать `main` и не содержать ветку задачи.

Это сужение запрета с одновременным усилением буквы — не ослабление:
множество запрещённых действий по существу не уменьшилось (merge в
main вне гейта запрещён как был), а класс невидимых свипу merge
исчез.

## Раскатка
- `docs/invariants.md`, строка 12 — новая формулировка (+ссылка сюда).
- `tests/test_invariants.py::MergeOnlyFromMergeGateTest` — свип по
  нормализованному argv (правка Оператора по этому ADR).
- T051 возвращается в разработку и реализует SPEC буквально:
  `git -C <worktree> merge --no-ff main` + `merge --abort` при
  конфликте.

Исполнено: строка 12 `docs/invariants.md` совпадает с п.1–2;
актуализация ветки — `orchestrator/pull.py` (`_run_merge`, ссылка на
п.2 этого ADR); свип — `tests/test_invariants.py::
MergeOnlyFromMergeGateTest`.

Дополнено ADR-0013 (03.09.2026): в аварийном режиме допускается
правка прямо в `main` мимо конвейера с обязательной легализацией, а
12.09.2026 пин однократно сдвинут вручную; оба случая — помеченные
исключения, а не новый путь в `main` (ADR-0013, «Ограничители»).

## Последствия
Актуализация веток становится штатной операцией оркестратора — без
неё контур параллельности (merge queue, N=2) генерировал бы конфликт
на каждом мерже соседа. Цена: чуть более сложный свип в неослабляемом
тесте; выигрыш: свип закрывает и ранее невидимую форму `-C`.

# ADR-0002: Принцип целостности

Дата: 2026-08-20. Статус: принят (решение Оператора).

## Контекст
Система дорабатывает сама себя своим же конвейером: почти каждая задача
меняет оркестратор, guard'ы или скилы. Локальный фикс может ослабить
систему в целом (снять лимит, смягчить тест, изменить поведение вне зоны
задачи), и ни одна роль не обязана была это оценивать. «Не навреди» как
гарантия недоказуемо — принцип сформулирован как набор проверяемых
обязанностей ролей.

## Решение
Принцип целостности (четвёртый несущий принцип, docs/design.md):
задача выполнена, только если система в целом не стала хуже — ни один
инвариант не нарушен, ни один существующий гейт/тест/лимит не ослаблен,
поведение вне зоны задачи не изменилось. Производные правила:

1. Оценка влияния — артефакт: обязательная секция «Влияние на систему»
   в PLAN.md (проверяется guard).
2. Ослабление любых защит (тест, гейт, лимит, guard, инвариант) — только
   Оператором через ADR; для ролей это blocker в ревью.
3. Изменение обратимо; необратимое требует ручного гейта независимо
   от политики.
4. Неуверенность в безопасности изменения = эскалация, не попытка.

## Раскатка
- design.md: принцип 4 в несущих принципах.
- CLAUDE.md: правило для всех ролей.
- templates/PLAN.md + scripts/guard.py: секция «Влияние на систему»
  обязательна (старые PLAN дополнены ретроспективной пометкой).
- skills/review-checklist.md: пункт 6 «Системная целостность».
- skills/conventions-core.md: запрет ослабления защит без ADR.
- Отдельной задачей конвейера: «инварианты как тесты» — системные
  инварианты кодируются неослабляемыми тестами.

## Последствия
Ревью получает формальное основание заворачивать «тихие» ослабления
защит; разработчик обязан думать о blast radius до кода; стоимость —
чуть больше текста в PLAN и чуть дольше ревью.

# ADR-0008: Инвариант 16 — история переживает задачу, не эпоху

Дата: 2026-08-31. Статус: принят (решение Оператора).

## Контекст
T073 «Retention-политика и команда prune» (роадмап P3) ввела
политику хранения `.artel/logs/` (90 дней И N последних задач,
docs/retention.md) и команду `prune` (dry-run по умолчанию),
которая логи удаляет. Прежняя формулировка инварианта 16 («История
наблюдаемости переживает задачу: `.artel/logs/` уборка не трогает»)
о prune молчит и при буквальном чтении звучит как «логи не
удаляются никогда» — действующая команда системы оказалась в серой
зоне относительно реестра инвариантов: будущий ревьювер вправе
счесть prune нарушением. Текст уточнения подготовлен в артефактах
T073 (PLAN.md, «Подход» п.5; принятие — вне объёма задачи, SPEC
«Не входит»).

## Решение
Инвариант 16 уточняется до своего намерения — запрета КОСВЕННОГО
стирания истории:

1. **Уборка `kill`/`done` не трогает `.artel/logs/`** — побочный
   эффект перехода FSM отдельной задачи не имеет права стирать
   наблюдаемость. Это ядро инварианта, оно не ослаблено.
2. **Единственный законный путь удаления логов — политика
   хранения**: явная, поимённая, отчётная команда `prune`
   (docs/retention.md), симметричная остальным операторским
   командам (`kill`, `budget`, `alert-ack`), прямо и явно
   меняющим состояние системы.
3. Формула: история переживает ЗАДАЧУ — да; но не переживает
   ЭПОХУ без предела: у логов есть собственная, отдельно
   объявленная политика хранения, и её исполняет только явная
   операторская команда, а не судьба чьей-то задачи.

Новый текст строки 16 docs/invariants.md: «История наблюдаемости
переживает задачу: уборка `kill`/`done` не трогает `.artel/logs/` —
их удаляет только политика хранения (`prune`, docs/retention.md),
не побочный эффект перехода FSM отдельной задачи.»

## Последствия
- Кодирующий тест не меняется:
  `test_kill_cleanup.KillCleanupTest.test_run_logs_survive_the_kill`
  проверяет ровно нерушимое ядро (п.1). Запрещённое поведение
  не расширено и не сужено — инвариант перестал молчать о prune.
- `prune` остаётся dry-run по умолчанию: принятие ADR само по себе
  не удаляет ни байта.
- Журнал БД и артефакты гейтов политикой не покрыты — вечны
  (docs/retention.md), это решение не меняется.

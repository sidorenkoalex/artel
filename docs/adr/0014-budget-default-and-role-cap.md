# ADR-0014: дефолт, потолок ролей и статическая оценка бюджета задачи

Статус: принят. Дата: 05.09.2026. Решение Оператора (сессия 05.09,
значения названы Оператором: дефолт $50, потолок ролей $100).

## Контекст

Потолок бюджета задачи задаётся сегодня одной константой
`config.DEFAULT_BUDGET_USD = 50`, которая играет две роли сразу:
значение по умолчанию для задачи без оценки и верхняя граница для
`budget_usd` из SPEC (`budget.spec_budget`: значение выше константы
отвергается, поднять потолок вправе только Оператор командой `budget`,
инвариант 10). Поле `budget_usd` в SPEC необязательное.

Замер 05.09 по 51 завершённой задаче нового формата (данные — БД
пульта, артефактные ветки, мерж-коммиты):

| Факт | Значение |
|---|---|
| потолок из SPEC применился | 2 задачи из 50; у 48 потолок выставлял Оператор командой `budget` |
| команд `budget` за 04–05.09 | 88 по 46 задачам |
| эскалаций «бюджет исчерпан» за 04–05.09 | 30 по 23 задачам |
| задач с расходом выше $50 | 20 из 51 |
| задач с расходом выше $100 | 4 из 51 (все поднимал Оператор осознанно) |
| медиана расхода: до 5 AC / 6–10 AC / больше 10 AC | $32 / $37 / $50 |
| связь расхода с числом AC / числом файлов в мерже | корреляция 0.47 / 0.68 |

Вывод: граница $50 отсекает обычные задачи, а не аномалии; оценка
аналитика не доходит до потолка задачи, и каждая вторая задача проходит
через ручной подъём с эскалацией. Автоматический подъём при исчерпании
Оператором отклонён (05.09): подъём без статического основания
маскирует ошибку оценки. Число файлов известно на стадии PLAN и
предсказывает расход лучше числа критериев.

## Решение

1. **Три уровня потолка.** `DEFAULT_BUDGET_USD = 50` — потолок задачи
   до применения SPEC (шаг аналитика). `ROLE_BUDGET_CAP = 100` — новая
   константа `config`: верхняя граница потолка, который выставляют роли.
   Выше потолка ролей — только Оператор командой `budget`, без границы.
2. **`budget_usd` в SPEC обязателен.** `scripts/guard.py` отказывает SPEC
   без поля; значение применяется на гейте SPEC как потолок задачи в
   обе стороны (и ниже, и выше дефолта) в пределах `ROLE_BUDGET_CAP`.
   Значение выше потолка ролей — отказ guard с подсказкой: делить задачу
   (оценка объёма, 01M1KS8K9R…) либо эскалировать вопрос бюджета
   Оператору. Оператор видит потолок на гейте SPEC и понижает командой
   `budget` при несогласии.
3. **Однократная переоценка на PLAN.** Разработчик вправе указать
   `budget_usd` во frontmatter PLAN. Пульт применяет его один раз — при
   первой сдаче PLAN (`status: ready`, итерация 1) — и только вверх, не
   выше `ROLE_BUDGET_CAP`; источник потолка в БД — `plan`
   (`budget_source`). Возврат из ревью или приёмки переоценку не
   открывает; PLAN без поля потолок не меняет; значение выше потолка
   ролей — отказ guard с той же подсказкой, что в п.2.
4. **Потолок Оператора сильнее.** Потолок, выставленный командой
   `budget` (`budget_source = operator`), значениями из SPEC и PLAN не
   перебивается ни вверх, ни вниз — как сегодня.
5. **Исчерпание без изменений.** Исчерпанный потолок блокирует запуск
   агента и эскалирует задачу (инварианты 9 и 10); снимает блокировку
   только команда `budget`. Стоп-лосс программы
   (`PROGRAM_STOP_LOSS_USD`, ADR-0010) не затрагивается.
6. **Инвариант 10 уточняется:** «поднять потолок ВЫШЕ `ROLE_BUDGET_CAP`
   может только Оператор командой `budget`; в пределах потолка ролей
   потолок задаёт SPEC на гейте SPEC и один раз PLAN при первой сдаче».
   Тест инварианта дополняется: SPEC и PLAN со значением выше
   `ROLE_BUDGET_CAP` потолок не поднимают.
7. **Калибровка в скиле аналитика** переписывается по замеру: до 5 AC
   и до 3 файлов ~$35, 6–10 AC ~$45, больше 10 AC или 5 и более файлов
   ~$70 либо деление; задачи с планкой — не ниже $25. Скил разработчика
   получает правило переоценки на PLAN: по числу файлов и шагов, только
   при расхождении с оценкой SPEC, с обоснованием в PLAN.

## Последствия

Плюс: оценка перестаёт упираться в дефолт, ручные подъёмы и эскалации
по бюджету сокращаются ожидаемо вдвое и больше (20 задач из 51 ушли
выше $50, 4 — выше $100). Минус: роль может выставить до $100 без
участия Оператора в моменте; риск ограничен потолком ролей,
однократностью переоценки и стоп-лоссом программы. Обратимо:
`ROLE_BUDGET_CAP = DEFAULT_BUDGET_USD` возвращает прежнее поведение.

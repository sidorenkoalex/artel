# ADR-0019: Классы канарейки и условие сдвига пина

Статус: принят в части принципов; числа (модель быстрого класса, число
прогонов и пробных задач для допуска) — после замера канарейки на моделях каталога. Дата: 27.09.2026. Решение
Оператора. Дополняет ADR-0013 (условие `pin-update`), не ослабляя его до
исполнения задач, перечисленных в «Следствиях».

## Контекст

Канарейка одним прогоном делает две работы: проверяет код пульта перед
сдвигом пина и измеряет качество и стоимость ролей. Шаблон выбирался
случайно; 27.09 три прогона стоили $56.49, один из них — $26.25 и 85
минут — дал красный вердикт при исправном коде (исчерпан потолок
учебной задачи). С задачи 01M3HJQV2QV9BXNXSH3F8STAYH шаблон выбирается
флагом `--template`.

Пульт отвязывается от одного провайдера моделей (ADR-0017): роли могут
исполняться разными провайдерами, боевой набор может меняться. Решение
сформулировано без привязки к провайдеру.

## Термины

Боевой набор — соответствие «роль → провайдер и модель», по которому
пульт запускает роли настоящих задач на момент прогона (`roles.yaml` и
локальный слой `.artel/models.yaml`). Запасной набор — набор, на который
Оператор намерен переключать роли без отдельной проверки (например, при
исчерпании лимита основного провайдера).

## Решение

1. Класс прогона определяется тем, что изменилось между пином и
   вершиной главной ветки:

   | Изменено | Класс | Шаблон |
   |---|---|---|
   | только документы и бэклог; тесты, если не тронуты общие помощники `tests/` (`tests/sandbox.py`, `conftest.py`) | прогон не требуется | — |
   | команды пульта, отчёты, `doctor`; общие помощники `tests/` | быстрый | простой |
   | запуск ролей, бриф, гейты, цикл `auto`, мерж | полный | средний |
   | скилы, шаблоны артефактов, роли, модели, модули провайдеров | трудный | с неясностью ТЗ |

   Изменены файлы из нескольких строк — берётся старший класс.

2. Частота привязана к сдвигу пина, а не к календарю: новый код пульта
   впервые исполняется именно в канарейке. Трудный класс вне изменений
   своей строки — не реже раза в две недели.

3. Набор ролей. Для сдвига пина засчитывается прогон, исполнивший тот
   же код, через который пойдут боевые роли:
   - полный и трудный классы — только на боевом наборе;
   - быстрый класс допускает более дешёвую модель того же провайдера,
     что у соответствующей роли боевого набора;
   - прогон на наборе, не совпадающем с боевым по провайдерам, не
     засчитывается: он не исполняет модули провайдеров боевых ролей.
   Боевой набор с ролями разных провайдеров проверяется одним прогоном:
   он исполняет модули всех участвующих провайдеров.

4. Смена боевого набора (провайдер или модель роли) — изменение строки
   «роли, модели»: до переключения нужен зелёный прогон трудного класса
   на новом наборе. Запасной набор проверяется наравне с основным: пин
   считается проверенным для набора, на котором есть зелёный прогон не
   ниже требуемого класса.

5. Допуск набора. Двигать пин и вести настоящие задачи можно только на
   наборе, имеющем допуск:
   - допуск выдаётся паре «роль и модель» решением Оператора по итогам
     прогонов канарейки и пробных настоящих задач под обычными гейтами;
     решение записывается в репозитории;
   - набор допущен, если допущена каждая его пара и набор целиком прошёл
     зелёный прогон трудного класса (роли передают друг другу артефакты,
     пара проверяется и в соседстве);
   - допуск пары возобновляется при смене версии модели у провайдера и
     приостанавливается после двух красных прогонов подряд по вине роли,
     а не кода пульта, — до разбора Оператором;
   - число прогонов и пробных задач, достаточное для допуска,
     записывается в это решение после замера;
   - боевой набор на дату решения (все роли — `claude-opus-5`) считается
     допущенным по факту: на нём смержено более двухсот задач.
   Допуск отвечает на вопрос «годится ли набор для работы» и выдаётся
   один раз на набор; класс прогона (пункты 1–4) отвечает на вопрос
   «исправен ли код пульта» и проверяется при каждом сдвиге пина.

6. Прогон с исходом «исчерпан потолок задачи» зелёным не считается.

7. Замер канарейки на всех моделях каталога — измерение: для сдвига пина
   не засчитывается, для допуска даёт первые данные.

## Следствия

- Задача «классы канарейки»: пульт называет требуемый класс по диффу
  между пином и вершиной; запись о прогоне хранит набор, на котором он
  шёл; `pin-update` проверяет прогон не ниже класса на боевом наборе.
  До её мержа действует ADR-0013 как есть, класс и набор выбирает
  Оператор.
- Конкретная модель быстрого класса и числа допуска записываются в это
  решение после замера (строка бэклога 27.09).
- Задача «допуск набора»: место записи допусков, проверка допуска в
  `pin-update` и при запуске роли, счёт по ролям показателей качества на
  настоящих задачах (круги ревью, эскалации, ложные заявки в тестах).
  До её мержа допуск ведёт Оператор вручную.
- Проигрывание записанного прогона без моделей — отдельная задача; после
  неё быстрый класс может быть заменён проигрыванием отдельным решением.
- Если будет принят перенос приёмочных тестов в `tests/` (ADR-0018,
  «Следствия»), строка «тесты» пункта 1 пересматривается: в набор начнут
  попадать проверки команд пульта целиком.

# ADR-0017: Провайдеры ролей — исполнитель шага за интерфейсом провайдера

Статус: принят (решения Оператора 20.09.2026 и 22.09.2026,
`docs/research/providers-codex-plan.md`, раздел 6). Дата: 26.09.2026.
Инициатор — Оператор (план линии провайдеров от 20.09, пересмотр пункта
авторизации 22.09 по фактам живых запусков). Класс по ADR-0002 —
архитектурное решение плюс изменение рубежей безопасности роли: решение
только Оператора. Действует с мержа задач линии 1–4 (смержены); эта запись
фиксирует уже принятые решения, чтобы они жили не в исследовательском
файле, а в реестре решений.

## Контекст

До линии провайдеров пульт был написан вокруг одного CLI. Знание «чем
исполняется шаг роли» лежало литералами в семи местах: argv шага
(`orchestrator/runner.py`), окружение процесса роли и белый список
переменных (`orchestrator/stack.py`), курируемый дом роли и его
развёртывание (`orchestrator/catalog.py`), предполётные проверки и смоки
изоляции (`orchestrator/doctor/`), разбор вывода и стоимость шага
(`orchestrator/agent_log.py`, `orchestrator/spend.py`), классификация
провалов попытки (`orchestrator/failure_classification.py`), таблица
«модель → минимальная версия CLI» (`orchestrator/stack.py`). Добавление
второго исполнителя означало бы ветвление по имени CLI в каждом из этих
мест.

Второй исполнитель понадобился не из любопытства: подписка Claude имеет
лимит окна, роли простаивают, а у Оператора есть подписка ChatGPT с Codex
CLI. При этом Codex — не Claude ни в одном из семи пунктов: у него другой
формат событий (JSONL `codex exec --json`), нет доллара в выводе вовсе,
другая модель изоляции (песочница и выключаемые функции вместо
`--allowedTools` и `deny`-правил) и нет хуков на вызовы инструментов.

Живой запуск Codex CLI 0.155.1 с пользовательским конфигом Оператора в
песочнице `read-only` позвал MCP-сервер `cua_repl` («Computer Use») и
попытался открыть браузер на машине Оператора — не вышло только потому,
что браузера не было. Это и определило форму пункта 6 ниже: рубеж роли —
механизм исполнителя, а не текст правил в доме роли.

## Решение

1. **Исполнитель шага живёт за интерфейсом провайдера.**
   `orchestrator/providers/base.py` объявляет контракт
   (`RoleExecutorProvider`): команда шага, окружение процесса, курируемый
   дом роли, предполётные проверки, инструмент манифеста, вердикт
   совместимости модели с установленным CLI, разбор строки вывода в
   событие общего вида, сигнатуры провалов. Регистрация нового
   исполнителя — запись в словарь `PROVIDERS`, не правка ветвления в
   вызывающем коде. Имя провайдера роли читается из `roles.yaml`
   (`roles.provider`); имени вне реестра соответствует именованный отказ
   `run`/`auto` до старта агента и красная строка `doctor` — не тихий
   откат на провайдера по умолчанию.
2. **Модель роли — не строка у роли, а цепочка «роль → ярус → модель →
   провайдер».** Каталог поддерживаемых моделей (`models.yaml` в корне,
   защищённый путь) держит разделы по провайдерам, минимальную версию CLI
   у каждой модели, тариф и признак `cost_from_cli`. Ярус роли
   (`model_tier`) разрешается в конкретную модель локальным слоем пульта
   (`.artel/models.yaml`, вне git — у каждого пульта свой). Разрешение
   fail-closed: модели вне каталога соответствует отказ, не запуск «как
   есть».
3. **Смешанные ярусы разрешены** (решение 20.09, п.3): ярус роли
   разрешается в модель любого провайдера каталога, и одна задача может
   идти на двух исполнителях. Цена решения — обязательная сверка обеих
   половин конфигурации: ярус на модель одного провайдера при
   `provider:` другого блокируется строкой `model-provider-cli` до старта
   агента, иначе шаг ушёл бы в чужой CLI оплаченной попыткой.
4. **Авторизация роли — по подписке, а не ключом API** (решение 22.09,
   пересмотр п.1 от 20.09). У Claude это токен подписки
   (`claude setup-token`) из слота связки ключей, приходящий шагу
   переменной окружения. У Codex — вход по подписке ChatGPT: токены
   хранит и продлевает сам CLI в системной связке ключей
   (`cli_auth_credentials_store = keyring`,
   `forced_login_method = chatgpt`) для `CODEX_HOME` дома роли, а пульт их
   не читает, не пишет и не видит. Ключей API окружение шага не несёт ни
   под одним именем. Основание пересмотра: отдельный платный API
   Оператору не нужен, а зелёная строка `doctor` по наличию ключа в слоте
   авторизацию не доказывала вовсе — `codex exec` читает ключ из
   `CODEX_API_KEY`, а слот отдавался шагу под именем `OPENAI_API_KEY`
   (живая проверка 22.09, `docs/research/codex-live-check-2026-09-22.md`).
   Следствие: лимит окна подписки есть у ролей ОБОИХ провайдеров, и
   проверка остатка нужна для обоих.
   Белый список переменных окружения роли общий на пульт, поэтому
   окружение шага сужается по провайдеру: имена секретов чужого
   исполнителя (`secret_env_names()` реестра) вычитаются в
   `runner.role_env`, а их появление в собранном окружении — отказ строки
   `foreign-provider-secrets`.
5. **Сеть роли под Codex запрещена** (решение 20.09, п.2): песочница
   `workspace-write` с выключенной сетью
   (`sandbox_workspace_write.network_access = false`). Всё сетевое идёт
   объявленными инструментами пульта; push и MR делает пульт, не роль.
6. **Защита роли — песочница провайдера плюс гейты пульта, а не текст
   правил.** Правила в брифе и в доме роли объясняют, а отказывают
   механизмы: у Claude — флаги команды шага (`--allowedTools`,
   `--setting-sources`, `--strict-mcp-config`) и `deny`-правила
   курируемого `settings.json`; у Codex — песочница, выключение
   одиннадцати функций 0.155.1 и `-c`-переопределения, продублированные в
   курируемом `config.toml` дома роли, потому что `.artel/home` эфемерен
   (ADR-0005 п.3), а команду шага собирает код. Хуков на вызовы
   инструментов у Codex нет, и аналога `bash_guard.py` ему не заводится:
   хук, включённый ради запрета, сам становится исполняемым кодом в доме
   роли. Там, где рубежа у исполнителя нет вовсе (чтение каталога пула
   канарейки, посторонние файлы и защищённые пути), держат гейты пульта
   ПОСЛЕ шага — и это записано честно, а не выдано за паритет:
   построчная таблица «запрет у роли на Claude → чем закрыт у Codex → чем
   подтверждено» живёт в `docs/stack.md`, раздел «Паритет безопасности
   роли», и стережётся тестом.
7. **Единица бюджетов и гейтов — доллар** (решение 20.09, п.5); токены
   показываются рядом и в единицу гейтов не превращаются. Провайдер,
   который доллар в выводе не сообщает (Codex: `usd is None`, отличимо от
   нулевой цены), эту единицу не отменяет: расход шага считает пульт по
   действующему тарифу модели из каталога — публичному прейскуранту с
   датой, с локальным переопределением по желанию Оператора (решение
   20.09, п.4). Отсутствие тарифа — отказ, а не ноль: ноль в `spent_usd`
   выглядел бы учтённым шагом. История тарифов живёт в таблице
   `model_tariffs`, и расхождение расчёта с фактом CLI там, где факт есть,
   попадает в журнал и в предупреждение.

## Последствия

- Плюс: второй исполнитель заводится записью в реестр и разделом
  каталога, без ветвления по имени CLI в семи модулях; третий заведётся
  тем же путём.
- Плюс: «чем идёт шаг» стало проверяемым — предполёт, смоки изоляции и
  вердикт модели спрашивают провайдера роли, а не литерал, и врать о
  чужом CLI больше не могут.
- Минус: конфигурация роли разъехалась по двум файлам (`roles.yaml` —
  исполнитель, локальный слой — ярус и модель), и их расхождение
  приходится сторожить отдельной проверкой (п.3). Это цена смешанных
  ярусов.
- Минус: паритет безопасности неполон и останется неполным, пока у Codex
  нет рубежа ДО действия роли (п.6). Размен принят сознательно: рубеж
  после шага держат гейты пульта, они общие на оба исполнителя и от
  исполнителя не зависят.
- Ослабления по ADR-0002 нет: ни одна проверка `doctor`, ни один гейт и
  ни один инвариант линией провайдеров не ослаблены; единственное
  изменение статуса строки шло вверх (`warn` → `fail` на чужом секрете в
  собранном окружении шага).
- Живой смок Codex обычный прогон `doctor` не запускает: вызов платный, а
  провайдер заведён раньше, чем на него переведена роль.

## Раскатка

1. Задачи линии 1–4 (интерфейс провайдера, каталог моделей и ярусы,
   вывод и стоимость, провайдер `codex`) — смержены.
2. Задача 5 линии: таблица паритета в `docs/stack.md`, сужение окружения
   шага по провайдеру, отказ строки `foreign-provider-secrets`, проверка
   утечки пула по логам шагов обоих провайдеров — и эта запись.
3. Перевод роли на Codex остаётся действием Оператора: ярус локального
   слоя, `provider:` в `roles.yaml` (защищённый путь), два однократных
   шага подписочного входа — порядок в `docs/stack.md`, раздел
   «Провайдер codex».
4. Задача 6 линии: калибровка расхода, канарейка на ролях Codex и
   проверка остатка лимита подписки для обоих провайдеров.

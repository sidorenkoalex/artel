# Дизайн-система пульта Артели

Компактный стандарт UI-поверхностей пульта (роадмап §3 «Панель», этап 1,
П4). Не изобретение с нуля: систематизирует фактуру, уже существующую в
двух реальных источниках, и фиксирует расхождения между ними нормой, а
не произвольным выбором одного из двух.

## Источники

- `tasks/T080/mockup.html` — утверждённый макет панели (П1): статический
  артефакт UX, кнопки без обработчиков, борд/карточка/алерты/очередь
  гейтов размечены полностью.
- `orchestrator/report.py` — живой статический HTML-отчёт пульта
  (tasks/T092/SPEC.md): read-only срез `state.db`, без демона и сборки,
  тот же дух самодостаточности, но часть разметки макета не несёт
  (кнопки, баннер, per-состояние цвет карточек — см. «Расхождения»).

Любое будущее UI-задание (доработки report, панель Г0+) сверяется с
этим документом, а не с одним из источников напрямую — расхождения
между источниками здесь уже разобраны и нормированы.

## Принципы самодостаточности

Оба источника и любая будущая UI-поверхность этапа 1 держат три правила
без исключений:

- **Самодостаточный HTML** — один файл, стили инлайном в `<style>`,
  открывается напрямую как `file://`, без сервера.
- **Без JS-фреймворков** — ни React/Vue/иного фреймворка, ни сборки под
  них; вся интерактивность (если есть) — обычный `<script>` без
  зависимостей, либо чистая разметка без обработчиков (как в
  `mockup.html`, где кнопки — только визуальная разметка).
- **Без шага сборки и без внешних ресурсов/CDN** — ни webpack/vite/иного
  бандлера, ни `<link>`/`<script src="https://...">` на внешний CDN или
  шрифт: всё, включая шрифтовой стек, — системные шрифты или инлайн.
  Демоны, HTTP-серверы и БД-подключения из панели — вне объёма этапа 1
  (появятся только с панелью Г0+, роадмап §3).

## Палитра (цветовые токены)

Базовые токены `:root` совпадают в обоих источниках дословно — общий,
уже устоявшийся фундамент палитры:

| Токен | Значение | Назначение |
|---|---|---|
| `--bg` | `#f4f5f7` | фон страницы |
| `--panel` | `#ffffff` | фон панелей/карточек/тайлов |
| `--border` | `#dde1e6` | рамки панелей, колонок, тайлов |
| `--text` | `#1c2530` | основной текст |
| `--muted` | `#667085` | вторичный текст (подписи, метаданные) |
| `--accent` | `#2f5fd6` | акцент (имя гейта, ссылки на действие) |
| `--accent-soft` | `#e8edfc` | фон акцентной плашки (`.gate-name`) |

Токены состояний FSM — несёт только `mockup.html` (норма, см.
«Расхождения» ниже за пояснением, почему `report.py` их пока не несёт):

| Токен | Значение | Состояние/смысл |
|---|---|---|
| `--ok` | `#1f8a4c` | успех — `done` |
| `--warn` | `#b7791f` | требует внимания — `in_dev`, алерт-предупреждение |
| `--danger` | `#c22b2b` | критично — `escalated`, алерт-инцидент |
| `--killed` | `#6b7280` | снята — `killed` |

Тёмная тема — см. отдельный раздел «Граница стандарта» ниже.

## Типографика

- Шрифтовой стек текста: `-apple-system, "Segoe UI", "Helvetica Neue",
  Arial, sans-serif` — системный, без веб-шрифтов и CDN.
- Моноширинный стек для идентификаторов и служебных тегов (`tile-id`,
  `state-tag`, `gate-name`): `ui-monospace, Menlo, Consolas, monospace`.
- Иерархия размеров: заголовок топбара `header h1` — 18px/600;
  заголовок панели `section.panel > h2` — 15px/600; подзаголовки
  метрик `h3` — 13px; тело карточек/тайлов — 12–13px; служебные подписи
  (`muted`, `hint`, `field dt`) — 10–11px.
- `line-height: 1.4` на `body` — общий межстрочный интервал документа.

## Раскладка: борд / карточки / панели

- **Панель** (`section.panel`) — базовый строительный блок страницы:
  фон `--panel`, рамка `1px solid var(--border)`, `border-radius: 10px`,
  паддинг `16px 18px`; заголовок панели — `margin: 0 0 12px`.
- **Борд** (`.board`) — горизонтальный ряд колонок FSM, `display: flex`,
  `gap: 12px`, `overflow-x: auto` (борд шире экрана скроллится, а не
  переносится).
- **Колонка борда** (`.col`) — фон `#fafbfc`, рамка `var(--border)`,
  `border-radius: 8px`, паддинг `8px`, `display: flex; flex-direction:
  column; gap: 8px`. Норма ширины колонки: **`min-width: 168px; flex: 0
  0 168px`** — значение `mockup.html`, применено косметической правкой
  `report.py` этой задачей (см. «Расхождения», пункт 2).
- **Тайл задачи** (`.tile`) — фон `--panel`, рамка `var(--border)`,
  `border-radius: 6px`, паддинг `7px 8px`, размер шрифта 12px;
  `tile-id` моноширинный/жирный, `tile-title` блоком с отступом
  `2px 0 4px`, остальные поля — `--muted`, 11px.
- **Карточка задачи** (`aside.task-card` / аналог) — та же геометрия
  панели (рамка, `border-radius: 10px`, паддинг `16px 18px`), поля —
  `dl`/`dt`/`dd` с `dt` в верхнем регистре 11px `--muted`.

## Состояния FSM и цветовое кодирование

Норма — цветовое кодирование `mockup.html`, по состояниям, левой рамкой
тайла (`border-left: 3px solid <токен>`) через класс колонки
`.col.<состояние> .tile`. Таблица покрывает полный список состояний
`orchestrator/report.py::STATE_ORDER` (11 состояний) — `mockup.html`
моделирует колонками только 10 из них, `verifying` в борде макета нет;
это отдельно выявленное расхождение источников, разобрано ниже
(«Расхождения», пункт 5) с предложенной нормой:

| Состояние FSM | Токен | Класс колонки (`mockup.html`) |
|---|---|---|
| `spec_writing`, `spec_gate`, `tests_writing`, `acceptance` | без цвета (нейтральные, ожидание/подготовка) | — |
| `verifying` | без цвета (нейтральный, ожидание CI) — норма по аналогии с `acceptance`; колонки в `mockup.html` нет, см. «Расхождения», пункт 5 | — (в `mockup.html` не представлено) |
| `in_dev` | `--warn` | `.col.in_dev` |
| `review`, `merge_gate` | `--accent` | `.col.review`, `.col.merge_gate` |
| `escalated` | `--danger` | `.col.escalated` |
| `done` | `--ok` | `.col.done` |
| `killed` | `--killed` | `.col.killed` |

Та же пара токенов (`--warn`/`--danger`) кодирует и два уровня алертов
(`.alert-item` / `.alert-item.incident`).

## Расхождения между источниками и предложенные нормы

1. **Цветовое кодирование состояний борда** (основное расхождение).
   `mockup.html` красит тайлы борда по состоянию через токены `--ok`,
   `--warn`, `--danger`, `--killed` и классы колонок
   `.col.done`/`.col.killed`/`.col.escalated`/`.col.in_dev`/
   `.col.merge_gate`/`.col.review`. `orchestrator/report.py` не несёт ни
   этих токенов в `:root`, ни этих классов — `_board_html` рендерит
   каждую колонку одинаковым `<div class="col">` без класса состояния,
   а `_STYLE` не содержит правил `.col.<state>`.
   **Норма**: таблица «Состояния FSM и цветовое кодирование» выше —
   `report.py` должен прийти к тому же кодированию. **Не применяется
   этой задачей**: добавление токенов `--ok`/`--warn`/`--danger`/
   `--killed` в `:root` и новых селекторов `.col.<state> .tile` — это
   новые CSS-объявления и новые правила внутри `_STYLE`, а класс
   состояния в HTML тайла/колонки — правка функций `_tile_html`/
   `_board_html`, то есть структурное изменение рендера и разметки, а
   не значение существующего объявления (SPEC требование 4, AC-7).
   Отдельная задача.

2. **Ширина колонки борда** (косметическое, применено этой задачей).
   `mockup.html`: `.col { min-width: 168px; flex: 0 0 168px; }`.
   `orchestrator/report.py` (до правки): `.col { min-width: 200px; flex:
   0 0 200px; }`. Расхождение — только значения существующих объявлений
   `min-width`/`flex` внутри уже существующего правила `.col`, без
   добавления или удаления свойств/селекторов. **Норма**: `168px`
   (значение `mockup.html`) — применена диффом этой задачи к `_STYLE`
   `orchestrator/report.py`.

3. **Баннер, шапка с подзаголовком и действиями, кнопки approve/reject/
   pause** — есть в `mockup.html` (`header.topbar` с `.subtitle` и
   `.topbar-actions`, `p.banner`, `.btn`/`.btn.approve`/`.btn.reject`/
   `.btn.pause`), отсутствуют в `orchestrator/report.py` целиком:
   `report.py` — read-only срез (SPEC T092, требование 9/AC-10), не
   несёт действий Оператора и баннера-пояснения по построению. **Норма**:
   элементы, специфичные для интерактивной панели (кнопки, действия),
   в `report.py` не нужны, пока он read-only; появятся вместе с панелью
   Г0+. Не расхождение стандарта, а следствие разного назначения
   поверхностей — не требует правки `report.py`.

4. **Тонкая структурная разница `.col-head`**: у `mockup.html`
   `.col-head` несёт `display: flex; flex-direction: column; gap: 2px`,
   у `report.py` — только `margin-bottom: 2px` (свойств меньше).
   **Норма**: выровнять на `display: flex; flex-direction: column; gap:
   2px`. **Не применяется этой задачей**: добавление свойств —
   структурное изменение правила по критерию AC-7 (набор CSS-свойств
   правила меняется), не значение уже существующего объявления.
   Отдельная задача вместе с пунктом 1.

5. **Состояние `verifying` не смоделировано в `mockup.html`** —
   `orchestrator/report.py::STATE_ORDER` (`orchestrator/report.py:29-32`)
   несёт 11 состояний, включая `verifying` (ожидание CI после
   `in_dev`/`review`, до `acceptance` — см. `orchestrator/auto.py:62-171`,
   `orchestrator/canary.py:85-119`), а борд `mockup.html:291-393` рисует
   ровно 10 колонок и колонки `verifying` не содержит вовсе — не пропуск
   цвета у уже нарисованной колонки, а полное отсутствие состояния в
   макете. **Норма**: колонка `verifying` — нейтральная (без цвета), по
   аналогии с `acceptance` (тоже промежуточное ожидание, не решение и не
   финал); зафиксировано строкой в таблице «Состояния FSM и цветовое
   кодирование» выше. **Не применяется этой задачей**: добавление
   колонки `verifying` в борд `report.py` тем же классом «нейтральная
   колонка», что и остальные не окрашенные состояния — уже сегодня
   `_board_html` рендерит её без класса состояния (см. пункт 1 выше);
   отдельного действия не требует и диффом не меняется. Правки макета
   `mockup.html` — вне объёма (исторический артефакт, AC-6).

## Граница стандарта: только светлая тема

Ни `tasks/T080/mockup.html`, ни `orchestrator/report.py` не несут
медиа-запроса `prefers-color-scheme` (или любого другого механизма
тёмной темы) — оба источника целиком светлые. Это текущая **граница**
стандарта: **тёмная тема не поддерживается и не несётся** ни одним из
источников, документ её не домысливает. Появление тёмной темы —
отдельное расширение стандарта, когда (и если) один из источников
действительно её получит.

## Вне объёма этой задачи

- Демон/панель этапа 2 (роадмап §3, этап 2) — этот документ описывает
  только статические HTML-поверхности этапа 1.
- Структурные изменения `orchestrator/report.py` из раздела
  «Расхождения» (пункты 1 и 4) — требуют правки функций рендера и
  добавления CSS-правил/свойств, что выходит за рамки допуска AC-7
  («значение существующего объявления»); фиксируются здесь как норма
  для будущей отдельной задачи, не применяются диффом П4.
- Правки `tasks/T080/mockup.html` — исторический артефакт, неизменен.

# Копилка и бэклог

Два списка с разной природой записи. Здесь — единственное место для
обоих; в `docs/roadmap.md` остаются фазы, приоритеты и решения.

- **Копилка** — наблюдение без решения: антипаттерн, сигнал, предложение
  роли из секции «Предложения системе» PLAN/RETRO. Решения «что с этим
  делать» ещё нет. Вход контура обучения: К2 (куратор знаний) по
  триггеру «антипаттерн повторился» дистиллирует копилку в правки скилов
  и удаляет дистиллированное. Запись: дата, что наблюдали, где (задача),
  чем закончилось.
- **Бэклог** — решение Оператора «заводим, но позже»: кандидат в задачу с
  рамкой, зонами и условием старта. Когда задача заведена через
  `cmd_new`, строка получает id и через один цикл сверки удаляется —
  реестр живых задач ведёт БД пульта, не этот файл. Старые отложенные
  темы с классом приоритета — таблица «Задача / Суть / Класс» в
  `docs/roadmap.md` §3; новые кандидаты — сюда.

Закрытые пункты не хранятся: закрыто задачей — остаётся её RETRO и
запись в §4 роадмапа; закрыто правилом — остаётся правило в скиле или
`docs/operator-session.md`.

## Приоритет строк

Строки всех трёх таблиц упорядочены по критичности (раскладка 05.09,
сверена с БД пульта). Колонка «П» — приоритет:

- **1 — сейчас**: ущерб идёт каждый день (деньги, потерянные шаги ролей,
  ложные отказы гейтов) либо пункт блокирует ближайший ручной гейт;
  условие старта наступило.
- **2 — ближайшее окно**: ущерб заметный и повторяющийся, но условие
  старта ещё не наступило (занята зона, ждёт мержа соседней задачи)
  либо нужно решение Оператора.
- **3 — тихое окно**: гигиена, наблюдаемость, рефакторинг, документные
  правки; заводить после волны.
- **4 — держать**: закрывается другой задачей или правилом; заводить
  только при срыве её условия, иначе снять при следующей сверке.

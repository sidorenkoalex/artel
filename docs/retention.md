# Retention-политика

Что и как долго живёт в системе, по видам данных (tasks/T073/SPEC.md,
требование 1; roadmap P3 «Retention-политика», $25). Реализует политику
команда `prune` (`orchestrator/prune.py`) для видов, где хранение не
привязано к переходу FSM одной задачи, и сам оркестратор — для видов,
где привязано (ветка/worktree на `done`).

## `.artel/logs/` — логи прогонов агентов

Лимит двойной, `prune` исполняет ОБА разом (AND, не OR): файл лога
удаляется, только если он ОДНОВРЕМЕННО

- старше **90 дней** (`config.LOG_RETENTION_DAYS`) по mtime, **И**
- его задача — вне **N=20 последних ЗАКРЫТЫХ задач** по ДАТЕ ЗАКРЫТИЯ
  из журнала (`config.LOG_RETENTION_KEEP_TASKS`, значение — решение
  Оператора 29.08, tasks/T073/TZ.md, «Ответы Оператора»; правка —
  только Оператор, ADR-0002, класс «лимит»; отбор по дате закрытия, не
  по числовому номеру задачи — SPEC T094, требование 5: ULID-id
  сравнимого по величине номера не несёт, а `Tnnn`-задачи участвуют в
  этом же датовом отборе, не в отдельном отборе «последние N по
  номеру»). Ещё не закрытая задача в датовый отбор не попадает вовсе —
  её логи retention не трогает независимо от возраста.

Свежий лог не удаляется никогда, даже у древней задачи; лог задачи из
последних 20 закрытых не удаляется никогда, даже если ему сто лет.
Исполняет — `prune --execute` (без флага — dry-run, план без удаления).

## Ветки `task/*` пульта

Ветка задачи удаляется оркестратором при переходе в `done` — сразу
после уборки worktree (`git branch -d`, безопасное удаление: git
откажет сам, если ветка внезапно не влита). Тем же правом, каким
оркестратор уже убирает ветку/worktree при `kill` (T008/T045). Merge в
main остаётся **без squash** (`git merge --no-ff`) — история мержа
задачи в main полная и не теряется удалением самой ветки-указателя.

## `.artel/canary/` — диагностика незелёного прогона канарейки

Файл диагностики (SPEC 01M1TKP269W9JN3NBJCR5Q6C3B, требование 4) убирается,
только если он старше **90 дней** (`config.LOG_RETENTION_DAYS`) по mtime
— тот же порог давности, что и у `.artel/logs/` выше, но БЕЗ второго
условия («последние N закрытых задач»): `task_id` в пути диагностики
(`.artel/canary/<run_stamp>/<task_id>/`) — id уже уничтоженного
эфемерного клона канарейки, не задачи пульта, и в датовый отбор
`.artel/logs/` не участвует. Исполняет — `prune --execute` (без флага —
dry-run, план без удаления), тем же вызовом, что и остальную политику
этой страницы.

## Alerts

Alerts (любой `kind`, вне зависимости от `ack`) старше **90 дней**
(`config.ALERT_ARCHIVE_DAYS`) не удаляются — `prune --execute`
переносит их в архивную таблицу `alerts_archive` (та же схема, с
`archived_ts` момента переноса). Запись покидает `alerts` и появляется
в архиве с тем же `id` — перенос, не дублирование и не потеря.

## Worktree задачи (`.artel/worktrees/<id>`)

Убирается оркестратором при переходе задачи в `done` (уже было,
T045) и в `killed` (уже было, T008) — тем же правом уборки хвостов
задачи. `prune` этого вида не касается — переход FSM убирает worktree
сам, немедленно, не по расписанию.

## Report-страница (П2′, когда появится)

Перегенерируется на месте при каждом обновлении — истории отчётов
(прежних версий страницы) система не хранит.

## Журнал БД и артефакты гейтов

Вечны. Retention их не касается никогда — ни `prune`, ни любая другая
уборка. Журнал шагов (`steps`) — источник истины прошлого поведения
системы (docs/design.md §7); артефакты гейтов, попавшие в main
(SPEC/PLAN/REVIEW смерженных задач), — история проекта (ADR-0005 п.1,
уровень `full`).

## premod-очередь — будущая строка (не реализована)

premod-очередь не существует до C3 (roadmap). Когда появится, у неё
будет своя строка политики хранения; эта задача (T073) её не заводит
и не реализует — только резервирует место в этом документе.

## Инвариант 16 и `prune`

`prune` — не часть уборки задачи (`kill`/`done`) и не срабатывает на
переходе FSM ни одной задачи: явная, отдельно вызываемая Оператором
команда над `.artel/logs/`/`alerts` в целом, по собственной политике
выше, с отчётом о сделанном. Инвариант 16 («История наблюдаемости
переживает задачу: `.artel/logs/` уборка не трогает») запрещает
КОСВЕННОЕ стирание логов как побочный эффект закрытия/убийства одной
конкретной задачи — этому `prune` не противоречит: у логов есть
собственная, отдельно объявленная политика хранения (эта страница), и
её исполняет только явная операторская команда. Полный текст уточнения
инварианта 16 (для ADR, который вправе принять только Оператор) —
`tasks/T073/PLAN.md`, раздел «Подход», п.5.

# Реестр триггеров

Все триггеры возврата отложенных механизмов и перевода механик
в следующий режим — в одном месте: условие без наблюдателя
не срабатывает, а обнаруживается пробоем.

Правила (ADR-решения, вшиты в A3):

- **Событийные** триггеры (запрос людей, решение Оператора,
  конфигурационное событие) — владелец Оператор, автоматический
  наблюдатель не нужен.
- **Ползучие пороговые** (вычислимые из журнала/логов) — считает
  `doctor` и пишет в таблицу `alerts` с `kind=trigger` (A3);
  показываются отдельной секцией CLI/report, НЕ смешиваются
  с инцидентами. **Ack триггера обязан фиксировать решение**:
  «внедряем — задача N» либо «отложено до <новая граница>».
- Обязательный пункт повестки go/no-go после C2 — пробег этого
  реестра: какие триггеры близко, какие сработали незамеченными.

Не триггеры (зафиксировано, чтобы не искать):

- **Переход ноутбук → корп-сервер** — не гейт и не триггер: по
  потребности в мощностях, после обкатки флоу (ADR-0003 3к).
  Гейтится запуск постоянного фонового режима — он требует серверной
  эпохи и сервисных УЗ (Р7).
- **Регенерация gates.yaml** — не триггер, а часть задачи Г1a
  (`artel describe`); до Г1a файл помечен недействующим.

### CR-2026-09-30-1 ★ — база сравнения ветки задачи — локальный `main` (пин), а ветка растёт от origin/main
- Адрес: orchestrator/github_adapter.py:27–44 `_commits_over_base`, :115–123; orchestrator/review.py:700–706, :797–806;
  ветка заводится от origin/main — orchestrator/workspace.py:73–81.
- Суть: (а) правка 01M3HP7WAX (хвост CR-2026-09-26-7) решает «в ветке нет коммитов → черновик MR не нужен» по
  `rev-list main..<ветка>`: коммиты origin сверх пина попадают в счёт, GitHub отвечает «No commits between».
  (б) Итерация ревью > 1 без якоря прошлого вердикта (и отказ `diff_base`) строит diff от `config.MAIN_BRANCH` —
  ревьювер получает изменения всех задач, слитых после пина. Готовый критерий рядом: `gitcmd.diff_base`, gitcmd.py:390.
- Цена / риск: $15 (оба места и сверка прочих вызовов `commits_behind`/`git_diff_part` с `MAIN_BRANCH`); низкий.
- Доказательство: после пина фикса 15 из 15 `Draft MR FAILED` — «No commits», «пропущен» — 1; за окно 41 отказ = 41 алерт
  без ack (открытых `github_adapter` 123 → 157); ветка 01M3S9HRZY: `main..` = 3, `origin/main..` = 0. Ревью 01M3GKJ84X,
  итерация 2 (27.09): diff от пина 137 файлов / 22 196 строк (итерация 1 — 1 497), промпт 1,6 МБ, $21.05 против $6.78 и
  $4.41 соседних итераций; из 112 пакетов с 13.09 единственный ≥ 8 частей.

### CR-2026-09-30-2 ★ — журнал шага пишется отрисованным текстом, три потребителя разбирают его как сырой JSON
- Адрес: запись — agent_log.py:154–173 (`event.log_text`); потребители — spend.py:98 `partial_tokens_from_log`

  застыло на T093–T102. Образец верного решения есть: трение считается на лету (`OutputPump`) и пишется в журнал.
- Цена / риск: $25; низкий. По (1) решение Оператора: счётчики usage при потоке или снять недостижимую ветку.
- Доказательство: в 300 последних логах нет `"usage"|"input_tokens"`, в 60 логах developer — 0 строк `{"type":"assistant"`;

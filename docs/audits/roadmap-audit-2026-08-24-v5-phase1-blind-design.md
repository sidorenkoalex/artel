# Фаза 1 — блайнд-проект главного инженера (зафиксирован ДО чтения наследства)

Зафиксировано: 2026-08-24. Прочитано к этому моменту: README.md, имена файлов
верхнего уровня, промпт v5. roadmap.md / design.md / adr/ / audits/ — НЕ открыты.

## 0. Несущая идея

Система — детерминированный конвейер поверх стохастичных исполнителей.
Всё, что может быть скриптом, — скрипт. LLM оставлены три работы:
превратить намерение в спецификацию, превратить спецификацию в дифф,
попытаться дифф сломать. Всё остальное (маршрутизация, лимиты, гейты,
метрики, чистка) — код без интеллекта.

## 1. Декомпозиция флоу

Классы задач при приёме: S (микро: ≤1 файл, шаблонное), M (обычная фича/фикс),
L (многофайловая, нужен план). Класс выбирает форму конвейера — не гонять
пять стадий ради опечатки.

Стадии (M как базовый случай):
1. intake: спец-агент из свободной формы Оператора делает SPEC
   (цель, исполняемые критерии приёмки, out-of-scope, целевой репозиторий,
   класс, бюджет). Гейт Оператора на SPEC — несократим: это единственная
   точка, где намерение человека входит в систему.
2. plan: только для L — PLAN-артефакт, гейт автоматический (guard-схема),
   не Оператор.
3. implement: dev-агент, чистый контекст: SPEC + дайджест знаний о целевом
   репо + скил роли. Выход: ветка, PR, SELF_REPORT (сделано/не сделано/риски).
4. verify: два независимых слоя:
   a) детерминированный: CI (тесты, линт, guard, diff-scope-чекер,
      анализатор ослабления тестов, coverage-ratchet);
   b) адверсариальный: ревью-агент, вход = SPEC + дифф, БЕЗ рассуждений
      dev (анти-конвергенция). Обязан прикладывать свидетельства
      (запуски, строки), вердикт — enum: approve / return(коды) / escalate.
5. merge: оркестратор мержит после гейтов. В тестовую эпоху гейт Оператора
   на мерж для M/L; для S — автомерж по зелёным детерминированным гейтам
   (решение помечаю как «выбор по вкусу» — конфликт с «молчание≠согласие»
   снимается тем, что гейт S-класса объявлен автоматическим, а не ручным).
6. close: DIGEST задачи (5–10 строк) → журнал; метрики; janitor: ветка
   удалена, tasks/<id> в архив по retention.

Циклы: dev↔review ≤ 2 возврата, дальше escalate. Всё с числовым лимитом
и денежным потолком.

## 2. Артефакты как интерфейсы

- Каждый артефакт: YAML-frontmatter (машинные поля: task, role, status,
  schema_version, коды вердиктов) + ограниченные секции markdown.
- Один валидатор (guard) на писателя и читателя, версия схемы в frontmatter —
  расхождение форматов детектится, а не случается.
- Вердикты — enum + коды причин; свободный текст — дополнение, не носитель.
- DIGEST — первоклассный артефакт со своей схемой; даунстрим получает
  дайджесты, а не полные артефакты, выше порога размера.
- Лимиты размера артефактов в guard (жёсткие, в токенах).

## 3. Состояние и восстановление

- Истина: git-артефакты + append-only журнал событий (JSONL на задачу).
- SQLite state.db — кэш/индекс, перестраиваемый из журнала. `doctor`
  перестраивает и диффует; расхождение — дефект.
- Каждый запуск агента — запись в журнале: входной хэш, выходы, стоимость,
  модель. Ретраи: 1 на инфраструктурный сбой; «плохой контент» — не ретрай,
  а возврат со счётчиком.
- Рестарт оркестратора = чтение журнала, продолжение с последнего
  завершённого перехода.

## 4. Качество при стохастичных исполнителях

- Судейство скриптами где возможно: guard, тесты, diff-scope (файлы vs
  allowlist из SPEC), детектор ослабления тестов (удалённые/skip/ослабленные
  asserts → авто-эскалация), coverage-ratchet.
- Независимость ревьюера: отдельный контекст, без обоснований dev.
- Анти-сервильность: после гейта SPEC агенты спорят с артефактами, ссылка
  «так сказал Оператор» не является свидетельством.
- Канарейки: фиксированная эталонная задача, реплеится периодически и после
  любого изменения промптов/скилов/модели; дрейф исход/стоимость/итерации =
  сигнал деградации.
- Посев мутаций: периодически ревьюеру подсовывается заведомо дефектный
  дифф; пропуск — метрика слепоты ревьюера.

## 5. Оператор как асинхронное устройство

- Один inbox решений: файл/панель со списком ожидающих гейтов; каждый
  пункт — пакет решения (контекст ≤ 1 экран, варианты, рекомендация,
  класс обратимости). Никаких таймаут-автопроходов.
- Гейт одной задачи не блокирует другие; конвейер продолжает остальное.
- Каждое решение Оператора — артефакт (decision log); оркестратор не
  пропускает гейт без записи. Решения в чате не существуют.

## 6. Экономика токенов

- Бюджет по классу задачи задаётся в SPEC; жёсткий стоп на потолке →
  эскалация (стоп исполняет оркестратор, не агент).
- Стоимость/токены/время меряет оркестратор на выходе каждого запуска
  (не самоотчёт агента), пишет в журнал.
- Контекстная диета: промпт = стабильный префикс (скил роли) + дайджесты;
  никакой истории чата; кэшируемая раскладка префикса.

## 7. Гигиена — таблица жизненного цикла (каждый артефакт: создатель,
читатели, событие смерти, удаляющий)

| Артефакт | Создатель | Читатели | Смерть | Удаляющий |
|---|---|---|---|---|
| tasks/<id>/* | роли | даунстрим-роли, Оператор | close + M дней | janitor (artel gc) |
| журнал JSONL | оркестратор | метрики, replay | компакция в агрегаты через N мес | janitor |
| ветки task/* | dev | CI | merge/abandon | оркестратор post-merge |
| дайджест целевого репо | refresher | dev, reviewer | supersede (K мержей или staleness) | перезапись, хранится 1 |
| уроки/память | предложения агентов → файл proposals | Оператор | promote в скил или reject | Оператор (promote = смерть proposal) |
| метрики | оркестратор | еженедельный отчёт | raw → агрегаты | janitor |
| state.db | оркестратор | оркестратор | в любой момент (кэш) | doctor rebuild |
| еженедельный отчёт | генератор | Оператор | 8 недель | janitor |

Janitor — шаг FSM на close + еженедельный проход; doctor верифицирует
отсутствие сирот. Всё, что копится без retention, — дефект.

Ключевой запрет: агенты не пишут в скилы/память напрямую — только
в proposals; промоушен — акт Оператора (защита от отравления памяти).

## 8. Эволюция

- Промпты/скилы/гейты — в git, изменение — через PR со своим гейтом;
  правила/инварианты меняет только Оператор (инвариант входа).
- После любого изменения скила/промпта/модели — прогон канарейки;
  регресс = откат.
- Самоописание: `artel describe` генерирует документ пайплайна из кода
  (состояния FSM, гейты, роли) — рукописная документация о механике
  не поддерживается, чтобы не дрейфовала.
- Переходы между фазами — по метрикам выхода, не по ощущению.

## 9. Реестр отказов (детекция — сигнал, не надежда)

1. Конвергентная галлюцинация dev+reviewer — детект: исполняемые критерии
   приёмки из SPEC + CI, независимые от обоих; мутационный посев.
   Гасит: ревьюер без рассуждений dev.
2. Сервильность к Оператору (спека принята с противоречиями) — детект:
   SPEC-линтер требует фальсифицируемых критериев; обязательная секция
   «допущения/риски» не может быть пустой.
3. Тихое ослабление тестов — детект: детерминированный анализатор диффа
   тестов + coverage-ratchet → авто-эскалация.
4. Деградация от мусора в контекстах — детект: лимиты размера в guard;
   тренд токенов-на-стадию в метриках.
5. Отравление памяти/скилов — детект: скилы меняются только PR-гейтом;
   канарейка после изменения. Гасит: запрет прямой записи.
6. Дрейф инструкций после серии правок — детект: канарейка + diff
   `describe` vs docs; месячный чейнджлог скилов в отчёте.
7. Бюджетная прорва — детект: жёсткий потолок в оркестраторе, дневной
   расход в отчёте; стоп → эскалация.
8. Недетерминизм при ретраях маскирует флаки — детект: журнал пишет
   каждый аттемпт; лимит 1 инфра-ретрай; метрика ретраев.
9. Устаревание знаний о целевом репо — детект: штамп HEAD в дайджесте,
   doctor сверяет с текущим HEAD; refresh по событию.
10. Расхождение форматов писатель/читатель — детект: единый guard +
    schema_version; несовпадение = красный.
11. Крэш оркестратора / потеря состояния — детект: doctor диффует
    журнал vs state.db. Гасит: event-sourcing, DB перестраиваемая.
12. Задачи-зомби (вечно ждут) — детект: метрика возраста в состоянии,
    еженедельный отчёт перечисляет всё старше X дней.
13. Регресс «гейт стал автопроходить» — детект: инвариант-тест в CI:
    синтетическая задача не может пройти ручной гейт без decision-записи.
14. Ревьюер-штамповщик — детект: метрика доли approve с первого прохода;
    ~100% на окне → алярм; мутационный посев ловит слепоту.
15. Расползание скоупа dev — детект: diff-scope-чекер против allowlist SPEC.
16. Эскалационный потоп — детект: метрика доли эскалаций; порог →
    ревизия скилов.
17. Потерянные решения Оператора (в чате) — детект: FSM отказывает
    в переходе без decision-артефакта.
18. Мусор веток/PR в целевом репо — детект: еженедельный janitor-свип
    перечисляет stale; удаление на close.
19. Утечка секретов в артефакты/журнал — детект: secrets-scan хук
    (регэкспы/энтропия) на коммит артефактов; токены только в keychain.
20. Промпт-инъекция из содержимого целевого репо — детект: периодическая
    канарейка с инъекционной нагрузкой; гасит: «репо = данные» в скилах,
    песочница с минимumi правами.
21. Флаки CI порождает ложные «починки» — детект: оркестратор реранит CI
    1 раз до передачи dev; метрика flake-rate.
22. Конвейер дороже ручной работы — детект: cost-per-task vs бейзлайн
    класса в месячном отчёте.
23. Интерференция параллельных задач — детект: конфликт-метрика; гасит:
    лок по целевому репо/сериализация мержей.
24. Смена модели под капотом — детект: model id в журнале каждого запуска;
    канарейка после смены.

## 10. Наблюдаемость конвейера

Пишется с рождения оркестратором (не агентами) в журнал, агрегируется
в metrics-таблицу, рендерится в еженедельный статический отчёт → inbox
Оператора:
- per task: $ / токены / время / возвраты / эскалации / time-to-merge /
  время ожидания гейтов;
- per week: пропускная способность, first-pass approve rate, доля
  эскалаций, результат канарейки, flake-rate, расход.
Регрессия = текущая неделя против медианы 4 недель, пороги в конфиге,
флаги ставит код и кладёт в inbox. Смотрит Оператор (еженедельно)
и оркестратор (автофлаги).

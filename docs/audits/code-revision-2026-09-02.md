### CR-2026-09-02-2 ★ — `_AutoClosingConnection.__del__` бросает в чужом потоке: 28 «Exception ignored» за прогон suite
- Адрес: orchestrator/store.py:89-90 (`def __del__(self): self.close()`,
  введён T090 — лечением CR-2026-08-31-3); наблюдение — полный прогон
  `python3 -m unittest discover`: 28 блоков «Exception ignored in:
  _AutoClosingConnection.__del__ … sqlite3.ProgrammingError: SQLite
  objects created in a thread can only be used in that same thread».
- Суть: лечение сработало (ResourceWarning 3663 → 0), но `close()` из
  финализатора падает, когда соединение, созданное в рабочем потоке
  (тесты конкурентных acquire/гонки cmd_new), доуничтожается GC в
  главном. Итог — тот же класс болезни, что лечили: шум stderr хоронит
  настоящие предупреждения; плюс готовая грабля для многопоточных
  вызывателей будущего (панель Г0, поллер C0). Кандидат: перехват
  `sqlite3.ProgrammingError` внутри `__del__` (закрытие — best-effort,
  объект всё равно уничтожается; C-деаллокатор напечатает свой
  ResourceWarning только для реально живого межпоточного соединения —
  честная деградация, не ослабление).
- Класс: $15. Риск: низкий (одна функция; ассерты не меняются, критерий
  — 0 строк «Exception ignored» на полном прогоне).
- Доказательство: grep -c "Exception ignored" по stderr прогона = 28;
  grep -c ResourceWarning = 0.

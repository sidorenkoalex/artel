## 3. Кандидаты на сведение методов с сохранением утверждений

### 3.1. Как это увидит гейт сегодня (важно для всех групп ниже)

Утверждения считаются **статически по тексту**: `assert`, `self.assert*`,
`self.fail`, `pytest.raises/warns` в теле метода и в помощниках первого уровня,
определённых **в том же классе** или функцией модуля (`scripts/guard.py:912`,
`_helper_calls` на `:889`). Поэтому:

- таблица случаев с циклом (`for raw, want in CASES: with self.subTest(...):
  self.assertEqual(slugify(raw), want)`) даёт **одно** утверждение вместо N и
  другую нормальную форму (литералы стали локальными именами) — храповик увидит
  убыль утверждений, хотя проверок во время исполнения столько же;
- форма «один метод, N явных утверждений, каждое в своём `subTest`» сохраняет
  мультимножество нормальных форм **дословно** — убыли утверждений нет, остаются
  только находки «метод исчез».

Поэтому ниже «станет» везде означает вторую форму (явные утверждения), если не
оговорено иное.

## 6. Механизм: как пропускать слияние без помесячного мандата

### 6.1. Как считает гейт сейчас (разбор `orchestrator/advance_gates/test_integrity.py`)

1. **Находки по файлу** (`_file_findings`, `:374`): для каждого файла диффа
   `tests/**/*.py` — «удалён», «переименован в …», «метод `Класс::метод` исчез»
   (по квалифицированному имени), появившиеся маркеры пропуска и ранний `return`.
   Перенос метода в другой файл = «исчез» в старом файле; переименование класса =
   «исчез» по каждому методу.
2. **Изменённые утверждения** (`_assertion_observation`, `guard.changed_test_assertions`,
   `scripts/guard.py:957`): только для методов, сохранивших имя; сравниваются
   мультимножества нормальных форм; добавление не находка, потеря — находка, если
   не объявлена в SPEC «Меняемое поведение» как смена ожидания.
3. **Храповик** (`_ratchet_decline`, `:768`): суммы по **всем файлам диффа вместе**
   (не по каждому файлу): число методов и сумма утверждений головы должны быть
   не меньше базы — **оба** условия (`:787`). Убыль показывается по файлам, где
   она случилась. Храповик добавляет находку, только если других непокрытых
   находок нет (`:924`).
4. **Мандат** (`_answer_mandate`, `:661`): строка «Ослабление тестов разрешено:»
   в `ANSWER-n.md`; элемент — путь файла (покрывает **все** находки файла, в том
   числе убыль храповика), `путь::Класс` или `путь::Класс::метод`.

Что увидит гейт при слиянии методов A, B, C класса K в метод D:
- три (или две, если D унаследовал имя одного из них) находки «метод исчез»;
- храповик: методы убыли на 2–3; утверждения — не убыли, если D несёт явные
  утверждения A, B, C; убыли, если D — цикл по таблице (TR-22 и 3.1);
- если D сохранил имя A и форма утверждений A изменилась (таблица) — ещё и находка
  «утверждения изменены».
Мандат нужен не «на каждый метод»: элемент-путь файла покрывает всё сразу. Но
такой мандат слишком широк — он заодно разрешает в этом файле настоящее
ослабление, поэтому на практике его и правда приходится писать по методам.

### 6.2. Предложение (без кода)

**TR-27. Объявленное слияние как третий вид записи раздела SPEC.** По образцу
«Меняемое поведение» (`scripts/guard.py:3120`, запись approve гейта SPEC
`DECLARED_CHANGE_ACTION`, `test_integrity.py:101`) — раздел «Сведение тестов»
со строками `tests/<файл>.py::K::a, K::b, K::c → tests/<файл>.py::K2::d`.
Записывается approve гейта SPEC (решение Оператора — одно на задачу, не на метод).

**TR-28. Сверка покрытия на рубеже.** Для каждой объявленной строки гейт проверяет:
1. все методы левой части в базе существуют, а в голове исчезли; метод правой
   части в голове существует (новый или прежний);
2. мультимножество нормальных форм утверждений D (с помощниками) **покрывает**
   объединение мультимножеств A, B, C: для каждой формы число вхождений в D не
   меньше суммы по A, B, C — та же функция, что `changed_test_assertions`, но на
   объединении;
3. ни один метод левой части не присутствует в двух строках (одно утверждение
   нельзя «засчитать» дважды);
4. в D нет новых маркеров пропуска и раннего `return` (действующие правила);
5. если A, B, C жили в разных классах с разной подготовкой — отказ (разная
   подготовка — разные предметы; объединять можно только методы с одинаковыми
   нетестовыми членами класса, это проверяется сравнением `ast` класса).
При выполнении всех условий находки «метод исчез» по A, B, C снимаются, а
храповик сравнивает число методов с поправкой на объявленное сведение (база −
(|A, B, C| − 1)), утверждения — без поправки.

**TR-29. Развёртка таблицы случаев (по желанию, второй этап).** Чтобы
разрешить форму «цикл по таблице», нормализатор должен развёртывать `for` над
**литеральным** кортежем/списком кортежей (без вычислений, без генераторов)
с подстановкой литералов в утверждения тела цикла; тогда таблица из 8 строк даёт
8 нормальных форм, совпадающих с прежними. Всё, что не развёртывается
(таблица из вызова функции, `itertools.product`), считается одной формой —
то есть гейт остаётся строгим. Без TR-29 механизм TR-27/28 работает только для
формы «явные утверждения в `subTest`».

**TR-30. Закрыть слепое пятно помощников.** Считать утверждения помощников по
цепочке наследования внутри того же файла и помощников из `tests/sandbox.py`
(разбор модуля песочницы — тот же `ast`). Без этого (а) ослабление в помощнике
базового класса невидимо, (б) вынос утверждений в песочницу выглядит убылью.
Внимание: включение счёта сразу увеличит числа утверждений в базе всех файлов —
вводить так, чтобы обе стороны сравнения считались одной версией правила (иначе
первая же задача после правки получит ложную убыль или ложный прирост).

Почему это не открывает дорогу ослаблению: слияние разрешено только объявленное
до кода и утверждённое Оператором на гейте SPEC; каждое прежнее утверждение
обязано остаться в D в той же нормальной форме; любое отличие — прежняя находка,
и прежний мандат по-прежнему единственный способ её снять.

Чего это не решает: изоляцию. D выполняет одну подготовку на все случаи, а A, B,
C — каждый свою. Гейт этого не проверит; ревьювер обязан проверить, что случаи
не делят изменяемое состояние (для чистых функций — тривиально; для песочниц —
состояние сбрасывается в теле или случаи только читают). Это правило стоит
вписать в `skills/test-authoring.md`/чек-лист ревью отдельной строкой.

## Резюме для Оператора

1. Набор: 332 файла, 124 тыс. строк, 1 365 классов, 4 301 тестовый метод,
   10 747 утверждений (счёт самого гейта); долгоживущие файлы — 73 / 575 методов /

   631,7 с при нагрузке машины 7–10.
2. Главная находка по скорости (TR-1): 12 самых медленных тестов (два по 45 с и
   десять по 15 с, ≈ 244 с) почти целиком спят в паузе повтора агента

   236 диагностируют это неверно. Лечение — подмена паузы в песочнице (и
   приложением к PLAN в `test_invariants.py`): −240 с работы, ≈ −60 с по стене.
3. Подготовка песочницы (git init/commit в каждом `setUp`) — ещё ≈ 100 с работы;
   шаблон репозитория с копированием (14 мс вместо 34–119 мс) сохраняет изоляцию.
   `setUpClass` с общим состоянием не рекомендую.

   395 утверждений сохраняются; почти все в модульных файлах; на время прогона

   классы — это критерии приёмки, их сливать не стоит.

   храповика (он считает суммы по всем файлам диффа и требует не убывать ни

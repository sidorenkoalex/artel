Фактура входит в финальный текст ADR-0003.

## 1. Флаги изоляции CLI — ✅ подтверждено

- Claude Code CLI 2.1.227: `--setting-sources <sources>` и
  `--strict-mcp-config` существуют (`claude --help`).
- Smoke-тест изоляции (механика A3): пустой репо с подложными
  `CLAUDE.md` (маркер), `.mcp.json` (сервер `evil`), `.claude/settings.json`.
  - `claude -p --setting-sources user --strict-mcp-config` → маркер
    **не** достиг контекста (ответ NO).
  - `claude -p` без флагов → маркер достиг контекста (ответ YES, ZEBRA).
- Деградационный путь (санация клона) не нужен. Пин версии 2.1.227 +
  этот smoke-тест — в doctor (A3, B1a).

## 2. «Токен без прав merge» — ⚠️ допущение переформулировано

- У PAT GitLab нет скоупа «писать, но не мержить»: `api` даёт всё,
  что может пользователь; `read_api` не позволяет комментировать MR
  (нужно для вердиктов, п.5). Свойство «не может смержить» —
  **не у токена, а у защиты ветки целевого**: `merge_access_levels`
  базовой ветки должен быть выше роли учётки.
- Факт gitlab.corp.example: учётка operator-account — Developer (30) во всех
  проектах членства. Примеры:
  - `bdpr/whatif/wi-promo-service`: develop/master/release —
    merge = Maintainers (40) → учётка мержить **не может** — подходит.
  - `promo/dq`: master — merge = Developers+Maintainers (30) → учётка
    **может** мержить — допущение не выполняется.
- Следствие для ADR-0003: условие подключения target-human-проекта —
  проверка doctor при подключении и периодически: `merge_access_levels`
  базовой ветки > access_level учётки; иначе проект не подключается
  до решения Оператора (деградационный путь роадмапа сохранён,
  проверка переносится с «выпуска токена» на «сверку защиты ветки»
  — тот же механизм, что сверка base-ветки/merge-политики в A3).

## 3. Поллинг MR gitlab.corp.example из корп-сети — ✅ подтверждено

- `GET /merge_requests?scope=all&state=opened&order_by=updated_at`
  отвечает; есть фильтр `updated_after` (инкрементальный догон C0)
  и поле `sha` головы MR (hash-фиксация п.15, approve-по-хэшу A2b),
  `detailed_merge_status`, `blocking_discussions_resolved`.
- 2FA на учётке включена, OIDC/LDAP — PAT работает поверх.

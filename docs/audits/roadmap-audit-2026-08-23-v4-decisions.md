## 2. Тест симметрии (топ по стоимости переделки)

Для каждого — абзац «за противоположное» в стиле роадмапа, затем вердикт.

### 2.1 D02 — панель отдельным репо (противоположное монорепо)
*Адвокат противоположного:* «Панель — единственный компонент, который
рендерит чужие тексты и принимает ввод. Отдельный репо даёт то, чего
инвариант импортов не даёт: **независимый релизный цикл** — панель
переделывается дизайн-системой (П4) десятки раз, и каждая её правка сегодня
идёт через A7 с stage0/stage1, пином и smoke-тестом *оркестратора*, хотя
оркестратор не трогала. Контракт API стабилизируется принудительно, потому
что его нельзя “починить в том же MR” — ровно то свойство, что даёт честный
API. Два репо — два пина, но пин панели не роняет конвейер.»
*Вердикт:* не симметрично. Несущий аргумент монорепо — wall-clock на лаге
гейтов — реальный и измеримый; аргумент «независимый релиз» упирается
в то, что панель как процесс в монорепо *тоже* можно рестартовать без
пина оркестратора (пин — на коммит, процессы разные). Но **незаписанный
критерий** есть: после A7 любая правка панели = Draft-PR + гейты + обновление
пина; роадмап не сказал, что обновление пина для «только panel/» диффа может
быть облегчённым. Держится; текст — дописать.

### 2.2 D46 — A7 (противоположное: оставить особый режим догфуда)
*Адвокат противоположного:* «Догфуд — единственный проект, где конвейер
работает 16 задач подряд. Перевод его во внешний флоу до первого реального
внешнего проекта меняет под ногами ровно ту среду, в которой фаза A должна
обкатать шесть новых механизмов (A1–A6). Особый режим стоит $0; A7 — $25 плюс
stage0/stage1, плюс всё дальнейшее развитие самой артели идёт через Draft-PR
и поллер, которых ещё нет. “Класс багов догфуд≠целевой” не исчезает — артель
остаётся особой (без песочницы, с пином). Подопытного для B1b можно получить
без A7: адаптер обкатывается на репо artel как на *чужом* target'е из
отдельного клона.»
*Вердикт:* частично симметрично. Оба абзаца убедительны, отличить «за»
от «против» вслепую трудно — **кроме одного факта, которого в роадмапе нет**:
CI-джоба `protected-paths` работает только на `pull_request`, а догфуд PR не
создавал ни разу — единственный механический enforcement принципа целостности
не исполнялся всю Фазу 0. A7 включает его. С этим фактом решение держится;
незаписанный реальный критерий — «принцип целостности должен иметь работающий
enforcement», а не «единообразие».

### 2.3 D03/D61 — sled (противоположное: без второго проекта; фаза B = артель через A7 + панель + B3)
*Адвокат противоположного:* «После A7 артель — внешний target на GitHub
с настоящим remote, настоящим CI и Draft-PR. Задачи панели — чужой по коду
пакет в песочнице B3 (“обкатка на задачах панели”, L823). Что добавляет
sled? Репо, которое аудит не может открыть, с бэклогом, который никто не
описал, с тулчейном, под который нет образа песочницы, и без branch
protection. За $50 он доказывает одно: “конвейер работает на коде, который
не является оркестратором” — но это же доказывает `panel/`. Фаза B без sled
короче на одно подключение и одну неизвестность.»
*Адвокат роадмапа:* «`panel/` живёт в репо пульта: агент, работая над
панелью, видит оркестратор, БД, скилы — всё, что внешний target *не должен*
видеть. Только чужой репо проверяет, что workspace-изоляция (п.4, п.14)
не держится на том, что “всё рядом”. $50 на реальный бэклог — дешёвая

*Вердикт:* **симметрично.** Выбор сделан по незаписанному критерию —
«у Оператора есть проект, которым он и так хотел заняться». Это легитимный
критерий, но он должен быть записан, а sled — проверен (§6). Переведено
в открытый вопрос (§8).

### 2.4 D22 — единая БД (противоположное: БД per-project + system.db)
*Адвокат противоположного:* «Подключение проекта = каталог (3д). Всё в этом
каталоге — его: артефакты, знания, логи, *и его строки состояния*.
Отключение = переместить каталог, бэкап = скопировать каталог, периметр =
права на каталог. Единая БД ломает project-first ровно в одном месте —
и это место требует колонку target во всех таблицах, архивацию вместо
DELETE, персистентные счётчики per-target (3ж) — три механизма, которых
у per-project БД нет по построению. “Сквозная экономика одним запросом” —
`ATTACH DATABASE` в SQLite.»
*Вердикт:* симметрично по аргументам; **несимметрично по стоимости**:
state.db существует, A1a снята = $0. Незаписанный критерий — стоимость
сейчас. Держится как «по стоимости», текст 3ж должен это сказать вместо
«серверная рамка сняла аргументы».

### 2.5 D66 — демон + FastAPI/WebSocket (противоположное: без демона до этапа 2)
*Адвокат противоположного:* «Критерий выхода этапа 1 — “Оператор читает
состояние в панели вместо CLI” (L951–953). Его выполняет `artel report --html`:
статическая страница из единой БД (борд, метрики, журнал), регенерируемая
при каждом вызове CLI — так же, как CLI уже печатает алерты и premod.
Демон, WebSocket, live-лог — нужны этапу 2 (кнопки) и этапу 4 (события).
A6(д) сам говорит: демонизация — по нагрузке, не по номеру этапа. П2+П3 =
$75 и процесс, который надо держать живым на ноутбуке; статика — ~$15.»
*Вердикт:* **симметрично.** Роадмап не оставил следа рассмотрения
«панель без демона». Незаписанный критерий — привычный стек (в `~/projects`
Оператора есть `fastapi-boilerplate`) и «всё равно понадобится на этапе 2».
Открытый вопрос (§8).

### 2.6 D71 — ассистент на Agent SDK (противоположное: MCP-сервер артели + Claude Code)
*Адвокат противоположного:* «Формула ADR-0004 п.8 — “сегодняшний ассистент
минус shell и коммиты, плюс наблюдаемая память, плюс кнопки” — это Claude Code
с `--tools ""` и единственным MCP-сервером `artel`, отдающим API
(`--strict-mcp-config`). Матрица полномочий = список инструментов сервера;
инвариант Г2 “API отклоняет необратимое для actor=assistant” остаётся.
Хранилище сессий (Ч2) — сессии Claude Code; память — его auto-memory в
каталоге пульта (наблюдаема, в git). Ч1–Ч3 с $90 падают до одной задачи —
MCP-сервер над Г2.»
*Адвокат роадмапа:* «Панельный чат — канал для Оператора с телефона и для
“что происходит?” без терминала; Claude Code — терминальный. Память Claude
Code не имеет потолка и журнала изменений (Чистка-5).»
*Вердикт:* симметрично до этапа 3; выбор носителя можно отложить до
go/no-go (он и так после него). Открытый вопрос (§8), решения сейчас не
требует.

### 2.7 D25 — Postgres = серверная эпоха (противоположное: SQLite на сервере)
*Адвокат противоположного:* «Писатель в БД один — оркестратор. Агенты в БД
не пишут, панель — read-проекция через API того же процесса. SQLite в WAL
с одним писателем и N читателями — штатный серверный режим для такой
нагрузки на годы. Переезд на Postgres добавляет сервис, бэкап СУБД,
миграцию и второй диалект — ради параллелизма, которого в модели нет.»
*Вердикт:* **несимметрично в пользу противоположного.** Роадмап не назвал
ни одного несущего аргумента за Postgres, кроме «параллелизм по триггеру».
Решение — переформулировать: Postgres — по триггеру (второй писатель /
второй пульт), не по эпохе. Движко-независимость схемы остаётся.

### 2.8 D57 — лок тестов test_author, спор = эскалация (противоположное: тест правится через ревью)
*Адвокат противоположного:* «Тест до кода пишется по SPEC без знания тест-инфры
целевого; доля тестов, не компилирующихся или проверяющих не то, будет
заметной. Каждый такой случай — эскалация к Оператору с лагом часы–дни,
причём Оператор план не читает (Б2), а тесты — тем более. Альтернатива:
правка acceptance-теста разрешена разработчику, но обязана пройти ревью
отдельным чеклистом “тест стал слабее?” — ревьювер у нас и так стохастичный,
но он хотя бы в контуре.»
*Адвокат роадмапа:* «Цикл “dev просит — test_author меняет” ровно то, что
превращает приёмку в самосогласование. Лаг — цена честной приёмки; число
эскалаций будет метрикой качества SPEC.»
*Вердикт:* не симметрично (лок — несущий), но **критерия провала нет**:
сколько эскалаций по локу на задачу допустимо, прежде чем признать,
что test_author без контекста кода не работает. Нужна проверка в фазе A
(§8).

### 2.9 D38/D05 — поллинг основной во всех эпохах (противоположное: вебхуки на сервере)
*Адвокат противоположного:* «Аргумент за поллинг — “входящей связности
к ноутбуку нет”. Корп-сервер в той же сети, что scm.x5.ru; вебхук GitLab —
одна настройка проекта; лаг 10 минут исчезает. Роадмап сам держит вебхук
“опцией”.»
*Вердикт:* не симметрично: «догон без потерь» обязателен при любом канале,
значит поллер нужен всё равно, вебхук — только ускоритель. Держится;
незаписанный критерий — «сервер не должен отличаться функционально».

### 2.10 D78 — планирование ×2 от номинала (противоположное: ≈×1)
См. §5.2: «×1.5–3.5» — три ранние задачи со стартовыми $5/$10 до появления
бюджета из SPEC; три поздние (T014–T016) потратили 0.19–0.64 номинала.
*Вердикт:* факт выборочный; симметрии нет — нужен пересчёт. §8.

### 2.11 D62 — N=2 (противоположное: оставить одну активную)
*Адвокат противоположного:* «Узкое место — внимание Оператора на гейтах, не
машинное время. Две задачи в полёте = два контекста в голове part-time
Оператора и общий session limit подписки (T010 умер на нём трижды

гейты пачками.»
*Вердикт:* не симметрично — лаг гейтов это латентность, две задачи ждут
её одновременно. Но «×2–3» — декор, и session limit — реальный риск
без критерия (§5.3).

### 2.12 D44 — B3 первой задачей фазы B (противоположное: песочница к входу в C)
*Адвокат противоположного:* «sled и панель — код Оператора, тот же домен
доверия, что артель (роадмап сам это говорит про артель, L777–780).
Песочница защищает от чужого кода — он появляется в C. Ставить B3 первой
значит блокировать фазу B на задаче, у которой не названы предпосылки:
аутентификация CLI в контейнере, тулчейн целевого в образе, сетевой

*Вердикт:* симметрично по месту в очереди; **несимметрично по готовности**:

### 2.13 D58 — analyst в конвейере (противоположное: SPEC ассистентом в сессии + guard)
*Адвокат противоположного:* «Формат SPEC держит guard, а не роль; стоимость

*Вердикт:* не симметрично — несущий аргумент «ТЗ сохраняется артефактом,

### 2.14 D76 — runbook до серверной эпохи (противоположное: минимальный runbook к C2)
*Адвокат противоположного:* «Окно риска — фаза C на ноутбуке: реальные

*Вердикт:* **симметрии нет, противоположное сильнее** — обоснование

### 2.15 D49 — hash-фиксация (носитель угрозы)

Вопросы по пустым клеткам (как задал бы Оператор) и ответы:

**В1. «А можно ли панель этапа 1 без демона — страницей, которую генерирует
CLI?»** — Стоит рассмотреть. Критерий этапа 1 выполняется; A6(д) уже
говорит, что демон — по нагрузке. Цена решения сейчас: П2+П3 ($75) vs ~$15.
Демон появится для этапа 2 (кнопки) — там он несущий.

**В2. «А можно ли поллер не отдельным процессом, а догоном при каждом
вызове CLI (`artel sync`)?»** — Стоит рассмотреть для тест-эпохи. Роадмап
уже печатает алерты и premod «при каждом запуске» (L669, L475); «догон без
потерь» — свойство алгоритма, а не процесса. Отдельный процесс нужен, когда
есть кому работать без Оператора — это серверная эпоха. C0 с $25 худеет;
health-check становится «давность последнего sync > N → алерт».

**В3. «А где после A7 живут артефакты задач самой артели — в `tasks/`
репо (как 16 задач Фазы 0) или в `.artel/projects/artel/` вне git?»** —
Роадмап отвечает дважды и по-разному (L297–302 vs L299–302/L616–619).
Если в `.artel/` — история догфуда на GitHub обрывается на T016, CI-джоба
`guard --all` становится пустой, ревьювер на GitHub не видит SPEC/REVIEW
(публикация отложена). Если в `tasks/` — артель не «обычный target».
Решение нужно (§8).

**В4. «А можно ли роли на API-ключе, а Оператора — на подписке?»** —
Стоит рассмотреть. Факты: T010 трижды упал на session limit подписки
(общий с интерактивной работой Оператора); `--bare` (самый сильный режим
изоляции CLI) OAuth не читает; контейнер B3 и демон на сервере требуют
`setup-token` или ключ. Ответ зависит от стоимости — роадмап её не считал.

**В5. «А должны ли роли видеть мои личные `~/.claude/CLAUDE.md` и хуки
моих плагинов?»** — Нет, и сегодня видят (§5.2). Вариант: отдельный HOME
для ролей (`HOME=.artel/home`) или `--setting-sources ""` (проверить,
принимает ли CLI пустой список) — дешевле, чем `--bare` с ключом.

**В6. «А нужна ли песочница для target'ов моего же домена доверия (sled,
панель)?»** — Нет как защита, да как репетиция. Роадмап это и делает
(обкатка на панели), но формулирует B3 как условие *фазы B*, а не C.
Ответ «по триггеру `trusted: false` в targets.yaml» не абсурден и снял бы
блокировку фазы B; при этом песочницу всё равно надо построить до C.

**В7. «А можно ли sled не подключать?»** — см. §2.3; открытый вопрос.

**В8. «А можно ли ассистента — как Claude Code с MCP-сервером артели?»** —
см. §2.6; решение не требуется до go/no-go, но стоит записать как
кандидата, чтобы Ч1–Ч3 не оценивались как единственный путь.

**В9. «А Postgres — зачем?»** — см. §2.7; переформулировать в триггер.

**В10. «А обновление пина при диффе только в `panel/` — тоже полный
doctor → smoke → пин?»** — Не абсурдно облегчить; роадмап молчит. Текст.

Компенсирующие механизмы с ушедшей причиной:
- **3и guard `related`** — причина (panel отдельным репо) ушла; механизм
  остался «минимальной механикой» в A1. Перевести в «по триггеру: первая
  реальная кросс-репо задача».
- **Г1a/Г1b как две задачи** — в одном репо и одном домене это один MR
  с инвариантом импортов; сплит на две задачи удваивает гейты.

Взаимно обоснованные пары:
- «A7 после B1b, потому что адаптер нужен раньше клиента» ↔ «B1b первый
  прогон на артели, потому что подопытный нужен до sled» — согласованно, не

### Требования ко второму проекту фазы B (чтобы B2 что-то доказала) и что проверить в sled до подключения
1. **Remote и CI не пульта**: GitHub Actions (или иной CI) реально запускается
   на PR — иначе `verifying`/await-ci в B1b обкатывается вхолостую.
   Проверить: `.github/workflows/*` существуют и зелёные на последнем PR.
2. **Бэклог**: 2–3 задачи объёмом «доки/тесты/малая фича» с проверяемыми
   критериями приёмки, записанные ДО подключения (иначе «из бэклога, не
   выдуманный» — декларация).
3. **Тулчейн в образе B3**: язык/раннер sled должен исполняться в образе
   песочницы (сейчас — node 20 + python3). Проверить: `sled` тесты
   запускаются в `sandbox/Dockerfile` командой одной строки.
4. **Наличие агентской обвязки** (CLAUDE.md/.claude/.mcp.json) в sled —
   иначе п.14 на нём не проверяется; если нет — подложить маркер (как
   в A-спайке) в ветке задачи.
5. **Свежесть**: последний коммит не старше месяца, иначе карта и
   конвенции — археология, а «реальный» — формально.
6. **Права**: Оператор — owner ⇒ `merge_gate=operator`; target-human
   на sled не проверяется — записать, что B2 не покрывает п.7/п.9.
7. **Размер**: репо умещается в workspace/бриф (карта < потолка пакета).
Если ≥2 пунктов не выполняются — sled не лучше «артель + панель» (§2.3),
и открытый вопрос §8 решается в пользу «без второго проекта».

## 1. Проект системы (фаза 1, зафиксирован до чтения наследства)

Черновик целиком (включая полную таблицу жизненного цикла артефактов):
`docs/audits/roadmap-audit-2026-08-24-v5-phase1-blind-design.md`;
здесь — несущие решения.

### 1.1 Несущая идея и флоу

Детерминированный конвейер поверх стохастичных исполнителей. LLM оставлены
три работы: намерение → SPEC, SPEC → дифф, попытка дифф сломать. Всё
остальное — код без интеллекта.

- Классы задач S/M/L при приёме выбирают форму конвейера (не гонять пять
  стадий ради опечатки).
- Стадии: intake (спец-агент делает SPEC c исполняемыми критериями AC;
  гейт Оператора на SPEC несократим — единственная точка входа намерения)
  → plan (только L, гейт автоматический) → implement (чистый контекст:
  SPEC + дайджест знаний о репо + скил роли) → verify (два независимых
  слоя: детерминированный CI/guard/diff-scope/coverage и адверсариальный
  ревьюер БЕЗ рассуждений разработчика, вердикт enum + свидетельства
  исполнением) → merge (гейт) → close (DIGEST ≤ 30 строк, метрики,
  janitor).
- Циклы: dev↔review ≤ 2 возвратов → эскалация; всё с числовым лимитом
  и денежным потолком, стоп исполняет оркестратор, не агент.

### 1.2 Артефакты, состояние, качество, Оператор, экономика

- Артефакт = frontmatter (машинные поля + schema_version) + ограниченные
  секции; один валидатор на писателя и читателя; вердикты — enum; лимиты
  размера в guard; дайджесты вместо полных артефактов в даунстрим.
- Истина — git-артефакты + append-only журнал; state-БД перестраиваемая,
  doctor диффует. Ретраи: 1 на инфраструктурный сбой; «плохой контент» —
  возврат со счётчиком, не ретрай.
- Качество: судейство скриптами где возможно; независимость ревьюера;
  канарейка (эталонная задача, перепрогон после смены промптов/модели);
  посев мутаций (заведомо дефектный дифф ревьюеру — метрика слепоты);
  детерминированный детектор ослабления тестов в диффе.
- Оператор — асинхронное устройство с лагом: один inbox решений,
  пакет решения ≤ 1 экран, никаких таймаут-автопроходов; каждое решение —
  артефакт, решения в чате не существуют; гейт одной задачи не блокирует
  другие.
- Экономика: бюджет по классу в SPEC, жёсткий стоп; стоимость меряет
  оркестратор на выходе шага; контекстная диета (стабильный префикс,
  дайджесты, никакой истории чата).

### 1.3 Гигиена: таблица жизненного цикла

У каждого артефакта — создатель, читатели, событие смерти, удаляющий.
Ключевые строки: tasks/<id> — janitor после close+M дней; журнал — вечен
или компакция; ветки — оркестратор post-merge; дайджест репо —
перезапись, хранится 1; **уроки/память — агенты пишут только
в proposals, промоушен в скилы — акт Оператора** (защита от отравления);
метрики raw → агрегаты; отчёты — 8 недель. Janitor — шаг FSM на close +
еженедельный свип; doctor верифицирует отсутствие сирот. Всё, что
копится без retention, — дефект проекта.

### 1.4 Эволюция

Промпты/скилы/гейты в git, изменение через PR со своим гейтом; после
любого изменения — канарейка, регресс = откат. Самоописание: `artel
describe` генерирует документ пайплайна из кода — рукописная документация
о механике не поддерживается. Фазы — по метрикам выхода.

### 1.6 Наблюдаемость конвейера

Пишет оркестратор (не агенты) с рождения: per task — $, токены, время,
возвраты, эскалации, time-to-merge, ожидание гейтов; per week —
пропускная способность, first-pass approve rate, доля эскалаций,
канарейка, flake-rate, расход. Ответ на «хуже, чем месяц назад» —
код, не глаза: текущая неделя против медианы 4 недель, пороги в конфиге,
флаг → alerts(kind=threshold) → инбокс. Наследство (журнал T007/T010/
T011, alerts A3, report П2′, трение, go/no-go по числам) закрывает всё,
кроме автоматических регресс-флагов — предложение №2.

### 2.4 Пропуски у меня (наследство защищает от угроз, которые я не покрыл)

1. **Конфиг-инъекция через обвязку** (п.14): CLAUDE.md/.claude/hooks/
   .mcp.json целевого и user-слой HOME Оператора исполняются CLI
   автоматически — вектор хуже prompt injection; мой блайнд знал только
   «репо = данные» и песочницу. Плюс пин версии CLI и смоук-тест обоих
   векторов в doctor.
2. **Институт реестра инвариантов**: документ + кодирующие тесты +
   мутационная проверка «тест краснеет на сломанном инварианте» + честная
   вторая таблица некодируемых. У меня были отдельные инвариант-тесты,
   не институт.
3. **Залоченные acceptance-тесты до кода** (A4): лок merge-путём, спор
   с тестом = эскалация, счётный критерий пересмотра лока (>1 эскалации
   на задачу по первым 5).
4. **Весь внешний хвост target-human** (пп.7, 9): undraft ≡ merge_gate,
   awaiting_human с лимитом 3, триаж комментариев 4 класса, премодерация
   обоих каналов, протокол «merge раньше приёмки», kill-протокол
   disconnect с ручной деградацией.
5. **Approve-по-sha** и сверка входа при старте шага (закрытие TOCTOU
   между «показали» и «исполнили») — мой decision-артефакт фиксировал
   решение, но не хэш предмета решения.
6. **Инкрементальный дифф поздним итерациям ревью** — мои дайджесты
   покрывали артефакты, не диффы; экономика ~15–25% стоимости ревью.
7. **Бюджет из SPEC только вниз** — точный механизм против самоподнятия
   потолка через артефакт, который пишет агент.
8. **«Догон без потерь»** как несущий инвариант поллера (сверка полного
   состояния наблюдаемых MR с курсорами, а не событийная подписка).
9. **Метрика «трение»** как целевая функция эргономики агентов.
10. **«Чини класс ошибки, не экземпляр»** + обязательство ревьюера
    перечислять все места класса — микроправило с прямой экономией
    итераций.

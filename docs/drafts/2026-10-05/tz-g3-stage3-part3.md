Требуется:
1. Прочие 28 развилок: SPEC таблицей решает по каждой — удалить (общая
   ветка логики) или оставить с обоснованием, почему это свойство
   артели как пульта, а не проекта (например клон для `note`). Всё
   оставленное проверяет признак одной функцией (`repo_context.is_artel`
   либо её преемник), а не прямым сравнением на месте; дубль `resolve`
   в `orchestrator/fsm.py` ~140-165 сводится к `repo_context`. Итог в
   PLAN — новая разбивка упоминаний по тем же категориям.
2. Сторож: в модулях проверок пункта 8 (`orchestrator/advance_gates/`,
   гейт мержа) прямых сравнений с `config.DEFAULT_TARGET` нет — тест
   разбирает исходники и называет найденное место.
3. Сквозной тест внешнего потока в песочнице: проект с локальным
   «форджем» (голый репозиторий как `origin`) и профилем — гейт зон
   отказывает на файле вне зон, правка пути из его `no_paths` —
   отказ, удаление теста без мандата — отказ неослабления, новый тест
   без заявки — отказ заявки мутации, мерж такой задачи эскалирует
   защищённый путь. Тот же проект без профиля — языковые проверки не
   включаются, запись журнала есть, гейт зон и защищённые пути
   работают.
4. `docs/codebase-map.md` описывает профиль, перечень защищённых путей
   проекта и перевод проверок (всех трёх частей этапа).
5. Тесты в `tests/` с заявками «Ловит мутацию» на пп.1–3 этой части;
   существующие тесты не ослабляются. Смену ожиданий существующих
   тестов роль выносит эскалацией с точным списком — файл, тест,
   прежнее и новое ожидание — и проводит по мандату Оператора разделом
   SPEC «Меняемое поведение» механикой задачи «Смена поведения в
   существующих тестах», с перечнем в PLAN.

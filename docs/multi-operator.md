# Многооператорная эпоха: правила

Досерверная эпоха: N операторов, у каждого свой клон пульта, свои
LLM-подписки и лимиты; координатор — origin пульта (форджа), истина —
git, локальная БД — кэш. Решения Оператора 31.08.2026 (обсуждение
двухоператорного контура); топология — прочтение Б₃ (31.08, по
BL-1/Q-1 аудита v6): при жизни задачи артефакты `tasks/<id>/` — в
артефактной ветке ПУЛЬТА (её push в `cmd_new` = атомарный клейм
сквозного номера), код — в ветке целевого; при закрытии (done И
killed) снапшот артефактов + RETRO уходит в несмерживаемый
`refs/artifacts/<id>` ЦЕЛЕВОГО — жизнь где механика, вечность где
принадлежность; main везде чист; в `.artel/` — кэш-проекция.
`refs/artifacts/*` удаляет только Оператор — несмерженный ref,
в отличие от истории main, смертен, его защита — политика.
Отдельный state-репозиторий — по триггеру, см. docs/triggers.md.

Машинная часть контура (pull --ff-only на входе команд; push ветки
в `cmd_new` как атомарный клейм номера; push артефактов после шагов
и гейтов) — обязанность `artel.py`, не человека: оператор про
артефакты не думает. Ниже — только то, что код не решает.

## Правила

0. **Артефакты чужих задач эфемерны** (решение Оператора 31.08).
   Артефакты несущие локально (FSM инициатора без них не шагает —
   инвариант 2) и эфемерные глобально: пульт показывает то, что
   доехало; недоехавшее — не инцидент, а устаревшая проекция.
   Синхронизация — best-effort транспорт (push с ретраем, fetch по
   возможности); синхронных операций у транспорта нет: имена задач
   уникальны по построению (ULID, решение 31.08 — M1), коллизия
   имён исключена конструкцией, не координацией. (Клейм мерж-окна
   M2 — отдельная синхронная точка мержа, не транспорта.)
   Истина живёт в main целевого (сериализует форджа), истории git
   и локальном журнале инициатора. Граница принципа (решение
   Оператора 31.08, аудит v6 Q-3/MJ-7): информация, входящая
   в АВТОМАТИЧЕСКИЕ решения, best-effort быть не может — при
   неизвестности или устаревании автоматика деградирует в manual
   (после ADR-0010 таких входов один — политика гейтов: origin
   недоступен дольше порога → автогейты в manual + алерт, M2).
1. **Одно перо на файл.** Задачу ведёт её инициатор; чужие файлы в
   `tasks/<id>/` не редактируются. Файл гейта или kill-маркер пишет
   исполнитель полномочия — новым файлом, не правкой чужого.
2. **Чужая задача — после прямой договорённости с инициатором.**
   Общего чата у операторов может не быть (разные машины, разные
   каналы) — канал координации фиксируется при онбординге
   оператора; техническая сериализация (клейм мерж-окна, клейм
   имени) не полагается на канал вовсе. Kill, approve за
   отсутствующего, перехват мёртвой задачи — сначала договорённость,
   потом команда; след в git остаётся автоматически.
3. **Конфиги меняет только Оператор.** `gates.yaml`, `roles.yaml`,
   `targets.yaml` и остальные protected-paths — отдельным MR, как
   и сейчас.
4. **Ничего личного в git.** Токены, привязки моделей, журналы,
   логи — keychain и `.artel/`; в git — только артефакты и паспорта.
5. **Конфликт не чинится молча.** Коллизия номера, конфликт в
   `tasks/`, расхождение sha — сообщить второму оператору по
   согласованному каналу и разобрать руками; повторившийся класс
   конфликта — кандидат в механизм (строка P3).

# Многооператорная эпоха: правила

Досерверная эпоха: N операторов, у каждого свой клон пульта, свои
LLM-подписки и лимиты; координатор — origin пульта (форджа), истина —
git, локальная БД — кэш. Решения Оператора 31.08.2026 (обсуждение
двухоператорного контура); топология — артефакты живут в пульте,
каталоги done-задач со временем удаляются с сохранением в истории
(RETRO хранит sha-адрес; отдельный state-репозиторий — по триггеру,
см. docs/triggers.md).

Машинная часть контура (pull --ff-only на входе команд; push ветки
в `cmd_new` как атомарный клейм номера; push артефактов после шагов
и гейтов) — обязанность `artel.py`, не человека: оператор про
артефакты не думает. Ниже — только то, что код не решает.

## Правила

1. **Одно перо на файл.** Задачу ведёт её инициатор; чужие файлы в
   `tasks/<id>/` не редактируются. Файл гейта или kill-маркер пишет
   исполнитель полномочия — новым файлом, не правкой чужого.
2. **Чужая задача — после слова в чате.** Kill, approve за
   отсутствующего, перехват мёртвой задачи — сначала договорённость,
   потом команда; след в git остаётся автоматически.
3. **Конфиги меняет только Оператор.** `gates.yaml`, `roles.yaml`,
   `targets.yaml` и остальные protected-paths — отдельным MR, как
   и сейчас.
4. **Ничего личного в git.** Токены, привязки моделей, журналы,
   логи — keychain и `.artel/`; в git — только артефакты и паспорта.
5. **Конфликт не чинится молча.** Коллизия номера, конфликт в
   `tasks/`, расхождение sha — сказать в чате и разобрать руками;
   повторившийся класс конфликта — кандидат в механизм (строка P3).

# Изоляция недоверенного проекта — отложено

Статус: **отложено** (решения Оператора 06.11.2026). Действующая
часть: все внешние проекты — доверенные и работают с `sandbox: off`
(или без поля `sandbox`) на условиях второй поправки ADR-0023 от
16.10.2026: шаг роли и тесты — на машине пульта, тесты со службами —
раннером `compose` в контейнере (третья поправка 05.11.2026) с
перекрытием пульта и границей стенда (задача 01M6QRMYW4: монтирования,
секреты и контекст сборки — только внутри дерева прогона, привилегии и
проброс SSH — отказ).

Решения Оператора 06.11.2026 (дословно):
- «пусть пока что sandbox: off как есть, пока что все проекты
  доверенные, недоверенный будет обозначен явно»;
- «давай отложим песочницу».

Следствия решений:
- отсутствие поля `sandbox` у проекта означает прежнее поведение, а не
  `required`: правило ADR-0023 п. 9 «отсутствие означает `required`» по
  второй поправке 16.10 (п. 4) вводится только вместе с D1а и сейчас не
  действует; при активации закрепить пятой поправкой: отсутствие поля —
  прежнее поведение;
- песочница включается только явным `sandbox: required` у проекта,
  который Оператор назвал недоверенным; сейчас такого проекта нет;
- остаточный риск четвёртой поправки ADR-0023 от 05.11.2026 (п. 3:
  роль может вызвать `docker` по полному пути в обход пульта, а клиент
  модели читает файлы машины с правами Оператора) для доверенных
  проектов принят этими решениями.

**Триггер активации:** Оператор назвал проект недоверенным — до первой
задачи этого проекта. Отдельного наблюдателя не требуется (решение
Оператора).

## Что сделать при активации

1. Сверить ТЗ частей 1а–2 с текущей главной веткой: номера строк ТЗ
   — по `origin/main` `971ad3db` (06.11.2026); переписать ссылки и
   заново провести независимую проверку.
2. Внести пятую поправку ADR-0023: механизм круга 1 — `sandbox-exec`
   (отменённый поправкой 16.10.2026 для круга 2 профиль возвращается
   только для шага роли), белый список хостов — прокси пульта;
   семантика поля `sandbox` по решению 06.11.2026.
3. Ответить на вопросы плана частей (команды пульта из шага, сеть до
   части 2, отдельный дом роли, явные `GIT_DIR`).
4. Завести части 1а → 1б → 2 по порядку; `sandbox: required` у проекта
   — только после мержа части 2 и ручных проверок частей.

## Происхождение

ТЗ частей подготовлены ассистентской сессией 06.11.2026 по ADR-0023
(п. 7, поправки 13.10, 16.10, 05.11), протоколу пробы
`docs/research/2026-10-sandbox-probe.md` и опытам `sandbox-exec` на
машине Оператора (фильтра по имени хоста нет; запуск через
LaunchServices закрывается запретом трёх служб вместе); прошли
независимую проверку, замечания внесены.

# Публикация следа в целевые репозитории — отложено

Статус: **отложено целиком** (ADR-0003 п.3). Ближний горизонт:
артефакты внешних целевых — только локально в пульте
(`.artel/projects/<target>/`, ADR-0003 3д); в целевом от Артели —
только ветки `task/` и MR; контекст людям — описание MR
из SPEC + вердикты комментариями (ADR-0003 п.5).

**Триггер активации:** первый запрос людей целевого проекта
на полные артефакты (строка в docs/triggers.md). Включение задним
числом — идемпотентная дозаливка всей истории (первичка в пульте).
Все допущения о ветке (protected, имя, отключение CI) проверяются
только при активации — из предусловий фаз они исключены.

Этот документ — спецификация механики на момент активации
(ADR-0003 п.3 «место спецификации»). Источники — ADR-0003
пп.3/3а/3б/3в/3г/3е и публикационные части пп.15/17; текст ниже
собирает их без изменения смысла.

## 1. Носитель: orphan-ветка `artel` в репозитории целевого

Target-branch — единственный режим (ADR-0003 п.3): orphan-ветка
`artel` (имя конфигурируемо) в репозитории целевого — только
артефакты (`tasks/<id>/` + производные знания 3а: codebase-map,
проектные скилы, per-project копилка К1), без кода и без общей
истории с main (прецедент — gh-pages); рабочие ветки задач всегда
от main. Что даёт: main чист; ничего не создаём на forge; те же
права/токены, что на целевой; люди видят полные артефакты в своём
же репо; периметр по построению.

Роль ветки — «журнал проекта для людей», НЕ бэкап: сохранность
первички — бэкап `.artel/` (тест-эпоха, ADR-0003 3к) и серверные
механизмы (нормальная работа).

## 2. Модель «реплика»

Первичные артефакты — локально, ветка — публикация (ADR-0003 3в).
Публикация фоновая; дефолт частоты — каждый ручной гейт (настройка):
к моменту, когда человек открывает MR, SPEC и вердикты уже в ветке.
Механика: `code_sha` во frontmatter (+guard); идемпотентная дозаливка
реплики (она же лечит любые проблемы ветки); «в ветку artel коммитит
только оркестратор» — точка guard, гигиены п.16 и hash-фиксации п.15.
Записанные компромиссы: лаг видимости до ближайшего гейта; черновики
между гейтами — только локально.

Триггеры публикации — ручные гейты ПЛЮС терминальные переходы
(done/killed/escalated), атомарно одним коммитом (артефакты +
журнальный срез): концовки задач в следе не теряются. При публикации
сверяется ожидаемый head ветки с журналом — расхождение = событие
«внешняя правка ветки», алерт (переписывание не лечится молча).
Зеркальность: «каталог `projects/<target>/` минус workspace →
ветка» (ADR-0003 3д). Публикации сериализуются: per-target очередь +
одна глобальная очередь на запись в git пульта.

## 3. Права записи и enforcement (из ADR-0003 п.15)

Запись в ветку артефактов — только учётка Артели, людям read
(protected branch — силами forge целевого). Для GitLab-целевых
enforcement честный (protected branch у админа целевого); общий
случай (GitHub Free private, чужие админы) — best effort. НЕСУЩАЯ
гарантия всегда — hash-фиксация в журнале БД пульта + approve-по-sha
(безусловны и без публикации). Подписанные коммиты — по триггеру
«появился верификатор подписи».

## 4. CI целевого на ветке artel

По умолчанию GitLab запускает пайплайн на любую ветку — при
активации публикации потребуется `workflow: rules` у целевого
(ADR-0003 п.3). Это допущение проверяется при активации,
не в спайках.

## 5. Bootstrap и знания (из ADR-0003 3а/3е)

Производные знания проекта публикуются рядом с артефактами
(`knowledge/` → ветка artel). Bootstrap первой карты — в механике
подключения проекта; занос в ветку — при активации публикации.

## 6. Внешние правки артефактов — отдельный отложенный концепт

ADR-0003 п.17: без публикации людям физически нечего править.
**Триггер:** активация публикации + первый реальный запрос людей
на правки (ADR-0003 п.18). При активации концепт потребует
отдельного дизайна; рамка: канал правок — MR в ветку artel, приём =
re-гейт (SPEC → повторный spec_gate и т.д.) + занос в первичку
оркестратором; правка никогда не принимается молча; счётчик
external_edit_regates с лимитом 2 → эскалация. Безусловные правила
(сверка хэша при старте шага, авторство вердикта, budget только
вниз) действуют всегда и живут в ADR-0003 п.17, не здесь.

## 7. Двухуровневый срез и ledger-экспорт (из ADR-0003 3г)

Уровень 1 (процессный след) — отложен вместе с публикацией; экономика
в уровень 1 — настройка состава, дефолт нет (витрина сырости,
экспозиция денег, необратимость git-истории). Уровень 2
(ledger-экспорт экономики в git пульта) — отдельный **триггер:
«понадобился внешний экспорт экономики»**; при активации — только
структурированные поля, никаких свободных текстов (код не утекает
по построению состава).

## 8. Догфуд-артель

Git-след артели — по тому же триггеру публикации, что у всех
(«чистый B», ADR-0003 3д): после A7 артефакты новых задач артели
в репо не попадают ни в ветку задачи, ни в ветку artel.

# Пространства (spaces) — отложено

Статус: **отложено целиком** (ADR-0003 п.18) — вместе с hub-storage,
`spaces.yaml` и онбордингом storage в панели. После решения «только
target-branch» (ADR-0003 п.3) у пространства не осталось
материального компонента в ближнем горизонте: панель работает
селектором проектов по `targets.yaml`; производные знания живут
per-project (`.artel/projects/<target>/knowledge/`, ADR-0003 3а);
общепространственное — дома не имеет.

**Триггеры активации** (строки в docs/triggers.md):

- общепространственное хранилище понадобилось фактически —
  кросс-проектная память ассистента или сквозная копилка знаний
  (сегодня память ассистента хранит решения и указатели, знание кода
  не покидает периметр проекта — ADR-0003 3а);
- второй пользователь / второй периметр.

Что уже проверено на будущее: корп-политика допускает storage-репо
на scm.x5.ru (решение зафиксировано в ADR-0003 п.18) — пригодится
при триггере.

Смежное: кросс-таргетные задачи пространство не требуют — модель
«задача = один target, фича на два репо = две связанные задачи
(поле related в SPEC)» — ADR-0003 3и; related-guard — по своему
триггеру в docs/triggers.md.

# Песочница ОС шага роли, часть 2: белый список хостов через прокси пульта, проверки `doctor` и ранний отказ Codex

Статус: **отложено** 06.11.2026 (решение Оператора дословно: «давай отложим песочницу»); триггер и порядок активации — [`../untrusted-project-isolation.md`](../untrusted-project-isolation.md).

Источник: ADR-0023, «Решение» пп. 4, 5, 9 («Сеть», «Секреты», «Отказ при недоступности»); проба пп. 2, 3 (`docs/research/2026-10-sandbox-probe.md`, «Минимальные списки хостов»). Предусловие: части 1а и 1б (`TZ-b3-role-sandbox-1a.md`, `TZ-b3-role-sandbox-1b.md`) смержены — модуль `orchestrator/role_sandbox.py` и обёртка шага существуют; механизм круга 1 — `sandbox-exec` (рекомендация ТЗ; решение — пятой поправкой ADR-0023 при активации); песочница включается только явным `sandbox: required` у проекта, обозначенного Оператором недоверенным. Номера строк ниже — на `origin/main` `971ad3db` (код совпадает с `2d7047e4`); строки модуля частей 1а–1б разработчик берёт с головы `main`.

Термины: «круг 1», «профиль», «пин» — как в части 1а; «прокси шага» — локальный процесс-посредник пульта, через который шаг под песочницей ходит в сеть.

## Факты

1. Фильтра по хосту у `sandbox-exec` нет: в правилах сети допустимы только `*` и `localhost` (опыт 06.11: профиль с адресом или именем хоста не собирается, код 65 — часть 1а, факт 11). После части 1а шаг под песочницей достаёт любой хост на порту 443.
2. Проба п. 2: клиент Claude 2.1.283 под профилем «сеть — только локальный порт прокси» соблюдает `HTTPS_PROXY`, строчные имена переменных прокси не нужны; через прокси прошёл только `api.anthropic.com:443`. Проба п. 6: тот же приём для установки пакетов (`pypi.org`, `files.pythonhosted.org`). Порт прокси под правилом `(allow network-outbound (remote ip "localhost:<порт>"))` достижим, прочие локальные порты — нет (проба п. 13, обратный случай: без запрета локальных адресов тесты доставали и прокси).
3. Переменные прокси в белый список окружения роли не входят (`orchestrator/stack.py:314-333`) — у артели их в окружении шага нет.
4. Проверки `doctor` изоляции шага — `orchestrator/doctor/isolation.py` (`isolation_smoke` `:15`, `codex_isolation_smoke` `:164`, `check_role_git_boundary` `:449`); проверки записи проекта — `orchestrator/doctor/project_checks.py` (`project_entry_checks` `:37`). Таблица паритета `docs/stack.md:629-640` называет живые проверки `doctor`; сторож — `tests/test_stack_parity_table.py`.
5. Набор моделей задачи задаётся при заведении (`catalog.cmd_new`, параметр `model_set`, проверка допуска `:868-870`) и меняется командой `set-models` (`orchestrator/fsm.py:2242`). Наборы с моделями Codex — `codex-dev`, `codex-build`, `codex-all` (`model_sets.yaml:12-23`). Провайдер роли без набора — `providers.for_role(role)` (`orchestrator/runner.py:883-895`).
6. После части 1а отказ Codex на проекте с `sandbox: required` срабатывает только на старте шага: задача с набором Codex доходит до первого шага такой роли и останавливается посередине конвейера (ADR-0023 п. 5 требует отказа раньше).

## Требуется

1. Новый модуль `orchestrator/role_proxy.py` — прокси шага на стандартной библиотеке:
   - слушает только `127.0.0.1` на свободном порту, выбранном ОС; принимает только `CONNECT <хост>:443`; хост сравнивается с белым списком точным совпадением имени без учёта регистра (не подстрокой, не суффиксом); иной метод, порт, хост с управляющими символами или длиннее 253 знаков — ответ 403 и закрытие;
   - белый список круга 1 для Claude — константа `api.anthropic.com` (проба, «Минимальные списки хостов»); расширение — только правкой константы решением Оператора;
   - каждый отказ — запись журнала задачи новым действием с хостом в безопасном виде (`watch.safe_text` или равный по строгости приём); потолок — 20 записей отказов на шаг (константа модуля), сверх него — одна запись «потолок отказов прокси достигнут» и счёт без записей;
   - запускается пультом на шаг до пробного запуска песочницы и снимается при любом исходе шага; не поднялся за 5 с — отказ шага частью 1а (новая причина «прокси шага не поднялся»).
2. В профиле части 1а для шага с прокси сетевые правила заменяются целиком на `(deny network-outbound)` + `(allow network-outbound (remote ip "localhost:<порт прокси>"))`: разрешение `*:443`, разрешение сокета службы имён и последнее правило `(deny network-outbound (remote ip "localhost:*"))` части 1а снимаются (последнее закрыло бы и порт прокси; имена разрешает прокси вне песочницы). В окружение шага модуль ставит `HTTPS_PROXY` и `HTTP_PROXY` = `http://127.0.0.1:<порт>`, `NO_PROXY` — пустой. В `ROLE_ENV_ALLOWLIST` эти имена не добавляются.
3. `doctor`, только для проектов с `sandbox: required` (артель и проекты без поля — строк нет и запуск пульта не блокируется, ADR-0023, решение 9):
   - офлайн-проверка `role-sandbox-command`: собранная для синтетической задачи такого проекта команда шага начинается с `/usr/bin/sandbox-exec -f`, профиль собирается, в нём есть правила записи, чтения, служб, запуска и сети части 1а (сверка по функции сборки, не литералами);
   - живая проверка `role-sandbox-live`: пробный запуск профиля с `/usr/bin/true`, затем под профилем — запись вне корней отказана, подключение к своему слушателю на `127.0.0.1` (не порт прокси) отказано, `CONNECT` к хосту вне белого списка через прокси получает 403. Красная проверка — отказ шагов этого проекта уже на старте `run` с текстом проверки: проверка входит в блокирующие быстрые проверки перед шагом `preflight_checks` (`orchestrator/doctor/preflight.py:757`) только для проектов с `sandbox: required`;
   - проверка записи `role-sandbox-field` в `project_entry_checks` (`orchestrator/doctor/project_checks.py:37`): значение `sandbox` вне `required | off` — `fail` с названием записи, поля и значения (отказ шага при этом даёт уже часть 1а; проверка загрузки `targets.py` не меняется — её поведение закрепляют существующие тесты);
   - имена новых проверок экспортируются из `orchestrator/doctor/__init__.py` рядом с прочими проверками изоляции (`:142-146`).
4. Ранний отказ Codex для проекта с `sandbox: required`: `new --set <набор>` и `set-models <id> <набор>` с набором, назначающим хотя бы одной роли модель провайдера `codex`, и `run`/`auto` задачи, у которой провайдер роли из `roles.yaml` — `codex`, отказывают до заведения или смены набора и до lease, с названием проекта, набора (или роли) и ссылкой на ADR-0023 п. 5. Для артели и проектов без `required` — без изменений.
5. Таблица паритета `docs/stack.md:629-640`: строка «Сеть» и строка «Связка ключей и секреты» у Claude дополняются словами о песочнице шага для проектов с `sandbox: required` и именами проверок требования 3; сторож `tests/test_stack_parity_table.py` остаётся зелёным без правки. Раздел «Песочница шага роли» частей 1а–1б — дополняется прокси.

## Критерии приёмки

Тесты — в новых долгоживущих файлах задачи. Обычные — прокси против своего локального «сервера назначения» (слушатель теста на `127.0.0.1`), подключение имитируется подменой разрешения имени в модуле прокси на адрес слушателя теста; внешняя сеть не используется. Живые — с настоящим `/usr/bin/sandbox-exec`, пометка и пропуск — как в части 1а.

- AC-1: `CONNECT api.anthropic.com:443` (имя подменено на адрес слушателя теста) — туннель установлен, байты проходят в обе стороны. Ловит мутацию: прокси не передаёт данные после ответа 200.
- AC-2: отказы по случаю: хост `api.anthropic.com.evil.test`, `evil.test`, `xapi.anthropic.com`, порт `:80`, метод `GET http://…`, хост с `\r\n`, хост длиной 300 знаков — ответ 403, подключения к слушателю теста нет; в журнале задачи запись с хостом без управляющих символов. Ловит мутацию: сравнение подстрокой или суффиксом; управляющие символы в журнале.
- AC-3: 50 отказов за шаг — ровно 20 записей отказов и одна запись «потолок достигнут». Ловит мутацию: журнал без потолка; потолок на прокси, а не на шаг.
- AC-4: прокси не поднялся (порт недоступен — подмена привязки отказом) — шаг `skipped` с причиной, `spawn_agent` не вызван. После шага при успехе, ошибке и таймауте порт прокси закрыт (подключение — отказ). Ловит мутацию: прокси живёт после шага.
- AC-5 (живой): изнутри профиля с прокси подключение к своему слушателю на `127.0.0.1` (другой порт) и к сокету Unix — отказ; к порту прокси — проходит; `CONNECT` к хосту вне списка — 403. Ловит мутацию: в профиле остался `*:443`.
- AC-6: окружение шага с `sandbox: required` несёт `HTTPS_PROXY`/`HTTP_PROXY` на порт прокси шага и пустой `NO_PROXY`; у артели и проекта без `required` этих имён нет (сравнение с `role_env`). Ловит мутацию: имена прокси в белом списке окружения.
- AC-7: `doctor` для записи с `sandbox: required` даёт строки `role-sandbox-command` и `role-sandbox-live`; при отсутствии `sandbox-exec` (временный дублёр отсутствует) — `fail` с причиной, и `run` задачи этого проекта отказывает на старте до lease; для артели и записи без поля этих строк нет и `preflight_checks` прежние. Запись со случайным словом в `sandbox` — `role-sandbox-field` `fail`; с `required`, `off` и без поля — `ok` или строки нет. Ловит мутацию: проверки для всех проектов; красная проба не блокирует шаг; неизвестное значение проходит `doctor`.
- AC-8: `new --set codex-dev` на проекте с `sandbox: required` — отказ, задача не заведена (нет строки в БД, нет артефактной ветки); `set-models <id> codex-all` — отказ, набор прежний; роль на провайдере `codex` из `roles.yaml` — `run` отказывает до lease. На артели те же команды — как раньше. Ловит мутацию: проверка только набора, не провайдера роли.
- AC-9: `tests/test_stack_parity_table.py` зелёный; строки таблицы «Сеть» и «Связка ключей и секреты» называют проверки требования 3. Ловит мутацию: имя проверки в таблице, которой нет в `doctor`.
- AC-10 (ручной, при Операторе; при первом обозначении проекта недоверенным, не на гейте этой задачи): шаг developer на учебной задаче проекта с `sandbox: required` проходит через прокси; в журнале задачи нет отказов прокси для `api.anthropic.com`; если клиенту нужен другой хост — эскалация с журналом отказов, а не расширение списка ролью.

Каждый автоматический тест — со строкой «Ловит мутацию: …».

Безопасность тестов: внешняя сеть не используется; настоящий клиент модели не запускается; БД пульта, связка ключей, секреты Оператора не трогаются; слушатели и прокси — свои, на `127.0.0.1`, снимаются в `tearDown`; каждый запуск с ограничением времени.

Существующие тесты: не меняются, кроме случаев, когда тест прямо закрепляет старую строку таблицы паритета, — тогда эскалация с именем теста.

Зоны: `orchestrator/role_proxy.py` (новый), `orchestrator/role_sandbox.py`, `orchestrator/runner.py`, `orchestrator/doctor/isolation.py`, `orchestrator/doctor/cli.py`, `orchestrator/doctor/preflight.py`, `orchestrator/doctor/__init__.py`, `orchestrator/doctor/project_checks.py`, `orchestrator/catalog.py`, `orchestrator/fsm.py`, `docs/stack.md`, `tests/` (долгоживущие файлы задачи).

Только чтение: `orchestrator/providers/claude.py`, `orchestrator/providers/codex.py`, `orchestrator/stack.py`, `orchestrator/models.py`, `model_sets.yaml`, `roles.yaml`, `tests/test_stack_parity_table.py`, `docs/adr/0023-role-step-sandbox.md`.

Не входит: прокси для круга 2 и установки пакетов; белый список хостов для Codex; отдельный дом роли; поиск беглых процессов после шага; смена значения по умолчанию поля `sandbox`; правка ADR.

| Сеть шага с `required`: вместо `*:443` — только порт прокси | часть 1а: локальные порты и сокеты закрыты, внешний 443 открыт | закрытое остаётся закрытым; внешний 443 сужается до белого списка | AC-2, AC-5, AC-10 |
| Новый процесс-посредник пульта | — | отказ прокси = отказ шага, без тихого выхода в сеть | AC-4 |

| `doctor` | строки изоляции существующие | да; новые — только для `required`, артель не блокируется | AC-7 |
| Codex на проекте с `required` | отказ на старте шага (часть 1а) | да, плюс ранний отказ | AC-8 |

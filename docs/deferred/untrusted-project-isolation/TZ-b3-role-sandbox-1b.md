# Песочница ОС шага роли, часть 1б: сверка `.git` рабочей копии после шага под песочницей

Статус: **отложено** 06.11.2026 (решение Оператора дословно: «давай отложим песочницу»); триггер и порядок активации — [`../untrusted-project-isolation.md`](../untrusted-project-isolation.md).

Источник: ADR-0023, «Решение» п. 3 (сверка перед git-операциями пульта) и критерий приёмки 3. Предусловие: часть 1а (`TZ-b3-role-sandbox-1a.md`) смержена. План — `TZ-b3-role-sandbox-plan.md`. Номера строк — на `origin/main` `971ad3db`; строки модуля `orchestrator/role_sandbox.py` — с головы `main` после части 1а.

Термины — как в части 1а.

## Факты

1. Профиль части 1а разрешает роли запись `HEAD` каталога администрирования рабочей копии (нужна коммиту, проба п. 8) и закрывает запись файла `.git` рабочей копии, `commondir`, `gitdir`, `config.worktree` и `config` клона. Проба п. 8: подмена `HEAD` на `ref: refs/heads/main` из профиля проходит (код 0); сверка её обнаруживает.
2. После шага пульт до любой проверки ветки коммитит рабочую копию за роль: `_finish_ok` — `checkpoint.commit_success_checkpoint` и `commit_step_artifacts` (`orchestrator/runner.py:2207-2231`); `_finish_failed` — `commit_abnormal_checkpoint` (`:2152-2161`); таймаут — `commit_timeout_checkpoint` (`:2133`); отсутствие артефакта — `:2196`. Коммит идёт на ветку, на которую указывает `HEAD`.
3. До шага ветка рабочей копии сверяется `workspace.on_task_branch` (`orchestrator/workspace.py:494-506`, вызов `runner.py:594-602`, отказ «run отклонён: чужая ветка worktree»); сверка идёт через `git -C <рабочая копия> rev-parse --abbrev-ref HEAD` — то есть сама доверяет файлу `.git` рабочей копии и `commondir`. После шага сверки нет.
4. git-вызовы пульта в репозитории проекта — `gitcmd.in_repo` с позиционным `-C <репо>` (`orchestrator/gitcmd.py:1648-1665`); ADR п. 3 требует явных `GIT_DIR`/`GIT_COMMON_DIR` отдельной функцией области проекта, без правки `in_repo`.
5. Запись инцидента — журнал и `alerts.raise_alert(conn, <проект>, "incident", <источник>, <текст>)` (образец `orchestrator/github_adapter.py:67-70`).

## Требуется

1. Функция модуля `role_sandbox` «сверка `.git` задачи» по ожидаемым значениям из БД (ветка — `store.task_branch`, рабочая копия и клон — `workspace.path`/`workspace.repo`), без запуска git: файл `.git` рабочей копии — обычный файл ровно с одной строкой `gitdir: <путь>`, `realpath` пути равен `<клон>/.git/worktrees/<имя каталога рабочей копии>`; `commondir` каталога администрирования — `realpath` относительно него равен `<клон>/.git`; `HEAD` каталога администрирования — ровно `ref: refs/heads/<ветка задачи>\n`. Файл — не символьная ссылка, читается без следования ссылкам, с потолком размера 4 КиБ.
2. Для шага с `sandbox: required` сверка исполняется после выхода процесса агента (при любом исходе: успех, ошибка, таймаут, отсутствие артефакта, обрыв потока) и до любого `checkpoint.commit_*`. Расхождение: чекпоинт не делается; запись журнала новым действием и инцидент (факт 5) с перечнем расхождений (ожидалось / найдено, без содержимого файлов сверх первых 200 знаков в безопасном виде); исход шага — `failed` без повторов той же попытки (повтор шёл бы на подменённой рабочей копии); `HEAD` пульт сам не чинит.
3. Та же сверка — перед стартом шага с `sandbox: required` в дополнение к `on_task_branch` (`runner.py:594`): расхождение — отказ шага тем же действием журнала.
4. Для артели и проектов без `required` — без изменений: сверка не вызывается.
5. `docs/stack.md`, раздел «Песочница шага роли»: остаточный риск «`HEAD` до части 1б» снимается, описывается сверка.

## Критерии приёмки

Тесты — в новом долгоживущем файле задачи, обычные: настоящий git во временном каталоге теста (`tests/sandbox.py`), клон и связанная рабочая копия теста; запуск агента подменён через `runner.spawn_agent`, подменённый агент меняет файлы `.git` теста как «роль»; `sandbox-exec` — временный дублёр части 1а.

- AC-1: подменённый агент пишет в `HEAD` рабочей копии `ref: refs/heads/main` (`main` клона теста существует) и оставляет грязное дерево — после шага коммита на `main` нет, коммита на ветке задачи нет, запись журнала и инцидент есть, исход `failed`, повтора попытки нет. Ловит мутацию: сверка после чекпоинта; сверка только на успешном исходе.
- AC-2: по случаю на каждое расхождение — `HEAD` на другую ветку задачи; `HEAD` — отделённый sha; `commondir` указывает на чужой каталог; файл `.git` рабочей копии с `gitdir:` на другой каталог; `.git` — символьная ссылка; `HEAD` больше 4 КиБ — отказ с инцидентом, чекпоинта нет. Ловит мутацию: сверка через `git rev-parse` (доверяет подменённому `commondir`); следование ссылкам.
- AC-3: по случаю на исход — ненулевой код, таймаут, отсутствие артефакта, обрыв потока — подменённый `HEAD` обнаружен до чекпоинта. Ловит мутацию: сверка только в `_finish_ok`.
- AC-4: подменённый `HEAD` до шага (между шагами) — шаг `skipped` до `spawn_agent`. Ловит мутацию: сверка только после шага.
- AC-5: честный шаг (коммит на ветке задачи) — сверка проходит, чекпоинт и автокоммит как раньше. Ловит мутацию: ложный отказ на `HEAD` с ветки, имя которой содержит `/`.
- AC-6: артель и проект без `required` — функция сверки не вызывается (подменена исключением). Ловит мутацию: сверка для всех проектов.

Каждый тест — со строкой «Ловит мутацию: …».

Безопасность тестов: только временный каталог теста; настоящий клиент модели, БД пульта, клоны проектов Оператора не трогаются; `sandbox-exec` не нужен (дублёр).

Существующие тесты: не меняются; покраснение — эскалация с именем теста.

Зоны: `orchestrator/role_sandbox.py`, `orchestrator/runner.py`, `docs/stack.md`, `tests/` (долгоживущие файлы задачи).

Только чтение: `orchestrator/checkpoint.py`, `orchestrator/workspace.py`, `orchestrator/gitcmd.py`, `orchestrator/store.py`, `orchestrator/alerts.py`, `docs/adr/0023-role-step-sandbox.md`.

Не входит: явные `GIT_DIR`/`GIT_COMMON_DIR` во всех git-вызовах пульта в области проекта (план, вопрос 4); сверка после прогонов круга 2; сверка `config` клона (закрыт профилем на запись).

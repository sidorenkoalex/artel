# План: песочница ОС шага роли (ADR-0023 п. 7, круг 1)

Статус: **отложено** 06.11.2026 (решение Оператора дословно: «давай отложим песочницу»); триггер и порядок активации — [`../untrusted-project-isolation.md`](../untrusted-project-isolation.md).

Основание: четвёртая поправка ADR-0023 05.11.2026, п. 3 — остаточный риск «роль вызывает `docker` по полному пути в обход пульта» закрывает песочница ОС шага роли, следующая задача по решению Оператора 05.11. Правило деления: рамка задачи — до $100, большее — делить, первая часть самодостаточна и безопасна для артели. Сверено с `origin/main` `971ad3db` (код совпадает с `2d7047e4`); замечания независимого проверяющего 06.11 внесены.

**Решение Оператора 06.11.2026** (дословно): «пусть пока что sandbox: off как есть, пока что все проекты доверенные, недоверенный будет обозначен явно». Следствия: отсутствие поля `sandbox` — прежнее поведение; песочница включается только явным `sandbox: required` у проекта, который Оператор назовёт недоверенным; сейчас `required` нет ни у одного проекта и задачи его не ставят. Механизм круга 1 — `sandbox-exec` с профилем пульта, белый список хостов — прокси пульта: рекомендация ТЗ, решение — пятой поправкой ADR-0023 при активации; семантика поля `sandbox` — по решению 06.11. Задачи готовят механизм заранее: после мержа поведение всех проектов прежнее.

Итого $205. Запасной путь для 1а при превышении: живой AC-16 (LaunchServices) — в ручной AC-13.

После мержа частей песочница ни у кого не включена (решение Оператора 06.11). Когда Оператор обозначит проект недоверенным, он ставит ему `artel.py target-set <проект> policy.sandbox required`, не раньше мержа 1б (до неё роль может подменить `HEAD`) и после ручных AC-13 части 1а и AC-10 части 2 на этом проекте. На гейтах приёмки задач исполняются только автоматические критерии. Артель — `sandbox: off`, без изменений.

Дальше, отдельными задачами по решению Оператора (не входят): прогоны в контейнере по запросу роли (четвёртая поправка, п. 4); отдельный дом роли для проектов с песочницей; открытие кругу 1 каталога интерпретаторов и кэша uv; поиск беглых процессов после шага; смена значения по умолчанию поля `sandbox`; песочница для артели; канарейка под песочницей.

## Ключевые решения ТЗ

- Механизм — `sandbox-exec`, профиль строит пульт; стиль «всё разрешено, кроме перечисленного», позднее правило сильнее (проба п. 9) — рекомендация ТЗ, решение — пятой поправкой ADR-0023.
- Решение «оборачивать ли шаг» — по записи проекта, без проверки имени: путь артели записи не читает (`runner.py:876-877`); отсутствие поля и `off` — прежнее поведение (решение Оператора 06.11); неизвестное значение — отказ шага и `fail` в `doctor`, проверка загрузки `targets.load()` не ужесточается (её поведение закрепляют существующие тесты).
- Команды пульта из шага исполняются внутри круга 1 с тем же профилем: запись — рабочая копия, документы, каталог `suite-run`; БД на чтение; журнал — существующим досылом, как у шага Codex. Вопрос 1.
- Сеть 1а — `*:443` и служба имён без фильтра хостов (опыт 06.11: фильтра по хосту у механизма нет). Вопрос 2.
- Запрет запуска программ по пути (`open`, `osascript`, `launchctl`, `security`, `docker`) — второй рубеж: через интерпретатор он обходится (опыт 06.11). Границы — запрет служб (LaunchServices, связка ключей) и сети (сокет Docker).
- Пропажа клиента под обёрткой даёт код 71 (повторы) — поэтому путь клиента проверяется до обёртки, исход прежний `skipped`.

## Помечено как предположение (снимается ручным AC-13 части 1а при первом обозначении проекта недоверенным)

- Полный перечень файлов, которые клиент Claude пишет в доме роли (проба на 2.1.283); работает ли клиент при закрытых `remote-settings.json`, `policy-limits.json*`, `.last-cleanup`, `HOME/.local/state`.
- Клиент работает при запрете LaunchServices, AppleEvents и буфера обмена; запрет буфера обмена действует.
- Клиент работает напрямую на `*:443` со службой имён (проба шла через прокси).
- Файлы `-wal`/`-shm` БД существуют, пока работает пульт (проба п. 10).
- `plank-run`/`suite-run` проекта с `runner: pytest-own` через uv под профилем 1а, вероятно, не исполнятся — нет доступа к каталогу интерпретаторов и кэшу uv.

## Вопросы Оператору

1. **Команды пульта из шага внутри круга 1** (отступление от раздела Д поправки 13.10: там — отказ читающих команд при исполнителе запросов, отменённом поправкой 16.10, п. 7). У проекта с `compose` прогоны из шага уже отказывают (четвёртая поправка, п. 2) — для него вопрос касается только `knowledge`, `guard`, `status` и подобных; у проекта с `runner: pytest-own` через uv `plank-run`/`suite-run` под профилем, вероятно, не исполнятся. Рекомендация: разрешить команды пульта в круге 1 (читающие работают, журнал — досылом); прогоны тестов из шага не открывать в этих задачах — разработчик недоверенного проекта опирается на гейты пульта до задачи прогонов по запросу роли, как у `compose`. Альтернатива — открыть кругу 1 на чтение каталог интерпретаторов uv и кэш пакетов на шаг (расширение профиля, отдельное решение).
2. **Сеть части 1а без белого списка хостов** до мержа части 2. Рекомендация: принять как промежуточное — это сужение против сегодняшнего (закрыты локальные порты, сокеты, порты кроме 443); включать у недоверенного проекта — только после части 2. Альтернатива — допустить включение после 1б, до части 2.
3. **Общий дом роли.** Шаг под песочницей читает журналы сессий всех проектов в общем доме роли (`.artel/home/.claude/projects/`, `sessions/`, `session-env/`) и может переписать `.claude.json` (то и другое возможно и сегодня). Рекомендация: задача «отдельный дом роли для проектов с песочницей» — до включения песочницы у первого недоверенного проекта; до неё — строкой `docs/triggers.md`. Альтернатива — закрыть чтение чужих журналов правилом по закодированному пути рабочей копии (форма кодирования клиентом не проверена).
4. **Явные `GIT_DIR`/`GIT_COMMON_DIR` во всех git-вызовах пульта в области проекта** (ADR п. 3). Рекомендация: не в этих задачах — файл `.git`, `commondir` и `config` клона закрыты профилем на запись, а 1б сверяет их по БД до чекпоинтов; явные переменные — при переходе круга 2 под песочницу. Альтернатива — отдельная задача сразу после 1б.

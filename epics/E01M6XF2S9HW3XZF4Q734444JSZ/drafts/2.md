## ТЗ

# Раннер compose: контейнеры стенда с init — процессы без родителя не копятся

## Факты

1. Замер 08.11.2026 Оператора (строка копилки `a49dfed34` в `docs/backlog.md`): полный набор артели в `docker run` без `--init` шёл с pytest процессом номер 1. Процессы, оставшиеся без родителя, переходили к нему и не забирались (20 450 зомби); проверка «жив ли процесс» (`kill -0`) видела их живыми — около 175 падений и зависание на 97 % до предела. С `--init` (процесс номер 1 — `tini`) — без зависания.
2. Раннер `compose` пульта поднимает службы `up -d --wait` и запускает тесты `run --rm -T -w <workdir> <сервис> <pytest…>` (`orchestrator/acceptance.py:1435`, `:1452`) по собранной конфигурации с перекрытием пульта `_compose_override` (`:1257-1270`): у сервисов снимается `ports`, добавляются метки; у сетей — `internal: true`. Признака `init` пульт не ставит: в `acceptance.py` нет ни `--init`, ни `init: true`.
3. Версия правила перекрытия `COMPOSE_OVERRIDE_RULE` (`:830-839`) входит в ключ итога; комментарий `:827-829` требует менять её при любой правке `_compose_override`.
4. Тесты перекрытия — `tests/test_01m6paj61d4pyap79adrpa6mwv_compose_run.py` (подменённый `docker`, ответ `config --format json` — единственный канал).

## Требуется

1. `_compose_override` ставит `init: true` каждому сервису собранной конфигурации, если у сервиса нет `init: true`. Значение `init: false` проекта перекрывается на `true`: процесс номер 1 стенда — всегда `init` Docker.
2. `COMPOSE_OVERRIDE_RULE` получает новую версию (номер в начале строки увеличен) и называет `+init` среди правил сервисов.
3. Прочие правила перекрытия, отказы, их порядок и тексты — без изменений.

## Критерии приёмки

Тесты — в новом долгоживущем файле задачи, по образцу песочницы `stand` файла ядра: подменённый `docker`, ответ `config --format json` — единственный канал; функции модуля не подменяются.

- AC-1: конфигурация из двух сервисов (сервис тестов и служба из `depends_on`) без `init` — в файле перекрытия пульта `compose.json`, переданном `up` и `run`, у обоих сервисов `init: true`.
- AC-2: сервис с `init: false` в конфигурации проекта — в перекрытии `init: true`.
- AC-3: прежние правила не сломаны: в том же перекрытии у сервиса нет `ports`, у сетей `internal: true`, метки на месте, а поля сервиса из конфигурации проекта (`image`, `depends_on`, `environment`) сохранились с прежними значениями (ловит замену словаря сервиса вместо добавления поля).
- AC-4: `COMPOSE_OVERRIDE_RULE` не равен литералу прежней строки (значение на `a3b4fc004`, `:830-839`), начинается с увеличенного номера версии и содержит `+init` в части правил сервисов (ловит правку перекрытия без смены ключа итога).

Каждый тест — со строкой «Ловит мутацию: …».

Безопасность тестов: настоящий Docker не вызывается; образы не скачиваются.

Существующие тесты: не меняются. Если тест ядра краснеет из-за нового поля перекрытия (сверка файла перекрытия целиком) — эскалация с именем теста, а не правка теста.

Зоны: `orchestrator/acceptance.py`, `tests/` (долгоживущие файлы задачи).

Только чтение: `tests/test_01m6paj61d4pyap79adrpa6mwv_compose_run.py`, `tests/test_01m6paj61d4pyap79adrpa6mwv_compose_docker.py`, `tests/sandbox.py`.

Не входит:
- `init` для прогонов `pytest-own` и `pult-pytest` на машине (там процесс номер 1 — системный);
- перевод прогонов артели в контейнер (поправка ADR-0023 — Оператор отдельно);
- проверка, затрагивает ли отсутствие `init` наборы подключённых проектов: роль пишет это в «Предложения системе»;
- тест с настоящим Docker на то, что `docker compose run` учитывает `init` сервиса (стандартное поведение Compose; проверяет Оператор живым прогоном после мержа).

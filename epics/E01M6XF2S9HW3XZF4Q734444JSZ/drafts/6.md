## ТЗ

# Уборка doctor не удаляет базу живого suite-run, если каталог процесса не узнан

## Факты

1. `doctor --fix` удаляет каталоги-сироты `artel-canary-*` и `artel-suite-base-*`; базу `suite-run` без маркера владельца защищает только `_live_suite_run_in(path)` (`orchestrator/doctor/orphans.py:62-83`, вызов `:117`): для каждого `run.json` в `config.LOGS/suite-run/` с живым pid он узнаёт рабочий каталог процесса через `doctor._process_cwd` (`orchestrator/doctor/hung_test_watchdog.py:68-81`, вызов `lsof -a -p <pid> -d cwd -Fn`) и защищает каталог, если cwd лежит в нём.
2. `_process_cwd` возвращает `None`, если `lsof` нет, он вернул не 0 или превысил 10 с. Тогда `_live_suite_run_in` пропускает живой прогон (`continue`, `orphans.py:76-77`) и в итоге возвращает `False` — база живого прогона считается сиротой и удаляется (закрыто не по умолчанию).
3. На macOS `lsof` есть всегда (`/usr/sbin/lsof`, `orphans.py:74`), на Linux — не обязательно: в образе `python:3.13` его нет. Тест `tests/test_01m4axpy1py4ps1yafamd47vby_canary_doctor.py::CanaryDoctorTest::test_ac10_fix_removes_only_orphan_among_live_owners` (`:223-240`) — единственный тест файла с настоящим `lsof` — в контейнере падал 3 из 3 (08.11.2026): живая база `suite-run` удалена. Строка копилки `4a21a85b9`; прежняя строка `f26634bc6` называла неверную причину.
4. `_process_cwd` зовёт и сторож зависших прогонов (`hung_test_watchdog.py:172`).

## Требуется

1. Живой прогон, чей рабочий каталог не узнан, защищает базу: `_live_suite_run_in` при живом pid и неизвестном cwd возвращает «защищено» для любого каталога `artel-suite-base-*` (закрыто по умолчанию). `doctor` выводит строку-предупреждение: pid, путь `run.json`, причина («каталог процесса не узнан»), что база не удалена.
2. На Linux `_process_cwd` сначала читает ссылку `/proc/<pid>/cwd` (`os.readlink`); недоступна — прежний путь через `lsof`. На macOS — без изменений.
3. Сторож зависших прогонов (`hung_test_watchdog.py:172`) с новым `_process_cwd` ведёт себя как раньше там, где `lsof` отвечал; поведение при `None` не меняется.
4. Удаление сирот при мёртвом pid и при cwd вне каталога — без изменений.

## Критерии приёмки

Тесты — в новом долгоживущем файле задачи, по образцу песочницы файла `test_01m4axpy1py4ps1yafamd47vby_canary_doctor.py`; `lsof` и `/proc` подменяются в тесте (функция чтения ссылки и исполняемый файл `lsof` в `PATH` песочницы), настоящий живой процесс — дочерний процесс теста.

- AC-1: живой прогон, `lsof` отсутствует и `/proc` недоступен — `doctor --fix` не удаляет базу `artel-suite-base-*`, выводит предупреждение с pid и причиной (ловит прежний `continue`).
- AC-2: `lsof` вернул код 1 — то же, что AC-1.
- AC-3: мёртвый pid в `run.json` — база-сирота удаляется, как раньше.
- AC-4: живой прогон с узнанным cwd в другом каталоге — сирота удаляется, база с cwd внутри — сохраняется (ловит «защищать всё при любом живом прогоне»).
- AC-5: на Linux (`sys.platform` подменён на `linux`) cwd узнаётся по `/proc/<pid>/cwd` без вызова `lsof` (журнал вызовов подменённого `lsof` пуст).
- AC-6: существующий тест `test_ac10_fix_removes_only_orphan_among_live_owners` на машине — зелёный, без правки.

Каждый тест — со строкой «Ловит мутацию: …».

Безопасность тестов: настоящие каталоги `config.LOGS` и клоны канарейки главной копии не читаются и не удаляются.

Существующие тесты: не меняются. Красный существующий тест — эскалация с именем теста.

Зоны: `orchestrator/doctor/orphans.py`, `orchestrator/doctor/hung_test_watchdog.py`, `tests/` (долгоживущие файлы задачи).

Только чтение: `orchestrator/doctor/__init__.py`, `orchestrator/liveness.py`, `tests/test_01m4axpy1py4ps1yafamd47vby_canary_doctor.py`.

Не входит:
- установка `lsof` в образы;
- правка теста канарейки;
- другие места, где неизвестное состояние процесса считается «мёртв» (роль перечисляет найденные в «Предложения системе»).

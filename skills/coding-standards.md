# Скил: coding-standards (разработчик; ревьювер — как эталон проверки)

## Общее
- Код читается чаще, чем пишется: ясность важнее краткости и «умности».
- Меняй минимум, необходимый для требований SPEC. Рефакторинг вне зоны
  задачи — отдельная задача (отметь в PLAN «Риски» или эскалируй).
- Стиль целевого репозитория важнее личных предпочтений: смотри соседние
  файлы — имена, комментарии, структура тестов — и повторяй их идиому.

## Тесты
- Юнит-тесты — часть определения «сделано», не опция. Пишутся на
  поведение из требований, не на структуру кода.
- Падающий тест чинится пониманием причины, не подгонкой ассерта.

## Комментарии
- Комментарий объясняет «почему», код объясняет «что». Комментарии-пересказ
  строки — мусор, не пиши.

## Запрещено
- Секреты/токены/URL внутренних сервисов в коде или тестах.
- Заглушки «TODO потом» вместо требований SPEC — либо реализовано,
  либо эскалация.
- Отключение/скип линтера и тестов, чтобы CI позеленел.

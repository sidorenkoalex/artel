## Реестр замечаний
<Обязательна при schema_version >= 3 (иначе не читается guard'ом и FSM
— требование 6, tasks/T100/SPEC.md). Каждое замечание из «Замечания»
выше — своя строка здесь с id `R<итерация>-F<номер>` (номер записи
внутри ЭТОЙ итерации, с 1, без пропусков). Секция кумулятивна: неси
статус каждой ещё не `accepted` записи из прошлых итераций этой же
задачи — уже `accepted` можно не повторять, она восстановима из
git-истории файла.

| id | статус | файл/строка | суть | последствие | решение |
|---|---|---|---|---|---|
| R1-F1 | open | orchestrator/example.py:42 | ... | ... | ... |

Статус — одно из: `open` (заведено ревьювером, ждёт разработчика),
`fixed` (разработчик отметил исправленным), `rejected` (разработчик
отклонил с обоснованием, код не менялся), `needs_work` (ревьювер
вернул на новую попытку), `accepted` (ревьювер подтвердил закрытие —
терминальный статус). `fixed` и `rejected` закрываются в `accepted`
ТОЛЬКО явным решением ревьювера в следующей итерации — разработчик не
закрывает собственную запись сам. Вердикт `approved` не пройдёт
машинный гейт `review -> verifying`, пока в реестре есть хоть одна
запись со статусом, отличным от `accepted`.
